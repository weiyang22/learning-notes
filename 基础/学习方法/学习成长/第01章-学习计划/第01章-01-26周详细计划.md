### Week 1 · 推荐系统起源 + LR/FM

**周目标**：理解推荐系统的「线性时代」，画出推荐演化主线图。

**本周 OKR**：
- KR1：完成 LR / FM / DeepFM 公式推导笔记 + 1 张推荐系统链路图
- KR2：精读 DLRM 论文，写 200 字摘要
- KR3：跑通 sklearn LR + FM 实验（movielens 数据集）
- KR4：LC 完成 1-2 题（链表）

#### 周中任务（周一-周五，各 2h）

| 日 | 主题 | 时长 | 任务 |
| :--- | :--- | :--- | :--- |
| 周一 | 推荐系统全貌 | 2h | 阅读《推荐系统实战》第 1-2 章；画推荐系统链路图（召回→粗排→精排→重排） |
| 周二 | LR 原理 | 2h | 推导 LR 公式、交叉熵损失、L1/L2 正则；阅读 DLRM 论文 |
| 周三 | LR 工程实践 | 2h | LC 1 题（链表）：LC 206 反转链表 |
| 周四 | FM 原理 | 2h | 推导 FM 二阶交叉公式；阅读 FM 论文 |
| 周五 | FM vs DeepFM | 2h | 阅读 DeepFM 论文；写 1 张 Anki 卡片 |

##### 周一子步骤（推荐系统全貌）
1. **30 min**：读《推荐系统实战》第 1 章，做"推荐系统链路图"草图（手绘拍照存到 `~/kb/papers/W01/`）。
2. **30 min**：对照草图补全"召回/粗排/精排/重排"每个环节的输入输出与典型算法（DSSM / 双塔 / LR / DIN / Listwise）。
3. **30 min**：理解"为什么需要分层"——延迟、特征量、候选集的差异。
4. **30 min**：写 1 张"推荐系统链路" Anki 卡（正反两问：链路顺序 + 每层职责）。

> 💡 **本日子步骤的常见坑**：把"召回"和"粗排"混为一谈。两者本质区别是召回用简化模型处理百万级候选，粗排处理千级候选。

##### 周二子步骤（LR 原理）
1. **20 min**：推导 LR 公式（sigmoid + 交叉熵），写在 A4 纸上。
2. **20 min**：推导 L1/L2 正则的梯度公式，理解为什么 L1 稀疏、L2 平滑。
3. **30 min**：阅读 DLRM 论文 Section 1-3，重点看"为什么 DLRM 把 LR 的稀疏特征和 DNN 的稠密特征拼接"。
4. **40 min**：用 NumPy 写一个 LR mini demo（30 行代码，movielens 子集），验证 AUC > 0.7。
5. **10 min**：写 2 张 Anki 卡（LR 公式 + L1 vs L2）。

##### 周三子步骤（LR 工程 + LC 206）
1. **30 min**：手写 LC 206 反转链表（关 IDE 提示，限时 15 分钟）。
2. **30 min**：用三指针法（prev/curr/next）写 1 遍，再递归法写 1 遍。
3. **40 min**：思考"链表反转在推荐系统哪里用到"——比如用户行为序列反转。
4. **20 min**：把 LC 206 录 1 分钟讲解视频，发到 Anki 卡片备注。

##### 周四子步骤（FM 原理）
1. **30 min**：推导 FM 二阶交叉公式 `y = w0 + Σw_i·x_i + Σ⟨v_i, v_j⟩·x_i·x_j`，理解为什么参数从 O(n²) 降到 O(n)。

| 23 | MTGR 引入 Query 支路，避免 Decoder-only 的 Intent Dilution（用户历史被平均稀释）；Query 直接来自当前请求，强制聚焦。 |
| 30 | LLM4Rec 把 LLM 当特征提取器或生成器；MTGR 把推荐 token 化用 Transformer Decoder 自回归生成；本质区别 = LLM4Rec 偏 LLM 能力迁移，MTGR 偏端到端推荐重塑。 |

class RQVAE(nn.Module):
    """残差量化 VAE"""
    def __init__(self, input_dim, num_quantizers=4, num_codes=256, code_dim=64):
        self.encoder = Encoder(input_dim, code_dim)
        self.decoder = Decoder(code_dim, input_dim)
        self.quantizers = nn.ModuleList([
            VectorQuantizer(num_codes, code_dim) for _ in range(num_quantizers)
        ])

    def forward(self, x):
        z = self.encoder(x)
        residual = z
        codes = []
        for q in self.quantizers:
            code, vq_loss = q(residual)
            codes.append(code)
            residual = residual - self.decoder(code)  # 残差
        recon = self.decoder(sum(codes))
        return codes, recon, vq_loss

```python
# scheduler.py 核心
class ContinuousBatchingScheduler:
    """Continuous Batching 调度器"""
    def __init__(self, max_batch_size, model):
        self.waiting_queue = deque()
        self.running = []
        self.max_batch_size = max_batch_size
        self.model = model

    def add_request(self, request):
        self.waiting_queue.append(request)

    def step(self):
        # 1. 处理 running 中所有请求
        outputs = self.model.forward(self.running)

        # 2. 标记完成的请求
        finished = [r for r in self.running if r.is_finished()]

        # 3. 移除完成的请求
        for r in finished:
            self.running.remove(r)

        # 4. 从 waiting 补充新请求
        while len(self.running) < self.max_batch_size and self.waiting_queue:
            new_req = self.waiting_queue.popleft()
            self.running.append(new_req)

        return outputs, finished
```

**实验设计**：
- 模型：HuggingFace GPT-2 小模型。
- 请求：随机生成 100 个不同长度的请求。

- 指标：吞吐量（tokens/s）、平均延迟、P99 延迟。

## 附录 L · 新增（v3）：落后补救 / 加速 / 跳级策略

### L.1 落后补救（5 类典型场景）

#### 场景 1：工作突然变忙，整周没学习

**诊断**：
- 这周学习时长 0h，OKR 完全没达成。

**补救方案**：
1. 立即把"周末"延长到周日整天（6h+）。
2. KR 砍半：只保留"读 1 篇论文" + "做 2 张 Anki"。
3. 下周恢复正常节奏前，加 1 个"补偿周末"。

**预防**：
- 工作日最低保底：每天 30 分钟（1 个番茄）。
- 不能 30 分钟都没有时，写"今天为什么没学"到 bug-diary。

#### 场景 2：理论推导卡住，整周停滞

**诊断**：
- 公式推导卡了 3 天没进展。

**补救方案**：
1. 暂停推导，直接看论文公式 + labml.ai 注释实现。
2. 抄一遍公式（手写到 A4 纸）。
3. 跳过这周推导，专注"代码实现 + Anki"。

**预防**：
- 任何公式推导最多卡 2 天，否则必须看资料。
- 公式不理解 ≠ 不能用，先用再理解。

#### 场景 3：Coding 卡题，连续 5 题失败

**诊断**：
- LC 卡壳率 > 50%，信心崩塌。

**补救方案**：
1. 切换难度：从 Hard 降到 Medium，刷 10 题恢复信心。
2. 限时放宽：从 30 min 放宽到 60 min。
3. 找题解 + 默写模板，不强求"自己想出来"。

**预防**：
- 每 5 题必须有 1 题"完全会做"（Easy 或刷过的）。
- 卡 30 min 看题解是 OK 的，不丢人。

#### 场景 4：项目精修写不出

**诊断**：
- 项目卡片写了 3 周还没定稿。

**补救方案**：
1. 用"模板填空法"：先填五段式模板，每个空不超过 50 字。
2. 找朋友口述 1 遍，再写下来。
3. 录 5 分钟视频，再整理成文字。

**预防**：
- 项目卡片 = 5 个段落，每段 50 字左右。
- 不要追求"完美"，能讲清就行。

#### 场景 5：心态崩（不想学了）

**诊断**：
- 连续 3 天没有打开任何学习资料。

**补救方案**：
1. 强制放假 2 天（完全不学）。
2. 第 3 天做"最小可行单位"：只刷 1 道 LC Easy。
3. 第 4 天恢复正常节奏。

**预防**：
- 每周至少 1 天完全不学（休息日）。
- 心态崩是正常生理现象，不是"你不适合这条路"。

### L.2 加速策略（4 周压缩到 2 周）

#### 场景：你想跳过 Pre-Phase 0，直接从 Week 1 开始
