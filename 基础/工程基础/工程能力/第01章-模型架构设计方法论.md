# 第01章-模型架构设计方法论

求到架构的 7 步法

1. **明确任务与指标**: 分类/回归/生成/检索? 离线 AUC 还是在线时延? 优化目标决定损失与输出头。
2. **刻画数据**: 模态(表格/序列/图像/文本/多模态)、规模、稀疏性、长尾。数据形态决定 backbone。
3. **选归纳偏置**: 数据的结构假设匹配哪种算子(见 §2)。
4. **定容量**: 参数量对齐数据量与算力预算(见 [第03章](第03章-参数量与显存预估.md))。
5. **设计骨架**: Embedding/Backbone/Head 三段式, 明确每层张量形状。
6. **校验约束**: 复杂度([第02章](第02章-时间与空间复杂度分析.md))、显存、延迟是否达标, 不达标回到 3-4。
7. **可演进性**: 预留可插拔接口(换 backbone、加任务头), 别写死。

---

## 2. 归纳偏置: 算子选型的第一性原理

**归纳偏置(inductive bias)**= 模型对数据结构的先验假设。选对了, 少数据也能学好。

| 数据结构 | 匹配算子 | 归纳偏置 |
| :--- | :--- | :--- |
| 局部平移不变(图像) | CNN | 局部性 + 权值共享 |
| 时序/因果(文本) | RNN / 因果注意力 | 顺序依赖 |
| 集合/长程依赖 | Self-Attention | 全局交互, 弱结构假设 |
| 图结构(社交/分子) | GNN | 邻接聚合 |
| 高基数类别(ID 特征) | Embedding | 可学习查表 |

> **越强的归纳偏置**(CNN)→ 越省数据但越受限; **越弱**(Transformer)→ 越通用但越吃数据算力。设计时按"数据量"在两端权衡。

## 3. 三段式骨架(通用模板)

几乎所有深度模型都可拆成:

```text
输入 → [Embedding/Tokenizer] → [Backbone 若干 Block] → [Task Head] → 输出
```

```python
import torch.nn as nn

class Model(nn.Module):
    def __init__(self, cfg):
        super().__init__()
        self.embed = build_embedding(cfg)          # 输入表征
        self.backbone = nn.ModuleList([            # 可堆叠的同构 Block
            Block(cfg) for _ in range(cfg.depth)
        ])
        self.head = build_head(cfg)                # 按任务定制输出头

    def forward(self, x):
        h = self.embed(x)
        for blk in self.backbone:
            h = blk(h)                             # 残差在 Block 内部
        return self.head(h)
```

**要点**: backbone 用**同构可堆叠 Block**(如 Transformer Block), 深度是超参; head 与任务解耦, 换任务只改 head。

## 4. 深度 vs 宽度(容量分配)

给定参数预算, 是"深而窄"还是"浅而宽"?

- **深**: 表达力强(复合函数), 但难训(梯度)、串行延迟高。需残差 + 归一化。
- **宽**: 好并行、易训, 但参数效率低、易过拟合。
- **经验**: Transformer 常见 $d_{ff}=4d_{model}$; 层数 $L$ 与 $d_{model}$ 大致同步放大(见 scaling law)。
- **宽深比**约束: 太深太窄易梯度不稳, 太浅太宽浪费容量。

## 5. 设计取舍 Checklist

设计完问自己:

- [ ] 每个组件的**归纳偏置**是否匹配数据?
- [ ] 参数量是否与数据量、算力匹配(不过拟合/欠拟合)?
- [ ] 前向复杂度、显存峰值、推理延迟是否在预算内?
- [ ] 是否有**残差 + 归一化**保证可训性?
- [ ] 输入/输出/中间张量**形状**是否推演清楚?
- [ ] 是否可以**消融**(每个模块能单独开关做实验)?
- [ ] 换 backbone / 加任务头是否只需改配置, 不动核心?

---

## 6. 反模式(常见坑)

- **堆模块崇拜**: 无脑加 attention/gate, 不做消融, 收益未知还拖慢。
- **形状黑箱**: 不推张量形状, 靠报错调试, 效率极低。
- **过早优化**: 还没跑通就上分布式/量化。
- **写死超参**: 维度/层数散落代码各处, 无法搜参(见 [第06章](第06章-超参数与配置设计.md))。

## 7. 案例串讲: 设计一个精排模型

需求: 推荐精排, 特征=用户序列 + 上百个稀疏 ID + 数值特征, 时延 < 20ms。

- 数据→归纳偏置: 序列用注意力(建模兴趣), 稀疏 ID 用 Embedding, 数值直接过 MLP。
- 骨架: `Embedding(拼接) → 序列注意力池化 → 特征交叉(DCN/MLP) → MTL 多任务头`。
- 约束: 时延 20ms → 注意力序列长度截断到 50, backbone 浅(2-3 层)。
- 演进: 特征交叉层可插拔(DCN ↔ MLP ↔ FM), 任务头可增删。

> 完整落地见 [rec教程 第15章-训练流程与工程实践](../../../搜推广与生成式推荐/经典推荐/第15章-训练流程与工程实践.md)。

## 8. 深入原理：为什么"归纳偏置"是第一性原理

### 8.1 No-Free-Lunch 与先验

**No-Free-Lunch Theorem (NFL)**：若不对数据分布作任何假设，所有算法的平均性能相同。这意味着：要让某个模型**优于**另一个，必须对数据施加**先验知识**——这就是归纳偏置。

用贝叶斯视角表达：

$$\hat{\theta} = \arg\min_{\theta} \underbrace{\mathcal{L}(\theta)}_{\text{损失/似然}} + \underbrace{\lambda \cdot \Omega(\theta)}_{\text{正则/先验}}$$

不同算子对应不同的 $\Omega$：

| 算子 | $\Omega$ 项 | 体现 |
| :--- | :--- | :--- |
| CNN | 局部性 + 平移不变核 | 权值共享 + 局部感受野 |
| RNN | 序列因果性 | 单向信息流 |
| Self-Attention | 弱结构 | 任意 token 全连接 |
| GNN | 邻居聚合 | 排列等变性 |

> **理解"归纳偏置"的口诀**：模型 = 先验 + 数据 + 算力。先验越强，越省数据；先验越弱，越吃数据。

### 8.2 模型选择与 Occam 剃刀

奥卡姆剃刀要求：在同等经验风险下，选择**参数更少、结构更简单**的模型。这与"参数效率"对应。

$$\text{BIC} = n \cdot \ln(\hat{\sigma}^2) + k \cdot \ln(n)$$

其中 $n$ 为样本量，$k$ 为参数个数。同样的训练损失，$k$ 小的模型 BIC 更优 → 泛化更好。这一指标可用于**模型族选型决策**。

```python
# 模型族选择：比较不同族的 BIC
def bic(nll, n, k):
    return n * np.log(nll / n) + k * np.log(n)

# 用于：CNN vs Transformer vs Mamba 在固定数据上的比较
```

## 9. 数学基础：万有逼近与深度

### 9.1 万有逼近定理（Universal Approximation）

单隐层 MLP（足够宽）可以逼近任意紧集上的连续函数：

$$\forall f \in C([0,1]^d), \forall \epsilon > 0, \exists \text{MLP}: \sup_x |f(x) - \hat{f}(x)| < \epsilon$$

但定理**只保证存在，不保证可学/可泛化**——容量够了不等于能学好。

### 9.2 容量的形式化

**VC 维** $\text{VC}(H)$：能被假设空间 $H$ 打散的最大样本数。

**Rademacher 复杂度**：

$$R_m(H) = \mathbb{E}_{\sigma}\left[\sup_{h \in H} \frac{1}{m} \sum_i \sigma_i h(x_i) \right], \quad \sigma_i \in \{-1, +1\}$$

泛化界：

$$\mathbb{E}[R(h)] \leq \hat{R}(h) + 2 R_m(H) + \sqrt{\frac{\ln(1/\delta)}{2m}}$$

即"经验风险 + 复杂度惩罚"。深度模型的泛化常**显著优于**这些最坏情形界——这是活跃研究区。

### 9.3 缩放律（Scaling Law）经验法则

经验上 loss 随参数 $N$、数据 $D$、算力 $C$ 的幂律下降：

$$L(N) = \left(\frac{N_c}{N}\right)^{\alpha_N}, \quad \alpha_N \approx 0.07 \sim 0.08$$

Chinchilla 给出最优分配：

$$N^* \propto C^{a}, \quad D^* \propto C^{b}, \quad a \approx b \approx 0.5$$

即算力翻倍时，**参数量与数据量同比例增长**，约 $D \approx 20N$ token/参数。设计上避免"参数过载、数据不足"或"小模型、大数据浪费"。

## 10. 算子设计：从数学到 PyTorch 骨架

### 10.1 主流算子的统一视角

大多数算子都可写为：$y = \sigma(W x + b) + \text{residual}(x)$。

```python
# 线性/卷积/注意力的统一骨架
class OpBlock(nn.Module):
    def __init__(self, in_d, out_d, op_type="linear"):
        super().__init__()
        self.op_type = op_type
        if op_type == "linear":
            self.W = nn.Linear(in_d, out_d)
        elif op_type == "conv":
            self.W = nn.Conv2d(in_d, out_d, 3, padding=1)
        elif op_type == "attn":
            self.qkv = nn.Linear(in_d, out_d * 3)
        self.norm = nn.LayerNorm(out_d)
    def forward(self, x):
        return self.norm(x + self.W(x))
```

> **设计要点**：同一个骨架可切换算子，方便做 ablation（消融）。这正是 MMDetection/timm 的设计哲学。

### 10.2 多头注意力的形状推导

设 $d_{model}$、$h$ 头、序列长 $n$：

```text
输入 x: (B, n, d_model)
QKV 投影: (B, n, 3*d_model)
reshape: (B, h, n, d_k), d_k = d_model/h
attn = softmax(QK^T / sqrt(d_k)) @ V   # (B, h, n, d_k)
合并: (B, n, d_model)
```

**复杂度的形状依据**：

- $QK^T$：$(B,h,n,d_k) \times (B,h,d_k,n) = (B,h,n,n)$
- softmax·V：$(B,h,n,n) \times (B,h,n,d_k) = (B,h,n,d_k)$

可见注意力矩阵是 $n \times n$，长序列时**平方增长**——这就是后续 Flash Attention/Paged Attention 优化的根源。

## 11. 行业架构案例库

### 11.1 NLP：Transformer 与 Decoder-only

**架构定位**：通用序列建模，弱归纳偏置 → 需大数据/规模。

```text
Token Embedding (V, d) + Pos Embedding (n, d)
→ L × [RMSNorm → Attention(RoPE) → FFN(SwiGLU)]
→ LM Head (与 embedding 权重共享)
```

**关键设计选择**：

- **位置编码**：RoPE > Sinusoidal，支持长度外推。
- **激活**：SwiGLU > ReLU/GELU（FFN 表现更佳）。
- **归一化**：RMSNorm > LayerNorm（参数少、速度略快）。
- **KV 缓存**：自回归必选，GQA/MQA 减显存。

> 例：LLaMA3-8B 用 GQA($n_{kv}=8$, $n_q=32$) → KV 显存减 4x。

### 11.2 视觉：CNN vs ViT 的现代混合

**Hybrid 架构**（ConvNeXt、Swin）：

```text
Stage 1: Conv stem (下采样 4x)
Stage 2: Residual Blocks (局部特征)
Stage 3: Window Attention (局部+全局)
Stage 4: Global Attention + AvgPool
```

**关键选择**：

- **早期用 CNN**：保留局部归纳偏置，对小数据友好。
- **后期用 Attention**：捕捉长程依赖，对大尺度友好。
- **层级下采样**：patch merging，特征图减半、维度翻倍。

### 11.3 推荐：DLRM vs DIN vs Two-Tower

**Two-Tower 召回**：

```text
User Tower: user features → embedding → MLP → u (B, d)
Item Tower: item features → embedding → MLP → v (B, d)
相似度: score = u ⋅ v / (|u| |v|)
```

排序模型（DIN）：

```text
User history (n_behaviors, d) + Candidate (d)
→ Local Activation Unit (注意力加权)
→ Concat(u_pool, candidate, ctx) → MLP → score
```

**架构选择本质**：

- 两塔适合**高效检索**（Faiss 向量召回）。
- DIN 适合**精排**（个性化交互）。
- 多任务用 **MMoE/PLE**（gate 路由）。

### 11.4 多模态：CLIP / BLIP 风格

```text
Image → ViT → img_emb (B, d)
Text  → Transformer → txt_emb (B, d)
对比学习: sim = img_emb @ txt_emb.T / tau
```

**设计要点**：

- **塔大小一致**或**可独立扩展**。
- **温度** $\tau$ 是关键超参（一般 0.07）。
- **数据**：对比学习核心是**大批量配对数据**。

### 11.5 强化学习：Actor-Critic

```text
Actor: state → π(a|s) → action
Critic: state → V(s) → 估计未来回报
→ 优势 A(s,a) = Q(s,a) - V(s)
```

**架构要点**：

- **共享 backbone**：state encoder 共用，提速。
- **输出头分开**：policy head 与 value head 各为线性层。
- **PPO 等算法**：clip ratio 阈值是核心超参。

**Hydra / OmegaConf** 提供 yaml + 命令行覆盖。

### 12.2 模块化与可插拔

```python
class Backbone(nn.Module):
    """可插拔 Backbone，方便换 CNN/ViT/Swin"""
    def __init__(self, cfg):
        super().__init__()
        if cfg.backbone == "vit":
            self.body = ViT(cfg)
        elif cfg.backbone == "cnn":
            self.body = ResNet(cfg)
        elif cfg.backbone == "swin":
            self.body = SwinTransformer(cfg)
    def forward(self, x): return self.body(x)
```

### 12.3 形状断言（开发期）

```python
def forward(self, x):
    assert x.dim() == 4, f"expect (B,C,H,W), got {x.shape}"
    B, C, H, W = x.shape
    # 下采样倍数 = 32
    assert H % 32 == 0 and W % 32 == 0
    return self.body(x)
```

**shape check** 在模型首次 forward 时启动一次，省去日后调试时间。

## 13. 容量分配与算力预算的工程估算

### 13.1 参数量快速估算（规则）

对 dense Transformer：

$$N \approx 12 L d^2 \quad (\text{不含 embedding})$$

加 embedding：

$$N \approx 12 L d^2 + V \cdot d$$

**Hand-rule 实例**：

| 模型 | d | L | N（不含 emb） | FP16 字节 |
| :--- | :--- | :--- | :--- | :--- |
| GPT-2 small | 768 | 12 | 85M | 170 MB |
| GPT-2 medium | 1024 | 24 | 302M | 604 MB |
| GPT-2 large | 1280 | 36 | 711M | 1.4 GB |
| LLaMA-7B | 4096 | 32 | 6.7B | 13.4 GB |
| LLaMA-13B | 5120 | 40 | 12.6B | 25.2 GB |

### 13.2 算力需求（6ND 法则）

训练：

$$\text{FLOPs}_{\text{train}} \approx 6 N D$$

其中 $D$ 为 token 数。

例：LLaMA-7B、1T tokens → $6 \times 7 \times 10^9 \times 10^{12} = 4.2 \times 10^{22}$ FLOPs ≈ 6e6 GPU·h（H100 算力约 700 TFLOPS 假设利用率 40%）。

### 13.3 显存估算

| 项 | 字节/参数 |
| :--- | :--- |
| FP16 权重 | 2 |
| FP16 梯度 | 2 |
| FP32 master | 4 |
| Adam m, v | 8 |
| **合计** | **16** |

7B 模型训练 ≈ 112 GB → 单卡装不下，需 ZeRO-3 / FSDP 分片。

## 14. 设计取舍：常见决策表

### 14.1 CNN vs Transformer

| 维度 | CNN | Transformer |
| :--- | :--- | :--- |
| 数据需求 | 中等 | 大 |
| 推理速度 | 快 | 慢（自注意力二次） |
| 可解释性 | 中（局部特征可视化） | 低 |
| 长程依赖 | 弱 | 强 |
| 适用 | 视觉小数据 | NLP / 视觉大数据 |

### 14.2 深度 vs 宽度

经验：**深度 = 容量，长度 = 表达**。

- 深 → 更复杂的函数组合；浅 → 更宽的特征空间。
- Transformer：$d_{ff} = 4 d_{model}$, $L \propto \log d_{model}$。

### 14.3 激活函数

| 激活 | 优点 | 缺点 |
| :--- | :--- | :--- |
| ReLU | 快、稀疏 | 死亡神经元 |
| GELU | 平滑、SOTA 默认 | 略慢 |
| SwiGLU | SOTA（PaLM/LLaMA3） | 多一倍参数 |
| SiLU | 折中 | — |

### 14.4 归一化位置

| 位置 | 影响 |
| :--- | :--- |
| Post-Norm（原 Transformer） | 训练不稳，需 warmup |
| Pre-Norm（GPT/LLaMA） | 训练稳，省 warmup |
| RMSNorm（LLaMA） | 比 LayerNorm 快，省参数 |

### 14.5 位置编码

| 方式 | 优势 | 劣势 |
| :--- | :--- | :--- |
| 绝对位置（Sinusoidal） | 简单 | 不可外推 |
| 可学习位置 | 灵活 | 不可外推，长度=训练长度 |
| RoPE | 相对位置 + 长度外推 | 略复杂 |
| ALiBi | 线性偏置，外推强 | 性能略降 |

## 15. 算法伪代码：通用架构设计决策流

```text
**Algorithm 1.1** 通用架构设计决策流
**Input**: 任务定义、数据统计、算力预算 (GPU 数 × 时长)、延迟预算
**Output**: 模型骨架配置

1. 解析任务类型 T in {分类, 回归, 序列, 生成, 检索, 多模态}
2. 评估数据：(N_samples, modality, seq_len, vocab_size)
3. 根据 T 选择归纳偏置族 f(T):
       - 图像/网格 → CNN family
       - 序列/语言 → Transformer family
       - 图/网络 → GNN family
4. 用 Chinchilla 缩放公式估算合理参数量 N
5. 在算力预算内 6ND < C_budget 反推最大 D
6. 分配深度 L 与宽度 d: L * d^2 ~ N/12
7. 选算子变体（attention 类型、激活、归一化、位置编码）
8. 验证 FLOPs/显存/延迟在预算内
9. 输出 cfg.yaml, 含可演进点（backbone / head 可换）
```

**复杂度**：$O(\text{超参数空间})$, 通常靠经验 + 小规模网格搜索。

## 16. 完整代码：可演进 Transformer 骨架

```python
"""
可演进 Transformer 骨架
- 同构 Block，可切换注意力/FFN 实现
- 配置驱动，从 yaml 读全部超参
- 形状断言，便于开发期排查
"""
import math
from dataclasses import dataclass, field
from typing import Optional, List
import torch
import torch.nn as nn
import torch.nn.functional as F


@dataclass
class ModelConfig:
    vocab_size: int = 32000
    d_model: int = 512
    depth: int = 6
    n_heads: int = 8
    d_ff: int = 2048
    max_len: int = 2048
    rope_theta: float = 10000.0
    dropout: float = 0.0
    norm_eps: float = 1e-6
    tie_embeddings: bool = True
    # 可演进: 选择不同 Attention 实现
    attn_impl: str = "sdpa"  # "sdpa" | "flash" | "manual"
    ffn_impl: str = "swiglu"  # "swiglu" | "gelu" | "relu"


class RMSNorm(nn.Module):
    """均方根归一化：x / RMS(x) * gamma"""
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.gamma = nn.Parameter(torch.ones(d))
        self.eps = eps
    def forward(self, x):
        rms = x.pow(2).mean(-1, keepdim=True).add(self.eps).sqrt()
        return x / rms * self.gamma


def precompute_rope_cache(d_head, max_len, base=10000.0, device=None):
    """RoPE: rotary position embedding 缓存"""
    inv_freq = 1.0 / (base ** (torch.arange(0, d_head, 2, device=device).float() / d_head))
    pos = torch.arange(max_len, device=device).float()
    freqs = torch.einsum("i,j->ij", pos, inv_freq)
    return torch.cos(freqs), torch.sin(freqs)


def apply_rope(x, cos, sin):
    """x: (B, h, n, d). 标准 RoPE 旋转。"""
    cos = cos[: x.size(-2)]   # (n, d/2)
    sin = sin[: x.size(-2)]
    x1, x2 = x[..., ::2], x[..., 1::2]
    rot = torch.stack([x1 * cos - x2 * sin, x1 * sin + x2 * cos], dim=-1)
    return rot.flatten(-2)


class Attention(nn.Module):
    """多头注意力，支持 sdpa / flash / manual 三种实现。"""
    def __init__(self, d_model, n_heads, attn_impl="sdpa"):
        super().__init__()
        assert d_model % n_heads == 0
        self.d_model = d_model
        self.n_heads = n_heads
        self.d_head = d_model // n_heads
        self.attn_impl = attn_impl
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.out_proj = nn.Linear(d_model, d_model, bias=False)

    def forward(self, x, cos, sin):
        B, n, _ = x.shape
        qkv = self.qkv(x).reshape(B, n, 3, self.n_heads, self.d_head)
        q, k, v = qkv.unbind(dim=2)  # (B, n, h, d)
        q = q.transpose(1, 2)
        k = k.transpose(1, 2)
        v = v.transpose(1, 2)

        # RoPE
        q = apply_rope(q, cos, sin)
        k = apply_rope(k, cos, sin)

        if self.attn_impl == "sdpa":
            out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        else:
            # manual reference (for ablation/learning)
            attn = (q @ k.transpose(-2, -1)) / math.sqrt(self.d_head)
            mask = torch.triu(torch.full_like(attn, float("-inf")), diagonal=1)
            attn = (attn + mask).softmax(-1)
            out = attn @ v
        out = out.transpose(1, 2).contiguous().view(B, n, self.d_model)
        return self.out_proj(out)


class FFN(nn.Module):
    """FFN，支持 swiglu / gelu / relu 三种激活。"""
    def __init__(self, d_model, d_ff, impl="swiglu"):
        super().__init__()
        self.impl = impl
        if impl == "swiglu":
            self.w_gate = nn.Linear(d_model, d_ff, bias=False)
            self.w_up = nn.Linear(d_model, d_ff, bias=False)
            self.w_down = nn.Linear(d_ff, d_model, bias=False)
        else:
            self.w_in = nn.Linear(d_model, d_ff, bias=False)
            self.w_out = nn.Linear(d_ff, d_model, bias=False)

    def forward(self, x):
        if self.impl == "swiglu":
            return self.w_down(F.silu(self.w_gate(x)) * self.w_up(x))
        elif self.impl == "gelu":
            return self.w_out(F.gelu(self.w_in(x)))
        else:
            return self.w_out(F.relu(self.w_in(x)))


class Block(nn.Module):
    """Pre-Norm Transformer Block. 残差 + 同构设计。"""
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        self.norm1 = RMSNorm(cfg.d_model, cfg.norm_eps)
        self.attn = Attention(cfg.d_model, cfg.n_heads, cfg.attn_impl)
        self.norm2 = RMSNorm(cfg.d_model, cfg.norm_eps)
        self.ffn = FFN(cfg.d_model, cfg.d_ff, cfg.ffn_impl)

    def forward(self, x, cos, sin):
        x = x + self.attn(self.norm1(x), cos, sin)
        x = x + self.ffn(self.norm2(x))
        return x


class TinyLLM(nn.Module):
    """可演进骨架：可换 attn_impl / ffn_impl，方便做 ablation."""
    def __init__(self, cfg: ModelConfig):
        super().__init__()
        self.cfg = cfg
        self.tok_emb = nn.Embedding(cfg.vocab_size, cfg.d_model)
        self.blocks = nn.ModuleList([Block(cfg) for _ in range(cfg.depth)])
        self.norm = RMSNorm(cfg.d_model, cfg.norm_eps)
        if cfg.tie_embeddings:
            self.lm_head = None  # 与 tok_emb 共享
        else:
            self.lm_head = nn.Linear(cfg.d_model, cfg.vocab_size, bias=False)
        # RoPE 缓存（lazy init）
        self._rope_cache = None

    def _get_rope(self, n, device):
        if (self._rope_cache is None or
            self._rope_cache[0].size(0) < n or
            self._rope_cache[0].device != device):
            cos, sin = precompute_rope_cache(
                self.cfg.d_model // self.cfg.n_heads, self.cfg.max_len,
                base=self.cfg.rope_theta, device=device)
            self._rope_cache = (cos, sin)
        return self._rope_cache

    def forward(self, ids):
        B, n = ids.shape
        x = self.tok_emb(ids)
        cos, sin = self._get_rope(n, x.device)
        for blk in self.blocks:
            x = blk(x, cos, sin)
        x = self.norm(x)
        return F.linear(x, self.tok_emb.weight) if self.cfg.tie_embeddings else self.lm_head(x)
```

## 19. 面试高频：深度展开

### 19.1 为什么 Transformer 用 LayerNorm 而不用 BatchNorm？

- **维度不同**：BN 在 batch 维归一化，对序列长度敏感；LN 在 hidden 维，序列长度无关。
- **推理一致性**：BN 需 running mean/var，LN 无此问题。
- **小 batch 友好**：BN 在 batch=1 时方差无意义，LN 不受影响。

### 19.2 为什么 Decoder 用 Causal Mask？

- 自回归：当前位置只能看过去。
- 上三角 mask 实现：attn_scores.masked_fill_(mask, -inf)。
- 训练时并行、推理时串行——训练效率 vs 推理灵活性。

### 19.3 为什么 Multi-Head 而非 Single-Head？

- 多个 head 关注不同子空间（语法/语义/指代等）。
- $h$ 个 head 表达力 ≈ 1 个 hidden 维 $h$ 倍的 MLP。
- 同时算 FLOPs 增加有限（投影线性）。

### 19.4 Self-Attention 的对偶视角

Self-Attention 可视为**两层 MLP**——特殊权重矩阵：

$$\text{Attn}(x) = \sigma(x W_Q W_K^T x^T / \sqrt{d}) \cdot x W_V$$

其中 $W_Q W_K^T$ 是**对称的 token-token 权重**。这一视角启发了 **Synthesizer**、**FAVOR+**（Performer）等线性注意力变体。

### 19.5 Q/K/V 拆分的设计动机

- **解耦查询与键**：让模型学习"谁去查谁"。
- **Multi-head 拆分**：每一头可以学不同子空间。
- **KV 缓存**：推理时 K/V 可复用，节省计算。

### 19.6 ViT 为什么用 [CLS] token

- 借鉴 BERT，将 [CLS] 视为"全局表征 token"。
- 通过 attention pooling，[CLS] 聚合所有 patch 信息。
- 也可用 GAP（global average pooling）替代，性能接近。

```python
    def register(cls, name):

        return deco
    @classmethod

@ArchFactory.register("decoder_only")
class DecoderOnly(nn.Module): ...
```

### 20.2 策略模式：训练循环中各组件

```python
class TrainStrategy:
    def setup(self, model): ...  # 优化器/调度器/AMP
    def step(self, loss): ...    # backward / clip / step
    def on_epoch_end(self, metrics): ...  # 调整 LR / 早停

class AdamWStrategy(TrainStrategy):
    def __init__(self, lr=3e-4, wd=0.1):
        self.lr, self.wd = lr, wd
    def setup(self, model):
        self.opt = torch.optim.AdamW(model.parameters(), lr=self.lr, weight_decay=self.wd)
    def step(self, loss):
        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        self.opt.step()
        self.opt.zero_grad()
```

**好处**：换优化器/换 AMP/换混合精度都是换策略。

### 20.3 模板方法：通用训练流程

```python
class GenericTrainer:
    """骨架：通用训练/评测/checkpoint 流程，差异点在 strategy."""
    def __init__(self, model, strategy, evaluator, ckpt_manager):
        self.model = model
        self.strategy = strategy
        self.evaluator = evaluator
        self.ckpt = ckpt_manager
    def fit(self, train_loader, val_loader, n_epochs):
        self.strategy.setup(self.model)
        for epoch in range(n_epochs):
            self.model.train()
            for batch in train_loader:
                loss = self._step(batch)
                self.strategy.step(loss)
            metrics = self.evaluator(self.model, val_loader)
            self.strategy.on_epoch_end(metrics)
            self.ckpt.maybe_save(epoch, metrics)
```

## 23. 失败案例与改进

### 23.1 案例：把 CNN 用在长文档上

**症状**：模型不收敛，AUC 随机。
**根因**：CNN 局部性归纳偏置与"长程语义依赖"不符。
**改进**：换 Transformer 或加 Self-Attention 层。

### 23.2 案例：残差没加导致深度模型不收敛

**症状**：20 层 MLP 加到 50 层，loss 不降。
**根因**：深度网络退化（degradation）。
**改进**：加残差 + 归一化，再回到 20 层 vs 50 层 ablation。

### 23.3 案例：Token 切分错误

**症状**：中文推荐 ID 出现 [UNK] 大量。
**根因**：词表未覆盖中文。
**改进**：训练 tokenizer 用业务数据；用 BPE + 字符级 fallback。

### 23.4 案例：位置编码硬编码 max_len

**症状**：推理时遇到更长的序列，截断位置预测崩坏。
**根因**：绝对位置编码不可外推。
**改进**：换 RoPE / ALiBi 或预训练时即支持更长 max_len。

### 23.5 案例：多任务权重失衡

**症状**：CTR 涨 5%、CVR 跌 10%。
**根因**：CVR 数据稀疏，主任务压垮。
**改进**：用 GradNorm / Uncertainty Weighting 自动平衡权重。

## 26. 算法伪代码：模型可演进性插入点

```text
**Algorithm 1.2** 模型族的可演进插入点扫描
**Input**: 现有模型 + 候选算子（新 Attention/FFN/Norm/PE）+ 评测集
**Output**: 候选替换带来的指标提升

1. 加载 base model 与 ckpt
2. 提取可替换层候选集合 R:
       R = {"attn", "ffn", "norm", "pos_enc", "embedding"}
3. FOR each candidate c in R:
4.     实例化两个版本: base_v, alt_v(c)
5.     finetune 5 个 epoch（部分数据）
6.     评测指标 delta_v = metric(alt_v) - metric(base_v)
7.     IF delta_v > threshold:
8.         标记为"可能有益"，进 A/B
9. RETURN ranked candidates
```

**复杂度**：$O(|R| \cdot C_{\text{ft}})$，$|R|$ 通常 5-10。

## 27. 完整代码：架构选型 A/B Harness

```python
"""
架构 A/B Harness: 在保持超参一致的前提下，对比多个候选架构。
用于"换 backbone"、"换 norm"、"换位置编码" 等消融。
"""
from dataclasses import asdict
from contextlib import contextmanager
import torch
import torch.nn as nn


@contextmanager
def arch_swap(model: nn.Module, layer_name: str, new_layer: nn.Module):
    """临时替换某层，跑评测，再恢复原层。"""
    parts = layer_name.split(".")
    parent = model
    for p in parts[:-1]:
        parent = getattr(parent, p)
    name = parts[-1]
    old_layer = getattr(parent, name)
    setattr(parent, name, new_layer)
    try:
        yield
    finally:
        setattr(parent, name, old_layer)


def arch_search(base_model, layer_options, eval_fn, threshold=0.005):
    """
    返回: [(layer, option, score_delta)] 排序
    eval_fn: 输入 model, 输出标量指标
    """
    base_score = eval_fn(base_model)
    results = []
    for layer_name, options in layer_options.items():
        for option in options:
            with arch_swap(base_model, layer_name, option):
                new_score = eval_fn(base_model)
            delta = new_score - base_score
            results.append((layer_name, option.__class__.__name__, delta))
    results.sort(key=lambda r: r[2], reverse=True)
    return [r for r in results if r[2] > threshold]
```

## 29. 推论训练算力的工程实战

### 29.1 数据需求估算

$$\text{Token 总量} = \sum_{\text{训练步}} B \times n_{\text{ctx}}$$

例：训练 1 epoch，B=4M tokens，10B 文档 → 1 epoch 约 4T tokens。

### 29.2 算力估算

$$\text{GPU·h} = \frac{6ND}{\text{利用率} \times \text{单卡算力}}$$

例：LLaMA-7B、4T tokens、A100 80GB、利用率 40%：

$$\text{GPU·h} = \frac{6 \times 7 \times 10^9 \times 4 \times 10^{12}}{0.4 \times 312 \times 10^{12}} \approx 134 \times 10^3 \,\text{GPU·h}$$

### 29.3 训练时长

$$\text{训练时长} = \frac{\text{GPU·h}}{N_{\text{GPU}} \cdot \text{扩展效率}}$$

8 节点 × 8 GPU = 64 卡，扩展效率 0.7：

$$\text{训练时长} = \frac{134000}{64 \times 0.7} \approx 3000 \,\text{小时}$$

约 4 个月单次训练——超大规模模型需要并行策略（TPU pod、H100 cluster 等）。

## 30. 决策案例：从需求到代码

### 30.1 需求 → 设计

**需求**：对话问答系统，支持中文，回答 100 字内、200 ms 内。

**约束推导**：

- 200 ms 内 → 中等模型（1-3B）+ 量化
- 中文 → 多语言 tokenizer，BPE
- 对话 → 系统 prompt + 历史

**架构选择**：

- LLaMA-3-8B 或 Qwen2-1.5B
- INT8 量化 → 显存 8GB → 可塞消费级 GPU
- LoRA 微调 → 适配业务风格

**代码骨架**：

```python
from transformers import AutoModelForCausalLM, AutoTokenizer
import torch

model_name = "Qwen/Qwen2-1.5B-Instruct"
tok = AutoTokenizer.from_pretrained(model_name)
model = AutoModelForCausalLM.from_pretrained(
    model_name, torch_dtype=torch.bfloat16, device_map="cuda")

# 量化（如果需要更小）
# model = AutoModelForCausalLM.from_pretrained(
#     model_name, load_in_4bit=True, device_map="cuda")

# 推理
def chat(messages):
    text = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
    inputs = tok(text, return_tensors="pt").to("cuda")
    out = model.generate(**inputs, max_new_tokens=200, do_sample=True,
```

## 31. 进阶话题：稀疏 MoE 与状态空间模型

### 31.1 Mixture of Experts (MoE)

**动机**：在不增加推理成本（激活参数）的前提下，扩大总参数量。

```text
输入 → Router (gate) → Top-k 专家 (k=2)
   └───────────────────────────────→ 输出

总参数 N_total = N_experts * n_experts
激活参数 N_active = N_experts * k
```

**优势**：

- 推理算力按激活参数计算 → 可训练超大模型
- 通过 gating 实现**专家专精**

**挑战**：

- 训练不稳定（router collapse / imbalance）
- 显存压力（总参数都要装）
- 通信开销（专家在不同设备）

**代码骨架**：

```python
class MoE(nn.Module):
    def __init__(self, d, n_experts, k=2):
        super().__init__()
        self.experts = nn.ModuleList([nn.Linear(d, d) for _ in range(n_experts)])
        self.gate = nn.Linear(d, n_experts)
        self.k = k
    def forward(self, x):
        # x: (B, n, d)
        scores = self.gate(x)                       # (B, n, E)
        topk = scores.topk(self.k, dim=-1)          # (B, n, k)
        weights = topk.values.softmax(-1)            # (B, n, k)
        idx = topk.indices                            # (B, n, k)
        out = torch.zeros_like(x)
        for i in range(self.k):
            token_idx = idx[..., i]                  # (B, n)
            w = weights[..., i].unsqueeze(-1)         # (B, n, 1)
            expert_out = torch.stack(
                [self.experts[e](x[b, t]) for b, t, e in enumerate(...)], dim=0)
            # 实际用 einsum 优化
            out = out + w * expert_out
        return out
```

**简化版**（教学用，生产用 `transformers` 库的 `MixtralSparseMoeBlock`）。

### 31.2 状态空间模型 (Mamba)

**动机**：Self-Attention $O(n^2)$ 在长序列爆炸，SSM 选择性状态机制可降到 $O(n)$。

```text
h_t = A h_{t-1} + B x_t
y_t = C h_t
```

加入选择性扫描（input-dependent $B/C/\Delta$）后，SSM 在长序列上能与 Transformer 持平或更好。

**架构**：

```text
输入 → 投影 d → Mamba Block（Conv1d + SSM + 残差）
   → LayerNorm → FFN (GLU) → 输出
```

**适用场景**：

- 超长序列（> 10K）
- 流式 / 实时（无 KV Cache 成本）
- 与 Attention 混合（Jamba）：长序列部分 SSM，短依赖 Attention。

## 34. 工程"反常识"教训 8 则

1. **类别不均衡的精排**：CTR 0.1% 正样本，单纯 BCE 收敛慢；用 Focal Loss 或正负样本 1:10 采样。
2. **位置编码硬编码**：模型能外推到 8x 训练长度，推理时设更长 max_len 反而崩——用 RoPE + NTK-aware scaling。
3. **多卡 all-reduce 不重叠**：DDP 默认 `bucket_cap_mb=25`，小模型反而慢，调大到 100+。
4. **混合精度下 log_softmax 数值不稳**：用 log_softmax(logits, dim=-1) + 上采样 log 概率。
5. **Adam 与 weight_decay 解耦**：weight_decay 应该只作用于 weight，不作用于 bias/LayerNorm；PyTorch 主流实现正确，分组检查。
6. **Dropout 在测试时不消失**：调用 `model.eval()`，别用 `with torch.no_grad()` 替代。
7. **bf16 优于 fp16**：bf16 数值范围大，无需 loss scaling；但 fp16 兼容老硬件。
8. **RNN 梯度爆炸**：clip_grad_norm_=1.0 必加；LSTM 比 GRU 难收敛。

## 35. 算法伪代码：模型族注册与选择

```text
**Algorithm 1.3** 模型族注册器 + 自动选型
**Input**: 模型族集合 F, 任务 T, 数据 D, 预算 B
**Output**: 选中的模型 M

1. 初始化 Registry R = {} with built-in (mlp, cnn, transformer, ...)
2. FOR f in F:
3.     instantiate f with default config
4.     finetune 5 epochs on D
5.     eval on val set → (metric, latency, mem)
6. SORT F by metric normalized by latency (Pareto front)
7. RETURN best f on Pareto front within B
```

**复杂度**：$O(|F| \cdot C_{\text{ft}})$，$|F|$ 通常 5-15 个候选。

```python
# 用法
class ModelRegistry:
    def __init__(self):
        self._models = {}
    def register(self, name):
        def deco(klass): self._models[name] = klass; return klass
        return deco
    def build(self, name, cfg): return self._models[name](cfg)

REGISTRY = ModelRegistry()

@REGISTRY.register("transformer")
class TransformerModel(nn.Module):
    def __init__(self, cfg): ...

@REGISTRY.register("mamba")
class MambaModel(nn.Module):
    def __init__(self, cfg): ...

# 自动尝试多个候选
def auto_select(registry, cfg_candidates, eval_fn, budget):
    results = []
    for name, cfg in cfg_candidates.items():
        m = registry.build(name, cfg)
        metric, latency = eval_fn(m)
        results.append((name, metric, latency))
    # 找 Pareto 最优
    results.sort(key=lambda r: r[1] / r[2], reverse=True)
    return results[0]
```

```python
# Softmax 数值稳定
def log_softmax(x, dim=-1):
    m = x.max(dim=dim, keepdim=True).values
    return x - m - (x - m).exp().sum(dim=dim, keepdim=True).log()

# LayerNorm 用 sqrt(mean(x^2) + eps)
```

## 39. 拓展：拓扑与数据流视角

### 39.1 残差 / 跳跃连接

形式：$y = F(x, W) + x$

解决深度网络退化 + 梯度消失。ResNet vs Plain Network 比较：56 层 Plain 比 20 层误差高（退化），56 层 ResNet 比 20 层误差低（良态）。

### 39.2 稠密连接 (DenseNet)

每一层与后续所有层直连：$x_l = H_l([x_0, x_1, ..., x_{l-1}])$

参数少、特征复用，但显存大。

### 39.3 Highway Network

带变换门的跳跃：$y = T(x) \cdot H(x) + (1 - T(x)) \cdot x$

$T$ 是 sigmoid 门，门控连接强度。

## 42. 附录：常用数学公式速查

### 42.1 Attention 完整推导

**Step 1**: 输入 $X \in \mathbb{R}^{n \times d}$，经 $W_Q, W_K, W_V \in \mathbb{R}^{d \times d}$ 投影：

$$Q = X W_Q, \quad K = X W_K, \quad V = X W_V$$

**Step 2**: 多头切分，$h$ 个头每头 $d_k = d/h$：

$$Q_i \in \mathbb{R}^{n \times d_k}, \quad K_i \in \mathbb{R}^{n \times d_k}, \quad V_i \in \mathbb{R}^{n \times d_k}$$

**Step 3**: 单头注意力：

$$\text{Attn}_i(Q_i, K_i, V_i) = \text{softmax}\left(\frac{Q_i K_i^\top}{\sqrt{d_k}}\right) V_i$$

**Step 4**: 多头合并 + 输出投影：

$$\text{MultiHead}(X) = \text{Concat}(\text{Attn}_1, \ldots, \text{Attn}_h) W_O$$

### 42.2 RoPE 完整公式

对于偶数维 $d$：

$$\text{RoPE}(x_m, m) = \begin{pmatrix} \cos m\theta_0 & -\sin m\theta_0 & 0 & 0 \\ \sin m\theta_0 & \cos m\theta_0 & 0 & 0 \\ 0 & 0 & \cos m\theta_1 & -\sin m\theta_1 \\ 0 & 0 & \sin m\theta_1 & \cos m\theta_1 \end{pmatrix} \begin{pmatrix} x_{m,0} \\ x_{m,1} \\ x_{m,2} \\ x_{m,3} \end{pmatrix}$$

其中 $\theta_i = 10000^{-2i/d}$。

### 42.3 LayerNorm vs RMSNorm

$$\text{LayerNorm}(x) = \gamma \cdot \frac{x - \mu}{\sigma + \epsilon} + \beta$$
$$\text{RMSNorm}(x) = \gamma \cdot \frac{x}{\sqrt{\frac{1}{d}\sum_i x_i^2 + \epsilon}}$$

RMSNorm 比 LayerNorm 少了均值中心化 + 偏置项，但效果接近、速度更快。

### 42.4 GQA（Grouped Query Attention）

$n_q = h, n_{kv} = g$，$g$ 通常 4-8：

- 标准 MHA：$g = 1, h = n$
- GQA：$1 < g < h$
- MQA：$g = 1, h = n$ 极端情况

KV Cache 显存节省：$\text{MHA}:h \rightarrow \text{GQA}:g$，比例 $g/h$。

### 42.5 SwiGLU

$$\text{SwiGLU}(x) = \text{SiLU}(x W_g) \odot (x W_u) \cdot W_d$$

3 个权重矩阵（gate + up + down），比标准 FFN 多一倍参数，但效果更好。

### 42.6 损失函数对照

| 任务 | 损失 | 公式 |
| :--- | :--- | :--- |
| 二分类 | BCE | $-y\log p - (1-y)\log(1-p)$ |
| 多分类 | CE | $-\sum y_c \log p_c$ |
| 回归 | MSE | $(y - \hat{y})^2$ |
| 回归 | Huber | $\max((y-\hat{y})^2, \|y-\hat{y}\|) - 0.5$ |
| 排序 | Margin | $\max(0, m + s_- - s_+)$ |
| 检索 | InfoNCE | $-\log \frac{e^{s_+}}{\sum e^{s_i}}$ |
| 检测 | Focal | $-\alpha (1-p)^\gamma \log p$ |

### 43.4 模型族注册器（最终版）

```python
import torch.nn as nn

class ArchRegistry:
    """架构族注册器：所有可演进点统一管理"""
    def __init__(self):
        self._items = {}
        self._configs = {}

    def register(self, name, default_cfg=None):
        def deco(klass):
            self._items[name] = klass
            self._configs[name] = default_cfg or {}
            return klass
        return deco

    def build(self, name, cfg=None):
        klass = self._items[name]
        merged = {**self._configs[name], **(cfg or {})}
        return klass(**merged)

    def list(self):
        return list(self._items.keys())

REG = ArchRegistry()

@REG.register("transformer", {"d_model": 512, "depth": 6})
class TransformerBackbone(nn.Module):
    def __init__(self, d_model, depth):
        super().__init__()
        self.layers = nn.ModuleList(
            [nn.TransformerEncoderLayer(d_model, 8) for _ in range(depth)]
        )
    def forward(self, x):
        for l in self.layers:
            x = l(x)
        return x

@REG.register("mamba", {"d_model": 512})
class MambaBackbone(nn.Module):
    def __init__(self, d_model):
        super().__init__()
        # 占位实现，生产用 mamba-ssm 包
        self.proj = nn.Linear(d_model, d_model)
    def forward(self, x):
        return self.proj(x)

# 用法
model = REG.build("transformer", {"depth": 12})
print(REG.list())
```

### 43.5 简单 ablation runner

```python
def ablation_study(model_cls, configs, eval_fn, n_runs=3):
    """
    对每个配置跑 n_runs 次取平均
    eval_fn(model) -> 标量（越大越好）
    """
    results = {}
    for cfg_name, cfg in configs.items():
        scores = []
        for run in range(n_runs):
            torch.manual_seed(run)
            model = model_cls(**cfg)
            scores.append(eval_fn(model))
        mean = sum(scores) / len(scores)
        std = (sum((s - mean) ** 2 for s in scores) / len(scores)) ** 0.5
        results[cfg_name] = (mean, std)
        print(f"{cfg_name:40s} {mean:.4f} ± {std:.4f}")
    return results
```

## 45. 附录：常见面试追问

**Q：怎么决定用 4 还是 8 heads？**
A：从 $d_{model}$ 出发，每头 $d_k \in \{64, 128\}$。$h = d_{model}/d_k$。$d_k = 128$ 通常表现更好，$d_k = 64$ 在多 heads 时更灵活。

**Q：为什么 LayerNorm 比 BatchNorm 更适合 Transformer？**
A：序列变长时 BN 的归一化范围变化大，LN 单样本独立归一化更稳定。

**Q：Attention 公式里的 $\sqrt{d_k}$ 为什么？**
A：$QK^T$ 的方差随 $d_k$ 增长，softmax 在大值时梯度消失。除以 $\sqrt{d_k}$ 让方差归一化。

**Q：Self-Attention 与卷积的关系？**
A：单头 Self-Attention 退化为全连接；多头 + ReLU 模式 = 通用函数逼近器。局部窗口 Self-Attention ≈ 局部卷积。

**Q：为什么 RoPE 可以外推？**
A：旋转矩阵作用于复平面，相同角度下不同位置等价于不同 transformer。$m\theta$ 只依赖于 $m$ 与 $d_k$ 的乘积，序列加长仍可用。

**Q：多大的模型适合 FP16？**
A：通常所有模型，BF16 更稳。FP16 需 loss scaling，BF16 在 H100/A100 上原生支持。

**Q：训练多久收敛？**
A：经验：参数量越大、训练数据越多，epoch 数越少。LLM：1T tokens 一次过；中型模型（100M）：50-200 epochs。

**Q：dropout 加哪里？**
A：残差相加之后、激活函数之后；FFN 两层间、Self-Attn 输出前。

**Q：如何处理类别极度不平衡？**
A：类别权重、Focal Loss、过采样、欠采样、SMOTE、加权采样器。

**Q：训练时 NaN 怎么办？**
A：logits 削幅（clip）、nan_to_num、梯度裁剪、换 BF16、降低 LR、检查数据。

## 51. 32 道面试高频真题（带详解）

### Q1：为什么 CNN 比全连接更适合图像？
1. **局部性**：图像相邻像素强相关。
2. **平移不变性**：目标可在任意位置。
3. **权值共享**：参数少，易学。
4. **层次化**：边缘→纹理→部件→对象。

### Q2：Transformer 为什么能并行而 RNN 不能？
- RNN 第 $t$ 步依赖 $t-1$ 隐藏状态，必须串行。
- Self-Attention 所有位置同时算 QKV，可并行。

### Q3：Multi-Head 注意力比 Single-Head 强在哪？
- 多个子空间关注不同模式（语法/语义/指代）。
- 增加参数量有限（投影层共享）。
- 表达力近似 $h$ 倍单头。

### Q4：LayerNorm 与 BatchNorm 的差异？
- **LN**：单样本内归一化，序列变化不敏感。
- **BN**：batch 内归一化，batch=1 时方差无意义。

### Q5：为什么有 residual 才好训深度网络？
- 反向时梯度有跳过路径，避免消失。
- 允许"什么都不做"，退化起码不劣于浅网络。

### Q6：Self-Attention 计算复杂度？
$O(n^2 d + n d^2)$，$n^2$ 项主导，长序列爆炸。

### Q7：KV Cache 为什么能省算力？
- 自回归第 $t$ 步只需算当前 token 的 Q。
- K/V 可缓存（历史 token 不变），不重算。

### Q8：RoPE 比 Sinusoidal 强在哪？
- 相对位置 + 长度外推。
- 矩阵形式优雅，支持 sinusoidal attention bias 形式。

### Q9：bf16 vs fp16？
- **bf16**：8 位指数，范围 ~$10^{38}$，无 loss scaling 必要。
- **fp16**：5 位指数，范围 ~$10^4$，需 loss scaling 防 overflow。

### Q10：为什么 Adam 比 SGD 在 Transformer 上更好？
- 自适应学习率，不同参数不同 lr。
- 一阶动量 + 二阶动量，训练更快。

### Q11：Warmup 为什么必要？
- 初始权重随机，Adam 的二阶动量估计有偏。
- Warmup 让 lr 渐增到稳定值。

### Q12：dropout 在推理时怎么处理？
- 必须关：`model.eval()`，缩放因子 $1/(1-p)$ 在训练时已 apply。

### Q13：为什么 LayerNorm 不依赖 batch？
- 单样本统计量 $\mu, \sigma$，无 batch 信息。
- 适合 batch=1 / variable length 场景。

### Q14：Position Encoding 不可学习怎么办？
- 用 RoPE / ALiBi / Sinusoidal。
- 训练长度 + 推理长度不匹配时显式插值。

### Q15：MoE 推理时如何省显存？
- 激活参数 = top-k 专家。
- 总参数全加载。
- 通过 expert parallelism 分摊显存。

### Q16：模型参数量怎么估算？
- Dense Transformer：$N \approx 12 L d^2$。
- MoE：$N_{\text{total}} = n_{\text{experts}} \cdot 12 L d^2$。

### Q17：训练时间怎么估算？
6ND / (GPU·h TFLOPS 利用率)。

### Q18：推理显存怎么算？
$2N + 2 L n d_{kv} h_{\text{kv}} B \cdot \text{dtype}$。

### Q19：GQA 是什么？
- 多 Query 共享 1 KV。
- 显存减 n_query/n_kv_factor。

### Q20：Flash Attention 做了什么？
- Tiling + 重计算：减少 HBM 读写。
- 不减少 FLOPs，但减慢 wall-clock。

### Q21：1.5B 模型推理用多少显存？
- FP16 ≈ 3 GB。
- INT8 ≈ 1.5 GB。
- INT4 ≈ 0.75 GB。

### Q22：为什么 LLM 用 ALiBi/RoPE 而非可学习位置？
- 可学习位置 hardcode 长度。
- RoPE/ALiBi 支持外推。

### Q23：Encoder vs Decoder vs Encoder-Decoder？
- Encoder：双向，适合理解。
- Decoder：单向，适合生成。
- Encoder-Decoder：seq2seq（翻译、摘要）。

### Q24：Mixture of Experts 的 gating 怎么做？
- Linear → softmax → top-k → 加权求和。
- 训练时加负载均衡 loss。

### Q25：Gradient Accumulation 是什么？
- 多 mini-batch 累加梯度再更新，等价于大 batch。

### Q26：ZeRO-1/2/3 的区别？
- ZeRO-1：分片 optimizer state。
- ZeRO-2：+ 分片 gradient。
- ZeRO-3：+ 分片 parameter。

### Q27：Activation Checkpointing 是什么？
- 不存中间激活，反向重算。
- 显存 $O(\sqrt{L})$，算力 $O(L)$ +33%。

### Q28：FFN 中的 GLU 是什么？
- Gated Linear Unit：$\text{GLU}(x) = \sigma(W_g x) \cdot W_u x$。
- SwiGLU、GeGLU 是变体。

### Q29：缩放 Law 的核心公式？
- $L(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta}$
- 给定算力最优分配 $N^* \propto D^* \propto C^{0.5}$（Chinchilla）。

### Q30：模型蒸馏是怎么回事？
- 大模型（teacher）输出作为小模型（student）的软目标。
- 学生通过模仿 teacher logits 或中间特征学习。

### Q31：INT8 量化为什么会精度损失？
- 每参数 256 个值 → 8 位精确表达。
- outlier 参数主导 range，常见做法 per-channel scaling。

### Q32：LoRA 与全参数微调的差异？
- LoRA 冻结原参数，增 $\Delta W = AB$（低秩分解）。
- 训练参数少（< 1%），显存小，多任务可换 adapter。

## 68. 7 步法的工业实战: LLaMA-3 / Qwen / DeepSeek 架构案例

把第 1 节的"7 步法"落到工业级 LLM, 对比 LLaMA-3-8B、Qwen2.5-7B、DeepSeek-V3 的设计选择。

### 68.1 任务与数据刻画

| 模型 | 任务 | 训练 token | 词表 |
| :--- | :--- | :--- | :--- |
| LLaMA-3-8B | 通用对话/生成 | 15T | 128K (BPE) |
| Qwen2.5-7B | 通用对话/代码 | 18T | 152K (BBPE) |
| DeepSeek-V3 | 通用对话/推理 | 14.8T | 129K (BBPE) |

> **第一步：明确任务** = 多语言 + 长上下文 + 推理。**第二步：刻画数据** = 15T token 级别、100+ 语言 → 词表需要 ≥ 100K。

### 68.2 归纳偏置选择

三者都选 **Decoder-only Transformer** 作为 backbone:

- 因果注意力: 任务要求生成 → 自回归约束 → 选因果 mask。
- 弱结构假设: 多语言 + 通用任务 → 不强加结构。
- 共享 embedding: 参数量上限 → 减少 $V \cdot d$ 项。

```text
LLM 通用 = 因果 Attention + Decoder-only + 共享 embedding + RoPE
```

### 68.3 容量定标: Chinchilla 法则

按 Chinchilla 最优 $D \approx 20N$ token, 15T tokens 训 7B 模型:

$$D^* = 20 \times 7\text{B} = 140\text{B tokens}$$

但三者都用 15T, **数据量远超 Chinchilla 最优**, 原因:

1. 推理/代码类任务对数据量不饱和, 多训仍有收益。
2. 工程预算充足 → 多训 100× 廉价, 减少再训练成本。

### 68.4 骨架设计对比

```text
LLaMA-3-8B:      d=4096, L=32,  d_ff=14336, n_heads=32, n_kv_heads=8  (GQA)
Qwen2.5-7B:      d=3584, L=28,  d_ff=18944, n_heads=28, n_kv_heads=4  (GQA)
DeepSeek-V3-7B:  d=4096, L=32,  d_ff=12288, n_heads=32, MoE 8/2 路由
```

**关键差异**:
- LLaMA-3: 经典 GQA(8 KV heads), SwiGLU, RoPE 500K。
- Qwen2.5: d_ff 更大(5.3×d vs 3.5×d), 词表更大, 推理 + 数学任务导向。
- DeepSeek-V3: **MoE 架构**, 7B 激活但 67B 总参数, 廉价推理。

### 68.5 复杂度与显存校验

| 模型 | 激活参数 | FP16 权重 | 训练显存 (ZeRO-3, 8卡) |
| :--- | :--- | :--- | :--- |
| LLaMA-3-8B | 8B | 16 GB | ~32 GB/卡 |
| Qwen2.5-7B | 7B | 15 GB | ~30 GB/卡 |
| DeepSeek-V3-67B(总) | 7B | 134 GB | ~50 GB/卡 (TP=8) |

DeepSeek 之所以"67B 总参但 7B 激活", 靠 MoE + Expert Parallelism。

### 68.6 演进性: 同一套骨架派生多个尺寸

LLaMA 系列是教科书例子:

```text
LLaMA-7B → 13B → 33B → 65B (同结构, 缩 d 和 L)
LLaMA-2 → LLaMA-3 (GQA, 长上下文, 更大词表)
LLaMA-3 → LLaMA-3.1 → LLaMA-3.2 (MoE 变体)
```

**复用同一份训练代码 + config**, 只改 `d_model, n_layers` → "scale up" 几乎是免费的工作。

### 68.7 取舍分析: 为什么不用 MoE

LLaMA-3 不用 MoE 原因:
1. **推理部署**: MoE 路由导致 batch 内不规则访存, 推理引擎难优化。
2. **训练稳定**: MoE 的负载均衡 loss 与 gating 梯度需小心调。
3. **硬件适配**: dense 模型在 Tensor Core / 分布式框架中成熟。

Qwen / DeepSeek 反向选 MoE 原因:
- DeepSeek-V3 算力充足 + 推理极廉价, MoE 优势明显。
- Qwen2.5-Max 也是 MoE 变体。

> **设计本质**: "哪个组件 (MoE vs dense) 适合, 取决于**目标场景**——是优先推理速度 (dense) 还是参数规模 (MoE)"。

## 69. 归纳偏置深入: CNN / Transformer / SSM 的对比

### 69.1 三种偏置的数学表达

每种算子对应不同的"先验正则项" $\Omega(\theta)$:

$$
\text{CNN}: \quad \Omega(\theta) = \lambda \sum_{i,j,k} |\theta_{i,j,k}|^2 + \text{translation invariance penalty}
$$

$$
\text{RNN}: \quad \Omega(\theta) = \text{causal mask: } h_t \text{ 不依赖 } h_{t+1...T}
$$

$$
\text{Transformer}: \quad \Omega(\theta) = \text{位置编码先验 (RoPE/ALiBi)}
$$

### 69.2 CNN: 局部性 + 平移不变

**数学**: 卷积是"局部线性组合 + 权值共享"。

```python
y[i,j] = sum_{u,v} W[u,v] * x[i+u, j+v]  # 2D 卷积
```

**归纳偏置**:
- **局部性**: $W$ 的感受野有限, 远距离像素无直接交互。
- **平移不变**: $W$ 共享, 模式识别与位置无关。

**优势**:
- 参数量与分辨率**无关**: $W \in \mathbb{R}^{k \times k \times C_{in} \times C_{out}}$, 任何输入大小都用同一组参数。
- 强先验 → **小数据也能训**。

**劣势**:
- 远距离依赖需多层堆叠, 每层只能看 $k$ 像素。
- 对大尺度模式不友好。

### 69.3 Transformer: 全局 + 弱结构

**数学**: 自注意力是"任意位置的全连接加权"。

$$
\text{Attn}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V
$$

**归纳偏置**:
- **位置无关的内容交互**: $QK^T$ 不限制距离。
- 位置编码 (RoPE/ALiBi) 是**唯一**的位置先验。

**优势**:
- 任意位置对距离 $O(1)$ 交互。
- 通用任务表现 SOTA。

**劣势**:
- $O(n^2)$ 复杂度 → 长序列瓶颈。
- 数据需求大 (无强先验)。
- **归纳偏置弱 → 易学坏模式** (需大量清洗)。

### 69.4 SSM (Mamba/S4): 长程 + 状态压缩

**数学**: 状态空间模型把序列压缩到固定大小 hidden state。

$$
h_t = A h_{t-1} + B x_t, \quad y_t = C h_t
$$

**归纳偏置**:
- **线性时不变 (LTI)**: 状态转移矩阵 $A$ 不随时间变。
- **马尔可夫性**: 当前状态包含历史全部信息。

**优势**:
- $O(1)$ 每步推理 (vs $O(n)$ self-attention decode)。
- 训练 $O(n)$ 线性 (vs $O(n^2)$ attention)。
- 适合**超长序列** (百万 token)。

**劣势**:
- 状态压缩 → 信息瓶颈, 需 selective scan 弥补 (Mamba)。
- 内容检索能力弱于 attention。
- 工程生态不如 Transformer 成熟。

### 69.5 对比表

| 维度 | CNN | Transformer | SSM (Mamba) |
| :--- | :--- | :--- | :--- |
| 偏置强度 | 强 | 弱 | 中 |
| 数据需求 | 小 | 大 | 中 |
| 远距离交互 | $O(L/k)$ 层 | $O(1)$ | $O(1)$ via state |
| 推理复杂度 | $O(k^2 \cdot C \cdot HW)$ | $O(n^2 d)$ | $O(d^2)$ |
| 长序列 | 弱 | 弱 | **强** |
| 适用 | 视觉小数据 | NLP / 多模态 | 长上下文 |

### 69.6 混合架构: Conv + Attention + SSM

现代 LLM 越来越混合:

- **Jamba** (AI21): Transformer + Mamba 7:1 比例, 256K 上下文。
- **RWKV**: RNN 训练 + Transformer 推理等价, 无限上下文。
- **Hyena**: 长卷积替代 attention。

**设计哲学**: 注意力用于"内容检索", SSM/卷积用于"位置模式"。两者互补。

### 69.7 如何选?

**经验决策树**:

```text
任务有清晰网格结构 (图像/视频)? → CNN (ResNet/ViT)
任务是对话/通用语言? → Transformer
任务是长上下文 (32K+)? → 混合 (SSM + Attention)
任务是小数据 + 强先验? → CNN/RNN
数据规模极大 + 任务通用? → Transformer (大模型路线)
```

> **核心**: 偏置越强, 数据需求越少; 偏置越弱, 通用性越强。**根据数据规模选边站**。

## 70. 容量与数据规模匹配: Scaling Laws 工程化

### 70.1 Chinchilla 法则回顾

Kaplan et al. (2020) + Hoffmann et al. (2022) 给出**最优算力分配**:

$$
L(N, D) = E + \frac{A}{N^\alpha} + \frac{B}{D^\beta}, \quad \alpha \approx \beta \approx 0.07-0.08
$$

给定算力预算 $C = 6ND$, 最优:

$$
N^*(C) \propto C^{0.5}, \quad D^*(C) \propto C^{0.5}
$$

即 $D \approx 20N$ tokens/参数。

### 70.2 LLaMA 系列: 偏离 Chinchilla

| 模型 | 参数 | 训练 tokens | Chinchilla 比例 (D/N) |
| :--- | :--- | :--- | :--- |
| LLaMA-7B | 7B | 1T | 143 |
| LLaMA-13B | 13B | 1T | 77 |
| LLaMA-33B | 33B | 1.5T | 45 |
| LLaMA-65B | 65B | 1.5T | 23 |
| LLaMA-3-8B | 8B | 15T | 1875 |

**LLaMA-3 严重"过训"**: 8B 用了 15T tokens, 是 Chinchilla 最优的 100×。

### 70.3 为什么过训?

1. **推理 token 廉价**: 训练算力一次性, 推理每天发生 → 多训 100× 摊薄到推理上千次。
2. **Instruct 任务不饱和**: 推理 / 代码 / 数学对数据量敏感。
3. **数据可得性**: 互联网文本廉价, 算力是真正瓶颈。
4. **实验证据**: 8B 训 15T 在下游任务上仍持续提升。

### 70.4 小模型 + 多数据 vs 大模型 + 少数据

**实验** (LLaMA-2 论文):
- 7B + 2T tokens ≈ 13B + 1T tokens (在 MMLU 上)
- 13B + 2T > 70B + 0.5T (算力相同时)

**结论**: **数据 + 模型 同等重要**。但 70B 算力成本高 5-10×, 通常优选小模型 + 多数据。

### 70.5 实际设计流程

**场景**: 你的产品要训 1B 参数模型, 数据有 100B tokens。

```python
# Chinchilla 建议
N_optimal = (D / 20) ** 0.5 * constant
# 100B / 20 = 5B → 但 scaling law 实验显示 1-3B 已足够

# 决策:
#   1B 训 100B tokens → 比 Chinchilla 建议"过训" 20×, 推理质量更好
#   3B 训 100B tokens → 接近 Chinchilla 最优
#   7B 训 100B tokens → 数据不足, 训不满
```

**工程经验**:
- LLM 预训练: $D/N \in [50, 300]$ 都合理。
- 下游微调: 数据量小 → 反而大模型 + LoRA 更划算。
- **永远 profile 训练 loss 曲线**: 还在降 → 继续训。

### 70.6 Scaling Law 失败的情况

Scaling law 在以下场景失效:

1. **数据质量差**: 1T 噪声 token < 100B 优质 token。
2. **任务特异性**: 数学/代码等小众任务, scaling law 预测不准。
3. **超长上下文**: 32K+ 注意力, $O(n^2)$ 主导, 标度行为不同。
4. **多模态**: 图文对齐, scale 行为尚未收敛。

### 70.7 反向应用: 给定数据量选模型

工程问题: "我们有 500B tokens, 模型该多大?"

```python
# 方法 1: Chinchilla 公式
N_optimal = D / 20  # = 25B, 但不是硬性

# 方法 2: 经验 (LLaMA-3 论文)
# 8B 用 15T, 70B 用 15T, 405B 用 15T
# 实际: 70B 用 15T 比 Chinchilla 30B 多训 50×, 仍有效

# 方法 3: 任务为先
# 对话/聊天/推理: 模型别太大 (7-13B), 数据要多
# 知识/事实: 模型要大 (70B+), 知识存在参数里
```

**黄金法则**: "不确定时, 先小模型训 10× 数据看 loss 曲线, 再决定 scale up"。

## 72. 高级面试题 10 道

### Q1: LLaMA-3-8B 比 LLaMA-2-7B 强在哪? 架构差异?

- **GQA**: KV heads 从 32 → 8, 推理 KV 显存减 4×。
- **词表**: 32K → 128K, 多语言能力大幅提升。
- **RoPE theta**: 1万 → 50万, 支持 128K 上下文。
- **训练数据**: 2T → 15T, 8× 数据。
- **架构微调**: d_ff 增大, SwiGLU 比例调整。

### Q2: 为什么 MoE 模型在推理时"7B 激活但 67B 总参数"?

- 总参数: 所有专家 + 路由 + embedding → 67B, 占显存。
- 激活参数: 每个 token 只走 top-2 专家 → 实际算力 7B。
- 推理时: 加载 67B 权重, 计算只走 2 个专家。
- **优势**: 大模型容量, 小模型算力。
- **劣势**: 访存不规则, 推理引擎优化难。

### Q3: 7B 模型在 8xA100 上用 ZeRO-3 训练, 单卡显存多少?

- 7B FP16 = 14 GB
- Adam (FP32 master + m, v) = 7B × 12B = 84 GB
- 总共 (无 ZeRO): 98 GB, 装不下 A100 80GB
- ZeRO-3 分 8 卡: 14/8 + 84/8 ≈ 1.75 + 10.5 = 12.25 GB/卡 ✓
- 加激活 + 框架开销: ~20-25 GB/卡

### Q4: 序列长度从 2K 升到 8K, 哪些算子 FLOPs 变 4×, 哪些变 16×?

- 注意力 QK^T: $O(n^2 d)$, 4×→16× (4²)
- 注意力 softmax·V: 同上 16×
- FFN: $O(n d^2)$, 4×→4× (线性)
- 注意力投影: $O(n d^2)$, 4×→4×

→ 注意力 $O(n^2)$ 主导, 长序列必须用 Flash Attention。

### Q5: 为什么 SwiGLU 比 GELU FFN 表现好?

$$
\text{SwiGLU}(x) = \text{Swish}(W_g x) \cdot W_u x
$$

- **门控机制**: $W_g$ 提供"开/关"信号, FFN 可学条件计算。
- **参数多 50%**: 3 个权重矩阵 vs 2, 容量更大。
- **实际**: LLaMA/PaLM 全部默认 SwiGLU, 5-10% loss 改善。

### Q6: GQA 的 n_kv_heads 怎么选? 太小会怎样?

- 经验: $n_{kv} = n_{q} / 4$ 或 $n_{q} / 8$ (LLaMA-3-8B 用 8/32)
- 太小 (如 1 = MQA): KV 极小但**模型质量下降** (经验 1-2%)
- 太大 (如 32 = MHA): 退化为标准 attention, KV 显存大
- 工业: 4-8 是甜点

### Q7: Pre-Norm vs Post-Norm 在大模型里的取舍?

- **Pre-Norm** (主流): $x + f(\text{Norm}(x))$, 训练稳, 不需 warmup。
- **Post-Norm** (原 Transformer): $\text{Norm}(x + f(x))$, 性能略好, 训练需 warmup。
- **结论**: LLaMA/Qwen/DeepSeek 全部 Pre-Norm, 工程友好。

### Q8: 数据归一化对训练 LLM 的影响?

- **Embedding 归一化**: $\hat{e} = e / \|e\|$ + 可学习 scale, 稳定训练。
- **Layer Norm 不需 batch**: 单样本统计, 不依赖 batch 统计。
- **RMS Norm** (LLaMA): 去掉均值, 略快, 略省参数, 效果相当。

### Q9: 长上下文 (32K+) LLM 的核心工程挑战?

1. **注意力 $O(n^2)$ 显存/算力**: Flash Attention 缓解但不消除。
2. **KV Cache 显存爆炸**: 32K 上下文, KV 可达 8-15 GB (7B)。
3. **位置编码外推**: RoPE theta 调大 (1万 → 50万)。
4. **数据稀缺**: 长文档数据少, 训练不充分。
5. **解决方案**: 滑动窗口 attention / linear attention / 状态压缩 (Mamba)。

### Q10: 预训练 → SFT → RLHF 阶段, 显存/算力如何变?

- **预训练**: 满 16N 显存, 海量算力, 几百到几千 GPU·月。
- **SFT**: 小数据, 满参数或 LoRA, 单机多卡即可。
- **RLHF**: 4 个模型 (Actor/Critic/Reward/Reference), 显存 × 4, 常用 LoRA 缓解。
- **DPO**: 去掉 Critic, 2 个模型, 比 PPO 省 50% 显存。

## 74. 实战案例: 设计一个 1B 文本生成模型

**需求**: 1B 参数, 100B tokens 训练数据, 单机 8xA100。

### 74.1 7 步法应用

1. **任务**: 中文对话 + 代码。
2. **数据**: 100B tokens, 中文为主, 含 5B 代码。
3. **偏置**: 因果 Decoder-only, RoPE。
4. **容量**: 1B, 100B tokens → 比例 100, 过训但合理。
5. **骨架**:
   ```python
   d=2048, L=22, n_heads=16, n_kv_heads=4, d_ff=5632
   SwiGLU FFN, RMSNorm, RoPE theta=100万
   V=32K, 共享 embedding
   ```
6. **校验**:
   - 参数: $12 \times 22 \times 2048^2 + 32000 \times 2048 \approx 1.1B$ ✓
   - 训练显存: $16 \times 1.1B = 17.6$ GB, 装得下
   - 推理显存: $2 \times 1.1B + KV$ = 2.2 GB + 0.5 GB
7. **演进**: 留 config 钩子, 后续可 scale up 到 7B。

### 74.2 训练配置

```yaml
# train.yaml
model:
  d_model: 2048
  n_layers: 22
  n_heads: 16
  n_kv_heads: 4
  d_ff: 5632
  vocab_size: 32000
  rope_theta: 1000000
  norm: rms
  ffn: swiglu

train:
  batch_tokens: 4M
  lr: 3.0e-4
  warmup: 2000
  weight_decay: 0.1
  precision: bf16
  grad_ckpt: true
  zero_stage: 2

data:
  corpus_path: /data/100B_tokens
  tokenizer: BBPE-32K

dist:
  world_size: 8
  backend: nccl
```

### 74.3 关键决策

- **GQA (n_kv=4)**: 推理 KV 显存减 4×, 8 GPU 推理 batch 可达 32。
- **RoPE theta=1M**: 支持到 64K 上下文, 适合长文档。
- **Gradient Checkpointing**: 训练时序列 8K 仍 OK。
- **ZeRO-2**: 优化器状态分片, 单卡仅 4 GB optimizer。

### 74.4 消融计划

设计 5 个 ablation 变体:

| 变体 | 改动 | 目的 |
| :--- | :--- | :--- |
| A1 | baseline | 对照 |
| A2 | n_kv=8 (GQA 减小) | 推理加速影响 |
| A3 | d_ff=4096 (FFN 减小) | 参数效率 |
| A4 | rope_theta=10K (短上下文) | 外推 vs 短训 |
| A5 | n_layers=18 (浅) | 深度影响 |

每组 100B tokens, 评测下游任务 (MMLU / C-Eval / HumanEval)。

### 74.5 上线检查

- 模型转 ONNX / TensorRT, 推理 < 50ms/token。
- INT8 量化后 1.1 GB, 单卡可服务 8 路并发。
- KV cache INT4 量化, 进一步减 50%。
- 监控: token 吞吐量、p99 延迟、显存峰值。
