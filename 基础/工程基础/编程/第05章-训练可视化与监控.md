# 深度学习内部表征诊断：直方图、热力图与分布可视化实战教程

## 1. 为什么需要“向内看”

很多算法工程师优化模型时习惯看损失曲线、验证集指标，但面对“优化无效”时往往束手无策。**模型不收敛、过拟合、梯度消失/爆炸、特征坍塌**等问题，根源通常藏在网络内部——某一层的激活值分布是否畸形？条件信息（如 FiLM 模块的调制参数）是否真的被利用？梯度是否顺利回传？

本教程将构建一套**零侵入、低开销**的可视化分析框架，利用 **直方图、热力图、降维分布图** 对网络中的 embedding、激活值、梯度、调制参数等关键张量进行监控，帮助你：
- 快速定位网络失效层
- 判断模块是正向贡献还是负向破坏
- 建立“先看分布，再调结构”的科学诊断习惯

所有示例基于 PyTorch + TensorBoard，但核心思想可迁移至 TensorFlow / JAX / W&B 等工具。

## 2. 核心可视化工具

| 工具 | 适用场景 | 特点 |
| :--- | :--- | :--- |
| **TensorBoard** | 直方图、标量、图像、Embedding 投影 | PyTorch 官方集成，异步写入不阻塞训练 |

## 3. 搭建无痛监控基础设施

### 3.1 注册全局 Hook 存储中间量

我们在模型定义或初始化时注册 forward hook，将感兴趣层的输入/输出暂存到全局字典中，并用 `.detach()` 切断计算图，避免额外显存和梯度开销。

```python
import torch
import torch.nn as nn

# 全局存储
layer_outputs = {}
gradients = {}

def save_output(name):
    """保存前向输出"""
    def hook(module, input, output):
        # 只保留 output 中的张量，detach 避免干扰计算图
        layer_outputs[name] = output.detach() if isinstance(output, torch.Tensor) else output
    return hook

def save_grad(name):
    """保存反向梯度"""
    def hook(grad):
        gradients[name] = grad.detach()
    return hook

# 在模型构建时挂载
# 假设有一个 FiLM 模块
model.film.register_forward_hook(save_output('film_out'))
model.film.fc_gamma.register_forward_hook(save_output('gamma'))
model.film.fc_beta.register_forward_hook(save_output('beta'))
# 对需要梯度的张量注册 backward hook
# 通常更推荐在训练循环内部对具体张量注册，见下文梯度热力图部分
```

对于需要同时看输入的情况，在 `forward` 函数内部直接存：

```python
class FiLM(nn.Module):
    def forward(self, emb1, emb2):
        layer_outputs['emb1'] = emb1.detach()
        layer_outputs['emb2'] = emb2.detach()
        gamma = self.fc_gamma(emb2)
        beta  = self.fc_beta(emb2)
        emb3 = gamma * emb1 + beta
        layer_outputs['emb3'] = emb3.detach()
        layer_outputs['gamma'] = gamma.detach()
        layer_outputs['beta']  = beta.detach()
        return emb3
```

### 3.2 训练循环中条件触发记录

```python
from torch.utils.tensorboard import SummaryWriter

writer = SummaryWriter('runs/diagnosis')
log_every = 200  # 每200步记录一次

for step, batch in enumerate(train_loader):
    # 正常训练步骤
    optimizer.zero_grad()
    loss = model(batch).backward()
    optimizer.step()

    if step % log_every == 0 and is_rank0():
        record_histograms(writer, step)
        record_heatmaps(writer, step)
        # 梯度记录通常放在 backward 之后，optimizer.step 之前
```

## 4. 直方图：看分布“长什么样”

直方图是诊断激活值饱和、梯度消失/爆炸、死 ReLU 的最直接手段。

### 4.1 记录激活值直方图

```python
def record_histograms(writer, step):
    # 遍历需要监控的层
    for name in ['emb1', 'emb3', 'gamma', 'beta']:
        if name in layer_outputs:
            vals = layer_outputs[name].cpu().numpy().flatten()
            writer.add_histogram(f'activations/{name}', vals, step)
```

**在 TensorBoard 中你会看到**：
- `emb1` 与 `emb3` 分布是否相似？若几乎一致，说明调制未生效。
- `gamma` 是否退化为全部为 1？`beta` 是否全部为 0？
- 某个层标准差极小 → 可能表示表达能力不足。

### 4.2 记录梯度直方图

在 `loss.backward()` 之后，`optimizer.step()` 之前，对感兴趣参数的梯度做直方图。

```python
for name, param in model.named_parameters():
    if param.grad is not None:
        writer.add_histogram(f'gradients/{name}', param.grad.cpu().numpy(), step)
```

**观察点**：
- 深层网络某层梯度全为零 → 梯度消失，检查残差连接或 BN 位置。
- 梯度值极大 (>1e3) → 梯度爆炸，考虑裁剪。
- FiLM 模块中 `emb1` 来源的 encoder 参数梯度突然变小 → 调制可能阻断了梯度。

### 4.3 嵌入向量 (embedding) 分布

如果最后分类层之前有一个 embedding 向量（如 `(B, 512)`），记录其整体分布或每个维度的分布，可判断是否发生了 **表示坍塌**（所有样本嵌入变得极其相似）。

```python
# 假设最后一层输出 embedding
if 'final_embedding' in layer_outputs:
    emb = layer_outputs['final_embedding'].cpu().numpy()
    writer.add_histogram('embedding/values', emb, step)
    # 还可以记录每维度的标准差
    writer.add_scalar('embedding/std', emb.std(), step)
```

## 5. 热力图：洞察空间模式与调制强度

热力图让我们看到数据在**空间维度**或**通道维度**上的结构，特别适合卷积特征或序列特征。

### 5.1 空间特征热力图

对于形状为 `(B, C, H, W)` 的特征图，可以取单个样本的 **通道均值** 或 **特定通道** 绘制热力图。

**工具函数**：将二维 numpy 数组绘制成彩色图并转为 TensorBoard 可接受的 Tensor。

```python
import matplotlib.pyplot as plt
import io
import torchvision.transforms as T
from PIL import Image

def fig2tensor(fig):
    buf = io.BytesIO()
    plt.savefig(buf, format='png', bbox_inches='tight')
    buf.seek(0)
    img = Image.open(buf).convert('RGB')
    tensor = T.ToTensor()(img)
    plt.close(fig)
    return tensor

def plot_2d_heatmap(data, title='', cmap='viridis'):
    fig, ax = plt.subplots()
    im = ax.imshow(data, cmap=cmap, aspect='auto')
    plt.colorbar(im, ax=ax)
    ax.set_title(title)
    return fig2tensor(fig)
```

**记录 FiLM 模块的 emb1 和 emb3 空间模式**：
```python
def record_spatial_heatmaps(writer, step):
    emb1 = layer_outputs['emb1']  # (B, C, H, W)
    emb3 = layer_outputs['emb3']
    # 取第0个样本，所有通道平均
    heat_emb1 = emb1[0].mean(dim=0).cpu().numpy()
    heat_emb3 = emb3[0].mean(dim=0).cpu().numpy()
    writer.add_image('heatmap/emb1', plot_2d_heatmap(heat_emb1, 'emb1 space', 'hot'), step)
    writer.add_image('heatmap/emb3', plot_2d_heatmap(heat_emb3, 'emb3 space', 'hot'), step)
```

**解读**：若 `emb3` 的空间热力图与 `emb1` 相比出现了**明显的高亮区域转移**，说明调制成功地根据条件强调了某些空间位置。

### 5.2 通道调制参数热力图

FiLM 的 `γ` 和 `β` 通常是形状 `(B, C)` 或 `(B, C, 1, 1)` 的向量。单个样本是一个 `(C,)` 向量，我们可将其展开成 `(C, 10)` 的条形图，直观显示每个通道的增益/偏置。

```python
def plot_channel_strip(vec, title='', cmap='RdYlGn'):
    # vec: (C,) numpy array
    vec_2d = np.tile(vec[:, np.newaxis], (1, 10))
    return plot_2d_heatmap(vec_2d, title, cmap)

# 记录
gamma = layer_outputs['gamma'][0].squeeze().cpu().numpy()
beta  = layer_outputs['beta'][0].squeeze().cpu().numpy()
writer.add_image('heatmap/gamma', plot_channel_strip(gamma, 'γ (channel gain)', 'RdYlGn'), step)
writer.add_image('heatmap/beta',  plot_channel_strip(beta,  'β (channel bias)', 'coolwarm'), step)
```

**红绿颜色**（如 RdYlGn）使得 >1 的增益通道呈绿色，<1 呈红色，一眼看出哪些通道被选择性增强/抑制。

### 5.3 序列特征热力图

若 `emb1` 形状为 `(B, seq_len, dim)`，则直接对一个样本绘制二维热力图，x轴为特征维度，y轴为序列位置。

```python
seq_data = layer_outputs['emb1'][0].cpu().numpy()  # (seq_len, dim)
writer.add_image('heatmap/emb1_seq', plot_2d_heatmap(seq_data, 'emb1 sequence', 'viridis'), step)
```

### 5.4 梯度敏感度热力图（简易 Grad-CAM）

对某个中间张量的梯度求空间均值，可以得到该张量对最终损失的敏感度图。

```python
# 在 backward 之前注册 hook
def record_grad_heatmap(writer, step):
    if 'emb3' in gradients:
        grad = gradients['emb3']  # (B, C, H, W)
        # 通道平均得到空间敏感度
        saliency = grad[0].mean(dim=0).abs().cpu().numpy()
        writer.add_image('heatmap/grad_saliency', plot_2d_heatmap(saliency, 'grad sensitivity', 'hot'), step)
```

要在训练循环的合适位置获取梯度，需要对 `emb3` 调用 `.register_hook(save_grad('emb3'))`，注意这必须在模型前向之后、`backward` 之前进行。

## 6. 降维分布图：看特征分离与条件有效性

### 6.1 t-SNE / PCA 可视化 Embedding 分离度

使用 `sklearn.manifold.TSNE` 将高维 embedding 降至 2D，并按照真实标签着色。每几个 epoch 做一次，保存到 TensorBoard。

```python
from sklearn.manifold import TSNE
import seaborn as sns
import pandas as pd

def record_tsne(writer, embeddings, labels, epoch, title='emb3 t-SNE'):
    tsne = TSNE(n_components=2, random_state=42)
    emb_2d = tsne.fit_transform(embeddings.cpu().numpy())
    df = pd.DataFrame({'x': emb_2d[:,0], 'y': emb_2d[:,1], 'label': labels.cpu().numpy()})
    fig, ax = plt.subplots(figsize=(8,6))
    sns.scatterplot(data=df, x='x', y='y', hue='label', palette='tab10', ax=ax, alpha=0.7)
    ax.set_title(title)
    writer.add_figure(f'tsne/{title}', fig, global_step=epoch)
    plt.close(fig)
```

**诊断**：
- **同类点形成紧密团簇，不同类彼此远离** → 特征提取健康。
- **所有点混在一起** → 网络容量不足或任务本身困难。
- **训练集分离完美，验证集混乱** → 严重过拟合。

### 6.2 条件调制效果可视化

对于 FiLM 网络，想知道 `emb2` 是否真的改变了 `emb3`，可以用 `emb2` 的某个维度（或主成分）作为颜色，绘制 `emb3` 的 t-SNE 图。

```python
emb2 = layer_outputs['emb2']  # (B, d)
# 取 emb2 的第一维作为颜色（或进行 PCA 取第一主成分）
color = emb2[:, 0].cpu().numpy()
# 绘制 emb3 的 t-SNE 并用 color 着色
tsne = TSNE(n_components=2)
emb3_2d = tsne.fit_transform(layer_outputs['emb3'].cpu().numpy())
fig, ax = plt.subplots()
sc = ax.scatter(emb3_2d[:,0], emb3_2d[:,1], c=color, cmap='viridis')
plt.colorbar(sc)
writer.add_figure('tsne/emb3_by_emb2', fig, global_step=epoch)
```

**如果散点图沿颜色呈现平滑梯度或带状结构，说明 `emb2` 成功编码到了特征空间中；否则条件信息可能被忽略。**

### 6.3 相似度矩阵热力图

计算一批 `emb2` 的 pairwise 余弦相似度，可检验条件嵌入是否产生了足够的多样性。

```python
import torch.nn.functional as F

emb2 = layer_outputs['emb2']  # (B, d)
normed = F.normalize(emb2, dim=1)
sim = torch.mm(normed, normed.t()).cpu().numpy()
writer.add_image('heatmap/emb2_similarity', plot_2d_heatmap(sim, 'emb2 cosine sim', 'coolwarm'), step)
```

理想情况：对角线很亮，其他区域较暗，说明不同样本条件向量彼此正交，信息丰富。如果所有值都接近 1，说明 `emb2` 塌缩为常向量，条件无效。

## 7. 案例实战：诊断 FiLM 调制是否有效

结合上述方法，我们设计一个完整的监控流程，训练一个带 FiLM 的网络时回答：
- FiLM 模块到底有没有用？
- 是增强了有效特征还是破坏了原有信息？
- 梯度是否健康？

### 7.1 记录清单

在训练循环中每 200 步执行：

1. **直方图**：`emb1`, `emb3`, `gamma`, `beta`，以及关键参数的梯度。
2. **热力图**：
   - `emb1` 与 `emb3` 的空间热力图（通道平均）。
   - `gamma` 和 `beta` 的通道条带图。
   - 如果为序列数据，增加序列特征图。
3. **标量**：`emb1` 和 `emb3` 的均值、标准差，`gamma` 均值（是否偏离 1），`beta` 均值（是否偏离 0）。
4. **每 epoch 结束**：t-SNE 图（`emb3` 按真实标签着色，以及按 `emb2` 主成分着色）。

### 7.2 观察并判断

| 现象 | 诊断 | 行动 |
| :--- | :--- | :--- |
| `gamma` 直方图始终集中在 1 附近，`beta` 在 0 附近 | FiLM 退化为恒等映射，条件信息未被利用 | 检查 `emb2` 是否合理，增加 FiLM 表达能力（更多层），降低学习率 |
| `emb3` 方差远小于 `emb1`，空间热力图变模糊 | 调制过度压缩特征，信息丢失 | 初始化 `fc_gamma` 权重靠近 1，`fc_beta` 靠近 0，或添加残差连接 `emb3 = emb1 + gamma*emb1 + beta` |
| 某些通道 `gamma` 持续 ≈ 0 | 通道被完全压制，可能成为瓶颈 | 考虑减少 FiLM 的压缩比，或加 L2 正则鼓励非零 |
| `emb1` 对应编码器的梯度范数趋于 0 | 梯度被 FiLM 阻隔 | 确保乘法反向传播无误，检查广播维度，或使用 `torch.where` 等操作 |
| t-SNE 图中同类样本聚拢且 `emb2` 着色呈现结构 | 调制正向有效 | 继续保持 |

### 7.3 不影响运行的实现原则

- **条件记录**：`if step % 200 == 0 and is_main_process()`。
- **detach 所有中间量**，绝不保留在计算图中。
- **异步写入**：TensorBoard `add_*` 函数立即返回，不阻塞 GPU。
- **绘图频率**：t-SNE 等耗时操作只每 1~5 个 epoch 进行一次。
- **显存清理**：`plt.close('all')`，`del fig`。

## 8. 总结：建立“先分布，后结构”的诊断直觉

这套可视化工具箱让你能够**看到网络的内心活动**。当优化失效时，不应再盲目地改学习率或增加层数，而是执行以下步骤：

1. **看直方图**：激活值是否饱和？梯度是否消失？
2. **看热力图**：空间关注区域是否正确？调制通道是否有差异化？
3. **看降维图**：嵌入是否有判别力？条件信息是否被编码？
4. **对现象定位结构问题**：梯度全零层引入残差；调制无效则重新设计 FiLM 输入。

习惯这种分析流程后，你将能更快地发现网络设计中的缺陷，训练出更稳健、更可解释的模型。本教程的代码模板可直接嵌入现有项目，几分钟内即可获得内部监控面板。接下来，不妨在你的 FiLM 网络上亲自实验一下，让数据告诉你“优化为什么无效”。

## 第 9 章:TensorBoard 高级用法

### 9.1 自定义 Scalars 面板

```python
from torch.utils.tensorboard import SummaryWriter

writer = SummaryWriter('runs/exp_001')

# 1. 标量(scalars) - 损失、指标、学习率
for epoch in range(100):
    writer.add_scalar('train/loss', train_loss, epoch)
    writer.add_scalar('val/auc', val_auc, epoch)
    writer.add_scalar('lr', optimizer.param_groups[0]['lr'], epoch)

# 2. 多个标量合并(同一图)
for step in range(1000):
    writer.add_scalars('loss_components', {
        'main': main_loss,
        'aux': aux_loss,
        'reg': reg_loss
    }, step)

# 3. 直方图
for name, param in model.named_parameters():
    writer.add_histogram(f'params/{name}', param, epoch)
    if param.grad is not None:
        writer.add_histogram(f'grads/{name}', param.grad, epoch)

# 4. 图像
img_grid = torchvision.utils.make_grid(images, nrow=8)
writer.add_image('predictions', img_grid, epoch)

# 5. 文本
writer.add_text('hyperparameters', f'lr={lr}, batch={bs}', 0)

# 6. PR 曲线
writer.add_pr_curve('precision_recall', labels, predictions, epoch)

# 7. 模型图
writer.add_graph(model, input_to_model)

# 8. Embedding 投影
writer.add_embedding(
    embeddings, metadata=labels, label_img=images,
    global_step=epoch
)

writer.close()
```

```python
def extract_attention(model, input_ids, layer_idx=-1, head_idx=0):
    """提取 Transformer 某一层的某一头的注意力权重"""
    attention_weights = []

    def hook(module, input, output):
        # output: (attn_output, attn_weights)
        if isinstance(output, tuple) and len(output) > 1:
            attention_weights.append(output[1].detach())

    # 注册 hook
    target_layer = model.transformer.layers[layer_idx].self_attn
    handle = target_layer.register_forward_hook(hook)

        _ = model(input_ids)

    handle.remove()

    if attention_weights:
        # attention_weights: [B, num_heads, T, T]
        return attention_weights[0][0, head_idx].cpu().numpy()
    return None
```

### 11.4 特征重要性(Permutation Importance)

```python
from sklearn.metrics import roc_auc_score
import numpy as np

def permutation_importance(model, X_val, y_val, feature_names, n_repeats=10):
    """特征置换重要性"""
    model.eval()

    # 基线分数
    with torch.no_grad():
        y_pred_baseline = model(X_val).cpu().numpy()
    baseline_score = roc_auc_score(y_val.cpu().numpy(), y_pred_baseline)

    importances = []
    for i in range(X_val.size(1)):  # 遍历每个特征
        scores = []
        for _ in range(n_repeats):
            X_permuted = X_val.clone()
            X_permuted[:, i] = X_permuted[:, i][torch.randperm(X_permuted.size(0))]

            with torch.no_grad():
                y_pred_permuted = model(X_permuted).cpu().numpy()
            score = roc_auc_score(y_val.cpu().numpy(), y_pred_permuted)
            scores.append(baseline_score - score)  # 下降量 = 重要性
        importances.append(np.mean(scores))

    # 排序
    sorted_idx = np.argsort(importances)[::-1]
    for idx in sorted_idx[:20]:  # Top 20
        print(f"{feature_names[idx]}: {importances[idx]:.4f}")

    return importances


# 用法
```

### 12.1 权重变化率监控

```python
class WeightChangeMonitor:
    """监控权重变化率, 防止权重爆炸"""
    def __init__(self, model):
        self.model = model
        self.prev_weights = {n: p.clone().detach() for n, p in model.named_parameters()}

    def update(self, step):
        """每步调用, 记录权重变化率"""
        changes = {}
        for n, p in self.model.named_parameters():
            if p.grad is None:
                continue
            change = (p.detach() - self.prev_weights[n]).norm().item()
            ref = p.detach().norm().item() + 1e-8
            relative_change = change / ref
            changes[n] = relative_change
            self.prev_weights[n] = p.detach().clone()

        # 记录到 TensorBoard
        for n, c in changes.items():
            writer.add_scalar(f'weight_change/{n}', c, step)

        # 报警: 任何层变化率超过 0.1 视为异常
        for n, c in changes.items():
            if c > 0.1:
                print(f"⚠️ {n} 权重变化率 {c:.4f} 异常!")
                return False
        return True
```

```python
class ActivationSaturationMonitor:
    """监控激活饱和(全为 0 或全为 1)"""
    def __init__(self, dead_threshold=0.5):
        self.dead_threshold = dead_threshold

    def check(self, activations, name):
        """
        activations: 激活值 Tensor
        dead_threshold: 超过这个比例的神经元为 0 则认为是 dead
        """
        if activations.dim() > 2:
            activations = activations.flatten(2).mean(2)  # [B, D]

        total_neurons = activations.size(1)

        if dead_neurons > 0:
            dead_ratio = dead_neurons / total_neurons
            writer.add_scalar(f'dead_neurons/{name}', dead_ratio, step)

            if dead_ratio > 0.3:
```

### 13.2 数据漂移检测(PSI)

```python
class FeatureDriftDetector:
    """特征分布漂移检测"""
    def __init__(self, reference_data, threshold_psi=0.2):
        self.reference_data = reference_data
        self.threshold = threshold_psi

    def compute_psi(self, current_data, bins=10):
        """PSI = Population Stability Index"""
        # 用 reference 的分位数做分桶
        quantiles = np.percentile(self.reference_data, np.linspace(0, 100, bins + 1))
        quantiles[0] = -np.inf
        quantiles[-1] = np.inf

        ref_counts, _ = np.histogram(self.reference_data, bins=quantiles)
        cur_counts, _ = np.histogram(current_data, bins=quantiles)

        # 加 1 防止 0
        ref_ratio = (ref_counts + 1) / (len(self.reference_data) + bins)
        cur_ratio = (cur_counts + 1) / (len(current_data) + bins)

        psi = np.sum((cur_ratio - ref_ratio) * np.log(cur_ratio / ref_ratio))
        return psi

    def check_drift(self, current_data):
        psi = self.compute_psi(current_data)

        if psi > self.threshold:
            return {
                'drift': True,
                'psi': psi,
                'action': 'retrain' if psi > 0.5 else 'investigate'
            }
        return {'drift': False, 'psi': psi}
```

### 13.3 预测置信度监控

```python
class PredictionConfidenceMonitor:
    """监控预测分数的分布变化"""
    def __init__(self, reference_scores, window_size=1000):
        self.reference_scores = reference_scores
        self.recent_scores = deque(maxlen=window_size)

    def update(self, score):
        self.recent_scores.append(score)

    def check_drift(self):
        if len(self.recent_scores) < 100:
            return None

        recent = np.array(self.recent_scores)
        ref = self.reference_scores

        # 计算 PSI
        psi = self._compute_psi(ref, recent)

        # 计算 KS 检验
        from scipy.stats import ks_2samp
        ks_stat, ks_p = ks_2samp(ref, recent)

        return {
            'psi': psi,
            'ks_statistic': ks_stat,
            'ks_pvalue': ks_p,
            'drift_detected': psi > 0.2 or ks_p < 0.01
        }

    def _compute_psi(self, reference, current, bins=10):
        quantiles = np.percentile(reference, np.linspace(0, 100, bins + 1))
        quantiles[0] = -np.inf
        quantiles[-1] = np.inf
        ref_counts, _ = np.histogram(reference, bins=quantiles)
        cur_counts, _ = np.histogram(current, bins=quantiles)
        ref_ratio = (ref_counts + 1) / (len(reference) + bins)
        cur_ratio = (cur_counts + 1) / (len(current) + bins)
        return np.sum((cur_ratio - ref_ratio) * np.log(cur_ratio / ref_ratio))
```

```python
class TrainingAnomalyDetector:
    """训练异常自动检测"""
    def __init__(self):
        self.history = deque(maxlen=100)
        self.alert_callbacks = []

    def add_alert_callback(self, callback):
        self.alert_callbacks.append(callback)

    def step(self, loss, grad_norm, lr, step):
        """每步调用, 检测异常"""
        self.history.append({'loss': loss, 'grad_norm': grad_norm, 'lr': lr})

        anomalies = []

        # 1. NaN/Inf 检测
        if math.isnan(loss) or math.isinf(loss):
            anomalies.append(("NaN/Inf loss", f"loss={loss}"))

        # 2. Loss 不下降(过去 50 步变化 < 1%)
        if len(self.history) >= 50:
            recent_losses = [h['loss'] for h in list(self.history)[-50:]]
            if max(recent_losses) - min(recent_losses) < 0.01 * recent_losses[0]:
                anomalies.append(("Loss 不下降", f"loss 范围 {min(recent_losses):.4f} ~ {max(recent_losses):.4f}"))

        # 3. 梯度爆炸
        if grad_norm > 100:
            anomalies.append(("梯度爆炸", f"grad_norm={grad_norm:.2e}"))

        # 4. 学习率异常
        if lr <= 0:
            anomalies.append(("学习率异常", f"lr={lr}"))

        # 触发告警
        if anomalies:
            for cb in self.alert_callbacks:
                cb(anomalies)

        return anomalies
```

### 15.2 避免常见错误

1. **不要每个 epoch 都画 t-SNE**: 慢, 价值低。改为每 10-50 epoch。
2. **不要记录所有层的激活**: 选关键层 (输入层, 中间层, 输出层)。
3. **不要混淆训练和验证的可视化**: 用不同 tag 区分。
4. **不要忘记 normalize 数据**: 不同特征的可视化前要做归一化。
5. **不要记录到主进程**: 用 rank 0 限制, 避免冗余写入。

```python
            'param_norm': deque(maxlen=1000)
        }

        # 注册 hooks
        self._register_hooks()

        # 异常检测
        self.anomaly_detector = TrainingAnomalyDetector()

    def _register_hooks(self):
        """注册 forward/backward hooks 记录激活和梯度"""
        self.activations = {}
        self.gradients = {}

        def forward_hook(name):
            def hook(module, input, output):
                if isinstance(output, torch.Tensor):
                    self.activations[name] = output.detach()
            return hook

        def backward_hook(name):
            def hook(module, grad_input, grad_output):
                if grad_output[0] is not None:
                    self.gradients[name] = grad_output[0].detach()
            return hook

        # 给关键层注册
        for name, module in self.model.named_modules():
            if isinstance(module, (nn.Linear, nn.Conv2d, nn.LayerNorm)):
                module.register_forward_hook(forward_hook(name))

    def step_log(self, loss, optimizer, step, batch_idx):
        """每步调用"""
        # 1. 梯度范数
        grad_norm = 0
        for p in self.model.parameters():
            if p.grad is not None:
                grad_norm += p.grad.data.norm(2).item() ** 2
        grad_norm = grad_norm ** 0.5

        # 2. 参数范数
        param_norm = 0
        for p in self.model.parameters():
            param_norm += p.data.norm(2).item() ** 2
        param_norm = param_norm ** 0.5

        # 3. 学习率
        lr = optimizer.param_groups[0]['lr']

        # 4. 异常检测
        anomalies = self.anomaly_detector.step(loss, grad_norm, lr, step)

        # 5. 记录
        self.tb_writer.add_scalar('train/loss', loss, step)
        self.tb_writer.add_scalar('train/grad_norm', grad_norm, step)
        self.tb_writer.add_scalar('train/param_norm', param_norm, step)
        self.tb_writer.add_scalar('train/lr', lr, step)

        self.history['train_loss'].append(loss)
        self.history['grad_norm'].append(grad_norm)
        self.history['param_norm'].append(param_norm)

        if self.use_wandb:
            wandb.log({
                'train/loss': loss,
                'train/grad_norm': grad_norm,
                'train/param_norm': param_norm,
                'train/lr': lr,
                'step': step
            })

        return anomalies

    def epoch_log(self, epoch, val_auc, val_loss):
        """每 epoch 调用"""
        self.tb_writer.add_scalar('val/auc', val_auc, epoch)
        self.tb_writer.add_scalar('val/loss', val_loss, epoch)
        self.history['val_auc'].append(val_auc)

        # 记录激活直方图(每 10 epoch 一次)
        if epoch % 10 == 0:
            for name, act in self.activations.items():
                self.tb_writer.add_histogram(f'activations/{name}', act, epoch)

        # 记录梯度流图(每 50 epoch)
        if epoch % 50 == 0:
            fig = plot_grad_flow(self.model.named_parameters())
            self.tb_writer.add_figure('grad_flow', fig, epoch)

        if self.use_wandb:
            wandb.log({
                'val/auc': val_auc,
                'val/loss': val_loss,
                'epoch': epoch
            })

    def close(self):
        self.tb_writer.close()
        if self.use_wandb:
            wandb.finish()
```

## 第 17 章:核心面试题(8 题)

### Q1: 为什么训练监控必须看梯度流?

**答**: 梯度流能告诉你"是否有层没收到梯度"。如果有层梯度为 0,说明上游有问题(梯度消失、初始化错误、in-place 操作破坏计算图)。**没有梯度流监控,优化问题排查会走弯路**。

### Q2: PSI 是什么?多大算漂移?

**答**: Population Stability Index,衡量两个分布的差异。公式: $\text{PSI} = \sum (P_i^{\text{new}} - P_i^{\text{old}}) \ln(P_i^{\text{new}}/P_i^{\text{old}})$。**PSI < 0.1 稳定, 0.1-0.2 关注, > 0.2 显著漂移, > 0.5 严重**。

### Q3: 训练时如何检测 NaN 而不显著降低速度?

**答**: 不用每步都 `torch.isfinite()` 全检查(慢)。改为:**(1) 关键张量(loss、grad_norm)用 `item()` 时检查;**(2) 训练前 100 步开启 `detect_anomaly`, 之后关闭;**(3) 监控梯度范数, > 100 立即报警**。

### Q4: 什么是 t-SNE 的局限性?

**答**: (1) 计算慢 O(N²); (2) perplexity 参数敏感; (3) 不能保留全局结构(只关注局部); (4) 每次运行结果不同(random_state 不固定时)。**生产监控用 UMAP 更快**。

### Q5: WandB vs TensorBoard 的核心区别?

**答**: TensorBoard 本地运行, 离线, 数据可视化强; WandB 云端协作, 支持团队共享、超参搜索、模型版本管理。**个人项目用 TensorBoard, 团队协作/正式实验用 WandB**。

### Q6: 如何监控模型的"过拟合信号"?

**答**: 监控 **train_loss vs val_loss 差距**。如果 train_loss 持续下降但 val_loss 上升, 模型在过拟合。**预防**: 早停(Early Stopping) + Dropout + Weight Decay + 数据增强。

### Q7: 模型上线后如何判断需要重新训练?

**答**: 监控三个信号:(1) 关键特征 PSI > 0.2;(2) 实时 AUC 下降 > 1%;(3) 预测分布显著偏移。**任一信号触发即启动自动重训流程**。

### Q8: Embedding 漂移如何检测?

**答**: (1) Embedding 范数分布变化(整体分布上移 = 漂移);(2) Embedding 余弦相似度变化(高频 ID 间相似度降低 = 漂移);(3) 用旧模型推理新数据,AUC 显著下降。

### 19.1 案例:DIN 模型 AUC 从 0.81 提升到 0.83 的可视化诊断过程

**背景**:某推荐团队的 DIN 模型训练 20 epoch 后 AUC 卡在 0.81,无法继续提升。

**诊断步骤**:

**第一步:看 Loss 曲线**
```text
Train loss: 平稳下降, 从 0.5 到 0.35
Val loss:  平稳下降, 从 0.5 到 0.38
```
结论: 训练正常, 没有过拟合迹象。AUC 停在 0.81 不是因为过拟合。

**第二步:看激活分布**
```python
# 注册 hook 监控 attention 层的输出
record_histograms(writer, step)
```
发现: DIN 的 attention 权重分布**严重偏向少数几个历史商品**, 大量历史商品的 attention ≈ 0。
```text
attn_weights 直方图:
[0.000-0.005] ████████████████████ 80%  (历史 80% 商品被忽略)
[0.005-0.050] █████                 15%
[0.050-0.500] █                     5%
```
诊断: DIN 的 attention 过于集中, 没有充分利用用户的历史行为。

**第三步:看热力图**
```python
record_attention_heatmap(writer, step)
```
可视化单个样本的 attention 矩阵, 发现模型几乎只关注"最近一次点击的商品"。

**第四步:验证假设**
检查数据分布, 发现用户历史序列的 95% 都集中在最近 1-2 个商品(老数据被截断)。

**修复方案**:
1. 增加历史序列长度: max_len 从 50 改到 200。
2. 加入时间衰减权重, 让老行为也贡献注意力。
3. 加入位置编码。

**修复后效果**:
```text

[0.000-0.005] ████                  20%
[0.005-0.050] ████████████          50%
[0.050-0.500] ████                  25%
[0.500-1.000] █                      5%
```
AUC 提升到 0.83。

**沉淀**: **可视化的核心价值不是"看着好看",而是"暴露问题"**。如果不看激活分布,我们会以为是模型结构问题,反复调超参,浪费时间。

### 19.3 案例:训练 Loss 不下降的可视化诊断

**背景**:训练一个文本分类模型, 1000 步后 loss 仍在 2.3 附近震荡, 不下降。

**诊断**:

**Step 1: 检查梯度**
```python
grad_flow = compute_grad_norm_per_layer(model)
print(grad_flow)
# embedding.weight: 0.0001  ← 梯度极小!
# conv1.weight: 0.01
# conv2.weight: 0.05
# fc.weight: 0.5
```
**结论**: Embedding 层梯度几乎为 0, 说明上游信号没传过来。

**Step 2: 检查 Embedding 分布**
```text
Embedding 范数直方图:
- 大部分 ID: norm ≈ 0.1
- 少量 ID: norm ≈ 0.0  ← 初始化没改?
```

**Step 3: 检查初始化代码**
```python
def init_weights(m):
    if isinstance(m, nn.Embedding):
        # 错误: 这里把整个 embedding 清零了!
        m.weight.data.zero_()
```
**根因**: 自定义初始化函数错误, 把 Embedding 清零了。所有 ID 的 Embedding 完全相同, 模型无法区分它们, 梯度无法有效回传。

**修复**: 改为 `nn.init.normal_(m.weight, std=0.01)`。

**沉淀**: **Embedding 初始化错误是搜推广最常见的 bug 之一**。训练前**必须**打印 `model.embedding.weight.std()` 验证。

```python
class BusinessMetricsDecomposition:
    """CTR 变化的根因拆解"""
    def decompose_ctr_change(self, baseline_ctr, current_ctr, segments):
        """
        把总 CTR 变化拆解到不同人群/物品
        segments: [(segment_name, baseline_ctr, current_ctr, segment_volume)]
        """
        baseline_volume = sum(s[3] for s in segments)
        baseline_weighted = sum(s[1] * s[3] for s in segments) / baseline_volume

        contributions = []
        for name, b_ctr, c_ctr, vol in segments:
            # 这部分的绝对贡献
            contribution = (c_ctr - b_ctr) * vol / baseline_volume
            contributions.append({
                'segment': name,
                'baseline': b_ctr,
                'current': c_ctr,
                'delta': c_ctr - b_ctr,
                'contribution': contribution,
                'volume': vol
            })

        total_change = current_ctr - baseline_ctr
        return sorted(contributions, key=lambda x: abs(x['contribution']), reverse=True)
```

### 20.3 A/B 测试监控

```python
class ABTestMonitor:
    """A/B 测试实时监控"""
    def __init__(self, baseline_metric, mde=0.01):
        self.baseline = baseline_metric
        self.mde = mde  # Minimum Detectable Effect
        self.group_data = {'control': [], 'treatment': []}

    def update(self, group, value):
        self.group_data[group].append(value)

    def check_significance(self):
        from scipy.stats import ttest_ind

        if len(self.group_data['control']) < 30 or len(self.group_data['treatment']) < 30:
            return {'significant': False, 'reason': '样本不足'}

        stat, p_value = ttest_ind(
            self.group_data['control'],
            self.group_data['treatment']
        )

        control_mean = np.mean(self.group_data['control'])
        treatment_mean = np.mean(self.group_data['treatment'])
        relative_lift = (treatment_mean - control_mean) / control_mean

        return {
            'significant': p_value < 0.05,
            'p_value': p_value,
            't_statistic': stat,
            'control_mean': control_mean,
            'treatment_mean': treatment_mean,
            'relative_lift': relative_lift,
            'sample_size_control': len(self.group_data['control']),
            'sample_size_treatment': len(self.group_data['treatment']),
            'meets_mde': abs(relative_lift) >= self.mde
        }
```

### 23.2 完整面试题清单(8 题)

#### Q9: 用什么可视化方法诊断模型不收敛?

**答**: 三步法:(1) 看 Loss 曲线 - 是否下降;(2) 看梯度流 - 是否有层梯度为 0;(3) 看激活直方图 - 是否有死神经元。**这三步能覆盖 80% 的不收敛问题**。

#### Q10: 如何监控"模型效果突然下降"?

**答**: 实时计算在线 AUC,与历史值对比。如果 AUC 下降 > 1% 或 PSI > 0.2, 自动触发告警 + 自动重训。

#### Q11: 训练集效果很好但测试集差,如何诊断?

**答**: (1) 检查过拟合: train_loss 持续下降, val_loss 上升 → 加 dropout/weight decay;(2) 检查数据分布: PSI 检验;(3) 检查数据泄漏: 特征是否包含了未来信息。

#### Q12: 为什么要监控"参数范数"?

**答**: 参数范数能告诉你"模型是否稳定"。如果参数范数快速增长,说明学习率过大;如果突然下降,可能有数值问题。

#### Q13: 你如何向非技术同事解释模型效果?

**答**: 用业务指标说话。例如:"AUC 提升 0.003, 对应日均 GMV 增加 50 万"。**永远把技术指标翻译成业务影响**。

#### Q14: 推荐系统的可解释性为什么重要?

**答**: (1) 产品经理想知道"为什么推这个";(2) 用户想知道"为什么看到这个";(3) 监管要求算法可解释; (4) 调试时需要知道模型学到了什么。

#### Q15: Embedding 可视化用什么方法?

**答**: (1) t-SNE: 局部结构, 慢;(2) PCA: 全局结构, 快;(3) UMAP: 局部+全局, 中速。**生产监控用 PCA(快), 论文可视化用 t-SNE 或 UMAP(美观)**。

#### Q16: WandB 的 sweep 是什么?

**答**: 自动超参搜索工具。支持贝叶斯优化、随机搜索、网格搜索。**核心价值**: 找到最优超参组合, 减少人工调参时间。

**1. 背景与动机**

任何技术或方法的出现都不是孤立的,而是回应特定历史条件下的具体问题。"第05章-训练可视化与监控" 的发展也不例外。要理解它,必须回到它出现的那个时间点,看清它要解决的真实问题是什么。当时的主流方案有哪些不足? 它的提出填补了哪些空白? 这些问题的回答,决定了我们今天该如何使用它。

从知识论角度看,**技术演进是问题驱动的**——不是先有方案再找问题,而是先有问题再有方案。这个观察可以帮助我们避免"拿着锤子找钉子"的陷阱,真正把方法用对地方。

历史维度上,我们看到三个规律:

1. **从特殊到一般**: 早期方法往往针对特定场景,后期抽象出通用框架。学习的认知规律也是先掌握具体案例,再抽象出一般模式。这种"自下而上"的学习方式,在机器学习模型的设计里反复出现。

3. **从局部到全局**: 关注单个组件,演进到关注整个系统。早期模型评估只关注单点指标,现在更关注全链路的协同效应。这种"系统视角"的转变,与软件工程从单体架构到微服务架构的演进高度相似。

**3. 数学形式化(简洁版)**

虽然我们强调最佳实践视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

偏差-方差分解是另一个核心框架:误差可以分解为模型偏差(欠拟合)、方差(过拟合)和不可约噪声三部分。理解这个分解有助于诊断模型表现、选择合适复杂度。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

信息论为"第05章-训练可视化与监控" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。

互信息衡量知道一个变量后,另一个变量不确定性减少的量。在机器学习中,它被广泛用于特征选择、表示学习、多模态对齐等场景。

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

信息瓶颈原则指出,我们应该寻找既紧凑又预测性强的表示。这一思想影响了大量表示学习方法的设计,包括对比学习、自监督学习、多模态预训练等。

**7. 实践建议**

结合 "第05章-训练可视化与监控" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "第05章-训练可视化与监控" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。

**7. 实践建议**

结合 "第05章-训练可视化与监控" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "第05章-训练可视化与监控" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
