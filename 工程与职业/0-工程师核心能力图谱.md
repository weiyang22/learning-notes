# 0-工程师核心能力图谱

> **定位**: 算法工程师的"职业发展 GPS", 把"我该学什么"映射到"我该会什么"
> **适用**: P5 校招 → P8 专家的全阶段, 算法工程师 / 研究员 / 团队负责人
> **风格**: 能力维度 + 级别标准 + 自评表 + 发展路径, 一份文档讲透"该会什么"

---

## 0. 一句话总结

**算法工程师 = 业务理解 + 算法能力 + 工程能力 + 系统设计 + 沟通协作 + 影响力**. P5 看单点, P6 看链路, P7 看生态, P8 看行业. 本文把"软实力"补进"硬技能", 让成长路径不再依赖运气.

---

## 1. 算法工程师的 6 大核心能力

> 6 大能力不是平行的, 而是有层级关系的: 算法/工程是底盘, 系统设计是骨架, 业务理解是皮肤, 沟通/影响力是空气. 缺任何一个, 都成不了高 P.

### 1.1 业务理解 (Business Sense)

**定义**: 能听懂业务语言, 把业务问题翻译成技术问题, 把技术结果翻译成业务价值.

**为什么重要**:
- 算法工程师的成果必须用业务指标衡量, 不是 AUC
- 业务不理解, 模型做得再好也没用 (解决错的问题)
- P7+ 必备, P5 容易忽略

**核心问题**:
1. 业务的核心指标 (OEC / 北极星指标) 是什么?
2. 业务的用户痛点是什么? 频次? 强度?
3. 业务的竞争对手是谁? 我们差异化在哪?
4. 业务的护城河 / 长期壁垒是什么?

**典型表现**:
| 级别 | 业务理解表现 |
|------|------------|
| **P5** | "把模型 AUC 从 0.72 提到 0.74" |
| **P6** | "模型 AUC 提升 + 在线 CTR +0.8%" |
| **P7** | "重构召回架构, 业务 GMV +3%" |
| **P8** | "主导新业务 0→1 算法建设, 半年成为行业第一" |

### 1.2 算法能力 (Algorithm Skills)

**定义**: 掌握 ML/DL/RL/LLM 核心算法, 能选型, 能改进, 能复现 SOTA.

**为什么重要**:
- 这是算法工程师的"本职"
- P5 必备, P6 主流模型要熟, P7 要能改, P8 要能定义

**包含维度**:
- 基础 ML: LR, GBDT, FM, 树模型
- 深度学习: CNN, RNN, Transformer, GNN
- 推荐模型: DIN, DIEN, MMoE, PLE
- 生成式推荐: HSTU, OneRec, TIGER, MTGR
- 大模型: GPT, BERT, LLaMA, RLHF/DPO/GRPO
- 强化学习: Bandit, PPO, SAC
- 检索: 双塔, 向量检索, FAISS

### 1.3 工程能力 (Engineering Skills)

**定义**: 把算法变成能跑、能上线、能 scale 的代码. 包括训练, 部署, 监控, 调优.

**为什么重要**:
- 算法只能"做出来", 工程才能"跑起来"
- 工业界 90% 的价值来自工程落地
- 工程 bug 翻车 = 上线事故, 直接 KPI 影响

**包含维度**:
- 代码能力: Python / PyTorch / C++ / SQL
- 训练: DDP / FSDP / AMP / Checkpoint
- 部署: TF Serving / Triton / vLLM
- 监控: Prometheus / Grafana / 日志
- 性能: Profiler / 量化 / 编译

### 1.4 系统设计 (System Design)

**定义**: 从 0 到 1 设计完整系统, 包括数据流, 模型架构, 服务架构, 监控体系.

**为什么重要**:
- 高级工程师的核心能力
- 晋升答辩高频题
- 面试必考

**典型场景**:
- 设计一个推荐系统
- 设计一个广告系统
- 设计一个 LLM 服务
- 设计一个 AB 实验平台

### 1.5 沟通协作 (Communication)

**定义**: 把想法传达给团队 / 跨团队 / 老板, 让对方听懂 + 接受 + 行动.

**为什么重要**:
- 算法工程师 80% 工作是沟通 (写文档, 评审, 拉通)
- P6 开始权重逐步上升, P7 决定晋升成败

**包含维度**:
- 写: 设计文档, RFC, 报告
- 说: 会议, 评审, 答辩
- 听: 需求, 反馈
- 协调: 跨团队, 资源, 优先级

### 1.6 影响力 (Influence)

**定义**: 让别人愿意跟着你做事, 让团队以外的人也知道你.

**为什么重要**:
- P7 决定能否独立方向, P8 决定能否定义领域
- 影响力 = 资源 + 机会 + 选择权

**包含维度**:
- 内部: 跨团队认可, 项目 leader, 团队方向
- 行业: 论文, 演讲, 开源, 博客

## 2. 能力图谱

> P5/P6/P7/P8 不是"年龄/年限"决定, 而是"能力层级"决定. 同一个人在不同公司可能是 P6 或 P7. 这里给"能力维度"做级别映射.

### 2.1 P5 (初级) 期望

> 校招 / 0-2 年 / 能独立完成被分配的任务

| 能力维度 | 期望水平 | 具体表现 |
|---------|---------|---------|
| **业务理解** | 了解业务 | 能复述业务目标, 理解所在团队 OEC |
| **算法能力** | 掌握基础 | 熟悉主流模型原理 (DIN, MMoE), 能用 PyTorch 实现 |
| **工程能力** | 写能跑的代码 | 能独立完成训练脚本, 会用 DDP, 理解数据流 |
| **系统设计** | 理解模块 | 知道召回/粗排/精排是什么, 不需要设计 |
| **沟通协作** | 表达清楚 | 能写周报, 能讲清楚自己做的 |
| **影响力** | 个人产出 | 1-2 个有数据支撑的小项目 |

### 2.2 P6 (中级) 期望

> 3-5 年 / 能独立负责一个模块, 跨小团队协作

| 能力维度 | 期望水平 | 具体表现 |
|---------|---------|---------|
| **业务理解** | 深度理解 | 能主动发现业务问题, 提出技术方案 |
| **算法能力** | 主流水平 | 能选型, 能复现 SOTA, 能改 |
| **工程能力** | 上线过 1-2 个模型 | 熟悉完整 pipeline, 能 debug 性能问题 |
| **系统设计** | 能设计模块 | 能设计召回/粗排/精排中的一个完整模块 |
| **沟通协作** | 跨小组沟通 | 能拉通 PM / 工程 / 数据 |
| **影响力** | 团队内有名 | 1-2 个有业务影响的项目, 1-2 个跨团队合作 |

### 2.3 P7 (高级) 期望

> 5-8 年 / 能独立负责一条业务线算法, 带 3-5 人小团队

| 能力维度 | 期望水平 | 具体表现 |
|---------|---------|---------|
| **业务理解** | 业务 owner | 把业务指标当作自己的指标 |
| **算法能力** | 能定义问题 | 能提"应该做什么问题", 而不是"做哪个模型" |
| **工程能力** | 推动工程化 | 主导 1 个工程平台 / 工具的建设 |
| **系统设计** | 设计完整系统 | 能设计一个完整推荐系统 (含召回+排序+AB+监控) |
| **沟通协作** | 跨部门协调 | 能拉通 3-5 个团队 |
| **影响力** | 行业可见 | 1-2 篇论文 / 1 个开源项目 / 1 次行业演讲 |

### 2.4 P8 (专家) 期望

> 8-12 年 / 能定义领域方向, 带 10+ 人团队

| 能力维度 | 期望水平 | 具体表现 |
|---------|---------|---------|
| **业务理解** | 行业视野 | 能看到行业 3-5 年趋势, 定义业务方向 |
| **算法能力** | 行业前沿 | 能引领一个细分方向, 出 benchmark 级别的工作 |
| **工程能力** | 平台级建设 | 主导 1 个公司级平台 (特征平台, 模型平台) |
| **系统设计** | 行业 SOTA | 设计的系统成为业界参考 |
| **沟通协作** | 跨 BU 协调 | 拉通 10+ 团队 |
| **影响力** | 行业 leader | 多篇高质量论文, 行业大会 keynote, 开源影响力 |

### 2.5 各级别对照表 (速查)

```text
┌────────────────────────────────────────────────────────────────┐
│  P5 初级     → "做"  : 能按要求完成模块                          │
│  P6 中级     → "选"  : 能选型, 能独立负责                       │
│  P7 高级     → "定"  : 能定义问题, 能带团队                     │
│  P8 专家     → "创"  : 能开创新方向, 行业 leader               │
└────────────────────────────────────────────────────────────────┘
```

1. 先选一个对象，不要同时打开整章；
