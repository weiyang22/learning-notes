## 二、核心补充内容

### 2.1 端到端的时间预算与缓存策略（fun-rec ch10 在线流程）

推荐请求的端到端时延预算是"总装视角"独有的内容（各分章看不到全局）：

| 阶段 | 典型预算 | 手段 |
| :--- | ---: | :--- |
| 网关 + 预处理 | ~5ms | 请求池化 |
| 召回（多路） | ~10ms | ANN 索引 + 各路并行 |
| 特征获取 | ~5ms | 本地缓存 + 批量拉取 |
| 粗排 | ~10ms | 小模型 + 候选截断（千→百） |
| 精排 | ~20ms | 打分批量化 |
| 重排 + 业务规则 | ~5ms | 轻量逻辑 |
| **合计** | **< 60ms** | 超时降级：跳过重排/用缓存 |

**缓存三层**：用户画像缓存（分钟级）、召回结果缓存（秒级，翻页复用）、Item 侧特征缓存（小时级）——缓存的失效策略与特征新鲜度要求绑定。

### 2.2 前端与交互：反馈闭环的起点（fun-rec ch10 前端节）

本地"工程与职业"系列全部面向服务端，fun-rec ch10 补上了展示与埋点侧：

1. **埋点即数据源**：曝光/点击/停留/滑走的埋点规范决定样本可信度——曝光必须"真实可见"（防渲染未出即计曝光），这是样本偏差的源头；
2. **反馈闭环**：负反馈（不感兴趣）入口直连特征/重排规则；点赞/收藏进实时特征流（Flink），分钟级生效；
3. **多目标入口设计**：页面的交互元素（关注/分享/评论）对应多目标建模的各任务标签——前端设计即标签体系设计。

### 2.3 项目脚手架：从零搭一个最小可跑系统

fun-rec ch10 给出的项目结构可直接作为练习模板（配 MovieLens 级数据）：

```text
rec-system/
├── offline/          # 数据同步、特征、训练（Airflow DAG）
│   ├── feature/      # 用户/物品/上下文特征
│   └── train/        # 召回双塔 + 精排 DeepFM
├── online/           # 召回服务 / 排序服务 / 融合服务（FastAPI）
├── index/            # faiss 索引构建与更新任务
├── web/              # 展示页 + 埋点上报
└── deploy/           # docker-compose：全套服务编排
```

**练习目标**：全链路跑通 > 单点精度——重点体会"样本生成 → 训练 → 导出 → 索引更新 → 在线查询"的一致性检查点（这正是特征平台课的落地场景）。

### 2.4 迭代节奏与指标看板

ch10 收尾的运维视角：离线指标（AUC/GAUC/召回命中率）与在线指标（CTR/时长/多样性）**分看板但同源口径**；每次迭代的固定流程：离线过门槛 → 影子/小流量 → 全量 → 复盘归档（与本库《GR研究/第07章-02-实验模版》的实验纪律衔接）。

## 三、可直接动手的实践

1. 按 2.3 脚手架搭最小系统：MovieLens 数据上双塔召回（faiss）+ DeepFM 精排 + 融合服务，docker-compose 一键起；
2. 给系统加"曝光-点击"埋点闭环，验证训练样本与线上行为的一致性；
3. 测全链路时延并画预算表（2.1），找出你的系统的最大瓶颈段并优化一次。
