# 2. 生产工程与模型服务化

> 配套 [[1-推荐系统端到端设计]] 的"模型部署"部分,深入讨论模型从训练到上线的全流程。

## 0. 一句话总结

**模型服务化 = 离线训练(TF/PyTorch)→ 模型导出(SavedModel/ONNX/TorchScript)→ 在线推理(批处理/异步)→ 服务编排(Triton/TFServing/vLLM)→ 监控与回滚;核心矛盾是"延迟 × 吞吐 × 效果 × 成本"四维权衡。**

---

## 1. 模型服务化的全流程

### 1.1 训练 → 导出 → 部署 → 监控

**完整链路:**

```text
[训练数据] → [模型训练] → [Checkpoint] → [模型导出] → [模型仓库] → [推理服务] → [监控告警]
    ↑                                                                            ↓
    └────────────────────────── 反馈闭环 ──────────────────────────────────────┘
```

**各环节的关键产出:**

| 环节 | 输入 | 输出 | 关键工具 |
|------|------|------|----------|
| 训练 | 训练样本 + 特征 | Checkpoint(.pt/.ckpt) | PyTorch/TF/Paddle |
| 导出 | Checkpoint | 模型文件(.pb/.onnx/.pt) | torch.onnx/saved_model |
| 仓库 | 模型文件 + 配置 | 版本化的模型 | MLflow/ModelScope/自研 |
| 部署 | 模型仓库 + 服务配置 | 运行中的容器 | K8s/Triton/TFServing |
| 监控 | 推理流量 | 指标/日志/告警 | Prometheus/Grafana |

**模型仓库的设计:**

```text
model_registry/
├── ranker/
│   ├── v1/  (历史版本)
│   │   ├── model.onnx
│   │   ├── config.pbtxt
│   │   └── metrics.json
│   ├── v2/
│   └── latest → v3  (软链接指向当前生产版本)
├── reranker/
└── ...
```

**关键设计点:**

- 版本化:每个版本独立目录,支持快速回滚
- 元信息:记录训练时间、数据版本、关键指标
- 一致性 hash:模型 + 推理服务版本绑定,防止"模型升级但服务没升级"的错位
- 签名 (Signature):明确定义输入/输出 schema

### 1.2 模型版本管理

**版本号规范:**

```text
{major}.{minor}.{patch}

major: 架构大改(DIN → DIEN)
minor: 特征或目标大改(加多任务)
patch: 超参微调或 bug 修复
```

**版本元信息:**

```json
{
  "model_name": "ranker",
  "version": "3.2.1",
  "created_at": "2026-07-23T10:00:00Z",
  "trained_by": "wangwei@bytedance",
  "git_commit": "abc123def456",
  "training_data_version": "events_20260720",
  "feature_version": "feat_v42",
  "metrics": {
    "auc": 0.8523,
    "online_ctr_lift": 0.024,
    "training_loss": 0.234
  },
  "dependencies": {
    "torch": "2.0.1",
    "triton": "23.06"
  },
  "ab_test_id": "exp_ranker_v3_2026q3"
}
```

**版本管理的常见做法:**

| 工具 | 特点 |
|------|------|
| MLflow | 通用,支持多框架 |
| ModelScope | 阿里开源,国内主流 |
| Weights & Biases | 实验追踪强 |
| 自研 ModelStore | 字节/美团/阿里都有 |

### 1.3 灰度发布

**灰度发布的 4 个阶段:**

```text
训练 → 内部验证 → 离线 A/B → 小流量线上 → 全量上线
```

**灰度流量分配:**

| 阶段 | 流量比例 | 观察时长 | 关键指标 |
|------|----------|----------|----------|
| 内部验证 | 0% | - | 模型本身 AUC/LogLoss |
| 小流量 | 1% | 1-3 天 | 实时 P99、错误率 |
| 中流量 | 10% | 3-7 天 | 核心业务指标 |
| 全量 | 100% | 持续监控 | 全指标 |

**灰度的工程实现:**

```python
# 流量路由:根据 user_id 哈希 + 实验配置分流
class GrayRouter:
    def __init__(self):
        self.experiments = {}  # {exp_id: {layer: ratio}}

    def assign(self, user_id, layer):
        """返回应该走哪个版本"""
        for exp_id, config in self.experiments.items():
            if layer in config:
                bucket = hash(f"{user_id}:{exp_id}") % 100
                if bucket < config[layer]['ratio'] * 100:
                    return config[layer]['target_version']
        return 'production'
```

## 2. 模型导出格式

模型导出是把"训练框架的内部表示"转换成"推理框架能加载的格式"。

### 2.1 SavedModel (TF)

**SavedModel = MetaGraphDef + Variables**,TF 原生格式,包含计算图 + 变量 + 签名。

```python
import tensorflow as tf

# 保存
model = build_model()
tf.saved_model.save(
    model,
    "saved_model/ranker_v1",
    signatures={
        'serving_default': model.serving_fn  # 自定义签名
    }
)

# 签名定义
@tf.function(input_signature=[
    tf.TensorSpec([None, 128], dtype=tf.float32, name='user_features'),
    tf.TensorSpec([None, 64], dtype=tf.float32, name='item_features'),
])
def serving_fn(user_features, item_features):
    return {'ctr': model(user_features, item_features)}
```

**SavedModel 的目录结构:**

```text
saved_model/ranker_v1/
├── saved_model.pb       # MetaGraphDef
├── variables/
│   ├── variables.data   # 变量值
│   └── variables.index  # 变量索引
└── assets/              # 静态资源
```

**优点:** TF 生态最完整,TFServing 直接支持
**缺点:** 跨框架不友好,体积大

### 2.2 TorchScript

**TorchScript = PyTorch 的序列化格式**,支持 Python 子集或直接 trace。

```python
import torch

class Ranker(torch.nn.Module):
    def __init__(self):
        super().__init__()
        self.fc = torch.nn.Linear(128, 1)

    def forward(self, x):
        return torch.sigmoid(self.fc(x))

model = Ranker()
model.eval()

# 方法 1:trace(简单模型)
example = torch.randn(1, 128)
traced = torch.jit.trace(model, example)
traced.save("ranker_traced.pt")

# 方法 2:script(动态控制流)
scripted = torch.jit.script(model)
scripted.save("ranker_scripted.pt")

# 加载
loaded = torch.jit.load("ranker_traced.pt")
```

**优点:** PyTorch 官方支持,体积小
**缺点:** 部分算子不支持,动态控制流需 script

### 2.3 ONNX

**ONNX (Open Neural Network Exchange)** = 跨框架模型交换格式,主流框架都支持。

```python
# PyTorch → ONNX
import torch.onnx

model = Ranker()
model.eval()

dummy_input = torch.randn(1, 128)
torch.onnx.export(
    model,
    dummy_input,
    "ranker.onnx",
    input_names=['input'],
    output_names=['output'],
    dynamic_axes={
        'input': {0: 'batch_size'},
        'output': {0: 'batch_size'}
    },
    opset_version=17
)

# 验证 ONNX 模型
import onnx
onnx_model = onnx.load("ranker.onnx")
onnx.checker.check_model(onnx_model)

# 测试推理
import onnxruntime as ort
import numpy as np

sess = ort.InferenceSession("ranker.onnx")
output = sess.run(None, {'input': np.random.randn(10, 128).astype(np.float32)})
```

**ONNX Runtime 推理性能:**

| 模型 | PyTorch Eager | PyTorch JIT | ONNX Runtime (CPU) | ONNX Runtime (GPU) |
|------|---------------|-------------|---------------------|---------------------|
| BERT-base | 200ms | 100ms | 50ms | 8ms |
| ResNet-50 | 50ms | 30ms | 20ms | 3ms |
| DIN (小型) | 30ms | 20ms | 10ms | 2ms |

**优点:** 跨框架、性能好、生态完善
**缺点:** 动态 shape 控制流支持有限

### 2.4 TensorRT / OpenVINO

**TensorRT = NVIDIA GPU 推理优化引擎**,支持 FP16/INT8 量化、层融合、内核自动调优。

```python
# ONNX → TensorRT 转换
import tensorrt as trt

logger = trt.Logger(trt.Logger.WARNING)
builder = trt.Builder(logger)
network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
parser = trt.OnnxParser(network, logger)

with open("ranker.onnx", "rb") as f:
    parser.parse(f.read())

config = builder.create_builder_config()
config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 1 << 30)  # 1GB
config.set_flag(trt.BuilderFlag.FP16)  # 启用 FP16

engine = builder.build_serialized_network(network, config)
with open("ranker.trt", "wb") as f:
    f.write(engine)
```

**TensorRT 的优化手段:**

| 优化 | 说明 | 加速比 |
|------|------|--------|
| 层融合 (Layer Fusion) | 多个算子合并成一个 kernel | 1.5-2x |
| 内核自动调优 | 选择最优 CUDA 实现 | 1.2-1.5x |
| FP16/INT8 量化 | 降低精度提升吞吐 | 1.5-4x |
| 动态 Tensor | 减少显存占用 | 1.2x |
| 多流并行 | 多个 stream 并行 | 1.5-2x |

**OpenVINO = Intel CPU 推理优化引擎**,适合 X86 部署。

```python
# ONNX → OpenVINO IR
from openvino.runtime import Core
from openvino.tools import mo

# 转换
ov_model = mo.convert_model("ranker.onnx", model_name="ranker")
from openvino.runtime import serialize
serialize(ov_model, "ranker.xml", "ranker.bin")

# 推理
core = Core()
compiled = core.compile_model("ranker.xml", "CPU")
output_layer = compiled.output(0)
result = compiled([input_data])[output_layer]
```

### 2.5 模型转换实战

**典型转换链路:**

```text
PyTorch → ONNX → TensorRT (GPU 推理)
                 → OpenVINO (CPU 推理)
                 → ONNX Runtime (跨平台)
```

**一个完整的转换工具:**

```python
class ModelConverter:
    """统一的模型转换工具"""

    @staticmethod
    def pytorch_to_onnx(model, dummy_input, output_path, input_names, output_names):
        model.eval()
        torch.onnx.export(
            model, dummy_input, output_path,
            input_names=input_names,
            output_names=output_names,
            dynamic_axes={'input': {0: 'batch'}},
            opset_version=17
        )
        return output_path

    @staticmethod
    def onnx_to_tensorrt(onnx_path, trt_path, fp16=True, int8=False, calib_data=None):
        """ONNX → TensorRT"""
        logger = trt.Logger(trt.Logger.WARNING)
        builder = trt.Builder(logger)
        network = builder.create_network(1 << int(trt.NetworkDefinitionCreationFlag.EXPLICIT_BATCH))
        parser = trt.OnnxParser(network, logger)

        with open(onnx_path, "rb") as f:
            if not parser.parse(f.read()):
                for i in range(parser.num_errors):
                    print(parser.get_error(i))
                raise RuntimeError("Failed to parse ONNX")

        config = builder.create_builder_config()
        config.set_memory_pool_limit(trt.MemoryPoolType.WORKSPACE, 1 << 30)
        if fp16:
            config.set_flag(trt.BuilderFlag.FP16)
        if int8 and calib_data:
            config.set_flag(trt.BuilderFlag.INT8)
            # 设置 INT8 校准器(略)

        engine = builder.build_serialized_network(network, config)
        with open(trt_path, "wb") as f:
            f.write(engine)
        return trt_path

    @staticmethod
    def onnx_to_openvino(onnx_path, output_dir):
        """ONNX → OpenVINO IR"""
        from openvino.tools import mo
        from openvino.runtime import serialize
        ov_model = mo.convert_model(onnx_path)
        serialize(ov_model, f"{output_dir}/model.xml", f"{output_dir}/model.bin")
        return output_dir
```

**转换中的常见坑:**

1. **动态 shape**:某些算子不支持动态轴,需要用 dynamic_axes 或固定 batch
2. **自定义算子**:PyTorch 自定义算子 ONNX 不支持,需要注册 ONNX op
3. **控制流**:Python 的 if/for 不能直接导出,需要 trace 或重写
4. **混合精度**:模型训练时是 FP32,转换时要明确指定目标精度
5. **校准数据**:INT8 量化必须提供有代表性的校准数据,否则精度爆炸

## 3. 在线推理优化

在线推理的核心约束:**延迟 < 100ms(精排)**,**吞吐 > 1 万 QPS(单实例)**,**效果不能掉**。

### 3.1 延迟目标设定

**各阶段的延迟预算:**

| 阶段 | 延迟预算 | 失败容忍 |
|------|----------|----------|
| API 网关 | 5ms | 不可失败 |
| 召回 | 30ms | 局部失败可降级 |
| 粗排 | 10ms | 失败用召回分数兜底 |
| 精排 | 50ms | 失败用粗排兜底 |
| 重排 | 5ms | 失败用精排兜底 |
| 总 RT | < 100ms | 必须 |

**延迟预算的分级监控:**

```python
# OpenTelemetry 风格的延迟埋点
from opentelemetry import trace

tracer = trace.get_tracer("recsys")

def recall(user_ctx):
    with tracer.start_as_current_span("recall") as span:
        span.set_attribute("user_id", user_ctx.user_id)
        # ... 召回逻辑
        span.set_attribute("candidates", len(candidates))
```

### 3.2 批处理 (Batching)

**批处理 = 把多个请求合并成一个 batch**,GPU 推理的标配。

**为什么批处理能提速?**

GPU 的并行性远高于 CPU,但 GPU 调用有"启动开销"(launch overhead)。一次调用 batch=64 比 64 次调用 batch=1 快 5-10 倍。

**静态 vs 动态批处理:**

| 模式 | 说明 | 优点 | 缺点 |
|------|------|------|------|
| 静态 | 固定 batch_size | 简单 | 长尾延迟差 |
| 动态 | 根据流量动态合并 | GPU 利用率高 | 实现复杂 |

**Triton 动态批处理配置:**

```protobuf
dynamic_batching {
  preferred_batch_size: [32, 64, 128]  # 优先这些 batch
  max_queue_delay_microseconds: 5000   # 最长等 5ms
}
```

**关键参数解释:**

- `preferred_batch_size`:优选的 batch 大小,Triton 会优先攒到这个大小再推理
- `max_queue_delay_microseconds`:最长等待时间,防止长尾延迟

**自适应批处理:**

```python
class AdaptiveBatcher:
    """根据当前负载动态调整 batch_size"""
    def __init__(self, max_batch=128, max_wait_ms=10):
        self.queue = asyncio.Queue()
        self.max_batch = max_batch
        self.max_wait_ms = max_wait_ms

    async def submit(self, request):
        future = asyncio.Future()
        await self.queue.put((request, future))
        return await future

    async def _worker(self):
        while True:
            batch = []
            futures = []
            deadline = time.time() + self.max_wait_ms / 1000

            while len(batch) < self.max_batch and time.time() < deadline:
                timeout = max(0, deadline - time.time())
                try:
                    req, fut = await asyncio.wait_for(self.queue.get(), timeout=timeout)
                    batch.append(req)
                    futures.append(fut)
                except asyncio.TimeoutError:
                    break

            if batch:
                results = await self._infer_batch(batch)
                for fut, result in zip(futures, results):
                    fut.set_result(result)
```

### 3.3 异步推理

**异步推理 = 发起请求后不阻塞,等回调/await**。

```python
import asyncio
import aiohttp

class AsyncRanker:
    """异步精排服务客户端"""
    def __init__(self, endpoint):
        self.endpoint = endpoint
        self.session = None

    async def rank(self, candidates, user_features):
        async with aiohttp.ClientSession() as session:
            payload = {
                'user_features': user_features.tolist(),
                'candidates': [
                    {'item_id': c.item_id, 'features': c.features.tolist()}
                    for c in candidates
                ]
            }
            async with session.post(self.endpoint, json=payload) as resp:
                result = await resp.json()
                return result['scores']
```

**异步的 3 个层次:**

1. **I/O 异步**:网络/磁盘操作异步,不阻塞主线程
2. **推理异步**:多模型/多版本并发推理
3. **流水线异步**:召回/粗排/精排 pipeline 并行(用 `asyncio.gather`)

```python
async def recommendation_pipeline(user_ctx):
    """整条链路并发执行"""
    recall_task = asyncio.create_task(recall(user_ctx))
    user_feat_task = asyncio.create_task(get_user_features(user_ctx.user_id))
    context_task = asyncio.create_task(get_context(user_ctx))

    # 召回与特征获取并发
    candidates, user_features, context = await asyncio.gather(
        recall_task, user_feat_task, context_task
    )

    # 粗排
    coarse_scores = await coarse_rank(candidates, user_features)

    # 精排
    final_scores = await precision_rank(coarse_scores, user_features, context)

    # 重排
    final = rerank(final_scores)

    return final
```

### 3.4 缓存策略

**推理缓存的 4 类:**

| 缓存 | 内容 | TTL | 命中率 |
|------|------|-----|--------|
| 物品 embedding | 物品向量 | 长(小时~天) | 95%+ |
| 用户特征 | 用户画像 | 短(分钟) | 80%+ |
| 模型中间结果 | attention 分数 | 极短(秒) | 30% |
| 推荐结果 | Top-N 列表 | 短(秒~分钟) | 20% |

**物品 embedding 缓存(关键):**

```python
class ItemEmbeddingCache:
    """物品 embedding 的两级缓存:本地 LRU + Redis"""
    def __init__(self, redis_client, local_size=100000):
        self.redis = redis_client
        self.local = LRUCache(local_size)

    def get(self, item_id):
        # 先查本地
        emb = self.local.get(item_id)
        if emb is not None:
            return emb

        # 查 Redis
        cached = self.redis.get(f"item_emb:{item_id}")
        if cached:
            emb = np.frombuffer(cached, dtype=np.float32)
            self.local.put(item_id, emb)
            return emb

        # 实时算
        emb = self._compute_embedding(item_id)
        self.redis.set(f"item_emb:{item_id}", emb.tobytes())
        self.local.put(item_id, emb)
        return emb
```

**推荐结果缓存的注意事项:**

- 不能缓存太久(用户偏好会变)
- 必须考虑上下文(时间、场景、网络)
- 失效策略:TTL + 用户行为触发

### 3.5 模型并行

**模型并行 = 把一个大模型拆分到多个 GPU 上推理**。

**张量并行 (Tensor Parallel):**

把单个矩阵乘法拆分到多张卡:

```python
# 假设 Linear 层权重 W 是 (out_features, in_features)
# 拆分到 4 张卡上
W_chunk_size = out_features // 4
W_local = W[i * W_chunk_size : (i+1) * W_chunk_size]

# 每张卡算自己的输出
y_local = x @ W_local.T  # (batch, out_features/4)

# all-gather 收集所有卡的结果
y = all_gather(y_local)  # (batch, out_features)
```

**流水线并行 (Pipeline Parallel):**

把模型按层拆分到不同卡:

```text
GPU 0: Layer 1-10
GPU 1: Layer 11-20
GPU 2: Layer 21-30
```

**序列并行 (Sequence Parallel):**

把长序列拆分到不同卡,适合超长序列推荐(GR 长序列建模)。

**DeepSpeed 的模型并行配置:**

```python
import deepspeed

ds_config = {
    "train_batch_size": 64,
    "fp16": {"enabled": True},
    "zero_optimization": {
        "stage": 3,  # ZeRO-3: 优化器状态 + 梯度 + 参数都分片
        "offload_optimizer": {"device": "cpu"},
        "offload_param": {"device": "cpu"}
    },
    "tensor_parallel": {
        "tp_size": 4  # 4 路张量并行
    },
    "pipeline_parallel": {
        "pp_size": 2,  # 2 路流水线并行
        "partition_method": "uniform"
    }
}

model_engine, optimizer, _, _ = deepspeed.initialize(
    model=model,
    config=ds_config
)
```

## 4. 推理框架对比

### 4.1 TensorFlow Serving

**TF Serving = TensorFlow 官方推理服务**,基于 gRPC + REST。

```bash
# 启动 TF Serving
tensorflow_model_server \
  --rest_api_port=8501 \
  --grpc_api_port=8500 \
  --model_name=ranker \
  --model_base_path=/models/ranker \
  --enable_batching=true \
  --batching_parameters_file=/config/batching.txt
```

**Batching 配置:**

```text
# batching.txt
max_batch_size { value: 128 }
batch_timeout_micros { value: 5000 }
max_enqueued_batches { value: 1000000 }
num_batch_threads { value: 4 }
```

```python
class MonolithService:
    """字节内部的统一推理服务"""

        self.models = {}
        self.cache = LRUCache(100000)

    def load_model(self, name, version, framework):

        elif framework == 'pt':

        # ... 字节自研的 Blade 引擎

    def predict(self, name, version, inputs):

        cache_key = self._make_key(inputs)
```

### 5.2 显存优化

**显存占用的组成:**


| 组件 | 占总显存比例 | 优化手段 |
|------|--------------|----------|
| 模型权重 | 30% | 量化、剪枝 |
| 优化器状态 | 30% | ZeRO、AdamW |
| 梯度 | 15% | 混合精度、累积 |
| 激活值 | 15% | Gradient Checkpointing |
| 其他 | 10% | 框架开销 |

**显存优化手段:**

**1. 混合精度训练 (AMP):**

```python
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()

for x, y in dataloader:
    with autocast():
        output = model(x)
        loss = criterion(output, y)

    scaler.scale(loss).backward()
    scaler.step(optimizer)
    scaler.update()
    optimizer.zero_grad()
```

**2. Gradient Checkpointing:**

```python
from torch.utils.checkpoint import checkpoint

class CheckpointedModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.layer1 = nn.Linear(1024, 1024)
        self.layer2 = nn.Linear(1024, 1024)
        self.layer3 = nn.Linear(1024, 1024)

    def forward(self, x):
        # 只保存 layer1 和 layer3 的激活,layer2 重计算
        x = self.layer1(x)
        x = checkpoint(self.layer2, x, use_reentrant=False)
        x = self.layer3(x)
        return x
```

### 5.3 量化 (INT8/INT4)

**量化的基本概念:**

```text
FP32: 32 位浮点
FP16: 16 位浮点(半精度)
BF16: 16 位浮点(更大指数,适合训练)
INT8: 8 位整型(推理加速)
INT4: 4 位整型(极限压缩)
```

**量化的 3 种方法:**

| 方法 | 描述 | 精度损失 |
|------|------|----------|
| **PTQ (Post-Training Quantization)** | 训练后量化,无需数据 | 中(0.5-2%) |
| **QAT (Quantization-Aware Training)** | 训练中模拟量化 | 小(<0.5%) |
| **混合精度量化** | 关键层 FP16,其他 INT8 | 极小 |

```python
# 准备校准数据(1000 个有代表性的样本)
calib_data = load_calibration_dataset(n=1000)

    def read_calibration_cache(self):
```

**量化的精度损失控制:**

```python
# 量化误差补偿
def quantization_error_compensation(weight_fp32, weight_int8):
    """对量化误差做补偿"""
    delta = (weight_fp32.max() - weight_fp32.min()) / 256
    quantized = torch.clamp(torch.round(weight_fp32 / delta), -128, 127)
    dequantized = quantized * delta
    error = weight_fp32 - dequantized
    # 把误差累积到下一个权重
    return dequantized, error
```

### 5.4 剪枝与蒸馏

**剪枝 = 去掉不重要的权重/神经元/层**。

| 粒度 | 描述 | 加速比 | 实现难度 |
|------|------|--------|----------|
| 权重剪枝 | 剪掉单个权重 | 1.2-1.5x | 难(稀疏矩阵难加速) |
| 神经元剪枝 | 剪掉整个神经元 | 1.5-2x | 中 |
| 通道剪枝 | 剪掉整个通道 | 2-3x | 易 |
| 层剪枝 | 剪掉整个层(BERT) | 2-5x | 易 |

**蒸馏实战:**

```python
class DistillationLoss(nn.Module):
    """知识蒸馏损失 = α * 硬标签损失 + (1-α) * 软标签损失"""
    def __init__(self, alpha=0.5, T=4):
        super().__init__()
        self.alpha = alpha
        self.T = T
        self.ce = nn.CrossEntropyLoss()
        self.kl = nn.KLDivLoss(reduction='batchmean')

    def forward(self, student_logits, teacher_logits, labels):
        # 硬标签损失(student 学 ground truth)
        hard_loss = self.ce(student_logits, labels)

        # 软标签损失(student 学 teacher 的分布)
        soft_loss = self.kl(
            F.log_softmax(student_logits / self.T, dim=-1),
            F.softmax(teacher_logits / self.T, dim=-1)
        ) * (self.T ** 2)

        return self.alpha * hard_loss + (1 - self.alpha) * soft_loss
```

**蒸馏的工程要点:**

1. **Teacher 必须足够强**:教师模型太差,学生学不到东西
2. **温度 T 的选择**:T=2~10 常见,T 越大,学生越关注 teacher 的相对关系
3. **特征蒸馏**:除了 logits,中间特征也可以蒸馏

```python
# 特征蒸馏(简化)
def feature_distillation_loss(student_features, teacher_features):
    """对齐中间层特征"""
    loss = 0
    for s, t in zip(student_features, teacher_features):
        # 1x1 卷积对齐通道
        s_proj = nn.Conv2d(s.shape[1], t.shape[1], 1).to(s.device)(s)
        loss += F.mse_loss(s_proj, t)
    return loss
```

### 7.1 蓝绿部署

**缺点:** 资源消耗大(两倍)

### 7.2 金丝雀发布

**金丝雀发布 = 新版本先给小比例流量,逐步放量**。

```text

```

**放量策略:**

| 阶段 | 流量比例 | 持续时间 | 决策标准 |
|------|----------|----------|----------|
| 1 | 1% | 1 小时 | 无错误,延迟正常 |
| 2 | 5% | 6 小时 | 核心指标无显著下降 |

**自动放量逻辑:**

```python
class CanaryController:
    """自动金丝雀发布控制器"""
    def __init__(self, model_name, health_checks):
        self.model_name = model_name
        self.health_checks = health_checks
        self.current_traffic = 0.01  # 当前比例

    def check_and_advance(self):
        """检查健康度,决定是否放量"""
        results = {check: check.run() for check in self.health_checks}

        if all(r.passed for r in results.values()):
            self.current_traffic *= 2
            self.current_traffic = min(self.current_traffic, 1.0)
            return True, f"Advanced to {self.current_traffic*100}%"
        else:
            return False, f"Blocked: {results}"
```

### 8.1 字节抖音模型升级流程

```text
1. 训练完成 → 内部 AUC 评估
    ↓
```

## 9. 与 RL/GR 的连接

### 9.1 GR 模型在线推理挑战

**GR (Generative Recommendation) = 用生成式模型做推荐**,核心是用 LLM/Transformer 一次性生成 Top-K 物品 ID 序列。

**典型架构:**

```text
用户行为序列 → [Transformer] → [生成 Top-K 物品序列]
                              (类似 NLP 的 seq2seq)
```

**推理挑战:**

1. **超长序列**:用户历史可能有 10000+ 物品,Transformer 计算量 O(n²)
2. **生成成本**:自回归生成 100 个 token,需要 100 次 forward
3. **KV cache**:超长序列的 KV cache 可能爆显存

**优化方案:**

```python
# GR 模型推理的关键优化
class GRInferenceOptimizer:
    def __init__(self, model, max_seq_len=8192):
        self.model = model
        self.kv_cache = {}

    @torch.inference_mode()
    def generate(self, user_history, max_new_tokens=100):
        # 1. 预计算用户历史的 KV cache(只算一次)
        if user_history.id not in self.kv_cache:
            self.kv_cache[user_history.id] = self.model.encode(
                user_history, return_kv=True
            )
        past_kv = self.kv_cache[user_history.id]

        # 2. 自回归生成(每次用 KV cache)
        generated = []
        for _ in range(max_new_tokens):
            logits = self.model.decode_step(past_kv)
            next_token = sample(logits)
            generated.append(next_token)

            # 提前停止
            if next_token == EOS_TOKEN:
                break

        return generated
```

### 9.2 NEZHA 投机解码案例

**NEZHA = NEZHA: A Model-Zoo-Hub for Generative Recommendation**,字节 2025 提出的投机解码方案。

**投机解码原理:**

用一个小的"draft model"先生成候选,再用大模型"verify"是否采纳,加速生成 2-3 倍。

```python
class SpeculativeDecoder:
    """投机解码:draft + verify"""
    def __init__(self, draft_model, target_model, k=4):
        self.draft = draft_model       # 小模型,快速生成
        self.target = target_model     # 大模型,精确验证
        self.k = k                     # 投机长度

    @torch.inference_mode()
    def generate(self, prompt, max_new_tokens=100):
        # 1. Draft 阶段:小模型生成 k 个候选
        draft_tokens = self.draft.generate(prompt, max_new_tokens=self.k)

        # 2. Target 阶段:大模型一次验证 k 个
        logits = self.target(prompt + draft_tokens)

        # 3. 接受/拒绝策略
        accepted = 0
        for i in range(self.k):
            p_draft = softmax(self.draft_logits[i])
            p_target = softmax(logits[i])
            # Metropolis 接受准则
            acceptance = min(1.0, p_target[draft_tokens[i]] / p_draft[draft_tokens[i]])
            if random.random() < acceptance:
                accepted += 1
            else:
                break

        # 4. 用 target 模型重新采样被拒绝的位置
        return draft_tokens[:accepted] + self.target.resample(...)
```

**投机解码的收益:**

| 模型大小 | 普通生成 | 投机解码 | 加速比 |
|----------|----------|----------|--------|
| 7B | 200ms | 80ms | 2.5x |
| 13B | 400ms | 150ms | 2.7x |
| 70B | 2000ms | 700ms | 2.9x |

**在 GR 推荐中的应用:**

- Draft model:小型推荐模型(快速但精度一般)
- Target model:大型 GR 模型(精确但慢)
- 投机解码:用 draft 模型快速生成候选,target 模型批量验证

### 推理框架选择决策树

```text
Q1: 模型是 LLM 吗?

    是 → Triton + TensorRT (GPU) / OpenVINO (CPU)
    否 → ONNX Runtime
```

### 部署检查清单

上线一个模型前,必须验证:

- [ ] **延迟**:P99 ≤ 业务阈值
- [ ] **吞吐**:QPS 满足峰值需求
- [ ] **效果**:离线 AUC 与训练时一致(±0.005)
- [ ] **特征一致性**:在线特征 schema 与训练一致
- [ ] **异常输入**:空输入、维度错误、极端值的处理
- [ ] **监控**:P50/P99/QPS/错误率全部接入
- [ ] **告警**:延迟/错误率超阈值自动告警
- [ ] **回滚**:一键回滚脚本可用
- [ ] **日志**:推理日志可追溯
- [ ] **文档**:模型卡片 (model card) 已写

### 性能调优黄金法则

1. **先测量,后优化**:profile 找到瓶颈再动手
2. **量化/混合精度是免费的午餐**:默认开 FP16
3. **动态 batch 是必须的**:Triton dynamic_batching
4. **缓存能解决一切**:物品 embedding、用户特征、推荐结果
5. **GPU 利用率 < 60% 时考虑合部署**:把多个小模型塞一张 GPU
