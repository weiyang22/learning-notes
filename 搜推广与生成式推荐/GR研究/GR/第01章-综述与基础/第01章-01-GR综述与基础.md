# 生成式推荐综述：从基础范式到商业落地

> Generative Recommendation: From Foundational Paradigms to Industrial Deployment

---

## 摘要

生成式推荐（Generative Recommendation, GR）是推荐系统领域的前沿方向，它将传统推荐中的"判别-排序"范式重构为"生成-匹配"范式。本文从发展历程、核心技术、生成式检索、商业优化四个维度，系统梳理生成式推荐的方法论体系。内容涵盖基于 Transformer 的序列生成、扩散推荐模型、大语言模型驱动的推荐系统、语义 ID 编码与端到端生成式检索，以及面向工业部署的推理加速、级联架构与冷启动优化。每个算法模块均配有理推导和结构图示，旨在为该领域的研究者与工程师提供一份完整的技术参考。

**关键词**：生成式推荐；扩散模型；大语言模型；生成式检索；序列推荐；推荐系统工程

## 1. 引言

### 1.1 背景与动机

推荐系统是现代互联网服务的核心组件，广泛部署于电子商务、短视频、新闻推送、音乐流媒体等场景。经典推荐系统通常采用**两阶段级联架构**：**召回（Retrieval）** 阶段从海量候选池中筛选出数百个候选物品，再由**精排（Ranking）** 阶段精细打分排序。这一范式在过去十年取得了巨大成功，但也暴露了根本性局限：

1. **召回与精排的目标割裂**：召回阶段使用的向量检索或图索引与精排阶段的深度模型优化目标不一致，导致信息损失。
2. **特征工程依赖**：传统方法高度依赖人工设计的交叉特征与统计信号，难以自动捕获用户行为中的高阶语义。
3. **交互范式受限**：推荐结果以"列表打分排序"的形式呈现，缺乏对用户意图的主动推理与内容生成能力。

生成式推荐的提出正是为了突破这些限制。其核心思想是：**将推荐任务重新定义为条件生成问题**——给定用户的历史行为序列，生成一个有序的物品序列或直接生成用户的下一项交互。这一视角的转变带来了几项关键能力：

- **端到端的统一建模**：召回与排序可在一个生成式框架下联合优化。
- **语义理解与推理**：借助预训练语言模型的世界知识，实现超越行为模式的语义级推荐。
- **多任务泛化**：同一生成式架构可适配推荐、搜索、对话等不同交互形式。

### 1.2 生成式推荐的定义与范畴

广义上的生成式推荐包含以下三个层次：

| 层次 | 定义 | 代表方法 |
| :--- | :--- | :--- |
| **序列生成** | 将推荐视为用户行为序列中下一项的条件预测 | SASRec, BERT4Rec |
| **分布生成** | 学习用户偏好的潜在分布，从中采样推荐结果 | Multi-VAE, DiffRec |
| **语义生成** | 利用预训练语言模型生成推荐理由或直接输出物品标识 | P5, TIGER, LlamaRec |

### 1.3 与传统推荐范式的对比

| 维度 | 传统判别式推荐 | 生成式推荐 |
| :--- | :--- | :--- |
| 建模目标 | $P(y_{ui}=1 \mid u,i)$ | $P(i_{t+1} \mid i_1,...,i_t)$ |
| 输出形式 | 分数/概率 | 序列/分布/语义文本 |
| 召回策略 | 向量检索+近似最近邻 | 自回归解码/扩散采样 |
| 特征利用 | 人工特征交叉 | 端到端语义表示 |
| 扩展性 | 独立训练召回与排序 | 统一的生成框架 |

## 2. 发展历程

### 2.1 萌芽期：早期序列推荐 (2015-2018)

推荐系统中最朴素的"生成"概念表现为**预测下一个交互物品**。马尔可夫链模型（FPMC, 2010）首次将用户行为建模为转移概率矩阵。然而，真正的转折来自循环神经网络的引入：

- **GRU4Rec** (Hidasi et al., 2015) 首次使用 GRU 对用户点击序列建模，在会话推荐中取得显著提升。
- **Caser** (Tang & Wang, 2018) 使用卷积神经网络捕捉序列中的局部跳转模式。
- 这一时期的模型本质上仍是**判别式**的，但"预测下一项"的任务设定已具备生成式雏形。

### 2.2 爆发期：Transformer与自编码器 (2018-2022)

自注意力机制的引入彻底改变了序列推荐的建模方式：

- **SASRec** (Kang & McAuley, 2018) 使用单向 Transformer 从左到右建模行为序列，以自回归方式预测下一项。其核心公式为：
  $$\text{Attention}(Q,K,V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d}} + M\right)V$$
  其中因果掩码 $M$ 确保每个位置只能看到历史物品。

- **BERT4Rec** (Sun et al., 2019) 使用双向 Transformer 与遮住语言模型（Cloze task）训练：
  $$\mathcal{L} = -\sum_{i_t \in \mathcal{M}} \log P(i_t = i_t^* \mid \mathcal{I}_{\setminus \mathcal{M}})$$
  其中 $\mathcal{M}$ 表示被随机遮盖的位置集合。

- **Multi-VAE** (Liang et al., 2018) 引入变分自编码器学习用户隐式反馈的生成式分布：
  $$\mathcal{L}_{\text{ELBO}} = \mathbb{E}_{q_\phi(z|u)}[\log p_\theta(\mathbf{x}_u | z)] - \beta \cdot \text{KL}(q_\phi(z|u) \| p(z))$$
  其中 $z$ 是用户隐变量，$\mathbf{x}_u$ 表示用户 $u$ 对所有物品的交互向量。

这一时期的技术迭代可概括为：

```text
GRU4Rec → Caser → SASRec → BERT4Rec → BERT4Rec+ → SRGNN
                         ↓
                    Multi-VAE → RecVAE → MacridVAE
                         ↓
                xDeepFM → DCN-v2 → AutoInt + 序列交叉
```

### 2.3 变革期：扩散模型与大语言模型 (2022-至今)

2022 年以来，两个技术浪潮深刻影响了生成式推荐：

**扩散推荐模型**：将去噪扩散概率模型（DDPM）引入推荐领域，将用户-物品交互矩阵视为带噪声的结构化数据，通过逐步去噪生成用户偏好的完整向量。

**大语言模型驱动的推荐**：利用 LLM 的上下文理解与推理能力，将推荐任务嵌入自然语言指令框架中。代表性路线包括：

- **ID 映射路线**：为物品学习语义 ID（TIGER, 2023），使用编码器-解码器架构生成目标物品 ID。
- **自然语言路线**：直接将推荐表达为文本到文本的任务（P5, FLAN-T5），所有输入输出均序列化为文本。
- **混合路线**：结合传统 ID 特征与 LLM 语义表征（RecLLM, LlamaRec）。

```text
SASRec/BERT4Rec (判别-序列预测)
    ↓
Multi-VAE, DiffRec (隐变量/分布生成)
    ↓
P5, TIGER, GENRE (LLM + 序列生成)
    ↓
ChatGPT-Rec, LlamaRec (大模型指令调优)
    ↓
Agent4Rec, RecAgent (工具使用+多步推理)
```

## 3. 核心技术方法

### 3.1 基于 Transformer 的序列生成

#### 3.1.1 SASRec：自回归序列推荐

**模型结构**：

```text
User Sequence: [i_1, i_2, ..., i_t]
     ↓  Embedding Lookup + Positional Encoding
   [e_1, e_2, ..., e_t]
     ↓
  ┌───────────────────────────────────────────┐
  │    Multi-Head Self-Attention (Causal)     │
  │    LayerNorm → Attention → LayerNorm      │
  │    Point-wise Feed-Forward Network        │
  │    Dropout + Residual Connection          │
  └───────────────────────────────────────────┘
     ↓  × L (堆叠 L 层)
   [h_1, h_2, ..., h_t]
     ↓  Projection
   [s_1, s_2, ..., s_t]   (每个位置的分数向量)
     ↓  Softmax
   P(i_{t+1} = k | i_1,...,i_t) = softmax(s_t)_k
```

**数学推导**：

SASRec 的每一层 Transformer block 的计算过程如下：

**步骤 1：缩放点积注意力**

给定输入序列的嵌入矩阵 $E \in \mathbb{R}^{t \times d}$，通过线性变换得到 Query、Key、Value：

$$Q = EW_Q, \quad K = EW_K, \quad V = EW_V$$

其中 $W_Q, W_K, W_V \in \mathbb{R}^{d \times d_k}$ 为可学习参数，$d_k = d/h$ 为每个注意力头的维度。

注意力输出为：

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^\top}{\sqrt{d_k}} + M\right) V$$

因果掩码 $M$ 定义为：

$$M_{ij} = \begin{cases} 0, & i \geq j \\ -\infty, & i < j \end{cases}$$

确保位置 $i$ 只能关注到位置 $\leq i$ 的历史信息。

**步骤 2：多头注意力**

$$h_i = \text{Concat}(\text{head}_1, \text{head}_2, ..., \text{head}_h) W_O$$

其中 $\text{head}_k = \text{Attention}(QW_Q^k, KW_K^k, VW_V^k)$，$W_O \in \mathbb{R}^{hd_k \times d}$。

**步骤 3：前馈网络**

$$\text{FFN}(x) = \text{GELU}(xW_1 + b_1)W_2 + b_2$$

**步骤 4：残差连接与层归一化**

$$x' = \text{LayerNorm}(x + \text{Attention}(x))$$
$$x'' = \text{LayerNorm}(x' + \text{FFN}(x'))$$

**优化目标**：

SASRec 使用二元交叉熵（Binary Cross-Entropy）损失：

$$\mathcal{L} = -\sum_{t=1}^{T-1} \left[\log \sigma(\hat{y}_{t}^+) + \sum_{j \in \mathcal{N}} \log(1 - \sigma(\hat{y}_{t}^-))\right]$$

其中 $\hat{y}_t = \text{FFN}(h_t) \cdot \text{ItemEmb}[i_{t+1}]$，$\mathcal{N}$ 是负样本集合。现代实现在此基础上广泛采用 **交叉熵损失**（对整个物品空间 softmax）或 **InfoNCE 对比损失**：

$$\mathcal{L}_{\text{InfoNCE}} = -\log \frac{\exp(\text{sim}(h_t, e_{t+1})/\tau)}{\sum_{j \in \mathcal{B}} \exp(\text{sim}(h_t, e_j)/\tau)}$$

其中 $\tau$ 是温度系数，$\mathcal{B}$ 为批内样本集合。

#### 3.1.2 BERT4Rec：双向序列理解

**核心差异**：与 SASRec 的因果自回归不同，BERT4Rec 使用双向 Transformer 和 Cloze 训练目标，在训练时随机遮蔽序列中的物品，要求模型预测被遮蔽的物品。

**输入表示**：

```text
输入序列：[i_1, [MASK], i_3, i_4, [MASK], i_6]
位置编码：[p_1,  p_2,   p_3, p_4,  p_5,   p_6]
 输出目标：[?,  i_2^* , ?,   ?,   i_5^*,  ?]
```

**损失函数**：

$$\mathcal{L} = -\frac{1}{|\mathcal{M}|} \sum_{t \in \mathcal{M}} \log P(i_t = i_t^* \mid \mathcal{I}_{\setminus \mathcal{M}})$$

其中 $\mathcal{M}$ 表示被遮蔽的位置集合。推理时，BERT4Rec 在序列末尾添加 `[MASK]` 标记，通过一次前向传播同时预测多项候选（实际使用自回归逐步解码）。

#### 3.1.3 位置编码与序列顺序建模

序列推荐中物品的顺序至关重要。SASRec 使用**可学习的位置编码**：

$$\text{PE}(t) = \text{Embedding}_{\text{pos}}[t] \in \mathbb{R}^d$$

最近的改进工作**FMLP-Rec** 使用傅里叶变换替代注意力机制：

$$\text{FFT}(x)_i = \sum_{j=0}^{T-1} x_j \cdot e^{-2\pi i \cdot j \cdot i / T}$$

而 **SRFormer** 引入了相对位置编码，使模型能更好泛化到不同长度的序列。

### 3.2 基于扩散模型的生成式推荐

#### 3.2.1 DiffRec：去噪扩散推荐

**核心思想**：扩散模型包含两个过程：(1) 前向过程——逐步向数据添加高斯噪声直至纯噪声；(2) 反向过程——学习从噪声逐步去噪恢复原始数据。DiffRec 将用户的历史交互向量视为"数据"，通过扩散过程生成用户的完整偏好分布。

**模型结构概览**：

```text
┌─────────────────── 扩散过程概览 ───────────────────┐

  前向过程（噪声注入）
  x₀ → x₁ → x₂ → ... → xₜ → xₜ₊₁ → ... → x_T  ≈  N(0,I)
  用户  ↑    ↑                  ↑
  交互   q(xₜ|xₜ₋₁)  =  N(√αₜ xₜ₋₁, (1-αₜ)I)

  反向过程（去噪生成）
  x_T → ... → x̂ₜ → x̂ₜ₋₁ → ... → x̂₀
  纯噪声 ↑         ↑
         p_θ(xₜ₋₁|xₜ)  =  N(μ_θ(xₜ,t), Σ_θ(xₜ,t))

  x₀：用户 u 的原始交互向量
  x_T：纯高斯噪声

└───────────────────────────────────────────────────────┘
```

**前向扩散过程**：

定义用户的原始交互为 $\mathbf{x}_0 \in \mathbb{R}^N$（$N$ 个物品），包含隐式反馈（如点击=1, 未点击=0）。前向过程逐步添加噪声：

$$q(\mathbf{x}_t \mid \mathbf{x}_{t-1}) = \mathcal{N}(\mathbf{x}_t; \sqrt{\alpha_t} \mathbf{x}_{t-1}, (1 - \alpha_t) \mathbf{I})$$

其中 $\alpha_t \in (0,1)$ 是噪声调度参数，随 $t$ 单调递减。利用重参数化技巧，可直接计算任意 $t$ 步的噪声分布：

$$\mathbf{x}_t = \sqrt{\bar{\alpha}_t} \mathbf{x}_0 + \sqrt{1 - \bar{\alpha}_t} \epsilon, \quad \epsilon \sim \mathcal{N}(0, \mathbf{I})$$

其中 $\bar{\alpha}_t = \prod_{s=1}^t \alpha_s$。

**反向去噪过程**：

扩散模型学习反向转移 $p_\theta(\mathbf{x}_{t-1} \mid \mathbf{x}_t)$。根据 DDPM 推导，这等价于训练神经网络 $\epsilon_\theta(\mathbf{x}_t, t)$ 来预测添加的噪声 $\epsilon$：

$$\mathcal{L}_{\text{simple}} = \mathbb{E}_{t, \mathbf{x}_0, \epsilon} \left[ \left\| \epsilon - \epsilon_\theta(\sqrt{\bar{\alpha}_t} \mathbf{x}_0 + \sqrt{1 - \bar{\alpha}_t} \epsilon, t) \right\|^2 \right]$$

在推理时，从纯噪声 $\mathbf{x}_T \sim \mathcal{N}(0, \mathbf{I})$ 开始，迭代进行 $T$ 步去噪：

$$\mathbf{x}_{t-1} = \frac{1}{\sqrt{\alpha_t}} \left( \mathbf{x}_t - \frac{1 - \alpha_t}{\sqrt{1 - \bar{\alpha}_t}} \epsilon_\theta(\mathbf{x}_t, t) \right) + \sigma_t \mathbf{z}$$

其中 $\mathbf{z} \sim \mathcal{N}(0, \mathbf{I})$ 在 $t>1$ 时加入随机噪声，$\sigma_t$ 控制噪声量。

**推荐生成**：

去噪完成后，$\mathbf{x}_0$ 即为生成的用户偏好分数向量。对 $x_0$ 中所有未交互物品的分数降序排列，取 Top-K 作为推荐候选。

$$\text{Top-K} = \arg\max_{i \in \mathcal{I} \setminus \mathcal{I}_u} [\mathbf{x}_0]_i$$

#### 3.2.2 DreamRec：面向检索的扩散推荐

DreamRec (Ding et al., 2023) 进一步将扩散模型用于**极致检索生成**——将全量物品的 ID 映射到潜在空间，在生成过程中直接产生候选物品列表。

**技术要点**：

1. 使用预训练物品编码器 $f_{\text{enc}}$ 将物品映射到潜在空间：$\mathbf{h}_i = f_{\text{enc}}(i)$。
2. 对用户的偏好向量 $\mathbf{z}_u$ 执行扩散生成。
3. 在潜在空间中用最近邻检索找到匹配的物品。

相较于 DiffRec 在全物品空间操作，DreamRec 在低维潜在空间生成，显著降低计算成本。

#### 3.2.3 扩散推荐的变体与改进

| 方法 | 创新点 | 关键公式 |
| :--- | :--- | :--- |
| **CDiffRec** | 引入条件信息（时间、上下文） | $\epsilon_\theta(\mathbf{x}_t, t, c)$ |
| **LDiffRec** | 将生成空间压缩到低维隐空间 | $\mathbf{z}_t = \sqrt{\bar{\alpha}_t}E(\mathbf{x}_0) + \sqrt{1-\bar{\alpha}_t}\epsilon$ |
| **DiffuSeq** | 离散扩散（多项分布） | $q(\mathbf{x}_t \mid \mathbf{x}_{t-1}) = \text{Cat}((1-\beta_t)\mathbf{x}_{t-1} + \beta_t/K)$ |
| **DiffRec+** | 减少去噪步数（DDIM 加速） | $\mathbf{x}_{t-\Delta} = \sqrt{\bar{\alpha}_{t-\Delta}}\hat{\mathbf{x}}_0 + \sqrt{1-\bar{\alpha}_{t-\Delta}}\epsilon_\theta$ |

**去噪步数减少（DDIM 风格推理）**：

传统 DDPM 需要 1000 步采样，DDIM 通过引入非马尔可夫前向过程将其减少到 50-100 步：

$$\mathbf{x}_{t-\Delta} = \sqrt{\bar{\alpha}_{t-\Delta}} \left( \frac{\mathbf{x}_t - \sqrt{1 - \bar{\alpha}_t} \epsilon_\theta^{(t)}}{\sqrt{\bar{\alpha}_t}} \right) + \sqrt{1 - \bar{\alpha}_{t-\Delta}} \epsilon_\theta^{(t)}$$

### 3.3 基于大语言模型的生成式推荐

#### 3.3.1 范式概述

LLM 在推荐系统中的角色可分为三个层次：

```text
层次一：LLM 作为特征编码器
   预训练 LLM → 文本编码 → 物品表示 → 送入传统推荐模型
   例：BERT-4Rec (使用 BERT 编码物品描述)

层次二：LLM 作为推荐引擎
   推荐指令 → LLM → 推荐结果/排序列表
   例：P5, Chat-Rec, LlamaRec

层次三：LLM 作为推理代理
   多轮对话 → LLM + 工具调用 → 综合推荐决策
   例：Agent4Rec, RecAgent
```

#### 3.3.2 P5：万能推荐模型

P5 (Geng et al., 2022) 提出了"一切推荐任务都是文本生成"的统一范式。

**输入输出格式化**：

$$ \text{Input} = "\text{User: } u \text{ has watched [SEP]} i_1, i_2, ..., i_t" $$
$$ \text{Output} = "\text{[Target]} i_{t+1}" $$

P5 将用户 ID、物品 ID、评分等所有信号映射到共享的词汇表中，使用 T5 架构进行序列到序列的训练：

$$\mathcal{L} = -\log P(\mathbf{y} \mid \mathbf{x}) = -\sum_{j=1}^{|\mathbf{y}|} \log P(y_j \mid y_{<j}, \mathbf{x})$$

其中 $\mathbf{x}$ 是格式化的输入文本，$\mathbf{y}$ 是目标输出序列。

**多任务训练**：P5 将如下任务统一在同一架构下：

- 序列推荐：历史 → 下一项
- 评分预测：用户+物品 → 评分文本
- 解释生成：用户+物品 → 推荐理由
- 直接推荐：用户 → 推荐列表

**局限性**：P5 将物品映射为离散 token 的组合（如 `item_12345`），当物品数超过百万时，词汇表急剧膨胀，训练不可行。

#### 3.3.3 TIGER：语义 ID 生成

TIGER (Wang et al., 2023) 通过分层的**语义 ID 编码**解决了物品 ID 生成的可扩展性问题。

**语义 ID 编码**：

```text
┌─────────────────────────────────────────────────────┐
│ 语义 ID 码本生成                                     │
│                                                      │
│  物品文本描述 (Title + Category + Brand)              │
│      ↓                                               │
│  文本编码器 (T5 Encoder) → h_i ∈ ℝ^d                │
│      ↓                                               │
│  RQ-VAE (残差量化)                                    │
│  ┌─────────────────────────────────────────┐         │
│  │  Level 1: h_i → L1 Code c₁ ∈ C₁        │         │
│  │            r₁ = h_i - q(c₁)             │         │
│  │  Level 2: r₁ → L2 Code c₂ ∈ C₂         │         │
│  │            r₂ = r₁ - q(c₂)             │         │
│  │  Level 3: r₂ → L3 Code c₃ ∈ C₃         │         │
│  └─────────────────────────────────────────┘         │
│      ↓                                               │
│  物品 ID = [c₁, c₂, c₃] ∈ [K]³ (K 为码本大小)        │
│                                                      │
└─────────────────────────────────────────────────────┘
```

**残差量化（RQ-VAE）数学推导**：

给定物品 $i$ 的文本表示向量 $\mathbf{h}_i \in \mathbb{R}^d$，$L$ 个码本 $\{\mathcal{C}_l\}_{l=1}^L$，每个码本包含 $K$ 个可学习向量 $\{e_{l,k} \in \mathbb{R}^d\}_{k=1}^K$。

第 $l$ 层的量化过程：

$$c_l(i) = \arg\min_{k \in [K]} \| e_{l,k} - \mathbf{r}_{l-1}(i) \|^2$$

其中 $\mathbf{r}_0(i) = \mathbf{h}_i$，$\mathbf{r}_{l}(i) = \mathbf{r}_{l-1}(i) - e_{l, c_l(i)}$ 为残差。

物品 $i$ 的语义 ID 为 $[c_1(i), c_2(i), ..., c_L(i)]$，码本总大小为 $K \cdot L$ 而非 $K^L$。

**生成过程**：

TIGER 使用编码器-解码器 Transformer：

```text
用户行为序列: [i_1, i_2, ..., i_t]
   ↓ 将物品映射为语义 ID 序列
语义 ID: [c₁(i₁)...c_L(i₁), c₁(i₂)...c_L(i₂), ..., c₁(i_t)...c_L(i_t)]
   ↓
Encoder (T5 Encoder) → 上下文表示 H_enc
   ↓
Decoder (T5 Decoder) 自回归生成目标语义 ID:
   P(c_L(i_{t+1}), ..., c₁(i_{t+1}) | H_enc)
   ↓
目标物品 = 通过语义 ID 查找到的原物品

解码器优化目标:
ℒ = -∑_{l=1}^{L} log P(c_l(i_{t+1}) | c_{>l}(i_{t+1}), H_enc)
```

注意解码器以**倒序**（从粗粒度到细粒度）生成语义 ID，即先预测最顶层（最具区分性）的编码，再逐层细化。

#### 3.3.4 LlamaRec：无需 ID 的文本推荐

LlamaRec (Yue et al., 2023) 探索了直接用自然语言标题替代物品 ID 的可能性。它将用户历史行为序列转化为文本序列：

**输入格式化**：

```text
"Given the user's watched movies: [m₁_title], [m₂_title], ..., [m_t_title]
Recommend the next movie:"
```

**推理方式**：

LlamaRec 使用 Top-K 交叉注意力评分代替自回归生成全部候选：

$$\text{Score}(i) = \frac{1}{S} \sum_{s=1}^{S} \text{sim}(\mathbf{h}_{\text{[SEP]}}, \mathbf{h}_i^{(s)})$$

其中 $\mathbf{h}_{\text{[SEP]}}$ 是提示中 `[SEP]` 位置的 LLM 隐状态，$\mathbf{h}_i^{(s)}$ 是物品 $i$ 的标题分词后第 $s$ 个 token 的隐状态。

**关键发现**：

1. 仅使用文本语义即可获得有竞争力的推荐效果，说明 LLM 具备"零样本推荐能力"。
2. 在长尾物品推荐上，文本表示优于纯 ID 表示，因为 LLM 可以利用语义相关性迁移知识。

#### 3.3.5 LLM 推荐的知识注入策略

| 策略 | 描述 | 代表方法 |
| :--- | :--- | :--- |
| **Prompt Tuning** | 固定 LLM 参数，优化 soft prompt | Prompt4Rec |
| **Adapter Tuning** | 在 Transformer 层间插入小型适配器 | RecAdapter |
| **LoRA** | 低秩适配，在注意力权重上施加低秩约束 | LoRA4Rec |
| **全参数微调** | 在推荐数据上微调所有 LLM 参数 | FLAN-T5 |

**LoRA 数学表示**：

对预训练权重矩阵 $W_0 \in \mathbb{R}^{d \times k}$，约束其更新为低秩形式：

$$W = W_0 + \Delta W = W_0 + BA$$

其中 $B \in \mathbb{R}^{d \times r}$，$A \in \mathbb{R}^{r \times k}$，$r \ll \min(d, k)$（典型取 $r=8$ 或 $16$）。

前向计算：

$$h = Wx = W_0 x + BA x$$

训练时仅更新 $A$ 和 $B$，$W_0$ 冻结。

### 3.4 基于变分自编码器的生成式推荐

#### 3.4.1 Multi-VAE：多项变分自编码器

Multi-VAE (Liang et al., 2018) 是生成式推荐在隐式反馈场景的标志性工作，将用户的交互向量视为多项分布生成的观测。

**模型结构**：

```text
用户 u 的交互向量 x_u ∈ {0,1}^N （N 个物品的点击/非点击）
     ↓
  编码器: q_φ(z|x_u) = N(μ_φ(x_u), diag(σ²_φ(x_u)))
     ↓
  隐变量 z ∈ ℝ^d （用户偏好的低维表示）
     ↓
  解码器: p_θ(x_u|z) = Multinomial(π_θ(z))
     ↓
  输出: 重构的交互概率 π(z) ∈ ℝ^N
```

**ELBO 推导**：

变分下界的完整推导：

$$\log p(\mathbf{x}_u) \geq \mathbb{E}_{q_\phi(\mathbf{z} | \mathbf{x}_u)}[\log p_\theta(\mathbf{x}_u | \mathbf{z})] - \beta \cdot \text{KL}(q_\phi(\mathbf{z} | \mathbf{x}_u) \| p(\mathbf{z}))$$

第一项为重构损失，第二项为正则化项使后验接近标准高斯先验 $p(\mathbf{z}) = \mathcal{N}(0, \mathbf{I})$。

**重构项的具体形式**：

$$\mathbb{E}_{q_\phi}[\log p_\theta(\mathbf{x}_u | \mathbf{z})] = \sum_{i: x_{ui}=1} \log \pi_i(\mathbf{z}) + \sum_{i: x_{ui}=0} \log(1 - \pi_i(\mathbf{z}))$$

由于反馈信号极度稀疏（大多数 $x_{ui}=0$），Multi-VAE 使用**多项似然**并引入权重衰减：

$$\log p_\theta(\mathbf{x}_u | \mathbf{z}) = \sum_i x_{ui} \log \pi_i(\mathbf{z})$$

这等价于仅对正样本优化，有效缓解了负样本占比过高的问题。

**重参数化技巧**：

为允许梯度的反向传播，隐变量采样过程使用重参数化：

$$\mathbf{z} = \mu_\phi(\mathbf{x}_u) + \sigma_\phi(\mathbf{x}_u) \odot \epsilon, \quad \epsilon \sim \mathcal{N}(0, \mathbf{I})$$

#### 3.4.2 RecVAE：改进变分推荐

RecVAE (Shenbin et al., 2020) 针对 Multi-VAE 的训练不稳定性做了关键改进：

1. **复合先验**：不使用标准高斯先验，而是使用从编码器输出的聚合后验：
   $$p(\mathbf{z}) = \mathcal{N}\left(\frac{1}{|\mathcal{U}|}\sum_u \mu_\phi(\mathbf{x}_u), \frac{1}{|\mathcal{U}|}\sum_u \Sigma_\phi(\mathbf{x}_u)\right)$$

2. **交替训练**：编码器和解码器独立优化，减少相互干扰。

3. **SELU 激活函数**：替代 ReLU，改善深层网络的梯度流动。

#### 3.4.3 MacridVAE：宏观-微观解耦

MacridVAE 提出将隐变量解耦为宏观偏好（全局品味）和微观偏好（局部场景）：

$$\mathbf{z} = [\mathbf{z}_{\text{macro}}; \mathbf{z}_{\text{micro}}]$$

其中 $\mathbf{z}_{\text{macro}}$ 建模用户长期稳定的偏好，$\mathbf{z}_{\text{micro}}$ 建模短期的上下文敏感偏好。

## 4. 生成式搜索与检索

### 4.1 从生成式推荐到生成式检索

**问题定义**：在传统的推荐系统中，检索阶段通过双塔模型将用户和物品映射到共同向量空间，使用近似最近邻搜索（ANN）进行匹配。生成式检索（Generative Retrieval）则**直接生成**目标物品的标识符，将检索转化为序列生成问题。

### 4.2 语义 ID 编码与检索体系

**核心架构**：

```text
┌──────────────── 生成式检索流程 ────────────────┐
                                                  │
 离线阶段:                                          │
   Item Corpus → 文本编码器 → RQ-VAE → 语义 ID 码本 │
                                                  │
 在线阶段:                                          │
   用户历史序列 → Encoder → Decoder → 目标语义 ID  │
    → 码本映射 → 目标物品列表                       │
                                                  │
└─────────────────────────────────────────────────┘
```

**关键优势**：

1. **紧凑表示**：使用 $L$ 层码本，每层 $K$ 个码字，仅需 $L \cdot K$ 的存储量即可表示 $K^L$ 个物品。
2. **语义保真**：编码过程保留了物品的语义邻居结构——语义相近的物品具有相似的 ID 前缀。
3. **端到端联合优化**：编码器、量化器、生成式解码器可端到端训练。

### 4.3 生成式搜索的实现

#### 4.3.1 编码器-解码器架构

$$
\begin{aligned}
\mathbf{H}_{\text{enc}} &= \text{Encoder}(\text{Emb}(i_1), ..., \text{Emb}(i_t)) \\
P(c_1, ..., c_L \mid \mathbf{H}_{\text{enc}}) &= \prod_{l=1}^{L} P(c_l \mid c_{<l}, \mathbf{H}_{\text{enc}}) \\
\hat{c}_l &= \arg\max_{k \in [K]} P(c_l = k \mid \hat{c}_{<l}, \mathbf{H}_{\text{enc}})
\end{aligned}
$$

使用**束搜索（Beam Search）** 生成 Top-K 候选序列，然后映射回物品 ID。

#### 4.3.2 对比学习增强的检索

为进一步提升检索质量，引入对比学习损失：

$$\mathcal{L}_{\text{cont}} = -\log \frac{\exp(\text{sim}(\mathbf{h}_{\text{dec}}, \mathbf{h}_i^+)/\tau)}{\sum_{j=1}^{B} \exp(\text{sim}(\mathbf{h}_{\text{dec}}, \mathbf{h}_j)/\tau)}$$

其中 $\mathbf{h}_{\text{dec}}$ 是解码器输出的表示，$\mathbf{h}_i^+$ 是目标物品的编码表示。这使生成结果在潜在空间中的表示与目标物品的表示高度对齐。

### 4.4 与经典搜索的对比

| 维度 | 传统搜索 | 生成式搜索 |
| :--- | :--- | :--- |
| 索引结构 | Inverted Index + ANN Index | 码本 + Transformer |
| 匹配方式 | TF-IDF/BM25/向量内积 | 自回归解码 |
| 延迟 | ~10ms (ANN) | ~50-200ms (Beam Search) |
| 检索精度 | 受限于向量压缩损失 | 受限于量化误差 |
| 语义理解 | 浅层语义 | 深层语义 (LLM) |
| 冷启动物品 | 无法检索 | 可通过文本描述推理 |

### 4.5 工业级生成式检索系统

以 Google 的 **TIGER** 系统为例，其工业部署架构为：

```text
用户行为 → 实时序列特征 → Transformer Encoder
      ↓
Transformer Decoder (Beam Search K=10)
      ↓
10 条语义 ID 序列 → 码表查找 → 10 个候选物品
      ↓
候选物品特征丰富 → 精排模型打分 → Top-1/Top-K 展示
```

**效率优化实践**：

1. **KV Cache**：在解码器中缓存 Key 和 Value，避免重复计算历史 token 的注意力输出。
2. **Early Exit**：在束搜索中，对各束的累计概率设定阈值，提前剪枝低概率分支。
3. **并行解码**：使用非自回归解码（Mask-Predict）在 2-3 次迭代中完成序列生成。

## 5. 商业化落地与工程优化

### 5.1 推理效率优化

#### 5.1.1 扩散模型采样加速

扩散模型的推理瓶颈在于多步去噪采样。工业部署中可采用以下策略：

**DDIM 确定性采样**：
将去噪步数从 $T=1000$ 减少到 $S=50$，通过非马尔可夫过程直接预测 $\hat{\mathbf{x}}_0$：

$$\mathbf{x}_{t-\Delta} = \sqrt{\bar{\alpha}_{t-\Delta}} \underbrace{\frac{\mathbf{x}_t - \sqrt{1 - \bar{\alpha}_t} \epsilon_\theta^{(t)}}{\sqrt{\bar{\alpha}_t}}}_{\text{预测的 } \hat{\mathbf{x}}_0} + \sqrt{1 - \bar{\alpha}_{t-\Delta}} \epsilon_\theta^{(t)}$$

**一致性模型蒸馏**：
将步骤 $S$ 的扩散模型蒸馏为一步生成模型：

$$\mathcal{L}_{\text{CD}} = \mathbb{E}_{t, \mathbf{x}_0, \epsilon} \left[ d\left(f_\theta(\mathbf{x}_{t+1}, t+1), f_\theta(\hat{\mathbf{x}}_t, t)\right) \right]$$

其中 $f_\theta$ 为一致性函数，直接预测 $\hat{\mathbf{x}}_0$，$d$ 为距离度量。

**潜在空间降维**：
LDiffRec 对用户向量进行 PCA 降维后再执行扩散，显著降低 $N$ 维向量操作的复杂度。

#### 5.1.2 LLM 推理优化

| 技术 | 原理 | 加速比 | 质量影响 |
| :--- | :--- | :--- | :--- |
| **KV Cache** | 缓存注意力 Key/Value | 2-5x | 无损 |
| **FlashAttention** | 分块注意力减少显存读写 | 2-3x | 无损 |
| **INT8 量化** | 8-bit 权重+激活量化 | 2x | 轻微下降 (<2%) |
| **SmoothQuant** | 平滑激活值异常值 | - | 无损 |
| **Speculative Decoding** | 小模型草稿+大模型验证 | 2-3x | 无损 |
| **连续批处理** | 动态批量调度请求 | 吞吐提升 10x+ | 无损 |

**量化感知训练的数学形式**：

$$\text{Quantize}(W) = \Delta \cdot \text{round}\left(\frac{W}{\Delta}\right) + \text{ZeroPoint}, \quad \Delta = \frac{\max(W) - \min(W)}{2^{b-1}}$$

对于 LLM 推荐中的量化，通常对混合精度量化——敏感层（注意力投影）保留 FP16，非敏感层（FFN）量化为 INT8：

$$W_{\text{attn}} = \text{FP16}, \quad W_{\text{ffn}} = \text{INT8}$$

#### 5.1.3 Transformer 解码器加速

针对生成式检索中的自回归解码，实用加速方法包括：

**推测解码（Speculative Decoding）**：

```text
输入序列 → 小草稿模型（Draft Model）→ K 步推测
     ↓
目标验证模型（Target Model）→ 并行验证 K 步 → 接受/拒绝

期望加速比 = K / (1 + K · (计算成本比))
```

实验表明，当草稿模型为原模型 1/4 大小，$K=5$ 时，加速比约为 2.3x。

### 5.2 多阶段级联架构

在工业推荐系统中，生成式模型通常不独立部署，而是嵌入到级联体系中：

```text
                      ┌─────────────┐
                      │  全量物品池  │
                      │  (上千万级)  │
                      └──────┬──────┘
                             ↓
┌──────────────────────────────────────────┐
│  阶段一：生成式召回                        │
│  模型：TIGER / DiffRec                      │
│  输入：用户实时序列特征                      │
│  输出：Top-500 候选物品 ID                  │
│  Latency: ~30ms                             │
└──────────────────────────────────────────┘
                             ↓
┌──────────────────────────────────────────┐
│  阶段二：向量精召回                          │
│  模型：双塔 DNN + ANN Index                  │
│  输入：用户向量 + 500 候选                   │
│  输出：混合后的 Top-2000 候选                 │
│  Latency: ~5ms                              │
└──────────────────────────────────────────┘
                             ↓
┌──────────────────────────────────────────┐
│  阶段三：预排序（粗排）                      │
│  模型：小型 MLP / DeepFM                     │
│  输入：用户+物品交叉特征                      │
│  输出：Top-500 候选 (分数排序)               │
│  Latency: ~10ms                             │
└──────────────────────────────────────────┘
                             ↓
┌──────────────────────────────────────────┐
│  阶段四：精排                                │
│  模型：大型 DCN-v2 / DIN / DIEN              │
│  输入：完整用户+物品交叉特征                   │
│  输出：Top-100 候选 (精确排序)                │
│  Latency: ~20ms                             │
└──────────────────────────────────────────┘
                             ↓
┌──────────────────────────────────────────┐
│  阶段五：重排                                │
│  逻辑：多样性控制 + 去重 + 业务规则           │
│  Latency: ~5ms                             │
└──────────────────────────────────────────┘
                             ↓
                         输出
```

**混合召回的集成策略**：

生成式召回与传统的向量召回、图召回、热门召回的结果进行**合并+去重+加权**：

$$\text{FinalScore}(i) = \sum_{m \in \mathcal{M}} w_m \cdot \text{Score}_m(i)$$

其中 $w_m$ 为各召回通道的权重，可通过贝叶斯在线学习动态调整。

### 5.3 冷启动与数据效率

生成式推荐在冷启动场景具有天然优势——通过文本语义理解，可以对没有交互记录的新物品进行推理。

#### 5.3.1 物品冷启动

对于新上架的商品，传统 ID 召回模型需要积累一定交互后才能有效推荐。生成式模型的冷启动流程：

```text
新物品上架：
  物品信息（标题、描述、类目）→ 文本编码器 → 语义向量
      ↓
  语义 ID 映射：通过最近邻找到码本中最近的码字组合
      ↓
  生成式检索：用户历史 → 解码器 → 可能包含语义 ID 路径中的新物品
```

**语义 ID 的冷启动泛化**：

当新物品的语义 ID 与已有物品共享前缀时（即它们属于同一粗粒度类目），生成式模型可隐式地将其纳入候选：

$$P(\text{新物品被推荐}) \propto P(c_1^*) \cdot P(c_2^* \mid c_1^*) \cdot \prod_{l=3}^{L} P(c_l^{\text{(new)}} \mid c_{<l}^{\text{(new)}})$$

其中 $c_1^*, c_2^*$ 为与用户偏好匹配的高层语义码字。

#### 5.3.2 用户冷启动

对新用户的处理策略：

1. **属性特征初始化**：基于用户画像（年龄、性别、地域）生成初始的偏好向量：
   $$\mathbf{z}_{u}^{\text{(init)}} = \text{MLP}(\mathbf{x}_u^{\text{(profile)}})$$

2. **语义级推荐**：不依赖交互历史，直接通过文本提示生成首屏推荐：
   $$\text{Prompt} = \text{"推荐适合25岁北京男性的科技产品"}$$
   $$\text{Output} = \text{LLM 解码} \rightarrow \text{语义 ID} \rightarrow \text{候选物品}$$

3. **连续学习**：随着交互累积，逐步增加扩散模型/LLM 对用户个性化信号的权重。

### 5.4 在线学习与自适应更新

#### 5.4.1 在线更新挑战

生成式推荐模型的在线更新面临以下挑战：

- **灾难性遗忘**：新数据微调可能破坏预训练学到的语义知识。
- **训练-推理分布偏移**：在线数据的分布与离线训练数据不一致。
- **推理频率限制**：大型模型的在线更新延迟高，难以实时。

#### 5.4.2 实践经验

**经验回放缓冲区**：

$$\mathcal{L}_{\text{online}} = \mathcal{L}_{\text{new}}(\mathcal{D}_{\text{new}}) + \lambda \cdot \mathcal{L}_{\text{replay}}(\mathcal{D}_{\text{buffer}})$$

其中 $\mathcal{D}_{\text{buffer}}$ 会按比例采样历史数据，$\lambda$ 控制新旧任务平衡。

**增量式码本更新**：

对 RQ-VAE 码本，使用动量更新：

$$e_{l,k}^{(t+1)} = m \cdot e_{l,k}^{(t)} + (1 - m) \cdot \frac{1}{|\mathcal{S}_{l,k}|} \sum_{\mathbf{r} \in \mathcal{S}_{l,k}} \mathbf{r}$$

其中 $\mathcal{S}_{l,k}$ 是分配到码字 $e_{l,k}$ 的残差向量集合，$m \in (0,1)$。

**快慢模型架构**：

```text
快模型（高频更新）：
  用户表示网络 + 轻量头部 → 每日更新
  参数规模: 10M

慢模型（低频更新）：
  码本 + 生成式解码器 → 每周更新
  参数规模: 300M+
```

### 5.5 AIGC 增强推荐

生成式 AI（AIGC）不仅改变推荐的核心推理方式，还可用于**数据增强与特征扩充**：

#### 5.5.1 商品展示图生成

使用 Stable Diffusion 为商品生成多样化展示图，替换原始低质量图片，提升 CTR：

$$
\text{Image}_{\text{new}} = \text{SD}(\text{商品标题} + \text{风格Prompt}), \quad \text{CTR} \uparrow 3\text{-}8\%
$$

#### 5.5.2 用户行为模拟

使用生成式模型合成用户交互序列，用于数据增强：

$$P_{\text{synthetic}}(\mathbf{s}) = \prod_{t=1}^{T} P(i_t \mid i_{<t}, \text{UserProfiles})$$

合成数据与真实数据的混合训练策略：

$$\mathcal{L} = \alpha \cdot \mathcal{L}_{\text{real}} + (1 - \alpha) \cdot \mathcal{L}_{\text{synthetic}}, \quad \alpha \in (0,1)$$

## 8. 生成式推荐 vs 判别式推荐：形式化对比

### 8.1 问题的两种数学视角

#### 8.1.1 判别式推荐的判别函数视角

传统判别式推荐的目标是学习一个**判别函数** $f_\theta: \mathcal{U} \times \mathcal{I} \rightarrow \mathbb{R}$，直接估计用户 $u$ 对物品 $i$ 的偏好分数：

$$
\hat{y}_{u,i} = f_\theta(u, i) = \mathbb{P}(y=1 \mid u, i; \theta)
$$

其中 $\mathbb{P}$ 由 sigmoid、softmax 或更深层的网络建模。推荐时通过 $\arg\max_{i \in \mathcal{I}} f_\theta(u, i)$ 排序。**核心假设**：用户与物品的特征空间存在可分的判别边界。

判别式方法的训练目标一般为：

$$
\mathcal{L}_{\text{disc}}(\theta) = -\sum_{(u,i,y) \in \mathcal{D}} y \log \sigma(f_\theta(u,i)) + (1-y)\log(1-\sigma(f_\theta(u,i)))
$$

或者 Pairwise 形式的 BPR 损失：

$$
\mathcal{L}_{\text{BPR}}(\theta) = -\sum_{(u,i,j) \in \mathcal{D}_p} \log \sigma(f_\theta(u,i) - f_\theta(u,j))
$$

#### 8.1.2 生成式推荐的生成模型视角

生成式推荐的目标是学习**条件生成模型** $p_\theta(\cdot \mid u)$，直接生成用户的下一项或候选序列：

$$
\hat{i}_{t+1} \sim p_\theta(i_{t+1} \mid u) = p_\theta(i_{t+1} \mid i_{1:t}, c_u)
$$

其中 $i_{1:t}$ 为历史交互序列，$c_u$ 为用户上下文。**核心假设**：物品之间存在可被建模的语义依赖关系。

训练目标为最大化对数似然：

$$
\mathcal{L}_{\text{gen}}(\theta) = -\sum_{u \in \mathcal{U}} \log p_\theta(i_{t+1}^* \mid i_{1:t}, c_u)
$$

当物品被表示为 Semantic ID（语义标识符序列）时，问题退化为序列到序列的翻译：

$$
p_\theta(\mathbf{s} \mid \mathbf{x}) = \prod_{k=1}^{K} p_\theta(s_k \mid \mathbf{s}_{<k}, \mathbf{x})
$$

### 8.2 假设空间的本质差异

| 维度 | 判别式 $f_\theta(u,i)$ | 生成式 $p_\theta(i \mid u)$ |
| :--- | :--- | :--- |
| **建模对象** | 决策边界 $P(y\mid x)$ | 数据分布 $P(x,y)$ 或 $P(x\mid y)$ |
| **推理方式** | 检索 + 重排 | 自回归解码 / 一步采样 |
| **特征耦合** | 强依赖交叉特征工程 | 隐式学习 token 间依赖 |
| **数据效率** | 小样本友好（直接拟合边界） | 大规模数据上更优 |
| **长尾处理** | 容易过拟合头部 | 通过语言先验平滑长尾 |
| **冷启动** | 受限于未见过的 ID | 可借助文本/语义缓解 |

**直观解释**：判别式模型是"裁判"，告诉你 $i$ 对 $u$ 的分数；生成式模型是"作家"，它需要理解 $u$ 的全部历史才能写出下一个物品。**前者学到的是相关性，后者学到的是因果性**（形式上的，而非严格的因果推断）。

### 8.3 生成式推荐的三大形式化分支

#### 8.3.1 分支 A：判别式 → 生成式重构（Discriminative-to-Generative）

将点击率模型 $\sigma(f_\theta(u,i))$ 改写为指数族分布形式：

$$
p_\theta(i \mid u) = \frac{\exp(f_\theta(u,i) / T)}{\sum_{j \in \mathcal{I}} \exp(f_\theta(u,j) / T)}
$$

其中 $T$ 为温度系数。当 $T \to 0$ 时退化为判别式 argmax；当 $T > 0$ 时退化为采样生成。这一改写揭示了：**判别式模型实际上是生成式模型在零温度下的特殊情形**。GPT4Rec、SASRec 的 decoder 输出本质都是这类 softmax。

#### 8.3.2 分支 B：自回归序列生成（Autoregressive Generation）

```text
Algorithm 1: 自回归序列推荐 (SASRec / BERT4Rec / TIGER)
─────────────────────────────────────────────────────
Input: 用户序列 S = (i_1, i_2, ..., i_T), 物品词表 V
Output: 下一项 i_{T+1} 的分布 p(·|S)

1.  Embedding: e_t = Embed(i_t) + PosEmbed(t)
2.  Context:   h = TransformerEncoder({e_1, ..., e_T})
3.  Logits:    logits = h_T · E_vocab^T
4.  Softmax:   p(i_{T+1}=v | S) = softmax(logits)_v
5.  Loss:      L = -log p(i_{T+1}=i_{T+1}^* | S)
6.  Inference: i_{T+1} = argmax_v p(v|S)  OR  sample
─────────────────────────────────────────────────────
```

其中第 3 步的 `E_vocab` 是物品 embedding 矩阵。**关键观察**：SASRec 的输出层已经把推荐问题转化为"全词表上的下一个 token 预测"——这与 GPT 预训练任务形式上完全一致。

#### 8.3.3 分支 C：扩散生成（Diffusion-based Generation）

将用户偏好 $z \in \mathbb{R}^d$ 视为潜在变量，通过扩散过程生成：

**前向过程**（加噪）：

$$
q(z_t \mid z_{t-1}) = \mathcal{N}(z_t; \sqrt{1-\beta_t} z_{t-1}, \beta_t \mathbf{I})
$$

**反向过程**（去噪，由神经网络 $\epsilon_\theta$ 预测噪声）：

$$
p_\theta(z_{t-1} \mid z_t) = \mathcal{N}(z_{t-1}; \mu_\theta(z_t, t), \Sigma_\theta(z_t, t))
$$

**训练目标**（简化形式）：

$$
\mathcal{L}_{\text{diff}} = \mathbb{E}_{t, z_0, \epsilon} \left[ \| \epsilon - \epsilon_\theta(\sqrt{\bar\alpha_t} z_0 + \sqrt{1-\bar\alpha_t} \epsilon, t) \|^2 \right]
$$

**推理**时从 $z_T \sim \mathcal{N}(0, I)$ 出发迭代去噪得到 $z_0$，再映射到物品空间。DiffRec、CDiffRec 等是该分支代表。

### 8.4 联合视角：生成式框架内的判别式目标

实践中，纯判别目标和纯生成目标往往**混合使用**：

$$
\mathcal{L}_{\text{hybrid}} = \underbrace{\lambda_1 \mathcal{L}_{\text{BPR}}}_{\text{判别式排序}} + \underbrace{\lambda_2 \mathcal{L}_{\text{NLL}}}_{\text{生成式似然}} + \underbrace{\lambda_3 \mathcal{L}_{\text{contrast}}}_{\text{对比学习}}
$$

这种混合损失让模型同时具备：① 精确的排序能力；② 对物品语义结构的理解；③ 对未见物品的泛化能力。TIGER、KDD-Cup 冠军方案普遍采用这种范式。

### 8.5 信息论视角：互信息与交叉熵

**互信息分解**：判别式方法最大化 $\mathbb{I}(y; \hat{y})$，而生成式方法额外建模 $\mathbb{I}(x; z)$ 和 $\mathbb{I}(z; y)$。

**逐 token 交叉熵**（生成式训练的核心）：

$$
H(p, p_\theta) = -\sum_{k=1}^{K} p^*(s_k) \log p_\theta(s_k \mid \mathbf{s}_{<k}, \mathbf{x})
$$

其中 $p^*$ 是 one-hot 真实分布。**这一损失形式与语言模型预训练完全一致**，这也是 LLM 能直接迁移到推荐的根本原因——它们共享同一个目标函数。

### 8.6 失败案例与改进

**失败案例 1：曝光偏差放大**
- 现象：自回归模型倾向于重复推荐历史高频物品
- 根因：MLE 训练 + 曝光偏差 → 模型学到"重复 = 安全"
- 改进：① 因果曝光去偏（IPS）；② 反事实推理；③ RLHF 调整

**失败案例 2：长序列位置编码失效**
- 现象：超过 512 长度后性能陡降
- 根因：绝对位置编码外推性差
- 改进：① ALiBi 线性偏置；② RoPE 旋转位置；③ 分块相对位置

**失败案例 3：冷启动物品推荐失败**
- 现象：新物品几乎无曝光
- 根因：缺乏 ID embedding 训练
- 改进：Semantic ID 替代随机 ID；文本特征对齐

## 9. Semantic ID 与生成式目标的关系

### 9.1 为什么需要 Semantic ID？

传统推荐系统的物品 ID 是**任意整数索引**：

```text
物品 #1024  ←→  "iPhone 15 Pro 256GB 深空黑"
```

这种"乱序 ID"导致三大问题：

1. **冷启动灾难**：新物品的 embedding 从零开始训练，曝光机会为零
2. **语义缺失**：模型无法从 ID 本身推断物品属性（如品类、价格、品牌）
3. **跨域迁移困难**：不同业务域的 ID 空间相互独立

**Semantic ID（语义标识符）** 的核心思想是：**用内容特征编码出"语义上有意义的 token 序列"**，让相似物品共享前缀，从而：

- 冷启动物品天然获得邻居信息
- 模型可以从 token 序列本身学习语义层级
- 跨域、跨模态的语义对齐成为可能

### 9.2 Semantic ID 的形式化定义

定义**编码器** $E: \mathcal{I} \rightarrow \mathcal{T}^K$，将物品 $i$ 映射为长度为 $K$ 的 token 序列：

$$
\mathbf{s}_i = (s_{i,1}, s_{i,2}, \ldots, s_{i,K}) = E(i)
$$

其中每个 $s_{i,k} \in \{1, 2, \ldots, V\}$，$V$ 是 vocabulary 大小。

**解码器** $D: \mathcal{T}^K \rightarrow \mathcal{I}$ 满足：

$$
i = D(\mathbf{s}_i) \quad \text{且理想情况下} \quad i \approx D(\hat{\mathbf{s}}_i) \text{ for similar } \hat{\mathbf{s}}_i
$$

**关键性质**：相似的物品在 token 空间具有**小汉明距离**：

$$
\|\mathbf{s}_i - \mathbf{s}_j\|_H \ll K \iff \text{sim}(i, j) > \tau
$$

### 9.3 Semantic ID 的构造方法谱系

#### 9.3.1 方法 1：RQ-VAE（残差量化 VAE）

RQ-VAE 是当前工业界最主流的 Semantic ID 构造方法，由 TIGER (KDD 2023) 提出。

```sql
Algorithm 2: RQ-VAE Semantic ID 编码
─────────────────────────────────────────────────────
Input: 物品内容特征 x ∈ R^d (如文本 embedding)
Output: Semantic ID s ∈ {0,...,V-1}^K

1. Encode:  z = E_enc(x)                              # RQ-VAE encoder
2. Init:    residual = z,  codes = []
3. For k = 1 to K:
       a.  Find nearest codebook:  c_k = argmin_j ||residual - e_j||
       b.  Append token:  codes.append(c_k)
       c.  Update residual:  residual = residual - e_{c_k}
4. Decode:  x̂ = D_dec(Σ_{k=1}^K e_{c_k})
5. Loss:    L = ||x - x̂||^2 + β·KL(q(z|x) || p(z))
6. Return:  s = (c_1, c_2, ..., c_K)
─────────────────────────────────────────────────────
```

**核心思想**：通过 K 级**残差量化**将物品映射到 K 个层级。每一层捕获不同粒度的语义：

- 第 1 层：粗粒度（如品类）
- 第 2 层：中粒度（如子类）
- 第 3 层：细粒度（如品牌、价格段）

**PyTorch 简化实现**：

```python
import torch
import torch.nn as nn

class RQVAE(nn.Module):
    def __init__(self, d_in=768, d_hidden=512, d_code=64, K=3, V=256):
        super().__init__()
        self.K, self.V, self.d_code = K, V, d_code
        self.encoder = nn.Sequential(
            nn.Linear(d_in, d_hidden), nn.ReLU(),
            nn.Linear(d_hidden, d_hidden))
        self.decoder = nn.Sequential(
            nn.Linear(d_hidden, d_hidden), nn.ReLU(),
            nn.Linear(d_hidden, d_in))
        # K 个 codebook，每层 V 个 d_code 维向量
        self.codebooks = nn.Embedding(K * V, d_code)
        self.codebooks.weight.data.uniform_(-1/V, 1/V)

    def encode(self, x):
        z = self.encoder(x)                        # (B, d_hidden)
        residual, codes = z, []
        for k in range(self.K):
            cb = self.codebooks.weight[k*self.V:(k+1)*self.V]  # (V, d_code)
            dist = torch.cdist(residual.unsqueeze(1), cb.unsqueeze(0)).squeeze(1)
            idx = dist.argmin(dim=-1)              # (B,)
            codes.append(idx)
            residual = residual - cb[idx]          # 残差更新
        return torch.stack(codes, dim=1), z        # (B, K)

    def forward(self, x):
        codes, z = self.encode(x)
        # 重建
        z_q = sum(self.codebooks[k*self.V:(k+1)*self.V][codes[:, k]].mean(dim=0)
                  for k in range(self.K))
        # ponytail: 平均代替 sum 不严谨；此处仅为示意
        x_hat = self.decoder(z_q)
        recon_loss = ((x - x_hat) ** 2).mean()
        return codes, recon_loss
```

#### 9.3.2 方法 2：SentencePiece / BPE 离散化

对物品的文本描述（标题、tags）直接用 SentencePiece 或 BPE 分词：

```text
"iPhone 15 Pro 256GB 深空黑"
   → ["iPhone", "15", "Pro", "256GB", "深空黑"]
   → token IDs: [8342, 1203, 5621, 9023, 7745]
```

**优点**：天然处理未见物品，跨语言友好
**缺点**：无语义层级，分词稳定性差

#### 9.3.3 方法 3：哈希 / 聚类离散化

对预训练 embedding 做 K-Means 聚类，多层聚类得到层级 ID：

```text
item_emb → KMeans(K=256) → 第1层ID
         → 第1层聚类内 KMeans → 第2层ID
         → ...
```

**优点**：简单可控
**缺点**：聚类不稳定，新物品需要重新聚类

### 9.4 Semantic ID 与生成式目标的耦合

#### 9.4.1 训练范式

```text
Algorithm 3: 基于 Semantic ID 的生成式推荐 (TIGER)
─────────────────────────────────────────────────────
Input: 用户历史 s = (i_1, ..., i_T)
Output: 下一物品的 Semantic ID 分布 p(·|s)

1.  编码:  s_ids = [RQ-VAE(i_t) for t = 1..T]      # 长度 K*T
2.  嵌入:  emb = TokenEmb(s_ids) + PosEmb
3.  编码:  h = TransformerEncoder(emb)
4.  预测:  logits = LMHead(h[:, -K:])                 # 预测下一物品的 K 个 token
5.  损失:  L = CrossEntropy(logits, RQ-VAE(i_{T+1}))
6.  推理:  束搜索 K 个 token → 解码为候选物品 → 重排
─────────────────────────────────────────────────────
```

#### 9.4.2 数学等价性证明

**命题**：基于 Semantic ID 的序列推荐与受限词表语言模型在数学上等价。

**证明**：

定义物品集合 $\mathcal{I} = \{i_1, \ldots, i_N\}$，Semantic ID 映射 $E: \mathcal{I} \to \mathcal{T}^K$。在 $E$ 是单射（不同物品 ID 不同）的假设下：

$$
p_\theta(i_{T+1} \mid i_{1:T}) = p_\theta(E(i_{T+1}) \mid E(i_1), \ldots, E(i_T))
$$

而后者是一个标准的自回归语言模型：

$$
p_\theta(\mathbf{s} \mid \mathbf{s}_{1:T}) = \prod_{k=1}^{K} p_\theta(s_k \mid \mathbf{s}_{<k}, \mathbf{s}_{1:T})
$$

因此训练目标的负对数似然：

$$
\mathcal{L} = -\log p_\theta(E(i_{T+1}) \mid E(i_{1:T}))
$$

与 LLM 预训练目标的负对数似然完全同构。**QED**

**推论**：所有 LLM 的优化技巧（dropout、label smoothing、temperature scaling）都可以直接迁移。

### 9.5 Semantic ID 的失败案例与改进

**失败案例 1：码本崩溃（Codebook Collapse）**
- 现象：部分 code 永远不被选中
- 根因：训练初期 codebook 利用不均衡
- 改进：① EMA codebook 更新；② 死码重生（每隔 N 步用当前 batch embedding 重新初始化）；③ Gumbel-Softmax 退火

**失败案例 2：重建失真（Reconstruction Drift）**
- 现象：Semantic ID 解码回物品时与原物品差距大
- 根因：codebook 维度不足
- 改进：① 增大 codebook 容量；② 增加 code 层数 K；③ 联合优化重建与推荐损失

**失败案例 3：层级语义不稳定**
- 现象：训练后期层级含义漂移（如第 1 层应捕获品类，实际捕获价格）
- 根因：端到端优化无显式层级约束
- 改进：① 添加层级辅助损失；② 固定后层只训前层；③ 多任务学习

**失败案例 4：跨域语义不一致**
- 现象：电商的"红色"与内容平台的"红色"语义编码冲突
- 根因：各业务域独立训练 RQ-VAE
- 改进：① 跨域对比学习统一 codebook；② 共享底层 encoder；③ 多任务联合训练

### 9.6 Semantic ID 的工业实践要点

| 实践要点 | 经验值 | 依据 |
| :--- | :--- | :--- |
| codebook 数量 V | 256 ~ 4096 | 商品量级决定 |
| code 层数 K | 3 ~ 6 | 层级语义粒度 |

| 输入维度 d_in | 768 (BERT) | 与文本 embedding 对齐 |

| 推理解码 | beam=10~50 | 候选数量与时延 |

**冷启动物品处理流程**：

```python
def handle_cold_start(new_item):
    # 1. 提取文本特征
    text_emb = text_encoder(new_item.title + new_item.tags)  # 768-d

    # 2. RQ-VAE 编码 → Semantic ID
```

## 10. 评估指标对比：分类指标 vs 排序指标 vs 生成指标

### 10.1 推荐系统的三层评估目标

```text
┌─────────────────────────────────────────────┐
│  Layer 3: 业务层  (CTR / GMV / 时长 / 留存)   │ ← 最终北极星
├─────────────────────────────────────────────┤
│  Layer 2: 排序层  (NDCG / MAP / MRR)        │ ← 离线核心
├─────────────────────────────────────────────┤
│  Layer 1: 召回层  (Recall@K / Hit@K)        │ ← 召回核心
└─────────────────────────────────────────────┘
```

生成式推荐涉及所有三层指标，但因输出形式（序列、采样、重排候选）不同，**指标选择直接影响优化方向**。

### 10.2 分类指标（AUC / LogLoss）

#### 10.2.1 AUC（Area Under ROC Curve）

$$
\text{AUC} = \mathbb{P}(\hat{y}_{i^+} > \hat{y}_{i^-})
$$

其中 $i^+$ 为正样本，$i^-$ 为负样本。AUC 衡量**随机正样本排在随机负样本之前的概率**。

**优点**：对正负比例不敏感，理论范围 [0,1]
**缺点**：只关心相对序，不关心绝对值；对长尾不友好

**AUC 的优化目标**：

$$
\mathcal{L}_{\text{AUC}} \approx -\sum_{(i^+, i^-)} \log \sigma(\hat{y}_{i^+} - \hat{y}_{i^-})
$$

#### 10.2.2 LogLoss（交叉熵损失）

$$
\text{LogLoss} = -\frac{1}{N} \sum_{i=1}^{N} \left[ y_i \log \hat{y}_i + (1-y_i) \log(1-\hat{y}_i) \right]
$$

**优点**：直接对应概率校准；与 MLE 目标等价
**缺点**：对极端概率敏感；需要大量负采样

#### 10.2.3 生成式场景下的 AUC

虽然生成式推荐最终输出是序列，但可以**采样多个候选**计算 pairwise AUC：

```python
def generative_auc(model, user_history, positive_items, n_negatives=100):
    """采样评估 AUC"""
    # 1. 生成器采样 K 个候选
    candidates = model.sample(user_history, K=50)

    # 2. 正样本从历史中取
    pos_score = model.score(user_history, positive_items)

    # 3. 随机负样本
    neg_score = model.score(user_history, sample_neg(n_negatives))

    # 4. 计算 AUC
    return roc_auc_score(
        y_true=[1]*len(pos_score) + [0]*len(neg_score),
        y_score=np.concatenate([pos_score, neg_score])
    )
```

### 10.3 排序指标（Recall@K / NDCG@K / MAP@K / MRR）

#### 10.3.1 Recall@K（召回率）

$$
\text{Recall@K} = \frac{|\text{Top-}K \cap \text{Relevant}|}{|\text{Relevant}|}
$$

**含义**：Top-K 候选中命中真实正样本的比例。

**生成式推荐下的计算**：

```python
def recall_at_k(model, test_users, k=10):
    hits, total = 0, 0
    for user in test_users:
        # 生成 K 个候选
        candidates = model.generate(user.history, k=k)
        # 检查真实下一项是否在候选中
        if user.next_item in candidates:
            hits += 1
        total += 1
    return hits / total
```

#### 10.3.2 Hit@K（命中率）

$$
\text{Hit@K} = \mathbb{I}[\text{Relevant} \cap \text{Top-}K \neq \emptyset]
$$

与 Recall@K 类似，但每个用户只算一次命中。

#### 10.3.3 NDCG@K（归一化折损累积增益）

$$
\text{NDCG@K} = \frac{\text{DCG@K}}{\text{IDCG@K}}
$$

其中：

$$
\text{DCG@K} = \sum_{i=1}^{K} \frac{2^{rel_i} - 1}{\log_2(i+1)}
$$

$$
\text{IDCG@K} = \text{DCG@K with ideal ordering}
$$

**含义**：考虑排序位置的折损增益；位置越靠前权重越高。

**生成式推荐的 NDCG 计算**：

```python
def ndcg_at_k(model, test_users, k=10):
    ndcg_scores = []
    for user in test_users:
        candidates = model.generate(user.history, k=k)
        relevance = [1 if item == user.next_item else 0 for item in candidates]
        dcg = sum(rel / np.log2(i + 2) for i, rel in enumerate(relevance))
        idcg = 1.0  # 只有一个正样本时，IDCG = 1/log2(2) = 1
        ndcg_scores.append(dcg / idcg)
    return np.mean(ndcg_scores)
```

#### 10.3.4 MAP@K（平均精度均值）

$$
\text{MAP@K} = \frac{1}{|U|} \sum_{u \in U} \frac{1}{\min(R_u, K)} \sum_{k=1}^{K} P(k) \cdot rel_u(k)
$$

其中 $P(k) = \frac{|\{relevant \cap top\_k\}|}{k}$，$R_u$ 是用户相关物品总数。

**含义**：精度在所有相关物品位置的均值，对多正样本场景更友好。

#### 10.3.5 MRR（平均倒数排名）

$$
\text{MRR} = \frac{1}{|U|} \sum_{u \in U} \frac{1}{\text{rank}_u}
$$

**含义**：第一个相关物品排名的倒数。简单但只关注第一个 hit。

### 10.4 生成指标（Coverage / Diversity / Novelty）

传统 AUC/NDCG 关注**准确性**，但生成式推荐还需要评估**生成质量**的多样性维度。

#### 10.4.1 Catalog Coverage（目录覆盖率）

$$
\text{Coverage} = \frac{|\bigcup_{u \in U} \text{Rec}(u)|}{|\mathcal{I}|}
$$

**生成式推荐下的现象**：模型倾向于生成头部物品，coverage 通常低于判别式。**改进**：温度采样、解码多样性约束。

#### 10.4.2 Intra-List Diversity（列表内多样性）

$$
\text{Diversity} = \frac{2}{K(K-1)} \sum_{i<j} (1 - \text{sim}(r_i, r_j))
$$

**生成式推荐的解法**：在束搜索中加入多样性奖励。

#### 10.4.3 Novelty（新颖性）

$$
\text{Novelty} = -\log_2 \frac{|\{u : i \in \text{Hist}(u)\}|}{|U|}
$$

**含义**：推荐用户历史中未见过物品的偏好。

### 10.5 离线指标 vs 在线指标的鸿沟

| 指标 | 离线表现 | 在线表现 | 鸿沟原因 |
| :--- | :--- | :--- | :--- |
| NDCG@10 ↑5% | CTR ↑1~3% | 曝光偏差 → 实际 CTR 下降 | 排序稳定性差 |
| Recall@100 ↑10% | 业务指标 ↑ | 模型时延增加 → QPS 下降 | 系统未优化 |
| Coverage ↑50% | 用户停留时长 ↑ | 长尾物品加载慢 → 体验下降 | 工程不匹配 |

**核心教训**：**离线指标只能保证相关性，不能保证因果性**。必须在 A/B 测试中验证。

### 10.6 工业级评估流水线

```python
class Evaluator:
    """工业级推荐评估器"""

    def __init__(self, model, test_data):
        self.model = model
        self.test_data = test_data

    def full_evaluation(self):
        metrics = {}

        # 1. 准确性指标
        metrics['Recall@10'] = self.recall_at_k(10)
        metrics['Recall@50'] = self.recall_at_k(50)
        metrics['NDCG@10'] = self.ndcg_at_k(10)
        metrics['NDCG@50'] = self.ndcg_at_k(50)
        metrics['MRR'] = self.mrr()

        # 2. 多样性指标
        metrics['Coverage@10'] = self.coverage_at_k(10)
        metrics['Diversity@10'] = self.diversity_at_k(10)
        metrics['Novelty@10'] = self.novelty_at_k(10)

        # 3. 校准指标
        metrics['AUC'] = self.auc()
        metrics['LogLoss'] = self.logloss()
        metrics['ECE'] = self.expected_calibration_error()

        # 4. 推理性能
        metrics['Latency_ms_p99'] = self.measure_latency(p=0.99)
        metrics['QPS'] = self.measure_qps()

        # 5. 公平性指标（可选）
        metrics['Popularity_Bias'] = self.popularity_bias()

        return metrics

    def assert_improvement(self, baseline_metrics, min_rel_improve=0.02):
        """业务断言：核心指标至少提升 min_rel_improve"""
        for key in ['NDCG@10', 'Recall@50']:
            base = baseline_metrics[key]
            curr = getattr(self, key.lower().replace('@', '_at_'))()
            rel_improve = (curr - base) / base
            assert rel_improve >= min_rel_improve, \
                f"{key} 仅提升 {rel_improve:.2%}, 低于阈值 {min_rel_improve:.2%}"
```

### 10.7 评估指标的失败案例

**失败案例 1：NDCG 提升但 CTR 下降**
- 现象：离线 NDCG@10 提升 5%，A/B 测试 CTR 下降 2%
- 根因：模型学会了"预测用户会点击什么"，但推荐策略是"让用户点击"
- 改进：① 引入因果推断；② RLHF 调整；③ 全局去偏

**失败案例 2：Recall 提升但用户停留时长下降**
- 现象：Recall@50 提升 10%，停留时长下降 8%
- 根因：召回变多但排序质量下降
- 改进：① 评估分层；② 引入业务指标到训练目标

**失败案例 3：AUC 接近 1 但线上崩溃**
- 现象：训练 AUC=0.95，但线上 CTR=0
- 根因：标签泄漏（future information）
- 改进：① 严格时序切分；② 离线验证在线一致性

```python
# 简化版 YouTube DNN
class YouTubeDNN(nn.Module):
    def __init__(self, n_users, n_items, d_emb=256):
        super().__init__()
        self.user_emb = nn.Embedding(n_users, d_emb)
        self.item_emb = nn.Embedding(n_items, d_emb)
        self.mlp = nn.Sequential(
            nn.Linear(d_emb * 2 + feature_dim, 1024), nn.ReLU(),
            nn.Linear(1024, 512), nn.ReLU(),
            nn.Linear(512, n_items))  # 多分类

    def forward(self, user_id, watch_history, context_features):
        u = self.user_emb(user_id)
        # 平均池化观看历史
        h = self.item_emb(watch_history).mean(dim=1)
        x = torch.cat([u, h, context_features], dim=-1)
        return self.mlp(x)  # 全部物品的分数
```

```python
def stock_aware_recommendation(scores, inventory):
    """库存感知的生成式推荐"""
    # 1. 对零库存物品的分数惩罚
    mask = inventory > 0
    adjusted_scores = scores * mask.float()

    # 2. 库存不足的物品降温
    low_stock_mask = inventory < threshold
    adjusted_scores = torch.where(
        low_stock_mask,
        adjusted_scores * 0.5,
        adjusted_scores
    )

    return adjusted_scores
```

#### 11.4.2 HSTU (Hierarchical Sequential Transduction Unit)

Meta 2024 年提出的 HSTU 是生成式推荐的标志性架构，专为高吞吐量设计：

```python
class HSTU(nn.Module):
    """Hierarchical Sequential Transduction Unit"""
    def __init__(self, d, n_heads):
        super().__init__()
        self.d = d
        self.qkv = nn.Linear(d, 3 * d)
        self.out = nn.Linear(d, d)

    def forward(self, x, mask=None):
        # x: (B, T, d)
        B, T, _ = x.shape
        qkv = self.qkv(x).chunk(3, dim=-1)
        q, k, v = [t.view(B, T, -1, self.d // n_heads).transpose(1, 2)
                   for t in qkv]
        # 改进的注意力：相对位置 + 因果 mask
        attn = (q @ k.transpose(-2, -1)) / (self.d // n_heads) ** 0.5
        if mask is not None:
            attn = attn.masked_fill(mask == 0, float('-inf'))
        attn = F.softmax(attn, dim=-1)
        out = (attn @ v).transpose(1, 2).reshape(B, T, self.d)
        return self.out(out)
```

**HSTU 的核心创新**：

1. **点对点相对注意力**：替代标准点积注意力，训练收敛更快
2. **加权平均池化**：替代传统 softmax，提升推理速度
3. **大规模并行训练**：单卡可处理百万级序列长度

#### 11.6.1 推理优化

**KV Cache**：生成式推理时缓存历史 token 的 K/V：

```python
class CachedGenerator:
    def __init__(self, model, max_seq_len=512):
        self.cache = {}  # user_id -> (k_cache, v_cache)

    @torch.no_grad()
    def generate_step(self, user_id, new_token):
        """单步生成，支持增量 KV cache"""
        if user_id not in self.cache:
            self.cache[user_id] = self.init_cache()
        k_cache, v_cache = self.cache[user_id]

        # 只计算新 token 的 attention
        new_k, new_v = self.compute_kv(new_token)
        k_cache = torch.cat([k_cache, new_k], dim=1)
        v_cache = torch.cat([v_cache, new_v], dim=1)

        # 更新缓存
        self.cache[user_id] = (k_cache, v_cache)

        # 完整 attention
        return self.model.decode(k_cache, v_cache)
```

### 13.1 基础概念类

**Q1：什么是生成式推荐？与判别式推荐的本质区别是什么？**

**参考答案**：

生成式推荐将推荐问题建模为**条件生成任务**，直接生成候选物品的标识符（ID 或 Semantic ID），而不是对所有候选物品打分排序。

本质区别：

| 维度 | 判别式 | 生成式 |
| :--- | :--- | :--- |
| 目标 | 学习 $P(y\|x)$ | 学习 $P(x\|c)$ 或 $P(z\|c)$ |
| 推理 | 全候选集打分 | 自回归解码 |
| 特征 | 依赖人工交叉 | 隐式语义 |
| 冷启动 | 困难 | 通过 Semantic ID 缓解 |

---

**Q2：什么是 Semantic ID？为什么要用它？**

**参考答案**：

Semantic ID 是用内容特征编码出的"语义上有意义的 token 序列"。

核心优势：
1. **冷启动**：新物品无需重训，立即可用
2. **语义共享**：相似物品共享前缀
3. **跨域对齐**：不同业务域可共享语义空间
4. **LLM 兼容**：可直接用 LM Head 训练

构造方法：
- **RQ-VAE**：残差量化 VAE（最主流）
- **BPE/SentencePiece**：文本分词
- **聚类**：多层 K-Means

---

**Q3：RQ-VAE 的 K 层 codebook 各自捕获什么语义？**

**参考答案**：

理论上 K 层捕获**由粗到细**的语义层次：
- **第 1 层**：粗粒度（如品类、领域）
- **第 2 层**：中粒度（如子类、风格）
- **第 3 层**：细粒度（如品牌、价格段）
- **第 K 层**：极细粒度（如 SKU 级别差异）

但**实际训练中**层级语义不一定严格对齐，需要通过层级辅助损失或可视化验证。

### 13.3 训练技巧类

**Q7：生成式推荐中如何处理曝光偏差？**

**参考答案**：

**问题**：用户没看到 ≠ 不喜欢，传统训练会严重低估未见物品。

**解决方案**：

1. **IPS (Inverse Propensity Scoring)**：
$$
\mathcal{L}_{\text{IPS}} = \frac{1}{P(\text{exposure})} \mathcal{L}_{\text{original}}
$$

2. **Doubly Robust**：
$$
\mathcal{L}_{\text{DR}} = \mathcal{L}_{\text{IPS}} + \mathcal{L}_{\text{imputation}}
$$

3. **生成式重新加权**：
对未曝光物品按 popularity 反比采样为负样本

---

**Q8：如何处理 Semantic ID 训练中的码本崩溃（Codebook Collapse）？**

**参考答案**：

码本崩溃：部分 code 永远不被选中，造成 embedding 浪费。

**解决方案**：

1. **EMA 更新**：用指数移动平均更新 codebook，而非 SGD
2. **死码重生**：每隔 N 步检查未使用 code，用 batch 中活跃 embedding 重新初始化
3. **Gumbel-Softmax**：退火采样保证 code 利用均匀
4. **Code 平衡损失**：添加 -Σ p(c) log p(c) 熵正则

```python
# 死码重生实现
def revive_dead_codes(codebook, usage_count, batch_emb, dead_threshold=0):
    dead_mask = usage_count < dead_threshold
    n_dead = dead_mask.sum()
    if n_dead > 0:
        # 用 batch 中的随机向量初始化
        idx = torch.randperm(batch_emb.size(0))[:n_dead]
        codebook.weight.data[dead_mask] = batch_emb[idx]
        usage_count[dead_mask] = 1
    return codebook, usage_count
```

**Q9：生成式推荐中如何平衡准确性与多样性？**

**参考答案**：

**问题**：MLE 训练倾向于高频物品，导致推荐同质化。

**解决方案**：

1. **Temperature Sampling**：
$$
p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}
$$
- T=1：标准 softmax
- T>1：更均匀 → 多样性 ↑
- T<1：更尖锐 → 准确性 ↑

2. **Top-p (Nucleus) Sampling**：
累积概率达到 p 的最小集合，然后重新归一化采样。

3. **多样性奖励的束搜索**：
$$
\text{score}(S) = \sum_{i \in S} \text{rel}(i) + \lambda \sum_{i<j} (1 - \text{sim}(i,j))
$$

4. **MMR (Maximal Marginal Relevance)**：
迭代选最相关且与已选最不相似的物品。

历史维度上,我们看到三个规律:

1. **从特殊到一般**: 早期方法往往针对特定场景,后期抽象出通用框架。学习的认知规律也是先掌握具体案例,再抽象出一般模式。这种"自下而上"的学习方式,在机器学习模型的设计里反复出现。

2. **从手工到自动**: 经验规则逐步被数据驱动的方法取代。在早期,很多 AI 系统依赖人工编写的规则。统计学习方法的崛起让"从数据中学习"成为可能。深度学习进一步把特征工程也自动化了。今天的大模型时代,我们看到端到端学习从感知扩展到了推理与生成。

**3. 数学形式化(简洁版)**

虽然我们强调结果分析视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

**4. 信息论视角**

信息论为"GR" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。

互信息衡量知道一个变量后,另一个变量不确定性减少的量。在机器学习中,它被广泛用于特征选择、表示学习、多模态对齐等场景。

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

**7. 实践建议**

结合 "GR" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "GR" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。

**9. 与相关主题的关系**

"GR" 与以下主题密切相关:

- **上游**: 数据质量、特征工程、业务理解。这些决定了模型的天花板。
- **下游**: 工程部署、效果监控、迭代优化。这些决定了模型的下限。
- **平行**: 类似方法、竞争方案、补充技术。了解竞品才能做得更好。

理清这些关系,有助于建立完整的知识图谱。技术学习不能孤立,要在关系网络中理解。每一个技术节点都与其他节点相连,只看到一个节点会失去全局视野。
