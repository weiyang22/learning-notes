# 01-如何阅读论文 - 3 遍阅读法 + 笔记模板

> **目标**: 在有限时间内最大化提取论文价值
> **核心**: 3 遍阅读法 (鸟瞰 → 主线 → 重建) + 笔记模板
> **实战**: 用 TokenMixer-Large 演示完整流程

---

## 0. 一句话总结

**3 遍阅读法** = 用 5 分钟抓摘要、1 小时抓方法、5 小时重建细节. 配合结构化笔记模板, 把"读论文"变成"会读论文".

---

## 1. 论文阅读的 5 类典型错误

### 1.1 顺序错误: 从第一行读到最后一行的"线性阅读"

**症状**: 从 Abstract 一路读到 Conclusion, 像读教科书
**问题**: 效率极低, 抓不到核心
**正确**: 先鸟瞰, 再深入

### 1.2 范围错误: 试图一次读懂所有细节

**症状**: 第一遍就试图理解每个公式
**问题**: 数学劝退, 信心崩盘
**正确**: 第一遍只看图和表, 公式第二遍再看

### 1.3 视角错误: 只读作者想让你看到的

**症状**: 完全相信作者的说法, 不质疑
**问题**: 学不到批判性思维, 错过隐藏洞察
**正确**: 每个设计都要问"为什么这样, 而不是那样"

### 1.4 链接错误: 孤立读论文, 不建立跨论文联系

**症状**: 读 100 篇, 写 100 个独立笔记
**问题**: 知识是孤岛, 不能形成洞察
**正确**: 用 24 篇 deep-dives 的方式建立知识图谱

### 1.5 行动错误: 读完不输出

**症状**: 读完就忘, 或者收藏吃灰
**问题**: 没有内化, 时间浪费
**正确**: 必须有产出 (笔记 / 复现 / 演讲 / 博客)

## 2. 3 遍阅读法详解

### 2.1 时间分配

| 遍数 | 时间 | 目标 | 产出 |
|------|------|------|------|
| **第 1 遍** | 5-10 分钟 | 鸟瞰, 决定是否深读 | 一句话判断 + 优先级 |
| **第 2 遍** | 1-2 小时 | 抓住主线, 理解核心 | 结构化笔记 (骨架) |
| **第 3 遍** | 3-5 小时 | 重建细节, 批判分析 | 深度笔记 + 个人洞察 |

### 2.2 第 1 遍: 鸟瞰 (5 分钟)

**目标**: 决定这篇论文**值不值得**我花更多时间

**步骤**:
1. **读标题 + 摘要**: 1 分钟. 用一句话概括论文做了什么.
2. **看图表**: 3 分钟. 重点看主要架构图 + 主要结果表.
3. **看结论**: 1 分钟. 看作者宣称的"最重要贡献"是什么.
4. **看作者和单位**: 1 分钟. 是工业界 SOTA 还是学术界?

**判断**:
- 如果和我的工作**直接相关**: 进入第 2 遍
- 如果**间接相关或可借鉴**: 跳过细节, 只记核心思路
- 如果**无关**: 收藏, 后续按需

**示例: TokenMixer-Large**
- 标题: "Scaling Up Large Ranking Models"
- 公司: ByteDance
- 一句话: 在 TokenMixer 基础上扩展到 7B-15B, 用 Mixing-and-Reverting + Per-token MoE
- **判断**: 和 GR 直接相关, 必须深读

### 2.3 第 2 遍: 抓住主线 (1-2 小时)

**目标**: 理解论文的**核心方法**和**主要结果**

**步骤**:
1. **读 Introduction** (10 分钟): 问题是什么? 前作有什么不足? 作者怎么声称解决?
2. **读 Method 主章节** (40 分钟): 重点关注架构图, 不要陷入公式细节
3. **读 Experiments** (20 分钟): 主要结果表 + 关键消融
4. **画架构图** (10 分钟): 用自己的话重新画出核心架构

**产出**: 一份**结构化笔记**, 包含:
- 一句话核心方法
- 3-5 个关键创新点
- 主要结果 (数字)
- 主要消融 (哪些组件重要)

**示例: TokenMixer-Large**
- 核心方法: 在 TokenMixer 基础上加 Mixing-and-Reverting + Per-token MoE
- 关键创新: (1) Mixing-and-Reverting (2) Inter-Residual (3) Per-token MoE (4) Token-Parallel
- 主要结果: 7B 在线, +2% ADSS / +2.98% GMV
- 主要消融: Mixing-and-Reverting 是关键

### 2.4 第 3 遍: 重建细节 (3-5 小时)

**目标**: **批判性**理解, 形成个人洞察

**步骤**:
1. **精读 Method** (90 分钟): 每个公式都要推一遍
2. **批判性分析** (30 分钟): 找作者的局限 / 隐藏假设 / 没解决的子问题
3. **跨论文联系** (30 分钟): 和之前读过的论文建立联系
4. **写"如果是我"** (30 分钟): 想象自己设计这个方案, 会怎么做
5. **记个人洞察** (30 分钟): 这篇论文给你的启发是什么

**产出**: 一份**深度笔记**, 包含:
- 完整的公式推导
- 5+ 个批判性问题
- 与 5+ 篇其他论文的联系
- 个人 "如果是我" 的设计想法
- 可应用到工作中的 3 个具体想法

## 3. 笔记模板

### 3.1 第 1 遍笔记 (5 分钟版)

```text
# {论文标题}

> **作者 / 单位**: {公司}
> **会议/期刊**: {CIKM 2025 / arxiv}
> **一句话**: {核心方法}
> **核心数字**: {主要结果}
> **判断**: {值不值得深读}
> **优先级**: {P0/P1/P2/P3}
```

### 3.2 第 2 遍笔记 (1 小时版)

```text
# {论文标题}

## 1. 问题与动机
- 工业痛点: ...
- 现有方法的局限: ...
- 作者的洞察: ...

## 2. 方法核心
- 整体架构 (用 ASCII 图)
- 3-5 个关键模块

## 3. 主要结果
- 离线: ...
- 在线: ...

## 4. 关键消融
- 模块 A 影响: +X%
- 模块 B 影响: +Y%

## 5. 待深入的问题
- [ ] ...
- [ ] ...
```

### 3.3 第 3 遍笔记 (深度版)

见 TokenMixer-Large 深度解析 的完整结构:

- 元信息
- 背景与动机 (100+ 行)
- 相关工作对比
- 方法详解 (300+ 行, 含公式 + PyTorch 伪代码)
- 实验设置 + 结果 + 消融
- 工业部署细节
- 局限性与未来
- 个人评价
- 引用与延伸

## 4. 关键问题清单

读论文时要问自己的 20 个问题:

### 4.1 关于问题 (5 个)

1. 论文解决了什么**真实问题**?
2. 这个问题在工业上**痛**吗? 谁痛? 多痛?
3. 之前的解决方案**有什么问题**?
4. 作者**为什么**要解决这个特定问题 (不是其他)?
5. 问题解决后, **谁受益**?

### 4.2 关于方法 (5 个)

6. 核心方法**一句话**是什么?
7. 方法**相对前作的增量**是什么?
8. 这个方法**为什么有效** (机制 / 直觉)?
9. 方法**牺牲了什么**换取了什么?
10. 方法的**最关键假设**是什么?

### 4.3 关于实验 (5 个)

11. 离线数据集**和真实场景匹配**吗?
12. baseline **够强**吗? 缺了哪个 SOTA?
13. 消融**完整**吗? 有哪些没做的消融?
14. 在线 A/B 是**真实流量**吗? 多大流量?
15. 业务指标的**统计显著性**怎么样?

### 4.4 关于未来 (5 个)

16. 这篇论文**打开**了什么新方向?
17. **下一步**最该做什么?
18. 在你自己的**场景**能用吗? 怎么改?
19. 如果是你, 会怎么做 (批判性思维)?
20. 一年后回头看, 这篇论文**还有价值**吗?

## 5. 实战: 用 TokenMixer-Large 演示 3 遍阅读法

### 5.1 第 1 遍 (5 分钟)

读完 TokenMixer-Large 深度解析 后, 你能写出:

```text
- 公司: ByteDance
- 一句话: TokenMixer 升级版, 7B-15B 参数, 用 Mixing-and-Reverting + Per-token MoE 解决深层问题
- 主要数字: +2% ADSS, +2.98% GMV, +1.4% 营收
- 判断: 必读, 是字节规模化的代表作
```

### 5.2 第 2 遍 (1 小时)

理解:
- **整体架构**: Tokenization → TokenMixer-Large Block × N → Sparse Per-token MoE
- **关键模块**:
  - Mixing & Reverting (解决 token 混合后的信息损失)
  - Per-token SwiGLU (token-specific FFN)
  - Inter-Residual (稳定深层梯度)
  - Sparse Per-token MoE (稀疏激活扩展参数)

### 5.3 第 3 遍 (5 小时)

**批判性问题**:
1. 为什么 Mixing-and-Reverting 就能解决深层梯度消失? 作者没给出严格的数学证明
2. Per-token MoE 和 standard MoE 的实际差异? 训练稳定性如何?
3. 7B 参数的实际训练成本是多少? 单次训练需要多少 GPU 小时?
4. 在线推理 7B 参数的延迟是多少? 是否能扛住 p99 要求?

**个人洞察**:
- Token Mixer 派的核心是用 MLP 替代 attention, 牺牲全局建模换 MFU
- 字节的路线: TokenMixer → TokenMixer-Large, 是 "渐进式改进"
- 对比 Meta 的 HSTU: HSTU 是"激进式重新表述"

## 9. 实战深度演练: 用 3 遍阅读法读 HSTU

> HSTU (Hierarchical Sequential Transduction Unit, Meta 2024) 是 GR 范式的开山之作。下面用完整时间戳展示 3 遍阅读法。

### 9.1 第 1 遍: 鸟瞰 (5 分钟)

**00:00 - 00:30** 读标题 + 摘要
- 标题: "Actions Speak Louder than Words: Trillion-parameter Sequential Transducers for Generative Recommendations"
- 作者: Meta (Facebook)
- 会议: arXiv 2402.17152
- 一句话: 把推荐重新表述为 sequential transduction, 用统一架构表达召回 + 排序 + 重排

**00:30 - 03:00** 看图表
- Figure 1: 整体架构图 - HSTU block + 多任务 heads
- Table 1: 公开数据集结果 (MovieLens, Amazon Reviews)
- Table 2: 工业数据集 + 在线 A/B 结果

**03:00 - 04:00** 看结论
- 主要贡献: (1) 重新表述问题 (2) 设计 HSTU (3) 1.5T 参数 scaling (4) +12.4% 在线

**04:00 - 05:00** 看作者和单位
- 作者: Meta 应用 ML 团队 + 多伦多大学
- 判断: Meta 出品 + 工业级 + 范式创新 = **必读 P0**

**产出**: 一句话判断 + 优先级
```text
HSTU: Meta 出品的 GR 范式创新, 1.5T 参数. P0 必读.
```

### 9.2 第 2 遍: 抓住主线 (1.5 小时)

**00:00 - 15:00** 读 Introduction (15 分钟)
- **问题**: 推荐系统无法像 NLP 那样 scaling, 现有架构被召回/排序/重排的分离设计限制
- **洞察**: 如果把推荐表述为 sequential transduction (类似语言建模), 就能用统一架构
- **声称**: 我们的架构可以 scaling 到 1.5T 参数, 比 DLRM 在线 +12.4%

**15:00 - 60:00** 读 Method 主章节 (45 分钟)
- 3.1 Generative Recommendation Formulation
- 3.2 HSTU Architecture
  - Pointwise Projection
  - Spatial Aggregation
  - Gated MLP
- 3.3 Multi-task training
- 3.4 Scaling

**60:00 - 90:00** 读 Experiments (30 分钟)
- 4.1 Datasets (公开 + 工业)
- 4.2 Main Results (Table 1 + Table 2)
- 4.3 Ablation Study (Section 4.3)
- 4.4 Scaling (Section 4.4)

**90:00 - 105:00** 画架构图 (15 分钟)

```text
Input: User History (item sequence)
       ↓
[HSTU Block × N]  ← 共享参数
       ↓
Multi-task Heads (CTR / CVR / Like)
       ↓
Output: Top K items
```

**105:00 - 120:00** 写结构化笔记 (15 分钟)

**产出**: 一份结构化笔记, 包含:
- 核心方法: sequential transduction 统一召回+排序
- 关键创新: (1) Pointwise Projection (2) Gated MLP (3) 长序列稀疏注意力
- 主要结果: 公开 +65.8% NDCG, 工业 +12.4% 在线
- 主要消融: Gated MLP > Pointwise Projection

### 9.3 第 3 遍: 重建细节 (5 小时)

**00:00 - 90:00** 精读 Method (90 分钟)
- 3.1 节: 把推荐公式化为 P(y_t | x_1, ..., x_t), 类似 GPT 的 next token prediction
- 3.2 节: 仔细推导 HSTU 的每个组件
- 公式 (1): Pointwise Projection
- 公式 (2): Spatial Aggregation (稀疏注意力)
- 公式 (3): Gated MLP
- 3.3 节: 多任务 loss 加权
- 3.4 节: Scaling 实验设计

**90:00 - 120:00** 批判性分析 (30 分钟)
- 局限性 1: 论文没给出严格数学证明 sequential transduction 为什么优于 DLRM
- 局限性 2: 长序列稀疏注意力的"稀疏模式"是 hand-designed, 没有 learned sparse pattern
- 局限性 3: 1.5T 参数的部署成本可能很高, 没给出详细部署方案
- 局限性 4: 没讨论冷启动 (新用户/新物品) 如何处理
- 局限性 5: 多任务 loss 权重如何确定, 没说清楚

**120:00 - 150:00** 跨论文联系 (30 分钟)
- vs TokenMixer-Large: HSTU 用 attention, TokenMixer 用 MLP - MFU 取舍
- vs OneRec: HSTU 是 decoder-only, OneRec 是 end-to-end 生成
- vs TIGER: HSTU 不需要 Semantic ID, TIGER 需要 - 召回路径取舍
- vs MTGR: HSTU 是统一架构, MTGR 保留 DLRM 交叉特征 - 落地性取舍
- vs LFM4Ads: HSTU 是 Transformer, LFM4Ads 是 LFM - 范式差异

**150:00 - 180:00** 写"如果是我" (30 分钟)
- 如果我是 Meta 团队, 我会尝试:
  1. 用 learned sparse attention 代替 hand-designed pattern
  2. 探索 cold-start 场景 (HSTU 没覆盖)
  3. 给出"在低端 GPU 上的部署方案", 拓展落地性
  4. 用更小数据集验证是否真的需要 1.5T 参数
- 我会用 HSTU 的 sequential transduction 思想, 但用 TokenMixer 替代 attention (效率更好)
- 我会探索 HSTU + Semantic ID 的结合 (HSTU 做排序, SID 做召回)

**180:00 - 210:00** 记个人洞察 (30 分钟)
- **洞察 1**: HSTU 的真正贡献不是 architecture, 而是 "把推荐重新表述为 sequential transduction" (Kuhn 视角)
- **洞察 2**: HSTU 没说"为什么之前没人这么做", 但我相信原因是 DLRM 范式太成功, 没人愿意冒险 (Lakatos 视角)
- **洞察 3**: 1.5T 参数的部署成本是隐含 trade-off, 论文没讨论 (Popper 视角)
- **洞察 4**: HSTU 留下了 3 个开放问题: cold-start, learned sparse pattern, 与 LLM 融合
- **洞察 5**: HSTU 可能在 long-tail 用户上效果一般, 因为 sequential transduction 假设有"足够长的历史"

**210:00 - 240:00** 写"3 个可应用到工作中的想法" (30 分钟)
1. **想法 A**: 把我们当前的 DLRM 改成 sequential transduction 风格, 看 AUC 变化
2. **想法 B**: 用 HSTU 的稀疏注意力思想, 改造我们的 DIN, 看延迟能否降低
3. **想法 C**: 写一篇"GR 与 DLRM 取舍分析"的内部技术报告, 帮助团队理解方向

**产出**: 一份完整的深度笔记 (300+ 行), 包含公式推导、批判性分析、跨论文联系、个人洞察、可应用想法。

## 10. 阅读特殊章节的方法

### 10.1 数学附录 (Math Appendix)

**何时需要**:
- 第 1-2 遍: 不需要
- 第 3 遍: 必须, 但要选择性

**阅读策略**:
1. 先看附录标题, 判断是否相关
2. 跳到结论部分, 看作者的核心 claim
3. 再回到证明, 看每一步是否合理
4. 标注 3 类内容: (a) 接受 (b) 怀疑 (c) 不懂

**实战: HSTU 的 scaling analysis 附录**
- 附录 A: Chinchilla-like scaling law 推导
- 阅读策略: 跳过推导细节, 只看结论 (FLOPs-optimal 模型大小 vs 数据量)
- 个人收获: 推荐的最优 scaling 比例大约是 N ∝ D^0.5 (比 NLP 的 N ∝ D^0.5 略不同)

### 10.2 代码与开源实现

**何时需要**: 第 2 遍后, 准备复现时

**阅读代码的 3 个层次**:
1. **入口文件**: 看出输入输出
2. **核心模块**: 看出算法逻辑
3. **训练循环**: 看出优化策略

**24 篇论文的开源情况**:
- 大多数没有官方开源 (工业机密)
- 部分有 GitHub 仓库 (如 TIGER)
- 复现要自己实现: 从伪代码 + 论文描述

**实战建议**:
- "5 个核心文件原则": 复现时, 先读 5 个核心文件 (data loader / model / loss / train / eval)
- 不要追求完整复现, 先复现最核心的 1 个创新点
- 复现失败时, 记录失败原因 (比成功更有价值)

### 10.3 补充材料 (Supplementary)

**何时需要**:
- 论文会议版本 vs arxiv 版本: 可能有差异
- 补充材料常包含: 详细消融 / 失败案例 / 更多 baseline / 用户研究

**实战策略**:
- 第 1 遍: 跳过
- 第 2 遍: 看补充材料的"额外消融"
- 第 3 遍: 仔细看补充材料的"失败案例"

**HSTU 补充材料案例**:
- 提供了 6 个数据集的详细结果 (主论文只列 3 个)
- 提供了 sensitivity analysis (学习率 / batch size / 序列长度)
- 提供了 cold-start 场景的简单讨论

### 10.4 引言 (Introduction) 的精细阅读

**引言的 3 段式结构 (大多数论文)**:
1. **第 1 段**: 大背景 (RecSys is important)
2. **第 2 段**: 现有方法的不足 (DLRM can't scale)
3. **第 3 段**: 我们的方法 (We propose HSTU)

**精读引言的 3 个关键问题**:
1. **作者把问题框定为什么?** (决定了你怎么理解它)
2. **作者认为前作有什么不足?** (决定了你知道哪些限制)
3. **作者声称的核心贡献是什么?** (决定了你期待什么)

**反例: 引言中常见的"过度宣称"**:
- "We are the first to..." (未必)
- "State-of-the-art performance..." (baseline 可能不强)
- "Significant improvement..." (5% 算不算 significant?)

## 11. 阅读不同类型论文的方法

### 11.1 研究论文 vs 综述论文

| 维度 | 研究论文 | 综述论文 |
|------|---------|---------|
| **目标** | 提出新方法 | 总结已有工作 |
| **结构** | Intro → Method → Exp → Conclusion | Introduction → Taxonomy → Methods → Trends |
| **阅读重点** | 方法 + 创新 | 分类 + 全局视角 |
| **时间分配** | 5h 第 3 遍 | 2h 第 2 遍 |
| **笔记形式** | "5 问 5 答" | "分类 + 对比表" |

### 11.2 长论文 (50+ 页) 的阅读法

**典型案例**: TIGER 论文 + 补充材料 30 页, HSTU 论文 20 页 + 补充 20 页

**阅读策略**:
1. **第 1 遍**: 只看主论文, 不看补充
2. **第 2 遍**: 主论文 + 补充材料的核心表格
3. **第 3 遍**: 补充材料的"细节消融"

**避免"补充材料疲劳"**:
- 补充材料不是"必读", 而是"按需"
- 只看与你研究相关的部分
- 用 Ctrl+F 搜索关键词 (cold-start, scaling, ablation)

### 11.3 中文论文 vs 英文论文

**差异**:
- 中文: 表达直接, 实验详尽, 但创新性可能弱
- 英文: 表达严谨, 创新性强, 但实验有时"飘"

**阅读策略**:
- 中文论文: 重点看实验 + 业务背景
- 英文论文: 重点看方法 + 理论分析

**24 篇论文的语种**:
- 大多数英文 (顶会标准)
- 部分中文 (工业实践导向)

### 11.4 工业博客 vs 学术论文

**工业博客 (如 Meta AI Blog, Google Research Blog)**:
- 通常更通俗
- 重点展示业务价值
- 缺少完整消融

**学术论文**:
- 严谨但枯燥
- 重点展示方法创新
- 有完整消融

**阅读建议**:
- 工业博客: 5 分钟鸟瞰 + 关注业务价值
- 学术论文: 3 遍阅读法 + 关注方法创新

## 12. 5 类常见阅读陷阱

### 12.1 陷阱 1: "我全看懂了"幻觉

**症状**: 读完一篇论文, 觉得"挺简单, 我也会"
**问题**: 实际上没看懂, 只是看过了文字
**修正**: 第 3 遍后, 尝试**口述给朋友听**, 看能不能讲清楚

### 12.2 陷阱 2: "过度相信作者"

**症状**: 论文说"我们的方法最好", 你就信了
**问题**: 论文 baseline 可能不强, 数据集可能适合他们
**修正**: 主动找 baseline 的强实现, 对比看

### 12.3 陷阱 3: "细节迷失"

**症状**: 纠结某个公式的某一步
**问题**: 失去了对全篇的整体理解
**修正**: 用"先全局后细节"原则, 第 1-2 遍不要陷入细节

### 12.4 陷阱 4: "读 100 篇但不深入"

**症状**: 读 100 篇论文, 但每篇只读了 5 分钟
**问题**: 没有真正的洞察
**修正**: "5 + 1 原则": 每周 5 篇 5 分钟鸟瞰 + 1 篇 5 小时深读

### 12.5 陷阱 5: "只看 2024 年的论文"

**症状**: 只看最新论文, 忽略经典
**问题**: 不理解技术演进的历史
**修正**: 经典论文 (如 DIN, DLRM, BERT4Rec) 必须读 + 现代论文 (如 HSTU, TIGER) 必须读

## 13. 阅读效率提升: 5 条小技巧

### 13.1 技巧 1: 用 AI 工具做第 1 遍

**工具**: alphaxiv.org, ChatGPT, Claude
**用法**:
- 粘摘要 + 结论, 让 AI 总结核心方法
- 让 AI 列出 3-5 个关键创新点
- 让 AI 评估"这篇论文适合谁读?"

**优点**: 5 分钟变 2 分钟
**风险**: AI 可能不准确, 第 2-3 遍还是要亲自读

### 13.2 技巧 2: 用 Ctrl+F 搜索关键词

**何时用**: 第 2 遍后, 找具体细节
**搜索关键词**:
- "ablation": 找消融
- "limitation": 找局限
- "future work": 找未来方向
- "compared to": 找对比
- "trade-off": 找取舍

### 13.3 技巧 3: 看图先于看字

**原理**: 图像信息密度比文字高 10 倍
**应用**:
- 第 1 遍只看图 (架构图 + 结果表)
- 第 2 遍看图 + 文字
- 第 3 遍看图 + 文字 + 公式

### 13.4 技巧 4: 记下"看不懂的地方"

**实践**:
- 读到不懂的地方, 不跳过, 标记 "?"
- 第 2 遍后, 看 ? 是否自然解决
- 第 3 遍还不懂的, 跳过 (可能是论文没说清楚)

### 13.5 技巧 5: 把论文变成"卡片"

**实践**:
- 每篇论文做成一张"卡片", 包含:
  - 一句话核心方法
  - 3-5 个创新点
  - 主要结果 (数字)
  - 主要消融
  - 跨论文联系 (与哪 3 篇相关)
- 把卡片放在 Obsidian / Notion 里, 形成知识图谱

## 14. 多种论文的实战阅读示例

### 14.1 示例 1: OneTrans 的 3 遍阅读 (字节 2024)

**第 1 遍**:
- 公司: ByteDance
- 一句话: 异构参数化 Transformer, 序列 token 共享权重, 非序列 token 特化权重
- 主要数字: Feeds +5.68% gmv/u
- 判断: P1 必读, 字节的 GR 架构代表作

**第 2 遍**:
- 整体架构: Unified Tokenizer → Mixed Param Transformer → Pyramid Schedule
- 关键模块: (1) S-token / NS-token 区分 (2) 异构参数化 (3) Pyramid 剪枝 (4) Cross-request KV Cache
- 主要消融: 异构参数化是关键

**第 3 遍 批判**:
- 局限 1: 异构参数化增加了实现复杂度, 维护成本高
- 局限 2: Pyramid Schedule 的剪枝比例没有理论依据
- 局限 3: Cross-request KV Cache 假设用户行为可缓存, 但隐私场景下不成立
- 跨论文联系: OneTrans 借鉴了 HiFormer 的双塔思想; 与 TokenMixer-Large 都属于字节派

**个人洞察**:
- OneTrans 的核心是 "异构参数化", 解决 "序列 vs 非序列 不同处理" 的问题
- OneTrans 的 trade-off: 复杂度↑ vs 效果↑

### 14.2 示例 2: NEZHA 的 3 遍阅读 (快手 2024)

**第 1 遍**:
- 公司: Kuaishou
- 一句话: 用 speculative decoding 把 GR 推理延迟从 1000ms 降到 30ms
- 主要数字: 30x 加速, AUC 损失 < 1%
- 判断: P3 必读, 工程优化代表作

**第 2 遍**:
- 整体架构: Draft Model + Verify Model + Hash-based Verification
- 关键模块: (1) Draft Model (轻量) (2) Hash 验证 (3) Beam Search 优化
- 主要消融: Hash 验证是关键 (没有它, 加速只有 5x)

**第 3 遍 批判**:
- 局限 1: Draft Model 训练需要额外成本, 没详细说
- 局限 2: Hash 验证假设语义空间稳定, 但 SID 微调会失效
- 局限 3: 30x 加速在生产环境能保持吗? (论文用了 toy 例子)
- 跨论文联系: 借鉴了 LLM 的 speculative decoding (Leviathan et al. 2023); 与 GR 系列 (HSTU, OneRec) 是配套技术

**个人洞察**:
- NEZHA 的核心是 "在 GR 推理中应用 LLM 的投机解码思想"
- NEZHA 的 trade-off: 训练成本↑ vs 推理成本↓ (对在线服务很重要)

### 14.3 示例 3: Wukong 的 3 遍阅读 (Meta 2024)

**第 1 遍**:
- 公司: Meta
- 一句话: 发现 DLRM 的 scaling law, 提出 Stacking 机制
- 主要数字: 首次给出 DLRM 的 FLOPs-optimal 比例
- 判断: P0 必读, 理论分析代表作

**第 2 遍**:
- 整体架构: 改进 DLRM + 找到 scaling law
- 关键模块: (1) Stacking Layer (2) Scaling Law 推导
- 主要消融: Stacking Layer 比单纯增加 dense layer 更有效

**第 3 遍 批判**:
- 局限 1: Scaling Law 的形式假设与 NLP 类似, 缺乏理论证明
- 局限 2: Stacking Layer 的具体实现细节不清楚
- 局限 3: 在小模型 (< 1B) 上的表现没说
- 跨论文联系: 与 HSTU 是姊妹篇 (HSTU 找 Transformer 的 scaling, Wukong 找 DLRM 的 scaling)

**个人洞察**:
- Wukong 的核心是 "首次给出 DLRM 的 scaling law", 回答了 "DLRM 能不能 scaling?" 的问题
- Wukong 的 trade-off: 架构改进 vs scaling 规律 (两者是相关的)

### 14.4 示例 4: TIGER 的 3 遍阅读 (Google 2023)

**第 1 遍**:
- 公司: Google
- 一句话: 用 RQ-VAE 生成 docID, 用 Transformer 生成 docID 序列
- 主要数字: 零样本检索接近 BM25
- 判断: P0 必读, GR 范式的另一个分支

**第 2 遍**:
- 整体架构: RQ-VAE Encoder → Semantic ID → Transformer Decoder → Beam Search
- 关键模块: (1) RQ-VAE (2) docID tokenization (3) Constrained Beam Search
- 主要消融: RQ-VAE 是关键 (没有它, 性能大幅下降)

**第 3 遍 批判**:
- 局限 1: docID 编码的质量直接影响检索质量, 但如何保证高质量没说
- 局限 2: Constrained Beam Search 的计算成本高
- 局限 3: 没在工业规模数据上验证
- 跨论文联系: 与 HSTU 同期独立提出 GR 范式; 借鉴了 NLP 的生成式检索 (DocNLI, GENRE)

**个人洞察**:
- TIGER 的核心是 "用生成取代检索", 重新定义召回
- TIGER 的 trade-off: 召回质量 vs 计算成本

### 14.5 示例 5: LFM4Ads 的 3 遍阅读 (腾讯 2024)

**第 1 遍**:
- 公司: Tencent
- 一句话: 三塔 LFM (UR/IR/CR) + 时序 EMA 聚合, 用 LLM 风格训练广告基础模型
- 主要数字: 5 个公开数据集 + 腾讯广告业务均提升
- 判断: P0 必读, 借鉴 LLM 范式

**第 2 遍**:
- 整体架构: User Tower + Item Tower + Cross Tower → Mix Tower → 输出
- 关键模块: (1) 三塔设计 (2) Mix Tower (3) 时序 EMA 聚合 (4) LFM 风格预训练
- 主要消融: 三塔比单塔好, Mix Tower 是关键

**第 3 遍 批判**:
- 局限 1: 三塔增加了工程复杂度
- 局限 2: 时序 EMA 聚合假设历史分布稳定, 但广告场景分布变化快
- 局限 3: 预训练成本没说
- 跨论文联系: 借鉴了 LLM 的 Foundation Model 思想 (BERT, GPT); 与 HSTU 是同一波 GR 浪潮

**个人洞察**:
- LFM4Ads 的核心是 "把广告推荐做成 Foundation Model"
- LFM4Ads 的 trade-off: 工程复杂度↑ vs 跨场景泛化↑

## 15. 阅读论文的元方法: 5 个认知工具

### 15.1 工具 1: "先找作者, 再读论文"

**方法**:
- 读论文前, 先看作者群
- 查作者过去 3 年的工作
- 看作者在 Twitter / 知乎 / 个人博客的发言

**目的**: 理解作者的"研究纲领" (Lakatos 视角)

**例子**:
- HSTU 作者: 多来自 Meta 应用 ML 团队, 长期做 DLRM 和 scaling
- HSTU 不是"突然的灵感", 而是 DLRM 团队 3 年的累积

### 15.2 工具 2: "先找基线, 再读方法"

**方法**:
- 列出论文的所有 baseline
- 查这些 baseline 的原始论文
- 看 baseline 在你的场景下表现如何

**目的**: 评估论文的"相对贡献"

**例子**:
- TokenMixer-Large 的 baseline 包括 RankMixer, Wukong, HiFormer, DHEN
- 如果你不知道这些 baseline, 就无法评估"贡献了多少"

### 15.3 工具 3: "先找数据集, 再读结果"

**方法**:
- 列出论文用的所有数据集
- 查数据集的规模、特点、限制
- 看结果在哪些数据集上"涨"了, 哪些"跌"了

**目的**: 评估论文的"泛化性"

**例子**:
- HSTU 在 MovieLens / Amazon Reviews / 工业数据上都涨了
- 说明 HSTU 跨数据集泛化能力强

### 15.4 工具 4: "先找消融, 再读结论"

**方法**:
- 看消融表, 找出哪些组件是关键
- 看作者如何"讲故事": 把关键组件放在最显眼位置

**目的**: 区分"必要"和"可选"组件

**例子**:
- TokenMixer-Large 消融: Mixing-and-Reverting 去掉后, AUC 下降最多 → 关键
- 其他组件去掉后, AUC 下降较小 → 可选

### 15.5 工具 5: "先找局限, 再读贡献"

**方法**:
- 主动找论文的 Limitations 章节
- 主动找消融中的"异常"
- 主动找实验结果中的"反常"

**目的**: 批判性理解

**例子**:
- HSTU 没明确说冷启动问题 → 可能的局限
- TokenMixer-Large 在电商场景涨 2.98%, 但广告场景涨 2% → 可能电商场景更适配

## 16. 跨论文阅读: 形成"知识图谱"

### 16.1 为什么需要跨论文阅读

- 单篇论文是"点", 跨论文是"面"
- 真正的洞察来自"模式识别": 5 篇都提了 X, 那 X 可能是趋势

### 16.2 跨论文的 4 类联系

| 联系类型 | 例子 |
|---------|------|
| **同源** | HSTU 和 OneRec 都基于 sequential transduction |
| **对比** | HSTU (attention) vs TokenMixer (MLP) |
| **互补** | HSTU (架构) + NEZHA (推理) |
| **演进** | TokenMixer → TokenMixer-Large → MixFormer |

### 16.3 跨论文笔记模板

```text
# 主题: {例如 "GR 的稀疏化"}

## 涉及论文 (5 篇)
1. HSTU - 稀疏 attention
2. TokenMixer-Large - 稀疏 MoE
3. SMES - 稀疏 expert
4. MSN - PKM 替代 MoE
5. MTmixAtt - AutoToken

## 共性
- 都在追求"减少计算量, 保持效果"

## 差异
- HSTU 用结构化稀疏 (固定 pattern)
- TokenMixer-Large 用动态稀疏 (MoE routing)
- MSN 用 memory-based 稀疏 (PKM)
- 各有适用场景

## 我的洞察
- 稀疏化是"规模化的必经之路"
- 不同稀疏方法适合不同场景
- 下一步: 探索 learned sparse pattern
```

## 20. 论文阅读的元认知: "如何学会阅读"

> 最后谈谈"如何学会阅读论文"这件事本身。

### 20.1 阅读论文是"技能", 不是"天赋"

**常见误解**: "我读得慢, 我不适合做研究"
**真相**: 阅读论文是 learned skill, 通过训练可以变快

**训练方法**:
- 每周 5 篇 5 分钟鸟瞰 + 1 篇 1 小时主线 + 0.2 篇 5 小时深读
- 持续 3 个月后, 阅读速度会明显提升

### 20.2 阅读论文有"复利效应"

**第 1 个月**: 读完一篇, 只能写 5 句话
**第 3 个月**: 读完一篇, 能写 3 段笔记
**第 6 个月**: 读完一篇, 能写完整分析
**第 12 个月**: 读完一篇, 能立即想到 3 个改进方向

### 20.3 阅读论文是"研究"的 50%

**另一半是什么?**
- 20% 是"做实验"
- 20% 是"写代码"
- 10% 是"思考"

**启示**: 不要轻视阅读, 它是研究的"地基"

### 20.4 阅读的 3 个层次

```text
Level 1: 读懂作者说了什么 (5 分钟)
Level 2: 读懂作者为什么这么说 (1 小时)
Level 3: 读懂作者没说什么 (5 小时)
```

**最高境界是 Level 3**: 读出作者没说出口的假设、局限、隐含的 trade-off。

### 20.5 最后: 5 个阅读习惯

1. **每天 30 分钟**: 5 分钟鸟瞰 2-3 篇, 选 1 篇深读
2. **每周 1 篇精读**: 至少 1 小时主线 + 1 小时批判
3. **每月 1 次复盘**: 整理本月读过的, 形成知识图谱
4. **每季度 1 次输出**: 写 1 篇博客 / 综述
5. **每年 1 次范式扫描**: 看 NLP / CV 领域有什么新思想

## 扩展 A · 论文阅读方法 的可执行手册（2026-07-24）

> 本扩展围绕“从摘要扫描推进到公式、代码、实验和批判性复现，避免只记标题和结论”补充决策表、练习卡和复盘证据。它不替代正文，而是把正文转化为可以执行、检查和复用的工作单元。

### A.1 使用规则

1. 先选一个对象，不要同时打开整章；
2. 先写假设和约束，再选择方法或工具；
3. 每次只改变一个主要变量，保留原始证据；
4. 结论必须连接到一个指标、一个链接或一个可运行的最小例子；
5. 没有通过验证的内容，标记为“待证据”，不要写成确定事实。

## 21. 实战练习 (5 个可立刻动手)

### 21.1 练习 1: 用三遍阅读法读一篇未读过的论文

**目标**: 验证你已掌握三遍阅读法, 且能在 ≤ 2 小时内产出 5 张结构化卡片。

```text
步骤:
  Day 1  选 1 篇未读过的论文 (推荐: HSTU 或 TIGER)
        用 30 分钟做"第一遍": 只看标题/摘要/结论/图表
        写下: "这篇论文解决什么问题? 用什么方法? 效果如何?"

  Day 2  用 60 分钟做"第二遍": 完整读, 不查任何东西
        写下: 模型架构、损失函数、训练目标、数据集、baseline
        画出 1 张"模型流程图" (手绘即可)

  Day 3  用 30 分钟做"第三遍": 重点读公式 + 实验
```

**目标**: 不止"读懂", 还要"挑刺"。每篇论文至少写 5 个批判性问题。

4. **成本/收益**: "提升 2% 需要 10x 算力, 值吗?"
5. **业务约束**: "上线延迟 30ms 能满足吗? 在线学习能支持吗?"

## 23. 常见错误案例 (6 个)

### 23.1 错误 1: "我读完了 100 篇论文, 但什么都没记住"

**症状**: 收藏 100+ PDF, 真正读懂的 < 10 篇。

**根因**:
- 缺少笔记 → 读完即忘
- 没有"用自己的话重写" → 信息没有内化
- 没有定期复盘 → 笔记躺在 Obsidian 吃灰

**解决**:
1. 强制"读完必写卡"
2. 每月 1 次"卡片大扫除", 把旧卡和新学到的连接
3. 每季度 1 次"反向叙述", 不看笔记讲 5 分钟

### 23.2 错误 2: "我复现了 baseline, 但不知道怎么改进"

**症状**: 能跑通 baseline, 但提不出有价值的改进方向。

**根因**:
- 只读了"做了什么", 没读"为什么这么做"
- 没有记录"作者的 design choice", 不知道为什么选 A 不选 B
- 没读 follow-up 论文, 不知道后续怎么改进

**解决**:
1. 复现时强制写"作者为什么选 X" (即使论文没明说)
2. 读 3 篇 follow-up 论文, 提炼"改进方向"
3. 与 mentor 聊 30 分钟, 验证自己的判断

### 23.3 错误 3: "我的笔记全是原文复制"

**症状**: 笔记 = PDF 文字 + 图, 没自己的判断。

**根因**: 误以为"摘抄 = 学习"。

**解决**: 强制"用自己的话写 3 句话总结" + 5 个 takeaway。

### 23.4 错误 4: "我看完摘要就觉得这篇不行"

**症状**: 30 秒看摘要, 直接跳过。

**根因**:
- 没做"第一遍"应有的扫描
- 没有"暂时搁置"机制, 直接判死刑

**解决**: "第一遍"后不确定时, 放进"待定"文件夹, 不直接跳过。

### 23.5 错误 5: "我读了别人的笔记, 没读原文"

**症状**: 看过 50 篇二手笔记, 但没读过 5 篇原文。

**根因**: 二三手笔记有信息损失, 关键细节会丢失。

**解决**: 任何核心论文必须读原文至少 1 遍。

### 23.6 错误 6: "我只读 SOTA 论文, 不读经典"

**症状**: 只追最新 KDD/SIGIR, 不读 DIN/Transformer/DLRM。

**根因**: 以为"老 = 过时", 但经典论文定义了问题。

**解决**: 经典论文至少读 1 遍 (DIN/DLRM/Transformer/GBDT+LR)。

## 26. 跨方法对照: 三遍阅读法 vs SQ3R vs 其他

| 方法 | 步骤 | 适合场景 | 优点 | 缺点 |
|------|------|---------|------|------|
| **三遍阅读法** | 概览 → 完整 → 验证 | 学术论文 | 节奏清晰 | 不适合科普 |
| **SQ3R** | Survey → Question → Read → Recite → Review | 教科书 | 主动回忆 | 速度慢 |
| **逆向工程** | 实验 → 方法 → 问题 | 复现型阅读 | 实践导向 | 容易只见树木 |
| **关键词阅读** | 摘要 → 关键词 → 章节 | 快速筛选 | 极快 | 信息损失大 |
| **主题阅读** | 5+ 篇同主题横向 | 写综述 | 系统全面 | 耗时极长 |
| **AI 辅助阅读** | AI 总结 → 原文验证 | 大量初筛 | 10x 提速 | 依赖 AI 质量 |

### 26.1 何时用哪种方法?

| 场景 | 推荐方法 | 时间预算 |
|------|---------|---------|
| 入门新方向 | 主题阅读 (5 篇) | 1 周 |
| 跟进最新 SOTA | 三遍阅读法 | 2h/篇 |
| 复现一篇论文 | 逆向工程 | 1-2 周 |
| 写综述/博客 | 主题阅读 + 三遍 | 2-4 周 |
| 快速决策 (是否要做) | AI 辅助 + 第一遍 | 30min |
