# 第09章-10 - 科研日志模板

> **核心问题**: 如何把"看论文 / 做实验 / 写笔记 / 复盘"系统化, 让科研工作**可持续积累**?
>
> **目标**: 建立一套"日 / 周 / 月 / 季"4 层次的科研日志体系, 让 24 篇论文的学习过程可追踪、可复盘、可复用.
>
> **实战**: 以 TokenMixer-Large 为例, 演示完整的科研日志流程.

---

## 0. 一句话总结

> **科研日志不是"写日记", 而是"建立个人知识管理体系", 让你的工作**留痕、可检索、可复用**.

---

## 1. 为什么需要科研日志

### 1.1 痛点: 不做日志的代价

| 痛点 | 表现 | 后果 |
|------|------|------|
| **遗忘** | 看完论文 1 周后只记得标题 | 知识无法沉淀 |
| **重复** | 同一卡点反复卡 3 次 | 时间浪费 |
| **孤立** | 论文 A 和 B 的关系想不起来 | 无法横向对比 |
| **无复盘** | 半年没回头看, 不知道学到了什么 | 成长曲线不清晰 |
| **丢失** | 实验跑过的最佳超参忘了 | 重复劳动 |

### 1.2 日志的价值

| 价值 | 体现 |
|------|------|
| **外脑** | 帮你记住细节, 释放脑容量 |
| **可检索** | 1 分钟后找到 3 周前的某个想法 |
| **可复盘** | 季度总结直接基于日志数据 |
| **可分享** | 日志 = 给未来的自己 / 同事的文档 |
| **可量化** | "本周读了 5 篇论文" = 客观进度 |

### 1.3 谁需要科研日志?

| 人群 | 价值体现 |
|------|---------|
| **学生 / PhD** | 论文阅读 / 实验记录 / 文献综述 |
| **工业研究员** | 论文跟踪 / 实验记录 / A/B 报告 |
| **算法工程师** | 论文 + 工作日志 + 性能调优记录 |
| **面试准备者** | 知识点积累 + 模拟面试记录 |
| **终身学习者** | 跨学科学习笔记 |

## 2. 日志的 4 个层次

```text
日常科研日志体系
═══════════════════════════════════════════════════════════════
   每日 (Day)        ←  当日阅读 / 实验 / 想法 / 卡点
   每周 (Week)       ←  周报 (本周读完哪些, 实验跑完哪些)
   每月 (Month)      ←  月度复盘 (主线推进, 卡点, 下月计划)
   每季度 (Quarter)  ←  季度回顾 (大方向调整, OKR 校准)
═══════════════════════════════════════════════════════════════
```

### 2.1 4 层次的核心差异

| 层次 | 频率 | 时长 | 核心问题 | 输出物 |
|------|------|------|---------|--------|
| **每日** | 每天 | 5-15 分钟 | 今天做了什么? | 当日总结 |
| **每周** | 周末 | 30-60 分钟 | 本周推进了什么? | 周报 |
| **每月** | 月末 | 2-3 小时 | 本月主线卡在哪? | 月度复盘 |
| **每季度** | 季末 | 4-8 小时 | 季度目标完成多少? | 季度回顾 + OKR |

### 2.2 4 层次的依赖关系

```text
每日日志 ─── 7 条 ──→ 每周日志 (周报)
                            │
                            ↓
                  4-5 条周报 ──→ 每月日志 (复盘)
                                      │
                                      ↓
                            3 条月报 ──→ 每季度日志 (回顾)
```

### 7.3 实战示例: TokenMixer-Large 阅读日志

```text
## 论文阅读日志: TokenMixer-Large

## 1. 一句话总结
> TokenMixer-Large 通过 Mixing-and-Reverting + Sparse Per-token MoE 把 TokenMixer 从 1B 扩展到 15B (离线) / 7B (在线), 跨 1.5 个数量级仍遵循 alpha_N=0.093 的幂律.

## 2. 核心问题
- 现有 TokenMixer (RankMixer) 在深层堆叠遇到 4 大瓶颈:
  1. 次优的残差路径
  2. 深度堆叠时梯度消失
  3. MoE 稀疏化不完整
  4. 总规模化受限

## 3. 核心方案
### 3.1 架构图
```
Input → Tokenization → [TokenMixer-Large Block × N] → Sparse Per-token MoE → Output

Block = Mixing-and-Reverting + Per-token SwiGLU + Residual + LN + Interval Residual + Aux Loss
```text

### 3.2 关键创新
1. **Mixing-and-Reverting**: 修复 TokenMixer 的残差缺陷
2. **Interval Residual + Aux Loss**: 保证 7B-15B 深度时梯度健康
3. **Sparse Per-token MoE**: per-token expert, 参数扩展但计算量不成比例增加

## 4. 实验结果
- Feed Ads: +2.0% ADSS
- E-Commerce: +1.66% Order, +2.98% GMV
- Live Streaming: +1.4% 营收
- 参数: 15B 离线 / 7B 在线

## 5. 我的评价
- 优点: 真正解决 RankMixer 的扩展性问题
- 缺点: 15B 模型训练成本高
- 适用: 大公司 + 大流量场景
- 不适用: 中小公司 (算力不够)

## 扩展 A · 科研日志体系 的可执行手册（2026-07-24）

> 本扩展围绕“让每日观察、实验记录、周月复盘和季度目标形成可检索、可复用的证据链”补充决策表、练习卡和复盘证据。它不替代正文，而是把正文转化为可以执行、检查和复用的工作单元。

### A.1 使用规则

1. 先选一个对象，不要同时打开整章；

## 18. 常见错误案例 (5 个)

### 18.1 错误 1: "日志成了负担"

**症状**: 写日志 = 应付, 内容空洞。

**解决**: 模板极简 (5 个字段), 写满 5 分钟。

### 18.2 错误 2: "OKR 设定太空"

**症状**: OKR 像 wishlist, 不可量化。

**解决**: 用 [[10-科研日志模板]] 严格量化。

### 18.3 错误 3: "想法只进不出"

**症状**: backlog 满, 但没 1 个 PoC。

**解决**: 每月强制 1 个 idea 进 PoC。

### 18.4 错误 4: "实验日志不记录失败"

**症状**: 只记成功的实验。

**解决**: 强制"失败日志", 失败案例是金矿。

### 18.5 错误 5: "工具太多, 用不过来"

**症状**: 装了 10 个工具, 实际只用 2 个。

**解决**: 锁死 5 个核心工具, 不加新工具。
