## 1. LFM4Ads: Large Foundation Model for Ads Recommendation (腾讯)

**arXiv**: [2508.14948](https://arxiv.org/abs/2508.14948) · **作者**: Shangyu Zhang, Shijie Quan, Zhongren Wang, Junwei Pan 等 31 人 · **公司**: **Tencent** + **Tsinghua University** · **发表**: 2025-08

### 1.1 核心问题

现有基于 LFM (Large Foundation Model) 的广告推荐**只迁移 User Representations (UR)**, 忽视了 **Item Representations (IR)** 和 **User-Item Cross Representations (CR)**. 此外, 迁移机制限于特征级 (线性投影), 无法捕获语义差距. 多任务 / 多域场景下还有**负迁移**和**跷跷板现象**.

### 1.2 方法 / 架构

**三塔 Foundation Model** 在跨域 / 跨任务数据上训练:

1. **User Tower** → UR
2. **Item Tower** → IR
3. **Mix Tower** (双分支: 内容 + 广告) → 通过 FM, CrossNet, DNN 交互层产生 CR

**CR Aggregation (时序 EMA)**:
```text
CR(u) ← β(t(u)) · CR(u) + (1-β(t(u))) · CR(u, i)         # Eq. 1
CR(i) ← β(t(i)) · CR(i) + (1-β(t(i))) · CR(u, i)         # Eq. 2
```
β 是时间间隔的非递增函数 → 自适应活跃度.

**Layer Selection**: Mix Tower 的倒数第二层 MLP 是 CR 提取的最优层.

**三种下游使用粒度**:
- **特征级**: 非线性交互 `E' = E ⊙ σ(CR(u) · M)` (Eq. 3-4) — 作为 adapter 的门控
- **模块级**: 同构交互模块迁移用户-物品相关性
- **模型级**: 独立检索直接使用 UR + IR

### 1.3 创新点

1. **All-Representation Transfer** (UR + IR + CR), 首次系统利用工业 LFM 中的跨表征
2. **时序 EMA 聚合**: 把样本级 CR 转换为可迁移的用户 / 物品级形式
3. **多粒度迁移** (特征 → 模块 → 模型): 粒度越粗, 微调参数越少
4. **Mix Tower 双分支** (内容 + 广告): 缓解广告域数据稀疏

### 1.4 实验结果

- **离线**: Mix Tower 倒数第二层提取的 CR 一致优于其他层; 非线性交互优于线性投影
- **在线 (腾讯广告平台, 2024 Q4 生产)**: 微信朋友圈 / 视频号等场景 10+ 成功生产发布
- **平台级 +2.45% GMV 提升**, 年收入估算数亿美元
- 规模: 日均数百亿样本, TB 级参数, 千亿级稀疏 embedding keys, ~2000 特征

### 1.5 部署 / 代码

- **部署**: 腾讯广告平台 (微信朋友圈 / 视频号 / 视频号小店), 2024 Q4 起
- **代码**: 未开源

## 2. SMES: Scalable Multi-Task Recommendation via Expert Sparsity (快手)

**arXiv**: [2602.09386](https://arxiv.org/abs/2602.09386) · **作者**: Yukun Zhang, Si Dong, Xu Wang, Bo Chen 等 14 人 · **公司**: **Kuaishou Technology** (北京) · **发表**: 2026-02

### 2.1 核心问题

朴素扩展 Dense MoE 用于多任务推荐会:
- 在线推理成本高昂
- 在稀疏任务 (Like, Follow) 上边际收益递减 (标签分布偏斜)

两个关键障碍:
1. **专家激活爆炸**: 朴素 task-wise routing 产生 union |𝒰| ≤ min(E, TK), 退化为 dense-like 执行
2. **专家负载严重倾斜**: 多任务累积造成 hot-experts

### 2.2 方法 / 架构

**Progressive Expert Routing (PER)** + **Multi-Task Load-Balancing (MTLB) Regularizer**

#### Progressive Expert Routing (3 阶段)
```text
1. Task routers: 每个任务 t 有 logits z_t ∈ ℝ^E, softmax → p_t
2. Stage-I (任务共享 expert): s_e = Σ_t w_t · p_{t,e}  (Eq. 10)
                             𝒮 = TopK({s_e}, K_s)      (Eq. 11)
3. Stage-II (任务自适应 expert): 对每个任务,
                             𝒜_t = TopK({z_{t,e}}_{e∉𝒮}, K_a)  (Eq. 12)
4. 激活集: 𝒦_t = 𝒮 ∪ 𝒜_t, |𝒦_t| = K = K_s + K_a  (Eq. 13)
5. 去重执行: 𝒰 = ⋃_t 𝒦_t, 每个 expert 每个 instance 最多计算一次  (Eq. 14)
```

#### MTLB Regularizer (Eq. 16-17)
```text
聚合选择频率 f̄_e = (1/BT) Σ_b Σ_t 𝕀[e ∈ 𝒦_t^(b)]
聚合概率质量 p̄_e = (1/BT) Σ_b Σ_t p_{t,e}^(b)
Loss: ℒ_lb = (E/K) Σ_e f̄_e · p̄_e
```
耦合所有 T 个 router, 抑制跨任务热点.

#### 部署优化
- **Reindexed Grouped GEMM** (MegaBlocks 启发): Gather → Index Map → GroupedGEMM → Task-wise Reconstruction (Eq. 19-20)
- **Profiling-guided workspace allocator**: 从离线负载分布 P(N_act) 预分配固定大小内存页

### 2.3 创新点

1. **Expert 激活分解** (共享 + 私有), 把 |𝒰| 限制在 K_s + TK_a
2. **全局多门控负载均衡** (跨所有任务), 直接瞄准跨任务热点
3. **Reindexed Grouped GEMM**: 工业级去重稀疏执行

### 2.4 实验结果

- **离线 (KuaiRand-1K + 快手工业 4 亿用户 / 500 亿日志)**: SMES-S 匹配参数预算, 击败 PLE, MMoE, MoME, HoME, RankMixer; SMES-L 在 8% 稀疏度下进一步扩展且无延迟惩罚
- **在线 (快手短视频, 4 亿+ DAU)**: **+0.29% GAUC**, **+0.31% 用户观看时长**

### 2.5 部署 / 代码

- **部署**: 快手大规模短视频服务 (4 亿+ DAU)
- **代码**: 未开源

## 3. LASER: Long-sequence Attention with Segmented Efficient Representation (小红书)

**arXiv**: [2602.11562](https://arxiv.org/abs/2602.11562) · **作者**: Tianhe Lin, Ziwei Xiong, Baoyuan Ou, Yingjie Qin, Lai Xu 等 11 人 · **公司**: **Xiaohongshu (RedNote)** + Fudan University + Xi'an Jiaotong University · **发表**: 2026-02

### 3.1 核心问题

部署超长用户行为序列 (数千 item) 在工业规模遇到"延迟墙":

1. **系统 I/O 瓶颈**: 通过 RocksDB (RedLastN) 检索海量用户历史延迟高
2. **模型计算瓶颈**: 标准 attention 的 O(L²)

现有两阶段检索 (SIM) 遭受不可逆信息损失.

### 3.2 方法 / 架构 — 全栈优化框架

#### (1) SeqVault Serving Infrastructure
- 混合 **DRAM-SSD 索引**: 哈希表在内存 + 序列存储在磁盘
- **Schema-aware** 存储 (vs RocksDB 的 schema-unaware 字符串存储) → 紧凑数据布局
- 序列级 merge job (无 compaction)
- 分布式训练用 **ZSTD 压缩** 嵌入传输 → **40% 带宽减少**

#### (2) Segmented Target Attention (STA)
```text
将长度 L 序列分成 L' 段 (每段 w): [S_1, ..., S_L'] = split_seq(ℋ, w)  (Eq. 3)
每段目标注意力 + Sigmoid 门控 (silence 机制):
   s_i = STA(t, S_i) = Sigmoid(QK^T / γ) · V                       (Eq. 5)
```
- 低维投影: d_q ≪ d, 把 O(L·d²) → O(L·d·d_q)
- Sigmoid 取代 softmax (和不再受约束) → 独立门可逼近 0 (滤除噪声)
- Reshape-and-batched matmul (Eq. 8-12) 全局并行

#### (3) Global Stacked Target Attention (GSTA)
- M 层堆叠, 在压缩序列 ℋ' (长度 L') 上运算
```text
a_l = softmax((t_{l-1} W_q^l) (ℋ' W_k^l)^T / √d)  (Eq. 7)
t_l = t_{l-1} + o_l
```

#### (4) Multi-Resolution Feature Fusion
全局上下文 z + max_pool(ℋ') + 最近 r 段 → 输入 RankMixer

**复杂度 (Eq. 18)**: `C_LASER ≈ Ld²(1 + d_q/d + (2r+2M)/w)` — 线性 in L
例: L=1000, d=128, d_q=32, w=10, r=4, M=2: **0.4×10⁸ FLOPs** vs self-attention 的 3.2×10⁸ (**~8× 减少**)

### 3.3 创新点

1. **SeqVault** schema-aware DRAM-SSD 基础设施
2. **Sigmoid-based silence 机制** — 首次把 sigmoid 作为独立门用于目标注意力
3. **Vectorized global attention with reshape** — 避免冗余的 per-segment 矩阵乘

### 3.4 实验结果

- **SeqVault**: P99 延迟 ↓50%, CPU 使用 ↓75% vs RocksDB-based RedLastN
- **离线 (小红书广告, 30 天训练 / 3 天测试)**: LASER AUC = 0.7826, **+0.24% over base**; 优于 DIN (+0.12%), HSTU (+0.20%), Transformer (+0.22%)
- **消融**: recency embedding 最关键 (-0.09%); 多分辨率融合 -0.08%; sigmoid vs softmax -0.03%; w=10 最优
- **在线 A/B (>1 亿 DAU)**: **+2.36% ADVV**, **+2.08% 营收**
- 训练: 32 × NVIDIA L20 GPUs, batch size 2048/GPU, L=1000

### 3.5 部署 / 代码

- **部署**: 小红书广告生产排序, 替换短序列注意力, 与 RankMixer 集成
- **代码**: 未开源

## 4. OxygenREC: 京东电商 GR 框架

**arXiv**: [2512.22386](https://arxiv.org/abs/2512.22386) · **作者**: Xuegang Hao, Ming Zhang, Alex Li 等 32 人 · **公司**: **JD.com** (北京) · **发表**: 2025-12 (v2)

### 4.1 核心问题

现有生成式推荐 (GR) 方法:
1. 依赖**归纳模式匹配**, 缺乏基于世界知识的**演绎推理** (复杂上下文数据缺口, 意图解释逻辑缺口)
2. LLM 推理延迟对实时服务过高
3. **多场景可扩展性瓶颈**: 现有方法每个场景需独立训练 / 部署, 浪费资源

### 4.2 方法 / 架构 — Fast-Slow Thinking (京东 Oxygen 下一代电商 AI)

#### (1) Slow Thinking (近线 LLM 流水线)
- **时空 + 画像推理 (STP)**: LLM (JoyAI) 生成文本指令 / 推理, 用 (time, location, persona) 三元组索引
- **User Query Rewrite**: LLM_QR (Qwen3-0.6B 微调) 归一化噪声 query (通过率 95.33% vs DeepSeek-R1 88.67%)
- **User Intent Reasoning**: DeepSeek-R1 自动生成 rationale, 然后 SFT Qwen3-0.6B (72% 可用性)

#### (2) Fast Thinking (Encoder-Decoder Backbone)
- **Multimodal SIDs**: Item 通过对比 I2I 编码, 然后 RQ-KMeans 残差量化 → **3 层 × 8192 vocab 的层次化 SIDs**
- **Q2I Loss** 用于指令-物品对齐 (Eq. 2):
```text
ℒ_Q2I = -Σ q_i · t_i (对齐) + λ_r (-log[Var(Q) · Var(T)]) (正则) + λ_d · decorrelation
```
- **Instruction-Guided Retrieval (IGR)**: 用对齐的 query 嵌入从长期历史检索 top-K
- **Dual-Instruction**: I_s (场景信息 + trigger item) + I_r (推理指令嵌入)

#### (3) Multi-Scenario RL Alignment
- **Reward Mapping Service**: 统一格式 + 相对 + 排序 + 多样性奖励
- **Soft Adaptive Group Clip Policy Optimization (SA-GCPO)**: 一个策略对齐多个业务目标

### 4.3 创新点

1. **Fast-Slow Thinking 解耦**: LLM 推理近线化, 在线无 LLM 延迟
2. **Q2I 对齐** 把文本指令映射到 item 嵌入空间用于检索式过滤
3. **SA-GCPO** 通过场景指令 + 统一奖励实现 "train-once-deploy-everywhere"
4. **首个 GR 框架通过指令条件生成应对多场景可扩展性**

### 4.4 实验结果

- **训练框架**: 40% Model FLOPs Utilization (MFU)
- **xLLM 推理框架开源** (高性能 serving)
- **在线 A/B (京东核心场景)**: 订单量 / GMV 在首页 / 频道 Feed / 搜索 / I2I 等多场景显著提升
- 详细指标: Q2I 对齐提升检索精度; IGR 减少长历史噪声; SA-GCPO 在多场景上优于 GRPO/PPO

### 4.5 部署 / 代码

- **部署**: JD.com 多核心推荐场景 (首页 / 频道 Feed / 搜索 / I2I)
- **代码**: xLLM 推理框架已开源

## 5. InterFormer: Effective Heterogeneous Interaction Learning for CTR (Meta)

**arXiv**: [2411.09852](https://arxiv.org/abs/2411.09852) (v4 2025-09) · **作者**: Zhichen Zeng, Xiaolong Liu, Mengyue Hang 等 28 人 · **公司**: **Meta AI** + **UIUC** + **UIC** · **发表**: 2024-11 (v1) / 2025-09 (v4) · **接收**: CIKM 2025

### 5.1 核心问题

CTR 预测中处理异构信息 (用户画像, 行为序列, 上下文) 存在两个根本局限:
1. **跨模态交互不足** — 现有方法用**单向信息流** (非序列引导序列, 反向被忽略)
2. **信息聚合过于激进** — 早期求和 (sum/pool/concat) 造成信息过度损失

### 5.2 方法 / 架构 — InterFormer 模块, 交错式异构交互学习

**每个 Block 三个子架构**:

1. **Interaction Arch (橙)** — 学习**行为感知的非序列嵌入** (DCNv2 / DHEN 风格). 用序列摘要作为 query 指导非序列学习.
2. **Sequence Arch (蓝)** — 学习**上下文感知的序列嵌入** (Multihead Attention + **Personalized FFN (PFFN)**):
```text
PFFN(X_sum^(l), S^(l)) = f(X_sum^(l)) · S^(l)
```
f 是两层 MLP, 从非序列上下文生成个性化权重.

3. **Cross Arch (绿)** — Interaction 和 Sequence Arches 之间的双向桥, 用 MHA 进行有效信息选择 (保留一对一映射, 避免早期聚合).

**CLS Token** 在第一层添加, 用于全局序列表征.

### 5.3 创新点

1. **双向信息流** (序列 ↔ 非序列) — 首次处理相互利益
2. **Cross Arch** 通过 MHA 选择保留每个模态的完整信息
3. **Interleaving 设计** 统一异构交互为一个 stack
4. 兼容各种交互模块 (DCNv2, DHEN 等)

### 5.4 实验结果

- **公共数据集**: 高达 +0.14% AUC over SOTA
- **工业 Meta 数据集**: +0.15% Normalized Entropy (NE)
- **生产部署 (Meta Ads)**: **+0.15% 性能**, **+24% QPS** 提升 vs prior SOTA, 显著在线影响

### 5.5 部署 / 代码

- **部署**: Meta Ads 多平台生产 (自 2024 起)
- **代码**: 未开源

## 6. Kunlun: Establishing Scaling Laws for Massive-Scale Recommendation Systems (Meta)

**arXiv**: [2602.10016](https://arxiv.org/abs/2602.10016) (v3 2026-02) · **作者**: Bojian Hou, Xiaolong Liu, Xiaoyi Liu, Jiaqi Xu 等 27 人 · **公司**: **Meta Platforms** + OpenAI · **发表**: 2026-02

### 6.1 核心问题

联合建模用户历史 (序列) 和非序列上下文特征的推荐系统, 在规模化时遇到两个瓶颈:
1. **低效模块**: 3-15% MFU (vs LLM 的 40-60%) — 异构特征空间, 小 embedding dim, 不规则 tensor 形状, 内存受限操作
2. **资源分配低效**: 朴素均匀扩展带来递减收益

### 6.2 方法 / 架构 — 多层架构 + 两级效率协同设计

#### 低层级模块优化

1. **Generalized Dot-Product Attention (GDPA)** — 把 PFFN 重新表述为 cross-attention:
```text
Q = S^(l), K = w_1^(h) (X_sum^(l)), V = w_2^(h) (X_sum^(l))
GDPA_h(Q, K, V) = Activation_h(QK^T / τ) · V  (τ = maxlen(seq))  (Eq. 5)
```
FlashAttention 风格融合 kernel → **PFFN MFU ↑6×**, 通过残差支持稳定堆叠

2. **Hierarchical Seed Pooling (HSP)** — 3 阶段:
- Stage 1: 可学习 seed embeddings E_seed ∈ ℝ^(n_seeds × d) (n_seeds > n_tokens)
- Stage 2: Seed-level attention H_seed = MHA(Norm(E_seed), S, S)  (Eq. 7)
- Stage 3: **SumKronLinear** — Kronecker 压缩
```text
Y_b = Σ_i Z_i^T · X_b · W_i  (Eq. 8)
Z_i ∈ ℝ^(S×T), W_i ∈ ℝ^(D×D)
```
**14× 参数减少** vs 全连接; rank-k 跨维度表达力

3. **Sliding Window Attention** — O(Tw) 取代 O(T²): **31.1% QPS 提升** (Eq. 9)

#### 高层级计算再分配

4. **Computation Skip (CompSkip)** — 交替模式 (偶数层跳过 self-attn, 奇数层跳过 HSP+PFFN) → **~43.1% FLOPs 减少**, **~35% QPS 提升**
5. **Event-level Personalization** — 每事件类型配置 (d_model, n_heads, n_tokens, L, w). 例: Click (d=256, h=8, L=3, w=100) vs Impression (d=128, h=4, L=2, w=50)

#### 多层架构
- 每层 = Kunlun Transformer Block (GDPA-PFFN + MHA) + Kunlun Interaction Block (Weight Gen + HSP + Global Interaction with **Mixture of Wukong Experts**)
- 双向流: 非序列 → 序列 (通过个性化 GDPA) 和 序列 → 非序列 (通过 HSP 摘要)
- **Rotary Temporal Embeddings (ROTE)** — 扩展 RoPE 加 τ_t = log(1 + Δt/τ_scale)

### 6.3 创新点

1. **GDPA** — 首次注意力风格重新表述 PFFN, FlashAttention 风格 kernel 融合
2. **SumKronLinear** — Kronecker 压缩用于序列摘要, **14× 参数效率**
3. **CompSkip** 交替 + **Event-level personalization** 自适应资源分配
4. 建立**首个联合序列-非序列建模的可预测 scaling law**

### 6.4 实验结果

- **MFU**: 17% → **37%** on NVIDIA B200 GPUs
- **Scaling 效率**: 比 SOTA **↑2×**
- 数据集: 700 亿+ 样本, 数百 / 数千非序列特征, 10+ 序列 (长度数百到数千)
- Baselines: Wukong, InterFormer. HSTU 排除 (仅序列)
- **生产部署**: Meta Ads 主要模型, **+1.2% topline metric**

### 6.5 部署 / 代码

- **部署**: Meta Ads 主要生产模型
- **代码**: 未开源

## 7. HoMer: 解决异构性 (美团)

**arXiv**: [2510.11100](https://arxiv.org/abs/2510.11100) (v2 2025-10) · **作者**: Shuwei Chen, Jiajun Cui, Zhengqi Xu, Fan Zhang, Jiangke Fan 等 7 人 · **公司**: **Meituan** (上海) · **发表**: 2025-10

### 7.1 核心问题

CTR 预测的工业系统中三种异构性降低效果:
1. **特征异构**: 行为序列只有少量 side features, 而非序列特征丰富 → 兴趣表征粗粒度
2. **上下文异构**: 点级预测忽略跨物品交互上下文 (如多个相似物品同时曝光, 用户会做比较评估)
3. **架构异构**: 专业化模块 (DIN, DSIN, TWIN, SENet, FiBiNet, DCN, MoE) 碎片化整合 → 跷跷板效应, 低效模块, 难以扩展

### 7.2 方法 / 架构 — Homogeneous-Oriented Transformer

#### (1) Panoramic Sequence (全景序列)
每个行为现在包含**该历史请求时刻记录的所有非序列特征** (用户/物品画像, 交叉特征, 上下文). 由历史 CTR 预测样本按时间顺序聚合构建.

#### (2) Set-wise CTR Prediction
**每个请求一个样本** (不是每个 item). 把请求中所有 item 的画像 + 用户-item 交叉特征聚合成单个样本; 共享 item-independent 特征 (用户, 上下文, 全景序列). 一次模型调用处理所有 items.

#### (3) Homogeneous-Oriented Transformer (Encoder-Decoder)
- **Sequential Encoder** (L blocks) 处理全景序列:
```text
E_i^0 = σ_1(φ(f_pan_seq, i)) + σ_2(φ(p_i)) + σ_3(φ(a_i))  (Eq. 3)
标准 Transformer block  (Eq. 4-5)
```
- **Set-wise Decoder** (M blocks), 每个 block 两个子块:
  - **Cross-item interaction**: items 集合上的 self-attention
  - **User-item interaction**: 与 encoder 用户的 cross-attention
  - Eq. 6-11 详细描述输入准备和双注意力计算
- 输出: 两个 MLP 预测 p_i^exp (曝光) 和 p_i^clk (点击)

**训练目标**: 组合 loss + 辅助 impression signal (Eq. 14-16)
```text
ℒ = ℒ_clk + λ · ℒ_imp
```
ℒ_imp 在**所有**预排序 items 上计算 (不仅是已曝光) → 捕获丰富未曝光 items.

#### 部署优化
- Flash Attention + jagged tensor 处理变长输入
- Encoder / decoder 块 kernel fusion → MFU 7.8% → 12.2%
- **GPU 资源 ↓27%** vs baseline

### 7.3 创新点

1. **Panoramic sequence** — 首次把所有 side features 对齐到非序列特征丰富度
2. **Set-wise 预测范式** — 单次调用, 并行预测, 跨物品上下文
3. **Homogeneous 架构** — 移除模块碎片化, 支持扩展
4. 辅助 impression loss over full pre-ranking item set

### 7.4 实验结果

- **离线**: 4.2 亿请求, 3900 万用户, 69 万 items, 12.5 亿行为 (美团搜索广告)
- **+0.0099 AUC** over industrial baseline (0.001 即值得部署)
- Baselines: Point-wise Baseline, SASRec, DCNv2, Wukong, CIM, Point-wise HoMer
- HoMer 随 FLOPs 扩展优于 baselines
- **在线 A/B**: **+1.99% CTR, +2.46% RPM**, 服务数千万用户

- **部署**: 美团搜索广告系统
- **代码**: 未开源

## 8. MTmixAtt: Integrating MoE with Multi-Mix Attention for Large-Scale Recommendation (美团)

**arXiv**: [2510.15286](https://arxiv.org/abs/2510.15286) · **作者**: Zhaoyu Hu 等 · **公司**: **Meituan** · **发表**: 2025-10

### 8.1 核心问题

工业排序模型有三个瓶颈:
1. **手动特征工程** — 从业者手动聚类异构特征, 主观且不一致
2. **架构异构** — 不同模态需要不同网络 (稠密用 MLP, 序列用 Transformer, 图用 GNN), 集成复杂
3. **跨场景泛化** — 模型在场景间迁移失败 (如 首页 → 团购促销)

### 8.2 方法 / 架构 — 统一 token-mixing MoE

#### (1) AutoToken (自动特征分组)
```text
维度对齐: x̂_i = DNN_i(x_i)  (Eq. 2)  → X̂ ∈ ℝ^(n_f × e)  (Eq. 3)
可学习特征选择矩阵 W ∈ ℝ^(n_g × n_f)
Top-k 索引选择: T_k(W_i) = arg top-k(W_i)  (Eq. 4)
加权聚合: X = G(T_k(W), X̂) · S_k(W)  其中 S_k(W_i) = softmax(top-k(W_i))  (Eq. 5)
输出 shape: ℝ^(d × n_g), d = k × e
```

#### (2) MTmixAttBlock — 三个子模块

1. **Learnable Mixing Matrix (head-wise)**:
   - 每个 head h: Y^(h) = W_h^T · M^(h)  (Eq. 8)
   - 残差: Z^(h) = (I + W_h^T) M^(h)  (Eq. 9)
   - 转置后混合, 把 token 维度作为主维度
   - 最佳初始化: 正交矩阵 (启动时简化为转置)

2. **Shared Dense MoE**:
   - **细粒度 expert 切分**: 每个 FFN expert 切分成 m 子 expert (固定计算, 更多 expert)
   - **共享 expert 隔离**: K_s 始终激活的 expert 用于通用知识
```text
   h_t^l = Σ_{i=1}^{K_s} α_{i,t} · FFN_i(u_t^l) + Σ_{j=1}^{mN} β_{j,t} · FFN_j(u_t^l)  (Eq. 11)
   sigmoid gating  (Eq. 12)
```

3. **Multi-scenario Expert Networks**:
   - **跨场景共享 expert**: 门 p_{i,t} = σ(Gate_3(u_t^l || u_c^l))  (Eq. 13)
   - **稀疏场景 expert**: 路由 logit z_{i,t} = Gate_4([u_t^l || u_c^l]) + γ · 𝕀[i=i*]  (Eq. 14) — 奖励 γ 强制当前场景 expert 激活
   - Top-k 稀疏门控 + sigmoid (Eq. 15-17)

4. **输出头**: DNN for main scenario + MLoRA adapters for 其他场景

### 8.3 创新点

1. **AutoToken** — 首个数据驱动的自动特征分组, 去除人类偏见
2. **Multi-Mix Attention** — token mixing + expert mixing 在单一注意力式公式中
3. **Shared + 场景特定稀疏 expert** + 场景奖励路由
4. **正交 init** 给 mixing matrix 提供最佳起点

### 8.4 实验结果

- **TRec 数据集** (美团): 7.86 亿用户, 1.62 亿 items, 413 特征, 2 个月
- Baselines: Online Base, Transformer, WuKong, HiFormer, MLP-Mixer, RankMixer
- **MTmixAtt-15M**: CTR AUC 0.7792 (+0.11% vs RankMixer), CTCVR AUC 0.8840 (+0.08%)
- **MTmixAtt-1B**: CTR AUC 0.7811, CTCVR AUC 0.8858 — 全部指标最佳
- 消融: AutoToken 击败 random + manual; 可学习 mixing 击败转置; sigmoid dense MoE 击败 ReLU sparse; V4 (2 shared + 1 manual + 1 auto scenario expert) 最佳; PostNormR 最佳归一化
- **幂律 scaling**: 15M → 1B 参数线性提升
- **在线 A/B**:
  - 首页: **+3.62% 支付 PV, +2.54% 实际支付 GTV, +1.05% NIEV**
  - 跨场景 1-4 (团购, 拼团, 短视频): +0.51% ~ +1.59% 支付 PV, +1.02% ~ +2.71% 实际支付 GTV

### 8.5 部署 / 代码

- **部署**: 美团大规模本地生活推荐系统 (数亿 DAU), 扩容到 1B 参数
- **代码**: 未开源

```text

   - 训练成本
   - 部署复杂

   - 多任务标签
   - 实时反馈

   - GR 不是银弹
   - 必须适配业务

4. 跨业务 / 跨域
   - 知识共享难
   - 任务冲突
   - 评估复杂
```

   - 大幅节省开发成本

   - 视频 / 音频 / 文本 统一
   - 提升用户体验

   - 模型小型化
