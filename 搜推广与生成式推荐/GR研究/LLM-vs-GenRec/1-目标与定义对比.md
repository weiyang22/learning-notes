## 0. 一句话总结

> **LLM 优化"人类偏好的对齐"——文本生成的 helpfulness / harmlessness / honesty;GenRec 优化"业务 KPI 的对齐"——推荐系统的 CTR / GMV / watch-time / 留存;LLM 是"主观对齐 + 长决策 + 高容错",GenRec 是"客观对齐 + 高频决策 + 低容错"——目标差异决定了两者在数据、Reward、评估、部署上的所有不同。**

## 1. LLM 的目标

### 1.1 三层目标体系

LLM 的目标可以分为**三个层次**,从底层到顶层:

```text
┌────────────────────────────────────────────────────────────────┐
│ LLM 三层目标体系                                                │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  Layer 1 (基础): 语言建模能力                                    │
│   ├─ Next-Token Prediction Loss 最小化                           │
│   ├─ 困惑度 (Perplexity) 下降                                    │
│   ├─ 文本流畅性 / 连贯性                                        │
│   └─ 知识覆盖率 (Knowledge Coverage)                             │
│                                                                │
│  Layer 2 (核心): 任务执行能力                                    │
│   ├─ Instruction Following (指令遵循)                           │
│   ├─ Reasoning (推理)                                           │
│   ├─ Code Generation (代码生成)                                  │
│   ├─ Multi-Modal (多模态)                                       │
│   └─ Tool Use (工具使用)                                         │
│                                                                │
│  Layer 3 (顶层): 对齐人类偏好                                    │
│   ├─ Helpful (有帮助)                                            │
│   ├─ Honest (诚实)                                              │
│   └─ Harmless (无害)                                            │
│                                                                │
│  → 三层目标缺一不可                                              │
│  → 现代 LLM 必须三层都做好                                       │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```

### 1.2 形式化目标

#### 1.2.1 预训练目标

```math
\mathcal{L}_{\text{Pretrain}}(\theta) = -\mathbb{E}_{(\mathbf{x}, \mathbf{y}) \sim \mathcal{D}_{\text{pretrain}}} \left[ \sum_{t=1}^{T} \log p_\theta(y_t \mid y_{<t}, \mathbf{x}) \right]

```
目标: 最小化 next-token prediction 的 cross-entropy loss
数据: 大规模文本语料 (数 T tokens)
期望: 模型学会"语言的统计规律 + 世界知识"
```text

#### 1.2.2 SFT 目标

```math
\mathcal{L}_{\text{SFT}}(\theta) = -\mathbb{E}_{(\mathbf{x}, \mathbf{y}) \sim \mathcal{D}_{\text{SFT}}} \left[ \sum_{t=1}^{T} \log p_\theta(y_t \mid y_{<t}, \mathbf{x}) \right]

```text
目标: 在高质量 (prompt, response) 对上 fine-tune
数据: 数万到数百万指令对
期望: 模型学会"遵循指令"
```

#### 1.2.3 RM 目标 (Bradley-Terry)

```math
\mathcal{L}_{\text{RM}}(\phi) = -\mathbb{E}_{(\mathbf{x}, y_w, y_l) \sim \mathcal{D}_{\text{RM}}} \left[ \log \sigma \left( r_\phi(\mathbf{x}, y_w) - r_\phi(\mathbf{x}, y_l) \right) \right]

```
目标: 学习人类偏好 (y_w 优于 y_l)
数据: 数十万 pairwise 比较
期望: 模型学到"好 vs 坏" 的判别
```text

#### 1.2.4 PPO 目标

```math
\mathcal{L}_{\text{PPO}}(\theta) = -\mathbb{E}_{\mathbf{x} \sim \mathcal{D}_{\text{prompt}}, y \sim \pi_\theta(\cdot|\mathbf{x})} \left[ r_\phi(\mathbf{x}, y) \right] + \beta \cdot \text{KL}(\pi_\theta \| \pi_{\text{ref}})
```text

```
目标: 最大化 expected reward, 同时约束 KL 散度
算法: PPO (Proximal Policy Optimization)
期望: 模型生成 "RM 打分高" 的回复, 同时不偏离 SFT 太远
```text

#### 1.2.5 DPO 目标

```math
\mathcal{L}_{\text{DPO}}(\theta) = -\mathbb{E}_{(\mathbf{x}, y_w, y_l)} \left[ \log \sigma \left( \beta \log \frac{\pi_\theta(y_w|\mathbf{x})}{\pi_{\text{ref}}(y_w|\mathbf{x})} - \beta \log \frac{\pi_\theta(y_l|\mathbf{x})}{\pi_{\text{ref}}(y_l|\mathbf{x})} \right) \right]

```text
目标: 隐式学习偏好, 无需 RM
算法: 直接在偏好对上优化
期望: 与 PPO 等价, 但更简单稳定
```

#### 1.2.6 GRPO 目标 (DeepSeek)

```math
\mathcal{L}_{\text{GRPO}}(\theta) = -\mathbb{E}_{\mathbf{x}, \{y_i\}_{i=1}^{G} \sim \pi_\theta} \left[ \frac{1}{G} \sum_{i=1}^{G} \min \left( \frac{\pi_\theta(y_i|\mathbf{x})}{\pi_{\theta_{\text{old}}}(y_i|\mathbf{x})} A_i, \text{clip}(\cdot, 1-\epsilon, 1+\epsilon) A_i \right) \right] + \beta \text{KL}

```
目标: 组内相对优势 (Group Relative)
A_i = (r_i - \text{mean}(r)) / \text{std}(r)
期望: 同组内"好的更好, 差的更差", 免 Critic
```text

### 1.3 终极目标: AGI

LLM 的**终极目标**是**AGI (Artificial General Intelligence, 通用人工智能)**:

```
┌────────────────────────────────────────────────────────────────┐
│ LLM 终极目标: AGI                                              │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  1. 通用智能      跨任务 (文本 / 图像 / 视频 / 音频 / 代码)      │
│  2. 强推理        数学 / 逻辑 / 常识 / 规划 / 反思               │
│  3. 长上下文      1M-10M tokens                                  │
│  4. 工具使用      Agent / Web / DB / Code                       │
│  5. 多模态        实时语音 / 视频理解                            │
│  6. 自我改进      自我训练 / 自我评估                             │
│  7. 安全对齐      HHH / Constitutional                          │
│                                                                │
│  → 这是 LLM 公司的"圣杯"                                        │
│  → OpenAI / Anthropic / DeepSeek / Google 都在朝此方向          │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```text

### 1.4 LLM 目标的本质: 对齐人类价值

LLM 的核心使命是**对齐人类价值**——把模型的行为对齐到人类认为"好"的方向。

**这意味着**:
- **主观性**: "好" 没有客观标准, 是人类集体判断
- **多维性**: HHH 只是简化, 实际是数十种价值的平衡
- **动态性**: 人类价值观随文化、时间演化
- **难定义**: "good" 是高维概念, 难以形式化

**典型的对齐目标**:

| 对齐目标 | 描述 | 案例 |
|----------|------|------|
| **Helpful** | 有帮助地回答问题 | ChatGPT |
| **Honest** | 诚实, 不编造 | GPT-4 |
| **Harmless** | 不产生有害内容 | Constitutional AI |
| **Fair** | 无偏见, 公平 | RLHF |
| **Privacy** | 保护用户隐私 | 联邦学习 |
| **Truthful** | 真实 | Truthful AI |
| **Calibrated** | 不确定性表达正确 | GPT-4 |
| **Coherent** | 一致性 | RLHF |
| **Creative** | 有创造性 | DPO |

### 1.5 LLM 目标的评估维度

LLM 目标的评估非常复杂, 通常涉及:

| 维度 | 描述 | 评估方法 |
|------|------|----------|
| **能力** | 模型能做什么 | Benchmark (MMLU, GSM8K, HumanEval) |
| **偏好** | 模型是否对齐人类偏好 | AlpacaEval, MT-Bench, Chatbot Arena |
| **安全** | 模型是否安全 | HarmBench, Red Teaming |
| **公平** | 模型是否公平 | Bias Benchmark |
| **真实** | 模型是否真实 | TruthfulQA, Factuality |
| **推理** | 模型是否推理强 | GSM8K, MATH |
| **代码** | 模型是否写代码 | HumanEval, MBPP, SWE-Bench |
| **多模态** | 模型是否多模态 | MMMU, MMBench |
| **Agent** | 模型是否用工具 | AgentBench |

## 2. GenRec 的目标

### 2.1 多层目标体系

GenRec 的目标可以分为**多个层次**,从底层到顶层:

```
┌────────────────────────────────────────────────────────────────┐
│ GenRec 多层目标体系                                              │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  Layer 1 (基础): 序列预测能力                                    │
│   ├─ Next-Item Prediction Loss 最小化                            │
│   ├─ Recall@K / NDCG@K 提升                                     │
│   └─ AUC / LogLoss                                              │
│                                                                │
│  Layer 2 (业务核心): 业务 KPI 最大化                              │
│   ├─ CTR (点击率)                                                │
│   ├─ watch-time / dwell time (停留时长)                          │
│   ├─ GMV (成交总额)                                              │
│   ├─ Conversion Rate (转化率)                                    │
│   └─ LTV (生命周期价值)                                          │
│                                                                │
│  Layer 3 (体验): 用户体验优化                                    │
│   ├─ Diversity (多样性)                                          │
│   ├─ Novelty (新颖性)                                            │
│   ├─ Serendipity (惊喜度)                                        │
│   ├─ Coverage (覆盖率)                                           │
│   └─ Fairness (公平曝光)                                         │
│                                                                │
│  Layer 4 (长期): 长期价值                                       │
│   ├─ Retention (次日 / 7 日 / 30 日留存)                         │
│   ├─ Engagement (DAU / MAU / 时长)                               │
│   └─ Ecosystem Health (生态健康)                                │
│                                                                │
│  → 多层目标相互制约, 必须权衡                                    │
│  → 不存在"绝对最优", 只有"业务最优"                              │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```text

### 2.2 形式化目标

#### 2.2.1 预训练目标 (Next-Item Prediction)

```math
\mathcal{L}_{\text{Pretrain}}^{\text{GR}}(\theta) = -\mathbb{E}_{(\mathbf{h}, \mathbf{s}) \sim \mathcal{D}_{\text{GR}}} \left[ \sum_{t=1}^{T} \log p_\theta(s_t \mid s_{<t}, \mathbf{h}) \right]

```text
目标: 最小化 next-SID-token prediction 的 cross-entropy loss
数据: 用户行为序列 + 物品 SID
期望: 模型学会"用户的兴趣演化规律"
```

**与 LLM 的区别**:
- LLM: $y_t$ 是文本 token, $\mathbf{x}$ 是 prompt
- GenRec: $s_t$ 是 SID token, $\mathbf{h}$ 是用户历史

#### 2.2.2 多目标加权 (业务)

```math
\text{KPI}_{\text{business}} = w_1 \cdot \text{CTR} + w_2 \cdot \text{watch-time} + w_3 \cdot \text{GMV} + w_4 \cdot \text{Retention}

```
目标: 多目标加权求和
权重: 业务方设定 (A/B 测试调优)
期望: 整体业务 KPI 最大化
```text

#### 2.2.3 GR RL 目标 (OneRec V1 DPO)

```math
\mathcal{L}_{\text{GR-DPO}}(\theta) = -\mathbb{E}_{(\mathbf{h}, \mathbf{i}_w, \mathbf{i}_l)} \left[ \log \sigma \left( \beta \log \frac{p_\theta(\mathbf{i}_w|\mathbf{h})}{p_{\text{ref}}(\mathbf{i}_w|\mathbf{h})} - \beta \log \frac{p_\theta(\mathbf{i}_l|\mathbf{h})}{p_{\text{ref}}(\mathbf{i}_l|\mathbf{h})} \right) \right]

```text
目标: 偏好对的隐式奖励, 偏好对来自业务反馈
其中 i_w > i_l 是业务反馈 (高 watch-time 优于低)
期望: 模型学会推"业务指标高"的物品
```

#### 2.2.4 GBPO 目标 (OneRec V2)

```math
\mathcal{L}_{\text{GBPO}}(\theta) = -\mathbb{E}_{\mathbf{h}, \{i_j\}_{j=1}^G \sim \pi_\theta} \left[ \frac{1}{G} \sum_{j=1}^{G} \min \left( \frac{\pi_\theta(i_j|\mathbf{h})}{\pi_{\theta_{\text{old}}}(i_j|\mathbf{h})} A_j, \text{clip}(\cdot) A_j \right) \right] + \beta \text{KL}

```
目标: Group-Based Policy Optimization
A_j = (r_j - \text{mean}(r)) / \text{std}(r) + \text{Duration-Aware Adjustment}
期望: 组内相对优势, 考虑时长 (Duration-Aware)
```text

#### 2.2.5 HEPO 目标 (GPR, Tencent)

```math
\mathcal{L}_{\text{HEPO}}(\theta) = -\mathbb{E}_{(\mathbf{h}, \{i_j\})} \left[ \sum_{j} A_j \log \pi_\theta(i_j|\mathbf{h}) \right] + \beta \text{KL} + \lambda \mathcal{L}_{\text{Hybrid}}

```text
目标: Hybrid Experience Policy Optimization
混合: 离线 SFT 经验 + 在线 RL 经验
期望: 利用离线数据, 同时在线优化
```

#### 2.2.6 SA-GCPO 目标 (OxygenREC, JD)

````math
\mathcal{L}_{\text{SA-GCPO}}(\theta) = -\mathbb{E}_{\mathbf{h}, \{i_j\}} \left[ \frac{1}{G} \sum_{j} \min \left( \frac{\pi_\theta(i_j|\mathbf{h})}{\pi_{\theta_{\text{old}}}(i_j|\mathbf{h})} A_j, \text{clip}_{\text{soft}}(A_j) \right) \right] + \beta \text{KL}

```
目标: Soft Adaptive Group Clip Policy Optimization
Soft Clip: clip 范围随 reward 动态调整
期望: 多业务目标自适应平衡
```text

### 2.3 终极目标: 业务 KPI 最大化

GenRec 的**终极目标**是**业务 KPI 最大化**:

│  → 这是推荐系统工程师的"圣杯"                                    │

### 2.4 GenRec 目标的本质: 对齐业务价值

GenRec 的核心使命是**对齐业务价值**——把模型的行为对齐到业务认为"好"的方向。

**这意味着**:
- **客观性**: 业务 KPI 是相对客观的 (有数据可衡量)
- **多维性**: CTR / GMV / 时长 / 留存 多目标并存
- **动态性**: 业务 KPI 随季节、活动、战略调整

**典型的业务目标**:

| **Engagement** | 互动率 | 社交 |
| **Diversity** | 多样性 | 内容平台 |
| **Fairness** | 公平曝光 | 创作者生态 |
| **Novelty** | 新颖性 | 新闻 |

## 3. 输出的本质区别

### 3.1 LLM 输出: 开放生成

LLM 的输出是**自然语言文本**,具备以下特征:

```
LLM 输出特征:
├─ 开放性: 可以生成任意文本 (理论上)
├─ 创造性: 可创造新句子 / 想法
├─ 长度可变: 数十 token 到数十万 token
├─ 多样性: 同一 prompt 可生成不同回复
├─ 可读性: 人类可读
└─ 可解释: 自我解释
```text

**示例**:

```
输入: "请用 Python 写一个快速排序"
输出:
"def quicksort(arr):
    if len(arr) <= 1:
        return arr
    pivot = arr[len(arr) // 2]
    left = [x for x in arr if x < pivot]
    middle = [x for x in arr if x == pivot]
    right = [x for x in arr if x > pivot]
    return quicksort(left) + middle + quicksort(right)

## 示例
print(quicksort([3, 6, 8, 10, 1, 2, 1]))
## 输出: [1, 1, 2, 3, 6, 8, 10]"
```python

**本质**: 输出是**字符串**, 由 BPE 子词 token 组成, 长度可变, 内容开放。

### 3.2 GenRec 输出: 封闭生成

GenRec 的输出是**物品 SID 序列**, 必须能解码为有效 item-id:

```
GenRec 输出特征:
├─ 封闭性: 必须落在物品库内
├─ 唯一性: 每个序列对应一个 (或一组) 物品
├─ 长度固定: 通常 1-N 个 SID token (N=层级数)
├─ 受限多样性: 输出空间是离散的物品集合
├─ 不可读: 人类难以直接理解 (除非有层级含义)
└─ 可解码: SID 序列 → item-id (查表)
```text

**示例**:

```
输入: 用户历史 [(item_123, watch_30s), (item_456, watch_120s), ...]
输出: SID 序列 (12, 345, 6789) → item_123456
```text

**本质**: 输出是**离散索引**, 必须查表解码为具体物品。

### 3.3 对比表

| 维度 | LLM 输出 | GenRec 输出 |
|------|----------|-------------|
| **形式** | 自然语言文本 | SID token 序列 |
| **空间** | 开放 (任意文本) | 封闭 (物品库) |
| **长度** | 可变 | 通常固定 (1-N 个 token) |
| **多样性** | 高 | 受限 (物品总数) |
| **可读性** | 高 | 低 (但 SID 可有层级含义) |
| **可解码** | 直接可读 | 需查表解码 |
| **创意性** | 高 (可创造) | 低 (只能选已有) |
| **约束** | 语法 / 风格 / 长度 | 必须有效物品 |
| **失败模式** | 幻觉 / 编造 | 推荐错物品 / 重复 |

### 3.4 输出失败的代价

**LLM 输出失败**:

```
失败 1: 幻觉 (Hallucination)
   例: 编造事实, 不存在的引用
   代价: 用户信任受损 (中)

失败 2: 重复 / 啰嗦
   例: 反复说同样的话
   代价: 用户体验下降 (低)

失败 3: 偏离指令
   例: 用户问 A, 模型答 B
   代价: 用户失望 (中)

失败 4: 有害内容
   例: 生成偏见 / 暴力 / 违法
   代价: 法律 / 声誉风险 (极高)
```text

**GenRec 输出失败**:

```
失败 1: 推荐错物品
   例: 推荐明显不相关的物品
   代价: 用户跳过 / 流失 (中)

失败 2: 信息茧房
   例: 反复推相似内容
   代价: 用户体验下降 (中)

失败 3: 冷启动失败
   例: 新物品 / 新用户推不出
   代价: 平台增长受限 (高)

失败 4: 公平性问题
   例: 长尾物品 / 创作者无曝光
   代价: 生态受损 (高)

失败 5: 业务事故
   例: 推荐违规 / 危险品
   代价: 法律 / 声誉风险 (极高)
```text

#### 4.1.2 人类评估

| 评估方法 | 描述 | 用途 |
|----------|------|------|

| 方法 | 描述 |
|------|------|
| **GPT-4 as Judge** | 用 GPT-4 给其他模型打分 |
| **Claude as Judge** | 用 Claude 给其他模型打分 |
| **Pairwise Comparison** | LLM 比较两个回复 |
| **Reference-based** | LLM 对比参考答案 |

### 4.2 GenRec 评估体系

#### 4.2.1 离线评估

| 指标 | 公式 | 含义 |
|------|------|------|
| **AUC** | ROC 曲线下面积 | 二分类质量 |
| **LogLoss** | $-\sum y \log p + (1-y) \log(1-p)$ | 概率校准 |
| **Recall@K** | Top-K 中命中真实物品比例 | 召回 |
| **NDCG@K** | $\frac{\text{DCG@K}}{\text{IDCG@K}}$ | 排序质量 |
| **MAP** | Mean Average Precision | 排序 |
| **MRR** | Mean Reciprocal Rank | 首个相关物品位置 |
| **Hit Rate** | Top-K 命中比例 | 召回 |
| **Coverage** | 推荐物品占总物品比例 | 多样性 |

#### 4.2.2 在线评估 (A/B 测试)

| 指标 | 含义 | 业务方关心 |
|------|------|------------|
| **CTR** | 点击 / 曝光 | 广告 / 短视频 |
| **watch-time** | 总停留时长 | 视频 |
| **GMV** | 成交总额 | 电商 |
| **Conversion** | 转化率 | 广告 / 电商 |
| **Retention** | 次日 / 7 日留存 | 游戏 / 应用 |
| **LTV** | 生命周期价值 | 订阅 |
| **DAU / MAU** | 日活 / 月活 | 平台 |
| **Diversity** | 推荐多样性 | 内容平台 |
| **Fairness** | 创作者曝光公平 | UGC 平台 |

#### 4.2.3 长期评估

| 指标 | 含义 |
|------|------|
| **30-day Retention** | 30 日留存 |
| **90-day LTV** | 90 日 LTV |
| **NRR** | Net Revenue Retention |
| **Ecosystem Health** | 生态健康度 |

### 4.3 对比表

| 维度 | LLM 评估 | GenRec 评估 |
|------|----------|-------------|
| **评估类型** | 自动 Benchmark + 人类偏好 | 离线指标 + 在线 A/B |
| **评估速度** | 数小时 (Benchmark) | 数天到数周 (A/B) |
| **可重复性** | 高 (固定 benchmark) | 低 (业务动态) |
| **跨模型可比** | 强 (MMLU 等) | 弱 (各公司指标不同) |
| **成本** | 中 (推理成本) | 高 (A/B 影响业务) |
| **偏差** | Benchmark contamination | Selection bias / novelty |
| **反馈周期** | 快 (小时) | 慢 (周) |
| **真实业务** | 弱 (Benchmark ≠ 真实) | 强 (A/B = 真实) |

### 4.4 评估的根本差异

```
┌────────────────────────────────────────────────────────────────┐
│ LLM 评估哲学                                                   │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  Benchmark-driven: 用标准化 benchmark 横向比较                  │
│  → MMLU / GSM8K / HumanEval 等                                │
│  → 优点: 可比, 客观, 快速                                      │
│  → 缺点: 可能 contamination, 与真实使用脱节                     │
│                                                                │
│  → LLM 评估正在从 Benchmark 走向"真实任务"                     │
│                                                                │
└────────────────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────────────────┐
│ GenRec 评估哲学                                                 │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  Business-driven: 用业务 A/B 测试验证真实效果                    │
│  → CTR / GMV / 留存                                            │
│  → 优点: 真实, 直接对齐业务                                    │
│  → 缺点: 慢, 不可比, 风险高                                     │
│                                                                │
│  → GenRec 评估天然是业务驱动                                    │
│                                                                │
└────────────────────────────────────────────────────────────────┘
```text

│   ├─ 效果验证慢 (A/B 数天到数周)                                 │
│   └─ 模型迭代快 (在线学习, 小时)                                  │
│                                                                │
└────────────────────────────────────────────────────────────────┘

## 8. 决策频率的区别

### 8.1 LLM 决策频率

```
LLM 决策频率:
├─ 单次请求: 1 次决策 (生成 1 个 response)
├─ 用户使用: 数次 / 日 (按需)
├─ 模型训练: 1 次 / 数周 (重训)
└─ 模型迭代: 1 次 / 数月 (新版本)
```text

**特点**: **低频决策**, 每次决策价值高, 用户等待后获得完整结果。

### 8.2 GenRec 决策频率

```
GenRec 决策频率:
├─ 单次请求: 1 次推荐 (生成 K 个物品)
├─ 用户使用: 数十到数百次 / 日
├─ 模型训练: 在线 / 实时 (持续学习)
└─ 模型迭代: 小时 / 天 (A/B 测试)
```text

**特点**: **高频决策**, 每次决策价值分散, 用户无感但累计影响大。

### 8.3 频率对比

| 维度 | LLM | GenRec |
|------|-----|--------|
| **用户级频率** | 数次 / 日 | 数十到数百次 / 日 |
| **请求级决策** | 1 次决策 / 请求 | 1 次推荐 = K 个决策 |
| **系统级频率** | 中 (ChatGPT 高频) | 极高 (抖音 / 淘宝) |
| **模型更新** | 数周 | 小时 (在线) |
| **决策价值** | 高 (单次决定用户满意度) | 分散 (累计影响业务) |

### 8.4 频率决定的差异

```
高频 → 系统压力大 → 必须优化
├─ GenRec: 必须 < 50ms p99, 必须量化, 必须 KV Cache
└─ LLM: 数百 ms 可接受, 优化没那么紧迫

高频 → 数据流式 → 在线学习必要
├─ GenRec: 必须在线 / 近线学习
└─ LLM: 离线训练可接受

高频 → 实验压力大 → A/B 测试基础设施
├─ GenRec: 数十个实验并行, 必须 A/B 平台
└─ LLM: 实验少, 可手动切换

高频 → 监控压力大 → 必须实时监控
├─ GenRec: 实时监控 CTR / GMV
└─ LLM: 监控生成质量 (抽样)
```text

## 12. 多目标 vs 单目标

### 12.1 LLM 目标的多目标性

LLM 通常被视为**多目标对齐**:

```
LLM 多目标:
├─ Helpful (有帮助)
├─ Honest (诚实)
├─ Harmless (无害)
├─ Truthful (真实)
├─ Fair (公平)
├─ Private (隐私)
└─ Creative (创造性)
```text

**多目标冲突**:

| 冲突 | 描述 |
|------|------|
| **Helpful vs Harmless** | 用户问如何制造危险品, 帮还是不帮? |
| **Helpful vs Honest** | 用户问错误问题, 顺着答还是纠正? |
| **Truthful vs Creative** | 创造性写作 vs 事实准确性 |
| **Fair vs Specific** | 普适建议 vs 个性化建议 |
| **Helpful vs Private** | 个性化 vs 隐私保护 |

### 12.2 GenRec 目标的多目标性

GenRec 天然就是**多目标优化**:

```
GenRec 多目标:
├─ CTR (点击率)
├─ watch-time (时长)
├─ GMV (成交)
├─ Conversion (转化)
├─ Diversity (多样性)
├─ Novelty (新颖性)
├─ Coverage (覆盖率)
├─ Fairness (公平性)
└─ Retention (留存)
```text

**多目标冲突**:

| 冲突 | 描述 |
|------|------|
| **CTR vs GMV** | 高 CTR 不等于高 GMV |
| **CTR vs 时长** | 标题党提升 CTR 但降低时长 |
| **GMV vs 多样性** | 只推爆款降低多样性 |
| **短期 CTR vs 长期留存** | 短期最优不等于长期最优 |
| **个性化 vs 公平** | 个性化推爆款 = 长尾物品无曝光 |
| **业务 vs 体验** | 业务 KPI 高但用户体验下降 |

### 12.3 多目标的处理方式对比

**LLM 多目标处理**:

```
1. HHH 三元组 (简化版)
2. RM 加权融合 (权重调优)
3. Constitutional AI (原则排序)
4. 多 RM 集成 (取平均 / 取 max)
5. RLHF 训练中动态调整权重
```text

**GenRec 多目标处理**:

```
1. 多任务学习 (Multi-Task Learning)
   ├─ 共享底层 + 多个 head
   └─ 不同 head 对应不同业务目标
2. 加权损失 (Weighted Loss)
   ├─ L = w1·L_CTR + w2·L_GMV + ...
   └─ 权重通过 A/B 调优
3. 多目标排序 (Multi-Objective Ranking)
   ├─ Pareto Front
   └─ 业务方指定权重
4. ESMM / MMOE (Entire Space Multi-Task / Multi-gate MoE)
5. 多 RL Reward 加权 (OneRec V2, OxygenREC)
```text

### 12.4 多目标优化算法

```
LLM:
├─ PPO 多 RM 加权
├─ DPO 多偏好对 (混合数据集)
├─ GRPO 组内 advantage
└─ Constitutional AI 原则排序

GenRec:
├─ ESMM (Entire Space Multi-Task Model)
├─ MMOE (Multi-gate Mixture-of-Experts)
├─ PLE (Progressive Layered Extraction)
├─ 多 Reward RL (OneRec V2 / OxygenREC)
└─ Pareto 多目标优化
```text

## 13. 离线 vs 在线目标

### 13.1 LLM 离线 vs 在线

**离线目标**:

```
- Benchmark (MMLU / GSM8K / HumanEval)
- SFT Loss / RLHF Loss
- RM Score
- Perplexity
- 自评估 (Self-Evaluation)

用途: 训练过程监控, 模型选择
```text

**在线目标**:

```
- 用户满意度 (👍 / 👎 / 重写)
- 用户留存 (ChatGPT Plus 续费)
- 实际使用时长
- 用户问题难度分布
- 对话成功率 (任务完成率)

用途: 模型部署后监控, A/B 测试
```text

**离线-在线 gap**:

```
LLM gap:
├─ Benchmark SOTA ≠ 真实好用
├─ RM 高分 ≠ 用户喜欢
├─ RLHF loss 低 ≠ 对齐好
└─ 缓解: 持续在线评估, A/B 测试
```text

### 13.2 GenRec 离线 vs 在线

**离线目标**:

```
- AUC / NDCG / Recall / Hit Rate
- LogLoss / 训练 loss
- 验证集业务指标 (近似)
- 仿真模拟 (Replay)

用途: 模型选择, 超参调优
```text

**在线目标**:

```
- CTR / watch-time / GMV (真实)
- Retention / LTV (延迟反馈)
- A/B 测试对比
- 多样性 / 公平性 (长期监控)

用途: 真实效果验证, 模型迭代
```text

**离线-在线 gap**:

```
GenRec gap:
├─ AUC 高 ≠ 真实 CTR 高
├─ NDCG 高 ≠ 业务 GMV 高
├─ 离线 replay ≠ 在线分布
├─ 数据分布漂移
└─ 缓解: 持续 A/B, 在线学习, 分布监控
```text

### 13.3 离线在线 gap 的本质差异

```
LLM gap 本质:
├─ Benchmark ≠ 真实使用 (任务分布不同)
├─ RM ≠ 真实人类 (RM 拟合偏差)
├─ 训练分布 ≠ 用户分布 (任务难度)
└─ 缓解: 大规模人类评估, 持续在线监控

GenRec gap 本质:
├─ 离线 replay ≠ 在线 (用户会看到新内容)
├─ 历史数据 ≠ 当前数据 (概念漂移)
├─ 离线指标 ≠ 业务指标 (次级指标)
└─ 缓解: 在线 A/B 必做, 在线学习必要
```text

| **目标性质** | 主观 (Human Preference) | 客观 (Business Metric) |
| **目标数量** | 多 (HHH + 数十种价值) | 多 (CTR/GMV/时长/留存 + 多样性/公平性) |
| **目标冲突** | 有 (Helpful vs Harmless) | 严重 (CTR vs GMV vs 时长) |
| **终极目标** | AGI | 业务 KPI 最大化 |
| **评估方式** | Benchmark + 人类评估 | 离线指标 + 在线 A/B |
| **评估速度** | 快 (Benchmark 数小时) | 慢 (A/B 数天) |
| **评估成本** | 中 (推理成本) | 高 (A/B 影响业务) |
| **时间尺度** | 秒 (单次) / 月 (迭代) | 毫秒 (单次) / 日 (迭代) |
| **决策频率** | 数次/日 | 数十到数百次/日 |
| **错误容错** | 较大 | 较小 |
| **多目标优化** | RM 加权 / Constitutional | 多任务学习 / 多 Reward RL |
| **离线在线 gap** | 中 (Benchmark ≠ 真实) | 大 (Replay ≠ 真实分布) |
| **长期目标** | AGI / 通用智能 | 业务生态健康 |

### 14.3 形式化目标对比

**LLM 终极目标**:

$$
\max_\theta \mathbb{E}_{\mathbf{x} \sim \mathcal{D}_{\text{user}}, \mathbf{y} \sim \pi_\theta} \left[ r_{\text{HHH}}(\mathbf{x}, \mathbf{y}) \right]
$$

其中 $r_{\text{HHH}}$ 是 HHH 奖励模型 (人类偏好的拟合)。

**GenRec 终极目标**:

$$
\max_\theta \mathbb{E}_{u \sim \mathcal{U}, i \sim \pi_\theta} \left[ \sum_k w_k \cdot \text{KPI}_k(u, i) \right]
$$

其中 $\text{KPI}_k$ 是第 $k$ 个业务目标 (CTR/GMV/时长), $w_k$ 是权重。

### 14.4 目标差异的工程影响

│ 目标差异 → 工程差异                                            │
├────────────────────────────────────────────────────────────────┤

#### C.1.1 Reward 模型 (RM) 训练

```python
## 典型 RM 训练代码 (伪代码)
class RewardModel(nn.Module):
    def __init__(self, base_lm, hidden_size):
        self.backbone = base_lm  # 预训练 LM 作为 backbone
        self.value_head = nn.Linear(hidden_size, 1)  # 标量输出

    def forward(self, input_ids, attention_mask):
        hidden = self.backbone(input_ids, attention_mask).last_hidden_state
        # 取最后一个 token 的 hidden state
        last_hidden = hidden[:, -1, :]
        reward = self.value_head(last_hidden).squeeze(-1)
        return reward

## Bradley-Terry 损失
def bradley_terry_loss(rm, prompt, chosen, rejected):
    r_chosen = rm(prompt + chosen)
    r_rejected = rm(prompt + rejected)
    loss = -F.logsigmoid(r_chosen - r_rejected).mean()
    return loss

### C.2 GenRec Reward 设计

#### C.2.1 业务 Reward 设计

```python
## 典型 GenRec Reward (多目标加权)
def business_reward(user_history, generated_items, real_feedback):
    """
    user_history: 用户历史行为
    generated_items: GR 生成的物品
    real_feedback: 真实反馈 (CTR / watch-time / GMV)
    """
    # 多目标
    r_ctr = compute_ctr(generated_items, real_feedback)
    r_watch_time = compute_watch_time(generated_items, real_feedback)
    r_gmv = compute_gmv(generated_items, real_feedback)
    r_diversity = compute_diversity(generated_items)
    r_novelty = compute_novelty(generated_items, user_history)
    r_fairness = compute_fairness(generated_items)

    # 加权求和
    reward = (
        w_ctr * r_ctr +
        w_watch_time * r_watch_time +
        w_gmv * r_gmv +
        w_diversity * r_diversity +
        w_novelty * r_novelty +
        w_fairness * r_fairness
    )
    return reward
```python

#### C.2.2 Duration-Aware Reward (OneRec V2)

```python
## 时长感知 Reward
def duration_aware_reward(user_history, generated_item, watch_time, target_duration):
    # watch_time 是用户实际观看时长
    # target_duration 是物品总时长
    completion_rate = watch_time / target_duration

    # 完播率高 → 推更多此类物品
    # 完播率低 → 减少此类物品
    if completion_rate > 0.7:
        reward = 1.5  # 高完播, 大幅正向
    elif completion_rate > 0.3:
        reward = 1.0  # 中等完播, 正常
    else:
        reward = 0.3  # 低完播, 抑制

    return reward
```python

#### C.2.3 Soft Adaptive Clip (OxygenREC SA-GCPO)

```python
## Soft Adaptive Clip Reward
def sa_gcpo_reward(reward, target_rewards):
    """
    reward: 当前 trajectory 的总 reward
    target_rewards: 多业务目标的目标值
    """
    # 根据目标距离动态调整 clip 范围
    gap = target_rewards - reward
    # clip 范围随 gap 动态调整
    clip_low = -1.0 + 0.1 * gap.min()
    clip_high = 1.0 + 0.1 * gap.max()

    return torch.clamp(reward, clip_low, clip_high)
```python

## 多 Token + HEPO Reward
def gpr_reward(user_history, generated_tokens, real_feedback):
    # 生成多个 token, 每个 token 对应一个物品
    rewards = []
    for token in generated_tokens:
        item = decode_sid_token(token)
        r = compute_business_metric(item, user_history, real_feedback)
        rewards.append(r)

    # Hybrid Experience: 离线 SFT 经验 + 在线 RL 经验
    reward_online = sum(rewards)  # 在线 RL reward
    reward_offline = sft_loss(user_history, generated_tokens)  # 离线 SFT 经验

    # 加权融合
    total = alpha * reward_online + beta * reward_offline
    return total

## 关键洞察

> [!important] **核心 insight**: LLM 优化人类偏好(Helpful/Honest/Harmless),是主观对齐 + 长决策 + 高容错;GenRec 优化业务 KPI(CTR/GMV/留存),是客观对齐 + 高频决策 + 低容错。两者本质是"主观 vs 客观"对齐范式的根本差异。

> **总结**: LLM 与 GenRec 在**目标与定义**上的差异,本质上是**主观对齐 vs 客观对齐**的差异。前者优化"人类偏好的对齐",后者优化"业务 KPI 的对齐";前者是**长决策 + 高容错**,后者是**高频决策 + 低容错**;前者评估依赖**Benchmark + 人类**,后者评估依赖**离线指标 + 在线 A/B**。这种根本性的目标差异,决定了两者在数据、Reward、训练、评估、部署上的所有不同,也决定了二者未来的融合方向——**Unified Generative AI**。
