## 2. GenRec 工业案例

### 2.1 Meta News Feed (HSTU)

#### 2.1.1 业务背景

- 全球 20 亿+ 用户
- News Feed 推荐
- 电商 / Reels / Stories 整合

#### 2.1.2 模型架构

- **HSTU** (Hierarchical Sequential Transduction Unit)
- 单层序列编码 + 多任务输出
- 1.5T 参数最大规模

#### 2.1.3 在线指标

- +12% NE (Normalized Engagement)
- 显著优于 DLRM 基线

#### 2.1.4 工程细节

- 训练 cluster: 1024 H100
- 训练时长: 数周
- 在线 serving: 自研 Hopper-style
- 长序列 (16K) context parallelism (HSTU-CP)

### 2.2 字节抖音 (TokenMixer-Large)

#### 2.2.1 业务背景

- 抖音 / TikTok 主推荐
- 8 亿+ DAU
- 多路召回 + 排序

#### 2.2.2 模型架构

- TokenMixer-Large (15B offline / 7B online)
- Per-token MoE
- 多视图 latent diffusion

#### 2.2.3 在线指标

- +2.98% GMV
- 长行为序列 (10K+)
- < 50ms p99 延迟

#### 2.2.4 工程亮点

- **Cross-request KV Cache** (复用 KV)
- **Length Extrapolation** (训练 4K, 推理 10K)
- 自研 ByteRec 服务

### 2.3 快手 (OneRec 系列)

#### 2.3.1 业务背景

- 快手主站 / 极速版 / 电商
- 4 亿+ DAU
- 短视频 + 电商融合

#### 2.3.2 OneRec 演化

| 版本 | 关键创新 |
| :--- | :--- |
| OneRec-V1 | 端到端生成式推荐 |
| OneRec-V2 | 长序列 + 端到端 |
| OneRec-Think | CoT 推理 |
| OneRec-Foundation | 基础模型 + 下游迁移 |
| OneRec-Mall | 电商场景 |

#### 2.3.3 OneRec-Think 核心

- 推理时先生成 CoT
- 再生成 SID
- LLM 推理与 GenRec 解耦
- SA-GCPO 训练 (Open-KK 算法)

#### 2.3.4 工程指标

- 显著 CTR / GMV 提升
- 训练 cost ~ $1-2M
- 推理延迟 < 30ms

### 2.4 美团 (MTGR, HoMer)

#### 2.4.1 业务背景

- 多场景推荐

#### 2.4.2 MTGR

- **MTGR** (Multi-Task Generative Recommendation)

#### 2.4.3 HoMer

- **HoMer** (Holistic Generative Recommender)

## 25. 附录 I · 经典面试题

### 25.1 LLM 面试题

#### 题目 1: 为什么 LLM 推理要在 decode 阶段 cache K, V?

答: Self-attention 计算 $q K^T / \sqrt{d}$ 时, 历史 token 的 K, V 在下一步仍然需要。如果每步重新算, 复杂度 $O(L^2 d)$。缓存后只需算新 token 的 K, V, 复杂度降到 $O(L d)$。

#### 题目 2: Chinchilla 1:20 是什么意思?

答: 给定算力下, 最优训练 token $D$ 与模型规模 $N$ 之比约 20:1。70B 模型应训 1.4T tokens。

#### 题目 3: 什么是 MQA / GQA / MLA?

答:
- MHA: 每个 head 独立 K, V
- MQA: 所有 head 共享 1 组 K, V
- GQA: 几组 head 共享 K, V (中庸)
- MLA: 用矩阵吸收压缩 KV 到 latent space

#### 题目 4: KV Cache 显存怎么算?

答: 总显存 = 层数 × 2 × 序列长 × head 数 × head dim × 2 (fp16)
- 70B 模型, 4K 序列, 单 token KV 约 2.5 MB
- 总 70B 模型单 batch 4K seq KV 约 10 GB

### 25.2 GenRec 面试题

#### 题目 1: 为什么 GenRec 用 1B-5B 主流?

答:
1. 1B 以下能力不足
2. 5B 以上业务 ROI 锐减
3. 单卡 V100/T4 可放 1B 模型
4. 推理延迟要求 (< 30ms)

#### 题目 2: GenRec 的 SID 是怎么生成的?

答:
1. 用 RQ-VAE 编码物品到 latent
2. 残差量化得到 (c0, c1, c2)
3. 把 SID 当作 "token" 训练 Transformer
4. 推理时 beam search in Trie

#### 题目 3: HSTU 和传统 Transformer 区别?

答:
1. HSTU 用相对位置编码 + pointwise 投影, 比标准 attention 快
2. HSTU 引入任务兼容的多 head 输出
3. HSTU 是稀疏注意力 + scaling
4. 1.5T 规模训练

#### 题目 4: GenRec 如何保证冷启动?

答:
1. 新物品: 用内容 embedding (文本/图片) 替代 ID
2. 新用户: 用统计特征 + 探索

## 30. 写在最后

工业落地是 LLM 与 GenRec 真正分出高下的战场:

- LLM 走出"小作坊", 进入"千亿用户 + 万亿 token"的工业体量
- GenRec 走出"学术论文", 进入"千亿请求 + 百亿参数"的工程体量

两者的"**分与合**" 是未来 3-5 年的核心议题。LLM 想做"全 AI", GenRec 想做"全推荐"; 而真正能服务用户的, 是两者融合后的"全场景"。

**LLaMA / Qwen / DeepSeek 与 OneRec / HSTU / TokenMixer 的相遇, 是这次浪潮最美的产物**。

## 40. 终极总结

LLM 与 GenRec 的工业落地路径:

- **过去**: 各自独立发展, LLM 文字, GenRec 推荐
- **现在**: 双向渗透, 融合开始 (LLM-as-Feature / LLM-as-Reranker / GenRec-as-Plugin)
- **未来**: 真正统一, 一套模型服务 LLM + 推荐 + 搜索 + 广告

工业级别, 这一天的到来可能需要 3-5 年;学术级别, 已经开始了。
