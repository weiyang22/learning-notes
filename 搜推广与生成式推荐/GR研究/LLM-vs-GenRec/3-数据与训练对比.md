## 0. 一句话总结

> **LLM 数据 = 公开静态 (Web 文本数 T tokens, 一次性训练) vs GenRec 数据 = 私有流式 (业务日志数 B 行为, 持续训练)**;LLM 训练 = 大规模预训练优先 (千卡, 数周, 千万美元) vs GenRec 训练 = 持续优化优先 (百卡, 数天, 数十万到百万美元);二者共享 Pretrain + SFT + RL 三段式范式、AdamW + cosine + 混合精度 + 分布式训练基础设施,但在数据来源/规模/更新频率/优化目标/分布式策略上有本质差异。

| 维度 | LLM 数据 | GenRec 数据 |

## 2. 数据规模对比

### 2.1 LLM 数据规模

```text
LLM 训练数据规模 (tokens):
├─ GPT-1 (2018):   5B
├─ GPT-2 (2019):   40B
├─ GPT-3 (2020):   300B
├─ GPT-3.5 (2022): 估计 1T+
├─ LLaMA 1 (2023): 1.4T
├─ LLaMA 2 (2023): 2T
├─ LLaMA 3 (2024): 15.6T
├─ Qwen 1.5 (2024): 3T+

**典型计算**:
- 1T tokens ≈ 750 GB (纯文本)
- 10T tokens ≈ 7.5 TB
- 100T tokens ≈ 75 TB

```text
GenRec 训练数据规模 (行为数):

**典型计算**:
- 1B 行为 ≈ 100 GB (压缩后)

### 2.3 对比

| 维度 | LLM | GenRec |
|------|-----|--------|
| **单位** | tokens | 行为 |
| **规模** | 1T-100T | 1B-100B |
| **质量** | 低 (Web 噪声) | 高 (业务筛选) |
| **多样性** | 高 | 中 |
| **价值密度** | 低 (1% 高价值) | 高 (80% 有意义) |

### 2.4 有效数据量

```text
LLM 有效数据量:
├─ 原始: 100T tokens
├─ 清洗后: 50T

```

**关键差异**: LLM 数据有效率约 10-30%, GenRec 数据有效率约 50-80%。

## 3. 数据预处理对比

### 3.1 LLM 数据预处理

```text
┌────────────────────────────────────────────────────────────────┐
│ LLM 数据预处理流水线                                            │
├────────────────────────────────────────────────────────────────┤
│                                                                │
│  阶段 1: 原始数据采集                                            │
│   ├─ Common Crawl 抓取 (WARC 格式)                              │
│   ├─ Wikipedia dump                                              │
│   ├─ GitHub Archive                                              │
│   └─ 书籍扫描 (OCR)                                              │
│                                                                │
│  阶段 2: 文本提取                                                │
│   ├─ HTML → 文本 (trafilatura / jusText)                         │
│   ├─ PDF → 文本 (pdfplumber / Tika)                              │
│   ├─ 代码 → 文本 (保留结构)                                       │
│   └─ OCR 纠错                                                    │
│                                                                │
│  阶段 3: 质量过滤                                                │
│   ├─ 语言检测 (fastText langdetect)                              │
│   ├─ 长度过滤 (太短 / 太长)                                       │
│   ├─ 启发式规则 (符号比例 / 重复度)                                │
│   ├─ 模型过滤 (用 LLM 给数据打分)                                  │
│   └─ 关键词过滤 (NSFW / 违法)                                     │
│                                                                │
│  阶段 4: 去重                                                    │
│   ├─ 文档级去重 (MinHash / SimHash)                              │
│   ├─ 行级去重                                                     │
│   ├─ 句子级去重                                                    │
│   └─ n-gram 去重                                                   │
│                                                                │
│  阶段 5: 隐私处理                                                │
│   ├─ PII 检测 (邮箱 / 电话 / 身份证)                              │
│   └─ 替换 / 删除                                                  │
│                                                                │

## 4. 训练目标对比 (Next-Token vs Next-Item)

### 4.1 LLM 训练目标

#### 4.1.1 Next-Token Prediction (核心)

```math
\mathcal{L}_{\text{LM}}(\theta) = -\sum_{t=1}^{T} \log p_\theta(y_t \mid y_{<t}, \mathbf{x})
$$

```
目标: 给定上文, 预测下一个文本 token
数据: (prompt, response) 或纯文本
损失: Cross-Entropy on token
输出: 每个位置的 token 概率分布
```text

**特点**:
- 自回归: 每个 token 都参与损失
- 因果: 只能看到上文
- 全位置: 每个位置都计算 loss

#### 4.1.2 其它 LLM 训练目标

```
LLM 训练目标 (多阶段):
├─ 阶段 1: Pretrain - Next-Token Prediction (核心)
├─ 阶段 2: SFT - 同样 Next-Token, 但只在 response 上
│  loss = -sum log p(y_t | y_<t, x)  for t in response
├─ 阶段 3: RM - Bradley-Terry (Pairwise Ranking)
│  loss = -log sigmoid(r_chosen - r_rejected)
└─ 阶段 4: RL - Expected Reward Maximization
   loss = -E[r(x, y)] + KL  (PPO)
   loss = -log sigmoid(β log(π/π_ref)(chosen) - β log(π/π_ref)(rejected))  (DPO)
```text

#### 4.1.3 数学公式对比

```math
\text{Pretrain: } \mathcal{L} = -\sum_{t} \log p_\theta(y_t | y_{<t})

\text{SFT: } \mathcal{L} = -\sum_{t \in \text{response}} \log p_\theta(y_t | y_{<t})

\text{RM (Bradley-Terry): } \mathcal{L} = -\log \sigma(r_\phi(y_w) - r_\phi(y_l))

\text{PPO: } \mathcal{L} = -\min\left(\frac{\pi_\theta}{\pi_{\theta_{\text{old}}}} A, \text{clip}(\cdot) A\right) + \beta \text{KL}

\text{DPO: } \mathcal{L} = -\log \sigma\left(\beta \log \frac{\pi_\theta(y_w)}{\pi_{\text{ref}}(y_w)} - \beta \log \frac{\pi_\theta(y_l)}{\pi_{\text{ref}}(y_l)}\right)

\text{GRPO: } \mathcal{L} = -\frac{1}{G} \sum_{i} \min\left(\frac{\pi_\theta(y_i)}{\pi_{\theta_{\text{old}}}(y_i)} A_i, \text{clip}(\cdot) A_i\right) + \beta \text{KL}
$$

### 4.2 GenRec 训练目标

#### 4.2.1 Next-Item Prediction (核心)

```math
\mathcal{L}_{\text{GR}}(\theta) = -\sum_{t=1}^{T} \sum_{l=1}^{L} \log p_\theta(s_{t,l} \mid s_{t,<l}, s_{<t}, h)
$$

```
目标: 给定用户历史, 预测下一个物品 (SID)
数据: (用户历史, 下一个物品)
损失: Cross-Entropy on SID token (每层级)
输出: 每个 SID 层级的概率分布
```text

**与 LLM 的本质区别**:
- LLM: $y_t$ 是 1 个 token (BPE 子词)
- GenRec: $s_{t,l}$ 是 $L$ 个 token (SID 多层级)

#### 4.2.2 多目标 GenRec 训练目标

```math
\mathcal{L}_{\text{Multi-Objective}} = \sum_{k} w_k \cdot \mathcal{L}_k
$$

其中:
- $\mathcal{L}_{\text{CTR}}$: 二分类损失 (点击)
- $\mathcal{L}_{\text{watch-time}}$: 回归损失 (时长)
- $\mathcal{L}_{\text{GMV}}$: 回归损失 (GMV)
- $\mathcal{L}_{\text{diversity}}$: 多样性损失
- $\mathcal{L}_{\text{fairness}}$: 公平性损失

**常用架构**:
- MMOE (Multi-gate Mixture-of-Experts)
- ESMM (Entire Space Multi-Task Model)
- PLE (Progressive Layered Extraction)
- 共享 backbone + 多个 head

#### 4.2.3 GenRec RL 训练目标

```math
\text{DPO: } \mathcal{L} = -\log \sigma\left(\beta \log \frac{p_\theta(i_w | h)}{p_{\text{ref}}(i_w | h)} - \beta \log \frac{p_\theta(i_l | h)}{p_{\text{ref}}(i_l | h)}\right)
$$

```
目标: i_w > i_l (业务反馈)
偏好对来源: 用户行为 (高 watch-time 优于低)
算法: DPO (隐式奖励)
```text

```math
\text{GBPO (OneRec V2): } \mathcal{L} = -\frac{1}{G} \sum_j \min\left(\frac{\pi_\theta(i_j)}{\pi_{\text{old}}(i_j)} A_j, \text{clip}(\cdot) A_j\right) + \beta \text{KL}
$$

```text
目标: 组内 advantage + Duration-Aware 调整
A_j = (r_j - mean(r)) / std(r) + duration_adjustment
```

```math
\text{HEPO (GPR): } \mathcal{L} = -\mathbb{E}\left[\sum_j A_j \log \pi_\theta(i_j | h)\right] + \beta \text{KL} + \lambda \mathcal{L}_{\text{hybrid}}
$$

```
目标: 混合离线 SFT + 在线 RL 经验
```text

```math
\text{SA-GCPO (OxygenREC): } \mathcal{L} = -\frac{1}{G} \sum_j \min\left(\frac{\pi_\theta(i_j)}{\pi_{\text{old}}(i_j)} A_j, \text{clip}_{\text{soft}}(A_j)\right) + \beta \text{KL}
$$

```text
目标: Soft Adaptive Group Clip
clip 范围随 reward 动态调整
```

# LLM DPO
def llm_dpo(model, ref_model, dataset):
    for step in range(n_steps):
        # 1. 采样偏好对
        prompt, chosen, rejected = dataset.sample_pair()

        # 2. 计算 log probability
        chosen_logp = model.compute_log_prob(prompt + chosen)
        rejected_logp = model.compute_log_prob(prompt + rejected)
        chosen_logp_ref = ref_model.compute_log_prob(prompt + chosen)
        rejected_logp_ref = ref_model.compute_log_prob(prompt + rejected)

        # 3. DPO 损失
        chosen_logratio = chosen_logp - chosen_logp_ref
        rejected_logratio = rejected_logp - rejected_logp_ref

        loss.backward()
        optimizer.step()

# LLM GRPO (DeepSeek)
def llm_grpo(model, ref_model, dataset, G=8):
    for step in range(n_steps):
        # 1. 采样 prompt
        prompt = dataset.sample_prompt()

        # 2. 组采样: 用旧 policy 生成 G 个 response
        responses = []
        for _ in range(G):
            response = model_old.generate(prompt)
            responses.append(response)

        # 3. 计算每个 response 的 reward
        rewards = [reward_model(prompt + r) for r in responses]

        # 4. 组内 advantage
        mean_r = np.mean(rewards)
        std_r = np.std(rewards)
        advantages = [(r - mean_r) / (std_r + 1e-8) for r in rewards]

        # 5. PPO 损失 (组内)
        total_loss = 0
        for response, advantage in zip(responses, advantages):
            new_logp = model.compute_log_prob(prompt + response)
            old_logp = model_old.compute_log_prob(prompt + response)
            ratio = (new_logp - old_logp).exp()
            surr1 = ratio * advantage
            surr2 = torch.clamp(ratio, 1 - 0.2, 1 + 0.2) * advantage
            policy_loss = -torch.min(surr1, surr2).mean()

            kl = compute_kl(model, ref_model, prompt + response)
            total_loss = total_loss + policy_loss + 0.04 * kl

        total_loss = total_loss / G
        total_loss.backward()
        optimizer.step()

#### 5.2.3 GBPO 算法 (OneRec V2)

```python
# GenRec GBPO (Group-Based Policy Optimization)
def genrec_gbpo(model, ref_model, dataset, G=8):
    for step in range(n_steps):
        # 1. 采样 user history
        user_history = dataset.sample_user_history()

        # 2. 组采样: 生成 G 个候选物品
        candidates = []
        for _ in range(G):
            candidate = model.generate(user_history)
            candidates.append(candidate)

        # 3. 计算业务 reward (watch-time)
        rewards = []
        for c in candidates:
            # 模拟 / 真实反馈
            r = compute_business_reward(user_history, c, dataset)
            rewards.append(r)

        # 4. Duration-Aware Advantage
        mean_r = np.mean(rewards)
        std_r = np.std(rewards)
        advantages = []
        for r in rewards:
            # 时长调整: 高完播率额外奖励
            watch_time = compute_watch_time(c, user_history)
            target_duration = get_item_duration(c)
            completion_rate = watch_time / target_duration
            duration_bonus = 0.5 if completion_rate > 0.7 else 0.0

            adv = (r - mean_r) / (std_r + 1e-8) + duration_bonus
            advantages.append(adv)

        # 5. PPO 损失
        total_loss = 0
        for candidate, advantage in zip(candidates, advantages):
            new_logp = model.compute_log_prob(user_history, candidate)
            old_logp = model_old.compute_log_prob(user_history, candidate)
            ratio = (new_logp - old_logp).exp()
            surr1 = ratio * advantage
            surr2 = torch.clamp(ratio, 1 - 0.2, 1 + 0.2) * advantage
            policy_loss = -torch.min(surr1, surr2).mean()

            kl = compute_kl(model, ref_model, user_history, candidate)
            total_loss = total_loss + policy_loss + 0.04 * kl

        total_loss = total_loss / G
        total_loss.backward()
        optimizer.step()
```

#### 5.2.4 HEPO 算法 (GPR)

```python
# GenRec HEPO (Hybrid Experience Policy Optimization)
def genrec_hepo(model, ref_model, dataset):
    for step in range(n_steps):
        # 1. 离线 + 在线混合采样
        offline_data = dataset.sample_offline()  # 历史 SFT 数据
        online_data = dataset.sample_online()    # 在线生成

        # 2. 离线 SFT 损失
        sft_loss = F.cross_entropy(
            model(offline_data.history),
            offline_data.target
        )

        # 3. 在线 RL 损失 (类似 PPO)
        rl_loss = compute_ppo_loss(model, ref_model, online_data)

        # 4. 混合损失
        loss = alpha * sft_loss + (1 - alpha) * rl_loss

        loss.backward()
        optimizer.step()
```

### 5.3 算法对比

| 算法 | LLM | GenRec |
|------|-----|--------|
| **Pretrain** | Next-Token | Next-Item (SID) |
| **SFT** | 指令微调 | 高质量样本微调 |
| **RM** | Bradley-Terry (人类偏好) | 通常跳过 (业务 Reward 直接用) |
| **RL 主流** | PPO / DPO / GRPO | DPO / GBPO / HEPO / SA-GCPO |
| **推理 RL** | GRPO / RLVR (R1) | Rollout-Beam (OneRec-Think) |
| **多 Token** | MTP (GPT/DeepSeek) | HHD (GPR) |

### 5.4 算法选择的差异

```text
LLM 算法选择:
├─ Pretrain: Next-Token (标准)

## 11. 学习率调度

### 11.1 LLM 学习率调度

```text
LLM 学习率调度 (主流):
├─ 1. Warmup + Cosine Decay (主流)
│  ├─ Warmup: 1-2% 步数, 从 0 到峰值
│  ├─ Cosine: 剩余步数, 余弦衰减到 ~10% 峰值
│  └─ Llama / Qwen 标准
│
├─ 2. Warmup + Linear Decay
│  └─ 部分模型使用
│
├─ 3. Constant (SFT)
│  └─ 微调阶段常用
│
└─ 4. Inverse Square Root
   └─ Transformer 原始论文
```

**典型代码**:

```python
# LLM Warmup + Cosine (伪代码)
def get_lr(step, warmup_steps, total_steps, peak_lr, min_lr=0.1):
    if step < warmup_steps:
        # Warmup: 线性增加
        return peak_lr * step / warmup_steps
    else:
        # Cosine decay
        progress = (step - warmup_steps) / (total_steps - warmup_steps)
        return min_lr + 0.5 * (peak_lr - min_lr) * (1 + math.cos(math.pi * progress))

# 使用
for step in range(total_steps):
    lr = get_lr(step, warmup_steps=1000, total_steps=100000, peak_lr=3e-4)
    for param_group in optimizer.param_groups:
        param_group["lr"] = lr
```

### 11.2 GenRec 学习率调度

```text
GenRec 学习率调度:
├─ 1. Warmup + Cosine (主流)
│  └─ 与 LLM 类似
│
├─ 2. Warmup + Linear
│  └─ 简单场景
│
├─ 3. Reduce on Plateau
│  └─ 验证集指标停滞时降低
│
└─ 4. Online Learning
   ├─ 在线学习通常用小 lr
   └─ FTRL / Online Gradient Descent
```

### 11.3 对比

| 维度 | LLM | GenRec |
|------|-----|--------|
| **调度策略** | Warmup + Cosine | Warmup + Cosine |
| **Warmup 比例** | 1-2% | 1-5% |
| **峰值 lr** | 3e-4 | 1e-3 |
| **最小 lr** | 3e-5 (~10%) | 1e-4 (~10%) |
| **在线学习 lr** | 通常无 | 1e-5 - 1e-4 |

## 12. 预训练 vs 微调

### 12.1 LLM 预训练 vs 微调

```text
LLM 训练阶段:
├─ Pretrain (万亿 tokens, 数千 GPU, 数周-数月)

   ├─ 目标: Expected Reward
   ├─ 产出: Aligned Model
   └─ 成本: 万美元级

### 12.2 GenRec 预训练 vs 微调

```text
GenRec 训练阶段:
├─ Pretrain (数十亿行为, 数百 GPU, 数天-数周)

│  ├─ 产出: SFT GR Model

   └─ 成本: 万美元级

(可选) 在线学习:
├─ 数据: 实时反馈

## 13. 数据增强对比

### 13.1 LLM 数据增强

```text
LLM 数据增强 (有限):
├─ 1. Backtranslation
│  └─ 翻译增强 (中→英→中)
├─ 2. Paraphrase
│  └─ 同义改写 (用 LLM 自身)
├─ 3. Mixup / Manifold Mixup
│  └─ 训练时样本混合
├─ 4. Token Masking
│  └─ MLM 风格 (BERT 训练)
└─ 5. Self-Distillation
   └─ 用 LLM 生成数据训练自己
```

**特点**: LLM 主要依赖**数据质量**而非增强, 因为数据本身量大。

### 13.2 GenRec 数据增强

```text
GenRec 数据增强 (丰富):
├─ 1. 滑动窗口 (Sliding Window)
│  ├─ 用不同窗口构造训练样本
│  └─ 序列 → 多个 (input, target) 对
│
├─ 2. 随机截断 (Random Cropping)
│  └─ 截取序列的一部分训练
│
├─ 3. 物品重排 (Item Shuffling)
│  └─ 打乱物品顺序 (增加鲁棒性)
│
├─ 4. 负采样 (Negative Sampling)
│  ├─ 在序列中随机 mask 物品作为负样本
│  └─ 提升对比学习
│
├─ 5. 多任务构造 (Multi-Task)
│  ├─ Next-Item (主)
│  ├─ Next-Category
│  ├─ Next-Attribute
│  └─ 用户画像预测
│
├─ 6. 数据采样权重
│  ├─ 按行为类型加权 (购买 > 点击)
│  └─ 按用户活跃度加权
│
└─ 7. 跨域增强 (Cross-Domain)
   └─ 联合多场景训练
```

**特点**: GenRec 数据增强是**核心**, 因为业务数据有偏, 需要增强。

### 13.3 对比

| 维度 | LLM | GenRec |
|------|-----|--------|
| **数据增强** | 少 (数据本身量大) | 多 (业务数据有偏) |
| **负采样** | 不用 | 核心 |
| **滑动窗口** | 不用 | 核心 |
| **多任务** | 单一 (Next-Token) | 多 (Next-Item + 多目标) |
| **采样权重** | 少 | 重要 |

## 14. 持续训练对比

### 14.1 LLM 持续训练

```text
LLM 持续训练 (有限):
├─ 1. 持续预训练 (Continual Pretrain)

GenRec 持续训练 (核心):

│  ├─ FTRL / 增量训练
│  ├─ 小时级更新
│  └─ 应用: 兴趣漂移
│
├─ 2. 滚动训练 (Rolling Training)
│  ├─ 每日 / 每周用最新数据重训
│  └─ 应用: 季节性 / 活动
│
├─ 3. A/B 测试驱动 (A/B Driven)
│  ├─ 新模型 → 灰度 → 全量
│  ├─ 持续迭代
│  └─ 应用: 模型升级
│
└─ 4. 在线 RL (Online RL)
   ├─ 在线收集反馈
   ├─ 实时更新
   └─ 应用: 业务 KPI 实时优化
```

**典型周期**:

```text
GenRec 模型迭代周期:
├─ HSTU 类模型: 周级 / 月级重训
├─ 在线学习: 小时级
├─ A/B 测试: 持续 (数十实验并行)

LLM 持续训练困难:

## 深度扩展 · 多视角系统展开(续)

### 110. 3-LLM vs GenRec 数据与训练对比 - 融合方向 视角

**核心议题**: 本节从融合方向视角切入,系统展开 "3-LLM vs GenRec 数据与训练对比" 的相关讨论。

**1. 背景与动机**

任何技术或方法的出现都不是孤立的,而是回应特定历史条件下的具体问题。"3-LLM vs GenRec 数据与训练对比" 的发展也不例外。要理解它,必须回到它出现的那个时间点,看清它要解决的真实问题是什么。当时的主流方案有哪些不足? 它的提出填补了哪些空白? 这些问题的回答,决定了我们今天该如何使用它。

从知识论角度看,**技术演进是问题驱动的**——不是先有方案再找问题,而是先有问题再有方案。这个观察可以帮助我们避免"拿着锤子找钉子"的陷阱,真正把方法用对地方。

历史维度上,我们看到三个规律:

1. **从特殊到一般**: 早期方法往往针对特定场景,后期抽象出通用框架。学习的认知规律也是先掌握具体案例,再抽象出一般模式。这种"自下而上"的学习方式,在机器学习模型的设计里反复出现。

2. **从手工到自动**: 经验规则逐步被数据驱动的方法取代。在早期,很多 AI 系统依赖人工编写的规则。统计学习方法的崛起让"从数据中学习"成为可能。深度学习进一步把特征工程也自动化了。今天的大模型时代,我们看到端到端学习从感知扩展到了推理与生成。
