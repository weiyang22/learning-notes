## 0. 一句话总结

> **LLM 的训练目标是"自回归生成下一个 token",GenRec 是"自回归生成下一个物品 + 多任务对齐 + 列表级排序";两者都建立在 softmax 交叉熵上,但 GenRec 必须额外设计 pairwise / listwise / 多任务 / RL 损失来处理"用户兴趣的序关系"**,这是两者最大的差异。

| 维度 | LLM | GenRec |
| :--- | :--- | :--- |
| 主要目标 | NTP (Next-Token Prediction) | NIP (Next-Item Prediction) |
| 辅助目标 | MLM (BERT), Prefix LM | CTR + CVR + Engagement + RL |
| 损失函数 | CE / Focal / DPO | CE + BPR + ListNet + 多任务加权和 |
| 负采样 | 全词表 softmax / 随机负样本 | in-batch + hard negative |
| 课程学习 | 简单 → 复杂(预训练 → SFT → RL) | 易行为 → 难行为(短序 → 长序) |
| 优化技巧 | 标签平滑, Dropout, AdamW | 梯度累积, 任务平衡, 蒸馏 |

下面正式进入 11 节正文 + 1 节深度专题。

## 1. LLM 训练目标

LLM 的训练目标相对单一,核心是**自回归生成**;少数非自回归场景(BERT)用 MLM。下面 4 个子节覆盖主流训练目标。

### 1.1 Next-Token Prediction (NTP)

#### 1.1.1 定义

给定 token 序列 $x_1, x_2, \dots, x_n$,模型预测下一个 token 的条件概率:

$$
P_\theta(x_{t+1} | x_1, \dots, x_t)
$$

损失函数是负对数似然:

$$
\mathcal{L}_{\text{NTP}} = -\sum_{t=1}^{n} \log P_\theta(x_{t+1} | x_{\le t})
$$

#### 1.1.2 数学性质

- **目标可微**:softmax 输出 + 交叉熵,与模型端到端
- **梯度稳定**:$\nabla \mathcal{L} = \text{softmax}(\text{logits}) - \text{onehot}$,无饱和问题
- **等价 MLE**:在 i.i.d. 假设下,NTP = 最大似然估计

#### 1.1.3 PyTorch 实现

```python
import torch
import torch.nn.functional as F

def ntp_loss(logits, labels, ignore_index=-100):
    """
    logits: (B, L, V)
    labels: (B, L)
    """
    shift_logits = logits[:, :-1, :].contiguous()    # (B, L-1, V)
    shift_labels = labels[:, 1:].contiguous()        # (B, L-1)
    return F.cross_entropy(
        shift_logits.view(-1, shift_logits.size(-1)),
        shift_labels.view(-1),
        ignore_index=ignore_index
    )
```

#### 1.1.4 NTP 的局限

| 局限 | 表现 | 解决 |
| :--- | :--- | :--- |
| 单 token 独立 | 无法捕捉 token 间长程依赖 | Transformer attention 缓解 |
| 全词表 softmax | 计算重 | 层次 softmax / NEG sampling |
| 无显式序关系 | 句子顺序无关 | NTP 自带(因果 attention) |
| 没有负反馈 | 不能区分"差答案"与"好答案" | RLHF / DPO / GRPO |

### 1.2 Masked Language Modeling (MLM)

#### 1.2.1 定义

BERT 提出的预训练目标:随机 mask 15% 的 token,预测被 mask 的 token。

$$
\mathcal{L}_{\text{MLM}} = -\sum_{i \in \text{masked}} \log P_\theta(x_i | x_{\ne i})
$$

> 与 NTP 不同:MLM 是**双向**(被 mask 位置可以看到前后文),NTP 是**单向因果**(看不到未来)。

#### 1.2.2 80/10/10 策略

BERT 的关键 trick:

- 80% 概率:`[MASK]` token
- 10% 概率:随机替换为其他 token
- 10% 概率:保持原 token 不变

> 10% 的"非 MASK"避免了预训练-微调的 mismatch。

#### 1.2.3 PyTorch 实现

```python
def mlm_loss(logits, labels, mask_positions, vocab_size):
    """
    logits: (B, L, V)  全部位置的输出
    labels: (B, L)     -100 表示非 mask
    mask_positions: (B, num_masked)
    """
    # 提取 mask 位置的 logits
    masked_logits = logits[mask_positions]   # (B*num_masked, V)
    masked_labels = labels[mask_positions]   # (B*num_masked,)
    return F.cross_entropy(masked_logits, masked_labels, ignore_index=-100)
```

#### 1.2.4 MLM vs NTP 对比

| 维度 | MLM (BERT) | NTP (GPT) |
| :--- | :--- | :--- |
| 方向 | 双向 | 单向因果 |
| 主要应用 | 理解 / 分类 / 检索 | 生成 / 对话 |
| 训练成本 | 低(每步只看 15%) | 高(每步看全部) |
| 下游迁移 | 微调 | 微调 / 续训 |
| 长文本支持 | 弱 | 强(因果 attention) |
| 推理 | 一次前向 | 自回归 N 步 |

### 1.3 Causal LM

#### 1.3.1 严格定义

Causal LM 是 NTP 的标准实现:模型结构使用**下三角 attention mask**,每个位置只看前文。

```python
# 下三角 mask
mask = torch.tril(torch.ones(L, L))
# mask[i, j] = 1 if j <= i else 0
```

#### 1.3.2 与 NTP 的关系

> **Causal LM = NTP + 因果 attention mask**

实际上所有 GPT 风格的模型都是 Causal LM。NTP 是任务,Causal LM 是架构约束。

#### 1.3.3 主流 Causal LM 模型

| 模型 | 参数量 | 备注 |
| :--- | ---: | :--- |
| GPT-2 | 1.5B | 经典 Causal LM |
| GPT-3 | 175B | Few-shot ICL 涌现 |
| Llama 1/2/3 | 7B-405B | 开源代表 |
| Qwen 1/2/3 | 0.5B-72B | 中文最强 |
| DeepSeek-V2/V3 | 16B-670B(MoE) | MoE + MLA |
| Mistral | 7B-22B | 滑动窗口 attention |

### 1.4 Prefix LM

#### 1.4.1 定义

Prefix LM 是 NTP 和 MLM 的"混合":输入分为 **prefix(双向可见)** 和 **target(单向因果)** 两段。

$$
\mathcal{L}_{\text{Prefix LM}} = -\sum_{t \in \text{target}} \log P_\theta(x_t | x_{\text{prefix}}; x_{\text{target} < t})
$$

#### 1.4.2 代表模型

| 模型 | prefix 长度 | target 长度 | 用途 |
| :--- | ---: | ---: | :--- |
| UniLM | 1/2 | 1/2 | NLU 任务 |
| T5 | 变长 | 变长 | Text-to-Text |
| GLM | 50% | 50% | 中英双语 |

#### 1.4.3 与 NTP 的对比

| 维度 | NTP | Prefix LM |
| :--- | :--- | :--- |
| 输入分段 | 无 | prefix + target |
| Attention | 全因果 | prefix 双向,target 因果 |
| 优势 | 简单统一 | prefix 可利用上下文 |
| 缺点 | 无法利用未来 | 实现复杂 |
| 应用 | 纯生成 | 条件生成 |

## 2. GenRec 训练目标

GenRec 的训练目标比 LLM 复杂得多,因为:

1. **用户行为序列有显式时序关系**(昨天点的 → 今天推的)
2. **多个优化目标并存**(CTR、CVR、Engagement、RL)
3. **需要保持物品间的相对序**(不是"哪个对",而是"哪个更好")

### 2.1 Next-Item Prediction (NIP)

#### 2.1.1 定义

NIP 是 GenRec 最核心的训练目标,与 NTP 数学上完全同构:

$$
\mathcal{L}_{\text{NIP}} = -\sum_{t=1}^{n} \log P_\theta(i_{t+1} | i_1, \dots, i_t)
$$

> 把"token"换成"物品"就是 NIP。

#### 2.1.2 NIP 的实现要点

| 维度 | LLM NTP | GenRec NIP |
| :--- | :--- | :--- |
| 词表大小 | 32K – 256K | 1M+ |
| 序列长度 | 1K – 1M | 100 – 1000 |
| 单步 softmax | over 200K | over 1M |
| 训练瓶颈 | GPU 算力 | 显存 + softmax 算力 |
| 负采样 | 词表 vs in-batch | in-batch + hard neg |
| 收敛速度 | 慢(语料大) | 快(信号强) |

#### 2.1.3 PyTorch 实现(OneRec V1 风格)

```python
import torch
import torch.nn.functional as F

def nip_loss(logits, labels, ignore_index=-100):
    """
    logits: (B, L, N_items)
    labels: (B, L)
    """
    shift_logits = logits[:, :-1, :].contiguous()
    shift_labels = labels[:, 1:].contiguous()
    # 物品 N 通常很大,用 fused CE
    return F.cross_entropy(
        shift_logits.view(-1, shift_logits.size(-1)),
        shift_labels.view(-1),
        ignore_index=ignore_index
    )
```

#### 2.1.4 NIP 的关键工程

1. **高效 softmax**:Fused CE / 层次 softmax / 负采样
2. **大词表 embedding**:参数量 = N × d,可达 GB 级
3. **负样本缓存**:常见负样本提前算 logits
4. **混合精度**:FP16/BF16 训练节省 50% 显存

### 2.2 Sequence-to-Sequence

#### 2.2.1 定义

Seq2Seq 在 GenRec 里特指"输入历史 → 输出预测物品"的 Encoder-Decoder 架构:

$$
\mathcal{L}_{\text{Seq2Seq}} = -\sum_{t=1}^{T} \log P_\theta(\hat{i}_t | \text{history}; \hat{i}_{<t})
$$

#### 2.2.2 与 NIP 的区别

| 维度 | NIP (Decoder-only) | Seq2Seq (Encoder-Decoder) |
| :--- | :--- | :--- |
| 架构 | Decoder | Encoder + Decoder |
| 历史表征 | Self-Attention | Encoder 输出 |
| 训练目标 | 续写下一个物品 | 一次生成完整列表 |
| 推理 | 续写到 EOS | Decoder 续写 |
| 代表 | OneRec V1 | TIGER, COURIER |

#### 2.2.3 TIGER 风格 Seq2Seq

```python
class GenRecSeq2Seq(nn.Module):
    def __init__(self, encoder, decoder):
        super().__init__()
        self.encoder = encoder
        self.decoder = decoder

    def forward(self, history_tokens, target_tokens):
        # Encoder 编码历史
        memory = self.encoder(history_tokens)         # (B, L_h, d)
        # Decoder 生成 target
        logits = self.decoder(target_tokens, memory)  # (B, L_t, V)
        return logits
```

#### 2.2.4 Seq2Seq 的优势

- **历史与目标解耦**:Encoder 处理历史,Decoder 处理目标
- **更稳定**:Encoder 不参与生成,训练信号清晰
- **长历史友好**:Encoder 用 attention pooling 即可

#### 2.2.5 Seq2Seq 的劣势

- **推理慢**:两阶段
- **参数多**:Encoder + Decoder
- **优化难**:两阶段联合优化

### 2.3 多任务 (CTR + CVR + Engagement)

GenRec 通常是**多任务联合训练**:

#### 2.3.1 三个核心任务

| 任务 | 公式 | 业务含义 |
| :--- | :--- | :--- |
| CTR | $\mathbb{1}[\text{click}]$ | 用户对物品点击倾向 |
| CVR | $\mathbb{1}[\text{conversion} \| \text{click}]$ | 点击后转化倾向 |
| Engagement | $\mathbb{1}[\text{watch} > 30s]$ | 沉浸度(短视频) |
| GMV | $\text{price} \times \mathbb{1}[\text{buy}]$ | 商业价值 |

#### 2.3.2 多任务损失

$$
\mathcal{L}_{\text{MTL}} = \sum_{k} \alpha_k \mathcal{L}_k
$$

其中 $\alpha_k$ 是任务权重,通常用:

- **固定权重**:简单但需手动调
- **不确定性加权**(Kendall 2018):自动学习
- **GradNorm**:梯度平衡
- **Dynamic Weight Averaging**(DWA)

#### 2.3.3 PyTorch 多任务损失

```python
class MultiTaskLoss(nn.Module):
    def __init__(self, num_tasks):
        super().__init__()
        # 可学习权重
        self.log_vars = nn.Parameter(torch.zeros(num_tasks))

    def forward(self, losses):
        total = 0
        for i, loss in enumerate(losses):
            # uncertainty weighting: L / (2σ²) + log σ
            precision = torch.exp(-self.log_vars[i])
            total += precision * loss + self.log_vars[i]
        return total
```

#### 2.3.4 多任务 vs NTP 单任务

| 维度 | 单 NTP | 多任务 |
| :--- | :--- | :--- |
| 损失数 | 1 | 3 – 10 |
| 参数共享 | 全主模型 | 共享底层, 任务头分开 |
| 训练稳定性 | 高 | 中(任务冲突) |
| 业务对齐 | 弱(仅 NTP 准确) | 强(直接对齐业务) |
| 难度 | 低 | 高(负迁移) |

### 2.4 列表级损失

GenRec 经常需要输出**列表**(10-50 个物品),而非单个物品。这要求损失函数考虑**列表内排序**。

#### 2.4.1 ListNet

ListNet 把列表视为一个分布,用 KL 散度作为损失:

$$
\mathcal{L}_{\text{ListNet}} = -\sum_{j=1}^{|L|} P(j | L) \log P(j | \hat{L})
$$

其中 $P(j | L)$ 是 list-wise softmax 概率:

$$
P(j | L) = \frac{\exp(s_j)}{\sum_{k} \exp(s_k)}
$$

> **核心思想**:让预测列表的概率分布,接近真实列表的概率分布。

#### 2.4.2 ListMLE

ListMLE 用 Plackett-Luce 模型,直接最大化列表的排列概率:

$$
\mathcal{L}_{\text{ListMLE}} = -\sum_{t=1}^{n} \log \frac{\exp(s_{\pi_t})}{\sum_{k=t}^{n} \exp(s_{\pi_k})}
$$

> 其中 $\pi$ 是真实排序, $\pi_t$ 是第 $t$ 位的物品。

#### 2.4.3 与 NTP 的对比

| 维度 | NTP | ListNet / ListMLE |
| :--- | :--- | :--- |
| 输出 | 1 个物品 | 1 个列表 |
| 关注点 | 下一个物品准确 | 列表内序关系 |
| 优化 | 1 个 softmax | N 个 softmax 联合 |
| 工业用 | OneRec V1 | 推荐排序 |

### 2.5 Pairwise 损失

Pairwise 损失关注**物品对的相对序**,而不是绝对分。

#### 2.5.1 BPR Loss

BPR (Bayesian Personalized Ranking) 是推荐系统最经典的 pairwise 损失:

$$
\mathcal{L}_{\text{BPR}} = -\sum_{(i, j) \in D} \log \sigma(\hat{s}_i - \hat{s}_j)
$$

- $i$ 是用户喜欢(正样本)的物品
- $j$ 是用户不喜欢(负样本)的物品
- $\hat{s}$ 是模型预测的分数
- $D$ 是所有 (i, j) 对

#### 2.5.2 BPR 变种

| 变种 | 公式 | 改进 |
| :--- | :--- | :--- |
| BPR | $-\log \sigma(s_+ - s_-)$ | 经典 |
| BPR++ | $-\log \sigma(s_+ - s_-) + \lambda \| \theta \|^2$ | 加正则 |
| WARP | $-\log \frac{\exp(s_+)}{\sum \exp(s_j)}$ | 近似 pairwise ranking |
| SoftRank | $-\sum_{i<j} \log \sigma(s_i - s_j)$ | 软排序 |

#### 2.5.3 与 NTP 的关系

| 维度 | NTP | Pairwise (BPR) |
| :--- | :--- | :--- |
| 目标 | 下一个物品准确 | 物品对相对序 |
| 信息粒度 | point-wise | pair-wise |
| 数据需求 | 需要序列 | 需要 (正,负) 对 |
| 收敛速度 | 中 | 快(信号强) |
| 应用 | LLM, OneRec | 经典召回 / 排序 |

## 3. 损失函数对比

### 3.1 Cross-Entropy

#### 3.1.1 LLM 用法

$$
\mathcal{L}_{\text{CE}} = -\sum_{t} \log \frac{\exp(z_{t, x_{t+1}})}{\sum_{v} \exp(z_{t, v})}
$$

LLM 几乎只用 CE,数学性质好(梯度 = softmax - onehot)。

#### 3.1.2 GenRec 用法

GenRec 也大量用 CE(NIP 形式),但**多任务时是多个 CE 之和**:

$$
\mathcal{L} = \alpha_{\text{NIP}} \mathcal{L}_{\text{CE, NIP}} + \alpha_{\text{CTR}} \mathcal{L}_{\text{CE, CTR}} + \dots
$$

#### 3.1.3 数学对比

| 公式项 | LLM | GenRec |
| :--- | :--- | :--- |
| 分子 | $\exp(z_{x_t})$ | $\exp(z_{i_t})$ |
| 分母 | $\sum_v \exp(z_v)$ over V | $\sum_v \exp(z_v)$ over items |
| V 大小 | 32K – 256K | 1M+ |
| 加速 | Fused CE | Fused CE / 负采样 |

#### 3.1.4 CE 的局限

- **类别不平衡**:长尾物品梯度被淹没
- **Hard Example**:对"看似简单"的负样本无信息
- **没有序信息**:只关心"对"或"不对",不关心"哪个更对"

> 这些局限催生了 Focal Loss / BPR / ListNet 等。

### 3.2 Binary Cross-Entropy

#### 3.2.1 公式

$$
\mathcal{L}_{\text{BCE}} = -\frac{1}{N} \sum_i \left[ y_i \log p_i + (1 - y_i) \log(1 - p_i) \right]
$$

#### 3.2.2 在 GenRec 中的应用

| 任务 | 标签 | 模型输出 |
| :--- | :--- | :--- |
| CTR | click / no-click | sigmoid(logit) |
| CVR | conversion / no-conversion | sigmoid(logit) |
| Like | like / not-like | sigmoid(logit) |

#### 3.2.3 与 CE 的对比

| 维度 | CE (softmax) | BCE (sigmoid) |
| :--- | :--- | :--- |
| 输出 | V 维 softmax | 1 维 sigmoid |
| 多类互斥 | 强制 | 不强制 |
| 适用 | 单标签多类 | 多标签二类 |
| 优化难度 | 中 | 易 |
| 工业场景 | NTP, NIP | CTR, CVR |

### 3.3 ListNet / ListMLE

详见 [§2.4](#24-列表级损失)。

| 维度 | LLM | GenRec |
| :--- | :--- | :--- |
| 是否使用 | 否 | 是(列表输出时) |
| 代表 | — | ListNet, ListMLE, ApproxNDCG |
| 优势 | — | 直接优化 NDCG |
| 劣势 | — | 计算成本高 |

### 3.4 BPR Loss

详见 [§2.5.1](#251-bpr-loss)。

#### 3.4.1 在 GenRec 中的地位

BPR 是"经典召回"的核心损失,但在**生成式推荐**(OneRec / TIGER)里被 NIP 替代:

```text
传统召回: BPR (i, j) 对
生成式召回: NIP 下一物品

后者的优势:可以利用完整历史序列
```

#### 3.4.2 BPR vs NIP 数学对比

| 维度 | BPR | NIP |
| :--- | :--- | :--- |
| 输入 | 单个 (user, pos, neg) | 整个历史序列 |
| 损失 | $-\log \sigma(s_+ - s_-)$ | $-\log p(i_{t+1} \| i_{<t})$ |
| 复杂度 | $O(1)$ per pair | $O(N)$ per sequence |
| 表达力 | 弱 | 强 |
| 冷启动 | 一般 | 弱(需历史) |

### 3.5 Focal Loss

#### 3.5.1 公式

Focal Loss 在 BCE 基础上加 $\gamma$ 调节:

$$
\mathcal{L}_{\text{Focal}} = -\alpha (1 - p)^\gamma \log p
$$

- $\gamma = 0$: 退化为 BCE
- $\gamma = 2$: 显著抑制易样本
- $\alpha$: 类别平衡权重

#### 3.5.2 LLM 中是否使用?

LLM 主训练不用 Focal Loss,但**RLHF 的 reward model**会用(因为偏好对样本不平衡)。

#### 3.5.3 GenRec 中是否使用?

GenRec 的**二分类 head(CTR/CVR)**广泛用 Focal Loss,尤其是负样本远多于正样本时。

#### 3.5.4 对比表

| 维度 | BCE | Focal |
| :--- | :--- | :--- |
| 易样本权重 | 1.0 | $(1-p)^\gamma$ |
| 难样本权重 | 1.0 | $(1-p)^\gamma$ |
| 类别平衡 | 手动 | 自动($\alpha$) |
| 适用 | 均衡二分类 | 不均衡 |

## 4. 辅助损失对比

### 4.1 LLM: 语言学约束

LLM 的辅助损失主要是**正则化和语言学约束**:

#### 4.1.1 标签平滑 (Label Smoothing)

将 one-hot 改为:

$$
y_{\text{smooth}} = (1 - \epsilon) \cdot \text{onehot} + \frac{\epsilon}{V}
$$

> 防止过拟合,提升泛化。但 GPT-3+ 大模型已少用。

#### 4.1.2 Dropout

$$
h_{\text{drop}} = h \odot \text{Bernoulli}(1 - p)
$$

经典正则化,LLM 仍广泛使用(尤其 FFN 后)。

#### 4.1.3 权重衰减 (Weight Decay)

$$
\mathcal{L}_{\text{total}} = \mathcal{L}_{\text{CE}} + \lambda \| \theta \|_2^2
$$

AdamW 是事实标准,把 weight decay 与梯度解耦。

#### 4.1.4 辅助 NTP 损失 (ALiBi / 位置编码辅助)

部分 LLM 在中间层加辅助 NTP 损失(如 Google T5 的"中间层监督")。

#### 4.1.5 RLHF / DPO 损失

详见 [[7-RLHF与RL对齐对比]]。

### 4.2 GenRec: 多任务对齐

GenRec 的辅助损失**直接服务于业务**:

#### 4.2.1 CTR 辅助损失

```python
ctr_loss = F.binary_cross_entropy_with_logits(
    ctr_logits, click_labels
)
```

#### 4.2.2 CVR 辅助损失 (ESMM)

Entire Space Multi-task Model(ESMM)用全空间建模:

$$
P(\text{CTCVR}) = P(\text{CTR}) \cdot P(\text{CVR})
$$

损失:

$$
\mathcal{L}_{\text{ESMM}} = \mathcal{L}_{\text{CTR}} + \mathcal{L}_{\text{CTCVR}}
$$

> **关键**: CVR 是基于点击的,所以训练样本空间与推理样本空间不一致。ESMM 解决这个 selection bias。

#### 4.2.3 Engagement 辅助损失

短视频场景的"完播率 / 点赞 / 收藏":

```python
engagement_loss = (
    F.binary_cross_entropy_with_logits(finish_logits, finish_label) +
    F.binary_cross_entropy_with_logits(like_logits, like_label) +
    F.binary_cross_entropy_with_logits(fav_logits, fav_label)
)
```

#### 4.2.4 RL 辅助损失

详见 [[7-RLHF与RL对齐对比]]。典型方法:

- OneRec V1: DPO
- OneRec V2: GBPO
- OneRec-Think: GRPO + Rollout-Beam
- OneRec-Foundation: General Distillation + Rec-RL

#### 4.2.5 蒸馏损失

```python
# Teacher = 大模型
# Student = 部署模型
distill_loss = F.kl_div(
    student_logits.log(),
    teacher_logits.softmax(dim=-1),
    reduction='batchmean'
)
```

> **GenRec 蒸馏的特殊性**: 教师可能是 OneRec V3 大模型,学生是 OneRec V2 中等模型。

### 4.3 辅助损失设计的本质区别

| 维度 | LLM 辅助损失 | GenRec 辅助损失 |
| :--- | :--- | :--- |
| 目的 | 正则化 / 防过拟合 | 直接对齐业务 |
| 形式 | 平滑 / Dropout / 衰减 | 多任务 BCE / DPO |
| 信号来源 | 模型自身 | 业务指标 |
| 调整频率 | 一次性 | 持续(随业务变) |
| 优化空间 | 几乎已被穷尽 | 还在快速演进 |

## 5. 负采样对比

### 5.1 LLM 的负采样

LLM 几乎**不做负采样**:直接对全词表 softmax(200K 类),配合大 batch 实现高效 CE。

#### 5.1.1 替代方案:Full Softmax

```python
# 标准 NTP
logits = model(input_ids)              # (B, L, V)
loss = F.cross_entropy(
    logits.view(-1, V),
    labels.view(-1)
)
```

- 全词表大小 V
- 单步计算 V × dim

#### 5.1.2 偶尔使用负采样

- **Word2Vec** 时代:Negative Sampling(NEG)
- **小模型**:节省内存
- **大模型**:不需要

### 5.2 GenRec 的负采样

GenRec **必须**做负采样,因为物品库 N 通常 1M+,全 softmax 计算太重。

#### 5.2.1 In-Batch Negatives

```python
# 假设 batch 内 256 个用户,每个看过的下一个物品
# (B=256, N=1M)
# 候选 1 个正样本 + 255 个 in-batch 负样本
# loss 只算 256 个,不是全 1M
```

| 维度 | 数值 |
| :--- | ---: |
| 批次大小 | 256 |
| 正样本数 | 1 / 序列位置 |
| 负样本数 | 255 |
| 总候选 | 256 |
| softmax 计算 | 256 类 |

#### 5.2.2 Hard Negative Mining

随机负样本效果有限,**hard negative**(看起来像正样本但实际不是)显著提升模型:

```python
# 1. 用当前模型推理,取 top-K 中"未点击"的物品
# 2. 这些就是 hard negative
# 3. 重新训练
```

#### 5.2.3 负采样规模对比

| 场景 | LLM | GenRec |
| :--- | :--- | :--- |
| 正样本 | 1 token | 1 item |
| 负样本 | V - 1 tokens | in-batch 255 + hard neg 100 |
| 总 softmax | V = 200K | 256 + 100 = 356 |
| 比例 | 1 : 200K | 1 : 356 |

### 5.3 负采样数学对比

LLM:

$$
\mathcal{L}_{\text{LLM-NTP}} = -\log \frac{\exp(z_{x_{t+1}})}{\sum_{v \in V} \exp(z_v)}
$$

GenRec:

$$
\mathcal{L}_{\text{GenRec-NIP}} = -\log \frac{\exp(z_{i_{t+1}})}{\exp(z_{i_{t+1}}) + \sum_{n \in N} \exp(z_n)}
$$

> **本质**:GenRec 的 NIP 是**采样近似的 NTP**,仅对部分负样本计算 softmax。

## 7. 数学公式对比

### 7.1 LLM 训练目标形式化

$$
\mathcal{L}_{\text{LLM}} = \underbrace{-\sum_t \log P_\theta(x_{t+1} | x_{\le t})}_{\text{NTP}} + \underbrace{\lambda_1 \mathcal{L}_{\text{aux}}}_{\text{辅助}} + \underbrace{\lambda_2 \mathcal{L}_{\text{RL}}}_{\text{RLHF}}
$$

### 7.2 GenRec 训练目标形式化

$$
\mathcal{L}_{\text{GenRec}} = \underbrace{-\sum_t \log P_\theta(i_{t+1} | i_{\le t}; \text{context})}_{\text{NIP}} + \underbrace{\sum_k \alpha_k \mathcal{L}_k(\text{CTR, CVR, ...})}_{\text{多任务}} + \underbrace{\mathcal{L}_{\text{RL}}}_{\text{RL 对齐}} + \underbrace{\mathcal{L}_{\text{ListNet}}}_{\text{列表级}}
$$

### 7.3 关键差异对比表

| 公式元素 | LLM | GenRec |
| :--- | :--- | :--- |
| 主损失 | NTP(NLL) | NIP(NLL) |
| 多任务权重 | 几乎不用 | 多个 $\alpha_k$ |
| RL 损失 | 可选(RLHF/DPO) | 必备 |
| 列表级损失 | 无 | 可选 |
| Pairwise 损失 | 无 | 可选(BPR) |
| 负采样 | 全词表 | In-batch + hard neg |
| 总损失规模 | 1 项 | 5 – 10 项 |

## 12. 深度专题

### 12.1 训练目标的对偶关系

#### 12.1.1 NTP 与 NIP 的对偶

把"token"换成"物品",NTP ↔ NIP。这不是比喻,是**严格的数学对偶**:

```text
LLM:     P(x_t | x_{<t}) = softmax(E_x @ W^T)
GenRec:  P(i_t | i_{<t}) = softmax(E_i @ W^T)
```

> 训练目标函数**完全同构**,差别只在"token"的来源。

#### 12.1.2 RLHF 与 Rec-RL 的对偶

| LLM 阶段 | GenRec 阶段 |
| :--- | :--- |
| Pretrain | NIP 预训练 |
| SFT | NIP 监督微调 |
| RM 训练 | CTR / CVR / Engagement 拟合 |
| PPO | GRPO / GBPO |
| DPO | OneRec V1 DPO |
| GRPO | OneRec-Think |
| RLVR | RLVR-style 业务指标 |

> **两者本质同构**:先学大规模数据(SFT),再用偏好对齐(RL)。

### 12.2 标签平滑的细节

#### 12.2.1 标准 Label Smoothing

```python
def label_smooth(target, vocab_size, eps=0.1):
    # target: (B,) integer
    # output: (B, V) smoothed distribution
    one_hot = F.one_hot(target, vocab_size).float()
    smoothed = one_hot * (1 - eps) + eps / vocab_size
    return smoothed
```

#### 12.2.2 LLM 用 vs 不用

| 模型 | 标签平滑 | 备注 |
| :--- | :---: | :--- |
| GPT-2/3 | 0.1 | 使用 |
| Llama 1/2 | 0 | 不用(大模型不需要) |
| Llama 3 | 0 | 同 |
| Qwen | 0 | 同 |
| DeepSeek | 0 | 同 |
| GenRec(早期) | 0.1 | 用 |
| GenRec(2024+) | 0 | 大模型不用 |

### 12.3 任务权重的自动学习

#### 12.3.1 不确定性加权 (UW)

```python
class UWLoss(nn.Module):
    def __init__(self, num_tasks):
        super().__init__()
        # log σ², 可学习
        self.log_vars = nn.Parameter(torch.zeros(num_tasks))

    def forward(self, losses):
        total = 0
        for i, loss in enumerate(losses):
            # L_k / (2 exp(s_k)) + s_k / 2
            precision = torch.exp(-self.log_vars[i])
            total += precision * loss + self.log_vars[i]
        return total
```

#### 12.3.2 GradNorm

```python
# 在每个 step:
# 1. 计算每个任务的梯度范数
# 2. 与任务权重 α_k 一起,求解 α 平衡
# 3. 更新 α
```

#### 12.3.3 DWA (Dynamic Weight Averaging)

```python
# 在每个 step:
# 1. 记录上 k 个 step 的 loss
# 2. 计算每个任务的"训练速度"
# 3. 速度越快,权重越低(防止过快收敛)
```

#### 12.4.3 蒸馏 Loss 数学

```python

T = 2.0  # temperature
student_logits = student(x)
teacher_logits = teacher(x)
loss = F.kl_div(
    F.log_softmax(student_logits / T, dim=-1),
    F.softmax(teacher_logits / T, dim=-1),
    reduction='batchmean'
) * (T ** 2)

# GenRec 加权蒸馏(平衡多任务)
loss = (
    kl_weight_nip * kl_nip +
    kl_weight_ctr * kl_ctr +
    kl_weight_emb * mse(student_emb, teacher_emb)
)
```

### 12.5 Loss 监控与异常恢复

#### 12.5.1 Loss spike 检测

```python
class LossSpikeDetector:
    def __init__(self, window=100, threshold=2.0):
        self.losses = deque(maxlen=window)
        self.threshold = threshold

    def step(self, loss):
        self.losses.append(loss)
        if len(self.losses) < self.window:
            return False
        avg = sum(self.losses) / self.window
        return loss > avg * self.threshold
```

#### 12.5.2 异常恢复

| 异常 | 表现 | 恢复 |
| :--- | :--- | :--- |
| Loss spike | loss 突然 ↑3x | 回滚 checkpoint + 降 LR |
| Loss NaN | loss = NaN | 跳过 batch + 检查数据 |
| Loss plateau | loss 不下降 | LR 衰减 + early stop |
| Val loss ↑ train loss ↓ | 过拟合 | 加大 reg / dropout |
| 业务指标 ↓ loss ↓ | 任务权重失衡 | 调整 α_k |

### 12.10 不同损失函数的"梯度幅度"

#### 12.10.1 NTP/NIP 梯度

```python
∂L/∂z = softmax(z) - one_hot
幅度: O(1) (标准化后)
```

#### 12.10.2 BCE 梯度

```python
∂L/∂z = (p - y) / (p(1-p))     # 简化为 p - y
幅度: O(1)
```

#### 12.10.3 Focal 梯度

```python
∂L/∂z = α γ (1-p)^(γ-1) · (p - y) · log(p) + ...
幅度: 受 γ 控制
```

#### 12.10.4 ListNet 梯度

```python
∂L/∂s_j = - P(j|L) + P(j|L̂)
幅度: 受分布平滑度影响
```

#### 12.10.5 GRPO 梯度

```python
A_i = (r_i - mean(r)) / std(r)
∂L/∂π = -A_i · ∇log π(a_i|s_i)
幅度: 由 advantage 决定
```

## 13. 深度补充专题

> 进一步展开正文中控制体量的话题。每节独立可读。

### 13.1 损失函数的"信息论"视角

#### 13.1.1 NTP/NIP 作为 KL 散度

NTP/NIP 在数学上等价于**让模型分布 $P_\theta$ 逼近真实分布 $P_{\text{data}}$**:

$$
\mathcal{L}_{\text{NTP}} = \mathbb{E}_{P_{\text{data}}} [-\log P_\theta(x_{t+1} | x_{\le t})] = H(P_{\text{data}}, P_\theta)
$$

即交叉熵。KL 散度差一个常数项:

$$
D_{\text{KL}}(P_{\text{data}} \| P_\theta) = H(P_{\text{data}}, P_\theta) - H(P_{\text{data}})
$$

> **结论**:训练 NTP = 最小化 $D_{\text{KL}}$。

#### 13.1.2 BPR 的概率解释

BPR 最大化"用户喜欢 i 多于 j"的概率:

$$
P(i >_u j) = \sigma(\hat{s}_i - \hat{s}_j)
$$

整个训练是**最大似然估计**这个 pairwise 概率。

#### 13.1.3 ListMLE 的概率解释

ListMLE 最大化**整个排序**的概率:

$$
P(\pi | s) = \prod_{t=1}^{n} \frac{\exp(s_{\pi_t})}{\sum_{k=t}^{n} \exp(s_{\pi_k})}
$$

> 这就是 Plackett-Luce 模型。

### 13.2 Perplexity 与 Hit Rate 的关系

#### 13.2.1 Perplexity

LLM 用 Perplexity (PPL) 衡量:

$$
\text{PPL} = \exp\left(-\frac{1}{N} \sum_{t=1}^N \log P_\theta(x_t | x_{<t})\right)
$$

> PPL 越低越好,等价于交叉熵。

#### 13.2.2 Hit Rate

GenRec 用 Hit@K:

$$
\text{Hit@K} = \frac{1}{|U|} \sum_{u \in U} \mathbb{1}[\text{rank}(i^*) \le K]
$$

> Hit@K 越高越好。

#### 13.2.3 关系

两者**优化方向不同**:

| 维度 | PPL | Hit@K |
| :--- | :--- | :--- |
| 评估对象 | 单 token 概率 | top-K 准确 |
| 关注 | 全词表概率分布 | 排序质量 |
| 提升路径 | 训练所有 token | 训练 top-K 物品 |

> **优化 NTP 的同时 PPL 降,但 Hit@K 可能不变**。这正是 GenRec 需要额外 listwise loss 的原因。

### 13.3 Reward Hacking 与 Loss Hack

#### 13.3.1 LLM 中的 Loss Hacking

LLM 训练中常见的"曲线作弊":

| 现象 | 表现 | 原因 |
| :--- | :--- | :--- |
| Loss 降但 PPL 不降 | loss 数字漂亮,但概率无意义 | label smooth 过大 |
| Loss 降但下游差 | 评估指标差 | 过拟合到训练分布 |
| Loss 降但生成重复 | 模型陷入循环 | KL 太小 |

#### 13.3.2 GenRec 中的 Loss Hacking

| 现象 | 表现 | 原因 |
| :--- | :--- | :--- |
| NIP loss 降但 CTR 不升 | 自回归准但推荐差 | 仅优化 token,不优化业务 |
| BPR loss 降但召回差 | pairwise 对齐但全局差 | 局部最优 |
| 多任务 loss 全降但业务降 | 任务冲突 | 权重失衡 |

> **核心启示**:Loss 数字只是代理,真正目标是业务指标。

### 13.8 训练目标的"几何直觉"

#### 13.8.1 NTP 的几何

```text
P(x_{t+1} | x_{<t}) = softmax(E_x · h_t^T)

其中 h_t 是当前位置 hidden state
        E_x 是 token embedding 表

训练过程:
  - 让 h_t 指向"正确 token"的 embedding
  - 让"错误 token"的 embedding 与 h_t 距离变远
```

#### 13.8.2 NIP 的几何

```text
P(i_{t+1} | i_{<t}) = softmax(E_i · h_t^T)

其中 h_t 是当前位置 hidden state
        E_i 是物品 SID embedding 表

训练过程:
  - 让 h_t 指向"下一个物品"的 embedding
  - 头部物品被频繁指向,长尾物品靠聚类共享梯度
```

| 损失 | $-\log p_\theta(x_{t+1} \| x_{<t})$ | $-\log p_\theta(i_{t+1} \| i_{<t})$ |
| 辅助 | NTP + Label smooth | NIP + CTR + RL |
| 优化器 | AdamW | Adam |

> **形式上完全对偶**,差别在于:GenRec 必须额外加 listwise / pairwise / RL 损失。

| 收敛速度 | 慢 | 快 |
| 业务对齐 | 弱 | 强 |

### A.5 业务对齐与损失函数

| 业务目标 | LLM 对应损失 | GenRec 对应损失 |
| :--- | :--- | :--- |
| 内容质量 | DPO / GRPO | DPO / GBPO |
| 用户满意度 | RLHF Reward | CTR / CVR BCE |
| 商业价值 | (无对应) | GMV / RPM BCE |
| 多样性 | Temperature / Top-p | DPP / MMR 重排 |
| 公平性 | DPO bias 评估 | 长尾物品 BPR 加权 |
| 安全 | Constitutional AI | 内容过滤 / 黑名单 |

### A.6 训练目标-评估指标对齐表

| 训练目标 | 离线评估 | 在线评估 |
| :--- | :--- | :--- |
| LLM NTP | PPL, BLEU | 用户满意度 |
| LLM RLHF | MT-Bench | 留存,点赞 |
| GenRec NIP | Recall, NDCG | CTR, CVR |
| GenRec 多任务 | 多任务 BCE 总和 | GMV |
| GenRec RL | GBPO loss | RPM, ADVV |

### A.7 工业实践中"训-推"对齐的口诀

```text
LLM:
  训练 NTP          →  评估 PPL
  训练 DPO          →  评估 MT-Bench
  训练 GRPO         →  评估 HumanEval

GenRec:
  训练 NIP          →  评估 Recall@K
  训练 CTR head     →  评估 Logloss
  训练 GBPO         →  评估 RPM
  训练 多任务总和    →  评估 GMV
```

### A.9 一句话总结:训练目标的"双重对齐"

LLM 的训练目标需要对齐:
- **任务对齐**:Pretrain → SFT → RL
- **人类偏好对齐**:RLHF / DPO / GRPO

GenRec 的训练目标需要对齐:
- **任务对齐**:NIP → 多任务 → 列表级
- **业务指标对齐**:CTR / CVR / GMV / RL

> 两者本质同构:**"先学大规模基础,再对齐上层目标"**。

### A.10 训练目标的"工程优先级"

```text
第一优先:正确性 (Loss 数值准确)
第二优先:稳定性 (不 spike, 不 NaN)
第三优先:收敛速度 (epoch 数)
第四优先:泛化能力 (val 表现)
第五优先:业务对齐 (在线指标)
```

> 工业里"正确性 + 稳定性" > "收敛速度" > "业务对齐"。但研究方向相反。

### A.8 训练目标的设计反模式

| 反模式 | 表现 | 解决 |
| :--- | :--- | :--- |
| 单一目标过拟合 | train loss ↓ val loss ↑ | 加 reg / 多任务 |
| 任务权重固定 | 后期任务冲突 | UW / GradNorm |
| RL reward 过拟合 | reward 高但业务差 | KL 约束 + 在线 A/B |
| 蒸馏丢失教师 | 学生差 | 检查 teacher 质量 |
| Loss Hacking | 数字漂亮但效果差 | 真实业务评估 |

| 技巧 | LLM | GenRec |
| :--- | :---: | :---: |
| AdamW | ✅ | ✅ |
| Mixed Precision | ✅ | ✅ |
| Flash Attention | ✅ | ✅ |
| FSDP / ZeRO | ✅ | ✅ |

> [!summary] **关键 takeaway**:
> 1. LLM 的训练目标以单一 NTP 为主,GenRec 是 NIP + 多任务 + RL + 列表级的复杂组合。
> 2. 损失函数:LLM 主要用 CE;GenRec 还要 BPR、ListNet、Focal、DPO/GBPO/GRPO。
> 3. 负采样:LLM 全词表 softmax;GenRec 必须 in-batch + hard neg。
> 4. 课程学习:LLM 三阶段(Pretrain/SFT/RL);GenRec 多维度(长度/物品/任务)。
> 5. 优化技巧大体相似,但 GenRec 必须解决多任务平衡。
