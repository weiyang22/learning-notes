## 0. 一句话总结

> **LLM 用学术基准(MMLU/GSM8K/MT-Bench)+ Perplexity 衡量"理解 + 推理 + 对齐",GenRec 用离线排序指标(Recall/NDCG)+ 在线业务指标(CTR/CVR/GMV)衡量"召回 + 排序 + 商业价值"**;两者在评估哲学、指标维度、A/B 测试和长期价值上存在根本差异。

| 维度 | LLM | GenRec |
| :--- | :--- | :--- |
| 主要离线指标 | PPL, MMLU, HumanEval, GSM8K | Recall@K, NDCG@K, Hit@K |
| 主要在线指标 | 用户留存, 满意度 | CTR, CVR, RPM, ADVV |
| 人类评估 | MT-Bench, AlpacaEval | 用户行为(点击/购买) |
| 鲁棒性 | 对抗样本, prompt injection | 冷启动, 长尾 |
| 公平性 | 群体偏见, 毒害内容 | 曝光公平, 流行度偏差 |
| A/B 周期 | 周 ~ 月 | 天 ~ 周 |

## 1. LLM 评估指标

LLM 的评估指标体系非常丰富,从"基础语言建模能力"到"复杂推理能力"再到"人类偏好对齐",各有不同的基准。下面 9 个小节覆盖主流指标。

### 1.1 Perplexity

#### 1.1.1 定义

Perplexity (PPL) 是衡量语言模型最基础的指标,定义为:

$$
\text{PPL}(\mathcal{D}) = \exp\left(-\frac{1}{N} \sum_{t=1}^N \log P_\theta(x_t | x_{<t})\right)
$$

即**测试集平均负对数似然的指数**。

#### 1.1.2 解释

- PPL = 10:模型在每步上"等效于从 10 个选项中猜"
- PPL = 1:完美预测
- PPL = ∞:完全随机

#### 1.1.3 优缺点

| 维度 | 优点 | 缺点 |
| :--- | :--- | :--- |
| 计算简单 | ✅ | — |
| 客观 | ✅(无人工) | — |
| 与下游任务相关性 | 中 | 不直接 |
| 受 tokenizer 影响 | — | 是(同模型不同 tokenizer 也不同) |
| 多语言一致性 | 差 | 中文 PPL 通常更高 |

#### 1.1.4 主流模型的 PPL

| 模型 | WikiText-103 PPL |
| :--- | :---: |
| GPT-2 | 29.4 |
| GPT-3 175B | 20.5 |
| Llama 2 7B | 5.5 |
| Llama 3 8B | 4.6 |
| Qwen2.5 7B | 4.2 |

> PPL 越低越好,但**不直接代表下游任务能力**。

### 1.2 BLEU / ROUGE

#### 1.2.1 BLEU (Bilingual Evaluation Understudy)

用于**机器翻译**的 n-gram 精度指标:

$$
\text{BLEU} = \text{BP} \cdot \exp\left(\sum_{n=1}^N w_n \log p_n\right)
$$

其中:
- $p_n$ 是 n-gram 精度
- BP 是 brevity penalty(防止过短翻译)
- $w_n = 1/N$ 是权重

#### 1.2.2 ROUGE (Recall-Oriented Understudy for Gisting Evaluation)

用于**文本摘要**的 n-gram 召回指标:

$$
\text{ROUGE-N} = \frac{\sum_{S \in \text{Ref}} \sum_{n\text{-gram} \in S} \text{Count}_{\text{match}}(n\text{-gram})}{\sum_{S \in \text{Ref}} \sum_{n\text{-gram} \in S} \text{Count}(n\text{-gram})}
$$

#### 1.2.3 对比

| 维度 | BLEU | ROUGE |
| :--- | :--- | :--- |
| 关注 | Precision | Recall |
| 适用 | 翻译 | 摘要 |
| 范围 | 0 – 100 | 0 – 100 |
| 缺点 | 不考虑语义 | 同 |

#### 1.2.4 LLM 时代的地位

随着 NLG 任务的多样化,BLEU/ROUGE 已**不再是主流 LLM 评估指标**,仅在特定子领域(翻译、摘要)使用。

### 1.3 MMLU

#### 1.3.1 定义

MMLU (Massive Multitask Language Understanding) 是衡量**世界知识 + 多领域理解**能力的核心基准。

- **57 个学科**(数学、物理、法律、医学、历史...)
- **约 16K 个四选一题**
- 测试方式:zero-shot / few-shot

#### 1.3.2 数据样例

```text
Question: 下列哪个不是哺乳动物?
A. 鲸鱼 (whale)
B. 蝙蝠 (bat)
C. 鲨鱼 (shark)
D. 人类 (human)
Answer: C
```

#### 1.3.3 主流分数

| 模型 | MMLU 5-shot |
| :--- | :---: |
| GPT-3 175B | 70.0 |
| GPT-4 | 86.4 |
| Llama 2 70B | 69.0 |
| Llama 3 70B | 82.0 |
| Qwen2.5 72B | 86.0 |
| Claude 3.5 Sonnet | 88.7 |
| DeepSeek-V3 670B | 88.5 |

#### 1.3.4 局限

- **文化偏置**:以英文 / 美式知识为主
- **记忆 vs 推理**:可以靠记忆高分
- **题目类型单一**:四选一

### 1.4 HumanEval

#### 1.4.1 定义

HumanEval 是衡量**代码生成**能力的基准:

- 164 道编程题
- 通过率 = pass@k
- 函数签名 + docstring → 模型补全

#### 1.4.2 评分方式

```python
def pass_at_k(n, c, k):
    """n 个样本中, c 个正确, 至少一个正确的概率"""
    if n - c < k: return 1.0
    return 1.0 - np.prod(1.0 - k / np.arange(n - c + 1, n + 1))
```

| 模型 | HumanEval pass@1 |
| :--- | :---: |
| GPT-3.5 | 48.1 |
| GPT-4 | 67.0 |
| Claude 3.5 | 93.0 |
| Llama 3 70B | 81.7 |
| Qwen2.5 Coder 32B | 92.0 |
| DeepSeek-Coder-V2 | 90.0 |

#### 1.4.4 衍生基准

- **MBPP**:更基础的 Python 编程题

- **SWE-bench**:GitHub issue 级任务

## 2. GenRec 评估指标

GenRec 的评估指标体系分两层:**离线排序指标**(Recall/NDCG/Hit)和**在线业务指标**(CTR/CVR/RPM)。

### 2.1 AUC / GAUC

#### 2.1.1 AUC (Area Under ROC Curve)

$$
\text{AUC} = \mathbb{P}(s_+ > s_-)
$$

其中 $s_+$ 是正样本分数, $s_-$ 是负样本分数。

物理意义:**随机一对正负样本,正样本分数高于负样本的概率**。

#### 2.1.2 GAUC (Group AUC)

GAUC 是用户内 AUC 的加权:

$$
\text{GAUC} = \frac{\sum_{u} w_u \cdot \text{AUC}_u}{\sum_u w_u}
$$

其中 $\text{AUC}_u$ 是用户 $u$ 的 AUC, $w_u$ 通常是曝光量。

> **意义**:衡量"模型在每个用户内的排序能力",更贴近推荐本质。

#### 2.1.3 优缺点

| 维度 | AUC | GAUC |
| :--- | :--- | :--- |
| 反映整体 | ✅ | ✅ |
| 反映个体 | ❌ | ✅ |
| 与业务对齐 | 弱 | 强 |
| 计算 | 简单 | 中等 |
| 在线指标相关性 | 中 | 高 |

#### 2.1.4 工业典型值

| 任务 | AUC | GAUC |
| :--- | :---: | :---: |
| 召回 | 0.85 | 0.78 |
| 粗排 | 0.83 | 0.75 |
| 精排 CTR | 0.82 | 0.74 |
| 精排 CVR | 0.75 | 0.68 |

### 2.2 Recall@K

#### 2.2.1 定义

召回率:在前 K 个推荐结果中,真实正样本的比例。

$$
\text{Recall@K} = \frac{|\text{TopK} \cap \text{Positives}|}{|\text{Positives}|}
$$

#### 2.2.2 在 GenRec 中的应用

```python
def recall_at_k(predictions, labels, k=10):
    """
    predictions: (B, N) scores
    labels: (B, N) binary
    """
    topk_pred = torch.topk(predictions, k=k, dim=-1).indices  # (B, k)
    hits = torch.gather(labels, 1, topk_pred).sum(dim=-1)     # (B,)
    total = labels.sum(dim=-1)                                 # (B,)
    return (hits / total).mean()
```

#### 2.2.3 工业典型值

| 任务 | Recall@10 | Recall@50 | Recall@100 |
| :--- | :---: | :---: | :---: |
| 推荐系统 | 0.10 | 0.25 | 0.40 |
| 短视频 | 0.30 | 0.55 | 0.70 |
| 电商 | 0.15 | 0.35 | 0.50 |

### 2.3 NDCG@K

#### 2.3.1 定义

Normalized Discounted Cumulative Gain:考虑位置折扣的排序质量:

$$
\text{NDCG@K} = \frac{\text{DCG@K}}{\text{IDCG@K}}
$$

其中:

$$
\text{DCG@K} = \sum_{i=1}^K \frac{2^{rel_i} - 1}{\log_2(i + 1)}
$$

#### 2.3.2 物理意义

- **位置折扣**:排名靠前的物品权重更高
- **归一化**:与 IDCG 比较(完美排序)

#### 2.3.3 工业典型值

| 任务 | NDCG@10 | NDCG@20 | NDCG@50 |
| :--- | :---: | :---: | :---: |
| 推荐系统 | 0.20 | 0.28 | 0.40 |
| 短视频 | 0.40 | 0.55 | 0.70 |
| 电商 | 0.25 | 0.35 | 0.50 |

#### 2.3.4 NDCG vs Recall

| 维度 | Recall@K | NDCG@K |
| :--- | :--- | :--- |
| 位置敏感 | ❌ | ✅ |
| 分数敏感 | ❌ | ✅ |
| 适用 | 召回 | 排序 |

### 2.4 MRR

#### 2.4.1 定义

Mean Reciprocal Rank:第一个正样本的倒数排名:

$$
\text{MRR} = \frac{1}{|Q|} \sum_{q \in Q} \frac{1}{\text{rank}(q)}
$$

#### 2.4.2 物理意义

> "第一个正确答案出现的速度"。反映"模型能否快速找到正确答案"。

#### 2.4.3 适用场景

- 搜索(query → doc)
- QA(问题 → 答案)
- 推荐(用户 → 第一相关物品)

#### 2.4.4 工业典型值

| 任务 | MRR |
| :--- | :---: |
| 搜索 | 0.30 – 0.60 |
| 推荐 | 0.10 – 0.30 |
| QA | 0.40 – 0.80 |

### 2.5 Hit@K

#### 2.5.1 定义

是否在前 K 个推荐中至少命中一个正样本:

$$
\text{Hit@K} = \mathbb{1}[\text{TopK} \cap \text{Positives} \neq \emptyset]
$$

#### 2.5.2 与 Recall@K 的区别

| 维度 | Hit@K | Recall@K |
| :--- | :--- | :--- |
| 关注 | 是否命中 | 命中比例 |
| 多正样本 | 只要 1 个 | 必须全部 |
| 计算 | 简单 | 中等 |
| 适用 | 单目标 | 多目标 |

### 2.6 Logloss

#### 2.6.1 定义

二分类交叉熵:

$$
\text{Logloss} = -\frac{1}{N} \sum_i [y_i \log p_i + (1 - y_i) \log(1 - p_i)]
$$

#### 2.6.2 在 GenRec 中的应用

- **CTR 预测**:click/no-click
- **CVR 预测**:conversion/no-conversion
- **Engagement**:watch/no-watch

#### 2.6.3 优缺点

| 优点 | 缺点 |
| :--- | :--- |
| 数学性质好 | 受极端概率影响 |
| 校准好 | 不直接反映排序 |
| 工业标准 | 难解释 |

### 2.7 NDCG@10

NDCG@10 是工业**最常用的单一指标**之一:

#### 2.7.1 为什么是 10?

- 用户视野有限(看 10 个)
- 推荐卡片大小通常 5-10
- 工程目标:确保前 10 个推荐质量

#### 2.7.2 工业典型值

| 业务 | NDCG@10 |
| :--- | :---: |
| 电商(转化导向) | 0.20 – 0.30 |
| 短视频(沉浸度) | 0.40 – 0.55 |
| 信息流(CTR 导向) | 0.30 – 0.45 |
| 本地生活 | 0.25 – 0.40 |

## 3. 离线 vs 在线对比

| 维度 | LLM | GenRec |
| :--- | :--- | :--- |
| 离线评估 | 学术基准 + 内部测试集 | Recall/NDCG + 业务 logloss |
| 在线评估 | 用户满意度调查 + 留存 | CTR/CVR/GMV |
| 周期 | 周 ~ 月 | 天 ~ 周 |
| 主导指标 | MT-Bench / MMLU | CTR / RPM |

### 3.1 LLM 离线 vs 在线

#### 3.1.1 离线评估

- **学术基准**:MMLU / GSM8K / HumanEval
- **内部测试集**:红队对抗 + 业务测试集
- **安全评估**:有害内容检测

#### 3.1.2 在线评估

- **用户留存**:D1/D7/D30 活跃
- **对话长度**:平均对话轮数
- **满意度**:👍/👎 反馈
- **任务完成率**:用户是否完成目标

#### 3.1.3 周期

- LLM 模型一次训练:几周到几月
- 上线评估:1-2 周(收集足够反馈)
- 决策:2-4 周

### 3.2 GenRec 离线 vs 在线

#### 3.2.1 离线评估

- **排序指标**:Recall / NDCG / Hit
- **业务 logloss**:CTR / CVR logloss
- **校准**:ECE (Expected Calibration Error)

#### 3.2.2 在线评估

- **A/B 测试**:5-10% 流量
- **核心指标**:CTR / CVR / GMV / RPM
- **护栏指标**:多样性 / 长尾覆盖 / 延迟

#### 3.2.3 周期

- GenRec 模型训练:几天到 1 周
- A/B 测试:1-7 天
- 决策:1-2 周

### 3.3 对比

| 维度 | LLM | GenRec |
| :--- | :--- | :--- |

### 7.2 GenRec 多样性 / 公平性

#### 7.2.1 多样性

```text
场景: 推荐给用户 10 个物品
问题: 都是同一类(全是同款手机壳)

解决:
  - DPP(行列式点过程)
  - MMR(Maximum Marginal Relevance)
  - 多样性正则
```

```python
def mmr_score(item_scores, item_features, lambda_=0.5, k=10):
    selected = []
    candidates = list(range(len(item_scores)))
    for _ in range(k):
        if not candidates:
            break
        if not selected:
            best = max(candidates, key=lambda i: item_scores[i])
        else:
            best = max(candidates, key=lambda i:
                lambda_ * item_scores[i] -
                (1 - lambda_) * max(
                    cosine_sim(item_features[i], item_features[s])
                    for s in selected
                )
            )
        selected.append(best)
        candidates.remove(best)
    return selected
```

#### 7.2.2 流行度偏差

```text
头部物品被反复推荐
长尾物品几乎不曝光

评估:
  - Gini 系数
  - 长尾物品曝光占比
  - 覆盖率 (Coverage)

缓解:
  - Inverse Propensity Scoring
  - 长尾物品 boost
  - Exploration (UCB, Thompson)
```

#### 7.2.3 曝光公平性

```text
场景: 不同性别 / 年龄 / 地域的用户
        得到的推荐质量差距大

评估:
  - 各群体 NDCG 方差
  - 曝光分布

缓解:
  - 多目标加权
  - Fairness constraint
```

## 11. 深度专题

### 11.1 评估-训练不对齐的根源

#### 11.1.1 LLM 侧

```text
训练目标: 最小化 NTP loss = 学习 token 概率
评估目标: 回答 helpful / honest / harmless

不对齐:
  - NTP 训练好的模型可能"自信地胡说"
  - 概率高的 token 不等于"正确的 token"
  - 长文本生成需要 reasoning

解决:
  - RLHF / DPO / GRPO 直接对齐评估
```

#### 11.1.2 GenRec 侧

```text
训练目标: 最小化 NIP loss = 学习下一物品
评估目标: CTR / CVR / GMV

不对齐:
  - NIP 准的模型可能推荐"老物品"(训练集里多)
  - 离线 NDCG 高但线上 CTR 低(位置偏置)
  - 多任务 loss 都低但业务指标降

解决:
  - 多任务加权
  - RL(GRPO / GBPO)对齐业务
  - 在线 A/B 持续校准
```

### 11.2 评估指标的"代理问题"

#### 11.2.1 LLM 的代理指标

| 真实目标 | 代理指标 | 问题 |
| :--- | :--- | :--- |
| 用户满意 | MT-Bench | 评估员偏差 |
| 有用 | MMLU | 知识 ≠ 有用 |
| 安全 | TruthfulQA | 测试集 vs 真实使用 |
| 推理 | GSM8K | 数学 ≠ 真实推理 |

#### 11.2.2 GenRec 的代理指标

| 真实目标 | 代理指标 | 问题 |
| :--- | :--- | :--- |
| 用户满意 | CTR | 位置偏置 |
| 转化 | CVR | selection bias |
| 商业 | GMV | 短期 vs 长期 |
| 留存 | D7 留存 | 数据噪声大 |

### 11.3 离线评估的可复现性

#### 11.3.1 LLM 的可复现性问题

```text
问题:
  - 同一模型, 不同时间 evaluate 可能有 1-2 分波动
  - 数据采样顺序敏感
  - 评测 prompt 微小变化影响大

解决:
  - 固定 prompt
  - 多次取平均
  - 标准评估框架
```

#### 11.3.2 GenRec 的可复现性问题

```text

  - 同一份日志, 不同 sample 顺序结果不同
  - 离线 Recall@K 波动 1-3%
  - 多任务权重微调影响大

  - 固定 random seed
  - 多次取平均
  - 用户级 shuffle
```

### 11.4 在线 vs 离线指标的相关性

#### 11.4.1 LLM 相关性

| 离线 | 在线 | 相关性 |

### 11.5 多指标综合评估

#### 11.5.1 LLM 综合评分

### 12.1 Perplexity 的多面性

#### 12.1.1 PPL 的 5 个常用变种

| 变种 | 公式 | 特点 |
| :--- | :--- | :--- |
| Word-level PPL | $\exp(-\frac{1}{N_w} \sum \log p)$ | 按词统计 |

### 12.9 GAUC 的数学细节

#### 12.9.1 公式推导

$$
\text{GAUC} = \frac{\sum_{u \in U} w_u \cdot \text{AUC}_u}{\sum_{u \in U} w_u}
$$

其中:

$$
\text{AUC}_u = \frac{\sum_{i \in \text{pos}_u} \sum_{j \in \text{neg}_u} \mathbb{1}[\hat{s}_i > \hat{s}_j]}{|\text{pos}_u| \cdot |\text{neg}_u|}
$$

#### 12.9.2 权重的选择

| 权重 | 含义 |
| :--- | :--- |
| 曝光量 | 用户活跃度加权 |
| 行为数 | 反馈密度加权 |
| 价值 | LTGM 加权 |

#### 12.9.3 GAUC 的方差问题

```text
用户少: AUC 估计不准
权重小: 不影响整体
权重大: 单用户主导
```

> **实践**:剔除"行为过少"的用户(< 5 次曝光)。

### 12.10 NDCG 的位置折扣

#### 12.10.1 不同折扣函数

| 函数 | 公式 | 特点 |
| :--- | :--- | :--- |
| Log | $\frac{1}{\log_2(i+1)}$ | 经典 |
| Reciprocal | $\frac{1}{i}$ | 简单 |
| Exponential | $2^{-i}$ | 强衰减 |
| Linear | $\frac{N-i}{N}$ | 平滑 |

#### 12.10.2 工业默认值

```text
NDCG = $\sum_{i=1}^K \frac{2^{rel_i} - 1}{\log_2(i+1)}$
       ↑
       rel ∈ {0, 1, 2, 3, 4, 5}  # 多级相关性
```

#### 12.10.3 NDCG 的近似

```python

```

### 12.11 MRR 的多正样本扩展

#### 12.11.1 单正样本 MRR

$$
\text{MRR} = \frac{1}{|Q|} \sum_q \frac{1}{\text{rank}(q)}
$$

#### 12.11.2 多正样本 MRR

```text
选项 1: 取第一个正样本的位置
选项 2: 取所有正样本位置的均值倒数
选项 3: 加权倒数(相关性权重)
```

### 12.12 Hit@K 与 Recall@K 的差异

#### 12.12.1 公式对比

```text
Hit@K: 是否至少命中一个 (0/1)
Recall@K: 命中比例 (0-1)

例: K=10, 真实正样本 = {3, 50}
  - Hit@10 = 1   (因为 3 在前 10)
  - Recall@10 = 0.5 (只命中一半)
```

#### 12.12.2 工业选择

| 场景 | 选择 |
| :--- | :--- |
| 召回通道(粗) | Hit@K |
| 精排 | Recall@K |
| 单目标 | Hit@K |
| 多目标 | Recall@K |

### 12.13 Logloss 的多任务版本

#### 12.13.1 多任务总 Logloss

$$
\mathcal{L}_{\text{total}} = \sum_k w_k \cdot \text{Logloss}_k
$$

#### 12.13.2 Logloss 与 AUC 的关系

```text
Logloss ↓ + AUC ↑ → 完美
Logloss ↑ + AUC ↑ → 概率校准差
Logloss ↓ + AUC ↓ → 奇怪(罕见)
```

> **核心**:Logloss 关注概率校准,AUC 关注排序。

### A.5 评估指标的计算伪代码

```python
def evaluate_genrec(predictions, labels, k=10):
    """统一的 GenRec 离线评估"""
    metrics = {}
    # Recall@K
    topk = predictions.topk(k, dim=-1).indices
    hits = labels.gather(1, topk).sum(dim=-1)
    total = labels.sum(dim=-1)
    metrics[f'recall@{k}'] = (hits / total).mean().item()
    # NDCG@K
    ideal_dcg = (labels.sum(dim=-1)).log2().clamp(min=1)
    discount = 1.0 / torch.log2(torch.arange(2, k + 2).float())
    rel = labels.gather(1, topk)
    dcg = (rel * discount).sum(dim=-1)
    metrics[f'ndcg@{k}'] = (dcg / ideal_dcg).mean().item()
    # Hit@K
    metrics[f'hit@{k}'] = (hits > 0).float().mean().item()
    # AUC
    pos_scores = predictions[labels == 1]
    neg_scores = predictions[labels == 0]
    metrics['auc'] = (pos_scores.unsqueeze(1) > neg_scores.unsqueeze(0)).float().mean().item()
    return metrics
```

```python
def evaluate_llm(model, eval_data):
    """统一的 LLM 离线评估"""
    metrics = {}
    total_loss = 0
    total_tokens = 0
    for batch in eval_data:
        logits = model(batch.input_ids)
        shift_logits = logits[:, :-1, :]
        shift_labels = batch.input_ids[:, 1:]
        loss = F.cross_entropy(
            shift_logits.reshape(-1, shift_logits.size(-1)),
            shift_labels.reshape(-1),
            reduction='sum'
        )
        total_loss += loss.item()
        total_tokens += shift_labels.numel()
    metrics['ppl'] = math.exp(total_loss / total_tokens)
    return metrics
```

> [!summary] **关键 takeaway**:
> 1. LLM 评估以"理解 + 推理 + 对齐"为主(MMLU/GSM8K/MT-Bench);GenRec 评估以"排序 + 商业"为主(Recall/NDCG/CTR/CVR)。
> 2. 离线-在线 gap:LLM gap 较大,GenRec gap 较小。
> 3. 人类评估:LLM 显式(GPT-4 Judge);GenRec 隐式(用户行为)。
> 4. 鲁棒性挑战:LLM 是对抗 / 越狱;GenRec 是冷启动 / 长尾。
> 5. A/B 周期:LLM 数周;GenRec 数天。
