## 二、核心补充内容

### 2.1 Tokenizer 范式演进的全景图（fun-rec ch5.5）

fun-rec 把推荐 Tokenizer 的演进整理为三代，可作为本地 SID 12 章的"地图页"：

| 代际 | 代表 | 核心机制 | 问题 |
| :--- | :--- | :--- | :--- |
| 一代：规则/哈希 ID | 原始 ID、哈希分桶 | 无语义，纯标识 | 零泛化、冷启动死穴 |
| 二代：量化语义 ID | RQ-VAE、RQ-KMeans | 语义向量 → 残差量化 → 层级码 | tokenizer 与下游模型**分离训练**，语义码与推荐目标不对齐 |
| 三代：端到端离散化 | 与生成式推荐联合训练的 tokenizer | 量化目标与推荐 loss 联合优化 | 训练复杂度高、码表稳定性难控 |

**本地定位**：第03章整章属于二代（RQ-VAE 线，含 RQ-KMeans 工业简化版）；第06章 HY-Token 混合 Tokenization 已经在向三代过渡；fun-rec 的增量是把"为什么要走向端到端"的动机链讲透——**分离训练的 tokenizer 优化的语义空间与下游推荐目标（CTR/转化）之间存在系统性错位**。

### 2.2 端到端离散化：联合训练的两个关键设计

fun-rec 给出的端到端路线要点（本地第03章可对照补课）：

1. **梯度通路**：量化是不可导的 argmin——端到端方案用直通估计器（STE）或 Gumbel-Softmax 让推荐 loss 的梯度回传到语义编码器；此时码表学习的目标从"重建语义向量"变为"对下游任务有用"，两个目标用加权联合：`L = L_task + λ·L_quantize`；
2. **码表刷新与漂移控制**：联合训练中码表会随编码器漂移，工业做法是 EMA 更新 + 重新指派（re-assignment）+ 周期性码表重组，防止"语义漂移导致线上 embedding 缓存失效"——这正是本地第07章在线 SID 生成与服务关心的问题，fun-rec 给出了原因侧的解释。

### 2.3 工业级方案对照表（fun-rec ch5.5 工业级方案 + 本地第09章）

| 方案 | 来源 | Tokenizer 选择 | 与本地对照 |
| :--- | :--- | :--- | :--- |
| TIGER | Google | RQ-VAE（语义向量 → 三层残差码） | 第03章主线 |
| PLUM | Google | 物品索引学习 + 语义对齐（LLM 词表对齐） | 第09章 deep-dives/25-PLUM；GR 第08章补充文件 |
| HSTU 系 | Meta | 行为序列 token 化（含特征统一 token 流） | 第08章-01 |
| OneRec 系 | 快手 | 端到端离散化 + 多模态语义源 | GR 第08章补充文件 |
| HY-Token / 混合 | 工业实践 | 语义码 + ID 码混合残差 | 本地第06章 |

**读表要点**：方案差异的本质是"**语义源**"（内容embedding/行为共现/多模态）与"**对齐目标**"（重建/检索/任务loss）两个自由度的组合；评估新方案时先定位它在这个二维格子的位置。

### 2.4 核心挑战清单（fun-rec ch5.5，与本地第03章-05 对齐）

fun-rec 把挑战整理为可核对清单，补充本地"局限与改进"一章：

1. **码表崩溃**：部分码位永不命中（常用解法：码位利用率正则、死码重启）；
2. **长尾物品欠拟合**：低频物品的语义向量质量差 → 码无区分度（解法：内容模态补强，衔接本地第04章多模态与行为增强 SID）；
3. **层级码的误差累积**：上层码错则下层全错（解法：beam search 多码路径，衔接第12章生成式检索与约束解码）；
4. **训练-服务一致性**：tokenizer 更新导致全量 SID 重刷（解法：版本化码表 + 增量迁移，衔接第07章在线服务）；
5. **多语言/多区域共享码表**：语义空间对不同语言密度不均（解法：分域码表 + 对齐层）。

## 三、可直接动手的实践

1. 在本地第03章附录的 RQ-VAE 实现上加 STE，把一个下游 CTR 小任务的 loss 接进联合训练，观察码位利用率与 AUC 的变化（对照 2.2）；
2. 统计自己码表的码位利用率直方图，定位崩溃程度，实施死码重启，前后对比；
3. 按 2.3 的二维格子（语义源 × 对齐目标）给自己项目所用方案定位一次，写下局限与下一步。
