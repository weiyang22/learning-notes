## 1.1 重建指标 (Reconstruction)

### 1.1.1 最简实现

```python
def reconstruction_mse(model, dataloader):
    """重建 MSE"""
    model.eval()
    total = 0
    count = 0
    with torch.no_grad():
        for batch in dataloader:
            x = batch[0]
            x_recon, _, _, _ = model(x)
            total += F.mse_loss(x_recon, x, reduction='sum').item()
            count += x.numel()
    return total / count

mse = reconstruction_mse(model, test_loader)
print(f"重建 MSE: {mse:.4f}")  # 通常 < 0.05
```

### 1.1.2 数学定义

设原始 embedding 为 $\mathbf{x} \in \mathbb{R}^{d}$, 重建后为 $\hat{\mathbf{x}} \in \mathbb{R}^{d}$。在测试集 $\mathcal{D}_{\text{test}}$ 上 MSE 定义为:

$$
\text{MSE} = \frac{1}{|\mathcal{D}_{\text{test}}| \cdot d} \sum_{i=1}^{|\mathcal{D}_{\text{test}}|} \left\| \mathbf{x}_i - \hat{\mathbf{x}}_i \right\|_2^2 = \frac{1}{|\mathcal{D}_{\text{test}}| \cdot d} \sum_{i=1}^{|\mathcal{D}_{\text{test}}|} \sum_{j=1}^{d} \left( x_{i,j} - \hat{x}_{i,j} \right)^2
$$

**量纲解读**: MSE 的量纲与 embedding 量纲平方一致。若 embedding 经 L2 归一化(模长=1)再计算,MSE 的取值范围被压缩到 $[0, 4]$, 此时 0.05 已属"还不错", 但若原始 embedding 模长 = 10, MSE = 0.05 则代表**相对误差仅 0.005**——量级判断不能脱离 embedding 的预处理。

### 1.1.3 RQ-VAE 的 MSE 计算特殊性

RQ-VAE 的输出是**多层级残差累加**, 与单层 VQ-VAE 的输出结构不同:

```python
def rqvae_recon_mse(model, dataloader, num_layers=4):
    """RQ-VAE 重建 MSE - 注意残差累加结构"""
    model.eval()
    se_sum = 0.0
    n_elem = 0
    with torch.no_grad():
        for batch in dataloader:
            x = batch[0].cuda()
            # RQ-VAE forward: 残差逐层量化
            recon, sids, quantize_loss, perplexity = model(x)
            # recon = sum(e_i for i in 1..L)
            # 验证残差累加结构
            assert recon.shape == x.shape, f"shape mismatch {recon.shape} vs {x.shape}"
            se = ((x - recon) ** 2).sum().item()
            se_sum += se
            n_elem += x.numel()
    return se_sum / n_elem
```

**关键点**: RQ-VAE 的 `recon` 是 $L$ 个码字 embedding 之和, 不是最后一层码字的输出。这意味着"层数 $L$ 越大 → 单层残差越小 → 单层 MSE 自然越低", 但**总 MSE 反而随 $L$ 下降**——这是 RQ-VAE 残差量化的核心动机。

### 1.1.4 RMSE / MAE / PSNR 的扩展

```python
def reconstruction_metrics(x, x_recon):
    """完整重建指标族"""
    mse = ((x - x_recon) ** 2).mean()
    rmse = mse.sqrt()
    mae = (x - x_recon).abs().mean()

    # PSNR: 峰值信噪比(常用于图像, embedding 也可参考)
    max_val = x.abs().max()
    psnr = 20 * torch.log10(max_val / rmse)

    # 相对误差
    rel_err = ((x - x_recon).norm(dim=-1) /
               (x.norm(dim=-1) + 1e-8)).mean()

    return {
        'mse': mse.item(),
        'rmse': rmse.item(),
        'mae': mae.item(),
        'psnr_db': psnr.item(),
        'relative_error': rel_err.item(),
    }
```

| 指标 | 量纲 | 优势 | 陷阱 |
| :--- | :--- | :--- | :--- |
| MSE | $x^2$ | 凸可微, 与 L2 损失对齐 | 对异常值敏感(平方放大) |
| RMSE | $x$ | 与原 embedding 同量纲 | 同上 |
| MAE | $x$ | 对异常值鲁棒 | 训练时梯度常数, 不便优化 |
| PSNR | dB | 跨量纲可比 | 假设峰值已知, 推荐场景意义有限 |
| Relative Err | 无量纲 | 归一化, 可跨数据集比 | 分母为零时崩溃 |

### 1.1.5 按 embedding 维度分量的 MSE

推荐 embedding 的不同维度往往代表不同语义(在 transformer-based encoder 中尤其明显)。**逐维 MSE** 可以定位量化误差集中的方向:

```python
def per_dim_mse(x, x_recon):
    """逐维 MSE"""
    per_dim = ((x - x_recon) ** 2).mean(dim=0)  # [d]
    return per_dim

# 可视化: 找出"MSE 高的维度"
import matplotlib.pyplot as plt
per_dim = per_dim_mse(x_test, x_recon_test)
plt.figure(figsize=(12, 4))
plt.bar(range(per_dim.shape[0]), per_dim.cpu().numpy())
plt.xlabel('Embedding Dim')
plt.ylabel('MSE')
plt.title('Per-dim Reconstruction MSE')
plt.savefig('per_dim_mse.png', dpi=120)
```

工程意义: 若某几维 MSE 显著高于其他维, **这些维度可能承载了关键信息**——可以针对性增强(更细码本 / 多模态辅助), 或反之确认这些维是否真的对下游有用(冗余维度)。

### 1.1.6 MSE 的分布视角

均值达标 ≠ 全部达标。**重建 MSE 的长尾才是真问题**:

```python
def per_item_mse(x, x_recon):
    """每个物品的重建 MSE"""
    per_item = ((x - x_recon) ** 2).mean(dim=-1)  # [N]
    return per_item

# 分布视角
p = per_item_mse(x_test, x_recon_test).cpu().numpy()
p10, p50, p90, p99 = np.percentile(p, [10, 50, 90, 99])
print(f"P10={p10:.4f}  P50={p50:.4f}  P90={p90:.4f}  P99={p99:.4f}")
print(f"均值={p.mean():.4f}  最大={p.max():.4f}")
# 如果 P99 / 均值 > 10 → 严重长尾, 必须排查
```

**经验法则**: 若 P99 / 中位数 > 5×, 必有 1% 物品重建失败——通常是冷门/异常 item, 单独看它们的 SID, 往往发现是边缘码字或被错配到稀有码。

## 1.2 语义指标 (Cosine Similarity)

### 1.2.1 最简实现

```python
def semantic_similarity(model, dataloader):
    """原始与重建的余弦相似度"""
    model.eval()
    sims = []
    with torch.no_grad():
        for batch in dataloader:
            x = batch[0]
            x_recon, _, _, _ = model(x)
            cos = F.cosine_similarity(x, x_recon, dim=-1)
            sims.extend(cos.cpu().tolist())
    return np.mean(sims), np.std(sims)

mean, std = semantic_similarity(model, test_loader)
print(f"余弦相似度: {mean:.4f} ± {std:.4f}")  # 应该 > 0.95
```

### 1.2.2 数学定义

余弦相似度衡量**方向一致性**, 忽略模长:

$$
\cos(\mathbf{x}, \hat{\mathbf{x}}) = \frac{\mathbf{x} \cdot \hat{\mathbf{x}}}{\|\mathbf{x}\|_2 \|\hat{\mathbf{x}}\|_2} = \frac{\sum_{j=1}^{d} x_j \hat{x}_j}{\sqrt{\sum_{j=1}^{d} x_j^2} \sqrt{\sum_{j=1}^{d} \hat{x}_j^2}}
$$

取值范围 $[-1, 1]$。推荐 embedding 通常接近正空间(各维度非负或中心化后正负皆有), 实际 cosine 多落在 $[0.5, 1.0]$。

### 1.2.3 向量量化对 cosine 的"天花板"

VQ 类方法存在一个**不可消除的量化误差下界**: 即使完美选择最近码字, 重建 $\hat{\mathbf{x}}$ 也只是码字集合 $\mathcal{C} = \{e_1, \ldots, e_K\}$ 中的一个。因此:

$$
\max_{\hat{\mathbf{x}} \in \mathcal{C}} \cos(\mathbf{x}, \hat{\mathbf{x}}) \leq \max_{e \in \mathcal{C}} \cos(\mathbf{x}, e) = \cos(\mathbf{x}, e^*)
$$

其中 $e^* = \arg\max_{e \in \mathcal{C}} \cos(\mathbf{x}, e)$ 是 $\mathbf{x}$ 的最近码字。这个上限由码本大小 $K$ 决定:

- **K 越大** → 上限越接近 1
- **K 越小** → 上限显著低于 1, 重建 cosine 有天然天花板

```python
def cosine_upper_bound(emb, codebook):
    """理论上限: 每个 item 选最近的码字能达到的最大 cosine"""
    # emb: [N, d], codebook: [K, d]
    # 归一化
    emb_n = F.normalize(emb, dim=-1)
    cb_n = F.normalize(codebook, dim=-1)
    # [N, K]
    sim_matrix = emb_n @ cb_n.T
    # 每个 item 的最大 cosine
    max_sim = sim_matrix.max(dim=-1).values
    return max_sim.mean().item(), max_sim.std().item()
```

**用法**: 训练前先计算 `cosine_upper_bound`, 如果理论上限已经 < 0.95, 那训得再好 cosine 也上不去——必须先扩码本或换编码器。

### 1.2.4 RQ-VAE 的 cosine 计算

RQ-VAE 的输出是多层码字之和, **整体 cosine** 比单层更复杂:

```python
def rqvae_cosine(x, x_recon, dim=-1):
    """RQ-VAE 重建 cosine"""
    cos = F.cosine_similarity(x, x_recon, dim=dim)
    return cos.mean().item(), cos.std().item()

# 注意: 不能简单地把每层 cosine 求平均
# 因为 recon = sum(e_l), 各层 e_l 的模长/方向都对总 cosine 有贡献
```

### 1.2.5 与 MSE 的对比

```text
MSE  →  ||x - x_hat||²  →  距离(几何)
Cosine → 方向一致 → 角度(语义)

推荐场景常用 cosine: 因为 ANN 检索本质是内积/cosine, 方向比模长重要
图像/语音场景常用 MSE/PSNR: 因为像素值差异对应视觉/听觉差异
```

**反例**: 若 embedding 经 L2 归一化, MSE 与 cosine 高度相关($\|\mathbf{x} - \hat{\mathbf{x}}\|^2 = 2 - 2\cos(\mathbf{x}, \hat{\mathbf{x}})$), 二选一即可; 若未归一化, **必须同时看**。

### 1.2.6 Cosine 的分布监控

```python
def cosine_distribution(x, x_recon):
    cos = F.cosine_similarity(x, x_recon, dim=-1).cpu().numpy()
    p10, p50, p90, p99 = np.percentile(cos, [10, 50, 90, 99])
    return {
        'mean': cos.mean(),
        'std': cos.std(),
        'p10': p10, 'p50': p50, 'p90': p90, 'p99': p99,
        'min': cos.min(), 'max': cos.max(),
    }
# 期望: P10 > 0.85, P50 > 0.95, P99 > 0.98
```

## 1.3 工业阈值

| 指标 | 推荐 | 警告 | 失败 |
| :--- | :--- | :--- | :--- |
| MSE | < 0.05 | 0.05-0.10 | > 0.10 |
| Cosine | > 0.95 | 0.90-0.95 | < 0.90 |

### 1.3.1 阈值的设定依据

阈值不是"魔法数字", 来自三个维度:

1. **下游容忍度**: 经验上 cosine 跌 0.05 → 下游 Recall@K 跌 1-3%。但**相关性不严格**——可能跌 0.03 也无显著影响, 也可能跌 0.02 已崩塌, 看场景。
2. **数据集基准**: 用 v1 baseline 的指标作为 v2 的"必须持平"阈值。**最严的阈值是"持平或更好"**。
3. **场景差异**: 内容推荐(语义主导) vs 电商推荐(协同主导)对重建指标要求差异极大。协同主导场景 cosine 0.92 已够, 内容主导场景要求 0.97+。

### 1.3.2 不同 embedding 来源的阈值差异

| Embedding 来源 | 推荐 MSE | 推荐 Cosine | 原因 |
| :--- | :--- | :--- | :--- |
| Sentence-BERT (文本) | < 0.03 | > 0.97 | 文本空间结构清晰, 容易量化 |
| Two-tower DNN (推荐) | < 0.05 | > 0.95 | 工业推荐 embedding 噪声大 |
| Raw item feature (one-hot) | N/A | N/A | 应先转 dense 再评估 |
| 多模态融合(CLIP) | < 0.04 | > 0.96 | 不同模态融合, 维度差异大 |
| LLM hidden state | < 0.06 | > 0.94 | 高维稀疏, 量化难度大 |

### 1.3.3 阈值的"硬约束" vs "软约束"

```python
class SIDMetricChecker:
    """阈值检查器: 硬约束 + 软约束"""

    # 硬约束: 触发即告警/熔断
    HARD_FAIL = {
        'mse': 0.10,
        'cosine': 0.90,
    }

    # 软约束: 提示但不阻塞
    SOFT_WARN = {
        'mse': 0.05,
        'cosine': 0.95,
    }

    def check(self, metrics: dict):
        alerts = []
        warnings = []
        for k, v in metrics.items():
            if k in self.HARD_FAIL:
                if (k == 'mse' and v > self.HARD_FAIL[k]) or \
                   (k == 'cosine' and v < self.HARD_FAIL[k]):
                    alerts.append(f"{k}={v:.4f} 超过硬约束")
            if k in self.SOFT_WARN:
                if (k == 'mse' and v > self.SOFT_WARN[k]) or \
                   (k == 'cosine' and v < self.SOFT_WARN[k]):
                    warnings.append(f"{k}={v:.4f} 进入软告警区")
        return alerts, warnings
```

## 1.4 重建好 ≠ SID 好(评估的陷阱)

重建指标只衡量"SID 能否还原 embedding",但这**不等于**下游推荐效果好。三层评估缺一不可:

| 层级 | 指标 | 回答 |
| :--- | :--- | :--- |
| **重建层**(本节) | MSE / Cosine | SID 保住了多少信息? |
| **码本层** | 碰撞率/覆盖率/熵(见 [08-02](第08章-02-碰撞率与覆盖率.md)、[08-04](第08章-04-码本利用率与信息损失.md)) | 码本用得好不好? |
| **下游层** | AUC / Recall(见 [08-03](第08章-03-下游任务AUC与Recall.md)) | 真正的业务效果? |

> 经典陷阱:重建 MSE 很低但下游掉点——可能 SID 保住了"重建有用"的信息,却丢了"推荐有用"的信息(如协同信号)。**下游指标才是金标准**,重建/码本指标是先行诊断。

### 1.4.1 经典案例:重建好但下游差

**Case 1**: 文本主导的 SID 在 MSE 上很漂亮(文本 embedding 空间结构好量化), 但推荐效果差——因为推荐需要的是"协同信号"而非"内容相似度"。

**Case 2**: 多模态融合 SID 在 cosine 上达到 0.98, 但 A/B 测试 CTR 跌 5%——融合方式可能损坏了"用户行为相关"的子空间。

**Case 3**: 极端码本利用率(所有 item 都映射到 2-3 个码字)使"重建 MSE"看似合理(因为本来就稀疏), 但碰撞率 100%——根本区分不了 item。

### 1.4.2 重建指标与下游的相关性不是单调

```text
重建好 ──────→ 下游一定好?     NO
重建差 ──────→ 下游一定差?     大概率 YES
下游差 ──────→ 重建一定差?     NO
下游好 ──────→ 重建一定好?     大概率 YES
```

**结论**: 重建差是"必要不充分"的下游崩溃信号; 重建好不能保证下游好。**永远不要单独用重建指标定输赢**。

### 1.4.3 反向利用:用重建指标做"早期止损"

```python
# 训练流程中的快速 sanity check
def sanity_check_sid(model, val_loader):
    mse = reconstruction_mse(model, val_loader)
    cosine = semantic_similarity(model, val_loader)[0]

    # 如果重建都烂, 后面所有评估都是浪费
    if mse > 0.20 or cosine < 0.80:
        print("[SANITY FAIL] 重建指标不达标, 停止后续评估")
        return False
    return True
```

## 1.5 为什么 MSE 和 Cosine 都要看

- **MSE**:绝对重建误差,对**尺度/模长**敏感。
- **Cosine**:方向相似度,对**语义/夹角**敏感,忽略模长。

推荐里 embedding 常做内积/余弦检索,**方向比模长更重要** → Cosine 往往更贴近下游。但 MSE 能抓住 Cosine 忽略的模长退化。两者互补, 一起看。

### 1.5.1 数学上的关系

设 $\|\mathbf{x}\| = r_1$, $\|\hat{\mathbf{x}}\| = r_2$, $\theta = \angle(\mathbf{x}, \hat{\mathbf{x}})$:

$$
\text{MSE} = r_1^2 + r_2^2 - 2 r_1 r_2 \cos\theta
$$

- **固定 $\theta$, $r_1, r_2$ 变化** → MSE 变化, cosine 不变
- **固定 $r_1, r_2$, $\theta$ 变化** → MSE 和 cosine 都变

**推荐 embedding 模长的"折叠"问题**: 部分推荐场景下, 模型学习出的 embedding 模长差异巨大(头部 item 模长 = 100, 长尾 = 1)。若 SID 把所有 item 量化到模长 ≈ 10 的码字上, MSE 会因"模长对齐"而暴涨, cosine 却可能仍高——后者更贴近检索效果。

### 1.5.2 推荐场景的特殊性

| 检索方式 | 关心指标 | 原因 |
| :--- | :--- | :--- |
| Cosine 检索 | Cosine | 内积前通常归一化 |
| 内积检索 (IVF/HNSW) | 二者 | FAISS 内积索引对模长敏感 |
| 双塔召回 | Cosine | user/item 各自归一化后内积 |
| 排序模型 | 二者 | 排序分数通常为内积 |

**经验**: cosine 0.95+ 是底线, MSE < 0.05 是锦上添花; 但若 cosine 高但 MSE 也高(模长差异), 排序模型可能出问题——双塔召回通常没问题。

### 1.5.3 何时只看 cosine

- Embedding 已 L2 归一化(`F.normalize(emb, dim=-1)`)
- 检索方式是 cosine 相似度
- **MSE 与 cosine 数学上一一对应**: $\|\mathbf{x} - \hat{\mathbf{x}}\|^2 = 2(1 - \cos(\mathbf{x}, \hat{\mathbf{x}}))$

```python
# 验证: 若 x, x_recon 都 L2 归一化
x_n = F.normalize(x, dim=-1)
x_recon_n = F.normalize(x_recon, dim=-1)
mse_n = ((x_n - x_recon_n) ** 2).mean()  # = 2(1 - cos)
cos = (x_n * x_recon_n).sum(dim=-1).mean()
assert torch.allclose(mse_n, 2 * (1 - cos), atol=1e-5)
```

- 图像/语音/连续信号场景

## 1.6 监控:不只看均值,看分布

均值达标可能掩盖长尾崩溃:少数物品重建极差(冷门/异常物品)。监控要看:
- **分位数**:P10/P50/P90 的重建误差,而非只看均值。
- **分层**:热门 vs 长尾、各品类分别统计(长尾常是重灾区)。
- **随时间漂移**:新物料涌入会推高误差,设漂移告警。

### 1.6.1 分位数监控

```python
class ReconstructionDistributionMonitor:
    """重建分布监控器"""

    def __init__(self, alert_thresholds=None):
        self.alert_thresholds = alert_thresholds or {
            'p99_mse': 0.15,        # P99 MSE 阈值
            'p99_p50_ratio': 5.0,   # P99 / P50 比率阈值
            'p10_cosine': 0.85,     # P10 cosine 阈值
        }
        self.history = []

    def update(self, x, x_recon):
        mse_per_item = ((x - x_recon) ** 2).mean(dim=-1).cpu().numpy()
        cos_per_item = F.cosine_similarity(x, x_recon, dim=-1).cpu().numpy()

        stats = {
            'mse_mean': mse_per_item.mean(),
            'mse_p50': np.percentile(mse_per_item, 50),
            'mse_p90': np.percentile(mse_per_item, 90),
            'mse_p99': np.percentile(mse_per_item, 99),
            'cos_mean': cos_per_item.mean(),
            'cos_p10': np.percentile(cos_per_item, 10),
            'cos_p50': np.percentile(cos_per_item, 50),
            'cos_p90': np.percentile(cos_per_item, 90),
        }
        stats['p99_p50_ratio'] = stats['mse_p99'] / (stats['mse_p50'] + 1e-8)
        self.history.append(stats)
        return stats

    def check_alerts(self, stats):
        alerts = []
        if stats['mse_p99'] > self.alert_thresholds['p99_mse']:
            alerts.append(f"P99 MSE={stats['mse_p99']:.4f} 过高")
        if stats['p99_p50_ratio'] > self.alert_thresholds['p99_p50_ratio']:
            alerts.append(f"P99/P50={stats['p99_p50_ratio']:.1f} 长尾严重")
        if stats['cos_p10'] < self.alert_thresholds['p10_cosine']:
            alerts.append(f"P10 Cosine={stats['cos_p10']:.4f} 底部崩塌")
        return alerts
```

### 1.6.2 分层监控(热门 vs 长尾)

```python
def stratified_mse(x, x_recon, popularity):
    """按热度分层的 MSE"""
    # popularity: 每个 item 的曝光/点击数(归一化)
    n = len(x)

    # 三分位数分层
    p33 = np.percentile(popularity, 33)
    p67 = np.percentile(popularity, 67)

    head_mask = popularity >= p67
    body_mask = (popularity >= p33) & (popularity < p67)
    tail_mask = popularity < p33

    mse_per_item = ((x - x_recon) ** 2).mean(dim=-1).cpu().numpy()

    return {
        'head_mse': mse_per_item[head_mask].mean(),
        'body_mse': mse_per_item[body_mask].mean(),
        'tail_mse': mse_per_item[tail_mask].mean(),
        'tail_count': tail_mask.sum(),
    }
    # 通常 tail_mse >> body_mse >> head_mse (但应该是平缓增长)
```

```python
class TimeDriftMonitor:
    """时间漂移监控"""

    def __init__(self, window_days=7, alert_pct=10):
        self.window_days = window_days
        self.alert_pct = alert_pct  # 指标相对恶化百分比触发告警
        self.baseline = None
        self.recent = []

    def set_baseline(self, x, x_recon):
        """设置基线 (首次或重训后)"""
        self.baseline = reconstruction_mse(x, x_recon)

    def update_recent(self, x, x_recon):
        """更新近期数据 (滚动窗口)"""
        self.recent.append(reconstruction_mse(x, x_recon))
        if len(self.recent) > self.window_days:
            self.recent.pop(0)

    def check_drift(self):
        if not self.baseline or not self.recent:
            return []
        recent_mean = np.mean(self.recent)
        drift_pct = (recent_mean - self.baseline) / self.baseline * 100
        alerts = []
        if drift_pct > self.alert_pct:
            alerts.append(
                f"MSE 漂移 {drift_pct:.1f}% (baseline={self.baseline:.4f}, "
                f"recent={recent_mean:.4f})"
            )
        return alerts
```

### 1.7.2 Rank-based 指标:Top-K 重建

推荐场景的核心是"找到 top-K", 不是"重建零误差"。**Rank-aware 重建指标**比 MSE 更贴近下游:

```python
def rank_aware_reconstruction(x, x_recon, k=10):
    """Rank-aware: 原始 top-K vs 重建 top-K 的重叠度"""
    n = x.shape[0]
    overlaps = []

    # 每个 item x_i: 找它的 top-K 近邻 (基于原始 x)
    # 然后用 x_recon 重建, 再看 top-K 是否一致
    sim_orig = x @ x.T  # [N, N]
    sim_recon = x_recon @ x_recon.T

    # 排除自己
    mask = ~torch.eye(n, dtype=bool, device=x.device)
    sim_orig = sim_orig.masked_fill(~mask, -1e9)
    sim_recon = sim_recon.masked_fill(~mask, -1e9)

    topk_orig = sim_orig.topk(k, dim=-1).indices  # [N, K]
    topk_recon = sim_recon.topk(k, dim=-1).indices  # [N, K]

    # Overlap @ K
    for i in range(n):
        overlap = len(set(topk_orig[i].tolist()) &
                     set(topk_recon[i].tolist())) / k
        overlaps.append(overlap)

    return np.mean(overlaps)  # 期望 > 0.7
```

**意义**: 若原始 top-K 近邻 vs 重建 top-K 近邻重叠度高, 说明 SID 保留了"局部结构"——这正是 ANN 检索依赖的核心。若重叠度低, 即使 cosine 均值 0.97, 检索也崩。

### 1.7.3 Spearman 秩相关

```python
from scipy.stats import spearmanr

def spearman_per_item(x, x_recon):
    """每个 item 的逐维秩相关"""
    n = x.shape[0]
    corrs = []
    for i in range(n):
        rho, _ = spearmanr(x[i].cpu().numpy(), x_recon[i].cpu().numpy())
        corrs.append(rho)
    return np.mean(corrs), np.std(corrs)

# 注: Spearman 关注的是"维度排序", 不受线性变换影响
# 若 cosine 0.98 但 Spearman 0.6 → 重建保住了方向但打乱了"维度重要性"
```

### 1.7.4 Triplet Loss 风格指标

```python
def triplet_accuracy(x, x_recon, n_sample=1000):
    """三元组准确率: 重建 x_recon 与 x 的距离 < 与随机 x_j 的距离"""
    n = x.shape[0]
    idx = torch.randperm(n)[:n_sample]
    x_s = x[idx]
    x_r = x_recon[idx]

    # 随机负样本
    neg_idx = torch.randint(0, n, (n_sample,))
    x_neg = x[neg_idx]

    pos_dist = F.pairwise_distance(x_s, x_r)
    neg_dist = F.pairwise_distance(x_s, x_neg)

    return (pos_dist < neg_dist).float().mean().item()
    # 期望 > 0.95: 重建的"身份"被正确保留
```

### 1.7.5 邻居保持比(Neighborhood Preservation)

```python
def neighborhood_preservation(x, x_recon, k_values=(5, 10, 50)):
    """NPMI: 邻居保持率"""
    n = x.shape[0]

    # 原始空间 top-K
    sim_orig = x @ x.T
    sim_orig.fill_diagonal_(-1e9)

    # 重建空间 top-K
    sim_recon = x_recon @ x_recon.T
    sim_recon.fill_diagonal_(-1e9)

    results = {}
    for k in k_values:
        topk_orig = sim_orig.topk(k, dim=-1).indices.cpu().numpy()
        topk_recon = sim_recon.topk(k, dim=-1).indices.cpu().numpy()

        preservation = []
        for i in range(n):
            inter = len(set(topk_orig[i]) & set(topk_recon[i]))
            preservation.append(inter / k)
        results[f'np@{k}'] = np.mean(preservation)
    return results
    # 期望 NP@10 > 0.7 (70% 邻居保持)
```

```python
def mutual_info_proxy(x, x_recon, k=5):
    """互信息代理: 共享 k-近邻比例"""
    n = x.shape[0]
    sim_orig = (x @ x.T).fill_diagonal_(0)
    sim_recon = (x_recon @ x_recon.T).fill_diagonal_(0)

    topk_orig = sim_orig.topk(k, dim=-1).indices
    topk_recon = sim_recon.topk(k, dim=-1).indices

    inter = (topk_orig.unsqueeze(-1) == topk_recon.unsqueeze(-2)).any(-1)
    return inter.float().mean().item()

```

### 1.8.1 Sim-to-Recall 相关性

```python
def sim_recall_correlation(x_test, x_recon_test, behavior_data, k_list=(10, 50, 100)):
    """Sim 与 Recall 的相关性"""
    # x_test: 测试集 embedding, [M, d]
    # x_recon_test: 重建 embedding
    # behavior_data: (user, history_items, target_items)

    cos_per_item = F.cosine_similarity(x_test, x_recon_test, dim=-1)

    recalls_at_k = {k: [] for k in k_list}
    sims = []
    for user, hist, target in behavior_data:
        for t in target:
            if t < len(cos_per_item):
                recalls = [compute_recall_at_k(x_recon_test, user, hist, t, k)
                          for k in k_list]
                for k, r in zip(k_list, recalls):
                    recalls_at_k[k].append(r)
                sims.append(cos_per_item[t].item())

    sims = np.array(sims)
    for k in k_list:
        recalls = np.array(recalls_at_k[k])
        # Pearson 相关
        from scipy.stats import pearsonr
        if len(sims) > 5:
            r, p = pearsonr(sims, recalls)
            print(f"k={k}: Sim-Recall 相关性 r={r:.3f} (p={p:.4f})")
    # 期望 r > 0.5: Sim 越高, Recall 越高
```

### 1.8.2 Sim 阈值的下游标定

```python
def calibrate_sim_threshold(model, test_data, downstream_metric_fn):
    """用下游指标标定 Sim 阈值"""
    x_test = test_data['embeddings']
    x_recon_test = []
    with torch.no_grad():
        for batch in DataLoader(x_test, batch_size=256):
            x_recon, _, _, _ = model(batch.cuda())
            x_recon_test.append(x_recon.cpu())
    x_recon_test = torch.cat(x_recon_test)

    sims = F.cosine_similarity(x_test, x_recon_test, dim=-1).numpy()
    downstream = downstream_metric_fn(x_recon_test, test_data)

    # 按 sim 分桶, 算各桶的下游指标
    bins = [0.7, 0.8, 0.85, 0.9, 0.92, 0.95, 0.97, 0.99, 1.01]
    for i in range(len(bins)-1):
        lo, hi = bins[i], bins[i+1]
        mask = (sims >= lo) & (sims < hi)
        if mask.sum() > 0:
            print(f"sim ∈ [{lo:.2f}, {hi:.2f}): "
                  f"count={mask.sum()}, downstream={downstream[mask].mean():.4f}")
```

### 1.8.3 Sim 边际收益曲线

**Sim 不是越高越好, 要看边际收益**:

| Cosine 区间 | 下游 Recall 增量 | 训练成本增量 |
| :--- | :--- | :--- |
| 0.85 → 0.90 | +3-5% | 低(2× 训练步) |
| 0.90 → 0.95 | +1-2% | 中(2-3× 训练步) |
| 0.95 → 0.97 | +0.3-0.5% | 高(扩码本/换编码器) |
| 0.97 → 0.99 | +0.1-0.2% | 极高(ROI 不划算) |

工程上通常把目标定在 **cosine 0.95-0.97**, 而非 0.99。

### 1.10.3 灰度发布监控

```python
class GrayReleaseMonitor:
    """灰度发布监控 (5% → 25% → 50% → 100%)"""

    def __init__(self, baseline_metrics):
        self.baseline = baseline_metrics
        self.stages = ['5%', '25%', '50%', '100%']
        self.current_stage = '5%'

    def should_promote(self, current_metrics):
        """判断是否可以进入下一阶段"""
        for k in current_metrics:
            if k in self.baseline:
                # Cosine 不允许显著下跌
                if k.startswith('cos') and current_metrics[k] < self.baseline[k] - 0.02:
                    print(f"[BLOCK] cosine 下跌, 阻止下一阶段")
                    return False
                # MSE 不允许显著上涨
                if k.startswith('mse') and current_metrics[k] > self.baseline[k] + 0.02:
                    print(f"[BLOCK] MSE 上涨, 阻止下一阶段")
                    return False
        return True

    def should_rollback(self, current_metrics):
        """判断是否回滚"""
        for k in current_metrics:
            if k.startswith('cos') and current_metrics[k] < self.baseline[k] - 0.05:
                return True
            if k.startswith('mse') and current_metrics[k] > self.baseline[k] + 0.05:
                return True
        return False
```

## 1.11 常见陷阱与面试题

### 1.11.1 评估陷阱清单

1. **只看均值**: P99 已崩但均值 0.96 看着"还行"
2. **冷启动无评估**: 新 item 不在测试集, 评估永远漂亮
3. **数据泄露**: 测试集被训练集污染
4. **embedding 预处理不一致**: 训练时归一化, 测试时不归一化
5. **RQ-VAE 各层码本大小不同**: 假设每层都是 K=256, 但实际各层可能不同
6. **离线指标和 AB 测试脱钩**: 离线 +2%, AB -3%
7. **样本不均衡**: 测试集热门 item 多, 掩盖长尾问题

### 1.11.2 面试高频题

**Q1: 为什么 MSE 低不代表下游好?**

A: MSE 衡量"重建误差", 但下游推荐关心的是"item 间的相对关系"。若 SID 保留了"内容相似度"但丢了"协同信号", MSE 可能漂亮但下游崩塌。**层级评估**(重建/码本/下游)缺一不可。

**Q2: Cosine 和 MSE 何时一致?**

A: Embedding 经 L2 归一化时, $\|\mathbf{x} - \hat{\mathbf{x}}\|^2 = 2(1 - \cos(\mathbf{x}, \hat{\mathbf{x}}))$, 二者一一对应。此时选一个即可, 通常选 cosine (更直观)。

**Q3: RQ-VAE 的 MSE 怎么算?为什么不能直接用单层 VQ 的方法?**

A: RQ-VAE 输出是 $L$ 层码字 embedding 之和, 所以 MSE 计算的是"原始 vs 各层累加"。直接拿最后一层码字当 $\hat{\mathbf{x}}$ 是错的——会丢掉前几层信息。

**Q4: 如何判断 SID 是"重建好但下游差"?**

A: 对比**离线指标 vs AB 测试结果**。若离线 +3% 但 AB -2%, 拆解:
- 离线用的是不是历史 embedding? (可能过拟合)
- AB 流量分配是否均匀?
- 是不是冷启动 item 被低估?
- 是不是用户分层效果不同(老用户好, 新用户差)?

**Q5: 重建指标能不能预测下游?**

A: 部分可以。看相关分析:
- Cosine mean vs Recall@10: 通常 r > 0.5
- Cosine P10 vs Recall@10: r > 0.7 (更相关, 因为长尾决定召回质量)
- 邻居保持 vs Recall@10: r > 0.6

**Q6: 工业上 MSE > 0.05 还能上线吗?**

A: 取决于场景。若 cosine 仍 > 0.93 且 Recall 没退化, MSE 略高可接受(可能模长对齐未完美)。但若 MSE 高的同时 cosine 也低, 必须拒绝。

**Q7: 怎么排查"重建好但下游差"?**

A: 阶梯排查:
1. 下游任务是否过拟合 (在新数据上看)
2. SID 是否保留了 user-item 协同信号 (看 user embedding SID 的余弦)
3. 是否多模态融合时损坏了子空间
4. 是否码本分布不均导致长尾 item 检索失败

## 1.13 多任务重建指标

### 1.13.1 Multi-task SID 的评估

部分 SID (尤其 Google/TIGER 的工作) 同时优化多个目标:

$$
\mathcal{L}_{\text{total}} = \alpha \mathcal{L}_{\text{recon}} + \beta \mathcal{L}_{\text{predict}}
$$

其中:
- $\mathcal{L}_{\text{recon}}$: 重建损失 (MSE)
- $\mathcal{L}_{\text{predict}}$: 下游预测损失 (下一 item, 用户行为等)

```python
class MultiTaskSIDEvaluator:
    """多任务 SID 评估器"""

    def __init__(self, model, codebook):
        self.model = model
        self.codebook = codebook

    def evaluate_multitask(self, x, behavior_labels):
        self.model.eval()
        with torch.no_grad():
            x_recon, sids, task_loss = self.model(x, behavior_labels)

        # 重建指标
        recon_metrics = self.compute_recon(x, x_recon)

        # 任务指标
        task_acc = (task_loss.argmax(-1) == behavior_labels).float().mean().item()

        # 联合指标: 加权几何平均
        # Cosine 高 + 任务准 = 好 SID
        joint_score = (recon_metrics['cosine_mean'] ** 0.5) * (task_acc ** 0.5)

        return {
            **recon_metrics,
            'task_accuracy': task_acc,
            'joint_score': joint_score,
        }
```

### 1.13.2 Pareto 前沿分析

多任务 SID 不存在单一最优解, 用 Pareto 前沿描述:

```python
def pareto_front(metrics_list):
    """从多个实验结果中提取 Pareto 前沿"""
    pareto = []
    for i, m_i in enumerate(metrics_list):
        is_dominated = False
        for j, m_j in enumerate(metrics_list):
            if i == j: continue
            # m_j 在两个维度都不比 m_i 差
            if (m_j['cosine_mean'] >= m_i['cosine_mean'] and
                m_j['task_acc'] >= m_i['task_acc'] and
                (m_j['cosine_mean'] > m_i['cosine_mean'] or
                 m_j['task_acc'] > m_i['task_acc'])):
                is_dominated = True
                break
        if not is_dominated:
            pareto.append(i)
    return pareto
```

## 1.14 与下游任务的关联建模

### 1.14.1 信息论视角:重建 ↔ 下游的桥

**核心问题**: SID 重建 embedding 后, 到底保留了多少对下游有用的信息?

设原始 embedding 为 $\mathbf{x}$, 下游标签为 $y$, 重建后为 $\hat{\mathbf{x}}$:

$$
I(\mathbf{x}; y) \geq I(\hat{\mathbf{x}}; y)
$$

即**重建会损失互信息**——但好的 SID 应让 $I(\hat{\mathbf{x}}; y) \approx I(\mathbf{x}; y)$。

**度量方法**:

```python
def info_preservation_ratio(x, x_recon, y, estimator='knn'):
    """信息保留比"""
    if estimator == 'knn':
        # KSG estimator (Kraskov-Stögbauer-Grassberger)
        from sklearn.feature_selection import mutual_info_regression
        mi_orig = mutual_info_regression(x.cpu().numpy(), y.cpu().numpy())[0]
        mi_recon = mutual_info_regression(x_recon.cpu().numpy(), y.cpu().numpy())[0]
        return mi_recon / (mi_orig + 1e-8)
    elif estimator == 'classifier':
        # 用下游任务准确率比值
        from sklearn.linear_model import LogisticRegression
        from sklearn.metrics import accuracy_score

        clf_orig = LogisticRegression(max_iter=1000).fit(x.cpu().numpy(), y.cpu().numpy())
        acc_orig = accuracy_score(y.cpu().numpy(), clf_orig.predict(x.cpu().numpy()))

        clf_recon = LogisticRegression(max_iter=1000).fit(x_recon.cpu().numpy(), y.cpu().numpy())
        acc_recon = accuracy_score(y.cpu().numpy(), clf_recon.predict(x_recon.cpu().numpy()))

        return acc_recon / (acc_orig + 1e-8)
```

**期望**: 信息保留比 > 0.9 表示 SID 没有破坏关键信息; < 0.7 则说明损失严重。

### 1.14.2 重建 vs 下游的边际分析

**问题**: 多花 2× 训练资源把 cosine 从 0.94 提到 0.97, 下游能涨多少?

```python
def marginal_analysis(model_a, model_b, test_data):
    """两个模型的边际分析"""
    metrics_a = evaluate(model_a, test_data)
    metrics_b = evaluate(model_b, test_data)

    delta_cosine = metrics_b['cosine_mean'] - metrics_a['cosine_mean']
    delta_downstream = metrics_b['downstream_recall@10'] - metrics_a['downstream_recall@10']

    elasticity = delta_downstream / (delta_cosine + 1e-8)
    print(f"Cosine +{delta_cosine:.4f} → Recall@10 +{delta_downstream:.4f}")
    print(f"弹性 = {elasticity:.2f} (单位 cosine 带来的下游增量)")
    # 弹性 > 5 → 非常划算
    # 弹性 1-5 → 一般划算
    # 弹性 < 1 → 不划算, 投入产出比低
```

### 1.14.3 上界分析:用 teacher embedding 评估 SID 极限

```python
def upper_bound_analysis(teacher_model, student_sid_model, test_data):
    """用 teacher (如大模型) embedding 评估 SID 的理论上限"""
    with torch.no_grad():
        teacher_emb = teacher_model(test_data)
        student_recon, _, _, _ = student_sid_model(teacher_emb)

    # student 是否能"无损"重建 teacher
    perfect = torch.allclose(teacher_emb, student_recon, atol=1e-4)

    return {
        'mse': F.mse_loss(student_recon, teacher_emb).item(),
        'cosine': F.cosine_similarity(teacher_emb, student_recon, dim=-1).mean().item(),
        'is_perfect': perfect,
    }
```

5. **邻居保持低, cosine 高** → 重建保住了"全局方向", 但局部结构破坏——降维可视化排查

## 1.19 经典 FAQ (扩展版)

### Q1.1: 如何判断 cosine 跌了是否真问题?

**A**: 三步判断:
1. 看绝对值: cosine 跌 0.01 一般不严重, 跌 0.05 必查
2. 看分位数: P50 跌 0.01 比 P10 跌 0.01 严重(P50 是大多数)
3. 看下游: AB 测试 Recall@K 是否对应跌

### Q1.2: 重建指标能不能完全预测下游?

**A**: 不能。重建指标是必要不充分条件:
- cosine 0.95+ 且 NP@10 > 0.7 → **大概率**下游不掉
- 但 cosine 0.99 也可能下游崩塌 (过度拟合内容相似度)

### Q1.3: 用 L2 归一化后, MSE 突然变得很小, 是不是数据错了?

**A**: 不是。L2 归一化后, $\|\mathbf{x}\|_2 = 1$, 所以 $\|\mathbf{x} - \hat{\mathbf{x}}\|_2^2 \in [0, 4]$。MSE 0.05 对应余弦 ≈ 0.975——是合理的。

### Q1.4: 评估时要不要 batch?

**A**: **必须 batch**。逐条评估慢 100×+。但要注意:
- batch_size 256-1024 适合 GPU
- 大 batch 可能 OOM, 用 gradient checkpointing 或 chunked
- 评估时不需要梯度, `torch.no_grad()` + `model.eval()`

### Q1.5: cosine 评估时, 要不要 L2 归一化?

**A**: 都行, 但要**和训练时一致**。训练时如果归一化, 评估也归一化。否则 cosine 值不可比。

### Q1.6: SID 训练后, 离线评估很完美, 但上线后效果差, 为什么?

**A**: 经典问题, 常见原因:
1. **数据漂移**: 上线后新 item 涌入, 训练集分布过时
2. **用户分布不同**: 训练集用户 ≠ 实际服务用户
3. **冷启动未测**: 测试集全是已知 item, 上线后新 item 大量
4. **延迟限制**: 离线评估假设无限算力, 实际有延迟预算, 模型被裁剪
5. **缓存命中**: 离线评估是 fresh inference, 上线有缓存, 行为分布变化

### Q1.7: 离线 cosine 涨 0.01, AB 测试下游涨多少?

**A**: 经验值:
- cosine +0.01, P50 涨 → Recall@10 +0.5-1%
- cosine +0.01, P10 涨 → Recall@10 +2-3%
- 但 AB 测试通常只看 5% 提升, 小流量难验证

## 1.20 完整 PyTorch 评估工具类

### 1.20.1 SIDEvaluator 完整实现

```python
"""完整 SID 重建指标评估器"""
import numpy as np
import torch
import torch.nn.functional as F
from collections import Counter
from typing import Dict, Tuple, Optional


class SIDReconstructionEvaluator:
    """SID 重建指标评估器 (生产级)"""

    def __init__(self, num_codes=256, num_layers=4, device='cuda'):
        self.num_codes = num_codes
        self.num_layers = num_layers
        self.device = device

    def reconstruction_mse(self, original: torch.Tensor, recon: torch.Tensor) -> Dict:
        """重建 MSE / RMSE / MAE / PSNR"""
        mse = F.mse_loss(recon, original).item()
        rmse = mse ** 0.5
        mae = F.l1_loss(recon, original).item()
        max_val = original.abs().max().item()
        psnr = 20 * np.log10(max_val / (rmse + 1e-8))
        return {
            'mse': mse,
            'rmse': rmse,
            'mae': mae,
            'psnr': psnr,
        }

    def cosine_metrics(self, original: torch.Tensor, recon: torch.Tensor) -> Dict:
        """Cosine 全面指标"""
        cos = F.cosine_similarity(original, recon, dim=-1)
        cos_np = cos.cpu().numpy()

        return {
            'cosine_mean': cos_np.mean(),
            'cosine_std': cos_np.std(),
            'cosine_min': cos_np.min(),
            'cosine_max': cos_np.max(),
            'cosine_p10': np.percentile(cos_np, 10),
            'cosine_p50': np.percentile(cos_np, 50),
            'cosine_p90': np.percentile(cos_np, 90),
            'cosine_p99': np.percentile(cos_np, 99),
            'frac_below_0.9': (cos_np < 0.9).mean(),
            'frac_below_0.95': (cos_np < 0.95).mean(),
        }

    def neighborhood_preservation(self, original: torch.Tensor, recon: torch.Tensor,
                                   k_values=(5, 10, 50)) -> Dict:
        """邻居保持率 (NP@K)"""
        n = original.shape[0]
        if n > 5000:
            # 大数据集 subsample
            idx = torch.randperm(n)[:5000]
            original = original[idx]
            recon = recon[idx]
            n = 5000

        sim_orig = (original @ original.T).fill_diagonal_(-1e9)
        sim_recon = (recon @ recon.T).fill_diagonal_(-1e9)

        results = {}
        for k in k_values:
            topk_orig = sim_orig.topk(k, dim=-1).indices.cpu().numpy()
            topk_recon = sim_recon.topk(k, dim=-1).indices.cpu().numpy()

            preservation = []
            for i in range(n):
                inter = len(set(topk_orig[i]) & set(topk_recon[i]))
                preservation.append(inter / k)
            results[f'np@{k}'] = float(np.mean(preservation))
        return results

    def stratified_metrics(self, original: torch.Tensor, recon: torch.Tensor,
                            popularity: np.ndarray) -> Dict:
        """分层指标 (按 popularity)"""
        mse_per_item = ((original - recon) ** 2).mean(dim=-1).cpu().numpy()
        cos_per_item = F.cosine_similarity(original, recon, dim=-1).cpu().numpy()

        # 三分位数分层
        p33 = np.percentile(popularity, 33)
        p67 = np.percentile(popularity, 67)
        head_mask = popularity >= p67
        body_mask = (popularity >= p33) & (popularity < p67)
        tail_mask = popularity < p33

        results = {}
        for name, mask in [('head', head_mask), ('body', body_mask), ('tail', tail_mask)]:
            if mask.sum() > 0:
                results[f'{name}_mse'] = mse_per_item[mask].mean()
                results[f'{name}_cosine'] = cos_per_item[mask].mean()
                results[f'{name}_count'] = int(mask.sum())
        return results

    def evaluate(self, model, dataloader, popularity: Optional[np.ndarray] = None) -> Dict:
        """主入口: 全套重建评估"""
        model.eval()
        all_orig = []
        all_recon = []
        with torch.no_grad():
            for batch in dataloader:
                x = batch[0].to(self.device)
                x_recon, _, _, _ = model(x)
                all_orig.append(x.cpu())
                all_recon.append(x_recon.cpu())

        original = torch.cat(all_orig, dim=0)
        recon = torch.cat(all_recon, dim=0)

        # 聚合所有指标
        results = {}
        results.update(self.reconstruction_mse(original, recon))
        results.update(self.cosine_metrics(original, recon))
        results.update(self.neighborhood_preservation(original, recon))

        if popularity is not None:
            results.update(self.stratified_metrics(original, recon, popularity))

        return results
```

```python
    """批量对比多个 SID 版本"""

    def __init__(self, models: dict, test_loader):
        self.models = models  # {'v1': model_v1, 'v2': model_v2, ...}
        self.test_loader = test_loader
        self.results = {}

    def run_all(self):
        for name, model in self.models.items():
            print(f"评估 {name}...")
            evaluator = SIDReconstructionEvaluator()
            self.results[name] = evaluator.evaluate(model, self.test_loader)
        return self.results

    def make_comparison_table(self):
        """生成对比表"""
        import pandas as pd
        df = pd.DataFrame(self.results).T
        return df

    def find_best(self, metric='cosine_mean', mode='max'):
        """找最优模型"""
        best = None
        best_val = -np.inf if mode == 'max' else np.inf
        for name, res in self.results.items():
            val = res.get(metric)
            if val is None: continue
            if mode == 'max' and val > best_val:
                best_val = val
                best = name
            elif mode == 'min' and val < best_val:
                best_val = val
                best = name
        return best, best_val
```

```python
class LLMSIDReconstructionEvaluator:
    """LLM embedding 作为 SID 输入的评估"""

    def __init__(self, llm_model, sid_model):
        self.llm = llm_model
        self.sid = sid_model

    def evaluate_end_to_end(self, texts):
        # LLM 提取 embedding
        llm_emb = self.llm.encode(texts)  # [N, d_llm]

        # SID 量化
        with torch.no_grad():
            sid_recon, sids, _, _ = self.sid(llm_emb)

        # 重建指标
        return {
            'mse': F.mse_loss(sid_recon, llm_emb).item(),
            'cosine': F.cosine_similarity(llm_emb, sid_recon, dim=-1).mean().item(),
        }
```

### 1.22.2 LLM embedding 的特殊性质

LLM embedding (如 BERT, Sentence-BERT) 通常:
- 维度高 (768-4096)
- 各维度数值范围大
- 已经过良好归一化
- 语义结构清晰

**对 SID 的影响**:
- 量化难度大 (高维稀疏)
- 需要更深的码本 (L=8+) 或更宽的码本 (K=1024)
- 重建指标可能更漂亮 (因为 LLM embedding 本身结构好)

```python
class EarlyStoppingOnMetric:
    """基于重建指标的早期停止"""

    def __init__(self, patience=5, target_cosine=0.95, target_mse=0.05):
        self.patience = patience
        self.target_cosine = target_cosine
        self.target_mse = target_mse
        self.history = []
        self.counter = 0

    def __call__(self, val_metrics):
        self.history.append(val_metrics)

        cosine = val_metrics['cosine_mean']
        mse = val_metrics['mse']

        if cosine >= self.target_cosine and mse <= self.target_mse:
            self.counter += 1
            if self.counter >= self.patience:
                print(f"[EARLY STOP] 连续 {self.patience} 次达标")
                return True
        else:
            self.counter = 0
        return False
```

### 1.28.1 Case 1: 数据泄漏导致 cosine 虚高

```python
# 错误: 用训练集评估
```

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "1-重建指标与语义指标" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
