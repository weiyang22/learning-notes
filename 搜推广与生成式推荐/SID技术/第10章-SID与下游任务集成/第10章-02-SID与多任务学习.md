# 2. SID 与多任务学习

> **本章定位**: 讲清楚"为什么多任务推荐需要 SID"以及"SID 如何嵌入 MMoE / PLE / ESMM"。不是简单堆一个 `MMoEWithSID`，而是从**多任务的核心矛盾（跷跷板 / 梯度冲突）**出发，看 SID 的层次共享表征如何缓解它。
> **预计时长**: 120 分钟（含手撕代码）
> **前置**: 已读 [第10章-01 SID与生成式推荐](第10章-01-SID与生成式推荐-TIGER-OneRec.md)、了解 RQ-VAE 产出的层次 SID；对 MLP / Embedding / 反向传播熟悉。

## 2.0 本章知识地图

```text
业务动机: 一个推荐系统要同时优化 点击/转化/时长/点赞...
        ↓
核心矛盾: 多任务共享参数 → 梯度冲突 → 跷跷板 (一个涨一个跌)
        ↓
架构演进: Shared-Bottom → MMoE (软路由专家) → PLE (共享+专属专家)
        ↓
SID 的角色: 把稀疏 item-ID 换成"层次语义码"的共享底座
        ↓ 收益
  长尾更稳 (粗层码共享) + 参数更省 (L·K 而非 N_item) + 冷启动 (有码就能预估)
        ↓
损失与训练: 加权 / 不确定性加权 / GradNorm / PCGrad + 监控
        ↓
工业落地: ESMM 纠 CVR 样本偏差、层次码的粗细分工、上线监控
```

本章按这条主线展开，每一步都给**可运行代码 + 数学解释 + 面试话术**。

## 2.1 为什么推荐必须做多任务

### 2.1.1 业务漏斗决定了多目标

工业推荐/广告的价值链是一条漏斗：

```text
曝光(Impression) → 点击(Click) → 转化(Conversion) → 复购/时长/留存
     pCTR              pCVR             pLTV / pDuration
```

- 只优化 **CTR**：模型学会推"标题党/封面党"，点击高但不转化，长期伤害生态。
- 只优化 **CVR**：只在点击后的样本上有标签，样本量小且有偏（**样本选择偏差**，2.7 节详述）。
- 真正的线上目标常是一个**组合分**，例如：

$$
\text{score} = \text{pCTR}^{\alpha} \cdot \text{pCVR}^{\beta} \cdot (\text{bid or pLTV})^{\gamma}
$$

因此，**同一个模型同时预估多个目标**（多任务学习，Multi-Task Learning, MTL）是工业标配，而非可选项。

### 2.1.2 多任务的三个好处

| 好处 | 机制 | 例子 |
| :--- | :--- | :--- |
| **参数/算力共享** | 多个任务共用底座，省显存省时延 | 一次前向出 CTR/CVR/时长 |
| **正则化 / 迁移** | 任务 A 的监督信号约束共享表征，缓解任务 B 过拟合 | 时长任务帮 CTR 学到"深度兴趣" |
| **数据互补** | 稀疏任务借稠密任务的梯度 | CVR（稀疏）借 CTR（稠密）的表征 |

### 2.1.3 但天下没有免费的午餐

多任务不是"多加几个 head 就白赚"。当任务目标**不一致**时，共享参数会被相互撕扯，产生**负迁移（Negative Transfer）**与**跷跷板现象（Seesaw Phenomenon）**：一个任务的指标上去了，另一个掉下来。这正是 MMoE / PLE 要解决的问题，也是 SID 能帮忙的地方。

## 2.2 多任务的核心矛盾：梯度冲突与跷跷板

### 2.2.1 共享底座（Shared-Bottom）的数学

最朴素的 MTL 是 **Shared-Bottom**：一个共享网络 $f_\theta$，每个任务一个塔 $g_{\phi_t}$。

$$
\hat{y}_t = g_{\phi_t}\big(f_\theta(x)\big), \qquad
\mathcal{L} = \sum_{t=1}^{T} w_t \,\ell_t(\hat{y}_t, y_t)
$$

共享参数 $\theta$ 收到的梯度是各任务梯度的**加权和**：

$$
\nabla_\theta \mathcal{L} = \sum_{t=1}^{T} w_t \,\nabla_\theta \ell_t
$$

### 2.2.2 梯度冲突的定义

设任务 $i,j$ 对共享参数的梯度为 $g_i=\nabla_\theta \ell_i$、$g_j=\nabla_\theta \ell_j$。定义两者夹角 $\phi_{ij}$：

$$
\cos\phi_{ij} = \frac{\langle g_i, g_j\rangle}{\|g_i\|\,\|g_j\|}
$$

- $\cos\phi_{ij} > 0$：梯度方向一致，**互相促进**（正迁移）。
- $\cos\phi_{ij} < 0$：梯度方向相反，**互相拉扯**（梯度冲突）。此时加权和 $g_i+g_j$ 的模长可能比单个还小，共享参数"原地打转"，谁也学不好。

> **一句话面试点**：跷跷板的数学本质是**共享参数上多任务梯度的负内积**。任务越异质（如 CTR 追点击、时长追停留），$\cos\phi$ 越可能为负，冲突越严重。

### 2.2.3 一个直观的二维例子

```text
任务A 想把 θ 往右上推 (g_A = (1, 1))
任务B 想把 θ 往右下推 (g_B = (1, -1))
合梯度 g_A + g_B = (2, 0)    ← 纵向分量抵消, 只剩横向
若权重不均: 0.9*g_A + 0.1*g_B ≈ (1, 0.8) ← 几乎只服务 A, B 被牺牲
```

Shared-Bottom 只有**一个** $\theta$，无法同时满足方向相反的需求 → 必然有任务被牺牲。解药：**给不同任务不同的（部分）参数通道**，这就是 MMoE / PLE 的核心思想。

## 2.3 从 Shared-Bottom 到 MMoE 到 PLE

### 2.3.1 MMoE：多门控混合专家

MMoE（Multi-gate Mixture-of-Experts, KDD 2018）把单一底座换成 **$E$ 个专家网络** $\{f_e\}_{e=1}^{E}$，每个任务有**自己的门控** $\text{gate}_t$ 来对专家做加权：

$$
\text{gate}_t(x) = \text{softmax}(W_t\, x) \in \mathbb{R}^{E}, \qquad
h_t(x) = \sum_{e=1}^{E} \text{gate}_t(x)_e \cdot f_e(x)
$$

$$
\hat{y}_t = g_{\phi_t}\big(h_t(x)\big)
$$

- 每个任务通过门控**软选择**对自己有用的专家组合。
- 冲突的任务可以**路由到不同专家**，从而各取所需，缓解跷跷板。

### 2.3.2 PLE：显式区分共享专家与专属专家

MMoE 的所有专家仍是"全体共享"的——任务只能通过门控权重间接分开。**PLE**（Progressive Layered Extraction, RecSys 2020 最佳论文）更进一步：

- 每个任务有**专属专家（task-specific experts）**，只服务该任务；
- 另有**共享专家（shared experts）**，服务所有任务；
- 任务 $t$ 的门控只在 **{自己的专属专家 ∪ 共享专家}** 上路由。

这样把"该共享的共享、该私有的私有"**结构化地分开**，进一步减小冲突。PLE 还能堆叠多层（Progressive）逐层抽取。

### 2.3.3 三者对比

| 架构 | 参数分配 | 冲突缓解 | 复杂度 | 适用 |
| :--- | :--- | :--- | :--- | :--- |
| Shared-Bottom | 全共享 | 弱 | 低 | 任务高度相关 |
| MMoE | 软路由共享专家 | 中 | 中 | 通用首选 |
| PLE | 共享+专属显式分离 | 强 | 高 | 任务冲突明显 / 跷跷板严重 |

> SID 与这三者都能结合。SID 改变的是**输入表征**（底座喂什么），而 MMoE/PLE 改变的是**参数如何分配**——两者正交，可叠加。

## 2.4 SID 在多任务里到底扮演什么角色

回顾：RQ-VAE 把每个 item 编码成 $L$ 层码 $\text{sid}=(c_1,\dots,c_L)$，每层码取值 $0..K-1$，每层一张 Embedding 表。把 SID embedding 作为**多任务共享底座的输入**，带来三个独特收益：

### 2.4.1 长尾表征更稳（核心卖点）

传统做法：每个 item 一个独立 ID embedding。长尾 item 曝光少 → 其 embedding 更新次数少 → **训练不充分**，在多任务下更是雪上加霜（稀疏任务如 CVR 的长尾样本几乎学不到）。

SID 做法：粗层码 $c_1$ 被**大量同类 item 共享**。长尾 item 即使自身样本少，它的 $c_1$（大类）被高频 item 撑得很足 → 长尾借共享码本"蹭"到充分训练的表征。

$$
\underbrace{e_{\text{item}}}_{\text{传统: 独立, 长尾稀疏}} \;\;\Longrightarrow\;\;
\underbrace{\sum_{l=1}^{L} e_l[c_l]}_{\text{SID: 分层共享, 长尾借粗层}}
$$

### 2.4.2 参数效率

- 传统 ID embedding 表：$O(N_{\text{item}} \times d)$，$N_{\text{item}}$ 可达数亿。
- SID embedding 表：$O(L \times K \times d)$，例如 $L=5, K=256, d=128$ 仅约 16 万参数。

多任务模型本就参数量大，SID 让底座 embedding **缩小几个数量级**，省下的显存可以给专家网络。

### 2.4.3 冷启动友好

新 item 无行为 → 传统 ID embedding 随机初始化，多任务全预估不准。SID 只要能算出码（有内容 embedding 即可），就能立刻参与所有任务的预估。见 [第10章-05 冷启动与可解释性](第10章-05-SID与冷启动与可解释性.md)。

### 2.4.4 一张图总结

```text
             ┌─────────── 多任务塔 (CTR / CVR / 时长) ───────────┐
             │        MMoE / PLE 参数分配 (缓解梯度冲突)          │
             └───────────────────────▲───────────────────────────┘
                                      │ 共享底座输入
                     ┌────────────────┴────────────────┐
   传统:  item_id → [ 巨大稀疏 ID Embedding, 长尾稀疏 ]
   SID :  sid=(c1..cL) → [ L·K 小码本, 分层共享, 长尾稳/冷启动友好 ]
```

## 2.5 手撕：MMoE + SID 完整实现（逐行讲解）

下面给出一个**可训练、可跑通**的 MMoE+SID，比开头的骨架版更完整：加了序列聚合、门控温度、辅助监控。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class SIDEmbedding(nn.Module):
    """把 [B, L] 或 [B, T, L] 的层次 SID 映射为稠密向量。
    - 单 item: [B, L] -> [B, D]
    - 序列:    [B, T, L] -> [B, T, D] (再由上层聚合)
    聚合方式 'sum' 与 RQ 的残差累加语义一致。
    """
    def __init__(self, num_levels=5, codebook_size=256, dim=128, agg='sum'):
        super().__init__()
        self.L, self.agg = num_levels, agg
        self.embs = nn.ModuleList(
            [nn.Embedding(codebook_size, dim) for _ in range(num_levels)])
        if agg == 'concat':
            self.proj = nn.Linear(num_levels * dim, dim)

    def forward(self, sid):
        parts = [self.embs[i](sid[..., i]) for i in range(self.L)]  # each [..., D]
        if self.agg == 'sum':
            return torch.stack(parts, 0).sum(0)
        return self.proj(torch.cat(parts, -1))


class MMoEWithSID(nn.Module):
    """SID 输入 + MMoE 多任务。
    history_sids: [B, T, L]  用户历史 item 的层次 SID
    target_sid:   [B, L]     候选 item 的层次 SID (可选, 拼进底座)
    """
    def __init__(self, num_levels=5, codebook_size=256, dim=128,
                 num_experts=4, num_tasks=3, expert_hidden=256, gate_temp=1.0):
        super().__init__()
        self.sid_emb = SIDEmbedding(num_levels, codebook_size, dim, agg='sum')
        self.gate_temp = gate_temp
        # 底座输入 = 历史聚合向量 ⊕ 候选向量
        in_dim = dim * 2
        self.experts = nn.ModuleList([
            nn.Sequential(
                nn.Linear(in_dim, expert_hidden), nn.ReLU(),
                nn.Linear(expert_hidden, expert_hidden), nn.ReLU(),
            ) for _ in range(num_experts)
        ])
        self.gates = nn.ModuleList(
            [nn.Linear(in_dim, num_experts) for _ in range(num_tasks)])
        self.towers = nn.ModuleList([
            nn.Sequential(nn.Linear(expert_hidden, 64), nn.ReLU(), nn.Linear(64, 1))
            for _ in range(num_tasks)
        ])
        self.num_tasks = num_tasks

    def encode(self, history_sids, target_sid):
        # 历史: [B, T, L] -> [B, T, D] -> 平均池化 [B, D]
        hist = self.sid_emb(history_sids).mean(dim=1)           # [B, D]
        cand = self.sid_emb(target_sid)                         # [B, D]
        return torch.cat([hist, cand], dim=-1)                  # [B, 2D]

    def forward(self, history_sids, target_sid, return_gate=False):
        x = self.encode(history_sids, target_sid)              # [B, 2D]
        expert_out = torch.stack([e(x) for e in self.experts], dim=1)  # [B, E, H]
        logits, gates = [], []
        for gate, tower in zip(self.gates, self.towers):
            w = F.softmax(gate(x) / self.gate_temp, dim=-1)    # [B, E]
            mixed = (w.unsqueeze(-1) * expert_out).sum(dim=1)  # [B, H]
            logits.append(tower(mixed).squeeze(-1))            # [B]
            gates.append(w)
        logits = torch.stack(logits, dim=-1)                   # [B, num_tasks]
        if return_gate:
            return logits, torch.stack(gates, dim=1)           # gate: [B, T, E]
        return logits
```

### 2.5.1 逐行要点

1. **`SIDEmbedding.agg='sum'`**：各层码 embedding 相加，等价于 RQ 的 $z\approx\sum_l e_l[c_l]$，天然继承层次语义。想要更强表达力可用 `concat`（多一层线性投影）。
2. **`encode` 里历史用 `mean` 池化**：最简单的序列聚合。生产里通常换成 **target-attention（DIN 式）** 或 **Transformer**，让候选 item 对历史做注意力（见 2.9 进阶）。
3. **`gate_temp` 门控温度**：温度越低，门控越"硬"（接近 one-hot），专家分工更极端；温度越高越"软"，专家更均摊。跷跷板严重时可调低温度逼专家分化。
4. **`return_gate`**：把门控权重吐出来做监控（2.10 节），观察不同任务是否真的路由到不同专家。

### 2.5.2 训练循环

```python
def train_mmoe_sid(model, loader, epochs=5, lr=1e-3, task_weights=(1.0, 1.0, 0.5)):
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    tw = torch.tensor(task_weights)
    for ep in range(epochs):
        model.train(); running = 0.0
        for hist_sid, tgt_sid, labels in loader:   # labels: [B, num_tasks] 0/1
            logits = model(hist_sid, tgt_sid)       # [B, num_tasks]
            # 每个任务独立 BCE, 再按权重求和
            per_task = F.binary_cross_entropy_with_logits(
                logits, labels.float(), reduction='none').mean(0)  # [num_tasks]
            loss = (tw * per_task).sum()
            opt.zero_grad(); loss.backward(); opt.step()
            running += loss.item()
        print(f"epoch {ep}: loss={running/len(loader):.4f}, per_task={per_task.tolist()}")
    return model
```

## 2.6 手撕：PLE + SID（共享专家 + 专属专家）

当 MMoE 仍压不住跷跷板时，上 PLE。核心是把专家分成**共享**与**每任务专属**两组，门控只在"共享 ∪ 自己专属"上路由。

```python
class PLEWithSID(nn.Module):
    def __init__(self, num_levels=5, codebook_size=256, dim=128,
                 n_shared=2, n_specific=1, num_tasks=3, hidden=256):
        super().__init__()
        self.sid_emb = SIDEmbedding(num_levels, codebook_size, dim, agg='sum')
        in_dim = dim * 2
        self.num_tasks = num_tasks
        self.n_shared, self.n_specific = n_shared, n_specific

        def mlp():
            return nn.Sequential(nn.Linear(in_dim, hidden), nn.ReLU(),
                                 nn.Linear(hidden, hidden), nn.ReLU())

        self.shared_experts = nn.ModuleList([mlp() for _ in range(n_shared)])
        # 每个任务一组专属专家
        self.specific_experts = nn.ModuleList([
            nn.ModuleList([mlp() for _ in range(n_specific)])
            for _ in range(num_tasks)
        ])
        # 每个任务的门控: 在 (自己的专属 + 共享) 上路由
        self.gates = nn.ModuleList([
            nn.Linear(in_dim, n_specific + n_shared) for _ in range(num_tasks)
        ])
        self.towers = nn.ModuleList([
            nn.Sequential(nn.Linear(hidden, 64), nn.ReLU(), nn.Linear(64, 1))
            for _ in range(num_tasks)
        ])

    def encode(self, history_sids, target_sid):
        hist = self.sid_emb(history_sids).mean(dim=1)
        cand = self.sid_emb(target_sid)
        return torch.cat([hist, cand], dim=-1)

    def forward(self, history_sids, target_sid):
        x = self.encode(history_sids, target_sid)               # [B, 2D]
        shared_out = [e(x) for e in self.shared_experts]        # n_shared × [B, H]
        logits = []
        for t in range(self.num_tasks):
            spec_out = [e(x) for e in self.specific_experts[t]] # n_specific × [B, H]
            cand_experts = torch.stack(spec_out + shared_out, dim=1)  # [B, S+Sh, H]
            w = F.softmax(self.gates[t](x), dim=-1)             # [B, S+Sh]
            mixed = (w.unsqueeze(-1) * cand_experts).sum(dim=1) # [B, H]
            logits.append(self.towers[t](mixed).squeeze(-1))
        return torch.stack(logits, dim=-1)                      # [B, num_tasks]
```

### 2.6.1 PLE 相比 MMoE 的关键差别

- MMoE：所有任务共享**同一组**专家，靠门控软分。
- PLE：任务 $t$ 只能看到 **自己的专属专家 + 共享专家**，看不到别的任务的专属专家 → 从**结构上**杜绝了"别人的私货污染我"的路径，冲突进一步下降。

### 2.6.2 何时该用 PLE 而非 MMoE

| 信号 | 建议 |
| :--- | :--- |
| 任务相关性高、门控已能分化 | MMoE 够用，别过度设计 |
| 观察到明显跷跷板（一涨一跌） | 上 PLE |
| 任务数多且异质（点击 vs 时长 vs 分享） | PLE / 多层 PLE |
| 算力紧、时延敏感 | MMoE（PLE 专家更多） |

## 2.7 ESMM + SID：解决 CVR 的样本选择偏差

### 2.7.1 CVR 单独建模的两个致命问题

CVR = P(转化 | 点击)。若只用"点击后"的样本训练 CVR：

1. **样本选择偏差（Sample Selection Bias, SSB）**：训练只在"点击空间"，但线上要对"曝光空间"所有 item 打分 → 训练/推理分布不一致。
2. **数据稀疏（Data Sparsity）**：点击样本远少于曝光样本，CVR 标签极稀疏。

### 2.7.2 ESMM 的解法

ESMM（Entire Space Multi-task Model, SIGIR 2018）在**全曝光空间**上同时建模 CTR 和 CTCVR，用乘法关系间接得到 CVR：

$$
\underbrace{p(\text{click\&conv}\mid x)}_{\text{pCTCVR}} =
\underbrace{p(\text{click}\mid x)}_{\text{pCTR}} \times
\underbrace{p(\text{conv}\mid \text{click}, x)}_{\text{pCVR}}
$$

- 两个塔分别输出 pCTR 和 pCVR，**相乘**得到 pCTCVR。
- 损失在**全曝光空间**上对 pCTR 和 pCTCVR 监督（都有全空间标签），pCVR 作为中间量被**间接**学习 → 绕开 SSB。

### 2.7.3 ESMM + SID 实现

```python
class ESMMWithSID(nn.Module):
    """全空间多任务: 共享 SID 底座, 两塔输出 pCTR / pCVR, 相乘得 pCTCVR。"""
    def __init__(self, num_levels=5, codebook_size=256, dim=128, hidden=256):
        super().__init__()
        self.sid_emb = SIDEmbedding(num_levels, codebook_size, dim, agg='sum')
        in_dim = dim * 2
        def tower():
            return nn.Sequential(
                nn.Linear(in_dim, hidden), nn.ReLU(),
                nn.Linear(hidden, 64), nn.ReLU(), nn.Linear(64, 1))
        self.ctr_tower = tower()
        self.cvr_tower = tower()

    def forward(self, history_sids, target_sid):
        hist = self.sid_emb(history_sids).mean(dim=1)
        cand = self.sid_emb(target_sid)
        x = torch.cat([hist, cand], dim=-1)
        p_ctr = torch.sigmoid(self.ctr_tower(x).squeeze(-1))    # [B]
        p_cvr = torch.sigmoid(self.cvr_tower(x).squeeze(-1))    # [B]
        p_ctcvr = p_ctr * p_cvr                                 # 全空间可监督
        return p_ctr, p_cvr, p_ctcvr


def esmm_loss(p_ctr, p_cvr, p_ctcvr, click, conv):
    """click: 是否点击(全空间标签); conv: 是否转化(全空间, 未点击必为0)。
    注意: 不直接监督 p_cvr! 只监督 p_ctr 和 p_ctcvr。
    """
    l_ctr = F.binary_cross_entropy(p_ctr, click.float())
    l_ctcvr = F.binary_cross_entropy(p_ctcvr, conv.float())
    return l_ctr + l_ctcvr
```

> **面试高频**："为什么 ESMM 不直接对 pCVR 算 loss？" —— 因为 pCVR 的真值只在点击样本上存在（SSB）。ESMM 把它藏在 pCTCVR=pCTR×pCVR 里，用全空间可得的 CTR、CTCVR 标签**间接**约束，从而在全空间学到无偏的 pCVR。

### 2.7.4 SID 在 ESMM 里的额外价值

CVR 本就数据稀疏，长尾 item 的 CVR 更是几乎没样本。SID 的粗层共享让长尾 item 的 CVR 表征**借同类热门 item** 撑起来，缓解稀疏——这是纯 ID embedding 给不了的。

## 2.8 多任务损失设计：从手工加权到自适应

前面都用固定权重 $\sum_t w_t \ell_t$。权重怎么定？这是多任务的老大难。下面从简单到高级。

### 2.8.1 固定加权（Baseline）

$$
\mathcal{L} = \sum_t w_t \ell_t
$$

- 优点：简单、可控、线上可解释。
- 缺点：$w_t$ 靠人调，任务量纲/收敛速度不同，难调；线上目标变了要重调。

### 2.8.2 不确定性加权（Uncertainty Weighting, Kendall 2018）

给每个任务学一个**同方差不确定性** $\sigma_t$，自动平衡：

$$
\mathcal{L} = \sum_t \frac{1}{2\sigma_t^2}\,\ell_t + \log \sigma_t
$$

$\sigma_t$ 大（该任务噪声大/难）→ 权重 $\frac{1}{2\sigma_t^2}$ 自动变小；$\log\sigma_t$ 防止 $\sigma_t\to\infty$ 作弊。

```python
class UncertaintyWeightedLoss(nn.Module):
    def __init__(self, num_tasks):
        super().__init__()
        # 学 log(sigma^2) 更稳
        self.log_var = nn.Parameter(torch.zeros(num_tasks))

    def forward(self, per_task_losses):        # [num_tasks]
        precision = torch.exp(-self.log_var)   # 1/sigma^2
        return (precision * per_task_losses + self.log_var).sum()
```

### 2.8.3 GradNorm：让各任务梯度模长均衡

GradNorm（ICML 2018）动态调 $w_t$，让各任务在共享参数最后一层的**梯度模长**趋于一致，且训练慢的任务权重更大。核心是加一个"梯度范数的 L1 目标"。工程上稍重，收益视场景。

### 2.8.4 PCGrad：直接消除梯度冲突

PCGrad（NeurIPS 2020）针对 2.2 节的**负内积**下手：当 $g_i\cdot g_j<0$，把 $g_i$ 在 $g_j$ 方向的冲突分量**投影掉**：

$$
g_i \leftarrow g_i - \frac{\langle g_i, g_j\rangle}{\|g_j\|^2}\, g_j \quad(\text{当} \langle g_i,g_j\rangle<0)
$$

```python
def pcgrad(grads):
    """grads: List[Tensor], 每个任务对共享参数(展平)的梯度。返回投影后合梯度。"""
    import random
    pc = [g.clone() for g in grads]
    for i in range(len(pc)):
        order = list(range(len(grads))); random.shuffle(order)
        for j in order:
            if i == j: continue
            gj = grads[j]
            dot = torch.dot(pc[i], gj)
            if dot < 0:                              # 冲突 → 投影掉冲突分量
                pc[i] = pc[i] - dot / (gj.norm()**2 + 1e-12) * gj
    return torch.stack(pc).sum(0)
```

### 2.8.5 选型建议

| 方法 | 复杂度 | 何时用 |
| :--- | :--- | :--- |
| 固定加权 | 极低 | 起步、线上目标明确 |
| 不确定性加权 | 低 | 任务量纲差异大、懒得调权 |
| GradNorm | 中 | 任务收敛速度差异大 |
| PCGrad | 中高 | 观测到明显梯度冲突/跷跷板 |

> 实践顺序：先固定加权拿 baseline → 有跷跷板再上 PLE（架构层）→ 仍不行再上 PCGrad（优化层）。**架构 > 优化 > 调权**，别一上来就堆花活。

## 2.9 SID 层次结构与多任务的交互（进阶洞察）

这是 SID+多任务最有意思、也最容易被忽略的一点：**SID 的层次（粗→细）天然可以和多任务的"共享→专属"对齐**。

### 2.9.1 粗层共享、细层专精

- **粗层码 $c_1,c_2$**（大类、子类）：被大量 item 共享，编码"品类级"信息 → 适合喂给**共享专家**，服务所有任务。
- **细层码 $c_{L-1},c_L$**（细粒度残差）：编码 item 的个性化差异 → 适合喂给**任务专属专家**，捕捉任务特有的偏好。

可以设计一个**层次感知的门控**：让不同层的 SID embedding 走不同的专家路径。

```python
class HierAwareMMoE(nn.Module):
    """粗层码 -> 共享专家; 细层码 -> 任务专属专家 (示意)。"""
    def __init__(self, num_levels=5, split=2, codebook_size=256, dim=128,
                 n_shared=2, num_tasks=3, hidden=256):
        super().__init__()
        self.split = split          # 前 split 层算"粗层"
        self.coarse = SIDEmbedding(split, codebook_size, dim, agg='sum')
        self.fine = SIDEmbedding(num_levels - split, codebook_size, dim, agg='sum')
        def mlp(ind): return nn.Sequential(nn.Linear(ind, hidden), nn.ReLU(),
                                           nn.Linear(hidden, hidden), nn.ReLU())
        self.shared = nn.ModuleList([mlp(dim) for _ in range(n_shared)])
        self.specific = nn.ModuleList([mlp(dim) for _ in range(num_tasks)])
        self.gate_shared = nn.ModuleList([nn.Linear(dim, n_shared) for _ in range(num_tasks)])
        self.towers = nn.ModuleList([nn.Linear(hidden * 2, 1) for _ in range(num_tasks)])

    def forward(self, target_sid):                # [B, L]
        coarse = self.coarse(target_sid[..., :self.split])          # [B, D] 大类
        fine = self.fine(target_sid[..., self.split:])              # [B, D] 细节
        shared_out = torch.stack([e(coarse) for e in self.shared], 1)  # [B, n_shared, H]
        logits = []
        for t in range(len(self.towers)):
            w = F.softmax(self.gate_shared[t](coarse), -1)          # 粗层决定共享路由
            sh = (w.unsqueeze(-1) * shared_out).sum(1)              # [B, H]
            sp = self.specific[t](fine)                            # 细层进专属专家
            logits.append(self.towers[t](torch.cat([sh, sp], -1)).squeeze(-1))
        return torch.stack(logits, -1)
```

> 这不是唯一正确答案，而是一种**把 SID 层次语义显式接入多任务参数分配**的思路。工业上更多是把整段 SID embedding 一起喂，但理解这层对应关系能帮你在跷跷板严重时想出结构化解法。

### 2.9.2 用 target-attention 替换 mean 池化

前面历史用 `mean` 太粗。生产里用 **DIN 式 target-attention**：候选 item 的 SID 对历史序列做注意力，突出相关历史。

```python
class TargetAttentionSID(nn.Module):
    def __init__(self, dim=128):
        super().__init__()
        self.att = nn.Sequential(nn.Linear(dim * 4, 64), nn.ReLU(), nn.Linear(64, 1))

    def forward(self, hist_emb, cand_emb):    # hist:[B,T,D], cand:[B,D]
        T = hist_emb.size(1)
        c = cand_emb.unsqueeze(1).expand(-1, T, -1)       # [B,T,D]
        # DIN 交互特征: [h, c, h-c, h*c]
        feat = torch.cat([hist_emb, c, hist_emb - c, hist_emb * c], dim=-1)
        score = self.att(feat).squeeze(-1)                # [B,T]
        w = F.softmax(score, dim=-1).unsqueeze(-1)        # [B,T,1]
        return (w * hist_emb).sum(1)                      # [B,D] 加权历史
```

把 `MMoEWithSID.encode` 里的 `.mean(dim=1)` 换成这个模块，长尾/强意图场景 AUC 通常有可观提升。

## 2.10 训练技巧、监控与调参

### 2.10.1 必看的监控指标

| 指标 | 含义 | 异常信号 |
| :--- | :--- | :--- |
| 各任务 **GAUC**（分组 AUC） | 每任务真实排序能力 | 某任务持续走低 = 被牺牲 |
| **门控熵 / 分布** | 专家是否分化 | 所有任务门控几乎相同 = MMoE 退化成 Shared-Bottom |
| **梯度余弦** $\cos\phi_{ij}$ | 任务冲突程度 | 长期为负 = 需 PLE/PCGrad |
| **码本利用率** | SID 底座是否健康 | 大量死码 = 底座退化（见 第08章） |

### 2.10.2 门控监控代码

```python
@torch.no_grad()
def gate_report(model, loader, device='cpu'):
    model.eval()
    acc = None; n = 0
    for hist, tgt, _ in loader:
        _, gate = model(hist.to(device), tgt.to(device), return_gate=True)  # [B,T,E]
        g = gate.mean(0)                        # [T, E]
        acc = g if acc is None else acc + g; n += 1
    avg = acc / n
    print("平均门控 (任务×专家):\n", avg)
    # 门控熵: 越低越"专", 越高越"均摊"
    ent = -(avg * (avg + 1e-9).log()).sum(-1)
    print("各任务门控熵:", ent.tolist())
    return avg
```

### 2.10.3 常用技巧清单

1. **任务权重从"业务重要度"起步**，再按各任务收敛情况微调。
2. **稀疏任务（CVR）适当上采样正样本**或用 focal loss，防止被稠密任务淹没。
3. **门控温度**：跷跷板严重时调低，逼专家分化。
4. **SID 底座可先冻结再微调**：先用预训练好的 RQ-VAE embedding 冻结跑通多任务，再解冻联合微调。
5. **warmup + 梯度裁剪**：多任务 loss 尺度不一，早期易震荡。

## 2.12 常见陷阱（Debug 清单）

1. **门控不分化**：所有任务门控几乎一样 → MMoE 白搭。检查：门控温度是否过高、专家是否太少、任务是否其实高度相关（那就别硬上 MMoE）。
2. **稀疏任务被淹没**：CVR loss 被 CTR 主导 → 调权 / 上采样 / 不确定性加权。
3. **直接监督 pCVR**：在 ESMM 里对 pCVR 直接算 loss，破坏了全空间无偏性 → 只监督 pCTR、pCTCVR。
4. **SID 底座死码**：码本利用率低 → 多任务底座退化。先修 RQ-VAE（EMA、死码重启，见第 08 章）。
5. **共享层放太多任务专属信息**：Shared-Bottom 把冲突任务硬塞一个底座 → 上 MMoE/PLE。
6. **序列聚合用 mean**：丢失强意图 → 换 target-attention。
7. **多任务 loss 尺度悬殊**：回归任务（时长 MSE）和分类任务（CTR BCE）量纲差几个数量级 → 归一化 / 不确定性加权。

## 2.13 面试 Q&A

**Q1：多任务学习的跷跷板现象，数学本质是什么？怎么缓解？**
A：本质是**共享参数上多任务梯度的负内积** $\cos\phi_{ij}<0$，导致合梯度相互抵消，某任务被牺牲。缓解分三层：架构层（MMoE 软路由 / PLE 共享+专属专家分离冲突路径）、优化层（PCGrad 投影掉冲突分量、GradNorm 均衡梯度模长）、加权层（不确定性加权自适应）。优先级：架构 > 优化 > 调权。

**Q2：MMoE 和 PLE 的区别？什么时候用 PLE？**
A：MMoE 所有任务共享同一组专家、靠每任务独立门控软分；PLE 显式区分共享专家和任务专属专家，门控只在"共享∪自己专属"上路由，从结构上杜绝任务间私货污染。当观测到明显跷跷板、任务数多且异质时用 PLE，否则 MMoE 够用（别过度设计）。

**Q3：为什么在多任务里用 SID 而不是原始 item ID？**
A：三点。①长尾表征更稳：SID 粗层码被大量 item 共享，长尾借共享码本蹭到充分训练的表征，这对稀疏任务（CVR）尤其关键。②参数效率：ID 表 $O(N_{item})$ 可达数亿，SID 表仅 $O(L·K)$ 十万级。③冷启动：新品有码即可参与所有任务预估。

**Q4：ESMM 为什么不直接建模 CVR？**
A：CVR 真值只在点击样本上存在，直接建模有样本选择偏差（训练在点击空间、推理在曝光空间）和数据稀疏。ESMM 在全曝光空间建模 pCTR 和 pCTCVR=pCTR×pCVR，pCVR 作为中间量被间接学习，从而在全空间无偏。

**Q5：SID 的层次结构和多任务有什么可利用的对应关系？**
A：粗层码（大类、共享度高）适合喂共享专家服务所有任务；细层码（个性化残差）适合喂任务专属专家。可设计层次感知门控把二者对齐，在跷跷板严重时作为结构化解法。

**Q6：多任务权重怎么定？**
A：从业务重要度起步的固定加权拿 baseline；量纲差异大用不确定性加权（学 $\sigma_t$ 自适应）；收敛速度差异大用 GradNorm；有明显梯度冲突用 PCGrad。

**Q7：怎么判断你的 MMoE 真的在分工，而不是退化成 Shared-Bottom？**
A：监控门控分布/熵。如果所有任务的门控权重几乎相同，说明专家没分化，MMoE 退化。此时调低门控温度、减少专家冗余，或检查任务是否本就高度相关（那 MMoE 收益本就有限）。

---

## 2.14 本章小结

- 多任务是推荐的刚需，但共享参数带来梯度冲突/跷跷板，本质是梯度负内积。
- 架构演进 Shared-Bottom → MMoE → PLE，逐步把"共享/专属"参数分开。
- ESMM 用全空间 pCTR×pCVR 解决 CVR 的样本选择偏差。
- **SID 的价值在于把稀疏 item-ID 换成层次共享码本**：长尾更稳、参数更省、冷启动友好，且层次语义能与多任务的共享/专属对齐。
- 损失设计与监控（GAUC、门控、梯度余弦）是把这套跑好的工程内功。

## 2.15 端到端实战：从曝光日志到多任务 SID 模型

前面各节是"零件"，这一节把它们串成一条**能跑的流水线**：日志 → 特征（含 SID）→ Dataset → 多任务模型 → 评估。代码略去了工业级的分布式与存储细节，但结构与真实 pipeline 一致。

### 2.15.1 数据结构约定

一条曝光样本至少包含：

```text
{
  "user_id": 123,
  "hist_item_ids": [8871, 231, ...],   # 用户历史点击的 item id 序列
  "target_item_id": 9981,              # 本次曝光的候选 item
  "label_click": 1,                    # 是否点击 (全空间)
  "label_conv": 0,                     # 是否转化 (全空间, 未点击必 0)
  "label_finish": 1,                   # 是否完播/长停留
  "context": {...}                     # 时间/场景等上下文 (略)
}
```

item_id 在离线阶段已用 RQ-VAE 映射为 SID：`item_id -> sid=(c1..cL)`。这张映射表（`item2sid`）是把 SID 接进任何下游模型的**唯一桥梁**。

### 2.15.2 特征侧：item_id → SID 的查表

```python
import torch

class Item2SID:
    """离线产出的 item_id -> [L] 码 映射表的封装。
    未知/新 item 走冷启动 fallback (见第06章 HY-Token 冷启动路径)。
    """
    def __init__(self, item2sid: dict, num_levels: int, fallback=0):
        self.num_levels = num_levels
        self.fallback = fallback
        # 预建成 tensor 便于批量 gather; 这里用 dict 演示
        self.table = item2sid

    def lookup(self, item_ids):
        """item_ids: List[int] 或 [B] / [B, T] 的 python 列表 -> 同形状 + [L]。"""
        def one(i):
            return self.table.get(int(i),
                                  [self.fallback] * self.num_levels)
        if isinstance(item_ids, int):
            return one(item_ids)
        if item_ids and isinstance(item_ids[0], list):
            return [[one(i) for i in row] for row in item_ids]
        return [one(i) for i in item_ids]
```

```python
from torch.utils.data import Dataset, DataLoader

        # 左侧 padding, padding 位用 item 0 的 SID (或专门的 PAD 码)
        hist = [0] * pad + hist

        hist_ids = self._pad_hist(s["hist_item_ids"])
        hist_sid = self.item2sid.lookup(hist_ids)          # [T, L]
        tgt_sid = self.item2sid.lookup(s["target_item_id"])# [L]
        labels = [s["label_click"], s["label_conv"], s["label_finish"]]
        return (torch.tensor(hist_sid),
                torch.tensor(tgt_sid),
                torch.tensor(labels, dtype=torch.float))

def make_loader(samples, item2sid, batch_size=512, shuffle=True):
    ds = MTLDataset(samples, item2sid)
    return DataLoader(ds, batch_size=batch_size, shuffle=shuffle, num_workers=4)
```

### 2.15.4 完整训练脚本（含验证与早停）

```python
def run_training(train_samples, valid_samples, item2sid,
                 num_levels=5, codebook_size=256, epochs=10, lr=1e-3,
                 task_weights=(1.0, 1.0, 0.5), patience=2, device='cpu'):
    train_loader = make_loader(train_samples, item2sid, shuffle=True)
    valid_loader = make_loader(valid_samples, item2sid, shuffle=False)
    model = MMoEWithSID(num_levels=num_levels, codebook_size=codebook_size,
                        num_experts=4, num_tasks=3).to(device)
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    tw = torch.tensor(task_weights, device=device)

    best_gauc, bad = -1.0, 0
    for ep in range(epochs):
        model.train()
        for hist, tgt, y in train_loader:
            hist, tgt, y = hist.to(device), tgt.to(device), y.to(device)
            logits = model(hist, tgt)
            per_task = F.binary_cross_entropy_with_logits(
                logits, y, reduction='none').mean(0)
            loss = (tw * per_task).sum()
            opt.zero_grad(); loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), 5.0)  # 多任务防震荡
            opt.step()

        gaucs = evaluate_gauc(model, valid_loader, device)          # 见 2.16
        mean_gauc = sum(gaucs) / len(gaucs)
        print(f"epoch {ep}: per_task_gauc={['%.4f'%g for g in gaucs]}, mean={mean_gauc:.4f}")
        if mean_gauc > best_gauc:
            best_gauc, bad = mean_gauc, 0
            torch.save(model.state_dict(), "mmoe_sid_best.pt")
        else:
            bad += 1
            if bad >= patience:
                print(f"早停于 epoch {ep}, best mean GAUC={best_gauc:.4f}")
                break
    return model
```

## 2.16 评估：GAUC 的完整实现

多任务推荐**必须看 GAUC（分组 AUC）**，而非全局 AUC。原因：全局 AUC 把不同用户混在一起排序，会被"用户间的活跃度差异"污染；GAUC 按用户分组算 AUC 再按曝光数加权平均，衡量的是**同一用户内**的排序能力，更贴近线上体验。

$$
\text{GAUC} = \frac{\sum_{u} w_u \cdot \text{AUC}_u}{\sum_u w_u}, \qquad
w_u = \#\text{impressions}_u
$$

```python
import numpy as np
from collections import defaultdict

def _auc(labels, scores):
    """单组 AUC (Mann-Whitney U 等价实现)。全正或全负返回 None (跳过)。"""
    order = np.argsort(scores)
    ranks = np.empty_like(order, dtype=float)
    ranks[order] = np.arange(1, len(scores) + 1)
    pos = labels == 1
    n_pos, n_neg = pos.sum(), (~pos).sum()
    if n_pos == 0 or n_neg == 0:
        return None
    auc = (ranks[pos].sum() - n_pos * (n_pos + 1) / 2) / (n_pos * n_neg)
    return auc

@torch.no_grad()
def evaluate_gauc(model, loader, device='cpu', user_key=None):
    """返回每个任务的 GAUC。这里演示用 batch 内简单分组;
    真实需按 user_id 聚合全量预测再分组。"""
    model.eval()
    # 收集 (task -> user -> [(label, score)])
    buf = [defaultdict(list) for _ in range(3)]
    gid = 0
    for hist, tgt, y in loader:
        hist, tgt = hist.to(device), tgt.to(device)
        logits = torch.sigmoid(model(hist, tgt)).cpu().numpy()   # [B, T]
        y = y.numpy()
        for b in range(len(y)):
            u = gid; gid += 1  # 占位: 实际用真实 user_id
            for t in range(3):
                buf[t][u].append((y[b, t], logits[b, t]))
    gaucs = []
    for t in range(3):
        num, den = 0.0, 0.0
        for u, rows in buf[t].items():
            labels = np.array([r[0] for r in rows])
            scores = np.array([r[1] for r in rows])
            a = _auc(labels, scores)
            if a is None:
                continue
            num += len(rows) * a; den += len(rows)
        gaucs.append(num / den if den > 0 else 0.5)
    return gaucs
```

> **注意**：上面为演示，把每条样本当成一个"用户组"是不对的（GAUC 需要每组内有多条样本）。真实实现要**按 user_id 聚合该用户的全部曝光**再算组内 AUC。工程上常先落地全量 `(user_id, task, label, score)`，再用 SQL/Spark 分组算 GAUC。

## 2.17 进阶：多层 PLE（CGC → Progressive）

单层 PLE 的基本单元叫 **CGC（Customized Gate Control）**。把 CGC 堆叠多层，让共享/专属表征**逐层渐进抽取**，就是完整的 PLE。

```python
class CGCLayer(nn.Module):
    """单层 CGC: 输出每个任务的表征 + 一个更新后的共享表征。"""
    def __init__(self, in_dim, hidden, num_tasks, n_shared=2, n_specific=1):
        super().__init__()
        self.num_tasks, self.n_shared, self.n_specific = num_tasks, n_shared, n_specific
        def mlp(): return nn.Sequential(nn.Linear(in_dim, hidden), nn.ReLU())
        self.shared = nn.ModuleList([mlp() for _ in range(n_shared)])
        self.specific = nn.ModuleList([
            nn.ModuleList([mlp() for _ in range(n_specific)]) for _ in range(num_tasks)])
        self.task_gates = nn.ModuleList([
            nn.Linear(in_dim, n_specific + n_shared) for _ in range(num_tasks)])
        # 共享塔也有自己的门控 (看到所有专家), 供堆叠时向上传
        self.shared_gate = nn.Linear(in_dim, n_shared + num_tasks * n_specific)

    def forward(self, task_inputs, shared_input):
        shared_out = [e(shared_input) for e in self.shared]             # n_shared × [B,H]
        all_specific = []
        task_reps = []
        for t in range(self.num_tasks):
            spec = [e(task_inputs[t]) for e in self.specific[t]]        # n_specific × [B,H]
            all_specific += spec
            experts = torch.stack(spec + shared_out, dim=1)            # [B, S+Sh, H]
            w = F.softmax(self.task_gates[t](task_inputs[t]), -1)
            task_reps.append((w.unsqueeze(-1) * experts).sum(1))       # [B,H]
        # 更新共享表征 (供下一层)
        all_experts = torch.stack(all_specific + shared_out, dim=1)
        ws = F.softmax(self.shared_gate(shared_input), -1)
        new_shared = (ws.unsqueeze(-1) * all_experts).sum(1)
        return task_reps, new_shared


class MultiLayerPLEWithSID(nn.Module):
    def __init__(self, num_levels=5, codebook_size=256, dim=128,
                 n_layers=2, hidden=256, num_tasks=3):
        super().__init__()
        self.sid_emb = SIDEmbedding(num_levels, codebook_size, dim, agg='sum')
        in_dim = dim * 2
        dims = [in_dim] + [hidden] * n_layers
        self.layers = nn.ModuleList([
            CGCLayer(dims[i], hidden, num_tasks) for i in range(n_layers)])
        self.towers = nn.ModuleList([
            nn.Sequential(nn.Linear(hidden, 64), nn.ReLU(), nn.Linear(64, 1))
            for _ in range(num_tasks)])
        self.num_tasks = num_tasks

    def forward(self, history_sids, target_sid):
        hist = self.sid_emb(history_sids).mean(1)
        cand = self.sid_emb(target_sid)
        x = torch.cat([hist, cand], -1)
        task_inputs = [x] * self.num_tasks
        shared = x
        for layer in self.layers:
            task_inputs, shared = layer(task_inputs, shared)
        return torch.stack(
            [self.towers[t](task_inputs[t]).squeeze(-1) for t in range(self.num_tasks)], -1)
```

> **Progressive 的含义**：底层 CGC 抽取"通用共享 + 粗任务特征"，高层 CGC 在此基础上进一步分化。层数不是越多越好——2~3 层通常够，过深反而难训。

## 2.18 进阶损失：DWA 动态权重平均 + 完整训练整合

除了 2.8 的方法，**DWA（Dynamic Weight Average）** 用相邻两轮 loss 的下降速率反比来调权，实现简单、无需额外反传：

$$
w_t^{(k)} = T\cdot\frac{\exp(r_t^{(k-1)}/T)}{\sum_j \exp(r_j^{(k-1)}/T)}, \quad
r_t^{(k-1)} = \frac{\ell_t^{(k-1)}}{\ell_t^{(k-2)}}
$$

下降慢的任务 $r_t$ 大 → 权重大，自动"扶弱"。

```python
class DWA:
    def __init__(self, num_tasks, temp=2.0):
        self.T = temp; self.num_tasks = num_tasks
        self.prev = None; self.prev2 = None

    def weights(self):
        if self.prev is None or self.prev2 is None:
            return torch.ones(self.num_tasks)
        r = torch.tensor([self.prev[t] / (self.prev2[t] + 1e-8)
                          for t in range(self.num_tasks)])
        w = self.num_tasks * torch.softmax(r / self.T, dim=0)
        return w

    def update(self, epoch_losses):     # List[float] 本轮各任务平均 loss
        self.prev2 = self.prev
        self.prev = epoch_losses
```

整合进训练：每个 epoch 末用 `DWA.update(per_task_epoch_loss)`，下个 epoch 用 `DWA.weights()` 当 `task_weights`。

```python
class DecoupledMMoESID(MMoEWithSID):
    """把 encode 拆成'用户侧一次'和'候选侧批量', 千级候选打分时省算力。"""
    @torch.no_grad()
    def score_candidates(self, history_sids_one, cand_sids_many):
        # history_sids_one: [1, T, L]; cand_sids_many: [C, L]
        hist = self.sid_emb(history_sids_one).mean(1)         # [1, D] 只算一次
        cand = self.sid_emb(cand_sids_many)                   # [C, D]
        hist = hist.expand(cand.size(0), -1)                  # 广播到 C
        x = torch.cat([hist, cand], -1)                       # [C, 2D]
        expert_out = torch.stack([e(x) for e in self.experts], 1)
        outs = []
        for gate, tower in zip(self.gates, self.towers):
            w = F.softmax(gate(x) / self.gate_temp, -1)
            outs.append(tower((w.unsqueeze(-1) * expert_out).sum(1)).squeeze(-1))
        return torch.stack(outs, -1)                          # [C, num_tasks]
```

## 2.20 扩展面试 Q&A

**Q8：GAUC 和 AUC 有什么区别？多任务为什么必须看 GAUC？**
A：AUC 是全局排序，把所有用户样本混在一起，会被用户间活跃度差异污染；GAUC 按用户分组算组内 AUC，再按曝光数加权，衡量同一用户内的排序能力，更贴近线上体验。多任务里每个任务都要分别看 GAUC，才能发现某个任务是否被跷跷板牺牲。

**Q9：ESMM 里如果某个 item 从未被点击过，pCVR 还能学到吗？**
A：能，而且这正是 ESMM + SID 的优势。ESMM 在全空间通过 pCTCVR=pCTR×pCVR 间接约束 pCVR；SID 让该 item 借粗层共享码从"同类被转化过的 item"迁移到 CVR 表征。纯 ID + 单独 CVR 建模则几乎学不到。

**Q10：PLE 的层数、专家数怎么定？**
A：层数 2~3 起步（过深难训）；共享专家 + 每任务 1~2 个专属专家起步。核心看监控：门控是否分化、跷跷板是否缓解。别一上来堆很大，先小后大、按指标加。

**Q11：多任务模型上线后某个任务突然掉点，怎么排查？**
A：①先看是不是 SID 版本不一致（离线/线上码错位）；②看该任务门控分布是否突变（专家坍塌）；③看码本利用率是否恶化（底座退化）；④看数据分布/物料是否漂移；⑤看权重/loss 尺度是否被其他任务挤压。

**Q12：为什么 SID 的 sum 聚合能保留层次语义？concat 呢？**
A：sum 聚合 $\sum_l e_l[c_l]$ 与 RQ-VAE 重建 $z\approx\sum_l \text{cb}_l[c_l]$ 同构，天然保留"粗层管大类、细层管残差"的层次；concat 保留每层独立子空间、表达力更强但参数多、需线性投影融合。精排常用 concat，召回/底座常用 sum。

## 2.21 本章小结（完整版）

1. **动机**：业务漏斗决定多目标，多任务是刚需。
2. **矛盾**：共享参数上多任务梯度负内积 → 跷跷板。
3. **架构**：Shared-Bottom → MMoE → PLE/CGC（多层），逐步分离共享/专属。
4. **CVR 偏差**：ESMM 全空间 pCTR×pCVR 解 SSB。
5. **SID 价值**：层次共享码本 → 长尾稳、参数省、冷启动友好、层次可与共享/专属对齐。
6. **损失**：固定加权 → 不确定性/DWA → GradNorm → PCGrad，架构优先于优化优先于调权。
7. **工程**：GAUC 评估、门控/梯度/码本监控、SID 版本一致、打分解耦、冷启动回退。

把这套"架构—损失—SID—工程"的闭环讲清楚，多任务推荐的面试与落地就都拿下了。

## 2.22 从零实现：不用框架看清 MMoE 前向（教学版）

为了彻底看清 MMoE 的数据流，这里用 **纯 numpy** 手写一次前向，不依赖 PyTorch 的自动微分。读懂它，你就再也不会对"门控如何加权专家"感到模糊。

```python
import numpy as np

def softmax(x, axis=-1):
    x = x - x.max(axis=axis, keepdims=True)
    e = np.exp(x)
    return e / e.sum(axis=axis, keepdims=True)

def relu(x):
    return np.maximum(0, x)

class NumpyMMoE:
    """纯 numpy MMoE 前向。参数随机初始化, 仅用于理解数据流与形状。"""
    def __init__(self, in_dim, hidden, n_experts, n_tasks, seed=0):
        rng = np.random.default_rng(seed)
        s = 0.1
        # 每个专家: in_dim -> hidden -> hidden
        self.W_e1 = [rng.normal(0, s, (in_dim, hidden)) for _ in range(n_experts)]
        self.W_e2 = [rng.normal(0, s, (hidden, hidden)) for _ in range(n_experts)]
        # 每个任务的门控: in_dim -> n_experts
        self.W_g = [rng.normal(0, s, (in_dim, n_experts)) for _ in range(n_tasks)]
        # 每个任务的塔: hidden -> 1
        self.W_t = [rng.normal(0, s, (hidden, 1)) for _ in range(n_tasks)]
        self.n_experts, self.n_tasks = n_experts, n_tasks

    def forward(self, x):                       # x: [B, in_dim]
        # 1) 专家前向: 得到 [B, E, hidden]
        expert_out = np.stack(
            [relu(relu(x @ We1) @ We2) for We1, We2 in zip(self.W_e1, self.W_e2)],
            axis=1)                             # [B, E, H]
        logits = []
        gates = []
        for Wg, Wt in zip(self.W_g, self.W_t):
            # 2) 门控: [B, E]
            g = softmax(x @ Wg, axis=-1)        # [B, E]
            gates.append(g)
            # 3) 加权混合专家: [B, H]
            mixed = (g[:, :, None] * expert_out).sum(axis=1)
            # 4) 塔: [B, 1]
            logits.append(mixed @ Wt)
        return np.concatenate(logits, axis=1), np.stack(gates, axis=1)  # [B,T], [B,T,E]

# 跑一次看形状
if __name__ == "__main__":
    x = np.random.default_rng(1).normal(size=(4, 16))
    m = NumpyMMoE(in_dim=16, hidden=32, n_experts=4, n_tasks=3)
    logits, gates = m.forward(x)
    print("logits 形状:", logits.shape)   # (4, 3)
    print("门控 形状:", gates.shape)      # (4, 3, 4)
    print("任务0 的门控 (每行和为1):\n", gates[:, 0, :])
```

**数据流四步**（背下来，面试白板能写）：
1. 输入过 $E$ 个专家 → `[B, E, H]`；
2. 每个任务的门控对输入做 softmax → `[B, E]`；
3. 门控加权求和专家输出 → `[B, H]`；
4. 各任务塔输出预估 → `[B, 1]`。

SID 只改变第 0 步的 `x`（从 ID embedding 变成层次码 embedding），后面完全一样。

## 2.23 一个可复现的消融实验设计

要证明"SID + PLE"确实优于"ID + Shared-Bottom"，需要**控制变量的消融**。下面是实验矩阵与该记录的指标（配合 [GR 第07章 实验模版](../../GR研究/GR/第07章-复盘与实验/第07章-02-实验模版.md) 的记录法）。

### 2.23.1 实验矩阵

| 实验 | 底座输入 | 架构 | 损失 | 目的 |
| :--- | :--- | :--- | :--- | :--- |
| A（基线） | ID embedding | Shared-Bottom | 固定加权 | 对照 |
| B | ID embedding | MMoE | 固定加权 | 看架构增益 |
| C | **SID** | MMoE | 固定加权 | 看 SID 增益 |
| D | SID | **PLE** | 固定加权 | 看 PLE 增益 |
| E | SID | PLE | **不确定性加权** | 看损失增益 |

### 2.23.2 该看的指标（分层）

- **整体**：各任务 GAUC、组合分对齐线上目标的相关性。
- **长尾切片**：按 item 曝光频次分桶（热门/中频/长尾），分别看 GAUC —— **SID 的增益应主要体现在长尾桶**。
- **冷启动切片**：新品上架 N 天内的各任务 GAUC —— SID 应显著优于随机 ID。
- **健康度**：门控熵、梯度余弦、码本利用率。

### 2.23.3 预期结论（用于对照你的实验）

- B > A：MMoE 缓解冲突，整体 GAUC 升。
- C > B：SID 主要在**长尾/冷启动切片**上拉开差距，整体也升。
- D > C：跷跷板严重时 PLE 进一步提升，尤其冲突任务对。
- E ≥ D：损失自适应带来小幅稳态提升，主要是省了调权成本。

> **关键**：如果 C 相对 B 的增益**没有集中在长尾**，要怀疑 SID 底座是否健康（码本坍塌？），而不是简单归因"SID 没用"。

## 2.25 练习题（含参考答案）

**练习 1**：证明当两个任务梯度 $g_1,g_2$ 满足 $g_2=-g_1$ 时，Shared-Bottom 的合梯度为零，参数无法更新。
> 答：$\nabla_\theta\mathcal L=w_1 g_1+w_2 g_2=(w_1-w_2)g_1$。当 $w_1=w_2$ 时为零向量，参数不动；即使 $w_1\ne w_2$，也只能沿 $g_1$ 方向，完全牺牲另一个任务的独立需求。这正是需要分离参数（MMoE/PLE）的根因。

**练习 2**：把 2.5 的 `MMoEWithSID` 的历史聚合从 `mean` 换成 2.9.2 的 target-attention，写出 `encode` 的新实现。
> 答：见 2.9.2 `TargetAttentionSID`；在 `encode` 里 `hist = self.attn(self.sid_emb(history_sids), self.sid_emb(target_sid))` 替换 `.mean(dim=1)`。

**练习 3**：ESMM 中若错误地对 pCVR 直接加 BCE，会发生什么？
> 答：pCVR 的标签只在点击样本上有定义，直接监督等于在"点击空间"训练 CVR，重新引入样本选择偏差，线上对未点击 item 的 pCVR 预估失真；同时破坏 pCTCVR=pCTR×pCVR 的全空间无偏性。

**练习 4**：设计一个监控，能在门控退化（MMoE 变 Shared-Bottom）时报警。
> 答：计算各任务门控分布两两的 JS 散度（或所有任务门控的平均熵）。若任务间门控 JS 散度长期趋近 0（或熵趋近 $\log E$ 且各任务几乎相同），说明专家未分化，报警。

**练习 5**：为什么 SID 的粗层适合共享专家、细层适合专属专家？
> 答：粗层码被大量 item 共享、编码品类级信息，是跨任务通用的；细层码编码个性化残差，任务对细节的偏好不同（点击看封面、转化看价格），更适合任务专属通道。见 2.9.1。

## 2.27 进阶话题：多任务 SID 训练中的过拟合与正则化

### 2.27.1 过拟合的根源

多任务 SID 训练容易过拟合的三个原因：
1. **任务异质**：CTR/CVR/时长目标差异大。

### 2.27.3 早停与多任务平衡

```python
class MTLEarlyStopping:
    """多任务早停"""
    def __init__(self, patience=3, min_delta=0.001):
        self.patience = patience
        self.min_delta = min_delta
        self.best_score = -1
        self.counter = 0

    def __call__(self, current_scores):
        """current_scores: 每个任务的 GAUC"""
        # 用平均 GAUC 作为指标
        avg = sum(current_scores) / len(current_scores)

        if avg > self.best_score + self.min_delta:
            self.best_score = avg
            self.counter = 0
            return False  # 不停止
        else:
            self.counter += 1
            return self.counter >= self.patience  # 达到 patience 则停止
```

## 2.28 进阶话题：多任务 SID 与强化学习的结合

### 2.28.1 场景

推荐系统最终目标是**长期用户价值**（LTV / 留存），但短期优化的是 CTR/CVR。如何让多任务模型既优化短期又兼顾长期？

**答案**：用强化学习（RL）做"任务权重调度"。

### 2.28.2 简化方案：基于 PPO 的多任务权重

```python
class PPOWeightScheduler:
    """用 PPO 自动调节多任务权重"""
    def __init__(self, num_tasks, lr=1e-4):
        self.num_tasks = num_tasks
        # 策略网络: 输入是各任务当前 loss, 输出是新权重
        self.policy = nn.Sequential(
            nn.Linear(num_tasks, 32), nn.ReLU(),
            nn.Linear(32, num_tasks), nn.Softmax(dim=-1)
        )
        self.optimizer = torch.optim.Adam(self.policy.parameters(), lr=lr)

    def get_weights(self, current_losses):
        """根据当前 loss 输出权重"""
        losses_t = torch.tensor(current_losses, dtype=torch.float32)
        return self.policy(losses_t).detach().numpy()

    def update(self, current_losses, reward):
        """用 PPO 更新策略"""
        # reward: 综合指标（如线上 GMV 增量）
        losses_t = torch.tensor(current_losses, dtype=torch.float32)
        weights = self.policy(losses_t)
        # 简化: 用 reward 作为 baseline
        advantage = reward
        loss = -torch.log(weights.mean() + 1e-9) * advantage
        self.optimizer.zero_grad()
        loss.backward()
        self.optimizer.step()
```

## 2.29 进阶话题：联邦多任务 SID

### 2.29.1 场景

多个业务方（电商 / 短视频 / 新闻）想共建 SID，但数据不能共享。

**方案**：联邦学习。

```python
class FederatedMTLSID:
    """联邦多任务 SID"""
    def __init__(self, parties=['ecommerce', 'video', 'news']):
        self.parties = parties
        self.local_models = {p: MMoEWithSID(...) for p in parties}
        self.global_codebook = None

    def train_round(self):
        """一轮联邦训练"""
        # 1. 各方本地训练
        local_updates = {}
        for party in self.parties:
            update = self.local_models[party].train_one_epoch()
            local_updates[party] = update

        # 2. 联邦聚合 (FedAvg)
        global_update = average(local_updates.values())

        # 3. 分发到各方
        for party in self.parties:
            self.local_models[party].apply_update(global_update)
```

```python
def check_significance(control_ctr, treatment_ctr, n_control, n_treatment):
    """检查 CTR 提升是否显著"""
    from scipy import stats
    p_pool = (control_ctr * n_control + treatment_ctr * n_treatment) / (n_control + n_treatment)
    se = np.sqrt(p_pool * (1 - p_pool) * (1/n_control + 1/n_treatment))
    z = (treatment_ctr - control_ctr) / se
    p_value = 2 * (1 - stats.norm.cdf(abs(z)))
    return p_value < 0.05
```

## 2.33 进阶：多任务 SID 的"任务语义对齐"

### 2.33.1 概念

不同任务对 SID 层次的需求不同：
- **CTR**：关注粗层（哪些大类用户爱点）
- **CVR**：关注中层（具体子类转化）
- **时长**：关注细层（具体内容差异）

### 2.33.2 层次感知的多任务门控

```python
class HierarchicalTaskGate(nn.Module):
    """层次感知的多任务门控"""
    def __init__(self, num_layers=5, dim=128, num_tasks=3):
        super().__init__()
        # 每层有独立的门控
        self.layer_gates = nn.ModuleList([
            nn.Linear(dim, num_tasks) for _ in range(num_layers)
        ])

    def forward(self, sid_emb_per_layer, task_idx):
        """
        sid_emb_per_layer: [L, B, D]
        task_idx: int
        返回: 任务 task_idx 在每层的权重
        """
        layer_weights = []
        for l in range(self.num_layers):
            gate_logits = self.layer_gates[l](sid_emb_per_layer[l])
            # 取当前任务的权重
            w = F.softmax(gate_logits, dim=-1)[task_idx]
            layer_weights.append(w)
        return layer_weights
```

### 2.33.3 实际应用

**洞察**：CTR 任务在粗层码上权重更大，CVR 在中层，时长在细层。

**应用**：训练时记录每层每任务的重要性，做"层次对齐损失"。

## 2.40 进阶：MMoE vs PLE 的数学本质对比

### 2.40.1 参数空间分析

**MMoE 的参数共享**：
- 专家网络：$E$ 个，参数 $\theta_e$
- 每个任务的门控：$W_t$，参数 $\phi_t$
- 总参数：$O(E \cdot H + T \cdot E \cdot d)$

**PLE 的参数共享**：
- 共享专家：$E_s$ 个，参数 $\theta_s$
- 任务专属专家：$T \cdot E_p$ 个，参数 $\theta_p$
- 门控：每个任务 $T$ 个，参数 $\phi_t$
- 总参数：$O((E_s + T \cdot E_p) \cdot H + T \cdot (E_s + E_p) \cdot d)$

**对比**：PLE 比 MMoE 多 $T \cdot E_p \cdot H$ 个参数（任务专属专家）。当 $T=3, E_p=1, H=256$ 时，多约 768 参数。这点参数增加通常值得。

### 2.40.2 信息流分析

MMoE 的信息流：
```text
任务 t → 门控 t → 所有专家 → 任务塔 t
                ↑
                所有任务共享
```

PLE 的信息流：
```text
任务 t → 门控 t → {共享专家 ∪ 任务专属专家 t} → 任务塔 t
                  ↑                  ↑
                  所有任务共享       仅任务 t
```

**关键区别**：MMoE 的所有专家都被所有任务共享，PLE 的任务专属专家**只服务于特定任务**。这避免了"任务 A 的私货污染任务 B"。

### 2.40.3 优化难度

MMoE 更容易优化（参数少、结构简单）。PLE 更难调（参数多），但表达力强。

经验：**任务冲突严重时 PLE > MMoE；任务高度相关时 MMoE 够用**。

## 2.41 进阶：任务塔设计的细节

### 2.41.1 任务塔的深度

- **浅塔**（2 层）：任务简单时够用。
- **深塔**（3-4 层）：任务复杂时提升表达力。
- **超深塔**（>5 层）：易过拟合，需大量数据。

### 2.41.2 任务塔的宽度

- **窄塔**（64-128 维）：参数少，防过拟合。
- **宽塔**（256-512 维）：表达力强，需要更多数据。

### 2.41.3 任务塔的激活函数

- **ReLU**：常用。
- **GELU**：更平滑。
- **Swish**：Google 提出，自门控。
- **Dice**：阿里提出，参数化激活。

### 2.41.4 任务塔的批归一化

- **BN**：训练时稳定。
- **LN**：序列场景更合适。
- **不归一化**：任务塔较深时需要。

#### 策略 3: 梯度模长反比

```python
# 监控梯度模长, 让各任务梯度相当
class GradientBalancedWeights:
    def __init__(self, num_tasks, target_norm=1.0):
        self.target_norm = target_norm
        self.task_norms = [0] * num_tasks
        self.weights = [1.0] * num_tasks

    def update(self, norms):
        for i, n in enumerate(norms):
            self.task_norms[i] = 0.9 * self.task_norms[i] + 0.1 * n
            self.weights[i] = self.target_norm / (self.task_norms[i] + 1e-9)
```

### 2.42.2 Focal Loss 解决类别不平衡

```python
class FocalLoss(nn.Module):
    """Focal Loss 用于 CTR 等不平衡任务"""
    def __init__(self, alpha=0.25, gamma=2.0):
        super().__init__()
        self.alpha = alpha
        self.gamma = gamma

    def forward(self, logits, targets):
        bce = F.binary_cross_entropy_with_logits(logits, targets, reduction='none')
        p = torch.sigmoid(logits)
        p_t = p * targets + (1 - p) * (1 - targets)
        alpha_t = self.alpha * targets + (1 - self.alpha) * (1 - targets)
        focal_weight = alpha_t * (1 - p_t) ** self.gamma
        return (focal_weight * bce).mean()
```

### 2.42.3 多任务 Softmax Loss

```python
class MultiTaskSoftmaxLoss(nn.Module):
    """多任务 softmax loss, 用于多分类任务"""
    def __init__(self, num_classes_per_task):
        super().__init__()
        self.ce = nn.CrossEntropyLoss()
        self.num_classes_per_task = num_classes_per_task

    def forward(self, logits, targets):
        # logits: [B, sum(num_classes)] 多任务拼接
        # targets: dict {task: labels}
        offset = 0
        losses = []
        for task, n_cls in zip(targets.keys(), self.num_classes_per_task):
            task_logits = logits[:, offset:offset+n_cls]
            task_targets = targets[task]
            losses.append(self.ce(task_logits, task_targets))
            offset += n_cls
        return sum(losses) / len(losses)
```

## 2.46 章节配套 FAQ

### 2.46.1 训练类

**Q**: 多任务训练时，某个任务突然不收敛怎么办？

**A**: 检查：(1) 是否被其他任务梯度主导；(2) 数据是否有异常；(3) 学习率是否过大；(4) 该任务权重是否过低。修复：降权 / 升温 / 单独训练。

**Q**: MMoE 和 PLE 该选哪个？

**A**: 任务数 ≤ 3 且相关性高 → MMoE；任务数 > 3 或跷跷板严重 → PLE。

**Q**: 多任务训练的 batch size 怎么设？

**A**: 单任务 × 任务数（如单任务 256，三任务 768）。梯度累积可以模拟大 batch。

### 2.46.2 效果类

**Q**: SID vs raw ID 在多任务下的具体提升？

**A**: Meta HSTU 实验 +38% Recall@10；冷启动 +458%。

**Q**: 任务相关性怎么衡量？

**A**: 任务梯度的 cosine 相似度（§2.2）。cos < 0 表示冲突。

**Q**: 不确定性加权 vs GradNorm vs PCGrad 选哪个？

**A**: 任务量纲差异大 → UW；收敛速度差异大 → GradNorm；冲突严重 → PCGrad。

### 2.46.3 部署类

**A**: ①专家数控制；②任务塔共享；③稀疏激活；④量化。

**Q**: 多任务模型的在线学习怎么做？

**A**: 增量训练（partial fit）+ 在线学习率衰减。

**Q**: 多任务模型的 A/B 测试怎么做？

**A**: 流量分桶 + 综合指标（CTR + CVR + GMV）评估。

## 2.47 进阶：多任务 SID 与 Graph Neural Network 结合

### 2.47.1 思路

把物品-物品协同信号建模为图（GNN），再用 GNN 输出作为 SID 训练的额外监督。

```python
class GNAugmentedMTLSID(nn.Module):
    """图增强的多任务 SID"""
    def __init__(self, sid_model, gnn_model, mtl_model):
        super().__init__()
        self.sid_model = sid_model
        self.gnn_model = gnn_model  # PinSage / LightGCN
        self.mtl_model = mtl_model

    def forward(self, history_ids, target_id, graph_neighbors):
        # 1. SID 编码
        hist_sid = self.sid_model.encode(history_ids)
        tgt_sid = self.sid_model.encode(target_id)

        # 2. GNN 编码（额外信号）
        gnn_emb = self.gnn_model(target_id, graph_neighbors)

        # 3. 融合
        combined = sid_emb + 0.3 * gnn_emb  # SID 为主, GNN 为辅

        # 4. 多任务预测
        return self.mtl_model(combined)
```

### 2.47.2 优势

- GNN 提供协同信号，弥补纯内容 embedding。
- SID 提供语义结构，弥补纯协同信号。
- 两者结合 = 更鲁棒的表征。

详见 [第 10 章-03 SID 与知识蒸馏](第10章-03-SID与知识蒸馏.md)。

### 2.48.1 系统架构

```text
       ↓

       ↓

       ↓

       ↓
┌──────┬──────┬──────┐
│ 召回 │ 粗排 │ 精排 │
│(CTR) │(CTR) │(CTR+CVR)│
└──────┴──────┴──────┘
```

### 2.48.2 关键代码

```python
class AlibabaMTLSID(nn.Module):
    """阿里多任务 SID"""
    def __init__(self):
        self.sid_emb = SIDEmbedding(...)
        self.din = DIN(...)  # Target Attention
        self.ple = PLE(...)
        self.tower_recall = Tower(...)
        self.tower_ranking = Tower(...)

    def forward(self, history_ids, target_id):
        hist_sid = self.sid_emb(history_ids)
        tgt_sid = self.sid_emb(target_id)

        # DIN attention
        hist_emb = self.din(hist_sid, tgt_sid)
        cand_emb = tgt_sid

        # PLE
        x = torch.cat([hist_emb, cand_emb], dim=-1)
        ple_out = self.ple(x)

        # 多任务塔
        recall_score = self.tower_recall(ple_out)
        ctr_score = self.tower_ranking(ple_out)
        cvr_score = self.tower_cvr(ple_out)

        return recall_score, ctr_score, cvr_score
```
