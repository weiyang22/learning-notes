## 3.1 SID 作为蒸馏目标

```python
class KDWithSID(nn.Module):
    def __init__(self, teacher, student):
        super().__init__()
        self.teacher = teacher  # 大模型
        self.student = student  # 小模型

    def forward(self, x):
        # Teacher 输出 SID 分布
        with torch.no_grad():
            teacher_logits = self.teacher(x)  # [B, K, C]
        # Student 输出
        student_logits = self.student(x)  # [B, K, C]
        # KD 损失
        loss = F.kl_div(
            F.log_softmax(student_logits, dim=-1),
            F.softmax(teacher_logits, dim=-1),
            reduction='batchmean'
        )
        return loss
```

## 3.3 为什么 SID 让蒸馏更好做

传统推荐蒸馏,teacher 输出是稠密 logits/embedding,student 要对齐连续空间,信号弱、易过拟合。**SID 把目标变成离散码字上的分类分布**,带来三个好处:

- **软标签更有结构**:teacher 在每层码本上的概率分布,天然是"这个物品像哪些语义簇",比稠密向量更易学。
- **蒸馏 = 多分类 KD**:退化成经典的逐层交叉熵/KL 蒸馏(见 [rec教程第19章-知识蒸馏](../../经典推荐/第19章-知识蒸馏.md)),工具成熟。
- **对齐维度低**:码本大小 $K$(如 256)远小于 embedding 维度,student 好拟合。

---

## 3.4 三种 SID 蒸馏范式

| 范式 | teacher→student 传什么 | 适合 |
| :--- | :--- | :--- |
| **Logit KD** | 每层码字 softmax 分布(带温度) | 通用,最常用 |
| **特征 KD** | 量化前的连续 embedding | student 也要出 embedding |
| **码本共享** | student 复用 teacher 的码本 | 只蒸生成模型,码本固定 |

```python
# 带温度的逐层 SID 蒸馏 (温度软化分布, 传递"暗知识")
def sid_distill_loss(student_logits, teacher_logits, T=2.0):
    # logits: [B, L层, K码字]
    s = F.log_softmax(student_logits / T, dim=-1)
    t = F.softmax(teacher_logits / T, dim=-1)
    return F.kl_div(s, t, reduction='batchmean') * (T * T)   # T² 补偿梯度尺度
```

> 温度 $T$ 软化分布,让 student 学到"次优码字也有意义"的暗知识(Hinton KD,见 [数学第07章-案例12](../../../基础/数学/数学基础/第07章-系统思维/第07章-12-案例Hinton-KD温度软标签.md))。

## 3.7 蒸馏基础理论的完整推导

## 3.7.1 Hinton 经典 KD 的数学基础

Hinton 2015 蒸馏(Distilling the Knowledge in a Neural Network)的核心思想:用 teacher 的**软概率分布**作为 student 的额外监督。给定 teacher 在温度 $T$ 下的 softmax:

$$
p_i^{(T)} = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}
$$

当 $T=1$ 时退化为普通 softmax, $T \to \infty$ 时趋向均匀分布。**温度的本质**: 把极端概率"压平",使 student 能学到 teacher 在所有类别上的相对偏好,这正是 Hinton 所说的"暗知识"(dark knowledge)。

对于 SID 蒸馏,每层码本都是一个 $K$ 分类问题,teacher 输出 $[B, L, K]$ 的 logits,逐层应用温度 softmax 即可。

## 3.7.2 KL 散度的梯度分析

KL 散度作为蒸馏损失的梯度推导:

$$
\nabla_{\theta_s} \text{KL}(p_t \| p_s) = -\mathbb{E}_{p_t}\left[\nabla_{\theta_s} \log p_s(x)\right]
$$

对每个 token 的 logits $z_i^{(s)}$:

$$
\frac{\partial \text{KL}}{\partial z_i^{(s)}} = \frac{1}{T}\left(p_i^{(s)} - p_i^{(t)}\right)
$$

这是**残差学习**:student 学 teacher 的残差。温度 $T$ 同时缩小 logits 尺度和梯度尺度,需要乘 $T^2$ 补偿。

$$
\mathcal{L}_{\text{KD}} = T^2 \cdot \text{KL}\left(\text{softmax}(z_t/T) \| \text{softmax}(z_s/T)\right)
$$

## 3.7.3 SID 蒸馏的特殊性:层次化软标签

传统 KD 在一个分类头上做软化,SID 蒸馏在 $L$ 个码本头上做软化,**逐层独立或联合**?

| 策略 | 公式 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **逐层独立 KL** | $\sum_l \text{KL}(p_t^{(l)} \| p_s^{(l)})$ | 简单、易并行 | 忽略层间依赖 |
| **联合 KL** | $\text{KL}(p_t^{\otimes L} \| p_s^{\otimes L})$ | 保留层间互信息 | 复杂度 $O(K^L)$,爆炸 |
| **层级加权** | $\sum_l w_l \text{KL}(p_t^{(l)} \| p_s^{(l)})$ | 平衡粗/细层信号 | 需调权重 |
| **互信息蒸馏** | $\text{MI}(s^{(l)}; s^{(l+1)})$ | 显式保留层次结构 | 难训练 |

**实践推荐**: 层级加权 + 粗层权重大。粗层语义稳定,细层高频更新,粗层信号更可靠。

```python
# 层级加权蒸馏
def hierarchical_sid_distill(s_logits, t_logits, weights=None):
    """s_logits, t_logits: [B, L, K]"""
    L = s_logits.size(1)
    if weights is None:
        weights = torch.tensor([1.0, 0.8, 0.6, 0.4, 0.2])[:L]
        weights = weights / weights.sum()
    loss = 0.0
    for l in range(L):
        loss = loss + weights[l] * F.kl_div(
            F.log_softmax(s_logits[:, l] / 2.0, dim=-1),
            F.softmax(t_logits[:, l] / 2.0, dim=-1),
            reduction='batchmean'
        ) * (2.0 ** 2)
    return loss / weights.sum()
```

## 3.8 蒸馏范式的深度对比

## 3.8.1 Logit KD vs Feature KD vs Codebook 共享

### Logit KD(默认范式)

```python
class LogitKD(nn.Module):
    """最常用,只对齐输出分布,不管中间表征。"""
    def __init__(self, teacher, student, T=2.0, alpha=0.7):
        super().__init__()
        self.teacher = teacher
        self.student = student
        self.T = T
        self.alpha = alpha

    def forward(self, x, hard_label):
        with torch.no_grad():
            t_logits = self.teacher(x)  # [B, L, K]
        s_logits = self.student(x)     # [B, L, K]
        soft_loss = hierarchical_sid_distill(s_logits, t_logits)
        hard_loss = F.cross_entropy(s_logits.reshape(-1, s_logits.size(-1)),
                                      hard_label.reshape(-1))
        return self.alpha * soft_loss + (1 - self.alpha) * hard_loss
```

**优点**: teacher 和 student 结构可以完全不同;训练稳定;工具成熟。
**缺点**: 只学输出层,中间层信息丢失。

### Feature KD(中间层对齐)

```python
class FeatureKD(nn.Module):
    """把 teacher 中间层的连续 embedding 也蒸馏给 student,要求两者维度相同。"""
    def __init__(self, teacher, student, feat_dim=64):
        super().__init__()
        self.teacher = teacher
        self.student = student
        # 把 teacher 中间表征投影到 student 维度
        self.t_proj = nn.Linear(teacher.hidden_dim, feat_dim)
        self.s_proj = nn.Linear(student.hidden_dim, feat_dim)

    def forward(self, x):
        with torch.no_grad():
            t_feat = self.teacher.get_intermediate(x)  # [B, T, D_t]
        s_feat = self.student.get_intermediate(x)      # [B, T, D_s]
        # MSE 对齐投影后的特征
        loss = F.mse_loss(self.s_proj(s_feat), self.t_proj(t_feat))
        return loss
```

**优点**: 学生学到 teacher 的"中间思维",效果通常更好(+1~3% Recall)。
**缺点**: 必须有相同/可投影的中间层结构;教师慢,显存压力大。

### Codebook 共享(码本蒸馏)

```python
class SharedCodebookKD(nn.Module):
    """student 复用 teacher 的码本 Embedding,只训生成头。"""
    def __init__(self, teacher_code_embs, student_head):
        super().__init__()
        # 冻结 teacher 码本
        for emb in teacher_code_embs:
            emb.requires_grad_(False)
        self.code_embs = teacher_code_embs
        self.head = student_head

    def forward(self, sid):
        # 用 teacher 的码本 Embedding 拼出 item 特征,送入 student 头
        z = torch.stack([emb(sid[:, l]) for l, emb in enumerate(self.code_embs)], 0).sum(0)
        return self.head(z)
```

**优点**: 极致小;码本一致保证 student 与 teacher 输出同空间。
**缺点**: 必须用同一码本;若 teacher 码本更新,student 要重新对齐。

## 3.8.2 范式选择的决策树

```text
开始
  │
  ├─ 你的 student 结构与 teacher 差异大吗?
  │   ├─ 大 → Logit KD
  │   └─ 小 → Feature KD
  │
  ├─ 你能保证 student 与 teacher 用同一码本吗?
  │   ├─ 是 → Codebook 共享
  │   └─ 否 → Logit KD
  │
  └─ 你的显存允许 teacher 中间特征前向吗?
      ├─ 是 → Feature KD (效果最好)
      └─ 否 → Logit KD
```

## 3.9 蒸馏的损失函数族

## 3.9.1 硬标签 + 软标签混合

经典配方 (Hinton):

$$
\mathcal{L} = \alpha \cdot \mathcal{L}_{\text{soft}}(T) + (1-\alpha) \cdot \mathcal{L}_{\text{hard}}
$$

其中 $\alpha \in [0.5, 0.9]$,软标签权重更高,因为它包含 teacher 的"暗知识"。

```python
def combined_loss(student_logits, teacher_logits, hard_label, T=2.0, alpha=0.7):
    soft = F.kl_div(
        F.log_softmax(student_logits / T, dim=-1),
        F.softmax(teacher_logits / T, dim=-1),
        reduction='batchmean'
    ) * (T * T)
    hard = F.cross_entropy(student_logits, hard_label)
    return alpha * soft + (1 - alpha) * hard
```

## 3.9.2 PKD (Patient Knowledge Distillation)

PKD 让 student 学 teacher 在多个中间层的输出,而非仅最后一层。对于 Transformer 解码器,各层的 attention 模式可以反映"语义组合的不同抽象层次"。

```python
class PKDLoss(nn.Module):
    def __init__(self, teacher, student, n_layers=4, beta=0.1):
        super().__init__()
        self.beta = beta
        self.align = nn.ModuleList([
            nn.Linear(student.hidden, teacher.hidden)
            for _ in range(n_layers)
        ])

    def forward(self, x):
        t_feats = self.teacher.get_all_layers(x)  # list of [B, T, D_t]
        s_feats = self.student.get_all_layers(x)  # list of [B, T, D_s]
        loss = 0
        for t, s, proj in zip(t_feats, s_feats, self.align):
            loss = loss + F.mse_loss(proj(s), t.detach())
        return loss / len(t_feats) * self.beta
```

## 3.9.3 DKD (Decoupled Knowledge Distillation)

DKD (CVPR 2022) 把 KD 拆成**目标类**和**非目标类**两部分,独立加权。动机:对于长尾分类,非目标类的相对排序更重要。

$$
\mathcal{L}_{\text{DKD}} = \alpha \cdot \mathcal{L}_{\text{TC}} + \beta \cdot \mathcal{L}_{\text{NC}}
$$

其中 TC (Target Class) 让 student 在正确类上的概率逼近 teacher,NC (Non-target Class) 让 student 在错误类上的相对分布逼近 teacher。

```python
def dkd_loss(student_logits, teacher_logits, hard_label, alpha=1.0, beta=8.0, T=2.0):
    """Decoupled KD (Zhao et al. CVPR 2022)"""
    s = F.log_softmax(student_logits / T, dim=-1)
    t = F.softmax(teacher_logits / T, dim=-1)

    # 目标类 vs 非目标类
    mask = F.one_hot(hard_label, student_logits.size(-1)).bool()
    t_tc = t * mask.float()
    s_tc = s * mask.float()
    t_nc = t * (~mask).float()
    s_nc = s * (~mask).float()

    # 重新归一化
    t_tc = t_tc / (t_tc.sum(-1, keepdim=True) + 1e-8)
    s_tc = s_tc / (s_tc.sum(-1, keepdim=True) + 1e-8)
    t_nc = t_nc / (t_nc.sum(-1, keepdim=True) + 1e-8)
    s_nc = s_nc / (s_nc.sum(-1, keepdim=True) + 1e-8)

    tc_kl = F.kl_div(s_tc, t_tc, reduction='batchmean') * (T * T)
    nc_kl = F.kl_div(s_nc, t_nc, reduction='batchmean') * (T * T)
    return alpha * tc_kl + beta * nc_kl
```

**在 SID 上的应用**: DKD 让 student 不仅学会"主码字",还学会 teacher 在错误码字上的偏好(比如"虽然主码是 5,但 7 和 9 也不错")。对长尾 item 提升明显。

## 3.9.4 DISTILL 的对比损失

把蒸馏当成"对比学习": student 的样本分布应该和 teacher 相似。

```python
def contrastive_distill(student_emb, teacher_emb, temperature=0.07):
    """让 student 的内积矩阵逼近 teacher 的(余弦相似度矩阵)。"""
    s = F.normalize(student_emb, dim=-1)
    t = F.normalize(teacher_emb, dim=-1)
    sim_s = s @ s.T / temperature
    sim_t = t @ t.T / temperature
    return F.kl_div(F.log_softmax(sim_s, -1), F.softmax(sim_t, -1), reduction='batchmean')
```

## 3.9.5 Self-Distillation (Born-Again Networks)

让 student 和 teacher 结构完全相同,用 teacher 蒸馏 student,student 居然能**超过 teacher**。

```python
# 训练流程:
# 1. 训练 teacher: standard CE
# 2. 训练 student_1: KD from teacher
# 3. 训练 student_2: KD from student_1
# 4. ...重复 N 次
# 学生链式蒸馏,逐步超越 teacher
```

直觉:soft labels 提供"正则化",student 学到的不只是 teacher 的预测,还有 teacher 学到的**知识结构**。

## 3.10 工业级蒸馏 Pipeline

## 3.10.1 离线蒸馏 vs 在线蒸馏

| 维度 | 离线蒸馏 | 在线蒸馏 |
| :--- | :--- | :--- |
| teacher 输出 | 预先算好,存成 TFRecord | 每个 batch 前向 |
| 训练速度 | 快(只训 student) | 慢(双倍前向) |
| 显存占用 | 低 | 高 |
| teacher 更新 | 不同步 | 同步 |
| 适用 | teacher 大, student 中等 | teacher 中等,需持续对齐 |

```python
# 离线蒸馏:teacher logits 存盘
class OfflineKD(Dataset):
    def __init__(self, feat_path, logit_path, label_path):
        self.feats = np.load(feat_path)
        self.logits = np.load(logit_path)  # [N, L, K]
        self.labels = np.load(label_path)

    def __getitem__(self, idx):
        return self.feats[idx], self.logits[idx], self.labels[idx]

# 训练时:student 只需要自己的前向,teacher logits 直接读
for feat, t_logit, label in loader:
    s_logit = student(feat)
    loss = kd_loss(s_logit, t_logit, label)
    loss.backward()
    optimizer.step()
```

```python
# 在线蒸馏:teacher 和 student 同步更新
for x, y in loader:
    with torch.no_grad():  # teacher 不更新
        t_logit = teacher(x)
    s_logit = student(x)
    loss = kd_loss(s_logit, t_logit, y)
    loss.backward()
    optimizer.step()
```

## 3.10.2 蒸馏的训练 Trick

### Trick 1: Early stopping on teacher logits

teacher 训练前期 logits 还在剧烈变化,蒸馏 student 会让学生学到一个"还在动"的目标。用 EMA 保存 teacher logits 的平滑版:

```python
class TeacherLogitEMA:
    def __init__(self, decay=0.999):
        self.decay = decay
        self.ema_logits = None

    def update(self, t_logits):
        if self.ema_logits is None:
            self.ema_logits = t_logits.detach()
        else:
            self.ema_logits.mul_(self.decay).add_(t_logits.detach(), alpha=1 - self.decay)

    def get(self):
        return self.ema_logits
```

### Trick 2: 渐进式蒸馏(从小到大)

先训 small student 蒸馏 large teacher,得到 medium student;再 medium 蒸馏 large teacher → medium 蒸馏 mega teacher。链式蒸馏通常优于一步到位。

### Trick 3: 蒸馏 + 数据增广

对 input 做扰动(RQ-Kmeans 重抽 SID、随机 mask 几层),让 student 看到多样化的输入,学到更鲁棒的特征。

```python
def augment_sid(sid, mask_prob=0.1):
    """随机 mask 几层 SID, 强迫 student 学残差。"""
    mask = torch.rand(sid.shape) > mask_prob
    return sid * mask.long()
```

### Trick 4: 多 teacher 集成

蒸馏 = 教师投票。教师不是单一的,可以是多个模型/多 checkpoint 的集成,提升 student 上限。

```python
class MultiTeacherKD(nn.Module):
    def __init__(self, teachers, student, T=2.0):
        super().__init__()
        self.teachers = nn.ModuleList(teachers)
        self.student = student
        self.T = T

    def forward(self, x):
        with torch.no_grad():
            t_logits_list = [t(x) for t in self.teachers]
            # 平均 soft prediction
            t_avg = torch.stack([F.softmax(t / self.T, dim=-1) for t in t_logits_list]).mean(0)
        s_logits = self.student(x)
        return F.kl_div(F.log_softmax(s_logits / self.T, dim=-1),
                        t_avg, reduction='batchmean') * (self.T ** 2)
```

## 3.10.3 蒸馏的常见失败模式

| 失败模式 | 表现 | 原因 | 解法 |
| :--- | :--- | :--- | :--- |
| **Capacity gap** | student 学不动,效果远低于 teacher | student 太弱 | 加深/加宽 student,或加中间层 hint |
| **Temperature 错** | 分布过尖/过平 | $T$ 没调好 | 在 [1, 10] 网格搜 |
| **Hard label 过强** | student 忽略 soft label | $\alpha$ 太低 | 提高 $\alpha$ 到 0.7~0.9 |
| **Logits 尺度不匹配** | KL 梯度爆炸 | teacher/student logits 数量级差 | 加 batchnorm 或 logit clipping |
| **教师过拟合** | 蒸馏到噪声 | teacher 学到了训练集的偏差 | 检查 teacher 泛化,正则化 |

## 3.11 SID 蒸馏的端到端代码示例

下面给出一个**完整可运行**的最小蒸馏 pipeline,涵盖数据准备、teacher 训练、student 蒸馏、效果评估。

```python
"""SID 蒸馏最小可运行示例 (PyTorch 1.13+)

依赖:
    pip install torch transformers sentence-transformers numpy scikit-learn
"""

import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import Dataset, DataLoader
import numpy as np


# ============================================================
# 1. 数据准备: 用 Sentence-Transformers 生成 embedding, 再做 RQ-Kmeans 得 SID
# ============================================================

def build_sids(items, num_levels=3, codebook_size=256, dim=64):
    """模拟 RQ-Kmeans: 先降到 dim, 再逐层 KMeans 量化残差。"""
    from sklearn.cluster import KMeans
    from sentence_transformers import SentenceTransformer

    model = SentenceTransformer('BAAI/bge-small-zh-v1.5')
    embs = model.encode(items)  # [N, D_orig]
    # 降维到 dim
    from sklearn.decomposition import PCA
    pca = PCA(n_components=dim)
    embs_low = pca.fit_transform(embs)  # [N, dim]

    sids = np.zeros((len(items), num_levels), dtype=np.int64)
    residual = embs_low.copy()
    for l in range(num_levels):
        km = KMeans(n_clusters=codebook_size, n_init=10, random_state=42)
        sids[:, l] = km.fit_predict(residual)
        residual = residual - km.cluster_centers_[sids[:, l]]

    return sids, embs_low


# ============================================================
# 2. Teacher 模型: 大规模 DNN
# ============================================================

class TeacherModel(nn.Module):
    def __init__(self, num_levels=3, codebook_size=256, dim=128, hidden=512):
        super().__init__()
        self.embs = nn.ModuleList([nn.Embedding(codebook_size, dim) for _ in range(num_levels)])
        self.mlp = nn.Sequential(
            nn.Linear(num_levels * dim, hidden), nn.ReLU(), nn.Dropout(0.2),
            nn.Linear(hidden, hidden), nn.ReLU(), nn.Dropout(0.2),
            nn.Linear(hidden, codebook_size ** num_levels),  # 输出所有 SID 组合的 logit
        )

    def forward(self, sid):
        # sid: [B, L]
        x = torch.cat([emb(sid[:, l]) for l, emb in enumerate(self.embs)], dim=-1)
        return self.mlp(x).view(-1, 3, 256)  # [B, L, K]


# ============================================================
# 3. Student 模型: 小型 DNN
# ============================================================

class StudentModel(nn.Module):
    def __init__(self, num_levels=3, codebook_size=256, dim=32, hidden=64):
        super().__init__()
        self.embs = nn.ModuleList([nn.Embedding(codebook_size, dim) for _ in range(num_levels)])
        self.mlp = nn.Sequential(
            nn.Linear(num_levels * dim, hidden), nn.ReLU(),
            nn.Linear(hidden, codebook_size ** num_levels),
        )

    def forward(self, sid):
        x = torch.cat([emb(sid[:, l]) for l, emb in enumerate(self.embs)], dim=-1)
        return self.mlp(x).view(-1, 3, 256)


# ============================================================
# 4. KD 损失
# ============================================================

def kd_loss(student_logits, teacher_logits, hard_label, T=2.0, alpha=0.7):
    """经典 KD 损失 = 软标签 KL + 硬标签 CE"""
    soft = F.kl_div(
        F.log_softmax(student_logits / T, dim=-1),
        F.softmax(teacher_logits / T, dim=-1),
        reduction='batchmean'
    ) * (T * T)
    hard = F.cross_entropy(
        student_logits.reshape(-1, student_logits.size(-1)),
        hard_label.reshape(-1)
    )
    return alpha * soft + (1 - alpha) * hard

def train_teacher(teacher, loader, epochs=10):
    opt = torch.optim.Adam(teacher.parameters(), lr=1e-3)
    teacher.train()
    for ep in range(epochs):
        total_loss = 0
        for sid, label in loader:
            sid, label = sid.cuda(), label.cuda()
            logit = teacher(sid)
            loss = F.cross_entropy(logit.reshape(-1, 256), label.reshape(-1))
            opt.zero_grad(); loss.backward(); opt.step()
            total_loss += loss.item()
        print(f"[Teacher ep{ep}] loss={total_loss/len(loader):.4f}")


def train_student_with_kd(student, teacher, loader, epochs=20, T=2.0, alpha=0.7):
    opt = torch.optim.Adam(student.parameters(), lr=1e-3)
    teacher.eval(); student.train()
    for ep in range(epochs):
        total_loss = 0
        for sid, label in loader:
            sid, label = sid.cuda(), label.cuda()
            with torch.no_grad():
                t_logit = teacher(sid)
            s_logit = student(sid)
            loss = kd_loss(s_logit, t_logit, label, T=T, alpha=alpha)
            opt.zero_grad(); loss.backward(); opt.step()
            total_loss += loss.item()
        print(f"[Student KD ep{ep}] loss={total_loss/len(loader):.4f}")
```

## 3.12.1 Meta HSTU 中的蒸馏实践

Meta 2024 HSTU 论文显示,**大模型 → 小模型 SID 蒸馏**比直接训小模型 Recall@10 高 12%。他们使用:

- **Teacher**: 1B 参数的生成式 Transformer, 5 层 SID 输出
- **Student**: 100M 参数的双塔模型
- **蒸馏损失**: Logit KD + Feature KD 混合
- **温度**: $T=4$ (比 Hinton 默认的 2 大,因为 SID 的分类头数多)
- **关键技巧**: 教师 logit 做**层间平滑**——粗层和细层温度不同。

```python
# Meta HSTU 的层间温度
def hstu_distill_loss(student_logits, teacher_logits):
    L = student_logits.size(1)
    # 粗层温度大(更软),细层温度小(更锐)
    temps = [4.0, 3.0, 2.0, 2.0, 2.0][:L]
    loss = 0
    for l in range(L):
        T = temps[l]
        loss = loss + F.kl_div(
            F.log_softmax(student_logits[:, l] / T, dim=-1),
            F.softmax(teacher_logits[:, l] / T, dim=-1),
            reduction='batchmean'
        ) * (T * T)
    return loss / L
```

## 3.12.2 阿里 DIN-SID 蒸馏

阿里电商用 DIN(Deep Interest Network)+ SID 做粗排蒸馏:

- **Teacher**: DIN with raw item ID, 10亿物品
- **Student**: DIN with SID embedding, 256^5 词表
- **关键改进**: 学生端加**辅助任务**——预测每个 item 的细类目,把"商品理解"知识显式传递给学生

```python
class DINSIDStudent(nn.Module):
    def __init__(self, num_levels=5, codebook_size=256, dim=64, n_categories=1000):
        super().__init__()
        self.sid_embs = nn.ModuleList([nn.Embedding(256, dim) for _ in range(num_levels)])
        self.din = DIN(...)  # DIN backbone
        self.cls_head = nn.Linear(64, 256**5)  # 主任务:SID 预测
        self.cat_head = nn.Linear(64, n_categories)  # 辅助任务:类目预测

    def forward(self, hist_sids, target_sid, target_cat):
        z = torch.cat([emb(hist_sids[:, l]) for l, emb in enumerate(self.sid_embs)], -1)
        feat = self.din(z)
        sid_logit = self.cls_head(feat)
        cat_logit = self.cat_head(feat)
        return sid_logit, cat_logit

        cat_loss = F.cross_entropy(cat_logit, true_cat)
```

## 3.12.3 字节跳动 OneRec 的蒸馏

字节的 OneRec (2024) 用 teacher-student 蒸馏生成式推荐:

- **Teacher**: 7B 参数的生成式 LLM-style 推荐模型,多任务训练(CTR+CVR+时长+留存)
- **Student**: 500M 参数的轻量生成器
- **蒸馏 loss**: 多任务软标签 + 中间层 hidden state 对齐
- **数据**: 用 1000 亿次曝光蒸馏,学生继承教师的"全局多目标权衡"能力

```python
# OneRec 的多任务蒸馏
class OneRecDistill(nn.Module):
    def __init__(self, teacher, student, task_weights):
        super().__init__()
        self.teacher = teacher
        self.student = student
        self.task_weights = task_weights  # {'ctr': 1.0, 'cvr': 0.5, 'dwell': 0.3}

    def forward(self, sid):
        with torch.no_grad():
            t_outputs = self.teacher(sid)  # dict of task logits
        s_outputs = self.student(sid)
        loss = 0
        for task, w in self.task_weights.items():
            t_logit = t_outputs[task]
            s_logit = s_outputs[task]
            loss = loss + w * F.kl_div(
                F.log_softmax(s_logit / 2.0, dim=-1),
                F.softmax(t_logit / 2.0, dim=-1),
                reduction='batchmean'
            ) * 4
        return loss
```

效果: 学生端 Recall@50 +9%, 推理速度 4x, 显存 1/8。

## 3.12.4 Google YouTube 的两阶段蒸馏

YouTube 推荐分两阶段蒸馏:

1. **第一阶段**: 大 teacher → 中 student, 蒸馏"召回能力"
2. **第二阶段**: 中 student 直接线上, 用线上反馈继续蒸馏 → 小 student

```python
class TwoStageDistill:
    def __init__(self, teacher, mid_student, small_student):
        self.teacher = teacher
        self.mid = mid_student
        self.small = small_student

    def stage1_offline(self, dataset):
        """离线蒸馏: teacher → mid"""
        for x, y in dataset:
            t_logit = self.teacher(x)
            s_logit = self.mid(x)
            loss = kd_loss(s_logit, t_logit, y, T=4.0, alpha=0.8)
            loss.backward()
            self.mid_opt.step()

    def stage2_online(self, online_buffer):
        """在线蒸馏: mid → small, 用线上真实反馈"""
        for x, y_online in online_buffer:
            with torch.no_grad():
                m_logit = self.mid(x)
            s_logit = self.small(x)
            loss = kd_loss(s_logit, m_logit, y_online, T=2.0, alpha=0.5)
            loss.backward()
            self.small_opt.step()
```

效果: Recall@100 +6%, 线上 P99 时延从 80ms 降到 35ms。

```python
def diagnose_distillation(teacher, student, val_loader):
    """输出 student 相对 teacher 的差距图,定位问题层。"""
    metrics = {'per_layer_kl': [], 'per_layer_acc': [], 'gap': []}
    teacher.eval(); student.eval()
    with torch.no_grad():
        for sid, label in val_loader:
            t_logit = teacher(sid)
            s_logit = student(sid)
            for l in range(sid.size(1)):
                kl = F.kl_div(
                    F.log_softmax(s_logit[:, l], dim=-1),
                    F.softmax(t_logit[:, l], dim=-1),
                    reduction='batchmean'
                ).item()
                t_acc = (t_logit[:, l].argmax(-1) == label[:, l]).float().mean().item()
                s_acc = (s_logit[:, l].argmax(-1) == label[:, l]).float().mean().item()
                metrics['per_layer_kl'].append(kl)
                metrics['per_layer_acc'].append((t_acc, s_acc))
                metrics['gap'].append(t_acc - s_acc)

    # 打印每层 gap
    L = sid.size(1)
    for l in range(L):
        avg_gap = np.mean([g for g in metrics['gap'][l::L]])
        print(f"Layer {l}: teacher_acc={metrics['per_layer_acc'][l::L][0][0]:.3f}, "
              f"student_acc={metrics['per_layer_acc'][l::L][0][1]:.3f}, gap={avg_gap:.3f}")
```

## 3.14 蒸馏与冷启动的联动

## 3.14.1 新物品的 SID 蒸馏

冷启动的核心问题:新物品没有交互数据,无法直接训练 student。

**解决方案**: 新物品通过 RQ-Kmeans 算 SID → 用 teacher 预测其分布 → 当成"伪标签"蒸馏给学生。

```python
def cold_start_distill(student, teacher, new_items, alpha_decay=0.9):
    """对新物品做渐进式蒸馏。"""
    for i, item in enumerate(new_items):
        # 算 SID
        sid = compute_sid(item)  # [L]

        # Teacher 预测其分布
        with torch.no_grad():
            t_logit = teacher(sid.unsqueeze(0))  # [1, L, K]

        # Student 学这个分布
        s_logit = student(sid.unsqueeze(0))
        loss = F.kl_div(
            F.log_softmax(s_logit / 2.0, dim=-1),
            F.softmax(t_logit / 2.0, dim=-1),
            reduction='batchmean'
        ) * 4

        # 越新的物品,蒸馏权重越大(借 teacher)
        weight = alpha_decay ** i
        (weight * loss).backward()
        student.step()
```

## 3.15 蒸馏与多任务学习的协同

## 3.15.1 SID 蒸馏 + MMoE

蒸馏教师 + MMoE 多任务学生:

```python
class MMoESIDStudent(nn.Module):
    """蒸馏学生 + MMoE 多任务头。"""
    def __init__(self, num_levels=3, codebook_size=256, dim=64,
                 n_experts=4, n_tasks=3):
        super().__init__()
        self.sid_embs = nn.ModuleList([nn.Embedding(256, dim) for _ in range(num_levels)])
        self.experts = nn.ModuleList([
            nn.Sequential(nn.Linear(num_levels * dim, 128), nn.ReLU())
            for _ in range(n_experts)
        ])
        self.gates = nn.ModuleList([nn.Linear(num_levels * dim, n_experts) for _ in range(n_tasks)])
        self.task_heads = nn.ModuleList([nn.Linear(128, 256) for _ in range(n_tasks)])

    def forward(self, sid):
        x = torch.cat([emb(sid[:, l]) for l, emb in enumerate(self.sid_embs)], -1)
        expert_out = torch.stack([e(x) for e in self.experts], 1)  # [B, E, H]
        outs = []
        for gate, head in zip(self.gates, self.task_heads):
            w = F.softmax(gate(x), dim=-1).unsqueeze(-1)  # [B, E, 1]
            mixed = (w * expert_out).sum(1)
            outs.append(head(mixed))  # [B, K]
        return torch.stack(outs, 1)  # [B, n_tasks, K]


def mmoe_kd_loss(student_out, teacher_out, hard_label, T=2.0, alpha=0.7):
    """多任务 KD 损失。"""
    n_tasks = student_out.size(1)
    loss = 0
    for t in range(n_tasks):
        soft = F.kl_div(
            F.log_softmax(student_out[:, t] / T, dim=-1),
            F.softmax(teacher_out[:, t] / T, dim=-1),
            reduction='batchmean'
        ) * (T * T)
        hard = F.cross_entropy(student_out[:, t], hard_label[:, t])
        loss = loss + alpha * soft + (1 - alpha) * hard
    return loss / n_tasks
```

## 3.15.2 蒸馏与排序模型的协同

粗排蒸馏(召回→粗排):

```python
class CoarseRankDistill(nn.Module):
    """粗排模型蒸馏召回 teacher。"""
    def __init__(self, teacher_recall, student_coarse):
        super().__init__()
        self.teacher = teacher_recall   # 大召回模型
        self.student = student_coarse    # 小粗排模型

    def forward(self, sid_feat, sid_target):
        # teacher: 全物品 SID 的得分
        with torch.no_grad():
            t_scores = self.teacher(sid_feat)  # [B, N_items]
        # student: 只看候选
        s_scores = self.student(sid_feat, sid_target)  # [B, n_candidates]

        # 蒸馏: teacher 的相对排序 → student
        # 用 listwise loss
        teacher_rank = t_scores.argsort(-1, descending=True)
        # 取 teacher top-K 作为 pseudo-label
        pseudo_target = teacher_rank[:, :100]
        return F.cross_entropy(s_scores, pseudo_target[:, :s_scores.size(1)])
```

## 3.16.2 蒸馏的 Loss 曲线诊断

健康的蒸馏 loss 曲线:
- soft loss: 下降快,几 epoch 内接近 0
- hard loss: 下降慢,持续下降
- 总 loss: soft loss 主导,hard loss 收敛

不健康信号:
- soft loss 不降: teacher 和 student 容量差距太大
- hard loss 反弹: $\alpha$ 太大,student 忽略 ground truth
- 震荡: 学习率太大,需要 warmup

```python
class FederatedDistill:
    """每个客户端只训 student 的一部分,用 FedAvg 聚合。"""
    def __init__(self, teacher, global_student):
        self.teacher = teacher
        self.global_student = global_student

    def client_step(self, client_id, local_data):
        # 本地 student 拷贝 global
        local_student = copy.deepcopy(self.global_student)
        opt = torch.optim.Adam(local_student.parameters(), lr=1e-3)

        for x, y in local_data:  # 本地数据, 不上传
            with torch.no_grad():
                t_logit = self.teacher(x)
            s_logit = local_student(x)
            loss = kd_loss(s_logit, t_logit, y)
            opt.zero_grad(); loss.backward(); opt.step()

        return local_student.state_dict()  # 只传参数, 不传数据

    def server_aggregate(self, client_states):
        """FedAvg: 平均所有客户端的参数。"""
        avg_state = {}
        for key in client_states[0]:
            avg_state[key] = torch.stack([s[key].float() for s in client_states]).mean(0)
        self.global_student.load_state_dict(avg_state)
```

**SID 蒸馏的优势**: 蒸馏的是 teacher 的输出分布,不会泄露用户隐私;SID 的语义共享也让不同客户端的 student 学到一致的知识。

```python
class AttentionTransfer(nn.Module):

        super().__init__()

        # 把 student 的 head 维度对齐到 teacher
```

## 3.18.2 Self-Supervised Distillation

学生自己学自己,无 teacher:

```python
class SelfDistill(nn.Module):
    """student = teacher = 同一个模型, 不同 epoch 的快照互相蒸馏。"""
    def __init__(self, model):
        super().__init__()
        self.model = model
        self.ema_model = copy.deepcopy(model)
        for p in self.ema_model.parameters():
            p.requires_grad_(False)

    def update_ema(self, decay=0.999):
        for p_ema, p in zip(self.ema_model.parameters(), self.model.parameters()):
            p_ema.mul_(decay).add_(p.detach(), alpha=1 - decay)

    def forward(self, x, y):
        with torch.no_grad():
            t_logit = self.ema_model(x)
        s_logit = self.model(x)
        return kd_loss(s_logit, t_logit, y)
```

## 3.21.2 蒸馏失败的 Debug 流程

```text
1. 先单独训 teacher 到收敛
2. 单独训 student (无 KD), 看 baseline
3. 加 KD, 看是否 student 超过 baseline

5. 检查 hard loss 是否还下降
   - 不降 → 软标签权重过高,降 alpha
```

## A.1 蒸馏为何在推荐里特别难

推荐蒸馏和 CV/NLP 的蒸馏有结构性差异,理解这点才知道为什么 SID 让蒸馏"重新变得可行":

| 维度 | CV/NLP 蒸馏 | 推荐蒸馏 | SID 带来的变化 |
| :--- | :--- | :--- | :--- |
| teacher 输出 | 1000 类概率(ImageNet) / 32k BPE logits | **百万~亿级 item 的连续 embedding** | 离散成 $K^L$ 个语义槽,结构化 |
| 容量 gap | teacher 通常 5-10x 学生 | 100x ~ 1000x(双塔/生成模型 → 线上 MLP) | 中间多了一道"语义压缩",gap 缩小 |
| 标签 | 硬标签 one-hot | **隐式反馈**(点击/转化/时长) | 教师软标签比隐式反馈密度高 |
| 在线约束 | 时延 10ms 内 | **P99 < 30ms**(召回 5-10ms 占比最大) | 学生可缩到 $L \times K$ embedding,参数量降一个数量级 |
| 增量数据 | 静态数据集 | **数据分布天天漂**(新物品/新用户/新行为) | 教师每周重训一次,SID 准、学生轻 |

> **关键洞察**: 在 CV/NLP,teacher-student 的核心瓶颈是"如何把大容量模型的能力传给小容量模型"。在推荐,核心瓶颈变成了"**线上不能跑大模型 + 标签是隐式的**"。SID 把"大模型"能力压在"小维度的语义码字"上,让"小容量模型 + 稠密 embedding 拟合"变成了"小容量模型 + 多分类对齐",工具链立刻成熟(直接复用 Hinton 蒸馏、Mixup、CutMix 等)。

## A.2 Hinton 温度软标签的数学细节

设 teacher 在第 $l$ 层码本上的 logits 为 $z_t^{(l)} \in \mathbb{R}^K$,student 同层 logits 为 $z_s^{(l)}$。温度 $T > 0$ 的 softmax:

$$
p_t^{(l)}(k) = \frac{\exp(z_t^{(l)}(k) / T)}{\sum_{j=0}^{K-1} \exp(z_t^{(l)}(j) / T)}, \quad
p_s^{(l)}(k) = \frac{\exp(z_s^{(l)}(k) / T)}{\sum_{j=0}^{K-1} \exp(z_s^{(l)}(j) / T)}
$$

逐层 KL 蒸馏损失:

$$
\mathcal{L}_{\text{KD}}^{(l)}(z_s, z_t; T) = T^2 \cdot \text{KL}\!\left(p_t^{(l)} \,\|\, p_s^{(l)}\right)
$$

总蒸馏损失(对所有层 + 加权):

$$
\mathcal{L}_{\text{KD}}(z_s, z_t; T) = \sum_{l=1}^{L} w_l \cdot \mathcal{L}_{\text{KD}}^{(l)}(z_s^{(l)}, z_t^{(l)}; T), \quad \sum_l w_l = 1
$$

与硬标签交叉熵混合(经典 Hinton 配方):

$$
\mathcal{L} = \alpha \cdot \mathcal{L}_{\text{KD}}(z_s, z_t; T) + (1 - \alpha) \cdot \mathcal{L}_{\text{CE}}(z_s, y)
$$

其中 $y$ 是真实下一 token 的 one-hot(或 next-SID)。

> **$T^2$ 梯度补偿**: $T > 1$ 时 softmax 输出更"软",logits 的梯度被 $1/T$ 缩小,所以乘 $T^2$ 让蒸馏损失与硬标签损失的量级匹配(否则蒸馏损失会显得"不重要")。详见 [数学第07章-案例12 Hinton KD](../../../基础/数学/数学基础/第07章-系统思维/第07章-12-案例Hinton-KD温度软标签.md)。

## A.3 完整 PyTorch 实现:逐层 KDWithSID

### A.3.1 基础类:从 §3.1 扩展到工业可用版

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class KDWithSID(nn.Module):
    """逐层 KL 蒸馏,teacher→student 传每层码字 softmax。

    Args:
        teacher: 输出 [B, L, K] logits 的预训练模型(冻结)
        student: 待训练的学生模型, 输出同 shape
        T: 蒸馏温度, 推荐 2.0-4.0
        alpha: 蒸馏损失权重, 推荐 0.7-0.9
        layer_weights: 每层权重, 默认等权
    """
    def __init__(self, teacher, student, T=2.0, alpha=0.7, layer_weights=None):
        super().__init__()
        self.teacher = teacher.eval()
        self.student = student
        self.T = T
        self.alpha = alpha
        L = next(student.parameters()).new_tensor(0)  # 占位, 实际从 forward 推断
        # 冻结 teacher
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def forward(self, x, hard_target=None):
        with torch.no_grad():
            t_logits = self.teacher(x)              # [B, L, K]
        s_logits = self.student(x)                  # [B, L, K]

        # 软标签 KL
        T = self.T
        soft = F.kl_div(
            F.log_softmax(s_logits / T, dim=-1),
            F.softmax(t_logits / T, dim=-1),
            reduction='batchmean'
        ) * (T * T)

        loss = self.alpha * soft
        if hard_target is not None:
            hard = F.cross_entropy(
                s_logits.reshape(-1, s_logits.size(-1)),
                hard_target.reshape(-1)
            )
            loss = loss + (1 - self.alpha) * hard
        return loss, {'soft': soft.item(), 'hard': hard.item() if hard_target is not None else 0.0}
```

### A.3.2 进阶:层间动态权重(防止粗层坍缩)

工业经验:粗层(前 2-3 层)对效果影响最大,细层对多样性更重要。**让粗层权重更大**:

```python
class KDWithSIDWeighted(KDWithSID):
    """按层加权的 KD,粗层权重大(它决定大类语义)。"""
    def __init__(self, teacher, student, T=2.0, alpha=0.7, decay=0.8):
        # decay=0.8 → 粗层权重 1.0, 逐层衰减
        L = student.head.out_features // 256  # 假设 K=256
        # 更稳妥的写法: student 暴露 num_levels 属性
        L = getattr(student, 'num_levels', 5)
        weights = torch.tensor([decay ** l for l in range(L)])
        weights = weights / weights.sum()           # 归一化
        super().__init__(teacher, student, T, alpha)
        self.register_buffer('layer_weights', weights)

    def forward(self, x, hard_target=None):
        with torch.no_grad():
            t_logits = self.teacher(x)              # [B, L, K]
        s_logits = self.student(x)                  # [B, L, K]
        T = self.T
        # 逐层 KL 后加权
        L = s_logits.size(1)
        soft_per_layer = []
        for l in range(L):
            s = F.log_softmax(s_logits[:, l] / T, dim=-1)
            t = F.softmax(t_logits[:, l] / T, dim=-1)
            kl = F.kl_div(s, t, reduction='batchmean')
            soft_per_layer.append(kl)
        soft = (torch.stack(soft_per_layer) * self.layer_weights).sum() * (T * T)

        loss = self.alpha * soft
        if hard_target is not None:
            hard = F.cross_entropy(
                s_logits.reshape(-1, s_logits.size(-1)),
                hard_target.reshape(-1)
            )
            loss = loss + (1 - self.alpha) * hard
        return loss, {'soft': soft.item()}
```

## A.4 特征 KD(Feature KD):对齐量化前 embedding

有些场景 student 也是生成式模型(直接产 embedding),这时要传**量化前的连续向量**,而不是量化后的离散分布。

### A.4.1 数学

$$
\mathcal{L}_{\text{feat}}^{(l)} = \text{MSE}\!\left(e_s^{(l)}, e_t^{(l)}\right) = \left\| e_s^{(l)} - e_t^{(l)} \right\|_2^2
$$

若 student 与 teacher embedding 维度不同,加投影头:

$$
\mathcal{L}_{\text{feat}}^{(l)} = \text{MSE}\!\left(W_s \cdot e_s^{(l)}, W_t \cdot e_t^{(l)}\right), \quad W_s, W_t \in \mathbb{R}^{d \times d_t}
$$

完整目标:

$$
\mathcal{L} = \sum_{l=1}^{L} \beta_l \cdot \mathcal{L}_{\text{feat}}^{(l)} + \gamma \cdot \mathcal{L}_{\text{KD}}
$$

### A.4.2 实现

```python
class FeatureKD(nn.Module):
    """把 teacher 每层码字对应的连续 embedding 当软标签。"""
    def __init__(self, teacher, student, feat_proj=None, beta=1.0, gamma=0.5):
        super().__init__()
        self.teacher = teacher.eval()
        self.student = student
        self.feat_proj = feat_proj
        self.beta, self.gamma = beta, gamma
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def forward(self, x, hard_target=None):
        with torch.no_grad():
            t_feat = self.teacher.encode_continuous(x)   # [B, L, D_t]
        s_feat = self.student.encode_continuous(x)       # [B, L, D_s]
        if self.feat_proj is not None:
            t_feat = self.feat_proj(t_feat)
        feat_loss = F.mse_loss(s_feat, t_feat)

        # 离散 logits KD
        with torch.no_grad():
            t_logits = self.teacher(x)
        s_logits = self.student(x)
        T = 2.0
        kd = F.kl_div(
            F.log_softmax(s_logits / T, -1),
            F.softmax(t_logits / T, -1),
            reduction='batchmean'
        ) * (T * T)
        return self.beta * feat_loss + self.gamma * kd
```

## A.5 码本共享(Codebook Sharing):只蒸生成模型

当 student 是更小的生成式模型(如 6 层 decoder),teacher 是 12 层 decoder,**码本可共享**——直接复用 teacher 的码本 embedding,student 只训 transformer 部分。

```python
class SharedCodebookDecoder(nn.Module):
    """Student decoder,与 teacher 共用码本 Embedding。"""
    def __init__(self, codebook_emb, n_layers=4, n_heads=4, dim=128):
        super().__init__()
        # 共享! 来自 teacher 的冻结码本
        self.code_emb = codebook_emb                  # 冻结
        for p in self.code_emb.parameters():
            p.requires_grad_(False)
        self.pos_emb = nn.Embedding(512, dim)
        layer = nn.TransformerDecoderLayer(dim, n_heads, dim * 4, batch_first=True)
        self.decoder = nn.TransformerDecoder(layer, n_layers)
        self.head = nn.Linear(dim, codebook_emb.weight.size(0))

    def forward(self, src, tgt_in):
        pos = torch.arange(tgt_in.size(1), device=tgt_in.device)
        x = self.code_emb(tgt_in) + self.pos_emb(pos)[None]
        out = self.decoder(x, src, tgt_mask=nn.Transformer.generate_square_subsequent_mask(tgt_in.size(1)).to(x.device))
        return self.head(out)

# 训练时只更新 student 的 decoder / head, 码本不更新
def freeze_codebook(student):
    for p in student.code_emb.parameters():
        p.requires_grad_(False)
```

> **好处**: student 显存砍掉 $L \times K \times D$(对 $L=5, K=256, D=128$ 是 ~16M 参数)。**风险**: student 被钉死在 teacher 码本上,如果 teacher 码本坍塌,student 一起坏。

## A.6 自适应温度与课程式蒸馏

### A.6.1 为什么要"自适应温度"

固定 $T=2.0$ 在训练初期可能过强(student 完全学不动),后期可能过弱(信号饱和)。**让 $T$ 随 epoch 变化**:

```python
class CurriculumKD(KDWithSID):
    """温度从高(更软)线性降到 1.0(硬分布), 让学生渐进。"""
    def __init__(self, teacher, student, T_start=4.0, T_end=1.0, total_epochs=10, **kw):
        super().__init__(teacher, student, T=T_start, **kw)
        self.T_start, self.T_end, self.total_epochs = T_start, T_end, total_epochs

    def on_epoch_end(self, epoch):
        # 线性退火
        frac = epoch / max(1, self.total_epochs - 1)
        self.T = self.T_start + (self.T_end - self.T_start) * frac
```

### A.6.2 课程式"先粗后细"

```python
class CurriculumLayerKD(KDWithSID):
    """先只蒸馏粗层(L=1,2), 后逐步放开细层。"""
    def __init__(self, teacher, student, total_epochs=10, **kw):
        super().__init__(teacher, student, **kw)
        self.total_epochs = total_epochs

    def get_active_layers(self, epoch):
        L = getattr(self.student, 'num_levels', 5)
        # epoch 0: 1 层, epoch E: L 层 (线性)
        n_active = max(1, int((epoch + 1) / self.total_epochs * L))
        return list(range(n_active))

    def forward(self, x, epoch, hard_target=None):
        with torch.no_grad():
            t_logits = self.teacher(x)              # [B, L, K]
        s_logits = self.student(x)                  # [B, L, K]
        active = self.get_active_layers(epoch)
        T = self.T
        loss = 0.0
        for l in active:
            s = F.log_softmax(s_logits[:, l] / T, -1)
            t = F.softmax(t_logits[:, l] / T, -1)
            loss = loss + F.kl_div(s, t, reduction='batchmean') * (T * T)
        loss = loss / len(active)
        return self.alpha * loss, {'active_layers': active}
```

## A.7 工业案例

### A.7.1 字节跳动 Douyin:大生成模型 → 小精排

字节在生成式推荐上做过类似的蒸馏(详见 GR/ 教程相关论文): 教师是一个 12 层 decoder、12 heads、生成 top-100 SID 候选;学生是 6 层 decoder、4 heads,在教师候选上重排序。

**关键经验**:
1. **教师候选 K=100,学生重排 N=10**;学生只看教师选过的,搜空间小一个数量级。
2. **温度 T=3.0**(比 CV 的 2.0 高,因为 SID 类别数 256 > ImageNet 1000)。
3. **粗层权重大**:用 §A.3.2 的层间加权,粗层 1.0 → 细层 0.3 衰减。

> 引用场景:ByteDance 的生成式召回" $L \times K$ 软标签蒸馏"在 P99 < 30ms 约束下达到教师 95% Recall@10。

### A.7.2 阿里巴巴 Tmall:TIGER 教师 → 双塔学生

TIGER 是阿里提出的生成式推荐范式(见 [10-01](第10章-01-SID与生成式推荐-TIGER-OneRec.md))。蒸馏常见做法:

- **教师**:TIGER seq2seq,12 层 decoder,生成完整 SID 序列。
- **学生**:双塔(DSSM),用户塔/物品塔分别用 SID embedding。
- **蒸馏点**:在双塔物品塔的最后一层,加 KL 对齐 TIGER 的最终码字分布。

```python
class TwoTowerDistill(nn.Module):
    """双塔 + SID 蒸馏。"""
    def __init__(self, teacher_tiger, user_tower, item_tower, K=256, L=5):
        super().__init__()
        self.teacher = teacher_tiger.eval()
        self.user_tower = user_tower
        self.item_tower = item_tower
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def forward(self, hist_sids, cand_sid):
        # 用户塔
        u_vec = self.user_tower(hist_sids)             # [B, D]
        i_vec = self.item_tower(cand_sid)              # [B, D]
        score = (u_vec * i_vec).sum(-1)                # [B] 双塔打分

        # 教师 logits (从 TIGER 生成)
        with torch.no_grad():
            t_logits = self.teacher(hist_sids, cand_sid)  # [B, L, K]
        # 学生 logits: 用 SID embedding 做线性投影得 K 维 logits
        s_logits = self.item_tower.to_logits(cand_sid)    # [B, L, K]

        T = 2.0
        kd = F.kl_div(
            F.log_softmax(s_logits / T, -1),
            F.softmax(t_logits / T, -1),
            reduction='batchmean'
        ) * (T * T)
        return score, kd
```

### A.7.3 快手 KuaiShou:生成式召回的码本蒸馏

快手在生成式召回上的蒸馏特色是**只蒸馏码本,Transformer 用学生自己的**:

```python
class CodebookOnlyDistill(nn.Module):
    """教师只贡献码本,Transformer 学生自己训。"""
    def __init__(self, teacher_codebook, student):
        super().__init__()
        # 直接复用 teacher 码本
        student.codebooks = teacher_codebook
        for p in teacher_codebook.parameters():
            p.requires_grad_(False)
        self.student = student

    def forward(self, hist_sids, tgt_sid):
        return self.student(hist_sids, tgt_sid)   # 标准 next-token CE
```

> 优势:**学生 Transformer 比教师小 4 倍,但完全独立训练,不被教师带偏**;码本共享保证了"语义空间一致",两者可互换部署。

### A.7.4 YouTube:多任务蒸馏 + 层次软标签

YouTube 在多任务推荐中(同时预测点击/观看时长/满意度)用类似 MoSE 的方法,把每个任务的教师 logits 拼成 SID 多标签分布,然后蒸馏到学生。详见 GR/ 论文区。

### A.8.3 健康度监控

```python
# 监控: 学生输出分布与教师的 KL 距离, 防止 student 漂移
@torch.no_grad()
def monitor_drift(student, teacher, calib_loader, device='cuda'):
    kls = []
    for batch in calib_loader:
        x = batch.to(device)
        t = teacher(x)
        s = student(x)
        kl = F.kl_div(
            F.log_softmax(s / 2.0, -1),
            F.softmax(t / 2.0, -1),
            reduction='batchmean'
        ).item()
        kls.append(kl)
    return {'mean_kl': sum(kls) / len(kls), 'max_kl': max(kls)}
```

## A.9 蒸馏失败模式与排查

| 症状 | 原因 | 修法 |
| :--- | :--- | :--- |
| 学生 Recall 远低于教师 | 容量差太大 / $T$ 过高 | 增大 student 容量或降到 $T=1.5$ |
| 学生与教师输出分布偏差大 | 学习率过大 / $T$ 过低 | 调小学习率 / 升高 $T$ |
| 粗层准、细层乱 | 粗层权重大小 / 细层训练不够 | 用 §A.6.2 课程式先粗后细 |
| 学生对长尾物品没改进 | 蒸馏信号被头部位主导 | 加稀有 token 上采样 / focal 蒸馏 |
| 学生线上指标漂移 | 码本不一致(teacher 重训) | 锁定 SID 版本(见 §A.10) |

## A.10 SID 版本管理与教师刷新策略

**坑**:教师每周重训一次,如果 student 没冻结 SID 版本,学生 SID embedding 表会被反复覆盖。规范做法:

```python
class VersionedSIDKD:
    """教师刷新时,学生先把旧 SID embedding 拷贝出来。"""
    def __init__(self, sid_version):
        self.sid_version = sid_version   # e.g. "2026_07_18_v3"

    def freeze_sid(self, student):
        # 把当前 SID embedding 冻结成 CPU snapshot
        snapshot = {l: emb.weight.detach().cpu().clone()
                    for l, emb in enumerate(student.code_embs)}
        torch.save(snapshot, f'sid_emb_v{self.sid_version}.pt')

    def load_sid(self, student, version):
        snapshot = torch.load(f'sid_emb_v{version}.pt')
        for l, emb in enumerate(student.code_embs):
            emb.weight.data.copy_(snapshot[l].to(emb.weight.device))
```

## A.14 常见面试追问与答案

**Q1: 蒸馏时 teacher 和 student 的 SID embedding 表能否不同?**

答:可以,但代价大。如果 student 重新训一份码本,teacher 的软标签(每层 $K$ 维概率)直接套到 student 的码本上语义就错位了——teacher 的 code 7 可能是"手机",student 的 code 7 可能是"服装"。常见做法:
- **共享码本**:student 复用 teacher 冻结的码本(§A.5);
- **Hinton 软标签蒸馏**:即使码本不同,只要教师在每层上的概率分布结构对(student 通过优化学到了相似的聚类结构),也有弱监督效果;
- **跨码本对齐**:先用 Hungarian 匹配把 student 与 teacher 的码本对齐,再 KD。代价:每次 teacher 重训都要重新匹配。

**Q2: 蒸馏后学生模型是否还需要继续用真实标签训练?**

答:看场景。
- **完全蒸馏(纯 KD loss)**:学生只对齐 teacher,适合 teacher 很强且标签稀少的场景(如冷启动、长尾);
- **混合蒸馏(KD + 硬标签)**:§A.3 的配方,工业默认。$\alpha=0.7 \sim 0.9$ 偏蒸馏,$0.3 \sim 0.5$ 偏硬标签。
- **两阶段**:先纯 KD 训到收敛,再用硬标签 fine-tune(微调)几个 epoch,平衡 student 个性。

**Q3: 蒸馏后效果变差,可能的原因?**

排查清单:
1. **温度 $T$ 不对**:过高 → student 软到学不动;过低 → 退化成硬标签。$T \in [2, 4]$ 是工业甜点。
2. **学习率不匹配**:蒸馏学生 lr 通常比从零训练小 5-10 倍(teacher 信号已带噪声)。
3. **学生容量不够**:teacher 12 层 student 2 层,差太大;至少保证 1/3 ~ 1/2 容量。
4. **码本不一致**:teacher 重训后 student 没跟上,见 §A.10。
5. **粗层权重视而不见**:粗层错了整个语义就偏,必须给大权重(§A.3.2)。
6. **数据分布漂移**:teacher 在 A 数据上训,student 在 B 数据上蒸馏,SID 语义漂移。

**Q4: 蒸馏能突破 student 的容量上限吗?**

答:**不能完全突破**。蒸馏本质是"teacher 知识 → student 拟合",student 容量上限由参数量决定。但有两类"突破":
- **结构化蒸馏**:让 student 学 teacher 的"层间关系"而不只是"输出值"(类似 FitNets),可逼近 1.5x 容量。
- **课程式蒸馏**:见 §A.6,渐进地教,student 容量被"用尽"得更彻底。

**Q5: 蒸馏和量化/剪枝能叠加吗?**

答:可以,典型 pipeline:大模型 → 蒸馏(参数量降 4-10x) → INT8 量化(再降 2-4x) → 剪枝(可选)。但要小心:
- **顺序很重要**:先蒸馏再量化,效果好;反之 student 已被破坏,蒸馏难以恢复。
- **蒸馏感知量化(QA-Distill)**:训练时就把量化误差考虑进蒸馏损失,效果更稳。

```python
def full_eval(student, teacher, test_loader, metrics):
    student.eval()
    teacher.eval()
    results = {}
    # 1) Recall@K 损失
    for K in [1, 5, 10, 50, 100]:

        r_s = compute_recall(student, test_loader, K)
        results[f'recall@{K}_loss'] = (r_t - r_s) / r_t

    results['latency_ms_p99'] = measure_latency(student, n_runs=1000)
```

## A.17 蒸馏在 A/B 测试中的常见坑

### A.17.1 坑 1:学生模型与教师模型码本不一致

**现象**:学生 Recall@10 暴跌,Loss 正常。
**根因**:教师重训了码本,学生没同步。
**预防**:见 §A.10,锁定 SID 版本,版本切换时灰度(1% → 10% → 50% → 100%)。

### A.17.2 坑 2:蒸馏温度过高导致学生"软瘫"

**现象**:Loss 很低,但 Hit@1 退化严重。
**根因**:$T$ 过大时教师概率趋近均匀,学生学不到排序信息。
**诊断**:打印 teacher softmax 在 $T=2.0$ 下的分布,若最大概率 < 0.1(过软)说明 $T$ 太大。
**修法**:降到 $T=1.5 \sim 2.0$,或加 focal 蒸馏(见 §A.18)。

### A.17.3 坑 3:学生仅在头部 item 表现好

**现象**:长尾 item 的 Recall 远低于教师。
**根因**:教师软标签被头部位主导,长尾 item 软标签信号弱。
**修法**:按 item 频率反加权采样,让长尾 item 的 KL loss 权重更高。

```python
def weighted_kd(s_logits, t_logits, item_freq, T=2.0):
    # item_freq: [B] 每个样本目标 item 的频率
    weight = 1.0 / torch.sqrt(item_freq + 1)   # 频率越低权重越高
    s = F.log_softmax(s_logits / T, -1)
    t = F.softmax(t_logits / T, -1)
    kl_per_sample = F.kl_div(s, t, reduction='none').sum(-1)  # [B, L]
    kl = (kl_per_sample * weight.view(-1, 1)).mean()
    return kl * (T * T)
```

### A.17.4 坑 4:蒸馏后线上指标反而差

**可能原因**:
1. 蒸馏用离线数据,但线上分布漂移;
2. 学生模型架构差异大,被强行 KD;
3. 蒸馏信号与硬标签信号冲突,学生陷入局部最优。

**修法**:双盲 A/B 必须跑满 7 天;每周检查学生 vs 教师在新鲜数据上的 KL 漂移。

## A.18 Focal KD:头部位降权,长尾位加权

经典 KD 的问题是头部位概率大,梯度被头部位主导。**Focal 调制**:

$$
\mathcal{L}_{\text{focal-KD}}^{(l)} = -\sum_k (1 - p_t^{(l)}(k))^\gamma \cdot p_t^{(l)}(k) \log p_s^{(l)}(k)
$$

其中 $\gamma \geq 0$ 是 focal 系数,$\gamma = 0$ 退化为标准 KD,$\gamma = 2$ 让 student 更关注"教师也拿不准"的样本(往往是难/长尾)。

```python
class FocalKD(nn.Module):
    def __init__(self, teacher, student, T=2.0, alpha=0.7, gamma=2.0):
        super().__init__()
        self.teacher = teacher.eval()
        self.student = student
        self.T, self.alpha, self.gamma = T, alpha, gamma
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def forward(self, x, hard_target=None):
        with torch.no_grad():
            t_logits = self.teacher(x)
        s_logits = self.student(x)
        T = self.T
        # 教师概率
        p_t = F.softmax(t_logits / T, -1)              # [B, L, K]
        p_s = F.log_softmax(s_logits / T, -1)
        # focal 权重
        focal_w = (1 - p_t).pow(self.gamma)            # [B, L, K]
        # 逐元素 KL (不带 reduction),然后加权
        kl_elem = F.kl_div(p_s, p_t, reduction='none') # [B, L, K]
        loss = (focal_w * kl_elem).sum(-1).mean() * (T * T)

        if hard_target is not None:
            hard = F.cross_entropy(
                s_logits.reshape(-1, s_logits.size(-1)),
                hard_target.reshape(-1)
            )
            loss = self.alpha * loss + (1 - self.alpha) * hard
        return loss
```

## A.19 多教师集成蒸馏(MoE-style KD)

不同教师在不同子空间擅长,可以做**多教师加权**:

```python
class MultiTeacherKD(nn.Module):
    def __init__(self, teachers, student, weights=None, T=2.0, alpha=0.7):
        super().__init__()
        self.teachers = nn.ModuleList([t.eval() for t in teachers])
        self.student = student
        self.weights = weights or [1.0 / len(teachers)] * len(teachers)
        self.T, self.alpha = T, alpha
        for t in self.teachers:
            for p in t.parameters():
                p.requires_grad_(False)

    def forward(self, x, hard_target=None):
        s_logits = self.student(x)
        loss = 0.0
        T = self.T
        for t, w in zip(self.teachers, self.weights):
            with torch.no_grad():
                t_logits = t(x)
            kd = F.kl_div(
                F.log_softmax(s_logits / T, -1),
                F.softmax(t_logits / T, -1),
                reduction='batchmean'
            ) * (T * T)
            loss = loss + w * kd
        if hard_target is not None:
            hard = F.cross_entropy(
                s_logits.reshape(-1, s_logits.size(-1)),
                hard_target.reshape(-1)
            )
            loss = self.alpha * loss + (1 - self.alpha) * hard
        return loss
```

典型配置:
- 教师 1:TIGER(语义类目准);
- 教师 2:行为序列模型(协同信号强);
- 教师 3:多任务模型(综合指标好)。

学生同时学三者,效果通常优于单教师。

## A.20 自适应损失权重(GradNorm)

不同损失(粗层/细层/KD/硬标签)的量级不同,需要动态调权:

```python
class GradNorm(nn.Module):
    """GradNorm: 让不同 loss 的梯度量级对齐。"""
    def __init__(self, losses, alpha=0.12):
        super().__init__()
        self.w = nn.Parameter(torch.ones(len(losses)))
        self.alpha = alpha

    def forward(self, loss_values, shared_params):
        # loss_values: list of losses
        # shared_params: 用于算梯度的共享参数
        weighted = sum(w * l for w, l in zip(self.w, loss_values))
        grads = torch.autograd.grad(weighted, shared_params, retain_graph=True)
        # 计算每个 loss 的梯度范数
        norms = []
        for lv in loss_values:
            g = torch.autograd.grad(lv, shared_params, retain_graph=True)
            norms.append(torch.norm(g))
        # 动态调权 (简化版, 完整见 GradNorm 论文)
        return weighted, norms
```

工业实践:**简单做法是先验权重 + 线性 warmup**,不上 GradNorm。GradNorm 在 5+ 损失时收益明显,但实现复杂、训练不稳。

## A.21 在线蒸馏(Online Distillation)与 DML

传统蒸馏是"教师固定 → 学生学"。在线蒸馏是**教师和学生同时学,互教**(Deep Mutual Learning, DML):

```python
class DML(nn.Module):
    """学生互教:每个学生既是 student 又是其他学生的 teacher。"""
    def __init__(self, models, T=2.0):
        super().__init__()
        self.models = nn.ModuleList(models)
        self.T = T

    def forward(self, x, hard_target):
        losses = []
        for i, m_i in enumerate(self.models):
            l_i = F.cross_entropy(m_i(x), hard_target)
            for j, m_j in enumerate(self.models):
                if i == j: continue
                with torch.no_grad():
                    t_logits = m_j(x)
                kd = F.kl_div(
                    F.log_softmax(m_i(x) / self.T, -1),
                    F.softmax(t_logits / self.T, -1),
                    reduction='batchmean'
                ) * (self.T ** 2)
                l_i = l_i + 0.5 * kd
            losses.append(l_i)
        return sum(losses)
```

适用场景:**多个相似 student(不同种子或不同架构)互蒸馏**,集成效果。SID 场景里,可训 3 个 student(不同层数/不同头数),互教后取平均或集成。

## A.23 与多任务学习的组合蒸馏

学生不仅要做 next-token 预测,还要做 CTR/CVR 等多任务 → 多任务蒸馏:

```python
class MultiTaskDistill(nn.Module):
    """学生模型:多任务 + 多教师蒸馏。"""
    def __init__(self, mt_teacher, sid_student, T=2.0, alpha=0.5, beta=0.3):
        super().__init__()
        self.mt_teacher = mt_teacher.eval()    # 多任务教师
        self.sid_student = sid_student
        self.T, self.alpha, self.beta = T, alpha, beta
        for p in self.mt_teacher.parameters():
            p.requires_grad_(False)

    def forward(self, sid, click_label, conv_label):
        # 学生多任务输出
        ctr_pred, cvr_pred, sid_logits = self.sid_student(sid)  # [B] [B] [B, L, K]
        # 教师多任务输出
        with torch.no_grad():
            t_ctr, t_cvr, t_sid = self.mt_teacher(sid)
        # 三类损失
        ctr_loss = F.binary_cross_entropy_with_logits(ctr_pred, click_label)
        cvr_loss = F.binary_cross_entropy_with_logits(cvr_pred, conv_label)
        sid_kd = F.kl_div(
            F.log_softmax(sid_logits / self.T, -1),
            F.softmax(t_sid / self.T, -1),
            reduction='batchmean'
        ) * (self.T ** 2)
        total = ctr_loss + 0.5 * cvr_loss + 0.3 * sid_kd
        return total, {'ctr': ctr_loss.item(), 'cvr': cvr_loss.item(), 'sid_kd': sid_kd.item()}
```

## A.24 蒸馏在冷启动中的作用

**冷启动的本质**:新物品/新用户没行为数据,模型"不知道它像什么"。

**SID 蒸馏如何破冷启动**:
- 新物品有文本/图像 → RQ-VAE 生成 SID → 学生用已有 SID embedding 查到稠密向量;
- 学生模型在教师软标签上训过,具备**语义泛化**能力:即使没见过的 SID 组合,学生也能基于"见过的相似 SID 组合"打合理分;
- **冷启动场景**:把新 SID embedding 初始化为粗层相同 SID 的 embedding 平均,学生立刻有"合理"起点。

```python
def cold_init_sid(new_sid, existing_sids, code_emb):
    """冷启动: 新 SID 用粗层相同的已有 SID 平均初始化。"""
    # new_sid: [L]
    # existing_sids: [N, L]
    # code_emb: [K, D]
    coarse = new_sid[0]                          # 粗层
    mask = existing_sids[:, 0] == coarse
    similar = existing_sids[mask]
    if len(similar) == 0:
        return code_emb.weight[coarse]            # 用粗层 embedding 兜底
    avg_emb = code_emb(similar).mean(0)
    return avg_emb
```

效果:冷启动物品的 CTR 从原本的 ~0 提升到与"平均长尾"接近的水平。

## A.29 蒸馏与因果推断的结合

### A.29.1 为什么蒸馏要管"因果"

推荐系统里有大量混淆变量(位置偏差/曝光偏差/流行度偏差)。如果教师模型学到了"流行即相关"的偏差,学生蒸馏后只会强化这个偏差。**因果蒸馏**把教师信号的因果部分分离出来,蒸馏给学生。

### A.29.2 数学形式

记 $Y$ 为点击,$X$ 为用户/item 特征,$Z$ 为位置/曝光等混淆变量。教师模型 $\hat{Y}_t = f_t(X, Z)$,我们要蒸馏的是"去 $Z$ 后的因果预测" $\hat{Y}_{\text{causal}} = \mathbb{E}[\hat{Y}_t | X]$(对 $Z$ 做边缘化)。

```python
class CausalKD(nn.Module):
    """蒸馏教师信号的因果部分(对位置/曝光去偏)。"""
    def __init__(self, teacher, student, T=2.0, alpha=0.7):
        super().__init__()
        self.teacher = teacher.eval()
        self.student = student
        self.T, self.alpha = T, alpha
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def forward(self, x, hard_target, position_ids):
        """position_ids: [B], 用于去位置偏差。"""
        with torch.no_grad():
            t_logits = self.teacher(x, position_ids=position_ids)
        s_logits = self.student(x)
        T = self.T
        # 因果蒸馏: 对 position 求平均, 消除位置偏差
        # 教师多个 position 取平均
        if hasattr(self.teacher, 'causal_logit'):
            t_causal = self.teacher.causal_logit(x)   # 已经去偏
        else:
            # 简化: 用不同 position 的平均近似
            t_causal = t_logits.mean(dim=-1, keepdim=True).expand_as(t_logits)
        soft = F.kl_div(
            F.log_softmax(s_logits / T, -1),
            F.softmax(t_causal / T, -1),
            reduction='batchmean'
        ) * (T * T)
        hard = F.cross_entropy(
            s_logits.reshape(-1, s_logits.size(-1)),
            hard_target.reshape(-1)
        )
        return self.alpha * soft + (1 - self.alpha) * hard
```

工业效果:长尾位置的去偏蒸馏能让冷启动/中部位置的 AUC 提升 2-4%。

## A.30 蒸馏与去偏(De-biasing)的对比

| 方法 | 数据来源 | 偏差来源 | 工业适用 |
| :--- | :--- | :--- | :--- |
| **逆倾向加权(IPW)** | 真实曝光+点击 | 倾向分估计 | ★★★ |
| **因果蒸馏** | 教师软标签 | 因果分离 | ★★☆ |
| **双重稳健(DR)** | 两者结合 | 两者都管 | ★★(训练慢) |
| **曝光模型纠偏** | 曝光模型 | 曝光位置 | ★★★ |

因果蒸馏的局限:因果信号弱,需要大数据量才稳;倾向分估计不准时,反而把噪声当因果传给学生。

## A.33 蒸馏在联邦学习(Federated)下的扩展

**场景**:多个公司/事业部联合训大模型,但数据不出域(合规要求)。联邦蒸馏:各方训教师 → 教师软标签上云 → 学生上云统一蒸馏。

```python
class FederatedKD:
    """联邦蒸馏: 各客户端上传教师软标签, 云端训学生。"""
    def __init__(self, teacher_per_client, cloud_student):
        self.teachers = teacher_per_client   # list of frozen teachers
        self.student = cloud_student

    def aggregate_soft_labels(self, batches):
        """聚合多客户端的教师软标签 (求平均)。"""
        all_soft = []
        for batch, teacher in zip(batches, self.teachers):
            with torch.no_grad():
                t_logits = teacher(batch['x'])
                t_prob = F.softmax(t_logits / 2.0, -1)
                all_soft.append(t_prob)
        # 加权平均 (权重与样本量成正比)
        avg_soft = torch.stack(all_soft).mean(0)
        return avg_soft

    def train_step(self, batches, opt):
        avg_soft = self.aggregate_soft_labels(batches)
        # 学生预测
        s_logits = self.student(batches[0]['x'])
        loss = F.kl_div(
            F.log_softmax(s_logits / 2.0, -1),
            avg_soft,
            reduction='batchmean'
        ) * 4.0
        opt.zero_grad(); loss.backward(); opt.step()
        return loss.item()
```

联邦蒸馏的合规价值:**原始数据不出域,只传"软标签"**——软标签是模型的中间输出,法律上一般不算"原始用户行为"。但要注意:**软标签仍可被反推**,需要加噪或差分隐私。

## A.34 蒸馏 + 差分隐私(DP)

联邦蒸馏可能泄露用户隐私 → 加 DP 噪声:

```python
class DPKD(nn.Module):
    """蒸馏 + 差分隐私: 对教师软标签加 Laplace 噪声。"""
    def __init__(self, teacher, student, T=2.0, alpha=0.7, epsilon=1.0, sensitivity=1.0):
        super().__init__()
        self.teacher = teacher.eval()
        self.student = student
        self.T, self.alpha = T, alpha
        self.epsilon = epsilon
        self.sensitivity = sensitivity
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def forward(self, x, hard_target=None):
        with torch.no_grad():
            t_logits = self.teacher(x)
            # 加 Laplace 噪声: scale = sensitivity / epsilon
            scale = self.sensitivity / self.epsilon
            noise = torch.distributions.Laplace(0, scale).sample(t_logits.shape).to(t_logits.device)
            t_logits = t_logits + noise
        s_logits = self.student(x)
        T = self.T
        soft = F.kl_div(
            F.log_softmax(s_logits / T, -1),
            F.softmax(t_logits / T, -1),
            reduction='batchmean'
        ) * (T * T)
        if hard_target is not None:
            hard = F.cross_entropy(s_logits.reshape(-1, s_logits.size(-1)), hard_target.reshape(-1))
            return self.alpha * soft + (1 - self.alpha) * hard
        return self.alpha * soft
```

$\epsilon$ 越小,隐私越强,但学生效果越差。**经验值**:$\epsilon = 1.0$ 是甜点(强隐私 + 可用效果)。

## A.35 蒸馏与稀疏 MoE(Sparse MoE)的结合

学生若是稀疏 MoE(每个样本激活 top-2 专家),蒸馏要小心:教师是稠密的,学生是稀疏的,直接 KD 容易让学生"过载少数专家"。

```python
class MoEStudent(nn.Module):
    """学生 = 稀疏 MoE, 蒸馏时约束专家负载均衡。"""
    def __init__(self, n_experts=8, top_k=2, dim=128, K=256, L=5):
        super().__init__()
        self.gate = nn.Linear(dim, n_experts)
        self.experts = nn.ModuleList([nn.Linear(dim, dim) for _ in range(n_experts)])
        self.head = nn.Linear(dim, K * L)
        self.top_k = top_k

    def forward(self, x):
        gate = F.softmax(self.gate(x), -1)              # [B, n_experts]
        idx = gate.topk(self.top_k, -1).indices         # [B, top_k]
        # 稀疏激活 top_k 专家
        out = torch.zeros_like(x)
        for b in range(x.size(0)):
            for k in range(self.top_k):
                e_idx = idx[b, k].item()
                out[b] = out[b] + self.experts[e_idx](x[b])
        return self.head(out), gate  # 同时返回 gate 用于负载均衡损失

def moe_distill(student, teacher, x, T=2.0, alpha=0.7, balance_coef=0.01):
    s_logits, s_gate = student(x)
    with torch.no_grad():
        t_logits = teacher(x)
    # KD loss
    kd = F.kl_div(
        F.log_softmax(s_logits / T, -1),
        F.softmax(t_logits / T, -1),
        reduction='batchmean'
    ) * (T * T)
    # 负载均衡损失: 鼓励 gate 分布均匀
    avg_gate = s_gate.mean(0)                          # [n_experts]
    balance_loss = (avg_gate * torch.log(avg_gate + 1e-8)).sum()
    return alpha * kd + balance_coef * balance_loss
```

## A.36 蒸馏在长期留存(LTV)优化中的应用

短期点击(CTR)与长期价值(LTV)往往不一致。**蒸馏教师 LTV 信号到学生**:

```python
class LTVKD(nn.Module):
    """用教师的 LTV 预测作软标签, 蒸馏给学生。"""
    def __init__(self, ltv_teacher, sid_student, T=2.0, alpha=0.5):
        super().__init__()
        self.ltv_teacher = ltv_teacher.eval()    # 教师: LTV 预测模型
        self.student = sid_student
        self.T, self.alpha = T, alpha
        for p in self.ltv_teacher.parameters():
            p.requires_grad_(False)

    def forward(self, sid, click_label, ltv_label):
        # 学生 next-token 预测 + CTR 预测
        ctr_pred, sid_logits = self.student(sid)
        # 教师 LTV 预测
        with torch.no_grad():
            t_ltv = self.ltv_teacher(sid)        # [B] 长期价值
        # 软标签: LTV 越高的物品, 软标签概率越大
        # 把 LTV 当权重调制 KD
        s = F.log_softmax(sid_logits / self.T, -1)
        t = F.softmax(sid_logits / self.T, -1).detach()  # 自蒸馏 baseline
        kd = F.kl_div(s, t, reduction='none').sum(-1)      # [B]
        # 用 LTV 加权
        weights = torch.sigmoid(t_ltv / t_ltv.std())       # 归一化
        weighted_kd = (kd * weights).mean() * (self.T ** 2)
        # 硬标签
        hard = F.binary_cross_entropy_with_logits(ctr_pred, click_label)
        return self.alpha * weighted_kd + (1 - self.alpha) * hard
```

效果:CTR 微跌(-0.5%)但 LTV 提升 5%,长期看更赚。

## A.37 蒸馏与终身学习(Lifelong)

场景:教师每周重训(数据增长),学生也要跟,但不能"灾难性遗忘"。

```python
class LifelongStudent(nn.Module):
    """终身学习学生: 每个新教师蒸馏 + EWC 防遗忘。"""
    def __init__(self, base_student, ewc_lambda=1000.0):
        super().__init__()
        self.student = base_student
        self.ewc_lambda = ewc_lambda
        self.fisher = {}        # 每个参数的重要性
        self.old_params = {}

    def update_teacher(self, new_teacher):
        self.teacher = new_teacher.eval()
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def compute_fisher(self, calib_loader):
        """计算 Fisher 信息矩阵 (参数的'重要性')。"""
        fisher = {n: torch.zeros_like(p) for n, p in self.student.named_parameters()}
        self.student.eval()
        for batch in calib_loader:
            self.student.zero_grad()
            loss, _ = self.teacher_kd_step(batch, freeze_teacher=False)
            loss.backward()
            for n, p in self.student.named_parameters():
                if p.grad is not None:
                    fisher[n] += p.grad.detach() ** 2
        for n in fisher:
            fisher[n] /= len(calib_loader)
        self.fisher = fisher
        self.old_params = {n: p.detach().clone() for n, p in self.student.named_parameters()}

    def ewc_loss(self):
        """EWC 惩罚: 不让重要参数偏离旧值太远。"""
        loss = 0.0
        for n, p in self.student.named_parameters():
            if n in self.fisher:
                loss = loss + (self.fisher[n] * (p - self.old_params[n]) ** 2).sum()
        return self.ewc_lambda * loss

    def forward(self, x, hard_target):
        kd_loss, _ = self.teacher_kd_step({'x': x, 'target': hard_target}, freeze_teacher=True)
        return kd_loss + self.ewc_loss()
```

EWC(Elastic Weight Consolidation)防止学新教师时把旧能力忘掉。工业里更常见是"replay buffer + KD",效果相近但实现更简单。

## A.38 蒸馏的 Codebook-Aware 正则

学生重新训一份码本(不共享教师码本)时,常见问题是 student 码本坍塌/聚类结构不合理。加一个**码本正则**:让学生码本与教师码本的"分布"相近。

```python
class CodebookAwareKD(nn.Module):
    """学生码本不共享, 但用 KL 让学生码本的"使用分布"接近教师。"""
    def __init__(self, teacher, student, T=2.0, alpha=0.7, codebook_kl=0.1):
        super().__init__()
        self.teacher = teacher.eval()
        self.student = student
        self.T, self.alpha, self.codebook_kl = T, alpha, codebook_kl
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def forward(self, x, hard_target):
        with torch.no_grad():
            t_logits = self.teacher(x)
            t_prob = F.softmax(t_logits / self.T, -1)         # [B, L, K]
            t_code_freq = t_prob.mean(dim=0)                  # [L, K]
        s_logits = self.student(x)
        s_prob = F.softmax(s_logits / self.T, -1)
        s_code_freq = s_prob.mean(dim=0)                       # [L, K]
        # KD loss
        kd = F.kl_div(
            F.log_softmax(s_logits / self.T, -1),
            t_prob,
            reduction='batchmean'
        ) * (self.T ** 2)
        # 码本分布 KL
        code_kl = F.kl_div(
            torch.log(s_code_freq + 1e-8),
            t_code_freq,
            reduction='batchmean'
        )
        hard = F.cross_entropy(s_logits.reshape(-1, s_logits.size(-1)), hard_target.reshape(-1))
        return self.alpha * kd + (1 - self.alpha) * hard + self.codebook_kl * code_kl
```

## A.39 蒸馏的归因分析:什么知识被传过去了?

工业上想知道"教师到底传了什么给学生",常用归因:

```python
def attribution_analysis(student, teacher, batch, top_k=5):
    """归因: 找出 batch 中 teacher 最'决定性'的样本, 看 student 是否学到。"""
    with torch.no_grad():
        t_logits = teacher(batch['x'])
        s_logits = student(batch['x'])
    # 教师信息量: 概率分布的负熵(越集中信息量越大)
    t_prob = F.softmax(t_logits, -1)
    t_entropy = -(t_prob * torch.log(t_prob + 1e-8)).sum(-1).mean(-1)  # [B]
    # 学生对教师的拟合度: KL
    kl = F.kl_div(F.log_softmax(s_logits, -1), t_prob, reduction='none').sum(-1).mean(-1)
    # 排序: 找教师高熵(难例)的样本, 看学生是否拟合
    top_idx = t_entropy.argsort(descending=True)[:top_k]
    return {
        'top_entropy_indices': top_idx.cpu().tolist(),
        'top_entropy_values': t_entropy[top_idx].cpu().tolist(),
        'kl_at_top': kl[top_idx].cpu().tolist(),
    }
```

发现:**教师对长尾/争议物品最不确定(高熵),学生对这部分拟合最差(KL 大)**→ 这就是 §A.18 Focal KD 要解决的问题。

## A.43 蒸馏与知识图谱(KG)的结合

教师若有 KG 嵌入(实体关系),可把 KG 信号蒸馏到学生:

```python
class KGKD(nn.Module):
    """KG 增强蒸馏: 教师有 KG 嵌入, 学生学 KG 关系。"""
    def __init__(self, teacher_with_kg, student, kg_proj, T=2.0, alpha=0.6, kg_alpha=0.2):
        super().__init__()
        self.teacher = teacher_with_kg.eval()
        self.student = student
        self.kg_proj = kg_proj   # 学生空间 → KG 空间投影
        self.T, self.alpha, self.kg_alpha = T, alpha, kg_alpha
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def forward(self, x, sid, hard_target):
        # 基础 KD
        with torch.no_grad():
            t_logits = self.teacher(x)
        s_logits = self.student(x)
        kd = F.kl_div(
            F.log_softmax(s_logits / self.T, -1),
            F.softmax(t_logits / self.T, -1),
            reduction='batchmean'
        ) * (self.T ** 2)
        # KG 蒸馏: 学生 SID embedding 投影到 KG 空间, 对齐 KG 嵌入
        s_emb = self.student.sid_emb(sid)               # [B, D]
        s_kg = self.kg_proj(s_emb)                       # [B, D_kg]
        with torch.no_grad():
            t_kg = self.teacher.kg_emb(sid)              # [B, D_kg]
        kg_loss = F.mse_loss(s_kg, t_kg)
        hard = F.cross_entropy(s_logits.reshape(-1, s_logits.size(-1)), hard_target.reshape(-1))
        return self.alpha * kd + self.kg_alpha * kg_loss + (1 - self.alpha - self.kg_alpha) * hard
```

## A.45 蒸馏在排序阶段的特殊处理

召回阶段蒸馏是"对教师候选排序",精排阶段蒸馏更复杂:

| 阶段 | 教师输出 | 学生输入 | 蒸馏目标 |
| :--- | :--- | :--- | :--- |
| 召回 | top-100 SID | 用户历史 SID | 教师候选分布 |
| 粗排 | top-100 分数 | 用户历史 + 候选 | 粗排分数 |
| 精排 | top-100 分数 + 详细特征 | 全部特征 | 精排分数 |

精排蒸馏特别有效,因精排模型最大,蒸馏后推理降本最显著:

```python
class RankingKD(nn.Module):
    """精排蒸馏: 教师精排 logits → 学生精排 logits。"""
    def __init__(self, teacher_ranker, student_ranker, T=2.0, alpha=0.7):
        super().__init__()
        self.teacher = teacher_ranker.eval()
        self.student = student_ranker
        self.T, self.alpha = T, alpha
        for p in self.teacher.parameters():
            p.requires_grad_(False)

    def forward(self, user_feat, item_feat, sid, label):
        # 学生精排打分
        s_logits = self.student(user_feat, item_feat, sid)  # [B]
        # 教师精排打分
        with torch.no_grad():
            t_logits = self.teacher(user_feat, item_feat, sid)
        # 软标签 KL (二分类)
        p_t = torch.sigmoid(t_logits / self.T)
        p_s = torch.sigmoid(s_logits / self.T)
        soft = F.binary_cross_entropy(p_s, p_t) * (self.T ** 2)
        hard = F.binary_cross_entropy_with_logits(s_logits, label)
        return self.alpha * soft + (1 - self.alpha) * hard
```

精排蒸馏效果:CTR 损失 < 1%,QPS 提升 2-3x(精排模型通常占服务时长 50%+)。

## A.46 蒸馏与"蒸馏泄漏"的诊断

**蒸馏泄漏**(Distillation Leakage):学生通过教师的"软标签"反向学到"教师认为 X 重要",但 X 实际是噪声。

诊断方法:**在相同硬标签上对比教师-学生的"软标签差异"**。

```python
def distillation_leakage(student, teacher, batch):
    """诊断: 教师软标签是否'过度一致'(即泄漏)。"""
    with torch.no_grad():
        t_logits = teacher(batch['x'])
        s_logits = student(batch['x'])
    t_prob = F.softmax(t_logits, -1)
    s_prob = F.softmax(s_logits, -1)
    # 教师软标签的"信息量"(熵倒数)
    t_entropy = -(t_prob * torch.log(t_prob + 1e-8)).sum(-1)
    s_entropy = -(s_prob * torch.log(s_prob + 1e-8)).sum(-1)
    # 学生熵应该 > 教师熵(因为学生不确定)
    leakage = (t_entropy - s_entropy).mean()
    return leakage.item()
```

若 leakage 为负或异常小,说明学生"过于自信地复制教师",可能过拟合了教师的噪声。

## A.49 蒸馏与 A/B Test 的协同设计

蒸馏学生上线必经 A/B,但 A/B 跑出来的指标差异要拆解:

```python
def ab_decomposition(student_metrics, teacher_metrics, control_metrics):
    """A/B 指标拆解: 蒸馏损失 vs 真实业务价值。"""
    # 蒸馏损失 = 教师 - 学生
    distill_gap = {
        k: teacher_metrics[k] - student_metrics[k]
        for k in teacher_metrics if k in student_metrics
    }
    # 真实业务价值 = A/B 实验组 - 对照组
    ab_value = {
        k: student_metrics[k] - control_metrics[k]
        for k in student_metrics if k in control_metrics
    }
    # 蒸馏损失 vs AB 价值的"乘积"
    return {
        'distill_gap': distill_gap,
        'ab_value': ab_value,
        'leakage_to_business': sum(
            abs(distill_gap[k]) for k in distill_gap if 'ctr' in k or 'gmv' in k
        )
    }
```

若 A/B 实验组 CTR 提升但 Recall@10 蒸馏损失也变大 → 教师 recall 不等于业务价值,需要重新看教师本身。

## A.52 蒸馏的代码 review checklist

## A.61 蒸馏的"误用"清单

**这些做法是错的**:

1. ❌ 把教师和学生训一样的架构(没意义)
2. ❌ 蒸馏时硬标签权重为 0(学生学不到新东西)
3. ❌ 蒸馏损失 weight 设为 1 但 hard loss 为 100(蒸馏被淹没)
4. ❌ 学生容量是教师 10x(应该反过来)
5. ❌ 教师没冻结就蒸馏(教师被学生污染)
6. ❌ KL 不乘 $T^2$(梯度量级错位)
7. ❌ 多教师 KD 不归一化权重(某个教师主导)
8. ❌ 蒸馏后不监控漂移(线上悄悄退化)
9. ❌ 蒸馏与量化同时做(两者损失叠加,效果差)
10. ❌ 冷启动物品打分用原始 ID embedding(应该用 SID)

## A.62 蒸馏的"加分项"心法

面试/分享时能讲清的加分项:

1. **温度 $T$ 的物理意义**:把"one-hot 硬分布"软化成"概率分布",传递暗知识。
2. **粗层权重大**:粗层错则全错,粗层决定大类语义。
3. **课程式退火**:训练初期 $T$ 大(更软,易学),后期 $T$ 小(更准)。
4. **码本共享**:不共享则需对齐(Hungarian match),代价大。
5. **学生容量**:教师 1/3 是甜点。
6. **梯度补偿**:$T^2$ 不能少。
7. **冷启动**:共享 SID embedding 是关键。
8. **监控**:KL 漂移比 Loss 更能反映"是否过拟合教师"。

### 110. 3-SID与知识蒸馏 - 工业实践 视角

**核心议题**: 本节从工业实践视角切入,系统展开 "3-SID与知识蒸馏" 的相关讨论。

**1. 背景与动机**

任何技术或方法的出现都不是孤立的,而是回应特定历史条件下的具体问题。"3-SID与知识蒸馏" 的发展也不例外。要理解它,必须回到它出现的那个时间点,看清它要解决的真实问题是什么。当时的主流方案有哪些不足? 它的提出填补了哪些空白? 这些问题的回答,决定了我们今天该如何使用它。

从知识论角度看,**技术演进是问题驱动的**——不是先有方案再找问题,而是先有问题再有方案。这个观察可以帮助我们避免"拿着锤子找钉子"的陷阱,真正把方法用对地方。

历史维度上,我们看到三个规律:

1. **从特殊到一般**: 早期方法往往针对特定场景,后期抽象出通用框架。学习的认知规律也是先掌握具体案例,再抽象出一般模式。这种"自下而上"的学习方式,在机器学习模型的设计里反复出现。

2. **从手工到自动**: 经验规则逐步被数据驱动的方法取代。在早期,很多 AI 系统依赖人工编写的规则。统计学习方法的崛起让"从数据中学习"成为可能。深度学习进一步把特征工程也自动化了。今天的大模型时代,我们看到端到端学习从感知扩展到了推理与生成。

3. **从局部到全局**: 关注单个组件,演进到关注整个系统。早期模型评估只关注单点指标,现在更关注全链路的协同效应。这种"系统视角"的转变,与软件工程从单体架构到微服务架构的演进高度相似。

**2. 工业实践视角的展开**

从工业实践视角出发,我们可以把 "3-SID与知识蒸馏" 拆解为以下几个层次:

**第一层: 概念层** —— 这是最抽象的层次,定义了我们要研究的对象是什么。例如,"推荐系统"在概念层是一个"为用户从物品集合中筛选合适物品"的问题。这个层次的特点是清晰、稳定、不易变化。一个好的概念定义应该具备几个特征:可操作性、可测量性、可扩展性。

**第二层: 模型层** —— 把概念实例化为数学模型。同一概念可以有不同的模型化方式,例如"推荐系统"可以是协同过滤、矩阵分解、深度学习等。模型的选择决定了后续算法的空间,也决定了能利用的归纳偏置(比如序列模型擅长捕捉时序依赖,图模型擅长建模关系结构)。模型选型是工程实践中最重要的决策之一。

**第三层: 算法层** —— 在选定模型下,具体的求解方法。这一层最活跃,新算法层出不穷。同一模型往往有多种算法,各有优劣。例如同样是优化深度网络,可以选择 SGD、Adam、L-BFGS 等不同算法。算法的选择要考虑收敛速度、数值稳定性、计算成本等多个维度。

**第四层: 工程层** —— 算法落地的实现细节,包括数据流水线、训练框架、推理优化、监控告警等。工程层是研究到生产的桥梁,决定了一个方法能否真正用起来。一个在论文里表现很好的算法,如果不能高效实现、不能稳定运行、不能快速迭代,就没有实际价值。工程能力是把研究转化为生产力的关键。

**第五层: 业务层** —— 在具体业务场景中的表现。同一技术在不同业务里效果差异巨大,因为业务目标、数据分布、用户行为都有差异。从业务视角看技术,我们必须回答几个问题:这个技术解决了什么业务问题?投入产出比如何?长期可持续吗?技术评估必须与业务目标对齐,否则容易陷入"技术自嗨"的陷阱。

**3. 数学形式化(简洁版)**

虽然我们强调工业实践视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

偏差-方差分解是另一个核心框架:误差可以分解为模型偏差(欠拟合)、方差(过拟合)和不可约噪声三部分。理解这个分解有助于诊断模型表现、选择合适复杂度。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

信息论为"3-SID与知识蒸馏" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。

互信息衡量知道一个变量后,另一个变量不确定性减少的量。在机器学习中,它被广泛用于特征选择、表示学习、多模态对齐等场景。

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

信息瓶颈原则指出,我们应该寻找既紧凑又预测性强的表示。这一思想影响了大量表示学习方法的设计,包括对比学习、自监督学习、多模态预训练等。

**第二层: 模型层** —— 把概念实例化为数学模型。同一概念可以有不同的模型化方式,例如"推荐系统"可以是协同过滤、矩阵分解、深度学习等。模型的选择决定了后续算法的空间,也决定了能利用的归纳偏置(比如序列模型擅长捕捉时序依赖,图模型擅长建模关系结构)。模型选型是工程实践中最重要的决策之一。

**第四层: 工程层** —— 算法落地的实现细节,包括数据流水线、训练框架、推理优化、监控告警等。工程层是研究到生产的桥梁,决定了一个方法能否真正用起来。一个在论文里表现很好的算法,如果不能高效实现、不能稳定运行、不能快速迭代,就没有实际价值。工程能力是把研究转化为生产力的关键。

**第五层: 业务层** —— 在具体业务场景中的表现。同一技术在不同业务里效果差异巨大,因为业务目标、数据分布、用户行为都有差异。从业务视角看技术,我们必须回答几个问题:这个技术解决了什么业务问题?投入产出比如何?长期可持续吗?技术评估必须与业务目标对齐,否则容易陷入"技术自嗨"的陷阱。

**3. 数学形式化(简洁版)**

虽然我们强调量化视角视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

偏差-方差分解是另一个核心框架:误差可以分解为模型偏差(欠拟合)、方差(过拟合)和不可约噪声三部分。理解这个分解有助于诊断模型表现、选择合适复杂度。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

信息论为"3-SID与知识蒸馏" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。

互信息衡量知道一个变量后,另一个变量不确定性减少的量。在机器学习中,它被广泛用于特征选择、表示学习、多模态对齐等场景。

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

信息瓶颈原则指出,我们应该寻找既紧凑又预测性强的表示。这一思想影响了大量表示学习方法的设计,包括对比学习、自监督学习、多模态预训练等。

**7. 实践建议**

结合 "3-SID与知识蒸馏" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "3-SID与知识蒸馏" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
