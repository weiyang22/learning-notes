# 第12章-01-生成式检索范式

- | :--- |
| item 表示 | 稠密向量 | 语义 ID 序列(如 3-4 个码字) |
| 检索方式 | 向量近邻(ANN) | 自回归**生成** item ID |
| 索引 | 需 ANN 索引 | 模型参数即索引 |
| 冷启动 | 需向量 | 语义 ID 天然泛化 |
| 记忆容量 | 受向量维度 | 受模型参数 |

**核心转变**: 不再"编码 item 再检索", 而是像 GPT 生成文本一样, 给定用户历史, **逐 token 生成目标 item 的语义 ID**。

---

## 2. 为什么走向生成式

1. **端到端**: 检索直接由模型生成, 省去独立 ANN 系统与一致性维护。
2. **语义泛化**: SID 让相似 item 共享前缀码字, 冷启/长尾天然受益(见 [第05章-冷启动](../第05章-统一语义空间与冷启动/第05章-03-冷启动数学解释.md))。
3. **参数即记忆**: 借 LLM 的 scaling 红利, 用更大模型记住更多物料关系。
4. **统一建模**: 检索、排序、生成解释可在一个生成框架里统一。

---

## 3. TIGER 架构骨架

TIGER(Rajput et al. 2023): item 用 RQ-VAE 编成语义 ID, 用户历史 item 的 SID 序列作输入, T5 式 encoder-decoder 生成目标 item 的 SID。

```python
import torch, torch.nn as nn

class GenerativeRetriever(nn.Module):
    """seq2seq 生成目标 item 的语义 ID (概念骨架)"""
    def __init__(self, codebook_size, n_levels, d_model, n_layer):
        super().__init__()
        # 每个码本层级一套 token embedding (加偏移避免冲突)
        self.vocab = codebook_size * n_levels + 2      # +BOS/EOS
        self.tok_emb = nn.Embedding(self.vocab, d_model)
        self.transformer = nn.Transformer(
            d_model, batch_first=True, num_encoder_layers=n_layer,
            num_decoder_layers=n_layer)
        self.head = nn.Linear(d_model, self.vocab)
        self.n_levels = codebook_size

    def forward(self, hist_sids, tgt_sids):
        # hist_sids: 用户历史 item 展平的 SID 序列 (B, L)
        # tgt_sids:  目标 item 的 SID (B, n_levels)  teacher forcing
        src = self.tok_emb(hist_sids)
        tgt = self.tok_emb(tgt_sids)
        out = self.transformer(src, tgt)
        return self.head(out)                          # 预测下一个码字
```

训练: teacher forcing 交叉熵, 预测目标 item 每一级码字。

## 4. 生成 ≠ 保证合法

自由生成的码字序列**可能对应不存在的 item**(码本组合空间远大于真实物料)。因此必须**约束解码**到合法 item 集合 —— 这是生成式检索工程落地的关键, 见 [12-02](第12章-02-约束Beam-Search与Trie解码.md)。

---

## 5. 优势与挑战

**优势**: 端到端、语义泛化、冷启友好、可扩展。

**挑战**:
- 合法性约束(解码到真实 item)。
- 推理延迟(自回归多步, 需 KV Cache / 并行解码)。
- 新 item 加入需更新码本/模型(增量学习难)。
- 大规模物料下的召回率与多样性。

## 1. 推荐系统的根本问题

### 1.1 我们要解决什么?

给定用户 $u$ 和历史行为 $\{i_1, i_2, \ldots, i_T\}$, 从物料库 $\mathcal{I}$ (亿级) 中挑出 top-K 推荐。

传统:
- **判别式 (双塔 + ANN)**: 学习 $\phi(u) \cdot \psi(i) \to$ 相似度, 然后 ANN
- **生成式 (SID + seq2seq)**: 模型直接**生成**物品 ID

### 1.2 判别式 vs 生成式

| 维度 | 判别式 (传统) | 生成式 (SID) |
| :--- | :--- | :--- |
| **item 表示** | 稠密向量 (e.g. 256-d) | 离散 ID (e.g., 3 个码字) |
| **索引方式** | Faiss / Milvus / VDB | 模型参数 / Trie |
| **检索** | 向量近邻 (ANN) | 自回归生成 |
| **冷启动** | 难 (需向量) | 易 (语义即可) |
| **记忆方式** | 向量 similarity | 模型参数 |
| **规模** | 受向量维度限制 | 受模型参数限制 |
| **推理延迟** | 5-15 ms | 30-80 ms |
| **训练数据** | 用户行为日志 | 用户行为日志 |

### 1.3 优势对比

| | 判别式 | 生成式 |
| :--- | :--- | :--- |
| **训练速度** | 快 | 慢 |
| **部署复杂度** | 中 (需 Faiss 服务) | 高 (需 Trie + 顺序推理) |
| **业务效果** | baseline | +5% ~ +30% (因业务而异) |
| **冷启动** | 难 | 易 |
| **长尾** | 差 | 好 |
| **可扩展性** | 难扩 | 易扩 (大模型 scaling) |

### 1.4 何时用哪个?

```text
你的场景?
├── 亿级物品, 低延迟 (5ms)
│   └── 双塔 + Faiss (传统)
│
├── 千万级, 离线训练资源充足
│   └── 生成式检索 (TIGER 风格)
│
├── 强冷启动 / 新物品多
│   └── 生成式 (LLM-Encoder + SID)
│
├── 短视频 / 多模态
│   └── 生成式 (Multimodal-SID)
│
└── 多任务 / 重排
    └── 生成式 + 业务规则
```

## 2. 为什么走向生成式检索?

### 2.1 六大原因

#### A. 端到端 (End-to-End)

```python
# 判别式: 多阶段各自训练
# Stage 1: 双塔训练 (用 user × item 隐式反馈)
# Stage 2: ANN 索引 (离线)
# Stage 3: 在线粗排 (离线训练)
# Stage 4: 在线精排 (离线训练)
# 每阶段独立, 信息损失

# 生成式: 一站式
# 训练: 用户历史 → Transformer → SID
# 推理: 用户历史 → Transformer → Trie-constrained Beam → top-K
# 单一模型, 端到端
```

信息损失最小, 各阶段不会出现"前优化后恶化"。

#### B. 语义泛化

```python
# 判别式: 新物品需要向量
new_item = get_embedding(new_item_id)  # 难题: 冷启动

# 生成式: 语义即可
new_sid = llm_tokenizer.encode(new_item_text)
# 自动获得合理 SID, 因为语义近的物品 SID 前缀近
```

#### C. 参数即记忆

```python
# 模型越大, 记住的 item 关系越多
# 7B 参数可记忆数千万 item 关系
# 70B 参数可记忆数亿
```

参数 scaling 红利被借到推荐系统。

#### D. 统一建模

```python
# 一个 Transformer 同时:
#   - 检索 (生成 top-K)
#   - 排序 (精排)
#   - 解释 (生成自然语言解释)
#   - 对话 (RAG)
```

#### E. 跨任务泛化

```python
# 训练: 召回 + 排序联合损失
# 推理: 同一模型, 不同 temperature
```

#### F. 与 LLM 生态打通

```python
# LLM 生成 SID (LLM-as-Tokenizer)
# LLM 用 SID 表查询 (RAG)
# LLM 解释推荐 (CoT)
```

### 2.2 一个直观的例子

```text
判别式: "你是用户 A, 你可能喜欢?"
→ 计算 user_emb × item_emb_1, item_emb_2, ...
→ 取 top-K 相似

生成式: "你是用户 A, 你下一个物品的 ID 是?"
→ Transformer 逐码字生成 SID
→ Trie 约束合法
→ 反查 SID → item
```

本质: **判别式是"算相似度"**, **生成式是"算条件概率"**.

## 3. TIGER: 起点

### 3.1 论文背景

**TIGER** (Transformer Index for Generative RECommenders), Rajput et al., RecSys 2023, Meta。

**核心贡献**:
- 首次系统性地把"生成式"应用到工业推荐召回
- RQ-VAE 训语义 ID
- T5 式 encoder-decoder 生成

### 3.2 TIGER 架构详解

```python
class TIGER(nn.Module):
    """TIGER 完整实现"""
    def __init__(self, n_items, codebook_size, n_layers, d_model, n_decoder_layers):
        super().__init__()
        self.n_items = n_items
        self.codebook_size = codebook_size  # 256
        self.n_layers = n_layers  # 3-4

        # 1. RQ-VAE (离线训练, 在线冻结)
        self.rq_vae = RQVAE(input_dim=256, dim=128, num_codes=256, num_layers=self.n_layers)

        # 2. Encoder: 用户历史 → 序列表征
        encoder_layer = nn.TransformerEncoderLayer(d_model, nhead=4, dim_feedforward=512)
        self.encoder = nn.TransformerEncoder(encoder_layer, num_layers=n_decoder_layers)

        # 3. Decoder: 自回归生成 SID
        decoder_layer = nn.TransformerDecoderLayer(d_model, nhead=4, dim_feedforward=512)
        self.decoder = nn.TransformerDecoder(decoder_layer, num_layers=n_decoder_layers)

        # 4. SID Token Embeddings (各层独立)
        self.sid_token_embs = nn.ModuleList([
            nn.Embedding(codebook_size, d_model) for _ in range(n_layers)
        ])

        # 5. 输出头: 每位置码字 logits
        self.code_logits = nn.Linear(d_model, codebook_size)

        # 6. 特殊 token
        self.bos_emb = nn.Parameter(torch.randn(d_model))

    def forward(self, user_history_sids, target_sids=None):
        """训练时: 计算 loss; 推理时: 返回 None"""
        # user_history_sids: [B, L_history, K]
        # target_sids: [B, K]

        B, L, K = user_history_sids.shape
        # 1. Embed history (把 SID 当序列)
        history_seq = self._embed_history(user_history_sids)  # [B, L*K, D]
        # 2. Encode
        memory = self.encoder(history_seq)  # [B, L*K, D]

        if target_sids is None:
            return None

        # 3. Embed target with teacher forcing
        target_emb = self._embed_target(target_sids)  # [B, K, D]
        decoder_in = torch.cat([self.bos_emb.expand(B, 1, -1), target_emb[:, :-1]], dim=1)
        # 4. Decode
        out = self.decoder(decoder_in, memory)
        # 5. Predict code logits
        return self.code_logits(out)  # [B, K, codebook_size]

    def _embed_history(self, sids):
        """History: 把每层 SID 当序列 token"""
        B, L, K = sids.shape
        # 各层 lookup
        embs = []
        for k in range(K):
            e = self.sid_token_embs[k](sids[:, :, k])  # [B, L, D]
            embs.append(e)
        return torch.stack(embs, dim=-2).reshape(B, L * K, -1)

    def _embed_target(self, sids):
        """Target: 各层 lookup, 取均值 (避免重叠)"""
        return sum(
            self.sid_token_embs[k](sids[:, k])
            for k in range(sids.shape[1])
        ).unsqueeze(1)

    @torch.no_grad()
    def generate(self, user_history, trie, beam_size=100, top_k=10):
        """生成式推理"""
        # 用 constrained beam search (见第 12 章-02)
        from .constrained_beam import constrained_beam_search
        return constrained_beam_search(
            self, user_history, trie,
            n_levels=self.n_layers,
            vocab_size=self.codebook_size,
            beam=beam_size,
            top_k=top_k
        )
```

### 3.3 训练

**输入**: 真实用户的物品历史序列 $\{(u_1, i_1), (u_2, i_2), \ldots\}$, 每物品用 RQ-VAE 编码成 SID。

**目标**: teacher forcing, 最大化下一个码字的对数似然:

$$\mathcal{L} = -\sum_{u} \sum_{k=1}^{K} \log P_\theta(c_k^{(u)} | \text{history}^{(u)}, c_1^{(u)}, \ldots, c_{k-1}^{(u)})$$

**优化**: Adam, lr=3e-4, batch=64, epoch=20。

### 3.4 TIGER 的优势 vs 局限

| 优势 | 局限 |
| :--- | :--- |
| 简单 (encoder-decoder) | 仅用 SID, 不直接利用内容 |
| RecSys 2023 起源 | 推理较慢 (3 步 decode) |
| T5 系列可用 | 多模态需额外工作 |
| Meta 公开代码 | 模型大 (1B+), 难训 |

## 4. OneRec: 端到端扩展

### 4.1 论文背景

**OneRec**, 阿里 KDD 2024。

**核心思想**: 跳过召回, 直接生成 top-K 推荐。

### 4.2 OneRec 架构

```python
class OneRec(nn.Module):
    """端到端 GR: 跳过召回"""
    def __init__(self, n_items, codebook_size, n_layers, d_model=512):
        super().__init__()
        self.sid_emb = SIDEmbedding(codebook_size, n_layers, d_model)
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model, nhead=8, dim_feedforward=2048),
            num_layers=12
        )
        # 输出: 每个位置码字 logits
        self.code_head = nn.Linear(d_model, codebook_size)

    def forward(self, user_history):
        """用户历史 → SID logits"""
        # user_history: [B, L_history, K]
        emb = self.sid_emb(user_history)  # [B, L_history, D]
        # Transformer
        out = self.transformer(emb)
        # Logits
        return self.code_head(out)  # [B, L_history, codebook_size]
```

### 4.3 OneRec 的工程关键

```python
# 1. 训练数据: 100 亿样本
```

## 5. HSTU: 工业级广义 Attention

### 5.1 论文背景

**HSTU** (Hierarchical Sequential Transduction Unit), Meta SIGIR 2024。

### 5.2 核心创新

```python
class HSTU(nn.Module):
    """HSTU: 广义 Attention"""
    def __init__(self, dim, n_heads, n_layers):
        super().__init__()
        self.layers = nn.ModuleList([
            HSTULayer(dim, n_heads) for _ in range(n_layers)
        ])

    def forward(self, sequences):
        """sequences: [B, L, D] 用户行为序列"""
        h = sequences
        for layer in self.layers:
            h = layer(h)
        return h


class HSTULayer(nn.Module):
    """广义 attention: 无 softmax"""
    def __init__(self, dim, n_heads):
        super().__init__()
        self.qkv = nn.Linear(dim, 3 * dim)
        self.out = nn.Linear(dim, dim)
        self.n_heads = n_heads

    def forward(self, x):
        """核心修改: 不要 softmax"""
        B, L, D = x.shape
        qkv = self.qkv(x).reshape(B, L, 3, self.n_heads, D // self.n_heads)
        q, k, v = qkv.unbind(dim=2)
        # 广义 attention: 没有 softmax
        # 直接 QKV (类线性)
        attn = q @ k.transpose(-2, -1)  # 不要 / sqrt, 不要 softmax
        out = (attn @ v).reshape(B, L, D)
        return self.out(out)
```

### 5.3 HSTU vs Transformer

| 维度 | Transformer | HSTU |
| :--- | :--- | :--- |
| Attention | $Q K^T / \sqrt{d}$ + softmax | $Q K^T$ (no softmax) |
| 归一化 | softmax | LayerNorm |
| 多任务 | 各任务不同 head | 各任务不同 head, 主干共享 |
| 推荐 / NLP | NLP 友好 | 推荐行为序列友好 |

**为什么去掉 softmax?** 推荐系统不像 NLP, 稀有 token 不该被压平。

### 5.4 业务结果

- Recall@10: +38% (vs 标准 Transformer)
- 训练吞吐: 5x
- 推理延迟: 3x 加速
- Meta Reels 部署

## 6. 多任务生成式推荐

### 6.1 多任务 SID 训练

```python
class MultiTaskSID(nn.Module):
    """SID 与多任务学习"""
    def __init__(self, n_items, codebook_size, n_layers, d_model):
        super().__init__()
        # 共享 SID Emb
        self.sid_emb = SIDEmbedding(codebook_size, n_layers, d_model)
        # Transformer
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model, nhead=4), num_layers=6
        )
        # 多任务 head
        self.recall_head = nn.Linear(d_model, codebook_size)  # 召回
        self.rank_head = nn.Linear(d_model, 1)  # 排序
        self.ctr_head = nn.Linear(d_model, 1)  # CTR
        self.cvr_head = nn.Linear(d_model, 1)  # CVR

    def forward(self, user_history):
        emb = self.sid_emb(user_history)
        out = self.transformer(emb)
        return {
            'recall': self.recall_head(out[:, -1]),
            'rank': self.rank_head(out[:, -1]).squeeze(-1),
            'ctr': self.ctr_head(out[:, -1]).squeeze(-1),
            'cvr': self.cvr_head(out[:, -1]).squeeze(-1),
        }


def multi_task_loss(outputs, labels, weights=None):
    """多任务损失加权"""
    if weights is None:
        weights = {'recall': 1.0, 'rank': 0.5, 'ctr': 1.0, 'cvr': 1.0}
    loss = 0
    for task, logit in outputs.items():
        if task == 'recall':
            loss_t = F.cross_entropy(logit, labels[task])
        else:
            loss_t = F.binary_cross_entropy_with_logits(logit, labels[task])
        loss = loss + weights[task] * loss_t
    return loss
```

```python
def ppo_train_step(policy, ref_policy, history, target_sid, reward):
    """PPO 一步"""
    # 1. 当前策略 logp
    new_logits = policy(history)
    new_logp = F.log_softmax(new_logits, dim=-1)
    # 2. Reference logp
    with torch.no_grad():
        ref_logits = ref_policy(history)
        ref_logp = F.log_softmax(ref_logits, dim=-1)
    # 3. ratio
    ratio = torch.exp(new_logp - ref_logp)
    # 4. PPO loss
    surr1 = ratio * reward
    surr2 = ratio.clamp(0.8, 1.2) * reward
    loss = -torch.min(surr1, surr2).mean()
    # 5. KL 约束
    kl = (new_logp - ref_logp).mean()
    loss = loss + 0.1 * kl
    return loss
```

### 13.1 完整的端到端训练 + 推理

```python
"""完整示例: 训 RQ-VAE → 生成 SID → 训 TIGER → 生成式检索"""

import torch
import torch.nn as nn
import torch.nn.functional as F
from sentence_transformers import SentenceTransformer

# ============ 步骤 1: 数据准备 ============
items_text = ["item1 text", "item2 text", ...]
encoder = SentenceTransformer('BAAI/bge-large-zh-v1.5')
embeddings = encoder.encode(items_text)
print(f'Embeddings shape: {embeddings.shape}')

# ============ 步骤 2: 训练 RQ-VAE ============
class RQVAE(nn.Module):
    def __init__(self, input_dim, dim, num_codes, num_layers):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Linear(input_dim, 512), nn.GELU(),
            nn.Linear(512, 256), nn.GELU(),
            nn.Linear(256, dim))
        self.decoder = nn.Sequential(
            nn.Linear(dim, 256), nn.GELU(),
            nn.Linear(256, 512), nn.GELU(),
            nn.Linear(512, input_dim))
        self.codebooks = nn.ParameterList([
            nn.Parameter(torch.randn(num_codes, dim) * 0.05)
            for _ in range(num_layers)
        ])
        self.num_layers = num_layers
        self.dim = dim

    def forward(self, x):
        z_e = self.encoder(x)
        return self.encode(z_e)

    def encode(self, z_e):
        residual = z_e
        sids = []
        z_q_total = 0
        vq_loss = 0
        for cb in self.codebooks:
            dist = (residual.pow(2).sum(-1, keepdim=True)
                    - 2 * residual @ cb.t()
                    + cb.pow(2).sum(-1))
            codes = dist.argmin(-1)
            z_q = cb[codes]
            z_q_st = residual + (z_q - residual).detach()
            z_q_total = z_q_total + z_q_st
            vq_loss = vq_loss + F.mse_loss(z_q_st, residual.detach())
            residual = residual - z_q_st
            sids.append(codes)
        return z_q_total, torch.stack(sids, -1), vq_loss

rq_vae = RQVAE(input_dim=1024, dim=128, num_codes=256, num_layers=4)
opt = torch.optim.AdamW(rq_vae.parameters(), lr=1e-3)
for epoch in range(50):
    # 训练循环 (简化)
    x_batch = torch.tensor(embeddings[epoch*64:(epoch+1)*64])
    z_q, sids, vq_loss = rq_vae(x_batch)
    recon_loss = F.mse_loss(rq_vae.decoder(z_q), x_batch)
    loss = recon_loss + vq_loss
    opt.zero_grad(); loss.backward(); opt.step()
print('RQ-VAE 训练完成')

# ============ 步骤 3: 全量编码 ============
@torch.no_grad()
def encode_all(rq_vae, embeddings, batch_size=256):
    all_sids = []
    for i in range(0, len(embeddings), batch_size):
        x = torch.tensor(embeddings[i:i+batch_size])
        _, sids, _ = rq_vae(x)
        all_sids.append(sids)
    return torch.cat(all_sids, 0)

all_sids = encode_all(rq_vae, embeddings)
print(f'SIDs shape: {all_sids.shape}')  # [N, K]

# ============ 步骤 4: 构建 Trie ============
class SidTrie:
    def __init__(self):
        self.root = {}
    def insert(self, sid):
        node = self.root
        for c in sid:
            node = node.setdefault(int(c), {})
        node['#'] = True
    def allowed(self, prefix):
        node = self.root
        for c in prefix:
            if c not in node: return set()
            node = node[c]
        return {k for k in node if k != '#'}
    def is_leaf(self, prefix):
        node = self.root
        for c in prefix:
            if c not in node: return False
            node = node[c]
        return '#' in node

trie = SidTrie()
for sid in all_sids:
    trie.insert(sid.tolist())

# ============ 步骤 5: 训练 TIGER ============
class SimpleTIGER(nn.Module):
    """简化版"""
    def __init__(self, codebook_size, n_layers, d_model):
        super().__init__()
        self.d_model = d_model
        self.n_layers = n_layers
        self.codebook_size = codebook_size
        # 各层独立 embedding
        self.sid_embs = nn.ModuleList([nn.Embedding(codebook_size, d_model) for _ in range(n_layers)])
        # Transformer
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model, nhead=4), num_layers=4
        )
        # 输出头
        self.head = nn.Linear(d_model, codebook_size)

    def forward(self, history_sids):
        # history_sids: [B, L, K]
        B, L, K = history_sids.shape
        embs = []
        for k in range(K):
            e = self.sid_embs[k](history_sids[:, :, k])  # [B, L, D]
            embs.append(e)
        x = torch.stack(embs, dim=-2).reshape(B, L * K, -1)
        out = self.transformer(x)
        return self.head(out[:, -1])  # 预测下一码字

tiger = SimpleTIGER(codebook_size=256, n_layers=4, d_model=128)
# 训练循环 (简化)
# ...

# ============ 步骤 6: 推理 ============
def constrained_beam_search(model, history, trie, n_levels, vocab, beam=10, top_k=5):
    beams = [Beam(prefix=[], score=0.0, hidden=model.sid_embs[0](torch.tensor([0]))) ]
    for level in range(n_levels):
        candidates = []
        for beam in beams:
            allowed = trie.allowed(beam.prefix)
            if not allowed:
                continue
            # 模型预测
            history_sids = torch.tensor([beam.prefix[:-1] + [0] * (n_levels - len(beam.prefix) + 1)])  # 简化
            logits = model(history_sids)[0]
            # Mask
            mask = torch.full((vocab,), float('-inf'))
            mask[list(allowed)] = 0.0
            log_probs = F.log_softmax(logits + mask, dim=-1)
            # Top-K
            top_v, top_i = log_probs.topk(min(beam, len(allowed)))
            for v, i in zip(top_v.tolist(), top_i.tolist()):
                new_prefix = beam.prefix + [i]
                candidates.append(Beam(prefix=new_prefix, score=beam.score + v, hidden=beam.hidden))
        candidates.sort(key=lambda x: x.score, reverse=True)
        beams = candidates[:beam]
        if not beams: break

    # 过滤完整 SID
    final = [b for b in beams if trie.is_leaf(b.prefix)]
    return [b.prefix for b in final[:top_k]]

# 推荐
user_history_sids = torch.tensor([all_sids[0].tolist()])  # 简化
results = constrained_beam_search(tiger, user_history_sids, trie, n_levels=4, vocab=256)
print(f'推荐: {results}')
```

### Q1: 生成式检索与双塔的本质区别?

| 维度 | 双塔 | 生成式 |
| :--- | :--- | :--- |
| item 表示 | 连续向量 | 离散 ID (SID) |
| 检索 | ANN 向量近邻 | 自回归生成 |
| 模型大小 | 用户塔 + item 塔 | 单一 Transformer |
| 索引 | Faiss 索引 (大) | 模型参数 + Trie (小) |

### Q2: 为什么 SID 让冷启动更好?

答: SID 用 LLM 编码语义, 新物品文本 → 语义相似的物品 SID 接近。
语义近 → SID 前缀共享 → 在用户行为序列中也能"借位"。

### Q3: TIGER 用什么模型?

答: RQ-VAE 训 SID + T5 式 encoder-decoder 生成。

### Q4: OneRec 与 TIGER 区别?

答: OneRec 端到端 (跳过召回), TIGER 是召回 (再接排序)。

### Q5: HSTU 与 Transformer 区别?

答: HSTU 没有 softmax (推荐行为序列不需要 softmax), 多任务联合训练。

### Q6: 端到端 GR 的核心优势?

答: 单一模型, 端到端训练, 减少信息损失。业务指标 +5-30%。

### Q7: 端到端 GR 的工程挑战?

答:
- 训练数据大 (千亿)
- 训练时间长 (1 周+)
- 推理延迟 (KV Cache + Trie + 量化)
- 采样 softmax (避免全词表)

### Q8: OneRec 的业务收益?

答: CTR +8.5%, GMV +6.2%, 维护成本 -80%。

### Q9: 约束解码的核心?

答: Trie + logits mask, 保证生成合法 SID。

### Q10: 生成式检索的未来?

答:
- 与 LLM 双向赋能
- 多模态原生
- 实时更新 / 联邦
- World Model 结合

## 18. 一些"反潮流"思考

### 18.1 生成式检索≠一定好

**生成式不是银弹**:

- 简单业务: 双塔足够, 不必生成式
- 冷数据稀疏: 端到端难训
- 业务复杂: 排序规则不一定能生成式学到

**实际建议**:
1. 双塔 + ANN baseline
2. A/B 测试决定引入端到端
3. 慢慢迁移, 不必一步到位

### 18.2 SID≠一定要 RQ-VAE

**SID 可以用其他编码**:

- 哈希 (LSH): 极快, 简单
- 直方图: 紧凑
- 树: 层次化
- 深度哈希: 数据驱动

**RQ-VAE 是当前主流**, 但不唯一。

### 18.3 不必追所有新方法

很多新颖 SID 方法 (CapsID, R3-VAE) 在工业上**不可行**:

- 太复杂
- 推理慢
- 难训练

经典 RQ-VAE + LLM-Tokenizer 已够用 99% 业务。

## 20. 进阶话题: 生成式检索的"形式化"

### 20.1 形式化定义

**判别式检索**:

$$p(i | u) = \frac{\exp(\text{sim}(\phi(u), \psi(i)))}{\sum_{j \in \mathcal{I}} \exp(\text{sim}(\phi(u), \psi(j)))}$$

需要计算**全物品库**, 用 ANN 近似。

**生成式检索**:

$$p(i | u) = \prod_{k=1}^{K} p_\theta(c_k | u, c_1, \ldots, c_{k-1})$$

其中 $i$ 的 SID 是 $(c_1, \ldots, c_K)$。

**关键差别**:
- 判别式: "算 similarity"
- 生成式: "算条件概率序列"

### 20.2 数学性质

生成式检索的**优势**在两个数学性质:

#### 性质 1: 共享前缀

如果两个物品 $i, i'$ 语义近, 它们的 SID $(c_1, c_2, c_3)$ 与 $(c_1, c_2, c_3')$ 共享前缀, 模型可以**联合预测**:

$$p(c_1, c_2, c_3 | u) \approx p(c_1, c_2 | u) \cdot p(c_3 | u, c_1, c_2)$$

近似更**精细**判别式。

#### 性质 2: 端到端损失

生成式用一个 loss 直接优化:

$$\mathcal{L} = -\frac{1}{N} \sum_{n=1}^{N} \log p_\theta(\text{SID}(i_n) | u_n)$$

不需要 multi-stage 协调。

### 20.3 信息论视角

**判别式**:
- "用户对哪些物品有偏好?" → 评分
- 本质是**判别**: 区分正负样本

**生成式**:
- "用户的下一个物品是什么?" → 序列生成
- 本质是**生成**: 学到联合分布

**联合分布**: $p(i, u) = p(u) \cdot p(i | u)$。

判别式: 学 $p(i | u)$ 的一部分 (用 $\text{sim}$ 近似)。
生成式: 学 $p(i | u)$ 的全部 (用条件概率链)。

**理论上**, 生成式更优。

## 21. 推荐系统中的"语言模型"

### 21.1 类比

| LLM | 推荐系统 |
| :--- | :--- |
| Token (词) | Item (物品) |
| Sentence (句子) | Session (会话) |
| Document (文档) | User history (用户全部历史) |
| Embedding (词向量) | SID Embedding |
| LM Loss (predict next token) | GR Loss (predict next item) |

**本质**: 推荐 = 通用 LM 在 item 序列上的特例。

### 21.2 用 LLM 视角看 SID

LLM 用 BPE tokenization: 文本 → 256 个 BPE token ID → 序列。
推荐用 RQ-VAE tokenization: item → 256 个码字 × K 层 → 序列。

**SID 是 item 的"tokenization"**。

### 21.3 LLM-as-Tokenizer

```python
class LLMTokenizerForRec:
    """用 LLM 作为 item 的 tokenizer"""
    def __init__(self, llm_name='Qwen/Qwen2-7B'):
        self.llm = AutoModel.from_pretrained(llm_name)
        for p in self.llm.parameters():
            p.requires_grad = False
        self.proj = nn.Linear(self.llm.config.hidden_size, 128)
        # RQ 编码
        self.rq = ResidualQuantizer(num_codes=256, dim=128)

    def tokenize_item(self, text):
        """item text → SID (类似 LLM 的 tokenize)"""
        with torch.no_grad():
            emb = self.llm(text).last_hidden_state.mean(dim=1)
        z = self.proj(emb)
        sid = self.rq.encode(z)
        return sid
```

**LLM 的语义 → SID 的离散 → 推荐系统的输入**, 形成完整闭环。

```python
# onrec.py
class SimpleOneRec(nn.Module):
    """简化版 OneRec"""
    def __init__(self, codebook_size=256, n_layers=4, d_model=256):
        super().__init__()
        self.sid_emb = SIDEmbedding(codebook_size, n_layers, d_model)
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model, nhead=4, dim_feedforward=1024),
            num_layers=4
        )
        self.code_head = nn.Linear(d_model, codebook_size)

    def forward(self, history_sids):
        emb = self.sid_emb(history_sids)  # [B, L, D]
        out = self.transformer(emb)
        return self.code_head(out[:, -1])  # 下一码字
```

### 25.4 训练循环

```python
"""train_onrec.py"""
import torch
import torch.nn.functional as F
from torch.utils.data import DataLoader, Dataset

class SIDDataset(Dataset):
    def __init__(self, history_sids, target_sids):
        self.history = history_sids  # [N, L, K]
        self.target = target_sids  # [N, K]

    def __len__(self):
        return len(self.history)

    def __getitem__(self, i):
        return self.history[i], self.target[i]


def train_one_epoch(model, loader, optimizer, device='cuda'):
    model.train()
    total_loss = 0
    for history, target in loader:
        history = history.to(device)
        target = target.to(device)
        logits = model(history)
        # 预测目标 SID 的第一个码字 (简化)
        loss = F.cross_entropy(logits, target[:, 0])
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
        total_loss += loss.item()
    return total_loss / len(loader)


model = SimpleOneRec()
optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)
dataset = SIDDataset(history_sids, target_sids)
loader = DataLoader(dataset, batch_size=64, shuffle=True)

for epoch in range(20):
    loss = train_one_epoch(model, loader, optimizer)
    print(f'Epoch {epoch+1}: loss={loss:.4f}')
```

```python
@torch.no_grad()
def evaluate(model, test_history, test_target, trie, top_k=10):
    model.eval()
    recalls = []
    for h, t in zip(test_history, test_target):
        h = h.unsqueeze(0).cuda()
        # 生成式预测
        results = constrained_beam_search(model, h, trie, top_k=top_k)
        # Recall
        target_sid = t.tolist()
        hit = any(r[:len(target_sid)] == target_sid for r in results)
        recalls.append(1 if hit else 0)
    return sum(recalls) / len(recalls)
```

## 27. 与 LLM 的"双向赋能"

### 27.1 LLM 给 SID 提供什么?

1. **强 Encoder**: LLM 比 BERT 强 5-10x
2. **多语言**: 一致 SID
3. **冷启动**: 语义即可

### 27.2 SID 给 LLM 提供什么?

1. **物品索引**: LLM 输出 query, SID 表返回物品
2. **RAG 工具**: 在 LLM 推理中调用
3. **结构化输出**: SID 是有限集合, 易于解析

### 27.3 一个完整的 LLM + SID 推荐系统

```python
class LLMSIDRec:
    """LLM + SID 完整推荐"""
    def __init__(self):
        self.llm = QwenForCausalLM.from_pretrained('qwen-7b')
        self.sid_tokenizer = LLMSemanticTokenizer()
        self.sid_table = load_sid_table()
        self.trie = build_trie_from_sids(self.sid_table.values())
        self.dnn_ranker = DNNRanker()

    def encode(self, item):
        return self.sid_tokenizer.encode(item)

    def recommend(self, user_history):
        # 1. LLM 编码用户历史 + 上下文
        user_emb = self.llm(user_history).last_hidden_state

        # 2. 生成 top-100 SID
        sid_candidates = constrained_beam_search(
            user_emb, self.trie, beam=100
        )

        # 3. 反查 item
        items = [self.sid_to_item[s] for s in sid_candidates]

        # 4. DNN 精排
        ranked_items = self.dnn_ranker.rank(items, user_history)

        return ranked_items[:10]
```

```python
        else:
            # 输入是 query
            seq = self.encode_query(user_input.query)
        out = self.transformer(seq)
        return self.code_head(out[:, -1])
```

```python
class RAGRec:
    """RAG 风格的推荐"""
    def __init__(self):
        self.sid_table = load_sid_table()
        self.trie = build_trie()
        self.llm = LLM()

    def recommend_with_rag(self, user_query):
        # 1. LLM 编码 query → SID
        query_sid = self.llm.encode_sid(user_query)
        # 2. 检索相关 SID
        relevant_sids = self.trie.search_prefix(query_sid, top_k=20)
        # 3. 拿 item 描述
        items = [self.sid_to_item_meta[s] for s in relevant_sids]
        # 4. LLM re-rank + 解释
        prompt = f"用户 query: {user_query}\n候选: {items}\n推荐:"
        final = self.llm.generate(prompt)
        return final
```

### 34.1 SID (Semantic ID)

- **定义**: 用离散 ID 表示 item, 一般 K=3-4 层, 每层 256 个码字

### 37.1 模型

```python
class MiniOneRec(nn.Module):
    """200 行实现 OneRec 简化版"""
    def __init__(self, codebook_size=256, n_layers=4, d_model=256, n_history=10):
        super().__init__()
        # SID Embedding
        self.sid_emb = nn.ModuleList([
            nn.Embedding(codebook_size, d_model) for _ in range(n_layers)
        ])
        # Transformer
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d_model, nhead=4, dim_feedforward=512),
            num_layers=4
        )
        # 输出头
        self.code_head = nn.Linear(d_model, codebook_size)
        # 用户历史位置编码
        self.pos_enc = nn.Embedding(n_history, d_model)

    def forward(self, history_sids):
        """
        history_sids: [B, n_history, K]
        return: [B, codebook_size] (下一码字 logits)
        """
        B, L, K = history_sids.shape
        # Embed history
        x = torch.stack([
            self.sid_emb[k](history_sids[:, :, k])
            for k in range(K)
        ], dim=-2).mean(dim=-2)  # [B, L, D]
        # 加位置编码
        positions = torch.arange(L, device=x.device)
        x = x + self.pos_enc(positions).unsqueeze(0)
        # Transformer
        out = self.transformer(x)
        # 预测下一码字
        return self.code_head(out[:, -1])
```

```python
"""生成式推理"""
@torch.no_grad()
def generate_sequence(model, history_sids, trie, max_len=4, beam=10):
    """用约束 Beam Search 生成完整 SID"""
    beams = [Beam(prefix=[], score=0.0)]
    for level in range(max_len):
        candidates = []
        for beam in beams:
            if trie.is_leaf(beam.prefix):
                continue
            allowed = trie.allowed(beam.prefix)
            if not allowed:
                continue
            logits = model._step_with_prefix(history_sids, beam.prefix)
            mask = torch.full((logits.shape[-1],), float('-inf'))
            mask[list(allowed)] = 0.0
            log_probs = F.log_softmax(logits + mask, dim=-1)
            top_v, top_i = log_probs.topk(min(beam, len(allowed)))
            for v, i in zip(top_v.tolist(), top_i.tolist()):
                new_prefix = beam.prefix + [i]
                candidates.append(Beam(prefix=new_prefix, score=beam.score + v))
        candidates.sort(key=lambda x: x.score, reverse=True)
        beams = candidates[:beam]
    return [b.prefix for b in beams if trie.is_leaf(b.prefix)]
```

**7. 实践建议**

结合 "生成式检索范式" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "生成式检索范式" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

**7. 实践建议**

结合 "生成式检索范式" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "生成式检索范式" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
