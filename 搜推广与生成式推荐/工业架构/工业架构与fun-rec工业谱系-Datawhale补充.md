## 二、核心补充内容

### 2.1 "论文方案 → 工业方案"的四类降级改造（fun-rec 工业小节总结）

fun-rec 各章工业实践反复出现的改造模式，可作为读任何新论文的"工业化预检清单"：

| 改造类型 | 手段 | fun-rec 出处 |
| :--- | :--- | :--- |
| **算力降级** | 全量计算 → 近似/采样/分层（DPP 贪心化、候选分层） | ch4 重排 |
| **延迟约束** | 精确 → 近似（ANN 替暴力、流式索引替全量重建） | ch2 召回 |
| **依赖简化** | 复杂特征/模型 → 可用子集（特征冷热分级、模型蒸馏） | ch3/ch19 蒸馏 |
| **稳定性加固** | 离线最优 → 在线可用（降级链、兜底策略、影子验证） | ch10 |

**用法**：读完论文先问"四类改造里它动了哪类、还欠哪类"——欠的通常就是论文与生产之间的 gap，也是工程侧的创新空间。

### 2.2 工业谱系的分层视图（把本地 deep-dives 收进坐标系）

本地工业架构目录的各篇大厂 deep-dive 可按 fun-rec 的级联坐标归类，形成全景图：

```text
数据层：埋点 → 样本 → 特征平台（离线/实时）
召回层：多路（CF/向量/序列/热榜）→ 融合
排序层：粗排（轻量）→ 精排（重型）→ 多目标融合
重排层：多样性/业务规则/混排
反馈层：AB 平台 → 归因 → 迭代
```

每篇 deep-dive 读完后标注它覆盖哪几层、在哪层做了与通用谱系不同的选择——"不同点"就是该厂的特色（也是面试素材的差异化部分）。

### 2.3 torch-rechub 作为"工业基线锚点"

工业方案的复现起点：torch-rechub 的模型实现 = "论文结构 + 工程必要简化"的平衡点，适合作为对照基线——比论文代码易读、比 toy 示例完整。与《第24章补充》2.4 的实践方式一致：任何工业方案先在 torch-rechub 同类模型上复现小规模版，再读 deep-dive 对齐工业差异。

## 三、可直接动手的实践

1. 选一篇本地工业架构目录的 deep-dive，用 2.2 五层视图标注其覆盖层与特色选择，写一页对照笔记；
2. 任选一篇近期推荐论文，跑 2.1 四类改造预检，输出"工业化 gap 清单"；
3. 在 torch-rechub 上为 deep-dive 中的核心模型搭一个小规模基线，与文中线上指标的方向性对比（只看相对关系）。
