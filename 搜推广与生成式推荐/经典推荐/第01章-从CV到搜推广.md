# 第01章-从CV到搜推广

点击/转化) |
| :--- | :--- | :--- |
| **输入张量形态** | `[B, C, H, W]` 连续稠密,像素值 0~255 | `[B]` 或 `[B, T]` 离散 ID,取值范围 [0, 几千万) |
| **数据密度** | 稠密,几乎所有像素都"有意义" | 极度稀疏,一个用户-物品交互矩阵 99.99% 是 0 |
| **类别基数** | 通常 1000 类(ImageNet) | 用户/物品/位置/类目 ID 动辄千万~亿级 |
| **特征类型** | 主要是图像本身 | 异构:离散 ID + 连续数值 + 时序序列 + 文本 + 上下文 |
| **样本量** | ImageNet 128 万 | 工业界日均百亿~千亿条曝光 |
| **正负样本比** | 接近 1:1 | 1:100 ~ 1:1000(点击远少于曝光) |

**结论**:CV 里你拿到的 Tensor 都是"已经张好的图",直接喂 Conv2d 就完事;搜推广里你面对的是**一堆原始的 ID 字符串、时间戳、点击日志**,你必须亲手把它们**数值化 → 离散化 → Embedding → 拼成 batch**,每一步都可能踩坑。

**文字**:从 CV 转搜推广,工程师最大的认知冲击是数据形态。CV 拿到 [B,C,H,W] 稠密张量,像素 0-255,Conv2d 算子天然适配。搜推广拿到的是亿级 ID 字符串(用户 ID 109739245、商品 ID 8847362 等),加一串异构特征(年龄 23.5、设备 iphone15、时间戳 1701234567)。两类数据处理路径完全不同:稠密张量直接卷积,离散 ID 必须先 Embedding 查表。参数规模更爆炸:一个 V=10^8 物品、D=32 维的 Embedding 表需要 12.8 GB,比 VGG-16(138 MB)大两个数量级。这不是"换种网络结构"的问题,而是"数据表示范式"根本不同。发展角度看,从 2016 年 Wide&Deep 的稀疏 Embedding,到 2019 年 DLRM 工业级实现,再到 2023 年生成式推荐的 Semantic ID,核心都是"高效表征海量离散 ID"。

**公式**:

$$
\text{Emb\_size} = V \times D \times \text{sizeof(dtype)}
                = 10^8 \times 32 \times 4 \text{ bytes}
                = 12.8 \text{ GB}
$$

其中 V 是 ID 总数,D 是嵌入维度。搜推广里 V 常达 10^8~10^10 级。

**代码**:
```python
import torch
import torch.nn as nn

# CV 视角:稠密张量直接卷积(空间共享权重)
cv_input = torch.randn(8, 3, 224, 224)        # [B, C, H, W]
conv = nn.Conv2d(3, 64, kernel_size=3, padding=1)
cv_output = conv(cv_input)                    # 一次算出整图特征

# 搜推广视角:ID → Embedding 查表 → MLP 打分
item_ids = torch.tensor([109739245, 8847362, 552001])   # 离散 ID
emb_table = nn.Embedding(num_embeddings=10**8, embedding_dim=32)  # 12.8 GB
item_vectors = emb_table(item_ids)            # [3, 32] 只查 3 行,稀疏访存

mlp = nn.Sequential(nn.Linear(32, 128), nn.ReLU(), nn.Linear(128, 1))
scores = mlp(item_vectors)                    # [3, 1] 点击率预估
```

### 1.2 模型目标的根本差异

| 维度         | CV                      | 搜推广                                     |
| :--- | :--- | :--- |
| **核心问题**   | "这张图里有什么?"(分类/检测/分割)    | "给这个用户,在这个上下文,这个物品的点击率是多少?"(CTR/CVR 预估) |
| **模型主干**   | 卷积/Transformer,所有像素共享权重 | Embedding 查表 + 浅层 MLP(精排)或 双塔(召回)       |
| **参数量大头**  | 都在 MLP/Conv 权重里         | **全在 Embedding 表里**(几千万 × 几十维 = 几十 GB)  |
| **推理时延要求** | 100ms 内即可(检测/分割可放宽)     | **< 20ms**(精排),< 5ms(召回)                |
| **过拟合来源**  | 数据少/模型大                 | 长尾 ID 噪声(出现一两次的 ID 严重过拟合)               |

**结论**:CV 里你调参主要调学习率/数据增强;搜推广里你调参要调**正则化强度、Embedding 维度、稀疏更新策略、负采样数**。

**文字**:CV 分类任务是"封闭世界",ImageNet 1000 类固定,训练完对 1001 类无能为力。搜推广面对"开放世界",候选池每天新增(新商家入驻、新商品上架),模型必须泛化到未见过的 ID。评估指标完全不同:CV 用 top-K accuracy(前 K 个预测里包含正确答案),搜推广精排用 AUC(任意正样本打分高于负样本的概率),召回用 Recall@K / Hit@K。背后是业务诉求不同:CV 用户能接受 1 张图识别错,搜推广每漏掉 1 个优质商品都直接损失 GMV。指标演进路径:Accuracy $\to$ AUC $\to$ GAUC(分组 AUC) $\to$ CTCVR(点击$\times$转化) $\to$ 长期 LTV(用户生命周期价值),越来越贴近真实业务。生成式推荐时代又引入 NDCG@K、MRR 等排序指标。

**公式**:
$$
\text{AUC} = P(s_{\text{pos}} > s_{\text{neg}})
          = \frac{\sum_{i \in \text{pos}, j \in \text{neg}} \mathbb{1}[s_i > s_j]}{|\text{pos}| \cdot |\text{neg}|}
$$

对比 top-K accuracy(前 K 个预测里包含正确答案的比例),AUC 关心的是"正负样本打分序",不受候选集大小影响。

**代码**:
```python
import torch

# CV 视角:top-K accuracy(封闭世界,1000 类)
def top_k_accuracy(logits, labels, k=5):
    """logits: [B, 1000], labels: [B]"""
    _, pred = logits.topk(k, dim=1)              # [B, k]
    return pred.eq(labels.view(-1, 1)).any(dim=1).float().mean()

# 搜推广视角:AUC(开放世界,候选集动态变化)
def auc_score(pos_scores, neg_scores):
    """任意正样本打分 > 任意负样本打分 的概率"""
    diff = pos_scores.view(-1, 1) - neg_scores.view(1, -1)  # [N_pos, N_neg]
    return (diff > 0).float().mean()

# 搜推广精排:对 10 万候选打分排序
candidate_scores = torch.randn(100000)          # 10 万候选物品的预估 CTR
top_100 = candidate_scores.topk(100).indices    # 取 top 100 给用户
```

### 1.3 工程要求的根本差异

| 维度 | CV | 搜推广 |
| :--- | :--- | :--- |
| **数据规模** | GB 级(TFRecord) | **TB ~ PB 级**(原始日志) |
| **训练时长** | 几天~几周 | 几小时~几天(数据太大,反而 epoch 跑不完) |
| **线上服务** | 一张图 → 一次推理 | **一次请求 → 数百候选打分**(精排)、**亿级向量召回**(召回) |
| **特征一致性** | 训练/推理输入相同 | **离线特征 ≠ 线上特征**(典型坑,后面会详讲) |
| **可解释性** | 可视化注意力/GradCAM | 几乎不可解释,主要靠业务指标(AUC/CTCVR) |

**结论**:搜推广的工程复杂度主要不在"模型多炫",而在"**数据流**"和"**特征对齐**"上。

**文字**:CV 训练 1 epoch 通常几小时(ResNet-50 on ImageNet $\approx$ 2 小时),搜推广根本跑不完 1 epoch。日均 10^8 条曝光,batch_size=1024,每个 step 0.5s,跑完一轮要 5.6 万秒 $\approx$ 56 天。工业界普遍用"时间窗口滑动采样"代替 epoch。另一个核心差异是 train-inference 分布漂移:训练时用"事后特征"(用户点完后才知道他点过),推理时只有"在线特征"(用户当前请求那一刻),不对齐的话 AUC 看着很高,线上效果却崩盘。这要求工程上必须有"特征版本管理 + 离线/在线一致性校验"机制。发展角度看,Feature Store 成为搜推广团队标配,2020 年 Feast 开源、2022 年 Tecton 商业化,都把特征当"一等公民"管理。

**公式**:
$$
T_{\text{1 epoch}} = \frac{N_{\text{data}}}{\text{batch\_size}} \times t_{\text{step}}
                 = \frac{10^8}{1024} \times 0.5 \text{ s}
                 \approx 5.6 \times 10^4 \text{ s} \approx 56 \text{ 天}
$$

工业界通用做法:按 1 小时滑动窗口采样,每天训练一次,模型版本管理。

**代码**:
```python
# CV:训练-推理完全同分布
train_img = torch.randn(3, 224, 224)            # 训练时
infer_img = torch.randn(3, 224, 224)            # 推理时,完全相同

# 搜推广:必须做特征对齐,否则线上崩盘
class FeatureAligner:
    def __init__(self): self.store = {}

    def get_offline(self, uid, iid):
        return {"click_30d": 150}               # 日志回溯,可能含未来信息

    def get_online(self, uid, iid):
        return {"click_30d": self.store.get(uid, 0)}  # 实时查询

    def check(self, sample):                     # 关键:训练前对齐
        assert abs(self.get_offline(**sample)["click_30d"] -
                   self.get_online(**sample)["click_30d"]) < 0.01
```

### 1.5 过拟合来源的根本差异

| 维度          | CV                  | 搜推广                                                 |
| :--- | :--- | :--- |
| **数据/模型比例** | 数据少、模型大,经典过拟合       | 数据极多,但长尾 ID 稀少,另一种过拟合                               |
| **过拟合症状**   | 训练 loss ↓,验证 loss ↑ | 长尾 ID 训练打分 0.95,线上全错                                |
| **主因**      | 模型参数多于数据样本          | 单个 ID 出现次数过少(1~3 次)                                 |
| **正则化策略**   | Dropout / 数据增强 / L2 | 稀疏 L2(只对被查 Embedding) / 频率感知 dropout / Embedding 衰减 |
| **统计规律**    | 数据近似独立同分布           | 80% 物品出现 < 10 次(幂律分布)                               |

**结论**:CV 的正则化是"全局通用招式",搜推广需要"针对离散 ID 的外科手术式"正则化,否则一上线就崩。

**文字**:CV 过拟合主要来自"模型容量大 + 数据量不足",Dropout/数据增强/L2 就能搞定。搜推广过拟合来源完全不同:长尾 ID 噪声。一个用户-物品对只出现 1 次,模型却学到 0.95 高分,纯噪声。统计上 V=10^8 物品中 80% 出现次数 < 10 次,尾部 ID 的 Embedding 完全被随机梯度噪声"撞"出来。L2 正则化对此有效,损失 $J(θ)$ = $L(θ) + \lambda$||E[mask]||²,只对"被查过"的 Embedding 行加约束,未查过保持随机。发展角度看,业界演化出多种策略:2017 年 DeepFM 用 Sparse Regularization,2020 年 DLRM 用频率感知 dropout(出现 < 5 次直接 mask),2023 年生成式推荐用 Semantic ID 把长尾压缩到公共 token,从根本缓解。

**公式**:
$$
J(\theta) = L(\theta) + \lambda \sum_{i \in \text{queried}} \|E_i\|^2
$$

对比 CV 的 L2(对所有权重加约束),搜推广的 L2 只对"被查询过的 Embedding 行"加约束,未查询行保持随机(下次被查时仍是"陌生"状态)。

**代码**:
```python
import torch
import torch.nn as nn

class FreqAwareEmbedding(nn.Embedding):
    """搜推广专用:只对'被查过'的 Embedding 加 L2"""
    def __init__(self, num_emb, dim):
        super().__init__(num_emb, dim)
        self.query_count = torch.zeros(num_emb)

    def forward(self, input):
        u, c = torch.unique(input, return_counts=True)
        self.query_count[u] += c.float()
        return super().forward(input)

    def l2_loss(self, queried_ids, lam=1e-5):
        return lam * self.weight[queried_ids].pow(2).sum()

    def mask_low_freq(self, input, min_count=5):
        mask = self.query_count[input] < min_count
        return torch.where(mask, torch.zeros_like(input), input)
```

### 1.6 全章小结

**文字**:全章 5 大思维转变:(1) 数据形态,稠密张量 $\to$ 离散 ID + Embedding;(2) 模型目标,封闭分类 $\to$ 开放排序;(3) 工程重点,模型调参 $\to$ 数据流 + 特征对齐;(4) 过拟合来源,模型过大 $\to$ 长尾 ID 噪声;(5) 评估指标,Accuracy $\to$ AUC/CTCVR/LTV。这 5 个转变是连锁反应,数据形态变 $\to$ 模型结构变 $\to$ 工程要求变 $\to$ 训练技巧变 $\to$ 评估指标变。给你的行动建议:(a) 立刻补"概率统计 + 优化理论"两块数学(贝叶斯、梯度下降、凸优化),推荐 Boyd《凸优化》和 Murphy《Probabilistic Machine Learning》;(b) 动手写一遍 nn.Embedding + DataLoader + 负采样的最小可运行 Pipeline;(c) 阅读 1 篇工业界搜推广架构分享(阿里 DIN、字节 BST、Meta DLRM 任选),理解数据流全貌。

**公式**:
$$
\text{CV → 搜推广 5 大思维转变} =
\begin{cases}
\text{数据:稠密张量} \to \text{离散 ID + Embedding} \\
\text{目标:封闭分类} \to \text{开放排序} \\
\text{工程:模型调参} \to \text{数据流 + 特征对齐} \\
\text{过拟合:模型过大} \to \text{长尾 ID 噪声} \\
\text{指标:Accuracy} \to \text{AUC / CTCVR / LTV}
\end{cases}
$$

```python
# 行动 1:动手写一个最小搜推广 Pipeline
import torch
import torch.nn as nn

class MinimalRec(nn.Module):
    def __init__(self, n_items, d=32):
        super().__init__()
        self.item_emb = nn.Embedding(n_items, d)
        self.user_emb = nn.Embedding(100000, d)
        self.mlp = nn.Sequential(nn.Linear(d*2, 128), nn.ReLU(),
                                  nn.Linear(128, 1), nn.Sigmoid())

    def forward(self, uid, iid):
        return self.mlp(torch.cat([self.user_emb(uid), self.item_emb(iid)], 1)).squeeze()

# 行动 2:训练时给 Embedding 单独配正则化
optimizer = torch.optim.Adam([
    {'params': model.mlp.parameters(),     'weight_decay': 1e-5},
    {'params': model.item_emb.parameters(), 'weight_decay': 0},   # Embedding 单独处理
])
```

## 1.7 搜推广核心术语速查表(30 个术语)

**文字**:开会听不懂"AUC 涨了 0.3 个点但 GAUC 没动"、"CTCVR 跌了 0.5%"是转搜推广第一周的常态。本节按 5 大类(业务/模型/架构/数据工程/实验)整理 30 个高频术语,每条给"公式 + 工业界常用阈值 + CV 类比"。建议打印贴墙,前 3 个月高频翻阅。

**公式**:

$$
\begin{aligned}
\text{CTR}    &= \frac{\#\text{click}}{\#\text{imp}} &
\text{CVR}    &= \frac{\#\text{conv}}{\#\text{click}} \\
\text{CTCVR}  &= \text{CTR} \times \text{CVR} = \frac{\#\text{conv}}{\#\text{imp}} &
\text{GMV}    &= \sum_i p_i \cdot q_i \\
\text{LTV}    &= \sum_{t=1}^{T} \frac{\mathbb{E}[r_t]}{(1+d)^t} &
\text{RPM}    &= \frac{\text{GMV}}{\#\text{imp}} \times 1000 \\
\text{AUC}    &= P(s_+ > s_-) &
\text{GAUC}   &= \sum_{u} w_u \cdot \text{AUC}_u, \quad w_u = \frac{n_u}{\sum_v n_v} \\
\text{NDCG@K} &= \frac{\text{DCG@K}}{\text{IDCG@K}}, \quad
\text{DCG@K} = \sum_{i=1}^{K} \frac{2^{rel_i}-1}{\log_2(i+1)} &
\text{MRR}    &= \frac{1}{|Q|}\sum_{q} \frac{1}{\text{rank}_q}
\end{aligned}
$$

| 类别 | 术语 | 中文 | 公式 / 定义 | 工业阈值 | CV 类比 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 业务 | CTR | 点击率 | #click / #imp | 1% ~ 10% | mAP |
| 业务 | CVR | 转化率 | #conv / #click | 0.1% ~ 5% | recall |
| 业务 | CTCVR | 曝光-转化率 | CTR × CVR | 0.01% ~ 0.5% | 端到端精度 |
| 业务 | GMV | 商品交易总额 | Σ(单价×数量) | 行业差异大 | 无 |
| 业务 | LTV | 用户生命周期价值 | Σ 折现未来收益 | 看留存曲线 | 无 |
| 业务 | ARPU | 单用户收入 | 总营收 / DAU | 几十~几百元 | 无 |
| 业务 | RPM | 千次曝光收入 | GMV/imp × 1000 | $0.5 ~ $5 | 无 |
| 模型 | AUC | ROC 下面积 | P(s+>s-) | 0.7 ~ 0.85 | 排序版 acc |
| 模型 | GAUC | 分组 AUC | Σw_u·AUC_u | 0.75+ | 加权 mAP |
| 模型 | LogLoss | 对数损失 | -Σy log p | 越低越好 | 交叉熵 |
| 模型 | NDCG@K | 归一化折损增益 | DCG/IDCG | 排序质量 | mAP@K |
| 模型 | MRR | 平均倒数排名 | mean(1/rank) | 0.3 ~ 0.7 | top-1 倒数 |

```python
import numpy as np
from sklearn.metrics import roc_auc_score, ndcg_score

def calc_gauc(y_true, y_score, group_id):
    """y_true: [N] 0/1, y_score: [N] 预测分, group_id: [N] 用户/会话 ID"""
    aucs, weights = [], []
    for uid in np.unique(group_id):
        m = group_id == uid
        if m.sum() > 1 and y_true[m].sum() not in (0, m.sum()):
            aucs.append(roc_auc_score(y_true[m], y_score[m]))
            weights.append(m.sum())
    return np.average(aucs, weights=weights) if aucs else 0.0

def calc_ndcg(rel, score, k=10):
    """rel: [N, 1] 相关性(0/1/2), score: [N, 1] 预测分"""
    return ndcg_score(rel, score, k=k)

def business_kpi(imp, clk, ord, price):
    """一键计算核心业务指标"""
    return {
        'CTR':   clk / imp if imp > 0 else 0,    # 1% ~ 10%
        'CVR':   ord / clk if clk > 0 else 0,    # 0.1% ~ 5%
        'CTCVR': ord / imp if imp > 0 else 0,    # 0.01% ~ 0.5%
        'GMV':   price * ord,
        'RPM':   price * ord / imp * 1000,        # 千次曝光收入
    }
```

## 1.8 从 CV 到搜推广的 10 个思维误区

**文字**:从 CV 转搜推广,最大的"坑"不是算法不会,**而是用 CV 思维解决搜推广问题**。下面 10 个误区是血泪教训,每个都给出"CV 思维 vs 搜推广正确做法"对比。读完这一节,你去 review 同事的搜推广代码,就能立刻发现至少 3 个问题。

**公式**:

$$
\begin{aligned}
\text{误区 4 稀疏 L2} &\quad J(\theta) = L(\theta) + \lambda \sum_{i \in \text{queried}} \|E_i\|^2 \\
\text{误区 5 离线≠在线} &\quad P_{\text{train}}(x) \neq P_{\text{online}}(x),\; \Delta\text{AUC} \gg \Delta\text{业务} \\
\text{误区 8 负样本策略} &\quad \text{全量 1:1000} \;\to\; \text{in-batch 1:B} \;\to\; \text{hard neg 1:10}
\end{aligned}
$$

| # | 误区 | CV 思维 | 搜推广正确做法 | 一句话根因 |
| :--- | :--- | :--- | :--- | :--- |
| 1 | 拿 Conv 处理 ID | "图就是张量" | Embedding 查表 + MLP | 离散 ID 非空间结构 |
| 2 | 用 Accuracy 评估 | Top-1/Top-5 acc | AUC / GAUC / NDCG | 关心序不关心类 |
| 3 | 忽视 train-infer 漂移 | 训练/推理输入同 | 特征对齐 + 特征版本 | 时序+延迟反馈 |
| 4 | 全局 L2 解决过拟合 | weight_decay 通用 | 稀疏 L2 + 频率感知 | 长尾 ID 80% < 10 次 |
| 5 | 离线涨 = 线上涨 | 验证集涨即上线 | 还要 A/B + 业务指标 | 离线/在线分布异 |
| 6 | 忽视 Embedding 内存 | 几 MB~几 GB | 12.8 GB 起步,分片/量化 | V × D 爆炸 |
| 7 | 跑完 1 epoch 算训完 | epoch = 完成 | 滑动窗口,每天训 | TB 级数据跑不完 |
| 8 | 负样本不重要 | 全量反例即可 | in-batch / hard neg | 1:1000 比例噪声大 |
| 9 | AUC 是唯一指标 | top-K acc 够了 | + 多样性/新颖性/EE | 排序质量多维 |
| 10 | 特征版本无所谓 | 一次处理完 | Feature Store 严格对齐 | 离线在线必须一致 |

**代码**:

```python
import torch
import torch.nn as nn

# 误区 1 ❌:用 Conv1d 强行"卷" Embedding 序列(误把 ID 当像素)
# conv1d = nn.Conv1d(in_channels=32, out_channels=64, kernel_size=3)  # 错
# 正确 ✅:Embedding 查表 + MLP 打分
class RecModel(nn.Module):
    def __init__(self, n_items, d=32):
        super().__init__()
        self.item_emb = nn.Embedding(n_items, d, sparse=True)  # 稀疏梯度
        self.mlp = nn.Sequential(nn.Linear(d, 128), nn.ReLU(), nn.Linear(128, 1))
    def forward(self, iid):
        return self.mlp(self.item_emb(iid))

# 误区 4 ❌:全局 L2 对所有参数都加 weight_decay
# optim = torch.optim.Adam(model.parameters(), weight_decay=1e-5)
# 正确 ✅:Embedding 单独配稀疏 L2
optim = torch.optim.Adam([
    {'params': model.mlp.parameters(),      'weight_decay': 1e-5},
    {'params': model.item_emb.parameters(), 'weight_decay': 0},  # 单独处理
])
def sparse_l2(emb_weight, queried_ids, lam=1e-6):
    """只对'被查询过'的 Embedding 行加 L2,未查过保持随机"""
    return lam * emb_weight[queried_ids].pow(2).sum()

# 误区 7 ❌:固定 epoch 训练(ImageNet 思路)
# for epoch in range(10):
#     for batch in train_loader: train_step(batch)
# 正确 ✅:滑动窗口(1 小时窗口,每天训一次)
def sliding_window_loader(data, window=3600, stride=300):
    """data: 按时间戳排序的样本流;窗口以 stride 步进滑动"""
    t0 = data[0].timestamp
    i = 0
    while True:
        t_start = t0 + i * stride
        t_end   = t_start + window
        yield [s for s in data if t_start <= s.timestamp < t_end]
        i += 1

# 误区 8 ❌:全量负样本(1:1000 比例,负样本主导梯度)
# labels = [1 if clicked else 0 for sample in dataset]
# 正确 ✅:In-batch negative(同 batch 内其他样本当负样本)
def inbatch_neg_loss(user_emb, item_emb, labels, temperature=0.1):
    """user_emb: [B, d], item_emb: [B, d], labels: [B]"""
    logits = user_emb @ item_emb.T / temperature          # [B, B] 温度缩放
    return nn.functional.cross_entropy(logits, labels.argmax(-1))
```

## 2. CV 与搜推广的范式对比——一张表说透本质

第 1 章已经拆了 5 大思维转变,但都是"点对点"对比。这一节把"范式"上升到"系统级"对比,帮助你在脑海里建立一张完整的认知地图:**CV 是一个"封闭世界的静态学习系统",搜推广是一个"开放世界的动态决策系统"**。这一节不只对比"模型差异",更对比**数据流、训练范式、评估范式、推理范式**这 4 个完整流程的差异。学完这一节,你就能解释清楚"为什么搜推广不能像 CV 那样训练 100 epoch 然后一发上线"。

### 2.1 监督范式的本质对比

**文字**:CV 的主流范式是"**单任务有监督学习 + 预训练 backbone + 下游微调**"(Supervised Pretrain + Transfer)。搜推广则演化出**多任务学习(MTL)+ 持续学习(Continual)+ 强化学习(RL)+ 自监督预训练**的复合范式。两者本质差异来自"任务数量"和"数据分布稳定性"两个维度。

| 维度 | CV(图像/视频) | 搜推广 |
| :--- | :--- | :--- |
| **任务数量** | 通常 1~3 个(分类/检测/分割) | 5~20 个并列目标(CTR/CVR/GMV/时长/点赞/收藏...) |
| **主任务** | 1 个(Loss 主导) | 1 个主任务 + N 个辅助任务(各占一定权重) |
| **标签来源** | 人工标注(LabelMe/COCO) | 用户行为日志(曝光→点击→转化) |
| **标签延迟** | 标注即定,几乎无延迟 | 几小时~几天(转化可能在 D+7 才回传) |
| **标签噪声** | 5~10%(标注员分歧) | 20~40%(曝光未点击≠不喜欢,可能是没看到) |
| **样本权重** | 各类样本等权 | 长尾样本降权(否则 Embedding 被噪声主导) |
| **主范式** | Supervised + SSL(MAE/DINO) | MTL + Continual + RL + SSL |

**文字**:CV 的 ImageNet 分类任务"标签 100% 可靠",因为是人工标注。搜推广的"点击"标签不可靠——用户没点不代表不喜欢,可能是没看到/手滑/页面加载慢。工业界普遍假设"未点击样本中 20~40% 是潜在正样本",这就是著名的**位置偏差(position bias)** 和**曝光偏差(exposure bias)**。处理方式完全不同:CV 用 Label Smoothing 缓解硬标签噪声,搜推广用**拨正(unbias)**——根据位置/曝光概率反推真实 CTR。

**公式**:
$$
P_{\text{real}}(\text{click}=1 \mid u,i) = \frac{P_{\text{obs}}(\text{click}=1 \mid u,i, \text{pos})}{P(\text{seen} \mid \text{pos})}
$$

其中 $P(\text{seen} \mid \text{pos})$ 是"在位置 pos 被看到的概率",通常用位置 embedding 单独学一个二分类器预测。**这就是位置偏差拨正的核心思想**,来自华为 2019 年 PAL 论文。

**代码**:
```python
import torch
import torch.nn as nn

class PositionDebiasModel(nn.Module):
    """位置偏差拨正:P(click) = P(seen|pos) × P(click|seen,u,i)
    第一项由位置 embedding 学,第二项由主模型学"""
    def __init__(self, n_pos, d=8):
        super().__init__()
        self.pos_emb = nn.Embedding(n_pos, d)            # 位置偏差
        self.pos_mlp = nn.Sequential(nn.Linear(d, 1))     # P(seen|pos)
    
    def P_seen(self, pos):                                # 预测"被看到"的概率
        return torch.sigmoid(self.pos_mlp(self.pos_emb(pos)))

class MainCTRModel(nn.Module):
    """主模型只学 P(click|seen,u,i)"""
    def __init__(self, n_users, n_items, d=32):
        super().__init__()
        self.u_emb = nn.Embedding(n_users, d)
        self.i_emb = nn.Embedding(n_items, d)
        self.mlp = nn.Sequential(nn.Linear(d*2, 128), nn.ReLU(), nn.Linear(128, 1))
    
    def P_click_given_seen(self, uid, iid):
        return torch.sigmoid(self.mlp(torch.cat([self.u_emb(uid), self.i_emb(iid)], 1)))

# 训练时:
# L_total = L_position_bias(P_seen, position_labels) + L_main(P_click_given_seen, click_labels)
# 推理时: P(click|u,i,pos) = P_seen(pos) × P_click_given_seen(u,i)
```

### 2.2 数据流范式对比——静态 vs 持续

**文字**:CV 训练数据是"**封闭静态**"的——ImageNet 1.28M 张图,跑完即用完,不会自动新增。搜推广训练数据是"**持续流动**"的——每天新增 10^8~10^9 条曝光,模型必须用"今天的数据"训,而不是"昨天的数据"。这是"数据流"最根本的差异,直接决定了训练范式。

**公式**:
$$
\begin{aligned}
\text{CV 训练数据} &: D_{\text{train}} = \{(x_i, y_i)\}_{i=1}^{N}, \quad N \text{ 固定,跑完即结束} \\
\text{搜推广训练数据} &: D_{\text{train}}(t) = \{(x_i, y_i) : t_i \in [t - \Delta t, t]\}, \quad \text{窗口滑动,持续更新}
\end{aligned}
$$

其中 $\Delta t$ 是滑动窗口长度(常见 1 小时 ~ 1 天),$t$ 是当前训练时间戳。

**文字**:CV 数据是 IID(独立同分布)的——抽 100 张猫的图,和"猫这个概念"的统计无关,模型学到的是"通用特征"。搜推广数据是**非 IID** 的——同一用户连续点击的物品高度相关,前后会话的物品序列高度相关,这就引出"序列建模"(DIN/Transformer4Rec)的动机。

**代码**:
```python
import numpy as np

# CV:静态数据集,直接 DataLoader
class CVDataLoader:
    def __init__(self, images, labels, batch_size=32):
        self.images, self.labels = images, labels
        self.batch_size = batch_size
    
    def __iter__(self):
        idx = np.random.permutation(len(self.images))      # 全局 shuffle,IID
        for i in range(0, len(idx), self.batch_size):
            yield self.images[idx[i:i+self.batch_size]], self.labels[idx[i:i+self.batch_size]]

# 搜推广:滑动窗口,按时间切片
class SlidingWindowLoader:
    """工业界通用:按 1 小时窗口滑动,stride=5min"""
    def __init__(self, log_stream, window_sec=3600, stride_sec=300):
        self.logs = sorted(log_stream, key=lambda x: x['timestamp'])  # 按时间排序
        self.window = window_sec
        self.stride = stride_sec
    
    def __iter__(self):
        t0 = self.logs[0]['timestamp']
        n = len(self.logs)
        i = 0
        while True:
            t_start = t0 + i * self.stride
            t_end = t_start + self.window
            batch = [log for log in self.logs if t_start <= log['timestamp'] < t_end]
            if not batch: break
            yield batch
            i += 1

# 关键差异:CV 可多次 epoch,搜推广只能"近似 1 epoch"(滑动窗口)
# 内存使用:CV 把数据全加载(128M × 224 × 224 × 3 = 38GB,可全加载)
# 搜推广流式读取(10^9 条日志不可能全加载,必须流式)
```

**为什么"数据流"决定训练范式?**
1. **CV**:数据小、可全加载 → 多次 epoch → SGD 收敛
2. **搜推广**:数据大、流式到达 → 滑动窗口(近似 1 epoch)→ 在线学习(Online Learning)

### 2.3 训练范式对比——固定 epoch vs 持续学习

**文字**:CV 训练范式是"**固定 epoch + 大 batch + 数据并行**",搜推广训练范式是"**滑动窗口 + 增量更新 + 数据并行 + 模型并行(Embedding 分片)**"。前者优化目标是"在静态数据上收敛",后者优化目标是"在新数据上不停适配"。

| 维度 | CV | 搜推广 |
| :--- | :--- | :--- |
| **数据组织** | 全量加载 + shuffle | 流式 + 滑动窗口 |
| **epoch 概念** | 1 epoch = 跑完 1 遍 | 1 epoch ≈ 滑动 1 圈(实际跑不完) |
| **batch 构造** | 随机 batch(IID) | 时间相邻 batch(序列相关) |
| **并行策略** | 数据并行(DDP) | 数据并行 + Embedding 模型并行(TorchRec) |
| **学习率调度** | Cosine / Step | Warmup + 恒定 LR + 周期性 decay |
| **模型更新** | 离线训练完一键上线 | 离线训练 + 在线 incremental update |
| **灾难性遗忘** | 不存在(数据静态) | 严重(新数据覆盖旧知识) |

**文字**:搜推广面临"**灾难性遗忘**(catastrophic forgetting)"问题——模型用新数据训练后,在旧数据上的表现急剧下降。这是 CV 完全不会遇到的问题(因为 CV 数据是固定的)。解决方案:
- **Replay buffer**:保留 10% 旧样本 + 90% 新样本,混合训练
- **EWC(Elastic Weight Consolidation)**:对重要参数加约束
- **Online Learning + LR decay**:模型权重缓慢更新,新数据贡献小幅度调整

**公式**:
$$
\theta_{t+1} = \theta_t - \alpha \nabla L_{\text{new}}(B_t) - \beta (\theta_t - \theta_{t-1})   \quad \text{(带动量约束的在线更新)}
$$

其中 $\beta (\theta_t - \theta_{t-1})$ 项防止模型"突然漂移"。

**代码**:
```python
import torch
import torch.nn as nn

# CV:固定 epoch + cosine LR
def cv_train_step(model, batch, optimizer, scheduler):
    images, labels = batch
    loss = nn.functional.cross_entropy(model(images), labels)
    optimizer.zero_grad(); loss.backward(); optimizer.step()
    scheduler.step()             # cosine decay
    return loss.item()

# 搜推广:在线学习 + 增量更新 + EWC(防止灾难性遗忘)
class OnlineUpdate:
    def __init__(self, model, lr=1e-4, ewc_lambda=1e3):
        self.model = model
        self.optimizer = torch.optim.Adam(model.parameters(), lr=lr)
        self.ewc_lambda = ewc_lambda
        self.star_weights = {n: p.clone().detach() for n, p in model.named_parameters()}  # 保存"重要权重"
    
    def update(self, batch):
        # 1. 标准梯度下降
        loss_new = self.compute_loss(batch)
        self.optimizer.zero_grad(); loss_new.backward(); optimizer.step()
        
        # 2. EWC 约束:不让重要权重偏离太远
        ewc_loss = 0
        for n, p in self.model.named_parameters():
            ewc_loss += (p - self.star_weights[n]).pow(2).sum()
        (self.ewc_lambda * ewc_loss).backward()
        self.optimizer.step()
        return loss_new.item() + self.ewc_lambda * ewc_loss.item()
```

### 2.4 评估范式对比——离线测试集 vs 在线 A/B

**文字**:CV 的评估范式是"**离线测试集 + 单一指标 + 一次性评估**"(跑 1 遍 ImageNet test set,得到 top-1 acc)。搜推广的评估范式是"**离线 AUC + 在线 A/B + 业务指标 + 长期留存**",至少 3 层评估缺一不可。

| 维度 | CV | 搜推广 |
| :--- | :--- | :--- |
| **评估层次** | 1 层(离线) | 3 层(离线 AUC → 在线 A/B → 业务 GMV) |
| **核心指标** | Top-1/Top-5 acc | AUC/GAUC → CTR/CVR/GMV |
| **指标性质** | 客观、可复现 | 受流量分布影响,需正交分层 |
| **统计检验** | 95% CI + t 检验 | 95% CI + 序列检验(SPRT) |
| **实验周期** | 几小时(评测) | 至少 7 天(覆盖工作日/周末) |
| **失败代价** | 论文被拒 | 损失千万级 GMV |

**文字**:**离线涨 ≠ 线上涨** 是搜推广第一性原理。CV 中"ImageNet 涨 1% → 模型确实更好"是金标准,搜推广中"离线 AUC 涨 1% → 线上可能跌 5%"是常态。原因:
1. **分布漂移**:训练数据 ≠ 线上流量
2. **位置偏差**:A 模型把高分给位置 1,B 模型把高分给位置 5,AUC 看似涨,实际线上 CTR 跌
3. **延迟反馈**:转化延迟 D+7,离线评估只能看到 D+1 数据

工业界铁律:**"AUC 涨 0.5 个点 + A/B 涨 1% CTR + GMV 不跌"** 三者都满足才能上线。

**公式**:
$$
\text{上线决策} = \underbrace{\Delta \text{AUC} > +0.003}_{\text{离线涨}} \;\wedge\; \underbrace{\Delta \text{CTR} > +1\%}_{\text{A/B 涨}} \;\wedge\; \underbrace{\Delta \text{GMV} > 0}_{\text{业务不跌}}
$$

**代码**:
```python
import numpy as np
from scipy import stats

# CV 评估:单次 t 检验
def cv_eval(pred_acc_baseline, pred_acc_new, n_test=10000):
    se = np.sqrt(pred_acc_new * (1 - pred_acc_new) / n_test)
    z = (pred_acc_new - pred_acc_baseline) / se
    p_value = 2 * (1 - stats.norm.cdf(abs(z)))
    return p_value < 0.05                      # p < 0.05 即显著

# 搜推广评估:序列检验(SPRT)用于 A/B 实时监控
def sprt_test(p_null, p_alt, alpha=0.05, beta=0.2):
    """Wald's Sequential Probability Ratio Test
    在线累积样本,达到阈值立即给出结论,比固定样本量快 2~5 倍"""
    A = (1 - beta) / alpha
    B = beta / (1 - alpha)
    llr = 0  # log-likelihood ratio
    while True:
        # 每来一个新样本(x ∈ {0,1}),更新 LLR
        x = yield  # 接收新样本
        llr += np.log(p_alt ** x * (1 - p_alt) ** (1 - x) /
                      (p_null ** x * (1 - p_null) ** (1 - x)))
        if llr >= np.log(A):  return "reject H0 (新模型显著优)"
        if llr <= np.log(B):  return "accept H0 (无显著差异)"
```

### 2.5 推理范式对比——单次推理 vs 高并发打分

**文字**:CV 推理是"**单图 → 单结果**"(1 张图 → 1 个类别标签),搜推广推理是"**1 次请求 → 数百候选 → 排序结果**"(1 个用户请求 → 数百物品打分 → top-K 推荐)。两者在"批量大小"和"延迟要求"上完全不同。

| 维度 | CV 推理 | 搜推广推理 |
| :--- | :--- | :--- |
| **请求模式** | 单图/单视频 | 1 用户请求 → 数百候选 |
| **候选规模** | 1 | 100(精排)~10^9(召回) |
| **时延要求** | 100ms | < 20ms(精排)/ < 5ms(召回) |
| **吞吐量** | 10 QPS | 10 万 QPS(双 11 峰值) |
| **推理设备** | GPU(批推理) | CPU/GPU 混合,边缘部署 |
| **核心算子** | Conv/Attention | Embedding 查表 + MLP |
| **瓶颈** | FLOPS | 内存带宽(Embedding 查表) |

**文字**:搜推广精排"1 个用户请求 + 100 个候选 → 排序",通常用 CPU 部署(因为候选数小、模型小、GPU 不划算)。**召回"1 个用户 → 10^9 候选 → top-100"必须用 ANN(近似最近邻)**,FAISS / Milvus 是标配。整个推理链路是**多阶段级联**(Multi-Stage Cascade):召回(亿→千)→ 粗排(千→百)→ 精排(百→十)→ 重排(十→最终)。

**公式**:
$$
\underbrace{10^9}_{\text{全量候选}} \xrightarrow[\text{ANN}]{\text{召回}} \underbrace{10^3}_{\text{粗排}} \xrightarrow[\text{轻量 MLP}]{\text{粗排}} \underbrace{10^2}_{\text{精排}} \xrightarrow[\text{DNN}]{\text{精排}} \underbrace{10}_{\text{重排}} \xrightarrow[\text{规则}]{\text{重排}} \underbrace{5}_{\text{展示}}
$$

**代码**:
```python
import torch
import numpy as np

# CV 推理:单图分类
class CVInferencer:
    def __init__(self, model):
        self.model = model.eval()
    
    def __call__(self, image):
        with torch.no_grad():
            return self.model(image.unsqueeze(0))   # [1, 1000] 1000 类概率

# 搜推广精排:1 用户 + 100 候选 → 排序分
class RankInferencer:
    def __init__(self, model, n_items=10**8, d=32):
        self.model = model.eval()
        self.item_emb_table = nn.Embedding(n_items, d)  # 12.8 GB
    
    def __call__(self, user_feat, candidate_iids):
        """user_feat: [d], candidate_iids: [100]"""
        with torch.no_grad():
            cand_emb = self.item_emb_table(candidate_iids)        # [100, d]
            user_emb = user_feat.unsqueeze(0).expand(100, -1)     # [100, d]
            scores = self.model(torch.cat([user_emb, cand_emb], 1))  # [100, 1]
            return scores.squeeze().numpy()                       # [100] 排序分

# 搜推广召回:1 用户 → 10^9 候选 → top-100(FAISS ANN)
class ANNRetriever:
    def __init__(self, item_emb_path, d=32, index_type='IVF4096,PQ32'):
        import faiss
        self.index = faiss.index_factory(d, index_type)   # IVF + PQ 压缩
        self.index.add(np.load(item_emb_path))           # 加载 10^9 物品向量
    
    def __call__(self, user_emb, topk=100, nprobe=64):
        """user_emb: [1, d], 输出 top-100 候选 ID"""
        import faiss
        _, ids = self.index.search(user_emb, topk)
        return ids[0]
```

### 2.6 跨域迁移——CV 的预训练范式能用到搜推广吗?

**文字**:CV 的"**预训练 backbone + 下游微调**"范式(ResNet → ImageNet → 你的数据)在搜推广中部分可用,但有几个根本差异需要理解。核心差异是**预训练任务不同**:CV 预训练是"图像分类"(识别物体),搜推广预训练是"行为预测"(预测点击)。两者学到的"知识"完全不同。

| 维度 | CV 预训练 | 搜推广预训练 |
| :--- | :--- | :--- |
| **预训练任务** | 图像分类/MAE | 点击预测/序列建模 |
| **数据量** | 1.28M(ImageNet) | 10^11(曝光日志) |
| **预训练产物** | Backbone 权重 | Embedding 表 |
| **下游微调** | 换 head,freeze backbone | 增量更新 Embedding + 训练新塔 |
| **泛化方向** | 类别迁移(猫 → 狗) | 用户迁移(新用户 → 老用户) |
| **冷启动解决** | few-shot 5-shot | 元学习 / ID Embedding |

**文字**:CV 预训练范式能给搜推广的**最大启发是"表征学习"**——Embedding 不是直接学"用户/物品 ID",而是先在大量无标签数据上预训练**通用表征**(类似 BERT 的 MLM),再在搜推广任务上微调。这是 2023 年后生成式推荐的核心思想:**用 LLM 的 tokenizer 把物品 ID 抽象成"Semantic ID"(语义 token)**,把搜推广变成"序列生成问题"。

**代码**:
```python
import torch
import torch.nn as nn

# CV 预训练范式:ResNet backbone + 微调 head
class CVPretrain:
    def __init__(self):
        self.backbone = torchvision.models.resnet50(pretrained=True)  # 预训练
        self.backbone.fc = nn.Identity()                                # 去掉原 head
        self.new_head = nn.Linear(2048, 100)                           # 新 head(你的 100 类)
    
    def forward(self, x):
        return self.new_head(self.backbone(x))                         # 只训 head

# 搜推广"预训练"范式:用户行为序列预训练 + 微调精排
class SearchAdPretrain:
    """用户行为序列预训练:用 MLM 预测被 mask 的物品 ID"""
    def __init__(self, n_items, d=32):
        self.item_emb = nn.Embedding(n_items, d)
        self.pos_emb  = nn.Embedding(1000, d)
        self.transformer = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d, nhead=4, dim_feedforward=128), num_layers=3)
        self.head = nn.Linear(d, n_items)                             # 预测被 mask 的物品
    
    def forward(self, item_seq, pos_seq, mask_positions):
        """item_seq: [B, T], mask_positions: [B, n_mask]"""
        x = self.item_emb(item_seq) + self.pos_emb(pos_seq)
        x = self.transformer(x)
        return self.head(x[mask_positions])                           # 预测被 mask ID
    
    def fine_tune_for_ranking(self, n_tasks=3):
        """下游任务:多任务精排(CTR + CVR + 点赞)"""
        self.ctc_head = nn.Linear(32, 1)   # CTR
        self.cvr_head = nn.Linear(32, 1)   # CVR
        self.like_head = nn.Linear(32, 1)  # 点赞
        return [self.ctc_head, self.cvr_head, self.like_head]
```

**经验总结**:
- CV 范式 → 搜推广可借鉴"预训练 + 微调",但**预训练任务必须换成"行为预测"**
- 搜推广的核心创新点不在"模型结构",而在**数据流、特征工程、在线学习、EE(探索利用)** 这 4 块
- CV 工程师转搜推广,推荐路线:**先读 DIN(2018) + DIEN(2019) + SIM(2020) 三篇阿里论文**,理解"用户行为序列建模"的本质

> CV 范式给你的是"模型调优能力",搜推广需要的是"数据流工程能力"。两者结合 = 现代工业级推荐系统。

## 3. Embedding 共享与多任务学习——搜推广的"瑞士军刀"

如果说 Embedding 是搜推广的"血液",那么**多任务学习(Multi-Task Learning, MTL)就是搜推广的"瑞士军刀"**。一个真实业务的搜推广系统不可能只优化 CTR——CTR 涨但 GMV 跌、CVR 跌、留存跌,在工业界都是失败案例。本节系统讲清楚:为什么必须多任务?Embedding 怎么共享?梯度冲突怎么办?阿里 ESMM、谷歌 MMoE、腾讯 PLE 三大工业级方案的本质是什么?

### 3.1 为什么必须多任务?——单任务优化的 3 大陷阱

**文字**:搜推广业务的"真实目标"是 GMV(商品交易总额)和 LTV(用户生命周期价值),但 GMV 是 D+7 才能观测到的延迟指标,直接优化 GMV 不可行。工业界普遍做法是**用一个或多个代理指标(proxy metric)近似真实目标**——CTR、CVR、客单价、时长等。这多个代理指标之间往往存在**冲突**:

- **CTR 涨但 CVR 跌** → 推荐"标题党"物品,点击高但下单少
- **CVR 涨但 GMV 跌** → 推荐"低价高转化"物品,GMV 反而降
- **CTR 涨但留存跌** → 推荐"短期吸睛"物品,长期用户流失

**核心矛盾**:单一指标优化必然顾此失彼。**多任务学习(MTL)是公认的解决方案**——同时优化多个指标,在"帕累托最优"上寻找平衡点。

**公式**:
$$
L_{\text{total}}(\theta) = \sum_{k=1}^{K} w_k \cdot L_k(\theta), \quad \sum_k w_k = 1
$$

其中 $K$ 是任务数,$w_k$ 是任务权重(可学习或固定),$L_k$ 是第 $k$ 个任务的损失。

**文字**:MTL 在 CV 中早已存在——检测任务同时训分类 + 定位(Multi-task),但搜推广中的 MTL 有**两个独有特征**:
1. **任务数更多**:CV 通常 2~5 个任务,搜推广通常 5~20 个
2. **任务相关性复杂**:CTR / CVR / GMV / 留存 / 时长 / 完播率 / 收藏 等任务之间**有的正相关、有的负相关**

**代码**:
```python
import torch
import torch.nn as nn

# CV 中的多任务(检测):分类 + 定位
class CVMultiTask(nn.Module):
    def __init__(self):
        super().__init__()
        self.backbone = torchvision.models.resnet50()
        self.cls_head = nn.Linear(2048, 80)    # 80 类分类
        self.box_head = nn.Linear(2048, 4)     # bbox 坐标
    def forward(self, x):
        feat = self.backbone(x)
        return self.cls_head(feat), self.box_head(feat)
# Loss = L_cls + L_box,权重 1:1

# 搜推广中的多任务:CTR + CVR + 点赞 + 收藏 + 完播 + ...
class RecMultiTask(nn.Module):
    def __init__(self, n_users, n_items, n_tasks=5, d=32):
        super().__init__()
        # 共享的 Embedding 表(10^8 × 32 = 12.8 GB)
        self.user_emb = nn.Embedding(n_users, d)
        self.item_emb = nn.Embedding(n_items, d)
        # 共享底层(学习通用表征)
        self.shared_mlp = nn.Sequential(nn.Linear(d*2, 128), nn.ReLU())
        # 任务独立 head(各任务专属逻辑)
        self.heads = nn.ModuleList([nn.Linear(128, 1) for _ in range(n_tasks)])
    
    def forward(self, uid, iid):
        feat = torch.cat([self.user_emb(uid), self.item_emb(iid)], 1)
        shared = self.shared_mlp(feat)
        return [torch.sigmoid(self.heads[k](shared)) for k in range(self.n_tasks)]
```

### 3.2 Embedding 共享策略——硬共享 vs 软共享 vs 混合

**文字**:Embedding 共享是 MTL 的核心。共享策略决定"哪些知识共享、哪些知识独立"。三种主流策略对比:

| 策略 | 描述 | 优点 | 缺点 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **硬共享(Hard Sharing)** | 所有任务共享同一 Embedding + 底层 | 参数少、泛化好 | 任务冲突时互相干扰 | 任务高度相关(CTR+CVR) |
| **软共享(Soft Sharing)** | 每个任务独立 Embedding,通过正则约束相似 | 灵活、避免冲突 | 参数多、易过拟合 | 任务相关性低 |
| **混合(MMoE/PLE)** | 部分共享 + 部分独立 + 门控 | 灵活 + 高效 | 实现复杂 | 工业界主流 |

**公式**:
$$
\begin{aligned}
\text{硬共享} &: E_{\text{shared}} = E, \quad \text{所有任务共用} \\
\text{软共享} &: E_k = f_k(E_{\text{shared}}), \quad \text{第 k 任务有独立映射} \\
\text{MMoE} &: h_k = \sum_{m=1}^{M} g_{k,m}(x) \cdot E_m, \quad g \text{ 是门控}
\end{aligned}
$$

**代码**:
```python
import torch
import torch.nn as nn

# 硬共享:所有任务共用同一 Embedding
class HardSharing(nn.Module):
    def __init__(self, n_users, n_items, d=32, n_tasks=3):
        super().__init__()
        self.user_emb = nn.Embedding(n_users, d)        # 共享
        self.item_emb = nn.Embedding(n_items, d)        # 共享
        self.shared = nn.Sequential(nn.Linear(d*2, 128), nn.ReLU())
        self.heads = nn.ModuleList([nn.Linear(128, 1) for _ in range(n_tasks)])

# 软共享:每个任务独立 Embedding + L2 约束
class SoftSharing(nn.Module):
    def __init__(self, n_users, n_items, d=32, n_tasks=3):
        super().__init__()
        self.user_embs = nn.ModuleList([nn.Embedding(n_users, d) for _ in range(n_tasks)])  # 每个任务独立
        self.item_embs = nn.ModuleList([nn.Embedding(n_items, d) for _ in range(n_tasks)])
        self.heads = nn.ModuleList([nn.Sequential(nn.Linear(d*2, 128), nn.ReLU(), nn.Linear(128, 1)) for _ in range(n_tasks)])
    
    def reg_loss(self):
        """软共享正则:让不同任务的 Embedding 接近"""
        reg = 0
        for i in range(len(self.user_embs)):
            for j in range(i+1, len(self.user_embs)):
                reg += (self.user_embs[i].weight - self.user_embs[j].weight).pow(2).mean()
        return reg * 1e-4
```

### 3.3 MMoE——多门控混合专家(Multi-gate Mixture-of-Experts)

**文字**:**MMoE** 是谷歌 2018 年提出的工业级 MTL 架构,核心思想:**多个"专家网络" + 每个任务一个"门控"**,每个任务动态选择哪些专家对它重要。MMoE 解决了硬共享的"任务冲突"问题,是当前业界事实标准。

**公式**:
$$
\begin{aligned}
E_m(x) &= \text{Expert}_m(x), \quad m = 1, \ldots, M \\
g_k(x) &= \text{softmax}(W_k \cdot x), \quad g_k \in \mathbb{R}^M \\
h_k(x) &= \sum_{m=1}^{M} g_{k,m}(x) \cdot E_m(x) \\
y_k &= \text{Task}_k(h_k(x))
\end{aligned}
$$

**文字**:MMoE 的精妙之处——**门控网络 $g_k$ 根据输入 $x$ 动态决定专家权重**。同一个输入对 CTR 任务来说可能专家 1+2 重要,对 CVR 任务来说可能专家 2+3 重要。这种"动态路由"机制让 MMoE 兼顾"共享"和"独立"。

**代码**:
```python
import torch
import torch.nn as nn

class MMoE(nn.Module):
    """谷歌 KDD 2018: Modeling Task Relationships in Multi-task Learning with Multi-gate Mixture-of-Experts"""
    def __init__(self, n_features, d=32, n_experts=4, n_tasks=3):
        super().__init__()
        # 1. 多个专家网络(每个专家是一个小型 MLP)
        self.experts = nn.ModuleList([
            nn.Sequential(nn.Linear(n_features, d), nn.ReLU(), nn.Linear(d, d))
            for _ in range(n_experts)
        ])
        # 2. 每个任务一个门控网络
        self.gates = nn.ModuleList([
            nn.Linear(n_features, n_experts) for _ in range(n_tasks)
        ])
        # 3. 每个任务一个塔
        self.towers = nn.ModuleList([
            nn.Sequential(nn.Linear(d, d), nn.ReLU(), nn.Linear(d, 1)) for _ in range(n_tasks)
        ])
    
    def forward(self, x):
        """x: [B, n_features]"""
        # 1. 所有专家同时计算
        expert_outs = torch.stack([e(x) for e in self.experts], dim=1)  # [B, M, d]
        
        # 2. 每个任务门控加权
        task_outs = []
        for k in range(self.n_tasks):
            gate_k = torch.softmax(self.gates[k](x), dim=-1)             # [B, M]
            h_k = (gate_k.unsqueeze(-1) * expert_outs).sum(dim=1)        # [B, d]
            y_k = self.towers[k](h_k)                                    # [B, 1]
            task_outs.append(y_k)
        return task_outs                                                  # [n_tasks, B, 1]

# 工业界用法:底层接 Embedding,上层接 MMoE
class RecWithMMoE(nn.Module):
    def __init__(self, n_users, n_items, d=32, n_experts=8, n_tasks=3):
        super().__init__()
        self.user_emb = nn.Embedding(n_users, d)
        self.item_emb = nn.Embedding(n_items, d)
        self.mmoe = MMoE(n_features=d*2, d=d, n_experts=n_experts, n_tasks=n_tasks)
    
    def forward(self, uid, iid):
        x = torch.cat([self.user_emb(uid), self.item_emb(iid)], 1)
        return self.mmoe(x)
```

**MMoE 的局限**:门控网络是无监督学到的,可能多个任务都偏向同一组专家,**任务之间仍然会冲突**。PLE(Progressive Layered Extraction,腾讯 2020)解决了这个问题。

### 3.4 PLE——渐进式分层提取(Progressive Layered Extraction)

**文字**:**PLE** 是腾讯 2020 年提出的 MTL 架构,核心改进:**显式分离"共享专家"和"任务专属专家"**。避免 MMoE 中"门控偏向同组专家"的问题。

**公式**:
$$
\begin{aligned}
E_m^{\text{shared}}(x) &= \text{SharedExpert}_m(x), \quad m = 1, \ldots, M_s \\
E_{k,m}^{\text{task}}(x) &= \text{TaskExpert}_{k,m}(x), \quad k = 1, \ldots, K, \; m = 1, \ldots, M_t \\
h_k(x) &= \underbrace{\sum_{m=1}^{M_s} g_{k,m}^{\text{shared}}(x) \cdot E_m^{\text{shared}}(x)}_{\text{共享部分}} + \underbrace{\sum_{m=1}^{M_t} g_{k,m}^{\text{task}}(x) \cdot E_{k,m}^{\text{task}}(x)}_{\text{专属部分}}
\end{aligned}
$$

**代码**:
```python
class PLE(nn.Module):
    """腾讯 RecSys 2020: Progressive Layered Extraction"""
    def __init__(self, n_features, d=32, n_shared_experts=4, n_task_experts=2, n_tasks=3):
        super().__init__()
        # 共享专家(所有任务共用)
        self.shared_experts = nn.ModuleList([
            nn.Sequential(nn.Linear(n_features, d), nn.ReLU(), nn.Linear(d, d))
            for _ in range(n_shared_experts)
        ])
        # 每个任务的专属专家(独立参数)
        self.task_experts = nn.ModuleList([
            nn.ModuleList([
                nn.Sequential(nn.Linear(n_features, d), nn.ReLU(), nn.Linear(d, d))
                for _ in range(n_task_experts)
            ]) for _ in range(n_tasks)
        ])
        # 门控
        self.shared_gates = nn.ModuleList([nn.Linear(n_features, n_shared_experts) for _ in range(n_tasks)])
        self.task_gates = nn.ModuleList([nn.Linear(n_features, n_task_experts) for _ in range(n_tasks)])
        self.towers = nn.ModuleList([nn.Sequential(nn.Linear(d, d), nn.ReLU(), nn.Linear(d, 1)) for _ in range(n_tasks)])
    
    def forward(self, x):
        # 共享专家输出
        shared_out = torch.stack([e(x) for e in self.shared_experts], dim=1)  # [B, M_s, d]
        task_outs = []
        for k in range(self.n_tasks):
            # 任务专属专家输出
            task_expert_out = torch.stack([e(x) for e in self.task_experts[k]], dim=1)  # [B, M_t, d]
            # 门控加权
            g_shared = torch.softmax(self.shared_gates[k](x), dim=-1)                  # [B, M_s]
            g_task = torch.softmax(self.task_gates[k](x), dim=-1)                     # [B, M_t]
            # 合并:共享 + 专属
            h_k_shared = (g_shared.unsqueeze(-1) * shared_out).sum(dim=1)              # [B, d]
            h_k_task = (g_task.unsqueeze(-1) * task_expert_out).sum(dim=1)            # [B, d]
            h_k = h_k_shared + h_k_task                                                # [B, d]
            task_outs.append(self.towers[k](h_k))
        return task_outs
```

| :--- | :--- | :--- |
| AUC 涨点(多任务平均) | +0.5% | +1.2% |
| 参数量 | 中 | 大(+50%) |
| 训练稳定性 | 一般 | 较好 |
| 工业部署 | 主流 | 头部公司(微信/QQ) |

### 3.5 梯度冲突与 GradNorm

**文字**:多任务训练最大的坑是"**梯度冲突**"(Gradient Conflict)——不同任务的梯度方向相反,优化时互相抵消,模型卡在"哪个任务都训不好"的状态。**GradNorm** 是经典的解决方案:动态调整任务权重,让不同任务的梯度大小均衡。

**公式**:
$$
\begin{aligned}
G_k(t) &= \|\nabla_\theta L_k(t)\| \quad \text{第 k 任务的梯度范数} \\
\tilde{G}_k(t) &= G_k(t) / \mathbb{E}[G_k(t)] \quad \text{相对梯度} \\
w_k(t+1) &= w_k(t) + \alpha \cdot (\tilde{G}_k(t) - 1) \quad \text{动态调整权重}
\end{aligned}
$$

**文字**:GradNorm 的核心思想:**训练慢的任务(梯度小)增权,训练快的任务(梯度大)降权**,让所有任务"齐头并进"。类似 CV 中的 GradCAM、focal loss 的"难样本加权"思路。

**代码**:
```python
import torch
import torch.nn as nn

class GradNorm:
    """GradNorm: 动态多任务权重平衡(2018 ICML)"""
    def __init__(self, model, n_tasks=3, alpha=1.5, lr=0.025):
        self.n_tasks = n_tasks
        self.alpha = alpha
        self.lr = lr
        # 每个任务的"学习率"(作为权重)
        self.w = nn.Parameter(torch.ones(n_tasks, requires_grad=True))
        # 保存初始 loss,用于衡量"训练速度"
        self.initial_losses = None
    
    def reweight(self, losses, shared_params):
        """losses: [n_tasks], shared_params: 共享底层参数"""
        if self.initial_losses is None:
            self.initial_losses = losses.detach()
        
        # 1. 计算每个任务对共享参数的梯度范数
        G = []
        for k in range(self.n_tasks):
            self.w.grad = None  # 清零
            grads = torch.autograd.grad(losses[k], shared_params, retain_graph=True)
            G.append(torch.norm(torch.cat([g.view(-1) for g in grads])))
        G = torch.stack(G)
        
        # 2. 计算每个任务的"相对训练速度"
        loss_ratio = losses.detach() / self.initial_losses
        inverse_rate = loss_ratio / loss_ratio.mean()
        
        # 3. 目标:让所有任务的 G_k 与 inverse_rate^alpha 成正比
        target = (G.mean() * (inverse_rate ** self.alpha)).detach()
        loss_gradnorm = (G - target).abs().sum()
        
        # 4. 更新 w
        w_grad = torch.autograd.grad(loss_gradnorm, self.w)[0]
        self.w.data -= self.lr * w_grad
        # 投影到非负 + 求和约束
        self.w.data = torch.clamp(self.w.data, min=0)
        self.w.data = self.n_tasks * self.w.data / self.w.data.sum()
        
        return self.w.detach()

# 使用示例
class RecWithGradNorm(nn.Module):
    def __init__(self, n_users, n_items, d=32, n_tasks=3):
        super().__init__()
        self.user_emb = nn.Embedding(n_users, d)
        self.item_emb = nn.Embedding(n_items, d)
        self.shared = nn.Sequential(nn.Linear(d*2, 128), nn.ReLU())
        self.heads = nn.ModuleList([nn.Linear(128, 1) for _ in range(n_tasks)])
        self.gradnorm = GradNorm(self, n_tasks=n_tasks)
    
    def forward(self, uid, iid):
        x = torch.cat([self.user_emb(uid), self.item_emb(iid)], 1)
        shared = self.shared(x)
        return [self.heads[k](shared) for k in range(self.n_tasks)]
    
    def compute_loss(self, preds, labels):
        losses = [nn.functional.binary_cross_entropy_with_logits(preds[k], labels[k]) for k in range(self.n_tasks)]
        weights = self.gradnorm.reweight(losses, list(self.shared.parameters()))
        return sum(w * l for w, l in zip(weights, losses))
```

### 3.6 工业案例 1:阿里 ESMM——全空间多任务模型

**文字**:阿里 2018 年提出的 **ESMM**(Entire Space Multi-task Model)是搜推广 MTL 的里程碑。核心思想:**CTR 和 CTCVR(点击-转化率)同时建模,利用"点击"作为中间桥梁,解决 CVR 任务中的"样本选择偏差"(SSB)和"数据稀疏"(DS)问题**。

**公式**:
$$
\begin{aligned}
\text{pCTR} &= P(\text{click}=1 \mid u, i) \quad \text{(曝光空间建模)} \\
\text{pCVR} &= P(\text{conv}=1 \mid u, i, \text{click}=1) \quad \text{(点击空间建模)} \\
\text{pCTCVR} &= \text{pCTR} \times \text{pCVR} \quad \text{(乘性关系)}
\end{aligned}
$$

**关键洞察**:
- CVR 在"点击空间"建模,但推理时要在"曝光空间"用 → 分布不一致(SSB)
- 点击样本远少于曝光样本(DS)
- ESMM 用**乘性关系 pCTCVR = pCTR × pCVR** 在曝光空间同时学,自然解决 SSB+DS

**代码**:
```python
class ESMM(nn.Module):
    """阿里 SIGIR 2018: Entire Space Multi-task Model"""
    def __init__(self, n_users, n_items, d=32):
        super().__init__()
        self.user_emb = nn.Embedding(n_users, d)
        self.item_emb = nn.Embedding(n_items, d)
        # CTR 塔
        self.ctr_tower = nn.Sequential(nn.Linear(d*2, 128), nn.ReLU(), nn.Linear(128, 1))
        # CVR 塔(关键:CVR 塔的输入特征与 CTR 塔相同,保证乘性关系成立)
        self.cvr_tower = nn.Sequential(nn.Linear(d*2, 128), nn.ReLU(), nn.Linear(128, 1))
    
    def forward(self, uid, iid):
        x = torch.cat([self.user_emb(uid), self.item_emb(iid)], 1)
        pctr = torch.sigmoid(self.ctr_tower(x))
        pcvr = torch.sigmoid(self.cvr_tower(x))
        pctcvr = pctr * pcvr                          # 乘性关系
        return pctr, pctcvr
    
    def loss(self, pctr, pctcvr, click_label, conv_label):
        """曝光空间训练:所有曝光样本都有 click 标签,只有点击样本有 conv 标签"""
        loss_ctr = nn.functional.binary_cross_entropy(pctr.squeeze(), click_label.float())
        loss_ctcvr = nn.functional.binary_cross_entropy(pctcvr.squeeze(), conv_label.float())
        return loss_ctr + loss_ctcvr                   # 加权和(可调)

# 训练样本构造(关键!)
# 曝光样本 = 100%(全部曝光都给 click_label)
# 转化样本 = 仅在 click_label=1 的样本中有 conv_label,其他位置 conv_label=0
```

**ESMM 的工业价值**:阿里妈妈广告场景,**CTR + 4%,RPM + 6%**,直接收益数亿。ESMM 是搜推广工程师必读论文之一。

### 3.7 工业案例 2:阿里 MMoE 升级——ShareBottom → MMoE → PLE 演进

**文字**:阿里妈妈广告团队的 MTL 架构经历了 3 代演进:
- **2017 ShareBottom**:硬共享,任务冲突严重
- **2018 MMoE**:门控路由,效果提升 +0.5~1% AUC
- **2020 PLE**:显式分离共享/专属,效果再提升 +0.5~1% AUC

**代码演进**:
```python
# 第 1 代:ShareBottom(硬共享)
class ShareBottom(nn.Module):
    def __init__(self, n_features, n_tasks=3):
        super().__init__()
        self.bottom = nn.Sequential(nn.Linear(n_features, 128), nn.ReLU())   # 共享底层
        self.heads = nn.ModuleList([nn.Linear(128, 1) for _ in range(n_tasks)])  # 任务塔
    def forward(self, x):
        return [head(self.bottom(x)) for head in self.heads]

# 第 2 代:MMoE(门控路由)
class MMoE_v2(MMoE):
    """继承自 MMoE,共享层改为 Embedding 拼接"""
    def __init__(self, n_users, n_items, d=32, n_experts=8, n_tasks=3):
        super().__init__(n_features=d*2, d=d, n_experts=n_experts, n_tasks=n_tasks)
        self.user_emb = nn.Embedding(n_users, d)
        self.item_emb = nn.Embedding(n_items, d)
    
    def forward(self, uid, iid):
        x = torch.cat([self.user_emb(uid), self.item_emb(iid)], 1)
        return self.experts, self.gates, self.towers, x  # 完整 MMoE

# 第 3 代:PLE(显式分离)
class PLE_v2(PLE):
    """继承自 PLE,显式共享 + 专属"""
    def __init__(self, n_users, n_items, d=32, n_shared=4, n_task=2, n_tasks=3):
        super().__init__(n_features=d*2, d=d, n_shared_experts=n_shared, n_task_experts=n_task, n_tasks=n_tasks)
        self.user_emb = nn.Embedding(n_users, d)
        self.item_emb = nn.Embedding(n_items, d)
```

### 3.8 多任务的工业经验——25 条血泪教训

**文字**:多任务学习看似简单(几个 head 加起来),实际部署中坑极多。下面 25 条是阿里/字节/美团工业团队多年总结的经验,每条都附带"踩坑故事"。

| # | 经验 | 踩坑故事 |
| :--- | :--- | :--- |
| 1 | **主任务必须主导 Loss** | CTR/CVR 同训,但权重 1:1 → CVR 把 CTR 拖垮 |
| 2 | **任务权重用梯度平衡(GradNorm)** | 静态权重难调,动态平衡更稳 |
| 3 | **任务数不要超过 5** | 任务过多 → 每个任务都训不好 |
| 4 | **新任务上线前先离线评估** | 直接上 A/B → 占用 5% 流量但无显著收益 |
| 5 | **共享 Embedding 必须稀疏更新** | Dense update → 显存爆炸 |
| 6 | **任务塔必须独立** | 共用塔 → 任务冲突 |
| 7 | **样本权重按业务重要性** | CVR 业务重要,但样本少 → 必须过采样 |
| 8 | **延迟反馈任务用单独模型** | 转化 D+7 → 不能直接训主模型 |
| 9 | **MMoE 专家数 4~8 足够** | 16 个专家 → 训练慢 + 过拟合 |
| 10 | **门控网络必须初始化为均匀** | 全 0 初始化 → 所有专家权重相同 |
| 11 | **任务相关性 < 0.3 时用软共享** | CTR 和 GMV 相关性低 → 硬共享冲突 |
| 12 | **任务相关性 > 0.7 时用硬共享** | CTR 和 CVR 高相关 → 硬共享最优 |
| 13 | **离线 AUC 多任务取 macro 平均** | micro 平均被大类主导 |
| 14 | **在线 A/B 必须分层正交** | 任务实验与召回实验冲突 → 流量冲突 |
| 15 | **冷启动任务用零样本学习** | 新业务无样本 → 元学习/迁移 |
| 16 | **长尾任务的样本加权** | 头部任务梯度主导 → 必须 reweight |
| 17 | **辅助任务用对抗梯度** | 不想让主任务学辅助任务信息 → Gradient Reversal |
| 18 | **多任务模型增量训练** | 不能全量重训 → 用上次 checkpoint warmup |
| 19 | **监控每个任务独立 AUC** | 任务冲突时整体 AUC 不变但单独跌 |
| 20 | **避免负迁移** | 加任务前确认有正收益(否则撤掉) |
| 21 | **特征交叉层共享** | FM/DeepFM 的交叉部分共享 |
| 22 | **Loss 加权必须归一化** | 不归一 → 某任务主导梯度 |
| 23 | **Online Learning 关闭** | 多任务 + 在线学习 → 稳定性差,先离线训 |
| 24 | **正负样本比例保持** | 多任务混合样本 → 比例被稀释 |
| 25 | **任务塔不要过深** | 3 层 MLP 足够 → 再深反而过拟合 |

**代码:多任务训练最佳实践**:
```python
import torch
import torch.nn as nn

class BestPracticeMTL(nn.Module):
    """工业级多任务最佳实践"""
    def __init__(self, n_users, n_items, d=32, n_tasks=3):
        super().__init__()
        # 1. 共享 Embedding(稀疏 L2)
        self.user_emb = nn.Embedding(n_users, d, sparse=True)
        self.item_emb = nn.Embedding(n_items, d, sparse=True)
        
        # 2. 共享底层(轻量)
        self.shared = nn.Sequential(nn.Linear(d*2, 128), nn.ReLU())
        
        # 3. MMoE 路由(8 个专家)
        self.mmoe = MMoE(n_features=128, d=d, n_experts=8, n_tasks=n_tasks)
        
        # 4. 独立任务塔(2 层 MLP,不要过深)
        self.towers = nn.ModuleList([
            nn.Sequential(nn.Linear(d, 64), nn.ReLU(), nn.Linear(64, 1))
            for _ in range(n_tasks)
        ])
    
    def forward(self, uid, iid):
        x = torch.cat([self.user_emb(uid), self.item_emb(iid)], 1)
        shared = self.shared(x)
        expert_outs = self.mmoe(shared)
        return [torch.sigmoid(self.towers[k](expert_outs[k])) for k in range(self.n_tasks)]
    
    def multi_task_loss(self, preds, labels, task_weights=None):
        """GradNorm 动态加权 + 多任务损失"""
        if task_weights is None:
            task_weights = [1.0] * self.n_tasks
        
        losses = [nn.functional.binary_cross_entropy(preds[k].squeeze(), labels[k].float())
                  for k in range(self.n_tasks)]
        
        # 归一化(关键!)
        total_loss = sum(w * l for w, l in zip(task_weights, losses))
        return total_loss, losses

# 训练时,每个任务独立监控 AUC,及时发现冲突
def train_step_mtl(model, batch, optimizer):
    uid, iid, ctr_label, cvr_label, like_label = batch
    pctr, pcvr, plike = model(uid, iid)
    
    labels = [ctr_label, cvr_label, like_label]
    loss, _ = model.multi_task_loss([pctr, pcvr, plike], labels, task_weights=[1.0, 1.0, 0.5])
    
    optimizer.zero_grad()
    loss.backward()
    # 梯度裁剪(防止某任务梯度爆炸)
    nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
    optimizer.step()
    
    return loss.item()
```

### 3.9 Embedding 共享进阶——跨场景 / 跨域共享

**文字**:除了同场景多任务共享,工业界还有**跨场景共享**(如淘宝 vs 天猫 vs 闲鱼)和**跨域共享**(如电商 vs 内容)。这是大公司多个业务线的核心需求。

**三种主流方案**:

| 方案 | 描述 | 代表 |
| :--- | :--- | :--- |
| **User Embedding 跨场景共享** | 用户特征共享,物品特征独立 | 阿里 EATPP |
| **STAR(Stochastic Shared Architecture)** | 每个场景一个专属网络 + 共享主网络 | 阿里 STAR |
| **PEP(Personalized Embedding Pooling)** | 用户粒度的场景专属 vs 共享自动平衡 | 字节 PEP |

**STAR 公式**:
$$
h_k(x) = \underbrace{f_{\text{shared}}(x)}_{\text{共享主网络}} + \underbrace{f_{\text{specific},k}(x)}_{\text{场景 k 专属网络}}
$$

**PEP 公式**:
$$
E_u^{\text{all}} = \alpha_u E^{\text{shared}} + (1 - \alpha_u) E_u^{\text{specific}}, \quad \alpha_u = \sigma(W \cdot u)
$$

每个用户 $u$ 有自己的 $\alpha_u$,决定"用共享 vs 专属"。

**代码**:
```python
class STAR(nn.Module):
    """阿里 KDD 2020: Star Topology Adaptive Recommender"""
    def __init__(self, n_features, n_scenarios, d=32):
        super().__init__()
        # 共享主网络
        self.shared = nn.Sequential(nn.Linear(n_features, d), nn.ReLU(), nn.Linear(d, d))
        # 每个场景的专属网络
        self.specific = nn.ModuleList([
            nn.Sequential(nn.Linear(n_features, d), nn.ReLU(), nn.Linear(d, d))
            for _ in range(n_scenarios)
        ])
        # 场景判别器(决定用哪个专属网络)
        self.scenario_head = nn.Linear(n_features, n_scenarios)
    
    def forward(self, x, scenario_ids):
        """scenario_ids: [B]"""
        shared_out = self.shared(x)
        specific_outs = torch.stack([self.specific[k](x) for k in range(self.n_scenarios)], dim=1)  # [B, S, d]
        # 选择场景专属
        idx = scenario_ids.view(-1, 1, 1).expand(-1, 1, shared_out.size(-1))
        specific_out = specific_outs.gather(1, idx).squeeze(1)  # [B, d]
        return shared_out + specific_out
```

#### 4.1.1 DIN —— 用 Attention 关注用户历史中的相关物品

**论文**:KDD 2018, Deep Interest Network for Click-Through Rate Prediction

**核心思想**:传统模型把用户历史物品**简单平均**(sum pooling),忽略"不同历史物品对当前候选的重要性"。DIN 用**局部激活单元**(local activation unit),根据候选物品动态计算历史物品的 attention 权重——**用户最近看了 3 件衣服,候选也是衣服,则这 3 件历史衣物权重更高**。

**公式**:
$$
\begin{aligned}
v_U(A) &= f(v_A, e_1, e_2, \ldots, e_H) = \sum_{j=1}^{H} a(e_j, v_A) \cdot e_j \\
a(e_j, v_A) &= \frac{\exp(W \cdot [e_j; v_A; e_j \odot v_A])}{\sum_{k=1}^{H} \exp(W \cdot [e_k; v_A; e_k \odot v_A])}
\end{aligned}
$$

其中 $v_A$ 是候选物品向量,$e_1, ..., e_H$ 是用户历史物品向量,$a(\cdot)$ 是 attention 权重。

**文字**:DIN 的精妙在于**用候选物品"激活"历史物品**——同一段用户历史,候选不同,attention 权重不同。CV 中的 SENet 也有类似思想(用全局信息调整通道权重)。

**代码**:
```python
import torch
import torch.nn as nn

class DIN(nn.Module):
    """阿里 KDD 2018: Deep Interest Network"""
    def __init__(self, n_users, n_items, n_categories, n_shops, d=32, max_his=100):
        super().__init__()
        # 特征 Embedding
        self.user_emb = nn.Embedding(n_users, d)
        self.item_emb = nn.Embedding(n_items, d)
        self.cat_emb = nn.Embedding(n_categories, d)
        self.shop_emb = nn.Embedding(n_shops, d)
        self.his_item_emb = nn.Embedding(n_items, d)
        self.his_cat_emb = nn.Embedding(n_categories, d)
        
        # Attention 单元:输入 [候选, 历史] → 注意力权重
        self.attention_mlp = nn.Sequential(
            nn.Linear(d * 4, 64),    # [e_j; v_A; e_j * v_A; e_j - v_A]
            nn.ReLU(),
            nn.Linear(64, 32),
            nn.ReLU(),
            nn.Linear(32, 1)
        )
        
        # 精排 MLP
        self.mlp = nn.Sequential(
            nn.Linear(d * 6, 128),   # user + item + cat + shop + his + aux
            nn.ReLU(),
            nn.Linear(128, 64),
            nn.ReLU(),
            nn.Linear(64, 1)
        )
    
    def forward(self, uid, iid, cat_id, shop_id, his_item_ids, his_cat_ids):
        """his_item_ids: [B, H]"""
        # 候选 embedding
        u = self.user_emb(uid)                          # [B, d]
        i = self.item_emb(iid)                          # [B, d]
        c = self.cat_emb(cat_id)                        # [B, d]
        s = self.shop_emb(shop_id)                      # [B, d]
        
        # 历史 embedding
        his_i = self.his_item_emb(his_item_ids)         # [B, H, d]
        his_c = self.his_cat_emb(his_cat_ids)           # [B, H, d]
        his_vec = his_i + his_c                          # [B, H, d]
        
        # DIN Attention:用候选激活历史
        cand = (i + c).unsqueeze(1).expand(-1, his_vec.size(1), -1)  # [B, H, d]
        attn_input = torch.cat([his_vec, cand, his_vec * cand, his_vec - cand], dim=-1)  # [B, H, 4d]
        attn_weights = self.attention_mlp(attn_input).squeeze(-1)   # [B, H]
        attn_weights = torch.softmax(attn_weights, dim=-1)           # [B, H]
        
        # 加权求和
        his_pooled = (attn_weights.unsqueeze(-1) * his_vec).sum(dim=1)  # [B, d]
        
        # 精排
        feat = torch.cat([u, i, c, s, his_pooled, u * i], dim=-1)
        return torch.sigmoid(self.mlp(feat))
```

**DIN 工业数据**:阿里妈妈广告场景,AUC +1.5%,CTR +3.6%,RPM +6.6%,每年带来数亿收益。

#### 4.1.2 DIEN —— 兴趣演化建模(Interest Evolution)

**论文**:AAAI 2019, Deep Interest Evolution Network

**核心改进**:DIN 只关注"用户当前兴趣",忽略"兴趣演化"。DIEN 引入**兴趣抽取层**(Interest Extractor Layer)和**兴趣演化层**(Interest Evolution Layer),用 GRU 建模兴趣随时间的演化。

**公式**:
$$
\begin{aligned}
i_t &= \text{GRU}_{\text{extract}}(e_t, h_{t-1}) \quad \text{兴趣抽取} \\
i_t' &= \text{GRU}_{\text{evolution}}(i_t, \alpha_t \cdot h_{t-1}') \quad \text{兴趣演化} \\
\alpha_t &= \text{Attention}(i_t, \text{cand}) \quad \text{辅助 loss(AUGRU)}
\end{aligned}
$$

其中 $\alpha_t$ 是"当前兴趣对候选的重要性",用 Attention 计算。

**代码**:
```python
class DIEN(nn.Module):
    """阿里 AAAI 2019: Deep Interest Evolution Network"""
    def __init__(self, n_items, d=32):
        super().__init__()
        self.item_emb = nn.Embedding(n_items, d)
        # 兴趣抽取层(GRU)
        self.extractor = nn.GRU(d, d, batch_first=True)
        # 兴趣演化层(AUGRU,带 Attention 的 GRU)
        self.evolution = nn.GRUCell(d, d)
        self.attention = nn.Linear(d * 2, 1)   # 计算 attention 权重
        
        self.mlp = nn.Sequential(nn.Linear(d * 2, 128), nn.ReLU(), nn.Linear(128, 1))
    
    def forward(self, cand_iid, his_iids):
        """his_iids: [B, T]"""
        # 兴趣抽取
        his_emb = self.item_emb(his_iids)       # [B, T, d]
        interest_seq, _ = self.extractor(his_emb)  # [B, T, d]
        
        # 兴趣演化 + Attention
        cand = self.item_emb(cand_iid).unsqueeze(1)  # [B, 1, d]
        h = torch.zeros_like(cand.squeeze(1))
        for t in range(interest_seq.size(1)):
            i_t = interest_seq[:, t, :]
            attn_input = torch.cat([i_t, h], dim=-1)
            alpha = torch.sigmoid(self.attention(attn_input))  # [B, 1]
            h = self.evolution(i_t, alpha * h)                 # AUGRU: 用 alpha 调制 hidden state
        
        # 精排
        return torch.sigmoid(self.mlp(torch.cat([cand.squeeze(1), h], dim=-1)))
```

#### 4.1.3 SIM —— 长序列建模(Long Sequence)

**论文**:DLP-KDD 2020, Search-based Interest Model

**核心改进**:DIN/DIEN 只能处理 100~200 长度序列(显存限制),但用户真实历史可达 1000+。**SIM 用两阶段检索**——先 General Search Unit (GSU) 用粗筛模型从 1000 历史中筛出 top-100,再用 Exact Search Unit (ESU) 做精细 Attention。

**公式**:
$$
\begin{aligned}
\text{GSU} &: \text{top-}k_{\text{his}} = \text{argtopk}_{e_j \in H} \; \text{MLP}_{\text{GSU}}(e_j, v_A) \\
\text{ESU} &: v_U = \sum_{j \in \text{top-}k} a(e_j, v_A) \cdot e_j
\end{aligned}
$$

**SIM 工业数据**:阿里主搜场景,**用户序列长度从 100 提到 1000**,AUC 再涨 +0.5%。

### 4.2 京东电商——JMR + 时序 + 跨场景

**文字**:京东搜推广的特征是"商品 SKU 多(10^9 级)、客单价高、决策周期长(用户可能加购物车 7 天才下单)"。京东的核心架构是**JMR(JD Multi-Recall)+ 时序行为建模 + 跨场景共享**。

#### 4.2.1 JMR 召回架构

**文字**:京东召回分 3 路:
1. **Item-based CF**:基于物品相似度(I2I)的协同过滤
2. **User-based CF**:基于用户相似度(U2U)的协同过滤
3. **向量召回**:双塔模型(DSSM),用 FAISS 检索

```python
class JMRRecaller:
    """京东多路召回:CF + 双塔 + 规则"""
    def __init__(self):
        self.item_cf = ItemBasedCF()      # I2I
        self.user_cf = UserBasedCF()      # U2U
        self.vector_recall = DSSMRecall() # 双塔向量召回
        self.rule_recall = RuleBasedRecall()  # 规则(新品/促销)
    
    def recall(self, user_id, context, topk=100):
        """每路召回 100~200,合并去重,取 top-K"""
        candidates = set()
        candidates.update(self.item_cf.recall(user_id, topk=200))
        candidates.update(self.user_cf.recall(user_id, topk=200))
        candidates.update(self.vector_recall.recall(user_id, context, topk=200))
        candidates.update(self.rule_recall.recall(user_id, context, topk=100))
        return list(candidates)[:topk]

class DSSMRecall(nn.Module):
    """双塔召回:User 塔独立,Item 塔独立,向量点积"""
    def __init__(self, n_users, n_items, d=32):
        super().__init__()
        self.user_tower = nn.Sequential(nn.Embedding(n_users, d), nn.Flatten(0, 1), nn.Linear(d, d))
        self.item_tower = nn.Sequential(nn.Embedding(n_items, d), nn.Flatten(0, 1), nn.Linear(d, d))
    
    def user_emb(self, uid):  return self.user_tower(self.user_emb_raw(uid))
    def item_emb(self, iid):  return self.item_tower(self.item_emb_raw(iid))
    def score(self, u, i):    return (u * i).sum(-1)
```

#### 4.2.2 时序行为建模

**文字**:京东用户决策周期长(加购物车 → 7 天 → 下单),必须建模**长决策周期**。京东 2021 年提出**MIMN**(Multi-channel user Interest Memory Network),用记忆网络存储 1000+ 长度用户行为。

```python
class MIMN(nn.Module):
    """京东 KDD 2021: Multi-channel user Interest Memory Network"""
    def __init__(self, n_items, d=32, mem_size=1000):
        super().__init__()
        self.item_emb = nn.Embedding(n_items, d)
        self.memory = nn.Parameter(torch.randn(mem_size, d))  # 用户兴趣记忆
        self.attention = nn.MultiheadAttention(d, num_heads=4, batch_first=True)
        self.mlp = nn.Sequential(nn.Linear(d * 2, 128), nn.ReLU(), nn.Linear(128, 1))
    
    def forward(self, cand_iid, his_iids):
        cand = self.item_emb(cand_iid)             # [B, d]
        his = self.item_emb(his_iids)              # [B, T, d]
        # 从记忆中检索
        mem_out, _ = self.attention(cand.unsqueeze(1), self.memory.unsqueeze(0).expand(cand.size(0), -1, -1), his)
        return torch.sigmoid(self.mlp(torch.cat([cand, mem_out.squeeze(1)], dim=-1)))
```

### 4.3 美团本地生活——LBS + 多业务 + 时空特征

**文字**:美团业务高度复杂——外卖、到店、酒店、旅游、电影、买菜,**多个业务的搜推广系统差异巨大**。美团核心特征:**LBS(地理位置)+ 时空(早午晚餐时段)+ 多业务融合**。

#### 4.3.1 美团 LBS 召回

**文字**:美团召回必须在 3 公里范围内找商家,所以"地理召回"是基础。3 路召回:
1. **Geo-based**:基于用户位置 + 商户位置(距离 < 3km)
2. **LBS Embedding**:把经纬度 Embedding 后用 FAISS 检索
3. **Cascading Recall**:多业务联合召回(用户点外卖后推荐奶茶店)

**公式**:
$$
\text{score}_{\text{geo}}(u, m) = -\frac{\|u_{\text{loc}} - m_{\text{loc}}\|_2}{3\text{km}} \cdot \text{其他特征}
$$

```python
class GeoAwareRecall(nn.Module):
    """美团 LBS 召回:位置感知的双塔"""
    def __init__(self, n_users, n_merchants, d=32):
        super().__init__()
        # 用户位置经纬度 → Embedding
        self.user_loc_emb = nn.Linear(2, d)  # (lat, lon) → d
        # 商家位置经纬度 → Embedding
        self.merchant_loc_emb = nn.Linear(2, d)
        # 其他特征
        self.user_emb = nn.Embedding(n_users, d)
        self.merchant_emb = nn.Embedding(n_merchants, d)
        self.fusion = nn.Sequential(nn.Linear(d * 4, d), nn.ReLU())
    
    def forward(self, user_loc, merchant_loc, uid, mid):
        u_loc = self.user_loc_emb(user_loc)             # [B, d]
        m_loc = self.merchant_loc_emb(merchant_loc)     # [B, d]
        u = self.user_emb(uid)
        m = self.merchant_emb(mid)
        return (self.fusion(torch.cat([u, u_loc, m, m_loc], dim=-1))).sum(-1)  # 点积
```

### 4.4 字节跳动抖音信息流——BST + 双塔 + 长视频多模态

**文字**:字节是国内搜推广"绝对头部",核心业务是抖音信息流(用户刷视频)。字节的特征:**内容理解强(多模态)、用户时长重、视频序列建模**。

#### 4.4.1 BST —— Behavior Sequence Transformer

**论文**:字节 KDD 2019, Behavior Sequence Transformer for E-commerce Recommendation in Alibaba

虽然论文是阿里署名,实际是字节 + 阿里联合,字节内部已大规模落地。

**核心思想**:用 **Transformer Encoder** 替代 DIN 的 Attention,建模用户行为序列的**长距离依赖**。

**公式**:
$$
\text{BST}(H) = \text{TransformerEncoder}(E_1 + P_1, E_2 + P_2, \ldots, E_H + P_H)
$$

其中 $P_i$ 是位置 embedding,$E_i$ 是物品 embedding。

**代码**:
```python
class BST(nn.Module):
    """字节 + 阿里 KDD 2019: Behavior Sequence Transformer"""
    def __init__(self, n_items, d=32, max_seq=100, n_heads=4, n_layers=2):
        super().__init__()
        self.item_emb = nn.Embedding(n_items, d)
        self.pos_emb = nn.Embedding(max_seq, d)
        encoder_layer = nn.TransformerEncoderLayer(d_model=d, nhead=n_heads, dim_feedforward=128, batch_first=True)
        self.transformer = nn.TransformerEncoder(encoder_layer, num_layers=n_layers)
        self.mlp = nn.Sequential(nn.Linear(d * 2, 128), nn.ReLU(), nn.Linear(128, 1))
    
    def forward(self, cand_iid, his_iids):
        B, H = his_iids.shape
        # Embedding + Position
        his_emb = self.item_emb(his_iids) + self.pos_emb(torch.arange(H, device=his_iids.device))  # [B, H, d]
        # Transformer
        his_feat = self.transformer(his_emb)[:, -1, :]  # 取最后位置 [B, d]
        # 精排
        cand = self.item_emb(cand_iid)
        return torch.sigmoid(self.mlp(torch.cat([cand, his_feat], dim=-1)))
```

```python
        return self.user_tower(user_feat)
```

### 4.5 美卡(Meta)Facebook —— DLRM + 工业级 Embedding 基础设施

**论文**:Meta DLRM(Deep Learning Recommendation Model for Personalization and Recommendation Systems), 2019

**核心地位**:DLRM 是搜推广领域的"工业标准",Meta 开源了完整实现,几乎所有大厂都在参考或使用。

**公式**:
$$
\begin{aligned}
\text{稀疏特征} &: \text{Emb}(x_i) \quad (x_i \text{ 是离散 ID}) \\
\text{稠密特征} &: \text{MLP}(x_j) \quad (x_j \text{ 是连续值}) \\
\text{特征交互} &: \text{DotProduct}(E_1, E_2) \quad \text{(FM 风格)} \\
\text{预测} &: \text{MLP}(\text{concat}(E_1 \odot E_2, ..., E_{n-1} \odot E_n, \text{MLP}(x)))
\end{aligned}
$$

**文字**:DLRM 的最大贡献是**工业级 Embedding 基础设施**——模型并行(Embedding 分片到多卡)+ 数据并行(MLP 分片到多卡)+ 自动化混合并行。Meta 开源的 TorchRec 框架就是为 DLRM 服务的。

**代码**:
```python
import torchrec

class DLRM(nn.Module):
    """Meta DLRM: 工业级推荐系统标准架构"""
    def __init__(self, n_dense_features, sparse_feature_sizes, d_emb=32, dense_arch=[128, 64]):
        super().__init__()
        # 1. 稠密特征 MLP
        self.dense_mlp = nn.Sequential(
            nn.Linear(n_dense_features, dense_arch[0]),
            nn.ReLU(),
            nn.Linear(dense_arch[0], dense_arch[1])
        )
        # 2. 稀疏特征 Embedding(分布式分片!)
        self.sparse_emb = torchrec.EmbeddingBagCollection(
            tables=[
                torchrec.EmbeddingBagConfig(name=f"t{i}", num_embeddings=sparse_feature_sizes[i], embedding_dim=d_emb)
                for i in range(len(sparse_feature_sizes))
            ]
        )
        # 3. 特征交互(点积,类似 FM)
        self.interaction = torchrec.DenseInteraction()
        # 4. 顶部 MLP
        self.top_mlp = nn.Sequential(
            nn.Linear(dense_arch[-1] + d_emb * len(sparse_feature_sizes), 128),
            nn.ReLU(),
            nn.Linear(128, 64),
            nn.ReLU(),
            nn.Linear(64, 1)
        )
    
    def forward(self, dense_x, sparse_x):
        # 稠密特征
        dense_feat = self.dense_mlp(dense_x)             # [B, 64]
        # 稀疏特征 Embedding
        sparse_emb = self.sparse_emb(sparse_x)           # list of [B, d_emb]
        # 特征交互(所有稀疏特征两两点积)
        interacted = self.interaction(dense_feat, *sparse_emb)
        # 顶部 MLP
        return torch.sigmoid(self.top_mlp(interacted))
```

**DLRM 工业数据**:Meta News Feed,**CTR +2.7%,每天服务 30 亿用户**。

### 4.6 Google YouTube —— DNN 召回 + 精排双塔

**论文**:YouTube 2016 Recommending Videos for Millions of Users, RecSys 2016

**核心地位**:这是搜推广领域的"开山之作",YouTube 是第一个把深度学习大规模用于推荐的工业系统。

**架构**:召回(双塔 DNN) + 精排(Weighted Logistic Regression)。

**代码**:
```python
class YouTubeDNN(nn.Module):
    """YouTube 2016: DNN 召回"""
    def __init__(self, n_users, n_items, n_videos, d=256, max_watch=200):
        super().__init__()
        # 用户特征(搜索历史 + 观看历史 + 人口学)
        self.watch_emb = nn.EmbeddingBag(n_videos, d, mode='mean')  # 平均池化
        self.search_emb = nn.EmbeddingBag(n_items, d, mode='mean')
        self.user_static = nn.Linear(3, d)  # 性别/年龄/登录状态
        
        # 用户塔
        self.user_tower = nn.Sequential(
            nn.Linear(d * 3, 1024),
            nn.ReLU(),
            nn.Linear(1024, 512),
            nn.ReLU(),
            nn.Linear(512, d),  # 输出 d 维用户向量
        )
        
        # Item 塔(简化为 Embedding)
        self.video_emb = nn.Embedding(n_videos, d)
    
    def user_emb(self, watch_hist, search_hist, user_static):
        """watch_hist: [B, T_w], search_hist: [B, T_s]"""
        w = self.watch_emb(watch_hist)            # [B, d]
        s = self.search_emb(search_hist)          # [B, d]
        u = self.user_static(user_static)         # [B, d]
        return self.user_tower(torch.cat([w, s, u], dim=-1))
    
    def video_emb(self, vid):
        return self.video_emb(vid)
    
    def predict(self, user_vec, vid):
        return (user_vec * self.video_emb(vid)).sum(-1)
```

- 把推荐当作"极端多分类"(候选百万),用 softmax + 负采样
- 用户特征要"平均池化"而不是"sum"(防止刷量用户主导)
- 离线 AUC 必须配合在线 A/B,否则容易过拟合离线指标

### 5.1 基础概念题(5 题)

#### Q1: 搜推广和 CV/NLP 的本质差异是什么?

**标准答案**(3 点必答):
1. **数据形态**:CV 是稠密张量 `[B,C,H,W]`,搜推广是离散 ID + 异构特征
2. **目标**:CV 是封闭世界分类,搜推广是开放世界排序(候选池动态变化)
3. **工程**:CV 训练-推理同分布,搜推广离线-在线必须对齐(特征穿越、延迟反馈)

**延伸追问**:"搜推广为什么不用 Accuracy 而用 AUC?"
**回答**:搜推广关心"序"而不是"类"。一个用户 100 次曝光只点 1 次,准确率永远是 1%,没意义。AUC 衡量"任意正样本打分 > 任意负样本打分"的概率,直接对应"排序质量"。

---

#### Q2: AUC 和 GAUC 的区别?为什么搜推广更常用 GAUC?

**标准答案**:
$$
\text{AUC} = P(s_+ > s_-) \quad \text{全样本整体}
$$
$$
\text{GAUC} = \sum_u w_u \cdot \text{AUC}_u, \quad w_u = \frac{n_u}{\sum_v n_v} \quad \text{按用户分组加权}
$$

**为什么搜推广用 GAUC?** 不同用户的点击率分布差异巨大(高频用户 10% CTR,低频用户 0.1% CTR)。全局 AUC 可能被高频用户主导,无法反映模型在每个用户上的真实排序能力。**GAUC 是"用户级"的排序质量,更贴近业务**。

**代码**:
```python
import numpy as np
from sklearn.metrics import roc_auc_score

def calc_gauc(y_true, y_score, group_id):
    aucs, weights = [], []
    for uid in np.unique(group_id):
        m = group_id == uid
        if m.sum() > 1 and y_true[m].sum() not in (0, m.sum()):
            aucs.append(roc_auc_score(y_true[m], y_score[m]))
            weights.append(m.sum())
    return np.average(aucs, weights=weights) if aucs else 0.0

# 工业界经验:AUC 涨 0.3% 算显著,GAUC 涨 0.5% 算显著
```

**延伸追问**:"如果用户分组数极多(10^7),GAUC 计算太慢怎么办?"
**回答**:随机采样 1% 用户计算 GAUC,或用 Spark 分布式计算。工业界普遍接受"采样 GAUC"作为日常指标。

#### Q3: CTR、CVR、CTCVR 的区别?为什么工业界要单独建模 CVR?

**标准答案**:
- **CTR**:点击率,曝光后点击的概率 $P(\text{click} \mid \text{imp})$
- **CVR**:转化率,点击后转化的概率 $P(\text{conv} \mid \text{click})$
- **CTCVR**:曝光-转化率 $P(\text{conv} \mid \text{imp}) = \text{CTR} \times \text{CVR}$

**为什么单独建模 CVR?** CTR 和 CVR 关注点不同:
- CTR 关注"用户是否感兴趣"(吸引点击)
- CVR 关注"用户是否真要买"(完成转化)

如果只优化 CTR,推荐"标题党" → 点击高但转化低 → GMV 跌。**分别建模 + 多任务学习**是平衡方法。

**经典难题**:CVR 的样本选择偏差(SSB)——只在"点击样本"上训练 CVR,但推理时要在"曝光样本"上预测。**ESMM 用 pCTCVR = pCTR × pCVR 在曝光空间联合训练,解决 SSB**。

**代码**:
```python
class ESMM(nn.Module):
    """ESMM: 在曝光空间同时学 CTR + CVR"""
    def forward(self, uid, iid):
        feat = torch.cat([self.user_emb(uid), self.item_emb(iid)], 1)
        pctr = torch.sigmoid(self.ctr_tower(feat))      # 曝光空间
        pcvr = torch.sigmoid(self.cvr_tower(feat))      # 曝光空间(关键!)
        return pctr, pctr * pcvr                         # 乘性关系
```

**延伸追问**:"CVR 训练数据少怎么办?"
**回答**:过采样正样本 + label smoothing + 多任务迁移 + 主动学习(挑难样本标注)。

#### Q4: 召回、粗排、精排、重排的区别?为什么不能端到端?

**标准答案**:
| 阶段 | 候选规模 | 时延 | 模型复杂度 | 典型架构 |
| :--- | :--- | :--- | :--- | :--- |
| **召回** | 10^9 → 10^3 | < 5ms | 极简(双塔) | DSSM / FM |
| **粗排** | 10^3 → 10^2 | < 10ms | 简单 MLP | 双塔 + LightGBM |
| **精排** | 10^2 → 10 | < 20ms | 复杂 DNN | DIN / DIEN |
| **重排** | 10 → 最终 | < 5ms | 规则 + 轻模型 | EE + 多样性 |

**为什么不能端到端?**
1. **候选规模差 8 个数量级**:10^9 → 10,端到端模型要在 1 秒内对 10^9 物品打分,不可能
2. **每阶段优化目标不同**:召回关心"覆盖率",精排关心"精确率"
3. **模型异构**:召回用双塔(高效),精排用深度模型(精确),架构不同
4. **解耦易维护**:召回/精排可独立迭代,互不影响

**代码**:
```python
class CascadeRecSystem:
    """4 级级联搜推广系统"""
    def recall(self, uid, topk=1000):        # 召回:亿→千
        _, ids = self.faiss_index.search(self.user_emb(uid), topk)
        return ids[0]
    
    def prerank(self, uid, cand_iids, topk=100):  # 粗排:千→百
        scores = self.light_mlp(self.user_emb(uid), self.item_emb(cand_iids))
        return cand_iids[scores.topk(topk).indices]
    
    def rank(self, uid, cand_iids, topk=10):      # 精排:百→十
        scores = self.deep_model(self.user_emb(uid), self.item_emb(cand_iids), self.user_history(uid))
        return cand_iids[scores.topk(topk).indices]
    
    def rerank(self, candidates, context):         # 重排:十→最终
        return apply_business_rules(candidates, context)  # 去重复 + 加多样性 + EE
```

#### Q5: 冷启动问题怎么解决?

**标准答案**(4 种方法):
1. **基于规则**:新物品走"新物品池",强制曝光一定量
2. **基于内容**:用物品内容特征(文本/图像/类目)做 Embedding,缓解 ID 缺失
3. **基于元学习**:MAML / Prototypical Networks,快速适配新用户/物品
4. **基于探索**:UCB / Thompson Sampling,主动探索新物品的兴趣

**工业经验**:
- 新用户冷启动:用**人口学特征** + **设备特征** + **注册时填的兴趣标签**
- 新物品冷启动:用**内容 Embedding**(类目 + 标题 + 图片) → 找相似老物品
- **不要把冷启动用户直接喂老模型**,必须有专门策略

**代码**:
```python
class ColdStartStrategy:
    def __init__(self, content_emb_model, faiss_index):
        self.content_emb = content_emb_model        # 内容 Embedding
        self.faiss_index = faiss_index              # 老物品向量库
    
    def cold_start_user_recall(self, user_demographic, topk=100):
        """新用户:用人口学特征召回"""
        # 1. 找相似老用户(基于人口学)
        similar_users = self.faiss_index.search(self.demographic_to_vec(user_demographic), topk)
        # 2. 用相似用户喜欢的物品作为候选
        return self.get_user_liked_items(similar_users)
    
    def cold_start_item_recall(self, item_content, topk=100):
        """新物品:用内容找相似老物品"""
        vec = self.content_emb(item_content)        # 文本/图像 Embedding
        similar_items, _ = self.faiss_index.search(vec, topk)
        return similar_items[0]
```

### 5.2 Embedding 相关题(5 题)

#### Q6: Embedding 表太大(12.8 GB)放不进显存怎么办?

**标准答案**(4 种方法):
1. **模型并行**:Embedding 表分片到多卡(每个卡存 1/N)
2. **量化**:FP32 → INT8(4×压缩),INT4(8×压缩)
3. **Hash Trick**:用哈希函数把 ID 映射到更小的桶(降低 V)
4. **Parameter Server**:Embedding 放在 CPU/SSD,MLP 放在 GPU(Mixed Precision)

**公式**:
$$
\text{原始} = V \times D \times 4 = 10^8 \times 32 \times 4 = 12.8 \text{ GB}
$$
$$
\text{INT8 量化后} = 12.8 / 4 = 3.2 \text{ GB}
$$
$$
\text{INT4 量化后} = 12.8 / 8 = 1.6 \text{ GB}
$$
$$
\text{Hash Trick (1\% bucket)} = 10^6 \times 32 \times 4 = 128 \text{ MB}
$$

**代码**:
```python
# 1. 量化(FX Graph Mode Quantization)
import torch.quantization as quant
model_int8 = quant.quantize_dynamic(model, {nn.Embedding}, dtype=torch.qint8)

# 2. Parameter Server(Embedding 在 CPU, MLP 在 GPU)
class PSModel(nn.Module):
    def __init__(self):
        super().__init__()
        self.emb_table = nn.Embedding(10**8, 32).to('cpu')   # CPU
        self.mlp = nn.Sequential(nn.Linear(32, 128), nn.ReLU()).to('cuda')  # GPU
    
    def forward(self, iid):
        emb = self.emb_table(iid.to('cpu')).to('cuda')      # CPU 查 → GPU
        return self.mlp(emb)
```

**延伸追问**:"INT8 量化对 AUC 影响多大?"
**回答**:通常 < 0.1% AUC 影响,工业可接受。INT4 影响稍大(0.3~0.5% AUC),需要敏感业务谨慎。

#### Q7: 长尾 ID 怎么防止过拟合?

**标准答案**(3 种方法):
1. **稀疏 L2**:只对被查过的 Embedding 行加 L2 约束
2. **频率感知 Dropout**:出现 < 5 次的 ID 直接 mask
3. **Embedding 衰减**:长尾 ID 的 Embedding 缓慢衰减到 0,定期清理

**公式**:
$$
J(\theta) = L(\theta) + \lambda \sum_{i \in \text{queried}} \|E_i\|^2 \quad \text{(稀疏 L2)}
$$

**代码**:
```python
class FreqAwareEmbedding(nn.Embedding):
    """频率感知 Embedding:只对被查过的行加 L2 + 频率感知 mask"""
    def __init__(self, num_emb, dim):
        super().__init__(num_emb, dim)
        self.register_buffer('query_count', torch.zeros(num_emb))
    
    def forward(self, input):
        # 更新查询计数
        u, c = torch.unique(input, return_counts=True)
        self.query_count[u] += c.float()
        # 频率感知 mask:出现 < 5 次的 ID mask 掉
        mask = self.query_count[input] < 5
        input_masked = torch.where(mask, torch.zeros_like(input), input)
        return super().forward(input_masked)
    
    def l2_loss(self, queried_ids, lam=1e-6):
        return lam * self.weight[queried_ids].pow(2).sum()
```

#### Q8: 负采样策略有哪些?In-batch Neg vs Hard Neg vs Random?

**标准答案**:
| 策略 | 描述 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| **Random Neg** | 随机采样负样本 | 简单、噪声小 | 容易训出"区分度低"的模型 |
| **In-batch Neg** | 同 batch 其他样本当负样本 | 免费、高效 | 负样本难度低 |
| **Hard Neg** | 召回错的高分物品 | 训练更有信号 | 噪声大、可能过拟合 |
| **Popularity Neg** | 按物品流行度采样 | 缓解流行度偏差 | 偏向热门 |
| **Mix** | 多策略混合 | 平衡 | 工程复杂 |

**公式**(In-batch Neg Loss):
$$
L = -\frac{1}{B} \sum_{i=1}^{B} \log \frac{\exp(s_i \cdot t_i / \tau)}{\sum_{j=1}^{B} \exp(s_i \cdot t_j / \tau)}
$$

其中 $t_i$ 是物品向量,$s_i$ 是用户向量,$\tau$ 是温度系数。

**代码**:
```python
class InBatchNegLoss(nn.Module):
    """In-batch Negative Sampling (双塔召回常用)"""
    def __init__(self, temperature=0.05):
        super().__init__()
        self.temperature = temperature
    
    def forward(self, user_emb, item_emb):
        """user_emb: [B, d], item_emb: [B, d]"""
        logits = user_emb @ item_emb.T / self.temperature   # [B, B]
        labels = torch.arange(user_emb.size(0), device=user_emb.device)
        return nn.functional.cross_entropy(logits, labels)
```

**延伸追问**:"Hard Negative 怎么挖?"
**回答**:用当前模型召回 1000 候选,取打分 top-K 但**不在 Ground Truth**的物品作为 Hard Neg。也可以用 ANN 索引(FAISS)高效检索 Hard Neg。

#### Q9: DIN 的 Attention 和 Transformer 的 Self-Attention 有什么区别?

**标准答案**:

| 维度 | DIN Attention | Transformer Self-Attention |
| :--- | :--- | :--- |
| **Query** | 候选物品 | 历史物品(自己) |
| **Key/Value** | 历史物品 | 历史物品(自己) |
| **因果 Mask** | 不需要(候选不在历史) | 需要(自回归) |
| **位置信息** | 无显式位置编码 | 有 RoPE / Sinusoidal |
| **目标** | "激活相关历史" | "全局序列建模" |

**DIN Attention 公式**:
$$
a(e_j, v_A) = \frac{\exp(W \cdot [e_j; v_A; e_j \odot v_A])}{\sum_k \exp(\ldots)}
$$

**Transformer Self-Attention 公式**:
$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right) V
$$

**本质差异**:DIN 用候选当 Query 检索历史,Transformer 用历史自查询。DIN 是"跨序列检索",Transformer 是"序列内建模"。

**代码**:
```python
# DIN Attention:候选 → 历史
def din_attention(cand, history):
    # cand: [B, d], history: [B, H, d]
    cand_expand = cand.unsqueeze(1).expand(-1, history.size(1), -1)
    attn_input = torch.cat([history, cand_expand, history * cand_expand], dim=-1)
    weights = torch.softmax(self.mlp(attn_input).squeeze(-1), dim=-1)
    return (weights.unsqueeze(-1) * history).sum(dim=1)  # [B, d]

# Transformer Self-Attention:历史 → 历史
def self_attention(history):
    # history: [B, H, d]
    Q = self.W_q(history); K = self.W_k(history); V = self.W_v(history)
    attn = torch.softmax(Q @ K.transpose(-1, -2) / self.sqrt_d, dim=-1)
    return attn @ V
```

#### Q10: 为什么搜推广要用稀疏 L2 而不是普通 L2?

**标准答案**:普通 L2 对**所有参数**加约束,搜推广的 Embedding 表有 V=10^8 行,但**每个 batch 只查几十~几百行**(用户/物品 ID),99.99% 的 Embedding 行本 batch 没被查。如果对这些"未被查"的行加 L2,会导致**本 batch 的梯度更新很小**(被平均掉了)。

**稀疏 L2** 只对"被查过"的行加 L2:
$$
J(\theta) = L(\theta) + \lambda \sum_{i \in \text{queried}} \|E_i\|^2
$$

这样**每个被查的 Embedding 都有充分约束**,未被查的保持随机(下次被查时仍是"陌生"状态,等真正被多次查后才慢慢学到合理值)。

**代码**:
```python
# ❌ 普通 L2:对所有 Embedding 加约束(无效)
optimizer = torch.optim.Adam(model.parameters(), weight_decay=1e-5)

# ✅ 稀疏 L2:只对被查的 Embedding 加约束
optimizer = torch.optim.Adam([
    {'params': model.mlp.parameters(), 'weight_decay': 1e-5},
    {'params': model.item_emb.parameters(), 'weight_decay': 0},   # Embedding 不加 L2
])
# 在 loss 里手动加稀疏 L2
queried_ids = batch['iid'].unique()
loss = main_loss + sparse_l2(model.item_emb.weight, queried_ids, lam=1e-6)
```

### 5.3 模型架构题(5 题)

#### Q11: Wide & Deep 的 Wide 部分和 Deep 部分分别学什么?

**标准答案**:
- **Wide 部分**:学"显式记忆"(memorization),即**特征组合的直接记忆**(比如"用户 A 经常买 iPhone")
- **Deep 部分**:学"隐式泛化"(generalization),即**特征的深层非线性组合**(比如"25 岁男性 + 北京 + 周三晚上 → 可能买运动装备")

**公式**:
$$
P(\text{click} \mid x) = \sigma(w_{\text{wide}}^T [x, \phi(x)] + w_{\text{deep}}^T a^{(l_f)} + b)
$$

其中 $\phi(x)$ 是特征交叉(交叉特征),$a^{(l_f)}$ 是 Deep 塔最后一层输出。

**代码**:
```python
class WideDeep(nn.Module):
    """Google 2016: Wide & Deep Learning"""
    def __init__(self, n_users, n_items, n_features, d=32):
        super().__init__()
        # Wide 部分(线性 + 特征交叉)
        self.wide = nn.Linear(n_features, 1)   # 一阶 + 交叉项
        
        # Deep 部分(Embedding + MLP)
        self.user_emb = nn.Embedding(n_users, d)
        self.item_emb = nn.Embedding(n_items, d)
        self.deep = nn.Sequential(nn.Linear(d * 2, 128), nn.ReLU(), nn.Linear(128, 64), nn.ReLU(), nn.Linear(64, 1))
    
    def forward(self, uid, iid, cross_features):
        """cross_features: 手工交叉特征(如 用户-类目组合)"""
        wide_out = self.wide(cross_features)               # [B, 1]
        deep_in = torch.cat([self.user_emb(uid), self.item_emb(iid)], 1)
        deep_out = self.deep(deep_in)                       # [B, 1]
        return torch.sigmoid(wide_out + deep_out)
```

#### Q12: DeepFM 相比 Wide & Deep 改进在哪?

**标准答案**:**DeepFM 用 FM 层替代 Wide 的手工交叉**,自动学习二阶特征交叉,无需人工构造。

| 维度 | Wide & Deep | DeepFM |
| :--- | :--- | :--- |
| **交叉方式** | 人工构造(需要领域知识) | FM 自动学习 |
| **交叉阶数** | 仅手工交叉的阶数 | 二阶(可扩展到 DNN 学高阶) |
| **特征工程** | 重 | 轻 |
| **性能** | 依赖人工交叉质量 | 通常更优 |

**FM 公式**:
$$
\phi_{\text{FM}}(x) = \sum_{i=1}^{n} \sum_{j=i+1}^{n} \langle v_i, v_j \rangle x_i x_j
$$

**代码**:
```python
class DeepFM(nn.Module):
    """华为 2017: DeepFM"""
    def __init__(self, n_features, d=32):
        super().__init__()
        # 1. FM 一阶 + 二阶
        self.first_order = nn.Linear(n_features, 1)       # 一阶线性
        self.emb = nn.Embedding(n_features, d)            # 二阶 Embedding
        # 2. Deep 部分
        self.deep = nn.Sequential(nn.Linear(n_features * d, 128), nn.ReLU(), nn.Linear(128, 1))
    
    def forward(self, x):
        # x: [B, n_features] 稀疏 0/1
        
        # FM 一阶
        first = self.first_order(x)                        # [B, 1]
        
        # FM 二阶(特征两两 Embedding 点积)
        emb = self.emb(x)                                  # [B, n_features, d]
        sum_square = emb.sum(dim=1).pow(2)                 # (Σv_i)²
        square_sum = (emb.pow(2)).sum(dim=1)               # Σv_i²
        second = 0.5 * (sum_square - square_sum).sum(dim=-1, keepdim=True)  # [B, 1]
        
        # Deep
        deep_out = self.deep(emb.flatten(1))                # [B, 1]
        
        return torch.sigmoid(first + second + deep_out)
```

#### Q13: DIN 和 DIEN 的关键区别?为什么 DIEN 涨点更多?

**标准答案**:
- **DIN**:用 Attention 关注"用户当前兴趣",但忽略"兴趣演化"
- **DIEN**:用 GRU + AUGRU 建模"兴趣的时序演化"

**DIEN 涨点更多的原因**:
1. 兴趣有"惯性"——用户昨天看运动鞋,今天可能还在看
2. 兴趣有"漂移"——用户最近又看了电子产品,运动鞋兴趣衰减
3. DIEN 用 AUGRU 显式建模兴趣的"激活 + 衰减",更符合实际

**公式对比**:
$$
\text{DIN}: v_U = \sum_j a(e_j, v_A) \cdot e_j \quad \text{(静态 attention)}
$$
$$
\text{DIEN}: i_t' = \text{AUGRU}(i_t, \alpha_t \cdot h_{t-1}') \quad \text{(时序演化)}
$$

#### Q14: 为什么 MMoE 用门控(Gate)而不是直接 concat?

**标准答案**:直接 concat 共享底层会让所有任务"争夺"同一组参数,任务冲突严重。门控机制让**每个任务动态选择专家**,缓解冲突:
$$
h_k(x) = \sum_{m=1}^{M} g_{k,m}(x) \cdot E_m(x), \quad g_k = \text{softmax}(W_k x)
$$

**门控的本质**:让模型"决定"对每个任务来说哪些专家重要。这是 **Input-dependent Routing**,类似 Mixture of Experts (MoE)。

**代码**:
```python
class Gate(nn.Module):
    """MMoE 门控网络"""
    def __init__(self, d_in, n_experts):
        super().__init__()
        self.fc = nn.Linear(d_in, n_experts)
    
    def forward(self, x):
        return torch.softmax(self.fc(x), dim=-1)    # [B, n_experts]
```

#### Q15: 生成式推荐(GR)相比传统推荐的核心优势是什么?

**标准答案**(3 点):
1. **统一架构**:召回+粗排+精排统一为一个生成模型,简化工程
2. **冷启动缓解**:Semantic ID 把长尾物品压缩到公共 token,新物品也能被生成
3. **LLM 能力迁移**:复用 LLM 的训练技巧(预训练 + 微调 + RLHF)

**公式**(生成式推荐):
$$
P(\text{next item} \mid \text{history}) = \prod_{t=1}^{T} P(s_t \mid s_{<t}, \text{history})
$$

其中 $s_t$ 是 Semantic ID 的第 $t$ 个 token。

**代码**:
```python
class GenerativeRec(nn.Module):
    """生成式推荐:用 Transformer 预测下一个 Semantic ID"""
    def __init__(self, n_tokens, d=128, n_layers=4):
        super().__init__()
        self.token_emb = nn.Embedding(n_tokens, d)
        self.pos_emb = nn.Embedding(1000, d)
        encoder_layer = nn.TransformerEncoderLayer(d_model=d, nhead=8, dim_feedforward=512, batch_first=True)
        self.transformer = nn.TransformerEncoder(encoder_layer, num_layers=n_layers)
        self.head = nn.Linear(d, n_tokens)
    
    def forward(self, history_sids):
        """history_sids: [B, T] Semantic ID 序列"""
        B, T = history_sids.shape
        x = self.token_emb(history_sids) + self.pos_emb(torch.arange(T, device=history_sids.device))
        x = self.transformer(x)
        return self.head(x)                              # [B, T, n_tokens]
```

#### Q16: 离线 AUC 涨了但线上 CTR 跌,可能原因?

#### Q17: A/B 实验怎么做?怎么确定实验周期?

**标准答案**:
- **流量分配**:哈希分流(uid % 100 < 10 → 实验组,否则对照组)
- **正交分层**:互斥层(同一用户只能在一个实验里)+ 正交层(不同实验可重叠)
- **实验周期**:至少 7 天(覆盖工作日/周末),统计检验 p < 0.05
- **最小样本量**:根据 baseline CTR 和期望 MDE(最小可检测效应)计算

**公式**(样本量):
$$
N = \frac{(z_{\alpha/2} + z_{\beta})^2 \cdot (p_1(1-p_1) + p_2(1-p_2))}{(p_2 - p_1)^2}
$$

```python
def ab_sample_size(baseline_ctr=0.05, mde=0.005, alpha=0.05, power=0.8):
    """A/B 实验所需样本量"""
    from scipy.stats import norm
    p1, p2 = baseline_ctr, baseline_ctr + mde
    z_alpha = norm.ppf(1 - alpha / 2)
    z_beta = norm.ppf(power)
    N = (z_alpha + z_beta) ** 2 * (p1 * (1-p1) + p2 * (1-p2)) / (p2 - p1) ** 2
    return int(N)

# 例:baseline CTR 5%,期望涨 0.5%,每组需 30 万样本,1000 QPS 下 5 分钟
print(ab_sample_size(baseline_ctr=0.05, mde=0.005))  # 输出 297456
```

#### Q18: 推荐系统的 EE(探索-利用)问题怎么解?

**标准答案**:**EE = Exploration vs Exploitation**——推荐"已知用户喜欢的物品"(利用)vs 推荐"未知但可能喜欢的物品"(探索)。长期来看,**完全利用 → 信息茧房 → 用户流失**。

**3 种主流解法**:
1. **$\epsilon$-Greedy**:10% 流量随机推荐
2. **UCB(Upper Confidence Bound)**:用置信区间上界打分 $s_a + c \sqrt{\ln t / n_a}$
3. **Thompson Sampling**:从后验分布采样,概率性探索

**公式**(UCB):
$$
a^* = \arg\max_a \left[ Q(a) + c \sqrt{\frac{\ln t}{n_a}} \right]
$$

其中 $Q(a)$ 是物品平均收益,$n_a$ 是被推荐次数,$t$ 是总推荐次数。

```python
class UCB:
    """Upper Confidence Bound Bandit"""
    def __init__(self, n_arms, c=1.0):
        self.n_arms = n_arms
        self.c = c
        self.counts = np.zeros(n_arms)        # 每个 arm 被选次数
        self.values = np.zeros(n_arms)        # 每个 arm 平均收益
    
    def select(self, t):
        """UCB 选择"""
        ucb = self.values + self.c * np.sqrt(np.log(t + 1) / (self.counts + 1e-6))
        return np.argmax(ucb)
    
    def update(self, arm, reward):
        self.counts[arm] += 1
        self.values[arm] += (reward - self.values[arm]) / self.counts[arm]
```

#### Q19: 在线学习(Online Learning)怎么避免灾难性遗忘?

**标准答案**(4 种方法):
1. **EWC(Elastic Weight Consolidation)**:对重要参数加约束
2. **Replay Buffer**:保留 10% 旧样本
3. **LwF(Learning without Forgetting)**:用旧模型输出做蒸馏
4. **渐进式学习**:LR 衰减 + 慢更新

**公式**(EWC):
$$
L_{\text{EWC}}(\theta) = L_{\text{new}}(\theta) + \lambda \sum_i F_i (\theta_i - \theta_i^*)^2
$$

其中 $F_i$ 是 Fisher 信息矩阵(参数 $i$ 的重要性),$\theta_i^*$ 是旧值。

#### Q20: 推理时延要求高(精排 < 20ms)怎么优化?

**标准答案**(5 种方法):
1. **模型蒸馏**:Teacher → Student,Student 精度损失 < 1%,推理快 5x
2. **量化**:FP32 → INT8(精度损失 0.5%,快 2x)
3. **模型剪枝**:剪掉 50% 不重要参数
4. **TensorRT / ONNX**:算子融合 + 静态图优化
5. **批处理**:多个请求合并推理(精排场景有限)

**代码**:
```python
# 蒸馏:Teacher 训完后指导 Student
class DistillationLoss(nn.Module):
    def __init__(self, T=3.0, alpha=0.7):
        super().__init__()
        self.T = T          # 温度
        self.alpha = alpha  # 蒸馏权重
    
    def forward(self, student_logits, teacher_logits, labels):
        soft_loss = nn.functional.kl_div(
            nn.functional.log_softmax(student_logits / self.T, dim=-1),
            nn.functional.softmax(teacher_logits / self.T, dim=-1),
            reduction='batchmean'
        ) * (self.T ** 2)
        hard_loss = nn.functional.cross_entropy(student_logits, labels)
        return self.alpha * soft_loss + (1 - self.alpha) * hard_loss
```
