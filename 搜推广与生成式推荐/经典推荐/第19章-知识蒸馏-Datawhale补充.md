## 二、核心补充内容

### 2.1 蒸馏的三条信息通道（awesome-compression 类型学）

awesome-compression 把蒸馏按"教师向学生传什么"分三条通道，比"软标签蒸馏"更完整的坐标系：

| 通道 | 传递物 | 典型损失 | 推荐场景对应 |
| :--- | :--- | :--- | :--- |
| 输出层 | 软标签（含温度 T 的类目分布） | KL(p_T ‖ p_S) | 排序模型 CTR 蒸馏（本地正文主线） |
| 特征层 | 中间表征/Embedding | MSE / 对齐损失 | 双塔召回：大塔教小塔（本地"检索侧蒸馏"） |
| 关系层 | 样本间关系（相似度矩阵） | RKD 类 | 排序序关系保持（精排→粗排蒸馏） |

**温度的直觉**：T 越大软标签越平滑（暴露"类目间相对关系"的暗知识），T→0 退化为硬标签。推荐场景的排序蒸馏本质是"关系通道"——教师分数的序比绝对值重要。

### 2.2 压缩四件套的组合策略（awesome-compression 全景）

蒸馏与其他压缩手段的组合顺序有讲究：

```text
训练期：蒸馏（教师帮助学生学得更准）
部署期：量化（INT8/INT4，几乎必做）+ 结构化剪枝（可选）
组合纪律：先蒸馏出强小模型 → 再量化 → 剪枝留最后（不可逆且最伤精度）
```

| 组合 | 结论 |
| :--- | :--- |
| 蒸馏 + 量化 | **黄金组合**：蒸馏保精度、量化保部署，精度损失通常 <1% |
| 量化感知训练(QAT) + 蒸馏 | 教师软标签可缓解 QAT 的精度坍缩 |
| 蒸馏 + 非结构化剪枝 | 工业少用（稀疏硬件不友好），用结构化剪枝替代 |

**与本地正文的衔接**：本地第19章"模型小型化"的动机段可用此坐标系收编——"为什么要蒸馏"的第一性回答是：量化/剪枝只能压缩已有模型，蒸馏能**生成更适合部署容量的新模型**。

### 2.3 推荐/LLM 两侧的蒸馏对照

| 维度 | 推荐侧（本地正文） | LLM 侧（awesome-compression 延伸） |
| :--- | :--- | :--- |
| 教师-学生 | 精排大模型 → 粗排/召回小模型 | 大 LLM → 小 LLM（对应本地 LLM发展/第02章小模型蒸馏） |
| 传递内容 | 打分/序关系/用户表征 | token 分布（soft targets）/ CoT 轨迹 |
| 特殊性 | 在线-离线特征一致性问题 | 数据生成的教师标注成本（白盒 vs 黑盒蒸馏） |

## 三、可直接动手的实践

1. 用 awesome-compression 代码跑 MNIST/Criteo 级"输出层蒸馏"，扫温度 T ∈ {1,2,4,8} 画学生精度曲线，验证温度的甜点区间；
2. 实现"关系通道"蒸馏的一个最小版（学生拟合教师的 pairwise 序），对比纯软标签在排序指标（NDCG）上的差异；
3. 组合实验：蒸馏后的小模型分别做 PTQ 与 QAT，记录"蒸馏 → 量化"流水线的总精度损失。
