# 第 19 章:知识蒸馏——大模型教小模型

> **本章目标**: 知识蒸馏(Knowledge Distillation, KD)是工业推荐系统的**核心技术之一**——用大模型(Tacher)的"知识"教小模型(Student),在保持精度的同时**降低推理成本**。本章系统讲解:
> - KD 的**核心思想**:为什么"软标签"比"硬标签"信息更丰富
> - 三种蒸馏范式:**Logit 蒸馏、Feature 蒸馏、Relation 蒸馏**
> - 搜推广的特殊蒸馏:**特征级、物品级、序列级蒸馏**
> - 工业实践:TIGER、OneRec、特征蒸馏、跨模态蒸馏
>
> 学完本章,你能:
> - 在自己的搜推广模型上**实施 KD 蒸馏**
> - 理解 LLM 教师 / 推荐学生 的范式
> - 选对**蒸馏温度**和**损失权重**

**为什么"知识蒸馏"是搜推广的"工业必备"而不是"论文玩具"?**

现实中的搜推广永远面对一个根本矛盾:**模型越大效果越好,但推理成本也越高**。这个矛盾在 GenRec 时代尤其尖锐:
- 训练侧:字节的 OneRec 用了 7B+ 参数的 Transformer 教师,在 1024 张 A100 训 2 周,离线 AUC 比基线高 5-8%
- 推理侧:但线上要求 P99 < 50ms、单实例内存 < 1GB,QPS 上万——7B 模型单次推理就要 200ms+、占 14GB,**根本不能上线**

**这正是知识蒸馏的核心价值**:
- **教师**(Teacher):大模型,训得起、训得久,**追求极致精度**
- **学生**(Student):小模型,**追求极致速度**
- **蒸馏**:把教师的"暗知识"(dark knowledge)浓缩进学生,**精度损失 < 1%,推理加速 10-50 倍**

字节 OneRec 公开报告:**用 7B 教师蒸馏 0.5B 学生,学生 AUC 几乎不掉,但推理 QPS 提升 14 倍**。这就是为什么蒸馏是"必学"而不是"选学"。

**这一章会讲清楚**:

1. **Logit 蒸馏**(Hinton 2015):最经典,软标签对齐
2. **Feature 蒸馏**(FitNet):中间层特征对齐,信息更丰富
3. **Relation 蒸馏**(CRD):样本间关系矩阵对齐,泛化更强
4. **搜推广专用蒸馏**:特征级、物品级、序列级、教师多模态
5. **工业细节**:温度、权重、调度、A/B 实验方法

**学完后你能**:在 1-2 周内把团队 7B 教师蒸馏成 < 1B 学生,**几乎不掉点地上线**。

## 1. 知识蒸馏:核心思想与历史

**文字**: 知识蒸馏成为工业推荐系统标配,根源是'大模型训得起,小模型推不起'的张力。hidden=512 的 DIN 教师在 8 张 A100 训练,离线 AUC 高 2 个点;但在线推理要求 P99 < 50ms、内存 < 1GB,只能部署 hidden=64 的 DNN 学生。**从信息论看,硬标签 [0,0,1,0,0] 损失了类别间的相似度,'像猫 0.7、像狗 0.1'这些细节被丢弃**;而教师的软概率保留了完整分布,学生学到的不是'答案是 X',而是'为什么不是 Y,有多像 Y'。这就是 Hinton 所说的 dark knowledge,蒸馏的全部价值都建立在这之上。

### 1.1 知识蒸馏的诞生

**Hinton 2015 的开创性论文**《Distilling the Knowledge in a Neural Network》:

> **核心洞察**: 一个训练好的大模型(Tacher)的**软标签**(soft label)携带了**比硬标签(0/1)更丰富的信息**。

**示例**:
- 硬标签: "这是猫" = `[0, 0, 1, 0, 0]` ("猫")
- 软标签: "这是猫,有点像狗" = [0.05, 0.05, 0.7, 0.1, 0.1] ← 软概率

**学生模型学软标签** → 学到:
1. 哪些类别**容易混淆**(猫 vs 狗的相似度 > 猫 vs 桌子)
2. 哪些类别**不相似**
3. 大模型的"**暗知识**"(dark knowledge)——硬标签无法表达的细节

### 1.2 数学形式化

**软化(Temperature scaling)**:

$$p_i = \frac{\exp(z_i / T)}{\sum_j \exp(z_j / T)}$$

当 $T = 1$ 时,等价于普通 softmax;当 $T \to \infty$ 时,趋向均匀分布;当 $T \to 0$ 时,趋向 one-hot。

**蒸馏损失**(KL 散度):

$$\mathcal{L}_{\text{distill}} = T^2 \cdot D_{\text{KL}}(\text{softmax}(z^S / T) \| \text{softmax}(z^T / T))$$

其中 $z^S, z^T$ 是学生/教师的 logits。

**总损失**:

$$\mathcal{L} = (1 - \alpha) \mathcal{L}_{\text{hard}} + \alpha \mathcal{L}_{\text{distill}}$$

### 1.3 信息论视角

**为什么 KD 有效**:
- 软标签包含**互信息** $I(\text{样本}; \text{类别})$,而硬标签只保留 $\arg\max$ 信息
- $T > 1$ 让教师暴露**类别之间的相似度**(猫/狗都四条腿)
- 学生学**完整分布** → 更好的泛化

参考 `./第21章-信息论深层次理解.md` §2。

## 2. Logit 蒸馏:Hinton 2015 经典 KD

**文字**: 温度 T 是蒸馏的核心抓手,它把'尖锐'的 $\mathrm{softmax}$ 拉成'平坦'的分布。**T=1 是标准 $\mathrm{softmax}$,教师对正确类输出 0.99,其他接近 0,几乎和硬标签没区别**;T=4 时正确类掉到 0.7,负类从 0.001 抬到 0.05,**这些'微小概率'恰恰是类别相似性的载体,猫和狗在 T=4 时教师告诉学生'它们有点混',T=1 时不会**。KL 方向是'学生逼近教师',**前面的 T² 系数是为了 T 变化时 soft loss 和 hard loss 梯度量级一致**,否则 T 越大 soft 梯度越小,蒸馏信号被淹没。搜推广经验甜区在 T=2~4,这个区间既保留了教师暗知识,又不至于平滑到均匀分布。

### 2.1 完整实现

```python
import torch
import torch.nn.functional as F

class LogitDistillationLoss(torch.nn.Module):
    """Hinton 2015 经典 KD 损失"""
    def __init__(self, temperature=4.0, alpha=0.7):
        super().__init__()
        self.T = temperature
        self.alpha = alpha
    
    def forward(self, student_logits, teacher_logits, labels):
        """
        student_logits: [B, num_classes]
        teacher_logits: [B, num_classes]
        labels: [B]
        """
        # 硬损失(学生自己的 CE)
        hard_loss = F.cross_entropy(student_logits, labels)
        
        # 蒸馏损失(KL 散度 × T²)
        soft_student = F.log_softmax(student_logits / self.T, dim=-1)
        soft_teacher = F.softmax(teacher_logits / self.T, dim=-1)
        distill_loss = F.kl_div(soft_student, soft_teacher, reduction='batchmean') * (self.T ** 2)
        
        # 加权
        total = (1 - self.alpha) * hard_loss + self.alpha * distill_loss
        return total, hard_loss, distill_loss
```

### 2.2 关键超参

**温度 T**:
- $T = 1$: 退化为标准 CE
- $T = 2 \sim 5$: 经验甜区
- $T \to \infty$: 均匀分布,无信息
- $T \to 0$: one-hot,等价于硬标签

**蒸馏权重 α**:
- $\alpha = 0$: 只用硬标签
- $\alpha = 0.5 \sim 0.9$: 平衡
- $\alpha = 1$: 只用蒸馏
- **搜推广经验**: $\alpha = 0.5 \sim 0.7$(让真实标签仍起作用)

### 2.3 在搜推广的应用

**典型场景**:
- Teacher: 大模型(如 DIN with hidden=512)
- Student: 小模型(如 DNN with hidden=64)用于在线推理

```python
# 训练循环
kd_loss_fn = LogitDistillationLoss(temperature=4.0, alpha=0.7)

for batch in train_loader:
    student_logits = student_model(batch)        # [B, 1] 或 [B, V]
    with torch.no_grad():
        teacher_logits = teacher_model(batch)   # [B, 1] 或 [B, V]
    
    # 蒸馏损失
    total_loss, hard_loss, distill_loss = kd_loss_fn(
        student_logits, teacher_logits, batch['label']
    )
    
    # 优化学生
    optimizer.zero_grad()
    total_loss.backward()
    optimizer.step()
    
    # 教师**冻结**,不更新
```

## 3. Feature 蒸馏:FitNet 与隐藏层对齐

**文字**: Logit 蒸馏只对齐最后一层,但教师真正的'知识资产'往往藏在中间层。**以 DIN 为例,它的 attention $\text{层(用户历史 vs 候选物品的注意力权重)}$学到了'这个用户为什么点这个'的局部结构**;学生 DNN 没有 attention 机制,直接学输出学不到这种'局部推理'。FitNet 2015 提出的 hint layer 思想是:用一层线性投影把学生中间层映射到教师同维度,再算 MSE 对齐。**什么场景下有效?教师和学生结构相近、容量差 3~10 倍时收益最大**。差异太大(LLM$\to$DNN)中间层语义已经对不上,强行对齐反而引入噪声;差异太小(<2 倍)中间层天然接近,蒸馏没增益。推荐场景里,粗排教师(8 层 Transformer)$\to$精排学生(3 层 DNN)最常用 Feature 蒸馏。

### 3.1 为什么需要 Feature 蒸馏

**Logit 蒸馏的局限**:
- 只对齐**最终输出**,中间层学到的"特征"没传递
- 教师模型容量大,可能学到了**比硬标签+软标签更丰富**的中间表示
- 学生容量小,直接学 logit 学不到

**Feature 蒸馏**: 让学生模型的**隐藏层**模仿教师模型的**隐藏层**。

### 3.2 FitNet(Romero 2015)

**核心思想**: 学生模型**多一个"提示层"**(hint layer),通过线性变换与教师的某个中间层对齐。

**架构**:

```
教师: [输入] → [Conv1] → [Conv2] → [Conv3] → [Logits]
                                ↓ (教师引导层)
学生: [输入] → [Conv1'] → [Conv2'](guided) → [Logits']
                                            ↑ (学生引导层)
```

```python
class FitNetDistillation(torch.nn.Module):
    """FitNet: Feature 蒸馏"""
    def __init__(self, teacher, student, teacher_hidden_dim, student_hidden_dim):
        super().__init__()
        self.teacher = teacher
        self.student = student
        # 学生的"引导层",把学生 hidden 映射到教师 hidden 的同维度
        self.hint_layer = torch.nn.Linear(student_hidden_dim, teacher_hidden_dim)
    
    def forward(self, x, labels):
        # 教师前向(冻结)
        with torch.no_grad():
            teacher_hidden, teacher_logits = self.teacher.get_intermediate(x)
        # 学生前向
        student_hidden, student_logits = self.student.get_intermediate(x)
        # Feature 蒸馏:对齐中间层
        hint = self.hint_layer(student_hidden)
        feature_loss = F.mse_loss(hint, teacher_hidden)
        # Logit 蒸馏(可选)
        logit_loss = F.mse_loss(student_logits, teacher_logits)
        # 硬损失
        hard_loss = F.cross_entropy(student_logits, labels)
        return feature_loss + logit_loss + hard_loss
```

### 3.3 在搜推广的 Feature 蒸馏

**典型场景**: 教师 DIN → 学生 DNN

```python
class DINToDNNDistillation(nn.Module):
    """DIN 教师蒸馏到 DNN 学生(中间层对齐)"""
    def __init__(self, teacher_din, student_dnn):
        super().__init__()
        self.teacher = teacher_din
        self.student = student_dnn
        # DIN 中间层维度 vs DNN 中间层维度
        # DNN 学生 hidden=64, DIN 教师 hidden=256
        # 用线性投影对齐
        self.align = nn.Linear(64, 256)
    
    def forward(self, user_features, item_features, user_history, labels):
        # 教师前向
        with torch.no_grad():
            teacher_attention, teacher_logits = self.teacher(
                user_features, item_features, user_history
            )  # teacher_attention: [B, hidden_T]
        
        # 学生前向
        student_emb, student_logits = self.student(user_features, item_features)
        # student_emb: [B, hidden_S]
        
        # Feature 蒸馏:对齐
        student_aligned = self.align(student_emb)  # [B, hidden_T]
        feature_loss = F.mse_loss(student_aligned, teacher_attention)
        
        # Logit 蒸馏
        logit_loss = F.mse_loss(student_logits, teacher_logits)
        
        # 硬损失
        hard_loss = F.binary_cross_entropy_with_logits(student_logits, labels.float())
        
        return hard_loss + 0.5 * feature_loss + 0.3 * logit_loss
```

## 4. Relation 蒸馏:CRD 与关系矩阵对齐

**文字**: Logit 和 Feature 蒸馏都只关心'单个样本的预测',但推荐系统的核心是'用户 vs 物品'的相对关系,**用户 A 和用户 B 在教师空间里都偏好数码产品,学生在自己的空间里也应该体现这个相似性**。CRD 2020 把这种'关系结构'显式蒸馏:用对比学习构造 [B,B] 相似度矩阵,让学生矩阵逼近教师矩阵,而不是让学生单点特征逼近教师单点特征。**为什么有效?推荐是排序问题,AUC 看的是相对顺序**;教师即便单点预测有偏,只要关系结构对,学生继承后排序能力就保住了。OneRec 在兴趣分布层做关系蒸馏,把'用户兴趣形状'作为监督信号,比单纯对齐 user embedding 效果好 1~2 个 AUC 点。

### 4.1 关系蒸馏的思想

**更进一步**: 不只对齐"特征值",还对齐**样本之间的关系**。

**核心洞察**: 教师模型的"知识"不只是单个样本的预测,还体现在**样本之间的关系**:
- 样本 A 和 B 在教师空间里**相似**,学生在自己的空间里也应该相似
- 样本 A 和 C 在教师空间里**不相似**,学生也应该不相似

### 4.2 CRD(Contrastive Representation Distillation, Tian 2020)

**核心思想**: 用**对比学习**对齐学生和教师的"关系矩阵"。

```python
class CRDLoss(torch.nn.Module):
    """Contrastive Representation Distillation"""
    def __init__(self, temperature=0.07):
        super().__init__()
        self.T = temperature
    
    def forward(self, student_features, teacher_features):
        """
        student_features: [B, D]
        teacher_features: [B, D]
        """
        # 归一化
        s = F.normalize(student_features, dim=-1)
        t = F.normalize(teacher_features, dim=-1)
        # 相似度矩阵
        sim_s = s @ s.T / self.T     # [B, B] 学生内样本相似度
        sim_t = t @ t.T / self.T     # [B, B] 教师内样本相似度
        # 对齐:让学生的相似度矩阵 ≈ 教师的
        # 用 KL 散度
        loss = F.kl_div(
            F.log_softmax(sim_s, dim=-1),
            F.softmax(sim_t, dim=-1),
            reduction='batchmean'
        )
        return loss
```

### 4.3 推荐系统中的关系蒸馏

**思想**: 用户的兴趣分布"形状"应该被蒸馏。

```python
class InterestDistributionDistill(nn.Module):
    """兴趣分布蒸馏: 用户的兴趣分布应该被模仿"""
    def __init__(self, num_topics, temperature=0.1):
        super().__init__()
        self.T = temperature
    
    def forward(self, student_interest_dist, teacher_interest_dist):
        """
        student_interest_dist: [B, num_topics] 用户在每个 topic 的兴趣概率
        teacher_interest_dist: [B, num_topics]
        """
        # KL 散度
        return F.kl_div(
            F.log_softmax(student_interest_dist / self.T, dim=-1),
            F.softmax(teacher_interest_dist / self.T, dim=-1),
            reduction='batchmean'
        ) * (self.T ** 2)
```

## 5. 搜推广的蒸馏:TIGER / OneRec / 跨模态

**文字**: 推荐系统是蒸馏技术的'主战场',根本原因是**推理时延是搜推广最硬的 KPI**,召回 10ms、粗排 20ms、精排 50ms 是不成文的工业线。一个 7B 参数的 LLaMA 教师精排模型 AUC 能到 0.78,直接上线 P99 超过 200ms,无法满足业务。**TIGER/OneRec 等生成式推荐更是如此:教师是 T5-XXL(11B),学生必须压到 T5-Small(60M)以内才能在 30ms 内出分**。蒸馏的另一个隐性收益是'特征工程去依赖':教师用 1000 个交叉特征、学生用 200 个,通过蒸馏让学生的简化特征学会教师的复杂决策边界,这是手工调特征做不到的。**搜推广数据规模大(亿级样本)、分布稳定,蒸馏的偏差-方差权衡更适合大教师学结构、小学生学推理**。

### 5.1 TIGER 的 RQ-VAE 蒸馏

**文字**: 为什么生成式推荐特别需要蒸馏?因为**GenRec 的教师-学生体量差异比判别式更大**。判别式精排里,7B 教师蒸馏到 0.5B 学生,容量比 14×;但在 GenRec 里,**教师 T5-XXL(11B)对每个物品序列都要做完整 200+ 步自回归生成,推理本身就是 O(L²) 注意力计算**,10ms 延迟根本压不下来。**TIGER 选择 T5-Small(60M)作为学生**就是被迫的——学生参数必须降到 1/180 才能在 30ms 内出分。**TIGER 蒸馏还多了一层 RQ-VAE 的"语义 ID 化"**——把物品的连续 Embedding 量化成 4-8 个 code,教师先在 code 空间上做下一 token 预测,学生再蒸馏这个**已经压缩的离散分布**。**为什么非要 RQ-VAE 一步?因为连续 Embedding 的 vocabulary 太大(百万级),自回归生成时 softmax 计算 O(V) 在 GPU 上慢;量化到 256 的 code book 后,softmax 只在 256 上算,推理加速 50-100 倍**。

**TIGER (Google 2023)** 用 RQ-VAE 把物品编码为"语义 ID",然后用 T5 蒸馏。

**蒸馏过程**:
1. 训练 RQ-VAE,得到物品的离散 ID 序列
2. 训练大教师模型(T5-XXL)在 ID 序列上做下一 token 预测
3. 用教师预测的 logits 蒸馏小学生(T5-Small)

```python
# TIGER 蒸馏
def tiger_distill(student_model, teacher_model, dataloader, T=4.0):
    optimizer = torch.optim.AdamW(student_model.parameters(), lr=1e-4)
    for batch in dataloader:
        # 学生:输入 ID 序列,预测下一个 ID
        student_logits = student_model(input_ids=batch['input_ids'])
        # 教师(冻结)
        with torch.no_grad():
            teacher_logits = teacher_model(input_ids=batch['input_ids'])
        # 蒸馏
        loss = kd_loss(student_logits, teacher_logits, batch['labels'], T=T)
        optimizer.zero_grad()
        loss.backward()
        optimizer.step()
```

### 5.2 OneRec 的多层级蒸馏

**文字**: 为什么 OneRec 要"训三次蒸馏两次"?(1) 第一次: 10B 教师直接蒸馏到 0.5B 学生时,容量比 20× 太大,容易出现 **capacity gap**——学生根本学不到教师的复杂决策。**所以中间插一个 1.5B 的"助教"(TAKD, Teacher Assistant KD)**,先把教师容量压到 1.5B,再从 1.5B 蒸馏到 0.5B。**这种"阶梯式蒸馏"在工业界已是标准操作**——Meta 的 Llama 3、字节的 OneRec、阿里 Qwen 蒸馏都用了这个范式。(2) 第二次: 1.5B 学生到 0.5B 学生的蒸馏,温度和 α 都用更小的($\alpha$=0.5 而非 0.7),因为此时学生已经"很像"教师,再大的 α 会引入教师的过拟合噪声。

**OneRec (快手 2025)** 是端到端生成式推荐,**蒸馏教师 → 学生 → 蒸馏 → 部署**。

### 5.3 跨模态蒸馏

**CLIP 风格的图文对齐蒸馏**:用 CLIP 蒸馏推荐。

```python
class CrossModalDistillation(nn.Module):
    """图文 → 物品 ID 的跨模态蒸馏"""
    def __init__(self, clip_model, item_encoder):
        super().__init__()
        self.clip = clip_model
        self.item_encoder = item_encoder
    
    def forward(self, image_emb, text_emb, item_emb):
        # CLIP 给的图文相似度作为教师信号
        clip_sim = self.clip(image_emb, text_emb)  # [B, B]
        # 学生物品 Embedding 之间的相似度
        item_sim = self.item_encoder(item_emb)  # [B, B]

        return F.mse_loss(item_sim, clip_sim.detach())
```

## 6. 工业实践:温度、权重、调度

**文字**: 工业蒸馏最容易踩的坑是'温度照搬论文'。Hinton 原论文用 T=4 是 ImageNet 场景,搜推广的标签稀疏(CTR 普遍 < 5%)、负样本占绝大多数,**T 太大会让教师把几乎所有负类压成接近均匀,学生学不到正负差异**。经验曲线是:CTR > 10% 召回用 T=2~3,精排用 T=3~4;CTR < 2% 长尾场景用 T=1.5~2.5。**蒸馏权重 $\alpha$ 的调度更关键:学生冷启动时 random init 的特征噪声很大,如果一开始就用 $\alpha$=0.7,教师的'软知识'会放大这些噪声,导致学生学偏**。工业标准做法是前 1000~5000 step 线性 warmup $\alpha$ 从 0 到目标值,先让硬损失把骨架立起来,再让软损失填细节。**另一个高频踩坑是教师更新了**,KD 训练时教师必须冻结,评估阶段也用冻结教师,否则就是学生自己教自己,蒸馏失效。

### 6.1 温度 T 的搜索

### 6.2 蒸馏权重的渐进调度

```python
class ProgressiveDistillWeight:
    """蒸馏权重从 0 渐进到目标值(避免学生初期被教师误导)"""
    def __init__(self, target_alpha=0.7, warmup_steps=1000):
        self.target = target_alpha
        self.warmup = warmup_steps
        self.step = 0
    
    def get_alpha(self):
        if self.step < self.warmup:
            return self.target * (self.step / self.warmup)
        return self.target
    
    def step_count(self):
        self.step += 1
```

**理由**: 学生初期**还没学会硬标签**,直接蒸馏教师的"软知识"会让**学生学不到基础**。先**只学硬标签** → 慢慢引入蒸馏。

### 6.3 多教师蒸馏(Multi-Teacher KD)

**场景**: 不同教师擅长不同方面,可以综合多个教师。

```python
class MultiTeacherDistillation(nn.Module):
    """多教师蒸馏:每个教师权重不同"""
    def __init__(self, teachers, weights, student):
        super().__init__()
        self.teachers = teachers     # [teacher_1, teacher_2, ...]
        self.weights = weights        # [w_1, w_2, ...], sum = 1
        self.student = student
    
    def forward(self, x, labels):
        # 所有教师推理(冻结)
        with torch.no_grad():
            teacher_logits = sum(
                w * t(x) for w, t in zip(self.weights, self.teachers)
            )
        # 学生
        student_logits = self.student(x)
        # 蒸馏到"加权教师的预测"
        return F.kl_div(
            F.log_softmax(student_logits, dim=-1),
            F.softmax(teacher_logits, dim=-1),
            reduction='batchmean'
        )
```

### 6.4 自蒸馏(Self-Distillation)

**思想**: 不需要外部教师,**学生自己当自己的教师**——用 EMA 权重或早期 checkpoint 当教师。

```python
class SelfDistillation:
    """自蒸馏:用 EMA 模型当教师"""
    def __init__(self, model, ema_decay=0.999):
        self.model = model
        self.ema_model = copy.deepcopy(model)
        for p in self.ema_model.parameters():
            p.requires_grad_(False)
        self.decay = ema_decay
    
    def update_ema(self):
        """每个 step 后用 model 的 EMA 更新 ema_model"""
        with torch.no_grad():
            for p_ema, p in zip(self.ema_model.parameters(), self.model.parameters()):
                p_ema.data = self.decay * p_ema.data + (1 - self.decay) * p.data
    
    def distill_step(self, x, labels):
        # EMA 模型当教师
        with torch.no_grad():
            teacher_logits = self.ema_model(x)
        # 学生
        student_logits = self.model(x)
        # 蒸馏
        return F.kl_div(
            F.log_softmax(student_logits, dim=-1),
            F.softmax(teacher_logits, dim=-1),
            reduction='batchmean'
        )
```

**优势**: 不需要训两个模型,免费获得"正则化效果"(类似 EMA, 但更明确地传递知识)。

## 19.7 Decoupled Knowledge Distillation (DKD)

### 19.7.1 动机: 为什么把 KD 拆开?

经典 KD 把全部 logits 当成一个分布蒸馏,但两类信号性质不同:

| 信号 | 含义 | 物理意义 |
| :--- | :--- | :--- |
| **Target class** 概率 $b_t$ | 教师"答对哪一类" | 硬知识 / 判断力 |
| **Non-target** 概率分布 $\hat{b}_i$ | 教师"为何选 t 而非 i" | 暗知识 / 类间相似度 |

原始 KD 把两者绑在同一个温度 T 上,无法独立调节。DKD (CVPR 2022, Zhao et al.) 将两者解耦:

$$L_{DKD} = \alpha \cdot L_{TCKD} + \beta \cdot L_{NCKD}$$

- **TCKD** (Target Class KD): 只蒸馏 $b_t$ vs $s_t$ — 衡量教师多"确定"答案
- **NCKD** (Non-target Class KD): 蒸馏剩下 N−1 类的相对关系 — 携带类间结构

### 19.7.2 形式化推导

设教师概率 $b_i = \frac{\exp(z_i/T)}{\sum_j \exp(z_j/T)}$,目标类为 $t$。定义:

$$b_t = b_t, \quad \hat{b} = \sum_{i \neq t} b_i = 1 - b_t, \quad \hat{b}_i = \frac{b_i}{1 - b_t} \;\; (i \neq t)$$

两个标量概率的 KL(二元):

$$L_{TCKD} = KL\big(b_t \,\|\, s_t\big) = b_t \log\frac{b_t}{s_t} + (1-b_t)\log\frac{1-b_t}{1-s_t}$$

非目标类分布的 KL:

$$L_{NCKD} = \sum_{i \neq t} \hat{b}_i \log\frac{\hat{b}_i}{\hat{s}_i}$$

### 19.7.3 PyTorch 实现 (可直接训练)

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


def dkd_loss(logits_s, logits_t, target, alpha=1.0, beta=8.0, T=4.0):
    """
    DKD Loss (CVPR 2022).  logits_s/t: [B, N],  target: [B]
    """
    p_s = F.softmax(logits_s / T, dim=1)
    p_t = F.softmax(logits_t / T, dim=1)
    B, N = p_s.shape

    # 1) 提取 target class 概率
    pt_s = p_s.gather(1, target.unsqueeze(1)).squeeze(1)   # [B]
    pt_t = p_t.gather(1, target.unsqueeze(1)).squeeze(1)   # [B]

    # 2) 屏蔽 target 后归一化
    mask = torch.ones_like(p_s).scatter_(1, target.unsqueeze(1), 0)
    p_s_nt = p_s * mask
    p_t_nt = p_t * mask
    p_s_nt = p_s_nt / (p_s_nt.sum(dim=1, keepdim=True) + 1e-8)
    p_t_nt = p_t_nt / (p_t_nt.sum(dim=1, keepdim=True) + 1e-8)

    # 3) TCKD: 目标类的二元 KL (BCE 等价)
    tckd = (
        F.kl_div(torch.log(pt_s + 1e-8),     pt_t,     reduction='batchmean') +
        F.kl_div(torch.log(1 - pt_s + 1e-8), 1 - pt_t, reduction='batchmean')
    )

    # 4) NCKD: 非目标分布 KL
    nckd = F.kl_div(torch.log(p_s_nt + 1e-8), p_t_nt, reduction='batchmean')

    return (alpha * tckd + beta * nckd) * (T * T), tckd, nckd


class RecSys(nn.Module):
    """极简双塔精排模型,演示 DKD 用法"""
    def __init__(self, num_items, dim=64):
        super().__init__()
        self.embed = nn.Embedding(num_items, dim)
        self.fc = nn.Linear(dim, num_items)

    def forward(self, user_ids):
        u = self.embed(user_ids)
        u = u.mean(dim=1) if u.dim() == 3 else u   # [B, dim]
        return self.fc(u)


if __name__ == "__main__":
    torch.manual_seed(0)
    num_items, num_users, dim = 1000, 256, 64
    teacher = RecSys(num_items, dim).eval()
    student = RecSys(num_items, dim)

    user   = torch.randint(0, num_users, (32, 5))  # [B, seq]
    target = torch.randint(0, num_items, (32,))

    s_logits = student(user)
    t_logits = teacher(user).detach()

    loss_ce = F.cross_entropy(s_logits, target)
    loss_dkd, tckd, nckd = dkd_loss(s_logits, t_logits, target,
                                    alpha=1.0, beta=8.0, T=4.0)
    total = loss_ce + loss_dkd

    print(f"CE={loss_ce.item():.3f} | DKD={loss_dkd.item():.3f}  "
          f"(TCKD={tckd.item():.3f}, NCKD={nckd.item():.3f})")
    total.backward()     # 学生可正常反向传播
```

### 19.7.4 超参经验

| 场景 | α (TCKD) | β (NCKD) | T |
| :--- | :--- | :--- | :--- |
| CIFAR-100 (原论文) | 1.0 | 8.0 | 4 |
| ImageNet | 1.0 | 8.0 | 4 |
| 推荐 CTR 精排 | 0.5–1.0 | 4.0–8.0 | 2–4 |
| 召回 (N 极大) | — | — | 不推荐 |

> 长尾分布下 non-target 极度稀疏,适当提高 β 放大"暗知识"信号。

### 19.7.5 与经典 KD 的差异

| 维度 | KD | DKD |
| :--- | :--- | :--- |
| 蒸馏粒度 | 整分布 | target / non-target 解耦 |
| 温度作用 | 同时平滑两边 | 仅影响概率锐度 |
| 类间结构 | 易被 top-1 淹没 | NCKD 显式传递 |
| 长尾类收益 | 低 | 高 (β 独立放大) |
| 灵活度 | T, α 两参 | T, α, β 三参 |

### 19.7.6 推荐场景落地要点

1. **精排适用,召回慎用**: N 过大时 $\hat{b}_i$ 几乎全 0,NCKD 退化为均匀分布
2. **与 feature 蒸馏正交**: DKD(logit) + FitNet/CRD(feature) 并用,recall 提升 +1~3%
3. **温度 T 与 β 联动**: 长尾数据先把 T 调到 4 让分布平滑,再调 β

### 19.7.7 一句话总结

> DKD 把"会不会答" (TCKD) 和"为什么选这个" (NCKD) 分开蒸馏,在类间关系丰富的精排场景下,几乎零成本地把 KD 效果再推一个台阶。

## 19.8 蒸馏在生成式推荐中的 4 种 self-distillation 范式

**为什么 GR 的蒸馏和判别式推荐不一样?**

判别式推荐(DIN/DCN)的蒸馏很简单——**对齐 logits 或特征向量**。但 GenRec 是"自回归生成下一个 item token",蒸馏目标不是单一标量 logits,而是**整个生成序列的策略分布**。这带来三个新挑战:

1. **序列级一致性**:教师在第 1 步生成的 token,会影响后续所有步的分布。**蒸馏时必须考虑序列级联合分布**,不能只对齐单步 logits
2. **exposure bias**:学生模型可能生成教师"没见过"的 token 序列,这时 KL 散度无意义。需要用 **on-policy**(学生在自己的分布上采样)来对齐
3. **生成多样性 vs 准确性**:Forward KL(moda-covering)让学生学教师的"全部模式",容易产生幻觉;Reverse KL(mode-seeking)让学生只学最可能的模式,生成更稳定

下面展开 4 种主流 self-distillation 范式,以及它们在 GR 中的取舍。

### 19.8.1 4 种范式对比

| 范式 | 蒸馏对象 | 损失函数 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- | :--- |
| **Logit KD** (Hinton 2015) | Teacher 输出的 softmax(logits/T) | `KL(p_T || p_S)` | 简单稳定 | 只看最后一步,忽略中间层 |
| **Feature KD** (FitNets) | Teacher 隐层 h_T | `MSE(h_T, h_S)` | 利用中间表征 | 维度匹配困难,需要映射层 |
| **MiniLLM** (2023) | 整序列生成的策略 | Reverse KL `KL(p_S || p_T)` | 学生模式覆盖小,生成更稳定 | 训练慢,需要 RL loop |
| **GKD** (2023, Generalized KD) | Teacher 在输入数据上重生成的序列 | `KL` + 学生自己采样 | 解决 exposure bias | 多次采样,显存翻倍 |

### 19.8.2 MiniLLM 的数学原理

MiniLLM 的核心是用 **policy gradient + reverse KL** 来做序列级蒸馏:

$$\mathcal{L}_{\text{MiniLLM}} = -\mathbb{E}_{y \sim p_S}\left[ r_\theta(y) \cdot \log p_S(y) \right]$$

其中奖励 $r_\theta(y) = \log \frac{p_T(y|x)}{p_S(y|x)}$ 是 teacher 和 student 之间的对数似然比,这就是经典的 RLHF 形式。

为什么用 reverse KL(学生分布逼近教师)而不是 forward KL(教师逼近学生)?

- Forward KL (`KL(p_T || p_S)`):mode-covering,学生学到教师所有模式,容易"胡说"
- **Reverse KL** (`KL(p_S || p_T)`):**mode-seeking**,学生只学最可能的模式,生成更稳定

### 19.8.3 DKD (Decoupled Knowledge Distillation) 在 GR 中的应用

DKD 把 KD loss 拆成两部分:

$$\mathcal{L}_{\text{DKD}} = \alpha \cdot \mathcal{L}_{\text{TCKD}} + \beta \cdot \mathcal{L}_{\text{NCKD}}$$

- **TCKD (Target Class KD)**:正样本与负样本 logit 的关系
- **NCKD (Non-target Class KD)**:负样本之间的关系(在 GR 中相当于"这个 S-ID 比其他 S-ID 更像负样本")

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class DKDLoss(nn.Module):
    """
    DKD (Decoupled Knowledge Distillation) for Generative Recommendation.
    Reference: CVPR 2022 - Decoupled Knowledge Distillation
    """
    def __init__(self, alpha=1.0, beta=8.0, temperature=4.0):
        super().__init__()
        self.alpha = alpha  # TCKD 权重
        self.beta = beta    # NCKD 权重 (在 GR 中这个更重要!)
        self.T = temperature
    
    def forward(self, student_logits, teacher_logits, target):
        """
        student_logits: [B, V] 学生模型在词表上的预测
        teacher_logits: [B, V] 教师模型在词表上的预测
        target:         [B]    ground-truth S-ID 序列
        """
        # 标准 softmax with temperature
        p_s = F.log_softmax(student_logits / self.T, dim=-1)
        p_t = F.softmax(teacher_logits / self.T, dim=-1)
        
        # ===== TCKD: Target Class KD =====
        # 把正样本的概率单独处理
        p_s_target = p_s.gather(1, target.unsqueeze(1))  # [B, 1]
        p_t_target = p_t.gather(1, target.unsqueeze(1))  # [B, 1]
        
        tckd = F.kl_div(p_s_target, p_t_target, reduction='batchmean') * (self.T ** 2)
        
        # ===== NCKD: Non-target Class KD =====
        # 把负样本之间的相对关系蒸馏
        # 用 mask 把 target 位置 mask 掉
        mask = torch.ones_like(p_s).scatter_(1, target.unsqueeze(1), 0)
        
        # 在负样本维度重新归一化
        neg_s = (p_s * mask) / (p_s * mask).sum(dim=-1, keepdim=True).clamp(min=1e-8)
        neg_t = (p_t * mask) / (p_t * mask).sum(dim=-1, keepdim=True).clamp(min=1e-8)
        
        nckd = F.kl_div(neg_s, neg_t, reduction='batchmean') * (self.T ** 2)
        
        loss = self.alpha * tckd + self.beta * nckd
        return loss


# ===== 在 GR 训练中的使用 =====
def train_step_gr_dkd(student_model, teacher_model, batch, dkd_loss_fn, optimizer):
    """
    一次训练 step:用教师模型蒸馏学生模型。
    """
    # Teacher 推理 (no grad)
    with torch.no_grad():
        teacher_logits = teacher_model(batch['input_ids'])  # [B, L, V]
    
    # Student 推理
    student_logits = student_model(batch['input_ids'])  # [B, L, V]
    
    # Reshape for loss: [B*L, V]
    B, L, V = student_logits.shape
    student_logits = student_logits.view(-1, V)
    teacher_logits = teacher_logits.view(-1, V)
    target = batch['labels'].view(-1)
    
    # 过滤 padding 位置
    mask = target != 0  # 假设 padding_idx=0
    student_logits = student_logits[mask]
    teacher_logits = teacher_logits[mask]
    target = target[mask]
    
    # DKD Loss
    loss = dkd_loss_fn(student_logits, teacher_logits, target)
    
    # Backward
    optimizer.zero_grad()
    loss.backward()
    torch.nn.utils.clip_grad_norm_(student_model.parameters(), 1.0)
    optimizer.step()
    
    return loss.item()


# ===== 完整示例:在 TIGER 上的 DKD 蒸馏 =====
if __name__ == "__main__":
    # 模拟数据
    B, L, V = 32, 50, 1024  # batch=32, seq_len=50, vocab=1024 个 S-ID
    
    # 模拟教师/学生模型
    teacher = nn.Linear(64, V)  # 假设 hidden=64
    student = nn.Linear(64, V)
    
    # 构造 batch
    batch = {
        'input_ids': torch.randint(0, V, (B, L)),
        'labels':    torch.randint(0, V, (B, L)),
    }
    
    dkd = DKDLoss(alpha=1.0, beta=8.0, temperature=4.0)
    optimizer = torch.optim.AdamW(student.parameters(), lr=1e-4)
    
    # 训练 5 步
    for step in range(5):
        loss = train_step_gr_dkd(student, teacher, batch, dkd, optimizer)
        print(f"Step {step}, DKD Loss = {loss:.4f}")
```

### 19.8.4 蒸馏 8 大常见失败模式(GR 专属)

| 失败模式 | 症状 | 原因 | 解决方案 |
| :--- | :--- | :--- | :--- |
| 1. **Capacity Gap** | 学生 Loss 不下降 | 教师太强学生太弱 | 先用助教(TAKD)蒸馏 |
| 2. **Mode Collapse** | 学生只生成单一 S-ID | Forward KL 反向 | 改 Reverse KL (MiniLLM) |
| 3. **Exposure Bias** | 离线好线上差 | Teacher on gold, Student on self | 用 GKD 让学生自己采样 |
| 4. **Label Noise** | 蒸馏后指标反而降 | 教师本身有错(7B 仍有错) | 蒸馏前先 evaluate 教师 |
| 5. **Token Bias** | 某些 S-ID 总被错 | 词表长尾不均 | 加 class-balanced reweighting |
| 6. **长度偏差** | 学生生成太短/太长 | S-ID 序列长度分布偏移 | 加 length penalty loss |
| 7. **OOV 问题** | 学生词表小,有的 ID 没学 | 学生词表是教师子集 | 共享 embedding + freeze |
| 8. **训练崩溃** | 蒸馏到一半 Loss = NaN | 学生 LR 太大 + 教师 logits 大 | 降低 LR,加 temperature |

## 19.9 蒸馏的稳定性与失败模式(GR 专属)

### 19.9.1 三大经典失败模式

蒸馏在 GR 中比传统 CV/NLP 中更容易"翻车",因为推荐数据是**长尾稀疏**的。

**失败 1:灾难性遗忘(Catastrophic Forgetting)**

学生模型在拟合教师软标签时,**会忘记**自己原本的硬标签预测能力。

- **症状**:学生 AUC 在验证集上短期涨(对齐教师),但 3 天后回到 baseline,甚至更低
- **根因**:KL 散度 loss 与 CE loss 的梯度方向不一致
- **解决方案**:加 **anchor loss**(也叫 self-distillation,用学生自己的输出当 anchor)

```python
class AntiForgettingKD(nn.Module):
    def __init__(self, alpha_kd=0.7, alpha_anchor=0.2, alpha_ce=0.1, T=4.0):
        super().__init__()
        self.alpha_kd = alpha_kd
        self.alpha_anchor = alpha_anchor
        self.alpha_ce = alpha_ce
        self.T = T
    
    def forward(self, student_logits, teacher_logits, labels):
        # 1. 标准 KD loss
        kd = F.kl_div(
            F.log_softmax(student_logits / self.T, dim=-1),
            F.softmax(teacher_logits / self.T, dim=-1),
            reduction='batchmean',
        ) * (self.T ** 2)
        
        # 2. Anchor loss: 学生 vs 自己(蒸馏前的版本)
        with torch.no_grad():
            anchor_probs = F.softmax(student_logits.detach() / self.T, dim=-1)
        anchor = F.kl_div(
            F.log_softmax(student_logits / self.T, dim=-1),
            anchor_probs,
            reduction='batchmean',
        ) * (self.T ** 2)
        
        # 3. CE loss(硬标签)
        ce = F.cross_entropy(student_logits, labels)
        
        return self.alpha_kd * kd + self.alpha_anchor * anchor + self.alpha_ce * ce
```

**失败 2:教师能力差距(Teacher Capacity Gap)**

教师太"强",学生学不来——**学生学到的不是"软知识",而是"软噪声"**。

- **症状**:温度 T 越大,学生表现越差(违反常识——温度大应该更平滑更好)
- **根因**:教师的 logits 在 T 很大时变成"软噪声",学生拟合这些噪声
- **解决方案**:**Early-stop 教师**或**多教师 ensemble**

```python
class MultiTeacherKD(nn.Module):
    """用多个"中等能力"教师代替一个"超能力"教师."""
    def __init__(self, teachers, T=4.0, weights=None):
        super().__init__()
        self.teachers = nn.ModuleList(teachers)
        self.T = T
        self.weights = weights or [1.0 / len(teachers)] * len(teachers)
    
    def forward(self, student_logits, batch):
        kd_total = 0
        for teacher, w in zip(self.teachers, self.weights):
            with torch.no_grad():
                t_logits = teacher(batch)
            kd = F.kl_div(
                F.log_softmax(student_logits / self.T, dim=-1),
                F.softmax(t_logits / self.T, dim=-1),
                reduction='batchmean',
            ) * (self.T ** 2)
            kd_total += w * kd
        return kd_total
```

**失败 3:Reward Hacking(GR 专属)**

GR 中"模仿教师"可能导致学生学到**教师在曝光偏差下的偏好**而非真实兴趣。

- **症状**:学生推荐的内容 CTR 短期高,但 用户长期 LTV 下降
- **根因**:教师被训练来预测"曝光后点击",学生把"曝光"误学为"应该推荐"
- **解决方案**:**IPS 加权 + 反事实蒸馏**

```python
class IPSWeightedKD(nn.Module):
    """用 IPS 校正教师 logit,消除曝光偏差."""
    def __init__(self, propensity_estimator, T=4.0):
        super().__init__()
        self.propensity = propensity_estimator  # 预训练的 IPS 模型
        self.T = T
    
    def forward(self, student_logits, teacher_logits, items, labels):
        # 1. 计算每个 item 的曝光概率(IPS)
        propensities = self.propensity(items)  # [B]
        ips_weights = 1.0 / (propensities + 1e-6)  # 高 IPS 权重 = 低曝光概率
        
        # 2. IPS 加权 KD
        kd_per_sample = F.kl_div(
            F.log_softmax(student_logits / self.T, dim=-1),
            F.softmax(teacher_logits / self.T, dim=-1),
            reduction='none',
        ).sum(dim=-1)  # [B]
        kd = (kd_per_sample * ips_weights).mean() * (self.T ** 2)
        
        # 3. 标准 CE
        ce = F.cross_entropy(student_logits, labels)
        return kd + ce
```

### 19.9.2 蒸馏失败的 5 大诊断信号

| 信号 | 可能原因 | 排查方法 |
| :--- | :--- | :--- |
| 学生 AUC 涨,学生 ECE(校准误差)也涨 | 软标签过拟合 | 降温度 T 至 1-2 |
| 学生 AUC 涨,线上 AUC 跌 | 曝光偏差被放大 | 加 IPS 加权 |
| 训练 loss 降,验证 loss 升 | 灾难性遗忘 | 加 anchor loss |
| 学生多样性(ILAD)暴跌 | 教师太单调 | 多教师 ensemble |
| 学生对长尾 item 推荐率骤降 | 头部偏置放大 | 加 popularity regularization |

## 19.10 LoRA / QLoRA 蒸馏(GR 中的高效微调范式)

### 19.10.1 为什么 GR 需要 LoRA 蒸馏?

传统 KD 需要**全参数**学生 + 全参数教师。在 GR 场景:
- 教师(7B LLM)内存 14GB(FP16)
- 学生(0.5B)内存 1GB
- 蒸馏时教师 forward/backward → 学生端要**全参数更新** → 显存爆炸

**LoRA 蒸馏**:
- 教师:冻结(7B,14GB)
- 学生:冻结 backbone + LoRA(0.5B + 几 MB LoRA)
- 只更新 LoRA 参数 → 显存从 30GB 降到 8GB

### 19.10.2 LoRA-KD 完整实现

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from peft import LoraConfig, get_peft_model


class LoRAStudentKD(nn.Module):
    """学生 backbone 冻结,只训练 LoRA 适配器."""
    
    def __init__(self, student_backbone, teacher_model, lora_r=8, lora_alpha=16, T=4.0):
        super().__init__()
        # 1. 冻结学生 backbone
        for p in student_backbone.parameters():
            p.requires_grad = False
        
        # 2. 加 LoRA 适配器
        lora_config = LoraConfig(
            r=lora_r,
            lora_alpha=lora_alpha,
            target_modules=["q_proj", "v_proj"],  # 只 LoRA Q/V projection
            lora_dropout=0.05,
            bias="none",
        )
        self.student = get_peft_model(student_backbone, lora_config)
        # 统计可训练参数
        self.student.print_trainable_parameters()
        
        # 3. 冻结教师
        self.teacher = teacher_model
        for p in self.teacher.parameters():
            p.requires_grad = False
        self.teacher.eval()
        
        self.T = T
    
    def forward(self, input_ids, labels=None):
        # 学生 forward(只更新 LoRA)
        s_logits = self.student(input_ids).logits
        
        # 教师 forward(完全冻结)
        with torch.no_grad():
            t_logits = self.teacher(input_ids).logits
        
        # KD loss
        kd = F.kl_div(
            F.log_softmax(s_logits / self.T, dim=-1),
            F.softmax(t_logits / self.T, dim=-1),
            reduction='batchmean',
        ) * (self.T ** 2)
        
        # CE loss(可选,如果 labels 提供)
        loss = kd
        if labels is not None:
            ce = F.cross_entropy(s_logits.view(-1, s_logits.size(-1)), labels.view(-1))
            loss = 0.7 * kd + 0.3 * ce
        
        return loss
```

| LoRA-KD | 8GB | 0.85x | 96-98% |

## 19.11 多模态蒸馏(图文/视频/音频)

### 19.11.1 推荐中的多模态

现代推荐系统已经不止"标题+封面":
- **图文**:小红书、Pinterest
- **视频**:抖音、TikTok
- **音频**:音乐播客(Spotify)
- **3D 模型**:AR/VR 购物

多模态蒸馏的难点:**不同模态的特征空间不对齐**(图像 ∈ R^d_img,文本 ∈ R^d_text,音频 ∈ R^d_audio)。

### 19.11.2 CLIP 风格对齐蒸馏

```python
class MultimodalKD(nn.Module):
    """CLIP 风格:把不同模态映射到统一 embedding 空间."""
    def __init__(self, image_enc, text_enc, audio_enc, proj_dim=512):
        super().__init__()
        self.image_enc = image_enc
        self.text_enc = text_enc
        self.audio_enc = audio_enc
        
        # 投影层
        self.img_proj = nn.Linear(image_enc.dim, proj_dim)
        self.txt_proj = nn.Linear(text_enc.dim, proj_dim)
        self.audio_proj = nn.Linear(audio_enc.dim, proj_dim)
    
    def info_nce_loss(self, z_a, z_b, T=0.07):
        """对称 InfoNCE,CLIP 标配."""
        z_a = F.normalize(z_a, dim=-1)
        z_b = F.normalize(z_b, dim=-1)
        logits = (z_a @ z_b.T) / T
        labels = torch.arange(z_a.size(0), device=z_a.device)
        return 0.5 * (F.cross_entropy(logits, labels) + F.cross_entropy(logits.T, labels))
    
    def forward(self, images, texts, audios):
        # 多模态编码
        z_img = self.img_proj(self.image_enc(images))
        z_txt = self.txt_proj(self.text_enc(texts))
        z_aud = self.audio_proj(self.audio_enc(audios))
        
        # 三个 InfoNCE loss(全配对)
        loss = (
            self.info_nce_loss(z_img, z_txt) +
            self.info_nce_loss(z_img, z_aud) +
            self.info_nce_loss(z_txt, z_aud)
        ) / 3
        
        return loss
```

```
└─────┬────┘    └─────┬────┘    └─────┬────┘

      └───────────────┴───────────────┘
```

## 19.12 评估蒸馏效果:从离线到在线

### 19.12.1 离线评估指标

| 指标 | 公式 | 含义 | 推荐阈值 |
| :--- | :--- | :--- | :--- |
| **AUC Retention** | `AUC_student / AUC_teacher` | 学生相对教师的 AUC 保持率 | > 0.95 |
| **Top-K Hit Rate** | 学生在教师 top-K 推荐中的命中率 | 学生对教师高置信推荐的覆盖 | > 0.85 |
| **Calibration Error (ECE)** | 学生预测概率的校准误差 | 学生是否"知道自己不知道" | < 0.05 |
| **Diversity (ILAD)** | 学生推荐列表的多样性 | 防止"模仿教师 → 单一化" | 较 baseline 涨 > 5% |
| **Logit Cosine Sim** | 学生与教师 logit 的余弦相似度 | 软标签的对齐度 | > 0.7 |

```python
def compute_kd_metrics(student_logits, teacher_logits, student_preds, teacher_preds, true_labels):
    """蒸馏的 5 大离线指标."""
    metrics = {}
    
    # 1. AUC Retention(假设有真值)
    from sklearn.metrics import roc_auc_score
    auc_s = roc_auc_score(true_labels, student_preds.softmax(-1)[:, 1])
    auc_t = roc_auc_score(true_labels, teacher_preds.softmax(-1)[:, 1])
    metrics['auc_retention'] = auc_s / max(auc_t, 1e-6)
    
    # 2. Logit Cosine
    metrics['logit_cos'] = F.cosine_similarity(
        student_logits.flatten(1), teacher_logits.flatten(1)
    ).mean().item()
    
    # 3. ECE(Expected Calibration Error)
    n_bins = 10
    bin_boundaries = torch.linspace(0, 1, n_bins + 1)
    ece = 0
    for i in range(n_bins):
        mask = (student_preds.softmax(-1)[:, 1] >= bin_boundaries[i]) & \
               (student_preds.softmax(-1)[:, 1] < bin_boundaries[i + 1])
        if mask.sum() > 0:
            acc = true_labels[mask].float().mean()
            conf = student_preds.softmax(-1)[mask, 1].mean()
            ece += (mask.float().mean()) * (acc - conf).abs()
    metrics['ece'] = ece.item()
    
    return metrics
```

```python
class ReverseKDValidator:
    """用教师检验学生是否"过度独立"."""
    
    def __init__(self, teacher, students):
        self.teacher = teacher
        self.students = students  # List[student]
    
    def disagreement_rate(self, batch):
        """教师与学生 top-1 不同的比例."""
        with torch.no_grad():
            t_top1 = self.teacher(batch).argmax(-1)
        disagreements = []
        for s in self.students:
            with torch.no_grad():
                s_top1 = s(batch).argmax(-1)
            disagreements.append((s_top1 != t_top1).float().mean().item())
        return disagreements
```

**健康区间**:
- Disagreement < 5%:学生过度模仿,失去泛化
- Disagreement 5-20%:**健康**
- Disagreement > 30%:学生学偏了,需检查

```python
"""
GR 蒸馏 Pipeline 完整实现:
- 教师: Llama-3-8B (QLoRA 量化)
- 学生: Llama-3-1B + LoRA
- 数据: 模拟的 S-ID 推荐序列
"""

import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import Dataset, DataLoader
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training
from bitsandbytes.optim import AdamW8bit


# ============================================================
# 数据集:模拟 S-ID 推荐序列
# ============================================================
class RecSeqDataset(Dataset):
    def __init__(self, n_samples=1000, max_len=20, vocab_size=1000):
        self.data = []
        for _ in range(n_samples):
            seq = torch.randint(1, vocab_size, (max_len,))
            self.data.append(seq)
    
    def __len__(self):
        return len(self.data)
    
    def __getitem__(self, idx):
        seq = self.data[idx]
        # 训练任务:下一个 token 预测
        input_ids = seq[:-1]
        labels = seq[1:]
        return input_ids, labels


# ============================================================
# 蒸馏 Trainer
# ============================================================
class GRDistillationTrainer:
    def __init__(self, teacher_path="meta-llama/Llama-3-8B-Instruct",
                 student_path="meta-llama/Llama-3.2-1B-Instruct",
                 lora_r=8, T=4.0, lr=1e-4):
        # 1. 加载 QLoRA 教师
        from transformers import BitsAndBytesConfig
        bnb_config = BitsAndBytesConfig(
            load_in_4bit=True,
            bnb_4bit_quant_type="nf4",
            bnb_4bit_compute_dtype=torch.bfloat16,
        )
        self.teacher = AutoModelForCausalLM.from_pretrained(
            teacher_path,
            quantization_config=bnb_config,
            device_map="auto",
        )
        self.teacher.eval()
        
        # 2. 加载 LoRA 学生
        self.tokenizer = AutoTokenizer.from_pretrained(student_path)
        student = AutoModelForCausalLM.from_pretrained(student_path, torch_dtype=torch.bfloat16)
        
        lora_config = LoraConfig(
            r=lora_r, lora_alpha=16,
            target_modules=["q_proj", "v_proj"],
            lora_dropout=0.05, bias="none",
        )
        self.student = get_peft_model(student, lora_config)
        self.student.print_trainable_parameters()
        
        # 3. 优化器(只优化 LoRA 参数)
        self.optimizer = AdamW8bit(
            [p for p in self.student.parameters() if p.requires_grad], lr=lr
        )
        self.T = T
    
    def distillation_step(self, input_ids, labels):
        # 学生 forward
        s_out = self.student(input_ids=input_ids, labels=labels)
        s_logits = s_out.logits  # [B, T, V]
        ce_loss = s_out.loss
        
        # 教师 forward(冻结)
        with torch.no_grad():
            t_out = self.teacher(input_ids=input_ids)
            t_logits = t_out.logits
        
        # KD loss
        kd = F.kl_div(
            F.log_softmax(s_logits / self.T, dim=-1),
            F.softmax(t_logits / self.T, dim=-1),
            reduction='batchmean',
        ) * (self.T ** 2)
        
        # 总 loss
        loss = 0.7 * kd + 0.3 * ce_loss
        return loss, kd.item(), ce_loss.item()
    
    def train(self, dataloader, n_epochs=3, log_every=10):
        self.student.train()
        for epoch in range(n_epochs):
            for i, (input_ids, labels) in enumerate(dataloader):
                input_ids = input_ids.cuda()
                labels = labels.cuda()
                
                loss, kd, ce = self.distillation_step(input_ids, labels)
                
                self.optimizer.zero_grad()
                loss.backward()
                self.optimizer.step()
                
                if i % log_every == 0:
                    print(f"Epoch {epoch} | Step {i} | Loss {loss.item():.4f} | KD {kd:.4f} | CE {ce:.4f}")
    
    def merge_and_save(self, save_path):
        """合并 LoRA 到学生,得到最终模型."""
        merged = self.student.merge_and_unload()
        merged.save_pretrained(save_path)
        self.tokenizer.save_pretrained(save_path)


# ============================================================
# 主流程
# ============================================================
def main():
    # 数据
    dataset = RecSeqDataset(n_samples=500, max_len=20, vocab_size=1000)
    loader = DataLoader(dataset, batch_size=4, shuffle=True)
    
    # 训练
    trainer = GRDistillationTrainer(
        teacher_path="meta-llama/Llama-3-8B-Instruct",  # 实际请换成你有的模型
        student_path="meta-llama/Llama-3.2-1B-Instruct",
    )
    trainer.train(loader, n_epochs=2, log_every=5)
    
    # 保存
    trainer.merge_and_save("./gr_distilled_student")


if __name__ == "__main__":
    # 注: 实际运行需要 GPU + 模型权重
    # 这里只展示代码结构
    print("代码已就绪,请配置 GPU + 模型路径后运行")
```

## 19.15 蒸馏的理论极限:Vapnik-Chervonenkis 视角

### 19.15.1 为什么蒸馏"理论上一定能行"?

**Vapnik-Chervonenkis (VC) 理论** 给出了学习复杂度的下界,蒸馏能"绕过"这一下界吗?

**直觉**: 教师模型的"知识"是一种**隐式正则化**(implicit regularization)。它把整个函数空间 $F$ 约束到一个子空间 $F_T$ (教师所在的空间),学生只需要在这个子空间里搜索。

**形式化**:
- VC 维度 $h$ 的假设空间 $F$, 经验误差最小化需要 $O(\sqrt{h/n})$ 的样本复杂度。
- 加入教师约束后,有效 VC 维度降低到 $h_T \ll h$,样本复杂度降到 $O(\sqrt{h_T/n})$。

**结论**: 蒸馏把"找一个好函数"变成了"在教师附近找一个好函数",后者自由度低,所以泛化更好。

### 19.15.2 Bias-Variance 分解下的蒸馏

经典的 **bias-variance 分解**:
$$\mathbb{E}[(y - \hat{f}(x))^2] = \text{Bias}^2(\hat{f}) + \text{Var}(\hat{f}) + \sigma^2$$

蒸馏对这三项的影响:

| 项 | 蒸馏前 | 蒸馏后 | 原因 |
| :--- | :--- | :--- | :--- |
| **Bias²** | 高 | 低 | 教师把"目标函数"信息传递给学生,降低 bias |
| **Var** | 高 | **中** | 软标签是"无限样本"的经验分布,正则化效果 |
| **σ² (噪声)** | 不变 | 不变 | 蒸馏无法消除数据本身的噪声 |

**关键洞察**: 蒸馏**不是万能的**——如果教师本身 bias 很高(7B LLM 仍有 5-10% 错误),学生继承这个 bias,无法突破天花板。

### 19.15.3 蒸馏的 PAC-Bayes 界

**PAC-Bayes 理论** 给出了带先验的泛化界:

$$\mathbb{E}[L(f_S)] \leq L_{\text{empirical}}(f_S) + \sqrt{\frac{\text{KL}(f_S \| f_T) + \ln(2\sqrt{n}/\delta)}{2n}}$$

- $f_S$: 学生分布
- $f_T$: 教师先验分布
- $n$: 样本数

**物理意义**: 蒸馏 = 把"先验从均匀分布换成教师分布"。学生和教师的 KL 距离越小,泛化界越紧。

**工业启示**: **不应该让学生"离教师太远"**,否则 PAC-Bayes 界的松弛度增加,泛化变差。这也是为什么蒸馏权重 α 不能过大(详见 §19.9.2 的 anchor loss 讨论)。

```python
# PAC-Bayes 蒸馏损失: KL(f_S || f_T) 作为正则
def pac_bayes_kd_loss(student_logits, teacher_logits, labels, lam=1.0, T=4.0):
    """PAC-Bayes 视角的 KD: 把 KL 作为先验正则"""
    # 标准 CE
    ce = F.cross_entropy(student_logits, labels)
    # KL(q_S || q_T) 作为正则项
    kl = F.kl_div(
        F.log_softmax(student_logits / T, dim=-1),
        F.softmax(teacher_logits / T, dim=-1),
        reduction='batchmean'
    ) * (T ** 2)
    return ce + lam * kl
```

### 19.15.4 蒸馏何时失效? (理论下界)

蒸馏在以下情况失效:

1. **教师过拟合**: 教师在训练集上 100% 准确率,但测试集只有 70% → 学生继承过拟合模式
2. **域迁移**: 教师在域 A 训,学生蒸馏后部署到域 B → 蒸馏加剧分布偏移
3. **容量差过大**: 教师 70B,学生 1B → 学生的 capacity gap 太大,学不到核心结构

**经验阈值**(基于工业实践):

| 教师:学生比例 | 蒸馏效果 | 备注 |
| :--- | :--- | :--- |
| 1:1 - 2:1 | 微弱 | 同规模,蒸馏收益 < 0.5% AUC |
| 4:1 - 10:1 | **显著** | 标准 KD 甜区 |
| 10:1 - 50:1 | 中等 | 需要 TAKD 阶梯蒸馏 |
| > 50:1 | 困难 | 需要 Self-distillation + 大量数据 |

## 19.16 R-Drop / SimKD / 蒸馏变体大集合

### 19.16.1 R-Drop:双向 KL 自蒸馏

**R-Drop** (NeurIPS 2021) 提出让同一个 batch 跑两次前向(不同 dropout),两次输出互相蒸馏:

$$\mathcal{L}_{\text{R-Drop}} = \frac{1}{2}\left[\text{KL}(p_1 \| p_2) + \text{KL}(p_2 \| p_1)\right]$$

其中 $p_1, p_2$ 是两次前向的输出分布。

```python
class RDropLoss(nn.Module):
    """R-Drop: 双向 KL 自蒸馏"""
    def __init__(self, alpha=1.0):
        super().__init__()
        self.alpha = alpha
    
    def forward(self, logits1, logits2, labels):
        # 1. 标准 CE(两次)
        ce_loss = 0.5 * (
            F.cross_entropy(logits1, labels) +
            F.cross_entropy(logits2, labels)
        )
        # 2. 双向 KL
        kl_loss = 0.5 * (
            F.kl_div(F.log_softmax(logits1, dim=-1), F.softmax(logits2, dim=-1), reduction='batchmean') +
            F.kl_div(F.log_softmax(logits2, dim=-1), F.softmax(logits1, dim=-1), reduction='batchmean')
        )
        return ce_loss + self.alpha * kl_loss


# 用法:同一个 batch 跑两次(不同 dropout mask)
def train_step_rdrop(model, batch, rdrop_loss, optimizer):
    x, y = batch
    # 两次前向(dropout 不同)
    logits1 = model(x)
    logits2 = model(x)
    loss = rdrop_loss(logits1, logits2, y)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    return loss.item()
```

**R-Drop 的优势**: 不需要教师模型,免费获得正则化收益。在推荐系统的"小教师-中学生"场景特别有用。

### 19.16.2 SimKD:简单 KD 的极简主义

**SimKD** (CVPR 2022) 提出"SimKD 是最朴素但最有效的蒸馏":

- **不使用**教师变换层
- **不使用**复杂的 feature 蒸馏
- **只用**最后一层的 logit 蒸馏 + 一个简单的 projector

**效果**: SimKD 在 ImageNet 上把 ResNet-18 学生蒸馏的 top-1 从 71.5% 提到 73.5%,**超越**很多复杂方法。

```python
class SimKD(nn.Module):
    """SimKD: 极简单蒸馏"""
    def __init__(self, teacher_dim, student_dim):
        super().__init__()
        # 唯一的"额外参数": 维度对齐 projector
        self.projector = nn.Linear(student_dim, teacher_dim)
    
    def forward(self, student_logits, teacher_logits, labels):
        # 学生 logits -> 投影 -> 对齐教师维度
        s_proj = self.projector(student_logits)
        # 蒸馏 loss
        kd = F.kl_div(
            F.log_softmax(s_proj, dim=-1),
            F.softmax(teacher_logits, dim=-1),
            reduction='batchmean'
        )
        ce = F.cross_entropy(student_logits, labels)
        return kd + ce
```

### 19.16.3 FitNet 系列:中间层蒸馏变体

| 方法 | 蒸馏层 | 损失函数 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- | :--- |
| **FitNet** (2015) | 单一 hint 层 | MSE | 简单 | 只用一层 |
| **FitNets-HS** | 多层加权 | 多个 MSE 加权 | 充分利用中间层 | 权重难调 |
| **FSP** (2017) | 层间 Gram 矩阵 | MSE on Gram | 传递"风格" | 慢 |
| **AT** (Attention Transfer, 2017) | 注意力图 | L2(attention map) | 紧凑 | 注意力图定义因模型而异 |
| **NST** (Neuron Selectivity Transfer, 2018) | MMD 分布 | MMD loss | 鲁棒 | MMD 选择敏感 |

```python
def attention_transfer(student_attn, teacher_attn):
    """AT: 注意力图蒸馏"""
    # student_attn, teacher_attn: [B, num_heads, seq_len, seq_len]
    # 头维度求和
    s = student_attn.sum(dim=1)  # [B, seq_len, seq_len]
    t = teacher_attn.sum(dim=1)
    return F.mse_loss(s, t)
```

### 19.16.4 关系蒸馏变体对比

| 方法 | 关系矩阵 | 损失 | 时间复杂度 |
| :--- | :--- | :--- | :--- |
| **CRD** (2020) | 相似度矩阵 | KL | $O(B^2 D)$ |
| **RKD** (Relational KD, 2019) | 距离 + 角度 | Huber | $O(B^2)$ |
| **PKT** (Probabilistic Knowledge Transfer, 2020) | 概率分布匹配 | KL(分桶) | $O(B \log B)$ |
| **SP** (Similarity Preserving, 2019) | 余弦相似度矩阵 | MSE | $O(B^2 D)$ |

```python
class RKDLoss(nn.Module):
    """Relational KD: 距离 + 角度关系蒸馏"""
    def __init__(self, beta=1.0):
        super().__init__()
        self.beta = beta
    
    def forward(self, student_feat, teacher_feat):
        # student_feat, teacher_feat: [B, D]
        # 1. 距离关系
        with torch.no_grad():
            t_dist = torch.cdist(teacher_feat, teacher_feat, p=2)
            # 归一化到 [0, 1]
            t_dist = t_dist / t_dist.max()
        s_dist = torch.cdist(student_feat, student_feat, p=2)
        s_dist = s_dist / s_dist.max()
        dist_loss = F.smooth_l1_loss(s_dist, t_dist)
        
        # 2. 角度关系(三元组)
        with torch.no_grad():
            t_angle = self._compute_angles(teacher_feat)
        s_angle = self._compute_angles(student_feat)
        angle_loss = F.smooth_l1_loss(s_angle, t_angle)
        
        return dist_loss + self.beta * angle_loss
    
    def _compute_angles(self, feat):
        """计算三元组角度"""
        B = feat.size(0)
        angles = []
        for i in range(B):
            for j in range(i+1, B):
                for k in range(j+1, B):
                    v1 = feat[j] - feat[i]
                    v2 = feat[k] - feat[i]
                    cos = F.cosine_similarity(v1.unsqueeze(0), v2.unsqueeze(0))
                    angles.append(cos)
        return torch.stack(angles).squeeze()
```

### 19.17.1 字节 OneRec (2025):多阶段 TAKD

**OneRec** 是字节跳动 2025 年开源的生成式推荐系统,蒸馏是其核心架构之一。

**蒸馏架构**:
```
教师:  Tenrec-XL (10B 参数, 1024 A100 × 14 天)
   ↓ Stage 1 KD (T=4, α=0.8)
助教:  Tenrec-Large (1.5B 参数, 64 A100 × 3 天)
   ↓ Stage 2 KD (T=2, α=0.5)
学生:  Tenrec-Small (0.5B 参数, 8 A100 × 1 天)
   ↓ 部署(vLLM)
线上:  P99 < 30ms, QPS > 10K
```

**关键技术**:
1. **TAKD (Teacher Assistant KD)**: 解决 capacity gap
2. **动态温度调度**: T 从 4 → 2 → 1 阶梯下降
3. **课程蒸馏**: 先蒸馏"简单样本"(高频品类),再蒸馏"难样本"(长尾)

```python
class OneRecDistillationSchedule:
    """OneRec 多阶段蒸馏调度"""
    def __init__(self, stages):
        self.stages = stages
    
    def get_current_config(self, step):
        """根据训练 step 返回当前阶段的 T, α"""
        for stage in self.stages:
            if step < stage['end_step']:
                # 在 stage 内,线性插值
                progress = (step - stage['start_step']) / (stage['end_step'] - stage['start_step'])
                T = stage['T_start'] + (stage['T_end'] - stage['T_start']) * progress
                alpha = stage['alpha_start'] + (stage['alpha_end'] - stage['alpha_start']) * progress
                return T, alpha
        return self.stages[-1]['T_end'], self.stages[-1]['alpha_end']


# 配置示例
```

### 19.17.2 Meta HSTU (2024):序列推荐蒸馏

**HSTU** (Hierarchical Sequential Transduction Unit) 是 Meta 2024 年发布的统一推荐架构。

**蒸馏方案**:
- **教师**: HSTU-Large (8 层, hidden=2048)
- **学生**: HSTU-Base (4 层, hidden=512)
- **蒸馏**: 主损失 + Feature distillation (中间层对齐) + Logit distillation

```python
class HSTUDistillation(nn.Module):
    """HSTU 蒸馏: 多层中间特征对齐"""
    def __init__(self, teacher, student, teacher_dims, student_dims):
        super().__init__()
        self.teacher = teacher
        self.student = student
        # 每层一个 projector
        self.projectors = nn.ModuleList([
            nn.Linear(s_dim, t_dim)
            for s_dim, t_dim in zip(student_dims, teacher_dims)
        ])
    
    def forward(self, seq, labels):
        # 多层中间特征
        with torch.no_grad():
            t_layers = self.teacher.get_intermediates(seq)  # List of [B, L, D_t]
        
        s_layers = self.student.get_intermediates(seq)  # List of [B, L, D_s]
        
        # 每层对齐
        feat_loss = 0
        for s, t, proj in zip(s_layers, t_layers, self.projectors):
            feat_loss += F.mse_loss(proj(s), t)
        
        # Logit 蒸馏
        s_logits = self.student.head(seq)
        t_logits = self.teacher.head(seq)
        logit_loss = F.kl_div(
            F.log_softmax(s_logits, dim=-1),
            F.softmax(t_logits, dim=-1),
            reduction='batchmean'
        )
        
        # CE
        ce = F.cross_entropy(s_logits.view(-1, s_logits.size(-1)), labels.view(-1))
        
        return ce + 0.5 * feat_loss + 0.3 * logit_loss
```

### 19.17.3 Pinterest 的 L2D (Learn to Distill)

**L2D** (Pinterest 2024) 提出**学习蒸馏的蒸馏**(Meta-distillation):
- 用一个小型"蒸馏策略网络"决定**每个样本用哪种蒸馏方法**(KD / FitNet / CRD / DKD)
- 蒸馏策略网络通过强化学习优化(以学生最终 AUC 作为 reward)

```python
class L2D(nn.Module):
    """Learn to Distill: 学习如何蒸馏"""
    def __init__(self, distillation_methods, hidden=128):
        super().__init__()
        self.methods = nn.ModuleList(distillation_methods)
        self.policy_net = nn.Sequential(
            nn.Linear(768, hidden),  # 输入:样本特征
            nn.ReLU(),
            nn.Linear(hidden, len(distillation_methods)),
            nn.Softmax(dim=-1)
        )
    
    def forward(self, sample_features, student_logits, teacher_logits, labels):
        # 策略网络选择蒸馏方法
        weights = self.policy_net(sample_features)  # [B, num_methods]
        
        # 所有方法都跑一遍,加权求和
        total_loss = 0
        for i, method in enumerate(self.methods):
            method_loss = method(student_logits, teacher_logits, labels)
            total_loss += (weights[:, i] * method_loss).mean()
        
        return total_loss
```

### 19.17.4 Airbnb 的 Listing Embedding 蒸馏

Airbnb 2023 年的 paper 介绍如何把 listing 的多模态(图片+文本+属性)蒸馏到一个紧凑的 embedding:

- **教师**: CLIP (400M 参数) + 文本 BERT (110M)

## 19.18 数据增强式蒸馏

### 19.18.1 Mixup + KD

**Mixup** 是一种简单但有效的数据增强: 把两个样本按比例混合:

$$\tilde{x} = \lambda x_i + (1-\lambda) x_j$$
$$\tilde{y} = \lambda y_i + (1-\lambda) y_j$$

**Mixup + KD**: 在混合样本上也做蒸馏。

```python
class MixupDistillation(nn.Module):
    def __init__(self, alpha=0.2, T=4.0):
        super().__init__()
        self.alpha = alpha
        self.T = T
    
    def forward(self, student, teacher, x1, x2, y1, y2):
        # Mixup
        lam = np.random.beta(self.alpha, self.alpha)
        x_mix = lam * x1 + (1 - lam) * x2
        
        # 学生/教师 在混合样本上的输出
        s_logits = student(x_mix)
        with torch.no_grad():
            t_logits = teacher(x_mix)
        
        # KD 在混合样本上
        kd = F.kl_div(
            F.log_softmax(s_logits / self.T, dim=-1),
            F.softmax(t_logits / self.T, dim=-1),
            reduction='batchmean'
        ) * (self.T ** 2)
        
        # 混合标签 CE
        ce = lam * F.cross_entropy(s_logits, y1) + (1-lam) * F.cross_entropy(s_logits, y2)
        
        return ce + 0.5 * kd
```

### 19.18.2 CutMix + KD (推荐系统特化)

**CutMix** 把两个样本的一部分"切掉"再拼起来,在 CV 里效果好。

**推荐系统的特化**: 把两个用户的部分行为混合:

```python
class UserBehaviorMixup(nn.Module):
    """用户行为序列的 Mixup"""
    def forward(self, user_hist1, user_hist2, item_emb):
        """
        user_hist1, user_hist2: [B, max_len] 用户历史物品 ID
        item_emb: Embedding 表
        """
        lam = np.random.beta(0.2, 0.2)
        B, L = user_hist1.shape
        
        # 切点
        cut = int(L * lam)
        # 拼接: 前 cut 个是用户1, 后 L-cut 个是用户2
        mixed_hist = torch.cat([user_hist1[:, :cut], user_hist2[:, cut:]], dim=1)
        
        # Embedding lookup
        emb_mix = item_emb(mixed_hist)  # [B, L, D]
        # 教师/学生蒸馏
        return emb_mix
```

## 19.19 Curriculum 蒸馏(课程式蒸馏)

### 19.19.1 什么是课程式蒸馏?

**核心思想**: 先蒸馏"容易"的样本(高 CTR、高频),再蒸馏"难"的样本(低 CTR、长尾)。

**类比人类学习**: 先学加减,再学乘除,最后学微积分。

```python
class CurriculumDistillScheduler:
    """课程式蒸馏: 按样本难度排序训练"""
    def __init__(self, easy_threshold=0.1, hard_threshold=0.01):
        self.easy_threshold = easy_threshold  # CTR > 10% 视为"容易"
        self.hard_threshold = hard_threshold  # CTR < 1% 视为"难"
    
    def get_difficulty_bucket(self, ctr):
        """返回样本难度等级"""
        if ctr > self.easy_threshold:
            return 'easy'
        elif ctr > self.hard_threshold:
            return 'medium'
        else:
            return 'hard'
    
    def get_sample_weight(self, ctr, current_step, total_steps):
        """课程权重: 早期只训容易样本,后期逐渐引入难样本"""
        progress = current_step / total_steps
        difficulty = self.get_difficulty_bucket(ctr)
        
        if difficulty == 'easy':
            return 1.0  # 总是全权重
        elif difficulty == 'medium':
            # 中等样本: progress > 0.3 才用
            return min(1.0, max(0.0, (progress - 0.3) / 0.4))
        else:  # hard
            # 难样本: progress > 0.6 才用
            return min(1.0, max(0.0, (progress - 0.6) / 0.4))
```

### 19.19.2 反向课程蒸馏(从难到易)

**直觉**: 一些论文发现**从难样本开始训练反而效果更好**——因为容易样本太多,模型学不到关键模式。

```python
class ReverseCurriculumDistill:
    """反向课程: 先蒸馏难样本(头部偏置小)"""
    def __init__(self, model, teacher, n_steps=10000):
        self.model = model
        self.teacher = teacher
    
    def train(self, dataloader):
        # 按难度分组
        easy_loader = dataloader.filter(lambda x: x['ctr'] > 0.1)
        hard_loader = dataloader.filter(lambda x: x['ctr'] < 0.01)
        
        # Stage 1 (30% steps): 只训难样本
        for step in range(n_steps // 3):
            batch = next(hard_loader)
            self.train_step(batch)
        
        # Stage 2 (40% steps): 难 + 中等
        medium_loader = dataloader.filter(lambda x: 0.01 <= x['ctr'] <= 0.1)
        for step in range(n_steps * 2 // 5):
            batch = random.choice([next(hard_loader), next(medium_loader)])
            self.train_step(batch)
        
        # Stage 3 (30% steps): 全量
        for step in range(n_steps // 3):
            batch = next(dataloader)
            self.train_step(batch)
```

### 19.20.1 通用 KD Trainer

```python
class UniversalKDTrainer:
    """通用 KD 训练器: 支持 Logit / Feature / Relation / DKD"""
    
    def __init__(self, student, teacher, train_loader, val_loader, 
                 method='logit', T=4.0, alpha=0.7, lr=1e-4, device='cuda'):
        self.student = student.to(device)
        self.teacher = teacher.to(device).eval()
        self.train_loader = train_loader
        self.val_loader = val_loader
        self.method = method
        self.T = T
        self.alpha = alpha
        self.device = device
        
        # 选择损失函数
        if method == 'logit':
            self.criterion = LogitDistillationLoss(T, alpha)
        elif method == 'feature':
            self.criterion = FeatureDistillationLoss(T, alpha)
        elif method == 'relation':
            self.criterion = CRDLoss(T)
        elif method == 'dkd':
            self.criterion = DKDLoss(alpha=1.0, beta=8.0, T=T)
        else:
            raise ValueError(f"Unknown method: {method}")
        
        self.optimizer = torch.optim.AdamW(student.parameters(), lr=lr)
    
    def train_epoch(self, epoch):
        self.student.train()
        total_loss = 0
        for batch_idx, batch in enumerate(self.train_loader):
            batch = {k: v.to(self.device) for k, v in batch.items()}
            
            # 教师前向(冻结)
            with torch.no_grad():
                t_out = self.teacher(batch)
            
            # 学生前向
            s_out = self.student(batch)
            
            # 计算蒸馏损失
            if self.method in ['logit', 'dkd']:
                loss, _, _ = self.criterion(s_out['logits'], t_out['logits'], batch['labels'])
            elif self.method == 'feature':
                loss = self.criterion(s_out['features'], t_out['features'], batch['labels'])
            elif self.method == 'relation':
                loss = self.criterion(s_out['features'], t_out['features'])
            
            self.optimizer.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(self.student.parameters(), 1.0)
            self.optimizer.step()
            
            total_loss += loss.item()
        
        avg_loss = total_loss / len(self.train_loader)
        return avg_loss
    
    def evaluate(self):
        self.student.eval()
        all_preds, all_labels = [], []
        with torch.no_grad():
            for batch in self.val_loader:
                batch = {k: v.to(self.device) for k, v in batch.items()}
                s_out = self.student(batch)
                preds = torch.sigmoid(s_out['logits']).cpu()
                all_preds.append(preds)
                all_labels.append(batch['labels'].cpu())
        
        from sklearn.metrics import roc_auc_score
        auc = roc_auc_score(torch.cat(all_labels), torch.cat(all_preds))
        return auc
    
    def fit(self, n_epochs=10):
        best_auc = 0
        for epoch in range(n_epochs):
            train_loss = self.train_epoch(epoch)
            val_auc = self.evaluate()
            print(f"Epoch {epoch+1}/{n_epochs} | Train Loss: {train_loss:.4f} | Val AUC: {val_auc:.4f}")
            if val_auc > best_auc:
                best_auc = val_auc
                torch.save(self.student.state_dict(), 'best_student.pt')
        return best_auc
```

### 19.20.2 推荐系统特化的蒸馏 Pipeline

```python
class RecSysDistillationPipeline:
    """推荐系统蒸馏完整 Pipeline"""
    
    def __init__(self, teacher_ckpt, student_config, dataloader):
        # 1. 加载教师
        self.teacher = self._build_teacher(teacher_ckpt)
        # 2. 初始化学生
        self.student = self._build_student(student_config)
        # 3. 数据
        self.dataloader = dataloader
    
    def _build_teacher(self, ckpt_path):
        teacher = DINRec(hidden_dim=512, num_layers=8)
        teacher.load_state_dict(torch.load(ckpt_path))
        teacher.eval()
        for p in teacher.parameters():
            p.requires_grad = False
        return teacher
    
    def _build_student(self, config):
        return DNNRec(hidden_dim=64, num_layers=3)
    
    def distill(self, n_epochs=10, T=4.0, alpha=0.7):
        """核心蒸馏逻辑"""
        # 1. 准备多任务蒸馏损失
        criterion = MultiTaskDistillationLoss(T=T, alpha=alpha)
        optimizer = torch.optim.AdamW(self.student.parameters(), lr=1e-4, weight_decay=1e-5)
        
        # 2. 学习率 warmup + 余弦退火
        scheduler = torch.optim.lr_scheduler.OneCycleLR(
            optimizer, max_lr=1e-3, total_steps=n_epochs * len(self.dataloader),
            pct_start=0.1
        )
        
        # 3. 渐进式 α(从 0 到目标值)
        alpha_warmup = ProgressiveDistillWeight(target_alpha=alpha, warmup_steps=1000)
        
        for epoch in range(n_epochs):
            for step, batch in enumerate(self.dataloader):
                # 教师推理(冻结)
                with torch.no_grad():
                    t_out = self.teacher(batch)
                
                # 学生推理
                s_out = self.student(batch)
                
                # 蒸馏损失
                current_alpha = alpha_warmup.get_alpha()
                loss = criterion(s_out, t_out, batch, alpha=current_alpha)
                
                # 反向传播
                optimizer.zero_grad()
                loss.backward()
                torch.nn.utils.clip_grad_norm_(self.student.parameters(), 1.0)
                optimizer.step()
                scheduler.step()
                alpha_warmup.step_count()
                
                if step % 100 == 0:
                    print(f"Epoch {epoch} | Step {step} | Loss: {loss.item():.4f} | α: {current_alpha:.3f}")
        
        return self.student


class MultiTaskDistillationLoss(nn.Module):
    """多任务蒸馏: 同时蒸馏 CTR, CVR, 完播, 点赞 等多个目标"""
    def __init__(self, T=4.0, alpha=0.7, task_weights={'ctr': 1.0, 'cvr': 0.5}):
        super().__init__()
        self.T = T
        self.alpha = alpha
        self.task_weights = task_weights
    
    def forward(self, student_out, teacher_out, batch, alpha=None):
        if alpha is None:
            alpha = self.alpha
        
        total_loss = 0
        for task, weight in self.task_weights.items():
            # 蒸馏当前任务
            s_logits = student_out[task]
            t_logits = teacher_out[task]
            labels = batch[f'{task}_label']
            
            kd = F.kl_div(
                F.log_softmax(s_logits / self.T, dim=-1),
                F.softmax(t_logits / self.T, dim=-1),
                reduction='batchmean'
            ) * (self.T ** 2)
            ce = F.binary_cross_entropy_with_logits(s_logits, labels.float())
            
            task_loss = (1 - alpha) * ce + alpha * kd
            total_loss += weight * task_loss
        
        return total_loss
```

## 19.22 蒸馏的工程"反模式"与"最佳实践"

### 19.22.1 反模式 (Anti-Patterns)

| 反模式 | 表现 | 后果 | 解决方案 |
| :--- | :--- | :--- | :--- |
| **温度照搬论文** | 直接用 T=4 | 搜推广可能不收敛 | 网格搜索 T ∈ [2, 6] |
| **α 恒定不调度** | 全程 α=0.7 | 学生初期学偏 | 渐进式 α (warmup) |
| **教师没冻结** | 教师随学生一起更新 | 自蒸馏 → 退化为 self-train | `requires_grad=False` |
| **验证用同一教师** | 评估时教师还在更新 | AUC 评估虚高 | 加载 best teacher |
| **混合精度泄漏** | 教师 FP16, 学生 FP32 | logit 范围不一致 | 同精度或对齐 |
| **batch size 过小** | batch=64 | KD 失效(负样本太少) | batch ≥ 256 |
| **蒸馏数据泄漏** | 蒸馏和评估数据有重叠 | AUC 虚高 | 时间切分 + 严格隔离 |

**7. 实践建议**

结合 "第 19 章:知识蒸馏——大模型教小模型" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "第 19 章:知识蒸馏——大模型教小模型" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
