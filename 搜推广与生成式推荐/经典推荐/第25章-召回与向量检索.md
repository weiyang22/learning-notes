# 第 25 章:召回与向量检索

> **本章目标**: 召回是推荐漏斗的第一层, 从亿级物料里选出千级候选。核心是**双塔 + 负采样 + ANN**。

## 1. 推荐漏斗与多路召回

```
亿级物料 →[召回 千级]→[粗排 百级]→[精排 十级]→[重排]→ 曝光
```

**多路召回**: 协同(ItemCF/Swing)、向量(双塔)、热门、地域、SID 生成式召回等并行, 结果合并去重。互补覆盖不同兴趣。

## 2. 双塔模型(向量召回主力)

User 塔和 Item 塔各自编码成向量, 内积/余弦打分。训练后 **Item 向量离线建索引**, 线上只算 User 向量做 ANN 检索。

```python
import torch, torch.nn as nn, torch.nn.functional as F

class TwoTower(nn.Module):
    def __init__(self, u_dim, i_dim, d=64):
        super().__init__()
        self.user = nn.Sequential(nn.Linear(u_dim, 128), nn.ReLU(), nn.Linear(128, d))
        self.item = nn.Sequential(nn.Linear(i_dim, 128), nn.ReLU(), nn.Linear(128, d))
    def forward(self, u, i):
        u = F.normalize(self.user(u), dim=-1)        # 归一化 → 余弦
        i = F.normalize(self.item(i), dim=-1)
        return u, i

def in_batch_softmax_loss(u, i, temp=0.05):
    """In-batch 负采样: batch 内其他 item 作负例"""
    logits = u @ i.t() / temp                        # (B, B)
    labels = torch.arange(u.size(0), device=u.device)
    return F.cross_entropy(logits, labels)           # 对角线为正样本
```

**双塔的约束**: User/Item 不能提前交互(否则无法离线索引)→ 表达力弱于精排, 这是"召回-精排"分工的根源。

## 3. 负采样策略(召回的灵魂)

召回没有天然负样本, 采样质量决定效果:

| 策略 | 说明 | 注意 |
| :--- | :--- | :--- |
| In-batch | batch 内互为负例 | 需**纠偏**(热门 item 被过采) |
| 全局随机 | 从全库均匀采 | 简单, 易学 |
| 热门打压 | 按频次降采样热门 | 防止头部主导 |
| Hard negative | 相似但未点击 | 提升区分度, 别太 hard |

**采样偏差纠正(logQ 校正)**: In-batch 负采样中热门物品出现概率高, 打分要减去 $\log Q(item)$ 修正:

```python
logits = u @ i.t() / temp - torch.log(item_freq).unsqueeze(0)   # logQ 校正
```

## 4. ANN 近似最近邻检索

亿级向量精确 KNN 不可行, 用 ANN 近似:

| 方法 | 原理 | 特点 |
| :--- | :--- | :--- |
| **HNSW** | 多层近邻图, 贪心跳转 | 高召回、内存大, 主流 |
| **IVF** | 聚类倒排, 只搜近簇 | 快, 需训练聚类 |
| **PQ** | 乘积量化压缩向量 | 省内存, 精度略降 |
| **IVF-PQ** | 倒排 + 量化 | 十亿级工业标配 |

```python
import faiss, numpy as np
d, nlist = 64, 4096
quantizer = faiss.IndexFlatIP(d)
index = faiss.IndexIVFFlat(quantizer, d, nlist, faiss.METRIC_INNER_PRODUCT)
index.train(item_vecs); index.add(item_vecs)        # 离线建库
index.nprobe = 16                                    # 搜索簇数(召回/速度权衡)
D, I = index.search(user_vec, 200)                   # 线上 top-200
```

## 5. 与 SID / 生成式召回的关系

- 传统双塔: 学 Embedding, ANN 检索。
- **SID 生成式召回**(TIGER/OneRec): 把 item 表示成语义 ID 序列, 用生成模型**自回归生成** item ID, 无需 ANN。详见 [SID教程第10章](../SID技术/第10章-SID与下游任务集成/)。
- 两者互补: 生成式召回语义泛化强、冷启友好; 双塔成熟稳定。

## 6. 面试高频

1. 双塔为什么不能早交互? → 需离线索引 Item 向量。
2. In-batch 负采样的偏差如何纠正? → logQ 校正扣热门概率。
3. HNSW vs IVF-PQ 怎么选? → 内存够求高召回用 HNSW; 十亿级省内存用 IVF-PQ。
4. Hard negative 为什么不能太 hard? → 可能是伪负(未曝光而非不喜欢), 引入噪声。

## 7. 推荐漏斗的全景

推荐系统不是单模型问题, 而是**漏斗 + 多模型协同**。每一层都有不同的目标、算力和数据约束, 不能简单地"用一个模型搞定一切"。

### 7.1 漏斗的工程意义

```
物料池 (亿级)
   ↓ [召回: 100路并发, 每路取 1000 候选 → 合并去重 ~10万]
   ↓
候选池 (万级)
   ↓ [粗排: 轻量模型 100ms → 1000]
   ↓
精排池 (千级)
   ↓ [精排: 重模型 50ms → 100]
   ↓
TopK (百级)
   ↓ [重排: 多样性/规则 → 50]
   ↓
曝光 (~10-20)
```

**每一层的"成本-价值"权衡**:

| 层级 | 算力/请求 | 候选减少 | 模型复杂度 | 业务目标 |
| :--- | :--- | :--- | :--- | :--- |
| 召回 | 100 路 × 1k = 10万次粗打分 | 亿 → 万 | 极低 (双塔/规则) | 高召回率 |
| 粗排 | 1次轻打分 × 1万 = 1万次打分 | 万 → 千 | 中 (轻 FM/DCN) | 排序一致性 |
| 精排 | 1次重打分 × 1千 = 1千次打分 | 千 → 百 | 高 (DIN/MMoE) | 精准 AUC |
| 重排 | 1次重排 × 100 = 100次 | 百 → 十 | 中 (Transformer) | 多样性/约束 |

### 7.2 为什么不能只用一层

**只用召回**: 召回模型简单, 排序质量差, 漏斗顶部的错误无法挽回。

**只用精排**: 精排必须见全量候选, 亿级候选算力爆炸, 延迟不可接受。

**结论**: 漏斗是**算力与精度的最优折中**, 各层之间目标一致但手段不同。

### 7.3 各层之间的"目标对齐"

| 层级 | 评估指标 | 与下一层的关系 |
| :--- | :--- | :--- |
| 召回 | Recall@100 (在最终 TopK 中的召回率) | 召回率高 → 精排上限高 |
| 粗排 | AUC 与精排 AUC 的相关性 | 相关性高 → 精排选出的好 |
| 精排 | AUC / GAUC | 与业务指标强相关 |
| 重排 | NDCG@10 / 多样性 / 业务 CTR | 直接影响用户体验 |

**重要**: 召回的"多样性"比"精度"更重要。即使召回精度差一点, 但召回了 10 路不同的物品, 比召回 1 路高精度物品更好。

### 7.4 召回 vs 粗排 vs 精排的本质差异

```
召回: "用户可能喜欢什么?" → 候选生成
粗排: "哪些候选更值得精排?" → 候选筛选
精排: "每个候选的精确 CTR/CVR?" → 精确打分
重排: "列表怎么排?" → 上下文感知排序
```

| 维度 | 召回 | 粗排 | 精排 |
| :--- | :--- | :--- | :--- |
| 输入 | 用户历史 + 候选 ID | 召回候选 + 详细特征 | 粗排候选 + 全特征 |
| 输出 | 候选 ID 列表 | 候选 ID + 粗打分 | 候选 ID + 精打分 |
| 模型 | 双塔 / ItemCF / Swing | 轻 FM / 浅 DNN | DIN / MMoE / DCN-v2 |
| 训练目标 | InfoNCE / BPR | 蒸馏精排 | 多任务 CTR/CVR/时长 |
| 推理时延 | < 10ms | < 20ms | < 50ms |

## 8. 多路召回的工业实践

### 8.1 多路召回的典型架构

```python
class MultiChannelRecall:
    def __init__(self):
        self.channels = {
            'i2i': ItemCFRecall(),          # 物品协同过滤
            'u2u': UserCFRecall(),          # 用户协同过滤  
            'u2i': TwoTowerRecall(),        # 双塔
            'swing': SwingRecall(),         # Swing (字节)
            'hot': HotRecall(),             # 热门
            'context': ContextRecall(),     # 上下文 (地域/时间)
            'sid': SIDRecall(),             # 生成式召回 (TIGER)
            'explore': ExploreRecall(),     # 探索
        }
    
    def recall(self, user):
        candidates = []
        for name, channel in self.channels.items():
            c = channel.recall(user, top_k=200)
            candidates.append((name, c))
        # 合并去重 + 多路融合
        merged = self.merge(candidates)
        return merged
```

### 8.2 各路召回的特点与适用场景

| 召回路 | 模型 | 适用场景 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- | :--- |
| ItemCF | 物品共现 | 所有 | 简单, 解释性强 | 冷启动差 |
| UserCF | 用户相似 | 高活用户 | 兴趣聚类 | 长尾差 |
| 双塔 | 神经网络 | 大规模 | 通用, 易上线 | 表达力弱 |
| Swing | 用户-物品-物品 三元组 | 短视频 | 比 ItemCF 更鲁棒 | 实现复杂 |
| 热门 | 统计 | 兜底 | 必出 | 不个性化 |
| 上下文 | 规则 | 地域/时间 | 强相关 | 不个性化 |
| SID 生成式 | RQ-VAE + Transformer | 工业前沿 | 语义泛化, 冷启友好 | 推理慢 |
| 探索 | UCB/Thompson | 长尾 | 多样性 | 不精准 |

### 8.3 Swing 召回 (字节算法)

**思想**: 物品 $i$ 和物品 $j$ 的相似度 = "两个物品同时被多少用户行为过, 但行为不是同一类"。

$$\text{swing}(i, j) = \sum_{u \in U_i \cap U_j} \frac{1}{\alpha + |I_u|}$$

其中 $U_i$ 是对物品 $i$ 有行为的用户集合, $I_u$ 是用户 $u$ 的行为物品集合。

**为什么有效**: Swing 通过"非直接共现"度量物品相似度, 比 ItemCF 更鲁棒于热门物品。

```python
def swing_score(item_i, item_j, user_item_dict, alpha=1.0):
    """Swing score for item i and j"""
    users_i = set(user_item_dict.keys_for_item(item_i))
    users_j = set(user_item_dict.keys_for_item(item_j))
    common_users = users_i & users_j
    
    score = 0.0
    for u in common_users:
        items_u = user_item_dict[u]
        score += 1.0 / (alpha + len(items_u))
    return score
```

### 8.4 多路融合策略

**简单融合**: 每路取 TopK, 合并去重。

**加权融合**: 每路打分, 加权求和, 取 TopK。

**级联融合**: 先用规则/启发式过滤 (如热门), 再用模型。

**分层融合**: 每路打分, 高分优先。

```python
def merge_recalls(channels, top_k=1000):
    """合并多路召回结果, 加权打分"""
    score = defaultdict(float)
    for name, (candidates, weights) in channels.items():
        for i, (item_id, score_val) in enumerate(candidates):
            # 倒数排名加权
            rank_score = 1.0 / (i + 1)
            score[item_id] += weights[name] * rank_score * score_val
    
    # 取 TopK
    return sorted(score.items(), key=lambda x: -x[1])[:top_k]
```

### 8.5 多路召回的工程挑战

**挑战 1: 离线评估**

**指标**: Recall@100, HitRate@100, Coverage, 多样性。

**痛点**: 离线只看 Recall, 看不到长尾物品 (新物品需要专门评估)。

**挑战 2: 冷启动**

**新用户**: 用热门/地域/性别画像兜底。

**新物品**: 用内容特征 + SID + 探索流量。

**挑战 3: 多路之间的相关性**

**问题**: 双塔和 ItemCF 可能召回了相同物品, 浪费算力。

**解决**: 用 MMOE/PLSR 之类的模型对多路打分做"互补性"建模。

## 9. 双塔模型的细节深入

### 9.1 双塔为何无法早交互

**核心约束**: 推理时, Item 侧向量必须提前算好 (建库), 线上只算 User 侧。

```python
# 离线: 算所有 Item 向量并建索引
item_vecs = item_tower(item_features)  # (N, d)
index.add(item_vecs)

# 在线: 算 1 个 User 向量并检索
user_vec = user_tower(user_features)   # (1, d)
top_k = index.search(user_vec, 100)    # 毫秒级
```

**如果早交互 (Cross 特征)**: 每次召回都要重新算 Item 向量, 无法建库。

**结论**: 双塔的表达力受限于"User 和 Item 必须独立编码"。

### 9.2 双塔的多种变体

#### 9.2.1 经典双塔 (DSSM, 2013)

```python
class ClassicTwoTower(nn.Module):
    def __init__(self, user_dim, item_dim, embed_dim=64):
        super().__init__()
        self.user_tower = nn.Sequential(
            nn.Linear(user_dim, 256), nn.ReLU(),
            nn.Linear(256, 128), nn.ReLU(),
            nn.Linear(128, embed_dim)
        )
        self.item_tower = nn.Sequential(
            nn.Linear(item_dim, 256), nn.ReLU(),
            nn.Linear(256, 128), nn.ReLU(),
            nn.Linear(128, embed_dim)
        )
    
    def forward(self, user_feat, item_feat):
        u = F.normalize(self.user_tower(user_feat), dim=-1)
        i = F.normalize(self.item_tower(item_feat), dim=-1)
        return (u * i).sum(dim=-1)  # cosine
```

#### 9.2.2 序列双塔 (SDM, 2020)

加入用户行为序列建模:

```python
class SequenceTwoTower(nn.Module):
    def __init__(self, user_dim, item_dim, hist_dim, embed_dim=64):
        super().__init__()
        self.user_tower = UserTowerWithHistory(user_dim, hist_dim, embed_dim)
        self.item_tower = ItemTower(item_dim, embed_dim)
    
    def forward(self, user_feat, hist_feat, item_feat):
        u = self.user_tower(user_feat, hist_feat)  # 序列建模后输出 user 向量
        i = self.item_tower(item_feat)
        return u @ i.t()
```

**SDM (Long Short-term User Memory)** 把用户历史分成长期和短期:
- 长期: 所有历史平均池化
- 短期: 最近 N 个行为用 Transformer

#### 9.2.3 多模态双塔 (MM-DSSM)

物品侧融合文本/图像 Embedding:

```python
class MultimodalTwoTower(nn.Module):
    def __init__(self):
        super().__init__()
        self.text_encoder = BertModel.from_pretrained('bert-base')

        )
    
    def forward(self, user_feat, item_id, item_text, item_image):
```

### 9.3 双塔训练的关键细节

#### 9.3.1 温度系数

```python
def two_tower_loss(u, i, temp=0.05):
    """温度系数控制分布尖锐度"""
    logits = u @ i.t() / temp
    labels = torch.arange(u.size(0))
    return F.cross_entropy(logits, labels)
```

**温度系数的选择**:
- $\tau$ 小: 分布尖锐, 关注难负样本
- $\tau$ 大: 分布平滑, 容易收敛
- 经验值: $\tau \in [0.05, 0.1]$

#### 9.3.2 负采样策略

**In-batch Negatives (默认)**:

```python
# batch 大小 B, 每个样本有 1 个正例, B-1 个负例
logits = u @ i.t()  # (B, B), 对角线为正样本
labels = torch.arange(B)
loss = F.cross_entropy(logits, labels)
```

**Hard Negatives (提升区分度)**:

```python
# 1) 用 ItemCF 找相似但未点击的物品
# 2) 用当前模型找打分高但未点击的物品
hard_negs = retrieve_hard_negatives(user_history, model, top_k=100)

# 训练时, hard_negs 替换部分随机负样本
```

**Popularity-based Negative Sampling**:

```python
# 按频次的 $\alpha$ 次方采样
prob = item_freq ** alpha
prob = prob / prob.sum()
neg_item = np.random.choice(item_ids, p=prob)
```

**$\alpha$ 调节**:
- $\alpha = 0$: 均匀采样
- $\alpha = 1$: 按频次采样
- $\alpha = 0.75$: Word2Vec 经典值

#### 9.3.3 采样偏差纠正 (logQ Correction)

```python
# In-batch 负采样中, 热门物品出现概率高, 需要校正
def corrected_loss(u, i, item_freq, temp=0.05):
    logits = u @ i.t() / temp
    
    # 物品频率的对数
    log_q = torch.log(item_freq[i.long()])  # (B,)
    log_q = log_q.unsqueeze(0)  # (1, B)
    
    # 减去 logQ
    logits = logits - log_q
    
    labels = torch.arange(u.size(0))
    return F.cross_entropy(logits, labels)
```

**为什么有效**: 让模型学"在物品热度背景下的相对偏好", 而不是"绝对点击概率"。

#### 9.3.4 频率感知的双塔 (FAE)

完全避免 In-batch 的偏差:

```python
class FrequencyAwareTwoTower(nn.Module):
    """Frequency-Aware Embedding, 给每个物品加一个频率 Embedding"""
    def __init__(self, num_items, embed_dim):
        super().__init__()
        self.item_emb = nn.Embedding(num_items, embed_dim)
        self.freq_emb = nn.Embedding(num_items, embed_dim)  # 频率单独 Embedding
    
    def get_item_vec(self, item_ids):
        return self.item_emb(item_ids) + self.freq_emb(item_ids)
```

**效果**: 频率信息被单独建模, 主 Embedding 不需要承担"区分热门度"的负担。

### 9.4 双塔的评估指标

#### 9.4.1 Recall@K

**定义**: 在 TopK 召回了多少正样本。

$$\text{Recall@K} = \frac{1}{|U|} \sum_{u \in U} \frac{|\text{TopK}(u) \cap \text{Pos}(u)|}{|\text{Pos}(u)|}$$

```python
def recall_at_k(predictions, labels, k=100):
    """predictions: (B, N) scores, labels: (B, N) 0/1"""
    top_k = predictions.topk(k, dim=-1).indices  # (B, k)
    hits = labels.gather(-1, top_k).sum(-1)        # 命中的正样本数
    total_pos = labels.sum(-1)                      # 总正样本
    return (hits / total_pos.clamp(min=1)).mean()
```

#### 9.4.2 HitRate@K

**定义**: TopK 中是否至少有一个正样本。

$$\text{HitRate@K} = \frac{1}{|U|} \sum_{u \in U} \mathbb{1}[|\text{TopK}(u) \cap \text{Pos}(u)| > 0]$$

#### 9.4.3 NDCG@K

**定义**: 归一化折损累积增益。

$$\text{NDCG@K} = \frac{\text{DCG@K}}{\text{IDCG@K}}$$
$$\text{DCG@K} = \sum_{i=1}^K \frac{2^{rel_i} - 1}{\log_2(i+1)}$$

```python
def ndcg_at_k(predictions, labels, k=100):
    top_k_pred = predictions.topk(k, dim=-1).indices
    top_k_labels = labels.gather(-1, top_k_pred)
    discounts = torch.log2(torch.arange(2, k+2, device=predictions.device))
    dcg = (top_k_labels.float() / discounts).sum(-1)
    
    # IDCG (ideal)
    ideal_labels = labels.topk(k, dim=-1).values
    idcg = (ideal_labels.float() / discounts).sum(-1)
    
    return (dcg / idcg.clamp(min=1e-10)).mean()
```

### 9.5 双塔 vs 单塔 (精排) 的对比

| 维度 | 双塔 | 单塔 (精排) |
| :--- | :--- | :--- |
| User×Item 交叉 | 弱 (内积) | 强 (Cross/Attention) |
| 推理时延 | < 10ms | < 50ms |
| 适用候选量 | 亿级 | 千级 |
| 训练数据 | 点击/未点击 | 点击/转化 |
| 表达力 | 弱 | 强 |
| 主要 loss | InfoNCE | BCE/CrossEntropy |

**实践**: 双塔处理召回, 单塔处理精排, 两者**互补**而非替代。

### 9.6 双塔的常见坑

**坑 1**: User 侧和 Item 侧分布不一致, 训练/推理时归一化方式不同。
- **解决**: 统一用 cosine 相似度 + L2 归一化。

**坑 2**: 负样本太"硬", 模型学不到东西。
- **解决**: 混合"hard + random"负样本。

**坑 3**: In-batch 负采样在 GPU 显存受限时 batch 小, 负样本不足。
- **解决**: 用更深的队列 (Queue-based, 动态负样本池)。

**坑 4**: 双塔学到的向量空间坍缩 (所有 Item 向量聚在一起)。
- **解决**: 加温度系数, 加大 batch size, 检查 loss 是否真的下降。

**坑 5**: 用户行为序列太长, 双塔编码太慢。
- **解决**: 用聚类/采样压缩序列。

## 10. ANN 向量检索深度

### 10.1 为什么需要 ANN

精确 KNN 计算复杂度 $O(N \cdot d)$, 物品库 $N = 10^9$, $d = 64$ 时单次查询要 $6.4 \times 10^{10}$ 次乘加, 完全不可行。

**ANN 目标**: 用 $O(\log N)$ 或 $O(N^{0.5})$ 复杂度找到近似 TopK, 召回率 > 95%。

### 10.2 距离度量

| 度量 | 公式 | 范围 | 适用 |
| :--- | :--- | :--- | :--- |
| L2 欧氏 | $\sqrt{\sum (x_i - y_i)^2}$ | $[0, \infty)$ | 通用 |
| L1 曼哈顿 | $\sum |x_i - y_i|$ | $[0, \infty)$ | 稀疏向量 |
| Inner Product (IP) | $\sum x_i y_i$ | $(-\infty, \infty)$ | 推荐 (未归一化) |
| Cosine | $1 - \frac{x \cdot y}{\|x\| \|y\|}$ | $[-1, 1]$ | 归一化推荐 |

**推荐默认**: cosine (内积 + 归一化)。

### 10.3 HNSW 详解

**层次化 NSW**: 类似跳表 (Skip List), 多层图叠加。

**每层**: 一个近邻图, 节点数从下到上递减。

**搜索**: 从最上层开始, 贪心跳转, 层层下沉。

```python
import hnswlib

dim = 64
num_elements = 1_000_000

# 建库
index = hnswlib.Index(space='cosine', dim=dim)
index.init_index(max_elements=num_elements, ef_construction=200, M=16)
index.add_items(item_vecs, ids=np.arange(num_elements))

# 检索
index.set_ef(64)  # 搜索宽度, 越大越准但越慢
labels, distances = index.knn_query(query_vec, k=100)
```

**关键参数**:
- **M**: 每节点邻居数, 默认 16 (越大越准但内存大)
- **efConstruction**: 构建时的搜索宽度, 默认 200
- **efSearch**: 查询时的搜索宽度, 默认 64

**优缺点**:
- ✅ 高精度 (Recall > 99%)
- ✅ 适合动态更新 (边增边查)
- ❌ 内存大 (约 1.5x 向量大小)

### 10.4 IVF 详解

**Inverted File Index**: 把向量聚类到 nlist 个簇, 查询时只搜最近的 nprobe 个簇。

```python
import faiss

dim = 64
nlist = 4096
quantizer = faiss.IndexFlatIP(dim)
index = faiss.IndexIVFFlat(quantizer, dim, nlist, faiss.METRIC_INNER_PRODUCT)

# 训练 KMeans
index.train(item_vecs)

# 添加向量
index.add(item_vecs)

# 搜索
index.nprobe = 16  # 搜 16 个最近簇
D, I = index.search(query_vec, k=100)
```

**关键参数**:
- **nlist**: 簇数, 经验值 $\sqrt{N}$
- **nprobe**: 查询簇数, 默认 1, 推荐 8-32

**优缺点**:
- ✅ 训练快, 内存省
- ✅ 适合大规模 (亿级)
- ❌ 精度中等 (Recall ~95%)

### 10.5 PQ 详解

**Product Quantization**: 把 d 维向量切成 m 段, 每段独立 K-Means 到 256 个簇。

```python
m = 8  # 8 个子空间
index = faiss.IndexIVFPQ(quantizer, dim, nlist, m, 8)  # 8 bits per sub-quantizer
index.train(item_vecs)
index.add(item_vecs)
```

**内存**: $d \times 4$ → $m \times 1$ byte, 压缩 $4d/m$ 倍。

**优缺点**:
- ✅ 内存极小
- ✅ 距离查表快
- ❌ 精度损失 (Recall ~90%)

### 10.6 IVF-PQ 组合

工业十亿级标配:

```python
# IVF-PQ: IVF 负责粗筛, PQ 负责压缩
dim, nlist, m = 64, 4096, 8
quantizer = faiss.IndexFlatIP(dim)
index = faiss.IndexIVFPQ(quantizer, dim, nlist, m, 8)

# 训练 (耗时)
index.train(item_vecs)
index.add(item_vecs)
index.nprobe = 16

D, I = index.search(query_vec, k=100)
```

**Anisotropic Vector Quantization**: 学习非各向同性量化, 比 PQ 精度更高。

### 10.9 向量检索的常见坑

**坑 1**: Embedding 没归一化, cosine 检索失败。
- **解决**: 训练时 L2 归一化, 检索时 `IndexFlatIP`。

**坑 2**: IVF 训练集太小, 簇心不具代表性。
- **解决**: 至少 30 × nlist 个样本训练。

**坑 3**: nprobe 太小, 召回率低。
- **解决**: 调整 nprobe, 监控 Recall。

**坑 4**: PQ 子空间数选择不当。
- **解决**: $m$ 必须整除 $d$, 常用 $m = d/4$。

**坑 5**: 向量库更新后, 索引没重建。
- **解决**: 定期重建索引, 或用支持在线更新的索引 (HNSW)。

## 11. SID 生成式召回的细节

### 11.1 SID 生成式召回的动机

传统双塔:
- ❌ 向量空间稠密, 冷启动难
- ❌ 无法"语义泛化" (相似但未共现的物品)
- ❌ 排序能力有限 (只能算相似度)

SID 生成式:
- ✅ 离散 SID 序列, 冷启动友好 (新物品也能生成 SID)
- ✅ 序列生成, 自带排序
- ✅ 语义泛化 (学 SID 共现模式)

### 11.2 TIGER 完整流程

**离线**:
```python
# 1) 训练 RQ-VAE 生成 SID
rq_vae = RQVAE(input_dim=item_emb_dim, num_quantizers=3, codebook_size=256)
rq_vae.train(item_embeddings)
sids = rq_vae.encode(item_embeddings)  # (N, 3) 整数序列

# 2) 训练 Transformer 用户序列 → SID 序列
tiger = TigerTransformer(
    user_seq_len=50,
    sid_len=3,
    vocab_size=256,  # 每个 SID 位置的词汇量
    d_model=128,
    n_layers=4
)

# 训练样本: (用户历史 SID 序列) → (目标物品 SID 序列)
for batch in dataloader:
    user_sids = batch['user_sids']  # (B, 50, 3)
    target_sids = batch['target_sids']  # (B, 3)
    loss = F.cross_entropy(tiger(user_sids), target_sids)
    loss.backward()
    optimizer.step()
```

**在线**:
```python

# 2) 自回归生成 SID 序列 (Beam Search)

```

### 11.3 OneRec (快手 2025)

**端到端生成式推荐**: 直接生成物品 ID (无需 SID 中间表示)。

```python
class OneRec(nn.Module):
    """用户行为序列 → 物品 ID"""
    def __init__(self, num_items, d_model=512, n_layers=12):
        super().__init__()
        # 物品直接用 ID Embedding
        self.item_emb = nn.Embedding(num_items, d_model)
        self.transformer = nn.TransformerDecoder(
            nn.TransformerDecoderLayer(d_model, nhead=8), 
            num_layers=n_layers
        )
        self.head = nn.Linear(d_model, num_items)
    
    def forward(self, user_history):
        # user_history: (B, L)
        h = self.item_emb(user_history)
        # 自回归预测下一物品
        out = self.transformer(h)
        logits = self.head(out)
        return logits  # (B, L, num_items)
```

**关键创新**: 多阶段蒸馏 (10B → 0.5B), 推理延迟 < 30ms。

### 11.4 生成式召回的评估

**Recall@K**:
```python
def generative_recall_at_k(model, user_history, target_items, k=100, beam_size=10):
    """生成式召回的 Recall"""
    generated = model.generate(user_history, beam_size=beam_size)
    return (target_items.unsqueeze(-1) == generated[..., :1]).any(-1).float().mean()
```

**NDCG@K**: 考虑生成顺序。

**多样性**: 生成式召回天然有多样性 (Beam Search 的多条结果)。

## 12. 召回系统的端到端评估

### 12.1 离线指标体系

**核心指标**:

| 指标 | 公式 | 含义 |
| :--- | :--- | :--- |
| Recall@K | $\|\text{TopK} \cap \text{Pos}\| / \|\text{Pos}\|$ | 召回覆盖率 |
| HitRate@K | $\mathbb{1}[\|\text{TopK} \cap \text{Pos}\| > 0]$ | 是否召回到 |
| NDCG@K | $\text{DCG@K} / \text{IDCG@K}$ | 排序质量 |
| Coverage | $\|\bigcup \text{TopK}\| / N$ | 覆盖广度 |
| Diversity | $1 - \text{avg\_sim}$ | 多样性 |

**护栏指标**:
- 新物品召回率
- 长尾物品召回率
- 多样性不能太低

### 12.2 在线指标体系

**核心指标**: CTR, GMV, 时长。

**护栏指标**:
- 用户次日留存
- 负反馈率
- 多样性 (用户主动换一换的比例)

### 12.3 离线在线对齐

**常见不对齐原因**:

| 离线表现 | 在线表现 | 原因 |
| :--- | :--- | :--- |
| Recall@100 高 | CTR 低 | 召回候选分布偏, 精排"无米下锅" |
| AUC 高 | 留存低 | 短期指标涨, 长期体验变差 |
| 新物品召回到 | 用户不喜欢 | 探索流量不够 |

**解决**: 离线评估要分用户群、分物品群, 看长尾指标。

## 15. 召回的常见面试题扩展

### 15.1 双塔为何 User/Item 不能早交互

**标准答案**: 因为 Item 侧要离线建库, 线上只算 User 侧。

**深入答案**: 即使工程上可以让 Item 实时算, 但每个候选都算一次要 O(d²) 或更高, 候选 1000 个就 O(1000d²), 延迟不可接受。

**变体问题**: 双塔的 Item 侧能否用 Cross Feature?

**答案**: 部分可以 (如 Item 自身属性), 但 User-Item 交互特征不能用, 否则破坏"独立编码"假设。

### 15.2 召回为什么不能用 AUC

**标准答案**: 召回有海量负样本, AUC 会被简单负样本主导。

**深入答案**: 
- AUC 衡量"任意一对正负样本的排序", 召回场景 99% 的负样本是"易学的", 1% 是"难学的"
- AUC 看不出模型对难负样本的区分度
- 召回应该看 Recall@K, 直接反映"召回了多少正样本"

**补救**: 用 Recall@K + HitRate@K + 多样性指标。

### 15.3 召回和粗排的本质区别

**标准答案**: 召回用简单模型从亿到万, 粗排用蒸馏的精排模型从万到千。

**深入答案**:
| 维度 | 召回 | 粗排 |
| :--- | :--- | :--- |
| 模型 | 双塔/ItemCF | 蒸馏的精排 |
| 训练目标 | InfoNCE | 拟合精排打分 |
| 候选量 | 亿 → 万 | 万 → 千 |
| 时延 | < 10ms | < 20ms |

**本质**: 召回"找出可能喜欢的", 粗排"排序并筛掉明显不喜欢的"。

### 15.4 Hard Negative 怎么挖

**三种方法**:

**1. 离线挖**: 用一个旧模型召回 TopK, 取 TopK ∩ 未点击 = Hard Negatives。

**2. 在线挖**: 训练时动态用当前模型的 TopK 作为 Hard Negatives。

**3. 增强挖**: 跨域/跨场景挖掘 (如用搜过的 Query 找相关的未点击物品)。

**坑**: 太 hard 的负样本可能是"伪负" (用户没看到, 不是不喜欢)。

### 15.5 多路召回怎么调权重

**离线调**: 在验证集上, 用 Grid Search 找最优权重组合。

**在线调**: 
- Bandit (UCB/Thompson): 自动平衡各路流量
- 简单: 用 Recall 比例作为权重
- 进阶: 用 ESMM / MMoE 学权重

**经验**: 双塔和 ItemCF 通常权重最高 (各 30%), 探索流量固定 5-10%。

### 15.6 如何处理长尾物品召回

**问题**: 90% 的物品曝光 < 10 次, 双塔学不到。

**解决**:
1. **频率归一化**: logQ 校正, 让长尾物品不被压制
2. **频率 Embedding**: FAE 双塔
3. **冷启动流量**: 给长尾物品固定 5-10% 曝光
4. **SID 召回**: 新物品也能生成 SID, 召回友好
5. **多任务**: 用头部物品学知识, 迁移到长尾

### 15.7 向量库如何处理更新

**全量重建**:
- 周期: 天级
- 优点: 一致性好
- 缺点: 算力大, 中间有 downtime

**增量更新**:
- 周期: 分钟级
- 优点: 实时性好
- 缺点: HNSW 支持, IVF 不支持

**实践**: 用 HNSW 做实时更新, IVF-PQ 做天级全量。

### 15.8 向量检索的召回率与精排不一致

**症状**: 向量召回率 > 95%, 但精排 AUC 不涨。

**原因**: 向量召回的"容易召回到" ≠ "应该召回到"。

**解决**:
1. 分析长尾物品召回率
2. 看精排对召回候选的"打分分布"
3. 调整双塔的温度系数

## 21. 双塔模型训练的高级细节

### 21.1 Batch Size 与温度系数的 scaling

**关键观察**: 双塔训练中, batch size 与温度系数有强耦合关系。

**经验法则**:
- batch size 翻倍 → 温度系数适当降低
- 例如: B=1024 用 τ=0.07, B=4096 用 τ=0.05

**理论解释**: 
- 大 batch 意味着更多负样本, 分布更尖锐
- 小温度可以保持分布的相对尖锐度

```python
def adaptive_temp(batch_size, base_temp=0.07, base_batch=1024):
    """根据 batch size 自适应调整温度"""
    return base_temp * (base_batch / batch_size) ** 0.5
```

### 21.2 共享 Embedding 的双塔

**动机**: 召回和精排的物品 Embedding 应该共享, 否则召回-精排的目标不对齐。

```python
class SharedEmbTwoTower(nn.Module):
    def __init__(self, num_items, dim):
        super().__init__()
        self.item_emb = nn.Embedding(num_items, dim)  # 共享
        self.user_tower = nn.Sequential(...)  # 不共享
        # 精排侧的 Item Tower 也用 self.item_emb
        self.coarse_tower = nn.Sequential(...)
```

**实践**: 召回和粗排共用 Item Embedding, 召回单独 User Tower, 粗排单独 Coarse Tower。

### 21.3 双塔的过拟合与正则化

**过拟合信号**:
- 训练 Loss 持续下降, 验证 Recall 停滞
- 物品向量空间坍缩 (cosine 相似度过高)

**正则化方法**:

| 方法 | 公式 | 效果 |
| :--- | :--- | :--- |
| L2 | $\lambda \|W\|^2$ | 防 Embedding 过大 |
| Dropout | 随机失活 | 防过拟合 |
| Embedding noise | $E + \epsilon$, $\epsilon \sim \mathcal{N}(0, \sigma^2)$ | 防过拟合 |
| 梯度裁剪 | $\|g\| \le \tau$ | 防爆炸 |
| Early stop | 验证集 Recall 下降时停止 | 防过拟合 |

```python
# 双塔训练的正则化
def train_step(u, i, model, optimizer):
    u_emb, i_emb = model(u, i)
    
    # InfoNCE Loss
    logits = u_emb @ i_emb.t() / 0.05
    labels = torch.arange(u.size(0))
    loss_contrast = F.cross_entropy(logits, labels)
    
    # L2 正则 (只对 Embedding)
    loss_reg = (model.user_tower[-1].weight ** 2).sum() * 1e-5
    
    loss = loss_contrast + loss_reg
    loss.backward()
    optimizer.step()
    optimizer.zero_grad()
```

## 22. ANN 索引的选择决策

### 22.1 决策树

```
你的物品库多大?
├── < 100万 → Flat (精确 KNN, 简单)
├── 100万 - 1亿 → HNSW (高 Recall, 内存大)
├── 1亿 - 10亿 → IVF-PQ (省内存, 中等 Recall)
└── > 10亿 → IVF-PQ + 分布式 (Milvus / ScaNN)

你的延迟要求?
├── < 1ms → GPU 索引 (Faiss GPU)
├── 1-10ms → HNSW (内存索引)
└── > 10ms → IVF-PQ / ScaNN

你的召回率要求?
├── > 99% → HNSW
├── 95-99% → IVF
└── < 95% → IVF-PQ
```

### 22.2 各种索引的对比

| 索引 | 内存/向量 | 速度 (QPS) | Recall@10 | 适用规模 |
| :--- | :--- | :--- | :--- | :--- |
| Flat | 4 bytes × d | 1000 | 100% | < 100万 |
| HNSW | 16-32 bytes × d | 5000 | 99%+ | 1千万 - 1亿 |
| IVFFlat | 4 bytes × d | 3000 | 95%+ | 1亿+ |
| IVFPQ | 1 byte × d / 4 | 5000 | 90%+ | 10亿+ |
| ScaNN | 2-4 bytes × d | 8000 | 95%+ | 10亿+ |

### 22.3 HNSW vs IVF-PQ 的工程权衡

| 维度 | HNSW | IVF-PQ |
| :--- | :--- | :--- |
| 内存 | 高 (16x) | 低 (1x) |
| 速度 | 快 | 快 |
| Recall | 高 (99%) | 中 (90%) |
| 训练 | 无 | 有 (KMeans + PQ) |

### 23.4 召回服务的缓存策略

**多级缓存**:

```
请求 → Redis (热点用户) → 本地 (LRU) → Faiss (兜底)
         ↓ miss
         ↓ 本地查询
         ↓ miss
         ↓ Faiss 查询
```

```python
import functools
import hashlib

@functools.lru_cache(maxsize=10000)
def cached_recall(user_id, context_hash):
    """本地 LRU 缓存"""
    return faiss_index.search(...)

async def recall(user_id, context):
    ctx_hash = hashlib.md5(str(context).encode()).hexdigest()
    
    # 1) Redis
    cached = await redis.get(f"recall:{user_id}:{ctx_hash}")
    if cached:
        return json.loads(cached)
    
    # 2) 本地 LRU
    result = cached_recall(user_id, ctx_hash)
    
    # 3) 写回 Redis
    await redis.set(f"recall:{user_id}:{ctx_hash}", json.dumps(result), ex=60)
    return result
```

```python
def evaluate_recall(model, valid_data, item_pool, k=100):
    """召回评估: Recall@K, HitRate@K"""
    recalls, hits = [], []
    
    for user in valid_data['user_id'].unique():
        history = valid_data[valid_data['user_id'] == user]['history'].iloc[0]
        targets = valid_data[valid_data['user_id'] == user]['target_items'].iloc[0]
        
        # 1) 编码 User 向量
        user_emb = model.encode_user(history)
        
        # 2) 全量检索
        D, I = faiss_index.search(user_emb, k)
        
        # 3) 计算 Recall
        hit = len(set(I) & set(targets))
        recall = hit / len(targets)
        hit_rate = 1 if hit > 0 else 0
        
        recalls.append(recall)
        hits.append(hit_rate)
    
    return np.mean(recalls), np.mean(hits)
```

### 24.3 高级评估指标

**NDCG@K**:

```python
def ndcg_at_k(predictions, labels, k=100):
    # predictions: (N, num_items), labels: (N, num_items) 0/1
    top_k_pred = predictions.topk(k, dim=-1).indices
    top_k_labels = labels.gather(-1, top_k_pred)
    
    # DCG
    discounts = 1.0 / torch.log2(torch.arange(2, k+2))
    dcg = (top_k_labels.float() * discounts).sum(-1)
    
    # IDCG
    ideal = labels.topk(k, dim=-1).values
    idcg = (ideal.float() * discounts).sum(-1)
    
    ndcg = (dcg / idcg.clamp(min=1e-10)).mean()
    return ndcg
```

**MRR (Mean Reciprocal Rank)**:

```python
def mrr(predictions, labels):
    """第一个正确答案的倒数排名"""
    sorted_pred = predictions.argsort(dim=-1, descending=True)
    ranks = []
    for i in range(predictions.size(0)):
        for rank, idx in enumerate(sorted_pred[i]):
            if labels[i, idx] == 1:
                ranks.append(1.0 / (rank + 1))
                break
    return np.mean(ranks)
```

**覆盖率**:

```python
def coverage(all_predictions, num_items):
    """所有用户召回到的不同物品数 / 总物品数"""
    unique_items = set()
    for preds in all_predictions:
        unique_items.update(preds.tolist())
    return len(unique_items) / num_items
```

**多样性**:

```python
def diversity(predictions, item_emb_dict):
    """用户内召回物品的平均相似度的倒数"""
    diversities = []
    for preds in predictions:
        embs = np.array([item_emb_dict[i] for i in preds])
        sim = embs @ embs.T
        avg_sim = (sim.sum() - sim.trace()) / (len(preds) * (len(preds) - 1))
        diversities.append(1 - avg_sim)
    return np.mean(diversities)
```

### 25.1 多兴趣召回 (MIND)

**动机**: 一个用户可能有多个兴趣, 单向量表示太粗。

```python
class MIND(nn.Module):
```

### 25.3 因果召回 (CausCF)

**问题**: 双塔学的是"看到-点击"的相关性, 但用户没看到的物品可能不是不喜欢, 只是没机会。

**解决**: 用 IPS (Inverse Propensity Score) 校正曝光偏差。

$$\hat{L}_{\text{IPS}} = \frac{1}{N}\sum_i \frac{r_i \cdot \pi(x_i)}{\hat{e}(x_i)}$$

其中 $\hat{e}(x_i)$ 是物品的曝光倾向性 (从随机流量估计)。

**实现**: 用 5-10% 随机流量估算曝光概率, 再校正召回损失。

## 26. 召回与其他环节的协同

### 26.1 召回-粗排的协同

**目标**: 粗排要"承接召回的 TopK", 而不是"重新排序"。

**方法**: 蒸馏召回 TopK 的顺序。

```python
def coarse_distill_loss(coarse_logits, recall_logits, true_labels):
    """粗排蒸馏: 学召回 TopK 的顺序"""
    # 召回的 TopK 顺序作为软标签
    recall_probs = F.softmax(recall_logits, dim=-1)
    coarse_probs = F.log_softmax(coarse_logits, dim=-1)
    
    # KL 散度
    loss_distill = F.kl_div(coarse_probs, recall_probs, reduction='batchmean')
    
    # 真实标签的硬损失
    loss_true = F.binary_cross_entropy_with_logits(coarse_logits, true_labels)
    
    return 0.5 * loss_distill + 0.5 * loss_true
```

### 26.2 召回-精排的协同

**目标**: 召回-精排的"目标对齐"。

**问题**: 双塔用 InfoNCE, 精排用 BCE, 两者不完全对齐。

**解决**: 双塔蒸馏精排打分。

```python
def recall_distill_fine_loss(recall_logits, fine_logits, fine_labels):
    """召回蒸馏精排"""
    # 精排打分作为软标签
    fine_probs = torch.sigmoid(fine_logits)
    recall_probs = torch.sigmoid(recall_logits)
    
    # KL 散度
    loss = F.binary_cross_entropy(recall_probs, fine_probs.detach())
    
    return loss
```

### 26.3 召回-重排的协同

**目标**: 重排要考虑"召回的多样性"。

**问题**: 如果召回了 5 个相似物品, 重排再怎么调也是 5 个相似的。

**解决**: 多样性召回 (MMR), 或者重排时考虑"召回源平衡"。

```python
def recall_with_diversity(model, query, top_k=100, lambda_div=0.3):
    """多样性召回 (MMR)"""
    candidates = model.recall(query, top_k=200)  # 先取 200
    selected = []
    
    while len(selected) < top_k:
        best_score = -1
        best_idx = -1
        for i, c in enumerate(candidates):
            rel = c['score']
            # 与已选的最大相似度
            max_sim = max([cosine_sim(c['emb'], s['emb']) for s in selected], default=0)
            mmr = lambda_div * rel - (1 - lambda_div) * max_sim
            if mmr > best_score:
                best_score = mmr
                best_idx = i
        selected.append(candidates.pop(best_idx))
    
    return selected
```

## 27. 召回的代码实现模板

### 27.1 完整双塔训练代码

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import Dataset, DataLoader

class TwoTowerDataset(Dataset):
    """双塔训练数据集"""
    def __init__(self, user_features, item_features, labels):
        self.user_features = user_features
        self.item_features = item_features
        self.labels = labels
    
    def __len__(self):
        return len(self.labels)
    
    def __getitem__(self, idx):
        return (
            self.user_features[idx],
            self.item_features[idx],
            self.labels[idx]
        )

class TwoTower(nn.Module):
    """完整双塔模型"""
    def __init__(self, user_dim, item_dim, embed_dim=64):
        super().__init__()
        self.user_tower = nn.Sequential(
            nn.Linear(user_dim, 256), nn.ReLU(),
            nn.BatchNorm1d(256),
            nn.Linear(256, 128), nn.ReLU(),
            nn.Linear(128, embed_dim)
        )
        self.item_tower = nn.Sequential(
            nn.Linear(item_dim, 256), nn.ReLU(),
            nn.BatchNorm1d(256),
            nn.Linear(256, 128), nn.ReLU(),
            nn.Linear(128, embed_dim)
        )
    
    def forward(self, user_feat, item_feat):
        u = F.normalize(self.user_tower(user_feat), dim=-1)
        i = F.normalize(self.item_tower(item_feat), dim=-1)
        return u, i

def train_two_tower(model, train_loader, val_loader, epochs=10, lr=1e-3):
    """完整训练流程"""
    optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    
    for epoch in range(epochs):
        # Train
        model.train()
        for u, i, y in train_loader:
            u_emb, i_emb = model(u, i)
            
            # InfoNCE 损失 (in-batch)
            logits = u_emb @ i_emb.t() / 0.05
            labels = torch.arange(u.size(0))
            loss = F.cross_entropy(logits, labels)
            
            optimizer.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            optimizer.step()
        
        # Validate
        model.eval()
        recall = evaluate_recall(model, val_loader)
        print(f"Epoch {epoch}: Recall@100={recall:.4f}")

def evaluate_recall(model, val_loader, k=100):
    """评估 Recall@K"""
    model.eval()
    all_user_embs, all_item_embs, all_labels = [], [], []
    
    with torch.no_grad():
        for u, i, y in val_loader:
            u_emb, i_emb = model(u, i)
            all_user_embs.append(u_emb)
            all_item_embs.append(i_emb)
            all_labels.append(y)
    
    user_embs = torch.cat(all_user_embs)  # (N, d)
    item_embs = torch.cat(all_item_embs)  # (M, d)
    labels = torch.cat(all_labels)  # (N, M)
    
    # 检索 TopK
    top_k = (user_embs @ item_embs.t()).topk(k, dim=-1).indices  # (N, k)
    
    # 计算 Recall
    hits = labels.gather(-1, top_k).sum(-1)  # (N,)
    total_pos = labels.sum(-1)  # (N,)
    recall = (hits / total_pos.clamp(min=1)).mean()
    
    return recall.item()
```

### 27.2 Faiss 索引完整代码

```python
import faiss
import numpy as np
from typing import Tuple

class FaissIndex:
    """Faiss 索引封装"""
    
    def __init__(self, dim, index_type='IVF-PQ'):
        self.dim = dim
        self.index_type = index_type
        self.index = None
    
    def build(self, vectors: np.ndarray, nlist=4096, m=8):
        """构建索引"""
        if self.index_type == 'Flat':
            self.index = faiss.IndexFlatIP(self.dim)
        elif self.index_type == 'IVF-Flat':
            quantizer = faiss.IndexFlatIP(self.dim)
            self.index = faiss.IndexIVFFlat(quantizer, self.dim, nlist, faiss.METRIC_INNER_PRODUCT)
        elif self.index_type == 'IVF-PQ':
            quantizer = faiss.IndexFlatIP(self.dim)
            self.index = faiss.IndexIVFPQ(quantizer, self.dim, nlist, m, 8)
        else:
            raise ValueError(f"Unknown index type: {self.index_type}")
        
        # 训练
        self.index.train(vectors)
        # 添加
        self.index.add(vectors)
    
    def search(self, query: np.ndarray, k=100, nprobe=16) -> Tuple[np.ndarray, np.ndarray]:
        """检索 TopK"""
        if self.index_type.startswith('IVF'):
            self.index.nprobe = nprobe
        D, I = self.index.search(query, k)
        return D, I
    
    def save(self, path):
        """保存索引"""
        faiss.write_index(self.index, path)
    
    def load(self, path):
        """加载索引"""
        self.index = faiss.read_index(path)

# 使用
dim = 64
num_items = 1_000_000

# 模拟数据
item_vecs = np.random.randn(num_items, dim).astype('float32')
faiss.normalize_L2(item_vecs)

faiss.normalize_L2(query)

# 构建

# 检索
```
