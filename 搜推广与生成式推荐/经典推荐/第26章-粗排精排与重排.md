## 2. 粗排: 蒸馏精排的轻量模型

粗排要"又快又准": 常用**双塔或轻量交叉模型**, 用**精排打分做蒸馏目标**(让粗排逼近精排排序), 兼顾一致性。

```python
# 粗排蒸馏: 用精排 logits 作软标签
def distill_loss(coarse_logit, fine_logit_teacher, y_true, alpha=0.5):
    hard = F.binary_cross_entropy_with_logits(coarse_logit, y_true)
    soft = F.mse_loss(coarse_logit, fine_logit_teacher.detach())   # 对齐精排
    return alpha*hard + (1-alpha)*soft
```

## 3. 精排: 多目标融合与校准

### 3.1 多目标融合

精排常同时预估 CTR、CVR、时长等(MMoE/PLE, 见 [第04章](第04章-多任务学习.md))。线上用**融合公式**排序:

$$\text{score} = \text{pCTR}^{\alpha} \cdot \text{pCVR}^{\beta} \cdot (1 + \text{时长})^{\gamma} \cdots$$

指数权重按业务目标调; 也可用帕累托/强化学习自动搜权重。

### 3.2 校准(Calibration)

预估的 pCTR 要**数值准确**(不只是排序对), 才能用于出价/融合。常用 **保序回归 / Platt scaling**:

```python
# 保序回归校准: 保持单调, 把预估概率映射到真实频率
from sklearn.isotonic import IsotonicRegression
cal = IsotonicRegression(out_of_bounds='clip')
cal.fit(pred_ctr, actual_click)          # 拟合 预估→真实
calibrated = cal.transform(pred_ctr)
```

> 为什么要校准? 精排多目标融合、广告 eCPM 出价都依赖**绝对概率值**, 不校准会系统性偏差。

## 4. 重排: 上下文与多样性

精排逐个打分(point-wise)忽略了**曝光列表内的相互影响**。重排考虑上下文:

### 4.1 多样性 - MMR

边际相关性: 每步选"相关性高且与已选集不相似"的:

$$\text{MMR} = \arg\max_{i}\big[\lambda \cdot rel(i) - (1-\lambda)\max_{j\in S}sim(i,j)\big]$$

```python
def mmr(cand, rel, sim, k, lam=0.7):
    selected, pool = [], list(cand)
    while len(selected) < k and pool:
        best, bs = None, -1e9
        for i in pool:
            div = max((sim[i][j] for j in selected), default=0)
            s = lam*rel[i] - (1-lam)*div
            if s > bs: bs, best = s, i
        selected.append(best); pool.remove(best)
    return selected
```

### 4.2 DPP(行列式点过程)

用核矩阵行列式度量子集的"质量×多样性", 选行列式最大的子集。理论优雅, 工业用贪心近似。

### 4.3 上下文重排 - PRM

**PRM(Personalized Re-ranking)**: 用 Transformer 编码整个候选列表, 建模 item 间相互影响后重新打分。这是重排的 SOTA 方向, 与 GR 的 list 生成思想相通。

## 5. 全链路一致性

- 召回/粗排/精排目标要**级联一致**(粗排逼近精排, 精排逼近业务)。
- 各级样本分布不同(SSB, sample selection bias): 精排只见曝光样本, 粗排要见更广候选。用**全空间建模(ESMM)** 或负采样纠偏。

## 7. 三级排序的算力经济学

### 7.1 漏斗的算力预算

一个真实的工业推荐系统, 假设:
- QPS = 10万
- 每个用户候选从亿级 → 10 个曝光

**算力预算** (单请求):

| 层级 | 候选量 | 单次耗时 | 总耗时 | 占总算力 |
| :--- | :--- | :--- | :--- | :--- |
| 召回 | 10000 | 0.05ms | 500ms | 30% |
| 粗排 | 1000 | 0.05ms | 50ms | 5% |
| 精排 | 200 | 1ms | 200ms | 30% |
| 重排 | 50 | 1ms | 50ms | 5% |
| 业务逻辑 | - | - | - | 30% |

**关键洞察**:
- 召回虽然候选多, 但每个候选打分简单 (双塔)
- 精排候选少但打分复杂 (DIN + MMoE)
- 业务逻辑 (出价/规则) 占比很大

### 7.2 三层的目标函数差异

```text
召回:  max Recall@K
粗排:  max Coarse-AUC (逼近精排 AUC 的排序能力)
精排:  max Fine-AUC / 多目标 AUC
重排:  max NDCG / 多样性 / 业务约束
```

**全链路目标一致性**:
- 召回要让"精排选出的"尽可能在前
- 粗排要让"精排选出的"排在前面
- 精排要让"用户喜欢的"打分高
- 重排要让"列表整体"满足约束

**常见目标不对齐**:
- 召回按"点击率"训, 精排按"转化率"训 → 推荐了高点击低转化物品
- 粗排蒸馏精排的 AUC, 但业务关心 GMV → 偏离业务

### 7.3 各层的"损失函数"差异

| 层级 | 损失函数 | 训练样本 | 标签 |
| :--- | :--- | :--- | :--- |
| 召回 | InfoNCE / BPR | 点击 + 负采样 | 隐式 |
| 粗排 | MSE (蒸馏精排) + BCE | 精排打分 + 真实标签 | 混合 |
| 精排 | BCE / 多任务 BCE | 点击 / 转化 / 时长 | 显式 |
| 重排 | Listwise NLL | 列表排序 | 序列 |

### 7.4 粗排 vs 精排:工程视角的本质差异

**粗排的"粗"不是"粗略", 而是"快速"**:
- 模型小 (参数量 1/10)
- 特征少 (只用强特征)
- 时延低 (< 10ms)
- 候选量从 1万 → 1千

**精排的"精"是"精确"**:
- 模型大 (DIN/MMoE)
- 特征多 (全量特征)
- 时延较高 (< 50ms)
- 候选量从 1千 → 100

### 8.1 粗排的历史演进

**阶段 1 (2015-2018): LR 粗排**

**阶段 2 (2018-2020): 双塔粗排**

```python
class CoarseTwoTower(nn.Module):
    def __init__(self, num_items, embed_dim=32):
        super().__init__()
        # 共享 Item Embedding
        self.item_emb = nn.Embedding(num_items, embed_dim)
        self.user_tower = nn.Sequential(
            nn.Linear(user_dim, 128), nn.ReLU(),
            nn.Linear(128, embed_dim)
        )

    def forward(self, user_feat, item_ids):
        # Item 向量用共享 Embedding
        item_vec = self.item_emb(item_ids)
        # User 向量快速算
        user_vec = self.user_tower(user_feat)
        return (user_vec * item_vec).sum(-1)
```

**阶段 3 (2020-2023): 蒸馏精排的轻量模型**

```python
class CoarseDistilled(nn.Module):
    """粗排蒸馏精排: 用精排打分做软标签"""
    def __init__(self, num_items, num_features, embed_dim=32):
        super().__init__()
        self.embeddings = nn.ModuleList([
            nn.Embedding(num_feat, embed_dim) for num_feat in num_features
        ])
        self.mlp = nn.Sequential(
            nn.Linear(len(num_features) * embed_dim, 128), nn.ReLU(),
            nn.Linear(128, 64), nn.ReLU(),
            nn.Linear(64, 1)
        )

    def forward(self, features):
        embs = [emb(f) for emb, f in zip(self.embeddings, features)]
        x = torch.cat(embs, dim=-1)
        return self.mlp(x).squeeze(-1)

def coarse_distill_loss(coarse_logits, fine_logits, true_labels, alpha=0.5):
    """粗排蒸馏损失"""
    # 硬标签 (真实点击)
    loss_hard = F.binary_cross_entropy_with_logits(coarse_logits, true_labels)
    # 软标签 (精排打分)
    soft_target = torch.sigmoid(fine_logits).detach()
    loss_soft = F.binary_cross_entropy_with_logits(coarse_logits, soft_target)
    return alpha * loss_hard + (1 - alpha) * loss_soft
```

**阶段 4 (2023+): COLD (阿里) 等专用粗排模型**

COLD 是阿里 2020 年的工业粗排模型, 专门为粗排设计。

```python
class COLD(nn.Module):
    """阿里 COLD 粗排"""
    def __init__(self, num_features, embed_dim=32):
        super().__init__()
        # 共享 Embedding
        self.embeddings = nn.ModuleList([
            nn.Embedding(num_feat, embed_dim) for num_feat in num_features
        ])
        # 双线性交叉 (代替 DNN 节省算力)
        self.bilinear = BilinearInteraction(embed_dim)
        # 轻量输出
        self.head = nn.Sequential(
            nn.Linear(embed_dim, 64), nn.ReLU(),
            nn.Linear(64, 1)
        )

    def forward(self, features):
        embs = [emb(f) for emb, f in zip(self.embeddings, features)]
        embs = torch.stack(embs, dim=1)  # (B, F, d)
        # 双线性交叉 (轻量)
        cross = self.bilinear(embs)  # (B, d)
        return self.head(cross).squeeze(-1)

class BilinearInteraction(nn.Module):
    """双线性交互: 比 MLP 节省参数"""
    def __init__(self, dim):
        super().__init__()
        self.W = nn.Parameter(torch.randn(dim, dim) * 0.01)

    def forward(self, embs):
        # (B, F, d) -> (B, d)
        # embs @ W @ embs.T 形式
        B, F, d = embs.shape
        cross = embs @ self.W  # (B, F, d)
        cross = (cross * embs).sum(dim=1)  # (B, d)
        return cross / F
```

### 8.2 粗排的特征选择

**粗排特征 vs 精排特征**:

| 特征 | 粗排 | 精排 |
| :--- | :--- | :--- |
| User ID Embedding | ✅ | ✅ |
| Item ID Embedding | ✅ | ✅ |
| User Profile (年龄/性别) | ✅ | ✅ |
| Item Profile (类目/品牌) | ✅ | ✅ |
| Cross Feature (用户-物品) | ❌ (太重) | ✅ |
| 行为序列 | 简化版 | 全量 |
| 实时特征 | 简版 | 全量 |
| Context (位置/时间) | ✅ | ✅ |

**经验**: 粗排只用"通用特征" + "基础 cross", 精排才用"复杂 cross"。

### 8.3 粗排的蒸馏策略

**蒸馏方式对比**:

| 蒸馏方式 | 优点 | 缺点 |
| :--- | :--- | :--- |
| Logit 蒸馏 | 简单, 通用 | 只学打分, 不学排序 |
| Feature 蒸馏 | 学中间表示 | 强耦合, 难迁移 |
| Ranking 蒸馏 | 学排序顺序 | 实现复杂 |
| Listwise 蒸馏 | 学列表信息 | 训练慢 |

**实践**: Logit 蒸馏 + 软硬标签混合最常用。

```python
class MultiDistillLoss(nn.Module):
    """多种蒸馏方式的组合"""
    def __init__(self, alpha=0.3, beta=0.3, gamma=0.4):
        super().__init__()
        self.alpha = alpha
        self.beta = beta
        self.gamma = gamma

    def forward(self, coarse_logits, fine_logits, true_labels):
        # 1) 硬标签损失
        loss_hard = F.binary_cross_entropy_with_logits(coarse_logits, true_labels)

        # 2) Logit 蒸馏 (KL 散度)
        fine_probs = torch.sigmoid(fine_logits).detach()
        coarse_probs = torch.sigmoid(coarse_logits)
        loss_kd = F.binary_cross_entropy(coarse_probs, fine_probs)

        # 3) Ranking 蒸馏 (Listwise)
        # 假设 batch 内是同一用户的多个候选
        # 排序一致性损失
        coarse_rank = coarse_logits.argsort(dim=-1, descending=True)
        fine_rank = fine_logits.argsort(dim=-1, descending=True)
        # Kendall's tau 损失 (简化)
        loss_rank = F.mse_loss(coarse_rank.float(), fine_rank.float().detach())

        return self.alpha * loss_hard + self.beta * loss_kd + self.gamma * loss_rank
```

### 8.5 粗排的常见坑

**坑 1: 粗排 AUC 比精排还高**

**原因**: 粗排见过的样本分布和精排不同。

**解决**: 严格用同一份样本训练, 否则粗排蒸馏无意义。

**坑 2: 蒸馏后粗排 AUC 涨, 但精排 AUC 反而降**

**原因**: 粗排蒸馏过度, 过拟合到精排, 但偏离真实分布。

**解决**: 软标签权重 0.3-0.5, 不要 0.8+。

**坑 3: 粗排延迟过高, 比精排还慢**

**原因**: 模型没压缩, 特征没简化。

**解决**: 用 COLD 这种专用轻量模型, 而非直接精简精排。

```python
class LR(nn.Module):
    """逻辑回归精排"""
    def __init__(self, num_features):
        super().__init__()
        self.weights = nn.Parameter(torch.zeros(num_features))

        return torch.sigmoid((x * self.weights).sum(-1) + self.bias)
```

```python
class DIN(nn.Module):
    """Deep Interest Network"""
    def __init__(self, num_items, embed_dim=32):
        super().__init__()
        self.item_emb = nn.Embedding(num_items, embed_dim)
        self.user_feature_emb = nn.Linear(user_dim, embed_dim)
        # Local Activation Unit (Attention)
        self.attention = nn.Sequential(
            nn.Linear(4 * embed_dim, 80), nn.ReLU(),
            nn.Linear(80, 1)
        )
        self.mlp = nn.Sequential(
            nn.Linear(embed_dim * 3, 200), nn.ReLU(),
            nn.Linear(200, 80), nn.ReLU(),
            nn.Linear(80, 1)
        )

    def forward(self, user_features, history, target_item):
        # history: (B, L) 历史点击物品
        # target_item: (B,) 目标物品

        target_emb = self.item_emb(target_item)  # (B, d)
        history_emb = self.item_emb(history)  # (B, L, d)

        # Attention 权重
        # target_emb: (B, 1, d), history_emb: (B, L, d)
        target_expanded = target_emb.unsqueeze(1).expand(-1, history_emb.size(1), -1)
        att_input = torch.cat([
            history_emb, target_expanded,
            history_emb * target_expanded,
            history_emb - target_expanded
        ], dim=-1)
        att_weights = self.attention(att_input).squeeze(-1)  # (B, L)
        att_weights = F.softmax(att_weights, dim=-1)

        # 加权历史
        user_interest = (history_emb * att_weights.unsqueeze(-1)).sum(dim=1)  # (B, d)

        # 拼接
        x = torch.cat([
            user_features, user_interest, target_emb
        ], dim=-1)

        return torch.sigmoid(self.mlp(x).squeeze(-1))
```

```python
class MMoE(nn.Module):
    """Multi-gate Mixture of Experts"""
    def __init__(self, num_features, num_experts=4, num_tasks=2):
        super().__init__()
        self.embeddings = nn.ModuleList([
            nn.Embedding(num_feat, 16) for num_feat in num_features
        ])
        embed_dim = 16 * len(num_features)

        # Experts (共享)
        self.experts = nn.ModuleList([
            nn.Sequential(nn.Linear(embed_dim, 64), nn.ReLU(), nn.Linear(64, 64))
            for _ in range(num_experts)
        ])

        # Gates (每个任务一个)
        self.gates = nn.ModuleList([
            nn.Sequential(nn.Linear(embed_dim, num_experts), nn.Softmax(dim=-1))
            for _ in range(num_tasks)
        ])

        # Towers
        self.towers = nn.ModuleList([
            nn.Sequential(nn.Linear(64, 32), nn.ReLU(), nn.Linear(32, 1))
            for _ in range(num_tasks)
        ])

    def forward(self, features):
        embs = [emb(f) for emb, f in zip(self.embeddings, features)]
        x = torch.cat(embs, dim=-1)

        # Expert 输出
        expert_outputs = torch.stack([e(x) for e in self.experts], dim=1)  # (B, E, d)

        # 每个任务的输出
        outputs = []
        for gate, tower in zip(self.gates, self.towers):
            gate_weights = gate(x).unsqueeze(-1)  # (B, E, 1)
            task_input = (expert_outputs * gate_weights).sum(dim=1)  # (B, d)
            outputs.append(tower(task_input))

        return outputs  # [task1_logit, task2_logit, ...]
```

### 9.2 多目标融合 (Multi-Task Learning)

**典型任务组合**:

| 场景 | 任务 |
| :--- | :--- |
| 电商 | CTR + CVR + GMV |
| 信息流 | CTR + 时长 + 互动(点赞/评论) |
| 视频 | CTR + 完播率 + 互动 |
| 直播 | CTR + 观看时长 + 礼物 |

**融合公式 (经典)**:

```python
def fusion_score(p_ctr, p_cvr, watch_time, alpha=0.7, beta=0.3, gamma=0.1):
    """经典加权融合"""
    return p_ctr ** alpha * p_cvr ** beta * (1 + watch_time / 100) ** gamma
```

**进阶融合**: 帕累托搜索、强化学习搜索权重。

### 9.3 精排的多目标损失

```python
class MultiTaskLoss(nn.Module):
    """多任务损失加权"""
    def __init__(self, task_names, weights=None, use_uncertainty=True):
        super().__init__()
        if weights is None:
            weights = [1.0] * len(task_names)
        self.task_names = task_names
        self.weights = nn.Parameter(torch.tensor(weights, dtype=torch.float32))
        # Uncertainty Weighting (Kendall et al. 2018)
        self.log_vars = nn.Parameter(torch.zeros(len(task_names)))

    def forward(self, task_logits, task_labels):
        total_loss = 0
        for i, (name, logit, label) in enumerate(zip(self.task_names, task_logits, task_labels)):
            # 任务损失
            task_loss = F.binary_cross_entropy_with_logits(logit, label)
            # Uncertainty weighting
            precision = torch.exp(-self.log_vars[i])
            total_loss += precision * task_loss + self.log_vars[i]
        return total_loss
```

**自动调权**:

| 方法 | 公式 | 优点 | 缺点 |
| :--- | :--- | :--- | :--- |
| Uncertainty | $\exp(-s) L + s$ | 端到端 | 收敛慢 |
| GradNorm | 动态调权重 | 平衡训练速度 | 复杂 |
| DWA | 任务损失下降速度 | 简单 | 不稳定 |
| 手动调 | 业务经验 | 直观 | 难调 |

### 9.4 精排的校准 (Calibration)

**为什么需要校准**:
- 多目标融合依赖**绝对概率** (不是排序)
- 广告出价依赖**真实 CTR** (eCPM = pCTR × bid)
- 强化学习依赖**准确 reward**

#### 9.4.4 Histogram Binning

```python
def histogram_calibration(pred_probs, true_labels, n_bins=10):
    """直方图分桶校准"""
    bin_boundaries = np.linspace(0, 1, n_bins + 1)
    bin_lowers = bin_boundaries[:-1]
    bin_uppers = bin_boundaries[1:]

    calibrated = np.zeros_like(pred_probs)
    for bin_lower, bin_upper in zip(bin_lowers, bin_uppers):
        in_bin = (pred_probs > bin_lower) & (pred_probs <= bin_upper)
        if in_bin.sum() > 0:
            calibrated[in_bin] = true_labels[in_bin].mean()
    return calibrated
```

### 9.5 精排的常见坑

**坑 1: 训练 AUC 涨, 线上 AUC 不涨**

**原因**: 训练数据有穿越, 或者特征不一致。

**解决**: 严格按时间切分, 离线/在线特征处理统一。

**坑 2: 多任务 CTR 涨, GMV 跌**

**原因**: 模型学了"高点击低转化"物品。

**解决**: 加 ESMM (整个空间建模), 让 CVR 学习点击-转化全链路。

```python
class ESMM(nn.Module):
    """Entire Space Multi-task Model"""
    def __init__(self, ...):
        super().__init__()
        self.ctr_tower = CTRTower(...)
        self.ctcvr_tower = CTCVRTower(...)  # 同时预测 click 和 conversion

    def forward(self, x):
        # pCTR = click 概率
        pctr = self.ctr_tower(x)
        # pCTCVR = click 且 conversion 概率
        pctcvr = self.ctcvr_tower(x)
        # pCVR = conversion / click
        pcvr = pctcvr / pctr.clamp(min=1e-6)
        return pctr, pcvr, pctcvr

def esmm_loss(pctr, pcvr, pctcvr, click_label, conversion_label):
    """ESMM 损失"""
    # 在 click 样本上算 pCTR
    loss_ctr = F.binary_cross_entropy(pctr, click_label)
    # 在曝光样本上算 pCTCVR (全空间建模, 解决 SSB)
    loss_ctcvr = F.binary_cross_entropy(pctcvr, conversion_label)
    return loss_ctr + loss_ctcvr
```

**坑 3: 校准后业务指标反而跌**

**原因**: 校准改变了排序 (理论上不应该)。

**解决**: 用保序回归, 保证排序不变。

## 10. 重排的深度展开

### 10.1 为什么需要重排

**Pointwise 精排的局限**:
- 每个候选独立打分, 忽略列表内**相互影响**
- 不考虑**多样性**
- 不考虑**业务约束** (广告配额、合规)
- 不考虑**用户体验** (重复、单调)

**重排的核心目标**: 在精排基础上, 加入**列表级**优化。

### 10.2 重排的经典方法

#### 10.2.1 MMR (Maximal Marginal Relevance)

**思想**: 选"相关但与已选不相似"的物品。

$$\text{MMR}(i) = \lambda \cdot \text{rel}(i) - (1-\lambda) \cdot \max_{j \in S} \text{sim}(i, j)$$

```python
def mmr(candidates, rel_scores, sim_matrix, k, lam=0.5):
    """Maximal Marginal Relevance"""
    selected = []
    pool = list(range(len(candidates)))

    while len(selected) < k and pool:
        best_score = -float('inf')
        best_idx = -1

        for i in pool:
            rel = rel_scores[i]
            # 与已选的最大相似度
            div = max([sim_matrix[i][j] for j in selected], default=0)
            mmr_score = lam * rel - (1 - lam) * div
            if mmr_score > best_score:
                best_score = mmr_score
                best_idx = i

        selected.append(best_idx)
        pool.remove(best_idx)

    return [candidates[i] for i in selected]
```

**参数 λ**:
- $\lambda = 1$: 退化为按 rel 排序 (无多样性)
- $\lambda = 0$: 纯多样性 (可能选出无关物品)
- $\lambda = 0.5$ ~ $0.7$: 推荐系统常用值

#### 10.2.2 DPP (Determinantal Point Process)

**思想**: 选"行列式最大"的子集。行列式越大, 子集"质量 × 多样性"越高。

$$P(S) = \frac{\det(\mathbf{L}_S)}{\sum_{S'} \det(\mathbf{L}_{S'})}$$

其中 $\mathbf{L}_{ij} = q_i q_j \cdot \text{sim}(i, j)$ 是核矩阵, $q_i$ 是质量, $\text{sim}$ 是相似度。

```python
import numpy as np
from scipy.linalg import det

def dpp_select(candidates, quality, sim_matrix, k):
    """DPP 贪心选择"""
    selected = []

    for _ in range(k):
        best_score = -float('inf')
        best_idx = -1

        for i in range(len(candidates)):
            if i in selected:
                continue
            # 假设选 i, 行列式增量
            candidate_set = selected + [i]
            L = build_kernel(quality, sim_matrix, candidate_set)
            score = det(L) if len(candidate_set) > 1 else L[0, 0]
            if score > best_score:
                best_score = score
                best_idx = i

        selected.append(best_idx)

    return [candidates[i] for i in selected]
```

**特点**: 理论优雅, 但工业上 MMR 更常用 (实现简单)。

#### 10.2.3 PRM (Personalized Re-ranking)

**思想**: 用 Transformer 编码整个候选列表, 建模 item 间相互影响。

```python
class PRM(nn.Module):
    """Personalized Re-ranking Model"""
    def __init__(self, embed_dim=32, n_heads=4, n_layers=2):
        super().__init__()
        # 编码精排打分 + 物品 Embedding
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=embed_dim * 2, nhead=n_heads, dim_feedforward=128
        )
        self.encoder = nn.TransformerEncoder(encoder_layer, num_layers=n_layers)
        self.head = nn.Linear(embed_dim * 2, 1)

    def forward(self, item_embs, score_embs):
        # item_embs: (B, K, d) 物品 Embedding
        # score_embs: (B, K, d) 精排打分 Embedding
        x = torch.cat([item_embs, score_embs], dim=-1)  # (B, K, 2d)

        # Transformer 编码
        encoded = self.encoder(x)  # (B, K, 2d)

        # 重打分
        new_scores = self.head(encoded).squeeze(-1)  # (B, K)
        return new_scores
```

**训练**: Listwise 损失, 比如 ListNet/ListMLE。

```python
def listnet_loss(pred_scores, true_labels):
    """ListNet 损失: top-1 概率"""
    pred_probs = F.softmax(pred_scores, dim=-1)
    true_probs = F.softmax(true_labels, dim=-1)
    return -torch.sum(true_probs * torch.log(pred_probs + 1e-10))
```

### 10.3 重排的列表优化目标

**NDCG (Normalized Discounted Cumulative Gain)**:

$$\text{NDCG@K} = \frac{\text{DCG@K}}{\text{IDCG@K}}$$
$$\text{DCG@K} = \sum_{i=1}^{K} \frac{2^{rel_i} - 1}{\log_2(i+1)}$$

**MAP (Mean Average Precision)**:

$$\text{MAP} = \frac{1}{Q}\sum_{q=1}^{Q} \text{AP}(q)$$

**Listwise 损失函数**:

```python
class ListwiseLoss(nn.Module):
    """Listwise 损失"""
    def __init__(self, loss_type='listnet'):
        super().__init__()
        self.loss_type = loss_type

    def forward(self, pred_scores, true_relevance):
        if self.loss_type == 'listnet':
            # Top-1 概率分布匹配
            pred_probs = F.softmax(pred_scores, dim=-1)
            true_probs = F.softmax(true_relevance, dim=-1)
            return -(true_probs * torch.log(pred_probs + 1e-10)).sum(-1).mean()

        elif self.loss_type == 'listmle':
            # ListMLE: 最大似然估计
            sorted_idx = true_relevance.argsort(dim=-1, descending=True)
            sorted_pred = pred_scores.gather(-1, sorted_idx)
            cumsum = sorted_pred.cumsum(dim=-1)
            loss = -sorted_pred + cumsum.log()
            return loss.mean()

        elif self.loss_type == 'approxndcg':
            # ApproxNDCG: 软化 NDCG
            gain = 2 ** true_relevance - 1
            rank = pred_scores.argsort(dim=-1, descending=True).argsort(-1).float() + 1
            discount = 1.0 / torch.log2(rank + 1)
            ideal = gain.topk(gain.size(-1), dim=-1).values
            ideal_disc = 1.0 / torch.log2(torch.arange(2, gain.size(-1)+2).float())
            dcg = (gain * discount).sum(-1)
            idcg = (ideal * ideal_disc).sum(-1)
            return -(dcg / idcg.clamp(min=1e-10)).mean()
```

**典型约束**:

```python
def apply_business_constraints(rerank_scores, candidates, constraints):
    """应用业务约束"""
    rerank_scores = rerank_scores.copy()

    # 1) 已曝光物品置 0
    for item in constraints['exclude_items']:
        if item in candidates:
            rerank_scores[candidates.index(item)] = -float('inf')

    # 2) 同类目不超限
    category_count = defaultdict(int)
    final_order = []
    sorted_idx = rerank_scores.argsort(descending=True)
    for idx in sorted_idx:
        cat = candidates[idx]['category']
        if category_count[cat] < constraints['max_per_category']:
            final_order.append(idx)
            category_count[cat] += 1

    return final_order[:constraints['top_k']]
```

### 10.6 重排与 GR (生成式推荐)

**趋势**: 重排的 Listwise 思想与 GR 的 list 生成天然相通。

```python
class GRRerank(nn.Module):
    """生成式重排: 直接生成 TopK 序列"""
    def __init__(self, num_items, d_model=128):
        super().__init__()
        self.item_emb = nn.Embedding(num_items, d_model)
```

## 11. 全链路一致性

### 11.1 SSB (Sample Selection Bias)

**问题**: 精排只在"曝光过"的物品上训练, 召回的候选空间与精排不同。

**后果**: 精排对召回候选"无感", 上线后效果差。

**解决**:
1. **ESMM**: 全空间建模 (推荐)
2. **校准**: 让精排对召回候选也能给出合理打分
3. **反事实估计**: 用 IPS 校正

### 11.2 级联一致性

**问题**: 召回/粗排/精排的目标不一致, 导致漏斗上层错误无法挽回。

**解决**:

```python
class CascadedTrainer:
    """级联一致性训练"""
    def __init__(self, recall_model, coarse_model, fine_model):
        self.recall = recall_model
        self.coarse = coarse_model
        self.fine = fine_model

    def train_step(self, batch):
        # 1) 召回打分
        recall_scores = self.recall(batch)

        # 2) 粗排蒸馏精排
        fine_scores = self.fine(batch)
        coarse_loss = self.coarse.train_step(batch, recall_scores, fine_scores)

        # 3) 精排正常训练
        fine_loss = self.fine.train_step(batch)

        # 4) 召回学习精排 TopK
        # 召回的目标是"精排会选中的"排前面
        top_k_target = fine_scores.topk(50, dim=-1).indices
        recall_loss = InfoNCE(recall_scores, top_k_target)

        return coarse_loss + fine_loss + recall_loss
```

## 12. 粗排精排重排的常见面试题扩展

### 12.1 粗排 vs 精排的本质区别

**标准答案**: 粗排候选多、模型简单、蒸馏精排; 精排候选少、模型复杂、多目标。

**深入答案**:

| 维度 | 粗排 | 精排 |
| :--- | :--- | :--- |
| 模型 | COLD / 轻 FM / 浅 DNN | DIN / MMoE / DCN-v2 |
| 特征 | 通用特征 | 全量 + 复杂 cross |
| 训练 | 蒸馏精排 (软标签为主) | 多任务 BCE (硬标签为主) |
| 推理 | < 10ms | < 50ms |
| 候选量 | 1万 → 1千 | 1千 → 100 |

**本质**: 粗排是"过滤", 精排是"打分", 两者目标不同。

### 12.2 多目标学习 Loss 怎么加权

**方法 1**: 手动调 (业务经验)

```python
loss = 0.5 * loss_ctr + 0.3 * loss_cvr + 0.2 * loss_dwell
```

**方法 2**: Uncertainty Weighting (Kendall)

```python
loss = exp(-s1) * loss1 + s1 + exp(-s2) * loss2 + s2 + ...
```

**方法 3**: GradNorm (动态平衡训练速度)

**方法 4**: 强化学习 (Learn2Rank)

### 12.3 SSB 怎么解决

**标准答案**: ESMM 全空间建模。

**深入答案**:
1. **ESMM**: 在整个曝光空间上训练 CVR, 而不是只在 click 空间
2. **校准**: 让精排打分在召回候选上也有意义
3. **多任务**: CVR 预测全链路
4. **反事实**: IPS 校正

### 12.4 校准的必要性

**答案**: 多目标融合 / 广告出价 / RL reward 都依赖绝对概率, 不校准会系统性偏差。

### 12.5 重排怎么考虑多样性

**方法 1**: MMR (工业最常用)
**方法 2**: DPP (理论优雅)
**方法 3**: 多样性正则化 Loss

```python
def diversity_loss(rank_scores, item_embs):
    """多样性正则化"""
    # 相邻位置相似度尽量低
    sorted_embs = item_embs[rank_scores.argsort(descending=True)]
    adjacent_sim = (sorted_embs[:-1] * sorted_embs[1:]).sum(-1)
    return adjacent_sim.mean()  # 越小越好
```

### 12.6 重排的常见业务约束

1. **去重**: 已曝光物品不再出现
2. **类别平衡**: 同类目不超过 X 个
3. **创作者平衡**: 同作者不超过 X 个
4. **新物品比例**: 新物品占比 ≥ X%
5. **广告配额**: 广告位不超过 X 个
6. **合规过滤**: 违规内容不出现

### 12.7 粗排蒸馏的损失怎么写

```python
# 软标签 + 硬标签
loss = α * BCE(coarse_logit, true_label) + (1-α) * KL(coarse_prob, fine_prob)
```

其中 $\alpha$ 通常 0.3-0.5。

### 12.8 精排多目标融合公式

**经典**: $\text{score} = \text{pCTR}^\alpha \cdot \text{pCVR}^\beta \cdot (1+\text{时长})^\gamma$

**强化学习**: 自动学习融合权重。

**帕累托**: 找 Pareto 最优组合。

### 13.2 GR 与排序的融合

```python
class HybridRank(nn.Module):
    """GR + 传统排序融合"""
    def __init__(self):
        self.gr_ranker = GRRanker(...)
        self.traditional_ranker = DIN(...)
        self.fusion = nn.Linear(2, 1)

    def forward(self, user, candidates):
        gr_score = self.gr_ranker(user, candidates)
        traditional_score = self.traditional_ranker(user, candidates)
        # 加权融合
        return self.fusion(torch.stack([gr_score, traditional_score], dim=-1))
```

### 13.3 Listwise GR

```python
class ListwiseGR(nn.Module):
    """Listwise 生成式重排"""
    def __init__(self, num_items, d_model=128):
        super().__init__()
        self.item_emb = nn.Embedding(num_items, d_model)
        self.decoder = TransformerDecoder(num_layers=6)
        self.head = nn.Linear(d_model, num_items)

    def forward(self, candidates):
        # candidates: (B, K) TopK 候选 ID
        c_emb = self.item_emb(candidates)  # (B, K, d)

        # 自回归生成
        out = self.decoder(c_emb)
        logits = self.head(out)

        return logits  # (B, K, num_items)
```

## 15. 排序与上游下游的协同

### 15.1 排序与召回的协同

**召回蒸馏到粗排/精排**:
```python
class RecallDistill(nn.Module):
    """召回蒸馏到精排, 让精排认识召回候选"""
    def __init__(self, recall, fine):
        self.recall = recall
        self.fine = fine

    def train_step(self, batch):
        # 召回打分
        recall_scores = self.recall(batch)
        # 精排打分
        fine_scores = self.fine(batch)
        # 蒸馏
        loss = F.binary_cross_entropy(
            torch.sigmoid(fine_scores),
            torch.sigmoid(recall_scores).detach()
        )
        return loss
```

## 17. 排序与强化学习的结合

### 17.1 用 RL 优化多目标融合

**思想**: 把多目标融合看作 RL 问题。

- **State**: 用户 + 候选
- **Action**: 融合权重
- **Reward**: 业务指标 (CTR × 时长 × GMV)

```python
class FusionRL(nn.Module):
    """用 RL 学习融合权重"""
    def __init__(self, num_tasks):
        super().__init__()
        self.policy = nn.Sequential(
            nn.Linear(user_dim, 64), nn.ReLU(),
            nn.Linear(64, num_tasks), nn.Softmax(dim=-1)
        )

    def forward(self, user_context, task_scores):
        weights = self.policy(user_context)  # (B, num_tasks)
        # 加权融合
        fusion_score = (task_scores * weights.unsqueeze(1)).sum(-1)
        return fusion_score
```

### 17.2 RLHF 应用到排序

**思想**: 用人类偏好 (点击/时长/转化) 作为 reward。

```python
class RankingRLHF:

        scores = self.base(user, candidates)
        # 2) 计算 reward
        reward = self.reward_model(user, candidates, scores)
```

## 22. 排序的常见误解

### 22.1 误解 1: 精排 AUC 高 = 业务好

**正解**: 精排 AUC 只反映排序能力, 不反映业务效果。
- 精排 AUC 高 + 召回候选差 = 业务差
- 精排 AUC 高 + 业务约束没满足 = 业务差

**正确指标**: 在线 CTR + 留存 + GMV。

### 22.2 误解 2: 多目标越多越好

**正解**: 多目标会引入**跷跷板**和**梯度冲突**。
- 2-3 个核心目标
- 弱相关目标用 PLE 解耦

### 22.3 误解 3: 重排一定要用 Transformer

**正解**: 重排的目的是"列表优化", 简单的 MMR 已经能解决 80% 问题。
- MMR 简单, 工业首选
- DPP 理论优雅, 难实现
- PRM 强大, 但训练成本高

### 22.4 误解 4: 校准改变排序

**正解**: 校准保持排序不变 (保序回归), 只改变绝对值。

### 22.5 误解 5: GR 会替代所有排序

**正解**: GR 在一定场景下替代, 但不会完全替代。
- GR 训练成本高
- 工业落地需要时间
- 短期: GR + 传统排序混合

## 26. 粗排蒸馏的深度细节

### 26.1 蒸馏目标的演化

**第一代**: Logit 蒸馏
- 用精排打分作为软标签
- 简单, 但粗排学不到"为什么精排这么排"

**第二代**: Ranking 蒸馏
- 用精排的排序顺序作为软标签
- 粗排学"排序一致性", 更接近业务

**第三代**: Listwise 蒸馏
- 整个列表的精排打分分布作为软标签
- 粗排学"列表结构", 更鲁棒

**第四代**: 多教师蒸馏
- 用多个精排模型 (不同架构) 蒸馏
- 综合多视角, 效果更好

### 26.2 Listwise 蒸馏的代码实现

```python
class ListwiseDistillLoss(nn.Module):
    """Listwise 蒸馏损失"""
    def __init__(self, temperature=1.0, alpha=0.5):
        super().__init__()
        self.temperature = temperature
        self.alpha = alpha

    def forward(self, coarse_logits, fine_logits, true_labels, mask=None):
        """
        coarse_logits: (B, K) 粗排打分
        fine_logits: (B, K) 精排打分 (teacher)
        true_labels: (B, K) 真实标签
        """
        # 1) 硬标签损失
        loss_hard = F.binary_cross_entropy_with_logits(
            coarse_logits, true_labels, reduction='none'
        )
        if mask is not None:
            loss_hard = (loss_hard * mask).sum() / mask.sum().clamp(min=1)
        else:
            loss_hard = loss_hard.mean()

        # 2) Listwise KL 蒸馏
        # 把打分转换为概率分布
        fine_probs = F.softmax(fine_logits / self.temperature, dim=-1)
        coarse_log_probs = F.log_softmax(coarse_logits / self.temperature, dim=-1)
        loss_distill = F.kl_div(coarse_log_probs, fine_probs, reduction='batchmean') * (self.temperature ** 2)

        return self.alpha * loss_hard + (1 - self.alpha) * loss_distill
```

### 26.3 粗排的特征工程

**粗排特征选择原则**:

1. **强相关特征优先**: CTR / 类目匹配 / 用户画像
2. **实时特征简版**: 当前 session 的简单统计
3. **避免重计算特征**: 复杂 cross 不要

**特征分桶**:
- 价格: 分 5 桶 (0-10, 10-50, 50-200, 200-1000, 1000+)
- 流行度: 分 10 桶 (按分位数)
- 时间: hour, day_of_week, is_weekend

**特征 Embedding**:

### 26.5 粗排的在线学习

**场景**: 粗排与精排"目标漂移", 需要在线纠偏。

**方案**: 粗排与精排联合在线训练。

```python
class OnlineCoarseTrainer:
    def __init__(self, coarse_model, fine_model):
        self.coarse = coarse_model
        self.fine = fine_model

    def online_step(self, batch, lr=1e-4):
        # 1) 精排更新
        fine_loss = self.fine.train_step(batch)

        # 2) 用精排最新打分蒸馏粗排
        with torch.no_grad():
            fine_scores = self.fine(batch)
        coarse_loss = self.coarse.distill_step(batch, fine_scores)

        return fine_loss + coarse_loss
```

## 27. 精排的多任务细节

### 27.1 多任务的"任务关系"

### 27.2 任务权重的动态调整

```python
class DynamicTaskWeighting(nn.Module):
    """动态任务权重"""
    def __init__(self, num_tasks, warmup_steps=1000):
        super().__init__()
        self.num_tasks = num_tasks
        self.warmup_steps = warmup_steps
        self.weights = nn.Parameter(torch.ones(num_tasks))

    def forward(self, task_losses, step):
        # Warmup 期间固定权重
        if step < self.warmup_steps:
            return task_losses

        # 基于损失下降速度调权
        with torch.no_grad():
            loss_rates = [t.item() for t in task_losses]
            # 损失下降慢的任务权重高
            weights = torch.softmax(torch.tensor(loss_rates), dim=0)

        weighted_loss = sum(w * t for w, t in zip(weights, task_losses))
        return weighted_loss
```

**每个任务单独评估**:

- CVR 任务: AUC, LogLoss

**任务之间的相关性**:
- CTR 和 CVR 的 AUC 相关性 (强相关应该高)

```python
def evaluate_multi_task(model, val_loader):
    metrics = {}
    for task_name in model.task_names:
        preds, labels = [], []
        for batch in val_loader:
            task_logits = model(batch)
            preds.append(task_logits[task_name].cpu())
            labels.append(batch[f'{task_name}_label'].cpu())
        # 计算 AUC
        from sklearn.metrics import roc_auc_score
        auc = roc_auc_score(torch.cat(labels), torch.sigmoid(torch.cat(preds)))
        metrics[task_name] = auc
    return metrics
```

### 27.4 任务冲突的诊断

**任务跷跷板**: 训练时某些任务涨, 另一些跌。

**诊断方法**:
1. 监控每个任务的 AUC 曲线
2. 计算任务梯度夹角 (余弦)
3. 找冲突任务对

```python
def compute_task_grad_similarity(model, batch):
    """计算任务梯度相似度"""
    model.zero_grad()

    grads = []
    for task_name in model.task_names:
        task_logits = model(batch)
        loss = F.binary_cross_entropy_with_logits(
            task_logits[task_name], batch[f'{task_name}_label']
        )
        loss.backward(retain_graph=True)

        # 提取梯度
        grad = []
        for p in model.parameters():
            if p.grad is not None:
                grad.append(p.grad.flatten())
        grads.append(torch.cat(grad))
        model.zero_grad()

    # 任务梯度余弦相似度
    n = len(grads)
    sim_matrix = torch.zeros(n, n)
    for i in range(n):
        for j in range(n):
            sim_matrix[i, j] = F.cosine_similarity(grads[i], grads[j], dim=0)

    return sim_matrix
```

4. **监控**: 每个任务的 AUC + 任务冲突矩阵

### 28.2 重排的约束类型

**硬约束 (必须满足)**:
- 已曝光物品不重复
- 违规物品过滤
- 黑名单物品过滤

**软约束 (尽量满足)**:
- 类别平衡
- 创作者平衡
- 新物品占比
- 价格区间

```python
def rerank_with_constraints(candidates, fine_scores, constraints):
    """带约束的重排"""
    # 1) 应用硬约束
    candidates = [c for c in candidates if c['item_id'] not in constraints['exclude_set']]

    # 2) 初始排序 (按精排打分)
    sorted_candidates = sorted(candidates, key=lambda c: c['fine_score'], reverse=True)

    # 3) 应用软约束 (贪心)
    final_order = []
    cat_count = defaultdict(int)

    for c in sorted_candidates:
        cat = c['category']
        if cat_count[cat] < constraints['max_per_category']:
            final_order.append(c)
            cat_count[cat] += 1

    return final_order[:constraints['top_k']]
```

### 28.3 重排的在线评估

**核心指标**:
- NDCG@10
- 多样性 (1 - 平均相似度)
- 业务 CTR
- 用户主动换一换的比例

```python
def online_diversity(predictions, item_embs):
    """在线多样性"""
    sims = []
    for i in range(len(predictions)):
        for j in range(i+1, len(predictions)):
            sim = F.cosine_similarity(
                item_embs[predictions[i]], item_embs[predictions[j]], dim=0
            )
            sims.append(sim.item())
    return 1 - np.mean(sims)
```

### 28.4 重排的 A/B 测试

**实验设计**:

- C: PRM 重排 (Transformer)

**指标**:
- 短期: CTR, 时长
- 中期: 多样性, 次日留存

**反转检验**: 调换 A/B, 看指标是否反向变化。

### 28.5 重排的常见坑

**坑 1**: 重排把精排 Top1 排到了最后。

**原因**: 多样性权重过大。

**解决**: 限制重排变化幅度 (相邻位置最多移动 K 个)。

**坑 2**: 重排多样性涨, 但 CTR 跌。

**原因**: 多样性破坏了精排的"高 CTR"排序。

**解决**: 用 Listwise 训练, 让模型学"在保 AUC 的前提下提升多样性"。

**坑 3**: 重排模型太复杂, 推理超时。

**原因**: PRM 用 Transformer, 候选 100 个太慢。

**解决**: 用轻量 PRM (2 层 Transformer, hidden=64), 或退到 MMR。

```python
def rerank_change_rate(original_order, rerank_order):

    return changes / n
```

**没有最优**, 只有"适合业务的":
