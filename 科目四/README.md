```text
  直接从 SOLID 开始 → 然后按需查阅各模式

面试路线:
  23 种模式全部过一遍 → 第06章对比表 → 重点掌握: 单例/工厂/代理/观察者/策略/装饰/责任链
```

### 学习建议

1. **不要死记硬背** — 每个模式都解决特定问题, 理解问题比记结构重要
2. **先看动机** — 模式的"为什么"比"怎么做"更重要
3. **多写代码** — 每个模式至少手写 2-3 个变体
4. **看真实项目** — JDK / Spring / MyBatis 都用了大量设计模式
5. **避免过度设计** — 不是所有问题都需要模式, 简单问题用简单方案

## 📊 23 种 GoF 模式速查

### 创建型 (5 种) - 解决"对象创建"问题
| 模式 | 一句话 | 适用场景 |
| :--- | :--- | :--- |
| 单例 Singleton | 一个类只有一个实例 | 全局唯一 (配置/池/管理器) |
| 工厂方法 Factory Method | 子类决定创建哪个对象 | 框架扩展点 |
| 抽象工厂 Abstract Factory | 创建一系列相关对象 | 跨平台 UI/数据库切换 |
| 建造者 Builder | 分步构建复杂对象 | 参数多的对象 (HTTP 请求) |
| 原型 Prototype | 克隆而非新建 | 对象创建成本高 |

### 结构型 (7 种) - 解决"类与对象组合"问题
| 模式 | 一句话 | 适用场景 |
| :--- | :--- | :--- |
| 适配器 Adapter | 转换接口兼容 | 旧接口包装 |
| 桥接 Bridge | 抽象与实现分离 | JDBC 驱动 |
| 组合 Composite | 树形结构统一处理 | 文件系统/UI 组件树 |
| 装饰 Decorator | 动态添加职责 | Java I/O 流 |
| 外观 Facade | 统一高层接口 | 复杂子系统封装 |
| 享元 Flyweight | 共享细粒度对象 | 大量相似对象 (字符/棋盘) |
| 代理 Proxy | 替代访问控制 | 远程/RPC/虚拟代理 |

### 行为型 (11 种) - 解决"对象间职责与通信"问题
| 模式 | 一句话 | 适用场景 |
| :--- | :--- | :--- |
| 职责链 Chain of Responsibility | 多个对象依次处理 | 中间件/过滤器 |
| 命令 Command | 请求封装为对象 | 撤销/重做/任务队列 |
| 迭代器 Iterator | 顺序访问集合元素 | 遍历/foreach |
| 中介者 Mediator | 集中对象间通信 | GUI 组件/聊天室 |
| 备忘录 Memento | 保存对象状态 | 撤销/快照 |
| 观察者 Observer | 状态变化自动通知 | 事件监听/MVC |
| 状态 State | 行为随状态改变 | 状态机/订单状态 |
| 策略 Strategy | 算法可替换 | 排序/支付方式 |
| 模板方法 Template Method | 父类定骨架子类填细节 | 框架扩展 |
| 访问者 Visitor | 操作与数据结构分离 | 编译器 AST/报表生成 |
| 解释器 Interpreter | 自定义语法解析 | DSL/SQL 解析 |

## 📝 学习建议: 5 个常见误区

1. **为了用模式而用模式** — 没有合适的场景, 不要硬塞
2. **死记硬背模式结构** — 理解"为什么要这样设计"更重要
3. **混淆模式和原则** — SOLID 是原则, 模式是实现原则的具体方案
4. **忽略简单方案** — 能用普通方法解决的问题, 不要引入模式
5. **模式过度泛化** — 一个模式在不同场景可能有不同的最佳实践
