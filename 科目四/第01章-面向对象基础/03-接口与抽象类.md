# 03. 接口与抽象类

> 接口和抽象类是设计模式中最常用的"契约"工具. 理解它们的区别, 才能看懂模式中的抽象层.

---

## 1. 基本概念

### 1.1 接口 (Interface)

**定义**: 一组**方法签名**的集合, 不包含实现. 规定"能做什么", 不规定"怎么做".

**比喻**: **电源插座标准** — 规定接口形状 (3 孔/220V), 不规定内部电器.

**特点**:
- ✅ 只能声明方法 (不能有实现, 除非 default/static)
- ✅ 不能有实例变量 (可以有 static final 常量)
- ✅ 类可以实现多个接口 (多实现)
- ✅ 用于定义**协议/规范**

### 1.2 抽象类 (Abstract Class)

**定义**: **部分实现**的类, 包含抽象方法 (未实现) 和具体方法.

**比喻**: **半成品模板** — 框架代码写好, 留几个钩子让子类填.

**特点**:
- ✅ 可以有抽象方法, 也可以有具体方法
- ✅ 可以有实例变量 (成员变量)
- ✅ 类只能单继承一个抽象类
- ✅ 用于代码**复用 + 强制规范**

## 2. Java 中的对比

```java
// 接口 (Java 8 前)
public interface Flyable {
    void fly();  // 抽象方法 (隐式 public abstract)
}

// 抽象类
public abstract class Animal {
    protected String name;
    public Animal(String name) { this.name = name; }  // 具体方法
    
    public abstract void speak();  // 抽象方法
    
    public void eat() {  // 具体方法
        System.out.println(name + " eating");
    }
}

class Dog extends Animal implements Flyable {
    public Dog(String name) { super(name); }
    
    @Override
    public void speak() { System.out.println("汪汪"); }
    
    @Override
    public void fly() { System.out.println("狗在飞"); }
}
```

## 3. Python 中的实现

### 3.1 抽象基类 (ABC)

```python
from abc import ABC, abstractmethod

# 抽象类
class Animal(ABC):
    def __init__(self, name):
        self.name = name  # 实例变量
    
    @abstractmethod
    def speak(self):
        pass  # 抽象方法
    
    def eat(self):  # 具体方法
        print(f"{self.name} eating")

class Dog(Animal):
    def speak(self):
        return "汪汪"

# Animal()  # ❌ TypeError: 不能实例化抽象类
d = Dog("小黑")
d.speak()  # "汪汪"
```

### 3.2 接口 (Python 协议)

Python 3.8+ 推荐用 `Protocol` 定义接口:

```python
from typing import Protocol

# 接口 (协议)
class Flyable(Protocol):
    def fly(self) -> str: ...

class Person:
    def fly(self) -> str:
        return "人在跑"

# 不需要继承, 只要有 fly 方法就是 Flyable
def make_fly(thing: Flyable):
    print(thing.fly())

make_fly(Person())  # "人在跑"
```

### 3.3 抽象方法 vs 普通方法

```python
class Shape(ABC):
    @abstractmethod
    def area(self): pass    # 子类必须实现
    
    def describe(self):      # 子类可以继承
        return f"面积: {self.area()}"

class Square(Shape):
    def __init__(self, s): self.s = s
    def area(self): return self.s ** 2
```

## 4. 对比表

| 维度 | 接口 | 抽象类 |
| :--- | :--- | :--- |
| 方法 | 只能抽象 (Java 8+ 可 default) | 抽象 + 具体都可以 |
| 变量 | 只能 static final 常量 | 任何实例变量 |
| 构造器 | 无 | 有 |
| 继承 | 多实现 | 单继承 |
| 目的 | 定义**协议** | **代码复用 + 协议** |
| 关系 | "能做什么" (can-do) | "是什么" (is-a) |
| Java 关键字 | `interface` | `abstract class` |
| Python 等价 | `Protocol` | `ABC` (Abstract Base Class) |

## 5. 设计模式中的应用

### 5.1 抽象工厂模式

```java
// 抽象产品接口
public interface Button {
    void render();
}

// 具体产品
public class WindowsButton implements Button {
    public void render() { System.out.println("Windows 按钮"); }
}

// 抽象工厂接口
public interface GUIFactory {
    Button createButton();
    TextField createTextField();
}

// 具体工厂
public class WindowsFactory implements GUIFactory {
    public Button createButton() { return new WindowsButton(); }
}
```

### 5.2 模板方法模式

```java
public abstract class DataProcessor {
    // 模板方法 (定义骨架)
    public final void process() {
        readData();
        parseData();
        saveData();
    }
    
    protected abstract void readData();
    protected abstract void parseData();
    
    private void saveData() {  // 具体方法
        System.out.println("保存");
    }
}

class CSVProcessor extends DataProcessor {
    protected void readData() { System.out.println("读 CSV"); }
    protected void parseData() { System.out.println("解析 CSV"); }
}
```

### 5.3 策略模式

```python
from abc import ABC, abstractmethod

class SortStrategy(ABC):
    @abstractmethod
    def sort(self, data): pass

class QuickSort(SortStrategy):
    def sort(self, data):
        return sorted(data)  # 简化

class BubbleSort(SortStrategy):
    def sort(self, data):
        return sorted(data, reverse=True)

class Context:
    def __init__(self, strategy: SortStrategy):
        self.strategy = strategy
    def execute(self, data):
        return self.strategy.sort(data)
```

## 6. 抽象类 vs 接口: 怎么选?

### 用接口的情况
- ✅ 定义**行为规范** (如 Comparable, Serializable, Iterator)
- ✅ **多种类型** 想共享协议 (鸭子类型)
- ✅ 不需要共享代码, 只要规范
- ✅ 例子: Java 的 List 接口, Python 的 Iterable Protocol

### 用抽象类的情况
- ✅ 想**强制子类**实现某些方法
- ✅ 想**共享代码** (成员变量 + 具体方法)
- ✅ "是一个" 关系 (Dog **is-a** Animal)
- ✅ 例子: Spring 的 AbstractController

### 经验法则
- 如果**只是规范**, 用**接口**
- 如果**需要共享代码**, 用**抽象类**
- 可以**两者结合**: 抽象类实现接口

```java
abstract class AbstractList implements List {
    // 共享代码
    public int size() { return ... }
}

class ArrayList extends AbstractList {
    // 具体实现
}
```

## 7. 小结

✅ **接口**: 纯规范, 多实现, Java 8+ 可有默认实现

✅ **抽象类**: 部分实现, 单继承, 用于强制规范 + 代码复用

✅ Python: `Protocol` ≈ 接口, `ABC` ≈ 抽象类

✅ 设计模式中: 工厂/策略/装饰器/模板方法等都用接口定义协议
