# 01. 单例模式 (Singleton)

> **一句话**: 保证一个类**只有一个实例**, 并提供**全局访问点**.

---

## 1. 核心问题

有些对象**只能有一个**, 否则会有问题:
- 线程池/数据库连接池 — 多个池浪费资源
- 配置管理器 — 多个实例可能不一致
- 日志对象 — 多份日志文件冲突
- 设备驱动 — 一个电脑只有一个打印机管理器

## 3. Python 实现

### 3.1 基础版本 (线程不安全)

```python
class Singleton:
    _instance = None
    
    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

# 使用
s1 = Singleton()
s2 = Singleton()
print(s1 is s2)  # True
```

**问题**: 多线程下可能创建多个实例.

### 3.2 线程安全版本 (双重检查锁定)

```python
import threading

class Singleton:
    _instance = None
    _lock = threading.Lock()
    
    def __new__(cls):
        if cls._instance is None:
            with cls._lock:
                if cls._instance is None:  # 双重检查
                    cls._instance = super().__new__(cls)
        return cls._instance

# 双重检查的好处:
# - 第一次 if: 避免每次都加锁 (已创建好后无需锁)
# - 第二次 if: 防止多个线程同时通过第一次检查后, 都创建实例
```

### 3.3 Python 风格 (装饰器)

```python
def singleton(cls):
    instances = {}
    def get_instance(*args, **kwargs):
        if cls not in instances:
            instances[cls] = cls(*args, **kwargs)
        return instances[cls]
    return get_instance

@singleton
class Database:
    def query(self, sql):
        return f"执行: {sql}"

db1 = Database()
db2 = Database()
print(db1 is db2)  # True
```

### 3.4 Python 模块级单例 (最 Pythonic)

```python
# database.py
class _Database:
    def query(self, sql):
        return f"执行: {sql}"

database = _Database()  # 模块加载时创建
```

```python
# 使用
from database import database
db = database
print(db.query("SELECT *"))
```

**原理**: Python 模块只会被导入**一次**, 模块级变量天然单例.

### 3.5 Python 元类实现

```python
class SingletonMeta(type):
    _instances = {}
    
    def __call__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = super().__call__(*args, **kwargs)
        return cls._instances[cls]

class Database(metaclass=SingletonMeta):
    def query(self, sql):
        return f"执行: {sql}"

db1 = Database()
db2 = Database()
print(db1 is db2)  # True
```

## 4. Java 实现

### 4.1 经典实现

```java
public class Singleton {
    private static Singleton instance;
    
    private Singleton() {}  // 私有构造器
    
    public static synchronized Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

### 4.2 双重检查锁定 (推荐)

```java
public class Singleton {
    private static volatile Singleton instance;
    
    private Singleton() {}
    
    public static Singleton getInstance() {
        if (instance == null) {                    // 第一次检查 (无锁)
            synchronized (Singleton.class) {        // 加锁
                if (instance == null) {            // 第二次检查 (有锁)
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}
```

**关键点**:
- `volatile` 防止指令重排序 (确保多线程可见性)
- 第一次检查避免每次都加锁 (性能优化)
- 第二次检查防止多个线程同时创建

### 4.3 静态内部类 (最佳实践)

```java
public class Singleton {
    private Singleton() {}
    
    // 静态内部类只有在被引用时才加载 (懒加载)
    private static class Holder {
        private static final Singleton INSTANCE = new Singleton();
    }
    
    public static Singleton getInstance() {
        return Holder.INSTANCE;
    }
}
```

**优点**: 线程安全 + 懒加载 + 无锁 + 简洁.

### 4.4 枚举 (最简洁)

```java
public enum Singleton {
    INSTANCE;
    
    public void businessLogic() {
        System.out.println("业务逻辑");
    }
}

// 使用
Singleton.INSTANCE.businessLogic();
```

**优点**:
- ✅ 线程安全 (JVM 保证)
- ✅ 防止反序列化创建新对象
- ✅ 防止反射攻击
- ✅ Joshua Bloch 在 *Effective Java* 中推荐

## 7. 单例模式的破坏

### 7.1 反射破坏

```java
// 即使构造器私有, 反射也能创建新实例
Constructor<Singleton> c = Singleton.class.getDeclaredConstructor();
c.setAccessible(true);
Singleton s2 = c.newInstance();  // 创建了第二个实例!
```

**防御**: 在构造器中检查并抛异常.

```java
private Singleton() {
    if (instance != null) {
        throw new RuntimeException("禁止反射创建");
    }
}
```

### 7.2 反序列化破坏

Java 的 `ObjectInputStream` 通过反射调用构造器, 也能破坏单例.

**防御**: 实现 `readResolve()` 方法.

```java
protected Object readResolve() {
    return getInstance();  // 强制返回同一个实例
}
```

### 7.3 枚举天然免疫

Java 枚举的 `readResolve()` 由 JVM 保证, 单例不会被破坏.

## 8. 单例 vs 静态类

| 维度 | 单例 | 静态类 |
| :--- | :--- | :--- |
| 实例化 | 可以有状态 | 通常无状态 |
| 接口实现 | 可以实现接口 | 不行 |
| 继承 | 可以被继承 | 一般不继承 |
| 多例 | 严格单例 | 一个类只能有一个 |
| OOP | 是 | 偏向过程化 |

**结论**: 能用静态方法就不要单例 (更简单). 真需要面向对象特性时再用单例.

## 9. 实战思考

### Q1: 单例 vs 全局变量 区别?

| 单例 | 全局变量 |
| :--- | :--- |
| 面向对象 (类/实例) | 面向过程 (变量) |
| 可继承/多态 | 无继承 |
| 可懒加载 | 必须定义 |
| 可封装状态 | 难封装 |

### Q2: 单例模式的 5 大原则?

1. **唯一性**: 类只有一个实例
2. **全局访问**: 提供全局访问点
3. **自行实例化**: 类自己负责创建
4. **延迟初始化**: 通常懒加载 (按需创建)
5. **禁止外部实例化**: 构造器私有

### Q3: 单例模式的适用场景 vs 不适用?

✅ **适用**: 配置/日志/线程池/连接池/缓存/驱动/全局状态

❌ **不适用**:
- 单测 (单例阻碍 Mock)
- 多线程环境 (单例可能成为瓶颈)
- 分布式系统 (需要分布式锁)
