# 02. 工厂方法模式 (Factory Method)

> **一句话**: 定义一个**创建对象的接口**, 但让**子类决定实例化哪个类**.

---

## 1. 核心问题

直接 `new` 对象有什么问题?

```python
# ❌ 问题代码
class Logger:
    def log(self, msg):
        print(msg)

class FileLogger:
    def log(self, msg):
        with open("app.log", "a") as f:
            f.write(msg + "\n")

class App:
    def __init__(self):
        self.logger = Logger()  # ❌ 硬编码, 难以换实现
```

**问题**:
- **紧耦合**: App 直接依赖具体 Logger
- **难以扩展**: 想换 FileLogger 必须改 App 代码
- **难以测试**: 无法注入 Mock

**工厂方法模式的核心**: 把对象的创建**延迟到子类**, 让父类不指定具体类.

---

## 2. 模式结构

```text
                    ┌────────────────┐
                    │   <<creator>>   │
                    │    Creator      │
                    ├────────────────┤
                    │ +factoryMethod()│ ← 工厂方法 (创建 Product)
                    │ +operation()    │
                    └────────△───────┘
                             │ (继承)
              ┌──────────────┴──────────────┐
              │                             │
   ┌──────────────────┐          ┌──────────────────┐
   │ ConcreteCreatorA │          │ ConcreteCreatorB │
   ├──────────────────┤          ├──────────────────┤
   │+factoryMethod()  │          │+factoryMethod()  │
   │  return new A()  │          │  return new B()  │
   └──────────────────┘          └──────────────────┘
              △                             △
              │ (创建)                      │ (创建)
       ┌──────────────┐               ┌──────────────┐
       │ ProductA     │               │ ProductB     │
       ├──────────────┤               ├──────────────┤
       │+operation()  │               │+operation()  │
       └──────────────┘               └──────────────┘
```

**4 个角色**:
1. **Product**: 抽象产品 (接口/抽象类)
2. **ConcreteProduct**: 具体产品
3. **Creator**: 抽象创建者 (含工厂方法)
4. **ConcreteCreator**: 具体创建者 (重写工厂方法)

## 3. Python 实现

### 3.1 标准实现

```python
from abc import ABC, abstractmethod

# 1. 抽象产品
class Logger(ABC):
    @abstractmethod
    def log(self, msg): pass

# 2. 具体产品 A
class ConsoleLogger(Logger):
    def log(self, msg):
        print(f"[控制台] {msg}")

# 3. 具体产品 B
class FileLogger(Logger):
    def log(self, msg):
        with open("app.log", "a") as f:
            f.write(f"{msg}\n")

# 4. 抽象创建者
class AppBase(ABC):
    @abstractmethod
    def create_logger(self) -> Logger:
        pass
    
    def run(self):
        logger = self.create_logger()  # 多态调用
        logger.log("应用启动")

# 5. 具体创建者
class ConsoleApp(AppBase):
    def create_logger(self):
        return ConsoleLogger()

class FileApp(AppBase):
    def create_logger(self):
        return FileLogger()

# 使用
app = ConsoleApp()
app.run()  # [控制台] 应用启动

app = FileApp()
app.run()  # (写入 app.log)
```

### 3.2 带参数的工厂

```python
class LoggerFactory:
    def create_logger(self, log_level="INFO"):
        if log_level == "DEBUG":
            return DebugLogger()
        elif log_level == "INFO":
            return InfoLogger()
        return ErrorLogger()
```

## 4. Java 实现

```java
// 1. 抽象产品
public interface Logger {
    void log(String msg);
}

// 2. 具体产品
public class ConsoleLogger implements Logger {
    public void log(String msg) { System.out.println(msg); }
}

public class FileLogger implements Logger {
    public void log(String msg) {
        // 写入文件
    }
}

// 3. 抽象创建者
public abstract class Application {
    public abstract Logger createLogger();
    
    public void run() {
        Logger logger = createLogger();
        logger.log("App started");
    }
}

// 4. 具体创建者
public class ConsoleApp extends Application {
    public Logger createLogger() { return new ConsoleLogger(); }
}

public class FileApp extends Application {
    public Logger createLogger() { return new FileLogger(); }
}
```

## 5. 简单工厂 vs 工厂方法

| 维度 | 简单工厂 (Simple Factory) | 工厂方法 (Factory Method) |
| :--- | :--- | :--- |
| 类数 | 1 个工厂类 | 抽象工厂 + 多个子类 |
| 扩展性 | 改工厂类 (违反开闭) | 加新子类 (符合开闭) |
| 复杂度 | 简单 | 稍复杂 |
| 多态 | 无 | 有 (子类决定) |
| 开闭原则 | ❌ 违反 | ✅ 符合 |

**简单工厂**: 用一个 if-else 创建对象 (不是 GoF 23 种, 是简化版)

```python
class SimpleLoggerFactory:
    @staticmethod
    def create_logger(log_type):
        if log_type == "console":
            return ConsoleLogger()
        elif log_type == "file":
            return FileLogger()
        raise ValueError(f"未知类型: {log_type}")
```

**工厂方法**: GoF 23 种之一, 真正的多态.

## 6. 实际应用

### 6.1 JDBC: Connection.createStatement()

```java
// DriverManager 通过工厂方法创建 Connection
Connection conn = DriverManager.getConnection(url);
// 实际创建的 Connection 由具体 Driver 决定
// MySQL Driver 返回 MySQLConnectionImpl
// PostgreSQL Driver 返回 PgConnection
```

### 6.2 Java 集合框架

```java
// Collections 类的方法是静态工厂方法
List<String> list = Collections.emptyList();    // 返回 EmptyList
Map<String, Integer> map = Collections.singletonMap("k", 1);

// Iterator 是工厂方法
public interface Collection<E> {
    Iterator<E> iterator();  // 工厂方法
}
```

### 6.3 Spring BeanFactory

```java
// Spring 的 BeanFactory 就是巨大的工厂方法
ApplicationContext ctx = new ClassPathXmlApplicationContext("beans.xml");
UserService userService = (UserService) ctx.getBean("userService");
// getBean() 就是工厂方法, 根据 bean 定义创建不同类型
```

### 6.4 日志框架 SLF4J

```java
// LoggerFactory.getLogger() 是静态工厂方法
private static final Logger logger = LoggerFactory.getLogger(MyClass.class);
// 根据 classpath 上的具体实现 (Logback/Log4j) 返回不同 Logger
```

## 7. 优缺点

### 优点

✅ **解耦**: 创建者和产品解耦

✅ **符合开闭原则**: 增加新产品只需加新创建者, 不改原有代码

✅ **多态**: 运行时根据条件选择创建者

### 缺点

❌ **类数量增加**: 每个产品需要对应一个创建者

❌ **复杂度提升**: 相比直接 `new` 复杂

❌ **不易理解**: 新人需要理解抽象层

---

## 8. 实战思考

### Q1: 什么时候用工厂方法?

✅ **创建逻辑复杂**: 需要根据参数/配置决定创建哪种对象

✅ **需要扩展**: 经常增加新产品类型

✅ **需要解耦**: 调用方不依赖具体类

✅ **统一管理**: 想集中控制对象的创建 (如 Spring IoC)

❌ **简单对象**: 字符串/数字, 直接 `new` 就行

❌ **不会扩展**: 永远只有 1-2 种产品, 简单工厂就够

### Q2: 工厂方法 vs 抽象工厂?

| 维度 | 工厂方法 | 抽象工厂 |
| :--- | :--- | :--- |
| 粒度 | 单个产品 | **一族产品** |
| 方法数 | 1 个 | 多个 |
| 复杂度 | 低 | 高 |
| 例子 | `createLogger()` | `createButton() + createCheckbox()` |

详见 [03-抽象工厂模式](./03-抽象工厂模式.md).

### Q3: 工厂方法 vs DI (依赖注入)?

| 工厂方法 | 依赖注入 |
| :--- | :--- |
| 类自己创建依赖 | 容器创建并注入 |
| 编译时绑定 | 运行时配置 |
| 控制反转弱 | 控制反转强 |

**Spring** 等框架都用 DI 替代工厂方法, 但工厂方法的**思想**仍是核心.
