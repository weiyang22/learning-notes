# 03. 抽象工厂模式 (Abstract Factory)

> **一句话**: 创建一系列**相关或相互依赖**的对象, 而无需指定它们的具体类.

---

## 1. 核心问题

**工厂方法**只能创建**一种**产品, 但实际中常常需要创建**一族**产品:

- **跨平台 UI**: 按钮 + 文本框 + 滚动条 (Windows / Mac 风格)
- **数据库访问**: Connection + Command + Transaction (MySQL / Oracle)
- **游戏主题**: 道路 + 建筑 + 障碍物 (冬季 / 夏季)

**问题**: 这些产品**必须配套**使用 (Windows 按钮配 Windows 文本框), 不能混搭.

---

## 2. 模式结构

```text
                    ┌──────────────────────┐
                    │   <<abstract factory>>│
                    │    GUIFactory          │
                    ├──────────────────────┤
                    │ +createButton()        │
                    │ +createTextField()     │
                    │ +createCheckbox()     │
                    └──────────△────────────┘
                               │ (继承)
                ┌──────────────┴──────────────┐
                │                             │
   ┌──────────────────────┐      ┌──────────────────────┐
   │  WindowsFactory       │      │   MacFactory          │
   ├──────────────────────┤      ├──────────────────────┤
   │+createButton()        │      │+createButton()        │
   │  → WindowsButton      │      │  → MacButton          │
   │+createTextField()     │      │+createTextField()     │
   │  → WindowsTextField   │      │  → MacTextField       │
   └──────────△────────────┘      └──────────△────────────┘
              │                              │
       ┌──────┴────────┐              ┌───────┴────────┐
       │WindowsButton   │              │  MacButton    │
       ├───────────────┤              ├───────────────┤
       │+render()      │              │+render()      │
       └───────────────┘              └───────────────┘
```

**核心**:
- **AbstractFactory**: 抽象工厂接口 (含多个工厂方法)
- **ConcreteFactory**: 具体工厂, 创建一组产品
- **AbstractProduct**: 抽象产品 (多个, 如 Button, TextField)
- **ConcreteProduct**: 具体产品 (按家族分类, 如 WindowsButton, MacButton)

## 3. Python 实现

```python
from abc import ABC, abstractmethod

# 1. 抽象产品: Button
class Button(ABC):
    @abstractmethod
    def render(self): pass

class TextField(ABC):
    @abstractmethod
    def render(self): pass

class Checkbox(ABC):
    @abstractmethod
    def render(self): pass

# 2. 具体产品: Windows 系列
class WindowsButton(Button):
    def render(self):
        return "[Windows 风格按钮]"

class WindowsTextField(TextField):
    def render(self):
        return "[Windows 风格文本框]"

class WindowsCheckbox(Checkbox):
    def render(self):
        return "[Windows 风格复选框]"

# 3. 具体产品: Mac 系列
class MacButton(Button):
    def render(self):
        return "[Mac 风格按钮]"

class MacTextField(TextField):
    def render(self):
        return "[Mac 风格文本框]"

class MacCheckbox(Checkbox):
    def render(self):
        return "[Mac 风格复选框]"

# 4. 抽象工厂
class GUIFactory(ABC):
    @abstractmethod
    def create_button(self) -> Button: pass
    
    @abstractmethod
    def create_text_field(self) -> TextField: pass
    
    @abstractmethod
    def create_checkbox(self) -> Checkbox: pass

# 5. 具体工厂
class WindowsFactory(GUIFactory):
    def create_button(self): return WindowsButton()
    def create_text_field(self): return WindowsTextField()
    def create_checkbox(self): return WindowsCheckbox()

class MacFactory(GUIFactory):
    def create_button(self): return MacButton()
    def create_text_field(self): return MacTextField()
    def create_checkbox(self): return MacCheckbox()

# 6. 客户端
class Application:
    def __init__(self, factory: GUIFactory):
        self.factory = factory
    
    def render(self):
        print(self.factory.create_button().render())
        print(self.factory.create_text_field().render())
        print(self.factory.create_checkbox().render())

# 使用
app = Application(WindowsFactory())
app.render()
# [Windows 风格按钮]
# [Windows 风格文本框]
# [Windows 风格复选框]

app = Application(MacFactory())
app.render()
# [Mac 风格按钮]
# ...
```

## 4. Java 实现

```java
// 1. 抽象产品
public interface Button { void render(); }
public interface Checkbox { void render(); }

// 2. 具体产品 - Windows
public class WindowsButton implements Button {
    public void render() { System.out.println("Windows 按钮"); }
}
public class WindowsCheckbox implements Checkbox {
    public void render() { System.out.println("Windows 复选框"); }
}

// 3. 具体产品 - Mac
public class MacButton implements Button {
    public void render() { System.out.println("Mac 按钮"); }
}
public class MacCheckbox implements Checkbox {
    public void render() { System.out.println("Mac 复选框"); }
}

// 4. 抽象工厂
public interface GUIFactory {
    Button createButton();
    Checkbox createCheckbox();
}

// 5. 具体工厂
public class WindowsFactory implements GUIFactory {
    public Button createButton() { return new WindowsButton(); }
    public Checkbox createCheckbox() { return new WindowsCheckbox(); }
}

public class MacFactory implements GUIFactory {
    public Button createButton() { return new MacButton(); }
    public Checkbox createCheckbox() { return new MacCheckbox(); }
}

// 6. 客户端
public class Application {
    private final Button button;
    private final Checkbox checkbox;
    
    public Application(GUIFactory factory) {
        button = factory.createButton();
        checkbox = factory.createCheckbox();
    }
    
    public void render() {
        button.render();
        checkbox.render();
    }
}
```

## 5. 实际应用

### 5.1 Java AWT/Swing 跨平台 UI

```java
// AWT 使用抽象工厂
Button button = Toolkit.getDefaultToolkit().createButton();
// Windows 返回 WindowsButton
// Mac 返回 MacButton
```

### 5.2 JDBC 数据库连接

```java
// 不同数据库有不同的工厂实现
Connection conn = DriverManager.getConnection(url, user, pwd);
// MySQL 驱动返回 MySQLConnectionImpl
// PostgreSQL 驱动返回 PgConnectionImpl

// 每个 Connection 创建自己的 Statement, ResultSet
// 这些都是同一族产品
```

### 5.3 Spring Data Redis

```java
// Redis 抽象工厂: JedisConnectionFactory
// 根据配置创建不同的 Redis 连接工厂
@Bean
public RedisConnectionFactory redisConnectionFactory() {
    return new JedisConnectionFactory(redisConfig);
}
```

## 6. 优缺点

### 优点

✅ **保证产品族一致性**: 一族产品必须配套 (Mac 按钮 + Mac 文本框)

✅ **解耦**: 客户端与产品实现解耦

✅ **符合开闭原则**: 增加新族只需加新工厂

✅ **单一职责**: 每个工厂只负责创建自己族的产品

### 缺点

❌ **类数量爆炸**: 每加一族产品就要加 N 个类 (N = 产品数)

❌ **扩展产品族难**: 在已有族里加新产品 (比如加 Tooltip), 要改所有工厂

❌ **复杂度高**: 适合产品族稳定, 不常变的场景

---

## 7. 工厂方法 vs 抽象工厂

| 维度 | 工厂方法 | 抽象工厂 |
| :--- | :--- | :--- |
| 粒度 | **单个**产品 | **一族**产品 |
| 方法数 | 1 个 | 多个 |
| 复杂度 | 低 | 高 |
| 扩展 | 容易 (加子类) | 难 (改所有工厂) |
| 一致性 | 不保证 | 保证 (同族产品) |

**简单记忆**:
- **工厂方法**: 一个工厂生产**一种**产品
- **抽象工厂**: 一个工厂生产**一族**产品

## 8. 实战思考

### Q1: 抽象工厂 vs Spring Bean?

| 抽象工厂 | Spring IoC |
| :--- | :--- |
| 编译期确定 | 运行时配置 |
| 类数量多 | 配置驱动 |
| 显式多态 | 反射 + 注解 |

Spring 的 `BeanFactory` 本质上是一个巨大的抽象工厂, 但更灵活.

### Q2: 抽象工厂是不是过度设计?

✅ **适合**:
- 产品族**稳定** (Windows / Mac / Linux 风格多年不变)
- 产品必须**配套使用** (数据库 connection + statement)

❌ **不适合**:
- 产品经常变 (不如用工厂方法)
- 产品族之间没有关联 (不如直接 new)

### Q3: 抽象工厂 vs 简单工厂?

简单工厂: **一个工厂**类, **if-else** 创建不同产品
抽象工厂: **一族工厂**类, 每个工厂负责一组产品

简单工厂**违反开闭原则** (加新产品要改工厂), 抽象工厂**符合** (加新产品族不动现有代码).
