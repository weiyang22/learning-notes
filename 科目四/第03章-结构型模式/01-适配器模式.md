# 01. 适配器模式 (Adapter)

> **一句话**: 将一个类的接口**转换成**客户希望的另一个接口, 使原本因接口不兼容而不能一起工作的类可以**协同工作**.

**别名**: Wrapper (包装器)

---

## 1. 核心问题

老系统 / 第三方库的接口与新系统不兼容, 但又不能改原有代码:

```java
// 老接口 (第三方库)
public class OldLogger {
    public void writeLog(String msg) {  // 方法名不一致
        System.out.println("[OLD] " + msg);
    }
}

// 新接口 (自己系统定义的)
public interface NewLogger {
    void log(String message);  // 想用 log, 不是 writeLog
}
```

**问题**:
- 不能改老类 (可能没有源码)
- 又想用新接口统一调用

---

## 2. 模式结构

### 2.1 对象适配器 (组合)

```text
         ┌────────────────────┐
         │   <<Target>>        │ ← 客户期望的接口
         │      Target         │
         ├────────────────────┤
         │ +request(): void   │
         └──────────△─────────┘
                    │ (实现)
         ┌──────────┴─────────┐
         │     Adapter        │
         ├────────────────────┤
         │ -adaptee: Adaptee   │ ← 持有被适配者引用
         ├────────────────────┤
         │ +request(): void   │ ← 调用 adaptee 的方法
         └──────────┬─────────┘
                    │ 引用
         ┌──────────┴─────────┐
         │     Adaptee        │ ← 老接口 (需要适配)
         ├────────────────────┤
         │ +specificRequest() │
         └────────────────────┘
```

### 2.2 类适配器 (继承)

```text
         ┌────────────────────┐
         │     Adapter        │
         ├────────────────────┤
         │ extends Adaptee    │ ← 通过继承
         │ implements Target  │ ← 实现目标接口
         ├────────────────────┤
         │ +request()         │ ← 覆写, 调用父类方法
         └────────────────────┘
```

**Java 单继承限制**: 类适配器只能适配一个类, **对象适配器更灵活**.

## 3. Python 实现

### 3.1 对象适配器

```python
# 老接口 (不可修改, 如第三方库)
class OldLogger:
    def write_log(self, msg):
        print(f"[OLD] {msg}")

# 新接口 (自己定义)
from abc import ABC, abstractmethod

class NewLogger(ABC):
    @abstractmethod
    def log(self, msg): pass

# 适配器
class LoggerAdapter(NewLogger):
    def __init__(self, old_logger: OldLogger):
        self.old_logger = old_logger
    
    def log(self, msg):
        # 转换: 调用老接口
        self.old_logger.write_log(msg)

# 使用
old = OldLogger()
adapter = LoggerAdapter(old)
adapter.log("Hello")  # [OLD] Hello
```

### 3.2 多接口适配器

```python
# 假设我们需要适配多个老类
class FileStorage:
    def save_file(self, path, content):
        with open(path, "w") as f:
            f.write(content)

class CloudStorage:
    def upload(self, bucket, key, data):
        print(f"上传到 {bucket}/{key}: {data}")

# 统一接口
class StorageAdapter(NewLogger):  # 假装继承 NewLogger 表示统一接口
    def __init__(self, storage, storage_type):
        self.storage = storage
        self.type = storage_type
    
    def save(self, path, data):
        if self.type == "file":
            self.storage.save_file(path, data)
        elif self.type == "cloud":
            bucket, key = path.split("/", 1)
            self.storage.upload(bucket, key, data)
```

## 4. Java 实现

### 4.1 类适配器 (单继承)

```java
// 目标接口
public interface Target {
    void request();
}

// 被适配者 (老接口)
public class Adaptee {
    public void specificRequest() {
        System.out.println("老接口调用");
    }
}

// 类适配器 (Java 多继承不行, 所以用单继承 + 实现接口)
public class Adapter extends Adaptee implements Target {
    @Override
    public void request() {
        // 调用父类方法 (老接口)
        specificRequest();
    }
}

// 使用
Target t = new Adapter();
t.request();  // "老接口调用"
```

### 4.2 对象适配器 (推荐)

```java
public class Adapter implements Target {
    private Adaptee adaptee;
    
    public Adapter(Adaptee adaptee) {
        this.adaptee = adaptee;
    }
    
    @Override
    public void request() {
        // 委托给被适配者
        adaptee.specificRequest();
    }
}

// 使用
Target t = new Adapter(new Adaptee());
t.request();
```

## 5. 实际应用

### 5.1 Java I/O 流 (经典适配器)

```java
// InputStreamReader 把字节流适配成字符流
InputStream is = new FileInputStream("data.txt");
Reader reader = new InputStreamReader(is, "UTF-8");
// 现在能用 Reader 接口读字节流

// OutputStreamWriter 反过来
Writer writer = new OutputStreamWriter(System.out, "UTF-8");
```

### 5.2 Spring MVC HandlerAdapter

```java
// Spring 把各种 Controller (注解/实现接口/继承类) 适配成 HandlerExecutionChain
// HandlerAdapter 接口
public interface HandlerAdapter {
    boolean supports(Object handler);
    ModelAndView handle(HttpServletRequest request, ...);
}

// 多个实现
SimpleServletHandlerAdapter    // 处理实现 Servlet 接口的 Controller
SimpleControllerHandlerAdapter  // 处理继承 Controller 的
RequestMappingHandlerAdapter    // 处理 @RequestMapping 注解的
```

### 5.3 Java Arrays.asList

```java
// Arrays.asList 返回的 List 是数组的适配器
String[] arr = {"a", "b", "c"};
List<String> list = Arrays.asList(arr);
// list 是数组的视图 (适配器), 修改会互相影响
list.set(0, "x");
System.out.println(arr[0]);  // "x"
```

### 5.4 JavaScript jQuery

```javascript
// jQuery 是 DOM API 的适配器
// 现代浏览器: document.querySelectorAll()
// 老 IE: document.getElementsByTagName()
// jQuery 统一为 $() 接口
$('.btn').on('click', handler);
```

### 5.5 Python requests 库

```python
# requests 内部用适配器连接不同 HTTP 库
# https://github.com/psf/requests/tree/master/requests/adapters
# HTTPAdapter 可以挂载到 Session
import requests
s = requests.Session()
s.mount('https://', HTTPAdapter(max_retries=3))
```

## 6. 优缺点

### 优点

✅ **复用已有类**: 不修改老代码

✅ **解耦**: 客户端面向目标接口, 不依赖老接口

✅ **灵活性**: 对象适配器可适配多个 Adaptee

✅ **符合开闭原则**: 新增 Adapter 不改原有

### 缺点

❌ **类数量增加**: 每个老接口可能需要适配器

❌ **过多适配器**: 表示设计问题 (接口不一致)

❌ **性能**: 多一层调用有开销

## 7. 实战思考

### Q1: 适配器 vs 装饰器?

| 适配器 | 装饰器 |
| :--- | :--- |
| **转换接口** | **添加职责** |
| 改变对象行为 | 不改变接口 |
| 通常包装 1 个 | 可以嵌套多层 |

```java
// 适配器: 不同接口 -> 统一接口
Target t = new Adapter(oldImpl);

// 装饰器: 同接口 -> 添加功能
InputStream decorated = new BufferedInputStream(
    new GZIPInputStream(fileStream)
);
```

### Q2: 什么时候用适配器?

✅ **集成第三方库**: SDK 接口与你的接口不一致

✅ **老系统迁移**: 老 API 需要包装成新 API

✅ **统一多种实现**: 不同数据库驱动, 不同 UI 风格

✅ **测试**: 包装 Mock 对象以适配接口

❌ **能改原代码**: 直接改更好

❌ **接口差异太大**: 适配器会变得很复杂

### Q3: 双向适配器?

如果需要双向转换:

```python
class BidirectionalAdapter:
    def to_new(self, old_obj):
        # 老 -> 新
        ...
    
    def to_old(self, new_obj):
        # 新 -> 老
        ...
```

但实际很少用, 通常单向就够了.
