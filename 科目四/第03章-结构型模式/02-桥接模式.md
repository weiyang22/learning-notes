# 02. 桥接模式 (Bridge)

> **一句话**: 将**抽象部分**与它的**实现部分**分离, 使它们都可以**独立地变化**.

---

## 1. 核心问题

**继承爆炸** 问题:

```python
# ❌ 反例: 用继承表达 形状 + 颜色
class RedCircle: pass
class RedSquare: pass
class RedTriangle: pass
class BlueCircle: pass
class BlueSquare: pass
class BlueTriangle: pass
class GreenCircle: pass
class GreenSquare: pass
class GreenTriangle: pass
# 3 种形状 × 3 种颜色 = 9 个类!
```

**问题**:
- 每加一个形状或颜色, 类数量**相乘增长**
- 形状和颜色**紧耦合**
- 修改颜色逻辑要改所有形状

---

## 2. 模式结构

```text
            ┌──────────────────┐
            │  <<Abstraction>>  │  ← 抽象 (高层)
            │    Shape          │
            ├──────────────────┤
            │ -impl: Implementor│  ← 桥接 (持有引用)
            ├──────────────────┤
            │ +draw()           │
            └──────────△───────┘
                       │ (继承)
        ┌──────────────┴──────────────┐
        │                             │
  ┌────────────────────┐   ┌────────────────────┐
  │ RefinedAbstraction1 │   │ RefinedAbstraction2 │
  ├────────────────────┤   ├────────────────────┤
  │+draw()            │   │+draw()            │
  └────────────────────┘   └────────────────────┘
            △                             △
            │ (委托)                      │
            └──────────────┬──────────────┘
                           │
                ┌──────────▼────────────┐
                │  <<Implementor>>      │  ← 实现 (底层)
                │      Color           │
                ├──────────────────────┤
                │ +applyColor()        │
                └──────────△──────────┘
                           │ (继承)
            ┌──────────────┴────────────┐
            │                            │
   ┌─────────────────┐         ┌─────────────────┐
   │ RedColor        │         │ BlueColor       │
   ├─────────────────┤         ├─────────────────┤
   │+applyColor()    │         │+applyColor()    │
   └─────────────────┘         └─────────────────┘
```

**核心**: 用**组合 (桥接)** 替代 **继承 (耦合)**.

---

## 3. Python 实现

```python
from abc import ABC, abstractmethod

# 1. 实现部分: 颜色
class Color(ABC):
    @abstractmethod
    def apply(self): pass

class RedColor(Color):
    def apply(self):
        return "红色"

class BlueColor(Color):
    def apply(self):
        return "蓝色"

class GreenColor(Color):
    def apply(self):
        return "绿色"

# 2. 抽象部分: 形状
class Shape(ABC):
    def __init__(self, color: Color):
        self.color = color  # 桥接!
    
    @abstractmethod
    def draw(self): pass

class Circle(Shape):
    def draw(self):
        return f"{self.color.apply()} 圆形"

class Square(Shape):
    def draw(self):
        return f"{self.color.apply()} 正方形"

class Triangle(Shape):
    def draw(self):
        return f"{self.color.apply()} 三角形"

# 使用 - 组合创建
red_circle = Circle(RedColor())
blue_square = Square(BlueColor())
green_triangle = Triangle(GreenColor())

print(red_circle.draw())     # 红色 圆形
print(blue_square.draw())     # 蓝色 正方形
print(green_triangle.draw())  # 绿色 三角形

# 加新颜色: 1 个类
class YellowColor(Color):
    def apply(self): return "黄色"

# 加新形状: 1 个类
class Pentagon(Shape):
    def draw(self): return f"{self.color.apply()} 五角形"

# 组合爆炸? 不会! 因为通过组合, 类数 = 形状数 + 颜色数
# 而非 形状数 × 颜色数
```

## 4. Java 实现

```java
// 1. 实现部分
public interface Color {
    String applyColor();
}

public class Red implements Color {
    public String applyColor() { return "红色"; }
}

public class Blue implements Color {
    public String applyColor() { return "蓝色"; }
}

// 2. 抽象部分
public abstract class Shape {
    protected Color color;  // 桥接!
    
    public Shape(Color color) {
        this.color = color;
    }
    
    public abstract void draw();
}

public class Circle extends Shape {
    public Circle(Color color) { super(color); }
    public void draw() { System.out.println(color.applyColor() + " 圆形"); }
}

public class Square extends Shape {
    public Square(Color color) { super(color); }
    public void draw() { System.out.println(color.applyColor() + " 正方形"); }
}

// 使用
Shape redCircle = new Circle(new Red());
Shape blueSquare = new Square(new Blue());
redCircle.draw();   // 红色 圆形
blueSquare.draw();  // 蓝色 正方形
```

## 5. 实际应用

### 5.1 JDBC 驱动

```java
// JDBC 是桥接模式的经典案例
// 抽象: java.sql.Driver (接口)
// 实现: 各个数据库的 Driver (MySQL, PostgreSQL, Oracle)

// Connection 是抽象, 但依赖 Driver (实现)
Connection conn = DriverManager.getConnection(url, user, pwd);

// 加新数据库 (如 ClickHouse)? 加新 Driver 即可
// 改数据库? 换 URL, 应用代码不动
```

### 5.2 Java AWT 跨平台

```java
// 抽象: Button, TextField (java.awt.Button)
// 实现: WindowsButton, MacButton (sun.awt.windows / sun.awt.mac)

// Button 持有一个 implementation 引用
public class Button {
    private PlatformImplementation impl;  // 桥接
    public void paint() {
        impl.paintButton(this);
    }
}
```

### 5.3 Spring 日志

```java
// Spring JCL (Jakarta Commons Logging) 是桥接
// 抽象: org.apache.commons.logging.Log 接口
// 实现: log4j, logback, JUL

// 应用代码用 Log 接口, 底层可以切换任何实现
Log log = LogFactory.getLog(MyClass.class);
log.info("Hello");
// 实现可能换了, 代码不用改
```

### 5.4 Java InputStream

```java
// 字节流 -> 字符流 的桥接
InputStream is = new FileInputStream("file.txt");
Reader reader = new InputStreamReader(is, StandardCharsets.UTF_8);
// InputStreamReader 桥接 字节流 API -> 字符流 API
```

## 6. 优缺点

### 优点

✅ **解耦**: 抽象和实现独立变化

✅ **扩展性强**: 加新形状/颜色互不影响

✅ **避免类爆炸**: N + M 类, 不是 N × M

✅ **运行时切换实现**: 注入不同的 Color

### 缺点

❌ **增加设计复杂度**: 抽象层 + 实现层

❌ **需要提前识别维度**: 抽象和实现的边界

❌ **不易理解**: 新手需要时间理解

## 7. 实战思考

### Q1: 桥接 vs 适配器?

| 桥接 | 适配器 |
| :--- | :--- |
| **设计阶段**就用 | **事后**补救已有不兼容 |
| 抽象和实现都**独立变化** | 把已有接口**适配**到目标 |
| 预防性 | 解决性 |

**桥接**: 设计时就考虑分离, 如 JDBC

**适配器**: 老接口没法改, 加个适配器

### Q2: 桥接 vs 策略模式?

| 桥接 | 策略 |
| :--- | :--- |
| 结构型 (类/对象组合) | 行为型 (算法替换) |
| 抽象层 + 实现层 | Context + Strategy |
| 关注**结构**解耦 | 关注**算法**替换 |

**桥接**: 关注"如何拆分类"

**策略**: 关注"如何让算法可替换"

### Q3: 什么时候用桥接?

✅ **两个独立变化的维度**: 形状+颜色, 平台+UI

✅ **不希望使用继承**: 类数量爆炸

✅ **抽象和实现都要扩展**: 比如 JDBC

❌ **只有一个维度变化**: 用继承就够了

❌ **抽象和实现紧耦合**: 不如直接 new

✅ **核心**: 用组合替代继承, 解耦抽象和实现

✅ **应用**: JDBC 驱动, AWT 跨平台, Spring 日志

✅ **关键**: 识别两个独立变化的维度
