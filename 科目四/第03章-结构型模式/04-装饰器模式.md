# 04. 装饰器模式 (Decorator)

> **一句话**: **动态地**给一个对象添加一些**额外的职责**, 就增加功能来说, 装饰器模式相比生成子类更为**灵活**.

**别名**: 包装器模式 (Wrapper), 油漆工模式

---

## 1. 核心问题

咖啡店订单系统, 每杯咖啡可以加各种配料:

| 咖啡 | 价格 |
| :--- | :--- |
| 美式 | ¥20 |
| 拿铁 | ¥25 |
| 卡布奇诺 | ¥28 |

**配料**:

| 配料 | 价格 |
| :--- | :--- |
| 加奶 | +¥3 |
| 加糖 | +¥1 |
| 加巧克力 | +¥5 |

**问题**: 如果用继承表示组合, 会**类爆炸**:

```java
// ❌ 继承爆炸: 咖啡 × 配料组合
class 美式加奶: ¥23
class 美式加糖: ¥21
class 美式加奶加糖: ¥24
class 拿铁加奶: ¥28
class 拿铁加糖: ¥26
// 3 种咖啡 × 2^N 种配料组合 = 类爆炸!
```

**更好的方式**: 装饰器模式, **运行时**动态地给咖啡加配料:

```text
美式咖啡
  → 装饰一层加奶 → 美式咖啡+奶 (¥23)
    → 装饰一层加糖 → 美式咖啡+奶+糖 (¥24)
```

## 2. UML 类图

```text
              ┌─────────────────────┐
              │   <<Component>>      │ ← 抽象组件
              │      Coffee          │
              ├─────────────────────┤
              │ +getCost(): float   │
              │ +getDescription():  │
              │      String         │
              └──────────△──────────┘
                         │ (实现)
        ┌────────────────┴────────────────┐
        │                                 │
  ┌───────────────┐              ┌────────────────────┐
  │ ConcreteComp. │              │  <<Decorator>>      │
  │  Americano    │              │  CoffeeDecorator   │
  ├───────────────┤              ├────────────────────┤
  │+getCost()     │              │ -coffee: Coffee    │ ← 持有被装饰者
  │+getDesc()     │              ├────────────────────┤
  └───────────────┘              │+getCost()          │
                                 │+getDescription()   │
                                 └──────────△─────────┘
                                            │ (继承)
                          ┌─────────────────┴────────────────┐
                          │                                  │
                  ┌──────────────────┐            ┌──────────────────┐
                  │ ConcreteDecorator │           │ ConcreteDecorator │
                  │      Milk         │           │      Sugar       │
                  ├──────────────────┤            ├──────────────────┤
                  │+getCost()        │            │+getCost()        │
                  │+getDescription() │            │+getDescription() │
                  └──────────────────┘            └──────────────────┘
```

**核心**:
- `Decorator` **持有** Component (同一类型)
- 每个 Decorator **递归委托**给内部 component, 再加自己的职责
- 可以**多层嵌套**: `new Milk(new Sugar(new Americano()))`

## 3. Python 实现

```python
"""
装饰器模式 - 咖啡店订单系统
演示: 给咖啡动态添加配料
"""
from abc import ABC, abstractmethod


# ===== 1. 抽象组件 =====
class Coffee(ABC):
    """咖啡抽象组件"""

    @abstractmethod
    def get_cost(self) -> float:
        """获取价格"""
        pass

    @abstractmethod
    def get_description(self) -> str:
        """获取描述"""
        pass


# ===== 2. 具体组件 - 具体咖啡 =====
class Americano(Coffee):
    """美式咖啡"""

    def get_cost(self) -> float:
        return 20.0

    def get_description(self) -> str:
        return "美式咖啡"


class Latte(Coffee):
    """拿铁咖啡"""

    def get_cost(self) -> float:
        return 25.0

    def get_description(self) -> str:
        return "拿铁咖啡"


# ===== 3. 装饰器基类 =====
class CoffeeDecorator(Coffee):
    """
    装饰器基类 - 关键设计点:
    1. 继承自 Coffee (同一类型)
    2. 持有 Coffee 引用 (被装饰者)
    """

    def __init__(self, coffee: Coffee):
        self._coffee = coffee  # 持有被装饰者

    def get_cost(self) -> float:
        # 默认: 委托给被装饰者
        return self._coffee.get_cost()

    def get_description(self) -> str:
        # 默认: 委托给被装饰者
        return self._coffee.get_description()


# ===== 4. 具体装饰器 - 配料 =====
class MilkDecorator(CoffeeDecorator):
    """加奶装饰器"""

    def get_cost(self) -> float:
        return self._coffee.get_cost() + 3.0  # 加奶 +¥3

    def get_description(self) -> str:
        return self._coffee.get_description() + " + 牛奶"


class SugarDecorator(CoffeeDecorator):
    """加糖装饰器"""

    def get_cost(self) -> float:
        return self._coffee.get_cost() + 1.0  # 加糖 +¥1

    def get_description(self) -> str:
        return self._coffee.get_description() + " + 糖"


class ChocolateDecorator(CoffeeDecorator):
    """加巧克力装饰器"""

    def get_cost(self) -> float:
        return self._coffee.get_cost() + 5.0  # 加巧克力 +¥5

    def get_description(self) -> str:
        return self._coffee.get_description() + " + 巧克力"


# ===== 5. 客户端 - 自由组合 =====
def main():
    print("=" * 50)
    print("☕ 装饰器模式 - 咖啡订单系统")
    print("=" * 50)

    # 订单 1: 美式 + 奶 + 糖
    coffee1 = Americano()
    coffee1 = MilkDecorator(coffee1)    # 第一层装饰
    coffee1 = SugarDecorator(coffee1)   # 第二层装饰
    print(f"\n订单 1: {coffee1.get_description()}")
    print(f"价格: ¥{coffee1.get_cost()}")

    # 订单 2: 拿铁 + 巧克力 + 巧克力 (双份巧克力)
    coffee2 = Latte()
    coffee2 = ChocolateDecorator(coffee2)
    coffee2 = ChocolateDecorator(coffee2)
    print(f"\n订单 2: {coffee2.get_description()}")
    print(f"价格: ¥{coffee2.get_cost()}")

    # 订单 3: 美式 (无配料)
    coffee3 = Americano()
    print(f"\n订单 3: {coffee3.get_description()}")
    print(f"价格: ¥{coffee3.get_cost()}")

    # 订单 4: 任意组合 - 拿铁 + 奶 + 糖 + 巧克力
    coffee4 = Latte()
    coffee4 = MilkDecorator(coffee4)
    coffee4 = SugarDecorator(coffee4)
    coffee4 = ChocolateDecorator(coffee4)
    print(f"\n订单 4: {coffee4.get_description()}")
    print(f"价格: ¥{coffee4.get_cost()}")

    # 演示 Python 内置 @decorator 语法糖
    print("\n" + "=" * 50)
    print("Python @decorator 语法糖 (装饰器模式的应用)")
    print("=" * 50)

    def my_decorator(func):
        def wrapper(*args, **kwargs):
            print(f"  [日志] 调用函数 {func.__name__}")
            result = func(*args, **kwargs)
            print(f"  [日志] 函数 {func.__name__} 执行完毕")
            return result
        return wrapper

    @my_decorator
    def say_hello(name):
        print(f"  Hello, {name}!")

    say_hello("World")


if __name__ == "__main__":
    main()
```

## 4. Java 实现

```java
// ===== 1. 抽象组件 =====
public abstract class Coffee {
    public abstract double getCost();
    public abstract String getDescription();
}

// ===== 2. 具体组件 =====
public class Americano extends Coffee {
    @Override
    public double getCost() { return 20.0; }

    @Override
    public String getDescription() { return "美式咖啡"; }
}

public class Latte extends Coffee {
    @Override
    public double getCost() { return 25.0; }

    @Override
    public String getDescription() { return "拿铁咖啡"; }
}

// ===== 3. 装饰器基类 =====
public abstract class CoffeeDecorator extends Coffee {
    protected Coffee coffee;  // 持有被装饰者

    public CoffeeDecorator(Coffee coffee) {
        this.coffee = coffee;
    }

    @Override
    public double getCost() { return coffee.getCost(); }

    @Override
    public String getDescription() { return coffee.getDescription(); }
}

// ===== 4. 具体装饰器 =====
public class Milk extends CoffeeDecorator {
    public Milk(Coffee coffee) { super(coffee); }

    @Override
    public double getCost() { return coffee.getCost() + 3.0; }

    @Override
    public String getDescription() { return coffee.getDescription() + " + 牛奶"; }
}

public class Sugar extends CoffeeDecorator {
    public Sugar(Coffee coffee) { super(coffee); }

    @Override
    public double getCost() { return coffee.getCost() + 1.0; }

    @Override
    public String getDescription() { return coffee.getDescription() + " + 糖"; }
}

// ===== 5. 客户端 =====
public class Client {
    public static void main(String[] args) {
        Coffee order = new Milk(new Sugar(new Americano()));
        System.out.println(order.getDescription());  // 美式咖啡 + 糖 + 牛奶
        System.out.println("价格: ¥" + order.getCost());  // ¥24.0
    }
}
```

## 5. 实际应用

### 5.1 Java I/O 流 (经典案例)

```java
// Java I/O 流是装饰器模式的教科书级应用
// 装饰器链: 字节流 -> 缓冲流 -> 数据流
InputStream in = new FileInputStream("data.txt");
in = new BufferedInputStream(in);   // 装饰一层: 缓冲
in = new DataInputStream(in);       // 再装饰一层: 读 Java 类型

// 每一层都增强输入流:
// - BufferedInputStream: 加缓冲 (提高性能)
// - DataInputStream: 加 readInt(), readDouble() 等方法
// - GZIPInputStream: 加解压
```

**装饰器家族**:

```text
InputStream (Component)
├── FileInputStream (ConcreteComponent) - 基础字节流
├── ByteArrayInputStream (ConcreteComponent)
└── FilterInputStream (Decorator)
    ├── BufferedInputStream (ConcreteDecorator) - 加缓冲
    ├── DataInputStream (ConcreteDecorator) - 加数据类型
    ├── GZIPInputStream (ConcreteDecorator) - 加解压
    └── CipherInputStream (ConcreteDecorator) - 加解密
```

### 5.2 Python @decorator 语法

```python
# Python @decorator 是装饰器模式的语法糖

# 场景 1: 函数装饰器
@functools.lru_cache(maxsize=128)  # 加缓存
def fibonacci(n):
    if n < 2: return n
    return fibonacci(n-1) + fibonacci(n-2)

# 场景 2: 类装饰器
@dataclass  # 加 __init__, __repr__, __eq__
class Point:
    x: int
    y: int

# 场景 3: 多个装饰器叠加 (多层装饰)
@login_required           # 检查登录
@rate_limit(max=10)       # 限流
@timer                    # 计时
def api_view(request):
    return JsonResponse({...})
```

### 5.3 Spring AOP 装饰器

```java
// Spring AOP 本质上是装饰器模式的应用
// 业务方法被各种切面装饰

@Service
public class OrderService {
    @Transactional       // 装饰层 1: 事务
    @Cacheable("orders") // 装饰层 2: 缓存
    @LogExecution        // 装饰层 3: 日志
    public Order createOrder(Order order) {
        // 实际业务逻辑
        return orderRepository.save(order);
    }
}
// 执行顺序: 日志 → 事务 → 缓存 → 业务方法
```

### 5.4 Servlet HttpServletRequestWrapper

```java
// Tomcat/Jetty 用装饰器包装 HttpServletRequest
// 添加读取 body 多次、过滤参数等功能

public class CachedBodyHttpServletRequest extends HttpServletRequestWrapper {
    // 装饰器: 让 InputStream 可重复读
    @Override
    public ServletInputStream getInputStream() throws IOException {
        // 缓存 body 到 byte[], 多次读取
    }
}
```

### 5.5 Java Reader/Writer

```java
// 字符流的装饰器
Reader reader = new FileReader("file.txt");
reader = new BufferedReader(reader);  // 加缓冲, 支持 readLine()
// 多层装饰: 缓冲 + 字符集 + 加密...
```

## 6. 优缺点

### 优点

| 优点 | 说明 |
| :--- | :--- |
| ✅ **灵活扩展** | 运行时动态添加职责, 比继承灵活 |
| ✅ **符合开闭原则** | 新增装饰器不修改被装饰者 |
| ✅ **多层组合** | 可以嵌套任意层 (装饰器套装饰器) |
| ✅ **细粒度控制** | 不同对象可独立装饰不同功能 |

### 缺点

| 缺点 | 说明 |
| :--- | :--- |
| ❌ **类数量多** | 多种装饰器组合会创建很多小类 |
| ❌ **调试困难** | 多层嵌套后调用栈深 |
| ❌ **类型签名复杂** | `new A(new B(new C(x)))` 难读 |
| ❌ **装饰顺序敏感** | 不同顺序可能有不同效果 |

## 7. 实战思考

### Q1: 装饰器 vs 继承?

| 装饰器 | 继承 |
| :--- | :--- |
| **运行时**决定添加什么功能 | **编译时**确定 |
| 灵活组合 | 静态绑定 |
| 多层嵌套 | 单层结构 |

```python
# 继承: 编译时确定所有功能
class StreamWithBufferAndEncryption: pass  # 必须预先想到

# 装饰器: 运行时按需组合
stream = EncryptedStream(BufferedStream(FileStream()))
# 可以任意组合, 任意顺序
```

**经验法则**:
- 功能**组合**会**爆炸**: 用装饰器
- 功能**稳定**且**有限**: 用继承

### Q2: 装饰器 vs 代理?

| 装饰器 | 代理 |
| :--- | :--- |
| **添加职责** | **控制访问** |
| 通常客户端知道有装饰 | 客户端**不知道**有代理 (透明) |
| 装饰器**递归委托** | 代理可能**完全替换**行为 |

```java
// 装饰器: 客户端知道在装饰 (传入被装饰者)
new BufferedInputStream(fileStream)

// 代理: 客户端不知道在代理 (通过 Proxy.newProxyInstance)
UserService proxy = (UserService) Proxy.newProxyInstance(
    classLoader, interfaces,
    new LoggingHandler(realUserService)
);
```

### Q3: 装饰器模式的常见误区?

**❌ 错误 1: 装饰器改变了原接口**

```python
# 错误: 装饰器不该新增公开方法 (违反接口一致性)
class LoudMilk(MilkDecorator):
    def shout(self):  # ❌ 装饰器特有的方法
        print("大声!")
# 客户端调用 loud_milk.shout() 就会出问题 (类型不安全)
```

**❌ 错误 2: 装饰器改变了原行为**

```python
# 错误: 装饰器不应修改原有行为
class StrangeMilk(MilkDecorator):
    def get_cost(self):
        return 0  # ❌ 把咖啡变免费了? 不应改变原语义
```

**✅ 正确: 装饰器只**叠加**职责, 不**修改**原职责**
