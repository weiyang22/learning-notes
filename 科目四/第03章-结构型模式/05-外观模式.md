# 05. 外观模式 (Facade)

> **一句话**: 为子系统中的一组接口提供一个**一致的界面**, 此模式定义了一个**高层接口**, 这个接口使得这一子系统更加**容易使用**.

**别名**: 门面模式

---

## 1. 核心问题

启动一台计算机, 内部其实要做**很多事**:

```text
按下电源键 → 实际发生了什么?

1. CPU 初始化寄存器、缓存
2. 内存 (Memory) 自检、清零
3. 硬盘 (Disk) 加载引导扇区
4. BIOS 检查硬件
5. 加载操作系统内核
6. 启动系统服务...
```

**问题**:
- 用户**不想知道**这些细节
- 用户只想按一个按钮: "**开机**"
- 系统内部**多个子系统**协同工作

**用外观模式解决**: 提供一个 `Computer.start()` 方法, 把所有子系统的操作**封装**起来.

---

## 2. UML 类图

```text
       ┌─────────────────────────┐
       │      Client              │ ← 客户端 (用户)
       └─────────────┬───────────┘
                     │ 调用
                     ▼
       ┌─────────────────────────┐
       │   <<Facade>>             │ ← 外观 (高层接口)
       │     Computer             │
       ├─────────────────────────┤
       │ -cpu: CPU               │
       │ -memory: Memory         │
       │ -disk: Disk             │
       ├─────────────────────────┤
       │ +start()                │ ← 一键开机
       │ +shutdown()             │ ← 一键关机
       └─────────────┬───────────┘
                     │ 委托给子系统
       ┌─────────────┴───────────┐
       │     Subsystem Classes    │ ← 子系统
       ├─────────────────────────┤
       │ ┌─────────┐ ┌─────────┐ │
       │ │   CPU   │ │ Memory  │ │
       │ ├─────────┤ ├─────────┤ │
       │ │+freeze()│ │+load()  │ │
       │ │+execute()│ │+clear() │ │
       │ └─────────┘ └─────────┘ │
       │ ┌─────────┐              │
       │ │  Disk   │              │
       │ ├─────────┤              │
       │ │+read()  │              │
       │ │+spinUp()│              │
       │ └─────────┘              │
       └─────────────────────────┘
```

**核心**:
- `Facade` 知道所有子系统, **统一编排**
- 子系统**不知道**外观的存在 (解耦)
- 客户端只依赖**外观**, 不依赖子系统

## 3. Python 实现

```python
"""
外观模式 - 计算机启动系统
演示: 把复杂的子系统调用封装成一个简单接口
"""


# ===== 1. 子系统类 =====
class CPU:
    """CPU 子系统"""

    def freeze(self):
        print("  [CPU] 冻结寄存器")

    def execute(self):
        print("  [CPU] 执行指令")

    def jump(self, position):
        print(f"  [CPU] 跳转到位置 {position}")

    def halt(self):
        print("  [CPU] 停止运行")


class Memory:
    """内存子系统"""

    def load(self, position, data):
        print(f"  [Memory] 加载 {data} 到位置 {position:#x}")

    def clear(self):
        print("  [Memory] 清空内存")


class Disk:
    """硬盘子系统"""

    def read(self, sector, size):
        data = f"BOOT_SECTOR_{sector}"
        print(f"  [Disk] 读取扇区 {sector}, 大小 {size}KB")
        return data

    def spin_down(self):
        print("  [Disk] 停止旋转")


# ===== 2. 外观类 =====
class Computer:
    """
    外观 Facade - 把复杂的启动流程封装成简单接口
    """

    BOOT_ADDRESS = 0x00
    BOOT_SECTOR = 0x01
    SECTOR_SIZE = 1024

    def __init__(self):
        # 持有所有子系统引用
        self.cpu = CPU()
        self.memory = Memory()
        self.disk = Disk()

    def start(self):
        """
        一键开机 - 客户端只需调用这一个方法
        内部编排所有子系统协同工作
        """
        print("\n=== 🚀 计算机启动 ===")
        print("[步骤 1] CPU 冻结")
        self.cpu.freeze()
        self.cpu.jump(self.BOOT_ADDRESS)

        print("\n[步骤 2] 内存自检并清空")
        self.memory.clear()

        print("\n[步骤 3] 硬盘读取引导扇区")
        boot_data = self.disk.read(self.BOOT_SECTOR, self.SECTOR_SIZE)

        print("\n[步骤 4] 加载引导程序到内存")
        self.memory.load(self.BOOT_ADDRESS, boot_data)

        print("\n[步骤 5] CPU 执行")
        self.cpu.execute()

        print("\n=== ✅ 启动完成 ===\n")

    def shutdown(self):
        """
        一键关机
        """
        print("\n=== 🛑 计算机关机 ===")
        self.cpu.halt()
        self.disk.spin_down()
        self.memory.clear()
        print("=== ✅ 关机完成 ===\n")


# ===== 3. 客户端 =====
class User:
    """用户 - 只与外观交互"""

    def __init__(self, computer: Computer):
        self.computer = computer

    def use_computer(self):
        # 用户只调一个方法, 不需要知道 CPU/Memory/Disk 细节
        self.computer.start()
        print("💻 用户使用计算机工作...")
        print()
        self.computer.shutdown()


# ===== 4. 进阶: 子系统直接访问 (高级用户) =====
class AdvancedUser:
    """高级用户 - 可以绕过外观, 直接调子系统"""

    def __init__(self, computer: Computer):
        self.cpu = computer.cpu
        self.memory = computer.memory
        self.disk = computer.disk

    def run_benchmark(self):
        print("\n=== ⚡ 跑分测试 (高级模式) ===")
        self.cpu.freeze()
        self.cpu.jump(0x1000)
        self.memory.load(0x1000, "BENCHMARK_DATA")
        self.cpu.execute()
        print("=== ✅ 跑分完成 ===\n")


def main():
    print("=" * 50)
    print("外观模式 - 计算机启动系统演示")
    print("=" * 50)

    # 创建计算机
    computer = Computer()

    # 普通用户: 一键开机
    user = User(computer)
    user.use_computer()

    # 高级用户: 直接操作子系统
    advanced = AdvancedUser(computer)
    advanced.run_benchmark()


if __name__ == "__main__":
    main()
```

## 4. Java 实现

```java
// ===== 1. 子系统 =====
public class CPU {
    public void freeze() { System.out.println("[CPU] 冻结寄存器"); }
    public void execute() { System.out.println("[CPU] 执行指令"); }
    public void jump(int pos) { System.out.println("[CPU] 跳转到 " + pos); }
    public void halt() { System.out.println("[CPU] 停止"); }
}

public class Memory {
    public void load(long pos, String data) {
        System.out.println("[Memory] 加载 " + data + " 到 " + pos);
    }
    public void clear() { System.out.println("[Memory] 清空"); }
}

public class Disk {
    public String read(int sector, int size) {
        System.out.println("[Disk] 读扇区 " + sector);
        return "BOOT_DATA";
    }
    public void spinDown() { System.out.println("[Disk] 停止旋转"); }
}

// ===== 2. 外观 =====
public class Computer {
    private CPU cpu = new CPU();
    private Memory memory = new Memory();
    private Disk disk = new Disk();

    public void start() {
        System.out.println("=== 计算机启动 ===");
        cpu.freeze();
        cpu.jump(0);
        memory.clear();
        String data = disk.read(0, 1024);
        memory.load(0, data);
        cpu.execute();
        System.out.println("=== 启动完成 ===");
    }

    public void shutdown() {
        System.out.println("=== 计算机关机 ===");
        cpu.halt();
        disk.spinDown();
        memory.clear();
        System.out.println("=== 关机完成 ===");
    }
}

// ===== 3. 客户端 =====
public class Client {
    public static void main(String[] args) {
        Computer computer = new Computer();
        computer.start();     // 一键启动
        // computer.shutdown(); // 一键关机
    }
}
```

## 5. 实际应用

### 5.1 编译系统 (LLVM/GCC)

```c
// 编译流程: 词法分析 → 语法分析 → 语义分析 → 中间代码 → 优化 → 目标代码
// 用户只想编译, 不想知道每一步

// GCC 外观
gcc main.c -o main
// 内部: cpp (预处理) → cc1 (编译) → as (汇编) → ld (链接)
// gcc 是 Facade, 把这些工具串起来
```

### 5.2 Spring JDBC Template

```java
// Spring JdbcTemplate 是 JDBC 的外观
// JDBC 本身很复杂: DriverManager → Connection → Statement → ResultSet → 关闭...

// 使用 JDBC 原生 API (麻烦):
Connection conn = DriverManager.getConnection(url, user, pwd);
PreparedStatement ps = conn.prepareStatement("SELECT * FROM users WHERE id = ?");
ps.setLong(1, 1L);
ResultSet rs = ps.executeQuery();
while (rs.next()) {
    User user = new User();
    user.setId(rs.getLong("id"));
    user.setName(rs.getString("name"));
}
// 还要手动关闭...

// 使用 JdbcTemplate (外观):
User user = jdbcTemplate.queryForObject(
    "SELECT * FROM users WHERE id = ?",
    new Object[]{1L},
    (rs, rowNum) -> new User(rs.getLong("id"), rs.getString("name"))
);
// 一行搞定!
```

### 5.3 Web 框架的 Service 层

```java
// Controller → Service → Repository (外观)
// Service 是外观: 封装了多个 Repository + 业务逻辑

@Service
public class OrderService {
    @Autowired OrderRepository orderRepo;
    @Autowired InventoryRepository inventoryRepo;
    @Autowired PaymentRepository paymentRepo;

    public void placeOrder(Order order) {
        // 一键下单 = 多个子系统协作
        inventoryRepo.reduce(order);   // 减库存
        paymentRepo.charge(order);      // 收款
        orderRepo.save(order);          // 保存订单
    }
}
// Controller 只调 placeOrder(), 不关心内部细节
```

### 5.4 第三方 SDK 封装

```python
# 阿里云 OSS SDK 内部很复杂
# 用外观模式封装成简单接口

class AliyunOSSFacade:
    def __init__(self, access_key, secret_key, bucket):
        self.client = oss2.Bucket(oss2.Auth(access_key, secret_key),
                                    'https://oss-cn-hangzhou.aliyuncs.com',
                                    bucket)

    def upload_file(self, key, file_path):
        """一键上传"""
        return self.client.put_object_from_file(key, file_path)

    def download_file(self, key, save_path):
        """一键下载"""
        return self.client.get_object_to_file(key, save_path)

    def list_files(self, prefix=''):
        """一键列出文件"""
        return [obj.key for obj in self.client.list_objects(prefix=prefix)]

# 用户用简单接口, 不需了解 OSS 内部
oss = AliyunOSSFacade('ak', 'sk', 'my-bucket')
oss.upload_file('test.txt', '/local/test.txt')
```

### 5.5 Python `subprocess` 简化

```python
# 封装 subprocess 的复杂性
import subprocess

class CommandFacade:
    """命令执行外观"""

    def run(self, cmd):
        """运行命令并返回结果"""
        result = subprocess.run(
            cmd, shell=True, capture_output=True,
            text=True, timeout=60
        )
        return {
            'success': result.returncode == 0,
            'stdout': result.stdout,
            'stderr': result.stderr,
            'code': result.returncode,
        }

# 用户只需:
facade = CommandFacade()
result = facade.run("ls -la")
print(result['stdout'])
```

## 6. 优缺点

### 优点

| 优点 | 说明 |
| :--- | :--- |
| ✅ **简化客户端** | 客户端无需了解子系统细节 |
| ✅ **解耦** | 客户端与子系统松耦合 |
| ✅ **分层** | 外观层做边界, 内部自由重构 |
| ✅ **易维护** | 子系统修改不影响客户端 |

### 缺点

| 缺点 | 说明 |
| :--- | :--- |
| ❌ **违反开闭原则** | 新增功能可能改外观 |
| ❌ **违反单一职责** | 外观可能越来越臃肿 (上帝对象) |
| ❌ **隐藏细节** | 高级用户失去细粒度控制 |
| ❌ **额外间接层** | 多一层调用有性能开销 (通常可忽略) |

## 7. 实战思考

### Q1: 外观 vs 适配器?

| 外观 | 适配器 |
| :--- | :--- |
| **简化已有接口** | **转换不兼容接口** |
| 提供**新高层接口** | 把**老接口**适配到目标 |
| 子系统**仍然可用** | 老接口被**隐藏** |

```python
# 外观: 提供简化接口, 子系统仍可独立用
class Computer:
    def start(self): ...   # 一键启动
# cpu, memory, disk 仍可单独使用

# 适配器: 把老接口转换成新接口
class LoggerAdapter(NewLogger):
    def log(self, msg):
        self.old_logger.write_log(msg)
# 老接口被适配器隐藏
```

### Q2: 外观 vs 中介者?

| 外观 | 中介者 |
| :--- | :--- |
| **单向** (Client → Facade → Subsystems) | **双向** (同事通过中介者通信) |
| 客户端知道外观 | 同事**互相不知道**, 通过中介者 |
| 结构型 | 行为型 |

```python
# 外观: 客户端 → 外观 → 子系统
client.computer.start()  # 客户端知道外观

# 中介者: 同事A ↔ 中介者 ↔ 同事B
chat_room.send("A", "B", "Hi")  # A 和 B 不知道彼此
```

### Q3: 真实项目里如何决定?

| 场景 | 是否用外观 |
| :--- | :--- |
| **封装复杂第三方 SDK** | ✅ 推荐 |
| **为旧系统提供新 API** | ✅ 推荐 |
| **系统分层 (Controller→Service→Repo)** | ✅ Service 是外观 |
| **只有 1-2 个子调用** | ❌ 直接调更简单 |
| **需要灵活配置子系统** | ❌ 外观反而是阻碍 |

**经验法则**:
- **子系统 ≥ 3 个** 或 **调用 ≥ 5 步**, 用外观更划算
- 否则直接调用更清晰
