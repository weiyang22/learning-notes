# 07. 代理模式 (Proxy)

> **一句话**: 为其他对象提供一种**代理**以**控制**对这个对象的访问.

**别名**: Surrogate (代理), Substitute (替代)

---

## 1. 核心问题

图片查看器中, 一篇文章有 50 张图, 每张图可能 5MB:

```python
# ❌ 反例: 创建对象时立即加载所有图片
class Article:
    def __init__(self):
        self.images = [Image(f"img_{i}.jpg") for i in range(50)]
        # 创建时就加载 50 张 5MB 图片 = 250MB!
        # 但用户可能只看到前 3 张就退出
        # 浪费 245MB 内存和加载时间!
```

**问题**:
- 大对象**加载慢**, 占用内存
- 但**实际使用**时可能根本不需要
- 需要按需加载

**代理模式解决**: 用代理对象**代替**真实对象, **按需**加载真实数据:

```text
用户调用 image.display()
    ↓
ImageProxy.display()  ← 代理对象 (轻量)
    ↓ 第一次调用时才加载
RealImage.display()   ← 真实对象 (重量)
```

**代理的四种类型**:

| 类型 | 作用 | 示例 |
| :--- | :--- | :--- |
| **远程代理** | 隐藏远程对象细节 | RPC 客户端 |
| **虚拟代理** | 懒加载大对象 | 图片代理 |
| **保护代理** | 控制访问权限 | Spring Security |
| **智能引用** | 添加额外操作 (计数/缓存) | Spring AOP |

## 3. Python 实现

```python
"""
代理模式 - 虚拟图片代理 (懒加载)
演示: 只有真正显示时才加载图片
"""
import time


# ===== 1. 抽象主题 =====
class Image(ABC if False else object):
    """图片抽象接口"""

    def display(self):
        raise NotImplementedError


# ===== 2. 真实主题 =====
class RealImage(Image):
    """真实图片 - 加载慢, 占内存"""

    def __init__(self, filename: str):
        self.filename = filename
        self._load_from_disk()  # 创建即加载 (慢)

    def _load_from_disk(self):
        """模拟从硬盘加载图片 (耗时操作)"""
        print(f"  ⏳ [RealImage] 从硬盘加载图片 {self.filename} ...")
        time.sleep(0.1)  # 模拟加载耗时
        self.image_data = f"<图片数据: {self.filename} 5MB>"
        print(f"  ✅ [RealImage] {self.filename} 加载完成")

    def display(self):
        print(f"  🖼️  [RealImage] 显示图片: {self.filename}")


# ===== 3. 代理类 =====
class ImageProxy(Image):
    """
    虚拟代理 - 延迟加载 (Lazy Loading)

    关键设计:
    1. 创建代理时**不**加载真实图片
    2. 第一次调用 display() 时才加载
    3. 加载后缓存真实图片, 后续直接复用
    """

    def __init__(self, filename: str):
        self.filename = filename
        self._real_image: RealImage = None  # 懒加载: 初始为 None
        print(f"  📝 [ImageProxy] 创建代理 (未加载真实图片): {self.filename}")

    def display(self):
        """显示图片 - 第一次时才真正加载"""
        if self._real_image is None:
            print(f"  ⏳ [ImageProxy] 首次调用, 触发懒加载 ...")
            self._real_image = RealImage(self.filename)  # 真正加载
        self._real_image.display()


# ===== 4. 进阶: 保护代理 + 智能引用 =====
class ProtectedImageProxy(Image):
    """
    保护代理 - 检查用户权限
    """

    def __init__(self, filename: str, user_role: str):
        self.filename = filename
        self.user_role = user_role
        self._real_image: RealImage = None
        self.access_count = 0  # 智能引用: 计数

    def _check_permission(self) -> bool:
        """检查访问权限"""
        # 简单示例: 只有 admin 才能看机密图片
        if "机密" in self.filename and self.user_role != "admin":
            print(f"  🚫 [Proxy] 权限不足! 需要 admin 角色")
            return False
        return True

    def display(self):
        if not self._check_permission():
            return

        self.access_count += 1  # 智能引用: 计数
        if self._real_image is None:
            self._real_image = RealImage(self.filename)
        self._real_image.display()
        print(f"  📊 [Proxy] 访问次数: {self.access_count}")


# ===== 5. 客户端使用 =====
def main():
    print("=" * 50)
    print("代理模式 - 虚拟图片代理 (懒加载)")
    print("=" * 50)

    # ❌ 反例: 不用代理
    print("\n--- ❌ 反例: 直接创建 RealImage ---")
    print("  创建 3 个 RealImage 对象...")
    img1 = RealImage("photo1.jpg")
    img2 = RealImage("photo2.jpg")
    img3 = RealImage("photo3.jpg")
    print("  → 创建时就加载了 3 张图片, 即使可能不用")

    # ✅ 正例: 用代理
    print("\n--- ✅ 正例: 使用 ImageProxy ---")
    print("  创建 3 个 ImageProxy 对象...")
    proxy1 = ImageProxy("photo1.jpg")
    proxy2 = ImageProxy("photo2.jpg")
    proxy3 = ImageProxy("photo3.jpg")
    print("  → 创建时没加载图片, 仅创建代理 (轻量)")

    print("\n  用户只看 photo1 ...")
    proxy1.display()  # 此时才加载 photo1

    print("\n  用户又看 photo1 (复用缓存) ...")
    proxy1.display()  # 第二次不重新加载

    print("\n  用户没看 photo2, photo3 - 节省内存!")

    # 保护代理演示
    print("\n" + "=" * 50)
    print("保护代理 - 权限控制")
    print("=" * 50)

    print("\n--- 普通用户访问机密图片 ---")
    protected = ProtectedImageProxy("机密文件.jpg", user_role="guest")
    protected.display()  # 拒绝

    print("\n--- admin 访问机密图片 ---")
    protected2 = ProtectedImageProxy("机密文件.jpg", user_role="admin")
    protected2.display()  # 允许
    protected2.display()  # 第二次: 计数 +1


if __name__ == "__main__":
    main()
```

## 4. Java 实现

```java
// ===== 1. 抽象主题 =====
public interface Image {
    void display();
}

// ===== 2. 真实主题 =====
public class RealImage implements Image {
    private String filename;

    public RealImage(String filename) {
        this.filename = filename;
        loadFromDisk();  // 创建即加载
    }

    private void loadFromDisk() {
        System.out.println("  ⏳ 加载图片 " + filename);
    }

    @Override
    public void display() {
        System.out.println("  🖼️ 显示 " + filename);
    }
}

// ===== 3. 虚拟代理 =====
public class ImageProxy implements Image {
    private String filename;
    private RealImage realImage;  // 懒加载

    public ImageProxy(String filename) {
        this.filename = filename;
    }

    @Override
    public void display() {
        if (realImage == null) {
            realImage = new RealImage(filename);  // 真正加载
        }
        realImage.display();
    }
}

// ===== 4. Java 动态代理 (JDK Proxy) =====
public class DynamicProxyDemo {
    public static void main(String[] args) {
        // 创建真实对象
        Image realImage = new RealImage("photo.jpg");

        // 创建动态代理
        Image proxy = (Image) Proxy.newProxyInstance(
            Image.class.getClassLoader(),
            new Class[]{Image.class},
            (proxyObj, method, args1) -> {
                System.out.println("  [代理] 前置: " + method.getName());
                Object result = method.invoke(realImage, args1);
                System.out.println("  [代理] 后置: " + method.getName());
                return result;
            }
        );

        proxy.display();  // 通过代理调用
    }
}
```

## 5. 实际应用

### 5.1 Spring AOP (智能引用代理)

```java
// Spring AOP 本质上是动态代理
@Service
public class UserService {
    @Transactional    // 代理加事务管理
    @Cacheable("users")  // 代理加缓存
    @LogExecution      // 代理加日志
    public User getUser(Long id) {
        // 业务代码
        return userRepository.findById(id).orElseThrow();
    }
}

// 实际调用时, Spring 创建代理对象
// 在方法前后织入切面逻辑
```

### 5.2 RPC 框架 (远程代理)

```python
# gRPC / Dubbo 等 RPC 框架的客户端 stub 就是远程代理
# 用户调用本地方法, 实际是远程调用

import grpc

class UserServiceProxy:
    """远程代理 - 隐藏网络通信细节"""

    def __init__(self, server_address: str):
        self.channel = grpc.insecure_channel(server_address)
        self.stub = user_pb2_grpc.UserServiceStub(self.channel)

    def get_user(self, user_id: int):
        # 本地调用, 内部通过网络发请求
        request = user_pb2.GetUserRequest(id=user_id)
        response = self.stub.GetUser(request)
        return response.user

# 客户端以为在调本地方法, 其实是远程 RPC
proxy = UserServiceProxy("localhost:50051")
user = proxy.get_user(1)  # 实际跨网络
```

### 5.3 Hibernate 延迟加载 (虚拟代理)

```java
// Hibernate 的实体对象用代理实现延迟加载
@Entity
public class User {
    @Id Long id;
    String name;

    // OneToMany 默认懒加载
    @OneToMany(fetch = FetchType.LAZY)

}

// 调用 user.getOrders() 时, Hibernate 才发 SQL
// 这就是虚拟代理
```

## 6. 优缺点

### 优点

| 优点 | 说明 |
| :--- | :--- |
| ✅ **保护目标** | 控制访问, 加权限检查 |
| ✅ **性能优化** | 虚拟代理延迟加载大对象 |
| ✅ **位置透明** | 远程代理隐藏网络细节 |
| ✅ **智能增强** | 缓存/日志/计数等增强 |

### 缺点

| 缺点 | 说明 |
| :--- | :--- |
| ❌ **处理速度慢** | 多一层调用有开销 |
| ❌ **代码复杂** | 需要额外维护代理类 |
| ❌ **可能不一致** | 远程代理有网络延迟/失败 |
| ❌ **过度设计** | 简单场景用代理反而绕 |

## 7. 实战思考

### Q1: 代理 vs 装饰器?

| 代理 | 装饰器 |
| :--- | :--- |
| **控制访问** | **添加职责** |
| 客户端**不知道**有代理 (透明) | 客户端**显式**装饰 |
| 通常**一对一** (一个代理一个真实对象) | 可以**多层嵌套** |
| 代理类**自己创建**真实对象 | 装饰器**由客户端**传入被装饰对象 |

```python
# 代理: 客户端只调代理, 不直接接触真实对象
proxy = ImageProxy("photo.jpg")
proxy.display()  # 客户端不知道内部 RealImage

# 装饰器: 客户端显式传入被装饰对象
deco = SugarDecorator(MilkDecorator(Americano()))
# 客户端知道在装饰
```

### Q2: 代理 vs 适配器?

| 代理 | 适配器 |
| :--- | :--- |
| **同接口** (代理实现同一接口) | **转换接口** (适配成目标接口) |
| 透明替换 | 显式包装 |
| 控制访问 | 接口兼容 |

```python
# 代理: 实现同一接口
class ImageProxy:
    def display(self): pass   # 同 Image 接口

# 适配器: 实现新接口, 包装老接口
class LoggerAdapter:
    def log(self, msg): pass  # NewLogger 接口
    # 内部调 OldLogger.write_log()
```

### Q3: 静态代理 vs 动态代理?

| 静态代理 | 动态代理 |
| :--- | :--- |
| **手动**为每个类写代理 | **运行时**生成代理 |
| 类数量多 | 类数量少 |
| 性能稍好 | 反射调用稍慢 |
| Spring 早期 | Spring AOP 现代 |

```python
# 静态代理: 每个类一个代理
class UserServiceProxy:
    def __init__(self, real_service):
        self.real = real_service
    def get_user(self, id):
        # 前置日志
        print(f"[LOG] 调用 get_user({id})")
        result = self.real.get_user(id)
        print(f"[LOG] 返回: {result}")
        return result

# 动态代理: 一个通用代理处理所有类
def dynamic_proxy(func):
    """装饰器实现动态代理"""
    def wrapper(*args, **kwargs):
        print(f"[LOG] 调用 {func.__name__}")
        result = func(*args, **kwargs)
        print(f"[LOG] 返回 {result}")
        return result
    return wrapper

@dynamic_proxy  # 任何函数都可以用
def get_user(id): return ...
```
