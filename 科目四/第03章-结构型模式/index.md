# 第03章 结构型模式 (Structural Patterns)

> **关注点和对象组合**: 结构型模式描述如何将**类或对象**组合成更大的结构, 同时保持结构的**灵活**和**高效**.

## 🎯 一句话简介

### 01. 适配器模式 (Adapter)

> 将一个类的接口**转换成**客户希望的另一个接口, 使原本因接口不兼容而不能一起工作的类可以**协同工作**.

**真实例子**: Java `InputStreamReader` 把字节流包装成字符流

---

### 02. 桥接模式 (Bridge)

> 将**抽象部分**与它的**实现部分**分离, 使它们都可以**独立地变化**.

**真实例子**: JDBC 驱动 (抽象 `Driver` + 各数据库实现)

---

### 03. 组合模式 (Composite)

> 将对象组合成**树形结构**以表示"**部分-整体**"的层次结构, 使客户端对单个对象和组合对象的使用具有**一致性**.

**真实例子**: 文件系统 (文件 + 目录统一接口)

---

### 04. 装饰器模式 (Decorator)

> **动态地**给一个对象添加一些**额外的职责**, 就增加功能来说, 装饰器模式相比生成子类更为**灵活**.

**真实例子**: Java I/O 流家族 (BufferedInputStream 包装 FileInputStream)

---

### 05. 外观模式 (Facade)

> 为子系统中的一组接口提供一个**一致的界面**, 此模式定义了一个**高层接口**, 这个接口使得这一子系统更加**容易使用**.

**真实例子**: 编译系统 (gcc 把预处理/编译/汇编/链接串成一个命令)

---

### 06. 享元模式 (Flyweight)

> 运用**共享技术**有效地支持**大量细粒度**的对象, 减少创建对象的数量.

**真实例子**: Java `Integer` 缓存池 (–128~127 共享)

---

### 07. 代理模式 (Proxy)

> 为其他对象提供一种**代理**以**控制**对这个对象的访问.

**真实例子**: Spring AOP (动态代理织入切面逻辑)

---

## 📚 学习顺序建议

### 🟢 入门路径 (按难度递增)

```text
01 适配器  ──→  02 桥接  ──→  03 组合  ──→  05 外观
                                    ↓
                              04 装饰器  ──→  07 代理
                                    ↓
                              06 享元
```

### 推荐顺序与理由

1. **适配器 → 桥接** (先懂"包装", 再懂"分离")
   - 适配器讲的是事后补救 (包装已有类)
   - 桥接讲的是事前解耦 (抽象与实现分离)

2. **桥接 → 组合** (理解树形组合)
   - 组合模式是树形结构的统一接口

3. **组合 → 装饰器** (理解叠加)
   - 装饰器是递归叠加包装, 与组合结构相似

4. **装饰器 → 代理** (理解控制)
   - 代理是装饰器的"控制访问"特化版

5. **装饰器 → 外观** (理解封装)
   - 外观是对子系统的封装, 理解更容易

6. **享元** (单独理解)
   - 享元与其他模式不同, 关注的是**内存优化**

### 模式关联图

```text
结构型模式内部关联:

适配器 ──── 包装已有接口
   ↓
桥接  ──── 设计时就分离
   ↓
组合  ──── 树形结构
   ↓
装饰器 ──── 动态包装 + 叠加
   ↓ ↘
外观  ──── 封装子系统  代理  ──── 控制访问
   ↓
享元  ──── 共享对象
```

### 易混淆模式对照

| 对比 | 区别 |
| :--- | :--- |
| **适配器 vs 装饰器** | 适配器改接口, 装饰器不改接口 |
| **适配器 vs 外观** | 适配器包装老接口, 外观提供新接口 |
| **桥接 vs 策略** | 桥接是结构型, 策略是行为型 |
| **装饰器 vs 代理** | 装饰器加职责, 代理控访问 |
| **享元 vs 单例** | 享元是多个共享, 单例是单个唯一 |
| **享元 vs 对象池** | 享元生命周期长, 对象池借出/归还 |

## 🛠️ 实战选择指南

| 场景 | 推荐模式 |
| :--- | :--- |
| 集成第三方库, 接口不一致 | **适配器** |
| 多个维度独立变化 (如形状+颜色) | **桥接** |
| 树形数据结构 (文件/UI/组织) | **组合** |
| 动态添加功能 (咖啡配料, I/O 流) | **装饰器** |
| 子系统太复杂, 需要简化入口 | **外观** |
| 大量重复对象, 内存吃紧 | **享元** |
| 远程调用/懒加载/权限控制 | **代理** |
