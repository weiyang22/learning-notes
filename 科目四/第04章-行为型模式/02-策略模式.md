# 02. 策略模式 (Strategy)

> **一句话**: 定义一系列的**算法**, 把它们一个个**封装**起来, 并且使它们可**相互替换**.

---

## 1. 核心问题

多种算法/策略可以互换, 但调用方不该知道细节:

```python
# ❌ 反例: if-else 硬编码算法
class SortContext:
    def sort(self, data, algorithm):
        if algorithm == "bubble":
            self.bubble_sort(data)
        elif algorithm == "quick":
            self.quick_sort(data)
        elif algorithm == "merge":
            self.merge_sort(data)
        elif algorithm == "heap":
            self.heap_sort(data)
        # 加新算法要改这里
```

**问题**:
- 算法选择和使用耦合在一起
- 加新算法必须修改 Context
- 算法实现细节暴露给调用方

---

## 2. 模式结构

```text
              ┌─────────────────────┐
              │   <<Strategy>>      │
              │    Strategy         │
              ├─────────────────────┤
              │ +algorithm(i,f): void│
              └──────────△──────────┘
                         │ (实现)
       ┌─────────────────┼─────────────────┐
       │                 │                 │
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ ConcreteA    │  │ ConcreteB    │  │ ConcreteC    │
├──────────────┤  ├──────────────┤  ├──────────────┤
│+algorithm() │  │+algorithm() │  │+algorithm() │
└──────────────┘  └──────────────┘  └──────────────┘
       △                  △                  △
       └──────────────────┼──────────────────┘
                          │
              ┌───────────▼──────────┐
              │        Context       │
              ├──────────────────────┤
              │ -strategy: Strategy  │
              ├──────────────────────┤
              │ +setStrategy(s)     │
              │ +execute(i,f)       │ ← 委托给 strategy
              └──────────────────────┘
```

**3 个角色**:
- **Strategy**: 抽象策略接口
- **ConcreteStrategy**: 具体策略
- **Context**: 上下文, 持有 Strategy 引用

## 3. Python 实现

```python
from abc import ABC, abstractmethod
from typing import List

# 1. 抽象策略
class SortStrategy(ABC):
    @abstractmethod
    def sort(self, data: List[int]) -> List[int]:
        pass

# 2. 具体策略
class QuickSort(SortStrategy):
    def sort(self, data):
        return sorted(data)  # 简化

class BubbleSort(SortStrategy):
    def sort(self, data):
        sorted_data = data.copy()
        n = len(sorted_data)
        for i in range(n):
            for j in range(0, n - i - 1):
                if sorted_data[j] > sorted_data[j + 1]:
                    sorted_data[j], sorted_data[j + 1] = \
                        sorted_data[j + 1], sorted_data[j]
        return sorted_data

class MergeSort(SortStrategy):
    def sort(self, data):
        if len(data) <= 1:
            return data
        mid = len(data) // 2
        left = self.sort(data[:mid])
        right = self.sort(data[mid:])
        return self._merge(left, right)
    
    def _merge(self, left, right):
        result = []
        i = j = 0
        while i < len(left) and j < len(right):
            if left[i] <= right[j]:
                result.append(left[i])
                i += 1
            else:
                result.append(right[j])
                j += 1
        return result + left[i:] + right[j:]

# 3. 上下文
class SortContext:
    def __init__(self, strategy: SortStrategy):
        self.strategy = strategy
    
    def set_strategy(self, strategy: SortStrategy):
        """运行时切换算法"""
        self.strategy = strategy
    
    def sort(self, data):
        return self.strategy.sort(data)

# 使用
data = [5, 2, 8, 1, 9, 3]

ctx = SortContext(QuickSort())
print(ctx.sort(data))  # [1, 2, 3, 5, 8, 9]

# 运行时切换策略
ctx.set_strategy(BubbleSort())
print(ctx.sort(data))  # [1, 2, 3, 5, 8, 9]

ctx.set_strategy(MergeSort())
print(ctx.sort(data))  # [1, 2, 3, 5, 8, 9]
```

## 4. Java 实现

```java
// 抽象策略
public interface SortStrategy {
    int[] sort(int[] data);
}

// 具体策略
public class QuickSort implements SortStrategy {
    public int[] sort(int[] data) {
        return Arrays.copyOf(data, data.length);  // 简化
    }
}

public class BubbleSort implements SortStrategy {
    public int[] sort(int[] data) {
        int[] arr = Arrays.copyOf(data, data.length);
        // 冒泡...
        return arr;
    }
}

// 上下文
public class SortContext {
    private SortStrategy strategy;
    
    public SortContext(SortStrategy strategy) {
        this.strategy = strategy;
    }
    
    public void setStrategy(SortStrategy strategy) {
        this.strategy = strategy;
    }
    
    public int[] executeSort(int[] data) {
        return strategy.sort(data);
    }
}
```

### 5.5 支付方式选择

```python
class PaymentStrategy(ABC):
    @abstractmethod
    def pay(self, amount): pass

class Alipay(PaymentStrategy):
    def pay(self, amount):
        return f"用支付宝支付 {amount} 元"

class WechatPay(PaymentStrategy):
    def pay(self, amount):
        return f"用微信支付 {amount} 元"

class CreditCard(PaymentStrategy):
    def pay(self, amount):
        return f"用信用卡支付 {amount} 元"

class Order:
    def __init__(self, strategy: PaymentStrategy):
        self.strategy = strategy
    
    def checkout(self, amount):
        return self.strategy.pay(amount)
```

## 6. 优缺点

### 优点

✅ **算法可替换**: 运行时切换策略

✅ **避免多重条件**: 取代 if-else 硬编码

✅ **扩展性好**: 加新算法不动 Context

✅ **符合开闭原则**: 容易扩展

### 缺点

❌ **类数量增加**: 每个算法一个类

❌ **客户端必须知道差异**: Context 需了解不同 Strategy

❌ **Strategy 暴露细节**: Context 调用具体方法

## 7. 实战思考

### Q1: 策略 vs 状态?

| 策略 | 状态 |
| :--- | :--- |
| 行为型 | 行为型 |
| 算法可替换 | 行为随状态改变 |
| Context 主动选 | State 内部转换 |
| 互相独立 | 状态之间可转换 |

### Q2: 策略 vs 工厂?

| 策略 | 工厂 |
| :--- | :--- |
| 创建型 vs 行为型 | 都是创建型 |
| 关注**算法替换** | 关注**对象创建** |
| Context 用策略 | Client 用产品 |
| 接口 + 多实现 | 接口 + 多实现 |

策略: **怎么做事** (算法) 可换

工厂: **谁来做** (对象) 可换

### Q3: 什么时候用策略?

✅ **多种算法可替换**: 排序/压缩/支付/路由

✅ **算法独立变化**: 经常加新算法

✅ **避免 if-else**: 硬编码算法选择

❌ **算法极少 (1-2 种)**: 直接写更简单

❌ **算法不变化**: 不需要替换
