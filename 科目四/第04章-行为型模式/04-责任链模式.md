# 04. 责任链模式 (Chain of Responsibility)

> **一句话**: 使多个对象都有机会处理请求, 从而**避免请求发送者与接收者耦合**, 将这些对象**连成一条链**, 并沿着链传递请求, 直到有对象处理它为止.

---

## 1. 核心问题

请求需要经过**多个处理器**依次处理, 但调用方不知道具体谁会处理:

- HTTP 请求: 鉴权 → 日志 → 限流 → 业务处理
- Servlet Filter Chain
- Spring Interceptor
- 异常处理链
- JavaScript 事件冒泡 (Bubble)

```python
# ❌ 反例: 调用方直接知道所有处理器
def handle_request(request):
    if not authenticate(request):
        raise PermissionError
    
    log_request(request)
    
    if not rate_limit_check(request):
        raise RateLimitError
    
    return process_business(request)

# 问题: 加新处理器要改 handle_request
```

---

## 2. 模式结构

```text
              ┌────────────────────┐
              │   <<Handler>>       │
              │      Handler        │
              ├────────────────────┤
              │ -successor: Handler │  ← 下一个处理器
              ├────────────────────┤
              │ +setSuccessor(h)   │
              │ +handle(req)        │
              └──────────△─────────┘
                         │ (继承)
       ┌─────────────────┼─────────────────┐
       │                 │                 │
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ ConcreteA    │  │ ConcreteB    │  │ ConcreteC    │
├──────────────┤  ├──────────────┤  ├──────────────┤
│+handle()     │  │+handle()     │  │+handle()     │
│  转发?    │  │  转发?    │  │  处理      │
└──────────────┘  └──────────────┘  └──────────────┘
```

**关键**:
- 每个 Handler 持有**下一个 Handler** 的引用 (successor)
- 处理请求或转发给 successor
- 链式传递, 直到有人处理或链结束

## 3. Python 实现

### 3.1 基础实现

```python
from abc import ABC, abstractmethod

class Handler(ABC):
    def __init__(self):
        self.successor = None
    
    def set_successor(self, successor):
        self.successor = successor
    
    @abstractmethod
    def handle(self, request):
        pass
    
    def handle_request(self, request):
        handled = self.handle(request)
        if not handled and self.successor:
            self.successor.handle_request(request)

# 具体处理器
class AuthHandler(Handler):
    def handle(self, request):
        if "token" in request:
            print(f"[Auth] 已认证: {request['token']}")
            return True
        print("[Auth] 认证失败")
        return False

class LogHandler(Handler):
    def handle(self, request):
        print(f"[Log] 记录请求: {request}")
        return False  # 不处理, 转发给下一个

class BusinessHandler(Handler):
    def handle(self, request):
        print(f"[Business] 处理业务: {request.get('action', 'unknown')}")
        return True

# 使用
auth = AuthHandler()
log = LogHandler()
biz = BusinessHandler()

auth.set_successor(log)
log.set_successor(biz)

# 链式调用
print("--- 请求 1: 带 token ---")
auth.handle_request({"token": "abc123", "action": "create"})

print("\n--- 请求 2: 无 token ---")
auth.handle_request({"action": "delete"})
# 请求 2 没有 token, 认证失败, 但日志和业务仍执行? 取决于链设计
```

### 3.2 中间件风格 (Django 中间件)

```python
class Middleware:
    def __init__(self, get_response):
        self.get_response = get_response
    
    def __call__(self, request):
        # 前置处理
        response = self.get_response(request)
        # 后置处理
        return response

class AuthMiddleware(Middleware):
    def __call__(self, request):
        if not request.get("authenticated"):
            return {"error": "Unauthorized"}, 401
        return self.get_response(request)

class LoggingMiddleware(Middleware):
    def __call__(self, request):
        print(f"请求: {request}")
        response = self.get_response(request)
        print(f"响应: {response}")
        return response

# 链式组装
def build_middleware():
    def view(request):
        return {"data": "success"}, 200
    
    middleware = LoggingMiddleware(
        AuthMiddleware(view)
    )
    return middleware

handler = build_middleware()
result = handler({"authenticated": True})
```

## 4. Java 实现

```java
public abstract class Handler {
    protected Handler successor;
    
    public void setSuccessor(Handler successor) {
        this.successor = successor;
    }
    
    public abstract boolean handle(Request request);
    
    public final void handleRequest(Request request) {
        if (!handle(request) && successor != null) {
            successor.handleRequest(request);
        }
    }
}

public class AuthHandler extends Handler {
    public boolean handle(Request request) {
        if (request.getToken() != null) {
            System.out.println("认证通过");
            return true;
        }
        return false;
    }
}

public class LogHandler extends Handler {
    public boolean handle(Request request) {
        System.out.println("记录请求");
        return false;  // 转发
    }
}

public class BusinessHandler extends Handler {
    public boolean handle(Request request) {
        System.out.println("处理业务");
        return true;
    }
}

// 使用
Handler auth = new AuthHandler();
Handler log = new LogHandler();
Handler biz = new BusinessHandler();
auth.setSuccessor(log);
log.setSuccessor(biz);
auth.handleRequest(request);
```

## 5. 实际应用

### 5.1 Java Servlet Filter

```java
// Tomcat Filter Chain 就是责任链
public class AuthFilter implements Filter {
    public void doFilter(ServletRequest req, ServletResponse res,
                         FilterChain chain) {
        if (authenticated(req)) {
            chain.doFilter(req, res);  // 继续传递
        } else {
            res.getWriter().write("Unauthorized");
        }
    }
}
```

### 5.2 Spring Interceptor

```java
public class AuthInterceptor implements HandlerInterceptor {
    public boolean preHandle(HttpServletRequest req, HttpServletResponse res,
                              Object handler) {
        // 认证检查
        return authenticated(req);  // false 中断链
    }
}
```

### 5.3 Spring Security Filter Chain

```java
http.authorizeHttpRequests(authz -> authz
    .requestMatchers("/admin/**").hasRole("ADMIN")
    .anyRequest().authenticated())
    .addFilterBefore(new CustomFilter(), UsernamePasswordAuthenticationFilter.class);
// Filter Chain: CustomFilter → SecurityFilter → AuthorizationFilter → ...
```

### 5.4 Node.js Express 中间件

```javascript
app.use((req, res, next) => {
    console.log(`${req.method} ${req.path}`);
    next();  // 传递
});

app.use((req, res, next) => {
    if (!req.headers.authorization) {
        return res.status(401).send('Unauthorized');
    }
    next();
});
```

### 5.5 异常处理链

```java
try {
    doSomething();
} catch (BusinessException e) {
    // 第一层: 业务异常处理
    if (canRecover(e)) recover();
    else throw e;
} catch (NetworkException e) {
    // 第二层: 网络异常
    retry();
} catch (Exception e) {
    // 第三层: 兜底
    log(e);
}
```

### 5.6 OkHttp Interceptor (Android)

```kotlin
class AuthInterceptor : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val request = chain.request()
            .newBuilder()
            .addHeader("Authorization", "Bearer xxx")
            .build()
        return chain.proceed(request)
    }
}
```

## 6. 优缺点

### 优点

✅ **解耦**: 调用方不需知道链的细节

✅ **灵活**: 动态增删处理器

✅ **职责单一**: 每个 Handler 只做一件事

✅ **可配置**: 不同场景用不同链

### 缺点

❌ **调试困难**: 请求在哪一步停止不直观

❌ **性能**: 链越长越慢

❌ **不保证处理**: 可能没 Handler 处理

❌ **循环引用**: A -> B -> A

## 7. 实战思考

### Q1: 责任链 vs 装饰器?

| 责任链 | 装饰器 |
| :--- | :--- |
| 多个对象**依次处理** | **嵌套**包装对象 |
| 每个都做自己的事 | 每个**添加**功能 |
| 一条链 | 套娃 |
| **可能**没人处理 | 总是到最内层 |

### Q2: 责任链 vs 中介者?

| 责任链 | 中介者 |
| :--- | :--- |
| 线性传递 | 星形集中 |
| 单向流动 | 多方交互 |
| 请求沿链走 | 同事物通过中介者 |

### Q3: 什么时候用责任链?

✅ **多步骤处理**: 鉴权+日志+限流+业务

✅ **处理顺序重要**: 后一步依赖前一步

✅ **可配置的处理流**: 不同环境不同链

❌ **只有一个处理器**: 用普通方法即可

❌ **无明确顺序**: 用观察者更合适

## 8. 小结

✅ **核心**: 请求沿链传递, 每个 Handler 可处理或转发

✅ **应用**: Web 过滤器, Spring 拦截器, Express 中间件, OkHttp

✅ **关键**: 明确每个 Handler 的责任边界
