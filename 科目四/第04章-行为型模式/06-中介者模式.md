# 06. 中介者模式 (Mediator)

> **一句话**: 用一个**中介对象**来封装一系列的**对象交互**, 使各对象不需要显式地相互引用, 从而使其**耦合松散**, 而且可以独立地改变它们之间的交互.

---

## 1. 核心问题

多个对象之间**网状**通信, 难以维护:

```python
# ❌ 反例: 对象之间互相引用 (网状)
class ChatRoom:
    def __init__(self):
        self.users = []
    
    def add_user(self, user):
        user.room = self  # 用户要知道房间
        self.users.append(user)

class User:
    def __init__(self, name):
        self.name = name
        self.room = None
    
    def send(self, msg):
        # 用户直接通知其他用户
        for u in self.room.users:
            if u != self:
                u.receive(self, msg)
    
    def receive(self, sender, msg):
        print(f"{self.name} 收到 {sender.name}: {msg}")
```

**问题**:
- 每个对象要知道**所有其他对象**
- 加一个新对象要改所有对象
- 对象之间**强耦合**

---

## 2. 模式结构

```text
                    ┌──────────────────────┐
                    │   <<Mediator>>        │
                    │      Mediator         │
                    ├──────────────────────┤
                    │ +notify(s, ev): void  │
                    └──────────△───────────┘
                               │ (实现)
                ┌──────────┴────────┐
                │                   │
       ┌────────────────┐  ┌────────────────┐
       │ ConcreteMedi.  │  │ ConcreteColleagueA │
       ├────────────────┤  ├────────────────┤
       │+notify()       │  │+receive()      │
       └────────────────┘  │+send()         │
                △           └────────────────┘
                │                    △
                └────────────────────┘
                      (所有 Colleague 通过 Mediator 通信)
```

**核心**: 所有同事(Colleague) 只认识**中介者**, 不直接通信.

## 3. Python 实现

### 3.1 聊天室

```python
from abc import ABC, abstractmethod
from typing import List

# 1. 抽象中介者
class Mediator(ABC):
    @abstractmethod
    def notify(self, sender, event: str): pass

# 2. 抽象同事
class Colleague(ABC):
    def __init__(self, mediator: Mediator):
        self.mediator = mediator

# 3. 具体中介者: 聊天室
class ChatRoom(Mediator):
    def __init__(self):
        self.users: List[User] = []
    
    def register(self, user):
        if user not in self.users:
            self.users.append(user)
    
    def notify(self, sender, event):
        if event == "message":
            for user in self.users:
                if user != sender:
                    user.receive(sender, event)

# 4. 具体同事: 用户
class User(Colleague):
    def __init__(self, name: str, mediator: Mediator):
        super().__init__(mediator)
        self.name = name
    
    def send(self, msg):
        print(f"{self.name} 发送: {msg}")
        self.mediator.notify(self, "message")  # 通过中介者
    
    def receive(self, sender, event):
        print(f"  → {self.name} 收到 {sender.name} 的消息")

# 使用
room = ChatRoom()
alice = User("Alice", room)
bob = User("Bob", room)
charlie = User("Charlie", room)

room.register(alice)
room.register(bob)
room.register(charlie)

alice.send("大家好!")
# Alice 发送: 大家好!
#   → Bob 收到 Alice 的消息
#   → Charlie 收到 Alice 的消息
```

### 3.2 GUI 对话框协调

```python
class DialogMediator(ABC):
    @abstractmethod
    def widget_changed(self, widget): pass

class TextBox:
    def __init__(self, mediator):
        self.mediator = mediator
        self.text = ""
    
    def type(self, text):
        self.text = text
        self.mediator.widget_changed(self)

class SubmitButton:
    def __init__(self, mediator):
        self.mediator = mediator
        self.enabled = False
    
    def enable(self):
        self.enabled = True

class Dialog(Mediator):
    def __init__(self):
        self.textbox = TextBox(self)
        self.submit = SubmitButton(self)
    
    def widget_changed(self, widget):
        if widget is self.textbox:
            # 文本框变化时, 根据内容启用提交按钮
            self.submit.enable() if len(widget.text) > 0 else None
```

## 4. Java 实现

```java
public interface Mediator {
    void notify(Colleague sender, String event);
}

public abstract class Colleague {
    protected Mediator mediator;
    
    public Colleague(Mediator mediator) {
        this.mediator = mediator;
    }
}

public class ChatRoom implements Mediator {
    private List<User> users = new ArrayList<>();
    
    public void register(User user) {
        users.add(user);
    }
    
    public void notify(Colleague sender, String event) {
        for (User u : users) {
            if (u != sender) {
                u.receive(event);
            }
        }
    }
}

public class User extends Colleague {
    private String name;
    
    public User(String name, ChatRoom room) {
        super(room);
        this.name = name;
    }
    
    public void send(String msg) {
        System.out.println(name + " 发送: " + msg);
        mediator.notify(this, msg);
    }
    
    public void receive(String msg) {
        System.out.println("  → " + name + " 收到: " + msg);
    }
}
```

## 5. 实际应用

### 5.1 Java JMS (消息服务)

```
Producer → Broker (中介者) → Consumer
              ↓
        多个订阅者各自接收
```

### 5.2 GUI 控制器

```java
// MVC 中 Controller 是 View 和 Model 的中介者
public class LoginController implements Mediator {
    private LoginView view;
    private UserService model;
    
    public void onLoginClicked(String username, String password) {
        // View 通知 Controller (中介者)
        // Controller 协调 Model 和 View
        if (model.authenticate(username, password)) {
            view.showSuccess();
        } else {
            view.showError("登录失败");
        }
    }
}
```

## 6. 优缺点

### 优点

✅ **解耦**: 同事之间不直接通信

✅ **集中控制**: 交互规则集中在中介者

✅ **易于扩展**: 加新同事只需注册到中介者

✅ **简化对象**: 同事只知道中介者

### 缺点

❌ **中介者庞大**: 所有交互都在中介者中, 类膨胀

❌ **中介者复杂**: 中介者本身逻辑复杂

❌ **上帝对象**: 中介者可能成为 "什么都管" 的反模式

## 7. 实战思考

### Q1: 中介者 vs 观察者?

| 中介者 | 观察者 |
| :--- | :--- |
| **双向**通信 | **单向**通知 |
| 同事**互相**通信 | Subject **到** Observer |
| 通过中介者路由 | Subject 直接 notify |
| 中介者**知道**所有人 | Subject 知道 Observer 列表 |

### Q2: 中介者 vs 外观?

| 中介者 | 外观 |
| :--- | :--- |
| 行为型 (对象间交互) | 结构型 (子系统封装) |
| **双向**通信 | **单向**调用 |
| 同事**互相**调用 | 客户端**单向**调用子系统 |

### Q3: 什么时候用中介者?

✅ **多对象网状通信**: 5+ 对象互相调用

✅ **交互逻辑复杂**: 状态机/工作流

✅ **复用交互**: 不同场景用同一中介者

❌ **两个对象通信**: 用直接调用

❌ **中介者过于庞大**: 可能是设计问题, 需要拆分
