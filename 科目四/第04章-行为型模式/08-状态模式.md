# 08. 状态模式 (State)

> **一句话**: 允许对象在**内部状态**发生改变时**改变它的行为**, 对象看起来好像**修改了它的类**.

---

## 1. 核心问题

对象的行为随状态变化, 但用 if-else 难维护:

```python
# ❌ 反例: 订单状态用 if-else
class Order:
    def __init__(self):
        self.state = "created"
    
    def process(self):
        if self.state == "created":
            self.validate()
            self.state = "paid"
        elif self.state == "paid":
            self.ship()
            self.state = "shipped"
        elif self.state == "shipped":
            self.deliver()
            self.state = "completed"
        elif self.state == "cancelled":
            print("已取消")
        else:
            raise ValueError(f"未知状态: {self.state}")

# 问题:
# - 加新状态要改所有方法
# - 状态转换逻辑分散
# - 难维护
```

---

## 2. 模式结构

```text
              ┌────────────────────┐
              │   <<State>>        │
              │     State          │
              ├────────────────────┤
              │ +handle(): void   │
              └──────────△─────────┘
                         │ (实现)
       ┌─────────────────┼─────────────────┐
       │                 │                 │
┌──────────────┐  ┌──────────────┐  ┌──────────────┐
│ ConcreteA    │  │ ConcreteB    │  │ ConcreteC    │
├──────────────┤  ├──────────────┤  ├──────────────┤
│+handle()     │  │+handle()     │  │+handle()     │
└──────────────┘  └──────────────┘  └──────────────┘
       △                  △                  △
       └──────────────────┼──────────────────┘
                          │
                ┌─────────▼──────────┐
                │    Context        │
                ├───────────────────┤
                │ -state: State     │ ← 持有当前状态
                ├───────────────────┤
                │ +request()        │ ← 委托给 state
                │ +setState(s)      │
                └───────────────────┘
```

**3 个角色**:
- **State**: 抽象状态
- **ConcreteState**: 具体状态
- **Context**: 上下文, 持有当前状态

## 3. Python 实现

```python
from abc import ABC, abstractmethod

# 1. 抽象状态
class OrderState(ABC):
    def __init__(self, order):
        self.order = order
    
    @abstractmethod
    def process(self): pass
    
    @abstractmethod
    def cancel(self): pass
    
    @abstractmethod
    def __str__(self): pass

# 2. 具体状态: 已创建
class CreatedState(OrderState):
    def process(self):
        print("验证订单...")
        self.order.set_state(PaidState(self.order))
        print("订单已支付")
    
    def cancel(self):
        self.order.set_state(CancelledState(self.order))
    
    def __str__(self):
        return "已创建"

# 3. 具体状态: 已支付
class PaidState(OrderState):
    def process(self):
        print("发货中...")
        self.order.set_state(ShippedState(self.order))
    
    def cancel(self):
        print("已支付订单退款中...")
        self.order.set_state(CancelledState(self.order))
    
    def __str__(self):
        return "已支付"

# 4. 具体状态: 已发货
class ShippedState(OrderState):
    def process(self):
        print("已送达")
        self.order.set_state(CompletedState(self.order))
    
    def cancel(self):
        print("已发货订单无法取消")
    
    def __str__(self):
        return "已发货"

# 5. 具体状态: 已完成 / 已取消
class CompletedState(OrderState):
    def process(self):
        print("订单已完成, 无需操作")
    
    def cancel(self):
        print("订单已完成, 无法取消")
    
    def __str__(self):
        return "已完成"

class CancelledState(OrderState):
    def process(self):
        print("订单已取消")
    
    def cancel(self):
        print("订单已取消")
    
    def __str__(self):
        return "已取消"

# 6. 上下文
class Order:
    def __init__(self):
        self._state = CreatedState(self)
    
    def set_state(self, state):
        self._state = state
    
    def process(self):
        print(f"当前状态: {self._state}")
        self._state.process()
    
    def cancel(self):
        print(f"当前状态: {self._state}")
        self._state.cancel()

# 使用
order = Order()
order.process()  # 已创建 → 已支付
order.process()  # 已支付 → 已发货
order.process()  # 已发货 → 已完成
order.cancel()   # 已完成, 无法取消
```

## 4. Java 实现

```java
// 抽象状态
public interface OrderState {
    void process(Order order);
    void cancel(Order order);
}

// 具体状态
public class CreatedState implements OrderState {
    public void process(Order order) {
        System.out.println("验证订单");
        order.setState(new PaidState());
    }
    public void cancel(Order order) {
        order.setState(new CancelledState());
    }
}

public class PaidState implements OrderState {
    public void process(Order order) {
        System.out.println("发货");
        order.setState(new ShippedState());
    }
    public void cancel(Order order) {
        order.setState(new CancelledState());
    }
}

// 上下文
public class Order {
    private OrderState state;
    
    public Order() {
        state = new CreatedState();
    }
    
    public void setState(OrderState state) {
        this.state = state;
    }
    
    public void process() {
        state.process(this);
    }
}
```

class WorkflowState:
    def execute(self, context):

class DraftState(WorkflowState):

```python
class CharacterState(ABC):
    @abstractmethod
    def handle_input(self, character, input): pass

class StandingState(CharacterState):
    def handle_input(self, character, input):
        if input == "move":
            character.set_state(WalkingState())
        elif input == "jump":
            character.set_state(JumpingState())

class WalkingState(CharacterState):
    def handle_input(self, character, input):
        if input == "stop":
            character.set_state(StandingState())
        elif input == "jump":
            character.set_state(JumpingState())
```

### 5.6 电梯控制

```python
class Elevator:
    def __init__(self):
        self.state = IdleState()
    
    def call(self, floor):
        self.state.handle(self, floor)

class IdleState:
    def handle(self, elevator, floor):
        if elevator.current_floor != floor:
            elevator.set_state(MovingState(floor))

class MovingState:
    def __init__(self, target_floor):
        self.target_floor = target_floor
    
    def handle(self, elevator, floor):
        if elevator.current_floor == self.target_floor:
            elevator.set_state(DoorOpeningState())

class DoorOpeningState:
    def handle(self, elevator, floor):
        if elevator.door_open:
            elevator.set_state(IdleState())
```

## 6. 优缺点

### 优点

✅ **消除 if-else**: 每个状态独立类

✅ **状态转换清晰**: 集中在状态类内

✅ **扩展性好**: 加新状态加新类

✅ **符合开闭原则**: 不改 Context 加新状态

### 缺点

❌ **类数量多**: 每个状态一个类

❌ **状态少时不值**: 2-3 个状态用 if-else 更简单

❌ **Context 暴露**: 需要 Context 提供方法

## 7. 实战思考

### Q1: 状态 vs 策略?

| 状态 | 策略 |
| :--- | :--- |
| 对象**当前处于**什么状态 | 对象**怎么做事** |
| 状态之间**会转换** | 策略**独立**可替换 |
| 状态**知道**下一个状态 | 策略**不知道**其他策略 |

```python
# 状态: 订单
order.state = PaidState  # 订单处于"已支付"

# 策略: 排序
sort.strategy = QuickSort  # 使用快速排序策略
```

### Q2: 状态机 vs 流程图?

**状态机**: 严格的数学模型 (FSM), 适合有限状态

**流程图**: 通用业务流, 更灵活

**建议**: 简单状态用状态模式, 复杂业务用工作流引擎 (如 Camunda, Airflow)

### Q3: 什么时候用状态模式?

✅ **对象行为随状态明显变化**: TCP 连接, 订单, 游戏角色

✅ **状态转换复杂**: 多条件多分支

✅ **加新状态频繁**: 工作流系统

❌ **状态少 (2-3 个)**: 用 enum + if-else 更简单

❌ **状态不常变**: 不需要模式

## 8. 小结

✅ **核心**: 把状态封装成类, 行为随状态切换

✅ **应用**: TCP 连接, 工作流, 游戏状态机

✅ **关键**: 状态类持有 Context 引用, 可调用 Context 切换状态
