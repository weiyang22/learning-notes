# 09. 模板方法模式 (Template Method)

> **一句话**: 定义一个操作中的**算法的骨架**, 而将一些步骤延迟到子类中, 使得子类可以不改变一个算法的结构即可重定义该算法的某些特定步骤.

---

## 1. 核心问题

多个类的业务流程**大体一致**, 只有部分**细节步骤不同**. 用复制粘贴会出现大量重复:

```python
# ❌ 反例: CSV 报告与 JSON 报告, 流程相同但 read/save 不同
class CSVReport:
    def generate(self):
        print("读取文件")
        data = self.read_csv()
        print("解析数据")
        parsed = self.parse_csv(data)
        print("保存报告")
        self.save_csv(parsed)
        print("发送通知")
        self.notify()

class JSONReport:
    def generate(self):
        print("读取文件")       # 重复
        data = self.read_json()
        print("解析数据")       # 重复
        parsed = self.parse_json(data)
        print("保存报告")       # 重复
        self.save_json(parsed)
        print("发送通知")       # 重复

# 问题:
# - 流程骨架重复 4 次
# - 修改流程 (如加一个"压缩"步骤) 要改所有类
# - 难以保证所有子类流程一致
```

**模板方法**把**不变的算法骨架**放在父类, 把**变化的步骤**抽成抽象方法让子类实现.

### 适用场景

| 场景 | 描述 |
|------|------|
| 框架的扩展点 | 框架定义主流程, 用户实现扩展点 (Spring JdbcTemplate, Servlet) |
| 数据导入/导出 | 流程固定 (读取→解析→转换→保存), 数据源不同 |
| 单元测试框架 | setUp / runTest / tearDown 模板 |
| ETL 数据管道 | Extract→Transform→Load, 各阶段实现不同 |
| 算法步骤固定 | 某些步骤必须按特定顺序执行 |

## 2. UML 类图

```text
              ┌──────────────────────────────┐
              │     AbstractClass            │
              │     (抽象模板)                │
              ├──────────────────────────────┤
              │ + template_method()  ← 算法骨架│
              │ + step1()            ← 抽象方法│
              │ + step2()            ← 抽象方法│
              │ + step3()            ← 抽象方法│
              │ + hook()             ← 钩子方法 │
              │   (默认空实现或空返回)         │
              └───────────△──────────────────┘
                          │ (继承)
        ┌─────────────────┼─────────────────┐
        │                 │                 │
┌───────────────┐ ┌───────────────┐ ┌───────────────┐
│ ConcreteClassA│ │ ConcreteClassB│ │ ConcreteClassC│
├───────────────┤ ├───────────────┤ ├───────────────┤
│ +step1()      │ │ +step1()      │ │ +step1()      │
│ +step2()      │ │ +step2()      │ │ +step2()      │
│ +step3()      │ │ +step3()      │ │ +step3()      │
│ +hook()       │ │ +hook()       │ │ +hook()       │
└───────────────┘ └───────────────┘ └───────────────┘
```

### 角色说明

| 角色 | 职责 |
|------|------|
| **AbstractClass (抽象类)** | 实现模板方法, 定义算法骨架; 声明所有步骤; 提供钩子方法的默认实现 |
| **ConcreteClass (具体子类)** | 实现父类声明的抽象步骤, 可以选择性地覆盖钩子方法 |
| **template_method()** | 模板方法, 通常声明为 final, 防止被子类覆盖 |
| **hook() (钩子方法)** | 在抽象类中提供默认 (空) 实现的步骤, 子类可选择性覆盖 |

### 模板方法中的典型流程

```text
template_method():
    step1()           ← 必实现
    step2()           ← 必实现
    if hook():        ← 可选实现
        step_hook()
    step3()           ← 必实现
    common_step()     ← 父类已实现, 子类不可改
```

## 3. Python 实现

### 3.1 基础示例: 数据处理流程

```python
"""
模板方法模式 - Python 实现
场景: 数据处理流程 (read / parse / save 三步固定, 每种数据源细节不同)
"""
from abc import ABC, abstractmethod
from typing import Any


class DataProcessor(ABC):
    """抽象模板类 - 定义数据处理的算法骨架"""

    def process(self) -> None:
        """
        模板方法 (Template Method)
        定义算法的骨架, 通常不应被子类覆盖.
        """
        self._before_process()           # 钩子: 处理前
        data = self.read()               # 步骤 1: 抽象
        parsed = self.parse(data)        # 步骤 2: 抽象
        result = self.transform(parsed)  # 步骤 3: 抽象
        self.save(result)                # 步骤 4: 抽象
        if self.need_notify():           # 钩子: 是否需要通知
            self.notify_done()
        self._after_process()            # 钩子: 处理后

    # ---------- 抽象方法: 子类必须实现 ----------
    @abstractmethod
    def read(self) -> Any:
        """读取原始数据"""
        ...

    @abstractmethod
    def parse(self, raw: Any) -> Any:
        """解析原始数据为结构化对象"""
        ...

    @abstractmethod
    def transform(self, data: Any) -> Any:
        """转换/加工数据"""
        ...

    @abstractmethod
    def save(self, data: Any) -> None:
        """保存处理结果"""
        ...

    # ---------- 钩子方法: 子类可选覆盖 ----------
    def need_notify(self) -> bool:
        """是否需要发送通知, 默认 False"""
        return False

    def _before_process(self) -> None:
        """处理前的钩子, 默认空实现"""
        pass

    def _after_process(self) -> None:
        """处理后的钩子, 默认空实现"""
        pass

    # ---------- 具体方法: 通用逻辑 ----------
    def notify_done(self) -> None:
        """通知逻辑 (所有子类通用)"""
        print("  [notify] 处理完成, 已发送邮件通知")


# ============== 具体子类 1: CSV 数据处理 ==============
class CSVProcessor(DataProcessor):
    def read(self) -> str:
        print("  [CSV.read] 读取 CSV 文件")
        return "name,age\nAlice,30\nBob,25"

    def parse(self, raw: str) -> list:
        print("  [CSV.parse] 解析 CSV 字符串")
        rows = []
        for line in raw.strip().split("\n")[1:]:  # 跳过表头
            name, age = line.split(",")
            rows.append({"name": name, "age": int(age)})
        return rows

    def transform(self, data: list) -> list:
        print("  [CSV.transform] 年龄 +1")
        return [{"name": r["name"], "age": r["age"] + 1} for r in data]

    def save(self, data: list) -> None:
        print("  [CSV.save] 保存为 CSV: ", end="")
        print(",".join(f"{r['name']}={r['age']}" for r in data))

    def need_notify(self) -> bool:
        return True  # CSV 处理需要通知


# ============== 具体子类 2: JSON 数据处理 ==============
class JSONProcessor(DataProcessor):
    def read(self) -> str:
        print("  [JSON.read] 读取 JSON 文件")
        return '[{"name":"Carol","age":40}]'

    def parse(self, raw: str) -> list:
        import json
        print("  [JSON.parse] json.loads 解析")
        return json.loads(raw)

    def transform(self, data: list) -> list:
        print("  [JSON.transform] 添加 timestamp")
        return [{**r, "ts": "2026-09-11"} for r in data]

    def save(self, data: list) -> None:
        import json
        print("  [JSON.save] 保存为 JSON: ", end="")
        print(json.dumps(data, ensure_ascii=False))

    # need_notify 继承默认 False, 不通知


# ============== 具体子类 3: 数据库数据处理 (覆盖钩子) ==============
class DBProcessor(DataProcessor):
    def read(self) -> list:
        print("  [DB.read] SELECT * FROM users")
        return [{"name": "Dave", "age": 50}]

    def parse(self, raw: list) -> list:
        print("  [DB.parse] 无需解析, 直接返回")
        return raw

    def transform(self, data: list) -> list:
        print("  [DB.transform] 年龄 * 2")
        return [{"name": r["name"], "age": r["age"] * 2} for r in data]

    def save(self, data: list) -> None:
        print(f"  [DB.save] INSERT INTO users {data}")

    def _before_process(self) -> None:
        print("  [DB.before] 开启数据库事务")
        # 实际场景: self.conn.begin()

    def _after_process(self) -> None:
        print("  [DB.after] 提交数据库事务")
        # 实际场景: self.conn.commit()


# ============== 客户端 ==============
if __name__ == "__main__":
    print("===== 模板方法模式演示 =====\n")

    print("[CSV 处理器]")
    CSVProcessor().process()

    print("\n[JSON 处理器]")
    JSONProcessor().process()

    print("\n[DB 处理器]")
    DBProcessor().process()
```

### 3.2 Python 风格变体: 用 `__init_subclass__` + 类型提示

```python
"""
Python 风格: 用 functools + 类型注解实现, 更轻量
"""
import functools
import time


def timing_decorator(func):
    """钩子示例: 用装饰器自动给所有 process 计时"""
    @functools.wraps(func)
    def wrapper(self, *args, **kwargs):
        start = time.perf_counter()
        result = func(self, *args, **kwargs)
        elapsed = time.perf_counter() - start
        print(f"  ⏱  {func.__name__} 耗时 {elapsed*1000:.2f}ms")
        return result
    return wrapper


class ReportGenerator:
    """模板基类 (Python 风格, 用 raise NotImplementedError)"""

    def process(self) -> None:
        # 骨架
        raw = self.read()
        parsed = self.parse(raw)
        result = self.render(parsed)
        self.write(result)

    def read(self) -> str:
        raise NotImplementedError

    def parse(self, raw: str) -> dict:
        raise NotImplementedError

    def render(self, data: dict) -> str:
        raise NotImplementedError

    def write(self, content: str) -> None:
        raise NotImplementedError


class HTMLReport(ReportGenerator):
    @timing_decorator
    def read(self) -> str:
        return "<root><user>Alice</user></root>"

    def parse(self, raw: str) -> dict:
        return {"raw": raw, "tag": "html"}

    def render(self, data: dict) -> str:
        return f"<!DOCTYPE html><body>{data['raw']}</body>"

    def write(self, content: str) -> None:
        print(f"  [HTML] {content[:40]}...")


if __name__ == "__main__":
    HTMLReport().process()
```

## 4. Java 实现

### 4.1 经典实现: AbstractClass + 子类

```java
/**
 * 模板方法模式 - Java 实现
 * 场景: Spring JdbcTemplate 风格的"读取-处理-保存"模板
 */
public abstract class AbstractDataHandler<T, R> {

    /**
     * 模板方法 (声明为 final, 禁止子类覆盖算法骨架)
     */
    public final R handle(T input) {
        beforeHandle();           // 钩子
        validate(input);          // 通用校验 (具体方法)
        R parsed = doParse(input);
        R transformed = doTransform(parsed);
        save(transformed);
        afterHandle();            // 钩子
        return transformed;
    }

    // ---------- 抽象方法 ----------
    protected abstract R doParse(T input);
    protected abstract R doTransform(R parsed);
    protected abstract void save(R data);

    // ---------- 具体方法 (通用逻辑) ----------
    protected void validate(T input) {
        if (input == null) {
            throw new IllegalArgumentException("input 不能为空");
        }
    }

    // ---------- 钩子方法 (默认空实现) ----------
    protected void beforeHandle() {
        // 子类可选择性覆盖
    }

    protected void afterHandle() {
        // 子类可选择性覆盖
    }
}

// ============== 具体子类 1: 用户数据 ==============
class UserDataHandler extends AbstractDataHandler<String, User> {

    @Override
    protected User doParse(String input) {
        System.out.println("  [User.parse] " + input);
        String[] parts = input.split(",");
        return new User(parts[0], Integer.parseInt(parts[1]));
    }

    @Override
    protected User doTransform(User user) {
        System.out.println("  [User.transform] 年龄 +10");
        user.age += 10;
        return user;
    }

    @Override
    protected void save(User user) {
        System.out.println("  [User.save] 保存到 users 表: " + user);
    }

    @Override
    protected void beforeHandle() {
        System.out.println("  [User.before] 鉴权检查");
    }
}

// ============== 具体子类 2: 订单数据 ==============
class OrderDataHandler extends AbstractDataHandler<String, Order> {

    @Override
    protected Order doParse(String input) {
        System.out.println("  [Order.parse] " + input);
        String[] parts = input.split(",");
        return new Order(parts[0], Double.parseDouble(parts[1]));
    }

    @Override
    protected Order doTransform(Order order) {
        System.out.println("  [Order.transform] 折扣 0.8");
        order.amount *= 0.8;
        return order;
    }

    @Override
    protected void save(Order order) {
        System.out.println("  [Order.save] 保存到 orders 表: " + order);
    }
}

// ============== 数据类 ==============
class User {
    String name;
    int age;
    public User(String name, int age) { this.name = name; this.age = age; }
    @Override public String toString() { return "User(" + name + ", " + age + ")"; }
}

class Order {
    String id;
    double amount;
    public Order(String id, double amount) { this.id = id; this.amount = amount; }
    @Override public String toString() { return "Order(" + id + ", " + amount + ")"; }
}

// ============== 客户端 ==============
public class Main {
    public static void main(String[] args) {
        System.out.println("===== 模板方法模式 (Java) =====\n");

        System.out.println("[User]");
        new UserDataHandler().handle("Alice,30");

        System.out.println("\n[Order]");
        new OrderDataHandler().handle("O001,100.0");
    }
}
```

### 4.2 Java 8 风格: `default` 方法 + 函数式接口

```java
import java.util.function.Function;
import java.util.function.Consumer;
import java.util.function.Supplier;

/**
 * 函数式风格: 把步骤作为 lambda 传入
 */
public class Pipeline<T, R> {

    private final Supplier<T> reader;
    private final Function<T, R> transformer;
    private final Consumer<R> saver;

    public Pipeline(Supplier<T> reader,
                    Function<T, R> transformer,
                    Consumer<R> saver) {
        this.reader = reader;
        this.transformer = transformer;
        this.saver = saver;
    }

    // 模板方法
    public final R execute() {
        T raw = reader.get();
        R result = transformer.apply(raw);
        saver.accept(result);
        return result;
    }
}

// 使用:
Pipeline<String, Integer> p = new Pipeline<>(
    () -> "123",                          // read
    Integer::parseInt,                    // transform
    n -> System.out.println("saved: " + n) // save
);
p.execute();
```

## 5. 实际应用

### 5.1 Spring `JdbcTemplate` (Java)

`JdbcTemplate` 是模板方法的经典范例: 它封装了 JDBC 的固定流程 (获取连接→创建 PreparedStatement→执行 SQL→处理异常→释放资源), 用户只需提供 SQL 和回调.

```java
// Spring JdbcTemplate 的简化骨架 (伪代码)
public abstract class JdbcTemplate {

    public final List<Map<String, Object>> queryForList(String sql) {
        // 模板方法 - 固定流程
        Connection conn = null;
        PreparedStatement ps = null;
        try {
            conn = dataSource.getConnection();   // 步骤 1
            ps = conn.prepareStatement(sql);     // 步骤 2
            ResultSet rs = ps.executeQuery();    // 步骤 3
            return mapResultSet(rs);             // 步骤 4 (扩展点)
        } catch (SQLException e) {
            throw new DataAccessException(e);    // 通用处理
        } finally {
            close(ps);                           // 通用释放
            close(conn);
        }
    }

    protected abstract List<Map<String, Object>> mapResultSet(ResultSet rs);
}
```

### 5.2 Servlet 生命周期 (Java)

`HttpServlet.service()` 是模板方法, `doGet/doPost` 是抽象步骤:

```java
// javax.servlet.http.HttpServlet 简化版
public abstract class HttpServlet {

    // 模板方法
    public final void service(HttpServletRequest req, HttpServletResponse resp) {
        String method = req.getMethod();
        if (method.equals("GET"))    doGet(req, resp);
        else if (method.equals("POST"))   doPost(req, resp);
        // ...
    }

    protected abstract void doGet(HttpServletRequest req, HttpServletResponse resp);
    protected abstract void doPost(HttpServletRequest req, HttpServletResponse resp);
}
```

## 6. 优缺点

### 优点

| 优点 | 说明 |
|------|------|
| **封装不变部分, 扩展可变部分** | 算法骨架在父类, 子类只关心具体步骤 |
| **提取公共代码, 减少重复** | 相同流程只写一次, 避免复制粘贴 |
| **子类覆盖细节, 不影响骨架** | 符合开闭原则 (对扩展开放, 对修改关闭) |
| **便于框架扩展** | 框架作者定义主流程, 用户实现扩展点 |
| **反向控制结构** | 子类调用父类, 而非父类调用子类 (好莱坞原则) |

### 缺点

| 缺点 | 说明 |
|------|------|
| **继承耦合** | 子类必须继承抽象类, 违反"组合优于继承" |
| **流程固定** | 一旦骨架确定, 难以动态改变流程顺序 |
| **调试困难** | 子类的实现被父类的骨架"包围", 栈跟踪较深 |
| **不易扩展新步骤** | 在骨架中间插入新步骤需修改父类, 影响所有子类 |
| **增加类数量** | 每种变体都要一个子类, 子类膨胀 |

### 与其他模式对比

| 维度 | 模板方法 | 策略模式 | 工厂方法 |
|------|----------|----------|----------|
| 目的 | 算法骨架不变, 步骤变化 | 整个算法可替换 | 对象创建可替换 |
| 关系 | 继承 | 组合 | 继承 |
| 侧重点 | 控制流程 | 替换算法 | 创建对象 |

## 7. 实战思考

### Q1: 模板方法 vs 策略模式, 何时用哪个?

**答**:

| 维度 | 模板方法 | 策略模式 |
|------|----------|----------|
| **算法骨架** | 固定, 在父类 | 完全可替换 |
| **变体数量** | 少量, 流程一致 | 多样, 算法本身不同 |
| **运行时切换** | 编译期决定 | 运行时可切换 |
| **关系** | 继承 | 组合 (持有 Strategy 对象) |

**选择标准**:
- 若**多个类的算法骨架相同, 只细节不同** → 模板方法
- 若**整个算法都不一样, 只是同一类问题** → 策略模式
- 若**需要在运行时切换算法** → 策略模式 (因为模板方法通过继承绑定)

**举例**:
- Spring JdbcTemplate → 模板方法 (流程固定: 取连接/执行/释放)
- 排序算法 (快速排序/归并排序) → 策略模式 (算法完全不同)

### Q2: 模板方法中的"钩子方法"到底有什么用?

**答**: 钩子方法 (`hook`) 是**默认空实现**或返回合理默认值的步骤. 它的作用是给子类一个**可选的扩展点**, 而不强制子类必须实现.

**两种典型钩子**:

| 钩子类型 | 用途 | 示例 |
|---------|------|------|
| **控制流程的钩子** | 返回 bool, 决定是否执行某步骤 | `need_notify() -> bool` |
| **事件回调的钩子** | 空实现, 子类按需覆盖 | `before_handle()`, `after_handle()` |

**示例**: Spring 的 `AbstractView.render()` 有个 `exposeHelpers()` 钩子, 大多数视图不需要, 少数需要自定义的可以覆盖.

**与抽象方法的区别**:

| 维度 | 抽象方法 | 钩子方法 |
|------|----------|----------|
| 是否必须实现 | 必须 | 可选 |
| 默认实现 | 无 | 有 (空实现或默认值) |
| 目的 | 定义必要步骤 | 提供可选扩展点 |

### Q3: 模板方法在 Python 中不如 Java/静态语言常见, 为什么?

**答**:

| 原因 | 说明 |
|------|------|
| **没有真正的 `final`** | Python 没有 `final` 关键字, 子类可轻易覆盖骨架 (违反设计意图) |
| **鸭子类型** | Python 习惯用**协议**而非抽象基类, 不需要继承模板 |
| **一等函数** | 步骤可以作为参数传入 (`Pipeline` 示例), 不必通过继承实现 |
| **装饰器更灵活** | Python 习惯用装饰器组合行为, 而非继承 |

**Python 中等价的做法**:

```python
# 1. 函数式: 把步骤作为参数
def template(read, parse, save, data):
    raw = read(data)
    parsed = parse(raw)
    save(parsed)

# 2. 装饰器: 在函数前后插入逻辑
@log_time
@retry(3)
def my_process(data):
    ...

# 3. 上下文管理器: with 语句替代 try-finally 模板
with db.transaction():
    process(data)
```

**结论**: 在 Java/C++ 等静态语言中, 模板方法是框架的基石; 在 Python 中, 优先考虑**组合 + 函数 + 装饰器**, 但涉及复杂业务流 (如 ETL) 时模板方法依然清晰.

## 8. 小结

| 维度 | 内容 |
|------|------|
| **模式类型** | 行为型 |
| **核心思想** | 算法骨架在父类, 具体步骤在子类 |
| **关键角色** | AbstractClass (模板) + ConcreteClass (实现) |
| **好莱坞原则** | Don't call us, we'll call you (子类不调用父类, 父类调用子类) |
| **典型应用** | Spring JdbcTemplate, Servlet, JUnit, Django View |
| **Python 注意** | 可用 `abc` + 装饰器 + 函数组合替代 |
| **核心陷阱** | 不要让子类覆盖模板方法本身 (Java 用 `final`) |

**记忆口诀**: 模板搭骨架, 子类填细节; 钩子可选扩展, 流程永远一致.
