# 10. 访问者模式 (Visitor)

> **一句话**: 表示一个作用于某对象结构中的各元素的**操作**, 使你可以在**不改变各元素类**的前提下定义作用于这些元素的新操作.

---

## 1. 核心问题

对象结构 (如文档树、AST) 中有**多种元素**, 我们想对它们做**多种操作** (导出 Markdown、统计字数、压缩等). 若把每个操作都塞进元素类:

```python
# ❌ 反例: 把所有操作都放在元素类
class Paragraph:
    def __init__(self, text):
        self.text = text

    def to_markdown(self):
        return self.text + "\n\n"

    def to_html(self):
        return f"<p>{self.text}</p>"

    def word_count(self):
        return len(self.text.split())

    def compress(self):
        return Paragraph(self.text.replace(" ", ""))


class Image:
    def __init__(self, url):
        self.url = url

    def to_markdown(self):
        return f"![image]({self.url})\n\n"

    def to_html(self):
        return f'<img src="{self.url}"/>'

    def word_count(self):
        return 0

    def compress(self):
        return Image(self.url)

# 问题:
# - 每个新操作 (比如 to_pdf, translate) 都要改所有元素类
# - 元素类职责混乱 (数据 + 4 个操作混在一起)
# - 难以增加新元素类型 (要改所有操作)
```

**访问者模式**将"操作"从元素类中**抽离**出去, 每种操作作为独立的 Visitor, 元素类只负责 `accept(visitor)`.

### 适用场景

| 场景 | 描述 |
|------|------|
| 编译器 AST | 遍历语法树进行类型检查、优化、代码生成 |
| 文档对象模型 | 导出 Markdown / HTML / 统计字数 / 拼写检查 |
| 文件系统遍历 | 统计大小 / 搜索文件 / 备份 / 压缩 |
| XML/JSON 解析 | 多种序列化方式 (JSON / YAML / XML) |
| 复杂对象的多种操作 | 需要在不改动元素类的前提下, 增加新操作 |

## 2. UML 类图

```text
        ┌─────────────────────────┐
        │    <<Visitor>>          │
        │      Visitor            │
        ├─────────────────────────┤
        │ + visit_concrete_a(a)   │
        │ + visit_concrete_b(b)   │
        └─────────────△───────────┘
                      │ (实现)
        ┌─────────────┼─────────────┐
        │             │             │
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ ConcreteV1   │ │ ConcreteV2   │ │ ConcreteV3   │
├──────────────┤ ├──────────────┤ ├──────────────┤
│+visit_a(a)   │ │+visit_a(a)   │ │+visit_a(a)   │
│+visit_b(b)   │ │+visit_b(b)   │ │+visit_b(b)   │
└──────────────┘ └──────────────┘ └──────────────┘
       △                △                △
       └────────────────┼────────────────┘
                        │ (调用 visitor.visit_xxx)
              ┌─────────────────────────┐
              │   <<Element>>           │
              │     Element            │
              ├─────────────────────────┤
              │ + accept(v: Visitor)    │
              └─────────────△───────────┘
                            │ (实现)
              ┌─────────────┼─────────────┐
              │             │             │
      ┌──────────────┐ ┌──────────────┐
      │ ConcreteA    │ │ ConcreteB    │
      ├──────────────┤ ├──────────────┤
      │ +accept(v)   │ │ +accept(v)   │
      │ +op_a()      │ │ +op_b()      │
      └──────────────┘ └──────────────┘
```

### 角色说明

| 角色 | 职责 |
|------|------|
| **Visitor (抽象访问者)** | 为每种 ConcreteElement 声明一个 visit 方法 |
| **ConcreteVisitor (具体访问者)** | 实现每个 visit 方法, 定义对元素的具体操作 |
| **Element (抽象元素)** | 声明 accept(visitor) 方法 |
| **ConcreteElement (具体元素)** | 实现 accept, 在内部调用 visitor.visit_xxx(self) |
| **ObjectStructure (对象结构)** | 能枚举元素, 通常提供 `for_each` 让 visitor 遍历 |

### 双重分派 (Double Dispatch)

访问者模式的关键是**双重分派**: `element.accept(visitor)` → `visitor.visit_xxx(element)`, 运行时根据**两个对象的实际类型**决定调用哪个方法.

```text
第一次分派 (编译期决定): element.accept(visitor)
       ↓
第二次分派 (运行期决定): 实际调用 visitor.visit_xxx(element)
```

### 优缺点对比示意

| 场景 | 增加新元素 | 增加新操作 |
|------|-----------|-----------|
| **不用访问者** (操作在元素中) | 改所有类 | 改所有类 |
| **用访问者** | 改所有 Visitor + 添加 dispatch | **只增加一个新 Visitor** ✓ |

## 3. Python 实现

### 3.1 基础示例: 文档对象模型

```python
"""
访问者模式 - Python 实现
场景: 文档由段落 / 图片 / 表格组成, 多种操作 (Markdown 导出 / 字数统计 / 翻译)
"""
from abc import ABC, abstractmethod
from typing import List


# ============== 抽象访问者 ==============
class Visitor(ABC):
    """为每种元素声明 visit 方法"""

    @abstractmethod
    def visit_paragraph(self, p: "Paragraph") -> str:
        ...

    @abstractmethod
    def visit_image(self, img: "Image") -> str:
        ...

    @abstractmethod
    def visit_table(self, t: "Table") -> str:
        ...


# ============== 抽象元素 ==============
class DocumentElement(ABC):
    """文档元素基类"""

    @abstractmethod
    def accept(self, visitor: Visitor) -> str:
        ...


# ============== 具体元素 ==============
class Paragraph(DocumentElement):
    def __init__(self, text: str):
        self.text = text

    def accept(self, visitor: Visitor) -> str:
        return visitor.visit_paragraph(self)


class Image(DocumentElement):
    def __init__(self, url: str, alt: str = ""):
        self.url = url
        self.alt = alt

    def accept(self, visitor: Visitor) -> str:
        return visitor.visit_image(self)


class Table(DocumentElement):
    def __init__(self, headers: List[str], rows: List[List[str]]):
        self.headers = headers
        self.rows = rows

    def accept(self, visitor: Visitor) -> str:
        return visitor.visit_table(self)


# ============== 具体访问者 1: MarkdownExporter ==============
class MarkdownExporter(Visitor):
    """把文档导出为 Markdown"""

    def visit_paragraph(self, p: Paragraph) -> str:
        return f"{p.text}\n\n"

    def visit_image(self, img: Image) -> str:
        return f"![{img.alt}]({img.url})\n\n"

    def visit_table(self, t: Table) -> str:
        lines = []
        lines.append("| " + " | ".join(t.headers) + " |")
        lines.append("| " + " | ".join("---" for _ in t.headers) + " |")
        for row in t.rows:
            lines.append("| " + " | ".join(row) + " |")
        return "\n".join(lines) + "\n\n"


# ============== 具体访问者 2: WordCounter ==============
class WordCounter(Visitor):
    """统计文档字数 (图片不计入, 表格按行统计)"""

    def visit_paragraph(self, p: Paragraph) -> str:
        # 返回 "段落名: 字数"
        return f"段落[{len(p.text)}字]"

    def visit_image(self, img: Image) -> str:
        return f"图片[0字]"

    def visit_table(self, t: Table) -> str:
        total = sum(len(c) for row in t.rows for c in row)
        return f"表格[{total}字, {len(t.rows)}行]"


# ============== 具体访问者 3: HTMLExporter ==============
class HTMLExporter(Visitor):
    """导出为 HTML"""

    def visit_paragraph(self, p: Paragraph) -> str:
        return f"<p>{p.text}</p>\n"

    def visit_image(self, img: Image) -> str:
        return f'<img src="{img.url}" alt="{img.alt}"/>\n'

    def visit_table(self, t: Table) -> str:
        html = "<table>\n<tr>" + "".join(f"<th>{h}</th>" for h in t.headers) + "</tr>\n"
        for row in t.rows:
            html += "<tr>" + "".join(f"<td>{c}</td>" for c in row) + "</tr>\n"
        return html + "</table>\n"


# ============== 对象结构 ==============
class Document:
    """文档, 可被多种 Visitor 访问"""

    def __init__(self):
        self.elements: List[DocumentElement] = []

    def add(self, element: DocumentElement) -> None:
        self.elements.append(element)

    def accept(self, visitor: Visitor) -> str:
        """让 visitor 访问所有元素"""
        return "".join(e.accept(visitor) for e in self.elements)


# ============== 客户端 ==============
if __name__ == "__main__":
    doc = Document()
    doc.add(Paragraph("Hello, Visitor Pattern!"))
    doc.add(Image("https://example.com/cat.jpg", "cat"))
    doc.add(Table(["Name", "Age"], [["Alice", "30"], ["Bob", "25"]]))
    doc.add(Paragraph("The End."))

    print("===== 访问者模式演示 =====\n")

    print("[Markdown 导出]")
    print(doc.accept(MarkdownExporter()))

    print("[HTML 导出]")
    print(doc.accept(HTMLExporter()))

    print("[字数统计]")
    for e in doc.elements:
        # 也可以单独访问某个元素
        if isinstance(e, Paragraph):
            print(" ", e.accept(WordCounter()))
        elif isinstance(e, Image):
            print(" ", e.accept(WordCounter()))
        elif isinstance(e, Table):
            print(" ", e.accept(WordCounter()))
```

![cat](https://example.com/cat.jpg)

### 3.2 Python 风格变体: 用 `__visit_name__` 协议 (PEP 协议)

Python 没有真正的双重分派, 但可以用**反射**模拟:

```python
"""
Python 风格: 用 getattr 模拟双重分派, 避免每种元素都要写 visit_xxx
"""
class GenericVisitor:
    """通用访问者: 通过方法名约定自动 dispatch"""

    def visit(self, element):
        # 找到 visit_<element_type> 方法
        method_name = f"visit_{type(element).__name__.lower()}"
        method = getattr(self, method_name, self.generic_visit)
        return method(element)

    def generic_visit(self, element):
        raise NotImplementedError(f"未实现 {type(element).__name__}")


class MyVisitor(GenericVisitor):
    def visit_paragraph(self, p):
        return f"P: {p.text}"

    def visit_image(self, img):
        return f"IMG: {img.url}"


# 使用
v = MyVisitor()
print(v.visit(Paragraph("Hi")))    # "P: Hi"
print(v.visit(Image("a.jpg")))     # "IMG: a.jpg"
```

### 3.3 真实应用: 简单 AST 访问者

```python
"""
真实示例: 算术表达式 AST 的访问者 (求值 / 打印 / 优化)
"""
class Expr: pass

class Number(Expr):
    def __init__(self, value): self.value = value

class Add(Expr):
    def __init__(self, left, right): self.left, self.right = left, right

class Mul(Expr):
    def __init__(self, left, right): self.left, self.right = left, right


# 访问者
class Evaluator:
    def visit(self, expr):
        if isinstance(expr, Number):
            return expr.value
        elif isinstance(expr, Add):
            return self.visit(expr.left) + self.visit(expr.right)
        elif isinstance(expr, Mul):
            return self.visit(expr.left) * self.visit(expr.right)


class Printer:
    def __init__(self): self.indent = 0

    def visit(self, expr):
        if isinstance(expr, Number):
            return str(expr.value)
        elif isinstance(expr, Add):
            return f"({self.visit(expr.left)} + {self.visit(expr.right)})"
        elif isinstance(expr, Mul):
            return f"({self.visit(expr.left)} * {self.visit(expr.right)})"


# 表达式: (1 + 2) * 3
ast = Mul(Add(Number(1), Number(2)), Number(3))

print(Evaluator().visit(ast))   # 9
print(Printer().visit(ast))     # ((1 + 2) * 3)
```

## 4. Java 实现

### 4.1 经典实现: 文件系统

```java
import java.util.ArrayList;
import java.util.List;

/**
 * 访问者模式 - Java 实现
 * 场景: 文件系统 (文件/目录), 多种操作 (统计大小 / 搜索 / 打印)
 */

// ============== 抽象访问者 ==============
interface FileSystemVisitor {
    void visit(File file);
    void visit(Directory directory);
}

// ============== 抽象元素 ==============
interface FileSystemNode {
    void accept(FileSystemVisitor visitor);
    String getName();
}

// ============== 具体元素 1: 文件 ==============
class File implements FileSystemNode {
    private final String name;
    private final long size;

    public File(String name, long size) {
        this.name = name;
        this.size = size;
    }

    @Override
    public void accept(FileSystemVisitor visitor) {
        visitor.visit(this);  // 双重分派: 告诉 visitor 我是 File
    }

    @Override
    public String getName() { return name; }
    public long getSize() { return size; }
}

// ============== 具体元素 2: 目录 ==============
class Directory implements FileSystemNode {
    private final String name;
    private final List<FileSystemNode> children = new ArrayList<>();

    public Directory(String name) { this.name = name; }

    public void add(FileSystemNode node) { children.add(node); }

    @Override
    public void accept(FileSystemVisitor visitor) {
        visitor.visit(this);
        // 让 visitor 递归访问子节点
        for (FileSystemNode child : children) {
            child.accept(visitor);
        }
    }

    @Override
    public String getName() { return name; }
    public List<FileSystemNode> getChildren() { return children; }
}

// ============== 具体访问者 1: SizeCalculator ==============
class SizeCalculator implements FileSystemVisitor {
    private long totalSize = 0;

    @Override
    public void visit(File file) {
        totalSize += file.getSize();
    }

    @Override
    public void visit(Directory directory) {
        System.out.println("[dir] " + directory.getName());
    }

    public long getTotalSize() { return totalSize; }
}

// ============== 具体访问者 2: SearchVisitor ==============
class SearchVisitor implements FileSystemVisitor {
    private final String keyword;
    private final List<String> results = new ArrayList<>();

    public SearchVisitor(String keyword) { this.keyword = keyword; }

    @Override
    public void visit(File file) {
        if (file.getName().contains(keyword)) {
            results.add(file.getName());
        }
    }

    @Override
    public void visit(Directory directory) {
        // 暂不处理目录
    }

    public List<String> getResults() { return results; }
}

// ============== 客户端 ==============
public class Main {
    public static void main(String[] args) {
        // 构建文件系统
        Directory root = new Directory("root");
        root.add(new File("readme.txt", 100));
        root.add(new File("photo.jpg", 5000));

        Directory src = new Directory("src");
        src.add(new File("Main.java", 800));
        src.add(new File("Utils.java", 300));
        root.add(src);

        // 1. 计算总大小
        SizeCalculator sc = new SizeCalculator();
        root.accept(sc);
        System.out.println("总大小: " + sc.getTotalSize() + " bytes");
        // 输出: 总大小: 6200 bytes

        // 2. 搜索文件
        SearchVisitor searcher = new SearchVisitor(".java");
        root.accept(searcher);
        System.out.println("搜索 '.java': " + searcher.getResults());
        // 输出: 搜索 '.java': [Main.java, Utils.java]
    }
}
```

**运行结果**:

```text
[dir] root
[dir] src
总大小: 6200 bytes
搜索 '.java': [Main.java, Utils.java]
```

## 5. 实际应用

### 5.1 编译器 AST 访问者

几乎所有编译器都用访问者模式遍历 AST (抽象语法树):

```python
# clang AST / Python ast 模块的简化思想
import ast

class CodeAnalyzer(ast.NodeVisitor):
    """访问 Python AST, 统计函数定义数"""

    def visit_FunctionDef(self, node):
        print(f"函数: {node.name} (行 {node.lineno})")
        self.generic_visit(node)  # 递归访问子节点

    def visit_ClassDef(self, node):
        print(f"类: {node.name}")
        self.generic_visit(node)


source = """
def foo(): pass
class A: pass
def bar(): pass
"""

tree = ast.parse(source)
CodeAnalyzer().visit(tree)
# 输出:
# 函数: foo (行 2)
# 类: A (行 3)
# 函数: bar (行 4)
```

Java 生态中, **Lombok** 用访问者模式生成 AST, **Eclipse JDT** 用访问者遍历 Java AST.

### 5.2 Java NIO `Files.walkFileTree`

```java
import java.nio.file.*;
import java.nio.file.attribute.BasicFileAttributes;
import java.io.IOException;

class MyVisitor extends SimpleFileVisitor<Path> {
    // visitFile = File 的 visit
    @Override
    public FileVisitResult visitFile(Path file, BasicFileAttributes attrs) {
        System.out.println("文件: " + file);
        return FileVisitResult.CONTINUE;
    }

    // preVisitDirectory / postVisitDirectory = Directory 的 visit
    @Override
    public FileVisitResult preVisitDirectory(Path dir, BasicFileAttributes attrs) {
        System.out.println("目录: " + dir);
        return FileVisitResult.CONTINUE;
    }
}

// 使用
Files.walkFileTree(Paths.get("/tmp"), new MyVisitor());
```

## 6. 优缺点

### 优点

| 优点 | 说明 |
|------|------|
| **易于增加新操作** | 增加新 Visitor 不需要改动元素类, 符合开闭原则 |
| **集中相关操作** | 一个 Visitor 把一类操作聚拢, 高内聚 |
| **跨越类层级** | Visitor 可访问不同类层级的元素 |
| **状态累积方便** | Visitor 可作为状态机, 遍历过程中累积结果 |

### 缺点

| 缺点 | 说明 |
|------|------|
| **难以增加新元素** | 每加一个元素, 所有 Visitor 都要加一个方法 |
| **破坏封装** | Visitor 需要访问元素的内部状态, 可能要暴露 getter |
| **双重分派复杂** | Python 等动态语言没有真正的双重分派, 需模拟 |
| **违反依赖倒置** | Visitor 依赖具体元素类 (而非抽象) |
| **递归栈开销** | 深层对象结构遍历时, 栈空间消耗大 |

### 与其他模式对比

| 维度 | 访问者 | 迭代器 | 组合 |
|------|--------|--------|------|
| 目的 | 对元素施加多种操作 | 顺序遍历元素 | 树形结构表示 |
| 关注点 | 操作的扩展性 | 访问的顺序 | 结构的递归 |
| 复杂度 | 高 | 中 | 中 |

### 何时用访问者

| 适用 | 不适用 |
|------|--------|
| 对象结构稳定, 操作多变 | 对象结构经常变化 (加新元素) |
| 操作需要访问不同类型元素 | 操作很简单 (用 `isinstance` 就够) |
| 多种操作需要组合 | 只需 1-2 种操作 |
| 元素类的接口需要保护 | 性能敏感 (双重分派有开销) |

## 7. 实战思考

### Q1: 访问者模式的核心价值是什么? 什么时候不该用?

**答**: 核心价值是**对扩展开放, 对修改封闭** — 增加新操作时, **不修改元素类**, 只新增 Visitor.

**判断标准**:

| 维度 | 适合访问者 | 不适合访问者 |
|------|-----------|------------|
| **元素类型数量** | 稳定 (5-20 种) | 频繁变化 (经常加新类型) |
| **操作数量** | 多 (3+ 种, 且会增长) | 少 (1-2 种) |
| **操作复杂度** | 每种操作都涉及多种元素 | 只涉及一种元素 |
| **代码组织** | 想把操作集中管理 | 操作分散在元素类中也可接受 |

**反模式警示**:
- 只有 1 个 Visitor, 元素类 2-3 个 → 不必用访问者, 直接写在元素类中
- 元素类型经常加 → 用访问者会导致每个 Visitor 都改, 痛苦
- 操作很简单, 不涉及类型分发 → 用 `isinstance` 就够了

### Q2: Python 中访问者模式不如 Java 常见, 为什么?

**答**: Python 是**动态类型**语言, 没有真正的**双重分派**, 所以访问者模式的优势被削弱.

| 原因 | 说明 |
|------|------|
| **Python 没有 `final` 类** | 元素类可被任意扩展, Visitor 难以覆盖所有情况 |
| **没有方法重载** | Visitor 的 visit_xxx 系列方法名不能相同, 必须加后缀 |
| **`isinstance` 简单粗暴** | 直接 `if isinstance(e, Paragraph): ...` 更直观 |
| **Duck typing** | Python 习惯"看方法不看类型", 访问者的"分类型处理"理念与鸭子类型冲突 |
| **动态属性** | 可用 `__visit_name__` 等协议代替 |

**Python 中等价的做法**:

```python
# 1. 直接 isinstance 分发 (简单场景)
def process(element):
    if isinstance(element, Paragraph):
        return element.text.upper()
    elif isinstance(element, Image):
        return f"<img src='{element.url}'/>"

# 2. dict 映射 (策略 + 多态)
HANDLERS = {
    Paragraph: lambda p: p.text.upper(),
    Image: lambda img: f"<img src='{img.url}'/>",
}

def process(element):
    return HANDLERS[type(element)](element)

# 3. 反射 (通用访问者)
def visit(visitor, element):
    method = getattr(visitor, f"visit_{type(element).__name__}", None)
    if method:
        return method(element)
    raise ValueError(f"未处理 {type(element)}")
```

**结论**: Python 中访问者主要用于**框架层** (如 `ast.NodeVisitor`), 业务代码中优先用 `isinstance` 或字典映射.

### Q3: 访问者 vs 迭代器, 区别是什么?

**答**:

| 维度 | 访问者 | 迭代器 |
|------|--------|--------|
| **目的** | 对每种元素施加**不同操作** | 提供**统一遍历**方式 |
| **侧重点** | 操作的扩展性 (加 Visitor 不动元素) | 访问的封装 (不暴露内部结构) |
| **分派方式** | 双重分派 (按元素类型分派) | 单分派 (next 调用) |
| **状态** | Visitor 可累积状态 (如统计结果) | 迭代器只关心"下一个" |
| **典型方法** | `visit_xxx(element)` | `next()`, `has_next()` |

**举例对比**:

```python
# 迭代器: 顺序遍历列表
it = iter([1, 2, 3])
for x in it:
    print(x)  # 只是取值

# 访问者: 对每种节点做不同处理
ast.accept(CompilerVisitor())  # 每个节点类型做不同事
```

**配合使用**: 访问者内部常常用迭代器/递归来遍历对象结构.

### Q4: 访问者模式中, 如何处理新增元素?

**答**: 假设我们已经定义了 `Visitor` 接口和 5 个 `ConcreteElement`, 现在加一个新元素 `Video`:

```java
// 1. 修改 Visitor 接口 (影响所有实现)
interface FileSystemVisitor {
    void visit(File file);
    void visit(Directory directory);
    void visit(Video video);  // 新增
}

// 2. 所有已有 Visitor 都要实现新方法 (否则编译报错)
class SizeCalculator implements FileSystemVisitor {
    @Override public void visit(Video video) {
        totalSize += video.getDuration();
    }
    // ... 其他方法
}

// 3. 新增 ConcreteElement
class Video implements FileSystemNode {
    @Override
    public void accept(FileSystemVisitor v) { v.visit(this); }
}
```

**代价**: 改 `Visitor` 接口 + 改所有 `ConcreteVisitor` 实现.

**这就是访问者模式的"硬伤"**: 适合**元素类型稳定**的场景, 不适合元素类型频繁变化的场景.

**应对策略**:
- 用 Java `default` 方法给 `Visitor` 接口加默认实现 (Java 8+)
- 用 Python 的 `getattr` 兜底 (未实现时调用 `generic_visit`)
- 用抽象语法树 (AST) 模式, 元素类型有限且固定

## 8. 小结

| 维度 | 内容 |
|------|------|
| **模式类型** | 行为型 |
| **核心思想** | 把操作从元素类中抽离, 每种操作是一个 Visitor |
| **关键技术** | 双重分派 (`element.accept(v)` → `v.visit_xxx(e)`) |
| **典型应用** | 编译器 AST, 文件系统, 文档处理 |
| **优点** | 易于增加新操作, 集中操作逻辑 |
| **缺点** | 难以增加新元素, 破坏封装 |
| **Python 注意** | 优先用 `isinstance` / dict 映射, 框架层用 Visitor |
| **核心陷阱** | 不要让元素类频繁变化, 否则 Visitor 维护成本高 |

**记忆口诀**: 元素定结构, 访问者定操作; accept 搭桥, 双分派调方法.
