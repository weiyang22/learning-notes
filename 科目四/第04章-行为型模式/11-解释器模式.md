# 11. 解释器模式 (Interpreter)

> **一句话**: 给定一个语言, 定义它的文法表示, 并定义一个解释器, 这个解释器使用该标识来解释语言中的句子.

---

## 1. 核心问题

我们经常需要**解析**特定格式的表达式, 例如:

- 数学表达式: `1 + 2 * 3`
- 布尔表达式: `age >= 18 AND country == "CN"`
- 路径匹配: `/users/*/profile`
- 配置规则: `IF temperature > 30 THEN alert`

如果直接用 `if-else` 解析:

```python
# ❌ 反例: 硬编码解析算术表达式
def evaluate(expr: str) -> float:
    # 假设只支持 + 和 *
    if "+" in expr:
        a, b = expr.split("+")
        return float(a) + float(b)
    elif "*" in expr:
        a, b = expr.split("*")
        return float(a) * float(b)
    # 问题:
    # - 不支持优先级 (1 + 2 * 3 = 7, 不是 9)
    # - 加新运算符要改代码
    # - 嵌套表达式无法处理
```

**解释器模式**把**每种语法规则**映射成一个类 (表达式节点), 用**树形结构**表示任意复杂表达式, 然后**递归求值**.

### 适用场景

| 场景 | 描述 |
|------|------|
| **DSL (领域特定语言)** | 业务规则配置、规则引擎 |
| **正则表达式** | `re` 模块内部就是解释器 |
| **SQL 解析** | 数据库引擎解析 SQL |
| **数学公式** | Excel 公式、Matplotlib 数学排版 |
| **配置文件** | JSONPath / XPath 解析 |
| **业务规则引擎** | 保险定价、风险评分 |

### 何时**不**适合

| 场景 | 原因 |
|------|------|
| 语法复杂 (>20 条规则) | 类爆炸, 难维护, 改用解析器生成器 (ANTLR / YACC) |
| 性能要求高 | 解释器模式递归调用, 慢于手写解析 |
| 语法频繁变动 | 每次变动都要改语法树 |

## 2. UML 类图

```text
        ┌─────────────────────┐
        │   <<Abstract>>      │
        │   AbstractExpression│
        ├─────────────────────┤
        │ + interpret(ctx)    │
        └──────────△──────────┘
                   │
        ┌──────────┴──────────┐
        │                     │
┌─────────────────┐   ┌──────────────────┐
│ Terminal-       │   │ NonTerminal-    │
│ Expression      │   │ Expression      │
├─────────────────┤   ├──────────────────┤
│ +interpret(ctx) │   │ -exprs: Exp[]    │
│                 │   │ +interpret(ctx) │
└─────────────────┘   │ +add(expr)      │
                      └──────────────────┘
                              △
        ┌──────────┬──────────┴──────────┬──────────┐
        │          │                     │          │
   ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐ ┌────────┐
   │ Add    │ │ Sub    │ │ Mul    │ │ Div    │ │ Number │
   ├────────┤ ├────────┤ ├────────┤ ├────────┤ ├────────┤
   │left    │ │left    │ │left    │ │left    │ │value   │
   │right   │ │right   │ │right   │ │right   │ │        │
   └────────┘ └────────┘ └────────┘ └────────┘ └────────┘

   ┌─────────────────────────┐
   │    Context              │
   ├─────────────────────────┤
   │ -vars: dict             │
   │ +getVar(name): value    │
   │ +setVar(name, value)    │
   └─────────────────────────┘
```

### 角色说明

| 角色 | 职责 |
|------|------|
| **AbstractExpression** | 抽象表达式, 声明 `interpret()` 方法 |
| **TerminalExpression** | 终结符表达式, 如数字、变量, 不含其他表达式 |
| **NonTerminalExpression** | 非终结符表达式, 如 `+`、`-`、`AND`, 包含子表达式 |
| **Context** | 上下文, 保存解释器的全局状态 (如变量值) |
| **Client** | 构建语法树 (AST), 调用 `interpret()` |

### 文法示例

以算术表达式为例:

```text
expression ::= add | number
add        ::= expression '+' expression
number     ::= [0-9]+
```

可以对应到类:

| 文法 | 类 |
|------|-----|
| `expression` | `Expression` (抽象) |
| `add` | `AddExpression` (非终结符) |
| `number` | `NumberExpression` (终结符) |

## 3. Python 实现

### 3.1 基础示例: 简单算术表达式

```python
"""
解释器模式 - Python 实现
场景: 解析并求值算术表达式 1 + 2 - 3 * 4
"""
from abc import ABC, abstractmethod
from typing import Dict


# ============== 抽象表达式 ==============
class Expression(ABC):
    """所有表达式的基类"""

    @abstractmethod
    def interpret(self, context: Dict[str, int]) -> int:
        ...


# ============== 终结符表达式: 数字 ==============
class Number(Expression):
    def __init__(self, value: int):
        self.value = value

    def interpret(self, context) -> int:
        return self.value

    def __repr__(self):
        return f"Num({self.value})"


class Variable(Expression):
    """变量, 从 context 取值"""

    def __init__(self, name: str):
        self.name = name

    def interpret(self, context) -> int:
        return context[self.name]

    def __repr__(self):
        return f"Var({self.name})"


# ============== 非终结符表达式: 加减乘除 ==============
class Add(Expression):
    def __init__(self, left: Expression, right: Expression):
        self.left = left
        self.right = right

    def interpret(self, context) -> int:
        return self.left.interpret(context) + self.right.interpret(context)

    def __repr__(self):
        return f"({self.left} + {self.right})"


class Sub(Expression):
    def __init__(self, left: Expression, right: Expression):
        self.left = left
        self.right = right

    def interpret(self, context) -> int:
        return self.left.interpret(context) - self.right.interpret(context)

    def __repr__(self):
        return f"({self.left} - {self.right})"


class Mul(Expression):
    def __init__(self, left: Expression, right: Expression):
        self.left = left
        self.right = right

    def interpret(self, context) -> int:
        return self.left.interpret(context) * self.right.interpret(context)

    def __repr__(self):
        return f"({self.left} * {self.right})"


# ============== 客户端: 手动构造 AST ==============
if __name__ == "__main__":
    # 表达式: 1 + 2 - 3 * 4
    # 按运算符优先级: 1 + 2 - (3 * 4) = 3 - 12 = -9
    ast = Sub(
        Add(Number(1), Number(2)),
        Mul(Number(3), Number(4))
    )

    print(f"AST: {ast}")                    # (1 + 2 - 3 * 4)
    print(f"求值: {ast.interpret({})}")      # -9
```

**运行结果**:

```text
AST: ((1 + 2) - (3 * 4))
求值: -9
```

### 3.2 进阶: 带变量 + 词法解析器

上面的例子手动构造 AST, 不实用. 真实场景需要**词法分析** (token 化) + **语法分析** (生成 AST):

```python
"""
解释器模式 - 完整版
包含: Token, Lexer (词法分析), Parser (语法分析), Interpreter
支持: 数字 / 变量 / + - * / / 括号
"""
import re
from abc import ABC, abstractmethod
from typing import Dict, List, Optional


# ============== Token ==============
class Token:
    NUM, VAR, PLUS, MINUS, MUL, DIV, LPAREN, RPAREN, EOF = range(9)
    _NAMES = {NUM: "NUM", VAR: "VAR", PLUS: "+", MINUS: "-",
              MUL: "*", DIV: "/", LPAREN: "(", RPAREN: ")", EOF: "EOF"}

    def __init__(self, type_: int, value: str):
        self.type = type_
        self.value = value

    def __repr__(self):
        return f"Token({self._NAMES[self.type]}, {self.value!r})"


# ============== 词法分析器 ==============
class Lexer:
    """把字符串切分成 token"""

    TOKEN_PATTERNS = [
        (Token.NUM,    r"\d+"),
        (Token.VAR,    r"[a-zA-Z_][a-zA-Z_0-9]*"),
        (Token.PLUS,   r"\+"),
        (Token.MINUS,  r"-"),
        (Token.MUL,    r"\*"),
        (Token.DIV,    r"/"),
        (Token.LPAREN, r"\("),
        (Token.RPAREN, r"\)"),
    ]

    def __init__(self, text: str):
        self.text = text
        self.pos = 0
        self.tokens: List[Token] = self._tokenize()

    def _tokenize(self) -> List[Token]:
        tokens = []
        while self.pos < len(self.text):
            # 跳过空白
            if self.text[self.pos].isspace():
                self.pos += 1
                continue

            matched = False
            for type_, pattern in self.TOKEN_PATTERNS:
                regex = re.compile(pattern)
                m = regex.match(self.text, self.pos)
                if m:
                    tokens.append(Token(type_, m.group()))
                    self.pos = m.end()
                    matched = True
                    break

            if not matched:
                raise ValueError(f"非法字符: {self.text[self.pos]!r} at pos {self.pos}")

        tokens.append(Token(Token.EOF, ""))
        return tokens


# ============== 抽象语法树节点 ==============
class Expr(ABC):
    @abstractmethod
    def interpret(self, env: Dict[str, int]) -> int:
        ...


class Num(Expr):
    def __init__(self, value: int):
        self.value = value

    def interpret(self, env):
        return self.value


class Var(Expr):
    def __init__(self, name: str):
        self.name = name

    def interpret(self, env):
        if self.name not in env:
            raise NameError(f"未定义变量: {self.name}")
        return env[self.name]


class BinOp(Expr):
    def __init__(self, op: str, left: Expr, right: Expr):
        self.op = op
        self.left = left
        self.right = right

    def interpret(self, env):
        l = self.left.interpret(env)
        r = self.right.interpret(env)
        if self.op == "+":   return l + r
        if self.op == "-":   return l - r
        if self.op == "*":   return l * r
        if self.op == "/":
            if r == 0: raise ZeroDivisionError("除零")
            return l // r


# ============== 语法分析器 (递归下降) ==============
class Parser:
    """
    语法规则 (BNF):
        expr   ::= term ((+|-) term)*
        term   ::= factor ((*|/) factor)*
        factor ::= NUMBER | VAR | '(' expr ')'
    """

    def __init__(self, tokens: List[Token]):
        self.tokens = tokens
        self.pos = 0

    def peek(self) -> Token:
        return self.tokens[self.pos]

    def consume(self, expected_type: Optional[int] = None) -> Token:
        tok = self.tokens[self.pos]
        if expected_type is not None and tok.type != expected_type:
            raise ValueError(f"期望 {expected_type}, 实际 {tok.type}")
        self.pos += 1
        return tok

    def parse(self) -> Expr:
        expr = self.expr()
        if self.peek().type != Token.EOF:
            raise ValueError(f"未消费的 token: {self.peek()}")
        return expr

    def expr(self) -> Expr:
        """expr ::= term ((+|-) term)*"""
        node = self.term()
        while self.peek().type in (Token.PLUS, Token.MINUS):
            op = self.consume().value
            right = self.term()
            node = BinOp(op, node, right)
        return node

    def term(self) -> Expr:
        """term ::= factor ((*|/) factor)*"""
        node = self.factor()
        while self.peek().type in (Token.MUL, Token.DIV):
            op = self.consume().value
            right = self.factor()
            node = BinOp(op, node, right)
        return node

    def factor(self) -> Expr:
        """factor ::= NUMBER | VAR | '(' expr ')'"""
        tok = self.peek()
        if tok.type == Token.NUM:
            self.consume()
            return Num(int(tok.value))
        elif tok.type == Token.VAR:
            self.consume()
            return Var(tok.value)
        elif tok.type == Token.LPAREN:
            self.consume()
            node = self.expr()
            self.consume(Token.RPAREN)
            return node
        else:
            raise ValueError(f"意外 token: {tok}")


# ============== 客户端 ==============
def evaluate(expression: str, env: Dict[str, int] = None) -> int:
    env = env or {}
    tokens = Lexer(expression).tokens
    ast = Parser(tokens).parse()
    return ast.interpret(env)


if __name__ == "__main__":
    print("===== 解释器模式演示 =====\n")

    # 1. 简单表达式
    print(f"1 + 2 = {evaluate('1 + 2')}")                          # 3
    print(f"10 - 3 = {evaluate('10 - 3')}")                        # 7
    print(f"2 * 3 + 4 = {evaluate('2 * 3 + 4')}")                  # 10
    print(f"(1 + 2) * 3 = {evaluate('(1 + 2) * 3')}")              # 9
    print(f"10 / 2 / 5 = {evaluate('10 / 2 / 5')}")                # 1
    print(f"2 + 3 * 4 - 5 = {evaluate('2 + 3 * 4 - 5')}")          # 9

    # 2. 带变量
    print(f"\nx = 10; x * 2 + 1 = {evaluate('x * 2 + 1', {'x': 10})}")  # 21
    print(f"a + b * c = {evaluate('a + b * c', {'a': 1, 'b': 2, 'c': 3})}")
    # 输出: 1 + 2*3 = 7

    # 3. 复杂嵌套
    print(f"\n((1 + 2) * (3 + 4)) - 5 = {evaluate('((1 + 2) * (3 + 4)) - 5')}")
    # 输出: (3 * 7) - 5 = 16
```

**运行结果**:

```text
===== 解释器模式演示 =====

1 + 2 = 3
10 - 3 = 7
2 * 3 + 4 = 10
(1 + 2) * 3 = 9
10 / 2 / 5 = 1
2 + 3 * 4 - 5 = 9

x = 10; x * 2 + 1 = 21
a + b * c = 7

((1 + 2) * (3 + 4)) - 5 = 16
```

### 3.3 真实示例: 布尔表达式 DSL

```python
"""
业务规则 DSL: age >= 18 AND country == "CN"
可用于: 规则引擎, 权限校验, 风控规则
"""

class BoolExpr(ABC):
    @abstractmethod
    def interpret(self, ctx: Dict) -> bool:
        ...


class And(BoolExpr):
    def __init__(self, left: BoolExpr, right: BoolExpr):
        self.left = left
        self.right = right

    def interpret(self, ctx):
        return self.left.interpret(ctx) and self.right.interpret(ctx)


class Or(BoolExpr):
    def __init__(self, left: BoolExpr, right: BoolExpr):
        self.left = left
        self.right = right

    def interpret(self, ctx):
        return self.left.interpret(ctx) or self.right.interpret(ctx)


class Not(BoolExpr):
    def __init__(self, expr: BoolExpr):
        self.expr = expr

    def interpret(self, ctx):
        return not self.expr.interpret(ctx)


class Gt(BoolExpr):
    """age > 18"""
    def __init__(self, field: str, value):
        self.field = field
        self.value = value

    def interpret(self, ctx):
        return ctx[self.field] > self.value


class Eq(BoolExpr):
    """country == "CN" """
    def __init__(self, field: str, value):
        self.field = field
        self.value = value

    def interpret(self, ctx):
        return ctx[self.field] == self.value


# 规则: (age >= 18 AND country == "CN") OR vip == True
rule = Or(
    And(
        Gt("age", 17),
        Eq("country", "CN")
    ),
    Eq("vip", True)
)

# 应用规则
print(rule.interpret({"age": 20, "country": "CN", "vip": False}))   # True
print(rule.interpret({"age": 15, "country": "CN", "vip": True}))   # True
print(rule.interpret({"age": 15, "country": "US", "vip": False}))  # False
```

## 4. Java 实现

### 4.1 经典实现: 算术表达式解释器

```java
import java.util.*;

/**
 * 解释器模式 - Java 实现
 * 场景: 算术表达式 1 + 2 - 3 * 4
 */

// ============== 抽象表达式 ==============
interface Expression {
    int interpret(Map<String, Integer> context);
}

// ============== 终结符: 数字 ==============
class NumberExpression implements Expression {
    private final int value;

    public NumberExpression(int value) { this.value = value; }

    @Override
    public int interpret(Map<String, Integer> context) {
        return value;
    }
}

// ============== 终结符: 变量 ==============
class VariableExpression implements Expression {
    private final String name;

    public VariableExpression(String name) { this.name = name; }

    @Override
    public int interpret(Map<String, Integer> context) {
        if (!context.containsKey(name)) {
            throw new RuntimeException("未定义变量: " + name);
        }
        return context.get(name);
    }
}

// ============== 非终结符: 加减乘除 ==============
class AddExpression implements Expression {
    private final Expression left, right;

    public AddExpression(Expression left, Expression right) {
        this.left = left;
        this.right = right;
    }

    @Override
    public int interpret(Map<String, Integer> context) {
        return left.interpret(context) + right.interpret(context);
    }
}

class SubExpression implements Expression {
    private final Expression left, right;

    public SubExpression(Expression left, Expression right) {
        this.left = left;
        this.right = right;
    }

    @Override
    public int interpret(Map<String, Integer> context) {
        return left.interpret(context) - right.interpret(context);
    }
}

class MulExpression implements Expression {
    private final Expression left, right;

    public MulExpression(Expression left, Expression right) {
        this.left = left;
        this.right = right;
    }

    @Override
    public int interpret(Map<String, Integer> context) {
        return left.interpret(context) * right.interpret(context);
    }
}

// ============== 客户端 ==============
public class Main {
    public static void main(String[] args) {
        // 表达式: (1 + 2) * (5 - 3)
        // = 3 * 2 = 6
        Expression ast = new MulExpression(
            new AddExpression(
                new NumberExpression(1),
                new NumberExpression(2)
            ),
            new SubExpression(
                new NumberExpression(5),
                new NumberExpression(3)
            )
        );

        System.out.println("求值: " + ast.interpret(new HashMap<>()));
        // 输出: 求值: 6

        // 带变量: x * 2 + 1, x = 10
        Expression var = new AddExpression(
            new MulExpression(
                new VariableExpression("x"),
                new NumberExpression(2)
            ),
            new NumberExpression(1)
        );
        Map<String, Integer> env = new HashMap<>();
        env.put("x", 10);
        System.out.println("x*2+1 (x=10): " + var.interpret(env));
        // 输出: 21
    }
}
```

**运行结果**:

```text
求值: 6
x*2+1 (x=10): 21
```

### 4.2 Java 进阶: 带解析器

```java
import java.util.*;

/**
 * 完整的算术表达式解释器 (Java 版)
 * 包含: Token / Lexer / Parser / Expression
 */

// 词法单元
class Token {
    enum Type { NUM, VAR, PLUS, MINUS, MUL, DIV, LPAREN, RPAREN, EOF }
    final Type type;
    final String value;

    Token(Type type, String value) {
        this.type = type;
        this.value = value;
    }

    @Override
    public String toString() {
        return type + "(" + value + ")";
    }
}

// 词法分析器
class Lexer {
    private final String text;
    private int pos = 0;
    private final List<Token> tokens = new ArrayList<>();

    public Lexer(String text) { this.text = text; tokenize(); }

    private void tokenize() {
        while (pos < text.length()) {
            char c = text.charAt(pos);
            if (Character.isWhitespace(c)) { pos++; continue; }
            if (Character.isDigit(c)) {
                int start = pos;
                while (pos < text.length() && Character.isDigit(text.charAt(pos))) pos++;
                tokens.add(new Token(Token.Type.NUM, text.substring(start, pos)));
            } else if (Character.isLetter(c)) {
                int start = pos;
                while (pos < text.length() && Character.isLetterOrDigit(text.charAt(pos))) pos++;
                tokens.add(new Token(Token.Type.VAR, text.substring(start, pos)));
            } else {
                switch (c) {
                    case '+': tokens.add(new Token(Token.Type.PLUS, "+")); break;
                    case '-': tokens.add(new Token(Token.Type.MINUS, "-")); break;
                    case '*': tokens.add(new Token(Token.Type.MUL, "*")); break;
                    case '/': tokens.add(new Token(Token.Type.DIV, "/")); break;
                    case '(': tokens.add(new Token(Token.Type.LPAREN, "(")); break;
                    case ')': tokens.add(new Token(Token.Type.RPAREN, ")")); break;
                    default: throw new RuntimeException("非法字符: " + c);
                }
                pos++;
            }
        }
        tokens.add(new Token(Token.Type.EOF, ""));
    }

    public List<Token> getTokens() { return tokens; }
}

// 抽象语法树 (复用前面定义的 Expression 接口)
interface Expr2 {
    int interpret(Map<String, Integer> env);
}

class Num2 implements Expr2 {
    final int v;
    Num2(int v) { this.v = v; }
    public int interpret(Map<String, Integer> env) { return v; }
}

class Var2 implements Expr2 {
    final String name;
    Var2(String n) { this.name = n; }
    public int interpret(Map<String, Integer> env) { return env.get(name); }
}

class BinOp2 implements Expr2 {
    final String op;
    final Expr2 left, right;
    BinOp2(String op, Expr2 l, Expr2 r) { this.op = op; this.left = l; this.right = r; }

    public int interpret(Map<String, Integer> env) {
        int l = left.interpret(env), r = right.interpret(env);
        switch (op) {
            case "+": return l + r;
            case "-": return l - r;
            case "*": return l * r;
            case "/": return l / r;
            default: throw new RuntimeException("未知运算符: " + op);
        }
    }
}

// 语法分析器 (递归下降)
class Parser2 {
    private final List<Token> tokens;
    private int pos = 0;

    public Parser2(List<Token> tokens) { this.tokens = tokens; }

    private Token peek() { return tokens.get(pos); }
    private Token consume() { return tokens.get(pos++); }

    public Expr2 parse() {
        Expr2 e = expr();
        if (peek().type != Token.Type.EOF) {
            throw new RuntimeException("未消费的 token: " + peek());
        }
        return e;
    }

    private Expr2 expr() {  // expr ::= term ((+|-) term)*
        Expr2 node = term();
        while (peek().type == Token.Type.PLUS || peek().type == Token.Type.MINUS) {
            String op = consume().value;
            node = new BinOp2(op, node, term());
        }
        return node;
    }

    private Expr2 term() {  // term ::= factor ((*|/) factor)*
        Expr2 node = factor();
        while (peek().type == Token.Type.MUL || peek().type == Token.Type.DIV) {
            String op = consume().value;
            node = new BinOp2(op, node, factor());
        }
        return node;
    }

    private Expr2 factor() {  // factor ::= NUM | VAR | '(' expr ')'
        Token t = peek();
        if (t.type == Token.Type.NUM) {
            consume();
            return new Num2(Integer.parseInt(t.value));
        } else if (t.type == Token.Type.VAR) {
            consume();
            return new Var2(t.value);
        } else if (t.type == Token.Type.LPAREN) {
            consume();
            Expr2 e = expr();
            if (peek().type != Token.Type.RPAREN) {
                throw new RuntimeException("缺少 )");
            }
            consume();
            return e;
        }
        throw new RuntimeException("意外 token: " + t);
    }
}

// 客户端
public class InterpreterDemo {
    public static int evaluate(String expr, Map<String, Integer> env) {
        List<Token> tokens = new Lexer(expr).getTokens();
        Expr2 ast = new Parser2(tokens).parse();
        return ast.interpret(env);
    }

    public static void main(String[] args) {
        System.out.println("1 + 2 = " + evaluate("1 + 2", new HashMap<>()));
        System.out.println("2 + 3 * 4 = " + evaluate("2 + 3 * 4", new HashMap<>()));
        System.out.println("(1 + 2) * (3 + 4) = " + evaluate("(1 + 2) * (3 + 4)", new HashMap<>()));

        Map<String, Integer> env = new HashMap<>();
        env.put("x", 10);
        env.put("y", 3);
        System.out.println("x * 2 + y = " + evaluate("x * 2 + y", env));
    }
}
```

**运行结果**:

```text
1 + 2 = 3
2 + 3 * 4 = 14
(1 + 2) * (3 + 4) = 21
x * 2 + y = 23
```

## 6. 优缺点

### 优点

| 优点 | 说明 |
|------|------|
| **易于扩展语法** | 新增运算符只需新增一个 Expression 子类 |
| **实现简单** | 文法不太复杂时, 容易实现 |
| **直观对应文法** | 每个类对应一条文法规则, 易于理解 |
| **可嵌套组合** | 表达式可嵌套, 支持任意复杂度 |

### 缺点

| 缺点 | 说明 |
|------|------|
| **类数量爆炸** | 文法复杂时, Expression 子类数量多 |
| **难以维护** | 复杂的语法树难调试 |
| **性能较低** | 递归调用, 大量小对象, 慢于专用解析器 |
| **难以处理复杂文法** | 二义性、左递归、优先级需要手工处理 |
| **不支持错误恢复** | 简单的实现遇到语法错误直接抛出 |

### 与其他模式对比

| 维度 | 解释器 | 访问者 | 组合 |
|------|--------|--------|------|
| 目的 | 解释/执行表达式 | 对元素施加操作 | 树形结构 |
| 树结构 | AST | 对象结构 | 一般树 |
| 典型应用 | DSL, 正则, SQL | AST 遍历, 文件系统 | 文件系统, GUI |
| 操作 | `interpret()` | `accept()` | `operation()` |

### 何时使用解释器

| 适用 | 不适用 |
|------|--------|
| 文法**简单** (5-20 条规则) | 文法**复杂** (>20 条) |
| **效率**不是首要 | 性能敏感 |
| 语法**稳定** | 语法频繁变动 |
| 想**避免外部依赖** | 已有 ANTLR / YACC 等解析器 |

**对于复杂语法, 推荐使用专业工具**:

| 工具 | 语言 | 说明 |
|------|------|------|
| **ANTLR** | Java/Python/JS/C++ | 生成解析器 + 词法分析器 |
| **PLY** | Python | Python Lex-Yacc |
| **Lark** | Python | 现代 Python 解析器 |
| **YACC/Bison** | C/C++ | 老牌解析器生成器 |
| **PEG.js** | JavaScript | 解析表达式文法 |

## 7. 实战思考

### Q1: 解释器模式 vs 直接用 `eval()`, 何时用哪个?

**答**:

| 维度 | 解释器模式 | `eval()` |
|------|-----------|----------|
| **安全性** | 高 (自己控制语法, 不会有任意代码执行) | 低 (执行任意 Python 代码, 有注入风险) |
| **性能** | 中等 (递归调用) | 快 (内置 C 实现) |
| **可控性** | 高 (可追踪, 可优化, 可编译) | 低 (黑盒) |
| **跨语言** | 通用 (Java/Python/JS 都能实现) | 仅限 Python |
| **可维护性** | 好 (文法清晰) | 一般 |
| **适用规模** | 中小型 DSL | 临时脚本 |

**何时用 `eval()`**:
- 仅限内部受信任环境
- 表达式简单 (单行数学计算)
- 快速原型, 不追求安全

**何时用解释器模式**:
- **暴露给用户**配置规则
- 需要**审计 / 限流 / 重试**表达式
- 需要**详细错误信息** (eval 报错不友好)
- **跨平台 / 跨语言** (同一 DSL 在多个系统运行)

**举例对比**:

```python
# 用 eval (不推荐, 用户可以执行任意代码)
result = eval("__import__('os').system('rm -rf /')")   # 灾难!

# 用解释器 (安全, 只支持数字和 + - * /)
result = evaluate("1 + 2 * 3")    # 9, 任何非法输入都报错
```

### Q2: 如何处理运算符优先级? 为什么 `(1 + 2) * 3` 求值正确?

**答**: 解释器模式通过**递归下降语法分析**自然支持优先级. 关键是把表达式拆成**多层规则**:

```text
expr   ::= term ((+|-) term)*      ← 加减优先级最低
term   ::= factor ((*|/) factor)*  ← 乘除优先级高
factor ::= NUM | VAR | '(' expr ')' ← 括号最优先
```

**为什么这样设计有效**:

`expr` 调用 `term`, `term` 调用 `factor`. 优先级越**低**的运算符放在**外层**规则. 这样:

- `1 + 2 * 3` 解析过程:
  - `expr` → 调用 `term`
    - `term` → 调用 `factor` (读到 1, 返回 Num(1))
    - 看到 `+`, 不是 `*`/`/`, `term` 返回 Num(1)
  - `expr` 看到 `+`, 记录为 BinOp("+", Num(1), ...)
    - 调用 `term` (递归)
      - `term` → 调用 `factor` (读到 2, 返回 Num(2))
      - 看到 `*`, 调用 `factor` (读到 3, 返回 Num(3))
      - `term` 返回 BinOp("*", Num(2), Num(3))
  - `expr` 返回 BinOp("+", Num(1), BinOp("*", Num(2), Num(3)))

- 求值: `1 + (2 * 3) = 7` ✓

**关键原则**: 优先级越**低**的运算符, 放在**越外层**的规则. 这样低优先级的运算会**包裹**高优先级.

**如果优先级颠倒会怎样?**

```python
# 反例: 把 + 放在内层, * 放在外层
# 那么 1 + 2 * 3 会被解析为 (1 + 2) * 3 = 9
def expr():  # 处理 * 和 /
    left = factor()
    while peek() in ('+', '-'):  # 错误! + 应该在 expr
        ...
```

### Q3: 解释器模式中, Context 有什么用? 怎么用?

**答**: `Context` 保存解释器在求值过程中需要的**全局状态**, 最常见的是**变量绑定**.

```python
class Context:
    def __init__(self):
        self.variables: Dict[str, int] = {}

    def set(self, name: str, value: int):
        self.variables[name] = value

    def get(self, name: str) -> int:
        return self.variables[name]
```

**两种使用方式**:

**(1) 共享 Context (更常见)**:

```python
ctx = Context()
ctx.set("x", 10)

# 求值时传入同一 context
expr1.interpret(ctx)   # expr1 可以看到 x = 10
expr2.interpret(ctx)   # expr2 也看到 x = 10
```

**(2) 局部 Context (类似作用域)**:

```python
# 进入函数时创建新 context, 退出时销毁
def call_function(args, local_ctx):
    for param, value in zip(params, args):
        local_ctx.set(param, value)
    return body.interpret(local_ctx)
```

**进阶用法**:

| 用法 | 说明 |
|------|------|
| **存储变量值** | `x = 10` 等赋值 |
| **存储函数定义** | `def foo(): ...` |
| **作用域链** | 嵌套作用域 (内层可访问外层) |
| **性能缓存** | 缓存表达式结果 |
| **调用计数** | 跟踪表达式执行次数 |
| **调试信息** | 当前行号, 调试断点 |

**示例: 函数调用 + Context**:

```python
class CallExpr(Expr):
    def __init__(self, name: str, args: List[Expr]):
        self.name = name
        self.args = args

    def interpret(self, ctx):
        func = ctx.get_function(self.name)
        # 创建新的局部 context
        local_ctx = Context(parent=ctx)
        for param, arg in zip(func.params, self.args):
            local_ctx.set(param, arg.interpret(ctx))
        return func.body.interpret(local_ctx)
```

### Q4: 真实项目中, 解释器模式最常见的应用是什么?

**答**: 根据实战经验, 解释器模式最常见的应用是:

**应用 1: 规则引擎 (最常见)**

```python
# 业务规则 (保险定价, 风控, 营销)
rule = "premium_score > 80 AND has_insurance == True AND age IN (25, 55)"
# 解释器解释这条规则, 决定是否承保
```

**应用 2: 配置中心表达式**

```python
# 配置中心: 动态开关
feature_flag = "user.region == 'CN' AND user.vip_level >= 3"
# 解释器判断当前用户是否启用新功能
```

**应用 3: 工作流条件**

```python
# Airflow / 业务流程
condition = "env == 'prod' AND retry_count < 3 AND last_run_status == 'success'"
# 解释器判断是否触发下一步
```

**应用 4: 数据过滤 / 查询**

```python
# DataFrame filter, 类似 pandas query
df.query("age > 18 and country == 'CN'")
# pandas 内部用 Python `eval` 解释
```

**应用 5: 数学公式 / 报表**

```python
# Excel-like 公式
formula = "SUM(A1:A10) * 1.13"   # 含税金额
# 解释器计算结果
```

**为什么不用 ANTLR / 专业工具**:

- 文法简单 (10 条以内规则), 自己实现更快
- 不希望引入额外依赖
- 需要在嵌入式中运行 (无外部库)

**最佳实践**:

| 场景 | 建议 |
|------|------|
| 5-10 条规则 | 手写解释器模式 |
| 10-30 条规则 | 手写 + 优化 (LRU 缓存, 字节码) |
| > 30 条规则 / 复杂语法 | 用 ANTLR / Lark |
| 性能敏感 | 用 LR 解析表 + 编译为字节码 |

## 8. 小结

| 维度 | 内容 |
|------|------|
| **模式类型** | 行为型 |
| **核心思想** | 把每条语法规则映射成一个类, 构造 AST 后递归求值 |
| **关键角色** | AbstractExpression / Terminal / NonTerminal / Context |
| **典型应用** | DSL, 正则, SQL, 业务规则, 数学公式 |
| **优点** | 易于扩展语法, 直对应文法, 嵌套组合 |
| **缺点** | 类爆炸, 性能低, 难处理复杂文法 |
| **Python 注意** | 简单场景可用 `eval`, 复杂场景优先用 PLY/Lark |
| **核心陷阱** | 不要把运算符优先级搞反, 递归下降要层次分明 |

**记忆口诀**: 文法定类, 终结非终结; AST 递归求值, Context 存变量.
