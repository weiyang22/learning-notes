# 02-结构型模式对比

## 一、概述

**结构型模式** (Structural Patterns) 关注**类与对象的组合方式**。它们通过继承、聚合、封装等手段,让原本不兼容的接口可以协作、可以让职责动态叠加、可以控制访问、可以共享内部状态。

GoF 共归纳 7 种结构型模式:

| # | 模式 | 一句话定义 | 主要意图 |
|---|---|---|---|
| 1 | **适配器** (Adapter) | 将一个类的接口转换成客户希望的另一个接口 | **接口转换**,兼容旧 API |
| 2 | **桥接** (Bridge) | 将抽象部分与其实现部分分离,使它们都可以独立变化 | **抽象-实现解耦** |
| 3 | **组合** (Composite) | 将对象组合成树形结构以表示"部分-整体"层级 | **树形结构**统一处理 |
| 4 | **装饰器** (Decorator) | 动态地给对象添加职责,提供比继承更灵活的替代方案 | **动态增强功能** |
| 5 | **外观** (Facade) | 为子系统中的一组接口提供一个一致的界面 | **子系统封装**,简化调用 |
| 6 | **享元** (Flyweight) | 通过共享技术支持大量细粒度对象 | **对象共享**,节省内存 |
| 7 | **代理** (Proxy) | 为其他对象提供一种代理以控制对这个对象的访问 | **控制访问**,延迟/保护/远程 |

> **常见疑问**: 结构型模式看似都在"封装",它们的本质区别是什么?——它们**封装的"维度"不同**: 适配器封"接口"、桥接封"实现"、组合封"层级"、装饰器封"职责"、外观封"子系统"、享元封"对象状态"、代理封"访问控制"。理解封装的"维度"是区分它们的关键。

## 二、对比表格

### 2.1 核心维度对比

| 维度 | 适配器 | 桥接 | 组合 | 装饰器 | 外观 | 享元 | 代理 |
|---|---|---|---|---|---|---|---|
| **核心意图** | 接口转换 | 抽象/实现分离 | 部分-整体(树) | 动态加职责 | 子系统封装 | 对象共享 | 控制访问 |
| **类/对象结构** | 对象适配/类适配 | 抽象+实现双维度 | 树形 | 包装同一接口 | 多子系统聚合 | 内部/外部状态分离 | 包装同一接口 |
| **是否产生新接口** | ✅ 客户端目标接口 | ❌ 抽象/实现两侧 | ❌ Component 接口 | ❌ 同接口 | ✅ 简化接口 | ❌ Flyweight 接口 | ❌ 同接口 |
| **是否改变原有行为** | ✅ 转换调用 | ❌ 委托给实现 | ❌ 递归调用 | ✅ 增加职责 | ❌ 转发调用 | ❌ 共享数据 | ⚠️ 视类型而定 |
| **运行期可扩展** | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ | ✅ |
| **是否符合开闭原则** | ✅ | ✅ | ✅ | ✅ | ⚠️ 加子系统需改 | ✅ | ✅ |
| **继承 vs 组合** | 继承或组合 | 组合 | 组合 | 组合 | 组合 | 组合 | 组合 |
| **典型场景** | 旧 API 兼容 | 跨平台 UI | 文件系统/UI 树 | I/O 流/装饰 | Spring Facade | 字符串池/线程池 | RPC/AOP/缓存 |
| **代表实现** | `InputStreamReader` | AWT `Peer` | `java.awt.Container` | `BufferedInputStream` | SLF4J | `Integer.valueOf` | JDK 动态代理 |

### 2.2 目的-结构-场景对照

| 模式 | 解决了什么问题 | 内部关键角色 | 典型代码特征 |
|---|---|---|---|
| 适配器 | 已有类接口不匹配 | Adapter / Adaptee | `class Adapter implements Target { void request() { adaptee.specificRequest(); }}` |
| 桥接 | 多维度独立变化 | Abstraction / Implementor | `class RefinedAbstraction extends Abstraction { void operation() { impl.operationImpl(); }}` |
| 组合 | 树形结构整体-部分 | Component / Leaf / Composite | `void operation() { for (Component c : children) c.operation(); }` |
| 装饰器 | 运行时叠加职责 | Component / ConcreteComponent / Decorator | `class Decorator implements Component { Component wrapped; ... }` |
| 外观 | 复杂子系统易用 | Facade / Subsystems | `class Facade { void op() { sys1.do(); sys2.do(); }}` |
| 享元 | 海量对象内存占用 | Flyweight / FlyweightFactory | `Map<K, Flyweight> pool = ...` |
| 代理 | 控制对象访问 | Subject / RealSubject / Proxy | `class Proxy implements Subject { RealSubject real; ... }` |

### 2.3 装饰器 vs 代理 vs 适配器(易混对比)

| 维度 | 装饰器 | 代理 | 适配器 |
|---|---|---|---|
| **目的** | 增加职责 | 控制访问 | 接口转换 |
| **接口** | 与被包装对象**相同** | 与被代理对象**相同** | 与被适配对象**不同** |
| **是否知道被包装对象的具体类** | 通常知道 | 通常知道 | 通常知道 |
| **运行时叠加** | ✅ 多层嵌套 | ❌ 一般单层 | ❌ 单层 |
| **典型应用** | I/O 缓冲/加密 | AOP/RPC/缓存 | 旧 API 兼容 |

### 2.4 与 SOLID 原则的关系

| 原则 | 适配器 | 桥接 | 组合 | 装饰器 | 外观 | 享元 | 代理 |
|---|---|---|---|---|---|---|---|
| **S** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| **O** | ✅ | ✅ | ✅ | ✅ | ⚠️ | ✅ | ✅ |
| **L** | ✅ | ✅ | ✅ | ✅ | N/A | ✅ | ✅ |
| **I** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| **D** | ✅ | ✅ | ✅ | ✅ | ⚠️ | ✅ | ✅ |

## 四、实战代码示例

### 4.1 适配器 (Python + Java)

**Java 实现**: 把 `OldLogger` 适配成新接口 `Logger`。

```java
// 已有旧接口
public class OldLogger {
    public void writeLog(String level, String msg) {
        System.out.println("[" + level + "] " + msg);
    }
}

// 新接口(目标)
public interface Logger {
    void info(String msg);
    void error(String msg);
}

// 对象适配器
public class LoggerAdapter implements Logger {
    private final OldLogger old = new OldLogger();
    @Override
    public void info(String msg) { old.writeLog("INFO", msg); }
    @Override
    public void error(String msg) { old.writeLog("ERROR", msg); }
}
```

**Python 实现**: 适配不同 CSV 库。

```python
class CsvLibraryA:
    def read_csv(self, path): ...
    def write_csv(self, path, data): ...

class CsvLibraryB:
    def parse_csv(self, path): ...
    def dump_csv(self, path, data): ...

class CsvAdapter:
    """统一接口,内部可切换实现"""
    def __init__(self, impl: str = "A"):
        if impl == "A":
            self._lib = CsvLibraryA()
        else:
            self._lib = CsvLibraryB()

    def read(self, path):
        if isinstance(self._lib, CsvLibraryA):
            return self._lib.read_csv(path)
        return self._lib.parse_csv(path)

    def write(self, path, data):
        if isinstance(self._lib, CsvLibraryA):
            self._lib.write_csv(path, data)
        else:
            self._lib.dump_csv(path, data)
```

### 4.2 桥接 (Java)

```java
// 实现层接口
public interface DrawAPI {
    void drawCircle(int x, int y, int radius);
}

public class RedCircle implements DrawAPI {
    public void drawCircle(int x, int y, int r) { /* 用红色画 */ }
}
public class GreenCircle implements DrawAPI {
    public void drawCircle(int x, int y, int r) { /* 用绿色画 */ }
}

// 抽象层
public abstract class Shape {
    protected DrawAPI drawAPI;
    protected Shape(DrawAPI d) { this.drawAPI = d; }
    public abstract void draw();
}

public class Circle extends Shape {
    private int x, y, radius;
    public Circle(int x, int y, int r, DrawAPI d) {
        super(d);
        this.x = x; this.y = y; this.radius = r;
    }
    public void draw() { drawAPI.drawCircle(x, y, radius); }
}

// 使用: 形状和颜色可以独立组合
new Circle(1, 2, 3, new RedCircle()).draw();
new Circle(4, 5, 6, new GreenCircle()).draw();
```

### 4.3 组合 (Java)

```java
public interface FileSystemNode {
    void ls(int indent);
    long size();
}

// 叶节点
public class File implements FileSystemNode {
    private String name;
    private long bytes;
    public File(String n, long b) { name = n; bytes = b; }
    public void ls(int indent) { printIndent(indent); System.out.println(name); }
    public long size() { return bytes; }
}

// 复合节点
public class Directory implements FileSystemNode {
    private String name;
    private List<FileSystemNode> children = new ArrayList<>();
    public Directory(String n) { name = n; }
    public void add(FileSystemNode n) { children.add(n); }

    public void ls(int indent) {
        printIndent(indent);
        System.out.println(name + "/");
        for (FileSystemNode c : children) c.ls(indent + 2);
    }

    public long size() {
        long total = 0;
        for (FileSystemNode c : children) total += c.size();
        return total;
    }
}
```

### 4.4 装饰器 (Java I/O 经典案例)

```java
// 同接口
public interface DataSource {
    void writeData(String data);
    String readData();
}

// 基础实现
public class FileDataSource implements DataSource {
    private String filename;
    public FileDataSource(String f) { this.filename = f; }
    public void writeData(String data) { /* 写入文件 */ }
    public String readData() { /* 从文件读 */ return ""; }
}

// 装饰器基类
public class DataSourceDecorator implements DataSource {
    protected DataSource wrapped;
    public DataSourceDecorator(DataSource ds) { this.wrapped = ds; }
    public void writeData(String data) { wrapped.writeData(data); }
    public String readData() { return wrapped.readData(); }
}

// 加密装饰器
public class EncryptionDecorator extends DataSourceDecorator {
    public EncryptionDecorator(DataSource ds) { super(ds); }
    public void writeData(String data) { super.writeData(encrypt(data)); }
    public String readData() { return decrypt(super.readData()); }
    private String encrypt(String d) { return "[ENC]" + d; }
    private String decrypt(String d) { return d.replace("[ENC]", ""); }
}

// 使用: 多层叠加
DataSource ds = new EncryptionDecorator(
                       new CompressionDecorator(
                       new FileDataSource("test.dat")));
ds.writeData("Hello");
```

### 4.5 外观 (Python)

```python
class CPU:
    def freeze(self): ...
    def jump(self, pos): ...
    def execute(self): ...

class Memory:
    def load(self, pos, data): ...

class HardDrive:
    def read(self, lba, size): ...

class ComputerFacade:
    """门面: 屏蔽 CPU/Memory/HardDrive 细节"""
    def __init__(self):
        self.cpu = CPU()
        self.mem = Memory()
        self.disk = HardDrive()

    def start(self):
        self.cpu.freeze()
        self.mem.load(0, self.disk.read(0, 1024))
        self.cpu.jump(0)
        self.cpu.execute()


# 客户端不需要知道底层细节
pc = ComputerFacade()
pc.start()
```

### 4.6 享元 (Java)

```java
// 享元对象只保存内部状态(共享),外部状态由客户端传入
public class TreeType {
    private final String name;          // 内部
    private final String color;         // 内部
    private final String texture;       // 内部
    public TreeType(String n, String c, String t) { ... }
    public void draw(int x, int y) {    // 外部状态由参数传入
        System.out.println("在(" + x + "," + y + ")画 " + name);
    }
}

// 享元工厂
public class TreeFactory {
    private static final Map<String, TreeType> pool = new HashMap<>();
    public static TreeType get(String name, String color, String texture) {
        String key = name + color + texture;
        return pool.computeIfAbsent(key, k -> new TreeType(name, color, texture));
    }
}

// 客户端
for (int i = 0; i < 1000000; i++) {
    TreeType t = TreeFactory.get("松树", "绿", "粗糙");
    t.draw(randX(), randY());          // 外部状态
}
```

### 4.7 代理 (Java JDK 动态代理)

```java
public interface UserService { void save(); }

public class UserServiceImpl implements UserService {
    public void save() { System.out.println("save user"); }
}

// 调用处理器
public class LoggingHandler implements InvocationHandler {
    private Object target;
    public LoggingHandler(Object t) { this.target = t; }
    public Object invoke(Object proxy, Method m, Object[] args) throws Throwable {
        System.out.println("[LOG] before " + m.getName());
        Object r = m.invoke(target, args);
        System.out.println("[LOG] after  " + m.getName());
        return r;
    }
}

// 使用
UserService target = new UserServiceImpl();
UserService proxy = (UserService) Proxy.newProxyInstance(
        target.getClass().getClassLoader(),
        target.getClass().getInterfaces(),
        new LoggingHandler(target));
proxy.save();
// 输出:
// [LOG] before save
// save user
// [LOG] after  save
```

**Python 等价** (使用 `wrapt`):

```python
import wrapt

@wrapt.decorator
def logging(wrapped, instance, args, kwargs):
    print(f"[LOG] before {wrapped.__name__}")
    r = wrapped(*args, **kwargs)
    print(f"[LOG] after  {wrapped.__name__}")
    return r

class UserService:
    @logging
    def save(self):
        print("save user")
```

| 模式 | JDK 中的体现 |

## 六、选择建议

### 6.1 何时用哪个?

| 场景 | 推荐模式 | 原因 |
|---|---|---|
| 已有类接口不符合新代码 | 适配器 | 兼容旧代码,无需改源 |
| 类有 2+ 独立变化的维度 | 桥接 | 避免类爆炸 |
| 需要表示树形结构(文件/UI/组织架构) | 组合 | 客户端对叶/枝一视同仁 |
| 动态给对象增加职责,可选叠加 | 装饰器 | 比继承灵活 |
| 子系统复杂,需简化客户端调用 | 外观 | 减少客户端学习成本 |
| 大量细粒度对象,内存吃紧 | 享元 | 共享不变部分 |
| 远程/延迟/保护/缓存/同步等场景 | 代理 | 不修改被代理对象 |

### 6.2 模式组合

| 组合 | 示例 |
|---|---|
| 装饰器 + 装饰器 | Java I/O: `new DataInputStream(new BufferedInputStream(new FileInputStream(f)))` |
| 外观 + 适配器 | SLF4J 是外观,内部用适配器适配 logback / log4j |
| 代理 + 装饰器 | AOP 同时是代理 + 装饰器 |
| 享元 + 组合 | 树形 UI 共享 TreeNode 元数据 |
| 桥接 + 适配器 | 桥接设计抽象层,适配器接入第三方实现 |

### 6.3 反模式警告

| 错误 | 后果 |
|---|---|
| ❌ 用装饰器去改变接口 | 装饰器应保持同接口,要改接口请用适配器 |
| ❌ 用适配器去增加新职责 | 适配器只做转换,加职责请用装饰器 |
| ❌ 用组合去扁平化结构 | 失去了部分-整体的语义 |
| ❌ 用外观去包装 1 个类 | 没有意义 |
| ❌ 用享元去共享可变状态 | 会出现线程安全问题 |

---

## 七、常见误区

### 7.1 装饰器 vs 代理

**最常见的面试题**。它们的代码结构看起来一样,区别在于:

| 关注点 | 装饰器 | 代理 |
|---|---|---|
| 设计目的 | 增加行为 | 控制访问 |
| 关系 | 包装对象由客户端**显式传入** | 包装对象通常**自己创建**或由 DI 注入 |
| 数量 | 可以叠加多个 | 通常一对一 |
| 业务归属 | 装饰器自身是核心业务一部分 | 代理通常与核心业务无关(横切关注点) |

```java
// 装饰器: 客户端明确选择要装饰
new BufferedInputStream(new FileInputStream(f));

// 代理: 客户端拿到的是代理,内部已包好真实对象
UserService u = (UserService) Proxy.newProxyInstance(...);  // 内部包了 target
```

### 7.2 适配器 vs 桥接

| 适配器 | 桥接 |
|---|---|
| 已有类,被迫适配 | 主动设计,预防维度爆炸 |
| 通常**事后**引入 | 设计阶段就考虑 |
| 接口不兼容是"问题" | 抽象与实现分离是"方案" |

### 7.3 外观 vs 中介者

| 外观 | 中介者 |
|---|---|
| 单向: 客户端 → 外观 → 子系统 | 双向: 对象 ↔ 中介者 ↔ 对象 |
| 结构型 | 行为型 |
| 简化调用 | 解耦对象网状关系 |

### 7.4 享元 vs 缓存

| 享元 | 缓存 |
|---|---|
| 是一种**对象设计**模式 | 是一种**数据存储**策略 |
| 通过共享减少内存 | 通过复用减少计算 |
| 对象本身不可变 | 缓存值可变 |

## 八、小结

| 模式 | 一句话 | 关键角色 | JDK/Spring 案例 |
|---|---|---|---|
| **适配器** | 接口转换 | Target / Adaptee / Adapter | `InputStreamReader` |
| **桥接** | 抽象-实现分离 | Abstraction / Implementor | AWT `Component`/`Peer` |
| **组合** | 树形结构整体-部分 | Component / Leaf / Composite | `JComponent` 树 |
| **装饰器** | 动态叠加职责 | Component / Decorator | `BufferedInputStream` |
| **外观** | 子系统封装 | Facade / Subsystems | `JdbcTemplate` |
| **享元** | 共享细粒度对象 | Flyweight / Factory | `Integer.valueOf` 缓存 |
| **代理** | 控制访问 | Subject / Proxy | JDK 动态代理 / Spring AOP |

**核心选型原则**:
1. **问"封装的维度"**: 适配器封接口、桥接封实现、组合封层级、装饰器封职责、外观封子系统、享元封状态、代理封访问。
2. **运行时/编译时区分**: 装饰器、代理、享元是**运行期**生效;适配器、桥接、外观是**编译期**确定。
3. **避免模式污染**: 不是所有类都需要装饰器,不是所有接口都需要外观。
4. **优先组合,慎用继承**: 7 种结构型中,6 种都是基于组合(继承)。

> **金句**: "继承是面向对象的'静态复用',组合是面向对象的'动态复用'。"——结构型模式的本质就是教你怎么用好组合。
