# 03-行为型模式对比

## 一、概述

**行为型模式** (Behavioral Patterns) 关注**对象之间的通信、职责分配与算法抽象**。如果说创建型模式解决"对象怎么来",结构型模式解决"对象怎么组合",那么行为型模式解决的就是"对象之间怎么协作、职责怎么流转"。GoF 共归纳出 **11 种行为型模式**,是三大类中数量最多、变化最丰富的一族。

| # | 模式 | 一句话定义 | 主要意图 |
|---|---|---|---|
| 1 | **观察者** (Observer) | 对象间一对多依赖,状态变化自动通知 | **事件广播** |
| 2 | **策略** (Strategy) | 定义算法族,封装起来使它们可以互相替换 | **算法可替换** |
| 3 | **命令** (Command) | 把请求封装为对象,从而参数化对象/队列/撤销 | **请求对象化** |
| 4 | **责任链** (Chain of Responsibility) | 把请求沿处理链传递,直到有对象处理它 | **多步处理/拦截** |
| 5 | **迭代器** (Iterator) | 提供顺序访问聚合对象元素的方法,不暴露内部表示 | **统一遍历** |
| 6 | **中介者** (Mediator) | 用中介对象封装一系列对象交互,降低耦合 | **集中通信** |
| 7 | **备忘录** (Memento) | 在不破坏封装性的前提下,捕获并外部化对象的内部状态 | **快照/撤销** |
| 8 | **状态** (State) | 允许对象在内部状态改变时改变其行为 | **状态机** |
| 9 | **模板方法** (Template Method) | 在父类中定义算法骨架,把某些步骤延迟到子类 | **算法框架复用** |
| 10 | **访问者** (Visitor) | 在不修改元素类的前提下,为元素结构添加新操作 | **数据结构与操作解耦** |
| 11 | **解释器** (Interpreter) | 给定一种语言,定义其文法表示与解释器 | **DSL/表达式解析** |

> **常见疑问**: 11 种行为型模式看起来都很"虚",如何快速区分? 关键看**控制流走向**: 观察者/中介者关心**消息分发**,策略/状态/模板方法关心**算法骨架**,命令/责任链关心**请求处理链**,迭代器/访问者关心**元素遍历**,备忘录关心**状态保存**,解释器关心**语法解析**。

### 2.2 目的-结构-场景对照表

| 模式 | 解决了什么问题 | 内部关键角色 | 典型代码特征 |
|---|---|---|---|
| **观察者** | 一对象变化,多对象需要同步响应 | Subject 维护 Observer 列表 | `addObserver()` / `notifyAll()` |
| **策略** | 多算法经常切换,if-else 爆炸 | Context 持有 Strategy 引用 | `setStrategy()` / `execute()` |
| **命令** | 需要撤销、队列、日志、参数化对象 | Invoker 调用 Command,Command 调 Receiver | `execute()` / `undo()` |
| **责任链** | 多对象都可能处理请求,不确定由谁处理 | 链上每个 Handler 决定是否处理/传递 | `setNext()` / `handle()` |
| **迭代器** | 统一不同数据结构的遍历方式 | Iterator 提供 `hasNext()/next()` | `for-each` 语法糖 |
| **中介者** | 多个对象互相引用,呈网状耦合 | Mediator 集中协调所有 Colleague | `mediator.send(msg, from)` |
| **备忘录** | 需要保存/恢复对象状态,又不破坏封装 | Memento 仅 Originator 可读其内部 | `createMemento()` / `restore()` |
| **状态** | 对象行为随状态变化,代码充斥 if-else | Context 委托 State 处理 | `state.handle(context)` |
| **模板方法** | 多个类算法结构相同,某些步骤不同 | AbstractClass 定义骨架 | `final` 方法调 `abstract` 钩子 |
| **访问者** | 稳定的数据结构,频繁增加操作 | Visitor 双分派遍历 Element | `element.accept(visitor)` |
| **解释器** | 自定义简单语言/表达式 | Expression 解释 Context | `interpret(ctx)` |

### 2.3 "控制流" 视角对比

```
观察者:    Subject 主动 push,Observers 被动 react
策略:      Client 选择策略 → Context 委托给 Strategy → 算法执行
命令:      Client 创建 Command → Invoker 持有 → 调用 execute() → Receiver 执行
责任链:    Client → Handler1 → Handler2 → ... → HandlerN (或中断)
迭代器:    Client → Iterator.next() → Aggregate 内部移动游标
中介者:    Colleague A → Mediator → Colleague B (集中调度)
备忘录:    Originator → 创建 Memento → 交给 Caretaker → 恢复时回读
状态:      Context → State.handle() → 切换 State → 行为随 State 变
模板方法:  AbstractClass.templateMethod() → 调用 hook1() hook2() → 子类实现钩子
访问者:    ObjectStructure → accept(visitor) → visitor.visit(this)
解释器:    Expression.interpret(Context) → 递归求值
```

### 2.4 易混淆模式区分速查表

| 易混点 | 区别要点 |
|---|---|
| **观察者 vs 中介者** | 观察者是**一对多**,Observers 互相独立;中介者是**多对多集中**,所有同事通过 Mediator 通信 |
| **策略 vs 状态** | 策略由**客户端主动选择**,对象无内在状态变化;状态由**Context 自身**根据条件切换 |
| **策略 vs 模板方法** | 策略用**对象组合**,整个算法可换;模板方法用**继承**,只换算法中的某几步 |
| **命令 vs 策略** | 命令封装**请求(动词)**,可撤销/排队;策略封装**算法(名词)**,可替换 |
| **责任链 vs 装饰器** | 责任链上每个节点**决定是否处理/传递**;装饰器**一定会增强**,并继续调用 |
| **备忘录 vs 原型** | 备忘录是**受控的状态快照**,只对 Originator 暴露;原型是**通用克隆机制** |
| **迭代器 vs 访问者** | 迭代器只**遍历**,不操作元素;访问者**遍历 + 操作**元素 |
| **状态 vs 责任链** | 状态模式 Context **同一时刻只有一个 State**;责任链是**多个 Handler 排队处理** |
| **访问者 vs 解释器** | 访问者操作**已有数据结构**;解释器**定义新语法**并解释执行 |

## 四、实战代码示例

### 4.1 观察者模式 (Observer)

**意图**: 一对象状态变化,所有依赖它的对象都收到通知。

**Python**:
```python
class Subject:
    def __init__(self):
        self._observers = []

    def attach(self, observer):
        self._observers.append(observer)

    def detach(self, observer):
        self._observers.remove(observer)

    def notify(self, message):
        for obs in self._observers:
            obs.update(message)


class WeatherStation(Subject):
    def __init__(self):
        super().__init__()
        self._temperature = 0

    @property
    def temperature(self):
        return self._temperature

    @temperature.setter
    def temperature(self, value):
        self._temperature = value
        self.notify(f"温度更新为 {value}°C")


class PhoneDisplay:
    def update(self, msg):
        print(f"[手机] {msg}")


class TVDisplay:
    def update(self, msg):
        print(f"[电视] {msg}")


station = WeatherStation()
station.attach(PhoneDisplay())
station.attach(TVDisplay())
station.temperature = 25  # 输出: [手机]/[电视] 温度更新为 25°C
```

**Java**:
```java
// Spring ApplicationListener 风格
@Component
public class OrderEventPublisher {
    private final ApplicationEventPublisher publisher;

    public void publish(Order order) {
        publisher.publishEvent(new OrderCreatedEvent(order));
    }
}

@Component
public class InventoryListener implements ApplicationListener<OrderCreatedEvent> {
    public void onApplicationEvent(OrderCreatedEvent event) {
        // 扣减库存
    }
}

@Component
public class EmailListener implements ApplicationListener<OrderCreatedEvent> {
    public void onApplicationEvent(OrderCreatedEvent event) {
        // 发送邮件
    }
}
```

**JDK/Spring 应用**: `java.util.Observer/Observable`(已过时), Spring `ApplicationEvent`/`ApplicationListener`, Java `PropertyChangeListener`, Android `BroadcastReceiver`。

### 4.2 策略模式 (Strategy)

**意图**: 定义算法族,使它们可互相替换,算法的变化独立于使用算法的客户。

**Python**:
```python
from abc import ABC, abstractmethod
from typing import List


class SortStrategy(ABC):
    @abstractmethod
    def sort(self, data: List[int]) -> List[int]:
        pass


class QuickSort(SortStrategy):
    def sort(self, data):
        return sorted(data, reverse=False)  # 简化


class MergeSort(SortStrategy):
    def sort(self, data):
        return sorted(data, reverse=False)


class SortedList:
    def __init__(self, strategy: SortStrategy):
        self._strategy = strategy

    def set_strategy(self, strategy: SortStrategy):
        self._strategy = strategy

    def process(self, data):
        return self._strategy.sort(data)


ctx = SortedList(QuickSort())
print(ctx.process([3, 1, 4, 1, 5, 9]))
ctx.set_strategy(MergeSort())
print(ctx.process([3, 1, 4, 1, 5, 9]))
```

**Java**:
```java
public interface PaymentStrategy {
    PayResult pay(Order order);
}

@Component
public class AlipayStrategy implements PaymentStrategy {
    public PayResult pay(Order order) { /* ... */ return null; }
}

@Component
public class WechatPayStrategy implements PaymentStrategy {
    public PayResult pay(Order order) { /* ... */ return null; }
}

@Service
public class PaymentService {
    private final Map<String, PaymentStrategy> strategies;

    public PaymentService(List<PaymentStrategy> list) {
        this.strategies = list.stream()
            .collect(Collectors.toMap(s -> s.getClass().getSimpleName(), s -> s));
    }

    public PayResult pay(String channel, Order order) {
        return strategies.get(channel).pay(order);
    }
}
```

**JDK/Spring 应用**: `java.util.Comparator`, `java.util.concurrent.RejectedExecutionHandler` 的 4 种策略, Spring `ResourceLoader` 的多种实现。

### 4.3 命令模式 (Command)

**意图**: 把请求封装成对象,从而支持撤销、队列、日志、参数化。

**Python**:
```python
class Command:
    def execute(self): raise NotImplementedError
    def undo(self): raise NotImplementedError


class Light:
    def on(self): print("灯开")
    def off(self): print("灯关")


class LightOnCommand(Command):
    def __init__(self, light):
        self._light = light
        self._prev = None

    def execute(self):
        self._prev = self._light.is_on()  # 假设
        self._light.on()

    def undo(self):
        if self._prev:
            self._light.off()


class RemoteControl:
    def __init__(self):
        self._history = []

    def submit(self, cmd):
        cmd.execute()
        self._history.append(cmd)

    def undo_last(self):
        if self._history:
            self._history.pop().undo()
```

**Java**:
```java
// 文本编辑器撤销栈
public interface Command {
    void execute();
    void undo();
}

public class InsertTextCommand implements Command {
    private final Document doc;
    private final String text;
    private final int position;

    public void execute() { doc.insert(position, text); }
    public void undo() { doc.delete(position, text.length()); }
}

public class Editor {
    private final Deque<Command> undoStack = new ArrayDeque<>();
    public void execute(Command c) { c.execute(); undoStack.push(c); }
    public void undo() { if (!undoStack.isEmpty()) undoStack.pop().undo(); }
}
```

**JDK/Spring 应用**: `java.lang.Runnable`, `javax.swing.Action`, Spring `JdbcTemplate` 内部 `StatementCallback`, 任务调度框架 `Job`。

### 4.4 责任链模式 (Chain of Responsibility)

**意图**: 把请求沿处理链传递,直到有对象处理它。

**Python**:
```python
class Handler:
    def __init__(self):
        self._next = None

    def set_next(self, h):
        self._next = h
        return h

    def handle(self, request):
        if self._can_handle(request):
            return self._process(request)
        if self._next:
            return self._next.handle(request)
        return None

    def _can_handle(self, request): raise NotImplementedError
    def _process(self, request): raise NotImplementedError


class AuthHandler(Handler):
    def _can_handle(self, r): return "auth" in r
    def _process(self, r): return f"已鉴权: {r['auth']}"


class LogHandler(Handler):
    def _can_handle(self, r): return "log" in r
    def _process(self, r): return f"已记录: {r['log']}"


auth = AuthHandler()
auth.set_next(LogHandler())
print(auth.handle({"auth": "admin"}))   # 已鉴权: admin
print(auth.handle({"log": "event"}))    # 已记录: event
```

**Java**:
```java
// Servlet Filter 风格
public abstract class Filter {
    protected Filter next;
    public Filter setNext(Filter f) { this.next = f; return f; }
    public void doFilter(Request req, Response res) {
        if (shouldFilter(req)) process(req, res);
        else if (next != null) next.doFilter(req, res);
    }
    protected abstract boolean shouldFilter(Request req);
    protected abstract void process(Request req, Response res);
}
```

**JDK/Spring 应用**: Servlet `Filter`, Spring `HandlerInterceptor`, Spring Security `FilterChain`, Netty `ChannelPipeline`, Dubbo `Filter`。

### 4.5 迭代器模式 (Iterator)

**意图**: 提供顺序访问聚合对象元素的方法,不暴露聚合的内部表示。

**Python**:
```python
class TreeNode:
    def __init__(self, val, children=()):
        self.val = val
        self.children = list(children)


class DFSIterator:
    def __init__(self, root):
        self._stack = [root]

    def __iter__(self): return self
    def __next__(self):
        if not self._stack: raise StopIteration
        node = self._stack.pop()
        self._stack.extend(reversed(node.children))
        return node.val


root = TreeNode(1, [TreeNode(2), TreeNode(3, [TreeNode(4)])])
print(list(DFSIterator(root)))  # [1, 2, 3, 4]
```

**Java**:
```java
public interface MyIterator<T> {
    boolean hasNext();
    T next();
}

public class ArrayListIterator<T> implements MyIterator<T> {
    private final List<T> list;
    private int cursor = 0;
    public ArrayListIterator(List<T> list) { this.list = list; }
    public boolean hasNext() { return cursor < list.size(); }
    public T next() { return list.get(cursor++); }
}
```

**JDK/Spring 应用**: `java.util.Iterator`, `ListIterator`, `Enumeration`, `Spliterator`, Java 8 `Stream` 内部迭代。

### 4.6 中介者模式 (Mediator)

**意图**: 用一个中介对象封装一系列对象的交互。

**Python**:
```python
class ChatRoom:
    def __init__(self):
        self._users = []

    def join(self, user):
        self._users.append(user)
        user.room = self

    def broadcast(self, msg, sender):
        for u in self._users:
            if u is not sender:
                u.receive(msg, sender)


class User:
    def __init__(self, name):
        self.name = name
        self.room = None

    def send(self, msg):
        self.room.broadcast(msg, self)

    def receive(self, msg, sender):
        print(f"[{self.name}] {sender.name} 说: {msg}")


room = ChatRoom()
alice, bob = User("Alice"), User("Bob")
room.join(alice); room.join(bob)
alice.send("大家好!")  # Bob 收到消息
```

**Java**:
```java
// Java Concurrency 中的 Executor 充当 Mediator
ExecutorService executor = Executors.newFixedThreadPool(4);
executor.execute(task1);
executor.execute(task2);
executor.shutdown();
```

**JDK/Spring 应用**: `java.util.concurrent.Executor`, Java GUI `Dialog`, `java.util.Timer` 调度多个 `TimerTask`, 航空管制塔台类比。

### 4.7 备忘录模式 (Memento)

**意图**: 在不破坏封装性的前提下,捕获并外部化对象的内部状态,以便恢复。

**Python**:
```python
class Memento:
    def __init__(self, state):
        self._state = state  # 仅 Originator 可访问
    def get_state(self):
        return self._state


class Editor:
    def __init__(self):
        self._content = ""

    def type(self, text):
        self._content += text

    def save(self):
        return Memento(self._content)

    def restore(self, m):
        self._content = m.get_state()

    def __str__(self):
        return self._content


class History:
    def __init__(self):
        self._stack = []

    def push(self, m):
        self._stack.append(m)

    def pop(self):
        return self._stack.pop() if self._stack else None


editor = Editor()
history = History()
editor.type("Hello")
history.push(editor.save())
editor.type(" World")
print(editor)  # Hello World
editor.restore(history.pop())
print(editor)  # Hello
```

### 4.8 状态模式 (State)

**意图**: 允许对象在内部状态改变时改变它的行为,看起来好像修改了它的类。

**Python**:
```python
class State:
    def handle(self, context): pass


class OrderContext:
    def __init__(self):
        self.state = NewState()

    def set_state(self, s):
        self.state = s

    def request(self):
        self.state.handle(self)


class NewState(State):
    def handle(self, ctx):
        print("新订单 → 已支付")
        ctx.set_state(PaidState())


class PaidState(State):
    def handle(self, ctx):
        print("已支付 → 已发货")
        ctx.set_state(ShippedState())


class ShippedState(State):
    def handle(self, ctx):
        print("已发货 → 已完成")


order = OrderContext()
order.request()  # 新订单 → 已支付
order.request()  # 已支付 → 已发货
order.request()  # 已发货 → 已完成
```

**Java**:
```java
public interface OrderState {
    void handle(OrderContext ctx);
}

public class OrderContext {
    private OrderState state = new CreatedState();
    public void setState(OrderState s) { this.state = s; }
    public void next() { state.handle(this); }
}
```

**JDK/Spring 应用**: TCP 连接状态机 (CLOSED/LISTEN/ESTABLISHED), Spring `Lifecycle` (start/stop), 订单状态流转, 工作流引擎。

### 4.9 模板方法模式 (Template Method)

**意图**: 在父类中定义算法骨架,把某些步骤延迟到子类。

**Python**:
```python
class DataProcessor:
    def process(self, data):
        data = self.read(data)
        data = self.parse(data)
        data = self.transform(data)
        return self.write(data)

    def read(self, data): raise NotImplementedError
    def parse(self, data): raise NotImplementedError
    def transform(self, data): raise NotImplementedError
    def write(self, data): raise NotImplementedError


class CSVProcessor(DataProcessor):
    def read(self, data): return data.splitlines()
    def parse(self, data): return [line.split(",") for line in data]
    def transform(self, data): return [[c.upper() for c in row] for row in data]
    def write(self, data): return "\n".join(",".join(r) for r in data)
```

**Java**:
```java
public abstract class AbstractBankPayService {
    // 模板方法,final 不让子类覆写
    public final PayResult pay(Order order) {
        validate(order);
        PayRequest req = buildRequest(order);
        PayResponse resp = doPay(req);   // 钩子,子类实现
        return handleResponse(resp);     // 钩子
    }
    protected abstract PayRequest buildRequest(Order order);
    protected abstract PayResponse doPay(PayRequest req);
    protected abstract PayResult handleResponse(PayResponse resp);
}
```

**JDK/Spring 应用**: `java.io.InputStream` (read(byte[],int,int) 用 read() 实现), `AbstractList`, `AbstractSet`, Spring `JdbcTemplate`, `RestTemplate`, `RedisTemplate`, MyBatis `BaseExecutor`。

### 4.10 访问者模式 (Visitor)

**意图**: 在不修改元素类的前提下,为元素结构添加新操作。

**Python**:
```python
class File: pass
class TextFile(File): pass
class ImageFile(File): pass


class Visitor:
    def visit(self, element): raise NotImplementedError


class SizeCalculator(Visitor):
    def visit(self, element):
        if isinstance(element, TextFile):
            return len(element.content)  # 假设有 content
        if isinstance(element, ImageFile):
            return element.width * element.height


def process(files, visitor):
    return sum(visitor.visit(f) for f in files)
```

**Java**:
```java
public interface FileVisitor {
    void visit(TextFile f);
    void visit(ImageFile f);
}

public class FileNode {
    public void accept(FileVisitor v) { /* 双分派 */ }
}
```

**JDK/Spring 应用**: Java 编译器 `javax.lang.model.element.ElementVisitor`, Java NIO `Files.walkFileTree` 配合 `SimpleFileVisitor`, Spring `BeanDefinitionVisitor`。

### 4.11 解释器模式 (Interpreter)

**意图**: 给定一种语言,定义其文法表示与一个解释器。

**Python**:
```python
class Expr:
    def interpret(self, ctx): raise NotImplementedError


class Number(Expr):
    def __init__(self, v): self.v = v
    def interpret(self, ctx): return self.v


class Add(Expr):
    def __init__(self, l, r): self.l, self.r = l, r
    def interpret(self, ctx): return self.l.interpret(ctx) + self.r.interpret(ctx)


# 1 + 2 + 3
expr = Add(Add(Number(1), Number(2)), Number(3))
print(expr.interpret(None))  # 6
```

**Java**:
```java

}
```

**JDK/Spring 应用**: `java.util.regex.Pattern`, Spring `SpEL` (Spring Expression Language), `java.text.Format` 子类, SQL 解析器, 数学表达式库。

## 六、选择建议

### 6.1 按"诉求"选模式

| 你的诉求 | 推荐模式 | 理由 |
|---|---|---|
| 对象变化要让多个对象响应 | **观察者** | 一对多通知,松耦合 |
| 多种算法/规则要可替换 | **策略** | 避免 if-else,运行时切换 |
| 需要撤销/重做/任务队列 | **命令** | 请求对象化,自带历史 |
| 多个处理器都可能处理请求 | **责任链** | 解耦发送者与接收者 |
| 多种集合要统一遍历 | **迭代器** | 隐藏内部结构 |
| 多个对象网状通信变复杂 | **中介者** | 集中到 Mediator,降低耦合 |
| 需要保存/恢复对象历史状态 | **备忘录** | 不破坏封装地快照 |
| 对象行为高度依赖内部状态 | **状态** | 用类替代条件分支 |
| 算法骨架固定,部分步骤可变 | **模板方法** | 复用父类流程 |
| 数据结构稳定,操作经常扩展 | **访问者** | 易于增加新操作 |
| 自定义 DSL/简单表达式 | **解释器** | 直接解释执行 |

### 6.2 选型原则

1. **优先简单的**: if-else 几个分支不必上策略,几个监听者不必上中介者。
2. **优先 JDK 自带的**: 观察者用 `ApplicationListener`,模板方法用 `AbstractList`。
3. **优先 Spring 提供的**: 责任链用 `HandlerInterceptor`,命令风格用 `TaskExecutor`。
4. **警惕"模式滥用"**: 11 个行为型模式里,**观察者、策略、模板方法** 三者能解决 80% 的日常问题。

## 七、常见误区

### 误区 1: 把"回调"当作"观察者"
- **错误**: 一个对象的方法被另一个对象调用,就叫观察者。
- **正解**: 观察者需要**一对多**的广播能力,且 Observer 之间互不知道。

### 误区 2: 策略模式被写成 if-else 的"配置项"
- **错误**: `if (strategy == "ALIPAY") doAlipay(); else if ...`
- **正解**: 策略应该用**对象组合 + 多态**,而不是字符串判断。

### 误区 3: 命令模式没有"撤销"也强行套用
- **错误**: 仅仅为了"请求对象化"就强行做命令,但没有 `execute/undo`。
- **正解**: 命令模式的核心价值就是**撤销/重做/队列**,如果不需要,普通方法调用即可。

### 误区 4: 责任链每个节点都"处理"而不是"传递"
- **错误**: 链上每个 Handler 都处理请求,即使不属于自己。
- **正解**: Handler 应**判断是否能处理**,不能则向下传递。

### 误区 5: 中介者变成"上帝对象"
- **错误**: Mediator 知道所有同事的细节,体积膨胀。
- **正解**: Mediator 只做**协调与转发**,业务逻辑应在 Colleague 内部。

### 误区 6: 备忘录破坏封装性
- **错误**: Memento 的 getter 暴露所有内部状态。
- **正解**: Memento 应只对 Originator 可见(`internal class`),对外只暴露"快照"概念。

### 误区 7: 状态模式被退化成"标志位 + if"
- **错误**: `if (status == PAID) { ... } else if (status == SHIPPED) { ... }`
- **正解**: 应该把每种状态**封装为类**,Context 委托给 State。

### 误区 8: 模板方法违反"组合优于继承"
- **错误**: "组合优于继承"是普适原则,所以模板方法是反模式。
- **正解**: 模板方法在"**算法骨架复用**"场景下仍然合适,而且 Java/Spring 大量使用(`JdbcTemplate`)。

### 误区 9: 访问者破坏"开闭原则"
- **错误**: 访问者增加新元素类型时,要改所有 Visitor 子类,违反开闭。
- **正解**: 访问者适合**元素稳定,操作易变**的场景;反过来则不适用。

### 误区 10: 解释器用于复杂语言
- **错误**: 用解释器实现一个完整的 Python。
- **正解**: 解释器只适合**简单 DSL/表达式**,复杂语言应该用 YACC/ANTLR 等专业工具。

## 八、小结

行为型模式是设计模式中**数量最多、变化最丰富**的一族,涵盖了对象间通信、算法骨架、状态流转、遍历解析等核心场景。11 种模式按"控制流"可分为:

| 分组 | 包含模式 | 共性 |
|---|---|---|
| **消息分发组** | 观察者、中介者 | 处理对象间通信 |
| **算法替换组** | 策略、状态、模板方法 | 让算法/行为可变化 |
| **请求处理组** | 命令、责任链 | 围绕"请求"做文章 |
| **数据访问组** | 迭代器、访问者 | 围绕"集合/数据结构"做文章 |
| **状态保存组** | 备忘录 | 围绕"对象状态"做文章 |
| **语法解析组** | 解释器 | 围绕"自定义语法"做文章 |

**实战口诀**:
- 通知用**观察者**,算法换**策略**,撤销用**命令**,过滤用**责任链**。
- 遍历用**迭代器**,解耦用**中介者**,快照用**备忘录**,状态机用**状态**。
- 框架用**模板方法**,AST 用**访问者**,DSL 用**解释器**。

> **最后提醒**: 学习行为型模式不要陷入"模式清单",而要把握它们的**核心意图**——同一个问题可能有多种解法,真正的高手是看穿问题本质后选择最简单、最贴合的方案。
