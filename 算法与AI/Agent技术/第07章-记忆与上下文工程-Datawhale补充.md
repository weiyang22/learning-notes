## 二、核心补充内容

### 2.1 记忆的三层架构与生命周期（hello-agents ch8）

hello-agents 把 Agent 记忆按"认知科学式"分层，每层有不同的读写路径与持久化策略：

| 层 | 内容 | 生命周期 | 存储 |
| :--- | :--- | :--- | :--- |
| 工作记忆 | 当前任务的目标、中间结果、工具返回 | 会话内 | 上下文窗口本身 |
| 情景记忆（Episodic） | 历史交互轨迹（"上次用户让我…"） | 跨会话 | 向量库 / KV 日志 |
| 语义记忆（Semantic） | 从轨迹中蒸馏的事实与偏好（"用户偏好简洁回答"） | 长期 | 结构化存储 / 知识库 |
| 程序记忆 | 工作流、技能、成功计划的模板 | 长期 | Skill 文件 / 代码 |

**关键机制**（ch8 给出代码）：情景→语义的**蒸馏步骤**是多数实现的缺失环节——不是把所有历史都塞进向量库，而是定期用 LLM 把"这批轨迹里有哪些可复用的事实/偏好"提炼成结构化条目，淘汰一次性的过程细节。原文档的"记忆与上下文"若缺这一步，长期运行的 agent 会被过程噪声淹 没。

### 2.2 上下文工程的四操作（hello-agents ch9 + Extra02）

ch9 把上下文工程定义为对上下文窗口的四种主动管理操作，比"塞 prompt"的系统化程度高一级：

1. **写（Write）**：把关键状态显式写入外部（plan 文件、scratchpad），让上下文可重建——对应"外部记忆优于窗口记忆"原则；
2. **选（Select）**：每步只拉取与当前任务相关的记忆（检索 top-k + 相关度阈值），而不是全量注入；
3. **压（Compress）**：历史分段摘要（保留决策与结论、丢弃推理过程）；工具返回值做结构化裁剪（只留字段，不留原始 JSON 全文）；
4. **删（Isolate/Forget）**：多租户/多任务隔离；过期与矛盾事实的主动淘汰（带时间戳与置信度的记忆条目）。

**上下文预算表**（Extra02 的工程口径，可直接抄用）：

| 预算块 | 建议占比 | 说明 |
| :--- | ---: | :--- |
| System prompt + 角色定义 | ~10% | 稳定不动 |
| 长期记忆注入（语义记忆 top-k） | ~20% | 每会话开始时选取 |
| 任务目标 + 计划 | ~10% | 任务级更新 |
| 近期轨迹（最近 N 步，压缩后） | ~40% | 滚动窗口 |
| 工具返回 + 预留输出空间 | ~20% | 输出 token 必须预留 |

### 2.3 记忆 vs 上下文 vs 训练的边界（ch11 的视角）

hello-agents ch11（Agentic-RL）提供了一个重要区分：**什么值得烧进权重，什么留在上下文**：

- 高频、稳定、跨任务复用的行为模式（格式约定、工具使用习惯）→ 值得用 SFT/DPO 固化（ch11 的 SFT→GRPO 流程）；
- 低频、易变、个性化的事实（用户偏好、项目细节）→ 必须留在记忆/上下文层，训练反而会过拟合；
- 判断信号：某类信息在一周内被注入上下文超过几十次且内容不变——候选"晋升"为程序记忆（Skill）或训练数据。

### 2.4 自进化闭环（Extra10 社区精选的衔接）

hello-agents 的 Extra10（Agent Self-Evolution）把记忆系统与自进化连接：**轨迹 → 反思 → 沉淀（记忆/Skill）→ 复用 → 再评估**的四类闭环。对原文档的价值在于：记忆系统不是静态存储，其价值用"被复用次数"衡量——一个从不被检索命中的记忆条目是负债不是资产，应设淘汰机制。

## 三、可直接动手的实践

1. **给本地 Agent 加记忆蒸馏**：按 ch8 的分层，为会话历史实现"每 N 轮蒸馏一次语义记忆"的定时任务，对比蒸馏前后长会话的任务完成质量；
2. **上下文预算审计**：dump 一次真实运行的完整 prompt，按 2.2 的预算表归一化，检查哪块超标（常见：工具返回原文占 60%+）；
3. **记忆复用率统计**：为每条语义记忆记录 hit 次数，周报淘汰零命中条目。
