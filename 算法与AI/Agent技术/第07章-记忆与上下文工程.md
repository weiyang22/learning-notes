# 第07章-记忆与上下文工程


## 1. 为什么需要记忆

LLM 无状态: 每次调用只看到当前上下文。长任务/多轮对话/跨会话个性化都需要**外部记忆**来维持连贯。

---

## 2. 记忆分类

| 类型 | 内容 | 存储 |
| :--- | :--- | :--- |
| **短期(工作)记忆** | 当前任务的对话/中间结果 | 上下文窗口内 |
| **长期记忆** | 跨会话的知识/偏好 | 向量库/数据库 |
| **情景记忆(episodic)** | 过去的具体交互经历 | 检索式 |
| **语义记忆(semantic)** | 抽象出的事实/规则 | 知识库/图 |
| **程序记忆(procedural)** | 学到的技能/流程 | 提示/工具 |

---

## 3. 上下文窗口管理

即使 128K 窗口也有限且贵(且"lost in the middle"——中间信息易被忽略)。策略:

```python
def manage_context(history, max_tokens):
    if count_tokens(history) < max_tokens:
        return history
    # 保留最近若干轮 + 把更早的压成摘要
    recent = history[-K:]
    summary = llm(f"用要点总结以下对话:\n{history[:-K]}")
    return [{"role":"system","content":f"历史摘要: {summary}"}] + recent
```

技巧:
- **滑动窗口 + 摘要**: 近的原文、远的摘要。
- **关键信息置顶/置底**: 避开 lost-in-the-middle。
- **结构化而非堆原文**: 用字段/表格压缩信息密度。

## 4. 长期记忆: 存 + 检索

```python
class LongTermMemory:
    def __init__(self, vector_store): self.store = vector_store
    def write(self, text, meta):
        self.store.add(embed(text), text, meta)          # 写入(带时间/来源)
    def recall(self, query, k=5):
        return self.store.search(embed(query), k)        # 按需检索相关记忆
```

- 写什么: 用户偏好、重要事实、任务结论(不是全部对话)。
- 何时写: 会话结束/关键事件触发; 定期**记忆整理**(去重、合并、遗忘过时)。
- 前沿: 自演化图记忆(如 SAGE)用结构化关联记忆提升长程一致性。

---

## 5. 上下文工程原则

> "Context Engineering" = 系统性地决定每次调用上下文里放什么。

1. **相关性**: 只放与当前步相关的信息(RAG + 记忆检索)。
2. **信息密度**: 结构化 > 原文堆砌。
3. **顺序**: 重要信息放两端。
4. **预算**: token 是成本也是注意力预算, 别塞满。
5. **新鲜度**: 及时更新/淘汰过时信息。

这套原则贯穿 RAG(第02章)、工具结果回传(第03章)、多 Agent 通信(第06章)。

## 7. 上下文工程(Context Engineering) 深入

### 7.1 信息论视角

上下文工程的目标: 在固定的 `token budget` $B$ 内, 最大化 LLM 答案质量:
$$a^* = \arg\max_a \log p(a | C), \quad |C| \leq B$$

理想的 $C$ 应该:
- 包含所有"必要信息"。
- 排除所有"冗余/噪声"。
- 结构化, 关键信息靠前。

### 7.2 信息密度公式

设 $C = (c_1, c_2, \ldots)$, LLM 的"注意力熵"为:
$$H_\text{attn}(C) = -\sum_i \alpha_i \log \alpha_i$$

其中 $\alpha_i$ 是对 $c_i$ 的平均注意力。

经验: 上下文越长, $H_\text{attn}$ 越大(关注分散), 关键信息利用率越低。

**对策**: 信息密度 $\rho = I(C; a) / |C|$, 工程上要尽量提升 $\rho$。

### 7.3 上下文工程的五原则

| 原则 | 操作 |
| :--- | :--- |
| **相关性** | RAG + 记忆检索 |
| **信息密度** | 结构化代替堆砌 |
| **顺序** | 重要信息放两端(开头 / 结尾) |
| **预算** | 控制 token |
| **新鲜度** | 定期更新 |

### 7.4 与 Prompt Engineering 的区别

- **Prompt Engineering**: 一次性的"提示词设计"。
- **Context Engineering**: 系统化决定上下文**每次**放什么。

2025-2026 的关键词是 Context Engineering, 不再只是 prompt。

## 8. 记忆分类的深入

### 8.1 短期记忆(Working Memory)

存于 LLM 上下文窗口内的"工作记忆"。典型:
- 对话历史
- 当前任务的中间结果
- 当前的 scratchpad

**技术挑战**:
- 窗口限制(8k, 32k, 128k, 1M)。
- "Lost in the middle" 现象。
- 成本随长度上升。

### 8.2 长期记忆

跨会话存储的记忆:
- 用户偏好
- 重要事实
- 任务结论
- 学到的反思

**实现**: 向量数据库(Chroma / Weaviate / Pinecone)。

### 8.3 情景记忆(Episodic)

具体事件的记忆:
- "用户上次问过类似问题, 我这样回答过。"
- "昨天 11:23 我做错了工具调用。"

工程: 类似对话检索(用语义相似度找过去相关情景)。

### 8.4 语义记忆(Semantic)

抽象的"事实 / 概念":
- "公司政策: 退款 7 天内。"
- "用户喜欢简洁回答。"

工程: 知识库 + 知识图谱。

### 8.5 程序记忆(Procedural)

学到的"怎么做":
- 工具使用技能。
- 反思出的策略。

工程: 提示词中注入 + 工具描述 + few-shot examples。

## 9. 上下文窗口管理(Window Management)

### 9.1 滑动窗口

```python
def sliding_window(history, k=10):
    """保留最近 k 轮对话"""
    return history[-k:]
```

简单但丢远处信息。

### 9.2 滑动窗口 + 摘要

```python
def slide_with_summary(history, k=10, summary_threshold=20):
    if len(history) <= k:
        return history
    # 把旧的压成摘要
    summary = llm("用要点总结:\n" + str(history[:-k]))
    return [{"role": "system", "content": f"历史摘要: {summary}"}] + history[-k:]
```

经典做法, 平衡信息保留与 token 控制。

### 9.3 滑动窗口 + 重要性保留

```python
def importance_based_window(history, k=10):
    """保留最近 k + 关键信息"""
    recent = history[-k:]
    # 从 history[:-k] 中找出关键
    important = extract_important(history[:-k])
    return important + recent
```

`extract_important` 可以是:
- LLM 摘要关键事实。
- 关键词命中(用户偏好关键词)。
- 引用 / 出错的 step。

### 9.4 重要信息置两端

**Lost in the middle** 实证: LLM 对开头和结尾信息关注度高, 中段信息容易被忽略。

```python
def optimal_order(parts):
    """把关键信息放两端"""
    return [parts[0]] + [parts[-1]] + parts[1:-1]   # 两端为锚
```

工程上常见的做法:
- **System prompt**(开头)。
- **当前任务/工具结果**(结尾刚加)。
- 历史中间。

## 10. 长期记忆的实现

### 10.1 基本 API

```python
class LongTermMemory:
    """长期记忆的抽象"""
    def __init__(self, vector_store):
        self.store = vector_store

    def write(self, text: str, meta: dict = None):
        """写入"""
        self.store.add(embed(text), text, meta or {})

    def recall(self, query: str, k: int = 5):
        """按查询检索相关记忆"""
        results = self.store.search(embed(query), k)
        return results

    def update(self, doc_id, new_text, meta):
        """更新"""
        self.store.update(doc_id, embed(new_text), new_text, meta)

    def forget(self, doc_id):
        """删除"""
        self.store.delete(doc_id)
```

### 10.2 写策略

```python
class SmartLongTermMemory(LongTermMemory):
    """智能写入"""
    def should_write(self, event):
        """判断是否值得写"""
        prompt = f"""判断以下事件是否值得长期记住:
事件: {event}

输出 JSON: {{"write": bool, "reason": "...", "tags": [...]}}"""
        resp = llm(prompt)
        return json.loads(resp)
```

**什么值得写**:
- 用户明确偏好("我喜欢简洁")。
- 任务重要结论("项目的关键决策")。
- 错误经验("用工具 X 时需注意 Y")。

### 10.3 写入时机

- **会话结束**: 总结今天对话, 写入。
- **关键事件**: 用户说"记下这个"。
- **定期触发**: 每 N 步检查。
- **重要更新**: 检测到用户偏好变化。

### 10.4 记忆整理

```python
def consolidate_memory(memory_store, llm):
    """定期整理: 去重 + 合并 + 过期清理"""
    # 1. 找出相似记忆
    similar_pairs = find_similar_pairs(memory_store)
    # 2. 合并
    for pair in similar_pairs:
        merged = llm(f"合并以下两条记忆:\n1) {pair[0]}\n2) {pair[1]}")
        memory_store.update(pair[0].id, merged, ...)
        memory_store.forget(pair[1].id)
    # 3. 清理过期
    for m in memory_store.all():
        if m.age_days > 90 and not m.pinned:
            memory_store.forget(m.id)
```

### 10.5 自演化图记忆(SAGE 等前沿)

```python
class GraphMemory:
    """结构化关联记忆(基于图)"""
    def __init__(self):
        self.graph = nx.DiGraph()   # 实体 + 关系

    def add(self, entity, relations):
        """加入新记忆"""
        self.graph.add_node(entity)
        for rel, target in relations:
            self.graph.add_edge(entity, target, relation=rel)

    def recall(self, query, max_hop=2):
        """返回 query 相关的图子图"""
        relevant = self.search(query)
        neighbors = set([relevant])
        for hop in range(max_hop):
            new_neighbors = set()
            for node in neighbors:
                new_neighbors.update(self.graph.neighbors(node))
            neighbors.update(new_neighbors)
        return self.graph.subgraph(neighbors)
```

优势: 实体之间关系清晰, 长程一致性更强。

### 12.1 上下文的最优结构

def build_optimal_context(system_prompt, history, tools, memory_recall):
    """
    拼装 context, 关键信息分布:
    [1] System prompt(开头)
    [2] Key info: 用户偏好、用户身份(开头)
    [3] Tool schemas

    [5] History(中段)

        {"role": "system", "content": system_prompt},

        *history,
        # Current task
        {"role": "user", "content": current_query},
    ]
    return parts

## 13. 长上下文的未来

### 13.1 大窗口 LLM

GPT-4 1M / Claude 200K / Gemini 1.5 200K 已经覆盖很多场景。

但:
- **成本高**: 长 prompt 比短 prompt 贵。
- **延迟高**: 长 prompt 计算慢。
- **Lost in the middle**: 中段信息仍被忽略。

### 13.2 长上下文的工程建议

- **RAG 是默认**: 选择相关 + 引用 + 低成本。
- **长上下文是补充**: 用于"读到"全文需求。
- **结构化优先**: 即便有长窗口, 也用结构化。

### 13.3 长上下文 + RAG 的协同

```python
def hybrid_long_context(query, doc, llm_with_long_ctx):
    """对一份长文档, 先分块检索, 再用长窗口 LLM 重读相关段"""
    # 1. 检索相关 chunks
    chunks = retrieve(query, doc, k=10)

    # 2. 把 chunks 拼成长但聚焦的 context(可能仍 < 50K token)
    focused_context = "\n\n".join(chunks)

    # 3. 用长窗口 LLM 答
    return llm_with_long_ctx(f"问题: {query}\n资料: {focused_context}")
```

## 14. 真实案例:客服系统的记忆

### 14.1 需求

- 跨会话记住用户偏好("我叫小明, 喜欢简洁")。
- 跨会话记住历史咨询("上次问了退款")。

### 14.2 架构

```text
[用户消息]
     ↓
[短期记忆: 当前对话]
     ↓
[长期记忆检索: 偏好 + 历史]
     ↓
[System prompt 拼装]
     ↓
[LLM 处理]
     ↓
[写入长期记忆]
```

### 14.3 实现

```python
"""
customer_service_with_memory.py
"""
class CustomerServiceWithMemory:
    def __init__(self, llm, long_term):
        self.llm = llm
        self.long_term = long_term
        self.short_term = {}  # user_id -> history

    async def handle(self, user_id, message):
        # 1. 从长期记忆取上下文
        prefs = self.long_term.recall(
            f"用户偏好:{user_id}", k=3
        )
        history = self.long_term.recall(
            f"用户历史:{message[:100]}", k=3
        )

        # 2. 拼装 prompt
        prompt = build_prompt(
            system="你是客服助手",
            user_message=message,
            user_prefs=prefs,
            user_history=history,
            recent=self.short_term.get(user_id, [])[-10:]
        )

        # 3. LLM 答
        answer = await self.llm(prompt)

        # 4. 写入短期 + 长期
        self.short_term.setdefault(user_id, []).extend([
            {"role":"user","content":message},
            {"role":"assistant","content":answer}
        ])
        # 重要信息写入长期
        if should_remember(message, answer):
            self.long_term.write(
                f"用户 {user_id}: {message} → {answer}",
                {"user_id": user_id, "ts": now()}
            )

        return answer
```

## 15. 记忆工程的失败案例

### 15.1 记忆爆炸

**现象**: 用户偏好写了 100 条, prompt 撑爆。
**解决**: 写时筛选 + 读时排序。

### 15.2 记忆冲突

**现象**: 用户说"我喜欢简洁"和"我喜欢详细"都存了。
**解决**: 检测矛盾, LLM 决定保留哪个。

### 15.3 隐私泄露

**现象**: 长期记忆里存了用户 PII, 跨用户泄露。
**解决**: 加密 + 访问控制 + 定期清理。

### 15.4 过期信息

**现象**: 半年前的偏好, 用户已经改变。
**解决**: TTL + 定期询问"还这样吗?"。

## 16. 上下文工程的"反模式"

### 16.1 堆砌历史

❌ 把所有对话历史塞进 prompt。
✅ 只留关键事实 + 最近 5 轮。

### 16.2 重复信息

❌ 在 system prompt 和 user message 里重复说同一件事。
✅ 选一处说, 其它引用。

### 16.3 模糊指令

❌ "请认真回答。"
✅ 明确的输出格式、长度、风格。

### 16.4 无结构

❌ 一大段纯文本。
✅ 分节、表格、JSON。

### 16.5 工具描述过长

❌ 工具描述 500 字。
✅ 50-100 字说明用途 + 参数。

### Q2: lost-in-the-middle 怎么解决?

向量数据库(Chroma / Weaviate / Pinecone / Qdrant)。

系统性决定每次调用上下文放什么, 决定 Agent 成败。

## 20. 章节配套代码:完整记忆系统

```python
"""
memory_system.py
完整的 Agent 记忆系统
"""
class MemorySystem:
    """短期 + 长期 + 重要性评估"""
    def __init__(self, llm, vector_store):
        self.llm = llm
        self.vector_store = vector_store

        self.working = []    # 当前对话上下文
        self.episodic = []   # 当前会话的事件

    def add_turn(self, user_msg, assistant_msg):
        self.working.append({"role": "user", "content": user_msg})
        self.working.append({"role": "assistant", "content": assistant_msg})
        self.episodic.append({
            "user": user_msg,
            "assistant": assistant_msg,
            "time": now(),
        })

    def maybe_consolidate(self):
        """会话结束或定期执行"""
        # 写入长期
        facts = self.llm(
            "从对话中提取值得长期记住的事实:\n" + str(self.episodic)
        )
        for fact in facts:
            self.vector_store.add(fact)

        # 摘要 + 清空
        if len(self.episodic) > 20:
            summary = self.llm("摘要这段对话:\n" + str(self.episodic))
            self.vector_store.add(f"[会话摘要] {summary}")
            self.episodic = []

    def recall(self, query, k=5):
        """按 query 检索相关记忆"""
        return self.vector_store.search(query, k)

    def build_context(self, system, query, current_history=[]):
        """拼装最优上下文"""
        # 1. 长期检索
        relevant_memories = self.recall(query, k=3)

        # 2. 拼装
        parts = []
        # 系统
        parts.append({"role": "system", "content": system})
        # 重要记忆(顶部)
        for m in relevant_memories:
            parts.append({"role": "system", "content": f"相关记忆: {m}"})
        # 历史(中段)
        parts.extend(self.working[-5:])
        # 当前问题(底部)
        parts.append({"role": "user", "content": query})
        return parts
```

### 29.2 时间衰减

```python
class TimeDecayingMemory:
    """记忆随时间衰减"""
    def score(self, memory):
        age = (now() - memory.ts).days
        decay = math.exp(-age / 30)   # 30 天半衰期
        return memory.importance * decay

    def search(self, query):
        # 综合相似度 + 时间衰减
        candidates = self.vector.search(query)
        return sorted(candidates, key=lambda m: -self.score(m))
```

## 30. 记忆系统的工程经验

### 30.1 三大原则

1. **写什么比写多少重要**: 不要无差别写所有对话。
2. **读什么比读多少重要**: 检索时分清相关和噪声。
3. **遗忘是能力**: 主动忘记过期的才有空间。

### 30.2 失败模式

| 失败模式 | 表现 | 修复 |
| :--- | :--- | :--- |
| 写太少 | 跨会话失忆 | 写时更智能 |
| 写太多 | 检索噪声 | LLM 评估重要性 |
| 读不准 | 答非所问 | 优化 embedding + rerank |
| 读太多 | 上下文塞满 | 限制 top-k |
| 不遗忘 | 信息过期 | TTL + 主动定期整理 |

## 33. 上下文工程: 理论框架

### 33.1 信息增益公式

每次加入内容 $c$ 对最终答案 $a$ 的信息增益:
$$\Delta I(c, a) = I(a; c | q, C_{\text{prior}}) - I(a; q, C_{\text{prior}})$$

工程含义: 加什么到 prompt 能让答案更好?

### 33.2 上下文预算分配

总 token budget $B$, 分配给各部分:
$$B = B_\text{sys} + B_\text{memory} + B_\text{history} + B_\text{obs} + B_\text{task}$$

经验分配(客服场景):
- system: 200
- memory: 300
- history: 1000
- obs: 1000
- task: 500
- 总: ~3000

```python
"""
session_manager.py
"""
class SessionManager:
    """管理多用户多会话的状态"""
    def __init__(self):
        self.sessions = {}   # session_id -> state
        self.lock = threading.Lock()

    def get_or_create(self, session_id, user_id):
        with self.lock:
            if session_id not in self.sessions:
                self.sessions[session_id] = {
                    "user_id": user_id,
                    "history": [],
                    "context": {},
                    "created": now(),
                }
            return self.sessions[session_id]

    def update(self, session_id, key, value):
        with self.lock:
            self.sessions[session_id]["context"][key] = value

    def add_history(self, session_id, role, content):
        with self.lock:
            self.sessions[session_id]["history"].append({"role": role, "content": content})

    def cleanup_expired(self, ttl_days=7):
        with self.lock:
            cutoff = now() - timedelta(days=ttl_days)
            self.sessions = {
                s: state for s, state in self.sessions.items()
                if state["created"] > cutoff
            }
```

        self.short_term = []
        self.long_term = vector_store
        self.threshold = 20

    def add(self, message):
        self.short_term.append(message)
        if len(self.short_term) > self.threshold:
            # 触发整理
            facts = llm("提取值得长期记住的:\n" + str(self.short_term[:5]))
            for fact in facts:
                self.long_term.add(fact)
            self.short_term = self.short_term[5:]   # 留近的
            # 把剩下老的也摘要
            self.short_term.insert(0, {
                "role": "system",
                "content": f"摘要: {llm('摘要这段对话:\n' + str(self.short_term[1:]))}"
            })

    def build_context(self, query):
        return [
            {"role": "system", "content": f"相关记忆: {self.long_term.search(query, k=3)}"},
            *self.short_term,
            {"role": "user", "content": query}
        ]

## 46. 实践: 自己的长期记忆库

### 46.1 完整实现: 用 Chroma + 重要性评分

```python
"""
self_long_term_memory.py
完整的长期记忆系统
"""
import chromadb
from chromadb.utils import embedding_functions
from datetime import datetime
import json

class SelfLongTermMemory:
    def __init__(self, path="./memory_db"):
        self.client = chromadb.PersistentClient(path=path)
        self.ef = embedding_functions.OpenAIEmbeddingFunction(
            api_key=os.getenv("OPENAI_API_KEY"),
            model_name="text-embedding-3-small"
        )
        self.collection = self.client.get_or_create_collection(
            name="memories", embedding_function=self.ef
        )
        self.importance_scorer = LLM()
        self.summarizer = LLM()

    def write(self, fact, metadata=None):
        """写记忆(带评分 + 摘要)"""
        # 1. 评分
        importance = self.importance_scorer.score(fact)
        if importance < 4:
            return   # 不重要

        # 2. 摘要
        summary = self.summarizer.summarize(fact)

        # 3. 写
        self.collection.add(
            documents=[summary],
            metadatas=[{
                "importance": importance,
                "ts": datetime.now().isoformat(),
                "category": metadata.get("category", "general") if metadata else "general",
                **(metadata or {}),
            }],
            ids=[f"mem_{int(time.time() * 1000)}_{random.randint(1000, 9999)}"]
        )

    def recall(self, query, k=5, min_importance=0):
        """按 query 检索"""
        results = self.collection.query(
            query_texts=[query],
            n_results=k * 2,   # 多取一些, 再过滤
        )
        # 按 importance 过滤
        filtered = []
        for doc, meta in zip(results["documents"][0], results["metadatas"][0]):
            if meta.get("importance", 0) >= min_importance:
                filtered.append({"text": doc, "meta": meta})
        return filtered[:k]

    def forget(self, doc_id):
        self.collection.delete(ids=[doc_id])

    def forget_expired(self, ttl_days=90):
        """清理过期"""
        cutoff = (datetime.now() - timedelta(days=ttl_days)).isoformat()
        results = self.collection.get(where={"ts": {"$lt": cutoff}})
        if results["ids"]:
            self.collection.delete(ids=results["ids"])

    def consolidate(self):
        """定期整理"""
        # 1. 找出相似的
        similar_pairs = find_similar_pairs(self.collection)
        # 2. 合并
        for pair in similar_pairs:
            merged = self.summarizer.merge(pair[0], pair[1])
            self.collection.add(documents=[merged], ids=[pair[0].id])
            self.collection.delete(ids=[pair[1].id])
```

### 46.2 在 Agent 中使用

```python
"""
agent_with_self_memory.py
"""
class SmartAgent:
    def __init__(self, llm):
        self.llm = llm
        self.short_term = []     # 当前会话
        self.long_term = SelfLongTermMemory()

    def run(self, user_message):
        # 1. 加短期
        self.short_term.append({"role": "user", "content": user_message})

        # 2. 检索长期
        recalled = self.long_term.recall(user_message, k=3)
        recalled_str = "\n".join(f"- {r['text']}" for r in recalled)

        # 3. 拼装 prompt
        system = f"你是助手。\n相关记忆:\n{recalled_str}"

        # 4. LLM 答
        answer = self.llm([
            {"role": "system", "content": system},
            *self.short_term[-10:],
        ])

        # 5. 加短期
        self.short_term.append({"role": "assistant", "content": answer})

        # 6. 写入长期
        self._maybe_write(user_message, answer)

        return answer

    def _maybe_write(self, user_msg, assistant_msg):
        turn = f"用户: {user_msg}\n助手: {assistant_msg}"
        self.long_term.write(turn, metadata={"category": "conversation"})

    def end_session(self):
        """会话结束, 整理"""
        # 把整个会话摘要
        summary = self.llm.summarize(str(self.short_term))
        self.long_term.write(f"[会话摘要] {summary}", metadata={"category": "session_summary"})
        self.short_term = []
```

## 47. 生产级记忆系统: 经验教训

### 47.1 不要无差别写所有

教训: 经验显示, 直接把所有对话写入长期记忆会让 prompt 充满噪声。
**经验**: 写前先评分。

### 47.2 检索时多轮过滤

教训: 简单相似度检索会带回噪声。
**经验**: 多轮: 相似度 → 重要性 → 时间 → 用户偏好。

### 47.3 跨用户隔离

教训: 一次多用户系统 bug, 用户 A 的偏好被给到了用户 B。
**经验**: 用户级 namespace 隔离。

### 47.4 隐私与合规

教训: GDPR / 中国《个人信息保护法》要求数据可删除。
**经验**: 提供 forget API + 数据导出 + 加密。

### 47.5 监控

教训: 没监控, 不知道记忆系统是否在工作。
**经验**: 监控召回率 + 用户反馈 + 漂移检测。

## 48. 配套论文精读

### 48.1 MemGPT(2023)

**核心想法**: 让 LLM 像 OS 管理内存一样管理自己的"上下文窗口"。

MemGPT 引入:
- 主上下文(CPU): 始终在 prompt 里。
- 外部上下文(磁盘): 需要时检索进来。
- 函数调用: LLM 自己决定"加载/卸载"信息。

### 48.2 Lost in the Middle(2023)

**结论**:
- LLM 对开头 / 结尾位置的信息关注度高。
- 中段(20%-80%) 信息往往被忽略。
- 长上下文评估时, 这个偏差显著。

工程对策: 关键信息放两端 + 摘要中间。

### 48.3 SAGE: 自演化图记忆(2024)

**核心思想**: 把记忆组织成图, 节点是事实, 边是关系。
随着事实增加, 图自动演化(合并相似节点、分裂矛盾节点)。

效果: 长程一致性更好(具体事件回忆率 +20-30%)。

## 57. 总结与回顾

### 57.1 完整代码示例: 一个生产级 Agent 的记忆系统

```python
"""
production_agent_memory.py
"""
class ProductionAgent:
    """
    综合:
    - 短期(上下文窗口)
    - 长期(向量库)
    - 上下文工程(动态拼装)
    - 隐私(用户隔离)
    - 评估(每步监控)
    """
    def __init__(self, llm, vector_store, user_id):
        self.llm = llm
        self.vector = vector_store.with_namespace(user_id)
        self.user_id = user_id
        self.short_term = ShortTermMemory(max_turns=10)
        self.metrics = MemoryMetrics()

    def run(self, user_message):
        # 1. 长期检索
        recalled = self._recall(user_message)

        # 2. 上下文拼装(关键信息两端)
        context = self._build_context(user_message, recalled)

        # 3. LLM 调用
        answer = self.llm(context)

        # 4. 更新短期
        self.short_term.add(user_message, answer)

        # 5. 评估 + 监控
        self.metrics.record(self.short_term, recalled, answer)

        # 6. 定期整理(后台)
        if random.random() < 0.01:   # 1% 概率
            self._consolidate_in_background()

        return answer

    def _recall(self, query, k=5):
        results = self.vector.search(query, k=k)
        self.metrics.record_recall(len(results))
        return results

    def _build_context(self, query, recalled):
        """最优上下文拼装"""
        # 顶部: 系统 + 用户身份 + 关键记忆
        top = [
            {"role": "system", "content": f"你是 {self.user_id} 的助手。"},
            {"role": "system", "content": f"相关记忆:\n" + "\n".join(r.text for r in recalled)},
        ]
        # 中段: 对话历史
        middle = self.short_term.get()
        # 底部: 当前问题
        bottom = [{"role": "user", "content": query}]
        return top + middle + bottom

    def _consolidate_in_background(self):
        # 整理老对话 → 摘要写入长期
        old_history = self.short_term.dump_old()
        if old_history:
            summary = llm.summarize(str(old_history))
            self.vector.add(summary, category="summary")
```

这是 2026 工业 Agent 记忆系统的模样。

# minimal_memory.py
class MinimalMemory:
    """教课用, 50 行"""
    def __init__(self):
        self.facts = []
        self.recent = []

    def add_fact(self, fact):
        # 加长期
        self.facts.append(fact)

    def add_recent(self, role, msg):
        # 加短期
        self.recent.append({"role": role, "content": msg})
        if len(self.recent) > 20:
            self.recent = self.recent[2:]   # 去掉最早一对

    def recall(self, query):
        # 简单相似度(关键词)
        return [f for f in self.facts if query.lower() in f.lower()][:3]

    def build(self, query):
        # 拼装
        recalled = self.recall(query)
        return (
            [{"role": "system", "content": f"相关: {recalled}"}]
            + self.recent[-10:]
            + [{"role": "user", "content": query}]
        )

$$R(f_\theta) \leq \hat{R}(f_\theta) + \sqrt{\frac{2 \log(2|\mathcal{F}|/\delta)}{N}}$$

其中 $\hat{R}$ 是经验风险,$\mathcal{F}$ 是假设空间。这告诉我们:**模型越复杂($|\mathcal{F}|$ 越大),泛化误差越大**。这就是奥卡姆剃刀的形式化。

**偏差-方差分解**:
$$\mathbb{E}[(y - f_\theta(x))^2] = \text{Bias}^2 + \text{Variance} + \sigma^2$$

模型复杂度低 → 高 Bias,低 Variance(欠拟合)。
模型复杂度高 → 低 Bias,高 Variance(过拟合)。
最优模型在两者之间。

$$I(X; Y) = H(Y) - H(Y|X) = \sum_{x, y} p(x, y) \log \frac{p(x|y)}{p(x)}$$

其中 $H$ 是熵,$H(Y|X)$ 是条件熵。互信息衡量知道 $X$ 后,$Y$ 的不确定性减少量。

**KL 散度**:
$$D_{KL}(p \| q) = \sum_x p(x) \log \frac{p(x)}{q(x)}$$

衡量分布 $p$ 与 $q$ 的距离,**不对称**,在交叉熵损失中出现。

$$H(p, q) = -\sum_x p(x) \log q(x) = H(p) + D_{KL}(p \| q)$$

是分类问题的标准损失。最小化交叉熵等价于最小化 KL 散度(因为 $H(p)$ 不依赖模型)。

最小化输入与表示的互信息(压缩),最大化表示与目标的互信息(预测)。这是表示学习的理论框架。

设输入为 $x \in \mathcal{X}$,输出为 $y \in \mathcal{Y}$。我们的目标是学习映射 $f_\theta: \mathcal{X} \to \mathcal{Y}$。

**优化目标**:
$$\theta^* = \arg\min_\theta \mathbb{E}_{(x, y) \sim \mathcal{D}}[\mathcal{L}(f_\theta(x), y)]$$

$$\theta^* = \arg\min_\theta \mathbb{E}[\mathcal{L}(f_\theta(x), y)] + \lambda \|\theta\|_p^p$$

其中 $p=1$ 是 Lasso, $p=2$ 是 Ridge。**L1 产生稀疏解**(特征选择),**L2 产生平滑解**(权重衰减)。

**泛化界**: 在概率 $1-\delta$ 下:
$$R(f_\theta) \leq \hat{R}(f_\theta) + \sqrt{\frac{2 \log(2|\mathcal{F}|/\delta)}{N}}$$

其中 $\hat{R}$ 是经验风险,$\mathcal{F}$ 是假设空间。这告诉我们:**模型越复杂($|\mathcal{F}|$ 越大),泛化误差越大**。这就是奥卡姆剃刀的形式化。

**偏差-方差分解**:
$$\mathbb{E}[(y - f_\theta(x))^2] = \text{Bias}^2 + \text{Variance} + \sigma^2$$

模型复杂度低 → 高 Bias,低 Variance(欠拟合)。
模型复杂度高 → 低 Bias,高 Variance(过拟合)。
最优模型在两者之间。

**4. 信息论视角**

**互信息**:
$$I(X; Y) = H(Y) - H(Y|X) = \sum_{x, y} p(x, y) \log \frac{p(x|y)}{p(x)}$$

其中 $H$ 是熵,$H(Y|X)$ 是条件熵。互信息衡量知道 $X$ 后,$Y$ 的不确定性减少量。

**KL 散度**:
$$D_{KL}(p \| q) = \sum_x p(x) \log \frac{p(x)}{q(x)}$$

衡量分布 $p$ 与 $q$ 的距离,**不对称**,在交叉熵损失中出现。

最小化输入与表示的互信息(压缩),最大化表示与目标的互信息(预测)。这是表示学习的理论框架。

模型复杂度低 → 高 Bias,低 Variance(欠拟合)。
模型复杂度高 → 低 Bias,高 Variance(过拟合)。
最优模型在两者之间。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。
