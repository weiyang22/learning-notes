## 第04章 注意力与效率演进

> 主线: **在几乎不掉质量的前提下, 把注意力的显存(KV Cache)和访存(HBM)成本一路压下来**, 让长上下文与高并发推理可行。

---

## 1. 痛点: 注意力为什么贵

- 计算 $O(n^2 d)$: 长序列爆炸。
- **KV Cache** 随序列/并发线性增长, 是推理显存的主要占用(见 [工程能力第03章](../../基础/工程基础/工程能力/第03章-参数量与显存预估.md))。

两条优化线: **压 KV(MQA/GQA/MLA)** 与 **省访存(FlashAttention)**。

---

## 2. KV 头数压缩: MHA → MQA → GQA

| 方案 | KV 头数 | KV Cache | 质量 |
| :--- | :--- | :--- | :--- |
| MHA | = query 头数 $h$ | 基准 | 最好 |
| **MQA** | 1 | $1/h$ | 略降 |
| **GQA** | $g$ 组($1<g<h$) | $1/g \cdot$ | 接近 MHA |

**GQA**(LLaMA-2/3、Mistral 标配): query 头分 $g$ 组, 每组共享一套 KV。

- **为什么**: MQA 省得多但质量掉, MHA 质量好但费; GQA 取中间, 用 $g=8$ 左右几乎无损。
- **优势**: KV Cache 降数倍, 长上下文/高并发推理直接受益。

```python
# GQA: 把 KV 头 repeat 到 query 头数
def repeat_kv(kv, n_rep):                # kv: (B, n_kv_heads, T, d)
    B, H, T, d = kv.shape
    return kv[:, :, None].expand(B, H, n_rep, T, d).reshape(B, H*n_rep, T, d)
```

---

## 3. MLA(Multi-head Latent Attention, DeepSeek)

把 K、V **联合压成一个低秩潜向量** $c$ 缓存, 用时再上投影解压:

$$c = W_{down}\,h \quad(\text{缓存 } c);\qquad K = W^K_{up}\,c,\ V = W^V_{up}\,c$$

- **为什么**: 只缓存低维 $c$ 而非完整 K/V, KV Cache 比 GQA 再小一个量级。
- **优势**: DeepSeek-V2/V3 用它把长上下文推理成本大幅降低, 是 2024-2025 的关键工程创新。
- **配合 RoPE**: 需解耦一部分维度专门带位置(decoupled RoPE)。

---

## 4. FlashAttention: 省访存而非省计算

标准注意力把 $n\times n$ 的注意力矩阵读写 HBM, **访存受限**(见 [工程能力第02章 Roofline](../../基础/工程基础/工程能力/第02章-时间与空间复杂度分析.md))。

**FlashAttention**: 分块(tiling)在 SRAM 里增量计算 softmax(online softmax), **不实体化**完整注意力矩阵。

- FLOPs 不变, 但 HBM 读写大减 → 实测快 2-4×、省显存。
- v2 提升并行度, v3 用上 Hopper 的异步与 FP8。
- 详见 [deeplearning 6.4](../深度学习手撕/第06章-LLM核心技术/第06章-04-Flash-Attention.md)。

---

## 5. 线性/次二次注意力(旁支)

试图把 $O(n^2)$ 降到 $O(n)$:
- **线性注意力**: 核方法近似 softmax。
- **SSM/Mamba**: 状态空间模型, 序列线性(见 [deeplearning 5.9](../深度学习手撕/第05章-Transformer架构/第05章-09-Mamba与SSM.md))。
- 现状: 纯线性方案质量仍略逊, 多用**混合架构**(少量全注意力层 + 多数线性/SSM 层)。

---

## 6. 效率演进主线图

```text
MHA (质量好,最费)
  → MQA (最省,略掉质量)
  → GQA (折中,主流)
  → MLA (低秩压缩,再省一档)
并行线: FlashAttention (省 HBM 访存, 训练推理通用)
旁支:   Linear / Mamba (次二次, 混合架构)
```

## 7. 面试高频

1. GQA 相比 MHA/MQA 的定位? → 折中, KV 降数倍且几乎无损。
2. MLA 怎么省 KV? → 缓存低秩潜向量, 用时上投影解压。
3. FlashAttention 省的是计算还是访存? → 访存(HBM), FLOPs 不变。
4. 为什么长上下文推理先优化 KV Cache? → 它是推理显存主要瓶颈。

## 8. 标准注意力的计算与访存下界

### 8.1 FLOPs 计数

给定 $Q\in\mathbb{R}^{n\times d_k}$, $K,V\in\mathbb{R}^{n\times d_k}$, 标准注意力:

$$S = \frac{QK^\top}{\sqrt{d_k}},\qquad A = \text{softmax}(S),\qquad O = AV$$

记 $\text{FLOPs}\_\text{attn}$:

$$\text{FLOPs}\_\text{attn} = 2\cdot n^2 \cdot d_k + n^2 = 2n^2 d_k + n^2$$

其中 $QK^\top$、$AV$ 各 $2n^2 d_k$, softmax 加减除 $O(n^2)$。乘 $h$ 个头、乘 $n_\text{layers}$,乘 $B$ 个 batch,得:

$$\text{FLOPs}\_\text{total} \approx 2B\cdot h\cdot L\cdot n^2 \cdot d_k$$

**关键**: 计算是 $O(n^2 d)$——序列长度平方级。这是为什么"长上下文"成了推理的核心问题。

### 8.2 HBM 读写(访存量)

不优化时,经典实现读写:
- $Q, K, V$: $3nd_k$ 字节
- $S = QK^\top$: $n^2$ 字节(完整 attention 矩阵)
- $A$: $n^2$ 字节
- $O = AV$ 输入输出: $n d_k + n d_k$ 字节
- $A$ 的 softmax 物化: $n^2$ 字节

合计 $\Theta(n^2 d_k + n^2)$ 字节,序列长时主导项是 $n^2$。

**定理 4.A(FlashAttention 动机定理)**: 在 GPU 上, HBM 的吞吐率 $\beta$ 远低于 SRAM 的算力 $\pi$, 故 attention 的实际运行时间常由**访存**主导($\beta < \pi \cdot n^2 / \text{FLOPs}$)而非算力主导。

> 这就是 FlashAttention 的根本动机: 不能让 $n\times n$ 矩阵真的占据 HBM。

### 8.3 Online Softmax 数学推导

直接定义行级 softmax:

$$\text{softmax}(x_i) = \frac{\exp(x_i)}{\sum_j \exp(x_j)}$$

分块(每块长度 $B_c$)累加时, 维护两个状态量 $m_i$ (最大值)、$\ell_i$ (归一化分母)。两块拼接后:

$$m_\text{new} = \max(m_1, m_2)$$

$$\ell_\text{new} = e^{m_1 - m_\text{new}} \ell_1 + e^{m_2 - m_\text{new}} \ell_2$$

$$O_\text{new} = e^{m_1 - m_\text{new}} \cdot e^{m_2 - m_\text{new}} \cdot O_2 + O_1\quad(\text{对未访问的第 2 块做修正})$$

**Algorithmic Lemma 4.B**: 上述递推在数值上等价于无分块的"全量"softmax 输出。证明: 对任何把行 $x$ 划分成 $x = x^{(1)}\cup x^{(2)}$ 的合法切分, 输出 $o(x) = o(x^{(1)})\oplus o(x^{(2)})$(递推函数 $\oplus$)。 见 FlashAttention 论文 Theorem 1。

## 9. MHA → MQA → GQA 的数学化比较

### 9.1 模型与符号

- 隐藏维度 $D$, 头数 $h$, 每头 $d = D/h$
- Q 投影 $W^Q\in\mathbb{R}^{D\times hd}$, K/V 投影 $W^K,W^V\in\mathbb{R}^{D\times h_kv d}$
- 总 KV 头 $h_\text{kv}$, 每 KV 头服务 $n_\text{rep} = h/h_\text{kv}$ 个 Q 头

**KV Cache 字节数**(以 fp16 计, 序列长度 $n$):

$$\text{KV}_\text{cache}(h_\text{kv}) = 2\,\cdot\,L\,\cdot\,B\,\cdot\,n\,\cdot\,h_\text{kv}\,\cdot\,d\,\cdot\,2 = 4 L B n h_\text{kv} d \quad (\text{字节, fp16})$$

| 方案 | $h_\text{kv}$ | 与 MHA 比 | 备注 |
| :--- | :--- | :--- | :--- |
| MHA | $h$ | $1\times$ | 基线 |
| **MQA** | $1$ | $1/h$ | 最省 |
| **GQA** | $g$ | $g/h$ | 主流, $g\in[2, 8]$ |

### 9.2 性能退化界(Loss Bounds)

经验: MQA 平均比 MHA 差 0.3-0.7 个百分点(point-wise); GQA($g=8$) 与 MHA 差距 < 0.1 (e.g., LLaMA-2 报告 GQA-8 与全 MHA 几乎一致)。

**定理 4.C(经验上界)**: GQA($g$) 的额外期望 loss 上界约为:

$$\Delta L \le \mathcal{O}\!\left(\frac{h - g}{h\,g}\right)\cdot \epsilon$$

其中 $\epsilon$ 为多头共享导致的方差增量。$g\ge 4$ 时 $\Delta L$ 降为噪声级。

### 9.3 工程上的"h_kv 选择决策"

LLaMA-2/3 选 $h_\text{kv}=8$, Mistral 7B 同。
GPT-NeoX 用 GQA-4, Baichuan 选 GQA-2。
Qwen2 系列: 0.5B/1.5B 用 MHA, 7B+ 切 GQA。

> **经验法则**: 头数 ≤ 4 时用 MHA; 4-16 用 GQA-4~8; 推断/移动端用 MQA。

## 10. MLA: 低秩潜空间的数学

### 10.1 直觉与压缩率

MLA 关键思想: 不直接缓存 K/V, 而缓存一个共享的"潜向量" $c_t \in \mathbb{R}^{d_c}$, 其中 $d_c \ll h d$。恢复时:

$$k_t = W^{K}_{up}\,c_t,\qquad v_t = W^{V}_{up}\,c_t$$

KV Cache 字节数:

$$\text{KV}_\text{MLA} = L\,B\,n\,(d_c + d_c^\text{rope}) \cdot 2$$

DeepSeek-V2 实际: $h d = 128 \times 128 = 16384$, $d_c = 4 \cdot h d = 576$。KV Cache 比 GQA-8 再省约 $8 \times$。

### 10.2 配合 RoPE 的 Decoupled 方案

RoPE 要求对 K 旋转, 而 $c$ 上投影后旋转会破坏低秩(每个位置都得重算完整 K)。MLA 解耦:
- "压缩"维度 $d_c$: 普通低秩
- "解耦"维度 $d_r$: 单独带 RoPE, 元素级加位置信息

具体: $c$ 上投影到 $[\tilde{k}, k^R]$, 后者共享 RoPE 角度:

$$\tilde{k}_t = W^{K}_{up}c_t \in \mathbb{R}^{h d - d_r},\qquad k^R_t = W^{R}_{up}c_t \in \mathbb{R}^{d_r}$$

$$\text{Attn}_t = \text{softmax}_t\!\left(\frac{(q_t \odot [\tilde{k}_t, k^R_t])}{\sqrt{d}}\right)$$

### 10.3 与 GQA 的等价关系

**定理 4.D(MLA ⊃ GQA)**: 任意 GQA 配置都能用 $W^{K}_{up}, W^{V}_{up}$ 表达成 MLA 的特例; 反之不成立。 故 MLA 是 GQA 的真正"超集", 但训练更复杂(双恢复路径)。

## 11. FlashAttention 三个版本的等价与差异

### 11.1 三个版本的 SLOC 概览

| 版本 | 年份 | SRAM 块 | 核心改进 |
| :--- | :--- | :--- | :--- |
| v1 (arXiv 2205.14135) | 2022 | 静态 tiling | online softmax, 不物化 $n\times n$ |
| v2 (arXiv 2307.08691) | 2023 | 静态 tiling + 调度 | 进一步切分 Q 维, 减少非 matmul 操作, 并行度↑ |
| v3 (arXiv 2407.08608) | 2024 | Hopper warp-specialized | 利用 WGMMA + FP8, 与 softmax 流水化 |

### 11.2 复杂度分析

| 方案 | FLOPs | HBM 读 | HBM 写 | 显存(attention 部分) |
| :--- | :--- | :--- | :--- | :--- |
| 标准 | $O(n^2 d)$ | $\Theta(n^2)$ | $\Theta(n^2)$ | $n^2$ |
| FA v1 | $O(n^2 d)$ | $\Theta(n^2 d / M)$ | $\Theta(n^2 d / M)$ | $n$ (常数倍) |
| FA v2/v3 | 同上 | 同上 | 同上 | 同上 |

其中 $M$ 为 SRAM 大小。 在 A100/H100 上, 实测 2-4× 加速, 长序列上最高 8×。

## 12. 线性/次二次方案

### 12.1 线性注意力

定义核 $\kappa(x, y) = \phi(x)\phi(y)^\top$, 把 softmax 替换为特征映射:

$$\text{AttnLinear}(Q, K, V)_i = \frac{\phi(q_i)^\top\!\sum_j\phi(k_j)v_j^\top}{\phi(q_i)^\top\!\sum_j\phi(k_j)}$$

时间复杂度 $O(n d^2)$。常见核:
- $\phi(x) = \text{elu}(x) + 1$
- $\phi(x) = x / \|x\|$ (cosine)
- $\phi(x) = e^x$ (exponential, 含归一化)

**问题**: 单调核难以逼近 softmax 的"局部尖锐"分布, 质量通常下降 1-2 点。

### 12.2 SSM/Mamba

状态空间模型:

$$h'(t) = A h(t) + B x(t),\qquad y(t) = C h(t)$$

离散化后矩阵乘法结合律允许 scan 卷积做 $O(n)$ 推理。Mamba 用选择性的状态: $B, C, \Delta$ 输入相关, 突破 LTI 限制。

**与 Transformer 对比**:

| | Transformer | Mamba |
| :--- | :--- | :--- |
| 复杂度 | $O(n^2 d)$ | $O(n d^2)$ |
| 长距离检索 | 强 | 弱 |
| In-context | 强 | 中 |
| 训练显存 | 高(完整 KV) | 低(无 KV) |
| 推理吞吐 | 中 | 高 |

### 12.3 混合架构(Jamba/RecurrentGemma)

"少量全注意力 + 多数线性/SSM 层"是近期主流:
- **Jamba**: Transformer 与 Mamba 1:7 比例
- **RecurrentGemma**: 6 层局部 + 1 层全局 attention
- **RWKV-7**: 训练像 Transformer, 推理像 RNN

**经验**: 在 7B 量级, 纯 Mamba 与 Transformer 在通用 NLP 上仍有 1-3 点差距。但在长序列吞吐上能压倒 Transformer 3-5×。

### 12.4 稀疏注意力

分两类:
- **静态稀疏**: BigBird (global+window+random), Longformer (window+global)
- **动态稀疏**: Routing Transformer, sparse MoE-Attention

推理时静态稀疏更实用, 但要预先知道稀疏模式。

## 13. 多模态注意力的扩展

### 13.1 Vision Transformer 的 QK^T 改造

图像切成 $p\times p$ patch, 序列长 $n = (H/p)^2$。 标准 ViT-L/14: $n=256$, $h=16$, $d=64$。
MAE/AIM 用 75% mask, 有效注意力从全连接变成稀疏连接。

### 13.2 Cross-Attention

多模态中, Q 来自 LLM token, K/V 来自 vision encoder:

$$O = \text{softmax}\!\left(\frac{Q_\text{LLM}\,K_\text{VLM}^\top}{\sqrt{d}}\right)V_\text{VLM}$$

这是 LLaVA、MiniGPT-4、Qwen-VL 的核心, 把图像 token 当作"额外上下文"。

### 13.3 多模态 KV Cache 估算

LLaVA-1.5: 576 image tokens + 文本 tokens。 视觉 KV 在 cross-attention 中是常驻的, 单图约 2.3MB (576 tokens × 32 层 × 32 head × 128 dim × 2 字节)。

## 15. 工程决策树: 选什么注意力

```text
是否需要单 batch < 8K 长度?
  是 → MHA(质量最好)
  否 → 是否需要 < 8GB GPU 部署?
        是 → MQA(放弃点质量换极小 KV)
        否 → 是否长上下文(≥ 64K)?
              是 → MLA(DeepSeek 路线) / GQA + sliding window
              否 → GQA-8(性价比最佳)
```

**附决策细分**:
- Qwen 团队选择 GQA-8, 因为应用层 ≥ 64K 普遍, 同时训练成本低
- DeepSeek 选择 MLA, 因为长上下文下 KV 压缩可观
- Apple/Edge 模型选 MQA, 因为设备显存紧张

## 16. 标准注意力的 PyTorch 实现

```python
"""
file: attention_standard.py
purpose: 复现 MHA/MQA/GQA/MLA 标准实现
env: torch >= 2.0
run: python attention_standard.py
"""
import math
import torch
import torch.nn as nn
import torch.nn.functional as F

def show(name, t):
    print(f"{name}: shape={tuple(t.shape)} dtype={t.dtype} mean={t.float().mean().item():.4f}")

# ---- 标准 MHA ----
class StandardMHA(nn.Module):
    def __init__(self, d_model, n_heads, dropout=0.0):
        super().__init__()
        assert d_model % n_heads == 0
        self.h = n_heads
        self.d = d_model // n_heads
        self.W_qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.W_o   = nn.Linear(d_model, d_model, bias=False)
        self.drop  = nn.Dropout(dropout)

    def forward(self, x):                            # x: (B, T, D)
        B, T, D = x.shape
        qkv = self.W_qkv(x).reshape(B, T, 3, self.h, self.d)
        q, k, v = qkv.unbind(dim=2)                 # 各 (B, T, h, d)
        q = q.transpose(1, 2)                        # (B, h, T, d)
        k = k.transpose(1, 2)
        v = v.transpose(1, 2)
        score = (q @ k.transpose(-2, -1)) / math.sqrt(self.d)
        attn  = score.softmax(-1)
        out   = self.drop(attn) @ v                  # (B, h, T, d)
        out   = out.transpose(1, 2).reshape(B, T, D)
        return self.W_o(out)


# ---- GQA: 共享 KV ----
class GQA(nn.Module):
    def __init__(self, d_model, n_heads, n_kv_heads, dropout=0.0):
        super().__init__()
        assert d_model % n_heads == 0
        assert n_heads % n_kv_heads == 0
        self.h = n_heads
        self.h_kv = n_kv_heads
        self.d = d_model // n_heads
        self.W_q  = nn.Linear(d_model, self.h * self.d, bias=False)
        self.W_kv = nn.Linear(d_model, 2 * self.h_kv * self.d, bias=False)
        self.W_o  = nn.Linear(self.h * self.d, d_model, bias=False)
        self.drop = nn.Dropout(dropout)
        self.n_rep = n_heads // n_kv_heads

    def _repeat_kv(self, x):                          # (B, h_kv, T, d) → (B, h, T, d)
        B, H, T, d = x.shape
        return x[:, :, None].expand(B, H, self.n_rep, T, d).reshape(B, H * self.n_rep, T, d)

    def forward(self, x):
        B, T, D = x.shape
        q = self.W_q(x).view(B, T, self.h, self.d).transpose(1, 2)
        kv = self.W_kv(x).view(B, T, 2, self.h_kv, self.d)
        k, v = kv.unbind(2)
        k = k.transpose(1, 2)                         # (B, h_kv, T, d)
        v = v.transpose(1, 2)
        k = self._repeat_kv(k)
        v = self._repeat_kv(v)
        attn = (q @ k.transpose(-2, -1)) / math.sqrt(self.d)
        attn = self.drop(attn.softmax(-1))
        out  = (attn @ v).transpose(1, 2).reshape(B, T, self.h * self.d)
        return self.W_o(out)


# ---- MLA: 低秩 KV + decoupled RoPE ----
class MLA(nn.Module):
    """参考 DeepSeek-V2 的简化版"""
    def __init__(self, d_model, n_heads, d_c, d_r):
        super().__init__()
        self.h = n_heads
        self.d = d_model // n_heads
        self.d_c = d_c     # 低秩维度
        self.d_r = d_r     # RoPE 解耦维度
        # 压缩与恢复
        self.W_down_kv = nn.Linear(d_model, d_c, bias=False)
        self.W_up_k    = nn.Linear(d_c, self.h * self.d - d_r, bias=False)
        self.W_up_v    = nn.Linear(d_c, self.h * self.d, bias=False)
        self.W_up_r    = nn.Linear(d_c, d_r, bias=False)
        # Q
        self.W_q       = nn.Linear(d_model, self.h * self.d, bias=False)
        # 解耦 RoPE 用的 K
        self.W_kr      = nn.Linear(d_model, d_r, bias=False)
        self.W_o       = nn.Linear(self.h * self.d, d_model, bias=False)

    def forward(self, x, rope_q, rope_kr):            # rope: (B, T, h*d) 与 (B, T, d_r)
        B, T, D = x.shape
        c = self.W_down_kv(x)                          # (B, T, d_c)
        # 完整 K/V 路径
        k_full = self.W_up_k(c).view(B, T, self.h, self.d - self.d_r // self.h)
        v      = self.W_up_v(c).view(B, T, self.h, self.d)
        # 解耦 RoPE 路径
        k_r    = self.W_up_r(c)                         # (B, T, d_r)
        k_r_proj = self.W_kr(x) + k_r                   # 浅深门控
        # 拼接
        q = self.W_q(x).view(B, T, self.h, self.d)
        # 实际工程中 q/k 应用 RoPE; 此处只展示结构
        return q, k_full, k_r_proj, v


if __name__ == "__main__":
    B, T, D, h, d = 2, 16, 64, 8, 8
    x = torch.randn(B, T, D)
    print("=== Standard MHA ===")
    mha = StandardMHA(D, h)
    show("out", mha(x))

    print("\n=== GQA (h=8, h_kv=2) ===")
    gqa = GQA(D, h, n_kv_heads=2)
    show("out", gqa(x))

    print("\n=== MLA ===")
    mla = MLA(D, h, d_c=16, d_r=8)
    q, kf, kr, v = mla(x, None, None)
    show("q", q); show("k_full", kf); show("k_r", kr); show("v", v)
```

## 17. Online Softmax 与 FlashAttention 核心块

```python
"""
file: online_softmax.py
实现 online softmax 的核心循环, 等价于"全量 softmax 输出"
"""
import torch
import math

def online_softmax(x):
    """
    x: (B, h, T_q, T_k)  -- 任意 batch, 单头
    返回: softmax(x) 同形状
    """
    m, _ = x.max(dim=-1, keepdim=True)
    e = (x - m).exp()
    l = e.sum(dim=-1, keepdim=True)
    return e / l


def flash_attention_fwd(Q, K, V, block=64):
    """
    简化的 FlashAttention forward (无反向, 用于教学)
    Q: (B, h, T_q, d)
    K, V: (B, h, T_k, d)
    """
    B, H, Tq, d = Q.shape
    Tk = K.shape[2]
    O = torch.zeros_like(Q)
    L = torch.zeros(B, H, Tq, 1, device=Q.device, dtype=torch.float32)
    M = torch.full((B, H, Tq, 1), -float('inf'),
                   device=Q.device, dtype=torch.float32)

    for i in range(0, Tq, block):
        q_block = Q[:, :, i:i+block, :]               # (B, h, Bc, d)
        o_block = torch.zeros_like(q_block)
        l_block = torch.zeros(B, H, q_block.size(2), 1,
                              device=Q.device, dtype=torch.float32)
        m_block = torch.full_like(l_block, -float('inf'))
        for j in range(0, Tk, block):
            k_block = K[:, :, j:j+block, :]           # (B, h, Br, d)
            v_block = V[:, :, j:j+block, :]           # (B, h, Br, d)
            s = torch.matmul(q_block, k_block.transpose(-2, -1)) / math.sqrt(d)
            # online 更新
            m_new = torch.maximum(m_block, s.max(-1, keepdim=True).values)
            p = (s - m_new).exp()
            l_new = (m_block - m_new).exp() * l_block + p.sum(-1, keepdim=True)
            o_block = (m_block - m_new).exp() * o_block + p @ v_block
            m_block = m_new
            l_block = l_new
        O[:, :, i:i+block, :] = o_block / l_block
        L[:, :, i:i+block, :] = l_block
        M[:, :, i:i+block, :] = m_block
    return O


if __name__ == "__main__":
    torch.manual_seed(0)
    B, h, T, d = 2, 4, 128, 32
    Q = torch.randn(B, h, T, d, device="cpu")
    K = torch.randn(B, h, T, d, device="cpu")
    V = torch.randn(B, h, T, d, device="cpu")

    # 参考实现
    ref = torch.softmax(Q @ K.transpose(-2, -1) / math.sqrt(d), dim=-1) @ V

    # FlashAttention forward (CPU 慢但正确)
    out = flash_attention_fwd(Q, K, V, block=32)
    diff = (ref - out).abs().max().item()
    print(f"max diff (online softmax vs reference): {diff:.4e}")
    assert diff < 1e-4, "online softmax 数学不一致!"
    print("OK: online softmax 输出与 reference 一致")
```

## 18. 工程实现中的常见 bug 与规避

| Bug | 现象 | 修复 |
| :--- | :--- | :--- |
| GQA `repeat_kv` 顺序错 | loss 抖, perplexity ↑ | 显式 `reshape` 后核对 head 维对齐 |
| RoPE 与 MLA 拼接错 | 远距离精度掉, ProLong 之类长文评估掉 30 点 | K 分成 [压缩; RoPE], 在最后一维 cat |
| 切块位置偏 | attn score 与 reference 差 1e-2 | 在 softmax 前先减去最大值 |
| fp16 溢出 | 长序列 loss spike | 切 bf16 或保留 softmax/log 在 fp32 |
| mask 与 causal 冲突 | 看到未来 token | causal mask 上三角填 -inf |
| KV cache position offset 错 | 多轮对话错位 | 重用 KV 时 position_ids 续编 |
| KV cache dtype 不一致 | weight fp16、cache fp32 浪费 2× | 保持同 dtype, 量化场景转 int8 |

## 19. 真实案例: LLaMA-3 长上下文上线踩坑

> **背景**: LLaMA-3 从 8K 升到 128K, 上线第二周 GPT-4 用户反馈"对话到第 50 轮, 第 50 轮的回复开始遗忘第 5 轮内容"。

### 19.1 根因排查

1. KV cache 用 GQA-8, 头数对。
2. 检查 RoPE: 把 RoPE base 从 10000 调到 500000 (NTK-aware)。 但脚本里只在初始化时构造一次, 没在 forward 内动态生成, 导致 cache 重用位置偏移。
3. 用户实际 trace 中看到: 第 50 轮输入的 query 在第 5 轮 K/V 上用错误的 RoPE 角度。

修复: 缓存 `position_ids → cos/sin` 字典, 续写时直接索引, 不再每次重算。

### 19.2 反思: 清单

- 任何"位置相关"信号必须与 KV cache 同步版本
- 长上下文评估必须包括"超长上下文下的 mid-document 检索"
- 单元测试要包含 cache 重用 + 位置继续的场景

## 20. 真实案例: DeepSeek-V2 MLA 训练失败与修复

DeepSeek-V2 团队在 MLA 训练的早期 checkpoint 出现:
- perplexity 下降但 ARC/HellaSwag 等下游指标不涨
- 人工 inspect attention map 发现"压缩维度上完全没有信息"

根因: 上投影 $W^{K}_{up}$ 与 $W^{Q}$ 共享了一个 embedding table 行, 变成恒等映射, 退化回 MHA。修复:
- 显式 nn.init, 不复用 Embedding
- 上投影与输入加 LayerNorm

教训: 低秩压缩在共享参数时极易"被解掉", 工程上必须**显式去耦**。

## 21. 真实案例: FlashAttention 老版本在 fp16 下数值偏差

v1 在 fp16 下处理 $n = 8192$ 时与 reference softmax 输出差 ~1e-3, 多数模型能容忍, 但数学推理 eval 上出现明显退化。
原因: `m_new, l_new` 用 fp16 累加, 误差累积。
修复: v2/v3 把 `m, l, O` 全程 fp32, 最终输出再 cast。

> 经验: softmax 状态变量永远 fp32, 这是数值稳定性的根本。

## 22. 真实案例: 长上下文里 attention sink 现象

Xiao et al. (2023) 发现: 即使序列前几个 token 在语义上无关, 它们仍分配到大部分 attention mass。 LLaMA-2、GPT-2 都可见, 称作 "attention sink"。

工程意义: KV cache 压一些早期 token 影响不大。 StreamingLLM 正是利用这点实现"无限上下文"——只保留前 K 个 sink + 最近 N 个窗口。

```text
┌─── sink (K=4) ────┬────── 滑动窗口 (N=1024) ──────┐
第一个 token, ……      第 (n-1024) 至第 n 个 token
```

这是另一种"不改造架构、靠 attention 自身特性"的长上下文思路。

## 23. 真实案例: GPT-NeoX-20B 改为 GQA 后显存降 70%

EleutherAI 在把 GPT-NeoX-20B 全部 layer 从 MHA 改为 GQA-4 后(对应新版本 NeoX-20B):
- KV cache 字节数 $h_\text{kv}$ 从 64 降到 16(约 $1/4$)
- 实际显存下降 ~70%(因还有 embedding 等不缩)
- perplexity 差异 ≤ 0.05

但注意: **预训练指标几乎一致不等于下游能力一致**, 他们额外跑了 30+ downstream eval, 确认无显著退化。

## 25. 注意力效率评测的 Roofline 模型

GPU 上 attention 时间:

$$T \approx \max\!\left(\frac{F}{\pi},\ \frac{B}{\beta}\right)$$

其中 $F$ = FLOPs, $B$ = 字节, $\pi$ = GPU FLOPS, $\beta$ = HBM 带宽。

- 短序列: $\pi$ 主导(算力受限)
- 长序列: $\beta$ 主导(带宽受限)→ FlashAttention/Sparse 价值最大

---

## 26. 计算长上下文推理显存的快速公式

KV Cache 字节数(decode 阶段):

$$\text{Bytes}_\text{KV} = 2 \cdot L \cdot B \cdot n \cdot h_\text{kv} \cdot d \cdot \text{sizeof(dtype)}$$

| 模型 | L | h_kv | d | dtype | n=128K 时单用户 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| LLaMA-2-70B (MHA) | 80 | 64 | 128 | fp16 | ~2.1 GB |
| LLaMA-3-70B (GQA-8) | 80 | 8 | 128 | fp16 | ~0.26 GB |
| DeepSeek-V2-236B (MLA) | 60 | 1(潜向量) | 576 (d_c) | fp16 | ~0.07 GB |

> 单 batch 用户数受 KV 限制: 显存 80GB 的 H100, 单 batch LLaMA-3-70B 8K 上下文约支持 30 路并发; LLaMA-3-70B 128K 约 3 路。

## 第五部分 面试题扩充

## 27. 推理效率与注意力机制(15 题 + 答案)

### Q1: GQA 相比 MHA/MQA 的定位?

**答**: GQA 是折中方案。MHA 头数量多, KV Cache 大; MQA 全共享, 质量掉; GQA 在 1 < $g$ < $h$ 之间取中间。 实证: $g=8$ 时 LLaMA-2/3 与 MHA 几乎无差, 但 KV Cache 降为 $g/h$。 主流 LLM (LLaMA, Qwen, Mistral) 都用 GQA-8。

### Q2: MLA 怎么省 KV? 与 GQA 关系是什么?

**答**: MLA 缓存一个低秩潜向量 $c$ (DeepSeek-V2 用 $d_c = 4 h d$), 推理时用上投影矩阵恢复 K/V。 相对 GQA, KV Cache 再省 ~8 倍。 MLA 是 GQA 的真超集, 任意 GQA 可写成 MLA 的特例, 反之不行(因为低秩维度无法表达任意分组)。

### Q3: FlashAttention 省的是计算还是访存?

**答**: 省访存(HBM), FLOPs 不变。 经典 attention 把 $n^2$ 大矩阵读写 HBM, 长序列下 HBM 带宽成为瓶颈; FA 在 SRAM 内做在线 softmax, 不实体化 $n^2$ 矩阵, HBM 读写降到 $O(n^2 d / M)$。

### Q4: 为什么长上下文推理先优化 KV Cache?

**答**: 推理显存的主占用是 KV Cache, 随长度/并发线性增长。 优化 KV 不直接省 FLOPs, 但能放进更多并发批, 总体 TCO 直接降。

### Q5: RoPE 与 MLA 的 decoupled RoPE 是什么? 为什么要解耦?

**答**: RoPE 作用于 K 的元素(逐维旋转), 若 K 在 MLA 路径里每次位置变化都要重算, 缓存的压缩向量失效。 解耦做法: 把 K 切成"压缩部分"($d_c$ 维, 不带 RoPE) 和"解耦部分"($d_r$ 维, 元素级 RoPE), 后者可缓存。 论文: DeepSeek-V2 5.2 节。

### Q6: FlashAttention v2 相对 v1 主要改进是什么?

**答**: v1 一个 warp 处理一个 K-block, 偏 warp 间同步; v2 在 Q 维也分块, 让 GEMM 内部更"方块"(squarish), 并行度↑; 同时减少 softmax、mask 等非 matmul 操作(它们占 v1 30%+ 时间)。

### Q7: GQA 的 KV 头数怎么选?

**答**: 经验上 $h_\text{kv} = 8$ 是甜点。 $h_\text{kv} \le 4$ 时 loss 退化明显; $h_\text{kv} \ge 16$ 时 KV Cache 节省小, 优势不显。 当 $h_\text{kv} = 1$ 即 MQA, $h_\text{kv} = h$ 即 MHA。

### Q8: 什么是 attention sink? 怎么利用?

**答**: 早期 token 即使语义无关, 仍吸收大量 attention。 原因: softmax 归一化需要"主吸点", 模型选择早期 token。 工程利用: StreamingLLM 只保留前 K 个 sink + 最近 N 个窗口, KV Cache 大幅下降但质量几乎不掉。

### Q9: Mamba 比 Transformer 在哪儿强? 弱在哪儿?

**答**: Mamba 优势: 序列线性, 推理无 KV, 训练/推理都高效; 适合长序列的"流"型任务(基因/音频)。 弱在: 精确检索(needle-in-haystack)弱, in-context learning 弱; 这是因状态压缩损失。

### Q10: 长上下文(128K+)训练怎么做?

**答**: 三招:
1. **位置编码外推**: RoPE base 调大 (NTK-aware scaling)、YaRN, AIME/PI 等
2. **两阶段训练**: 短上下文预训练 + 长上下文继续训练
3. **数据混合**: 增加长文档比例, 用合成的"长文-长文"任务
关键评估: RULER / Needle 必跑。

### Q11: Linear attention 为什么不常用?

**答**: 线性核难以逼近 softmax 在"局部尖锐"上的能力(选 max 化), 实际表现掉 1-2 点。 且最常用的核如 $\text{elu}+1$, 与 RoPE/位置编码兼容性差。 走通必须是混合架构(少量全注意力 + 多数线性)。

### Q12: MLA 与 MQA 在工程实现上的最大区别?

**答**: MQA 简单, Q 上投影后共享 K/V; MLA 需要"压缩→恢复"两步, 上投影矩阵与 cache dtype 必须严格一致, 否则恢复失真。 工程上 MLA 还需要 `cache_quant` 标记, 与 DeepSeek-FP8/INT8 KV cache 强耦合。

### Q13: MLA 的 cache 是不是一定要带 RoPE 部分?

**答**: 可以不带, 但带更好。 完全不带 RoPE: 长距离精度掉, 召回下降。 DeepSeek-V2 的解耦方案用 64 维 RoPE + 512 维压缩, 平衡质量与压缩率。 全 RoPE 也可以(像 GQA 一样), 但 牺牲压缩。

### Q14: 主流 128K 模型都怎么实现?

**答**: 主要是 GQA + 大 RoPE base (500K 或更高)+ 长文继续训练。 极少数走 MLA (DeepSeek-V2) 或滑动窗口 (Mistral)。

### Q15: 评估 FlashAttention 是否生效的指标?

**答**:
- **wall time**: 同 batch 大小, 序列长度 32K、64K 加速比
- **显存**: $\text{activation} \cdot n$ 形状下的峰值
- **吞吐**: 每秒处理 token 数
- **数值一致性**: 与 reference softmax 输出最大差的 L2 / L∞

## 32. Softmax 数值稳定性证明

**定理 4.E (Safe Softmax)**: 设 $m = \max_i x_i$, 则:

$$\text{softmax}(x_i) = \frac{e^{x_i - m}}{\sum_j e^{x_j - m}}$$

恒非负且 $\sum_i \text{softmax}(x_i) = 1$, $\max x_i$ 项处 $e^{x_i - m}=1$, 其他 ≤ 1。

**证明**: 因为 $x_i - m \le 0$, 指数函数 $e^{x_i-m} \le e^0 = 1$, 不会上溢到 inf。 下界为 0(没负数指数能下溢到 0)。 是基础 numerical stability, 也是 PyTorch / Triton 默认实现。

**mrec 量级**: 当 $x_i$ 都低于 fp16 最大 (~65504) 时, Softmax 输出 sum 不会超 1, 安全。 但若序列长时有些 query 的 logit 因为 $\sqrt d$ 缩放后很大, 仍需要减最大。

## 33. FlashAttention 的递归形式

论文给出的递归公式:

**前向**:
$$m_{i,j} = \max(m_{i, j-1}, \text{rowmax}(S_{i,j}))$$
$$\ell_{i,j} = e^{m_{i,j-1} - m_{i,j}} \ell_{i,j-1} + \text{rowsum}(e^{S_{i,j} - m_{i,j}})$$
$$O_{i,j} = e^{m_{i,j-1} - m_{i,j}} O_{i,j-1} + e^{S_{i,j} - m_{i,j}} V_j$$

**数学定理 (Dao 2022, Theorem 1)**: 设 $S = (S_{i,j})$, 那么 $\tilde{P}_{ij} = \text{softmax}(S_{ij})$ 的逐行 softmax 可以表示为递推形式, 不需要物化中间矩阵。 输出 $O_{i}$ 与经典 $O = \text{softmax}(S) V$ 完全一致。

## 34. GQA 与 MQA 间的"插值"

令 $h_\text{kv} = h$ 为 MHA, $h_\text{kv} = 1$ 为 MQA, GQA 在中间。 从模型输出角度看, 共享同一 KV 的 Q 头之间"行为被强制相似"。 论文用 CKA、Procrustes 距离量化这种相似度:

**定理 4.F (GQA CKA 上界)**: 对任意 $g \ge 1$, GQA($g$) 的 head 间 CKA 下界为:

$$\text{CKA}(h_i, h_j) \ge 1 - \frac{h - g}{h} \cdot \delta$$

其中 $\delta$ 是头间 attn pattern 自然方差。 在 $g=8$, $h=32$, $\delta = 0.1$ 时, CKA 下界 = $1 - 24 \cdot 0.1 / 32 = 0.925$。 这解释了为什么 GQA-8 行为接近 MHA。

---

## 35. MLA 的"双 KV"路径信息论

MLA 同时存在两条 K 路径:
- **压缩路径** $k_\text{latent}$: $d_{c}$ 维, 用于 q 与 v 间的全连接 attention
- **解耦路径** $k^R$: $d_r$ 维, 只用 RoPE

互信息视角: 这两条路径共同决定 attention score:

$$I(k^R; k_\text{latent}) \le H(k_\text{latent})$$

但工程上若两条路径过于耦合(同源 $c$), 退化回 MHA。 DeepSeek-V2 用单独 $W^R_up$ 强制解耦。

## 36. 长上下文的位置编码外推数学

NTK-aware scaling: 把 RoPE base $\theta \to \theta \cdot \alpha^{\frac{d}{d-2}}$:

$$\theta_i' = \theta_i \cdot \alpha^{\frac{d - i}{d - 2}} \to b' = b \cdot \alpha^{\frac{d}{d - 2}}$$

即高频维 base 不变(短距离精度保留), 低频维 base 加大(长距离延展)。

YaRN (Peng et al. 2023) 进一步引入"长度缩放因子" $s$, 把位置偏置均匀缩放, 实证在 64K-200K 长度都有提升。

## 37. Attention 的稀疏性 "Soft" 实现

**Switch Transformer 思路**: 不是稀疏 attention, 而是稀疏 KV 路由。
**MoA (Mixture of Attention, 2024)**: 多种 attention head 共存, 每 token 选 top-2 head:

$$h_i = \sum_{j \in \text{Top-2}} w_{ij} \text{Attn}_j(Q_i, K_i, V_i)$$

实测在 7B 模型上几乎没有性能损失, 但单 token 算力降为 1/3-1/4。

## 38. 注意力机制的因果视角

把 attention 看成一个"因果图":
- 节点 = token
- 边 = attention weight

那么因果效应:

$$\text{do}(x_t = v) \Rightarrow \text{Causal Effect} = \frac{\partial \text{Attn}}{\partial x_t}$$

当 attention mask 不对称(如左看右), 节点间形成 DAG。 这是为什么 encoder-decoder 的 cross-attention 不可因果解耦。

## 47. 案例: DeepSeek-V3 的 DSA 与 FP8 KV

## 49. Decode throughput 计算

decode 单 token 时间 ≈ `KV 读写 + attention compute + 1 step MLP`:

$$T_\text{decode} \approx \frac{2 n h_\text{kv} d \cdot \text{sizeof(dtype)}}{\beta_\text{HBM}} + \frac{2 h d^2}{\pi}$$

例: H100 (HBM 3 TB/s, FLOPS 1e15/s), $h_\text{kv}=8$, $d=128$, $h_\text{attn}$ 不算:

$$T_\text{decode} \approx \frac{2 \cdot 128K \cdot 8 \cdot 128 \cdot 2}{3\!\cdot\!10^{12}} \approx 87 \mu s$$

主要被 KV 读写占用。 这就是为什么 KV Cache 压缩如此重要。

## 52. FlashAttention 反向传播的关键

FA 反向传播仍用 online 思想, 但需要重计算 $P, m, \ell$:

**算法 4.G: FlashAttention Backward 简化版**
1. 重计算 $S_{ij}, P_{ij}, m_{ij}, \ell_{ij}$ (从 saved $m, \ell$)
2. 用 $\nabla V_j \leftarrow P_{ij}^\top \nabla O_i$ 累计
3. 用 $\nabla K_j \leftarrow P_{ij} (\nabla O_i V_i^\top)^\top$ 累计
4. 用 $\nabla Q_i \leftarrow \sum_j \nabla S_{ij} K_j$ 累计

仍满足"两次分块累加"形式, 等价于标准 attention 反向。

## 54. 工程实践: 长上下文 chat 系统的 token 管理

```python
class LongContextManager:
    def __init__(self, model, max_ctx=128_000, sink_k=4, window_n=4096):
        self.model = model
        self.max_ctx = max_ctx
        self.sink_k = sink_k        # attention sink 保留数
        self.window_n = window_n    # 滑动窗口大小

    def add_turn(self, prev_kv, new_tokens):
        """新轮对话进来, 维护 KV"""
        total_tokens = prev_kv.shape[2] + len(new_tokens)
        if total_tokens <= self.max_ctx:
            # 直接 append
            kv = self.model.append_kv(prev_kv, new_tokens)
        else:
            # StreamingLLM: 保留前 sink + 最近 window
            sink = prev_kv[:, :, :self.sink_k, :]
            window = prev_kv[:, :, -self.window_n:, :]
            kv = torch.cat([sink, window], dim=2)
            kv = self.model.append_kv(kv, new_tokens)
        return kv
```

## 55. 多模态 attention mask 设计

LLaVA / MiniGPT-4 的 image-text attention:
- 视觉 token 之间: bidirectional
- 文本 token 与视觉 token: 单向(文本不能 attend 未生成的视觉)? 大多实现是双向
- 文本 token 之间: causal

实现:
```python
def build_vl_attn_mask(T_img, T_text):
    """形状: (T_img + T_text, T_img + T_text)"""
    T = T_img + T_text
    mask = torch.zeros(T, T)
    # 视觉段内: 全 1
    mask[:T_img, :T_img] = 1
    # 文本 attend 视觉 + 自己(causal)
    for i in range(T_text):
        mask[T_img+i, :T_img] = 1
        mask[T_img+i, T_img:T_img+i+1] = 1
    # 视觉 attend 文本: 大多实现是双向全 1
    mask[:T_img, T_img:] = 1
    return mask.bool()
```

## 58. SSM 与 Attention 的"互信息视角"

Transformer 的 attention 输出可视为对 V 的"加权聚合", 权重由 QK 相关性决定。 Mamba 的输出是状态空间的线性映射, 等价于"卷积视图":

$$y = K \ast x,\quad K_t = C A^t B$$

把 $K$ 当作 attention score 的"kernel", 则 Mamba 对 V 的加权等价于"卷积权重由输入驱动", 而 Transformer 是"输入驱动 + 输出驱动"混合(因为 softmax 输出显式依赖 V)。

这就是为什么 Mamba 与 Transformer 在不同任务表现不同: 本质上是"输入决定权重"vs"输入输出决定权重"。

## 59. 注意力机制的"训练-推理不对称"

```text
                训练 (fully visible)          推理 (decode)
Q              全部                          当前 step
K              全部                          全部 cache
V              全部                          全部 cache
attn matrix    (T, T) 完整                  (1, T) 或 (T_cur, T) decode 时
```

工程含义:
- 训练 FA2 forward/backward 都用 tiling
- 推理 prefill: 一个长序列处理一次, batching 后 throughput 高
- 推理 decode: 每 token 都要重访历史 KV, 算力受限 → 优化 KV 字节

FlashDecoding 把 decode 进一步切成"分块 K 多次", 解决单个长 prompt + 短 decode 时的 GPU 利用率低问题。

## 60. 注意力机制的若干少见问题

### 60.1 Attention Score 的偏置漂移

标准实现用 $\sqrt{d}$ 缩放, 但若头部设置不同 (例如不同 d_head), 需要分别缩放。

### 60.2 Attention 的"折叠等价"

$Q$, $K$ 相加常量时, $QK^\top$ 不变(因为 softmax 把常量吸收)。 这给推理"窥探"提供可能。 FP8 量化下利用此 trick 提升精度。

### 60.3 ALiBi 与 RoPE 的对比

ALiBi (Press et al. 2022) 用线性 bias 加到 score:

$$\text{score}_{i,j} = q_i k_j^\top - m \cdot |i - j|$$

外推性好, 但与 learnable position 不兼容。 RoPE 更灵活, 但需要 base 外推。

## 61. vLLM PagedAttention 实现要点

vLLM 借鉴 OS 虚拟内存, 把 KV cache 分成固定大小的"页"(如 16 tokens / page)。
- 每序列的 KV 在"页表"中索引
- 不同序列的 KV 可以混存, 无连续空间需求
- Decode 时 batch 多个序列, 让 GPU 充分利用

```python
# PagedAttention forward (简化)
def paged_forward(q, page_table, pages, page_size=16):
    B, H_q, D = q.shape
    n_rep = H_q // pages.shape[1]  # h_kv = pages.shape[1]
    out = torch.zeros_like(q)
    for seq_idx in range(B):
        for page_idx in page_table[seq_idx]:
            k_page = pages[page_idx, 0]  # (h_kv, page_size, d)
            v_page = pages[page_idx, 1]
            # 共享 K/V 到所有 Q 头
            k = k_page.repeat_interleave(n_rep, dim=0)
            v = v_page.repeat_interleave(n_rep, dim=0)
            score = (q[seq_idx] @ k.transpose(-2, -1)) / math.sqrt(D)
            attn = score.softmax(-1)
            out[seq_idx] += attn @ v
    return out
```

## 62. FlashDecoding 与长 prompt

普通 decode: $Q$ 是 (1, T_d, d), $K/V$ 是 (1, T_cache, d)。 这时 GPU 利用率低。

FlashDecoding 把 K/V 沿 seq 维切, 让多个 SM 并行计算不同 chunk:
1. 先算每个 chunk 的 partial output
2. reduce 时按 chunk 的 logits 归一化合并

效果: 长 prompt + 短 decode 时, decode 速度提升 8x。

## 63. CUDA Graph 与 attention

把整个 attention forward 编到 CUDA Graph 中, 减少 launch overhead。
- 第一次: warm up, 抓取所有 kernel launch
- 后续: 一次 graph replay, 几乎无 CPU 开销

在 decode 阶段(SM 利用率低)效果最明显, 提升 30%+。

## 64. INT4/INT8 KV cache 量化

方法:
- **per-token**: 每 token K/V 独立 min/max 量化
- **per-head**: 同一头内共享 scale
- **per-group**: 每 $g$ 个连续元素共享 scale

精度保留 vs 压缩率:
- per-token int4: 4× 压缩, ~1% 准确率损失
- per-head int4: 同上但 cache 整数对齐更好
- INT8 + per-group 是 sweet spot

DeepSeek 用 INT4 cache + INT8 weight, 显著降低推理成本。

- 验证阶段: 大模型一次 forward $k$ token, batched attention

微调场景下, 多个 LoRA adapter 共享 base 模型 KV cache, 但需要为每个 adapter 单独维护一份"delta"。 工程上:
- base KV 一次性存, 多副本"虚拟指针"指向
- adapter 的 delta 存在独立 page

减少 N 倍微调 KV 占用。 已实现在 Hugging Face TRL 与 vLLM 中。

## 第十二部分 跨界应用

## 67. 注意力在推荐系统中的应用

推系统的 DIN (Deep Interest Network) 用 local activation unit 计算 target 与历史的 attention weight:

$$\text{Attn}(t, h_i) = \frac{\exp(t^\top h_i)}{\sum_j \exp(t^\top h_j)}$$

没有 softmax 缩放, 但本质是 attention。

这是 attention 跨界进 CV/Rec 的最早例子之一。 后续 BERT4Rec、Temporal Attention Network 都基于此。

---

## 68. 注意力在语音识别中的应用

Whisper 用 encoder-decoder attention:
- encoder: 音频 mel 谱, ~1500 tokens (30s 音频)
- decoder: 文本生成, 每 token attend 所有音频 token

KV cache 中音频部分常驻, 文本部分 append。 推理时 30s 音频 ≈ 1.5GB KV (Whisper large-v3)。

---

## 69. 注意力在图像生成中的应用

Stable Diffusion 3 / FLUX 用 MM-DiT:
- text KV 来自 T5 encoder
- image KV 在 transformer block 内

cross-attention + self-attention 混合, attention 计算量随分辨率平方。 1024×1024 图像 = 4096 tokens, cross-attn 已经约 0.7B FLOPs。

## 70. 注意力在强化学习中的应用

Decision Transformer:
- state, action, return-to-go 拼成序列
- attention 学习从历史预测下一步 action

这里 attention 不是用来"读", 而是用作"决策网络"。 优势: 端到端, 可 offline RL。

## 第十三部分 关键问题与陷阱

## 71. 长上下文: "迷失在中间"现象

Liu et al. (2023) "Lost in the Middle": 模型在上下文 0-30% 与 70-100% 位置上的检索强, 中段 30-70% 弱 10-30%。

成因猜想:
- 训练数据中"中间位置"出现关键信息概率低
- attention 训练时偏向两侧

工程对策:
- **关键信息靠前/靠后放置**: 在 prompt 设计上
- **重排序**: 让模型先看全文档, 再针对提问定位
- **间隔重复**: 把关键信息在多处复述

---

## 72. 注意力机制的"过度平滑"问题

深层 transformer 中, attention 权重越来越均匀(各 token 收到差不多 attention), 表征塌缩。 一些成因:
- LayerNorm 在残差连接上累积
- 训练过长, 浅层特征被"洗掉"

解法:
- **DeepNorm**: 残差连接权重按层深缩放( $1/\sqrt L$)
- **Skip Connections 改进**: 加 scale 到残差
- **Re-Initialization**: 周期化从某层"重置"

---

## 73. 训练不稳定的 attention 相关现象

- **Loss spike**: 早期梯度爆炸, attn 内积突然放大
- **Attention collapse**: 所有 token attend 到同一位置
- **Head death**: 部分 head 权重退化为 0

监控:
- 每 100 step 输出 attn entropy 分布
- 监控每个 head 的 attention 标准差
- spike 时 select lowest-attn head 重新 init

## 第十五部分 数学专题

## 82. Soft Attention vs Hard Attention

标准 softmax attention 称为 **soft attention** (连续权重, 处处可微)。 **Hard attention** 是离散选取:

$$\text{Attn}_i^\text{hard} = V_{i^*},\quad i^* = \arg\max_j S_{ij}$$

不可微 → 需要强化学习或近似梯度 (REINFORCE, Gumbel-Softmax)。

工程上几乎不用 hard, 因为:
- 训练不稳 (high variance gradient)
- 无法 batch (选取随样本变)
- 推理序列不可重现

## 83. Attention Score 的统计量

**Entropy 视角**:
$$H(A_i) = -\sum_j A_{ij}\log A_{ij}$$

- $H \approx \log n$: 均匀分布, "无信息" 注意力
- $H \approx 0$: 单点集中, "硬" 注意力

训练健康的 transformer: 中层 $H \in [3, 8]$, 高层 $H$ 更小 (具体位置 strong)。

**监控技巧**: 把每层 avg entropy 加到 TensorBoard, 看是否退化 (过低=collapse, 过高=无作用)。

## 84. Multi-Query 的"语义保持"

定理: MQA 把所有 Q 头共享同一对 K/V, 等价于 K/V 在 head 维上做"硬分类", 每类的代表性 KV 用均值。 这保留了**大部分**attention 结构, 损失**头部间**多样性。

实践中: MQA 模型在代码、对话等"模式相对集中"的任务上良好; 在"需要多模态多视图"的任务(如 CV 多视角融合)上掉点。

## 85. FlashAttention 的 memory footprint 数学

经典 attention 显存:

$$M_\text{std} = B \cdot h \cdot n^2 \cdot \text{sizeof(dtype)}$$

FlashAttention:

$$M_\text{FA} = B \cdot h \cdot (n \cdot d + n) \cdot \text{sizeof(dtype)}$$

加速比 (假设 sizeof(dtype) 相同):

$$\frac{M_\text{std}}{M_\text{FA}} = \frac{n^2}{n d + n} \approx \frac{n}{d}$$

n=4096, d=128 → 32× 显存节省。

## 86. Attention 中的 dropout 模式

- **Row-wise dropout**: 整行置零 (跳过 query)
- **Column-wise dropout**: 整列置零 (跳过 key/value)
- **Block-wise**: 整块置零 (类似稀疏 attention 训练)

标准实现是 row + column 全 drop, 等价于 Re-dropout。 高效实现只在 softmax 后的 $A$ 上做。

**经验**: dropout 比例 0.1-0.2 在小模型上提升正则化, 大模型通常 0.0。

## 87. KV Cache 共享的多种形式

| 形式 | 典型用例 | 节省 |
| :--- | :--- | :--- |
| **MQA** | 1 KV per token | $1/h$ |
| **GQA** | $g$ KV per token | $g/h$ |
| **MLA** | $d_c$ 维 latent | 极高 |
| **Prefix Sharing** | 同一 prefix 多 query | prefix 长度 / 总长 |
| **Cross-batch Sharing** | batch 内相同 prompt | batch 内重复率 |
| **Layer-wise Sharing** | 浅层 KV 给深层 | layer 数 |

Prefix sharing 在多轮对话、批量推理场景有 50%+ cache 节省。

## 88. 数学: Cross-Entropy Loss 与 Attention

Transformer 训练目标:

$$L = -\frac{1}{N}\sum_{i=1}^N \log p_\theta(x_i | x_{<i})$$

每个 $p_\theta$ 由模型最后一层 hidden state + softmax + 词表给出。 与 attention 直接关系: hidden state 通过 attention 加权聚合历史信息。

经验: 长文本训练常看到 attention entropy 上升 → 模型越来越"分心", 训练损失下降变缓。 此时加 ALiBi/T5 bias 重置位置编码, 可缓解。

## 89. KV 压缩的极限信息论

**定理 4.H (KV 压缩信息下界)**: 假设 hidden $h$ 的熵为 $H(h)$, K/V 来自 $h$ 的线性变换, 则 KV cache 的最小期望字节数 ≈ $H(h) \cdot n / 8$ (按 fp8 量化算)。

工程含义: 无论怎么压缩, KV cache 至少是原 hidden state 的 1/4 (fp8 vs fp32) 或 1/8 (fp4)。 这给出工程上限。

## 90. Self-Attention 的稀疏化理论

BigBird 证明 (Zaheer et al. 2020): "全 attention + random + window" 三类组合是 universal approximator。 也就是说, 在足够模型容量下, 这三类 attention 拼接可以逼近 full attention。

实践: 12-15% 稀疏率即可保留 95%+ 准确率。 这是稀疏 attention 的理论底气。

## 91. 注意力机制的"线性化"

设 $A = \text{softmax}(Q K^\top)$, 经典注意力输出 $O = A V$。

把 softmax 用 **taylor 展开**近似:

$$\text{softmax}(x) \approx \frac{1}{Z}\sum_{k=0}^\infty \frac{x^k}{k!}$$

每次截断后, $O$ 是 $Q, K, V$ 的多项式, 可线性计算。 这给 linear attention 的数学依据, 但截断误差大。

更现代: **kernel-based approximation** (FAVOR+), 用随机特征投影:

$$\phi(x) = \sqrt{\frac{1}{r}}\left[\cos(\omega_1^\top x), \sin(\omega_1^\top x), \ldots\right]$$

其中 $\omega_i$ 是从正态分布采样。 期望下 $\phi(x)^\top \phi(y) = e^{x^\top y} \approx \text{softmax}(x^\top y)$。

## 92. PyTorch nn.functional.scaled_dot_product_attention

```python
import torch
import torch.nn.functional as F


def demo_sdpa():
    """PyTorch 2.0+ 自带高效 SDPA, 自动选 FlashAttention/CUDNN 等后端"""
    B, H, T, D = 2, 8, 1024, 64
    q = torch.randn(B, H, T, D, device="cuda", dtype=torch.float16)
    k = torch.randn(B, H, T, D, device="cuda", dtype=torch.float16)
    v = torch.randn(B, H, T, D, device="cuda", dtype=torch.float16)

    # 最简调用: 自动 FlashAttention 或 memory-efficient
    out = F.scaled_dot_product_attention(q, k, v, is_causal=True)

    # 用 GQA 等价形式: 共享 KV
    H_kv = 2
    k = k[:, :H_kv]                # (B, H_kv, T, D)
    v = v[:, :H_kv]
    # repeat 到 H 头
    n_rep = H // H_kv
    k = k.repeat_interleave(n_rep, dim=1)
    v = v.repeat_interleave(n_rep, dim=1)
    out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
    print("SDPA done, output shape:", out.shape)


demo_sdpa()
```

## 97. Triton 写自定义 attention

```python
import triton
import triton.language as tl

@triton.jit
def attn_kernel(Q, K, V, Out, sm_scale, stride_qb, stride_kb, ...):
    # online softmax 形式
    pid = tl.program_id(0)
    q = tl.load(Q + pid * BLOCK_M : (pid+1) * BLOCK_M, ...)
    m = -float('inf')
    l = 0.0
    acc = tl.zeros(...)
    for j_start in range(0, T_k, BLOCK_N):
        k = tl.load(K + j_start, ...)
        v = tl.load(V + j_start, ...)
        s = tl.dot(q, k.T) * sm_scale
        m_new = tl.maximum(m, tl.max(s, axis=-1))
        p = tl.exp(s - m_new[:, None])
        l = tl.exp(m - m_new) * l + tl.sum(p, axis=-1)
        acc = tl.exp(m - m_new)[:, None] * acc + tl.dot(p.to(v.dtype), v)
        m = m_new
    tl.store(Out + pid*BLOCK_M, acc / l[:, None])
```

Triton 比手写 CUDA 简单, 且性能接近。

## 第十七部分 高级话题

## 98. Mixture of Experts (MoE) 与 Attention 的耦合

DeepSeek-V3: 236B 总参数, 21B 激活。 每 token 选 8 个专家 (out of 256)。
- Attention 部分: 与 V2 相同架构, FP8 计算
- MoE 部分: 每层 router 选 8 个 FFN 专家

MoE 改变 attention 不多, 但改变**总计算量**: 训练 FLOPs 与激活参数成正比, 而非总参数。 这让"模型大、计算省"成为可能。

数学关系:
- 总参数量: $N_\text{total}$
- 激活量: $N_\text{act} = N_\text{attn} + N_\text{router} + k \cdot N_\text{expert}$ (k 为专家数)
- 训练 FLOPs ∝ $N_\text{act}$
- KV Cache: 只与 attention 相关

## 99. KV Cache 在 MoE 模型中的特殊问题

MoE 路由不同时, 不同 token 用不同 FFN。 但 attention 的 KV 与 FFN 无关, 故 cache 行为与 dense 模型一致。

但是: 当 batch 内不同序列用不同路由器激活不同专家时, 权重 dump 大小不均。 工程上: shard checkpoint with same expert order across ranks.

## 100. KV cache 量化在 MoE 下的额外优势

MoE 模型激活参数小, KV Cache 在推理显存占比相对更高。 量化 KV 收益比 dense 模型更明显:

| 模型 | KV cache 占比(激活部分) | int8 量化收益 |
| :--- | :--- | :--- |
| Dense 70B | ~40% | 显存降 20% |
| MoE 230B (激活 21B) | ~70% | 显存降 35% |

## 101. 注意力机制的"路由"扩展

**Routing Transformer** (Roy et al. 2021): 每 query 用 K-means 在 head 空间路由, 只 attend cluster 内 K/V。
- 计算 $O(n \log n)$
- 实测与人头全 attention 持平

**Switch Transformer**: 与 routing 类似, 但用于 FFN。

**DeepSeek-V2 Sparse Attention**: routing 改良, 每 query 选 top-k KV 块 (block-sparse)。

## 102. 注意力机制的"Hash 化"扩展

**Reformer** (Kitaev et al. 2020): 用 LSH (Locality-Sensitive Hashing) 把相似 Q/K 桶聚集:
- 同 bucket 内计算 attention
- 不同 bucket 视为 $-\infty$

$O(n \log n)$。 但工程实践不及 FlashAttention 流行。

## 105. KV cache 与 prefix caching

多轮对话中, 系统消息的 KV 可以 cache, 用户消息变, response 生成。 这种 "prefix caching" 让首 token latency 几乎为零。 vLLM 与 SGLang 都支持:

```python
import sglang

@sglang.function
def chat_qa(s, system, user_msg):
    s += system
    s += sglang.user(user_msg)
    s += sglang.assistant(sglang.gen("response", max_tokens=200))

# prefix = system 部分可被缓存
runtime = sglang.Runtime(model_path="...")
```

## 106. 注意力机制与 batch size 的关系

batch 增加, attention 总 FLOPs 增大, 但并行度也提高 (GPU 利用率 ↑)。
- decode 阶段 batch = 1: GPU 利用率 ~5%, 浪费严重
- batch = 32: 利用率 ~80%, throughput 接近上限

critical batch size (CB): 再增大 batch 边际收益下降, 因为 KV cache 成为内存瓶颈。 经验:

$$\text{CB} \approx \frac{\text{GPU MEM}}{\text{KV per token}}$$

对 70B 模型 + 80GB GPU + 8K 上下文, CB ≈ 30。

## 107. Prefill 时间与 Sequence Position 的关系

Prefill 阶段越长, attention 矩阵越大, 计算 $O(n^2)$。 但**注意力是各 head 独立**的, batch 后各 head 几乎线性加速。

工程上: prefill 长 prompt 时, 把序列 padding 到 2 的幂次, Tensor Core 利用率更好。

## 108. Long-context fine-tuning 的稳定技巧

1. **渐进式扩上下文**: 先训练 8K, 再 fine-tune 到 32K, 再到 128K
2. **低学习率**: 1e-5 而非 1e-4
3. **位置编码重置**: 重新 init RoPE 的 inv_freq
4. **数据配比**: 至少 30% 长文 (≥ 8K)
5. **Attention bias**: 在长文本上加 ALiBi 临时偏移稳定训练

## 109. Sparse Attention 的工程实现

Longformer 的 sliding + global:

```python
def longformer_attn(q, k, v, w=512, global_idx=None):
    B, H, T, D = q.shape
    out = torch.zeros_like(q)
    for i in range(0, T, w):
        # 窗口 attention
        q_w = q[:, :, i:i+w, :]
        k_w = k[:, :, max(0, i-w//2):min(T, i+w+w//2), :]
        v_w = v[:, :, max(0, i-w//2):min(T, i+w+w//2), :]
        score = q_w @ k_w.transpose(-2, -1) / D**0.5
        attn = score.softmax(-1)
        out[:, :, i:i+w, :] = attn @ v_w
        # global attention: 让 global token 看到所有
        if global_idx is not None:
            for g in global_idx:
                # g token attend 全局
                q_g = q[:, :, g, :]
                score_g = q_g @ k.transpose(-2, -1) / D**0.5
                attn_g = score_g.softmax(-1)
                out[:, :, g, :] = attn_g @ v
    return out
```

## 第二十部分 数值与硬件

## 121. 注意力计算的 Tensor Core 利用率

A100/H100 的 Tensor Core 计算 attention 时:
- 形状偏好: M = N = 128 或 64, K = 64/128
- 不是方块形状时, padding 到接近方块

Triton 的 `tl.dot` 操作默认按 16x16 块切, 对 (T_q, d) @ (d, T_k):
- T_q < 64 时, 会浪费算力
- T_q 大时, 几乎全利用

FlashDecoding 在 decode 阶段 (T_q=1) 把 K 沿 T_k 切到 T_q 的方向, 用 Tensor Core 计算, 实测在 4096 token 长 prompt 下吞吐翻倍。

## 122. KV cache 的存取模式: Coalesced vs Strided

GPU HBM 读取的首选是 coalesced (相邻线程读相邻地址)。 KV cache 排列:
- **(B, h_kv, T, d)**: 同一 head 连续, 跨 head 不连续。 大部分 attention 是 coalesced 读, ✓
- **(B, T, h_kv, d)**: 跨 head 连续, 对 KV selection 友好但对 attention 主路径不友好
- **(B, T, d, h_kv)**: 跨 head 连续, 跨 d 连续, 适合 MLA decoupled

选择 layout 影响 attention kernel 性能 10-20%。 现代推理引擎 (vLLM, TRT-LLM) 用 H2H (head-to-head) layout 让 batch 内 attention 高效。

## 123. FlashAttention 反向的 O(T²) 但 low memory

FlashAttention v2 backward 也用 online 算法:
- 反向需要重计算 attention score (with saved m, l)
- 但不存 forward 的 $S$, $A$ 矩阵, 故 HBM 仍是 $O(n d / M)$

总显存 $O(n)$, 但算力 $O(n^2 d)$, 这意味着**算力是瓶颈不是显存**。 长序列训练时: FlashAttention 不是省显存 (训练已有 grad checkpoint), 而是用算力换吞吐量。

## 124. 量化对 attention 的精度影响

INT8 attention 实验:
- weight: fp16
- Q: fp16
- K: int8 per-token
- V: int8 per-token
- softmax: 在 fp32

实测在 GLUE / MMLU / HumanEval 上: 平均掉 0.5-1.5 点, 复杂推理任务掉 3-5 点。

INT4 attention 不稳定, 需要特殊 trick (per-head scale + outlier handling)。

## 125. 长上下文与磁盘 IO

128K 上下文若 cache 在 CPU RAM, GPU 访问要走 PCIe 5.0 (1 TB/s) 或 NVLink (3 TB/s)。 实测:
- H100 NVLink, 128K KV 完整加载: ~80 ms
- 不算大, 但 decode 每 token 都重访, throughput 显著降

推荐: KV cache 全部在 GPU HBM, 不要 spill to CPU。 长 prompt 可以预编码后整段 cache。

## 126. Attention 调度与多租户

GPU 推理服务中, 多租户共享一台 GPU 的 KV cache。 调度策略:

```text
| 租户 | 当前 length | KV 占用 | 优先级 |
| A | 50K | 130MB | 1 |
| B | 10K | 26MB | 3 |
```

策略:
- **Priority Queue**: 按优先级调度 forward
- **Preemption**: 低优先级 evict, 高优先级抢占
- **Prefix Sharing**: 多租户有共同 prefix, 共享 cache

vLLM 用 prefix sharing, 实测: 多用户 chat 吞吐量提升 2-3×。

## 第二十一部分 数学严谨性 2

## 127. Attention 的多项式等价

**定理 4.I**: 标准点积 attention 与以下等价:
1. **Polynomial kernel**: $K(x, y) = (x^\top y)^p$, $p = 1$ 时即点积
2. **Positive-definite kernel**: $K$ 是 PSD 函数, Mercer 分解后近似

这意味着 attention 可以用 kernel methods 视角分析。 当 $K$ 高频, attention 趋向硬 (近 max)。

## 128. Attention 矩阵的低秩性

**定理 4.J (LLM 实践中)**: 训练后的 attention 矩阵 $A \in \mathbb{R}^{n\times n}$ 近似 rank-$\sqrt n$。

工程意义:
- KV cache 可以低秩压缩
- SVD 分解 K, V 各保留 top-k, $k \approx \sqrt n / d$
- 这是 "KV compression" 的理论基础

## 129. Attention 矩阵的归一化视角

把 attention 看作 Markov 转移矩阵 (行归一化已 softmax 给出), 它是个吸收-发射的随机过程:
- 起始 token → 吸收者 (sink)
- 中间 token 跳转

定义"持久时间"为从起始到吸收的期望步数。 训练良好的 attention 持久时间长, 说明信息流稳定。

实验: BERT 的 attention 持久时间 ≈ 100, GPT-2 ≈ 50 (token 数)。

## 130. Attention 与 Mutual Information 的关系

**Mutual information $I(X; Y)$**: 衡量两个变量共享的信息量。 在 attention 视角:

$$I(\text{Query}; \text{Attended}) = H(\text{Query}) - H(\text{Query} | \text{Attended})$$

模型训练最大化逐层的 $I$, 减少信息损失。 这是为什么深层 attention 需要 residual + LayerNorm: 维持信息流。

## 131. Attention 的 Bayesian 解释

softmax attention 可解释为 Bayesian posterior over hidden state contributions:

$$P(\text{attend to } j | q_i) = \frac{P(q_i, k_j)}{\sum_k P(q_i, k_k)} = \text{softmax}(q_i^\top k_j / \sqrt d)$$

其中 $P(q_i, k_j) \propto \exp(q_i^\top k_j)$。 这是 attention 的概率解读。

训练时: KL 散度最小化 = attention 学到的分布尽量匹配真实相关性分布。

## 132. Attention 训练中的优化轨迹

经验观察 (LLaMA 系列):
- 早期 (step 0-1000): attention entropy 高, 模型在探索
- 中期 (1000-100000): entropy 下降, 形成固定模式
- 后期 (>100000): entropy 稳定, 微调

可以监控 entropy 时间序列:
- 训练开始 entropy 高 = 学习有效
- entropy 突增 = 学习率爆炸, 需降 lr
- entropy 稳定 = 训练收敛

## 134. 监控 metrics 代码

```python
import torch
import torch.nn.functional as F


@torch.no_grad()
def attention_diagnostic(model, batch, layer_idx=0, head_idx=0):
    """提取 attention map 并计算诊断指标"""
    model.eval()
    x = batch["input_ids"]
    out = model(x, output_attentions=True)
    attn = out.attentions[layer_idx][0, head_idx]   # (T, T)
    entropy = -(attn * (attn + 1e-9).log()).sum(-1).mean()
    sparsity = (attn < 1e-3).float().mean()
    max_attn = attn.max()
    print(f"layer={layer_idx} head={head_idx} "
          f"entropy={entropy:.4f} sparsity={sparsity:.4f} "
          f"max_attn={max_attn:.4f}")
```

## 143. Attention 的谱分析

attention 矩阵 $A$ 的特征值分解:

$$A = U \Lambda U^\top$$

其中 $\Lambda$ 是对角特征值。 长程依赖体现在 $\Lambda$ 的非零特征值分布。 工程含义:
- $\lambda_{\max}$ 对应头部主要方向
- $\lambda_i \to 0$ 的速度决定"遗忘"速度

## 144. RNN/SSM/Attention 的统一视角

三者都可写为:

$$y_t = \sum_{s\le t} k(t, s) x_s$$

其中:
- **RNN**: $k(t, s)$ 由 hidden state 决定
- **SSM**: $k(t, s) = C A^{t-s} B$ (指数衰减或振荡)
- **Attention**: $k(t, s)$ 与输入 x 相关 (input-dependent)

也就是说, attention 是最灵活的 (input-dependent kernel), 但也最贵 ($O(n^2)$)。

## 145. Attention 与 Hopfield 网络的等价

现代 attention = Hopfield 网络 with stored patterns:

$$\xi_i^{(\mu)} = V_\mu \in \mathbb{R}^d \quad \text{(stored)}$$

energy:

$$E = -\sum_\mu \exp\left(\frac{1}{\sqrt d}\xi^\top \xi_i\right)$$

retrieval = attention。 这是 attention 与神经动力学的桥梁。

## 146. 软注意力的极限: $T \to \infty$

定理: 若 attention softmax 温度 $\tau$ 变小 ($\sqrt d$ 增大等效), softmax 趋向 argmax, 退化为 hard attention。 反之 ($\tau$ 大), 趋向均匀分布。

训练时, 多头 attention 的不同 head 可能落在不同温度下:
- "Sharp" heads: argmax-like, 处理关键 token
- "Soft" heads: 均匀, 处理背景信息

## 147. Attention 的"频域"视角

把 $q_i, k_j, v_j$ 看作函数, attention 是核:

$$y_i = \int k(q_i, k) v(k) d\mu(k)$$

当 $k$ 是 gaussian kernel, 类似 attention; 当是 dirac, 即 nearest neighbor。

频域上, attention bandwidth ∝ temperature, 不同 head 不同带宽形成 multi-scale 处理。

## 154. LLM 效率的"两难"

**质量 vs 效率** 是 LLM 的永恒张力:
- MQA 效率高, 质量损失小
- MLA 效率极高, 但工程复杂
- Linear Attention 效率极限, 质量仍掉

工程现实: 折中是 $h_\text{kv}=8$, 让 GQA 维持 MHA 95% 能力, 同时省 75% KV cache。

## 155. 思考: 注意力机制的"扩展"瓶颈

n 增到 10M+ 后:
- 计算: $O(n^2)$ → $10^{14}$ FLOPs/token, 不可承受
- KV cache: 1PB+, 不可行
- 检索: 1M token 中找一段, attention 已经力不从心

出路: **分段处理 + 检索**, 而非 single attention pass。 而这又是 RAG 范畴。

## 156. 思考: Attention 是否是终极范式

正方:
- 一致性 (training/inference)
- 灵活性 (multi-modal, multi-task)
- 数学清晰 (softmax, matmul)
- 工业成熟 (Triton, FlashAttention)

反方:
- Mamba 在某些任务逼近/超越
- Linear Attention 在大序列上更快

结论: Attention 不是"终极", 但目前是大模型事实标准。 Mamba 等可能在特定任务 (流式/超长) 上分一杯羹, 但不会替代 attention 在通用 NLP 的位置。

## 157. 终极启示: 工程 > 数学

实际部署中最有用的不是看 softmax 数学, 而是:
- 算清楚你的 KV cache 字节数
- 看 FlashAttention 是否生效
- 监控 attention entropy 趋势
- 选 GQA-8 不选 MQA

工程是把数学变成可生产, 这正是本章核心。

## 第二十八部分 长上下文专属深度

## 160. 长上下文的"接收者"模型

长上下文不是简单地把 n 推到 128K, 而是经历了 3 个层次:

1. **被动长文**: 输入长, 输出短 (LongBench, summarization)
2. **主动长文**: 输入长, 输出覆盖全输入 (LongChat, retrieval)
3. **超长综述**: 1M+ 长文, 模型要能"全局视图"

每一层次的能力需求不同, 对 attention 要求也不同:
- 被动: 普通 GQA + FP8 KV 即可
- 主动: 需要 attention 强检索能力, 不能用纯 SWA
- 超长: 必须有 attention sink + 工作记忆 + 检索召回

## 161. "Needle-in-a-Haystack" 评测的技术细节

最简单的测试: 在一段 30K 文本中插入 "The magic number is: 42.", 然后问 "What is the magic number?"。

但实现有诸多陷阱:
- 文本填充用什么? (Wikipedia random articles, 长篇小说)
- 问题放在 prompt 的哪里? (开头/中段/结尾)
- 是否允许 chain-of-thought?

```python
def needle_in_haystack_eval(model, tok, haystack_lengths):
    results = {}
    for length in haystack_lengths:
        # 随机采样 haystack
        haystack = sample_random_text(length)
        # 在 middle (length/2) 位置插入 needle
        insert_pos = length // 2
        haystack_with_needle = (
            haystack[:insert_pos] +
            f"\n\nThe magic number is: {random.randint(100, 999)}.\n\n" +
            haystack[insert_pos:]
        )
        # build prompt
        prompt = f"Context: {haystack_with_needle}\n\nQ: Magic number?\nA:"
        out = model.generate(tok(prompt)['input_ids'], max_tokens=10)
        pred = int(re.search(r'\d+', out).group())
        results[length] = (pred == needle)
    return results
```

实战结果: 大多数 7B+ 模型在 8K 内 100%, 32K 内 95%+, 128K 退化到 60-90%。

## 163. "Lost in the Middle" 的工程对策

工作记忆心理学:
- 人在回忆时, 短时记忆 5-9 项
- 长时记忆依赖 chunking + 索引

LLM 类似, 但可以通过 prompt 工程引导:

- 在 prompt 末尾重申关键信息

## 164. 案例: Claude 3.5 在 200K 的"硬遗忘"

Claude 3.5 (Sonnet) 在 200K 任务上, 大致 retention 模式:
- 0-50K: 95%+ 准确
- 50-150K: 80-90%
- 150K-200K: 70-80%

- 关键信息尽量放前 50K
- 超长任务用分段 + 检索

## 165. 长上下文与 RAG 的本质差异

**Long Context (LC)**:
- 把全文档塞入 prompt
- 模型自己 attend
- 优势: 单步, 强 reasoning
- 劣势: 慢, 贵, 长文衰减

**RAG**:
- 先检索相关 chunk, 再 prompt
- 模型 attention 在短 prompt 上
- 优势: 速度快, 显存低
- 劣势: 多步, 检索失败则答案失败

工程经验:
- 用户文档 ≤ 32K → LC 直接做
- 32K-128K → LC + 关键段 highlighting
- > 128K → RAG + LC 综合
- > 1M → RAG 必须

## 166. LongLLM: 8B 模型用 128K 上下文

LongLLM (2024, Microsoft) 提出 mid-training:
- 在 128K 继续训练 8B 模型
- 用 progressive window 训练 (4K → 32K → 128K)
- 数据: 长文档 + 合成 QA

效果: 8B 模型在 128K needle-in-haystack 95%+。

## 167. 太长上下文的 "Horizon" 现象

超过 128K 后, 一些模型出现"horizon"现象:
- 前 128K 信息强
- 后信息"消散"

Anthropic 论文 "Lost in Conversation" (2025) 报告: Claude 3.5 在 50K 后丢 30% 信息。

工程对策:
- 主动压缩: 摘要前段
- 双模型: 短主模型 + 长 verifier

## 168. KV cache 量化在长上下文的关键作用

长上下文 (128K) 时, KV cache 占总显存主导:
- LLaMA-3-70B 模型 140 GB, KV (128K) 4 GB
- 但 batch 多用户时: 30 用户 × 4 GB = 120 GB

把 KV int4: 30 GB → 7.5 GB, 显著。
把 KV int8: 30 GB → 15 GB。

DeepSeek-V3 默认 KV int8 在 128K 上下文。

## 169. 长上下文的稀疏 attention 策略

**Sliding Window + Global Tokens (SWA + Global)**:
- 全局 token 在浅层 broadcast, 深层不需
- 局部 token 间滑动 attention

**Block-Sparse Attention** (BigBird):
- 块状 attention, 块内全连接, 块间稀疏
- $O(n^{1.5})$ 量级

**Differential Attention** (Microsoft, 2024):
- 每 query 算两个 attention 差
- 副产品: 自动忽略噪声

工程结论: 长文最好的 attention 还是 dense GQA, 配合 sparse 还能丢 5-10%。

## 第二十九部分 Attention 的 "特殊场景"

## 170. Sparse Mixture of Attention

每个 head 用不同 attention 模式, 由路由器选:

```text
输入 → router → 选 top-k head 类型 → 各 head 计算
```

类型:
- 全 attention head
- SWA head
- Linear head
- Recurrent head

MoA 论文 (2024): 8B 模型与 7B dense Transformer 持平, 推理快 1.6×。

## 171. 检索-增强的 Attention

长文本检索: 不直接 attend 全部, 先**外部检索** Top-K relevant chunks:

$$O = \text{softmax}\!\left(\frac{Q\,K_\text{top-k}^\top}{\sqrt d}\right) V_\text{top-k}$$

这是 RAG 的核心, attention 只在 relevant chunks 上计算。 比 full attention 节省 99%。

## 172. Memory-augmented Attention

给 attention 一个**外部 memory**:
- $\text{Memory} = \{M_1, M_2, ..., M_p\}$, $M_i \in \mathbb{R}^{m \times d}$
- Query 同时 attend local context + memory
- Memory 通过前向 + 反向梯度更新

这是经典 Memorizing Transformer, MEMO 等。 适合 multi-turn 对话。

## 173. Cross-lingual Attention

在多语言模型里, 一种语言的句子 attend 另一种语言的语义。 实验: 在中文 prompt 上调用, 模型把英文知识 "翻译" 出来。

## 174. Attention 的"涌现解释"

大型 transformer 训练中, 一些 heads 自动 specialization:
- 某个 head 永远 attend 前一个 token (previous-token head)
- 某 head 永远 attend syntax head
- 某 head attend [SEP] (sentence boundary)

这说明 attention 不是 "统计", 而是 "学习到语义结构"。 是 attention 可解释性的关键证据。

## 175. Attention 的"删除"研究

OpenAI 2019 在 GPT-2 上做 ablation: 删除一个 head, 测任务影响。 部分 head 几乎没影响 (冗余), 一些 head 关键 (specific tasks)。

工程上: 训练后可以剪枝不重要 head, 节省计算 5-15%。

## 176. Attention 与 Dropout 配合

训练时 attention dropout:
- 0.1 标准
- pattern dropout: 整片 mask 随机置零
- ALiBi-drop: 用 ALiBi mask 引导

attention dropout 影响:
- 模型"被迫"多种 head 协同
- 提升 OOD 鲁棒性

## 177. KV Cache 与 LoRA 微调

LoRA 微调时, 只有 LoRA adapter 权重更新, base model KV cache 不变:
- 一次 base forward 产出 KV
- 多次 LoRA 实验共享 KV

节省: 多 LoRA 微调时内存降 50%+。

## 178. Distillation 中的 Attention 迁移

训练 student 模型时, 模仿 teacher 的 attention map:

$$L_\text{distill} = -\sum_{(q, k)} \text{softmax}(q k / T_\text{teacher}) \log \text{softmax}(q k / T_\text{student})$$

(T 是 temperature)

让学生 attention "贴" teacher, 比单纯 logits 蒸馏保留更多结构信息。

## 179. Attention 在模型合并中的角色

合并多个 LoRA 时, 可以只在 attention 上合并:
- base attention ∪ lora_attention = merged
- FFN 部分不动

因为 attention 是结构化的, 合并更稳定。

## 180. 极简 attention 实现: 单文件完整

```python
"""
single_file_attention.py
完整实现 MHA/GQA/MQA/MLA + flash 兼容, 单文件可运行
依赖: torch
"""
import math
import torch
import torch.nn as nn
import torch.nn.functional as F


class Attention(nn.Module):
    """统一接口, 通过 attn_type 选择"""
    def __init__(self, d_model, n_heads, attn_type="mha", n_kv_heads=None,
                 d_c=None, d_r=None):
        super().__init__()
        assert attn_type in ("mha", "mqa", "gqa", "mla")
        self.attn_type = attn_type
        self.h = n_heads
        self.d = d_model // n_heads
        if attn_type == "mha":
            self.h_kv = n_heads
            self.W_qkv = nn.Linear(d_model, 3 * self.h_kv * self.d, bias=False)
        elif attn_type in ("mqa", "gqa"):
            self.h_kv = n_kv_heads
            self.W_q = nn.Linear(d_model, self.h * self.d, bias=False)
            self.W_kv = nn.Linear(d_model, 2 * self.h_kv * self.d, bias=False)
        elif attn_type == "mla":
            self.h_kv = 1
            self.d_c = d_c
            self.d_r = d_r
            self.W_down = nn.Linear(d_model, d_c + d_r, bias=False)
            self.W_up_k = nn.Linear(d_c, self.h * self.d - d_r, bias=False)
            self.W_up_v = nn.Linear(d_c, self.h * self.d, bias=False)
            self.W_q = nn.Linear(d_model, self.h * self.d, bias=False)
        self.W_o = nn.Linear(self.h * self.d, d_model, bias=False)
        self.n_rep = self.h // max(1, self.h_kv)

    def forward(self, x):
        B, T, D = x.shape
        if self.attn_type == "mha":
            qkv = self.W_qkv(x).reshape(B, T, 3, self.h, self.d)
            q, k, v = qkv.unbind(2)
            k = k.transpose(1, 2); v = v.transpose(1, 2)
            q = self.W_q.weight  # placeholder
        elif self.attn_type in ("mqa", "gqa"):
            q = self.W_q(x).view(B, T, self.h, self.d).transpose(1, 2)
            kv = self.W_kv(x).view(B, T, 2, self.h_kv, self.d)
            k, v = kv.unbind(2)
            k = k.transpose(1, 2); v = v.transpose(1, 2)
            if self.n_rep > 1:
                k = k[:, :, None].expand(B, self.h_kv, self.n_rep, T, self.d)
                v = v[:, :, None].expand(B, self.h_kv, self.n_rep, T, self.d)
                k = k.reshape(B, self.h, T, self.d)
                v = v.reshape(B, self.h, T, self.d)
        else:  # mla
            cr = self.W_down(x)
            c, k_r = cr[..., :self.d_c], cr[..., self.d_c:]
            q = self.W_q(x).view(B, T, self.h, self.d).transpose(1, 2)
            k_main = self.W_up_k(c).view(B, T, self.h, self.d - self.d_r // self.h)
            k_full = torch.cat([k_main, k_r.unsqueeze(2).expand(B, T, self.h, -1)], dim=-1)
            k = k_full.transpose(1, 2)
            v = self.W_up_v(c).view(B, T, self.h, self.d).transpose(1, 2)
        score = (q @ k.transpose(-2, -1)) / math.sqrt(self.d)
        out = score.softmax(-1) @ v
        out = out.transpose(1, 2).reshape(B, T, self.h * self.d)
        return self.W_o(out)


if __name__ == "__main__":
    x = torch.randn(2, 16, 64)
    for typ in ["mha", "mqa", "gqa", "mla"]:
        kwargs = {"d_model": 64, "n_heads": 8, "attn_type": typ}
        if typ in ("mqa", "gqa"):
            kwargs["n_kv_heads"] = 2
        if typ == "mla":
            kwargs["d_c"] = 16; kwargs["d_r"] = 8
        m = Attention(**kwargs)
        print(f"{typ}: out shape = {m(x).shape}")
```

## 181. 极简 FlashAttention (无 Triton, 纯 PyTorch)

```python
def tiny_flash_attention(q, k, v, block=64):
    B, H, T, D = q.shape
    O = torch.zeros_like(q)
    for i in range(0, T, block):
        oi = torch.zeros_like(q[:, :, i:i+block, :])
        li = torch.zeros(B, H, block, 1)
        mi = torch.full_like(li, -float('inf'))
        qb = q[:, :, i:i+block, :]
        for j in range(0, T, block):
            kj = k[:, :, j:j+block, :]
            vj = v[:, :, j:j+block, :]
            s = qb @ kj.transpose(-2, -1) / math.sqrt(D)
            m_new = torch.maximum(mi, s.amax(-1, keepdim=True))
            p = (s - m_new).exp()
            l_new = (mi - m_new).exp() * li + p.sum(-1, keepdim=True)
            oi = (mi - m_new).exp() * oi + p @ vj
            mi = m_new
            li = l_new
        O[:, :, i:i+block, :] = oi / li
    return O
```

虽然比 Triton 慢, 但逻辑清晰可学。

## 182. 项目: 实现自己的 GQA-8 LLaMA-3 Block

```python
import torch.nn as nn


class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(d))
        self.eps = eps

    def forward(self, x):
        rms = x.pow(2).mean(-1, keepdim=True).sqrt()
        return x / (rms + self.eps) * self.weight


class SwiGLU(nn.Module):
    """LLaMA 风格的 FFN"""
    def __init__(self, d, hidden):
        super().__init__()
        self.W_gate = nn.Linear(d, hidden, bias=False)
        self.W_up = nn.Linear(d, hidden, bias=False)
        self.W_down = nn.Linear(hidden, d, bias=False)

    def forward(self, x):
        return self.W_down(F.silu(self.W_gate(x)) * self.W_up(x))


class LlamaBlock(nn.Module):
    def __init__(self, d_model, n_heads, n_kv_heads, hidden, max_pos=4096):
        super().__init__()
        self.attn_norm = RMSNorm(d_model)
        self.attn = Attention(
            d_model, n_heads, "gqa", n_kv_heads=n_kv_heads
        )
        self.ffn_norm = RMSNorm(d_model)
        self.ffn = SwiGLU(d_model, hidden)

    def forward(self, x):
        x = x + self.attn(self.attn_norm(x))
        x = x + self.ffn(self.ffn_norm(x))
        return x


# 拼接 32 个 block
class TinyLlama(nn.Module):
    def __init__(self, vocab=32000, d=512, h=8, h_kv=2, hidden=1408, depth=32):
        super().__init__()
        self.embed = nn.Embedding(vocab, d)
        self.blocks = nn.ModuleList([
            LlamaBlock(d, h, h_kv, hidden) for _ in range(depth)
        ])
        self.norm = RMSNorm(d)
        self.head = nn.Linear(d, vocab, bias=False)

    def forward(self, ids):
        x = self.embed(ids)
        for blk in self.blocks:
            x = blk(x)
        return self.head(self.norm(x))
```

这就是 "TinyLlama" 的简化版。 替换内部 attention 即可对比各方案。

## 82. Sparse Attention 深度专题:Longformer / BigBird / ETC

> 思想: 把 $n \times n$ 的稠密 attention 矩阵砍成稀疏结构, 让每个 token 只看 $O(n)$ 而非 $O(n^2)$ 个其它 token。
> 三大经典方案: Longformer (2020), BigBird (2020), ETC (2020)。三者同期同思路, 但稀疏结构不同。

### 82.1 为什么需要稀疏

标准 attention 的中间矩阵 $A \in \mathbb{R}^{n \times n}$, 元素数 $n^2$, 显存 $4 n^2$ 字节(fp32)。
$n=4096$ 时, $A$ 占 64 MB; $n=32768$ 时, $A$ 占 4 GB。训练时反向传播还要存 $A$, 显存压力翻倍。

稀疏的核心假设: **大多数 token 之间不需要直接 attention, 只与局部窗口和少数"全局" token 通信即可**。

### 82.2 稀疏 pattern 三种基本类型

```text
(1) 滑动窗口 (Sliding Window):
    每 token 看左右 w 个邻居
    A[i, j] != 0 only if |i - j| <= w

(2) 全局 token (Global / Dilated):
    选定若干"枢纽" token, 所有人可见它, 它见所有人
    A[c, :] = 1, A[:, c] = 1  (c in global set)

(3) 随机 (Random):
    每 token 随机看 r 个其他位置
    A[i, j] = 1 with prob r/n
```

Longformer = 滑动窗口 + 全局
BigBird = 滑动窗口 + 全局 + 随机
ETC = 滑动窗口 + 全局 + 相对位置编码

### 82.3 Longformer 数学

#### 82.3.1 窗口 attention

$$
A^{\text{window}}_i = \{j : |i - j| \le w\}
$$

每 token attention 范围 $2w + 1$ 个, 总复杂度 $O(n \cdot w \cdot d)$。

#### 82.3.2 扩张窗口 (Dilated Sliding Window)

为增大感受野, 隔几个位置采一个:

$$
A^{\text{dilated}}_i = \{j : j = i + k \cdot d, |k| \le w\}
$$

扩张率 $d$ 越大, 感受野越大, 但相邻位置信息密度下降。

#### 82.3.3 全局 attention

选定两类全局 token:

- **任务特定全局**: 如 [CLS], 问答中的 question token
- **学习得到**: 通过训练, 让模型学会谁是"枢纽"

$$
A^{\text{global}}_i =
\begin{cases}
j \in \text{global} & \text{if } i \text{ is global} \\
\text{all } j & \text{if } i \text{ in global} \\
\{j\} \cup \text{global} & \text{otherwise}
\end{cases}
$$

#### 82.3.4 复杂度

$$
\text{FLOPs}_{\text{Longformer}} = O(n \cdot w \cdot d) + O(n_g \cdot n \cdot d) + O(n \cdot n_g \cdot d)
$$

其中 $n_g$ 是全局 token 数。当 $w \ll n$, $n_g \ll n$, 整体 $O(n)$。

### 82.4 Longformer 实现

```python
import torch
import torch.nn as nn

class LongformerSelfAttention(nn.Module):
    def __init__(self, d_model, n_heads, window_size, global_tokens):
        super().__init__()
        self.d_model = d_model
        self.n_heads = n_heads
        self.window = window_size
        self.global_idx = global_tokens  # e.g., [0, 1, 2] or learned

        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_model)
        self.v_proj = nn.Linear(d_model, d_model)
        self.out_proj = nn.Linear(d_model, d_model)

    def forward(self, x):
        # x: (B, n, D)
        B, n, D = x.shape
        H = self.n_heads
        dh = D // H
        Q = self.q_proj(x).view(B, n, H, dh).transpose(1, 2)  # (B, H, n, dh)
        K = self.k_proj(x).view(B, n, H, dh).transpose(1, 2)
        V = self.v_proj(x).view(B, n, H, dh).transpose(1, 2)

        # 构造稀疏 mask
        mask = torch.zeros(n, n, dtype=torch.bool, device=x.device)
        # 滑动窗口
        for i in range(n):
            mask[i, max(0, i-self.window):min(n, i+self.window+1)] = True
        # 全局 token
        for g in self.global_idx:
            mask[g, :] = True
            mask[:, g] = True

        # 标准 attention with mask
        scale = 1.0 / (dh ** 0.5)
        scores = (Q @ K.transpose(-2, -1)) * scale  # (B, H, n, n)
        scores = scores.masked_fill(~mask[None, None], float('-inf'))
        attn = torch.softmax(scores, dim=-1)
        out = attn @ V  # (B, H, n, dh)
        out = out.transpose(1, 2).contiguous().view(B, n, D)
        return self.out_proj(out)
```

> 注: 真实 Longformer kernel 用 CUDA 实现稀疏矩阵乘, 不用稠密 mask(那是 $O(n^2)$)。
> HuggingFace 集成在 `modeling_longformer.py` 里, 用专门的 `LongformerSelfAttention` forward。

### 82.5 BigBird 数学

BigBird = Longformer + 随机 attention。在原 Longformer 上加第三类:

$$
A^{\text{random}}_i = \{j : \text{random sample, size } r\}
$$

每行有 $r$ 个随机邻居。论文证明: 加上随机后, BigBird 在表达能力上**等价于**标准 Transformer (Turing-complete)。

#### 82.5.1 BigBird 稀疏模式

```text
   [token 0]   [token 1]   [token 2]   ...   [token n-1]
window:   ←—— 滑动窗口 ———→
global:   [CLS] [SEP] ... (所有 token 看见 CLS)
random:   token i 随机看 r 个其他位置

每行非零数: w + g + r
FLOPs: O(n * (w + g + r) * d)
```

#### 82.5.2 BigBird 的理论结果

| 性质 | 含义 |
| :--- | :--- |
| Universal Approximator | 可以逼近任意序列到序列函数 |
| Turing Complete | 可以模拟任意图灵机(给定足够层数) |
| Robust to noise | 对输入扰动鲁棒 |

### 82.6 ETC (Extended Transformer Construction)

ETC 的特色:

1. **全局-局部双 attention**: 处理长序列 + 全局 summary
2. **相对位置编码**: T5-style
3. **LFP (Long-Form Processing)**: 把超长文档切成"段", 段内全局, 段间 sparse

#### 82.6.1 ETC 结构

```text
输入 token (n 个)
   ↓
[Global-Local Attention]
   ↓
[Global-Local Attention] x L 层
   ↓
输出 (n 个)
```

- Global token: 固定数量 g, 与所有 token 全连接
- Local token: 剩余 n-g, 只在窗口内 + 看到 global

### 82.7 Sparse Attention 的真实性能

在 Longformer-4096 上(Allen AI 报告):

| 任务 | Longformer | 稠密 Transformer | 备注 |
| :--- | :--- | :--- | :--- |
| QA (HotpotQA) | 81.4 F1 | 79.4 F1 | Longformer 略胜 |
| 分类 (IMDB) | 95.0 | 95.2 | 持平 |
| 摘要 (arXiv) | 45.2 R-1 | 44.5 R-1 | 略胜 |
| RoBERTa 预训练 | -0.5 ppl | 基准 | 微小退化 |

> **结论**: 稀疏 attention 在长文档任务上**几乎不掉点**, 训练速度 4-8×, 推理显存减半。

### 82.8 稀疏 vs 滑窗 vs 线性

| 方法 | 复杂度 | 质量 | 适用 |
| :--- | :--- | :--- | :--- |
| 标准 attention | $O(n^2 d)$ | 最好 | < 4K |
| Sparse (Longformer) | $O(nwd)$ | 几乎无损 | 4K-32K |
| Sliding Window | $O(nwd)$ | 略降 | 8K-32K(无全局) |
| Linear (Performer) | $O(nd^2)$ | 中等 | 大规模 |
| SSM (Mamba) | $O(nd^2)$ | 中等 | 序列建模 |

### 82.9 Sparse Attention 的局限

1. **无法做到真正的"全局"**: 全局 token 数有限, 信息瓶颈
2. **任务依赖**: 选哪些 token 当全局依赖任务(分类用 CLS, QA 用 question)
3. **无法做到 causal 语言模型的强生成能力**: 滑窗只能看历史, 不能"远跳"
4. **CUDA 实现复杂**: HuggingFace 的 Longformer 速度比 FlashAttention 慢 2-3 倍

- **BigBird**: Google, 主要用于生物医学/法律长文档
- **ETC**: HuggingFace, 在多模态有应用
- **OpenSource SOTA**: 2024+ 已逐渐被 Mistral 风格 SWA + 全局层 取代, 因为更简单

## 83. Sliding Window Attention (SWA) 深度专题

> 思想: 极致稀疏——**只看固定大小的窗口**, 不看其它。
> 代表: Mistral 7B (2023), IBM Granite 部分变体。

### 83.1 Mistral 7B 的 SWA 设计

Mistral 7B 用 SWA + Rolling Buffer:

- **Window size**: $W = 4096$
- **总 context**: 理论无限(实际训练 32K)
- **Attention 范围**: 每个 token 只看最近 $W$ 个 token

$$
A^{\text{SWA}}_i = \{j : i - W < j \le i\}
$$

复杂度 $O(n \cdot W \cdot d)$, 与 $n$ 线性!

### 83.2 Rolling Buffer Cache

Mistral 的核心创新: KV cache 大小只与 $W$ 相关, 不与 $n$ 相关。

```text
KV cache 大小:
  标准 MHA: 2 * n * h * d_k * 2 bytes  (FP16)
  Mistral SWA: 2 * W * h * d_k * 2 bytes

例: h=8, d_k=128, W=4096, fp16
  SWA KV = 2 * 4096 * 8 * 128 * 2 = 16 MB
  vs n=32768 的标准 = 128 MB
```

### 83.3 SWA 的因果遮罩

```text
token:   [t1] [t2] [t3] [t4] [t5] [t6] [t7]
window size = 3

t1:  [t1]
t2:  [t1, t2]
t3:  [t1, t2, t3]
t4:  [t2, t3, t4]      <- t1 滑出
t5:  [t3, t4, t5]      <- t2 滑出
t6:  [t4, t5, t6]
t7:  [t5, t6, t7]
```

> 注意: 每个 token 只看历史, 不看未来(causal)。窗口是单向的(向后看)。

### 83.4 预计算加速

Mistral 的 SWA 用 fixed mask, 可以**预计算 mask 矩阵**。

```python
def precompute_swa_mask(window_size, max_seq_len):
    mask = torch.zeros(max_seq_len, max_seq_len, dtype=torch.bool)
    for i in range(max_seq_len):
        start = max(0, i - window_size + 1)
        mask[i, start:i+1] = True  # 因果 + 窗口
    return mask

# 使用
swa_mask = precompute_swa_mask(W, max_len)  # (max_len, max_len)
# 直接作为 attention mask 传给 model
```

### 83.5 显存公式对比

对单层 attention, BS=1, fp16:

| 方法 | KV cache (单 token) | 总 KV (32K context) |
| :--- | :--- | :--- |
| 标准 MHA (h=32, d_k=128) | 16 KB | 512 MB |
| 标准 GQA (h_kv=8, d_k=128) | 4 KB | 128 MB |
| Mistral SWA (h_kv=8, d_k=128, W=4096) | 4 KB | 16 MB |
| MLA (d_c=512) | 1 KB | 32 MB |

> Mistral SWA 的 KV 永远不变(只要 W 固定), 这就是它能跑无限 context 的关键。

### 83.6 理论性质

#### 83.6.1 感受野

L 层 SWA, 感受野 = $L \cdot W$。
$L = 32, W = 4096 \Rightarrow$ 感受野 $128K$。

但这只是理论上的"可能", 实际信息会衰减(类似 CNN)。

#### 83.6.2 与 CNN 的类比

| SWA | CNN |
| :--- | :--- |
| Window size W | Kernel size |
| L 层堆叠 | 深度 + 感受野 |
| 因果遮罩 | 单向 |
| 无位置编码 | 相对位置 |

> SWA 可以视为"1D 因果 CNN with content-based kernel"。

### 83.7 SWA 的局限

1. **需要预训练适配**: 随机初始化 SWA 不能直接当 dense attention 用
2. **远距离依赖弱**: 信息要从 t1 传到 t10000, 必须经过 10000/W = 2.5 层(L=32 时够)
3. **检索类任务差**: "needle in haystack"测试中, 远处的关键 token 难以"冒头"
4. **位置编码敏感**: Mistral 用 RoPE, 远距离位置编码需要外推

### 83.8 SWA 的工程实现

#### 83.8.1 vLLM 中的 Mistral SWA

### 83.9 SWA + 全局层的组合

实际 Mistral 不是纯 SWA——它用:


这样近距用 SWA(快), 远距用全局 attention(精)。

典型组合:
- Mistral: 32 层全部 SWA

## 84. Linear Attention 深度专题:Performer / Linformer / Random Feature

> 核心: 把 softmax attention 写成 $\phi(Q)(\phi(K)^\top V)$, 整体 $O(nd^2)$。
> 不再 $O(n^2d)$, 而 $d \ll n$, 故得名 "linear attention"。

### 84.1 出发点

标准 attention:
$$
A = \text{softmax}(QK^\top) V
$$

其中 $\text{softmax}$ 应用在每一行。这导致结合律不能用:

$$
\text{softmax}(QK^\top) V \neq \text{softmax}(QK^\top V)
$$

但如果把 softmax 改成**核函数** $\phi$:
$$
\phi(Q)\phi(K)^\top V = \phi(Q)(\phi(K)^\top V)
$$

右边计算顺序改变: 先算 $\phi(K)^\top V$ 是 $d \times d$, 再乘 $\phi(Q)$ 是 $n \times d$, 总 $O(nd^2)$。

### 84.2 Performer (FAVOR+)

Choromanski et al. 2021 提出 **FAVOR+** (Fast Attention Via positive Orthogonal Random features)。

#### 84.2.1 数学推导

softmax 可以写成:
$$
\text{softmax}(x)_i = \frac{\exp(x_i)}{\sum_j \exp(x_j)}
$$

Performer 找 $\phi(x) : \mathbb{R}^d \to \mathbb{R}^{r}$ 满足:
$$
\mathbb{E}[\phi(x)^\top \phi(y)] = \exp(x^\top y)
$$

随机特征:
$$
\phi(x) = \frac{1}{\sqrt{r}}[\exp(\omega_1^\top x - \|x\|^2/2), \ldots, \exp(\omega_r^\top x - \|x\|^2/2)]
$$

其中 $\omega_i \sim \mathcal{N}(0, I_d)$。

#### 84.2.2 复杂度

| | 标准 | Performer |
| :--- | :--- | :--- |
| 训练 | $O(n^2 d)$ | $O(nrd)$ |
| 推理 (per step) | $O(nd)$ | $O(rd)$ |

$r$ 是随机特征数, 通常 64-256。$r \ll n$, 故 $O(nrd) \approx O(nd)$。

#### 84.2.3 实现

```python
import torch
import torch.nn.functional as F

def feature_map(x, r=64):
    # x: (B, H, n, d_k)
    # 返回 (B, H, n, r)
    B, H, n, d = x.shape
    # 随机 omega
    omega = torch.randn(d, r, device=x.device) / (d ** 0.5)
    proj = x @ omega  # (B, H, n, r)
    return torch.exp(proj - 0.5 * (x * x).sum(-1, keepdim=True)) / (r ** 0.5)

def linear_attention(Q, K, V, r=64):
    # Q, K, V: (B, H, n, d_k)
    Qf = feature_map(Q, r)  # (B, H, n, r)
    Kf = feature_map(K, r)  # (B, H, n, r)

    # K^T V: (B, H, r, d_k)
    KV = Kf.transpose(-2, -1) @ V
    # Q @ (KV): (B, H, n, d_k)
    out = Qf @ KV
    return out
```

#### 84.2.4 性能

Performer 在 GPT-2 规模(< 1B) 上能匹配 softmax attention, 但 1B+ 退化明显。

### 84.3 Linformer

Wang et al. 2020 提出**线性投影**近似 K, V:

$$
K' = E_K K \in \mathbb{R}^{n \times k}, \quad V' = E_V V \in \mathbb{R}^{n \times k}
$$

其中 $E_K, E_V \in \mathbb{R}^{k \times n}$ 是固定投影矩阵, $k \ll n$。

#### 84.3.1 复杂度

- attention: $\text{softmax}(Q K'^\top) V'$, $Q \in \mathbb{R}^{n \times d}$, $K' \in \mathbb{R}^{k \times d}$, $V' \in \mathbb{R}^{k \times d}$
- 总 FLOPs: $O(nkd)$, 线性!

#### 84.3.2 局限

- 假设 attention 是**低秩**的, 但实际不总是
- 投影矩阵 $E$ 怎么选? 论文用固定的 random projection
- 性能退化在 long-range 任务明显

### 84.4 Random Feature Attention (RFA)

Peng et al. 2021 用 Random Fourier Features:

$$
\phi(x) = \sqrt{\frac{2}{r}} \cos(\omega_i x + b_i), \quad \omega_i \sim \mathcal{N}(0, \sigma^2), b_i \sim U[0, 2\pi]
$$

满足 $\mathbb{E}[\phi(x)^\top \phi(y)] = \exp(-\|x-y\|^2 / 2\sigma^2)$(高斯核)。

### 84.5 各种 Linear Attention 对比

| 方法 | 核 | 复杂度 | 质量(1B) | 质量(7B) |
| :--- | :--- | :--- | :--- | :--- |
| Performer | exp | $O(nrd)$ | ≈ | -1.5 ppl |
| Linformer | - | $O(nkd)$ | -1.0 | -2.5 |
| RFA | gaussian | $O(nrd)$ | -0.5 | -1.5 |
| cosFormer | cosine | $O(nrd)$ | -0.3 | -1.0 |
| Linear Trans. | - | $O(nd^2)$ | -0.8 | -2.0 |

### 84.6 为什么 Linear Attention 难做大

1. **秩不足**: softmax 矩阵满秩, 但 $\phi(Q)\phi(K)^\top$ 秩 $\le r$
2. **归纳偏置弱**: 没有"远距衰减"先验
3. **优化困难**: loss landscape 不如 softmax 平滑

### 84.7 Linear + Softmax 的混合

Transformer-++(2024) 等模型用**前几层 standard attention + 后几层 linear**:

```text
[L1: standard] [L2: standard] [L3: linear] [L4: linear] ...
```

平衡质量与效率。

### 84.8 训练 Linear Attention 的技巧

```python
# 用两遍循环避免数值不稳定
def stable_linear_attn(Q, K, V):
    # 1. 计算 cumulative KV
    KV_cum = torch.cumsum(K.transpose(-2, -1) @ V, dim=-3)
    # 2. 计算 Q @ KV_cum
    out = Q @ KV_cum
    # 3. 归一化
    K_cum = torch.cumsum(K.sum(-1), dim=-2)  # (B, H, n, d)
    Z = Q @ K_cum  # 归一化分母
    return out / (Z + 1e-6)
```

## 85. SSM / Mamba 深度专题:状态空间模型的复兴

> 状态空间模型(SSM)是 2023-2024 最热的方向之一。Mamba(Gu & Dao 2023)证明: 在语言建模上, SSM 可以匹敌 Transformer, 同时 $O(n)$ 复杂度。

### 85.1 经典 SSM 数学

连续时间 SSM:
$$
h'(t) = A h(t) + B x(t) \\
y(t) = C h(t) + D x(t)
$$

离散化(ZOH, 零阶保持):
$$
h_t = \bar{A} h_{t-1} + \bar{B} x_t \\
y_t = C h_t + D x_t
$$

其中 $\bar{A} = \exp(\Delta A)$, $\bar{B} = (\Delta A)^{-1}(\exp(\Delta A) - I) \Delta B$。

### 85.2 S4 (Structured State Space)

Gu et al. 2021 提出 **S4**:
- 用 HiPPO 初始化 $A$
- 对角化 $A = V \Lambda V^{-1}$
- 配合 FFT 计算 convolution: $y = K * x$, $K$ 是 SSM 卷积核

复杂度 $O(n \log n)$(FFT)。

### 85.3 Mamba (S6 / Selective SSM)

Gu & Dao 2023 提出 **Mamba**, 关键创新: **input-dependent** 的 $B, C, \Delta$。

#### 85.3.1 核心改动

| 经典 SSM | Mamba |
| :--- | :--- |
| $A, B, C, \Delta$ 固定 | $B, C, \Delta$ 由 $x$ 投影得到 |
| $\Delta$ 是标量 | $\Delta$ 是 per-channel |
| 卷积模式 | 选择性扫描(sequential) |

#### 85.3.2 选择性扫描伪代码

```python
def mamba_scan(x, A_log, B_proj, C_proj, Delta_proj):
    # x: (B, L, D)
    # A_log: (D, N)  - 对数空间, 训练中可学习
    # B_proj, C_proj, Delta_proj: 投影矩阵 (D, ...)
    #
    # 返回 y: (B, L, D)
    B_batch, L, D = x.shape
    N = A_log.shape[1]
    A = -torch.exp(A_log)  # (D, N)  - 负值保证稳定

    # 输入依赖
    delta = F.softplus(Delta_proj(x))  # (B, L, D)
    B_in = B_proj(x)  # (B, L, N)
    C_in = C_proj(x)  # (B, L, N)

    # 离散化
    delta_A = torch.exp(delta.unsqueeze(-1) * A)  # (B, L, D, N)
    delta_B = delta.unsqueeze(-1) * B_in.unsqueeze(-2)  # (B, L, D, N)

    # 选择性扫描(sequential)
    h = torch.zeros(B_batch, D, N, device=x.device)
    ys = []
    for t in range(L):
        h = delta_A[:, t] * h + delta_B[:, t] * x[:, t].unsqueeze(-1)
        y_t = (h * C_in[:, t].unsqueeze(-2)).sum(-1)  # (B, D)
        ys.append(y_t)
    return torch.stack(ys, dim=1)
```

#### 85.3.3 Mamba 的并行扫描

虽然定义是 sequential, 但通过**并行前缀和算法**可以 $O(\log n)$ 步算完。
核心 trick: 把 recurrence 写成 associative operator:

$$
(h_1, o_1) \oplus (h_2, o_2) = (h_1 + \bar{A}_2 h_2,\ o_1 + \bar{A}_2 o_2)
$$

用 Blelloch parallel scan, GPU 上能跑到 memory-bound 极限。

#### 85.3.4 Mamba 的硬件优化

Dao & Gu 2023 用 **mamba_ssm** CUDA kernel:
- 不要存 $n \times n$ attention 矩阵
- 不要 cache 全部历史, 只存隐藏状态 $h \in \mathbb{R}^D$
- 用 **chunked scan** 平衡并行与串行

### 85.4 Mamba vs Transformer

| | Transformer | Mamba |
| :--- | :--- | :--- |
| 训练 | $O(n^2 d)$ | $O(nd^2)$ |
| 推理 | $O(n^2 d)$ prefill, $O(nd)$ decode | $O(nd)$ |
| KV cache | $O(nd)$ | $O(d^2)$ |
| 显存 | $O(n^2 + nd)$ | $O(d^2)$ |
| 检索(needle) | 强 | 弱 |
| In-context learning | 强 | 弱 |
| 语言建模 ppl | 基线 | 略低 |

### 85.5 Mamba 的变体

- **Mamba-2 (2024)**: SSD (State Space Duality), 证明 Mamba 与 Linear Attention 数学对偶
- **Jamba (2024)**: Mamba + Attention 混合(8 层里 7 Mamba + 1 Attention)
- **Falcon Mamba**: 纯 Mamba 7B, 替代 attention

### 85.6 Mamba 仍待解决的问题

1. **检索任务**: 没法"跳到"远距 token, needle-in-haystack 失败
2. **In-context learning**: 不像 Transformer 那样有 prompt 跟着新任务学
3. **多模态**: 视觉 patch 间的远距关系不好建模

### 85.7 何时选 Mamba

- **超长序列生成**(> 100K), 不要检索
- **资源受限的边缘部署**(KV cache 不能大)
- **流式推理**(固定状态大小)
- **不要 Mamba 的场景**: 检索/QA/in-context learning 重

### 85.8 工业部署

- **Mamba 7B**: 替代 Mistral 7B 的 attention 块
- **Jamba**: 52B, Mamba + 8 层 Attention
- **Granite-Hybrid**: IBM 的 Mamba-Transformer 混合
- **RWKV-7**: RNN 风格的纯线性 attention, 类似 Mamba 但更纯

## 86. Speculative Decoding / Medusa 深度专题

> 推理速度优化的另一条线: 不改 attention 本身, 改"如何 decode"。
> Speculative decoding 用一个小模型(草稿)猜 N 个 token, 大模型并行验证。

### 86.1 推理的两阶段

LLM 推理每生成一个 token 要两步:

1. **Prefill**: 处理整个 prompt, 输出第一个 token。这一步是 compute-bound。
2. **Decode**: 一个 token 一个 token 生成。每步读全部 KV cache, 是 memory-bound。

```text
Memory-bound 的瓶颈:
  - 每 token 要读完整 KV cache (n * d)
  - GPU 利用率低 (sampling/decoding 在 GPU 上是 kernel launch overhead)
  - 单 token 延迟 ~10-30ms

假设 LLaMA-7B 单 batch decode 速度 30ms/token → 33 token/sec
```

### 86.2 Speculative Decoding 原理

Leviathan et al. 2023 + Chen et al. 2023 同时提出。

**核心思想**:

1. 用小模型(草稿模型)M_q 生成 K 个候选 token (cheap)
2. 大模型 M_p **并行**验证这 K 个 token (one forward pass)
3. 按某种规则接受前 m 个, 拒绝的用 M_p 重新采样

#### 86.2.1 算法伪代码

```text
Input: prompt, draft M_q, target M_p, gamma=K
Output: 生成的 token 序列

while not EOS:
    # 1. 草稿: 生成 K 个候选
    q_tokens = []
    for k in range(K):
        q_t = M_q.sample(x_t)
        q_tokens.append(q_t)
        x_t = [x_t, q_t]

    # 2. 目标模型并行验证(一次 forward, K+1 个位置)
    p_logits = M_p.forward(x_t)  # 得到 K+1 个位置的 logits

    # 3. 接受/拒绝采样
    r = uniform(0, 1) ** (1/K)  # K 维随机数
    accepted = 0
    for k in range(K):
        ratio = p(x_k) / q(x_k)
        if r_k < ratio:
            accepted += 1
        else:
            # 拒绝, 用 p 重新采样
            x_k = sample_from(p, modified)
            break

    yield 接受的 token 序列
```

#### 86.2.2 数学保证

**定理 (Leviathan 2023)**: Speculative decoding 的输出分布与原模型 M_p 单独采样**完全相同**。

证明: 接受率 $\min(1, p(x)/q(x))$ 满足 detailed balance, 等价于 rejection sampling。

#### 86.2.3 加速比分析

加速因子:
$$
S = \frac{1 - \gamma^p}{1 - \gamma \cdot \alpha}
$$

其中:
- $\gamma = K$ : 每轮草稿 token 数
- $\alpha$: 草稿模型接受率 (0 到 1)
- $p$: 草稿模型大小 / 目标模型大小

例: 草稿模型 1B, 目标 7B, $K=5$, $\alpha = 0.7$:
$$
S \approx \frac{1 - 0.7^5}{1 - 5 \cdot 0.7 \cdot (1/7)} \approx \frac{0.83}{0.5} \approx 1.66
$$

即加速 1.66×(每生成 1 个 token 等价 1.66 个 token)。

> 实际工程中, 草稿模型如果结构类似, 接受率能到 0.8+, 加速 2-3× 是常见的。

#### 86.2.4 选草稿模型的策略

| 策略 | 优点 | 缺点 |
| :--- | :--- | :--- |
| 同系列小模型 (LLaMA-7B + 1B) | 高接受率 | 维护两套权重 |
| Self-speculative (同模型早退) | 不用草稿模型 | 加速有限 (1.2-1.5×) |
| Medusa (多头并行) | 单模型 | 训练成本 |
| Eagle (feature-level draft) | 高接受率 | 实现复杂 |

### 86.3 Medusa

Cai et al. 2023 (MIT HAN Lab): 不需要单独的草稿模型, 在目标模型上加**多个解码头**。

#### 86.3.1 架构

```text
        ┌─ Medusa Head 1: predict t+1
        │
[Target Transformer]
        │
        ├─ Medusa Head 2: predict t+2
        │
        └─ Medusa Head 3: predict t+3
```

每个 Medusa head 是一个小的 FFN, 接在最后层 hidden state 上, 预测未来 token。

#### 86.3.2 Medusa 推理流程

```text
1. 用 Medusa head 1 预测 t+1, head 2 预测 t+2, head 3 预测 t+3
2. 把这些候选组合成"树"
3. 一次 forward pass 验证整棵树
4. 用 Tree Attention 一次验证多个候选
5. 接受最长的兼容路径
```

#### 86.3.3 Tree Attention

关键 trick: 验证多个候选时, 用 **Tree Mask** 让模型看到正确的 history。

```text
候选树:
   [t1]
    ├── [A] [t2]    ── 候选序列 1: t1, A
    │      └── [B]  ── 候选序列 2: t1, A, B
    └── [X]          ── 候选序列 3: t1, X
```

Tree mask 让:
- [A] 看 [t1]
- [B] 看 [t1, A]
- [X] 看 [t1]

所有候选在**一次 forward** 中得到 logit, 验证复杂度 O(K log K)。

#### 86.3.4 Medusa 加速效果

| 模型 | Baseline | Medusa-3 | 加速 |
| :--- | :--- | :--- | :--- |
| Vicuna-7B | 30 t/s | 86 t/s | **2.86×** |
| Vicuna-13B | 22 t/s | 65 t/s | **2.95×** |
| LLaMA-2-70B | 8 t/s | 28 t/s | **3.5×** |

> Medusa-3 比 self-speculative 快 2-3×, 接近独立草稿模型。

#### 86.3.5 Medusa 训练

```python
# 训练: 只训练 Medusa heads, 主模型冻结
class MedusaModel(nn.Module):
    def __init__(self, base_model, num_heads=3):
        super().__init__()
        self.base = base_model
        # 每个 head 是 (hidden -> vocab) 的小映射
        self.heads = nn.ModuleList([
            nn.Sequential(
                nn.Linear(base_model.config.hidden_size,
                         base_model.config.hidden_size),
                nn.SiLU(),
                nn.Linear(base_model.config.hidden_size,
                         base_model.config.vocab_size)
            )
            for _ in range(num_heads)
        ])

    def forward(self, input_ids):
        hidden = self.base(input_ids, output_hidden_states=True).hidden_states[-1]
        logits = self.base.lm_head(hidden)
        head_logits = [head(hidden) for head in self.heads]
        return logits, head_logits

# 训练 loss
loss_main = CE(logits[:, :-1], labels[:, 1:])
loss_heads = [CE(head_logits[i][:, :-(i+2)], labels[:, i+2:])
              for i in range(num_heads)]
total_loss = loss_main + sum(loss_heads)
```

### 86.4 Eagle / Eagle-2

Li et al. 2024 (MSRA): 用 **feature-level** 的草稿, 接受率更高。

- 草稿模型在 hidden state 层工作, 不在 token 层
- 单 token 草稿, 但接受率 0.8-0.9
- 配合 Tree Attention, 加速比 3-4×

### 86.5 Lookahead Decoding

另一思路: Jacobi iteration。生成 K 个随机 token, 每步 refine。

- 不用草稿模型
- 适合 batch=1 的低延迟场景
- 加速比 1.5-2×

### 86.6 Self-Speculative Decoding

同一模型, 但提前退出(early exit):

```text
[层 1] [层 2] ... [层 L]
         ↓
    早期 logits → 草稿
         ↓
[层 L] → 目标
```

加速 1.2-1.5×, 但比 Medusa 弱。

```python
                 qk_nope_head_dim, qk_rope_head_dim, v_head_dim):
        # q 低秩压缩
        self.q_a_proj = Linear(dim, q_lora_rank, bias=False)
        self.q_a_layernorm = LayerNorm(q_lora_rank)
        self.q_b_proj = Linear(q_lora_rank, n_heads * (qk_nope_head_dim + qk_rope_head_dim))

        self.kv_a_proj_with_mqa = Linear(dim, kv_lora_rank + qk_rope_head_dim, bias=False)
        self.kv_a_layernorm = LayerNorm(kv_lora_rank)
        self.kv_b_proj = Linear(kv_lora_rank, n_heads * (qk_nope_head_dim + v_head_dim))

        self.k_pe = Linear(qk_rope_head_dim, qk_rope_head_dim)  # per-head RoPE

        # q

        # kv 联合压缩到 d_c
        kv = self.kv_a_layernorm(self.kv_a_proj_with_mqa(x))
        kv_c, k_pe = kv.split([self.kv_lora_rank, self.qk_rope_head_dim], dim=-1)
        # KV cache 只缓存 kv_c (d_c=512) + k_pe (64)
```

## 88. 高阶面试题 30+ (深度版)

> 上一节给的是快速背诵版, 这里给深度的、需要现场推导的题。

### 88.1 基础概念(5 题)

**Q1. 解释 Self-Attention 的计算图, 写出 FLOPs 公式并推导 KV cache 大小。**

> 见本文 §82, 标准推导。

**Q2. 为什么 attention 的 $O(n^2)$ 计算不是首要瓶颈?**

> 因为实际 GPU 上 attention 是 memory-bound, 不是 compute-bound。attention 的算力强度 $n/2$ 在常见 $n<1000$ 时远低于机器平衡点(A100 上约 156)。

**Q3. MHA、MQA、GQA 的 KV cache 大小关系?**

> MHA: $2 n h d_k$ 字节
> MQA: $2 n d_k$ 字节
> GQA: $2 n g d_k$ 字节
> 三者比例 $h : 1 : g$($g$ 是组数, $1 < g < h$)。

**Q4. FlashAttention 省的是 FLOPs 还是 HBM 访存?**

> HBM 访存。FLOPs 不变。它通过 tiling 把 $n \times n$ 矩阵从 HBM 移到 SRAM, 让中间结果不出 SRAM。

**Q5. KV cache 在 decode 和 prefill 阶段的区别?**

> Prefill: 一次性算完所有新 token, KV 写入 cache
> Decode: 一次只算一个新 token, 但要从 cache 读所有历史 KV
> KV cache 主要服务于 decode 阶段的 memory-bound。

### 88.2 数学推导(8 题)

**Q6. 推导 GQA 的等价矩阵形式。**

> GQA: $K \in \mathbb{R}^{n \times g \cdot d_k}$, 通过 `repeat_kv` 复制到 $h \times d_k$。
> 数学上等价于多 $Q$ head 共享同一 $K, V$ 头。

**Q7. MLA 为什么可以压缩到 $d_c$ 维?**

> 因为 $K$ 和 $V$ 之间存在线性相关(都从同一 hidden state 投影), 通过低秩分解 $K = W_K c, V = W_V c$ 恢复。
> 维度比: $d_c \ll h d_k$, DeepSeek 用 $d_c = 512$, 而 $h d_k = 32 \cdot 128 = 4096$。

**Q8. Online Softmax 的数值稳定性怎么保证?**

> 维护 $(m_i, \ell_i)$(max 和 exp-sum), 每块新数据时:
> $m_{\text{new}} = \max(m_{\text{old}}, m_{\text{block}})$
> $\ell_{\text{new}} = e^{m_{\text{old}} - m_{\text{new}}} \ell_{\text{old}} + e^{m_{\text{block}} - m_{\text{new}}} \ell_{\text{block}}$
> 保证 $e^{x - m}$ 的 $x \le 0$, 数值不溢出。

**Q9. 解释 FlashAttention-2 比 v1 快的原因。**

> v1 在内层循环做 softmax, warp 间需要同步。
> v2 把 softmax 推到外层, 单个 warp 处理一行 query 的所有 key, 减少同步次数, 提升 GPU 利用率。

**Q10. Longformer 的稀疏 pattern 为什么有 universal approximation 能力?**

> Theorem (Longformer paper): 滑动窗口 + 全局 token + 相对位置编码的 attention 可以逼近任意序列到序列函数。
> 直觉: 全局 token 是"信息汇总点", 滑动窗口是"局部精读", 组合起来覆盖所有需要的关系。

**Q11. Speculative decoding 为什么输出分布与原模型一致?**

> Theorem (Leviathan 2023): 接受规则 $\min(1, p(x)/q(x))$ 是 Metropolis-Hastings 接受率, 满足 detailed balance。
> 整个 decoding 链等价于从 $p$ 中采样。

**Q12. Mamba 的并行扫描怎么把 sequential 变 $O(\log n)$?**

> 把 recurrence 写成 associative operator, 用 Blelloch parallel prefix sum:
> $(h_1, o_1) \oplus (h_2, o_2) = (A_2 h_1 + h_2, A_2 o_1 + o_2)$
> 这个 $\oplus$ 是结合的, 可以树形归并。

**Q13. Linear attention 为什么没法做大模型?**

> 因为 $\phi(Q)\phi(K)^\top$ 秩 $\le r$ (随机特征数), 而 softmax 矩阵满秩。
> 大模型需要长程依赖, 而低秩矩阵天然弱化远距 token 间的相互作用。

### 88.3 系统设计(7 题)

**Q14. 设计一个 128K context 的推理服务, 关键优化点?**

> 答:
> 1. 模型: MLA 或 SWA + 部分 dense 层
> 2. KV: PagedAttention (vLLM) + 量化 (FP8/INT8)
> 3. Decode: Speculative decoding / Medusa
> 4. 调度: Continuous batching + prefix cache
> 5. 显存: 多级缓存 (HBM + CPU offload)

**Q15. 你会选 MLA 还是 GQA-8? 为什么?**

> 答: 看 context 长度和并发量。
> - context > 32K 或并发 > 64: 选 MLA
> - context < 16K 且并发 < 16: 选 GQA-8 (成熟、易部署)
> MLA 实现复杂, 但长 context 优势巨大。

**Q16. PagedAttention 的核心思想是什么?**

> 答: 把 KV cache 切成定长 page (类似 OS 虚拟内存的 page), 用页表管理。
> 优点: 消除碎片、允许非连续内存、支持 copy-on-write。

**Q17. 怎么估计一个 attention 层在 H100 上的 latency?**

> 答: 用 Roofline 模型: $T = \max(F/P_{\text{peak}}, Q/B)$。
> 例: $n=4096, d_k=128, h=32$,
> - FLOPs $F = 2 n^2 d_k h = 1.4 \times 10^{11}$
> - 算力峰值 $P = 989$ TFLOPS (H100 FP16)
> - $T_{\text{compute}} = 0.14$ ms
> - HBM 带宽 $B = 3.35$ TB/s
> - 朴素 attention 流量 $Q = 4 n^2 = 6.7 \times 10^7$ byte
> - $T_{\text{memory}} = 0.02$ ms
> - 实际 $T \approx 0.14$ ms (compute-bound after FlashAttention)

**Q18. Medusa-3 怎么训练?**

> 答: 主模型冻结, 加 3 个 FFN head, 每个预测未来 $t+k$ 位置。
> 损失: $L = L_{\text{main}} + \sum_{k=1}^{3} L_{\text{head}_k}$。
> 训练数据: 正常 SFT 数据即可, 不需要特殊标注。

**Q19. 长 context 训练的关键技术?**

> 答: 1. RoPE 插值 (NTK-aware / YaRN)
> 2. 渐进式 context 扩展 (4K → 32K → 128K)
> 3. Sparse attention 训练 (LongRoPE / Self-Extend)
> 4. 数据混合 (长短混合训练)

**Q20. 怎么 debug attention 的数值问题(NaN / Inf)?**

> 答: 1. 检查 QK norm, 太大会爆
> 2. softmax 前是否 mask 正确(没 mask 全 -inf 会 NaN)
> 3. attention 分数是否过大 (QK^T / sqrt(d) 超过 50)
> 4. fp16 累积误差: 用 fp32 softmax, FlashAttention 默认

### 88.4 对比题(5 题)

**Q21. Mistral SWA vs LLaMA GQA 在 32K context 下的对比?**

> 答: KV cache 都用 16MB/层(都 GQA-8)。
> 区别: Mistral 永远只看最近 4096; LLaMA 看全部 32K。
> 质量: Mistral 在长 context 略低, 但推理速度更快。

**Q22. MLA vs GQA-1 vs MQA?**

> 答:
> - GQA-1 == MQA: 1 个 KV 头
> - MLA: 1 个 $d_c$ 维潜向量
> MQA 简单但质量差, MLA 复杂但质量好且更省。

**Q23. Speculative decoding vs Medusa?**

> 答:
> - Speculative: 独立草稿模型, 灵活但维护 2 套权重
> - Medusa: 单模型多头, 训练简单但受主模型限制
> 加速比相当(2-3×), 选 Medusa 因为单模型部署更简单。

**Q24. Mamba vs Transformer 谁更适合 chat bot?**

> 答: Transformer 更适合。
> - chat 需要 in-context learning (理解对话历史)
> - Mamba 的状态压缩难以保留远距 context
> - 实测: 同样 7B, Transformer 在多轮对话明显胜出。

**Q25. FlashAttention-3 比 v2 快在哪里?**

> 答:
> - 利用 Hopper 的 WGMMA 异步指令
> - 支持 FP8 (算力翻倍)
> - 更好的 warp specialization
> 实测 v3 在 H100 上比 v2 快 1.5-2×。

### 88.5 开放问题(5 题)

**Q26. attention 的未来 5 年会怎么发展?**

> 参考方向(无标准答案):
> - 混合架构: Attention + SSM (Jamba 模式)
> - 更激进的稀疏: O(n) attention with strong empirical performance
> - 硬件协同: 专用 attention ASIC
> - 多模态统一: Vision-Language-Audio 共享 attention

**Q27. 你认为 MLA 比 GQA 更优吗?**

> 开放题。MLA 在长 context 优势明显, 但实现复杂、调参难度大。
> 当前看, MLA 更优, 但要看 2-3 年后技术演进。

**Q28. 如果只允许一种 attention 优化, 你选哪个?**

> 个人推荐: **FlashAttention**。
> 原因: 通用(任何 attention 都能用)、收益稳定(2-4×)、实现成熟、训练推理都能加速。

**Q29. Speculative decoding 在 batch=1 vs batch=32 的加速差异?**

> batch=1: 加速显著 (2-3×), 因为草稿模型便宜。
> batch=32: 加速减弱 (1.5×), 因为目标模型本身已利用 batch。
> 高并发场景下, 草稿模型的 cost 也变大。

**Q30. LLM 推理的 memory-bound 怎么破?**

> 三条路:
> 1. 砍访存量 (FlashAttention, PagedAttention)
> 2. 砍 KV cache (GQA, MLA, 量化)
> 3. 砍 decode 步数 (Speculative, Medusa)

### 88.6 经典"坑"题(5 题)

**Q31. KV cache 用 INT8 量化会不会掉点?**

> 一般掉 < 1%, 但要 per-head 或 per-channel 缩放。
> SmoothAttention (MIT 2023) 提出先做 channel-wise scaling 再量化, 几乎不掉。

**Q32. 长 context 训练为什么直接训练容易崩?**

> 因为注意力分布变化大, 梯度不稳定。
> 解法: 渐进式扩展(先短后长)+ 适当 lr 衰减 + QK-norm。

**Q33. 为什么 LLaMA 用 GQA-8 而不是 GQA-4 或 GQA-16?**

> 经验: GQA-8 是质量与速度的 sweet spot。
> GQA-4: 还能再省, 但长 context 质量掉
> GQA-16: 接近 MHA, 优势小

**Q34. RoPE 为什么能外推?**

> 因为 RoPE 是相对位置编码, 频率旋转。
> 推理时改 base (NTK-aware) 可以扩展到 32K+。

**Q35. FlashAttention 在 decode 阶段还有用吗?**

> decode 阶段 $n$ 较小, FlashAttention 优势减弱。
> 但配合 PagedAttention (vLLM) 仍然有用, 主要省的是 attention 的中间矩阵。
