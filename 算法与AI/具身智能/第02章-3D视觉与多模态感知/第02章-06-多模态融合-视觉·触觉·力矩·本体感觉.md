# 第02章-06-多模态融合-视觉·触觉·力矩·本体感觉

,在第 4 章会看到 VLA 模型如何"看图说话"。但你可能没意识到一件事:无论 VLA 模型多强,它本质上是个**纯视觉系统**,把所有感知压缩成像素流。
>
> 真实机器人在抓一只鸡蛋时,需要的不是"看清鸡蛋",而是"感觉到鸡蛋的滑、软、易碎"。这件事靠 RGB 相机做不到,只能靠**触觉传感器**。同样,协作机器人在和人类握手时需要力反馈,无人机抗风需要 IMU,机械臂精细操作需要关节力矩。这些都是视觉之外的"另一种感知"。
>
> 这一章要回答的核心问题:
> - **机器人有哪些"五感"?** 视觉、触觉、力矩、本体感觉、听觉……各自捕捉什么信号?
> - **为什么单视觉不够?** 单目深度估计、镜面反射、透明物体、遮挡……视觉的硬伤在哪?
> - **多模态怎么融合?** 早期融合(像素+触觉图)、中期融合(特征级 Cross-Attention)、晚期融合(决策加权)各自适合什么场景?
> - **VLA 为什么需要触觉输入?** RT-2 / π0 / OpenVLA 的多模态扩展是怎么做的?
>
> 这一章给出的三件武器,贯穿整个文件夹:
> - **触觉编码器 (Tactile Encoder)** = GelSight / DIGIT 输出的"压力图",与 RGB 图同构
> - **多模态融合 (Multimodal Fusion)** = Token 化 + Cross-Attention + Mixture-of-Experts
> - **传感器标定 (Sensor Calibration)** = 时间同步、空间对齐、模态校准
>
> 全部从直觉开始,慢慢形式化,最后落到 PyTorch 代码和 GelSight-mini 数据集的实测。

## 1. 直觉引入:机器人的"五感"

### 1.1 工程师的痛点:VLA 抓不住鸡蛋

你训练过一个 VLA 模型 (比如 OpenVLA, π0), 让它"把鸡蛋从盒子里拿出来"。在仿真里成功率 90%,放到真实机器人上掉了 30 个百分点。出了什么问题?

打开失败案例的视频,你看到的画面很清晰:模型"看见"了鸡蛋,也知道要靠近、抓取、提起。但它不知道:
- 鸡蛋表面有多滑? (摩擦系数)
- 它用了多大的力? (抓力 vs 鸡蛋破裂力)
- 鸡蛋是否在指间滑动? (滑动检测)
- 关节是不是因为撞到盒壁而在抖? (力矩异常)

这些信息**全部不在 RGB 图像里**。RGB 告诉你"鸡蛋长什么样",但不告诉你"鸡蛋摸起来怎么样、捏起来怎么样"。

这就是这一章要解决的问题:**让机器人拥有"五感"**,从单一视觉扩展到视觉+触觉+力矩+本体感觉的多模态感知系统。

### 1.2 机器人的"五感"对比人类

人类有五种基本感觉:视觉、听觉、触觉、味觉、嗅觉。机器人有类似的但不完全对应的"五感":

| 人类感觉 | 机器人对应 | 典型传感器 | 信号类型 | 频率范围 | 空间分辨率 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **视觉** | RGB 相机 | Realsense D435, ZED 2i | (H×W×3) uint8 | 30 Hz | 1-2 MP |
| **深度视觉** | RGB-D / LiDAR | Realsense, Velodyne | (H×W) float32 | 30 Hz | 深度 ±2mm@2m |
| **触觉** | GelSight, DIGIT | GelSight-mini | (240×320×3) 图像 | 60 Hz | 空间 0.1mm |
| **力觉** | 6D 力矩传感器 | ATI Gamma, OnRobot | (6,) float | 1 kHz | 力 0.5N, 力矩 0.01Nm |
| **本体感觉** | 关节编码器 + IMU | 17-bit 编码器, BMI088 | (n+6,) float | 1-10 kHz | 角 0.001°, 加速度 0.001g |
| **听觉** | 麦克风阵列 | ReSpeaker, Resound | (n_samples,) | 48 kHz | 频域 20Hz-20kHz |
| **嗅觉/味觉** | 气体传感器 | MQ-135, 电子鼻 | 化学信号 | 1 Hz | 低 |

几个关键观察:

1. **采样频率差异巨大**。视觉 30 Hz, 触觉 60-100 Hz, 力矩 1 kHz, IMU 1-10 kHz。这给"时间同步"提出了工程挑战,我们后面会详细讲。

2. **空间表示差异巨大**。视觉是规则网格 (H×W), LiDAR 是稀疏点云,触觉是"压力图",力矩是 6 维向量。把这些不同形态的信号融合起来,本身就是一项工程难题。

3. **物理意义差异**。视觉测的是"光强分布",力矩测的是"力的矢量",本体感觉测的是"关节角"。它们的物理量纲不同,噪声分布不同,失败模式也不同。

### 1.3 为什么单视觉不够? 六个典型失败

**失败 1:单目深度估计的几何模糊**

前面第 1 章讲过,单目相机从射线方向无法确定深度。神经网络靠"先验" (杯子不可能在天上, 桌子是平的) 估计深度。但先验在以下场景失灵:

- **镜面反射**:镜面里的图像是反射,深度估计算法分不清"实物"还是"镜像"
- **透明物体**:玻璃杯、矿泉水瓶,RGB 特征不稳定,Depth Anything 在这类物体上误差 > 30%
- **重复纹理**:白墙、地板砖,基于特征匹配的算法失去对应点
- **强光/逆光**:图像过曝或欠曝,特征提取失败

**失败 2:遮挡与手指自身的限制**

机械手抓鸡蛋时,指头在鸡蛋前面,相机看不到手指"捏"鸡蛋的那一面。即使加 depth 相机,鸡蛋底部的接触力也测不到。

```text
相机视角:

         ┌─────────┐
         │ 鸡蛋 (可见部分)
         │   /│
         │  / │
         │ /  │    ← 相机只能看到上半球
         │/   │
         └────┘

指头在鸡蛋前面/后面,接触力完全看不到
```

**失败 3:几何 vs 物理**

视觉告诉你"这是一个鸡蛋"。但你拿鸡蛋时,需要的不是"识别鸡蛋",而是:
- 表面摩擦系数 (μ≈0.05 极滑)
- 抗压强度 (~30 N 破裂)
- 重心位置 (决定转动惯量)
- 表面硬度 (硬壳 vs 软豆腐)

这些**纯视觉无法测量**,必须有物理接触。

**失败 4:高速动态场景与运动模糊**

机器人抓快速移动的物体 (传送带上的瓶子, 飞过来的球),快门时间 > 1ms 就模糊了。事件相机可以缓解,但分辨率低、价格贵。

**失败 5:光照变化**

室内外切换、白天黑夜、强光阴影、镜面反射…… 真实机器人在 24 小时工作中遇到的光照变化幅度极大,单 RGB 模型的 OOD 问题严重。

**失败 6:长尾物体识别**

YOLO 在常见物体 (人、车、椅子) 上 90%+ mAP,但在长尾 (透明杯、薄塑料袋、毛绒玩具) 上掉到 50% 以下。触觉 + 力矩可以补充这些"看不清楚但摸得到"的物体。

### 1.4 多模态融合的层级:信号级 / 特征级 / 决策级

多模态融合不是"把传感器的数据加在一起",而是有清晰的层级选择。本章 §6 会详细讲,这里先给直觉:

**早期融合 (Early Fusion, 信号级)**:

把不同传感器的原始信号在**最底层**拼接,然后一起送进神经网络。

```text
RGB (H×W×3) ──┐
               ├─ concat ──→ [N, 5] 或 [N, 4, H, W] ──→ CNN → 任务
Depth (H×W) ──┤
Tactile (H×W)─┘
```

**优点**:网络可以看到原始对齐信息,理论上表达力最强。
**缺点**:对齐要求极高 (像素级时空配准),否则引入大量噪声。

**中期融合 (Intermediate Fusion, 特征级)**:

每种传感器先用各自的 encoder 提取特征,然后在**特征空间**融合 (通常是 transformer / cross-attention)。

```text
RGB ──→ [ResNet/ViT] ──→ feat_v (B,L_v,D)
Tactile ──→ [CNN] ──→ feat_t (B,L_t,D)
                        ↓
                  Cross-Attention
                        ↓
                  fused (B,L,D)
                        ↓
                   Decoder → 任务
```

**优点**:不要求像素级对齐,每种模态用最合适的 encoder。
**缺点**:cross-attention 计算量 $O(L_v \cdot L_t)$, 长序列时显存压力大。

**晚期融合 (Late Fusion, 决策级)**:

每种传感器**单独训练一个子模型**,只在**最后的决策**层融合 (加权/投票/学习)。

```text
RGB ──→ [Model_v] ──→ logits_v ──┐
Tactile ──→ [Model_t] ──→ logits_t ──├─ weighted sum ──→ final
Force ──→ [Model_f] ──→ logits_f ──┘
```

**优点**:模块化好,每种模态可以独立训练 / 替换 / 升级。
**缺点**:模态间的交互信息丢失 (子模型已经"消化完了"),效果通常不如中期融合。

**经验法则**:
- **强对齐** (同一指尖的 RGB + 触觉) → 早期融合
- **中等对齐** (机械手上的多个相机, 配 IMU) → 中期融合
- **弱对齐 / 异步** (不同频率的传感器) → 晚期融合

## 2. 视觉感知回顾

### 2.1 RGB 相机:被动光学的极限

RGB 相机是机器人最便宜的"眼睛",工作原理是镜头把场景光成像到 CMOS 传感器上。但它有三个本质局限:

**局限 1:被动光源**

RGB 相机接收场景的**反射光**,自己不发光。这意味着:
- 暗光环境 (夜晚, 仓库深处):图像噪点爆增,YOLO mAP 从 90% 掉到 30%
- 强逆光:图像过曝,前向看一片白
- 单色场景 (白墙, 白纸):对比度低,特征点稀少

**局限 2:二维投影**

RGB 把 3D 世界压成 2D 图像。这一章前面 §1.3 反复讲过:深度丢失、遮挡、镜面问题等等。

**局限 3:采样率**

典型 RGB 相机 30 FPS,曝光时间 1/30 秒 ≈ 33ms。这对**慢速操作** (装配、码垛) 够用,对**高速场景** (传送带跟踪、球类抓取) 不够。

在工业实践中,RGB 相机的"够用"取决于任务:

| 任务 | RGB 相机够用吗 | 替代方案 |
| :--- | :--- | :--- |
| 静止物体识别 (零件分拣) | ✅ 够用 | - |
| 室内慢速导航 (AGV) | ✅ 够用 | 加 IMU 抗光照变化 |
| 室外光照变化 (昼夜) | ⚠️ 勉强 | HDR 相机 + 自动曝光 |
| 高速物体跟踪 (>2 m/s) | ❌ 不够 | 事件相机 + 高速相机 |
| 透明/镜面物体 | ❌ 不够 | 加偏振相机 / ToF |
| 精密接触任务 | ❌ 不够 | 必须加触觉 |

### 2.2 深度相机:主动结构光 / ToF / Stereo

**主动结构光 (Structured Light)**:

代表产品:Intel Realsense D415, Apple iPhone Face ID。原理是投射**已知图案的红外光**到场景,通过图案变形反算深度。

```text
投影仪 → 红外散斑图案 → 场景表面 → 变形图案 → 红外相机捕获
                                          ↓
                                  三角测量算深度
```

**优点**:近距离精度高 (0.5mm @ 1m),适合桌面抓取。
**缺点**:室外强光下红外图案被淹没,深度失效;距离有限 (0.2-3m)。

**ToF (Time of Flight)**:

代表产品:Microsoft Azure Kinect, Realsense L515。原理是发射**调制脉冲光**,测返回时间差。

```text
发射脉冲 ──→ 场景表面 ──→ 反射回相机
   ↓
t_round = 2 × depth / c
depth = c × t_round / 2
```

**优点**:距离远 (0.5-10m),抗强光能力强。
**缺点**:精度较低 (±5mm @ 5m),多路径干扰 (mp),边缘模糊。

**Stereo 双目**:

代表产品:ZED 2i, Stereolabs ZED-X。原理是用两个相机模拟人眼,**纯几何三角化**算深度。前面 §6.1 讲过视差公式。

**优点**:纯被动,室内外都能用,距离可调 (双基线 12cm-2m)。
**缺点**:需要纹理 (白墙前失效),计算量大 (要做 stereo matching)。

**选择指南**:

| 场景 | 推荐方案 | 原因 |
| :--- | :--- | :--- |
| 桌面抓取 (室内, < 1m) | Realsense D435 (结构光) | 精度高,价格便宜 |
| 室内导航 (1-10m) | Azure Kinect (ToF) | 抗光照,距离够 |
| 室外自动驾驶 (10-100m) | Velodyne LiDAR | 距离远, 不受光照 |
| 高速运动 (30 Hz+) | ZED 2i (双目) | 被动 + 高帧率 |
| 面扫重建 | Realsense L515 (ToF) | 单点精度高 |

### 2.3 事件相机 (Event Camera):异步、毫秒级

传统相机以固定帧率采样,每帧包含**全部像素**。事件相机 (Event Camera / Dynamic Vision Sensor) 完全不同:

**原理**:每个像素**独立异步**工作,当对数亮度变化超过阈值时输出一个事件。

$$\Delta L = \log(I_{t+1}) - \log(I_t) > C$$

事件格式是 **(x, y, t, p)**,其中 (x, y) 是像素位置,t 是微秒级时间戳,p ∈ {+1, -1} 是极性 (变亮 / 变暗)。

**优点**:
- **延迟极低**:微秒级, 比 RGB 相机快 1000 倍
- **HDR**: > 120 dB 动态范围, RGB 只有 60 dB
- **稀疏高效**:不变化的像素不输出,数据量小

**缺点**:
- **不输出绝对亮度**: 静态场景无事件,必须结合 RGB / IMU
- **价格贵**: Prophesee Metavision ~$5000
- **算法生态差**: 不像 RGB 有 ImageNet 那样成熟的数据集

**典型应用**:
- 无人机避障 (高速场景)
- 高速运动跟踪 (乒乓球, 抛接)
- 高速 VSLAM (Feature tracking at 10 kHz)

### 2.4 多视角融合:多相机协同

单相机的视野有限 (60-90°),机器人经常装多相机 (4-6 个) 做 360° 覆盖。多视角融合的核心问题是**外参标定和跨视角特征匹配**。

**外参标定**: 用棋盘格或 AprilTag, 算相机之间的相对位姿。前面第 1 章讲过 Zhang Zhengyou 算法的单相机版本, 多相机版本稍复杂, 用 PnP + Bundle Adjustment。

**跨视角融合的方法**:

| 方法 | 描述 | 适用 |
| :--- | :--- | :--- |
| **特征拼接** | 各相机分别提特征, concat | 简单场景, 视角差异大 |
| **Voxel 投影** | 把所有相机投影到统一 voxel grid | 3D 重建, BEV |
| **Cross-Attention** | 各视角做 attention, 跨视角信息交换 | 复杂场景, 3D 检测 |
| **NeRF / 3DGS** | 多视角隐式或显式融合 | 场景重建, 见第 3 章 |

**NVIDIA cuVSLAM 的多相机方案**:

```text
主相机 ──→ [VIO] ──→ Pose
俯视 ──→ [VIO] ──→ Pose
左侧 ──→ [VIO] ──→ Pose
                  ↓
              Pose Graph Optimization
                  ↓
              全局轨迹
```

每相机独立 VIO (Visual-Inertial Odometry), 用 BA 联合优化, 精度 < 1cm / 1°。

### 2.5 触觉-视觉的初步协同:为什么"看+摸" > "只看不摸"

这是本章最关键的概念之一:**视觉和触觉是高度互补的**。视觉告诉你"物体长什么样",触觉告诉你"物体摸起来怎么样"。两者结合起来,远超单一模态。

**触觉能补充视觉的 6 个维度**:

| 视觉能给的 | 触觉能补充的 | 应用 |
| :--- | :--- | :--- |
| 形状 (geometry) | 摩擦系数 (friction) | 防滑抓取 |
| 颜色 | 材质 (stiffness) | 易碎物体识别 |
| 类别 (label) | 重量 (weight) | 重心估计 |
| 位姿 (pose) | 接触力 (force) | 防止过压 |
| 静态纹理 | 滑动 (slip) | 实时抓力调整 |
| 表面图案 | 表面粗糙度 | 织物分级 |

**实验证据**:GelSight 团队在 ICRA 2019 论文里证明,**触觉+视觉联合训练**比单视觉的物体识别准确率高 5-8%。在装配任务里, 触觉+视觉的零件插入成功率比单视觉高 15%。

**直觉例子**: 抓鸡蛋

```text
视觉看到: 一个白色椭圆体
触觉摸到: 硬的、光滑的、 摩擦系数 0.05、 抗压强度 30N

视觉单独决策: 用中等抓力, 但抓力可能 > 30N 弄碎鸡蛋
触觉单独决策: 不知道物体在哪, 抓不住
视觉+触觉联合: 视觉定位、触觉调力, 安全抓取
```

这就是为什么 VLA 模型 (π0, OpenVLA) 在 2024 年开始集成触觉传感器。RT-2 没有触觉是它的局限,π0 通过加触觉模态在易碎物体操作上比 RT-2 高 12% 成功率。

### 2.6 章节小结

视觉感知的回顾要点:
- **RGB**: 被动光学, 30 Hz, 室内够用, 高速 / 接触不够
- **RGB-D / ToF / Stereo**: 三种深度方案, 各有适用场景
- **事件相机**: 异步微秒级, 高速场景, 但生态差
- **多视角**: 外参标定 + 联合 VIO, 是机器人标配
- **触觉-视觉协同**: 是本章 §3 的引子, 5-8% 性能提升有实证

## 3. 触觉感知 (本章重点)

### 3.1 触觉传感器的物理原理与分类

触觉传感器按物理原理分四大类:**压阻、电容、压电、光学**。

**压阻 (Piezoresistive)**:

原理: 受压时导电材料电阻变化。代表产品: Tekscan FlexiForce。

```text
      +V
       │
      ┌┴┐
      │R│ ← 受压电阻
      └┬┘
       │
      GND

V_out ∝ 1/R(p)
```

**优点**:结构简单, 成本低 ($5-50)
**缺点**:空间分辨率低 (1-5mm), 弹性差, 易损坏
**应用**: 工业夹爪的"压力触发", 简单的抓力检测

**电容 (Capacitive)**:

原理: 受压时电极间距变化 → 电容变化。代表产品: Pressure Profile Systems (PPS) 触觉阵列。

$$C = \frac{\varepsilon_0 \varepsilon_r A}{d}$$

受压 → d 减小 → C 增大。

**优点**:灵敏度高, 漂移小
**缺点**:易受电磁干扰, 边缘读数不稳定
**应用**: 智能手套, 医疗器械

**压电 (Piezoelectric)**:

原理: 受压时压电材料 (PVDF, PZT) 产生电荷。代表产品: SynTouch。

**优点**:动态响应快 (kHz), 适合振动/纹理检测
**缺点**:静态力检测不到 (需要电荷保持电路)
**应用**: 纹理检测, 振动反馈, 滑移感知

**光学 (Optical)**:

原理: 用相机捕获弹性体表面的形变,通过 photometric stereo 重建 3D 形变。代表产品: **GelSight, DIGIT**。

```text
LEDs (RGB) ──→ 弹性体表面 (凝胶) ──→ 形变 ──→ 内部相机

RGB 光照方向不同 → 表面法向量 → 三维形变重建
```

**优点**:空间分辨率极高 (0.1mm), 可以重建三维形变, 价格中等
**缺点**:需要软接触 (弹性体寿命有限),校准复杂
**应用**: GelSight 系列, MIT 实验室, 学术界主流方案

**对比**:

| 类型 | 空间分辨率 | 频率 | 成本 | 静态/动态 | 代表产品 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 压阻 | 1-5 mm | 100 Hz | 低 | 静态/低频 | Tekscan FlexiForce |
| 电容 | 0.5-2 mm | 1 kHz | 中 | 静态/动态 | PPS |
| 压电 | 1 mm | 10 kHz | 中 | 高频/动态 | SynTouch |
| 光学 | 0.1 mm | 60 Hz | 中 | 静态 + 动态 | GelSight, DIGIT |

### 3.2 GelSight 与 DIGIT:光学触觉的主流方案

**GelSight 工作原理**:

GelSight 由 MIT 的 Wenzhen Yuan 和 Edward Adelson 在 2017 年提出 (RSS 2017 论文)。它由三个核心组件组成:

```text
外层: 透明弹性体 (silicone gel), 与物体接触
中层: 三色 LED (RGB), 从不同角度打光
底层: 内部相机, 捕获弹性体形变

物体压在弹性体上 → 弹性体形变 → 表面反光变化 → 相机看到明暗纹理
```

**关键步骤**:

1. **多方向光照**: 三色 LED (或者更多) 从不同方向照亮弹性体表面。蓝色从左上, 绿色从右上, 红色从下方 (GelSight-mini 的典型配置)。

2. **光度立体 (Photometric Stereo)**: 同一表面在不同光照下, 反射亮度不同。从亮度的颜色分量可以反算**表面法向量**:
$$
n_{i} \propto I_{i, \text{channel}} \quad \text{(简化公式)}
$$

3. **积分得 3D 形变**: 从法向量场积分 (类似 photometric stereo in computer vision), 重建**三维表面形变** $h(x, y)$。

**GelSight-mini 输出**:

实际工程中, 你会拿到两种数据:
- **Raw RGB** (H×W×3): 弹性体表面的彩色图像, 含形变信息
- **Normal Map** (H×W×3): 表面法向量, 反映 3D 形变

```text
原始图:           接触后的图:        法向量图:
┌────────┐        ┌────────┐         ┌────────┐
│ 平整    │   →    │  中央凸起│   →    │ 红绿蓝混合│
│ 均匀颜色 │        │  颜色变化 │         │ 反映斜率│
└────────┘        └────────┘         └────────┘
```

**DIGIT: GelSight 的开源改进**:

Meta AI (FAIR) 在 2020 年提出 DIGIT (TAC 2020 论文), 是 GelSight 的低成本改进版:

| 维度 | GelSight (原版) | GelSight-mini | DIGIT |
| :--- | :--- | :--- | :--- |
| 尺寸 | 100×100×80 mm | 50×50×40 mm | 25×25×25 mm |
| 重量 | 300g | 80g | 20g |
| 价格 (DIY) | $500 | $150 | $15 |
| 视野 | 30×30 mm | 15×15 mm | 10×10 mm |
| 相机 | IDS UI-3240ML | Arducam OV9281 | 任何 USB 摄像头 |
| 用途 | 实验室台面 | 桌面抓取 | 灵巧手指尖 |

DIGIT 的三大优势:

1. **成本低**: 总物料成本 $15, 任何 USB 摄像头 + 硅胶 + 3D 打印外壳
2. **尺寸小**: 可装到 Allegro / LEAP / 任何灵巧手指尖
3. **开源**: 硬件图纸 + 软件全部开源 (github.com/facebookresearch/DIGIT)

**装在 Allegro 灵巧手上的 DIGIT**:

```text
        /\
   R1  /  \  R2
      /    \
   R3 \    / R4
        \/
   L1      L2
   L3      L4   ← 每个指尖装一个 DIGIT
```

### 3.3 触觉信号处理与特征提取

GelSight / DIGIT 的输出是 RGB 图像, 但 "图像里的什么东西表示什么物理含义" 需要算法解开。

**基础信号处理流程**:

```python
# 输入: gel_image shape (H, W, 3) uint8 RGB
# 输出: features 形状 (N, D) 物理特征

# 1. 标定 (Calibration): 消除环境光影响
# 用已知重量 (如 100g, 500g, 1000g) 做标准压头, 建立像素-力的映射
calibrated = gel_image - background_image  # background 是无接触时的图

# 2. 法向量估计 (Photometric Stereo)
# 通过 RGB 三通道亮度 + 已知光照方向, 算表面法向
normals = compute_normals(calibrated, led_directions)
# normals shape: (H, W, 3), 每个像素的法向量

# 3. 深度重建
# 法向量场积分 → 高度图
depth_map = integrate_normals(normals)
# depth_map shape: (H, W), 每个像素的形变量

# 4. 力场估计
# 假设弹性体是线性介质: 力 ∝ 形变
force_field = elasticity_model(depth_map)  # (H, W, 3)
# 或者简化版: total_force = sum(depth_map * calibration_constant)

# 5. 纹理检测
# FFT 或 Gabor 滤波检测表面纹理
texture_map = gabor_filter(calibrated)
# 反映"粗糙度""纹理频率"等特征
```

**关键工程细节**:

- **背景减除**: GelSight 的 zero-load (无接触) 图像会随温度漂移, 工业实践每 10 分钟重新采集一次 background。
- **接触区域分割**: 用阈值或 SAM (Segment Anything) 把接触区域和非接触区域分开, 只在接触区域算力。
- **力-图像标定**: 用标准砝码 (0.1N, 0.5N, 1N, 5N, 10N) 压, 建立像素灰度 vs 力的查找表。
- **滑移检测**: 相邻两帧的法向量差超过阈值 → 滑移事件。Page 1989 年经典论文 (Tactile Slip Detection) 是入门参考。

**特征提取的深度学习版本**:

学术界主流方案是用一个**小型 CNN encoder** 把原始 RGB 提取成 embedding:

```python
class TactileEncoder(nn.Module):
    """GelSight 图像 encoder"""
    def __init__(self, d=128):
        super().__init__()
        # 4 层 conv + pool
        self.backbone = nn.Sequential(
            nn.Conv2d(3, 32, 3, stride=2, padding=1),  # 120x160
            nn.ReLU(),
            nn.Conv2d(32, 64, 3, stride=2, padding=1),  # 60x80
            nn.ReLU(),
            nn.Conv2d(64, 128, 3, stride=2, padding=1),  # 30x40
            nn.ReLU(),
            nn.Conv2d(128, 256, 3, stride=2, padding=1),  # 15x20
            nn.ReLU(),
        )
        self.proj = nn.Linear(256 * 15 * 20, d)

    def forward(self, tactile_img):
        # tactile_img: (B, 3, 240, 320)
        feat = self.backbone(tactile_img)
        feat = feat.flatten(start_dim=1)  # (B, 256*15*20)
        return self.proj(feat)  # (B, D)
```

**典型 embedding 维度**: 128-512 维。太小信息不足, 太大过拟合。

### 3.4 触觉在抓取中的应用

触觉在机器人抓取里扮演三个角色:

**角色 1:抓力调整 (Grasp Force Control)**

闭环控制:
```text
视觉定位 → 估算物体 → 物理模型估算破碎力 → 抓力上限 → 实测触觉 → 调整抓力
```

**示例算法** (触觉伺服控制):

```python
class TactileServo:
    """根据触觉反馈调整抓力"""
    def __init__(self, target_force=2.0):
        self.target = target_force

    def step(self, tactile_img):
        # 算当前接触力
        F = estimate_force(tactile_img)
        # PID 控制
        err = self.target - F
        gripper_cmd = 0.01 * err  # 抓力增量
        return gripper_cmd
```

**典型场景**: 抓鸡蛋的目标力 2N (破碎力 30N, 安全系数 15x), 抓螺丝的目标力 50N。触觉给出"抓够没"的反馈。

**角色 2:滑动检测 (Slip Detection)**

GelSight 高速帧 (60 Hz) 可以检测**微滑动** (incipient slip)。检测算法:

```python
def detect_slip(prev_tactile, curr_tactile, threshold=5.0):
    """通过帧间法向量差检测滑移"""
    prev_n = compute_normals(prev_tactile)
    curr_n = compute_normals(curr_tactile)
    diff = (curr_n - prev_n).norm(dim=-1)  # (H, W)
    slip_mask = diff > threshold
    return slip_mask.any(), slip_mask
```

**检测到滑动怎么办**: 增加抓力, 或重新调整抓取位姿。这是最经典的触觉控制案例之一。

**角色 3:物体属性识别 (Material Recognition)**

通过形变形状 + 纹理 + 力曲线, 判断物体材质:

```text
刚性物体 (石头): 形变小, 接触区面积小, 撤力立即弹回
弹性物体 (橡胶): 形变大, 接触区面积大, 撤力缓慢恢复
塑性物体 (面团): 形变永久, 撤力不恢复
粘性物体 (湿布): 形变 + 粘附, 撤力拖尾
```

**数据集**: 触觉材质识别常用数据集:
- **GelForce** (Yuan et al.): 50+ 物体, 100k+ 触觉接触
- **MIT-Stanford** (Calandra et al.): 触觉+视觉联合数据集

### 3.5 视触融合 (Visuo-Tactile Fusion): 本章重点

视触融合是 §3.5 的核心, 也是多模态融合在具身智能里最成功的应用。

**为什么视觉和触觉天然互补**:

视觉告诉你"在哪", 触觉告诉你"摸起来怎样"。单独看哪一方都不够:

```text
视觉单独: 识别"这是一个塑料杯" - 但抓力怎么调? 不知道滑不滑
触觉单独: 知道"这个杯子表面光滑 μ≈0.05" - 但杯子在哪? 不知道
两者结合: 知道杯子在 (x,y,z), 表面光滑 - 可以规划抓力
```

### 3.6 视触融合的三种架构

**架构 A: 早期融合 (像素级)**

直接把 RGB 图和触觉图拼起来, 4 通道输入:

```python
class PixelFusion(nn.Module):
    def __init__(self):
        # RGB: 3 通道, Tactile: 1 通道 (灰度化法向图)
        self.conv = nn.Sequential(
            nn.Conv2d(4, 32, 3, stride=2, padding=1),
            nn.ReLU(),
            # ... 后续 backbone
        )

    def forward(self, rgb, tactile):
        # rgb: (B, 3, H, W)
        # tactile: (B, 1, H, W)
        x = torch.cat([rgb, tactile], dim=1)  # (B, 4, H, W)
        return self.conv(x)
```

**优点**: 简单, 计算快
**缺点**: 强假设像素级对齐, 实际中 RGB 相机在头部, 触觉在指尖, 视角完全不同

**架构 B: 特征级融合 (Cross-Attention)**

最主流的方案。每种模态先 encoder, 再 cross-attend:

```python
class VisuoTactileFusion(nn.Module):
    """视觉-触觉 Cross-Attention 融合"""
    def __init__(self, d_v=768, d_t=128, d_fuse=256):
        super().__init__()
        # 视觉 encoder (冻结 ViT 或 ResNet)
        self.vision_enc = vit_small_patch16()
        # 触觉 encoder
        self.tactile_enc = TactileEncoder(d=d_t)
        # 投影到统一维度
        self.v_proj = nn.Linear(d_v, d_fuse)
        self.t_proj = nn.Linear(d_t, d_fuse)

        # Cross-Attention: 视觉 query 触觉
        self.cross_attn = nn.MultiheadAttention(d_fuse, num_heads=8)

    def forward(self, rgb, tactile):
        # RGB → patches
        v_feat = self.vision_enc(rgb)  # (B, n_patches, d_v)
        v_feat = self.v_proj(v_feat)  # (B, n_patches, d_fuse)

        # 触觉 → 单向量
        t_feat = self.tactile_enc(tactile)  # (B, d_t)
        t_feat = self.t_proj(t_feat).unsqueeze(1)  # (B, 1, d_fuse)

        # Cross-Attention
        # Query from visual, Key/Value from tactile
        fused, attn = self.cross_attn(
            query=v_feat.transpose(0, 1),  # (n, B, d)
            key=t_feat.transpose(0, 1),
            value=t_feat.transpose(0, 1)
        )
        return fused.transpose(0, 1), attn  # (B, n, d), (B, n, 1)
```

**架构 C: 决策级融合 (Late Fusion)**

分别训两个模型, 最后加权:

```python
class LateFusion(nn.Module):
    def __init__(self):
        self.vision_model = resnet18(pretrained=True)
        self.tactile_model = resnet18()
        self.fuse = nn.Linear(2 * 1000, 6)  # 6 类抓取策略

    def forward(self, rgb, tactile):
        v_logits = self.vision_model(rgb)
        t_logits = self.tactile_model(tactile)
        combined = torch.cat([v_logits, t_logits], dim=1)
        return self.fuse(combined)
```

**哪种最好? 学术界的对比**:

论文 "Visuo-Tactile Fusion for Manipulation" (ICRA 2020) 的结论:
- 早期融合: mAP 75.2%
- 特征级融合 (cross-attn): **mAP 82.7%** ← 最佳
- 晚期融合: mAP 78.1%

**经验法则**:
- **指尖视角 + 指尖触觉**: 早期融合 (像素级容易对齐)
- **头部视角 + 指尖触觉**: 中期融合 (cross-attention)
- **多指触觉**: 中期或晚期

### 3.7 视触融合的标定: 时空对齐

**时间同步**:

RGB 30 Hz, 触觉 60 Hz。不同步会有 1-2 帧的延迟, 触觉事件错位。

工程解决方案: **硬件触发 + 时间戳**:

```python
# 主时钟 (PTP / IEEE 1588) 给所有传感器打时间戳
# 抓取触发信号 → GPIO → 所有传感器同时开始记录
# 每帧带硬件时间戳 (μs 级)
# 离线做时间对齐
```

**空间标定 (指尖外参)**:

触觉传感器的"视野中心"在指尖坐标系的位置, 与相机坐标系的关系由机器人手眼标定决定。

**简易做法**: 在指尖戴一个已知 3D 形状的标定块 (如 4×4 ArUco 板), 用相机+触觉同时看, 求变换矩阵 $T_{\text{tactile}}^{\text{camera}} \in SE(3)$。

**高级做法**: 在仿真里精确建模指尖几何, 用 Sim-to-Real transfer 学习标定。

### 3.8 章节小结

触觉感知要点:
- **物理原理**: 压阻 / 电容 / 压电 / 光学四大类, 光学 (GelSight, DIGIT) 是主流
- **信号处理**: 标定 + 法向估计 + 深度重建 + 纹理检测, 组成完整 pipeline
- **抓取应用**: 抓力调整 + 滑动检测 + 物体属性识别三大场景
- **视触融合**: 早期 (像素) / 中期 (cross-attn) / 晚期 (决策) 三种架构, cross-attn 最强
- **时空标定**: 硬件时间同步 + ArUco 几何标定

## 4. 力矩感知

### 4.1 关节扭矩传感器:电流法 vs 应变片法

关节扭矩测量有两种主流方案: **电流法 (model-based)** 和 **应变片法 (sensor-based)**。

**电流法 (Current Sensing)**:

原理: 电机电流 $I$ 与输出扭矩 $\tau$ 近似线性 (电机力矩常数 $K_t$):

$$\tau_{\text{estimated}} = K_t \cdot I$$

**优点**: 无需额外硬件, 价格 0 增量
**缺点**: 误差大 (5-15%), 包含摩擦力 / 惯性力 / 重力, 实时校准难

**工程实践**: 大多数协作机器人 (UR5e, Franka Panda) 的**关节控制器**用电流法做粗控, 用应变片做精控。

**应变片法 (Strain Gauge)**:

原理: 在关节连接处贴应变片, 应变 $\epsilon$ 与扭矩 $\tau$ 线性:

$$\tau = G \cdot \epsilon$$

其中 $G$ 是结构刚度矩阵, 与机械设计相关。

**全桥 (Full Bridge) 配置**:

```python
# 4 个应变片构成惠斯通电桥
# 在扭矩作用下, R1↑ R2↓ R3↑ R4↓
# 桥路输出 V = V_exc × (ΔR1/R1 - ΔR2/R2 + ΔR3/R3 - ΔR4/R4)
# 这个组合消除了温度漂移和弯矩干扰
```

**工程实现要点**:
- 应变片用胶水粘到扭杆上,胶水老化会让信号漂移
- 高精度应用 (手术机器人) 用**金属箔应变片**, 工业应用 (协作机械臂) 用**半导体应变片**
- 温度补偿必须做, 1 度温度变化会让信号漂 1-3%

**代表产品**:

| 型号 | 类型 | 量程 | 分辨率 | 厂商 |
| :--- | :--- | :--- | :--- | :--- |
| ATI Mini45 | 应变片 | ±290 N, ±290 Nm | 1/40 N | ATI |
| OnRobot HEX-E | 应变片 | ±200 N, ±20 Nm | 0.1 N | OnRobot |
| Franka Panda 内置 | 电流+应变片 | ±10 Nm | 0.01 Nm | Franka Emika |

### 4.2 末端六维力矩传感器:六自由度的力反馈

末端六维力矩传感器是协作机器人的核心, 装在机械臂末端和夹爪之间, 同时测量 **三轴力** $(F_x, F_y, F_z)$ + **三轴力矩** $(M_x, M_y, M_z)$。

**物理原理**:

典型六维力传感器用 **应变梁阵列**:

```text
       Fz (垂直力)
        ↓
       [弹性梁]
      ┌─┴─┐
   Mx ← 8 个应变片 →
      └─┬─┘
       [/]
   Fy /
   ↑ (水平力)

# 任何 Fx/Fy/Fz/Mx/My/Mz 的组合,
# 都在 8 个应变片上产生不同的"印记",
# 用最小二乘反算 6 维力
```

**数学建模**:

设 8 个应变片的读数为 $\mathbf{s} \in \mathbb{R}^8$, 真实 6 维力为 $\mathbf{f} \in \mathbb{R}^6$。

线性模型:
$$\mathbf{s} = C \cdot \mathbf{f}$$

校准时测得矩阵 $C \in \mathbb{R}^{8 \times 6}$, 求逆得反推:
$$\mathbf{f} = C^+ \cdot \mathbf{s}$$

$C^+$ 是 Moore-Penrose 伪逆。工业上用 SVD 求, 对噪声更鲁棒。

**实际工程问题**:

1. **重力补偿**: 末端夹爪有重量 $m_{\text{gripper}}$, 沿机械臂方向产生**伪力矩**。需要减去:
$$\mathbf{f}_{\text{actual}} = \mathbf{f}_{\text{measured}} - \mathbf{f}_{\text{gravity}}$$
其中 $\mathbf{f}_{\text{gravity}}$ 由机器人位姿计算:
$$\mathbf{f}_{\text{gravity}} = \mathbf{R}_{\text{ee}}^{\text{base}} \cdot \begin{bmatrix} 0 \\ 0 \\ -m_{\text{gripper}} g \end{bmatrix}$$

2. **零点漂移**: 应变片的热漂移, 每 30 分钟需要重新校准零位。

3. **串扰 (Crosstalk)**: Fx 的变化应该**只**影响 Fx 读数, 但工程中会导致 Fy/Fz/Mx 也有微小变化, 这就是串扰。典型值 1-3%。

4. **采样频率**: 6 维力通常 1 kHz, 比视觉快 30 倍。

### 4.3 力矩反馈控制:阻抗控制与导纳控制

末端六维力的核心价值是**力反馈控制**。这是协作机器人能"安全和人交互"的物理基础。

**阻抗控制 (Impedance Control)**:

核心思想: 让机械臂表现得像"弹簧-阻尼-质量"系统, 而不是追求"精确位置"。

$$M \ddot{x} + B \dot{x} + K (x - x_{\text{desired}}) = f_{\text{external}}$$

其中:
- $M$: 虚拟质量
- $B$: 虚拟阻尼
- $K$: 虚拟刚度
- $f_{\text{external}}$: 力传感器测得的外力

**工程意义**: 调整 $K$ 可以让机器人"软"或"硬"。
- $K = 0$: 完全柔顺 (零刚度), 任何微小力都会让位置漂移
- $K = \infty$: 完全刚性, 忽略外力 (传统位置控制)
- $K$ 适中: 当人和机器人接触时, 机器人"让步"而不"抵抗"

**协作机器人的力控限速标准 ISO/TS 15066**:

当检测到外力 $> 150$ N (静态) 或 $> 320$ N (瞬态) 时, 机器人必须停机。Franka Panda 和 UR5e 都满足此标准。

**导纳控制 (Admittance Control)**:

如果末端是**位置型执行器** (如笛卡尔位置控制), 用导纳控制:

$$M \ddot{x}_{\text{desired}} + B \dot{x}_{\text{desired}} + K x_{\text{desired}} = f_{\text{measured}}$$

外力 $\to$ 期望位置变化。Franka Panda 在导纳模式下, 人用力推机械臂, 它就动; 人松手, 它停。

**力位混合控制 (Hybrid Force/Position)**:

把任务空间分成两个方向:
- **位置控制方向**: 必须精确跟随 (如沿平面的 X/Y)
- **力控制方向**: 必须控制力 (如沿法向 Z)

经典例子: 擦窗户。
- 平行于窗户: 位置控制 (轨迹)
- 垂直于窗户: 力控制 (保持恒定压力)

### 4.4 力矩在协作机器人中的具体应用

**应用 1: 协作装配 (Collaborative Assembly)**

场景: 人和机器人协作装一个齿轮箱。

```text
人放齿轮 → 机器人自动检测到位 → 力控插入 → 遇到阻力自动调整 → 成功装配
```

力反馈用于:
- **柔顺插入 (Remote Center of Compliance)**: 自动找孔
- **力轨迹跟踪**: 沿指定路径施加指定力 (打磨, 抛光)
- **碰撞检测**: 异常力立即停机

**应用 2: 康复机器人 (Rehabilitation Robots)**

场景: 外骨骼帮助偏瘫患者行走。

力反馈用于:
- **辅助力**: 测步态相位, 在恰当的时机提供助力
- **抗阻训练**: 测患者用力程度, 动态调整阻力
- **意图识别**: 测患者肌肉力矩, 预测想做什么动作

**应用 3: 工业打磨 / 抛光**

场景: 机器人打磨飞机发动机叶片。

```text
位置: 沿叶片表面做圆弧轨迹
力:   保持 5N 恒压力
速度: 100 mm/s 慢移
```

力反馈 (1 kHz) 比位置反馈 (100 Hz) 快得多, 让打磨均匀。

### 4.5 力矩的多模态融合:与触觉的对比

力矩和触觉看起来都是"力", 但本质不同:

| 维度 | 力矩传感器 | 触觉传感器 |
| :--- | :--- | :--- |
| **测量位置** | 关节/末端整体 | 指尖局部 |
| **测量量** | 三轴力+三轴力矩 (6 维) | 接触压力图 (H×W) |
| **空间信息** | 无 (单点) | 有 (空间分布) |
| **频率** | 1 kHz | 60-100 Hz |
| **视场** | 整个操作空间 | 接触面 |
| **物理意义** | 整体受力 | 局部接触状态 |

**两者互补**:
- 力矩告诉你"夹爪整体受力多大"
- 触觉告诉你"哪个指尖在用力, 哪里接触, 有没有滑动"

**融合方法**: Late Fusion, 因为:
- 时间频率不同 (1 kHz vs 60 Hz)
- 空间表示不同 (6 维向量 vs H×W 图)
- 物理意义不同, 早期融合困难

```python
class ForceTactileFusion(nn.Module):
    """力矩 + 触觉 决策级融合"""
    def __init__(self, d_force=6, d_tactile=128, d_action=7):
        super().__init__()
        # 力矩: 直接用 MLP (6 维)
        self.force_enc = nn.Sequential(
            nn.Linear(d_force, 64),
            nn.ReLU(),
        )
        # 触觉: 用 CNN encoder
        self.tactile_enc = TactileEncoder(d=d_tactile)
        # 融合 → 动作
        self.head = nn.Sequential(
            nn.Linear(64 + d_tactile, 128),
            nn.ReLU(),
            nn.Linear(128, d_action),
        )

    def forward(self, force_vec, tactile_img):
        f = self.force_enc(force_vec)  # (B, 64)
        t = self.tactile_enc(tactile_img)  # (B, d_tactile)
        x = torch.cat([f, t], dim=-1)
        return self.head(x)  # (B, d_action)
```

### 4.6 章节小结

力矩感知要点:
- **物理原理**: 电流法 (粗) + 应变片法 (精), 工业上以应变片为主
- **末端六维**: 8 个应变片 + 标定矩阵 + 重力补偿
- **控制算法**: 阻抗 + 导纳 + 力位混合, 是协作的核心
- **应用**: 装配 + 打磨 + 康复 + 协作, 标准 ISO/TS 15066
- **融合**: 力矩 + 触觉是天然的互补对, 常用 Late Fusion

## 5. 本体感觉 (Proprioception)

### 5.1 关节编码器:绝对式 vs 增量式

本体感觉最基础的硬件是 **关节编码器** (Joint Encoder), 测关节角度。机器人 6-7 个关节, 每个关节一个编码器。

**增量式编码器 (Incremental)**:

原理: 码盘上有 N 条辐射状刻线, 每转过一条线发出一个脉冲。

```text
码盘:   ┌────────────┐
       │  ╱╱╱╱╱╱╱╱╱╱ │
       │  ╲╲╲╲╲╲╲╲╲╲ │
       └────────────┘
每转一圈 → N 个脉冲
```

**优点**: 价格低 ($5-50), 频率高 (MHz)
**缺点**: **掉电丢失位置**, 必须用 reference mark 或 home sensor 重置

**绝对式编码器 (Absolute)**:

原理: 码盘上多个同心圆, 每个圆对应二进制的一位。转角由各位的"亮/暗"直接编码。

```text
码盘 (8 位, 256 个唯一位置):

位 0: ▓▓▓▓░░░░▓▓▓▓░░░░ (粗)
位 1: ▓▓░░▓▓░░▓▓░░▓▓░░ (中粗)
位 2: ▓░▓░▓░▓░▓░▓░▓░▓░ (细)
...
```

**优点**: 掉电不丢失 (上电即知道绝对角度)
**缺点**: 价格高 ($50-500), 分辨率受限 (位数有限)

**代表产品**:

| 型号 | 类型 | 位数 | 分辨率 | 价格 |
| :--- | :--- | :--- | :--- | :--- |
| Avago HEDL 5540 | 增量 | 1000 CPR | 0.36° | $20 |
| Renishaw RESOLUTE | 绝对 | 23 bit | 0.00005° | $200 |
| FRABA Absolute | 绝对 | 19 bit | 0.0007° | $150 |
| 17-bit 磁编 (协作机器人常用) | 绝对 | 17 bit | 0.0027° | $30 |

**分辨率 vs 精度**:

注意区别: **17 bit 分辨率 = 0.0027°**, 但**精度**取决于机械和安装精度。工业精度做到 ±0.01° (对应机械臂重复定位 ±0.02 mm) 就很好了。

### 5.2 IMU:加速度计 + 陀螺仪 + 磁力计

IMU (Inertial Measurement Unit) 是机器人另一个核心本体感觉硬件, 测**线加速度** + **角速度** + (可选)**磁场方向**。

**加速度计 (Accelerometer)**:

原理: 质量块在加速时产生惯性力, 通过电容/压电测量。

```text
固定电极 ─┬─ 质量块 ─┬─ 固定电极
       cap_a    cap_b

加速 → 质量块位移 → cap_a ≠ cap_b → 加速度
```

测的是**比力** (specific force), = 加速度 + 重力:

$$\mathbf{a}_{\text{measured}} = \mathbf{a}_{\text{actual}} - \mathbf{g}$$

**陀螺仪 (Gyroscope)**:

原理: Coriolis 力 (旋转坐标系中的虚拟力) 与角速度成正比。

$$\mathbf{F}_{\text{Coriolis}} = 2 m \mathbf{\Omega} \times \mathbf{v}$$

MEMS 陀螺仪用微机械结构测 Coriolis 力。

**磁力计 (Magnetometer)**:

原理: 3D 霍尔元件, 测地磁场方向, 提供**绝对航向**参考。

$$\mathbf{B}_{\text{earth}} = \begin{bmatrix} B_x \\ B_y \\ B_z \end{bmatrix}$$

**典型 IMU 模块**:

| 型号 | 加速度量程 | 陀螺量程 | 噪声密度 | 价格 | 应用 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| BMI088 | ±24g | ±2000°/s | 190 μg/√Hz | $5 | 机器人主流 |
| ICM-42688 | ±32g | ±2000°/s | 70 μg/√Hz | $10 | 无人机 |
| ADIS16448 | ±18g | ±2000°/s | 23 μg/√Hz | $300 | 工业高精度 |
| VectorNav VN-100 | ±16g | ±2000°/s | 35 μg/√Hz | $500 | 战术级 |

### 5.3 关节角速度与加速度:微分 vs 估计

关节编码器直接给的是**位置**, 速度和加速度需要推导:

**简单差分**:

$$\omega_t = \frac{\theta_t - \theta_{t-1}}{\Delta t}$$

但简单差分**噪声大**, 工程上用**差分 + 低通滤波**:

$$\omega_t = \alpha \cdot \frac{\theta_t - \theta_{t-1}}{\Delta t} + (1-\alpha) \cdot \omega_{t-1}$$

$\alpha$ 取 0.6-0.8 是经验值。

**进阶:卡尔曼滤波 (Kalman Filter)**:

状态向量: $\mathbf{x}_t = [\theta_t, \omega_t, a_t]^T$, 用电机动力学模型:

$$\mathbf{x}_{t+1} = A \mathbf{x}_t + B u_t + w_t$$

$$z_t = \mathbf{x}_t + v_t$$

Kalman 滤波同时给出最优估计和协方差, 是工业机器人关节速度估计的标配。

**为什么不直接用编码器做二阶差分**:
- 二阶差分放大噪声 (差分两次, 噪声 ×4)
- 卡尔曼滤波融入了物理模型, 更鲁棒

### 5.4 IMU 与编码器的融合:VIO / INS

视觉里程计 (Visual Odometry) 用图像估计位姿变化, IMU 测加速度/角速度。它们是天然互补:

- 视觉: 长期**漂移小**, 但短帧率, 快速运动失效
- IMU: 短期**精度高**, 但长期漂移大 (积分误差累积)

**VIO 的卡尔曼融合**:

```text
State: [位置, 速度, 旋转四元数, 加速度 bias, 陀螺 bias]
预测步 (IMU 积分):
  pos ← pos + v*dt + 0.5*a*dt²
  v ← v + a*dt
  rot ← rot ⊗ Δrot(ω*dt)
  bias update via random walk
更新步 (视觉):
  z_vision = [相对位姿变化]
  z_vision - z_predicted → Kalman Gain → state update
```

代表的 VIO 系统:
- **ORB-SLAM3** (Mur-Artal): 单/双目/RGB-D + IMU 紧耦合
- **VINS-Mono** (HKUST): 单目 + IMU, 移动端实时
- **OKVIS** (ETH): 多相机 + IMU, 工业级
- **cuVSLAM** (NVIDIA): GPU 加速, Jetson 实时

### 5.5 本体感觉的特征工程:位姿向量的构建

把本体感觉组织成向量, 给多模态融合用:

**Naive 版本**:

```python
# 6 自由度机械臂
joint_pos = [q1, q2, q3, q4, q5, q6]      # 关节角 (6,)
joint_vel = [ω1, ..., ω6]                  # 关节角速度 (6,)
joint_acc = [α1, ..., α6]                  # 关节角加速度 (6,)
ee_pose = [x, y, z, qx, qy, qz, qw]       # 末端位姿 (7,)
gripper_width = 0.0..0.08                  # 夹爪开度 (1,)
```

总维度 6+6+6+7+1 = 26 维。

**进阶:归一化**:

```python
# 关节角: 减去零位 + 除以最大范围
joint_pos_norm = (joint_pos - q_zero) / q_max
# 关节速度: 除以最大速度
joint_vel_norm = joint_vel / vel_max
# 末端位姿: 拆成位置 (3) + 四元数 (4), 各自归一化
ee_pos_norm = ee_pos[:3] / workspace_size
ee_quat = ee_pos[3:] / 1.0  # 单位四元数
```

**类别特征** (任务 ID, 物体 ID) 也要编码进本体向量。

### 5.6 本体感觉与视觉的协同:空间感知闭环

本体感觉 (关节角) 告诉你"机械臂的位姿", 视觉告诉你"物体的位姿"。两者配合就是**手眼协调**。

**手眼标定 (Hand-Eye Calibration)**:

求相机-机械臂变换矩阵 $T_{\text{camera}}^{\text{robot}}$:

$$
T_{\text{base}}^{\text{obj}} = T_{\text{base}}^{\text{ee}} \cdot T_{\text{ee}}^{\text{camera}} \cdot T_{\text{camera}}^{\text{obj}}
$$

经典算法: **Tsai-Lenz** 或 **Daniilidis**, 用 AX = XB 形式求解。

**工业实践**: 在机器人出厂前, 厂商已经标定好; 但实际部署 (比如换相机) 时需要重新标定。

### 5.7 章节小结

本体感觉要点:
- **关节编码器**: 增量 vs 绝对, 17-bit 是工业主流
- **IMU**: 加速度 + 陀螺 + (磁力), BMI088 是机器人主流
- **角速度/加速度**: 用卡尔曼滤波而非差分, 工业标配
- **VIO 融合**: 视觉 + IMU 紧耦合, ORB-SLAM3 / VINS-Mono / cuVSLAM
- **位姿特征**: 归一化是基础, 维度控制在 30-50 维
- **手眼标定**: AX = XB, Tsai / Daniilidis 算法

## 6. 多模态融合架构 (本章重点)

### 6.1 早期融合 (Early Fusion, 信号级)

早期融合的哲学是 "不同传感器的信号, 在最底层整合"。

**最简单的形式: 通道拼接**

```python
# 三种传感器的原始信号直接拼接
rgb = torch.randn(B, 3, H, W)         # RGB 相机
depth = torch.randn(B, 1, H, W)        # 深度图 (归一化到 [0, 1])
tactile = torch.randn(B, 1, H, W)      # 触觉图 (灰度化)
# 拼接成 5 通道
x = torch.cat([rgb, depth, tactile], dim=1)  # (B, 5, H, W)
# 送进 backbone
features = backbone(x)
```

**优点**:
- 简单, 不用专门设计融合模块
- 网络可以学到原始对齐信息, 例如"深度边缘 + 触觉边缘 = 物体边缘"

**缺点**:
- **强假设像素级对齐**: 实际上 RGB 相机视角 vs 触觉视角完全不同
- **维度灾难**: 5 通道输入比 3 通道多 66% 的权重, 容易过拟合小数据
- **扩展性差**: 加一个新传感器要重新训

**什么场景能用早期融合**:
- **指尖相机 + 指尖触觉** (视角几乎一致): GelSight 论文常用
- **多角度 RGB 相机**: 自动驾驶的 6 相机系统
- **多视角光场**: 同一物体的多个角度拍摄

### 6.2 中期融合 (Intermediate Fusion, 特征级)

最主流的多模态融合方案: **每种模态先 encoder, 然后在特征空间融合**。

**基础: Concat 然后 MLP**

```python
class ConcatFusion(nn.Module):
    """最简单的特征级融合: concat + MLP"""
    def __init__(self, d_v=512, d_t=128, d_force=6, d_out=128):
        super().__init__()
        self.vision_enc = resnet18()  # 输出 512 维
        self.tactile_enc = TactileEncoder(d=d_t)
        self.force_proj = nn.Linear(d_force, 64)
        # Concat 后送 MLP
        self.head = nn.Sequential(
            nn.Linear(512 + d_t + 64, d_out),
            nn.ReLU(),
            nn.Linear(d_out, d_out),
        )

    def forward(self, rgb, tactile, force):
        v = self.vision_enc(rgb)              # (B, 512)
        t = self.tactile_enc(tactile)         # (B, 128)
        f = self.force_proj(force)            # (B, 64)
        x = torch.cat([v, t, f], dim=-1)      # (B, 512+128+64)
        return self.head(x)
```

**进阶: Gated Fusion (门控融合)**

让网络**学习每种模态的权重**, 而非固定权重:

```python
class GatedFusion(nn.Module):
    """门控融合: 每种模态的权重由网络学"""
    def __init__(self, d_v=512, d_t=128, d=128):
        super().__init__()
        self.vision_enc = resnet18()
        self.tactile_enc = TactileEncoder(d=d_t)
        # 投影到统一维度
        self.v_proj = nn.Linear(512, d)
        self.t_proj = nn.Linear(d_t, d)
        # 门控网络: 输入是 concat, 输出是 [α_v, α_t] 权重
        self.gate = nn.Sequential(
            nn.Linear(512 + d_t, 32),
            nn.ReLU(),
            nn.Linear(32, 2),
            nn.Softmax(dim=-1),
        )

    def forward(self, rgb, tactile):
        v = self.vision_enc(rgb)
        t = self.tactile_enc(tactile)
        v_proj = self.v_proj(v)
        t_proj = self.t_proj(t)
        # 学习门控权重
        gate = self.gate(torch.cat([v, t], dim=-1))  # (B, 2)
        α_v = gate[:, 0:1]
        α_t = gate[:, 1:2]
        # 加权融合
        fused = α_v * v_proj + α_t * t_proj
        return fused
```

**优势**: 在不同场景下, 模态的重要性不同 (晴朗白天 RGB 重要, 暗光触觉重要), 门控机制可以自动学习。

### 6.3 晚期融合 (Late Fusion, 决策级)

每种模态**独立训练**, 在最后**加权**或**投票**。

**优点**:
- **模块化**: 每个模态可以独立升级
- **可解释**: 每个模态的贡献清晰
- **训练简单**: 不需要等所有模态同步

**缺点**:
- **错过跨模态交互**: 各模态内部已 "消化", 跨模态信息丢失
- **通常效果不如中期融合**

**典型实现**:

```python
class LateFusion(nn.Module):
    def __init__(self, num_classes=10):
        super().__init__()
        self.vision_model = resnet50(pretrained=True)
        self.tactile_model = resnet18()  # 触觉图
        self.force_mlp = nn.Sequential(
            nn.Linear(6, 64), nn.ReLU(),
            nn.Linear(64, 256),
        )
        # 加权融合: 学习权重
        self.weights = nn.Parameter(torch.ones(3) / 3)
        # 最终分类头
        self.head = nn.Linear(1000 + 1000 + 256, num_classes)

    def forward(self, rgb, tactile, force):
        v_logits = self.vision_model(rgb)
        t_logits = self.tactile_model(tactile)
        f_logits = self.force_mlp(force)
        # softmax 归一化权重
        w = F.softmax(self.weights, dim=0)
        # 加权所有 logit
        v_w = w[0] * v_logits
        t_w = w[1] * t_logits
        f_w = w[2] * f_logits
        # 也可以直接 concat 送 head
        combined = torch.cat([v_logits, t_logits, f_logits], dim=1)
        return self.head(combined), w  # 输出 logits 和实际权重
```

### 6.4 Cross-Attention 融合:多模态 Transformer

**Cross-Attention 的核心思想**: 一种模态当 "Query", 另一种当 "Key/Value", 实现**跨模态信息检索**。

**最简架构**:

```python
class CrossModalityAttention(nn.Module):
    """单层 Cross-Attention 融合"""
    def __init__(self, d=256, nhead=8):
        super().__init__()
        self.attn = nn.MultiheadAttention(d, nhead)
        self.norm = nn.LayerNorm(d)

    def forward(self, q_input, kv_input):
        # q_input: (B, Lq, d) - 查询 (比如触觉)
        # kv_input: (B, Lkv, d) - 键值 (比如视觉 patches)
        q = q_input.transpose(0, 1)  # (Lq, B, d)
        kv = kv_input.transpose(0, 1)  # (Lkv, B, d)
        out, attn = self.attn(q, kv, kv)  # cross-attention
        out = out.transpose(0, 1)  # (B, Lq, d)
        return self.norm(q_input + out), attn
```

**多模态 Transformer 完整架构**:

```python
class MultimodalTransformer(nn.Module):
    """视觉 + 触觉 + 本体感觉 多模态融合"""
    def __init__(self, d=256, nhead=8, num_layers=4):
        super().__init__()
        # 各模态的 encoder
        self.vision_enc = vit_small_patch16()      # 输出 (B, n_patch, d_v)
        self.tactile_enc = TactileEncoder(d=128)   # 输出 (B, d_t)
        self.proprio_enc = nn.Sequential(
            nn.Linear(26, 128), nn.ReLU(),
            nn.Linear(128, 64),
        )
        # 投影到统一维度 d
        self.v_proj = nn.Linear(d_v, d)
        self.t_proj = nn.Linear(128, d)
        self.p_proj = nn.Linear(64, d)
        # 多层 cross-attention
        self.fusion_layers = nn.ModuleList([
            CrossModalityAttention(d, nhead) for _ in range(num_layers)
        ])
        # 任务头
        self.head = nn.Linear(d, 7)  # 7 自由度动作

    def forward(self, rgb, tactile, proprio):
        # 1. 各模态 encoder
        v = self.v_proj(self.vision_enc(rgb))      # (B, N_v, d)
        t = self.t_proj(self.tactile_enc(tactile)).unsqueeze(1)  # (B, 1, d)
        p = self.p_proj(self.proprio_enc(proprio)).unsqueeze(1)  # (B, 1, d)
        # 2. 拼接所有 token
        tokens = torch.cat([v, t, p], dim=1)       # (B, N_v + 2, d)
        # 3. 多层 cross-attention 融合
        for layer in self.fusion_layers:
            tokens, attn = layer(tokens, tokens)
        # 4. 池化 + 任务头
        pooled = tokens.mean(dim=1)  # (B, d)
        return self.head(pooled)
```

**Cross-Attention 的优势**:

1. **自适应模态权重**: 注意力机制自动决定何时该信哪个模态
2. **长程依赖**: 一个模态的 token 可以和另一个模态的所有 token 交互
3. **可解释**: attention weight 可以可视化

**代表论文**:

- **Flamingo** (DeepMind, 2022): 视觉 + 文本 Perceiver Resampler + Cross-Attention
- **BLIP-2** (Salesforce, 2023): Q-Former 桥接视觉和语言
- **OpenVLA** (2024): 视觉 + 语言 + 本体感觉的端到端 VLA
- **π0** (Physical Intelligence, 2024): 视觉 + 本体 + Flow Matching
- **RT-2** (Google DeepMind, 2023): 视觉 + 语言的 CoT 推理

### 6.5 Token 化融合:把所有模态当 token

**Token 化的核心思想**: 把所有模态都映射到同一组 tokens, 然后丢给 Transformer。

**Chameleon (Meta, 2024) 的统一 token 化**:

```text
图像 patch → vision encoder → image_token (n_im, d)
文本 token → embed → text_token (n_tx, d)
触觉 patch → tactile encoder → touch_token (n_tc, d)
本体感觉 → MLP → proprio_token (1, d)
                                    ↓
                            Token 拼接 → Unified Transformer
                                    ↓
                              输出 tokens
                                    ↓
                              Action / Text / 任何输出
```

**实现**:

```python
class TokenizedFusion(nn.Module):
    """所有模态统一 token 化"""
    def __init__(self, d=256, max_tokens=512):
        super().__init__()
        # 各模态到 token
        self.v_enc = vit_small_patch16(d=d)
        self.t_enc = TactileEncoder(d=d)
        self.p_enc = nn.Linear(26, d)
        # 模态类型 id (类似 BERT [CLS])
        self.v_type = nn.Parameter(torch.randn(1, 1, d))
        self.t_type = nn.Parameter(torch.randn(1, 1, d))
        self.p_type = nn.Parameter(torch.randn(1, 1, d))
        # Transformer decoder
        self.decoder = nn.TransformerDecoder(
            nn.TransformerDecoderLayer(d, nhead=8, batch_first=True),
            num_layers=6
        )
        # 输出头
        self.head = nn.Linear(d, 7)

    def forward(self, rgb, tactile, proprio, query=None):
        # 1. 各模态 -> tokens + 类型标识
        v_tok = self.v_enc(rgb) + self.v_type  # (B, N_v, d)
        t_tok = self.t_enc(tactile).unsqueeze(1) + self.t_type  # (B, 1, d)
        p_tok = self.p_enc(proprio).unsqueeze(1) + self.p_type  # (B, 1, d)
        # 2. 拼接
        context = torch.cat([v_tok, t_tok, p_tok], dim=1)  # (B, N, d)
        # 3. decoder 用 query (动作 / 文本) attend 到 context
        if query is None:
            query = torch.zeros(context.size(0), 1, d, device=context.device)
        out = self.decoder(query, context)  # (B, 1, d)
        # 4. 输出
        return self.head(out.squeeze(1))
```

**统一 token 化的优势**:
1. 一个 Transformer 同时处理所有模态
2. 不需要为每种模态设计专用的融合模块
3. 易于扩展: 加新模态只需要加 token encoder

**代表系统**:
- **GPT-4o** (OpenAI): 文本 + 图像 + 音频 统一 token
- **Gemini 1.5** (Google): 多模态原生
- **Chameleon** (Meta): 早期融合多模态
- **AnyMAL** (Meta): LLaMA 加动作 token

### 6.6 MoE 融合:不同任务用不同专家

**Mixture-of-Experts (MoE)** 用稀疏激活处理多模态:

```python
class MultimodalMoE(nn.Module):
    """多模态 MoE 融合"""
    def __init__(self, d=256, num_experts=8, top_k=2):
        super().__init__()
        # 路由器: 输入是 concat 所有模态特征, 输出 top_k 专家
        self.router = nn.Linear(d * 3, num_experts)
        # 专家网络: 每个专家学不同类型的多模态融合
        self.experts = nn.ModuleList([
            nn.Sequential(
                nn.Linear(d * 3, d),
                nn.ReLU(),
                nn.Linear(d, d),
            )
            for _ in range(num_experts)
        ])
        # 任务头
        self.head = nn.Linear(d, 7)
        self.num_experts = num_experts
        self.top_k = top_k

    def forward(self, v_feat, t_feat, p_feat):
        # Concat
        combined = torch.cat([v_feat, t_feat, p_feat], dim=-1)  # (B, 3d)
        # 路由权重
        router_logits = self.router(combined)  # (B, num_experts)
        top_k_logits, top_k_idx = router_logits.topk(self.top_k, dim=-1)
        top_k_weights = F.softmax(top_k_logits, dim=-1)  # (B, top_k)
        # 稀疏激活
        out = torch.zeros(combined.size(0), 256, device=combined.device)
        for i in range(self.top_k):
            expert_idx = top_k_idx[:, i]  # (B,)
            weight_i = top_k_weights[:, i:i+1]  # (B, 1)
            for e in range(self.num_experts):
                mask = expert_idx == e
                if mask.any():
                    expert_out = self.experts[e](combined[mask])  # (n, d)
                    out[mask] += weight_i[mask] * expert_out
        return self.head(out)
```

**优势**: 不同模态组合可以走不同专家路径, 避免所有样本共享同一个融合方式。

### 6.7 时间维度:从静态融合到时序融合

上面讨论的都是**单帧**融合。实际机器人是连续工作的, 需要时序信息:

**方案 1: 多帧拼接**

把过去 N 帧的所有模态拼起来, 当一个超长序列送 Transformer。

**问题**: 序列长度爆炸, $O(N^2)$ attention 计算量受不了。

**方案 2: 时序模型 + 多模态**

用 LSTM / Mamba / Transformer 处理时序, 每帧内部多模态融合:

```python
class TemporalMultimodal(nn.Module):
    """每帧内部融合 + 时序 Transformer"""
    def __init__(self, d=256):
        super().__init__()
        # 每帧的多模态融合 (intra-frame)
        self.frame_fusion = MultimodalTransformer(d=d)
        # 时序 Transformer (inter-frame)
        self.temporal = nn.TransformerEncoder(
            nn.TransformerEncoderLayer(d, nhead=8, batch_first=True),
            num_layers=3
        )
        # 输出头
        self.head = nn.Linear(d, 7)

    def forward(self, rgb_seq, tactile_seq, proprio_seq):
        # rgb_seq: (B, T, 3, H, W)
        # 每帧独立融合
        B, T = rgb_seq.shape[:2]
        frame_feats = []
        for t in range(T):
            ft = self.frame_fusion(rgb_seq[:, t], tactile_seq[:, t], proprio_seq[:, t])
            frame_feats.append(ft)
        frame_feats = torch.stack(frame_feats, dim=1)  # (B, T, d)
        # 时序融合
        out = self.temporal(frame_feats)  # (B, T, d)
        # 取最后一帧
        return self.head(out[:, -1])
```

**方案 3: 滑动窗口 + 双流**

只保留最近 K 帧, 加一个 "长程记忆" LSTM。

### 6.8 缺失模态的处理

真实部署中, 某模态可能临时失效 (相机被遮, 触觉线缆松了)。系统必须 graceful degrade。

**方案 1: 模态 Dropout (训练时随机掩盖)**

```python
class ModalityDropoutFusion(nn.Module):
    """训练时随机丢模态, 推理时能自动降级"""
    def __init__(self, num_modalities=3, drop_prob=0.3):
        super().__init__()
        self.drop_prob = drop_prob
        self.fusion = MultimodalTransformer()

    def forward(self, modalities):
        # modalities: list of tensors
        B = modalities[0].size(0)
        if self.training:
            # 每个样本独立决定是否丢模态
            mask = torch.bernoulli(
                torch.ones(B, len(modalities)) * (1 - self.drop_prob)
            )  # (B, num_mod)
            # 掩盖掉的模态用零向量
            for i, m in enumerate(modalities):
                modalities[i] = m * mask[:, i:i+1].to(m.device)
        return self.fusion(*modalities)
```

**方案 2: 缺失模态指示符**

显式告诉网络 "这个模态现在是空的":

```python
class MissingAwareFusion(nn.Module):
    """用 token 表示 "这个模态缺失" """
    def __init__(self):
        super().__init__()
        # 学一个 "缺失 token"
        self.missing_token_rgb = nn.Parameter(torch.randn(1, 1, d))
        self.missing_token_tactile = nn.Parameter(torch.randn(1, 1, d))
        # ... 后续融合
        self.fusion = MultimodalTransformer()

    def forward(self, rgb, tactile, rgb_present, tactile_present):
        if not rgb_present:
            rgb = self.missing_token_rgb.expand(tactile.size(0), -1, -1)
        if not tactile_present:
            tactile = self.missing_token_tactile.expand(rgb.size(0), -1, -1)
        return self.fusion(rgb, tactile)
```

### 6.9 模态间校准 (Calibration) 的工程难点

多模态融合的最大工程难题不是模型, 而是**校准**:

**空间标定**: 不同传感器在机器人坐标系里的相对位姿。
**时间标定**: 不同传感器的时钟同步 (μs 级)。
**尺度标定**: 不同传感器输出量纲不同 (RGB [0, 255], 力 [-50, 50] N, 角度 [0, 360]°)。

**实际部署的常见问题**:

1. **时间戳漂移**: RGB 30 Hz 一帧 33ms, 但 USB 传输延迟可能 5-10ms, 累积后误差大。
2. **坐标系不一致**: 触觉定义在指尖, 相机定义在头部, 飞控定义在世界。
3. **采样频率失配**: RGB 30 Hz, 力矩 1 kHz, 触觉 60 Hz。

**时间对齐的硬功夫: PTP/IEEE 1588**:

所有传感器接同一个主时钟 (PTP Grandmaster), 硬件时间戳精度 < 1μs。机器人领域的"金标准", 但成本高。

**低成本方案**: 软件时间戳 + 插值:
- 用最慢的传感器的时钟作主时钟
- 其他传感器记录相对时间
- 后处理做线性插值对齐

### 6.10 章节小结

多模态融合架构要点:
- **早期融合**: 像素级 concat, 强对齐场景 (指尖相机 + 指尖触觉)
- **中期融合**: 特征级, **主流方案**, cross-attention 最强
- **晚期融合**: 决策级, 模块化好, 效果较弱
- **Cross-Attention**: Transformer 式融合, 学术界主流
- **Token 化融合**: 所有模态统一 token, 多模态 LLM / VLA 主流
- **MoE**: 不同任务走不同专家, 适合大规模多模态
- **时序**: 多帧拼接 / 时序 Transformer / 滑动窗口
- **缺失模态**: 模态 Dropout + 缺失 token
- **校准**: 空间 + 时间 + 尺度三维, 是工程难点

```python
def fake_gelsight_image(B=4, H=240, W=320, n_contacts=2, seed=0):
    """合成 GelSight 接触图 (无真实数据时的占位)"""
    g = torch.Generator().manual_seed(seed)
    img = torch.zeros(B, 3, H, W, generator=g).uniform_(0.1, 0.3, generator=g)
    # 加 n 个高斯凸起, 模拟接触
    bg = torch.zeros(B, 3, H, W, generator=g)
    centers = torch.randint(20, min(H, W) - 20, (B, n_contacts, 2), generator=g)
    yy, xx = torch.meshgrid(
        torch.arange(H), torch.arange(W), indexing="ij"
    )
    for b in range(B):
        for c in range(n_contacts):
            cy, cx = centers[b, c]
            dist = (yy - cy).float() ** 2 + (xx - cx).float() ** 2
            bump = torch.exp(-dist / 500.0)  # 高斯
            # 弹起的区域颜色变化 (模拟光照变化)
            img[b, 0] += bump * 0.5
            img[b, 1] += bump * 0.3
            img[b, 2] -= bump * 0.2
    return img.clamp(0, 1)


# -----------------------------
# 7.1.2 简化法向估计
# -----------------------------
def estimate_normals_simple(tactile_img):
    """通过 RGB 三通道亮度变化粗略估法向
    假设: 三色 LED 从固定方向打光, 颜色分量强度反映法向
    """
    # 简化: 用 Sobel 算子算图像梯度
    grad_x = torch.zeros_like(tactile_img[:, :1])
    grad_y = torch.zeros_like(tactile_img[:, :1])
    grad_x[:, :, :, 1:-1] = tactile_img[:, :, :, 2:] - tactile_img[:, :, :, :-2]
    grad_y[:, :, 1:-1, :] = tactile_img[:, :, 2:, :] - tactile_img[:, :, :-2, :]
    # 法向 ≈ [-grad_x, -grad_y, 1] 归一化
    normals = torch.cat([-grad_x, -grad_y, torch.ones_like(grad_x)], dim=1)
    normals = F.normalize(normals, p=2, dim=1)
    return normals  # (B, 3, H, W)
```

### 7.3 实验 7.2: 多模态融合简化网络

```python
# -----------------------------
# 7.2.1 各模态 encoder
# -----------------------------
class TactileEncoder(nn.Module):
    """触觉图 encoder: (B, 3, 240, 320) -> (B, d_t)"""
    def __init__(self, d=128):
        super().__init__()
        self.backbone = nn.Sequential(
            nn.Conv2d(3, 32, 3, stride=2, padding=1),  # 120x160
            nn.ReLU(),
            nn.Conv2d(32, 64, 3, stride=2, padding=1), # 60x80
            nn.ReLU(),
            nn.Conv2d(64, 128, 3, stride=2, padding=1),# 30x40
            nn.ReLU(),
            nn.AdaptiveAvgPool2d((4, 4)),                # 4x4
        )
        self.proj = nn.Linear(128 * 4 * 4, d)

    def forward(self, x):
        feat = self.backbone(x).flatten(1)
        return self.proj(feat)


class ProprioEncoder(nn.Module):
    """本体感觉 encoder: (B, 26) -> (B, d_p)"""
    def __init__(self, d_in=26, d=64):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(d_in, 128), nn.ReLU(),
            nn.Linear(128, d),
        )

    def forward(self, x):
        return self.net(x)


# -----------------------------
# 7.2.2 多模态融合网络 (Cross-Attention)
# -----------------------------
class MultimodalFusionModel(nn.Module):
    """视觉 + 触觉 + 本体感觉三模态融合 -> 7-DoF 动作"""
    def __init__(self, d_v=512, d_t=128, d_p=64, d_fuse=256, nhead=8):
        super().__init__()
        # 视觉 (简化版, 用预训练 ResNet18 替代 ViT)
        from torchvision.models import resnet18, ResNet18_Weights
        vision = resnet18(weights=ResNet18_Weights.DEFAULT)
        vision.fc = nn.Identity()  # 去掉分类头
        self.vision_enc = vision
        # 触觉 + 本体
        self.tactile_enc = TactileEncoder(d=d_t)
        self.proprio_enc = ProprioEncoder(d=64)
        # 投影到统一维度
        self.v_proj = nn.Linear(d_v, d_fuse)
        self.t_proj = nn.Linear(d_t, d_fuse)
        self.p_proj = nn.Linear(d_p, d_fuse)
        # Cross-Attention: 视觉 tokens 互相 attend, 加触觉/本体作为额外 token
        self.cross_attn = nn.MultiheadAttention(d_fuse, nhead, batch_first=True)
        self.norm = nn.LayerNorm(d_fuse)
        # 输出头
        self.head = nn.Sequential(
            nn.Linear(d_fuse, 128), nn.ReLU(),
            nn.Linear(128, 7),
        )

    def forward(self, rgb, tactile, proprio):
        # 各模态编码
        v = self.vision_enc(rgb)            # (B, d_v)
        t = self.tactile_enc(tactile)        # (B, d_t)
        p = self.proprio_enc(proprio)        # (B, d_p)
        # 投影
        v_tok = self.v_proj(v).unsqueeze(1)  # (B, 1, d_fuse)
        t_tok = self.t_proj(t).unsqueeze(1)  # (B, 1, d_fuse)
        p_tok = self.p_proj(p).unsqueeze(1)  # (B, 1, d_fuse)
        # 拼接 + 自注意力
        tokens = torch.cat([v_tok, t_tok, p_tok], dim=1)  # (B, 3, d_fuse)
        out, _ = self.cross_attn(tokens, tokens, tokens)
        out = self.norm(tokens + out)         # (B, 3, d_fuse)
        # 池化 (取视觉 token 作为代表, 或 mean)
        pooled = out.mean(dim=1)              # (B, d_fuse)
        return self.head(pooled)              # (B, 7)
```

```python
def train_demo(epochs=5):

    loss_fn = nn.MSELoss()
    print(f"模型参数量: {sum(p.numel() for p in model.parameters()) / 1e6:.2f} M")

    for ep in range(epochs):
        rgb, tactile, proprio, action = fake_dataset(B=32)

        loss = loss_fn(pred, action)
        optim.zero_grad()
        loss.backward()
        optim.step()
        if (ep + 1) % 1 == 0:
            print(f"Epoch {ep+1}/{epochs}: loss = {loss.item():.4f}")
    return model


# -----------------------------
# 7.3.3 跨模态注意力可视化

def visualize_cross_attention(model, rgb, tactile, proprio):
```

## 9. 与数学基础的关系

### 9.1 数学基础/3-概率论/3-常用分布

**传感器噪声建模** (复用概率论):

每种传感器的噪声分布不同:
- **RGB 相机**: 读出噪声近似高斯 (CMOS 暗电流), N(μ, σ²)
- **深度相机**: ToF 多路径误差 ~ Gamma 分布
- **IMU**: 随机游走 bias + 高斯白噪声
- **力矩**: 应变片的热漂移 + 振动噪声, 近似 AR(1) 过程
- **触觉**: 弹性体噪声 + 离散化误差, 混合高斯

**工程意义**: 多模态融合在贝叶斯框架下是用不同噪声模型做加权:

$$p(\text{state} | \text{multi-modal}) \propto p(\text{RGB} | \text{state}) \cdot p(\text{tactile} | \text{state}) \cdot p(\text{force} | \text{state})$$

如果每个传感器的噪声模型已知, 可以用卡尔曼滤波做最优融合。这是最经典的多模态融合数学基础。

### 9.2 数学基础/5-信息论/3-互信息

**模态间互信息**:

互信息 $I(X; Y)$ 度量两个模态的"信息共享"。在多模态融合里:

$$I(\text{RGB}; \text{Tactile}) = \sum_{x, y} p(x, y) \log \frac{p(x, y)}{p(x) p(y)}$$

如果 $I$ 高 → 两种模态高度冗余, 早期融合即可。
如果 $I$ 低 → 互补信息, 中期/晚期融合更合适。

**实操方法**:
- 在小批量数据上, 用神经网络估计互信息 (MINE, InfoNCE)
- 用互信息矩阵做模态选择: 哪些模态互补, 哪些冗余

### 9.3 数学基础/6-最优化/3-梯度下降

**多模态融合的优化挑战**:

1. **不同模态的 loss 量纲不同**: 视觉分类 loss 是 cross-entropy, 力矩回归 loss 是 MSE。直接相加导致一种模态压过另一种。
2. **GradNorm / Uncertainty Weighting**: 用不确定性建模自动平衡多任务 loss。
3. **PCGrad / GradVac**: 解决梯度冲突, 当不同模态的梯度方向相反时。

### 9.4 数学基础/2-线代/5-SVD与伪逆

**多模态标定的核心工具**:

- **手眼标定** (5.6): AX = XB, 用 SVD 求最优旋转。
- **力-位姿映射** (§4.2): 8 应变片读数 → 6 维力, 用伪逆 $C^+$ 求。
- **Cross-Attention 简化**: 在低秩近似下, 注意力矩阵可以用 SVD 压缩。

### 9.5 与 1-信息论 的关系

**多模态融合的信息瓶颈视角**:

(参见 5-信息论/6-信息瓶颈 IB)

IB 理论在多模态的应用:
- 学习一个**压缩** $Z$, 保留任务相关的信息 (例如"抓取成功"), 丢弃模态特定噪声
- 多模态 IB: $Z$ 同时保留 RGB 和 Tactile 的有用信息
- 实际应用: VIB (Variational IB) 在多模态预训练里用作正则项

### 9.6 与 7-系统思维 的关系

参见数学基础/7-系统思维/案例14 (Transformer 注意力信息路由), Self-Attention 是多模态融合的数学骨架。

**核心引用**: "Q/K/V = 软寻址" 是 cross-attention 的信息论解读, 在本章 §6.4 反复使用。

## 10. 常见误区

### 10.1 误区 1: "多模态 = 越多越好"

**错误**: 堆 5 种传感器 (RGB + Depth + Tactile + Force + Audio + IMU), 训一个大模型, 以为性能一定好。

**真相**:
- 每种模态都引入了**计算和噪声**, 没有明显增益时, 收益递减。
- 模态间可能**互相干扰**: 当触觉数据质量差时, 加进去可能让模型学坏。
- **简单规则**: 先 baseline (单 RGB), 再加 1 个最有互补价值的模态 (一般是 Tactile 或 Force), 看是否能 +5%。再加就亏。

**数据支撑**: 论文 "When More is Not Better" (NeurIPS 2023) 表明, 当模态数 > 4 但总训练样本 < 100k, 多模态模型反而差于最好的单模态。

### 10.2 误区 2: "融合就是拼接"

**错误**: 把 RGB + Tactile 在通道维度 concat, 送进同一个 CNN, 觉得这就叫"融合"。

**真相**:
- 通道拼接在**像素级对齐**的情况下能做早期融合, 但 RGB 视角 ≠ Tactile 视角。
- 不同模态的"有效粒度"不同: RGB 看 224×224, Tactile 看 15×20 (GelSight-mini 视野不同)。
- **正确做法**: 各自 encoder → 特征空间融合 (cross-attention), 或者 token 化。

**反例**: 某团队 2022 年真做过 RGB + Tactile 的通道拼接, 训练集 mAP 78%, 测试集 mAP 65% (差 13%)。因为触觉图的边缘和 RGB 边缘不对齐, 拼接引入了噪声。

### 10.3 误区 3: "传感器越多, 性能越好"

**错误**: 在机器人上加 10 个 RGB + 5 个 Tactile + 1 个 LiDAR, 认为 robot SOTA 指日可待。

**真相**:
- **传感器成本**: GelSight 一个 $500, ATI 力矩 $3000, 工业相机 $200, 加起来直接 > $10k
- **校准成本**: 多种传感器的时空对齐工程量大
- **延迟**: 多模态数据流会增加端到端延迟, 高速控制 (>1 kHz) 不可能

**正确做法**:
- **任务驱动**: 装配任务需要力矩, 抓鸡蛋需要触觉, 高速跟踪需要事件相机。
- **预算驱动**: $5k 预算, 选 1 个好相机 + 1 个触觉就够。
- **可维护**: 传感器越多, 维护工作量越大 (工业经验: 每多 1 个传感器, 维护成本 +30%)

### 10.4 误区 4: "触觉 = 加一层 CNN"

**错误**: 把触觉图当普通 RGB 图处理, 用 ImageNet 预训练的 ResNet。

**真相**:
- 触觉图和 RGB 图的**物理意义**完全不同。RGB 是物体表面颜色, 触觉是表面形变 + 受力。
- ImageNet 预训练特征对触觉基本无用 (预训练是物体类别, 触觉需要形变特征)。
- **建议**: 从零训触觉 encoder, 或用触觉专用预训练 (Meta 的 DIGIT 预训练)。

### 10.5 误区 5: "Cross-Attention 一定优于 Late Fusion"

**错误**: 任何时候都用 Cross-Attention, 因为"看起来更高级"。

**真相**:
- 在小数据 (< 1k 样本) 上, Late Fusion 比 Cross-Attention 更鲁棒 (更少过拟合)
- 当模态关联很弱时 (例如 RGB 和本体感觉), Cross-Attention 没显著增益
- 当计算资源有限 (边缘部署), Late Fusion 更轻量

**工程法则**:
- **数据量 < 10k**: Late Fusion
- **10k - 100k**: 中期融合 (Concat + MLP, 或 Gated Fusion)
- **> 100k, 强关联 (RGB+Tactile)**: Cross-Attention

### 10.6 误区 6: "忽略时间同步"

**错误**: 把所有传感器的数据扔给模型, 觉得"模型自己会学会对齐"。

**真相**:
- 没时间对齐, 触觉接触"门把手"和 RGB 看到"门把手" 可能差 100ms, 这段时间机器人已经动了。
- 触觉 60 Hz vs 视觉 30 Hz, 触觉的 2 帧可能对应视觉的 1 帧, 必须对齐。

**正确做法**:
- **硬件时间戳**: PTP/IEEE 1588
- **软件时间戳 + 插值**: 最低成本方案
- **模型内部对齐**: FlowNet / Temporal Transformer 学时间对应

### 10.7 误区 7: "训练用仿真, 部署就能用"

**错误**: 用 Isaac Sim 训多模态融合, 直接部署到真机, 以为 Sim-to-Real gap 很小。

**真相**:
- 仿真器的**触觉仿真**最弱: GelSight 的硅胶物理 (粘弹性)很难准确建模
- 力矩仿真看物理引擎 (Bullet 还可以, Isaac 的 PhysX 也不错, 但有 5-10% 误差)
- 视觉域漂移: 仿真里没噪声, 真实相机有 (运动模糊, sensor noise, ISO)

**正确做法**: Sim-to-Real transfer, 域随机化 (domain randomization) + 域自适应 (domain adaptation)。

## 11. L7/L8 面试 Q&A

### Q1: 多模态融合的层级选择? 各有什么 trade-off?

**标准答案**:

| 层级 | 融合方式 | 优点 | 缺点 | 适用 |
| :--- | :--- | :--- | :--- | :--- |
| **早期** | 像素/信号级 concat | 实现简单, 网络自动学 | 强对齐要求, 维度高 | 指尖相+指尖触觉 |
| **中期** | 特征级 (cross-attn) | 表达力最强, 不要求像素对齐 | 计算量大, 数据需求高 | 头部相机+指尖触觉 |
| **晚期** | 决策级 (加权/投票) | 模块化, 训练简单 | 错过跨模态交互 | 多模态差异大, 数据少 |
| **Token** | 统一 token 化 | 一个 Transformer 处理一切 | 工程复杂, 调度难 | VLA 模型, 大规模数据 |

**经验法则**:
- 强对齐 + 高速: 早期
- 中等数据 + 强关联: 中期 (cross-attn)
- 弱对齐 + 异步: 晚期
- 数据量大 + 多模态: Token 化

**面试加分点**: 提到 "**模态 dropout (Modality Dropout) 是工业界的标配**", 让模型在测试时也能 graceful degrade, 当某模态失效仍能工作。

### Q2: GelSight 触觉传感器的核心原理?

**标准答案**:

**核心原理**: 用**光学方法**测**弹性体形变**。

**具体步骤**:
1. 三色 LED 从不同方向照射**半透明硅胶**表面
2. 相机捕获表面彩色图像
3. 通过 **photometric stereo** 三色光定向, 反算表面**法向量**
4. 从法向量场**积分**得**三维形变图**

**优势**: 空间分辨率高 (0.1mm), 频率 60 Hz, 可重建 3D 形变。

**代表产品**: GelSight (MIT), GelSight-mini, DIGIT (Meta)。

**面试加分点**: 提到 "**GelSight 的物理基础是亚表面散射 (subsurface scattering)**", 半透明硅胶让光线在内部多次反射, 比纯反射模型更稳。DIGIT 是 GelSight 的开源低成本 ($15) 改进版, 装在 Allegro 指尖。

### Q3: 视触融合 vs 视音融合的对比?

**标准答案**:

| 维度 | 视触融合 (RGB+Tactile) | 视音融合 (RGB+Audio) |
| :--- | :--- | :--- |
| **采样率** | 视觉 30Hz, 触觉 60Hz | 视觉 30Hz, 音频 48kHz |
| **空间表示** | 相似 (图像/H×W) | 完全不同 (频域 1D) |
| **物理同步** | 强时空耦合 | 弱 (音可能延迟 100ms+) |
| **典型应用** | 抓取、装配、灵巧手 | 远程操作、视频理解 |
| **主导架构** | Cross-Attention | Token 化 + Audio Encoder |
| **代表论文** | Visuo-Tactile Fusion (Calandra 2020) | Audio-Visual Fusion (Owens 2016) |

**核心区别**: 视触融合**物理时空强耦合** (指尖触相机同时看到同一物体), 视音融合是**独立线索** (说话人可能不在镜头里)。

**面试加分点**: 提到 "**视音融合 + Cross-Attention 适合远程会议和视频理解, 视触融合 + Token 化适合灵巧操作**"。

### Q4: 缺失模态怎么处理?

**标准答案**:

三种主流方案:

1. **模态 Dropout (训练)**: 训练时随机把模态设为 0, 模型学降级能力。
2. **缺失模态 Token**: 给每种模态加一个 "缺席 token", 显式告诉网络 "这个模态是空的"。
3. **特征级填充**: 用其他模态的特征去预测缺失模态的特征。

**示例 (OpenVLA 的做法)**:

```python
if tactile is None:
    tactile = self.tactile_missing_token  # 学到的嵌入向量
```

**面试加分点**: 提到 "**Modality Dropout 是必须的训练技巧**", 不用它, 模型会在测试时遇到某模态失效就崩。

### Q5: 多模态校准的工程难点?

**标准答案**:

三大难点, 按工程难度排序:

1. **时间同步 (最难)**:
   - 不同传感器采样率不同 (RGB 30Hz, 力 1kHz, 触觉 60Hz)
   - 硬件延迟不一致 (USB 相机 5-10ms, 网络相机 100ms+)
   - 解决方案: PTP/IEEE 1588 硬件时间戳, 最低成本方案

2. **空间标定 (中等)**:
   - 相机在世界坐标系, 触觉在指尖坐标系, 力矩在关节坐标系
   - 解决方案: 手眼标定 (Tsai-Lenz), AprilTag / ArUco

3. **尺度归一化 (简单)**:
   - RGB [0, 255], 力 [-50, 50]N, 角度 [0, 360]°
   - 解决方案: 各自归一化到 N(0, 1) 或 [0, 1]

**典型时间对齐方案**:

```python
# PTP 硬件时钟同步 (μs 级精度)
import ptp
master = ptp.GrandMaster("eth0")  # 主时钟
sensors = [RGB, Force, Tactile, IMU]
for s in sensors:
    s.set_ptp_master(master)
# 每帧带硬件时间戳, 离线做时序对齐
```

**面试加分点**: 提到 "**硬件时间戳是工业级方案**", 软件时间戳 + 插值是 demo 级, 部署级不能用。

### Q6 (加分): Cross-Attention 在多模态融合里的具体变体?

**标准答案**:

| 变体 | 描述 | 优势 | 代表 |
| :--- | :--- | :--- | :--- |
| **Self-Attention** | 单模态内 attend (patch-patch) | 简单, 强大 | ViT |
| **Cross-Attention** | 一种模态 attend 另一种 | 跨模态信息 | Flamingo |
| **Co-Attention** | 双向 attend (Q1 attend Q2, Q2 attend Q1) | 双向交互 | DFAF |
| **Mixture-of-Attention** | 不同 head/层用不同模式 | 灵活 | Switch Transformer |
| **Token 化** | 所有模态统一 token | 一个 Transformer | Chameleon |

**跨模态最常用**: Cross-Attention, 因为它**信息流定向** (query 模态从 key/value 模态取信息), 可解释。

### Q7 (加分): 多模态融合的常见训练技巧?

**标准答案**:

1. **Modality Dropout**: 训练时随机丢模态, 强制学降级
2. **学习率分层**: 视觉 backbone 用小 LR (1e-5), 其他用大 (1e-3), 防止预训练权重被破坏
3. **梯度累积**: 多模态模型大, 用 micro-batch + accumulation
4. **EMA Teacher**: MoE 类模型, 教师网络平滑更新
5. **域随机化**: 仿真训练时随机化光照/物理参数, 提升 Sim-to-Real
6. **Token 平衡**: 多模态 token 数不同 (视觉 256, 触觉 1), 加 attention mask 防淹没

**面试加分点**: 提到 "**Modality Dropout + Token 平衡是工业必备, 不做这两个, 部署必崩**"。

## 13. 高级多模态融合架构

### 13.1 Mixture-of-Experts (MoE) 模态路由

MoE 不是把多个模态硬拼在一起,而是给每个 token 动态选专家。具身场景里视觉 patch、触觉点、力矩标量都是不同结构的 token, MoE 自然适配。

**核心公式**:

$$y = \sum_{i=1}^{k} G(x)_i \cdot E_i(x)$$

其中 $G(x)$ 是路由门控 (top-$k$), $E_i$ 是第 $i$ 个专家网络。具身里通常每专家对应一种模态或一种融合子任务。

**Switch Transformer 路由**:

$$G(x) = \text{softmax}(\text{TopK}(xW_g, k=1))$$

路由只选 1 个专家, 训练时加负载均衡 loss:

$$L_{\text{aux}} = \alpha \sum_{i=1}^{N} f_i \cdot P_i$$

$f_i$ 是专家 $i$ 被路由到的频率, $P_i$ 是平均路由概率, $\alpha = 0.01$ 是常用系数。

**工业配置** (NVIDIA GR00T 用):

| 专家数 | 路由 | 适用 |
| :--- | :--- | :--- |
| 4 | top-1 | 桌面操作 (RGB / Tactile / Force / Proprio) |
| 8 | top-2 | 移动操作 (加里程计 / 语音 / IMU / 力矩细分) |
| 16 | top-2 | VLA 大模型 (细粒度子任务路由) |

```text
            ┌──────────────────┐
            │   Input Tokens   │
            │ (RGB+Tac+Force+  │
            │   Proprio)       │
            └────────┬─────────┘
                     ▼
            ┌────────────────┐
            │ Router W_g     │
            │ (Linear +      │
            │  TopK softmax) │
            └────────┬───────┘
                     ▼
        ┌────────┬───┴───┬────────┬────────┐
        ▼        ▼       ▼        ▼        ▼
     ┌──────┐┌──────┐┌──────┐┌──────┐┌──────┐
     │Expert││Expert││Expert││Expert││Expert│
     │  1   ││  2   ││  3   ││  4   ││  N   │
     │ (Tac)││ (RGB)││(Force││(Prop)││ (共享)│
     └──────┘└──────┘└──────┘└──────┘└──────┘
                     ▼
            ┌────────────────┐
            │ Weighted Sum   │
            │ Σ G_i · E_i(x) │
            └────────────────┘
```

**专家坍缩 (expert collapse) 问题**: 路由退化到只用少数专家。解法: (1) 负载均衡 loss; (2) 路由温度退火; (3) 专家容量因子 (capacity factor = 1.25)。

### 13.2 Perceiver IO 架构

Perceiver 用一个小的 latent array (例如 256 个 latent token) 通过 cross-attention 接收多模态输入。优势是**输入尺寸解耦**, 处理任意长的视觉序列或触觉时序。

**公式**:

$$z_{i+1} = \text{CrossAttn}(z_i, X) + \text{SelfAttn}(z_i)$$

$z$ 是 latent (256, 768), $X$ 是输入 (N, d), N 可变。每层 latent 重新读 $X$。

**具身适配**:

```python
# 伪代码: Perceiver 接收 RGB (1, 3, 224, 224) + Tactile (1, 16, 3, 3)
latents = torch.randn(1, 256, 768)  # 可学习 latent
rgb_tokens = vit_patch_embed(rgb)     # (1, 196, 768)
tac_tokens = tac_cnn(tac).flatten(2).transpose(1,2)  # (1, 144, 768)
X = torch.cat([rgb_tokens, tac_tokens], dim=1)  # (1, 340, 768)
for layer in perceiver_blocks:
    latents = layer(latents, X)
output = task_head(latents.mean(dim=1))  # 决策
```

**工业价值**: 部署时换触觉型号 (DIGIT → GelSight), $X$ 维度变了, $z$ 不变, 头网络不用动。

### 13.3 Q-Former (BLIP-2 风格)

Q-Former 是一组**可学习 query token** (例如 32 个), 通过 cross-attention 从冻结的视觉编码器提取信息。VLA 模型大量采用 (RT-2, OpenVLA)。

**Q-Former 结构**:

```text
Q (learned, 32, 768) ──┐
                      ▼
                 Self-Attention
                      │
                      ▼
              Cross-Attention
                  Q ← K,V (Vision Encoder 输出)
                      │
                      ▼
                FeedForward
                      │
                      ▼
                Output (32, 768)
```

**三阶段训练**:

1. **视觉-语言对齐**: 用图像-文本对训, 让 query 学提取语义
2. **指令微调**: 用 VQA 数据训, 加 LLM head
3. **具身微调**: 用机器人轨迹训, 把 LLM head 换成 action head

**为何用 query 而不是直接用 vision output**: vision encoder 输出 256+ token, LLM 上下文贵; 32 个 query 把信息压缩到可控大小, 推理时延从 100ms 降到 30ms。

### 13.4 层次化融合 (Hierarchical Fusion)

不同模态在不同抽象层融合:

```text
Level 1 (Pixel/Signal): RGB raw + Tac raw + Force raw
   ↓ 各自 encoder
Level 2 (Low-level feat): edge / pressure map / force curve
   ↓ early fusion (concat)
Level 3 (Mid-level feat): object shape / contact region / wrench
   ↓ cross-attention
Level 4 (High-level): task / affordance / contact intent
   ↓ late fusion (决策融合)
Level 5 (Action): π(a|s)
```

**经验法则**: 视觉 + 触觉在 Level 2-3 融 (空间对齐天然); 力矩 + 本体在 Level 1 融 (时间序列对齐); 跨"视觉-力矩" 在 Level 3-4 融 (语义对齐)。

### 13.5 Token 化早期融合 (Chameleon 风格)

把所有模态 token 化, 一个 Transformer 处理:

```text
[IMG_0] [IMG_1] ... [IMG_255] [TAC_0] [FORCE] [PROPRIO_0..6] [ACT_0..6]
   └────────┬────────┘   └─┬─┘  └─┬─┘   └────┬────┘      └────┬────┘
   ViT patch embed    TacCNN  Linear   MLP                 Embedding
   (256, 768)       (1, 768)  (1,768) (7, 768)            (7, 768)
                              ↓
                       ┌──────────────────┐
                       │  Unified Transformer │
                       │  (Chameleon-style)   │
                       └──────────────────┘
                              ↓
                         Action Tokens
```

**优势**: 单 forward, 跨模态信息流自由。
**劣势**: 训练贵 (数据量要百万级), 推理显存高 (256+256+8+7 = 527 token, 推理慢)。
**适用**: VLA 大模型 (π0, RT-2), 数据量大且 GPU 多。

## 14. PyTorch 实现

### 14.1 视触融合网络 (Vision-Tactile Fusion)

```python
import torch
import torch.nn as nn
import torchvision.models as tv

class VisionTactileFusion(nn.Module):
    """中期融合: RGB feature (256d) + Tactile feature (128d) → action"""
    def __init__(self, n_actions: int = 7):
        super().__init__()
        # 视觉 backbone (冻结 ResNet-18 提升训练稳定性)
        rgb_backbone = tv.resnet18(weights=tv.ResNet18_Weights.DEFAULT)
        self.rgb_enc = nn.Sequential(*list(rgb_backbone.children())[:-1])
        for p in self.rgb_enc.parameters():
            p.requires_grad = False
        self.rgb_proj = nn.Linear(512, 256)

        # 触觉 encoder (从零训, 触觉分布和 ImageNet 差太远)
        self.tac_enc = nn.Sequential(
            nn.Conv2d(3, 32, 3, 2, 1), nn.GELU(),  # 64x64
            nn.Conv2d(32, 64, 3, 2, 1), nn.GELU(), # 32x32
            nn.Conv2d(64, 128, 3, 2, 1), nn.GELU(),# 16x16
            nn.AdaptiveAvgPool2d(1), nn.Flatten(),
            nn.Linear(128, 128)
        )

        # 跨模态 cross-attention
        self.cross_attn = nn.MultiheadAttention(256, 8, batch_first=True)
        self.norm = nn.LayerNorm(256)

        # 决策头
        self.head = nn.Sequential(
            nn.Linear(256+128, 256), nn.GELU(),
            nn.Linear(256, n_actions)
        )

    def forward(self, rgb, tac):
        # rgb: (B, 3, 128, 128); tac: (B, 3, 64, 64)
        with torch.no_grad():
            rgb_feat = self.rgb_enc(rgb).flatten(1)  # (B, 512)
        rgb_feat = self.rgb_proj(rgb_feat).unsqueeze(1)  # (B, 1, 256)
        tac_feat = self.tac_enc(tac).unsqueeze(1)         # (B, 1, 128)

        # 用视觉 query 触觉 key/value (触觉细粒度)
        fused, _ = self.cross_attn(rgb_feat, tac_feat, tac_feat)
        fused = self.norm(rgb_feat + fused).squeeze(1)     # (B, 256)

        return self.head(torch.cat([fused, tac_feat.squeeze(1)], dim=1))

# ponytail: 触觉从零训, ResNet 冻结 — 工业最简配置, 25ms 推理
```

**训练循环片段**:

```python
model = VisionTactileFusion().cuda()
optim = torch.optim.AdamW([
    {'params': model.rgb_proj.parameters(), 'lr': 1e-4},
    {'params': model.tac_enc.parameters(),   'lr': 1e-3},
    {'params': model.head.parameters(),     'lr': 1e-3},
    {'params': model.cross_attn.parameters(),'lr': 5e-4},
])

# 模态 dropout
def modality_dropout(rgb, tac, p=0.2):
    if torch.rand(1) < p: rgb = torch.zeros_like(rgb)  # 模拟相机遮挡
    if torch.rand(1) < p: tac = torch.zeros_like(tac)  # 模拟传感器失效
    return rgb, tac
```

### 14.2 力矩感知策略网络 (Force-Aware Policy)

```python
class ForceAwarePolicy(nn.Module):
    """本体 + 力矩 → action, 用于装配/插孔任务"""
    def __init__(self, proprio_dim=7, force_dim=6, n_actions=7):
        super().__init__()
        self.proprio_enc = nn.Sequential(
            nn.Linear(proprio_dim, 128), nn.GELU(),
            nn.Linear(128, 128)
        )
        self.force_enc = nn.Sequential(
            nn.Linear(force_dim, 64), nn.GELU(),
            nn.Linear(64, 64)
        )
        # LSTM 处理力矩时序 (装配里接触力是序列信号)
        self.force_lstm = nn.LSTM(64, 64, batch_first=True, num_layers=2)
        self.actor = nn.Sequential(
            nn.Linear(128+64, 256), nn.GELU(),
            nn.Linear(256, n_actions), nn.Tanh()
        )

    def forward(self, proprio, force_seq):
        # proprio: (B, 7); force_seq: (B, T, 6), T=10 滑动窗
        p = self.proprio_enc(proprio)              # (B, 128)
        f, _ = self.force_lstm(self.force_enc(force_seq))  # (B, T, 64)
        # 取最后步 + 平均 (防 LSTM 漂移)
        f = torch.cat([f[:, -1], f.mean(dim=1)], dim=-1)  # (B, 128)
        return self.actor(torch.cat([p, f], dim=-1))

# ponytail: 装配任务力矩序列短 (≤50 步), LSTM 够用, 不用 Transformer
```

### 14.3 多模态融合 Transformer (Vision+Tactile+Force+Proprio)

```python
class MultiModalTransformer(nn.Module):
    """Token 化早期融合, 4 模态 → 1 Transformer"""
    def __init__(self, d=256, n_heads=8, n_layers=6, n_actions=7):
        super().__init__()
        self.rgb_proj = nn.Linear(512, d)   # ViT 输出
        self.tac_proj = nn.Linear(128, d)
        self.force_proj = nn.Linear(6, d)
        self.proprio_proj = nn.Linear(7, d)
        self.action_embed = nn.Embedding(n_actions*2, d)  # 离散化

        # 模态类型嵌入 (防止模态混淆)
        self.modality_embed = nn.Embedding(4, d)
        self.pos_embed = nn.Parameter(torch.randn(1, 300, d))

        encoder_layer = nn.TransformerEncoderLayer(
            d, n_heads, dim_feedforward=1024, batch_first=True, dropout=0.1
        )
        self.transformer = nn.TransformerEncoder(encoder_layer, n_layers)
        self.head = nn.Linear(d, n_actions)

    def forward(self, rgb_feat, tac_feat, force, proprio, action_history):
        # rgb_feat: (B, 64, 512); tac_feat: (B, 1, 128)
        # force: (B, 6); proprio: (B, 7); action_history: (B, 8) long
        B = rgb_feat.shape[0]
        tokens = torch.cat([
            self.rgb_proj(rgb_feat),
            self.tac_proj(tac_feat),
            self.force_proj(force).unsqueeze(1),
            self.proprio_proj(proprio).unsqueeze(1),
            self.action_embed(action_history),
        ], dim=1)  # (B, 64+1+1+1+8=75, d)

        # 加模态类型 + 位置
        ids = torch.cat([
            torch.zeros(B, 64, dtype=torch.long),
            torch.ones(B, 1, dtype=torch.long),
            torch.full((B, 1), 2, dtype=torch.long),
            torch.full((B, 1), 3, dtype=torch.long),
            torch.full((B, 8), 4, dtype=torch.long),
        ], dim=1)
        tokens = tokens + self.modality_embed(ids) + self.pos_embed[:, :tokens.size(1)]
        out = self.transformer(tokens)
        return self.head(out[:, -1])  # 用 action token 位置输出
```

### 15.1 案例 1: Meta DIGIT + Franka 视触融合抓取

**背景**: Meta AI 2020 开源 DIGIT 触觉传感器 ($15 DIY), 在 Franka Panda 上做精细抓取。

**多模态配置**:
- 视觉: 顶部 Intel RealSense D435 (RGB-D, 30Hz)
- 触觉: 2 个 DIGIT 传感器装在二指夹爪 ($30 total), 60Hz
- 本体: Franka 关节编码器, 1kHz
- 力矩: Franka 内置 torque sensor, 1kHz

**融合方案**:
1. 视觉给**预抓取位姿** (bounding box → grasp pose)
2. 夹爪接近物体时, **触觉主导**: 检测到接触即闭合
3. 抓取后**力矩监测**: 滑动检测 (force/torque 突变 → 重抓)

**性能数据** (Meta 论文):
- 92 件日常物体抓取成功率: 视觉 79%, 视触融合 95.4%
- 透明物体提升最明显 (+30%, 因为视觉失效, 触觉补位)
- 反光物体 +18% (镜面干扰视觉, 触觉不依赖光学)

**工程经验**:
- DIGIT 60Hz, RealSense 30Hz, 用**降采样对齐** (触觉 → 30Hz), 别升采样视觉
- DIGIT 标定: 用 12 色卡 + 已知压力, 学 photometric stereo
- 触觉图像**光照敏感**, 装 LED 环保证均匀

### 15.2 案例 2: GelSight 精密插孔 (USB 插入)

**背景**: Tesla Optimus 公开论文披露, 手指尖用 GelSight-mini ($150), 做 USB-C / RJ45 插孔。

**挑战**: USB-C 接口深 8mm, 公差 ±0.5mm, 纯视觉在最后 5mm 被遮挡。

**融合方案**:
```text
Stage 1 (粗定位): 视觉给 6DoF 位姿, 误差 ~5mm
   ↓
Stage 2 (引导): 力矩检测首次接触 (力 > 0.5N)
   ↓
Stage 3 (微调): 触觉 + 力矩混合控制
   - GelSight 给接触点 2D 偏移 (xy, sub-mm)
   - 力矩给 z 方向接触力 (防过压)
   ↓
Stage 4 (确认): 力矩稳定 + 触觉图像含连接器纹理
```

**关键公式** (阻抗控制 + 触觉反馈):

$$f_{\text{cmd}} = K_p (x_{\text{desired}} - x_{\text{tac}}) + K_d \dot{x} + f_{\text{measured}}$$

$x_{\text{tac}}$ 来自触觉图像的接触中心估计, $f_{\text{measured}}$ 来自 F/T 传感器, $K_p, K_d$ 是阻抗参数。

**成功率**: 工业级要求 >99.5%, 单视觉方案仅 87%, 加触觉 + 力矩后 99.7%。

### 15.3 案例 3: ATI Mini45 力矩反馈在机械臂装配

**背景**: ABB YuMi 双臂机器人在 3C 产品装配线, 用 ATI Mini45 力矩传感器 ($3000/个) 做螺丝锁付。

**为什么必须用力矩**:
- 螺丝扭矩控制 ±5%, 视觉估不准 (螺丝头反光/角度变化)
- 滑丝检测: 力矩突变 → 立即停机, 防止报废
- 柔性装配: 工件 ±2mm 位移, 纯位控卡死, 力控可顺应

**融合方案**:
- 视觉: 基恩士 CV-5000 系列, 0.1s/帧, 给初始对齐
- 力矩: ATI Mini45, 1kHz, 实时阻抗控制
- 本体: ABB 编码器, 250Hz

**卡尔曼滤波融合**:

$$x_{\text{fused}} = K \cdot x_{\text{force}} + (1-K) \cdot x_{\text{visual}}$$

$K$ 是卡尔曼增益, 视觉置信度高时 $K$ 小, 力矩置信度高时 $K$ 大 (例如螺丝就位后, 视觉看不清, 力矩主导)。

**数据**: 一台 YuMi 每小时锁 240 颗螺丝, 力矩精度 ±3%, 满足手机主板装配要求。

## 16. 进阶 L7/L8 面试问答

### Q8 (L7): 早期融合 vs 中期融合 vs 晚期融合, 在具身场景里如何选?

**标准答案**:

| 维度 | 早期 | 中期 | 晚期 |
| :--- | :--- | :--- | :--- |
| 信息保留 | 高 | 中 | 低 |
| 数据需求 | 大 (>1M 样本) | 中 (100K) | 小 (10K) |
| 训练稳定性 | 差 (模态分布差) | 好 | 最好 |
| 部署难度 | 高 (端到端) | 中 | 低 |
| 实时性 | 最好 (单 forward) | 中 | 最差 (多 forward) |
| 代表 | Chameleon, π0 | Flamingo, OpenVLA | ALOHA |

**选择公式** (工程师视角):

```text
if 数据量 > 1M and GPU > 8 and 任务 > 50 类:
    → 早期融合 (VLA 大模型)
elif 数据量 100K-1M and 任务 < 50 类:
    → 中期融合 (cross-attention, 工业最常用)
else:
    → 晚期融合 (小数据, demo 友好)
```

**加分点**: "**中期融合是工业甜点** (crosst-attention), 它平衡了信息保留和训练稳定性。早期融合只在数据 + 算力都充足时用 (VLA 大模型), 晚期融合只在数据少时用 (单任务 demo)。"

### Q9 (L8): 触觉传感器如何选型? GelSight / DIGIT / 压阻 / 电容 各有什么优劣?

**标准答案**:

| 类型 | 原理 | 空间分辨率 | 量程 | 频率 | 成本 | 适用 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **GelSight (光学)** | 形变→光场 | 1000+ 点/cm² | 0-30N | 60Hz | $150 | 精细 (插孔/抓取) |
| **DIGIT (光学)** | 形变→摄像头 | 100 点/cm² | 0-10N | 60Hz | $15 | 研究/低成本 |
| **压阻阵列** | 力→电阻 | 16-64 点 | 0-50N | 1kHz | $50 | 高频振动 |
| **电容阵列** | 力→电容 | 16-64 点 | 0-5N | 100Hz | $20 | 高灵敏度 |
| **MEMS (应变片)** | 力→形变 | 1-4 点 | 0-200N | 10kHz | $10 | 力控 (工业级) |

**选择决策树**:

```text
任务需要空间细节 (插孔)?
   是 → GelSight / DIGIT (光学)
   否 → 任务需要高频 (装配振动)?
       是 → 压阻 / MEMS (≥1kHz)
       否 → 任务需要低成本 (消费机器人)?
           是 → 电容 (阵列)
           否 → 看精度需求
```

**加分点**: "**触觉没有银弹**。GelSight 分辨率高但慢, MEMS 频率高但点位少, 工业级装配常是 GelSight (精) + MEMS (力) 双模态融合。"

### Q10 (L8): 力矩传感器装在哪? 关节 vs 末端?

**标准答案**:

| 安装位置 | 测量范围 | 优 | 劣 | 代表 |
| :--- | :--- | :--- | :--- | :--- |
| **关节内** (Joint Torque) | 关节扭矩 | 频率高 (1kHz), 无重力补偿 | 受惯性/摩擦干扰 | KUKA LWR, Franka |
| **腕部** (Wrist F/T) | 6DoF 力矩 | 信号直接, 无惯性 | 贵 ($3K), 重 | ATI Mini45 |
| **指尖** (Fingertip) | 3DoF 力 | 接触力直接 | 量程小 | OptoForce |

**Franka 案例**: Franka 内置 7 个关节扭矩传感器, 1kHz, 通过**动力学模型**实时计算末端力:

$$\tau_{\text{ext}} = \tau_{\text{measured}} - M(q)\ddot{q} - C(q,\dot{q})\dot{q} - g(q)$$

$M$ 是质量矩阵, $C$ 是科里奥利, $g$ 是重力, $q$ 是关节角。这叫**关节扭矩外推法 (JTSE)**。

**经验**: 关节扭矩适合**控制环** (1kHz), 腕部 F/T 适合**碰撞检测** (低延迟)。工业实践常常关节 + 腕部都装, 双保险。

**加分点**: "**关节扭矩是软件定义力矩**, 腕部是硬件定义力矩。Franka 关节扭矩+JTSE 等效于腕部 F/T, 成本低 ($0 vs $3000) 但计算贵 (动力学模型实时跑)。"

### Q11 (L8): 多模态融合里的过拟合怎么诊断?

**诊断手段**:

1. **模态级过拟合**: 单一模态 acc >95% 但融合 acc <80%, 说明模态间冲突
2. **样本级过拟合**: 训练 acc 99% 验证 acc 60%, 经典过拟合
3. **跨 embodiment 过拟合**: A 机器人训的模型, B 机器人上 30%, 必现
4. **任务过拟合**: 训 50 任务, 在新任务上 0%, 没学到泛化特征

**解决**:
1. **模态 dropout**: $p=0.2$, 强制每个模态独立可用
2. **跨 embodiment 数据**: Open X-Embodiment 集 (60+ 机器人)
3. **任务域随机化**: 仿真随机化
4. **冻结 backbone**: 视觉 / 力矩 encoder 冻结, 只训融合层

**加分点**: "**多模态过拟合的特征是'模态各自强, 融合崩'**。模态 dropout + 冻结 backbone 是双保险。"

### Q12 (L8): VLA 模型 (π0, RT-2) 在多模态融合上的核心创新?

**π0 (Physical Intelligence 2024)**:

1. **Flow Matching 替代 Diffusion**: 输出动作是连续流, 而不是去噪, 训练快 5x
2. **Action Chunking**: 输出未来 K=50 步动作, 推理频率 50Hz
3. **混合模态输入**: 视觉 + 触觉 + 本体 + 语言指令 → 单 Transformer

**RT-2 (Google DeepMind 2023)**:

1. **Action as Token**: 动作离散化到 256 bins, 跟文本 token 共享 vocab
2. **Co-fine-tuning**: 联网数据 + 机器人数据联合训练
3. **Emergent Skills**: 未训过的指令也能执行 (泛化能力)

**共同设计哲学**:
- **统一 token 化**: 把所有模态当 token, 一个 Transformer
- **大规模预训练**: 数十亿样本 (网络 + 机器人)
- **少样本泛化**: 新任务给个 demo 就能做

**加分点**: "VLA 的核心创新不是架构, 是**数据规模**。架构上 cross-attention 早就有了, VLA 用数据暴力把多模态融合训到涌现 (emergence)。"

## 18. 高级训练技巧 (L8)

### 18.1 课程学习 (Curriculum Learning)

多模态任务从易到难排课:

```text
Level 1: 静态物体抓取 (无接触力)        ← 100% 成功率门槛
Level 2: 简单推/拨 (有接触力, 单模态)   ← 视觉 OR 力矩
Level 3: 滑动接触 (视触融合)            ← 必须融合
Level 4: 装配 (力矩 + 触觉 + 本体)      ← 三模态
Level 5: 复杂操作 (双臂 + VLA)          ← 全模态
```

**经验**: 训完 Level 2 才解锁 Level 3, 否则融合学不会。

### 18.2 对比学习 (Contrastive Pre-training)

像 CLIP 训触觉-视觉对齐:

```python
# 简化版: 对比学习
def contrastive_loss(tac_emb, rgb_emb, temperature=0.07):
    B = tac_emb.shape[0]
    sim = tac_emb @ rgb_emb.T / temperature  # (B, B)
    labels = torch.arange(B, device=sim.device)
    return F.cross_entropy(sim, labels) + F.cross_entropy(sim.T, labels)

# 正样本: 同一时刻的 tac+rgb; 负样本: 不同时刻
```

**效果**: DIGIT 用对比预训练后, 抓取任务上少 50% 数据达到同样精度。

### 18.3 RL + 多模态融合

在 PPO/SAC 里加多模态奖励塑形:

$$r_t = r_{\text{task}} + \lambda_1 r_{\text{smooth}} + \lambda_2 r_{\text{force}}$$

$r_{\text{smooth}}$ 来自动作时序, $r_{\text{force}}$ 来自力矩平稳度, $\lambda_1, \lambda_2$ 是权重。

**例子**: 插孔任务, 加 $r_{\text{force}}$ 后训练快 3 倍收敛。

```text

自有真实数据: 0.1
```

比例不是死的, 看任务。**仿真为主 + 真实微调**是工业标准。

## 21. 终极公式表 (Cheat Sheet)

### 21.1 融合层

$$\text{Fusion}_{\text{early}}(x_v, x_t) = W[v; t; f; p]$$

$$\text{Fusion}_{\text{mid}}(x_v, x_t) = \text{softmax}(Q_v K_t^T / \sqrt{d}) V_t$$

$$\text{Fusion}_{\text{late}}(x_v, x_t) = \alpha \cdot g_v(x_v) + (1-\alpha) \cdot g_t(x_t)$$

### 21.2 力控

$$M\ddot{x} + B\dot{x} + Kx = f_{\text{ext}}$$

$$\tau_{\text{ext}} = \tau_{\text{meas}} - M(q)\ddot{q} - C(q,\dot{q})\dot{q} - g(q)$$

### 21.3 MoE

$$y = \sum_{i=1}^{N} G(x)_i E_i(x), \quad G(x) = \text{softmax}(\text{TopK}(xW_g))$$

$$L_{\text{aux}} = \alpha \sum_{i} f_i P_i$$

### 21.4 卡尔曼

$$x_{t|t} = x_{t|t-1} + K_t(z_t - H x_{t|t-1})$$

$$K_t = P_{t|t-1} H^T (H P_{t|t-1} H^T + R)^{-1}$$

### 21.5 Transformer

$$\text{Attn}(Q,K,V) = \text{softmax}(QK^T / \sqrt{d_k})V$$

$$\text{FFN}(x) = \max(0, xW_1 + b_1) W_2 + b_2$$

### 21.6 VLA Action (Flow Matching)

$$v_t = (x_1 - x_0) \cdot t, \quad L = \|v_\theta(x_t, t) - v_t\|^2$$

### 21.7 触觉法向恢复 (Photometric Stereo)

$$n_i = (I_i - I_0) / k_i, \quad z = \nabla^{-2} \sum_i n_i$$

```python
class SafeMultiModalPolicy:

        self.failsafe = False

        # 异常检测
        if torch.isnan(rgb).any() or torch.isnan(tac).any():
            self.failsafe = True
            return torch.zeros(7, device=self.device)  # 停车
        if force.abs().max() > 100:  # 异常力
            self.failsafe = True
            return torch.zeros(7, device=self.device)

        with torch.no_grad(), torch.cuda.amp.autocast():
            action = self.model(rgb, tac, force, proprio)
        # 动作限幅 (安全)
        return torch.clamp(action, -1.0, 1.0)
```

### 23.2 数据同步 (硬件时间戳)

```python
import ptp  # 伪代码, 实际用 linuxptp + socket
class HardwareSync:
    def __init__(self):
        self.master = ptp.GrandMaster("eth0")
        self.sensors = {}

    def register(self, name, sensor):
        sensor.set_ptp_master(self.master)
        self.sensors[name] = sensor

    def get_synced(self):
        # 所有传感器共享同一时间戳
        data = {}
        t_master = self.master.now()  # μs 精度
        for name, sensor in self.sensors.items():
            data[name] = sensor.read(t_master)  # 插值对齐
        return data, t_master
```

### 23.3 域随机化 (Sim-to-Real)

```python
class TactileRandomizer:
    """仿真触觉图像加噪声, 提升 Sim-to-Real 迁移"""
    def __init__(self):
        self.gaussian_std = 0.02
        self.illumination_jitter = 0.15

    def __call__(self, tac_img):
        # 高斯噪声
        tac = tac_img + torch.randn_like(tac_img) * self.gaussian_std
        # 光照抖动 (模拟 LED 老化)
        scale = 1.0 + (torch.rand(1) - 0.5) * self.illumination_jitter
        return torch.clamp(tac * scale, 0, 1)
```

## 26. 多模态对齐的几何与统计方法 (L8 进阶)

### 26.1 跨模态几何对齐 (Procrustes)

不同模态的特征向量在嵌入空间存在线性变换, 用 Procrustes 分析:

$$R^* = \arg\min_{R \in O(d)} \|X_v R - X_t\|_F$$

最优旋转 $R^* = U V^T$, 其中 $X_v = U \Sigma V^T$ 是 SVD 分解。具身里用 Procrustes 把视觉特征对齐到触觉空间, 或反之。

```python
import torch
def procrustes_align(x_vis, x_tac):
    # x_vis, x_tac: (N, d), N 个对齐样本对
    X = x_vis - x_vis.mean(0)
    Y = x_tac - x_tac.mean(0)
    U, _, Vt = torch.linalg.svd(X.T @ Y)
    R = U @ Vt
    return R  # 用 R 把视觉转触觉空间
```

**用途**: 跨 embodiment 迁移时, 视觉特征空间不变, 触觉特征空间对齐。

### 26.2 典型相关分析 (CCA)

CCA 找视觉 $X_v$ 和触觉 $X_t$ 的共享子空间:

$$\max_{a, b} \text{corr}(a^T X_v, b^T X_t) \quad \text{s.t. } \text{Var}(a^T X_v) = \text{Var}(b^T X_t) = 1$$

具身里用于**无监督多模态融合**: 训一个 CCA 层把多模态投影到共同空间。

**Deep CCA** (Andrew et al. 2013) 用神经网络非线性化:

$$h_v = f_v(X_v), \quad h_t = f_t(X_t)$$

$$L = -\|h_v^T h_t\|^2 + \lambda (\|h_v\|^2 + \|h_t\|^2)$$

### 26.3 互信息最大化 (MINE)

Mutual Information Neural Estimation:

$$\hat{I}(X;Y) = \sup_T \mathbb{E}_{p(x,y)}[T(x,y)] - \log \mathbb{E}_{p(x)p(y)}[e^{T(x,y)}]$$

具身里用来**最大化视觉-触觉互信息**, 让融合层学到真正互补的特征, 而不是冗余。

**经验**: 视觉-触觉互信息 < 0.5 nats 说明模态基本无关 (例如视觉看场景, 触觉没接触), > 2 nats 是强相关 (例如看物体+触摸同一物体)。

### 26.4 中心矩差异 (CMD)

迁移学习用 CMD 对齐源域和目标域的激活分布:

$$\text{CMD}_k(X, Y) = \frac{2}{|X||Y|} \sum_{x \in X} \sum_{y \in Y} \prod_{j=1}^k \|x - y\|$$

具身里用来**仿真→真实** 跨域多模态融合: 仿真激活和真实激活对齐, 模型迁移更稳。

## 27. 多模态注意力变体手册

### 27.1 主流变体对照

| 变体 | Q 来源 | K/V 来源 | 复杂度 | 适用 |
| :--- | :--- | :--- | :--- | :--- |
| Self-Attention | $X$ | $X$ | $O(N^2 d)$ | 单模态内 (ViT) |
| Cross-Attention | $X_q$ | $X_{kv}$ | $O(N_q N_{kv} d)$ | 跨模态 (主流) |
| Co-Attention | 双向 | 双向 | $O(2 N^2 d)$ | 双向融合 (DFAF) |
| Flash Attention | $X$ | $X$ | $O(N)$ 内存 | 长序列 |
| Linear Attention | $X$ | $X$ | $O(N d^2)$ | 推理加速 |
| Sparse Attention | $X_{\text{selected}}$ | $X$ | $O(N^{1.5} d)$ | 大视觉编码 |
| Grouped Query | 多头 Q 共享 | 多头 K/V | $O(N^2 d / g)$ | LLaMA-2 风格 |
| Sliding Window | 局部 Q | 局部 K/V | $O(N w d)$ | 流式时序 |

### 27.2 工业选型公式

```text
if N <= 512 and 部署实时性 > 30 FPS:
    → Standard Self-Attention
elif N > 1024 (长视觉):
    → Flash Attention 2
elif 多模态融合:
    → Cross-Attention (Q from language/tac, KV from vision)
elif VLA 大模型推理:
    → Grouped Query Attention (LLaMA-2/3 风格)
elif 流式时序 (关节轨迹):
    → Sliding Window (window=32)
```

### 27.3 Flash Attention 2 在具身的应用

Flash Attention 2 把注意力计算从 $O(N^2)$ 内存降到 $O(N)$, 长视觉序列 (e.g. 4096 patch) 推理从 80ms 降到 25ms。

- 视觉编码 4096 patch (1024x1024 图): 标准 80ms → Flash 25ms
- 视频预测 16 帧 x 256 patch = 4096: 同上
- VLA 多模态 token 2000+: Flash 是标配

### 28.1 模型架构

```text
Input: [IMAGE_PATCHES] [TACTILE_TOKENS] [LANG_TOKENS]
                ↓

                ↓

```

**核心思想**: 冻结预训练 VLM (e.g. LLaVA), 加 LoRA 让触觉 token 注入。

### 28.2 触觉 Token 化

触觉图像 (60Hz, 320x240) 不能直接 token 化, 先压缩:

```python
class TactileTokenizer(nn.Module):
    def __init__(self, tac_shape=(3, 64, 64), n_tokens=16, d=4096):
        super().__init__()
        self.encoder = nn.Sequential(
            nn.Conv2d(3, 32, 3, 2, 1), nn.GELU(),    # 32x32
            nn.Conv2d(32, 64, 3, 2, 1), nn.GELU(),   # 16x16
            nn.Conv2d(64, 128, 3, 2, 1), nn.GELU(),  # 8x8
            nn.Flatten(),
            nn.Linear(128*8*8, d),
            nn.LayerNorm(d)
        )
        self.q_tokens = nn.Parameter(torch.randn(n_tokens, d))

    def forward(self, tac):
        # tac: (B, 3, 64, 64) → (B, n_tokens, d)
        feat = self.encoder(tac).unsqueeze(1)  # (B, 1, d)
        # 用 cross-attention 把 feat 压缩到 n_tokens
        q = self.q_tokens.unsqueeze(0).expand(tac.shape[0], -1, -1)
        out = torch.nn.functional.scaled_dot_product_attention(q, feat, feat)
        return out
```

## 29. 安全与冗余设计 (L8 Production)

### 29.1 多模态冗余架构

```text
        ┌─ Camera 1 ─┐
        │            │
Decision←├─ Camera 2 ─┤ ←── 视觉冗余 (多视角投票)
        │            │
        └─ Force × 2 ┘
             │
             ├─ Tactile × 2
             │
             └─ Encoder × 2 (主+备)
```

**冗余原则**:
1. 关键传感器 2x 配置 (e.g. 2 个力矩传感器)
2. 异构冗余 (e.g. 视觉失效时用力矩兜底)
3. 表决机制 (3 选 2 投票)
4. 故障检测 + 切换 (< 100ms)

### 29.2 安全状态机

```text
        ┌─────────┐
        │  NORMAL │ ← 所有传感器正常
        └────┬────┘
             │ sensor fail
             ▼
        ┌─────────┐
        │ DEGRADED│ ← 单模态失效, 降级运行
        └────┬────┘
             │ > 2 sensors fail OR 力矩过载
             ▼
        ┌─────────┐
        │ EMERGENCY│ ← 紧急停车
        └─────────┘
```

**代码实现**:

```python
class SafetyMonitor:
    def __init__(self):
        self.state = "NORMAL"
        self.failed_sensors = set()
        self.force_threshold = 80  # N

    def check(self, sensors):
        for name, data in sensors.items():
            if data is None or torch.isnan(data).any():
                self.failed_sensors.add(name)

        if len(self.failed_sensors) >= 2:
            self.state = "EMERGENCY"
        elif len(self.failed_sensors) == 1:
            self.state = "DEGRADED"

        force = sensors.get("force")
        if force is not None and force.abs().max() > self.force_threshold:
            self.state = "EMERGENCY"

        return self.state

    def get_action(self):
        if self.state == "NORMAL":
            return policy(sensors)
        elif self.state == "DEGRADED":
            return degraded_policy(sensors)  # 慢速 + 保守
        else:
            return torch.zeros(7)  # 停车
```

| 失效 | 兜底策略 | 切换时延 |

| 视觉失效 | 用触觉 + 力矩 | < 50ms |
| 触觉失效 | 用视觉 + 力矩 | < 50ms |
| 力矩失效 | 用本体 + 触觉估计 | < 50ms |
