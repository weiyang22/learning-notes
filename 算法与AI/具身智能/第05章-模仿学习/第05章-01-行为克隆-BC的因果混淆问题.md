# 第05章-01-行为克隆-BC的因果混淆问题

训练过分类器, 跑过目标检测, 调过推荐模型...但让机器人**看着你做一遍就学会**, 是另一回事。
>
> 行为克隆 (Behavior Cloning, BC) 看起来简单到像"监督学习套到机器人上", 一个 MLP, 一对 (state, action), MSE 损失, 完事。但 1988 年 ALVINN (CMU 自动驾驶) 到 2024 年 Figure 02, 几乎所有用过 BC 的团队都撞过同一面墙:
>
> - **训练集上 99% 准确, 部署时 30% 成功率**? 这是协变量偏移。
> - **"学会"做任务, 但换条路线就废**? 这是因果混淆。
> - **专家做一次能成, 机器人做 100 次都不成**? 这是误差累积。
>
> BC 的失败模式与解决它, 构成了 §2 DAgger / §3 Diffusion Policy / §4 目标条件 / §5 人类视频 整章 90% 的内容。
>
> **学完本章, 你能回答**:
> - BC 在数学上等价于什么? 为什么"监督学习"三个字骗了你?
> - 为什么训练集和测试集的分布"看起来"一样, BC 还是会挂?
> - 误差累积 $\epsilon_t \le \epsilon_0 \cdot (1 + \varepsilon)^t$ 从哪来?
> - 工业界怎么用 BC? Tesla / Figure 02 / 1X NEO 的数据收集范式是什么?
> - 怎么在 200 行 PyTorch 里复现 BC + 因果混淆可视化?
>
> **与数学基础的关系** (高复用):
> - `数学基础/3-概率论/3-常用分布` ← 动作的分布建模 (高斯 / Categorical)
> - `数学基础/6-最优化/1-优化问题分类` ← BC 是经验风险最小化
> - `数学基础/3-概率论/6-MLE·MAP·贝叶斯估计` ← BC = 极大似然估计
>

> - §2 DAgger: 本章的因果混淆是 DAgger 的动机

## 1. 直觉引入

### 1.1 模仿学习的核心思想

想象一个场景: 你的同事用 VR 头显 + 手柄, 用 30 分钟演示了 50 次"把桌上的红方块放进蓝碗"。你把这 50 次的 (摄像头画面, 手柄位姿) 录下来, 然后训了一个神经网络: 输入是当前画面, 输出是 6 自由度手柄位姿 (x, y, z, roll, pitch, yaw)。

测试时, 把这个网络部署到机械臂上, 摄像头对着桌面, 网络输出位姿, 机械臂执行。

**问题**: 这个网络在训练画面上准确率 99%, 部署到真实机器人上, 成功率多少?

答案不是 99%, 也不是 50%, 通常是 0% 到 30%。为什么?

最简单的解释: **训练分布 ≠ 推理分布**。专家演示时, 画面里的红方块永远在桌面中央偏左。BC 学到的是"看到红方块在中央偏左, 就伸手过去"。部署时, 摄像头稍微一动, 红方块不在中央偏左了, 网络就懵了。

但这只是表象。背后有三个层层递进的问题:

1. **协变量偏移** (covariate shift): 训练时看到的 state 分布是 $d^{\pi^*}(s)$, 推理时是 $d^{\pi_\theta}(s)$。两个分布不同, 模型在 $d^{\pi^*}$ 上学到的关联, 在 $d^{\pi_\theta}$ 上不成立。
2. **误差累积** (error compounding): 推理时第一步偏离 1cm, 第二步偏离 2cm, 第三步偏离 4cm, ... $t$ 步后偏离 $2^t$ cm。BC 在长程任务上"指数级"退化。
3. **因果混淆** (causal confusion): BC 学到"看到 X 做 Y"的**关联**, 但专家**为什么**做 Y, 模型没学到。如果专家因"前方有障碍"而左转, BC 可能学成"看到红灯左转", 错过红灯就不左转。

这三点构成本章的"BC 失败三件套"。在 §3 我们会逐个拆解, 在 §2 之后的章节会看到 DAgger / Diffusion Policy 怎么解决它们。

### 1.2 监督学习视角

如果你只看到"输入 state, 输出 action", BC 看起来就是监督学习:

```text
监督学习 (图像分类):     image → cat
行为克隆 (机器人):        image → [x, y, z, r, p, y]
```

**表层结构相同**, 但隐藏假设完全不同:

| 维度 | 监督学习 | 行为克隆 |
| :--- | :--- | :--- |
| 输入分布 | 测试时和训练时 i.i.d. | 推理时是 $d^{\pi_\theta}(s)$, 与训练时不同 |
| 标签来源 | 人工标注 (人看到图, 写出答案) | 专家策略 $\pi^*$ 的输出 (人做动作, 录下来) |
| 错误影响 | 单样本错 | 状态转移, 错误会"传染"到下一步 |
| 评估指标 | 准确率 / MSE | 任务成功率 / 累计回报 |
| 失败模式 | 训练-测试分布差 | 训练-推理分布差 (更隐蔽) |

**关键差异**: 监督学习的 i.i.d. 假设在 BC 上**不成立**。机器人看到的状态是它**自己**产生的, 不是从固定数据集里采的。

这个差异在 1988 年 ALVINN 那篇论文里就被指出了。ALVINN 用神经网络从摄像头画面预测方向盘角度, 在训练路段上 100% 成功, 换条路就废。Sammut & Srinivasan 在 1996 年的论文里第一次用"因果混淆"来描述这个问题。

**为什么这个差异重要?** 监督学习失败时, 模型是"错的", 输错了标签, 算错了概率。BC 失败时, 模型是"过自信的", 它输出一个看起来很合理的动作, 但这个动作把机器人推到了训练分布之外, 之后每一步都在补救, 最终失败。

### 1.3 为什么机器人需要模仿学习?

到这里你可能问: 既然 BC 有这么多坑, 为啥不直接用强化学习 (RL)?

RL 在机器人上的三个根本问题:

1. **奖励函数难设计**: 倒水任务的奖励是"水位到 80%"? 失败了杯子碎没碎? 桌子湿不湿? 这些都难量化。
2. **样本效率低**: 一次机器人交互 1-5 秒, 跑 1M 步要 11-57 天。Sim-to-Real 有 sim2real gap, 真实环境训练 1 个月才跑得起一次。
3. **安全探索难**: RL 探索阶段会随机试动作, 真实机器人随机试可能撞坏自己、撞坏环境、撞坏人。

**模仿学习的优势** (vs RL):

- **样本效率高**: 50-100 次专家演示通常就够, 不需要 1M+ 探索步
- **不需要奖励函数**: 直接从示范学, 避免 reward shaping
- **安全性**: 部署时只执行模型输出, 没有探索
- **人类知识传递**: 人类"会做"的任务, 就能教机器人, 不需要把任务翻译成奖励

**模仿学习的劣势**:

- **性能上限 = 专家**: 机器人永远超不过演示者
- **分布外问题**: 演示覆盖不到的状态, 机器人不会处理
- **多模态难学**: 专家可能有多种"正确"做法, BC 用 MSE 退化成"平均动作"

**工业现实** (2023-2024): Tesla Optimus / Figure 02 / 1X NEO / 丰田 LBM / Physical Intelligence 几乎全用模仿学习 (主要是 BC + 大规模数据) 作为第一阶段训练, 然后在关键场景用 RL 微调。Diffusion Policy (CMU 2023) 和 ACT (Stanford 2023) 等 2023-2024 的进展让 BC 的能力上限大幅提高。

**核心结论**: BC 不是"玩具方法", 它是 2024 年人形机器人数据飞轮的事实基础。理解 BC 的因果混淆问题, 等于理解这一代人形机器人的根本局限。

## 2. 数学形式化

### 2.1 状态 s, 动作 a, 专家策略 π*

**状态 (state, s)**: 机器人在时间 $t$ 的观察, 包含所有"机器人能感知到的信息"。

形式化: $s_t \in \mathcal{S}$, $\mathcal{S}$ 是状态空间。常见状态表示:

| 任务 | 状态表示 | 维度 |
| :--- | :--- | :--- |
| 倒水 | RGB 图像 + 关节角 + 杯位 | 224×224×3 + 7 + 3 ≈ 150K |
| 抓取 | 深度图 + 夹爪位姿 | 128×128×1 + 7 ≈ 16K |
| 自动驾驶 | LiDAR + GPS + 摄像头 | 数十万维 |
| CartPole (toy) | 位置 + 速度 + 角度 + 角速度 | 4 维 |

**动作 (action, a)**: 机器人在时间 $t$ 执行的控制量。

- 离散动作: $a_t \in \{0, 1, ..., K-1\}$ (例如 Atari 游戏按键, 抓取"开/关")
- 连续动作: $a_t \in \mathbb{R}^d$ (例如机械臂 6 自由度位姿, 速度指令)
- 混合: 离散 + 连续 (例如"前进"是离散, "转 30 度"是连续)

**策略 (policy, π)**: 状态到动作的映射。形式化: $\pi: \mathcal{S} \to \Delta(\mathcal{A})$, 即给定状态, 输出动作上的概率分布。

- 确定性策略: $\pi(s) = a$ (一个动作)
- 随机性策略: $\pi(a|s) = P(a|s)$ (一个分布, 反映"不确定性")

**专家策略 (π\*)**: 人类演示者"理想"的策略, 产生数据集 $\mathcal{D} = \{\tau_1, \tau_2, ..., \tau_N\}$。我们假设 $\pi^*$ 是好的, 任务是学一个 $\pi_\theta \approx \pi^*$。

### 2.2 数据: τ = {(s_i, a_i)} from π*

**轨迹 (trajectory, τ)**: 一次完整演示, 是一连串 (state, action) 对:

$$\tau = \{(s_0, a_0), (s_1, a_1), ..., (s_T, a_T)\}$$

其中 $s_{t+1} \sim P(\cdot | s_t, a_t)$ 是环境的状态转移, 通常未知。

**专家数据集 (D)**:

$$\mathcal{D} = \{\tau^{(1)}, \tau^{(2)}, ..., \tau^{(N)}\}$$

每个 $\tau^{(i)}$ 由专家执行, 长度 $T^{(i)}$。展开为 $\mathcal{D} = \{(s_j, a_j)\}_{j=1}^{M}$, 其中 $M = \sum_i T^{(i)}$ 是总样本数。

**关键假设**: 数据是**独立同分布** (i.i.d.) 的吗?

不是! 在轨迹内部, $s_t$ 和 $s_{t+1}$ 是强相关的 (机器人在 $t$ 时刻在桌角, $t+1$ 时刻大概率还在桌角附近)。BC 通常**忽略**这种时序相关性, 把 $\mathcal{D}$ 当作 i.i.d. 样本。这在短程任务上能用, 在长程任务上是问题。

**状态分布 (d^π(s))**: 策略 $\pi$ 在环境里"实际访问到"的状态分布。形式化:

$$d^{\pi}(s) = \sum_{t=0}^{\infty} \gamma^t P(s_t = s | \pi)$$

其中 $\gamma \in [0, 1)$ 是折扣因子, 越远的状态权重越低。

**两个关键分布**:

- $d^{\pi^*}(s)$: 专家策略访问的状态分布 (训练数据来自这个分布)
- $d^{\pi_\theta}(s)$: 学习到的策略访问的状态分布 (推理时机器人自己产生的)

BC 的核心问题: $\pi_\theta$ 在 $d^{\pi^*}$ 上训练, 但在 $d^{\pi_\theta}$ 上评估。两个分布不同, 泛化失败。

### 2.3 目标: 最小化 E[L(π(s), a)]

BC 的目标是: 找到参数 $\theta$, 让 $\pi_\theta$ 在专家数据上"尽可能像" $\pi^*$。

**形式 1: 经验风险最小化 (ERM)**

$$\theta^* = \arg\min_\theta \mathbb{E}_{(s, a) \sim \mathcal{D}} \left[ \mathcal{L}(\pi_\theta(s), a) \right]$$

其中 $\mathcal{L}$ 是损失函数, 衡量"模型输出"和"专家动作"的差异。

**形式 2: 极大似然估计 (MLE)**

如果 $\pi_\theta$ 是条件分布 $P_\theta(a | s)$, 那么 BC 等价于:

$$\theta^* = \arg\max_\theta \prod_{(s, a) \in \mathcal{D}} P_\theta(a | s) = \arg\max_\theta \sum_{(s, a) \in \mathcal{D}} \log P_\theta(a | s)$$

**为什么等价?** 当 $\mathcal{L}$ 是负对数似然 (NLL) 时:

$$\mathcal{L}(\pi_\theta(s), a) = -\log P_\theta(a | s)$$

ER M 与 MLE 在数学上完全一致。

**形式 3: KL 散度最小化**

$$\theta^* = \arg\min_\theta D_{\mathrm{KL}}\left( d^{\pi^*}(s, a) \| d^{\pi_\theta}(s, a) \right)$$

其中 $d^{\pi}(s, a) = d^{\pi}(s) \pi(a | s)$ 是状态-动作联合分布。

这个形式把 BC 看作"分布匹配"问题, 直接联系到 §3 的因果混淆...我们其实想匹配的是**因果机制**, 但 BC 匹配的是**关联分布**, 两者在训练分布外可能不同。

### 2.4 损失: MSE / Cross-Entropy / 离散动作

**连续动作 + MSE**:

$$\mathcal{L}_{\mathrm{MSE}}(\theta) = \frac{1}{M} \sum_{i=1}^{M} \| \pi_\theta(s_i) - a_i \|_2^2$$

适用: 关节角预测, 速度预测, 6-DoF 位姿预测。假设动作是高斯分布, $\pi_\theta(s) = \mu_\theta(s)$ 是均值。

**连续动作 + NLL (高斯)**:

$$\mathcal{L}_{\mathrm{NLL}}(\theta) = \frac{1}{M} \sum_{i=1}^{M} \left[ \frac{\| \pi_\theta(s_i) - a_i \|_2^2}{2\sigma^2} + \log \sigma \right]$$

适用: 想要"不确定性估计", 适合"专家本身就有随机性"的任务。$\sigma$ 可以是固定的, 也可以是学到的。

**离散动作 + Cross-Entropy**:

$$\mathcal{L}_{\mathrm{CE}}(\theta) = -\frac{1}{M} \sum_{i=1}^{M} \sum_{k=1}^{K} a_i^{(k)} \log \pi_\theta(s_i)^{(k)}$$

适用: 离散控制 (Atari, 抓取开/关, 走路方向)。

**多模态动作**: BC 用 MSE 会退化

如果专家有两种"正确做法" (例如"左转避开障碍"和"右转避开障碍" 都是合理的), MSE 损失会训出"直走撞障碍", 这就是多模态问题。Diffusion Policy (§3 之后) 通过建模整个分布解决这个问题。

**多任务 BC**: 任务 ID 作为条件

$$\pi_\theta(a | s, z)$$

其中 $z$ 是任务 embedding (one-hot 或 language embedding)。多任务 BC 的损失是所有任务的加权和。

**Block / Action Chunking**: 一次预测 $k$ 步动作

$$\pi_\theta(a_t, a_{t+1}, ..., a_{t+k-1} | s_t)$$

ACT (Stanford 2023) 论文显示, action chunking 比"一次预测一步"在长程任务上稳定得多。直觉: 专家的动作是连贯的, 一次预测多步保持了连贯性。

## 3. 因果混淆问题

### 3.1 协变量偏移 (covariate shift)

**定义**: 训练数据来自分布 $P_{\mathrm{train}}(x, y)$, 推理时输入来自 $P_{\mathrm{test}}(x)$, 两者不同。

**BC 里的协变量偏移**:

- 训练时: $P_{\mathrm{train}}(s) = d^{\pi^*}(s)$ (专家访问的状态)
- 推理时: $P_{\mathrm{test}}(s) = d^{\pi_\theta}(s)$ (机器人自己访问的状态)

**为什么这两个分布不同?**

因为 $\pi_\theta \neq \pi^*$, 机器人执行的动作和专家不同, 状态转移结果就不同。例如:

- 专家: "看到红方块偏左 → 伸手向右, 抓方块" → 抓到方块 → 状态 $s_t$ = 抓到方块
- BC: "看到红方块偏左 → 伸手向左" (学错了) → 没抓到 → 状态 $s_t$ = 空手

同一个 $s_t$ 在训练时是"抓到方块", 在推理时是"空手", BC 输出"把方块放进碗"的动作, 但机器人手里没方块, 任务失败。

**形式化**:

$$\epsilon_{\mathrm{test}} = \mathbb{E}_{s \sim d^{\pi_\theta}} \left[ \mathbb{1}[\pi_\theta(s) \neq \pi^*(s)] \right]$$

$$\le \epsilon_{\mathrm{train}} + \underbrace{\mathrm{TV}(d^{\pi^*}, d^{\pi_\theta})}_{\text{分布差异}}$$

其中 $\mathrm{TV}$ 是 total variation 距离, 衡量两个分布的差异。

直觉: 即使 BC 在训练分布上准确率 99%, 如果推理时机器人跑到"训练分布外", 准确率会掉。

### 3.2 训练 vs 推理分布不同

**例子 1: 自动驾驶 ALVINN (1988)**

ALVINN 用神经网络从摄像头预测方向盘角度。训练数据: 人类在匹兹堡郊区驾驶 30 分钟。部署到真实车: 准确率 90%+ 在训练路段, < 30% 在新路段。

**为什么?** 训练路段全是直路 + 平缓弯道, 遇到陡弯 / 十字路口 / 行人, 模型从未见过。

**例子 2: 机械臂抓取 (现实工业)**

专家在 5 个固定位置抓方块, 50 次演示。BC 在这 5 个位置成功率 95%, 在第 6 个位置 (没演示过) 成功率 20%。

**为什么?** 训练数据集中, $d^{\pi^*}(s)$ 集中在 5 个位置附近。推理时, 关节偏差几度, 状态就跑到分布外了。

**例子 3: 倒水 (多步骤任务)**

专家演示"拿起杯子 → 对准碗 → 倾斜 → 倒水"。BC 学"拿起杯子时夹爪角度 30°"。推理时, 杯子位置稍偏, BC 仍然输出 30°, 但 30° 在新位置不对, 抓空。状态进入"没抓到杯子", 之后的动作全部失效。

**为什么 BC 在多步任务上特别脆弱?** 见 §3.3 误差累积。

### 3.3 误差累积: 走偏一点点 → 完全失败

**核心问题**: 一步偏离 1cm, 50 步后偏离 1m。这是 BC 在长程任务上"指数级失败"的根源。

**形式化**:

假设每步有 $\varepsilon$ 的偏离概率 (例如偏离 1cm 的概率是 10%)。在 $t$ 步后, 状态分布是:

$$d^{\pi_\theta}_t(s) \approx d^{\pi^*}(s) \otimes \mathcal{N}(0, \sigma^2 t)$$

其中 $\sigma$ 是单步偏离的标准差。直觉: $t$ 步后, 状态分布是"专家分布 + 高斯扰动 (方差随 $t$ 线性增长)"。

**累计误差上界**:

$$\mathbb{E}_{s \sim d^{\pi_\theta}_t} \left[ \mathrm{TV}(d^{\pi^*}(s), d^{\pi_\theta}_t(s)) \right] \le t \cdot \varepsilon$$

意思是 $t$ 步后, 训练-推理分布差异**线性增长**。

**任务成功率** (简化模型):

$$P(\text{success at } t) \approx (1 - \varepsilon)^t \le e^{-\varepsilon t}$$

直觉: 50 步任务, $\varepsilon = 0.05$ (5% 偏离率) → 成功率 $e^{-2.5} \approx 8\%$。

**为什么"更多数据"不能完全解决?** 见 §3.5 DAgger 动机。

直觉: 50 步任务, 每步 5% 错误, 要让成功率 > 90%, 需要 $\varepsilon < 0.002$ (0.2% 错误率)。即使 $10^6$ 次演示, 也只能把 $\varepsilon$ 从 5% 降到 4% (平方根衰减), 远不够。

### 3.4 形式化: error_t = Σ_{i=0}^{t-1} (π(s_i) - π*(s_i))

**Ross & Bagnell 2010 的严格界**:

BC 训练出的 $\pi_\theta$ 在 $T$ 步 MDP 上的累计误差是:

$$\mathbb{E}[\text{error}]_T \le T \cdot \epsilon_{\mathrm{train}}$$

其中 $\epsilon_{\mathrm{train}}$ 是单步错误率 (训练分布上)。

**对比**: 强化学习 (DAgger) 的界是:

$$\mathbb{E}[\text{error}]_T \le T \cdot \epsilon_{\mathrm{train}} \cdot \alpha$$

其中 $\alpha < 1$ 是"在线查询"的折扣因子。所以 RL/DAgger 累计误差是 $O(T \epsilon)$, BC 也是 $O(T \epsilon)$, 但 RL 的常数小一个 $\alpha$。

**BC 的下界** (Ross et al. 2011): 即使 $\epsilon_{\mathrm{train}}$ 任意小, BC 的累计误差也至少是 $O(T^{1/3})$ (在某些 MDP 上)。这意味着 BC 有**根本性的**性能上限, 不可能通过"更多数据"消除。

**为什么?** 因为 BC 只在专家状态上训练, 不知道如何从"自己的错误状态"恢复。即使训练集 100% 准确, 一旦第一步偏离, 之后全错。

**公式** (简化):

$$\text{error}_T = \sum_{t=0}^{T-1} \left( \pi_\theta(s_t) - \pi^*(s_t) \right)$$

每一步的误差累积求和, 总误差随 $T$ 线性增长。

### 3.5 DAgger 的动机

**核心思想**: 让 BC 在**自己产生的状态分布**上训练, 而不是专家的状态分布。

**DAgger (Dataset Aggregation, Ross et al. 2011)**:

1. 用 $\pi_\theta$ 跑轨迹, 记录访问的状态 $s_0, s_1, ..., s_T$
2. **在线查询专家** $\pi^*$ 在这些状态上的动作: $a_t = \pi^*(s_t)$
3. 把 $(s_t, a_t)$ 加入数据集 $\mathcal{D}$
4. 重新训 $\pi_\theta$, 用新数据

直觉: 强制 BC 在"自己可能访问的状态"上训练, 而不是只学"专家访问的状态"。

**为什么有效?**

- BC 训练分布变成 $d^{\pi_\theta}(s)$ + $d^{\pi^*}(s)$ 的混合
- 在 $\pi_\theta$ 偏离时, 有"专家标签"告诉它"应该做什么"
- 累计误差界从 $T \cdot \epsilon$ 降到 $T \cdot \epsilon \cdot \alpha$ (Ross & Bagnell 2010)

**为什么工业不用纯 DAgger?**

- 人类专家不可能"在线标注" 24/7
- 状态空间大时, 在线查询代价高
- DAgger 假设专家能"对任何状态给正确动作", 但专家也是有限的

**工业变体**:

- **HG-DAgger**: 用"专家何时介入"做 query (例如 BC 偏离 > 阈值时)
- **PLATO**: 离线 DAgger, 不用在线 query
- **SAIL**: 用 hindsight relabeling 解决多模态
- **IRL-based methods**: 学奖励函数, 让 BC 在奖励下"自我探索"

DAgger 是 §2 的核心动机, 我们会在那章详细展开。

## 4. 实践要点

### 4.1 收集多少数据? 50-100 条/任务

**经验法则** (2023-2024 工业标准):

| 任务复杂度 | 演示数 | 成功率 (1 step BC) | 适用场景 |
| :--- | :--- | :--- | :--- |
| 简单 (抓取固定位置) | 20-50 | 70-90% | 简单 pick-and-place |
| 中等 (倒水, 折叠毛巾) | 50-200 | 50-80% | ALOHA 级别的任务 |
| 复杂 (叠衣服, 做饭) | 200-1000 | 30-60% | 长期 horizon 任务 |
| 极复杂 (家务全套) | 1000-10000 | 20-40% | Figure 02, Optimus 级别 |

**为什么不是"越多越好"?**

- 边际收益递减: 50 → 100 提升 15%, 100 → 200 只提升 5%
- 多模态问题: 数据越多, MSE 越"平均化", 性能反而下降
- 演示成本: 一次演示 30-60 秒, 1000 次 = 8-16 小时纯演示时间

**数据质量 > 数量**:

- **多样性**: 不同位置, 不同光照, 不同物体
- **连贯性**: 演示要"自然", 不要"刻意完美" (避免 BC 学到错误的捷径)
- **失败演示**: 包含一些失败, 让 BC 学到"如何避免失败"
- **多模态**: 同一任务有多种"正确"做法时, 都要演示

### 4.2 状态/动作的归一化

**为什么归一化?**

神经网络对输入/输出的尺度敏感。状态可能是图像 (0-255), 关节角 (-π 到 π), 力矩 (-100 到 100 Nm), 全部混在一起训练会很慢。

**常见归一化方法**:

**Z-score 归一化** (均值 0, 方差 1):

$$s' = \frac{s - \mu_s}{\sigma_s}$$

$$a' = \frac{a - \mu_a}{\sigma_a}$$

其中 $\mu_s, \sigma_s$ 在训练集上估计。

**Min-Max 归一化** (区间 [0, 1]):

$$s' = \frac{s - s_{\min}}{s_{\max} - s_{\min}}$$

**图像归一化**: ImageNet 均值/方差 (RGB):

```text
mean = [0.485, 0.456, 0.406]
std = [0.229, 0.224, 0.225]
```

**常见坑**:

- 用整个数据集 (train+test) 估计 $\mu, \sigma$ → test 集污染
- 推理时归一化参数没保存 → 推理时 $\mu=0, \sigma=1$, 性能掉 50%
- 动作的 scale 没归一化 → 训练时 loss 巨大, 学习率难调
- 状态/动作的维度差异巨大 (图像 150K, 关节 7) → 网络难平衡

### 4.3 动作空间的离散化 vs 连续

**离散化** (action binning):

把连续动作切成 $K$ 个区间, 每个区间标号, 训分类器。

例子: 抓取的"夹爪开/合" → 2 类。6-DoF 末端位姿 → 离散化成 $K^6$ 类 ($K=11$ → 1.7M 类, 太大)。

**优缺点**:

- 优: 分类器是 well-studied, 训练稳定
- 优: 适合离散动作 (开/关, 按键)
- 缺: 高维连续动作离散化后类别爆炸
- 缺: 离散边界处精度差
- 缺: 难以处理多模态

**连续动作** (regression):

直接用 MSE / NLL 训回归器。

**优缺点**:

- 优: 自然处理高维连续动作
- 优: 精度高
- 缺: MSE 在多模态上退化 (退化成"平均动作")
- 缺: 训练不稳定 (loss 曲线震荡)

**经验选择**:

- 维度 < 10 + 任务精度要求高 → 连续
- 维度 < 10 + 任务有多模态 → Diffusion Policy (§3)
- 离散动作 (Atari, 抓取开合) → 离散
- 大规模多任务 → 连续 + Diffusion

### 4.4 多任务 BC 的设计

**挑战**: 一个 BC 网络如何处理 100 个不同任务?

**方案 1: 任务 ID 作为输入**

```python
state = encode(image)  # [B, 256]
task_id = one_hot(task_id)  # [B, 100]
input = concat([state, task_id])  # [B, 356]
action = mlp(input)  # [B, action_dim]
```

**优**: 简单。**缺**: 任务多时, 输入维度爆炸, 训练难。

**方案 2: Task embedding**

```python
state = encode(image)  # [B, 256]
task_emb = embed(task_id)  # [B, 64]
input = concat([state, task_emb])  # [B, 320]
action = mlp(input)  # [B, action_dim]
```

**优**: 任务 embedding 维度小, 共享 backbone。**缺**: 需要"任务 ID" 输入, 推理时要给。

**方案 3: Language condition (目标条件)**

```python
state = encode(image)  # [B, 256]
lang_emb = text_encoder("把红方块放进蓝碗")  # [B, 768]
input = concat([state, lang_emb])  # [B, 1024]
action = mlp(input)  # [B, action_dim]
```

**优**: 自然语言即可指定任务, 用户友好。**缺**: 需要语言编码器 (CLIP / T5), 推理慢。

**方案 4: 多头输出 (multi-head)**

```python
state = encode(image)  # [B, 256]
output = mlp(state)  # [B, action_dim * 100]  # 100 个任务头
action = output[:, task_id * action_dim : (task_id + 1) * action_dim]
```

**优**: 每个任务有独立输出, 任务不互相干扰。**缺**: 任务多时输出维度爆炸, 任务少数据时过拟合。

**多任务训练的核心问题**:

- **任务权重**: 不同任务数据量不同, 怎么平衡?
- **负迁移**: 学习新任务时, 旧任务性能下降
- **任务相关性**: 任务 A 和 B 相似时, 共享表示; 不相似时, 独立训练更好

工业常用方案 2 (task embedding) + 方案 3 (language condition) 的组合, 用大型预训练 VLA (RT-2, OpenVLA) 作为 backbone。

## 5. PyTorch 实现

### 5.1 简单 BC 训练 (Push-T 简化版)

**目标**: 用 BC 训一个网络, 让"小车把 T 形块推到目标位置"。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np
from torch.utils.data import Dataset, DataLoader

# ============================================================
# 1. 数据集: 专家演示 (state, action) 对
# ============================================================
class BCDataset(Dataset):
    """BC 数据集: 一堆 (state, action) 对"""
    def __init__(self, states, actions, normalize=True):
        """
        states: [N, state_dim] numpy array
        actions: [N, action_dim] numpy array
        """
        self.states = torch.from_numpy(states).float()
        self.actions = torch.from_numpy(actions).float()

        if normalize:
            # Z-score 归一化
            self.state_mean = self.states.mean(0)
            self.state_std = self.states.std(0) + 1e-6
            self.action_mean = self.actions.mean(0)
            self.action_std = self.actions.std(0) + 1e-6

            self.states = (self.states - self.state_mean) / self.state_std
            self.actions = (self.actions - self.action_mean) / self.action_std
        else:
            self.state_mean = torch.zeros(self.states.shape[1])
            self.state_std = torch.ones(self.states.shape[1])
            self.action_mean = torch.zeros(self.actions.shape[1])
            self.action_std = torch.ones(self.actions.shape[1])

    def __len__(self):
        return len(self.states)

    def __getitem__(self, idx):
        return self.states[idx], self.actions[idx]

    def denormalize_action(self, action_normalized):
        """推理时: 把归一化的动作还原"""
        return action_normalized * self.action_std + self.action_mean

# ============================================================
# 2. BC 策略网络 (简单 MLP)
# ============================================================
class BCPolicy(nn.Module):
    """简单 MLP 策略"""
    def __init__(self, state_dim, action_dim, hidden_dim=256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(state_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, action_dim),
        )

    def forward(self, state):
        return self.net(state)

# ============================================================
# 3. 训练循环
# ============================================================
def train_bc(states, actions, epochs=100, batch_size=64, lr=1e-3):
    # 数据
    dataset = BCDataset(states, actions, normalize=True)
    loader = DataLoader(dataset, batch_size=batch_size, shuffle=True)

    # 模型
    state_dim = states.shape[1]
    action_dim = actions.shape[1]
    policy = BCPolicy(state_dim, action_dim)
    optimizer = torch.optim.Adam(policy.parameters(), lr=lr)

    # 训练
    for epoch in range(epochs):
        total_loss = 0
        for state_batch, action_batch in loader:
            pred = policy(state_batch)
            loss = F.mse_loss(pred, action_batch)
            optimizer.zero_grad()
            loss.backward()
            optimizer.step()
            total_loss += loss.item()

        if (epoch + 1) % 10 == 0:
            avg = total_loss / len(loader)
            print(f"Epoch {epoch+1}/{epochs} | MSE Loss: {avg:.4f}")

    return policy, dataset

# ============================================================
# 4. 推理 (在真实环境跑)
# ============================================================
def rollout_bc(policy, dataset, env, max_steps=200):
    """在环境里跑一条轨迹"""
    state = env.reset()
    total_reward = 0

    for step in range(max_steps):
        state_norm = (state - dataset.state_mean.numpy()) / dataset.state_std.numpy()
        state_tensor = torch.from_numpy(state_norm).float().unsqueeze(0)

        with torch.no_grad():
            action_norm = policy(state_tensor).squeeze(0).numpy()

        action = dataset.denormalize_action(torch.from_numpy(action_norm)).numpy()
        state, reward, done, _ = env.step(action)
        total_reward += reward
        if done:
            break

    return total_reward, step
```

**关键点**:

- Z-score 归一化: 训练时用整个数据集的均值/方差, 推理时用同样的 (这里存在 dataset 里)
- MSE 损失: 假设动作是高斯分布
- 推理时反归一化: 模型输出是归一化空间的动作, 要还原到真实动作空间

### 5.2 玩具环境 (Push-T 简化版)

```python
class PushTEnv:
    """极简 Push-T 环境: 小车把 T 形块推到目标点"""
    def __init__(self):
        self.state_dim = 5  # [T_x, T_y, T_angle, target_x, target_y]
        self.action_dim = 2  # [force_x, force_y]
        self.max_steps = 200
        self.reset()

    def reset(self):
        self.t_pos = np.random.uniform(-0.5, 0.5, 2)
        self.t_angle = np.random.uniform(-np.pi, np.pi)
        self.target = np.random.uniform(-0.5, 0.5, 2)
        self.step_count = 0
        return self._get_state()

    def _get_state(self):
        return np.concatenate([self.t_pos, [self.t_angle], self.target])

    def step(self, action):
        # 简单的物理: T 形块朝施加力的方向移动
        self.t_pos += action * 0.01
        self.t_angle += np.random.normal(0, 0.01)  # 随机扰动
        self.step_count += 1

        # 距离目标的距离作为奖励
        dist = np.linalg.norm(self.t_pos - self.target)
        reward = -dist

        done = (dist < 0.05) or (self.step_count >= self.max_steps)
        return self._get_state(), reward, done, {}

# ============================================================
# 5. 生成专家演示
# ============================================================
def generate_expert_demos(env, n_demos=50, noise=0.05):
    """生成 '专家' 演示: 直接朝目标施力"""
    states, actions = [], []

    for _ in range(n_demos):
        state = env.reset()
        for _ in range(env.max_steps):
            # '专家' = 直接朝目标施力
            force = env.target - env.t_pos
            force = np.clip(force, -1, 1) + np.random.normal(0, noise, 2)

            states.append(state)
            actions.append(force)

            state, _, done, _ = env.step(force)
            if done:
                break

    return np.array(states), np.array(actions)

# 训练 + 评估
env = PushTEnv()
states, actions = generate_expert_demos(env, n_demos=50)
policy, dataset = train_bc(states, actions, epochs=50)

# 评估
rewards, lens = [], []
for _ in range(20):
    r, l = rollout_bc(policy, dataset, env)
    rewards.append(r)
    lens.append(l)
print(f"BC 成功率: {np.mean(rewards):.2f} ± {np.std(rewards):.2f}")
```

### 5.3 与随机策略对比

```python
def random_policy(env, max_steps=200):
    """随机策略: 每步随机施力"""
    state = env.reset()
    total_reward = 0
    for _ in range(max_steps):
        action = np.random.uniform(-1, 1, 2)
        state, r, done, _ = env.step(action)
        total_reward += r
        if done:
            break
    return total_reward

# 对比
bc_rewards = [rollout_bc(policy, dataset, env)[0] for _ in range(20)]
random_rewards = [random_policy(env) for _ in range(20)]

print(f"BC:    {np.mean(bc_rewards):.2f} ± {np.std(bc_rewards):.2f}")
print(f"Random: {np.mean(random_rewards):.2f} ± {np.std(random_rewards):.2f}")
```

**预期结果**:

- BC: 奖励 -5 到 -10, 成功率 80-90% (50 演示足够 Push-T)
- Random: 奖励 -50 到 -100, 成功率 0% (随机无法对齐目标)

**重要说明**: 这个玩具环境**没有协变量偏移**问题, 因为环境动力学简单 (T 块在小车上, 状态空间小)。真实环境 (倒水, 抓取) 才有 BC 失败三件套。下一节我们可视化因果混淆。

### 5.4 因果混淆的可视化

**实验设计**: 在状态里加一个"混淆变量", 让专家的"正确动作"和这个变量强相关, 但没有因果关系。

```python
class ConfoundedEnv:
    """有混淆变量的环境: '灯' 和 '障碍' 强相关, 但灯不导致动作"""
    def __init__(self):
        self.state_dim = 4  # [pos, light, obstacle, dist_to_target]
        self.action_dim = 1  # [steering]
        self.max_steps = 100
        self.reset()

    def reset(self):
        # 灯亮 = 100% 概率有障碍 (专家会左转)
        # 灯灭 = 100% 概率无障碍 (专家会直走)
        self.pos = 0.0
        self.light = np.random.choice([0, 1])
        self.obstacle = self.light  # 灯 = 障碍 (完美相关!)
        self.dist = 1.0
        return np.array([self.pos, self.light, self.obstacle, self.dist])

    def step(self, action):
        # 真实动力学: 障碍决定是否要左转
        if self.obstacle == 1:
            # 专家: 左转避开
            expert_action = -1.0
        else:
            # 专家: 直走
            expert_action = 0.0

        # BC 输出与专家的差距
        error = abs(action - expert_action)

        # 简化的状态转移
        if self.obstacle == 1 and action > -0.5:
            # BC 没左转 → 撞障碍
            self.dist = 0.0
            reward = -10
        else:
            # 成功避开或无障碍
            self.dist -= 0.1
            reward = 1.0

        self.pos += action * 0.1
        self.step_count = getattr(self, 'step_count', 0) + 1
        done = (self.dist <= 0) or (self.step_count >= self.max_steps)
        return self.array([self.pos, self.light, self.obstacle, self.dist]), reward, done, {}

# 生成专家演示
def generate_confounded_demos(n_demos=100):
    states, actions = [], []
    for _ in range(n_demos):
        env = ConfoundedEnv()
        state = env.reset()
        for _ in range(env.max_steps):
            # 专家: 看障碍, 不看灯
            if state[2] == 1:  # obstacle
                action = np.array([-1.0])
            else:
                action = np.array([0.0])
            states.append(state)
            actions.append(action)
            state, _, done, _ = env.step(action)
            if done:
                break
    return np.array(states), np.array(actions)
```

**因果混淆可视化** (训练后看 BC 学到了什么):

```python
# 训练

# 测试 1: 灯亮 + 障碍在 (训练分布内)
test_state_1 = np.array([0.0, 1.0, 1.0, 1.0])  # 灯亮, 障碍在

# 测试 2: 灯灭 + 障碍在 (训练分布外! 专家从未演示过)

print(f"灯灭 + 障碍: 预测动作 = {pred_2:.2f} (期望 -1 左转, 但 BC 学的是灯)")

# 测试 3: 灯亮 + 障碍不在 (训练分布外)
test_state_3 = np.array([0.0, 1.0, 0.0, 1.0])  # 灯亮, 障碍不在
norm_3 = (test_state_3 - dataset.state_mean.numpy()) / dataset.state_std.numpy()
pred_3 = policy(torch.from_numpy(norm_3).float()).item()
print(f"灯亮 + 障碍不在: 预测动作 = {pred_3:.2f} (期望 0 直走, 但 BC 学的是灯)")
```

**预期结果**:

- 测试 1: 预测 ≈ -1 (正确, 学到 "障碍 → 左转")
- 测试 2: 预测 ≈ 0 (**错误!** 灯灭 → 不左转, 但障碍在, 应该左转)
- 测试 3: 预测 ≈ -1 (**错误!** 灯亮 → 左转, 但无障碍, 应该直走)

BC 在训练分布外, 完全没用到"障碍"这个**真正因果**的变量, 而是用了"灯"这个**虚假关联**的变量。这就是因果混淆。

**怎么解决?** 见 §3.5 DAgger, §3 Diffusion Policy 也会通过多模态建模缓解。

## 6. 工业案例

### 6.1 Tesla 数据收集: 人类示教 vs VR

**Tesla Optimus 数据收集范式** (2023-2024):

- 摄像头记录环境, 动作捕捉记录人体姿态
- 50-100 次/任务, 多个工程师并行

**方式 2: VR 示教 (VR Teleoperation)**

- 记录 (VR 视角, 手柄位姿) 对

- 数据集总量: 数千万 (state, action) 对

- **大规模**: 100K 演示覆盖了 99% 的状态空间
- **数据增强**: 视觉增强 (颜色抖动, 裁剪), 动作增强 (噪声, 时间扭曲)
- **多任务**: 单网络处理 100+ 任务
- **混合训练**: BC + 视频预测 + RL 微调

- 人类示教成本高 ($100/小时 × 100 小时/任务)

### 6.2 1X Technologies 的"100 次"

**1X NEO (2024)** 是 1X Technologies 的家用机器人, 目标是"做家务"。他们的 BC 训练范式 (NEO 2024 launch talk):

**核心数据**: 每个任务 100 次专家演示。

**为什么 100 次?**

- 100 次足够覆盖一个任务的"基本变种" (位置, 物体类型)
- 不到 100 次时, BC 性能曲线陡升; 超过 100 次, 收益递减
- 工程师 1 天可以演示 5-10 个任务, 100 次/任务 = 1-2 周

**NEO 的数据流**:

1. 工程师用 VR 头显 + 手柄控制 NEO
2. NEO 的传感器记录 (RGB-D, 关节角, 力矩) 全部状态
3. 记录 (状态, VR 控制) 对, 50 Hz
4. 训 BC 网络 (1 hour training, 100 demos)
5. 部署到 NEO, 在线评估
6. 失败的轨迹加入下一轮训练 (类似 DAgger)

**NEO 的 BC 突破**:

- 神经网络大小: 50M 参数 (RT-2 级别)
- 训练数据: 100 demos/task × 100 tasks = 10K trajectories
- 任务成功率: 简单任务 80%, 复杂任务 40-60%

**1X 的经验**:

- 100 次是"甜区" (sweet spot)
- 演示要包含"自然变化" (工程师不能机械重复, 要"做出微调")
- 失败演示比成功演示更有价值 (教机器人"避免错误")

### 6.3 Figure 02 的演示数据

**Figure 02** (2024-09 发布) 是 Figure AI 的人形机器人, 走的是"BC + 大规模数据"路线。

**数据规模** (Figure 02 launch blog, 2024):

- 60+ 个任务 (例如"叠毛巾", "倒水", "开门")
- 每任务 200-1000 次演示
- 多个并行操作员 (5-10 人) 每天产生 1000+ 演示
- 6 个月累积 1M+ 演示

**Figure 02 的 BC 改进**:

- **视觉编码器**: 用 DINOv2 + CLIP 预训练, 提升对未见物体的泛化
- **动作空间**: 6-DoF 末端位姿 + 夹爪开合 (7 维), 连续动作 + MSE
- **多任务网络**: 单网络处理 60+ 任务, 任务用 language condition

**Figure 02 公开的成功率** (公司声明, 需谨慎对待):

- 在演示过 100+ 次的任务上表现好
- 罕见任务 (< 50 次演示) 性能差
- "长程规划" (例如"做饭 30 分钟") 仍然困难

### 6.4 ALOHA 的低成本 BC

**ALOHA** (Stanford, 2023) 是低成本双臂模仿学习平台, 总成本 $20K, 是 PR2 ($400K) 的 1/20。

**ALOHA 的 BC 训练**:

- 平台: 双臂 + 4 摄像头 + 2 个 VR 手柄
- 任务: 12 个 (叠毛巾, 倒水, 打鸡蛋, 装椅子螺丝, ...)
- 演示: 每任务 50 次, 2-3 小时采集
- 网络: ACT (Action Chunking Transformer) - 1 层 Transformer, 1M 参数

**ALOHA 的关键创新**:

- **Action Chunking**: 一次预测 1 步太脆弱, 一次预测 10 步
- **Hindsight Experience Replay**: 失败轨迹的"目标"重新标注, 数据利用效率提升 3×
- **Temporal Ensemble**: 多 chunk 的动作平均, 减少抖动

**ALOHA 的 BC 性能** (论文数据):

- 简单任务 (打开笔帽): 90%+
- 中等任务 (倒水): 70-85%
- 复杂任务 (打鸡蛋): 60-70%
- 50 次演示 vs 200 次: 性能差异 < 10% (ALOHA 数据效率高)

**为什么 ALOHA 用 BC 能达到这种水平?**

- **任务设计**: 任务"短程" (10-20 步), 误差累积不明显
- **演示质量**: 工程师精确演示, 状态空间小

**ALOHA 的局限**:

- 不能处理"长程"任务 (50+ 步)
- 不能泛化到新物体
- 误差累积在 20 步后开始严重

**Mobile ALOHA** (Stanford, 2024) 加上移动底盘, 任务扩展到"做菜", 50 次演示, 成功率 80%+。

## 7. 与其他章节的关系

### 7.1 → 2-DAgger: 本章的因果混淆是 DAgger 的动机

**直接关联**: §3.5 我们讨论了"BC 失败三件套", 协变量偏移, 误差累积, 因果混淆。DAgger 是第一个**系统性地**解决这三个问题的方法。

**DAgger 怎么解决**:

- **协变量偏移**: 让 $\pi_\theta$ 在自己访问的状态上训练, 而不只是 $d^{\pi^*}$
- **误差累积**: 在线查询专家在 $\pi_\theta$ 状态上的动作, 减少"长程偏移"
- **因果混淆**: 部分缓解 (专家在 $\pi_\theta$ 状态下给动作, 比纯 BC 更接近"专家意图")

**DAgger 在工业的局限**:

- 需要"在线专家", 成本高
- 人类专家无法标注"任意状态"
- 状态空间大时, 标注量爆炸

**§2 详细讨论**:

- HG-DAgger (Human-Gated DAgger)
- PLATO (offline DAgger)
- 工业级 DAgger 变体

### 7.2 → 3-Diffusion Policy: 本章是 Diffusion Policy 的对比

**直接关联**: §3.3 我们提到 BC 用 MSE 在多模态动作上"退化"成平均动作。Diffusion Policy 用条件扩散模型建模整个分布, 解决多模态问题。

**Diffusion Policy vs BC**:

| 维度 | BC (MSE) | Diffusion Policy |
| :--- | :--- | :--- |
| 动作分布 | 单高斯 (单峰) | 任意分布 (多峰) |
| 多模态 | 退化 (平均) | 显式建模 |
| 推理速度 | 1 ms (MLP) | 100 ms (10 步去噪) |
| 长程稳定 | 差 (误差累积) | 较好 (分布匹配) |
| 训练数据 | 50-100 | 50-100 (差不多) |
| 成功率 | 简单任务 80% | 简单任务 85-90% |
| 训练成本 | 1 小时 | 5-10 小时 |

**Diffusion Policy 的局限**:

- 推理慢 100× (实时控制可能不够)
- 训练需要更多计算 (diffusion 模型大)
- 在简单任务上 BC 反而更快

**§3 详细讨论**:

- 条件扩散 (classifier-free guidance)
- 1D U-Net backbone
- 动作 horizon vs observation horizon
- 与 BC 的混合训练

### 7.3 → 4-目标条件: 本章的扩展

**直接关联**: §4.4 我们讨论了多任务 BC, 提到 language condition 是核心方案。目标条件策略 (Goal-Conditioned Policy, GCP) 是多任务 BC 的"通用化", 用自然语言指定任务。

**目标条件 vs 多任务 BC**:

- 多任务 BC: 任务用 ID (整数) 指定
- 目标条件: 任务用语言指定 ("把红方块放进蓝碗")
- 优势: 用户友好, 可以泛化到"没演示过"的任务

**目标条件的核心挑战**:

- 语言编码器: CLIP, T5, LLaMA
- 视觉-语言对齐: 跨模态 grounding
- 长程任务: 语言 → 子任务分解

**§4 详细讨论**:

- RT-1, RT-2, OpenVLA 的语言条件方案
- Goal-Conditioned RL
- Language-Conditioned Diffusion

### 7.4 → 5-人类视频学习: 本章的扩展

**直接关联**: 本章 BC 用"专家演示", 但专家必须是"机器人"吗? 人类视频学习 (HPT, Bridge Data) 用"人类做任务"的视频, 通过**跨形态迁移** (cross-embodiment) 教机器人。

**人类视频 vs 机器人演示**:

- 人类视频: 便宜 (YouTube, 自拍), 多样, 但**形态不同** (人手 vs 夹爪)
- 机器人演示: 昂贵 ($100/小时), 少样, 但**形态匹配**

**跨形态迁移的方法**:

- HPT: 大规模人类视频预训练, 再用少量机器人数据 finetune
- 形态无关特征: 提取"任务级"特征, 忽略具体关节
- 形态映射: 人手关键点 → 夹爪位姿

**§5 详细讨论**:

- 人类视频预训练 (HPT, R3M, MVP)
- 形态迁移 (MimicPlay, CrossFormer)
- 视频预测 (VIP, GAIA-1)

## 8. 与数学基础的关系 (高复用)

### 8.1 数学基础/3-概率论/3-常用分布 ← 动作分布

**直接关联**: §2.4 我们讨论了 BC 损失 (MSE, NLL, CE), 背后的**动作分布**假设是核心。

**关键分布**:

- **高斯分布** (Gaussian): 连续动作的默认假设, 对应 MSE 损失
- **Categorical 分布**: 离散动作, 对应 Cross-Entropy
- **混合高斯** (Mixture of Gaussians): 多模态动作
- **狄拉克分布** (Dirac): 确定性动作 (高级用法, 配合 RL)

**3-常用分布** 章节给了这些分布的 PDF/CDF, 性质, 期望/方差, 极大似然估计。BC 训练本质是**对动作分布做极大似然估计**, 所以这部分是高复用的。

**例子**: BC 训高斯策略

$$\pi_\theta(a | s) = \mathcal{N}(a; \mu_\theta(s), \sigma^2 I)$$

NLL 损失 = $-\log \pi_\theta(a | s) = \frac{\|a - \mu_\theta(s)\|^2}{2\sigma^2} + \log \sigma + \text{const}$

MSE 是 $\sigma$ 固定为 1 的特殊情况。

### 8.2 数学基础/6-最优化/1-优化问题分类 ← BC 损失

**直接关联**: BC 是经验风险最小化 (ERM), 优化目标是

$$\min_\theta \mathbb{E}_{(s,a) \sim \mathcal{D}} [\mathcal{L}(\pi_\theta(s), a)]$$

**优化问题的分类**:

- 凸 vs 非凸: BC 的损失景观 (loss landscape) 通常**非凸**, 多个局部最优
- 光滑 vs 非光滑: ReLU 网络非光滑, 但实践中 Adam 仍能训
- 有约束 vs 无约束: BC 通常无约束 (参数自由)

**6-1 优化问题分类** 章节给出了这些分类的严格定义, 以及不同类别优化的难度。

**例子**: BC 训练的非凸性

- 简单 MLP, MSE 损失: 损失景观**非凸** (有多个局部最优)
- 但实践中, Adam + 合适的学习率能找到"足够好"的局部最优
- 全局最优理论上存在 (参数足够大时)

**6-2 一阶方法** (SGD, Adam) 是 BC 训练的**默认优化器**。学习率调度 (warmup, cosine decay) 在 §10 BC 实践中讨论。

### 8.3 数学基础/3-概率论/6-MLE·MAP·贝叶斯估计 ← 极大似然视角

**直接关联**: §2.3 我们指出 BC = 极大似然估计 (MLE), 即

$$\theta^* = \arg\max_\theta \sum_{(s, a) \in \mathcal{D}} \log P_\theta(a | s)$$

**MLE vs MAP vs 贝叶斯**:

- **MLE**: $\theta^* = \arg\max \log P(\mathcal{D} | \theta)$ (不假设先验)
- **MAP**: $\theta^* = \arg\max \log P(\mathcal{D} | \theta) + \log P(\theta)$ (加先验, 通常是正则化)
- **贝叶斯**: $P(\theta | \mathcal{D}) \propto P(\mathcal{D} | \theta) P(\theta)$, 完整后验

**BC = MLE** 的直觉: BC 假设"专家动作是从某个分布 $\pi^*$ 采的", 训练 $\pi_\theta$ 最大化"在数据上观测到专家动作的似然"。

**3-6 MLE·MAP·贝叶斯估计** 章节给了这些方法的严格推导, 以及何时用哪种。

**例子**: BC + 正则化 = MAP

如果对 $\theta$ 加 L2 正则 ($\| \theta \|^2$), 损失变成

$$\mathcal{L}_{\mathrm{MAP}} = \mathcal{L}_{\mathrm{MLE}} + \lambda \| \theta \|^2$$

这等价于 MAP with Gaussian prior $P(\theta) = \mathcal{N}(0, 1/\lambda)$。L2 正则在 BC 训练中能减少过拟合, 提升泛化。

## 9. 常见误区

### 9.1 ❌ "BC 等于监督学习"

**错误观点**: BC 就是"输入图像, 输出动作的监督学习", 跟图像分类没本质区别。

**实际情况**: BC 是**序列决策**问题, 不是 i.i.d. 监督学习。关键差异:

- 状态分布: BC 推理时机器人自己产生状态 ($d^{\pi_\theta}$), 监督学习测试集是固定的 ($d_{\mathrm{test}}$)
- 错误传播: BC 一步错导致状态偏离, 后续步错; 监督学习每样本独立
- 评估指标: BC 关心"任务完成率", 监督学习关心"标签准确率"

**为什么这个误区危险?** 用了"训练集-测试集" 的思路, 忽视协变量偏移, 部署时性能暴跌。

**怎么避免?** 时刻问自己: "机器人推理时看到的状态, 在训练集里有多少次?" 如果 < 100, 大概率失败。

### 9.2 ❌ "数据越多 BC 越好"

**错误观点**: BC 性能随数据量单调增长, 10K 演示 vs 100 演示, 一定更好。

**实际情况**:

- **多模态问题**: 数据多时, BC 用 MSE 训出"平均动作", 反而不如少数据。例: 抓取, 5 种抓法, 1000 次演示 → BC 学到"5 种的平均 = 抓不住", 50 次演示 → BC 学到"清晰的某种抓法"。
- **数据质量下降**: 数据多时, 演示质量参差不齐, BC 学到"平均"行为, 而非最优行为。
- **边际收益递减**: 50 → 100 提升 15%, 100 → 200 只提升 5%, 1000 → 2000 提升 < 1%。

**什么时候"数据多"有效?**

- 任务**单模态** (只有一种"正确"做法)
- 状态空间**巨大**, 需要数据覆盖 (例如自动驾驶)
- 演示**高质量** (专家一致)

**经验法则**: 50-100 演示是"快迭代甜区", 200-500 是"性能甜区", 1000+ 是"边际收益"。

### 9.3 ❌ "因果混淆可以忽略"

**错误观点**: "BC 不就学个映射吗? 因果不因果有什么关系? 大数据就完事。"

**实际情况**: 因果混淆是 BC 的**根本性**问题, 不是"多数据"能解决的。

**例子**: 自动驾驶, 100K 演示全是晴天, BC 学到"看到蓝天 → 直走"。下雪天, 看到灰天, BC 输出"直走" (训练时灰天 = 雾天, 减速), 但其实是下雪 (天灰但路滑, 应该直走 + 慢)。BC 完全搞反。

**为什么大数据不够?** 因为**反事实**数据永远缺失: 你无法演示"晴天但有障碍" (因为你没遇到过), BC 永远学不到"看到蓝天 + 检测到障碍 → 绕开"。

**怎么缓解?**

- **DAgger**: 让专家在反事实状态上给动作 (但成本高)
- **数据增强**: 视觉增强, 动作增强, 物体替换 (HPT 用了大量人类视频)
- **多模态动作**: Diffusion Policy, 显式建模"如果有障碍, 走哪都行"
- **数据平衡**: 确保不同条件 (天气, 光照, 物体) 的数据均匀

**为什么这个误区危险?** 忽视因果混淆, 训练集 99% 准确, 部署时 0% 成功率, 而且**失败模式不可预测**。

### 9.4 ❌ "BC 适合所有任务"

**错误观点**: "BC 简单, 训一个就能用, 不用 RL, 不用规划。"

**实际情况**: BC 只适合**演示充分**的任务。失败场景:

- **长程任务** (> 50 步): 误差累积严重
- **罕见场景** (< 50 演示): 训练数据不足
- **多模态决策**: MSE 退化成平均动作
- **对抗性环境**: 对手会根据 BC 行为调整 (例如游戏 AI)
- **安全关键**: 失败代价高 (医疗, 驾驶), 不能接受 BC 失败率

**什么时候用 BC?**

- 短程 (10-20 步) 任务
- 演示容易收集 (人类自然能做的)
- 失败代价低 (工业搬运, 家庭辅助)

**什么时候不用 BC?**

- 长程规划 (做饭, 打扫整套房间)
- 罕见/危险场景 (救火, 灾后救援)
- 对抗性场景 (游戏 AI, 谈判)
- 需要"超越人类"的任务 (复杂优化, 创新设计)

**怎么选 BC vs RL?**

- 有专家演示 → BC
- 有奖励函数 (能评估, 不能演示) → RL
- 两者都有 → BC 初始化 + RL 微调 (最常见)
- 两者都没有 → 不要做这个任务 (或者用 LLM 做规划 + BC 做执行)

## 10. L7/L8 面试 Q&A

### Q1: BC 的因果混淆为什么严重?

**标准答案结构** (4 段, ~5 分钟讲完):

**第 1 段: 因果 vs 关联**

"BC 学到的是**关联**: 状态 $s$ 出现时, 动作 $a$ 出现。但专家**为什么**做 $a$ (因果), BC 没学到。如果专家因"前方有障碍"而左转, BC 可能学成"看到红灯左转", 错过红灯时就不左转。"

**第 2 段: 训练分布外的问题**

"BC 训练时只在 $d^{\pi^*}(s)$ (专家状态分布) 上训练, 推理时是 $d^{\pi_\theta}(s)$ (机器人自己状态分布)。这两个分布不同, 关联就崩了。Ross & Bagnell 2010 证明, BC 的累计误差下界是 $O(T^{1/3})$, 不可能通过'更多数据'消除。"

**第 3 段: 误差累积**

"形式化: $\text{error}_T = \sum_{t=0}^{T-1} (\pi_\theta(s_t) - \pi^*(s_t))$, 累计误差随 $T$ 线性增长。50 步任务, 每步 5% 错误, 成功率 $(1 - 0.05)^{50} \approx 8\%$。"

**第 4 段: 工业影响**

"Tesla Optimus 50+ 步任务 (例如"组装螺丝") 用 BC + 大规模数据 (100K 演示) + DAgger 微调。Figure 02 在 60+ 任务上用 BC + Action Chunking + 视觉预训练, 把单步错误率从 5% 降到 1% 以下, 但 30 步任务成功率仍然只有 30-40%。这就是因果混淆的工业证据。"

**加分项**: 提到"反事实数据永远缺失", "数据增强缓解但不解决", "DAgger 是目前最好的解决方案之一"。

### Q2: BC vs 强化学习的根本差异?

**标准答案结构** (5 段):

**第 1 段: 监督信号不同**

"BC 用专家的 (state, action) 监督, RL 用奖励信号。BC 假设'专家动作是最优', RL 假设'奖励函数能评估好坏'。"

**第 2 段: 探索机制不同**

"BC 不探索 (直接模仿专家), RL 必须探索 (尝试新动作看奖励)。探索是 RL 训练的核心难点。"

**第 3 段: 性能上限不同**

"BC 上限 = 专家, RL 上限 = 奖励函数的天花板 (理论上可以超越专家)。这就是为什么 AlphaGo Zero 用 RL 不用 BC, 需要超越人类。"

**第 4 段: 样本效率**

"BC 50-100 演示, RL 1M-1B 步。在真实机器人上, BC 比 RL 高效 1000×。"

**第 5 段: 工业实践**

"2024 工业实际: BC 训基础策略 (50-100 demos/task) → RL 微调关键场景 (例如抓取异常物体)。Tesla / Figure 02 / 1X NEO 全是这个范式。"

**加分项**: 提到"offline RL" 是 BC + RL 的中间形态, "BC + RL 混合训练" 是当前前沿。

### Q3: 数据增强能解决 BC 问题吗?

**标准答案结构** (4 段):

**第 1 段: 能解决的部分**

"数据增强能**缓解**协变量偏移。例如: 视觉增强 (颜色抖动, 裁剪, 旋转) 让 BC 对光照/视角变化鲁棒; 动作增强 (加噪声) 让 BC 对小扰动鲁棒。"

**第 2 段: 不能解决的部分**

"数据增强**不能解决**因果混淆。例: 增强"晴天"成"阴天" (颜色抖动) 不能让 BC 学到"阴天 + 有障碍 → 绕开", 因为训练数据里没有"阴天 + 有障碍"这种组合。"

**第 3 段: 形式化**

"增强把训练分布从 $d^{\pi^*}(s)$ 变成 $\tilde{d}(s)$。只要 $\tilde{d}(s) \neq d^{\pi_\theta}(s)$, 偏移问题就存在。增强让 $\tilde{d}$ 更宽, 但不可能覆盖 $d^{\pi_\theta}$ 的所有状态。"

**第 4 段: 工业实践**

"ALOHA 用时间扭曲 (temporal augmentation) 缓解"演示节奏不一致", Diffusion Policy 用动作噪声增强, Figure 02 用 DINOv2 视觉增强。这些增强**都必要但不充分**。真正的解决方案是 DAgger / Diffusion / 大规模数据。"

**加分项**: 提到 "HPT (Human Pre-training) 用人类视频做数据增强" 是当前前沿。

### Q4: 多任务 BC 的核心挑战?

**标准答案结构** (5 段):

**第 1 段: 任务表示**

"任务怎么编码? One-hot (任务少时), embedding (任务多时), language (用户友好)。Language condition 是当前主流 (RT-2, OpenVLA), 但需要语言编码器 (CLIP/T5)。"

**第 2 段: 数据平衡**

"任务 A 1000 演示, 任务 B 50 演示。BC 训时, A 的 loss 占主导, B 学不好。常用方案: 任务权重, 数据重采样, 课程学习 (从多数据任务到少数据任务)。"

**第 3 段: 负迁移**

"学习新任务时, 旧任务性能下降。原因是网络参数被新任务'覆盖'。解决方案: 任务独立 head, 持续学习 (EWC, replay buffer), 多任务梯度手术 (PCGrad, GradVac)。"

**第 4 段: 任务相关性**

"任务 A 和 B 相似时, 共享表示; 不相似时, 独立训练更好。CLIP / 语言条件隐式学到了这个, 语言相似的任务 (例如"开门"和"开抽屉") 自然共享特征。"

**第 5 段: 工业实践**

"RT-2 (Google, 2023): 55B 参数 Transformer, 6 任务, 全部语言条件。OpenVLA (2024): 7B 参数, 800+ 任务。Tesla Optimus: 100+ 任务, 共享视觉 backbone。"

**加分项**: 提到"多任务 BC 的成功关键是**任务表示 + 数据平衡 + 防止负迁移**"。

### Q5: BC 在工业的局限性?

**标准答案结构** (5 段):

**第 1 段: 长程任务失败**

"BC 在 10-20 步任务上成功率 70-90%, 在 50+ 步任务上掉到 30-40%。原因是误差累积: $\text{error}_T = T \cdot \epsilon_{\mathrm{step}}$。"

**第 2 段: 多模态退化**

"MSE 损失训多模态动作退化成"平均动作", 失败率高。Diffusion Policy 解决了多模态, 但推理慢 100×。"

**第 3 段: 因果混淆**

"BC 学关联不学因果, 训练分布外失败。DAgger 部分缓解, 但需要在线专家, 成本高。"

**第 4 段: 演示成本**

"专家演示 1-2 小时/任务, 1000 任务 = 2000 小时人工 ($200K)。人类视频可以缓解, 但有形态差异。"

**第 5 段: 性能上限**

"BC 上限 = 专家。无法超越人类。这在'需要超越人类'的任务 (例如复杂操作) 上是致命限制。"

**加分项**: 提到"BC + RL 混合训练"是当前工业主流 (BC 训基础, RL 微调关键), "Diffusion Policy" 是 BC 的现代化升级。

## 章节小结

**核心要点**:

1. **BC 的本质**: 监督学习视角下的模仿学习, 数学上等价于极大似然估计 (MLE)。
2. **BC 失败三件套**: 协变量偏移 + 误差累积 + 因果混淆, 三者层层递进, 构成 BC 在长程任务上的根本性局限。
3. **数学形式化**: $\text{error}_T \le T \cdot \epsilon_{\mathrm{train}}$, 累计误差随 $T$ 线性增长; Ross 证明 BC 的下界是 $O(T^{1/3})$, 不可能通过"更多数据"消除。
4. **因果混淆**: BC 学关联不学因果, 训练分布外失败, 是 BC 在工业落地的根本挑战。
5. **工业实践**: 50-100 演示/任务是甜区, Tesla/Figure/1X 全部用 BC + 大规模数据 + 任务特定微调。

**面试三句话总结**:

> 1. BC = 监督学习套到机器人上, 数学上等价于 MLE, 简单但有"因果混淆"的根本问题。
> 2. 训练-推理分布不同 (协变量偏移) + 误差累积 (线性增长) + 因果混淆 (学关联不学因果) = BC 失败三件套。
> 3. 工业方案: 大规模数据 (100K+ 演示) + 数据增强 + 任务特定微调, 部分缓解但不能完全解决。

## 12. 因果混淆的数学深层 (Mathematical Deep Dive)

> **写给 L8 工程师的话**:
>
> 上一节我们把因果混淆当成"学到了错的关联"。这一节我们把它放到**形式因果模型**的框架里, 用 **Pearl 的 DAG / do-calculus** 严格描述它, 让你能用数学语言向面试官和同事精确地"说出问题在哪里"。这一节是 §3 的**理论加强版**, 跟 数学基础/3-概率论/6-MLE·MAP·贝叶斯估计 一起看效果最好。

### 12.1 形式因果图 (Causal DAG)

**符号约定** (Pearl, Glymour et al.):

- $V = \{X_1, X_2, ..., X_n\}$: 一组随机变量
- $\mathcal{G} = (V, E)$: 有向无环图 (DAG), 节点是变量, 边是直接因果关系
- $X \to Y$: $X$ 是 $Y$ 的**直接原因** (direct cause)
- $X \leftarrow Y$: 反过来
- $X \perp\!\!\!\perp Y \mid Z$: 给定 $Z$ 时, $X$ 和 $Y$ 条件独立 (在 $\mathcal{G}$ 中 d-分离)

**机器人任务里常见的因果结构**:

```text
                  (Confounder)        (Confounder)
                    Light              Door Open
                      |                    |
                      v                    v
  Obstacle ----> Steering <---- Expert Policy
   (cause)        (action)         (cause)
      \              |                /
       \             v               /
        +-------> Crashed <--------+
                  (effect)
```

**BC 实际学到的关联 (错误的)**:

```text
  Light  ---->  Steering  <----  Door Open
  (虚假)     (动作)         (虚假)
```

专家**为什么**在 light=1 / door_open=0 时左转? 因为**障碍物存在** ($O=1$), 而 light=1 和 door_open=0 都是 $O$ 的**果** (causal descendants), 不是因。BC 把 $O$ 的"果"当成了"因", 学到了错误的关联。

**关键概念**:

| 概念 | 含义 | 例子 |
| :--- | :--- | :--- |
| **Confounder** $Z$ | 同时影响 $X$ 和 $Y$ 的"共同原因" | 天气同时影响"路面湿"和"行人多" |
| **Collider** $C$ | $X \to C \leftarrow Y$, $C$ 是 $X, Y$ 的共同果 | 雨天 → 路面湿, 洒水车 → 路面湿; 给定"路面湿"反而让"雨天"和"洒水车"负相关 |
| **Mediator** $M$ | $X \to M \to Y$ 的中间变量 | "想吃东西" → "看食物" → "伸手" |
| **Instrument** $I$ | 只影响 $X$, 不直接影响 $Y$ 的变量 | 工具变量, 经典计量经济学 |

### 12.2 Do-calculus 与干预 (Interventions)

**观测分布 (observational)** vs **干预分布 (interventional)**:

$$P(Y \mid X) \quad \text{(观测, "看到 X 时, Y 的分布")}$$

$$P(Y \mid do(X=x)) \quad \text{(干预, "强制 X=x 时, Y 的分布")}$$

**关键差异**: 观测时, $X$ 可能由 $Y$ 引起 (反向因果) 或被共同原因混淆; 干预时, $X$ 被人为设置, 切断所有入边。

**Pearl 的 do-operator 三规则** (do-calculus):

1. **插入/删除观测** (insertion/deletion of observations):
$$P(y \mid do(x), z, w) = P(y \mid do(x), w) \quad \text{if } (Y \perp\!\!\!\perp Z \mid X, W)_{G_{\overline{X}}}$$

2. **干预与观测交换** (action/observation exchange):
$$P(y \mid do(x), do(z), w) = P(y \mid do(x), z, w) \quad \text{if } (Y \perp\!\!\!\perp Z \mid X, W)_{G_{\overline{X}, \underline{Z}}}$$

3. **插入/删除干预** (insertion/deletion of actions):
$$P(y \mid do(x), do(z), w) = P(y \mid do(x), w) \quad \text{if } (Y \perp\!\!\!\perp Z \mid X, W)_{G_{\overline{X}, \overline{Z(W)}}}$$

其中 $G_{\overline{X}}$ 是把 $X$ 的所有入边删除后的图, $G_{\underline{X}}$ 是把 $X$ 的所有出边删除后的图。

**BC 的核心问题**: BC 学的是 $P(A \mid S)$ (观测), 不是 $P(A \mid do(S=s^*))$ (干预, 即"在专家最优状态下, 专家会做什么")。

**直觉**: 专家演示时, 状态 $S$ 来自专家策略 $\pi^*$ 产生, 包含"专家意图"的信息。BC 看到 $S$, 模仿 $A$, 但**不区分** $S$ 里哪些是"因" (要干预) 哪些是"果" (要忽略)。结果: BC 学到"看到 $S$ 的某些部分就做 $A$", 而正确的应该是"在 $S^*$ (因) 上做 $A$"。

### 12.3 后门准则 (Backdoor Criterion)

**问题**: 给定 $X$ (原因) 和 $Y$ (结果), 怎么从观测数据估计 $P(Y \mid do(X))$?

**后门路径 (backdoor path)**: $X \leftarrow \cdots \rightarrow Y$, 任何从 $X$ 到 $Y$ 的"反向"路径 (起点是 $X$ 的入边)。

**后门准则**: 变量集 $Z$ 满足后门准则 (相对 $(X, Y)$), 如果:

1. $Z$ 阻塞所有从 $X$ 到 $Y$ 的后门路径
2. $Z$ 不包含 $X$ 的后代
3. $Z$ 不包含 $Y$ 的后代 (除非它们也是 $X$ 的中介)

**当后门准则满足时**:

$$P(Y \mid do(X)) = \sum_z P(Y \mid X, Z=z) P(Z=z)$$

这就是 **adjustment formula**, 允许从观测数据估计干预效果。

**BC 的应用**:

对于 "状态 $S$ → 动作 $A$" 的因果识别, BC 训练的是 $P_\theta(A \mid S)$, 隐式假设 $S$ 里**没有未观测的 confounder**。如果存在未观测 confounder $U$ (例如"专家的意图", "环境的隐藏状态"), BC 学到的关联是**有偏的**。

**例子**:

```text
            U (专家意图: "想抓杯子")
           / \
          v   v
         S    A
       (看到杯子) (伸手)
```

$S$ 和 $A$ 都由 $U$ 引起。BC 学 $P(A \mid S)$ 是**条件概率**, 正确应该是 $P(A \mid do(S))$。两者的差异就是 confounding bias。

### 12.4 BC 的因果识别 (Causal Identification)

**形式化**: BC 训 $\pi_\theta(a \mid s)$, 目标是最小化 $\mathbb{E}[\mathcal{L}(\pi_\theta(s), a^*)]$, 其中 $a^* \sim \pi^*(\cdot \mid s)$, $s \sim d^{\pi^*}$。

**因果可识别 (causal identification)** 问题: 我们能从数据 $D$ 中识别 $\pi^*$ 吗?

**答案 (一般情况)**: 不能, 因为 $D$ 只包含 $(s, a)$ 对, 不包含 $do(\cdot)$ 操作, 也不包含未观测 confounder $U$。

**可识别条件**:

1. **无未观测 confounder (unconfoundedness)**: 所有影响 $S$ 和 $A$ 的变量都被观测
2. **支撑集重叠 (positivity)**: $P(S = s) > 0$ 对所有关心的 $s$
3. **一致性 (consistency)**: $P(A \mid S=s) = P(A \mid do(S=s))$

**BC 不满足条件 1**: 演示中总有未观测的 confounder (专家的内在状态, 环境的隐藏动力学)。所以 BC 的关联学习**系统性有偏**。

**形式化 (Pearl 1995)**: 观测关联 vs 干预效果的差异

$$\text{Bias} = P(A \mid S) - P(A \mid do(S)) = \sum_{u} P(A \mid S, U=u) [P(U=u \mid S) - P(U=u)]$$

直觉: 给定 $S$, $U$ 的分布**变了** (因为 $S$ 提供了 $U$ 的信息), 这个差异就是 confounding bias。

### 12.5 反事实 (Counterfactuals)

**反事实问题**: "如果当时专家的状态是 $s'$ (而不是演示的 $s$), 专家会做什么?"

**形式化**: $P(A^* \mid S=s, \text{history})$ — "在历史是 history, 状态是 $s$ 的反事实下, 动作 $A^*$ 的分布"。

**BC 永远学不到反事实**, 因为:
- 演示里只有 $P(A \mid S = s^{\text{demonstrated}})$
- 推理时机器人遇到 $S = s'$ (反事实), 数据里没有这个 $s'$

**三步反事实推理** (Pearl):

1. **Abduction**: 用观测数据更新 $U$ 的后验 $P(U \mid S = s, A = a)$
2. **Action**: 修改模型 (例如 $do(S = s')$)
3. **Prediction**: 用更新后的 $U$ 和修改后的模型预测 $P(A \mid do(S=s'), U)$

**BC = 跳过 abduction, 直接做 prediction**, 假设 $U$ 不存在。结果: 反事实外推能力差, 因果混淆严重。

**实际意义**: 当机器人遇到"演示里没出现过的"状态组合, BC 没有机制利用"专家在其他状态下的行为"来推断"专家在这个状态下会做什么"。这是 §3 因果混淆的**根本性**原因。

## 13. 协变量偏移的严格理论 (Strict Theory of Covariate Shift)

> 这一节把 §3.1 的协变量偏移放到 **domain adaptation** 的数学框架里, 给出可操作的**界**和**修正方法**。跟 数学基础/3-概率论/3-常用分布 一起看。

### 13.1 Importance Sampling 修正

**核心思想**: 训练分布 $P_{\mathrm{train}}(s, a)$ 和推理分布 $P_{\mathrm{test}}(s, a)$ 不同, 但**联合分布**分解为:

$$P(s, a) = P(s) \pi(a \mid s)$$

**假设**: $\pi(a \mid s)$ 不变, 只有 $P(s)$ 变。即**条件策略**稳定, **状态分布**漂移。

**重要性权重 (importance weight)**:

$$w(s) = \frac{P_{\mathrm{test}}(s)}{P_{\mathrm{train}}(s)}$$

**修正后的 BC 目标 (重要性加权 BC)**:

$$\theta^* = \arg\min_\theta \mathbb{E}_{(s, a) \sim P_{\mathrm{train}}} \left[ w(s) \mathcal{L}(\pi_\theta(s), a) \right]$$

**理论保证**: 如果 $w(s)$ 已知, 重要性加权 BC 的性能上界是:

$$\mathbb{E}_{P_{\mathrm{test}}}[\mathcal{L}(\pi_\theta, \pi^*)] \le \mathbb{E}_{P_{\mathrm{train}}}[w(s) \mathcal{L}(\pi_\theta, \pi^*)]$$

**实际困难**: $w(s) = P_{\mathrm{test}}(s) / P_{\mathrm{train}}(s)$ 通常**未知**。

**估计方法**:

1. **密度比估计 (density ratio estimation)**:
   - 训分类器 $\rho(s)$ 区分 $s \sim P_{\mathrm{train}}$ vs $s \sim P_{\mathrm{test}}$
   - $w(s) \approx \rho(s) / (1 - \rho(s))$

2. **KLIEP (Kullback-Leibler Importance Estimation Procedure)**:
   - 直接最小化 $KL(P_{\mathrm{test}}(s) \| w(s) P_{\mathrm{train}}(s))$
   - 用核方法估计

3. **uLSIF (unconstrained Least-Squares Importance Fitting)**:
   - 最小化 $\mathbb{E}_{P_{\mathrm{train}}}[(w(s) - P_{\mathrm{test}}(s) / P_{\mathrm{train}}(s))^2]$
   - 解析解, 稳定

**BC 应用问题**: 推理时 $P_{\mathrm{test}}(s) = d^{\pi_\theta}(s)$ 未知, 因为 $\pi_\theta$ 在训完之前**还没确定**。所以**直接**用 importance sampling 修正 BC **理论上不可能**, 只能**间接**通过 DAgger (在 $\pi_\theta$ 跑过的状态上 query 专家) 实现。

### 13.2 Domain Adaptation 界 (Ben-David et al. 2010)

**经典定理**: 对于源域 $S$ 和目标域 $T$ (BC 里是 $d^{\pi^*}$ 和 $d^{\pi_\theta}$):

$$\epsilon_T(h) \le \epsilon_S(h) + \frac{1}{2} d_{\mathcal{H}\Delta\mathcal{H}}(S, T) + \lambda$$

其中:
- $\epsilon_T(h)$: 假设 $h$ (BC 策略) 在目标域的误差
- $\epsilon_S(h)$: 在源域的误差
- $d_{\mathcal{H}\Delta\mathcal{H}}(S, T)$: $\mathcal{H}\Delta\mathcal{H}$-divergence, 衡量两域的"可区分度"
- $\lambda$: 联合误差 (best joint hypothesis error), 通常假设小

**直观解释**:
- $\epsilon_S(h)$: 训练集误差 (BC 在 $d^{\pi^*}$ 上的 MSE)
- $d_{\mathcal{H}\Delta\mathcal{H}}$: 两域差异 (BC 训的 $d^{\pi^*}$ vs 推理的 $d^{\pi_\theta}$)
- $\lambda$: 两域里"最佳假设"的差异 (理想情况下应该小)

**BC 的应用**:

$$P(\text{test fail}) \le P(\text{train fail}) + d_{\mathcal{H}\Delta\mathcal{H}}(d^{\pi^*}, d^{\pi_\theta}) + \lambda$$

**这给出了 BC 失败的形式化原因**:
- 训练误差小 (BC 训到 MSE < 0.01)
- 域差异大 ($d^{\pi_\theta}$ 跟 $d^{\pi^*}$ 差很多)
- 联合误差可能非零 (不同域的最优策略不同)

### 13.3 H-divergence 与 H 散度

**定义** ($d_{\mathcal{H}\Delta\mathcal{H}}$):

$$d_{\mathcal{H}\Delta\mathcal{H}}(P, Q) = 2 \sup_{h_1, h_2 \in \mathcal{H}} \left| \mathbb{E}_{x \sim P}[\mathbb{1}[h_1(x) \neq h_2(x)]] - \mathbb{E}_{x \sim Q}[\mathbb{1}[h_1(x) \neq h_2(x)]] \right|$$

**直观**: 在假设类 $\mathcal{H}$ (BC 网络) 上, 两分布"最容易被区分"的程度。

**BC 实际**: $\mathcal{H}$ 是 MLP 类, $d_{\mathcal{H}\Delta\mathcal{H}}$ 衡量"BC 网络能否区分 $d^{\pi^*}(s)$ 和 $d^{\pi_\theta}(s)$"。

**实际估计**: 训一个域判别器 $d: \mathcal{S} \to \{0, 1\}$ 区分两域, $d_{\mathcal{H}\Delta\mathcal{H}} \approx 2(1 - 2 \cdot \text{error of } d)$。

**应用**: 训练时监控 $d_{\mathcal{H}\Delta\mathcal{H}}$:

- 小 (例如 0.1): 协变量偏移小, BC 部署可能成功
- 大 (例如 0.5+): 偏移严重, BC 部署**几乎一定失败**, 需要 DAgger 或其他方法

### 13.4 协变量偏移检测 (Detection)

**实践方法**:

1. **域判别器训练**:
   ```python
   # 收集训练状态的特征
   train_features = encoder(train_states)  # 冻结 BC 的 encoder
   # 收集推理状态 (用 BC 跑 10 条轨迹)
   test_features = encoder(test_states)
   # 训判别器
   discriminator = MLP(input_dim, hidden_dim, 2)
   discriminator.fit(train_features, test_features, labels=[0]*N_train + [1]*N_test)
   # 检测
   if discriminator.auc > 0.7:
       print("严重协变量偏移, BC 部署可能失败")
   ```

2. **统计检验**:
   - **KS 检验** (Kolmogorov-Smirnov): 比较单维特征的累积分布
   - **MMD** (Maximum Mean Discrepancy): 多维分布差异, 核方法
   - **能量距离** (Energy Distance): MMD 的特殊形式, 计算快

3. **可视化 (t-SNE / UMAP)**:
   - 训 BC encoder, 把训练状态和推理状态降到 2D
   - 看两分布是否重叠
   - 重叠 → BC 可能能用; 不重叠 → 必失败

**§3.2 我们举了"自动驾玫 / 抓取 / 倒水"三个例子, 现在可以严格地用 MMD / 域判别器量化**。

### 13.5 协变量偏移修正方法 (Taxonomy)

**方法 1: 重要性加权** (上节) - 理论干净, 实际难用

**方法 2: 域不变特征学习 (DANN, Domain-Adversarial Neural Networks)**:
- 训 encoder $f$ 同时骗过"动作预测"和"域判别"
- $f$ 学到的特征对域不敏感
- BC 训在 $f(s)$ 上, 部署时也用 $f(s)$

**方法 3: 域自适应数据增强**:
- 生成"看起来像目标域"的训练样本
- 例如 CycleGAN 把"白天" 变 "晚上"
- 缺点: 生成的数据有偏差

**方法 4: 测试时自适应 (Test-Time Adaptation, TTA)**:
- 部署时, 在推理状态上继续微调 (例如熵最小化, BN 重统计)
- 假设推理状态可获得 (实际中通常可以, 部署时就在跑)

**方法 5: 收集目标域数据 (最直接但贵)**:
- 雇专家在目标环境演示 50-100 次
- 训 BC 在新数据上
- 这就是 DAgger 的精神

**BC 工业实践**: 大多数团队用**方法 1+5 的混合**: 训 BC, 看 $d_{\mathcal{H}\Delta\mathcal{H}}$ 大不大; 大就收集 50-100 新演示重训。

## 14. 误差累积的几何视角 (Geometric View of Error Compounding)

> 这一节把 §3.3 的"误差累积"放到**动力系统** (dynamical systems) 的视角里, 让你能"看到"误差如何在状态空间里扩散, 什么时候会"失控"。跟 数学基础/6-最优化/1-优化问题分类 一起看。

### 14.1 状态空间流形 (Manifold)

**假设**: 有效状态 (能完成任务的) 构成状态空间 $\mathcal{S}$ 中的一个**低维流形** $\mathcal{M} \subset \mathcal{S}$。

**直觉**:
- 真实世界状态可能 100K 维 (RGB 图像 150K, 关节 7)
- "能完成任务的"状态是其中极小部分
- BC 在 $\mathcal{M}$ 上训, 部署时希望机器人留在 $\mathcal{M}$ 里

**数学表示**: 状态 $s$ 在 $\mathcal{M}$ 上, $s = \phi(z)$, 其中 $z \in \mathbb{R}^d$ ($d \ll 100K$) 是隐变量。

**BC 误差 = 状态偏离 $\mathcal{M}$ 的距离**:

$$\text{error}(s) = \inf_{s' \in \mathcal{M}} \| s - s' \|$$

### 14.2 Lyapunov 稳定性分析

**Lyapunov 函数** $V: \mathcal{S} \to \mathbb{R}_{\ge 0}$, 衡量"距离失败有多远"。

**BC 的 Lyapunov 函数**: 任务完成的"信心"。

**Lyapunov 稳定性**: 如果 $V(s_{t+1}) \le \alpha V(s_t)$ (其中 $\alpha < 1$), 系统是**渐近稳定** (asymptotically stable), 误差指数衰减。

**BC 的现实**: 实际是 $V(s_{t+1}) \ge \beta V(s_t)$ (其中 $\beta > 1$), 系统**发散**, 误差指数增长。

**形式化 (线性化动力学)**:

假设动力学是 $s_{t+1} = A s_t + B \pi_\theta(s_t) + \epsilon_t$, 局部线性化:

$$s_{t+1} = (A + B J_\theta(s_t^*)) s_t + \text{const}$$

其中 $J_\theta$ 是 $\pi_\theta$ 的 Jacobian。

**BC 失败条件**: 矩阵 $A + B J_\theta$ 的**谱半径** $\rho > 1$, 系统不稳定。

**谱半径的几何含义**: 误差每步被放大 $\rho$ 倍, $t$ 步后放大 $\rho^t$ 倍。

**任务时间步 $T$ 后**: 误差 $\sim \rho^T$, $\rho = 1.05$, $T = 50$ → 误差 $\sim 11$ 倍。

### 14.3 BC 的"失败 cone"

**定义**: 从初始状态出发, BC 策略不能完成任务的初始状态集合。

**几何 (2D 简化)**:

```text
   s1 (关节角1)
    ^
    |
    |  成功区域 (任务完成)
    |  ┌──────────┐
    |  │  ✓       │
    |  │     ✓    │  ← 专家演示的状态
    |  │  ✓       │
    |  └──────────┘
    |   ╲         ╱
    |    ╲ 失败  ╱
    |     ╲ cone╱  ← 失败 cone (BC 偏离后进入)
    |      ╲   ╱
    |       ╲ ╱
    |        X  ← 初始状态 (起点)
    +──────────────> s2 (关节角2)
```

**关键观察**: 成功区域是 $\mathcal{S}$ 中的一个**小区域**。BC 训在"成功区域内的状态"上, 但**不保证** 推理时机器人留在成功区域内。

**失败 cone 的"张角"** 取决于:
- $\pi_\theta$ 的误差 $\epsilon$ (大 → cone 宽)
- 任务的"容错" (容错高 → cone 窄)
- 状态空间的维度 (高维 → cone 几何复杂, 但"体积"按指数增长)

### 14.4 误差累积的 ODE 视角

**离散**: $s_{t+1} = s_t + \pi_\theta(s_t) + \epsilon_t$

**连续近似 (ODE)**: $\dot{s} = \pi_\theta(s) + \epsilon(t)$

**在 $\mathcal{M}$ 附近的局部动力学**: $\dot{\delta} = J \delta + \epsilon(t)$, 其中 $\delta = s - s^*$ 是偏离专家状态的量。

**ODE 解**: $\delta(t) = e^{Jt} \delta(0) + \int_0^t e^{J(t-\tau)} \epsilon(\tau) d\tau$

**关键**: 矩阵指数 $e^{Jt}$ 的增长率由 $J$ 的**最大特征值** $\lambda_{\max}$ 决定。

- $\lambda_{\max} < 0$: 误差衰减, 稳定
- $\lambda_{\max} > 0$: 误差增长, 不稳定 (BC 典型情况)
- $\lambda_{\max} = 0$: 误差常数, 临界 (理想情况)

**BC 的工程意义**: 训练时监控 $J$ 的谱 (例如通过 power iteration), 看 $\lambda_{\max}$ 是否过大。过大时考虑:
- 数据增强 (让 $\pi_\theta$ 更平滑)
- Action chunking (减少开环步数)
- DAgger (在偏离状态上 query 专家)

### 14.5 误差累积的"轨迹散度"图

```text
  t=0:  ●  ← 起点 (一致)
  t=1:  ●  ●  ← BC 和 expert 略有分歧
  t=2:  ●    ●  ← 分歧加大
  t=3:  ●      ●  ← 显著分歧
  t=4:  ●        ●  ← 失控
  t=5:  ●          ●  ← 完全失败

  时间步 → 误差指数增长
```

**BC 失败的几何原因**: 误差沿"不稳定方向" (对应 $J$ 的正特征向量) 指数增长, 沿"稳定方向" (对应 $J$ 的负特征向量) 衰减。任务的"成功"要求状态沿**所有**关键方向都接近专家轨迹, 而 BC 只在**初始**方向上接近。

### 14.6 Lyapunov 函数的工程实现

**构造 Lyapunov 函数** (用于检测 BC 何时会失败):

```python
import torch
import torch.nn as nn

class LyapunovDetector(nn.Module):
    """Lyapunov 函数: 预测"距离失败有多远"

    训练: 用 (state, success_or_failure) 对, 训一个分类器
    部署: 实时预测失败概率
    """
    def __init__(self, state_dim, hidden_dim=256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(state_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, 1),
            nn.Sigmoid(),  # 输出失败概率 [0, 1]
        )

    def forward(self, state):
        return self.net(state)


# 训练数据: 收集 BC 跑过的状态, 标注成功/失败
# 训: BC rollout 1000 次, 记录 (state, success)
#    失败的 rollout 中所有 state 标 1
#    成功的 rollout 中所有 state 标 0
# 部署: 实时预测 P(fail | state)
#       P > 0.5 时触发"求救" (e.g., 停下来, query 远程专家)
```

**工业应用**: Tesla Optimus 在执行任务时, 用类似 Lyapunov detector 监控"距离失败"的概率, > 0.5 时停止 + 切换到安全模式。

## 15. 因果混淆检测与缓解 (Detection & Mitigation)

> 这一节给出**可操作的**因果混淆检测方法和缓解策略。技术性强, 但每一项都有工业实现参考。

### 15.1 HSIC 检测 (Hilbert-Schmidt Independence Criterion)

**核心思想**: 用 HSIC 统计量检测"两个变量是否独立"。

**定义**: 给定变量 $X, Y$ 和核 $k, l$:

$$\text{HSIC}(X, Y) = \mathbb{E}_{X, X', Y, Y'}[k(X, X') l(Y, Y')] + \mathbb{E}_{X, X'}[k(X, X')] \mathbb{E}_{Y, Y'}[l(Y, Y')] - 2 \mathbb{E}_{X, Y}[\mathbb{E}_{X'}[k(X, X')] \mathbb{E}_{Y'}[l(Y, Y')]]$$

**经验估计**:

```python
import torch

def hsic_test(X, Y, sigma=1.0):
    """HSIC 独立性检验

    Args:
        X: [N, d_x] tensor
        Y: [N, d_y] tensor
        sigma: 高斯核带宽

    Returns:
        hsic_value: HSIC 统计量 (大 = 强依赖)
    """
    N = X.size(0)

    # 中心化
    H = torch.eye(N) - torch.ones(N, N) / N
    K = torch.exp(-torch.cdist(X, X) ** 2 / (2 * sigma ** 2))
    L = torch.exp(-torch.cdist(Y, Y) ** 2 / (2 * sigma ** 2))

    K_c = H @ K @ H
    L_c = H @ L @ H

    hsic_value = torch.trace(K_c @ L_c) / (N - 1) ** 2
    return hsic_value

# 用法: 检测 BC 学到的"虚假关联"
# X = state 中的"灯"特征 (light_state)
# Y = BC 的预测动作 (action)
# HSIC 大 = BC 在用 light 预测 action
# HSIC 小 = BC 不依赖 light
```

**应用**: 训完 BC 后, 用 HSIC 检测每个状态特征对动作的依赖度:

- **真因** (obstacle): HSIC 大, BC 在用 → 好
- **假因** (light): HSIC 大, BC 在用 → **坏**, 这是因果混淆
- **无关** (background): HSIC 小, BC 没用 → 好

**修复**: 找到 HSIC 大的假因, 在数据中**置换**这个变量 (随机化 light 状态), 重新训 BC, 让 BC 学会不用这个变量。

### 15.2 Information Bottleneck for BC

**IB 原理**: 学一个表示 $Z = f(S)$, 让 $Z$ 包含 $A$ 的信息 (IB objective 第一项), 但 $Z$ 不包含 $S$ 的**无关**信息 (第二项)。

**目标函数**:

$$\mathcal{L}_{\mathrm{IB}} = -I(Z; A) + \beta I(Z; S)$$

其中 $I$ 是互信息, $\beta$ 控制压缩强度。

**BC + IB**:

$$\pi_\theta(a \mid z), \quad z = f(s), \quad f \text{ 是 encoder}$$

$$\mathcal{L}_{\mathrm{BC+IB}} = \mathbb{E}[\mathcal{L}(\pi_\theta(z), a)] + \beta I(f(s); s)$$

**为什么能缓解因果混淆?**

- $S$ 里有"真因" (obstacle) 和"假因" (light)
- IB 强迫 $Z$ **只保留预测 $A$ 所需的信息**
- 如果 $Z$ 既能从 obstacle 也能从 light 预测 $A$, IB 倾向于保留**最少的那部分** (信息瓶颈的"最小充分统计量"原则)
- 在多解情况下, IB 不一定选 obstacle, 但 $Z$ 维度会下降, 因果混淆被压缩

**实际困难**: $I(Z; S)$ 难估计, 需要 MINE / variational upper bound 等方法。

### 15.3 Adversarial De-confounding

**核心思想**: 训 encoder $f$ 时, 同时训一个"混淆判别器" $d$, 强迫 $f$ 学到的表示**不包含** 已知混淆变量的信息。

**目标**:

$$\min_f \max_d \mathcal{L}_{\mathrm{BC}}(f, \pi_\theta) - \lambda \mathcal{L}_{\mathrm{adv}}(d, f)$$

其中 $\mathcal{L}_{\mathrm{adv}}$ 是 $d$ 预测混淆变量 (例如 light) 的损失。

**直觉**: $d$ 试图从 $Z = f(s)$ 中预测 light, $f$ 试图让 $d$ 失败。最终 $Z$ 不包含 light 的信息, BC 必须依赖 obstacle。

**PyTorch 实现**:

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class DeconfoundedBC(nn.Module):
    """带对抗去混淆的 BC"""
    def __init__(self, state_dim, action_dim, confound_dim, hidden_dim=256):
        super().__init__()
        self.state_dim = state_dim
        self.confound_dim = confound_dim

        # Encoder: state -> latent
        self.encoder = nn.Sequential(
            nn.Linear(state_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, hidden_dim),
        )

        # Policy: latent -> action
        self.policy = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, action_dim),
        )

        # 混淆判别器: 试图从 latent 预测 confounding variable
        self.confound_disc = nn.Sequential(
            nn.Linear(hidden_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, confound_dim),
        )

    def forward(self, state):
        z = self.encoder(state)
        action = self.policy(z)
        return action, z

    def compute_loss(self, state, action, confound, lambda_adv=0.1):
        """BC loss + 对抗 de-confounding loss"""
        pred_action, z = self(state)

        # BC 损失 (MSE)
        bc_loss = F.mse_loss(pred_action, action)

        # 对抗损失: 判别器预测 confounding
        confound_pred = self.confound_disc(z)
        # Gradient reversal: encoder 想最大化这个 loss (让判别器失败)
        adv_loss = F.mse_loss(confound_pred, confound)

        # 总损失
        loss = bc_loss + lambda_adv * adv_loss
        return loss
```

**训练** (两步交替):
```python
# Step 1: 训判别器 (从 latent 预测 confounding)
z_detached = z.detach()
confound_pred = confound_disc(z_detached)
disc_loss = F.mse_loss(confound_pred, confound)
disc_loss.backward()
disc_optimizer.step()

# Step 2: 训 encoder + policy (让判别器失败, 同时让 BC 损失小)
pred_action, z = model(state)
bc_loss = F.mse_loss(pred_action, action)
adv_loss = -F.mse_loss(confound_disc(z), confound)  # 负号: 想让判别器错
total_loss = bc_loss + lambda_adv * adv_loss
total_loss.backward()
optimizer.step()
```

### 15.4 Causal Attention Masking

**核心思想**: Transformer BC 中, 显式 mask 掉"已知假因" token 之间的 attention。

**例子**: 状态序列 $S = [\text{camera\_img}, \text{light}, \text{obstacle}, \text{joint\_angles}]$, 已知 light 是假因。

**Causal mask**:

```python
import torch.nn.functional as F

# 假设 4 个 token, light 是 token 1
# light 可以被其他 token attend, 但 light 不能 attend 任何 token
# (强迫模型不用 light 预测 action)

causal_mask = torch.ones(4, 4)
# light 不能 attend 其他
causal_mask[1, :] = 0  # light 的 attention score 全 0
# 但其他 token 可以 attend light (防止 encoder 太早丢弃这个信息)
# 这是 "soft" masking, 也可以 hard mask (light 输出置零)
```

### 15.5 Invariant Risk Minimization (IRM)

**原理 (Arjovsky et al. 2019)**: 训一个表示 $f$, 让最优分类器 (BC 策略) 在**所有环境**下都相同。

**环境**: 训练数据来自多个"环境" $e \in \mathcal{E}$, 不同环境下假因不同, 真因不变。

**IRM 目标**:

$$\min_f \sum_{e \in \mathcal{E}} \mathcal{L}^e(\pi_\theta \circ f) + \lambda \| \nabla_w \mathcal{L}^e(w \cdot f) \|_{w=1.0} \|^2$$

**第二项**: 强迫"在每个环境下, 最佳 $w$ 都是 1" (即"环境不变")。

**BC 应用**: 训练数据来自多个操作员 / 多个环境 / 多天, IRM 强迫 BC 学到跨环境不变的真因 (obstacle), 而不是环境特定的假因 (操作员 A 的"风格")。

**实际困难**: 真实机器人数据集通常没有显式的"环境"标签, 需要用 metadata 推断。

### 16.1 BC with Causal Attention (Transformer BC)

**目标**: 实现一个带因果 attention 的 transformer BC, 显式 mask 掉已知混淆变量, 提升因果鲁棒性。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
import math
from torch.utils.data import Dataset, DataLoader


class CausalAttention(nn.Module):
    """带因果 mask 的 multi-head attention

    功能: 在 attention score 上应用 mask, 让某些 token 不能 attend 其他 token
    用法: mask = torch.zeros(seq_len, seq_len); mask[confound_idx, :] = -inf
    """
    def __init__(self, d_model, n_heads, dropout=0.1):
        super().__init__()
        assert d_model % n_heads == 0
        self.d_model = d_model
        self.n_heads = n_heads
        self.d_k = d_model // n_heads

        self.w_q = nn.Linear(d_model, d_model)
        self.w_k = nn.Linear(d_model, d_model)
        self.w_v = nn.Linear(d_model, d_model)
        self.w_o = nn.Linear(d_model, d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        """
        Args:
            x: [B, seq_len, d_model]
            mask: [seq_len, seq_len] (None 表示无 mask, 否则 mask 位置加 -inf)
        """
        B, L, _ = x.shape

        Q = self.w_q(x).view(B, L, self.n_heads, self.d_k).transpose(1, 2)
        K = self.w_k(x).view(B, L, self.n_heads, self.d_k).transpose(1, 2)
        V = self.w_v(x).view(B, L, self.n_heads, self.d_k).transpose(1, 2)
        # Q, K, V: [B, n_heads, L, d_k]

        scores = (Q @ K.transpose(-2, -1)) / math.sqrt(self.d_k)
        # scores: [B, n_heads, L, L]

        if mask is not None:
            scores = scores + mask  # mask 位置加 -inf

        attn = F.softmax(scores, dim=-1)
        attn = self.dropout(attn)

        out = (attn @ V).transpose(1, 2).contiguous().view(B, L, self.d_model)
        return self.w_o(out)


class TransformerBCWithCausalMask(nn.Module):
    """Transformer BC with causal attention masking for de-confounding

    适用: 多模态状态 (image patch tokens + state tokens), 想显式屏蔽混淆变量
    """
    def __init__(
        self,
        state_dim,
        action_dim,
        d_model=256,
        n_heads=8,
        n_layers=4,
        n_patches=16,  # 视觉 token 数 (例如 4x4 patch)
        confound_token_idx=None,  # 混淆 token 的索引
        max_action_chunk=10,  # action chunking
        dropout=0.1,
    ):
        super().__init__()
        self.d_model = d_model
        self.n_patches = n_patches
        self.confound_token_idx = confound_token_idx
        self.max_action_chunk = max_action_chunk
        self.action_dim = action_dim

        # 状态编码: state -> token
        self.state_encoder = nn.Linear(state_dim, d_model)
        # 视觉编码 (简化: 假设 patch 已经提取)
        self.patch_encoder = nn.Linear(patch_dim := 768, d_model)  # patch_dim 视 backbone 而定
        # 动作解码: token -> action chunk
        self.action_decoder = nn.Linear(d_model, action_dim * max_action_chunk)

        # Causal attention layers
        self.layers = nn.ModuleList([
            CausalAttention(d_model, n_heads, dropout)
            for _ in range(n_layers)
        ])
        self.norms = nn.ModuleList([
            nn.LayerNorm(d_model) for _ in range(n_layers * 2)
        ])
        self.ffns = nn.ModuleList([
            nn.Sequential(
                nn.Linear(d_model, d_model * 4),
                nn.GELU(),
                nn.Linear(d_model * 4, d_model),
            )
            for _ in range(n_layers)
        ])
        self.dropout = nn.Dropout(dropout)

        # 构建 causal mask
        seq_len = 1 + n_patches + 1  # [cls, patches..., state]
        self.register_buffer(
            "causal_mask",
            self._build_causal_mask(seq_len),
        )

    def _build_causal_mask(self, seq_len):
        """构建 mask: 混淆 token 不能 attend 其他"""
        mask = torch.zeros(seq_len, seq_len)
        if self.confound_token_idx is not None:
            mask[self.confound_token_idx, :] = float("-inf")
        return mask

    def forward(self, state, patches):
        """
        Args:
            state: [B, state_dim]
            patches: [B, n_patches, patch_dim]

        Returns:
            action_chunk: [B, max_action_chunk, action_dim]
        """
        B = state.size(0)

        # 编码 token
        state_token = self.state_encoder(state).unsqueeze(1)  # [B, 1, d_model]
        patch_tokens = self.patch_encoder(patches)  # [B, n_patches, d_model]
        cls_token = torch.zeros(B, 1, self.d_model, device=state.device)  # [B, 1, d_model]

        # 拼接: [cls, patches..., state]
        x = torch.cat([cls_token, patch_tokens, state_token], dim=1)  # [B, L, d_model]
        x = self.dropout(x)

        # Transformer layers
        for i, (attn, ffn, norm1, norm2) in enumerate(zip(
            self.layers, self.ffns, self.norms[::2], self.norms[1::2]
        )):
            # Self-attention with causal mask
            attn_out = attn(x, mask=self.causal_mask)
            x = norm1(x + attn_out)
            # FFN
            ffn_out = ffn(x)
            x = norm2(x + ffn_out)

        # 取 state token (假设是最后一个) 输出 action
        out = x[:, -1, :]  # [B, d_model]
        action_flat = self.action_decoder(out)  # [B, action_dim * max_action_chunk]
        action_chunk = action_flat.view(B, self.max_action_chunk, self.action_dim)
        return action_chunk


# 训练循环
def train_causal_bc(
    states, patches, action_chunks, epochs=100, batch_size=32, lr=1e-4,
    confound_token_idx=1,  # 假设 patch 1 是混淆 token
):
    dataset = torch.utils.data.TensorDataset(
        torch.from_numpy(states).float(),
        torch.from_numpy(patches).float(),
        torch.from_numpy(action_chunks).float(),
    )
    loader = DataLoader(dataset, batch_size=batch_size, shuffle=True)

    model = TransformerBCWithCausalMask(
        state_dim=states.shape[1],
        action_dim=action_chunks.shape[2],
        n_patches=patches.shape[1],
        confound_token_idx=confound_token_idx,
    )
    optimizer = torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=1e-4)

    for epoch in range(epochs):
        total_loss = 0
        for s, p, ac in loader:
            pred = model(s, p)  # [B, max_action_chunk, action_dim]
            loss = F.mse_loss(pred, ac)
            optimizer.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            optimizer.step()
            total_loss += loss.item()

        if (epoch + 1) % 10 == 0:
            print(f"Epoch {epoch+1}/{epochs} | Loss: {total_loss / len(loader):.4f}")

    return model
```

**关键点**:
- `causal_mask` 让混淆 token 输出不被 attention 读取
- 多层 + LayerNorm + GELU FFN 是标准 transformer 配方
- Action chunking: 一次预测 10 步, 减少累积误差

### 16.2 Action Chunking BC (完整 ACT 简化版)

**ACT** (Action Chunking Transformer, Stanford 2023) 一次预测 $k$ 步动作, 训时用 MSE + temporal ensemble, 推理时用 receding horizon。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class ACTPolicy(nn.Module):
    """ACT: Action Chunking Transformer (简化版)

    关键创新:
    1. 一次预测 k 步动作 (chunking)
    2. 用 encoder 把可变长演示压缩到固定 latent z
    3. 用 CVAE 风格训 (reconstruction + KL)
    4. 推理时用 z 的 prior (不需 encoder)
    """
    def __init__(
        self,
        state_dim,
        action_dim,
        chunk_size=10,
        latent_dim=32,
        d_model=256,
        n_heads=8,
        n_encoder_layers=3,
        n_decoder_layers=3,
        kl_weight=0.01,
    ):
        super().__init__()
        self.state_dim = state_dim
        self.action_dim = action_dim
        self.chunk_size = chunk_size
        self.latent_dim = latent_dim
        self.kl_weight = kl_weight

        # Encoder: (state, action_chunk) -> latent z
        self.action_encoder = nn.Linear(action_dim, d_model)
        self.state_encoder_enc = nn.Linear(state_dim, d_model)
        encoder_layer = nn.TransformerEncoderLayer(
            d_model, n_heads, dim_feedforward=d_model * 4,
            dropout=0.1, batch_first=True,
        )
        self.transformer_encoder = nn.TransformerEncoder(
            encoder_layer, num_layers=n_encoder_layers,
        )
        self.latent_mu = nn.Linear(d_model, latent_dim)
        self.latent_logvar = nn.Linear(d_model, latent_dim)

        # Decoder: (state, z) -> action chunk
        self.latent_proj = nn.Linear(latent_dim, d_model)
        self.state_encoder_dec = nn.Linear(state_dim, d_model)
        self.action_queries = nn.Embedding(chunk_size, d_model)  # learnable queries
        decoder_layer = nn.TransformerDecoderLayer(
            d_model, n_heads, dim_feedforward=d_model * 4,
            dropout=0.1, batch_first=True,
        )
        self.transformer_decoder = nn.TransformerDecoder(
            decoder_layer, num_layers=n_decoder_layers,
        )
        self.action_head = nn.Linear(d_model, action_dim)

    def encode(self, state, action_chunk):
        """CVAE encoder: 训时用, 推理时不用"""
        B = state.size(0)
        # 把 state 复制 chunk_size 次, 每个时间步一个 state
        state_seq = self.state_encoder_enc(state).unsqueeze(1).expand(-1, self.chunk_size, -1)
        # 把 action chunk 编码
        action_seq = self.action_encoder(action_chunk)
        # 拼接
        x = state_seq + action_seq  # [B, chunk_size, d_model]
        # Transformer encoder
        x = self.transformer_encoder(x)
        # 平均池化到 latent
        x_pool = x.mean(dim=1)  # [B, d_model]
        mu = self.latent_mu(x_pool)
        logvar = self.latent_logvar(x_pool)
        return mu, logvar

    def decode(self, state, z):
        """Decoder: 用 z 重建 action chunk"""
        B = state.size(0)
        z_proj = self.latent_proj(z).unsqueeze(1)  # [B, 1, d_model]
        state_proj = self.state_encoder_dec(state).unsqueeze(1)  # [B, 1, d_model]
        # 用 z + state 作为 memory
        memory = z_proj + state_proj  # [B, 1, d_model]
        # Action queries (learnable)
        queries = self.action_queries.weight.unsqueeze(0).expand(B, -1, -1)  # [B, chunk_size, d_model]
        # Decoder
        out = self.transformer_decoder(queries, memory)  # [B, chunk_size, d_model]
        # 输出动作
        action_chunk = self.action_head(out)  # [B, chunk_size, action_dim]
        return action_chunk

    def forward(self, state, action_chunk=None, train=True):
        """前向传播
        Args:
            state: [B, state_dim]
            action_chunk: [B, chunk_size, action_dim] (训时)
            train: True 训, False 推理
        """
        if train and action_chunk is not None:
            # CVAE 训练: encode, sample z, decode
            mu, logvar = self.encode(state, action_chunk)
            # Reparameterization trick
            std = torch.exp(0.5 * logvar)
            z = mu + std * torch.randn_like(std)
            # Decode
            action_pred = self.decode(state, z)
            return action_pred, mu, logvar
        else:
            # 推理: 用 prior (mu=0, std=1)
            B = state.size(0)
            z = torch.randn(B, self.latent_dim, device=state.device)
            action_pred = self.decode(state, z)
            return action_pred, None, None


def act_loss(action_pred, action_target, mu, logvar, kl_weight=0.01):
    """ACT 损失: reconstruction + KL divergence"""
    recon_loss = F.mse_loss(action_pred, action_target)
    # KL divergence to standard normal
    kl_loss = -0.5 * torch.mean(1 + logvar - mu.pow(2) - logvar.exp())
    return recon_loss + kl_weight * kl_loss


# 训练循环
def train_act(states, action_chunks, epochs=200, batch_size=32, lr=1e-4, kl_weight=0.01):
    dataset = torch.utils.data.TensorDataset(
        torch.from_numpy(states).float(),
        torch.from_numpy(action_chunks).float(),
    )
    loader = DataLoader(dataset, batch_size=batch_size, shuffle=True)

    state_dim = states.shape[1]
    action_dim = action_chunks.shape[2]
    chunk_size = action_chunks.shape[1]

    model = ACTPolicy(state_dim, action_dim, chunk_size=chunk_size, kl_weight=kl_weight)
    optimizer = torch.optim.AdamW(model.parameters(), lr=lr, weight_decay=1e-4)

    for epoch in range(epochs):
        total_loss = 0
        for s, ac in loader:
            action_pred, mu, logvar = model(s, ac, train=True)
            loss = act_loss(action_pred, ac, mu, logvar, kl_weight=kl_weight)
            optimizer.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
            optimizer.step()
            total_loss += loss.item()

        if (epoch + 1) % 20 == 0:
            print(f"Epoch {epoch+1}/{epochs} | Loss: {total_loss / len(loader):.4f}")

    return model


# 推理: Receding horizon
def rollout_act(model, env, max_steps=200, chunk_size=10):
    """Receding horizon: 每步重新规划一个 chunk, 只执行第一步"""
    state = env.reset()
    for step in range(max_steps):
        with torch.no_grad():
            state_t = torch.from_numpy(state).float().unsqueeze(0)
            action_chunk, _, _ = model(state_t, train=False)
        action = action_chunk[0, 0, :].numpy()  # 取 chunk 的第一步
        state, _, done, _ = env.step(action)
        if done:
            break
    return step
```

**关键创新**:
- **Action chunking**: 一次预测 10 步, 减少开环误差
- **CVAE latent**: 用 latent z 表达"演示的特定风格" (力度, 速度), 推理时用 prior 让 z 不影响动作
- **Receding horizon**: 推理时每步重新规划, 用 closed-loop feedback

### 16.3 HSIC-based Causal Confusion Detector

**目标**: 训完 BC 后, 用 HSIC 检测 BC 是否在用某个混淆变量。

```python
import torch
import torch.nn as nn
import numpy as np
from torch.utils.data import DataLoader


def hsic_statistic(X, Y, sigma_x=1.0, sigma_y=1.0):
    """计算 HSIC 统计量

    Args:
        X: [N, d_x] tensor
        Y: [N, d_y] tensor
        sigma_x, sigma_y: 高斯核带宽

    Returns:
        hsic_value: scalar tensor
    """
    N = X.size(0)

    def rbf_kernel(Z, sigma):
        dist = torch.cdist(Z, Z, p=2) ** 2
        return torch.exp(-dist / (2 * sigma ** 2 + 1e-8))

    K = rbf_kernel(X, sigma_x)
    L = rbf_kernel(Y, sigma_y)

    # 中心化
    H = torch.eye(N, device=X.device) - torch.ones(N, N, device=X.device) / N
    K_c = H @ K @ H
    L_c = H @ L @ H

    hsic = torch.trace(K_c @ L_c) / (N - 1) ** 2
    return hsic


def detect_causal_confusion(
    policy, dataset, confound_feature_idx, action_dim,
    n_samples=500, sigma=1.0,
):
    """检测 BC 是否在用某个混淆变量

    Args:
        policy: 训好的 BC 策略
        dataset: 训练数据集 (states, actions)
        confound_feature_idx: 混淆特征在 state 中的索引
        action_dim: 动作维度
        n_samples: 采样数
        sigma: HSIC 核带宽

    Returns:
        hsic_value: HSIC 统计量 (大 = BC 在用这个变量)
        threshold: 临界值 (用 permutation test 估计)
    """
    # 采样
    indices = np.random.choice(len(dataset), size=n_samples, replace=False)
    states = torch.stack([dataset[i][0] for i in indices])  # [N, state_dim]

    with torch.no_grad():
        pred_actions = policy(states)  # [N, action_dim]

    confound_feature = states[:, confound_feature_idx:confound_feature_idx+1]

    # 计算 HSIC(confound, action)
    hsic_value = hsic_statistic(confound_feature, pred_actions, sigma_x=sigma, sigma_y=sigma)

    # Permutation test 估计临界值
    perm_values = []
    for _ in range(100):
        perm_idx = torch.randperm(n_samples)
        hsic_perm = hsic_statistic(
            confound_feature[perm_idx], pred_actions,
            sigma_x=sigma, sigma_y=sigma,
        )
        perm_values.append(hsic_perm.item())

    threshold = np.percentile(perm_values, 95)  # 95% 临界值

    is_confounded = hsic_value.item() > threshold

    return {
        "hsic_value": hsic_value.item(),
        "threshold": threshold,
        "is_confounded": is_confounded,
    }


# 用法
# dataset = 训练数据 (states, actions)
```

### 16.4 DAgger-lite 简化实现

**目标**: 实现 DAgger 的简化版, 用一个"虚拟专家" 在线 query, 验证协变量偏移的修复效果。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np


def dagger_lite(
    env, expert_policy, n_iterations=5, n_episodes_per_iter=10,
    max_steps=200, hidden_dim=256, lr=1e-3, epochs_per_iter=20,
):
    """DAgger-lite: 简化版 DAgger

    Args:
        env: 环境
        expert_policy: 专家策略 (callable, 输入 state, 输出 action)
        n_iterations: DAgger 迭代次数
        n_episodes_per_iter: 每次迭代跑的轨迹数
        max_steps: 单条轨迹最大步数
    """
    # 1. 初始数据: 专家演示
    all_states, all_actions = [], []
    for _ in range(n_episodes_per_iter):
        state = env.reset()
        for _ in range(max_steps):
            expert_action = expert_policy(state)  # 专家动作
            all_states.append(state)
            all_actions.append(expert_action)
            state = env.step(expert_action)[0]  # 真实执行专家动作 (DAgger 第一轮)

    states_np = np.array(all_states)
    actions_np = np.array(all_actions)
    state_dim = states_np.shape[1]
    action_dim = actions_np.shape[1]

    # 2. 训初始 BC
    policy = nn.Sequential(
        nn.Linear(state_dim, hidden_dim),
        nn.ReLU(),
        nn.Linear(hidden_dim, hidden_dim),
        nn.ReLU(),
        nn.Linear(hidden_dim, action_dim),
    )
    optimizer = torch.optim.Adam(policy.parameters(), lr=lr)

    def train_bc_on_data():
        states_t = torch.from_numpy(states_np).float()
        actions_t = torch.from_numpy(actions_np).float()
        dataset = torch.utils.data.TensorDataset(states_t, actions_t)
        loader = DataLoader(dataset, batch_size=32, shuffle=True)
        for _ in range(epochs_per_iter):
            for s, a in loader:
                pred = policy(s)
                loss = F.mse_loss(pred, a)
                optimizer.zero_grad()
                loss.backward()
                optimizer.step()

    train_bc_on_data()

    # 3. DAgger 迭代
    for it in range(n_iterations):
        new_states, new_actions = [], []
        for ep in range(n_episodes_per_iter):
            state = env.reset()
            for _ in range(max_steps):
                # 用当前 BC 选动作
                with torch.no_grad():
                    state_t = torch.from_numpy(state).float().unsqueeze(0)
                    bc_action = policy(state_t).squeeze(0).numpy()
                # 在 BC 状态上 query 专家
                expert_action = expert_policy(state)
                # 收集 (bc_state, expert_action) 对
                new_states.append(state)
                new_actions.append(expert_action)
                # 用 BC 动作执行 (而不是专家动作, 模拟部署分布)
                state = env.step(bc_action)[0]

        # 4. 把新数据加入训练集
        states_np = np.concatenate([states_np, np.array(new_states)])
        actions_np = np.concatenate([actions_np, np.array(new_actions)])
        print(f"Iteration {it+1}/{n_iterations}: dataset size = {len(states_np)}")

        # 5. 重训 BC
        train_bc_on_data()

    return policy


# 用法: 跟 §5.1 的简单 BC 对比
# env = PushTEnv()
# expert = lambda s: s[3:5] - s[0:2]  # 专家策略
# dagger_policy = dagger_lite(env, expert, n_iterations=5)
#
# 对比: 简单 BC 成功率 50%, DAgger 成功率 80%+
```

**DAgger 关键点**:
- 第 1 轮: 在专家状态上训 (跟 BC 一样)
- 第 2 轮起: 用 BC 跑, 记录访问状态, query 专家在这些状态上的动作
- 数据集变成"专家状态 + BC 状态" 的混合
- BC 学会从 BC 状态恢复

**收敛保证** (Ross & Bagnell 2010):

$$\text{error}_T^{\text{DAgger}} \le T \cdot \epsilon_{\text{train}} \cdot \alpha$$

其中 $\alpha$ 是 no-regret 学习率 (例如 $\alpha = 1/\sqrt{T}$), 所以 DAgger 的累计误差是 $O(T^{1/2} \cdot \epsilon)$, 比 BC 的 $O(T \cdot \epsilon)$ **指数级好**。

### Q6: 多模态动作的 BC 失败, 数学上怎么解释?

**标准答案结构** (4 段, ~5 分钟):

**第 1 段: 多模态的定义**

"多模态 (multimodal) 动作分布: 同一状态 $s$ 下, 专家可能用**多个不同**动作 $a$ 都能完成, $P(a \mid s)$ 是**多峰分布**。例: 抓取, 物体有多个稳定抓点, BC 训时数据包含多种抓法。"

**第 2 段: MSE 退化的数学**

"BC 用 MSE 训, 等价于拟合**单高斯**: $\pi_\theta(a \mid s) = \mathcal{N}(\mu_\theta(s), \sigma^2 I)$。多模态分布的**最优单高斯**是各模态的**平均**。例: 抓取, 5 种抓法的平均 = 物体中心 (不在任何抓点上), 抓不住。"

"形式化: 多模态 $P^*(a \mid s) = \frac{1}{K} \sum_{k=1}^K \mathcal{N}(\mu_k(s), \sigma_k^2)$, MSE 训出的 $\mu_\theta(s) = \mathbb{E}_{a \sim P^*}[a \mid s] = \frac{1}{K} \sum_k \mu_k(s)$。但 $\mathbb{E}[a] = \arg\min_a \mathbb{E}[\|a - a^*\|^2]$, 不是**任意** $a$ 的高似然。"

**第 3 段: 解决方法的对比**

"Diffusion Policy 显式建模整个分布: $\pi_\theta(a \mid s) = \int p_\theta(a \mid z, s) p(z) dz$, 用条件扩散生成多模态动作。Flow Matching 用 ODE 变换把简单分布 (高斯) 变换到多模态目标分布, 推理快 5-10x。Mixture Density Network (MDN) 用 $K$ 个高斯混合, 但 $K$ 难选。"

**第 4 段: 工业实践**

"ALOHA 用 ACT (action chunking) + CVAE latent, 让 latent 表征"哪种抓法", 推理时用 prior。Tesla Optimus 用 Flow Matching head, 推理 50 Hz。Mobile ALOHA 做菜 80% 成功率就是用多模态动作建模。"

**加分项**: 提到"Mixture of $K$ 高斯" 训练时需要 $K$ 选择, "latent space" 维度影响多模态质量。

### Q7: Diffusion Policy vs BC 的严格对比?

**标准答案结构** (5 段):

**第 1 段: 损失函数**

"BC 用 $\mathcal{L}_{\mathrm{MSE}} = \|a - \mu_\theta(s)\|^2$ 或 $\mathcal{L}_{\mathrm{NLL}} = -\log \mathcal{N}(a; \mu_\theta(s), \sigma^2 I)$, 假设**单高斯**。Diffusion Policy 用 $\mathcal{L}_{\mathrm{diff}} = \mathbb{E}_{t, \epsilon}[\|\epsilon - \epsilon_\theta(\sqrt{\bar\alpha_t} a_0 + \sqrt{1-\bar\alpha_t} \epsilon, s, t)\|^2]$, 不假设参数化形式, 拟合**任意分布**。"

**第 2 段: 推理**

"BC: 1 次前向, 1 ms (MLP)。Diffusion Policy: 10-100 次去噪, 100-1000 ms。Flow Matching: 10 次 ODE 步, 50-100 ms, 是 Diffusion Policy 的 5-10x 加速。"

**第 3 段: 多模态能力**

"BC (MSE) 退化成平均, Diffusion Policy / Flow Matching 保持多模态。在 ALOHA 12 任务上, Diffusion Policy 85%, BC (MSE) 65%, 提升 20%。在 Push-T 上, Diffusion Policy 90%, BC 75%。"

**第 4 段: 训练成本**

"BC: 1-2 小时 (单 GPU)。Diffusion Policy: 5-10 小时 (单 GPU) 或 1-2 小时 (8 GPU)。Flow Matching: 3-5 小时 (单 GPU)。"

**第 5 段: 工业选择**

"低延迟要求 (50 Hz+ 控制): BC 或 Flow Matching。多模态要求 + 慢控制可接受: Diffusion Policy。简单任务: BC (性价比高)。复杂长程任务: Diffusion Policy + Action Chunking。"

**加分项**: 提到 "Consistency Model" 是 Diffusion 的**单步**版本, 推理 < 10ms, 但性能略低。

### Q8: 怎么在生产环境检测 BC 部署时的因果混淆?

**标准答案结构** (5 段, ~7 分钟):

**第 1 段: 离线检测 (HSIC)**

"训完 BC, 用 §15.1 的 HSIC 检测每个 state 特征对动作的依赖度。HSIC 大的特征是 BC 在用的, 但**不一定**是 confounder。需要结合先验知识: 哪些特征是物理相关的 (obstacle → action), 哪些是 spurious (light → action)。"

**第 2 段: 反事实测试 (Counterfactual Test)**

"构造训练分布外的状态对, 测 BC 行为:
1. 状态 $s_1$: obstacle=1, light=0 (训练时没见过, 训练时 light 跟 obstacle 完美相关)
2. 状态 $s_2$: obstacle=0, light=1 (反事实)
3. 看 BC 行为: 如果 BC 行为依赖 light (而不是 obstacle), 就是因果混淆。"

```python
# 实现
s_normal = env.reset()  # obstacle=1, light=1
s_counterfactual = s_normal.copy()
s_counterfactual[light_idx] = 0  # 反事实: light=0 但 obstacle=1
action_normal = policy(s_normal)
action_counterfactual = policy(s_counterfactual)
# 期望: 两次动作相同 (因为 obstacle 没变, expert 都是左转)
# 实际: 两次动作不同 → 因果混淆
```

**第 3 段: 在线监控 (Lyapunov)**

"部署时, 实时监控 §14.6 的 Lyapunov detector (预测失败概率)。如果失败概率快速上升, 切换到 safe mode + query 远程专家。Tesla Optimus 用这个方案。"

**第 4 段: A/B 测试 + 任务成功率**

"工业标准: BC 部署后, 跑 A/B 测试。一组用 BC, 一组用 rule-based baseline (例如 hard-coded 策略)。如果 BC 显著低于 baseline, 说明有 BC 系统性问题 (协变量偏移 / 因果混淆)。"

**第 5 段: 失败模式分析 (Failure Mode Analysis)**

"BC 失败的轨迹, 人工分析"为什么失败"。常见模式:
- 失败在分布外状态 (e.g., 光照变化)
- 失败在长程任务后期 (误差累积)
- 失败在多模态分支 (MSE 平均化)
每种模式对应不同的修复 (数据增强 / Action Chunking / Diffusion Policy)。"

**加分项**: 提到 "Leave-One-Out" 测试: 留掉某个 state 特征, 看 BC 性能是否下降。如果不下降, 说明 BC 没在用这个特征 (可能是应该用的真因, BC 没用, 是个 bug)。

### Q9: BC + RL 混合训练怎么设计?

**标准答案结构** (5 段):

**第 1 段: 为什么需要混合**

"BC 上限 = 专家, 不会超越; RL 训练成本高, 1M+ 步; BC 数据效率高但有 causal confusion; RL 解决 causal confusion 但 sample 效率差。混合: BC 训基础, RL 微调关键场景。"

**第 2 段: 范式 1: BC 初始化 + RL 微调**

"用 BC 训初始策略 $\pi_\theta^{\mathrm{BC}}$, 然后用 PPO / SAC 在 reward function 上继续微调。优点: BC 提供 good prior, RL 不需要从随机开始。缺点: RL 可能"破坏"BC 训好的能力 (catastrophic forgetting)。"

```python
# 实现
bc_policy = train_bc(demos)
# RL 微调
rl_policy = bc_policy  # 用 BC 参数初始化
for episode in range(n_episodes):
    state = env.reset()
    for step in range(max_steps):
        action = rl_policy.select_action(state)  # 用当前策略
        next_state, reward, done, _ = env.step(action)
        replay_buffer.add(state, action, reward, next_state, done)
        state = next_state
    # PPO update
    ppo_update(rl_policy, replay_buffer)
```

**第 3 段: 范式 2: Offline RL (CQL, IQL)**

"用 BC 数据训 offline RL (CQL / IQL), 不需要在线交互。CQL 加保守正则, 避免对分布外动作的过自信。IQL 用 expectile regression 学 V 函数。优点: 不需要部署, 纯 offline。缺点: 性能受 BC 数据质量限制。"

**第 4 段: 范式 3: BC + RL 交替**

"BC 在 expert demos 上训, RL 在 self-collected data 上训, 交替进行 (类似 DAgger 但用 RL 替代 expert query)。优点: RL 解决 causal confusion, BC 保持稳定。缺点: 训练复杂, 超参数多。"

**第 5 段: 工业实践**

"Tesla Optimus: BC 训基础, PPO 微调抓取 / 拧螺丝。Figure 02: BC + Offline RL (IQL) 混合。1X NEO: BC + 在线 DAgger。Physical Intelligence π₀: BC + 少量 RL + LLM reward (Eureka 风格)。"

**加分项**: 提到 "RL from Human Feedback (RLHF)" 在语言模型上的成功可以借鉴到机器人, "BC from Human Preference" 是新方向。

### Q10: Action Chunking 为什么有效?

**标准答案结构** (4 段):

**第 1 段: 误差累积的视角**

"BC 一步错导致状态偏离, 后续步错。Action Chunking 一次预测 $k$ 步, 推理时**每步都重新规划** (receding horizon), 实际执行只有第一步, 但第一步是基于未来 $k$ 步的**全局考虑**, 不会陷入局部错误。"

**第 2 段: 形式化对比**

"BC (一次一步): 误差累积 $\epsilon_T = T \cdot \epsilon_{\mathrm{step}}$, $T$ 步后总误差 $O(T \epsilon)$。

Action Chunking (receding horizon): $\epsilon_T = k \cdot \epsilon_{\mathrm{chunk}} + (T - k) \cdot \epsilon_{\mathrm{step}}$, 其中 $\epsilon_{\mathrm{chunk}} \ll \epsilon_{\mathrm{step}}$ (因为 chunk 内是 closed-loop)。

实际工程: $k = 10$, $T = 50$, BC 误差 $50 \epsilon$, Action Chunking 误差 $10 \epsilon_{\mathrm{chunk}} + 40 \epsilon_{\mathrm{step}}$。如果 $\epsilon_{\mathrm{chunk}} = 0.1 \epsilon_{\mathrm{step}}$, 总误差 $1 + 40 = 41 \epsilon_{\mathrm{step}}$, 略好于 BC。"

**第 3 段: 专家演示的连贯性**

"专家动作是**连贯**的 (一次伸手到目标位置, 中间没有"跳变")。Action Chunking 一次预测 10 步, 保持连贯性; BC 一次一步, 每步独立预测, 容易"跳变"或"抖振"。

ACT 论文显示: ALOHA 任务, 一次 1 步 BC 65%, 一次 10 步 ACT 85%, 提升 20%。"

**第 4 段: 局限与对策**

"Action Chunking 也有问题:
- Chunk 之间不连续 (执行完 chunk 1 后, chunk 2 可能"跳")
- 解决: **Temporal Ensemble** (多 chunk 的动作平均, ALCHA 用)
- Chunk 大小难选: 大 = 计算贵 + 不灵活, 小 = BC 老问题
- 解决: **Hierarchical Action Chunking** (高层决定 chunk 大小, 低层执行)"

**加分项**: 提到 "HiP-BC" (2024) 用 latent variable 自动决定 chunk 大小。

### Q11: BC 的评估指标 (Evaluation Metrics) 在工业怎么选?

**标准答案结构** (4 段):

**第 1 段: 任务级 vs 动作级**

"BC 评估分两层:
- **动作级**: MSE, MAE, NLL, action accuracy (离最近 bin 的距离)。快, 但跟任务成功**不直接相关** (可能 MSE 0.01 但任务 0% 成功)。
- **任务级**: 任务成功率, 累计 reward, 完成时间。慢, 但直接反映 BC 价值。"

"工业实践: 离线训时用动作级 (快速迭代), 部署前用任务级 (准确评估), 部署后用 A/B 测试 (在线验证)。"

**第 2 段: 任务成功率 (Success Rate)**

"标准: 跑 $N$ 条轨迹 (工业上 $N = 20-50$ 在仿真, $N = 50-200$ 在真机), 计算成功率。

```python
# 标准评估代码
n_trials = 50
successes = 0
for _ in range(n_trials):
    state = env.reset()
    for step in range(max_steps):
        action = policy(state)
        state, reward, done, info = env.step(action)
        if done and info.get('success', False):
            successes += 1
            break
success_rate = successes / n_trials
print(f"Success rate: {success_rate:.1%}")
```

注意: 仿真里 $N = 50$ 够了 (CI ±10%), 真机里 $N = 100$ 以上 (CI ±5%)。"

**第 3 段: 累计回报 (Cumulative Reward)**

"如果环境有稠密 reward, 用累计 reward:

```python
total_reward = 0
for _ in range(n_trials):
    state = env.reset()
    episode_reward = 0
    for step in range(max_steps):
        action = policy(state)
        state, reward, done, _ = env.step(action)
        episode_reward += reward
        if done:
            break
    total_reward += episode_reward
avg_reward = total_reward / n_trials
```

注意: reward 设计影响评估, reward shaping 不当会高估 BC 性能。"

**第 4 段: 鲁棒性指标 (Robustness Metrics)**

"除了成功率, 还要测**鲁棒性**:
- **跨位置泛化**: 在训练时没演示过的位置测
- **跨光照泛化**: 不同光照下测
- **跨物体泛化**: 不同形状 / 颜色 / 材质的物体
- **对抗扰动**: 物理扰动 (推一下, 突然变亮), 测 BC 是否能恢复

```python
# 跨位置泛化
for object_pos in unseen_positions:
    success_rate_at_pos = evaluate_at_position(object_pos)
    print(f"Pos {object_pos}: {success_rate_at_pos:.1%}")
```

"工业标准: 鲁棒性指标 (跨位置 / 光照 / 物体) 比 in-distribution 成功率**更重要**, 因为部署环境永远跟训练不完全一样。"

**加分项**: 提到 "一次成功率" vs "3 次内成功率 (best of 3)", 工业上常用 best-of-3 给用户更好体验。

## 19. 调试与诊断清单 (Debugging & Diagnostic Checklist)

> 这一节是**工程师的 troubleshooting 工具箱**。当你训的 BC 在部署时失败, 按这个清单一步步排查。

### 19.1 协变量偏移检测 Checklist

**症状**: 训练集 99% 准确, 部署 0-30% 成功率。

**诊断步骤**:

- [ ] **Step 1**: 收集部署时的 50-100 条 rollout 状态, 跟训练状态用 **MMD / KS 检验** 比较
  - MMD > 0.5: 严重偏移
  - MMD < 0.1: 偏移小
- [ ] **Step 2**: 训**域判别器**区分训练状态 vs 推理状态
  - AUC > 0.7: 严重偏移
  - AUC < 0.55: 偏移可忽略
- [ ] **Step 3**: t-SNE / UMAP 可视化, 看两分布是否重叠
- [ ] **Step 4**: 物理检查: 摄像头角度 / 光照 / 物体位置跟训练一致吗?

**修复**:
- 偏移大 → 收集部署环境数据 (类似 DAgger)
- 偏移中 → 数据增强 (颜色, 视角, 物体)
- 偏移小 → 微调 BC (在少量部署数据上)

### 19.2 因果混淆检测 Checklist

**症状**: BC 在训练分布内准确, 但"反事实"状态行为错 (e.g., 灯灭 + 障碍在时, BC 不左转)。

**诊断步骤**:

- [ ] **Step 1**: 列**已知 confounder** (灯, 时间, 操作员 ID, ...)
- [ ] **Step 2**: 对每个 confounder 跑 **HSIC 检测** (见 §16.3)
  - HSIC > 阈值: BC 在用这个 confounder
- [ ] **Step 3**: 构造**反事实状态** (e.g., 灯灭 + 障碍在), 测 BC 行为
  - BC 行为改变 → 用了 confounder (坏)
  - BC 行为不变 → 用了真因 (好)
- [ ] **Step 4**: 跑 **Leave-One-Out**: 删掉某个 state 特征, 看 BC 性能
  - 性能不降: BC 没用这个特征 (可能是该用没用, 或该不用没用)
  - 性能降: BC 依赖这个特征 (检查是真因还是 confounder)

**修复**:
- 检测到 confounder → **对抗去混淆** (§15.3) 或 **Causal Mask** (§15.4) 或 **置换增强** (随机化 confounder)
- 关键 confounder 没法观测 → **收集反事实数据** (DAgger 风格) 或 **主动学习**

### 19.3 误差累积检测 Checklist

**症状**: 短程任务 (10 步) BC 80% 成功率, 长程任务 (50+ 步) 0-30% 成功率。

**诊断步骤**:

- [ ] **Step 1**: 看**单步错误率**: 训集 / 测集 single-step error
  - 单步错误 5% → 50 步后 $(1-0.05)^{50} = 8\%$
  - 单步错误 1% → 50 步后 $60\%$
- [ ] **Step 2**: 跑**逐步成功率曲线**: 在 1, 5, 10, 20, 50 步时分别测成功率
  - 曲线指数衰减 → 误差累积
  - 曲线平坦 → 其他问题
- [ ] **Step 3**: 看 **Lyapunov 谱**: 训一个 Lyapunov detector, 看失败概率随时间变化
  - 失败概率指数上升 → 累积
  - 突然上升 → 单点失败 (e.g., 抓空)

**修复**:
- 误差累积 → **Action Chunking** + **Receding Horizon** (见 §16.2)
- 单步错误高 → **更好的模型** (Transformer > MLP for 长程), **更多数据**
- Lyapunov 突变 → **异常检测 + safe mode** (e.g., 抓空时停下来, 重新尝试)

### 19.4 多模态退化检测 Checklist

**症状**: 同一状态, 专家有多种"正确"动作 (e.g., 多种抓法), BC 用 MSE 训后输出"平均"动作, 任务失败。

**诊断步骤**:

- [ ] **Step 1**: 看**演示的 action 分布**: 对同一 state (或近邻), action 的方差
  - 方差大 → 多模态
  - 方差小 → 单模态
- [ ] **Step 2**: 看 BC 输出的**单峰性**: 对同一 state 跑 BC 多次 (如果有 stochasticity), 看输出分布
  - 单峰 → BC 退化了
  - 多峰 → BC 还行
- [ ] **Step 3**: **可视化**: 2D 任务, 画 state → action 散点图, 看 BC 输出是不是在专家 action 的"中间"

**修复**:
- 多模态严重 → **Diffusion Policy** 或 **Flow Matching** (见 §3) 或 **MDN** (Mixture Density Network)
- 轻微多模态 → **CVAE** (ACT 风格) 加 latent 表征"哪种模态"

### 19.5 工业故障排查决策树

```text
BC 部署失败
├─ 训练集 acc < 80%?
│   ├─ 是 → 数据问题 (标注错, 演示质量差)
│   │        → 检查演示, 重训
│   └─ 否 → 部署问题
│       ├─ 短程任务 (10 步) 失败?
│       │   ├─ 是 → 多模态退化 (查 §19.4) 或 单步错误高
│       │   └─ 否 → 长程任务失败?
│       │       ├─ 是 → 误差累积 (查 §19.3)
│       │       └─ 否 → 反事实状态失败?
│       │           ├─ 是 → 因果混淆 (查 §19.2)
│       │           └─ 否 → 协变量偏移 (查 §19.1)
```

### 19.6 关键代码片段 (Snippets)

**1. HSIC 监测** (per training epoch):

```python
# 在训练循环里加
if (epoch + 1) % 10 == 0:
    with torch.no_grad():
        # 训集预测
        train_pred = policy(train_states)
        # 训集 state 特征
        confound_feat = train_states[:, confound_idx:confound_idx+1]
        # HSIC
        hsic_val = hsic_statistic(confound_feat, train_pred).item()
        print(f"Epoch {epoch+1} | HSIC(confounder, action) = {hsic_val:.4f}")
        if hsic_val > 0.05:  # 阈值根据数据调
            print("WARNING: BC may be using confounder!")
```

**2. Lyapunov 监控** (per environment step):

```python
# 部署时
for step in range(max_steps):
    state_t = torch.from_numpy(state).float().unsqueeze(0)
    with torch.no_grad():
        action = policy(state_t)
        fail_prob = lyapunov_detector(state_t).item()
    if fail_prob > 0.5:
        print("WARNING: High failure probability, switching to safe mode")
        # 触发 safe mode: 停下, query 远程专家, 或切到 rule-based backup
        break
    state, _, done, _ = env.step(action.numpy())
```

**3. Action Chunking 推理** (per environment step):

```python
# Receding horizon
chunk_buffer = []
for step in range(max_steps):
    if not chunk_buffer:
        with torch.no_grad():
            state_t = torch.from_numpy(state).float().unsqueeze(0)
            chunk = policy(state_t)  # [1, chunk_size, action_dim]
        chunk_buffer = chunk[0].numpy()

    action = chunk_buffer[0]
    chunk_buffer = chunk_buffer[1:]  # 弹出第一步

    state, _, done, _ = env.step(action)
    if done:
        break
```

## 21. 章节总结 (Final Summary)

**本章核心要点回顾**:

1. **BC 的数学本质**: 监督学习套到机器人上, $\theta^* = \arg\min \mathbb{E}[\mathcal{L}(\pi_\theta(s), a)]$, 等价于 MLE。

2. **失败三件套**:
   - **协变量偏移** (§3.1, §13): $P_{\mathrm{train}}(s) = d^{\pi^*}(s) \neq d^{\pi_\theta}(s) = P_{\mathrm{test}}(s)$
   - **误差累积** (§3.3, §14): $\epsilon_T \le T \cdot \epsilon_{\mathrm{step}}$, 指数级失败
   - **因果混淆** (§3, §12, §15): BC 学关联不学因果, 训练分布外失败

3. **形式化下界** (Ross 2011): BC 的累计误差下界是 $O(T^{1/3})$, **不可能**通过"更多数据"消除。

4. **因果视角** (§12): Pearl DAG / do-calculus / 后门准则严格刻画因果混淆, BC 跳过 abduction 直接 prediction, 缺反事实能力。

5. **严格理论** (§13): Ben-David 域适应界 $\epsilon_T \le \epsilon_S + d_{\mathcal{H}\Delta\mathcal{H}} + \lambda$, 域差异 $d_{\mathcal{H}\Delta\mathcal{H}}$ 量化协变量偏移。

6. **几何视角** (§14): BC 在不稳定动力系统里跑, 误差按 $\rho^T$ 指数增长, Lyapunov detector 监控失败概率。

7. **检测与缓解** (§15): HSIC 检测, IB 压缩, 对抗去混淆, causal attention mask, IRM 跨环境不变。

8. **PyTorch 实现** (§16): Causal attention transformer BC, ACT, HSIC detector, DAgger-lite 完整代码。

9. **工业案例** (§6, §17): Tesla / Figure / 1X / ALOHA / π₀ / RT-2 / GR00T, 100-1000 演示/任务 + 大规模多任务 + 特定微调。

10. **诊断清单** (§19): 协变量偏移 / 因果混淆 / 误差累积 / 多模态的检测与修复决策树。

**面试三句话终极总结**:

> 1. BC = 监督学习套到机器人上, 数学上等价于 MLE, 简单但有"训练-推理分布不同"的根本问题。
> 2. 协变量偏移 ($d^{\pi^*} \neq d^{\pi_\theta}$) + 误差累积 ($O(T \epsilon)$) + 因果混淆 (学关联不学因果) + 多模态退化 (MSE 平均化) = BC 失败四件套。
> 3. 工业方案: 大规模数据 (100K+ 演示) + Action Chunking + Diffusion Policy / Flow Matching + DAgger 风格在线 query + 跨形态数据, 部分缓解但完全消除需要新范式 (主动学习, 反事实推理, 因果表征学习)。
