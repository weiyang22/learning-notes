## 1. 直觉引入:为什么必须把 BC 和 RL 加起来

### 1.1 纯 RL 在机器人上的三个坑

回忆 [[第06章-02-PPO在机器人-从仿真到真实]] § 1.2, 仿真训练可以做到 95% 成功率。但**完全从零 on-policy 训一个机器人策略**, 有 3 个**几乎无法同时解决**的问题:

**坑 1: 稀疏奖励下的探索灾难**

抓杯子任务, 99.9% 的状态 reward=0, 只有"抓到"那一帧 reward=1。PPO 在 100 万步里只有 100 帧是"成功"的, **根本学不动梯度方向**。

```text
稀疏奖励的"奖励地形":

       reward
        ↑
        │    ╱╲
    1.0 │   ╱  ╲        ← 成功状态 (稀疏)
        │  ╱    ╲
        │ ╱      ╲
    0.0 │╱________╲_____→ state
        ↑
    100 万步里碰到 100 次

    PPO 梯度 ∝ # (成功样本), 几乎为 0
```

**坑 2: 真机不能随便探索**

仿真环境撞墙没事, 真机一次事故 5-10 万, PPO 训出来的策略在前 1 万步是**完全随机的**, 在真机上跑 = **硬件自杀**。

```text
PPO 训练早期 (0-1000 步) 的动作分布:

    真机 PPO step 0:    π ≈ Uniform(-1, 1)     ← 随机抖动, 力矩过大
    真机 PPO step 100:  π ≈ N(0, 0.5)          ← 还在抖, 撞墙 5 次
    真机 PPO step 1000: π ≈ N(π_BC, 0.2)       ← 有方向了, 但不稳

    时间成本: 单 episode 60 秒, 撞墙 reset 30 秒,
    1 万步 ≈ 5 小时, 期间烧坏驱动器 1-2 个
```

**坑 3: 仿真到真实的 gap**

仿真和真机的物理参数 (摩擦、阻尼、接触) 差 5-15%。**仿真训满分, 真机 0 分**。Sim2Real 域随机化能 cover 60-80% 的 gap, 但剩下 20% 必须**真机数据再训**。

### 1.2 BC 的天花板:90% 仿真, 60% 真机

上面三个坑推着我们去用 BC:有人示教, 没有奖励灾难, 没有真机烧毁。但 BC 的天花板在 [[../第05章-模仿学习/第05章-01-行为克隆-BC的因果混淆问题]] § 2.3 已经讲清楚:

| 真机表现 | 纯 PPO | 纯 BC | BC + 残差 RL (本章) |
| :--- | :--- | :--- | :--- |
| 抓杯子 (Franka Panda) | 30% | 60% | **88%** |
| 叠衣服 (dexterous hand) | 0% (训不动) | 35% | **62%** |
| 装轮 (汽车装配) | 15% | 55% | **82%** |
| 开门 (四足 + arm) | 25% | 50% | **80%** |

数值的具体含义不重要, 关键是**BC + 残差 RL 比纯 RL 和纯 BC 都高一档**。

### 1.3 残差 RL 的核心思想:BC 给先验, RL 学残差

把 BC 的"示教动作"和 RL 的"环境反馈"组合起来, 最自然的写法是:

$$
\pi_{\text{final}}(s) = \pi_{\text{IL}}(s) + \alpha \cdot \pi_{\text{residual}}(s; \theta)
$$

其中:
- $\pi_{\text{IL}}(s)$ 是冻结的 BC 策略 (从 [[../第05章-模仿学习/第05章-01-行为克隆-BC的因果混淆问题]] § 4 来的预训练模型)
- $\pi_{\text{residual}}(s; \theta)$ 是 RL 训练的"残差网络", 输出**小修正**
- $\alpha$ 是残差幅度, 控制"动作偏移 IL 多远"

**直觉上**: 大部分时间 BC 已经做对了, RL 只需要学**IL 漏掉的边界情况** (比如杯子被推到桌边、夹爪打滑、对接误差)。

```text
BC 和 RL 的分工:

    ┌─────────────────────────────────────────────┐
    │  任务: 抓杯子                                 │
    │                                               │
    │  90% 时间  →  BC 干得对, 残差 ≈ 0              │
    │  10% 时间  →  BC 干错, 残差来"扳"               │
    │                                               │
    │  RL 学习信号:                                 │
    │    - BC 做对了 (R=1): 残差被罚小                │
    │    - BC 做错了 (R=0): 残差被训大                │
    │                                               │
    │  最终策略:                                     │
    │    π_final(s) = π_BC(s) + α·π_residual(s)      │
    │    α 调度: 0.3 → 0.1, 后期让残差小              │
    └─────────────────────────────────────────────┘
```

**为什么这个思路 work?** 三个原因:

1. **BC 提供 warm start**: $\pi_{\text{residual}}$ 从零开始, 初始输出 ≈ 0, 起步就是 BC 策略, 不会"破坏"先验
2. **残差搜索空间小**: $\pi_{\text{residual}}$ 只学"对 IL 的小修正", 维度比端到端 RL 小很多, 样本效率高 5-10 倍
3. **天然安全**: 残差幅度受 $\alpha$ 控制, 动作不会偏离 BC 太远, 真机部署时也有"安全网"

### 1.4 工业上的真实做法:四家公司的招数

残差 RL 不是"实验室玩具", 2023-2025 年, **几乎所有头部机器人公司都在用**。举 4 个例子:

**NVIDIA Isaac Lab + GR00T (2024)**: 在 Isaac 仿真器里训 GR00T 基础模型, 然后**残差 RL 微调每个具体任务** (抓、推、装)。GR00T 发布的 demo 里, 抓杯子 90%+ 成功率靠残差 RL。

**Open X-Embodiment (Google + 21 家机器人公司, 2023)**: RT-2 / Octo 等基础模型 + 残差 RL 微调。论文 *Open X-Embodiment: Robotic Learning Datasets and Models* 明确写: **"残差 RL 是 BC 和 RL 的工业标准混合"**。

**ETH ANYmal 四足 (2024)**: BC 训一个基础步态, 残差 RL 在仿真里学"抗扰动"和"复杂地形适应"。论文 *Learning Robust Perceptive Locomotion* 公开了残差 PPO 实现。

**Figure 02 + 宇树 H1 (2024-2025)**: 工厂场景里, BC 训基础抓取, 残差 RL 在真机数据上学"对抗动态变化" (传送带速度变化、零件定位误差)。

## 2. 残差动作空间

### 2.1 核心公式: $\pi_{\text{RL}}(s) = \pi_{\text{IL}}(s) + \alpha \cdot \pi_{\text{residual}}(s)$

把"BC 先验"和"RL 残差"组合起来的最常见方式:

$$
\pi_{\text{RL}}(a | s) = \pi_{\text{IL}}(a | s) + \alpha \cdot \pi_{\text{residual}}(a | s; \theta)
$$

其中:
- $\pi_{\text{IL}}(s) \in \mathbb{R}^d$ 来自冻结的 BC 策略, 输出 mean
- $\pi_{\text{residual}}(s; \theta) \in \mathbb{R}^d$ 来自 RL 训练的策略, 输出 mean (也可输出 std, 见 2.3 节)
- $\alpha \in [0, 1]$ 是残差幅度, 控制 RL 学到的"修正"施加多少

**这个公式为什么这么写?** 三个原因:

1. **加法天然支持零初始化**: $\theta$ 初始化为 0 时, $\pi_{\text{residual}}(s) = 0$, $\pi_{\text{RL}}(s) = \pi_{\text{IL}}(s)$, 起步就是 BC 策略
2. **动作空间是连续的**: 末端执行器 / 关节空间都是 $\mathbb{R}^d$, 加法直接适用
3. **可微**: 梯度可以从 reward 反传到 $\theta$, 标准 PPO / SAC 直接套上去

**离散动作怎么办?** 分类任务 (BBQ 决策、抓/不抓) 需要分类组合, 通常用 logit 加法:

$$
\text{logit}_{\text{RL}}(a|s) = \text{logit}_{\text{IL}}(a|s) + \alpha \cdot \text{logit}_{\text{residual}}(a|s)
$$

后面 § 3.4 会专门讲离散动作的处理。

### 2.2 残差的初始化:零残差起步

**关键: $\theta$ 的初始化必须让 $\pi_{\text{residual}}(s; \theta_0) \approx 0$。**

标准 PyTorch 初始化 (线性层 uniform / kaiming / xavier) 输出的均值在 0 附近但**有非零方差**。残差网络在初始化时输出数量级约为 0.01-0.1, 已经能让机器人"小抖一下"。

工业上常见的两种初始化:

**方法 1:零输出层**

```python
class ResidualPolicy(nn.Module):
    def __init__(self, state_dim, action_dim):
        super().__init__()
        self.backbone = nn.Sequential(
            nn.Linear(state_dim, 256), nn.ReLU(),
            nn.Linear(256, 256), nn.ReLU(),
        )
        self.head = nn.Linear(256, action_dim)
        # 零初始化最后一层
        nn.init.zeros_(self.head.weight)
        nn.init.zeros_(self.head.bias)

    def forward(self, s):
        return self.head(self.backbone(s))  # 起步就是 0
```

**方法 2:小方差初始化**

```python
nn.init.normal_(self.head.weight, std=1e-3)  # 极小方差
```

两种都 work。方法 1 更"绝对保险", 方法 2 在复杂地形上偶尔能提前 1-2 个 episode 收敛。

### 2.3 残差的物理意义: BC 的"局部补丁"

残差不是"新动作", 是"对 BC 的局部修正"。理解这点很关键:

```text
BC 和残差 RL 的几何解释:

    状态空间 S (高维)
    ┌──────────────────────────────────────────┐
    │                                            │
    │     ★ s_0 (当前状态)                        │
    │      │                                      │
    │      │ BC 动作方向: a_BC = π_BC(s_0)         │
    │      ↓                                      │
    │      ─────────→ a_BC (均值)                 │
    │                    ╲                         │
    │                     ╲ α·a_res (残差方向)      │
    │                      ↘                       │
    │                       ───────→ a_RL (最终动作)│
    │                                            │
    │  几何意义: a_RL 是 a_BC + α·a_res            │
    │  a_res 是 "对 a_BC 的局部修正"               │
    │                                            │
    └──────────────────────────────────────────┘
```

**为什么残差可以是"任意方向"?** 因为残差网络本身没有约束, 可以输出任意方向的向量。**关键约束来自 $\alpha$**: $\alpha$ 小 → 残差是微调; $\alpha$ 大 → 残差可能"覆盖" BC (破坏先验)。

**和"动作扰动"(action perturbation)的区别**:

| 维度 | 动作扰动 | 残差 RL |
| :--- | :--- | :--- |
| 输出维度 | 单一动作 $a = \pi_\theta(s) + \epsilon$, $\epsilon \sim \mathcal{N}(0, \sigma)$ | 残差 $\Delta a = \pi_{\text{residual}}(s; \theta)$ |
| 网络输出 | 完整动作 | 仅"修正量" |
| 探索机制 | 随机噪声 (off-policy) | 网络输出 (on/off-policy 都行) |
| 训练信号 | reward 反馈 | reward 反馈 |
| BC 兼容性 | 差 (网络可能被训成完全不同分布) | 好 (起步等价 BC) |

残差 RL 本质上把"探索"和"修正"分开了: $\pi_{\text{residual}}$ 学"在哪些状态下需要修正", 配合 SAC 的熵正则来"探索修正的多样性"。

### 2.4 残差幅度 $\alpha$ 的调节:固定、调度、状态相关

$\alpha$ 是残差 RL 的"超参之王", 工业上有 3 种用法:

**用法 1: 固定 $\alpha$** (简单但次优)

```python
ALPHA = 0.1   # 残差幅度固定
a_RL = a_BC + ALPHA * a_residual
```

适用于: 残差本身就很小的场景 (比如轨迹跟踪微调)。

**用法 2: 线性 / 余弦调度** (推荐)

```python
def alpha_schedule(step, total_steps, alpha_start=0.3, alpha_end=0.05):
    """线性调度: 训练初期大残差, 后期小残差"""
    progress = min(step / total_steps, 1.0)
    return alpha_start + (alpha_end - alpha_start) * progress

def alpha_cosine(step, total_steps, alpha_start=0.3, alpha_end=0.05):
    """余弦调度: 衰减更平滑"""
    progress = min(step / total_steps, 1.0)
    return alpha_end + 0.5 * (alpha_start - alpha_end) * (1 + math.cos(math.pi * progress))
```

**为什么调度比固定好?** 三个理由:
1. 训练初期 BC 还没"完全调好", 需要大残差修正; 后期 BC 已经适配, 小残差收敛
2. 调度让残差"自然变小", 避免训练后期残差反向破坏 BC
3. 数学上等价于"残差空间的 learning rate decay", 收敛性更好

```text
α 调度曲线 (训练 step 在横轴):

    α
    ↑
0.3 │  ●
    │   ╲
0.2 │    ╲
    │     ╲
0.1 │      ╲___
    │          ╲____
0.05│                ●───────
    │___________________________→ step
    0    50%   100%   150%  200%

    训练 step: 0 → 200K
    α 衰减: 0.3 → 0.05
```

**用法 3: 状态相关 $\alpha(s)$** (高级)

让 $\alpha$ 本身也是网络输出, 学会"在不确定的地方用大残差, 在 BC 擅长的状态用小残差":

```python
class AdaptiveResidualPolicy(nn.Module):
    def __init__(self, state_dim, action_dim):
        super().__init__()
        self.backbone = nn.Sequential(...)
        self.action_head = nn.Linear(256, action_dim)
        self.alpha_head = nn.Linear(256, action_dim)  # 输出 α

    def forward(self, s):
        feat = self.backbone(s)
        a_res = self.action_head(feat)
        alpha = torch.sigmoid(self.alpha_head(feat))  # α ∈ [0, 1]
        return a_res, alpha
```

但这种"自适应 $\alpha$"训练不稳, 工业上只在 Sim2Real 的最难任务里用 (比如 Figure 02 灵巧手微调)。

### 2.5 残差空间的对称性: 不变性 vs 等变性

机器人动作有"对称群" (旋转、平移、尺度), 残差网络要保留这些不变性。

**末端位置残差 (end-effector position residual)**: 直接对笛卡尔坐标加残差, $\Delta x = \pi_{\text{residual}}(s)$, 不变性最好, 工业首选。

**关节角残差 (joint-space residual)**: 对关节角加残差, $\Delta q = \pi_{\text{residual}}(s)$, 简单但对机器人构型敏感, 调试难。

**速度残差 (velocity residual)**: 加到关节速度上, $\dot{q} + \Delta \dot{q}$, 适合周期性任务 (走路、旋转)。

**力矩残差 (torque residual)**: 加到关节力矩上, 最精细, 但容易激发未建模动力学, 真机部署容易抖。

```text
残差空间的"金字塔":

            ┌─────────────┐
            │  力矩残差     │  ← 最精细, 调试难
            │  Δτ          │
            ├─────────────┤
            │  速度残差     │  ← 周期任务
            │  Δq̇         │
            ├─────────────┤
            │  关节角残差   │  ← 最常用
            │  Δq          │
            ├─────────────┤
            │ 末端位姿残差  │  ← Sim2Real 友好
            │  Δx          │
            └─────────────┘
```

经验: **优先用末端位姿残差**, 调试简单、Sim2Real 友好。关节角残差只在末端控制不稳时才考虑。

### 2.6 残差网络的输出分布: mean-only vs mean+std

SAC 的策略输出 mean + log_std (高斯分布), 残差网络要不要也输出 std?

**mean-only (推荐)**: $\pi_{\text{residual}}(s)$ 只输出 mean, std 来自 BC 策略的 std。

```python
a_residual_mean = residual_net(s)            # RL 学 mean
std = bc_policy.get_std(s)                   # BC 的 std
dist = Normal(a_BC + α * a_residual_mean, std)
```

**mean+std**: 让 RL 同时学 mean 和 std。

```python
a_residual_mean, log_std = residual_net(s)   # RL 学 mean+std
std = exp(log_std) + bc_std                  # 残差 std 加到 BC std 上
```

mean+std 更灵活但难训练 (残差 std 容易爆炸或崩塌); mean-only 训得稳但探索受 BC 限制。**90% 的工业场景用 mean-only**。

## 3. 算法实现: PPO、SAC、离线、安全

### 3.1 PPO + 残差动作

残差 PPO 是最直接的实现: 把 § 2.1 的公式套到 PPO 的策略网络上, 其他什么都不变。

```python
class ResidualPPO:
    """残差 PPO: BC 策略冻结, RL 学残差"""
    def __init__(self, bc_policy, state_dim, action_dim, alpha=0.1):
        self.bc_policy = bc_policy.eval()           # 冻结
        for p in self.bc_policy.parameters():
            p.requires_grad = False

        self.residual_net = ResidualPolicy(state_dim, action_dim)  # 零初始化
        self.alpha = alpha

        self.value_net = ValueNet(state_dim)
        self.optimizer = torch.optim.Adam(
            list(self.residual_net.parameters()) + list(self.value_net.parameters()),
            lr=3e-4
        )

    def get_action(self, state, deterministic=False):
        with torch.no_grad():
            a_bc = self.bc_policy(state)              # BC 动作
        a_res = self.residual_net(state)              # 残差
        a_rl = a_bc + self.alpha * a_res             # 残差动作
        if deterministic:
            return a_rl
        # 加一点探索噪声 (训练时)
        a_rl = a_rl + 0.05 * torch.randn_like(a_rl)
        return a_rl

    def compute_loss(self, states, actions_old, advantages, returns):
        """PPO clip 目标 + value loss"""
        a_bc = self.bc_policy(states).detach()
        a_res = self.residual_net(states)
        a_rl_mean = a_bc + self.alpha * a_res

        # 残差策略的 log prob (假设固定 std)
        dist = Normal(a_rl_mean, torch.ones_like(a_rl_mean) * 0.1)
        log_prob = dist.log_prob(actions_old).sum(-1)

        # PPO ratio
        with torch.no_grad():
            dist_old = Normal(a_bc + self.alpha * self.residual_net(states).detach(),
                             torch.ones_like(a_rl_mean) * 0.1)
            log_prob_old = dist_old.log_prob(actions_old).sum(-1)
        ratio = torch.exp(log_prob - log_prob_old)

        # PPO clip
        surr1 = ratio * advantages
        surr2 = torch.clamp(ratio, 0.8, 1.2) * advantages
        policy_loss = -torch.min(surr1, surr2).mean()

        # Value loss
        v_pred = self.value_net(states)
        value_loss = F.mse_loss(v_pred, returns)

        # 总 loss
        loss = policy_loss + 0.5 * value_loss - 0.01 * dist.entropy().mean()
        return loss
```

**关键工程细节**:
- BC 策略 `requires_grad=False`, 冻结
- `actions_old` 是采样时的动作 (残差动作 = $a_{BC} + \alpha \cdot a_{res}$)
- PPO 的 ratio 是"新旧残差网络"的 ratio, 不是"新旧完整动作"的 ratio
- value net 学习残差动作下的 value, 同样需要"看 BC 输出"

### 3.2 SAC + 残差动作

SAC 训残差比 PPO 更"自然", 因为 SAC 是 off-policy + 最大熵, 残差的探索更平滑。

```python
class ResidualSAC:
    """残差 SAC: BC 策略冻结, RL 学残差, off-policy"""
    def __init__(self, bc_policy, state_dim, action_dim, alpha=0.1):
        self.bc_policy = bc_policy.eval()
        for p in self.bc_policy.parameters():
            p.requires_grad = False

        self.residual_net = ResidualPolicy(state_dim, action_dim)
        self.residual_log_std = nn.Parameter(torch.zeros(action_dim))

        self.q1_net = QNet(state_dim, action_dim)
        self.q2_net = QNet(state_dim, action_dim)
        self.target_q1 = QNet(state_dim, action_dim)
        self.target_q2 = QNet(state_dim, action_dim)
        self.target_q1.load_state_dict(self.q1_net.state_dict())
        self.target_q2.load_state_dict(self.q2_net.state_dict())

        self.alpha_ent = 0.2  # 熵温度 (固定 or 自动)
        self.alpha = alpha    # 残差幅度
        self.gamma = 0.99
        self.tau = 0.005

    def get_action(self, state, deterministic=False):
        a_bc = self.bc_policy(state).detach()
        a_res_mean = self.residual_net(state)
        a_res_std = torch.exp(self.residual_log_std)
        a_res = a_res_mean if deterministic else a_res_mean + a_res_std * torch.randn_like(a_res_mean)
        a_rl = a_bc + self.alpha * a_res
        return torch.clamp(a_rl, -1, 1)

    def soft_update(self):
        for tp, p in zip(self.target_q1.parameters(), self.q1_net.parameters()):
            tp.data.mul_(1 - self.tau).add_(p.data, alpha=self.tau)
        # ... 同 q2

    def compute_loss(self, replay_batch):
        s, a_old, r, s_next, done = replay_batch
        # 注意: a_old = a_BC + α·a_res, replay 里要保留
        a_bc = self.bc_policy(s).detach()
        a_bc_next = self.bc_policy(s_next).detach()

        # Target Q (Bellman backup)
        with torch.no_grad():
            a_res_next_mean = self.residual_net(s_next)
            a_res_next_dist = Normal(a_res_next_mean, torch.exp(self.residual_log_std))
            a_res_next = a_res_next_dist.rsample()                    # 重参数化
            log_prob_next = a_res_next_dist.log_prob(a_res_next).sum(-1)
            a_next = a_bc_next + self.alpha * a_res_next
            a_next = torch.clamp(a_next, -1, 1)

            q1_next = self.target_q1(s_next, a_next)
            q2_next = self.target_q2(s_next, a_next)
            q_next = torch.min(q1_next, q2_next) - self.alpha_ent * log_prob_next
            target_q = r + self.gamma * (1 - done) * q_next

        # Q loss
        q1_pred = self.q1_net(s, a_old)
        q2_pred = self.q2_net(s, a_old)
        q_loss = F.mse_loss(q1_pred, target_q) + F.mse_loss(q2_pred, target_q)

        # 残差 policy loss (最大化 Q - α_ent·log_prob)
        a_res_mean = self.residual_net(s)
        a_res_dist = Normal(a_res_mean, torch.exp(self.residual_log_std))
        a_res = a_res_dist.rsample()
        log_prob = a_res_dist.log_prob(a_res).sum(-1)
        a_rl = a_bc + self.alpha * a_res
        a_rl = torch.clamp(a_rl, -1, 1)

        q1 = self.q1_net(s, a_rl)
        q2 = self.q2_net(s, a_rl)
        q_min = torch.min(q1, q2)
        policy_loss = (self.alpha_ent * log_prob - q_min).mean()

        # log_std 调节 (可固定)
        std_loss = -policy_loss  # 见 [[第06章-03-SAC与离线RL-稳定训练]]

        return q_loss, policy_loss, std_loss
```

**SAC + 残差的关键优势**:
- off-policy + 经验回放, **复用 BC 演示数据**: replay buffer 里塞 BC 演示数据, RL 自然受 BC 约束
- 最大熵, **残差不会塌缩**: 即使 BC 输出差, 残差会探索"补丁"
- Twin Q, **减少过估计**: 残差小, Q 估计误差小

**什么时候 PPO+残差 vs SAC+残差?**
| 场景 | PPO + 残差 | SAC + 残差 |
| :--- | :--- | :--- |
| 仿真充足, 想快速试 | ✓ (实现简单) | |
| 真机数据贵, 想复用 | | ✓ (off-policy) |
| 想严格控制 KL 约束 | ✓ (PPO clip) | |
| 想鼓励探索 | | ✓ (最大熵) |
| 离散动作 | ✓ | |
| 连续动作 + 大残差空间 | | ✓ |

### 3.3 离线残差 RL: BC + 离线数据集

**问题**: 真机不能随便探索, 但我们有 BC 演示 + 真机部署日志 (老策略数据), 怎么用?

**解法**: 离线 RL (Offline RL), 用 [[第06章-03-SAC与离线RL-稳定训练]] § 5 讲的 CQL / IQL / TD3+BC。

残差 + 离线 RL 的 trick: **把 BC 演示也塞进 replay buffer**, RL 同时看到"成功轨迹"(来自 BC) 和"实际部署日志"(可能成功可能失败)。

```python
class OfflineResidualCQL:
    """CQL + 残差: 离线数据集 (BC 演示 + 真机日志) 训残差"""
    def __init__(self, bc_policy, state_dim, action_dim, dataset):
        self.bc_policy = bc_policy.eval()
        for p in self.bc_policy.parameters():
            p.requires_grad = False

        self.residual_net = ResidualPolicy(state_dim, action_dim)
        self.q1_net = QNet(state_dim, action_dim)
        self.q2_net = QNet(state_dim, action_dim)
        # ... Twin Q + 目标网络

        self.dataset = dataset  # (s, a, r, s', done) 离线数据
        self.cql_alpha = 5.0    # CQL 保守系数

    def cql_loss(self, s):
        """CQL 核心: 让 Q 在 OOD 动作上小"""
        # OOD 动作: 在数据集分布外采样的动作
        a_random = torch.rand(s.size(0), self.action_dim) * 2 - 1
        a_bc = self.bc_policy(s).detach()
        a_res = self.residual_net(s)
        a_rl = a_bc + self.alpha * a_res  # 当前策略动作

        q1_rand = self.q1_net(s, a_random)
        q2_rand = self.q2_net(s, a_random)
        q1_curr = self.q1_net(s, a_rl)
        q2_curr = self.q2_net(s, a_rl)

        # CQL 保守项: log-sum-exp over OOD actions - Q(data action)
        cql1 = torch.logsumexp(q1_rand, dim=0).mean() - q1_curr.mean()
        cql2 = torch.logsumexp(q2_rand, dim=0).mean() - q2_curr.mean()
        return self.cql_alpha * (cql1 + cql2)

    def train_step(self):
        batch = self.dataset.sample(256)
        s, a_data, r, s_next, done = batch

        # 标准 Bellman loss
        a_bc = self.bc_policy(s).detach()
        a_res_next = self.residual_net(s_next)
        a_next = a_bc + self.alpha * a_res_next
        # ... 同 SAC 的 Q loss

        # 加 CQL 保守项
        cql = self.cql_loss(s)
        total_q_loss = q_loss + cql

        return total_q_loss
```

**关键点**:
- 离线数据里**必须包含 BC 演示** (高质量成功轨迹)
- 离线数据**不能纯老策略**, 要有新策略的部署数据 (哪怕是失败轨迹, 让 RL 知道"什么是错的")
- CQL / IQL 的保守正则防"残差跑偏"

### 3.4 安全残差 RL: 硬约束加在残差空间

把 [[第06章-06-安全RL-避免物理损坏]] 的安全层套到残差上, 比端到端安全 RL 简单得多:

```python
class SafetyLayer:
    """安全层: 把残差动作投影到安全集合"""
    def __init__(self, constraint_fn, max_residual_norm=0.2):
        """
        constraint_fn: (s, a) -> bool, 安全约束
        max_residual_norm: 残差最大范数, 防大幅偏离 BC
        """
        self.constraint_fn = constraint_fn
        self.max_residual_norm = max_residual_norm

    def project(self, s, a_bc, a_res):
        """投影: 裁剪残差 + 安全约束"""
        # 1. 范数裁剪
        a_res_norm = a_res.norm(dim=-1, keepdim=True).clamp(min=1e-6)
        scale = torch.minimum(
            torch.ones_like(a_res_norm),
            self.max_residual_norm / a_res_norm
        )
        a_res_safe = a_res * scale

        # 2. 安全约束 (例如关节速度 < limit)
        a_rl = a_bc + self.alpha * a_res_safe
        for _ in range(10):  # 简单投影迭代
            if self.constraint_fn(s, a_rl).all():
                break
            a_res_safe *= 0.9  # 缩小
            a_rl = a_bc + self.alpha * a_res_safe

        return a_rl
```

**安全残差的工程价值**:
- $\alpha$ 已经是"软安全" (动作不偏离 BC 太远)
- max_residual_norm 是"硬安全" (物理关节限位)
- constraint_fn 是"任务级安全" (不撞桌、不伤人)
- **三层安全**: BC 先验 → 范数裁剪 → 任务约束, 真机部署几乎不可能崩

### 3.5 算法对比矩阵

| 算法 | 适用场景 | 数据需求 | 实现难度 | 真机部署难度 |
| :--- | :--- | :--- | :--- | :--- |
| 残差 PPO | 仿真充足, 短 episode | 1-5 万 step | 低 | 中 (on-policy 需环境交互) |
| 残差 SAC | 仿真+真机混合, 复用数据 | 1 万 + 复用 | 中 | 低 (off-policy 复用) |
| 离线残差 CQL | 纯离线 (BC + 老日志) | 5-10 万 | 中高 | 低 (无新交互) |
| 离线残差 IQL | 纯离线, 无需 query 策略 | 5-10 万 | 中 | 低 |
| 安全残差 RL | 物理安全敏感 (协作机器人) | 1 万 + 安全 demo | 高 | 中 (需安全层) |
| 残差 DAgger | 在线 IL, 专家可查询 | 在线专家 | 低 | 高 (需持续专家) |

**选型建议**: 默认 **残差 SAC** (off-policy 复用 + 最大熵); 真机完全不能交互时用 **残差 IQL**; 仿真充足想快速迭代用 **残差 PPO**; 安全关键场景加 **安全层**。

## 4. 实际训练策略

### 4.1 何时启动 RL?

不是 BC 训完就立刻启动 RL。**残差 RL 的启动时机是工程经验的关键**:

**启动过早**: BC 还没收敛, RL 在"烂 BC"上做残差, 学到错误的修正。
**启动过晚**: BC 已经"过拟合"到训练数据, RL 学不动 (梯度信号弱)。

```text
训练时间线 (示意):

    BC 训练                    残差 RL
    ┌─────────────┐           ┌──────────────────────┐
    │             │           │                       │
    │  0 ──────→ 收敛阈值     │  残差启动 ──────→  结束│
    │             │  ← 此处启动                        │
    │             │           │                       │
    └─────────────┘           └──────────────────────┘

    决策: 看 BC 在验证集上的成功率
        < 50% : BC 还在训, 别启动 RL
        50-70%: BC 凑合, RL 可以小 α 启动 (α=0.05)
        70-85%: BC 不错, α=0.1-0.2 启动
        > 85%: BC 已经很稳, α=0.3 启动, 让 RL 大改
```

**经验法则**: BC 仿真成功率 ≥ 70% 时启动残差 RL, 初始 $\alpha = 0.1$。

### 4.2 残差权重的衰减: 余弦调度

§ 2.4 给了调度公式, 这里讲**为什么余弦比线性好**:

```text
线性 vs 余弦 α 调度:

    α
    ↑
0.3 │  ●─────●
    │   ╲
0.2 │    ╲
    │     ╲
0.1 │      ╲_
    │        ╲___
0.05│            ●─────●─────●
    │_______________________________→ step

    线性 (虚线): 匀速下降
    余弦 (实线): 前期缓, 中期快, 后期缓

    工程经验: 余弦调度让残差 RL 的训练曲线更平滑,
    最终策略方差更小, 真机迁移更稳
```

**余弦调度的 PyTorch 实现**:

```python
import math

def cosine_alpha(step, total_steps, alpha_start=0.3, alpha_end=0.05):
    progress = min(step / total_steps, 1.0)
    return alpha_end + 0.5 * (alpha_start - alpha_end) * (1 + math.cos(math.pi * progress))

# 训练循环里
for step in range(total_steps):
    alpha = cosine_alpha(step, total_steps)
    a_rl = a_bc + alpha * a_residual
    # ... 训练
```

**调度的"重启"技巧**: 训练中如果发现残差已经收敛, 可以"重启"调度 (突然把 $\alpha$ 调回大值, 让 RL 重新探索)。工业上偶尔用, 但 90% 场景一次调度足够。

### 4.3 残差网络的容量选择

残差网络多大合适?

**经验**: 残差网络参数量约为 BC 网络的 1/4 到 1/2。

```text
BC 网络 (参数量 N_BC):
    state_dim → 1024 → 1024 → action_dim   (约 1M 参数)

残差网络 (参数量 N_res):
    state_dim → 256 → 256 → action_dim      (约 130K 参数)

比例: N_res / N_BC ≈ 1/8 到 1/2

理由:
    残差只学"小修正", 不需要和 BC 同样的容量
    容量太大 → 残差可能"覆盖" BC (破坏先验)
    容量太小 → 残差学不到有用的修正
```

**网络宽度 vs 深度**: 残差网络通常**宽而浅** (256-256, 不超过 4 层)。深度大的残差网络在初始化时输出更不稳定, 训练后期残差容易"突变"。

### 4.4 真实机器人的渐进式部署

真机部署残差 RL 最容易翻车的环节。**三阶段递进**:

```text
真机部署渐进流程:

阶段 1: 纯仿真 (1-3 天)
    ├─ 训练: 仿真 + 残差 RL (BC 演示 + 仿真探索)
    ├─ 验证: 仿真成功率 ≥ 90%, 残差幅度 ≤ 0.2
    └─ 通过条件: 仿真 1000 episode 连续 95%+ 成功

阶段 2: 仿真 + 真机混合 (1-2 周)
    ├─ 数据: 仿真 80% + 真机 20% (真机 = 老策略部署日志)
    ├─ 训练: 离线残差 RL (CQL 或 IQL) on 混合数据
    ├─ 真机测试: BC 策略 + 残差 (α=0.05, 小残差), 监控安全
    └─ 通过条件: 真机成功率 ≥ 75%, 残差幅度 ≤ 0.1

阶段 3: 纯真机微调 (持续)
    ├─ 数据: 真机部署日志 + 必要时的失败重训
    ├─ 训练: 离线 RL 周期性 retrain (每周/每天)
    ├─ 残差幅度: α ≤ 0.05, 严格 KL 约束
    └─ 通过条件: 真机成功率 ≥ 85%, 7×24 稳定运行
```

**关键工程细节**:
- 阶段 1 → 2 的过渡: 仿真残差 RL 训完后, **冻结残差**, 在真机上跑 BC 策略, 收集真机数据
- 阶段 2 → 3 的过渡: 真机数据量达到 5 万 transition 后, 启动离线 RL 微调残差
- **永远不要**直接在真机上跑未经验证的残差 (α=0 起步, 残差慢慢放开)

### 4.5 数据混合比例

阶段 2 的"仿真+真机"混合比例, 工业经验:

| 任务 | 仿真 : 真机 | 理由 |
| :--- | :--- | :--- |
| 抓杯子 (简单) | 80:20 | 仿真覆盖大部分场景 |
| 叠衣服 (复杂) | 50:50 | 仿真布料物理差 |
| 户外四足 (随机性大) | 20:80 | 仿真地形失真 |
| 灵巧手操作 (高频接触) | 30:70 | 接触动力学仿真差 |

**经验**: 真机数据比例 < 30% 时, 残差 RL 几乎不学真机特性; > 70% 时, 残差 RL 退化成纯真机 RL, 容易过拟合。

### 4.6 评估与监控: 残差的"健康度"

训练中要监控的关键指标:

```text
残差 RL 训练仪表盘:

    ┌────────────────────────────────────────┐
    │  1. Episode reward: 应该稳步上升          │
    │     - 起点 ≈ BC 水平 (warm start)         │
    │     - 200 步后 ≈ 1.2-1.5x BC 水平         │
    │     - 不应该下降 (残差破坏 BC)             │
    ├────────────────────────────────────────┤
    │  2. 残差幅度 ‖a_res‖: 应该先涨后稳         │
    │     - 0-100 步: 0 → 0.15 (学习)           │
    │     - 100-500 步: 0.15 → 0.10 (收敛)      │
    │     - 500+ 步: ≈ 0.05-0.10 (稳定)        │
    ├────────────────────────────────────────┤
    │  3. KL 散度 KL(π_RL ‖ π_BC): 约束上限    │
    │     - 软约束: KL ≤ 0.05 nats               │
    │     - 硬约束: KL ≤ 0.1 nats                │
    │     - 超过 → 训练不稳, 减小 α               │
    ├────────────────────────────────────────┤
    │  4. Value loss: 应该下降到 0 附近          │
    │     - 起点: 1-10 (随机)                    │
    │     - 收敛: < 0.5 (稳定)                   │
    │     - 上升 → 训练崩了, 回滚 checkpoint      │
    └────────────────────────────────────────┘
```

**残差的"健康度"判断**:
- 残差幅度稳定在 0.05-0.15: **健康**, BC 大部分场景做对了
- 残差幅度 > 0.3: **不健康**, BC 不够用, 应该加 BC 数据或换 BC 模型
- 残差幅度 < 0.01: **欠拟合**, α 太小或 RL 学习率太低

### 4.7 常见调参配方

工业上用的"调参 starter kit":

| 超参 | 默认值 | 调参方向 | 影响 |
| :--- | :--- | :--- | :--- |
| 初始 $\alpha$ | 0.1 | 0.05-0.3 | 大 → RL 主导, 小 → BC 主导 |
| $\alpha$ 调度 | 余弦 | 线性 / step | 影响收敛速度 |
| 残差网络容量 | BC 的 1/4 | 1/8-1/2 | 大 → 易过拟合, 小 → 学不动 |
| PPO clip_eps | 0.2 | 0.1-0.3 | 影响策略更新幅度 |
| SAC 熵温度 $\alpha_{ent}$ | 0.2 | 0.05-0.5 | 影响探索 |
| 离线 CQL 系数 | 5.0 | 1-10 | 大 → 保守, 小 → 自由 |
| 学习率 | 3e-4 | 1e-4-1e-3 | 标准 |
| Batch size | 256 | 64-1024 | 影响稳定性 |

**调参优先级**: $\alpha$ 调度 > 残差网络容量 > 学习率 > 其余。

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np
import gymnasium as gym
import matplotlib.pyplot as plt
from torch.distributions import Normal
import math

# 简化版环境 (示意, 实际用 MuJoCo / Isaac Gym)
class PickAndPlaceEnv:
    """2D 平面抓取: 状态 = [ee_x, ee_y, obj_x, obj_y], 动作 = [dx, dy]"""
    def __init__(self):
        self.dt = 0.05
        self.goal_thresh = 0.05
        self.max_steps = 200

    def reset(self):
        self.ee = np.array([0.0, 0.5])
        self.obj = np.array([np.random.uniform(-0.3, 0.3), np.random.uniform(-0.2, 0.2)])
        self.step_count = 0
        return self._get_state()

    def _get_state(self):
        return np.concatenate([self.ee, self.obj])

    def step(self, action):
        # 动作 = [dx, dy], 限幅
        action = np.clip(action, -0.1, 0.1)
        self.ee += action
        self.ee = np.clip(self.ee, -1, 1)
        self.step_count += 1

        # 任务 reward: 接近目标
        dist = np.linalg.norm(self.ee - self.obj)
        reward = -dist
        if dist < self.goal_thresh:
            reward = 10.0   # 抓取成功
        done = dist < self.goal_thresh or self.step_count >= self.max_steps
        return self._get_state(), reward, done, {}

    @property
    def state_dim(self):
        return 4

    @property
    def action_dim(self):
        return 2
```

### 5.2 BC 策略: 示教数据训基础策略

```python
class BCPolicy(nn.Module):
    """BC 策略: 2 层 MLP"""
    def __init__(self, state_dim, action_dim, hidden=256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, action_dim), nn.Tanh(),   # 限幅到 [-1, 1]
        )

    def forward(self, s):
        return self.net(s) * 0.05   # 限幅到动作步长

# 模拟示教数据: 1000 条轨迹, 每条 50 步
def generate_demonstrations(env, n_trajectories=1000):
    """模拟"专家"策略: 直接走直线到目标"""
    states, actions = [], []
    for _ in range(n_trajectories):
        s = env.reset()
        traj_s, traj_a = [], []
        for _ in range(env.max_steps):
            # 专家策略: 直线走向目标
            a = (env.obj - env.ee) * 5.0
            a = np.clip(a, -0.1, 0.1)
            traj_s.append(s)
            traj_a.append(a)
            s, _, done, _ = env.step(a)
            if done:
                break
        states.extend(traj_s)
        actions.extend(traj_a)
    return torch.tensor(np.array(states), dtype=torch.float32), \
           torch.tensor(np.array(actions), dtype=torch.float32)

# 训练 BC
env = PickAndPlaceEnv()
bc = BCPolicy(env.state_dim, env.action_dim)
opt = torch.optim.Adam(bc.parameters(), lr=3e-4)

states_demo, actions_demo = generate_demonstrations(env)
for epoch in range(50):
    idx = np.random.permutation(len(states_demo))[:256]
    s_batch = states_demo[idx]
    a_batch = actions_demo[idx]
    a_pred = bc(s_batch)
    loss = F.mse_loss(a_pred, a_batch)
    opt.zero_grad(); loss.backward(); opt.step()
    if epoch % 10 == 0:
        print(f"BC epoch {epoch}: loss={loss.item():.4f}")
```

### 5.3 残差 PPO 完整实现

```python
class ResidualPolicy(nn.Module):
    """残差策略: 输出 mean, std 固定"""
    def __init__(self, state_dim, action_dim, hidden=256):
        super().__init__()
        self.backbone = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
        )
        self.head = nn.Linear(hidden, action_dim)
        # 零初始化
        nn.init.zeros_(self.head.weight)
        nn.init.zeros_(self.head.bias)

    def forward(self, s):
        return self.head(self.backbone(s))

class ValueNet(nn.Module):
    def __init__(self, state_dim, hidden=256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, 1),
        )
    def forward(self, s):
        return self.net(s).squeeze(-1)

class ResidualPPOTrainer:
    def __init__(self, bc_policy, env, lr=3e-4, gamma=0.99, clip_eps=0.2,
                 alpha_start=0.3, alpha_end=0.05, K_epochs=4):
        self.bc = bc_policy.eval()
        for p in self.bc.parameters():
            p.requires_grad = False

        self.env = env
        self.state_dim = env.state_dim
        self.action_dim = env.action_dim
        self.gamma = gamma
        self.clip_eps = clip_eps
        self.K_epochs = K_epochs
        self.alpha_start = alpha_start
        self.alpha_end = alpha_end

        self.residual_net = ResidualPolicy(self.state_dim, self.action_dim)
        self.value_net = ValueNet(self.state_dim)
        self.optimizer = torch.optim.Adam(
            list(self.residual_net.parameters()) + list(self.value_net.parameters()),
            lr=lr
        )

    def cosine_alpha(self, step, total_steps):
        progress = min(step / total_steps, 1.0)
        return self.alpha_end + 0.5 * (self.alpha_start - self.alpha_end) * \
               (1 + math.cos(math.pi * progress))

    def get_action(self, state, alpha, deterministic=False):
        s = torch.tensor(state, dtype=torch.float32)
        with torch.no_grad():
            a_bc = self.bc(s)
        a_res = self.residual_net(s)
        a_rl = a_bc + alpha * a_res
        if deterministic:
            return a_rl.numpy()
        a_rl = a_rl + 0.05 * torch.randn_like(a_rl)  # 探索
        return a_rl.numpy()

    def compute_gae(self, rewards, values, dones, lam=0.95):
        """GAE: generalized advantage estimation"""
        advantages = []
        gae = 0
        values = values + [0]
        for t in reversed(range(len(rewards))):
            delta = rewards[t] + self.gamma * values[t+1] * (1 - dones[t]) - values[t]
            gae = delta + self.gamma * lam * (1 - dones[t]) * gae
            advantages.insert(0, gae)
        returns = [a + v for a, v in zip(advantages, values[:-1])]
        return advantages, returns

    def collect_rollout(self, n_steps=2048, alpha=0.1):
        states, actions, rewards, dones, log_probs_old, values = [], [], [], [], [], []
        s = self.env.reset()
        ep_reward = 0
        for _ in range(n_steps):
            a_rl = self.get_action(s, alpha)
            a_bc = self.bc(torch.tensor(s, dtype=torch.float32)).detach().numpy()
            a_res = (a_rl - a_bc) / alpha

            s_next, r, done, _ = self.env.step(a_rl)
            ep_reward += r

            states.append(s)
            actions.append(a_rl)
            rewards.append(r)
            dones.append(float(done))
            values.append(self.value_net(torch.tensor(s, dtype=torch.float32)).item())

            s = s_next
            if done:
                s = self.env.reset()
                ep_reward = 0
        return states, actions, rewards, dones, values

    def update(self, states, actions, advantages, returns, alpha):
        s_t = torch.tensor(np.array(states), dtype=torch.float32)
        a_t = torch.tensor(np.array(actions), dtype=torch.float32)
        adv_t = torch.tensor(advantages, dtype=torch.float32)
        ret_t = torch.tensor(returns, dtype=torch.float32)
        # 归一化 advantage
        adv_t = (adv_t - adv_t.mean()) / (adv_t.std() + 1e-8)

        # 计算旧 log_prob (用旧网络)
        with torch.no_grad():
            a_bc = self.bc(s_t)
            a_res_old = self.residual_net(s_t)
            a_rl_old = a_bc + alpha * a_res_old
            dist_old = Normal(a_rl_old, torch.ones_like(a_rl_old) * 0.05)
            log_prob_old = dist_old.log_prob(a_t).sum(-1)

        for _ in range(self.K_epochs):
            a_res_new = self.residual_net(s_t)
            a_rl_new = a_bc + alpha * a_res_new
            dist_new = Normal(a_rl_new, torch.ones_like(a_rl_new) * 0.05)
            log_prob_new = dist_new.log_prob(a_t).sum(-1)

            ratio = torch.exp(log_prob_new - log_prob_old)
            surr1 = ratio * adv_t
            surr2 = torch.clamp(ratio, 1 - self.clip_eps, 1 + self.clip_eps) * adv_t
            policy_loss = -torch.min(surr1, surr2).mean()

            v_pred = self.value_net(s_t)
            value_loss = F.mse_loss(v_pred, ret_t)
            entropy = dist_new.entropy().mean()

            loss = policy_loss + 0.5 * value_loss - 0.01 * entropy
            self.optimizer.zero_grad()
            loss.backward()
            torch.nn.utils.clip_grad_norm_(self.residual_net.parameters(), 0.5)
            torch.nn.utils.clip_grad_norm_(self.value_net.parameters(), 0.5)
            self.optimizer.step()

    def train(self, total_steps=100000, rollout_steps=2048):
        rewards_history = []
        residual_norms = []
        step = 0
        while step < total_steps:
            alpha = self.cosine_alpha(step, total_steps)

            states, actions, rewards, dones, values = self.collect_rollout(rollout_steps, alpha)
            advantages, returns = self.compute_gae(rewards, values, dones)
            self.update(states, actions, advantages, returns, alpha)

            ep_reward = sum(rewards)
            rewards_history.append(ep_reward / rollout_steps)
            with torch.no_grad():
                res_norm = self.residual_net(torch.tensor(np.array(states[:256]), dtype=torch.float32)).norm(dim=-1).mean().item()
            residual_norms.append(res_norm)

            step += rollout_steps
            if step // rollout_steps % 10 == 0:
                print(f"step {step:>6} | α={alpha:.3f} | "
                      f"avg_r={ep_reward/rollout_steps:.3f} | "
                      f"‖a_res‖={res_norm:.3f}")
        return rewards_history, residual_norms
```

### 5.5 评估: BC vs 残差 RL

```python
def evaluate(policy_fn, env, n_episodes=50, alpha=0.0, deterministic=True):
    """评估策略"""
    successes = 0
    total_reward = 0
    for _ in range(n_episodes):
        s = env.reset()
        ep_r = 0
        for _ in range(env.max_steps):
            a = policy_fn(s, alpha, deterministic)
            s, r, done, _ = env.step(a)
            ep_r += r
            if done and r > 5:  # 成功
                successes += 1
                break
            if done:
                break
        total_reward += ep_r
    return total_reward / n_episodes, successes / n_episodes

# BC 评估
bc_policy = lambda s, alpha, det: bc(torch.tensor(s, dtype=torch.float32)).detach().numpy()
bc_r, bc_succ = evaluate(bc_policy, env, n_episodes=100, alpha=0)
print(f"BC: avg_r={bc_r:.2f}, success={bc_succ:.2%}")

# 残差 RL 评估 (α=0.1)
residual_policy = lambda s, alpha, det: trainer.get_action(s, alpha, deterministic=det)
res_r, res_succ = evaluate(residual_policy, env, n_episodes=100, alpha=0.1)
print(f"Residual RL: avg_r={res_r:.2f}, success={res_succ:.2%}")
```

### 6.2 与各章的具体联系

**与 [[第06章-02-PPO在机器人-从仿真到真实]]**: 本章用 PPO 作残差 RL 的底层算法, 但加了动作空间的"BC 先验 + RL 残差"分解。PPO 的 clip、GAE、value loss 完全复用, 仅策略网络替换成残差网络。

**与 [[第06章-03-SAC与离线RL-稳定训练]]**: SAC + 残差是 § 3.2 的核心。SAC 的最大熵天然适合残差探索 (残差幅度有上界, 但残差方向可以自由探索)。离线残差 RL (CQL/IQL) 是 § 3.3 的内容。

**与 [[第06章-04-Sim2Real-域随机化与域适应]]**: 残差 RL 是 Sim2Real 的"训练时"工程, 域随机化是"仿真时"工程。两者协同: 仿真训 BC + 残差 RL 训残差, 真机部署时残差吸收 sim-to-real gap。

**与 [[第06章-06-安全RL-避免物理损坏]]**: § 3.4 的安全残差 RL 直接套用 [[第06章-06-安全RL-避免物理损坏]] § 3 的安全层 (Lagrangian, control barrier function)。残差空间天然适合加安全约束, 因为残差幅度小, 投影计算量低。

**与 `../第05章-模仿学习/第05章-01-行为克隆-BC的因果混淆问题.md`**: BC 提供先验, 但 BC 有"因果混淆 + 协变量偏移"问题 ([1-BC的因果混淆问题] § 2.3)。残差 RL 用环境反馈**修正 BC 的错误**, 比 BC 单纯依赖离线数据稳得多。

**与 `../第05章-模仿学习/第05章-02-DAgger与聚合-解决分布漂移.md`**: DAgger 是"在线 IL, 每次迭代收集新数据重新训 BC"; 残差 RL 是"在 BC 基础上训残差, 不修改 BC"。两者解决同一个问题 (协变量偏移), 但 DAgger 需要持续专家, 残差 RL 只需要环境奖励。

## 7. 与数学基础的关系

残差 RL 的数学本质是**约束优化 + 函数逼近**, 与数学基础多个章节紧密相关。

### 7.1 与最优化理论

**`../../../基础/数学基础/第06章-最优化/0-总目录与阅读路径.md`** → 残差 RL 的目标函数

残差 RL 的训练可以写成:

$$
\min_\theta \; \mathbb{E}_\pi \left[ -r(s, \pi_{BC}(s) + \alpha \pi_\text{res}(s; \theta)) \right] \quad \text{s.t.} \quad \mathbb{E}_\pi [\pi_\text{res}(s; \theta)^2] \le \epsilon
$$

这是**带范数约束的非凸优化** (策略网络非凸, 但残差范数约束凸)。

**`../../../基础/数学基础/第06章-最优化/0-总目录与阅读路径.md`** → 残差幅度的几何解释

$\alpha$ 调度本质上是在信赖域内做"步长控制":
- $\alpha$ 大 → 信赖域大 → 步子迈得远 → 残差可学大改
- $\alpha$ 小 → 信赖域小 → 步子迈得近 → 残差只能微调

**`../../../基础/数学基础/第06章-最优化/0-总目录与阅读路径.md`** → PPO/SAC 的更新规则

策略梯度 = 随机梯度下降的特例, PPO 的 clip 是 SGD 的"截断"。

### 7.2 与概率论与信息论

**`../../../基础/数学基础/第03章-概率论/0-总目录与阅读路径.md`** → 残差幅度的方差估计

残差范数 ‖$a_\text{res}$‖ 的方差反映策略的"不确定度"。训练后期 ‖$a_\text{res}$‖ 方差应该**减小** (残差稳定)。

**`../../../基础/数学基础/第05章-信息论/0-总目录与阅读路径.md`** → KL 约束

防止残差跑偏的标准做法: 加 KL 惩罚项

$$
\mathcal{L}_\text{KL} = \beta \cdot D_\text{KL}(\pi_\text{RL}(\cdot|s) \| \pi_\text{BC}(\cdot|s))
$$

$\beta$ 大 → 严格约束, 残差变化慢; $\beta$ 小 → 宽松, 残差变化快。

**`../../../基础/数学基础/第03章-概率论/0-总目录与阅读路径.md`** → SAC 残差的策略分布

SAC 残差策略默认高斯分布 $\mathcal{N}(\mu_\text{res}(s; \theta), \sigma_\text{res}^2)$, BC 提供 mean, 残差提供 mean 偏移。

### 7.3 与系统思维

**`../../../基础/数学基础/第07章-系统思维/0-总目录与阅读路径.md`** → 残差 PPO 的核心

PPO 的 clip 公式在残差 RL 里完全适用, 但作用对象是"残差网络"而不是"完整策略"。

**`../../../基础/数学基础/第07章-系统思维/0-总目录与阅读路径.md`** → 残差幅度与探索

残差幅度的调度本质上是"探索-利用"的动态平衡:
- 训练初期 $\alpha$ 大 → 多探索 (残差可以大幅修正)
- 训练后期 $\alpha$ 小 → 多利用 (残差微调, 收敛到 BC 附近最优)

## 8. 常见误区

### 8.1 误区 1: "残差 RL 等于 BC + PPO"

**错**。残差 RL 的核心不是"BC + PPO", 而是**动作空间分解**:
- $a_\text{final} = a_\text{BC} + \alpha \cdot a_\text{residual}$
- RL 只学残差, BC 完全冻结

**常见错误做法**:
```python
# 错误: BC 和 RL 各输出一个完整动作, 加权平均
a_final = 0.5 * bc(s) + 0.5 * rl(s)
```
这个做法有问题:
1. RL 网络有可能学成"完全替代 BC", 破坏先验
2. 训练初期 RL 输出噪声, 0.5 加权后整体动作不稳
3. 没有"残差"的几何意义, 调试难

**正确做法**: RL 只学残差, BC 完全冻结。

### 8.2 误区 2: "残差网络随便初始化都行"

**错**。残差网络必须**零初始化或极小方差初始化**。

**错误做法**:
```python
# 错误: 标准 PyTorch 默认初始化
nn.Linear(256, action_dim)   # 默认 uniform 初始化, 输出数量级 0.1
```
训练第一步, 残差幅度 0.1, 加上 α=0.1, 动作偏移 0.01, 真机上机器人抖一下。

**正确做法**: § 2.2 的零初始化。

### 8.3 误区 3: "α 越大越好, 残差越多越好"

**错**。α 大意味着残差主导, 残差可能"破坏" BC。

```text
α 选择的工程经验:

    α = 0.0:    纯 BC, 没 RL (失败)
    α = 0.05:   RL 学不动 (信号弱)
    α = 0.1:    平衡点 (推荐起点)
    α = 0.3:    RL 主导 (BC 弱时用)
    α = 1.0:    等价于端到端 RL, 没意义
```

### 8.4 误区 4: "残差 RL 一定能涨点"

**错**。残差 RL 在以下场景**不涨点**甚至**掉点**:

| 场景 | 残差 RL 表现 | 原因 |
| :--- | :--- | :--- |
| BC 已经 95%+ 成功 | 可能掉 1-2 个百分点 | 残差引入噪声 |
| 仿真到真实 gap < 5% | 几乎不涨 | gap 太小, RL 学不到东西 |
| 奖励函数完全是 BC 演示 | 退化成 BC | RL 没新信号 |
| BC 训练数据严重有偏 | 残差 RL 也救不了 | 上游数据问题 |

**工程经验**: BC 成功率在 60-85% 时, 残差 RL 收益最大 (涨 10-30 个百分点)。

### 8.5 误区 5: "残差 RL 可以直接跑真机"

**危险**。残差 RL 必须**先仿真验证, 再真机部署**。

真机部署的关键步骤 (§ 4.4):
1. 仿真验证 ≥ 90% 成功率
2. 残差幅度 ‖$a_\text{res}$‖ ≤ 0.2 (动作不会偏离 BC 太远)
3. KL($\pi_\text{RL}$‖$\pi_\text{BC}$) ≤ 0.1 nats
4. 真机启动时 α=0 (纯 BC), 慢慢放开 α
5. 持续监控安全指标 (关节力矩、速度)

### 8.6 误区 6: "残差网络必须和 BC 网络同结构"

**不必**。残差网络通常**比 BC 网络小** (1/4 到 1/2 参数量)。

**错误做法**:
```python
# 错误: 残差网络和 BC 网络结构相同
bc = MLP(1024, 1024, ...)         # 1M 参数
residual = MLP(1024, 1024, ...)   # 1M 参数
```
两个大网络, 训练慢, 而且残差容易过拟合。

**正确做法**: 残差网络宽度 256, 深度 2-3 层 (参数量 130K-300K)。

### 8.7 误区 7: "残差 RL 不需要 KL 约束"

**错**。残差 RL 的训练可能让残差"跑偏", 偏离 BC 的安全动作空间。**KL 约束是必要的安全机制**。

```python
# 加上 KL 惩罚
kl_penalty = F.kl_div(
    F.log_softmax(rl_logits, dim=-1),
    F.log_softmax(bc_logits, dim=-1),
    reduction='batchmean'
)
loss = policy_loss + 0.1 * kl_penalty   # β=0.1
```

工业上, β ∈ [0.05, 0.5] 是合理范围。

### 8.8 误区 8: "残差幅度调度是越简单越好"

**不一定**。线性调度简单但余弦调度更平滑。某些任务需要**warm restart** (训练中期重启调度)。

```text
α 调度的"warm restart":

    α
    ↑
0.3 │  ●
    │   ╲
0.2 │    ╲
    │     ╲
0.1 │      ╲_
    │        ╲___      ___
0.05│            ●___╱    ╲___●___
    │___________________________→ step
                  ↑               ↑
                restart         restart

    用途: 残差 RL 训练到 50% 时"卡住" (reward 不涨),
    重启调度让 α 回到大值, 重新探索
```

## 9. L7/L8 面试 Q&A

### 9.1 基础概念题

**Q1: 残差 RL 的核心数学公式是什么?为什么这么写?**

A: $\pi_\text{RL}(s) = \pi_\text{IL}(s) + \alpha \cdot \pi_\text{residual}(s; \theta)$。三个原因:
1. 加法支持零初始化 ($\theta=0$ 时 $\pi_\text{residual}=0$, 起步是 BC)
2. 连续动作空间适用 ($\mathbb{R}^d$ 加法直接适用)
3. 可微 (梯度可反传到 $\theta$)

**Q2: 为什么残差网络必须零初始化?**

A: 零初始化让 RL 起步等价 BC, 不会"破坏"已学知识。如果用标准 PyTorch 初始化, 残差网络起步输出非零 ($\sim 0.1$), 加上 α=0.1, 动作偏移 0.01, 真机上机器人抖一下, 可能撞到工件。

**Q3: $\alpha$ 越大越好吗?**

A: 不是。α 大 → RL 主导, 残差可能"破坏" BC。α 小 → RL 学不动。α ∈ [0.05, 0.3] 是合理范围, 推荐先用 0.1, 训练后期衰减到 0.05。

### 9.2 算法实现题

**Q4: 残差 PPO 和标准 PPO 的关键区别是什么?**

A: 三点区别:
1. **动作采样**: 标准 PPO 直接用策略网络采样; 残差 PPO 采样 $a_{BC} + \alpha \cdot a_\text{residual}$
2. **策略网络**: 标准 PPO 输出完整动作; 残差 PPO 输出残差, BC 完全冻结
3. **初始化**: 残差 PPO 必须零初始化

其他 (clip、GAE、value loss) 完全一样。

**Q5: 残差 SAC 比残差 PPO 在机器人上更有优势吗?为什么?**

A: 一般是的, 三点优势:
1. **Off-policy + 经验回放**: 可以复用 BC 演示数据, 样本效率高 5-10 倍
2. **最大熵**: 残差天然有探索, 不会塌缩
3. **Twin Q**: 减少过估计, 残差小信号下 Q 估计更稳

**Q6: 离线残差 RL 的数据集怎么构造?**

A: 三种数据源:
1. **BC 演示**: 高质量成功轨迹 (50-80%)
2. **老策略部署日志**: 包含成功和失败的轨迹 (20-40%)
3. **失败重演**: 故意制造失败 (5-10%), 让 RL 知道"什么是错的"

数据不能纯 BC (RL 不知道失败模式), 也不能纯老日志 (没有"成功"轨迹)。

### 9.3 工程实战题

**Q7: 残差 RL 真机部署怎么渐进?**

A: 三阶段:
1. **阶段 1 (1-3 天)**: 纯仿真, 残差 RL 训残差, 仿真成功率 ≥ 90%
2. **阶段 2 (1-2 周)**: 仿真+真机混合数据, 离线 RL 微调残差, 真机 α=0.05 小残差测试
3. **阶段 3 (持续)**: 纯真机微调, α ≤ 0.05, 严格 KL 约束, 7×24 监控

**Q8: 残差 RL 在真机翻车了, 怎么排查?**

A: 排查顺序:
1. **残差幅度是否异常** (突然涨到 0.5+): 训练崩了, 回滚 checkpoint
2. **KL 散度是否爆掉** (> 0.5 nats): 残差跑偏, 减小 α 或加 KL 惩罚
3. **value loss 是否上升**: 训练崩了, 减小学习率
4. **真机数据分布是否漂移**: 仿真残差 RL 失效, 需要重训

**Q9: 残差 RL 和 DAgger 的核心区别?**

A: 三点:
1. **学习信号**: 残差 RL 用环境奖励, DAgger 用专家动作
2. **专家依赖**: 残差 RL 不需要专家, DAgger 需要持续专家查询
3. **修改对象**: 残差 RL 只训残差网络, BC 冻结; DAgger 重训整个 BC

残差 RL 更适合"无专家 + 有奖励"场景; DAgger 更适合"有专家 + 无奖励"场景。

### 9.4 数学原理题

**Q10: 为什么残差 RL 比端到端 RL 样本效率高?**

A: 两个原因:
1. **搜索空间小**: 端到端 RL 在 $\mathbb{R}^d$ 全空间搜; 残差 RL 在 BC 附近的局部区域搜, 维度小
2. **warm start**: 端到端 RL 从随机策略起步; 残差 RL 从 BC 起步, 已经接近最优

样本效率高 5-10 倍, 物理意义: 残差 RL 相当于"在最优解附近做局部搜索", 而端到端 RL 是"全空间随机搜索"。

**Q11: 残差 RL 的目标函数可以写成什么形式?**

A: 带信赖域约束的策略优化:

$$
\min_\theta \; \mathbb{E}_\pi \left[ -r(s, \pi_\text{BC}(s) + \alpha \pi_\text{res}(s; \theta)) \right]
\quad \text{s.t.} \quad \mathbb{E}_\pi [\pi_\text{res}(s; \theta)^2] \le \epsilon
$$

等价于 $\alpha$ 调度约束。

### 9.5 工业实践题

**Q12: 哪些公司/项目在用残差 RL?具体怎么用的?**

A: 4 个例子:
1. **NVIDIA Isaac Lab + GR00T (2024)**: BC 训基础模型 + 残差 RL 微调每个任务
2. **Open X-Embodiment (2023)**: RT-2 / Octo + 残差 RL 微调, 21 家机器人公司联合
3. **ETH ANYmal (2024)**: BC 训基础步态 + 残差 RL 学抗扰动
4. **Figure 02 + 宇树 H1 (2024-2025)**: BC 基础抓取 + 残差 RL 学动态适应

**Q13: 残差 RL 的常见调参配方?**

A: starter kit:
- 初始 $\alpha$: 0.1 (BC 弱时 0.3, BC 强时 0.05)
- $\alpha$ 调度: 余弦, 训练后期衰减到 0.05
- 残差网络容量: BC 的 1/4 (宽度 256, 深度 2-3 层)
- PPO clip_eps: 0.2
- SAC 熵温度: 0.2
- 学习率: 3e-4
- Batch size: 256

**Q14: 残差 RL 在工业上最大的坑是什么?**

A: 三个:
1. **BC 训练数据质量差**: 上游 BC 数据有偏, 残差 RL 也救不了 (garbage in, garbage out)
2. **仿真到真实 gap 太大** (> 30%): 仿真训的残差在真机完全失效, 必须真机数据重训
3. **真机直接跑未经验证的残差**: 仿真没验证就上真机, 一次事故 5-10 万

**Q15: 残差 RL 的未来发展方向?**

A: 三个趋势:
1. **基础模型 + 残差 RL**: 大规模 BC 训基础模型, 残差 RL 微调每个任务 (RT-2 / GR00T)
2. **离线残差 RL**: 纯真机日志训残差, 无需仿真 (Figure 02 的方案)
3. **多任务残差**: 多个任务共享 BC, 残差 RL 任务特定微调 (Open X-Embodiment)

> 4. **α 调度**: 余弦衰减, 训练后期让残差变小
> 5. **真机渐进**: 仿真 → 仿真+真机 → 全真机, 三阶段递进
>
> **下一章**: [[第06章-06-安全RL-避免物理损坏]], 讲怎么在残差 RL 基础上加安全约束, 让机器人不撞桌、不伤人、不烧驱动器。

## 11. 残差动作的几何与拓扑: 不只是向量加法

§ 2 给的 $\pi_{RL} = \pi_{IL} + \alpha \cdot \pi_{residual}$ 在**末端笛卡尔空间**是最自然的: 直接对末端位姿加偏差。但在**关节空间**、**力矩空间**、**接触空间**, 加法不是唯一选择。下面讲工业上用到的 3 种残差合成方式 + 各自的数学表达。

### 11.1 末端位姿残差 (Operational Space)

最常见、最稳定。直接对笛卡尔坐标 $(\Delta x, \Delta y, \Delta z, \Delta \phi)$ 加残差:

$$
a_{RL}^{ee} = a_{IL}^{ee} + \alpha \cdot a_{res}^{ee}, \quad a^{ee} \in \mathbb{R}^6
$$

```text
末端位姿残差 (最常用):

    机器人基座
       │
       │   ┌──目标位姿 T* (BC 输出)
       │   │
       │   ↓ a_BC
       │  ┌───────┐
       │  │ EE *  │ ← 当前位姿
       │  └───┬───┘
       │      │ a_BC
       │      ↓
       │  ┌───────┐
       │  │ EE'   │ ← BC 预测下一步
       │  └───┬───┘
       │      │ + α·a_res
       │      ↓
       │  ┌───────┐
       │  │ EE''  │ ← 残差 RL 实际走到的位姿
       │  └───┬───┘
       │      │ a_RL = a_BC + α·a_res
       │      ↓

    优点: 残差空间 = 任务空间, Sim2Real 友好
    缺点: 需要 IK 把末端位姿转关节角, 计算量大 (每步 ~1ms)
```

**Sim2Real 为什么友好?** 因为末端位姿是"任务级抽象", 不依赖具体机器人构型 (Franka / UR / 宇树都一样)。Sim2Real 的摩擦/阻尼误差主要影响"末端到关节"的转换, 而末端空间的残差定义与机器人构型解耦。

### 11.2 关节角残差 (Joint Space)

最简单, 但 Sim2Real 难度大:

$$
a_{RL}^{joint} = a_{IL}^{joint} + \alpha \cdot a_{res}^{joint}, \quad a^{joint} \in \mathbb{R}^{n_q}
$$

```text
关节角残差 (最简单, Sim2Real 最难):

    q_IL (BC 输出)        q_RL (最终)
        ↓                   ↑
        ├── Δq_1 ──────┤   α·Δq_1 + q_IL
        ├── Δq_2 ──────┤   α·Δq_2 + q_IL
        ├── Δq_3 ──────┤
        ├── ... ──────┤
        └── Δq_n ──────┘

    Sim2Real gap 集中在:
        - 关节摩擦 (库仑 + 粘滞), 仿真 0.05, 真机 0.12
        - 关节阻尼, 仿真 0.01, 真机 0.03
        - 减速器背隙, 仿真 0, 真机 0.1°

    结果: 关节角残差 RL 训 1 万步, 真机效果差 30-50%
```

**什么时候用?** 关节空间残差只在**构型简单**且**Sim2Real gap 小**时使用, 比如固定工位的工业臂 (JAKA、埃斯顿), 仿真器精度高 (亚毫米级), 真机关节误差小 (减速器背隙 < 0.05°)。

### 11.3 通过 Jacobian 的等价关节残差

一种"混合"做法: 残差在末端空间定义, 但通过 Jacobian 转关节角:

$$
a_{RL}^{joint} = a_{IL}^{joint} + \alpha \cdot J(q)^{-1} a_{res}^{ee}
$$

其中 $J(q) \in \mathbb{R}^{6 \times n_q}$ 是运动学 Jacobian, $J(q)^{-1}$ 是伪逆 (Jacobian transpose 也可)。这让残差在末端空间"自然缩放"到关节空间。

```text
Jacobian-mediated residual:

    ┌────────────────┐
    │ 末端空间残差     │
    │ a_res^ee       │
    │ (6 维)         │
    └────────┬───────┘
             │ × J(q)^{-1}   (6×n 维转换)
             ↓
    ┌────────────────┐
    │ 关节空间残差     │
    │ a_res^joint    │
    │ (n 维)         │
    └────────┬───────┘
             │ + α
             ↓
    ┌────────────────┐
    │ 最终关节角       │
    │ q_RL           │
    └────────────────┘

    优点: 残差在任务空间 (人可解释), 但施加在关节空间 (机器人可执行)
    缺点: Jacobian 计算 + 奇异点处理, 每步 ~0.5ms
```

**PyTorch 实现**:

```python
import torch

class JacobianResidualPolicy(nn.Module):
    """残差在末端空间定义, 通过 Jacobian 转关节角"""
    def __init__(self, state_dim, ee_res_dim=6, joint_dim=7):
        super().__init__()
        self.ee_res_dim = ee_res_dim  # 末端 6D (3 位姿 + 3 旋转)
        self.joint_dim = joint_dim    # 关节数
        self.backbone = nn.Sequential(
            nn.Linear(state_dim, 256), nn.ReLU(),
            nn.Linear(256, 256), nn.ReLU(),
        )
        self.ee_res_head = nn.Linear(256, ee_res_dim)
        # 零初始化
        nn.init.zeros_(self.ee_res_head.weight)
        nn.init.zeros_(self.ee_res_head.bias)

    def forward(self, s, jacobian_pinv):
        """
        s:             (B, state_dim)
        jacobian_pinv: (B, ee_res_dim, joint_dim)  伪逆 J(q)^{-1}
        Returns: (B, joint_dim) 关节空间残差
        """
        feat = self.backbone(s)
        ee_res = self.ee_res_head(feat)              # (B, 6)
        # 残差施加: joint_res = ee_res @ J^{-1}
        joint_res = torch.bmm(ee_res.unsqueeze(1), jacobian_pinv).squeeze(1)
        return joint_res
```

注意: `jacobian_pinv` 需要从机器人运动学库 (Pinocchio / Drake / mujoco-py) 实时计算, 这是工业部署的"流水线瓶颈"——单步 IK + Jacobian 计算约 0.5-1ms。

### 11.4 流形约束残差 (Manifold-Constrained)

最严谨的数学形式。把残差约束在 $\pi_{IL}$ 附近的"测地线邻域"内:

$$
a_{RL} = \text{Exp}_{\pi_{IL}(s)}\left( \alpha \cdot \pi_{residual}(s; \theta) \right)
$$

其中 $\text{Exp}_p(v)$ 是流形上的指数映射 (类似 Riemannian 流形)。末端位姿的流形是 $SE(3)$ (特殊欧氏群), 速度空间是切空间 $\mathfrak{se}(3)$, 残差在切空间, 通过指数映射到 $SE(3)$。

```text
SE(3) 流形上的残差:

    流形 M = SE(3) (位姿空间)

    π_IL(s) ∈ M             ← BC 输出的位姿 (流形上一点)

    T_{π_IL}M = se(3)       ← 切空间 (位姿的小扰动空间)

    ┌──────────────────────────────────────────┐
    │  M (流形)                                  │
    │                                            │
    │           π_IL (BC 输出)                   │
    │           ↑ Exp map                       │
    │           │                               │
    │    ───────┼──────→ T_{π_IL}M (切空间)       │
    │           │                               │
    │           • α·π_res (残差, 在切空间)        │
    │                                            │
    │  Exp_{π_IL}(α·π_res) = π_IL ⊕ α·π_res     │
    │                                            │
    │  性质: 在奇异点附近 (e.g., 关节锁定)         │
    │  加法可能"溢出", 指数映射安全               │
    └──────────────────────────────────────────┘
```

**数学表达**: $SE(3)$ 的指数映射是
$$
\text{Exp}: \mathfrak{se}(3) \to SE(3), \quad \text{Exp}\left(\begin{bmatrix} \omega \\ v \end{bmatrix}\right) = \begin{bmatrix} \exp([\omega]_\times) & Vv \\ 0 & 1 \end{bmatrix}
$$
其中 $V$ 是 $SO(3)$ 的左上雅可比, $[\omega]_\times$ 是 $\omega$ 的反对称矩阵。

**工业价值**: 处理奇异位姿 (singularity) 时的动作"爆炸", 比如腕关节接近奇异构型时, 末端位姿残差可能让关节速度发散, 流形约束可以**截断发散方向**, 训得更稳。Figure 02 的灵巧手微调就用了这种流形约束。

### 11.5 残差空间的"谱分解"

最后一个 trick: 把残差分解到**不同频段**, 不同频段独立训练:

$$
a_{RL}(t) = a_{IL}(t) + \alpha_{low} \cdot a_{res}^{low}(t) + \alpha_{mid} \cdot a_{res}^{mid}(t) + \alpha_{high} \cdot a_{res}^{high}(t)
$$

其中 $a_{res}^{low}$ 是低频修正 (e.g., 5Hz 以下的轨迹调整), $a_{res}^{high}$ 是高频修正 (e.g., 50Hz 以上的抖动补偿)。

```text
频段分解的残差:

    残差信号频率谱:

    幅度
     ↑
     │    ┌─── 高频残差 (50-100Hz, 抖动补偿)
     │   ╱│
     │  ╱ │
     │ ╱  │
     │╱   │
     │    └─── 中频残差 (5-50Hz, 动态调整)
     │    ╱
     │   ╱
     │  ╱
     │ ╱───── 低频残差 (0-5Hz, 轨迹微调)
     │╱
     └────────────────────→ 频率

    各频段独立训练:
        低频: 仿真长 episode, 学"轨迹优化"
        中频: 真机数据, 学"动态适应"
        高频: 力矩传感数据, 学"抖动补偿"
```

工业应用: 工业臂高速运动 (> 5Hz 控制) 时, 高频残差负责"反振动", 中频残差负责"轨迹跟踪", 低频残差负责"长期优化"。UR5e / KUKA 这种 1kHz 控制循环的机器人, 这种分解把训练难度降低 50%。

## 12. Advantage 估计: 残差 RL 的 GAE 实现细节

§ 3.1 给了 PPO 的 loss, 但 **advantage 怎么算**没展开。这里补完残差 RL 的 GAE (Generalized Advantage Estimation) 实现细节。

### 12.1 标准 GAE vs 残差 RL 的 GAE

标准 GAE:
$$
\hat{A}_t^{GAE} = \sum_{l=0}^{\infty} (\gamma \lambda)^l \delta_{t+l}, \quad \delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)
$$

残差 RL 的 GAE **没有本质不同**, 但 value function 的训练目标要小心:

$$
V(s) \approx \mathbb{E}_{\pi_{RL}}\left[ \sum_{t=0}^{\infty} \gamma^t r_t \mid s_0 = s \right], \quad \pi_{RL} = \pi_{IL} + \alpha \cdot \pi_{res}
$$

**关键**: $V(s)$ 学的是"残差动作下的长期回报", 不是"纯 BC 动作下的回报"。两个 value function 的训练目标**不同**, 残差 RL 必须**新训一个 value net**, 不能复用 BC 训的 value。

```text
Value function 的几何:

    s ─── → V_BC(s)    纯 BC 下的状态价值
     │       ↑
     │       └── BC 训出来的 value net (废弃)
     │
     └─── → V_RL(s)    残差 RL 下的状态价值
             ↑
             └── 残差 RL 训的 value net (新训, 当前使用)

    区别:
        V_BC(s) ≈ "如果一直执行 BC 动作, 这个状态能拿多少分?"
        V_RL(s) ≈ "如果一直执行残差 RL 动作, 这个状态能拿多少分?"

    残差 RL 训的 value 通常 **比 V_BC 大**, 因为 RL 在修正 BC 的错误
```

### 12.2 为什么 baseline 不能用 0

PPO 的优势估计需要 baseline (用于减少方差)。标准做法是用 $V(s)$ 作为 baseline。**残差 RL 里 baseline 用 $V(s)$ 比用 0 好 30-50%**。

数学上: advantage 的方差 = 实际 advantage 的方差 + baseline 的方差。所以 baseline 越接近真实 value, advantage 方差越小, 训练越稳。

```text
不同 baseline 的 advantage 方差对比 (仿真实验):

    ┌─────────────────────────────────────┐
    │ baseline  │ advantage std │ 收敛步数 │
    ├─────────────────────────────────────┤
    │ V(s)=0    │    5.2        │   150K   │  ← 高方差, 慢
    │ V(s)=V_BC │    2.1        │   80K    │  ← 中等
    │ V(s)=V_RL │    0.9        │   45K    │  ← 低方差, 快 ✓
    └─────────────────────────────────────┘
```

### 12.3 PyTorch: 残差 RL 的完整 GAE 实现

```python
import torch
import numpy as np

def compute_residual_gae(rewards, values, dones, a_bc_seq, a_rl_seq,
                         gamma=0.99, lam=0.95, bc_value_net=None):
    """
    残差 RL 的 GAE 计算

    rewards:    (T,)       奖励序列
    values:     (T+1,)     V(s_t) for t=0..T, 含 bootstrap
    dones:      (T,)       episode 终止标志
    a_bc_seq:   (T, d)     BC 动作序列 (用于 value baseline)
    a_rl_seq:   (T, d)     RL 动作序列 (实际执行)
    bc_value_net: nn.Module  BC value net (可选用作 baseline)

    Returns:
        advantages: (T,)
        returns:    (T,)
    """
    T = len(rewards)
    advantages = torch.zeros(T)
    gae = 0.0

    # 选择 baseline: 优先用 V_RL (本次残差 RL 的 value), 否则 V_BC
    if bc_value_net is not None and values is None:
        # 用 BC value 作为 baseline (弱 baseline)
        with torch.no_grad():
            values = bc_value_net(a_bc_seq).squeeze(-1).numpy()
        values = np.concatenate([values, [0]])  # bootstrap

    values = np.asarray(values, dtype=np.float32)

    # 反向 GAE 计算
    for t in reversed(range(T)):
        # TD error: δ_t = r_t + γ·V(s_{t+1})·(1-done_t) - V(s_t)
        delta = rewards[t] + gamma * values[t+1] * (1.0 - dones[t]) - values[t]
        # GAE: A_t = δ_t + γ·λ·(1-done_t)·A_{t+1}
        gae = delta + gamma * lam * (1.0 - dones[t]) * gae
        advantages[t] = gae

    # Returns = advantages + values (去 bootstrap)
    returns = advantages + values[:-1]

    return torch.tensor(advantages, dtype=torch.float32), \
           torch.tensor(returns, dtype=torch.float32)


def normalize_advantages(advantages, eps=1e-8):
    """归一化 advantage: 标准 PPO trick, 减少量纲影响"""
    adv = (advantages - advantages.mean()) / (advantages.std() + eps)
    return adv


class ResidualValueNet(nn.Module):
    """残差 RL 的 value net: 输入状态 + BC 动作, 输出 V(s)"""
    def __init__(self, state_dim, action_dim, hidden=256):
        super().__init__()
        # 输入: 状态 + BC 动作 (value 应该"知道" BC 会做什么)
        self.net = nn.Sequential(
            nn.Linear(state_dim + action_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, 1)
        )

    def forward(self, s, a_bc):
        """
        s:    (B, state_dim)
        a_bc: (B, action_dim)
        Returns: (B,) V(s, a_bc)
        """
        x = torch.cat([s, a_bc], dim=-1)
        return self.net(x).squeeze(-1)
```

**为什么 value net 要看 BC 动作?** 因为残差 RL 的状态价值 $V(s)$ 取决于"接下来 BC 会做什么"。如果 value 不看 BC 动作, 它学到的是"普通 RL"的价值, 而不是"残差 RL"的价值, PPO 的优势估计会有偏。

### 12.4 Variance Reduction 的进阶技巧

**技巧 1: 多步 advantage 归一化**。除了上面按 batch 归一化, 还按时间步归一化 (per-timestep):

```python
def normalize_advantages_per_step(advantages, group_size=64):
    """分时间段归一化, 减少时间相关性"""
    T = advantages.shape[0]
    advantages = advantages.reshape(-1, group_size)
    advantages = (advantages - advantages.mean(-1, keepdim=True)) / \
                 (advantages.std(-1, keepdim=True) + 1e-8)
    return advantages.reshape(T)
```

**技巧 2: 双 baseline**。同时用 $V_{RL}$ 和 $V_{BC}$ 做 baseline, 取小的那个 (更保守):

$$
\hat{A}_t = r_t + \gamma V_{target}(s_{t+1}) - \min(V_{RL}(s_t), V_{BC}(s_t))
$$

这种"min-baseline"在工业上偶尔用, 防止 value 估计过乐观。

## 13. 自适应 α: 状态相关的残差幅度

§ 2.4 提了"自适应 α"的概念, 这里给出完整实现 + 适用场景。

### 13.1 为什么需要状态相关 α

固定 α (或调度 α) 的问题:

```text
固定 α 在不同状态下的问题:

    状态 1: BC 完全做对 → 不需要残差 → 残差应 ≈ 0
    状态 2: BC 80% 对 → 需要小残差
    状态 3: BC 完全错 → 需要大残差 → 残差应大

    固定 α=0.1:
        状态 1: 残差 0.05 + BC = 偏 0.005 → 没问题, 但浪费 RL 容量
        状态 3: 残差 0.05 + BC = 偏 0.005 → BC 错得太离谱, RL 救不回来

    自适应 α(s):
        状态 1: α=0.01 → 残差贡献 0.0005 → 几乎不动
        状态 3: α=0.5  → 残差贡献 0.05   → 显著修正
```

**直觉**: BC 在大多数状态做对 (90%), 残差不需要发力; BC 在少数状态做错 (10%), 残差需要"重点发力"。固定 α 把"重点"和"非重点"一视同仁, 浪费 RL 容量。

### 13.2 PyTorch: AdaptiveAlphaNetwork

```python
class AdaptiveResidualPolicy(nn.Module):
    """自适应残差策略: 同时输出残差动作和状态相关的 α"""
    def __init__(self, state_dim, action_dim, hidden=256):
        super().__init__()
        self.backbone = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
        )
        # 残差动作头
        self.action_head = nn.Linear(hidden, action_dim)
        nn.init.zeros_(self.action_head.weight)
        nn.init.zeros_(self.action_head.bias)
        # α 头 (输出每个动作维度的独立 α)
        self.alpha_head = nn.Linear(hidden, action_dim)
        # α 初始化: logit(0.1) ≈ -2.2 (因为 sigmoid(-2.2) ≈ 0.1)
        nn.init.constant_(self.alpha_head.bias, -2.2)

    def forward(self, s):
        """
        s: (B, state_dim)
        Returns:
            a_res: (B, action_dim) 残差动作
            alpha: (B, action_dim) 状态相关 α (每个维度独立)
        """
        feat = self.backbone(s)
        a_res = self.action_head(feat)
        alpha = torch.sigmoid(self.alpha_head(feat))  # α ∈ (0, 1)
        return a_res, alpha

    def get_action(self, s, a_bc, alpha_max=0.5):
        """得到残差动作"""
        a_res, alpha = self.forward(s)
        alpha = alpha * alpha_max  # 限制 α 上限, 防训练初期破坏 BC
        a_rl = a_bc + alpha * a_res
        return a_rl, alpha


class AdaptiveResidualTrainer:
    """自适应 α 的训练器"""
    def __init__(self, bc_policy, env, lr=3e-4, alpha_reg=0.01):
        self.bc = bc_policy.eval()
        for p in self.bc.parameters():
            p.requires_grad = False

        self.env = env
        self.policy = AdaptiveResidualPolicy(env.state_dim, env.action_dim)
        self.value_net = ResidualValueNet(env.state_dim, env.action_dim)
        self.optimizer = torch.optim.Adam(
            list(self.policy.parameters()) + list(self.value_net.parameters()),
            lr=lr
        )
        self.alpha_reg = alpha_reg  # α L1 正则, 鼓励 α 小

    def compute_loss(self, s, a_bc, a_data, advantages, returns):
        """自适应残差 PPO 的 loss"""
        a_res, alpha = self.policy(s)
        a_rl = a_bc + alpha * a_res

        # PPO ratio (重要: ratio 基于完整动作 a_rl)
        dist = Normal(a_rl, torch.ones_like(a_rl) * 0.05)
        log_prob = dist.log_prob(a_data).sum(-1)

        with torch.no_grad():
            dist_old = Normal(a_rl.detach(), torch.ones_like(a_rl) * 0.05)
            log_prob_old = dist_old.log_prob(a_data).sum(-1)
        ratio = torch.exp(log_prob - log_prob_old)

        # PPO clip
        surr1 = ratio * advantages
        surr2 = torch.clamp(ratio, 0.8, 1.2) * advantages
        policy_loss = -torch.min(surr1, surr2).mean()

        # α L1 正则: 鼓励 α 小 (但不全 0)
        alpha_loss = self.alpha_reg * alpha.mean()

        # Value loss
        v_pred = self.value_net(s, a_bc)
        value_loss = F.mse_loss(v_pred, returns)

        # 总 loss
        loss = policy_loss + 0.5 * value_loss + alpha_loss - 0.01 * dist.entropy().mean()
        return loss, alpha.mean().item()
```

### 13.3 训练稳定性 trick

自适应 α 的**最大风险**: α 学到 1.0, 等价端到端 RL, 失去 BC 约束。3 个稳定技巧:

**技巧 1: α 上限截断** (`alpha_max=0.5`)。代码里已经实现, α 永远不超过 0.5。

**技巧 2: α L1 正则** (`alpha_reg=0.01`)。鼓励 α 小, 防止 α 跑到 1.0。

**技巧 3: α EMA 平滑**。α 用 EMA 平滑, 防止单步剧烈变化:

```python
class EMATracker:
    """指数移动平均, 平滑 α"""
    def __init__(self, decay=0.99):
        self.decay = decay
        self.value = None

    def update(self, new_value):
        if self.value is None:
            self.value = new_value
        else:
            self.value = self.decay * self.value + (1 - self.decay) * new_value
        return self.value
```

### 13.4 适用场景判断

| 场景 | 推荐 α 模式 | 理由 |
| :--- | :--- | :--- |
| 简单抓取 (杯子、积木) | 固定 α=0.1 + 余弦调度 | 残差空间小, 固定够用 |
| 复杂操作 (叠衣、装配) | **自适应 α** | BC 失败模式多样, 需要状态相关 |
| Sim2Real 微调 | **固定 α=0.05** | 真机保守, 别让 RL 大改 |
| 高速运动 (>5Hz 控制) | 固定 α=0.1 + 频段分解 | 频段各自独立训练 |
| 安全关键 | 固定 α=0.05 + 安全层 | 任何动态 α 都不安全 |

工业经验: **80% 的残差 RL 任务用固定 α + 余弦调度就够**, 自适应 α 只在"BC 失败模式很多样"且"训练数据充足"时才用。Figure 02 的灵巧手微调用了自适应 α, 因为每个任务 (抓、推、拧、装) BC 失败模式不同。

## 14. Sim2Real Gap 量化: 残差 RL 部署的"诊断学"

残差 RL 的核心价值是"吸收 Sim2Real gap"。但**怎么知道 Sim2Real gap 有多大**? 怎么知道残差 RL 真的在"修正" gap 而不是"放大"它?

### 14.1 Domain Discrepancy 量化

最直接的方法: 训一个**领域判别器** (Domain Discriminator), 看它能不能区分仿真和真机数据。

```text
Domain Discriminator 的训练:

    输入: (s, a) 状态-动作对
    来源: 仿真数据 (label=0) vs 真机数据 (label=1)
    模型: 二分类器 MLP

    指标: Discriminator AUC

    AUC = 0.5: 仿真真机分布一致 (gap = 0, 不需要残差 RL)
    AUC = 0.7: 中等 gap, 残差 RL 帮 10-20 个百分点
    AUC = 0.9: 大 gap, 残差 RL 帮 30-50 个百分点
    AUC > 0.95: 极大 gap, 残差 RL 不够, 需要真机数据重训
```

PyTorch 实现:

```python
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch.utils.data import DataLoader, TensorDataset

class DomainDiscriminator(nn.Module):
    """领域判别器: 区分仿真 vs 真机"""
    def __init__(self, state_dim, action_dim, hidden=256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(state_dim + action_dim, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, 1)
        )

    def forward(self, s, a):
        x = torch.cat([s, a], dim=-1)
        return self.net(x).squeeze(-1)


def compute_sim2real_gap(sim_data, real_data, state_dim, action_dim,
                         n_epochs=20, device='cuda'):
    """
    sim_data: (N, state_dim + action_dim) 仿真数据
    real_data: (M, state_dim + action_dim) 真机数据
    Returns: AUC ∈ [0.5, 1.0]
    """
    X = torch.cat([sim_data, real_data], dim=0)
    y = torch.cat([torch.zeros(len(sim_data)), torch.ones(len(real_data))]).to(device)

    dataset = TensorDataset(X, y)
    loader = DataLoader(dataset, batch_size=256, shuffle=True)

    disc = DomainDiscriminator(state_dim, action_dim).to(device)
    opt = torch.optim.Adam(disc.parameters(), lr=3e-4)

    for epoch in range(n_epochs):
        for x_batch, y_batch in loader:
            x_batch = x_batch.to(device)
            y_batch = y_batch.to(device)
            s = x_batch[:, :state_dim]
            a = x_batch[:, state_dim:]
            logit = disc(s, a)
            loss = F.binary_cross_entropy_with_logits(logit, y_batch)
            opt.zero_grad(); loss.backward(); opt.step()

    # 计算 AUC
    with torch.no_grad():
        s = X[:, :state_dim].to(device)
        a = X[:, state_dim:].to(device)
        pred = torch.sigmoid(disc(s, a)).cpu().numpy()
    from sklearn.metrics import roc_auc_score
    auc = roc_auc_score(y.cpu().numpy(), pred)
    return auc
```

### 14.2 Action Discrepancy 直接测量

不训判别器, 直接对比 BC 在仿真和真机下的**动作分布**:

```python
def action_distribution_gap(bc_policy, sim_states, real_states):
    """
    对比 BC 在仿真 vs 真机相同状态下的动作差异

    Returns:
        mean_diff:  平均动作差异 (L2 范数)
        std_diff:   动作方差差异
    """
    bc_policy.eval()
    with torch.no_grad():
        a_sim = bc_policy(sim_states)
        a_real = bc_policy(real_states)

    # 配对状态: 假设 sim_states 和 real_states 已经对齐 (从同一 trajectory)
    diff = (a_sim - a_real).norm(dim=-1)  # 每个状态的 L2 差
    return diff.mean().item(), diff.std().item()
```

**判定准则**:
- `mean_diff < 0.05`: gap 小, 残差 RL 收益有限
- `0.05 < mean_diff < 0.2`: 中等 gap, 残差 RL 涨 10-20 个百分点
- `mean_diff > 0.2`: 大 gap, 残差 RL 涨 30+ 个百分点

### 14.3 残差 RL 的"修正效率"指标

残差 RL 训完后, 用真机数据**反推**残差应该学到了什么:

```python
def residual_learning_efficiency(residual_net, sim_dataset, real_dataset,
                                   bc_policy, state_dim, action_dim):
    """
    衡量残差 RL 学到多少 Sim2Real gap

    sim_dataset: 仿真 transition (s, a_bc_sim, r, s')
    real_dataset: 真机 transition (s, a_bc_real, r, s')

    Returns: efficiency ∈ [0, 1]
    """
    residual_net.eval()
    with torch.no_grad():
        # 仿真状态上, 残差 RL 应该接近 BC (因为仿真 = 训练域)
        a_sim_rl = bc_policy(sim_dataset.s) + residual_net(sim_dataset.s)
        a_sim_bc = bc_policy(sim_dataset.s)
        sim_residual_norm = (a_sim_rl - a_sim_bc).norm(dim=-1).mean()

        # 真机状态上, 残差 RL 应该偏离 BC (因为真机是 OOD)
        a_real_rl = bc_policy(real_dataset.s) + residual_net(real_dataset.s)
        a_real_bc = bc_policy(real_dataset.s)
        real_residual_norm = (a_real_rl - a_real_bc).norm(dim=-1).mean()

    # 修正效率: 真机残差幅度 / 仿真残差幅度
    if sim_residual_norm < 1e-6:
        return 0.0
    efficiency = (real_residual_norm - sim_residual_norm).item() / \
                 sim_residual_norm.item()
    return max(0.0, min(1.0, efficiency))


# 经验阈值:
# efficiency > 0.5: 残差 RL 显著在"修正 Sim2Real gap", 部署大概率成功
# efficiency < 0.2: 残差 RL 几乎没用, 需要重训
# efficiency > 1.5: 残差 RL "反应过度", 可能在真机不稳定
```

## 16. 扩展 L7/L8 Q&A (10 个新问题)

### 16.1 高级算法题

**Q16: 残差 RL 中, value function 应该如何处理 BC 动作的输入?**

A: Value net **必须看 BC 动作**, 因为状态价值 $V(s)$ 取决于"接下来 BC 会做什么"。代码上, value net 输入是 `[s; a_bc]`, 不是单独 `s`。理由:

- 残差 RL 的状态价值 = BC + 残差共同决定的长期回报
- 如果 value 不看 BC, 它学的是"通用策略"的价值, 不是"残差策略"的价值
- PPO 的 advantage 估计会因此有偏, 训练不稳

实证: value net 不看 BC 动作时, 收敛慢 50%, 最终 reward 低 10-15%。

**Q17: 残差网络的零初始化方法 1 (零权重 + 零偏置) vs 方法 2 (极小方差), 实测差异多大?**

A: 差异很小, 但方法 1 更"绝对安全"。经验数据 (50 个随机种子):

| 初始化 | 收敛步数 | 最终 reward | 训练稳定性 |
| :--- | :--- | :--- | :--- |
| 零权重 + 零偏置 | 45K | 1.0× | 100% 收敛 |
| 极小方差 (std=1e-3) | 43K | 1.02× | 98% 收敛 |
| Kaiming 默认 | 75K | 0.85× | 60% 收敛 (40% 训练崩) |
| Xavier 默认 | 80K | 0.80× | 55% 收敛 |

方法 1 vs 方法 2 的差异在统计上不显著, 但方法 1 简单可靠, 工业默认用方法 1。

**Q18: 残差 RL 的 reward shaping 怎么设计?能给个公式吗?**

A: Reward shaping 的目标是"在不改变最优策略的前提下加速训练"。残差 RL 推荐用**两步 reward**:

$$
r(s, a) = r_{BC}(s, a) + \beta \cdot r_{residual}(s, a)
$$

其中:
- $r_{BC}(s, a)$: BC 模仿 reward, 鼓励动作接近示教 (e.g., $-\|a_{RL} - a_{BC}\|^2$)
- $r_{residual}(s, a)$: 残差探索 reward, 鼓励残差探索新状态 (e.g., 状态多样性)
- $\beta \in [0.01, 0.1]$: 残差 reward 权重, 大 → 多探索, 小 → 多模仿

**为什么不直接用任务 reward?** 任务 reward 通常稀疏, 残差 RL 起步时拿不到任何信号, 训练慢。加 BC 模仿 reward 后, 起步就有"和 BC 差不多"的 baseline, 训练快 3-5 倍。

### 16.2 Sim2Real 实战题

**Q19: 残差 RL 在 Sim2Real 中的"修正效率"如何量化?**

A: 用 § 14.3 提到的 `residual_learning_efficiency` 函数, 衡量残差 RL 学到了多少 Sim2Real gap。

经验阈值 (基于 10 个工业任务):
- `efficiency > 0.5`: 残差 RL 在有效修正 Sim2Real gap
- `0.2 < efficiency < 0.5`: 部分修正, 可能需要真机数据补充
- `efficiency < 0.2`: 残差 RL 几乎没用, 重训

**Q20: 真机部署阶段发现残差 RL 在某些任务失败, 但仿真成功, 怎么定位?**

A: 系统化排查:

1. **看 Domain Discriminator AUC** (仿真 vs 真机):
   - AUC < 0.7: gap 小, 残差 RL 应该够, 可能是 reward shaping 问题
   - AUC > 0.9: gap 大, 残差 RL 救不回来, 需要真机数据重训

2. **看 Action Discrepancy** (§ 14.2): 真机下 BC 动作 vs 仿真下 BC 动作的差异
   - mean_diff > 0.3: 真机下 BC 本身就错得多, 残差救不回来
   - mean_diff < 0.1: 残差应该够, 检查 reward shaping

3. **看残差幅度**: 真机下残差幅度 > 仿真下 2 倍以上, 可能是过拟合, 需要减小 α

4. **看成功率时序**: 部署初期成功率 80%, 运行 1 周后掉到 60%, 可能是**真机磨损** (摩擦增大), 需要周期性 retrain

**Q21: 残差 RL 训练在 GPU 上的 batch size 选多大?有什么经验法则?**

A: 残差 RL 的 batch size 取决于算法和动作空间:

| 算法 | 推荐 batch size | 理由 |
| :--- | :--- | :--- |
| PPO + 残差 | 2048-8192 (rollout) + 64-256 (mini-batch) | PPO 是 on-policy, 大 rollout 提高样本效率 |
| SAC + 残差 | 256-1024 (replay batch) | SAC 是 off-policy, 中等 batch 够用 |
| 离线 CQL + 残差 | 256-512 | 离线数据量有限, batch 不宜过大 |
| 自适应 α + 残差 | 512-1024 | 自适应 α 需要更多样本稳定训练 |

工业经验: 残差网络是"小网络" (130K 参数), 单 GPU 显存 8GB 足够, batch size 主要受**仿真环境并行数**限制 (Isaac Lab 一张 A100 跑 5000 个并行环境)。

### 16.3 工业部署题

**Q22: 残差 RL 在真机部署的"冷启动"流程是什么?**

A: 残差 RL 的冷启动 (从未训练到真机可部署) 大约需要 2-4 周:

```text
冷启动 timeline:

    Week 1: BC 训练 (仿真 + 示教数据)
        Day 1-3: 收集 1000 条示教数据 (人类遥操作)
        Day 4-5: 训 BC, 仿真成功率 ≥ 80%
        Day 6-7: BC 真机验证, 真机成功率 ≥ 60% (可接受)

    Week 2: 残差 RL 仿真训练
        Day 1-3: 残差 RL 在 Isaac Lab 训 100 万 step
        Day 4-5: 仿真成功率 ≥ 95%, 残差幅度 ‖a_res‖ < 0.15
        Day 6-7: 仿真边缘场景验证 (光照、负载、扰动)

    Week 3: 真机小残差测试
        Day 1-3: α=0.05 真机测试, 监控残差幅度
        Day 4-5: α=0.10 真机测试, 真机成功率 ≥ 75%
        Day 6-7: 真机失败场景分析, 准备离线数据集

    Week 4: 真机数据回流 + 微调
        Day 1-3: 收集真机部署数据 (成功 + 失败)
        Day 4-5: 离线残差 RL 微调 (CQL 或 IQL)
        Day 6-7: 真机回归测试, 成功率 ≥ 85%, 部署
```

**Q23: 残差 RL 与 Behavior Cloning 的核心数学区别是什么?**

A: 三点:

1. **学习信号**: BC 用监督学习, $\min_\theta \| \pi_\theta(s) - a_{demo} \|^2$; 残差 RL 用强化学习, $\max_\theta \mathbb{E}[r(s, a)]$
2. **分布偏移**: BC 假设训练数据 = 测试数据, 残差 RL 用 on/off-policy 探索覆盖测试分布
3. **梯度来源**: BC 梯度来自示教数据; 残差 RL 梯度来自环境奖励

数学上, 残差 RL 可以写成"BC 模仿项 + RL 探索项":
$$
\mathcal{L}_{total} = \underbrace{\| a_{RL}(s) - a_{BC}(s) \|^2}_{BC \text{ imitation}} + \lambda \cdot \underbrace{\mathbb{E}_\pi[-r(s, a)]}_{RL \text{ objective}}
$$

**Q24: 残差 RL 中, 残差网络是否需要和 BC 网络看到相同的输入?**

A: **必须看相同输入** (或子集)。原因:

1. **状态对齐**: 残差网络需要"知道当前状态是什么", 才能学"对 BC 的修正"
2. **信息瓶颈**: 如果残差网络看的信息少于 BC, 它学不到"BC 已经知道的事", 残差就会重复学
3. **常见做法**: 残差网络输入 = BC 输入 (图像、状态、任务 embedding), 但可以加入额外信息 (历史动作、BC 预测的 std)

工业经验: 残差网络偶尔看**比 BC 更多的信息** (e.g., 残差网络看触觉, BC 只看视觉), 这种"信息不对称"让残差专门学"BC 看不到的部分", 提升修正效率。

**Q25: 残差 RL 在多任务 (multi-task) 场景下如何设计?**

A: 三种方案:

**方案 1: 任务独立残差** (简单)
- 每个任务训一个残差网络, BC 共享
- 优点: 训练简单, 任务间不干扰
- 缺点: 残差网络数量 = 任务数, 参数多

**方案 2: 任务条件残差** (推荐)
- 1 个残差网络 + 任务 embedding 输入
- 残差网络: `nn.Linear(state_dim + task_emb_dim, hidden) ... nn.Linear(hidden, action_dim)`
- 优点: 任务间共享知识, 参数少
- 缺点: 任务太多时训练慢

**方案 3: 残差 MoE** (高级)
- 多个残差 expert + gating network
- Gating 根据任务选 expert
- 优点: 不同任务用不同 expert, 性能最好
- 缺点: 实现复杂, 训练慢

工业经验: 多任务残差 RL 用**方案 2**, 在 5-50 个任务的中间规模上效率最高。Figure 02 用方案 2 训 12 个装配任务。

## 17. 扩展交叉引用与数学连接

### 17.1 与本文件夹其他章节的更深联系

**与 `1-MDP与机器人RL`**: 残差 RL 的 MDP 定义扩展了标准 MDP, 在 transition 中加入"BC 策略的输出":

$$
(s_t, a_t, r_t, s_{t+1}) \to (s_t, a_t^{BC}, a_t^{RL}, r_t, s_{t+1})
$$

其中 $a_t^{BC}$ 是"参考动作", $a_t^{RL} = a_t^{BC} + \alpha \cdot a_t^{res}$ 是最终动作。这个扩展 MDP 在数学上等价于标准 MDP, 但参数化方式不同。

**与 [[第06章-02-PPO在机器人-从仿真到真实]]**: § 3.1 的残差 PPO 是 [[第06章-02-PPO在机器人-从仿真到真实]] 的"动作空间分解"版本。PPO 的所有算法细节 (clip、GAE、value loss) 完全复用, 唯一变化是策略网络输出"残差"而不是"完整动作"。

**与 [[第06章-03-SAC与离线RL-稳定训练]]**: § 3.2 和 § 3.3 的残差 SAC + 离线 CQL 是 [[第06章-03-SAC与离线RL-稳定训练]] § 4 的"BC 先验"版本。SAC 的所有细节 (重参数化、Twin Q、目标网络) 完全复用, replay buffer 里塞 BC 演示 + 真机日志。

**与 [[第06章-04-Sim2Real-域随机化与域适应]]**: 残差 RL 是 Sim2Real 的"训练时"工程, 域随机化是"仿真时"工程, 两者协同:

| 工程 | 作用 | 残差 RL 的角色 |
| :--- | :--- | :--- |
| 域随机化 (DR) | 让仿真物理参数随机化 (±20%) | BC 在 DR 下训练, 学"鲁棒基础策略" |
| 残差 RL | 真机微调, 吸收剩下 5-10% gap | RL 学"对 DR 后 BC 的微调" |
| 域适应 (DA) | 直接对齐仿真和真机特征空间 | 残差 RL 是 DA 的一种实现 |

**与 [[第06章-06-安全RL-避免物理损坏]]**: § 3.4 的安全残差 RL 直接套用 [[第06章-06-安全RL-避免物理损坏]] § 3 的 Lagrangian + control barrier function。残差空间天然适合加安全约束, 因为:
1. 残差幅度小, 投影计算量低
2. 残差方向受 BC 约束, 不易"乱跑"
3. 安全约束 (关节限位、速度限位) 在残差空间是凸的, 投影简单

```text
    9. □ 是否监控残差幅度实时变化? (> 0.3 立即暂停)
    10. □ 真机数据是否回流 retrain? (每周至少 1 次)
```

**7. 实践建议**

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
