## 1. 直觉引入:为什么机器人 RL 需要安全

### 1.1 为什么机器人 RL 需要安全?

回到 [[第06章-02-PPO在机器人-从仿真到真实]] §1.2 的工程场景: 直接把 PPO 训的策略放到真机上跑, **几乎肯定出事**。但为什么"几乎"?

仿真环境是"宽容的"。Isaac Gym 里, 关节力矩超限只触发一个报错码, 仿真器仍然在跑。真实机器人上, 同样的力矩会触发**物理破坏**:

```text
仿真里 "超限" 的代价:

  关节力矩超限    →  Isaac Gym 抛 warning, 继续跑
  关节速度超限    →  状态被裁剪到上限, 仿真照常
  接触穿透        →  接触力变 0, 没有物理后果

真机上 "超限" 的代价:

  关节力矩超限    →  驱动器过流保护, 严重时烧电机
                   ↓ 5-10 万 / 关节 + 2-4 周返厂
  关节速度超限    →  减速器磨损, 半年内精度下降
                   ↓ 1-2 万 / 减速器
  接触穿透        →  撞坏末端执行器, 抓取机构卡死
                   ↓ 0.5-2 万 / 次 + 3-7 天维修
```

**仿真和真机的关键差异**: 仿真器是"无成本的可逆环境", 真机是"有成本的物理实体"。这意味着**所有在仿真里看起来"无害"的事情, 真机上都是真金白银的代价**。

机器人 RL 工程师的"安全感"来自 3 个层次:

```text
机器人 RL 安全防御的三层:

  ┌─────────────────────────────────────────────────┐
  │ Layer 1: 算法层 (训练时)                          │
  │  - CMDP 约束优化                                 │
  │  - Lagrangian 方法 + 对偶变量 λ                  │
  │  - 让策略 "主动" 学习满足约束                    │
  │  重点: 训练时 0 违反 (仿真中)                     │
  └─────────────────────────────────────────────────┘
                    ↓
  ┌─────────────────────────────────────────────────┐
  │ Layer 2: 安全层 (部署时, 算法外)                  │
  │  - 控制屏障函数 (CBF)                            │
  │  - Hamilton-Jacobi 到达性                        │
  │  - 把策略动作投影到 "安全集合" 上                 │
  │  重点: 部署时 0 违反 (硬约束, 兜底)              │
  └─────────────────────────────────────────────────┘
                    ↓
  ┌─────────────────────────────────────────────────┐
  │ Layer 3: 硬件层 (物理防护)                       │
  │  - 急停按钮 / 物理限位                            │
  │  - 电流保护 / 速度保护                            │
  │  - 人在回路 (HITL) / 遥操作                      │
  │  重点: 万一算法层 + 安全层都失败, 物理兜底        │
  └─────────────────────────────────────────────────┘
```

**这一章聚焦 Layer 1 + Layer 2**, Layer 3 是机械/电气工程范畴, 不展开。

### 1.2 物理损坏的成本:为什么不是"加个负权重就完事"

最直觉的安全方案: **在 reward 里加个负权重**。

```python
# 朴素方案: 把关节力矩超限做成 reward 惩罚
def reward_fn(state, action):
    torque_penalty = -10.0 * max(0, abs(action.tau) - tau_max).sum()
    return task_reward(state) + torque_penalty
```

这个方案 80% 的工程师会想, 但有 3 个根本缺陷:

**缺陷 1: 阈值附近的策略不稳定**

```python
# 训练中常见的 "在边界上抖动":
τ = 49.9 N·m   (上限 50 N·m)    ✓ 拿到 +0.1 reward
τ = 50.1 N·m   (超限 0.1 N·m)   ✗ 拿到 -1.0 reward (惩罚 10x)
```

策略会在阈值附近**反复横跳**: 时超时不超, reward 信号抖动, 训练不稳定。

**缺陷 2: 严重违反时, reward 信号被淹没**

抓取任务 reward = 100, 撞墙一次 penalty = -10。**一次撞墙只占 reward 的 10%**, 策略可能"觉得撞墙 10 次换一个抓取成功"划算。

```text
reward 信号失真:

  task_reward 范围:     [-1, 100]
  safety_penalty 范围:  [-10, 0]  (单步)
  ──────────────────────────────────
  整个 episode safety_penalty 累积:  [-200, 0]
  一次撞墙:    100 - 10 = 90   (仍然吸引人)
  5 次撞墙:    100 - 50 = 50   (仍然吸引人)
  结论:       "撞墙" 相对 task reward 太便宜
```

**缺陷 3: 真机无法承担 "学习期违反"**

仿真里违反 1000 次无所谓。真机违反 1 次就是 5 万。**reward shaping 需要探索, 探索就需要违反**——这在真机上根本不允许。

**正确做法: 把安全约束写成硬约束 (hard constraint)**。

$$
\begin{aligned}
\max_\pi \quad & \mathbb{E}_\pi \left[ \sum_t \gamma^t r(s_t, a_t) \right] \\
\text{s.t.} \quad & \mathbb{E}_\pi \left[ \sum_t \gamma^t c_i(s_t, a_t) \right] \le d_i, \quad \forall i = 1, \dots, m
\end{aligned}
$$

这就是**受限马尔可夫决策过程 (CMDP, Constrained MDP)**, 由 Altman (1999) 给出形式化定义。下一节详谈。

### 1.3 协作机器人的安全标准:ISO/TS 15066

真实部署时, 安全不是工程师的主观判断, 而是有**国际标准**。协作机器人 (cobot) 领域最重要的标准是 **ISO/TS 15066** (2016), 它给出 4 类安全要求:

```text
ISO/TS 15066 的 4 类协作操作:

  1. Safety-Rated Monitored Stop (SRMS)
     - 机器人检测到人进入工作区, 立即停机
     - 适用: 大部分工业 cobot 场景
     - 实现: 安全 PLC + 力矩传感

  2. Hand Guiding (HG)
     - 人手直接引导机器人运动
     - 适用: 教学、精密装配
     - 实现: 末端力传感器 + 阻抗控制

  3. Speed and Separation Monitoring (SSM)
     - 人和机器人保持最小距离, 速度受距离约束
     - 适用: 共享工作空间
     - 实现: 视觉/雷达定位 + 在线速度调整

  4. Power and Force Limiting (PFL)
     - 限制机器人的功率和力, 即使碰撞也不伤人
     - 适用: 紧密协作
     - 实现: 关节力矩限制 + 软甲覆盖
```

**关键数值 (PFL 模式)**:

- 准静态接触力 ≤ 65 N (头部), 140 N (四肢)
- 动态碰撞能量 ≤ 0.5 J
- 最大速度 ≤ 250 mm/s

**这意味着 RL 策略必须满足的硬约束**:

$$
\|F_{\text{contact}}\|_2 \le F_{\max}, \quad F_{\max} = 65 \text{ N (头部)}
$$

$$
\|\dot{x}_{\text{robot}}\|_2 \le v_{\max}, \quad v_{\max} = 250 \text{ mm/s}
$$

$$
\|\tau_i\|_2 \le \tau_{\max}, \quad \tau_{\max} = 50 \text{ N·m (典型 cobot)}
$$

这些不是"建议", 是**法律层面的安全要求**。违反导致产品无法通过 CE 认证, 不能在欧盟销售。

**对 RL 工程师的含义**: 策略训练时, 这些约束必须**在仿真阶段就强制**。不能寄希望于"真机调试时修一下"。

## 2. 受限马尔可夫决策过程 (CMDP)

### 2.1 CMDP 的形式化定义

**CMDP (Constrained Markov Decision Process)** 由 Altman (1999) 提出, 是 MDP 的扩展。它在标准 MDP 五元组 $(\mathcal{S}, \mathcal{A}, P, r, \gamma)$ 基础上, 加上**成本函数**和**约束阈值**:

$$
\text{CMDP} = (\mathcal{S}, \mathcal{A}, P, r, \{c_i\}_{i=1}^m, \{d_i\}_{i=1}^m, \gamma)
$$

其中:
- $\mathcal{S}$: 状态空间
- $\mathcal{A}$: 动作空间
- $P(s'|s, a)$: 状态转移概率
- $r: \mathcal{S} \times \mathcal{A} \to \mathbb{R}$: 任务奖励
- $c_i: \mathcal{S} \times \mathcal{A} \to \mathbb{R}_{\ge 0}$: 第 $i$ 个成本 (cost)
- $d_i \in \mathbb{R}_{\ge 0}$: 第 $i$ 个约束的阈值 (budget)
- $\gamma$: 折扣因子

**目标**:

$$
\begin{aligned}
\pi^* = \arg\max_\pi \quad & J_r(\pi) = \mathbb{E}_{\tau \sim \pi} \left[ \sum_{t=0}^{T} \gamma^t r(s_t, a_t) \right] \\
\text{s.t.} \quad & J_{c_i}(\pi) = \mathbb{E}_{\tau \sim \pi} \left[ \sum_{t=0}^{T} \gamma^t c_i(s_t, a_t) \right] \le d_i, \quad i = 1, \dots, m
\end{aligned}
$$

**关键差异 vs MDP**:

| 维度 | MDP | CMDP |
| :--- | :--- | :--- |
| 优化目标 | 1 个 (最大化累积奖励) | 1 个目标 + $m$ 个约束 |
| 解的性质 | 最优策略 (可能有多个) | 满足约束的最优策略 (可行域内的最优) |
| 训练方法 | 策略梯度、值迭代 | Lagrangian 对偶、信赖域约束 |
| 物理含义 | 没有"不允许的事" | 有"硬约束" (关节力矩上限、碰撞力上限) |

**机器人上的典型 cost 函数**:

```python
# 关节力矩约束 (cost = 超限量)
c_torque(s, a) = max(0, |a.tau| - tau_max).sum()

# 关节速度约束
c_velocity(s, a) = max(0, |s.qdot| - qdot_max).sum()

# 工作空间约束 (末端超出可达范围)
c_workspace(s, a) = max(0, ||s.x_ee|| - workspace_radius)

# 接触力约束 (协作机器人碰撞力)
c_contact(s, a) = max(0, ||s.F_contact|| - F_max_safe)
```

**约束阈值 $d_i$ 的工程取值**:

| 约束类型 | 阈值 $d_i$ 的物理含义 | 典型值 |
| :--- | :--- | :--- |
| 关节力矩 | 单 episode 内允许的超限量 (N·m·s) | 0.1 × τ_max × T |
| 关节速度 | 单 episode 内允许的超限量 (rad·s) | 0.05 × qdot_max × T |
| 接触力 | 单 episode 内允许的超限次数 | 0 (ISO/TS 15066 严格) |
| 工作空间 | 单 episode 内允许的越界次数 | 0 |

**为什么 $d_i$ 通常设为 0**: 真实机器人场景下, 任何超限都可能造成物理损坏。工程上**默认 $d_i = 0$**, 即"零违反"约束。

### 2.2 状态约束 vs 动作约束

CMDP 的约束按发生时机分两类:

**类型 1: 动作约束 (action constraint)**

约束**只涉及当前状态-动作对**, 与未来无关:

$$
c_i(s, a) \le d_i^{\text{step}}
$$

例: 关节力矩 $|\tau_i| \le \tau_{\max}$, 关节速度 $|\dot{q}_i| \le \dot{q}_{\max}$

动作约束的工程优势:

- **容易检测**: 单步检查, 不需要时间序列
- **容易实施**: 安全层 (CBF) 可以直接投影动作
- **训练友好**: 策略网络的输出可以直接 clip

动作约束的局限:

- **不约束轨迹**: 允许策略走到 "下一步必然违反" 的状态
- 例: 末端速度 1.9 m/s (未超 2 m/s 限), 但加速度 5 m/s², 0.05 秒后必超限

**类型 2: 状态约束 (state constraint)**

约束**只涉及状态**, 与动作无关:

$$
c_i(s) \le d_i^{\text{state}}
$$

例: 末端不能进入禁区、关节角不能超过机械限位

状态约束的工程挑战:

- **依赖动力学**: "现在不违反" 不等于 "未来不违反", 需要前向预测
- **需要 CBF 或 reachability**: 见 §3

**机器人上通常混用**:

```text
一个完整的协作机器人 CMDP:

  状态约束 (state):
    - 末端不能进入 "人活动区域"
    - 关节角不能超机械限位
    - 接触力不能超过 65 N

  动作约束 (action):
    - 关节力矩不能超驱动器限制
    - 关节速度不能超减速器限制
    - 单步加速度不能超电机响应能力

  → 训练时: 状态约束用 Lagrangian, 动作约束用 clip
  → 部署时: 状态约束用 CBF, 动作约束用物理限位
```

### 2.3 Lagrangian 方法:约束优化的标准武器

**CMDP 的标准解法是 Lagrangian 对偶**, 把约束优化转成 min-max 问题:

$$
\min_{\lambda \ge 0} \max_{\theta} \quad L(\theta, \lambda) = J_r(\theta) - \sum_{i=1}^{m} \lambda_i \left( J_{c_i}(\theta) - d_i \right)
$$

其中 $\lambda_i$ 是**对偶变量** (Lagrangian 乘子)。

**直观解释**:

- **内层 $\max_\theta$**: 固定 $\lambda$, 最大化对偶目标 (强化学习子问题)
- **外层 $\min_\lambda$**: 调整 $\lambda$, 让"违反量"等于 $d_i$

**对偶变量 $\lambda_i$ 的物理含义**: **违反约束的"价格"**。

- $\lambda_i$ 大 → 违反约束很"贵" → 策略主动避免
- $\lambda_i$ 小 → 违反约束"便宜" → 策略不care
- $\lambda_i = 0$ → 第 $i$ 个约束"没用"

**几何直觉**: 把约束想成"墙壁", 目标函数想成"等高线"。

```text
CMDP 的 Lagrangian 几何 (二维示意):

  J_r(θ) 等高线 (目标函数)
  ↗ ↗ ↗ ↗ ↗ ↗ ↗ ↗ ↗
  ↗ ↗ ↗ ↗ ↗ ↗ ↗ ↗
  ───────────────────── 约束边界: J_c(θ) = d
  ↘ ↘ ↘ ↘ ↘ ↘ ↘ ↘
  ↘ ↘ ↘ ↘ ↘ ↘ ↘ ↘ ↘

  左上区域 (约束满足, 目标最大) = 最优点
  左下区域 (约束满足, 目标小) = 次优解
  右上区域 (约束违反)         = 不可行
```

**对偶更新规则** (Paternain et al., 2019):

$$
\lambda_i \leftarrow \left[ \lambda_i + \eta_\lambda \cdot \left( J_{c_i}(\theta) - d_i \right) \right]_+
$$

其中 $[\cdot]_+ = \max(\cdot, 0)$ 保证 $\lambda_i \ge 0$。这是一个**梯度上升** (违反越多, $\lambda$ 涨越大)。

**为什么这能收敛** (在标准条件下):

如果策略类是充分丰富的 (universal function approximator), 且学习率足够小, Lagrangian 方法**收敛到 KKT 点**:

- $J_{c_i}(\theta^*) \le d_i$ (约束满足)
- $\lambda_i^* (J_{c_i}(\theta^*) - d_i) = 0$ (互补松弛)
- $\nabla_\theta L = 0$ (Lagrangian 稳定)

**收敛速率**: 通常 PPO 收敛后再训 Lagrangian 1-3 倍时间达到约束满足。OpenAI Safety Gym (2020) 报告: Hopper 速度约束 $\lambda$ 收敛约需 5M 步。

### 2.4 约束 PPO (CPPO):算法细节

**CPPO (Constrained PPO)** 是 PPO + Lagrangian 的组合。最早由 OpenAI Safety Gym (Achiam et al., 2020) 给出标准实现。

**算法流程**:

```python
# CPPO 单步更新 (简化)
for iteration in range(N):
    # 1. 采样 (用当前策略)
    traj = env.rollout(pi_theta, n_steps=2048)

    # 2. 计算 task advantage (标准 PPO 的 GAE)
    adv_r = gae(traj.rewards, traj.values, gamma=0.99, lam=0.95)

    # 3. 计算 cost advantage (成本版本的 GAE)
    adv_c = gae(traj.costs, traj.values_c, gamma=0.99, lam=0.95)

    # 4. 计算当前 cost 的平均值 (估计 J_c)
    J_c = traj.costs.sum() / traj.steps  # episode 平均 cost

    # 5. 更新 Lagrangian 乘子
    lambda_new = max(0, lambda_old + eta_lambda * (J_c - d))

    # 6. 计算 CPPO 目标 (PPO clip + cost penalty)
    for epoch in range(K):
        for mb in minibatches(traj):
            ratio = exp(logp_new - logp_old)
            # Task objective (标准 PPO clip)
            surr_task = min(ratio * adv_r, clip(ratio, 1-eps, 1+eps) * adv_r)
            # Cost objective (惩罚违反)
            surr_cost = min(ratio * adv_c, clip(ratio, 1-eps, 1+eps) * adv_c)
            # Lagrangian 组合
            loss = -(surr_task - lambda_new * surr_cost).mean()
            loss.backward(); opt.step()
```

**核心修改 (vs 标准 PPO)**:

1. **多一个 critic**: $V_c(s)$ 估计 cost value (代替 reward value 的"成本版")
2. **多一个 advantage**: $\hat{A}_c$ 用 cost 计算 GAE
3. **多一个 Lagrangian 乘子**: $\lambda$ 在策略更新后调整
4. **目标函数加 cost 项**: $-\lambda \cdot \mathbb{E}[\pi \cdot A_c]$

**关键超参** (OpenAI Safety Gym 默认值):

| 超参 | 默认值 | 含义 |
| :--- | :--- | :--- |
| $\eta_\lambda$ | 0.01 | Lagrangian 学习率 |
| $\lambda_{\max}$ | 50 | Lagrangian 上限 (防止数值爆炸) |
| $V_c$ 系数 | 0.5 | Cost value loss 权重 |
| Cost discount $\gamma_c$ | 0.99 | Cost 折扣因子 (可与 reward 不同) |

**训练曲线示例** (Safety Gym Hopper 速度约束):

```text
CPPO 训练曲线 (示意):

  Task reward ↑                 Cost ↓
       │                            │
   3000├        ╱─────────       50├──╲
       │      ╱                  40│   ╲
   2000├    ╱                   30│    ╲___
       │  ╱                     20│        ╲──╲
   1000├╱                       10│             ╲───
       │                        0├─────────────────
       └──────────── steps        └──────────── steps
         0  1M  2M  3M  4M         0  1M  2M  3M  4M

  注意: reward 在 2M 步后收敛, cost 同步下降到阈值附近
```

**Lagrangian 乘子 $\lambda$ 的演化**:

```text
λ 演化曲线 (示意):

  λ
  50├──────────────────  ← 上限, 防止爆炸
   │
  40├         ╱─────
   │       ╱
  30├     ╱
   │   ╱
  20├ ╱
   │╱
  10├
   │
   0└──────────────────── steps
     0  1M  2M  3M  4M  5M

  - 早期违反多, λ 快速增长
  - 中期策略学习避免违反, λ 下降
  - 后期稳定在某个值 (违反量 = 阈值附近)
```

**CPPO 在 Safety Gym 上的结果** (Achiam et al., 2020):

| 任务 | 约束 | CPPO 违反率 | PPO + 惩罚 违反率 |
| :--- | :--- | :--- | :--- |
| Hopper 速度 | $\|\dot{x}\| \le 2.0$ | 0.5% | 23% |
| Walker2d 速度 | $\|\dot{x}\| \le 1.5$ | 1.2% | 35% |
| Ant 力矩 | $\|\tau\| \le 0.5$ | 0.8% | 18% |
| Point 按钮 | 避开"危险区" | 0.3% | 12% |

### 2.5 约束 SAC (CSAC):off-policy 版本

**CSAC (Constrained SAC)** 是 SAC + Lagrangian, 由 Ha et al. (2020) 在 Safety Gym 同一时期提出。

**SAC 的特殊之处**: 最大熵框架天然鼓励探索, 加 Lagrangian 后效果比 CPPO 还稳 (off-policy 样本效率高)。

**CSAC 的目标**:

$$
\begin{aligned}
\max_\theta \quad & \mathbb{E}_{\tau \sim \pi_\theta} \left[ \sum_t \gamma^t \left( r(s_t, a_t) - \lambda \cdot c(s_t, a_t) + \alpha \cdot \mathcal{H}(\pi(\cdot | s_t)) \right) \right] \\
\text{where} \quad & \lambda \leftarrow \max(0, \lambda + \eta_\lambda (J_c - d))
\end{aligned}
$$

**和 CPPO 的关键差异**:

| 维度 | CPPO | CSAC |
| :--- | :--- | :--- |
| 数据效率 | on-policy, 低 | off-policy, 高 5-10 倍 |
| 训练稳定 | 中 (PPO 本身鲁棒) | 高 (SAC 的最大熵优势) |
| 实现复杂度 | 中 | 高 (双 Q + 温度自调节 + Lagrangian) |
| 样本效率 | 5-10 M 步 | 0.5-1 M 步 |
| 真机可用性 | 中 | 高 (样本效率 = 真机时间) |

**CSAC 的工程权衡**:

```python
# CSAC 单步更新 (简化, 与 SAC 相比多了 cost 部分)
for step in range(N):
    # 1. 从 replay buffer 采样
    s, a, r, c, s_next, done = buffer.sample(BATCH)

    # 2. 更新 Twin Q 网络 (标准 SAC)
    q1 = q1_net(s, a); q2 = q2_net(s, a)
    target = r + gamma * (min(q1_target, q2_target) + alpha * log_prob_next)
    q_loss = F.mse_loss(q1, target) + F.mse_loss(q2, target)

    # 3. 更新 Cost Q 网络 (CSAC 新增)
    qc = qc_net(s, a)  # cost value
    target_c = c + gamma_c * qc_target(s_next, a_next)
    qc_loss = F.mse_loss(qc, target_c)

    # 4. 更新 Lagrangian (CSAC 新增)
    lambda_new = max(0, lambda_old + eta_lambda * (qc.mean() - d))

    # 5. 更新策略 (重参数化 + Lagrangian 惩罚)
    a_new, log_prob = policy.sample(s)
    q_new = min(q1_net(s, a_new), q2_net(s, a_new))
    qc_new = qc_net(s, a_new)
    policy_loss = (alpha * log_prob - q_new + lambda_new * qc_new).mean()

    # 6. 更新温度 alpha (标准 SAC)
    alpha_loss = -alpha * (log_prob.detach() + target_entropy).mean()

    # 7. 反向传播
    q_loss.backward(); opt_q.step()
    qc_loss.backward(); opt_qc.step()
    policy_loss.backward(); opt_pi.step()
    alpha_loss.backward(); opt_alpha.step()
```

**CSAC 的双重 critic**: 一个学 reward ($Q_r$), 一个学 cost ($Q_c$)。这让策略同时考虑两个目标。

**Lagrangian 的更新时机**: 很多实现里, $\lambda$ 在每个 minibatch 后更新 (而不是 episode 后)。这让 $\lambda$ 反应更快, 但波动也更大。工程上常用:

- **保守**: episode 后更新 (噪声小, 反应慢)
- **激进**: minibatch 后更新 (反应快, 噪声大)
- **推荐**: 每 N=10 个 minibatch 更新一次 (平衡)

### 2.6 约束优化的工程细节

**坑 1: Lagrangian 乘子的初始值**

```python
# 推荐: 初始化 λ = 0, 让算法自己学习
lambda_init = 0.0

# 错误: 初始化 λ 太大, 训练一开始就压制探索
lambda_init = 10.0  # 训练 1M 步后才能稳定
```

**坑 2: Cost value 的初始化**

```python
# 标准 SAC 的 Q 网络初始化: 偏小 (避免高估)
def init_weights(m):
    if isinstance(m, nn.Linear):
        nn.init.uniform_(m.weight, -3e-3, 3e-3)

# Cost Q 必须独立初始化 (否则和 reward Q 耦合)
qc_net.apply(init_weights)  # 独立初始化
```

**坑 3: 多约束的 Lagrangian**

多约束时, 每个 $c_i$ 对应一个 $\lambda_i$, 独立更新:

```python
# 多约束 (例如: 力矩 + 速度 + 接触力)
n_constraints = 3
lambdas = [0.0] * n_constraints  # 每个约束一个

for i in range(n_constraints):
    J_c_i = estimate_cost(buffer, i)  # 第 i 个约束的累积 cost
    lambdas[i] = max(0, lambdas[i] + eta * (J_c_i - d[i]))
```

**Lagrangian 的"尺度"问题**: 不同 cost 的数量级差很大 (力矩 ~10, 速度 ~1, 接触力 ~50)。直接加和会让 $\lambda$ 的尺度失衡。**解决方案**: 每个 cost 先归一化到 [0, 1] 再加。

```python
# 归一化后的 cost
c_normalized = c_raw / c_max  # c_max 是该约束的理论最大违反
```

**坑 4: 约束满足 vs 任务性能**

满足约束的策略可能"过度保守": 不违反, 但任务完成度也低。

```text
策略光谱:

  极端保守                    极端激进
  ───────────────────────────────────
  │              │              │
  0 违反         10% 违反        50% 违反
  30% 任务       80% 任务        95% 任务
  成功率         成功率          成功率
  (避障为主)    (平衡)         (任务优先)
```

**工程目标**: 把策略推到约束边界附近 (违反量 ≈ 0, 但任务成功率最高)。这正是 Lagrangian 优化的目标: **在满足约束的前提下最大化任务奖励**。

## 3. 安全层 (Safety Layer)

### 3.1 为什么需要 Safety Layer?算法层的不足

CMDP + Lagrangian 在**训练阶段**表现良好, 但**部署时仍有风险**:

```text
算法层 (Lagrangian CMDP) 的 3 个不足:

  1. 训练-部署 gap
     - 仿真训练, 真机部署
     - 仿真器有 0.5% 违反, 真机可能放大到 5%

  2. 边界违反抖动
     - Lagrangian 收敛后, 策略在约束边界 ±5% 范围振荡
     - 关节力矩在 47-53 N·m 之间反复横跳 (上限 50)

  3. 紧急情况响应慢
     - 传感器故障 / 人闯入 / 突然障碍物
     - 策略可能"反应" 50-100 ms 后才调整
     - 这 100 ms 内已经撞了
```

**Safety Layer 的角色**: 在策略输出后, **真实机器人执行前**, 加一道投影, 保证"执行的动作一定安全"。这是**最后一道防线**。

```text
完整部署 pipeline:

  状态 s → 策略 π_θ → 动作 a_policy
                              ↓
              ┌───────────────────────────┐
              │ Safety Layer              │
              │  - CBF 投影               │
              │  - Hamilton-Jacobi 滤波   │
              │  - 把 a_policy 投影到     │
              │    "安全集合"             │
              └────────────┬──────────────┘
                              ↓
                          a_safe
                              ↓
                  真实机器人执行 (力矩环)
```

### 3.2 控制屏障函数 (CBF):最常用的安全层

**CBF (Control Barrier Function)** 由 Ames et al. (2017) 提出, 是机器人安全层的工业标准。

**核心思想**: 定义一个**安全集合** $\mathcal{C}$, 策略输出的动作必须**保持机器人在 $\mathcal{C}$ 内**。

**形式化**:

设 $h: \mathcal{S} \to \mathbb{R}$ 是**屏障函数**, 安全集合是:

$$
\mathcal{C} = \{ s \in \mathcal{S} : h(s) \ge 0 \}
$$

$h(s) \ge 0$ 表示"安全", $h(s) < 0$ 表示"不安全"。

例 (关节速度约束): $h(s) = v_{\max} - |s.\dot{q}|$, $h \ge 0$ 表示速度未超限。

**CBF 的关键性质**: 找到控制 $a$ 使得 $h$ 的"未来值"仍然 $\ge 0$。

**连续时间 CBF 条件**:

$$
\dot{h}(s, a) \ge -\alpha \cdot h(s), \quad \alpha > 0
$$

其中 $\alpha$ 是**类参数** (class-$\mathcal{K}$ function), 控制"接近边界时退缩多快"。

**直觉**:

- $h(s) > 0$ (远离边界): $\dot{h}$ 可以是任意值, 只要不迅速变负
- $h(s) \to 0$ (接近边界): $\dot{h}$ 必须 $\ge -\alpha h$, **强制 $h$ 保持非负**
- $\alpha$ 大: 退缩快 (保守), $\alpha$ 小: 退缩慢 (激进)

**离散时间 CBF (机器人实际用)**:

控制周期 $\Delta t = 0.01$ s (100 Hz), 离散 CBF 条件:

$$
h(s_{t+1}) - h(s_t) \ge -\alpha \cdot \Delta t \cdot h(s_t)
$$

或等价:

$$
h(s_{t+1}) \ge (1 - \alpha \Delta t) \cdot h(s_t)
$$

### 3.3 CBF 优化问题:QP 投影

CBF 的工程实现是**QP (Quadratic Program) 投影**:

$$
\begin{aligned}
a_{\text{safe}} = \arg\min_a \quad & \|a - a_{\text{policy}}\|^2 \\
\text{s.t.} \quad & h(s_{t+1}(a)) \ge (1 - \alpha \Delta t) h(s_t) \\
& a \in \mathcal{A}_{\text{feasible}}
\end{aligned}
$$

**直觉**: **最小化"对原动作的改动"**, 同时保证安全。

- 如果 $a_{\text{policy}}$ 已经安全 → $a_{\text{safe}} = a_{\text{policy}}$, 不修改
- 如果 $a_{\text{policy}}$ 接近违反 → 投影到安全边界
- 如果 $a_{\text{policy}}$ 严重违反 → $a_{\text{safe}}$ 沿"安全方向"投影

**例: 关节速度约束的 QP**:

```python
# CBF-QP: 关节速度约束
# h(s) = v_max - |qdot|
# 安全: h(s_{t+1}) >= (1 - alpha * dt) * h(s_t)

# 单关节标量版本
def cbf_projection(a_policy, qdot, v_max=1.0, alpha=1.0, dt=0.01):
    h = v_max - abs(qdot)

    # h 在 qdot 上的梯度: dh/dqdot = -sign(qdot)
    # 假设一阶动力学: qdot_next ≈ qdot + dt * (a / inertia)
    # 简化: dh/d(qdot_next) = -1, 通过 a 影响

    # QP: min (a - a_policy)^2
    #      s.t. h_next >= (1 - alpha*dt) * h
    #           → -dt/inertia * a >= -(1-alpha*dt)*h + (-sign(qdot) * qdot)
    #      (注意符号细节, 略)

    # 解析解: 如果 a_policy 满足约束, 返回 a_policy
    if abs(qdot + dt * a_policy) <= v_max:
        return a_policy
    else:
        # 否则投影到边界
        return -(v_max - 0.9 * abs(qdot)) / dt * np.sign(qdot)
```

**多约束版本 (实际机器人)**:

```python
# 多关节, 多约束的 CBF-QP
# 用 cvxpy 或 quadprog 求解
import cvxpy as cp

def cbf_projection_multi(a_policy, state, constraints):
    """多约束 CBF 投影"""
    a = cp.Variable(n_joints)

    # 目标: 最小化动作改动
    objective = cp.sum_squares(a - a_policy)

    # 约束列表
    constraint_list = []
    for h_func, grad_func, alpha in constraints:
        h_current = h_func(state)
        # h_next ≈ h_current + grad_h * (state_next - state)
        # state_next 由 a 决定 (通过动力学)
        constraint_list.append(
            h_current + grad_func(state) @ (state_dot_from_a(a)) >=
            (1 - alpha * dt) * h_current
        )

    # 求解 QP
    prob = cp.Problem(cp.Minimize(objective), constraint_list)
    prob.solve()

    return a.value
```

**CBF 的求解时间**: 100-500 Hz 控制循环要求 QP 在 1-5 ms 内求解。常用求解器:

- **小规模 (≤10 约束)**: cvxpy + OSQP, < 1 ms
- **中等规模 (10-50 约束)**: quadprog + 自定义 active set, 1-3 ms
- **大规模 (50+ 约束)**: 内点法 IPOPT, 5-10 ms (可能需要降频到 50 Hz)

### 3.4 CBF 在机器人上的具体例子

**例子 1: 协作机器人碰撞避免**

```text
场景: 末端执行器必须不进入 "人体工作区"

  h(s) = d_min - ||x_ee - x_human||
  其中:
    d_min = 0.3 m (最小安全距离)
    x_ee = 末端位置
    x_human = 人体位置 (来自视觉/雷达)

  CBF 条件:
    d_min - ||x_ee(t+1) - x_human|| >= (1 - alpha * dt) * (d_min - ||x_ee - x_human||)

  几何解释:
    当前 d_ee_human = 0.5 m (h = -0.2 m, 安全)
    如果 v_ee 朝人, 0.1 s 后 d = 0.3 m (h = 0, 边界)
    CBF: 限制速度, 让末端减速
```

**例子 2: 四足机器人脚力约束**

```text
场景: 接触力不超过 200 N (避免脚底传感器损坏)

  h(s) = F_max - |F_contact|
  F_contact = M(q) * qddot + C(q, qdot) * qdot + G(q)

  简化 (静态): F_contact ≈ K * (x_foot - x_ground) (弹簧模型)
  h(s) ≈ F_max - K * penetration

  CBF: 限制 foot 触地速度, 防止瞬时冲击力
```

**例子 3: 机械臂奇异位姿避免**

```text
场景: 避免接近 Jacobian 奇异 (关节卡死)

  h(s) = sigma_min(J(q)) - sigma_min_threshold
  其中:
    J(q) = 雅可比矩阵 (n x 6)
    sigma_min = 最小奇异值

  CBF: 限制 qdot, 避免运动到奇异
```

**CBF 的局限**: 单步预测。如果约束要求 "未来 N 步都安全", 需要**多步 CBF** 或 **reachability** (下一节)。

### 3.5 Hamilton-Jacobi 到达性:考虑未来

CBF 是**单步安全** (保证下一步不违反)。但很多约束是**多步**的:

- 例: 末端速度 1.9 m/s (未超 2 m/s), 但加速度 5 m/s², 0.05 秒后必超限

**Hamilton-Jacobi (HJ) 到达性分析** 给出**多步安全集合**:

$$
\mathcal{C}_{\text{HJ}} = \{ s_0 : \forall t \in [0, T], \forall a \in \mathcal{A}_{\text{feasible}}, s(t) \in \mathcal{C}_{\text{safe}} \}
$$

即"无论怎么走, T 时间内都不会违反约束"的初始状态集合。

**HJ 到达性的数学**: 解 **HJ PDE**:

$$
\frac{\partial V(s, t)}{\partial t} + \min_a \left[ \nabla_s V \cdot f(s, a) \right] = 0
$$

其中 $V(s, t)$ 是**值函数**, 表示"$t$ 时刻从 $s$ 出发, 是否能保持安全"。

**HJ 的工程问题**:

1. **计算昂贵**: 求解 PDE 需要网格化状态空间, 6 自由度机器人状态 ~$10^6$ 网格
2. **离线预计算**: 通常**离线**算好"安全区域", 在线查表
3. **近似方法**: 神经网络拟合 $V(s)$ (deep reachability, Hsu et al., 2023)

**HJ 在机器人上的应用**:

- **无人机避障**: 3 维位置 + 3 维速度 = 6 维状态, 离线算好"安全管"
- **自动驾驶**: 位置 + 速度 + 曲率, 离线计算, 在线校验
- **机械臂**: 关节位置 + 速度, 适合离线 + 在线查表

### 3.6 安全滤波:Safety Filter 的工业实现

把 CBF 和 HJ 组合成可部署的**安全滤波器**:

```python
class SafetyFilter:
    """工业级安全滤波器"""
    def __init__(self, constraints, control_freq=100):
        self.constraints = constraints  # 多个 CBF 屏障函数
        self.dt = 1.0 / control_freq
        self.alpha = 1.0  # CBF 类参数

    def filter(self, s, a_policy):
        """输入: 状态, 策略动作; 输出: 安全动作"""
        # 1. 检查所有约束
        for h, grad_h, dyn in self.constraints:
            h_current = h(s)
            # 2. 如果当前就违反, 触发紧急动作 (回退到上一安全状态)
            if h_current < 0:
                return self.emergency_action(s)
            # 3. CBF 投影
            a_safe = self.cbf_qp(s, a_policy, h, grad_h, dyn)
            # 4. 检查投影后是否满足
            if not self.is_safe(s, a_safe):
                a_safe = self.emergency_action(s)
            a_policy = a_safe  # 链式投影: 多约束依次满足

        return a_policy

    def emergency_action(self, s):
        """紧急动作: 减速到 0, 回到安全状态"""
        return -0.5 * s.velocity  # 阻抗控制风格的减速
```

**安全滤波的"安全保证"** (Ames et al., 2019):

如果 CBF 条件在每个控制周期都满足, 那么**只要初始状态安全, 整个轨迹都安全**。这是 CBF 的核心定理。

**实际部署的鲁棒性**:

```python
# 部署时的双重保险
def deploy_step(s):
    # 1. 策略输出
    a_policy = policy(s)

    # 2. 安全层投影
    a_safe = safety_filter.filter(s, a_policy)

    # 3. 物理限位 (硬件保护)
    a_final = np.clip(a_safe, -a_max, a_max)

    # 4. 平滑滤波 (防止动作抖动)
    a_final = lowpass_filter(a_final, cutoff=20Hz)

    return a_final
```

## 4. 恢复 RL (Recovery RL)

### 4.1 恢复 RL 的核心思想

**Safety Layer (CBF) 是"被动防御"**: 策略输出危险动作时, 投影到安全。**但更激进的做法是让策略"主动避免"进入危险状态**。

这就是 **Recovery RL** (Thananjeyan et al., 2021, Stanford):

```text
Recovery RL 的两层策略:

  ┌──────────────────────────────────────────────┐
  │ 主策略 π_task: 完成任务                       │
  │  - 学到的: "怎么从 A 到 B"                    │
  │  - 目标: 最大化任务 reward                     │
  │  - 可能进入 "接近违反" 状态                   │
  └───────────────────┬──────────────────────────┘
                      │ 监测: h(s) < h_recover
                      │ (安全裕度低于阈值)
                      ↓
  ┌──────────────────────────────────────────────┐
  │ 恢复策略 π_recover: 回到安全                  │
  │  - 学到的: "怎么从危险回到安全"               │
  │  - 目标: 最小化 cost (约束违反量)             │
  │  - 把状态带回 h(s) >= h_safe                 │
  └──────────────────────────────────────────────┘
                      │
                      ↓ h(s) >= h_safe
                      │ (恢复成功)
                      ↓
                  切换回主策略
```

**关键工程量**:

- $h_{\text{recover}}$: 触发恢复的安全阈值 (通常 $\approx 0.5 h_{\text{safe}}$)
- $h_{\text{safe}}$: 切换回主策略的安全阈值 (通常 = 约束边界)
- $\tau_{\text{recover}}$: 最大恢复时间 (超时强制人工接管)

### 4.2 主策略 + 恢复策略的训练

Recovery RL 的核心是**两个策略分开训练**:

**主策略训练**: 标准 CMDP, Lagrangian 约束, 学"完成任务"。

**恢复策略训练**: **关键区别** —— 学习"从危险状态回到安全":

$$
\pi_{\text{recover}}^* = \arg\max_\pi \mathbb{E}_{s_0 \sim \rho_{\text{danger}}} \left[ \sum_t \gamma^t r_{\text{recover}}(s_t, a_t) \right]
$$

其中:
- $s_0 \sim \rho_{\text{danger}}$: 初始状态从**危险区域**采样 (而非任务相关区域)
- $r_{\text{recover}}(s, a)$: 恢复奖励 (远离约束为正, 接近为负)

**恢复奖励的设计**:

```python
def recover_reward(s, a):
    # 主要项: 远离约束
    h = compute_barrier(s)  # 屏障函数值
    r_safety = h  # h 越大 (远离边界), 奖励越高

    # 辅助项: 任务相关 (可选)
    # 让恢复策略也尽量朝任务方向走, 而不是简单回原点
    r_task = task_progress(s)

    # 组合
    return r_safety + 0.1 * r_task
```

**训练算法**:

```python
# 恢复策略的训练 (off-policy 推荐)
# 从 replay buffer 采样 "危险起点"
danger_buffer = DangerBuffer(capacity=1e6)

# 1. 用主策略探索, 把进入危险区的状态存到 danger_buffer
for step in range(N):

    s_next, r, c, done = env.step(a)
    if compute_barrier(s_next) < danger_threshold:
        danger_buffer.add(s_next)  # 存危险状态

# 2. 单独训练恢复策略
for step in range(M):
    s0 = danger_buffer.sample(BATCH)  # 从危险区采样起点
    traj = rollout(recover_policy, env, init_state=s0, T=200)
    # 用 recover_reward 训练 (off-policy: SAC / TD3)

```

**主-恢复策略切换逻辑**:

```python
class RecoveryPolicySystem:
    """主-恢复策略切换系统"""
    def __init__(self, pi_task, pi_recover, h_safe=0.0, h_recover=0.5):
        self.pi_task = pi_task
        self.pi_recover = pi_recover
        self.h_safe = h_safe
        self.h_recover = h_recover
        self.in_recovery = False
        self.recover_time = 0

    def select_action(self, s):
        h = compute_barrier(s)

        # 切换逻辑 (滞回, 避免抖动)
        if not self.in_recovery:
            # 当前在主策略模式
            if h < self.h_recover:
                # 进入危险区, 切换到恢复
                self.in_recovery = True
                self.recover_time = 0
        else:
            # 当前在恢复模式
            if h >= self.h_safe:
                # 回到安全区, 切换回主策略
                self.in_recovery = False
            self.recover_time += 1
            if self.recover_time > MAX_RECOVER_TIME:
                # 恢复超时, 紧急停止
                return EMERGENCY_STOP_ACTION

        if self.in_recovery:
            return self.pi_recover(s)
        else:
            return self.pi_task(s)
```

**滞回 (hysteresis) 的作用**: 避免在边界附近反复切换。

```text
无滞回: h_safe = h_recover = 0
  → 状态在 0 附近抖动, 切换频繁 (100 Hz 下每秒 50 次切换)

有滞回: h_safe = 0, h_recover = 0.5
  → 切换次数 < 1 次 / 10 秒
```

### 4.3 干预机制:Recovery RL 的部署细节

**干预 (Intervention) 机制** 在 Recovery RL 中至关重要:

```text
干预的三种类型:

  1. Soft Intervention (软干预)
     - 用恢复策略的 action 替换主策略 action
     - 平滑切换, 不中断控制循环
     - 例: 末端接近人体, 自动减速

  2. Hard Intervention (硬干预)
     - 完全停止主策略, 启动预设的紧急动作
     - 控制循环可能短暂中断
     - 例: 碰撞力超 65 N, 立即停机

  3. Human Intervention (人工干预)
     - 远程操作员介入, 手动接管
     - 最慢, 但最灵活
     - 例: 异常行为, 操作员用遥操作接管
```

**干预的工程实现**:

```python
class InterventionSystem:
    def __init__(self):
        self.intervention_mode = 'auto'  # 'auto', 'soft', 'hard', 'human'

    def step(self, s):
        if self.intervention_mode == 'human':
            # 等待人工指令
            return self.wait_human_input()

        a_task = self.pi_task(s)
        a_recover = self.pi_recover(s)

        # 检查是否需要干预
        if needs_hard_intervention(s):
            self.intervention_mode = 'hard'
            return self.emergency_action()

        if needs_soft_intervention(s):
            # 软干预: 用恢复策略, 但主策略仍在运行
            # 两者加权混合 (随 h 平滑过渡)
            w = compute_intervention_weight(s)  # h 越小, w 越大
            return (1 - w) * a_task + w * a_recover

        return a_task

    def needs_hard_intervention(self, s):
        # 硬条件: 碰撞力 > 65 N, 关节力矩 > 100 N·m, 人突然进入
        return (s.contact_force > 65 or
                abs(s.tau).max() > 100 or
                s.human_intrusion)

    def needs_soft_intervention(self, s):
        return compute_barrier(s) < self.h_recover
```

**干预的"安全保证"** (Thananjeyan et al., 2021):

定理 (简化): 如果恢复策略能从任意危险状态回到 $\mathcal{C}_{\text{safe}}$, 那么主策略 + 恢复策略的组合**仍然安全**。

这个定理依赖恢复策略的"全局可达性", 即从**任何**危险状态都能恢复。**这是强假设**, 实际部署时需要保守设计。

### 4.4 真实机器人的安全部署

**真实机器人部署的 5 个最佳实践**:

```text
最佳实践 1: 多层防护 (Defense in Depth)

  Layer 1 (算法):  CMDP + Lagrangian 训练
  Layer 2 (部署):  CBF 安全层 + Recovery RL
  Layer 3 (硬件):  物理限位 + 急停 + 力矩保护
  Layer 4 (运维):  远程监控 + 日志审计 + 人工接管

  每层独立验证, 一层失败不致命
```

```text
最佳实践 2: 保守启动 (Conservative Launch)

  阶段 1: 仿真验证 100% 满足约束
  阶段 2: 真机低速 (< 25% 标称速度) 部署 1 周
  阶段 3: 收集违规事件, 修正策略
  阶段 4: 逐步提速 (50%, 75%, 100%) 每阶段 1 周
  阶段 5: 7×24 不间断运行

  不允许 "仿真 100%, 真机直接 100% 上"
```

```text
最佳实践 3: 失败安全 (Fail-Safe)

  默认假设: 任何环节都可能失败
    - 传感器故障 → 触发紧急停止
    - 通信延迟 → 自动减速
    - 策略失效 → 回退到示教轨迹
    - CBF 不可行 → 停止在当前位置

  Fail-Safe 的设计原则: 任何时候, 让机器人"安全停下"
  永远不假设 "策略一定能恢复"
```

```text
最佳实践 4: 可观测性 (Observability)

  每个部署 step 必须记录:
    - 状态: 关节位置/速度/力矩
    - 动作: 策略输出 + CBF 投影后
    - 干预: 是否触发恢复, 触发条件
    - 性能: 任务成功率, 约束违反次数

  日志分析: 每小时扫描异常, 自动报警
```

```text
最佳实践 5: 人在回路 (Human-in-the-Loop)

  远程操作员可以:
    - 实时查看机器人状态 (相机 + 遥测)
    - 紧急停止 (优先级 > 自动控制)
    - 接管控制 (从自动切到遥操作)
    - 修改参数 (调低速度上限等)

  关键: 人工接管的响应时间 < 200 ms
```

**Stanford ALOHA 的 Recovery RL 实验** (Thananjeyan et al., 2021):

- 任务: 桌面机械臂抓取 + 装配
- 约束: 末端不进入"禁区" (有易碎物品)

**Boston Dynamics Spot 的安全部署**:

- 4 层 CBF: 关节力矩 / 接触力 / 倾斜角 / 速度
- 7×24 部署, 1 万次任务, 0 次硬件损坏

**关键 insight**: 真实部署的安全**不是靠算法层单独保证**, 而是靠**多层冗余** + **保守启动** + **可观测性** + **人在回路**。**算法层只是其中一层**。

### 5.2 实验 1: 约束 PPO (CPPO) 完整实现

```python
"""
约束 PPO (CPPO) 实现
任务: Safety Gym Hopper, 速度约束
约束: ||v|| <= 2.0 m/s
"""
import torch
import torch.nn as nn
import torch.nn.functional as F
import numpy as np
import gymnasium as gym
import safety_gymnasium

# ===== 超参数 =====
GAMMA = 0.99
GAMMA_C = 0.99  # cost 的折扣因子
LAM = 0.95
CLIP_EPS = 0.2
K_EPOCHS = 4
BATCH_SIZE = 64
N_STEPS = 2048
LR = 3e-4
LAMBDA_LR = 0.01  # Lagrangian 学习率
LAMBDA_MAX = 50.0
D_VELOCITY = 0.5  # 速度约束阈值 (累积 cost <= 0.5)

# ===== Actor-Critic 网络 =====
class ActorCritic(nn.Module):
    """CPPO 的 Actor + 两个 Critic (reward + cost)"""
    def __init__(self, state_dim, action_dim, hidden=64):
        super().__init__()
        # Actor (策略网络)
        self.actor = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, action_dim)
        )
        self.log_std = nn.Parameter(torch.zeros(action_dim) - 0.5)

        # Reward Critic
        self.critic_r = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, 1)
        )

        # Cost Critic (CPPO 新增)
        self.critic_c = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, 1)
        )

    def policy(self, s):
        mean = self.actor(s)
        std = self.log_std.exp().expand_as(mean)
        return mean, std

    def sample(self, s):
        mean, std = self.policy(s)
        dist = torch.distributions.Normal(mean, std)
        a = dist.sample()
        log_prob = dist.log_prob(a).sum(dim=-1)
        entropy = dist.entropy().sum(dim=-1)
        return a, log_prob, entropy

    def get_value(self, s):
        return self.critic_r(s).squeeze(-1)

    def get_cost_value(self, s):
        return self.critic_c(s).squeeze(-1)


# ===== GAE 计算 =====
def compute_gae(rewards, values, dones, gamma=0.99, lam=0.95):
    """标准 GAE (用于 reward)"""
    advantages = torch.zeros_like(rewards)
    last_advantage = 0
    next_value = 0
    for t in reversed(range(len(rewards))):
        if dones[t]:
            next_value = 0
            last_advantage = 0
        delta = rewards[t] + gamma * next_value - values[t]
        last_advantage = delta + gamma * lam * last_advantage
        advantages[t] = last_advantage
        next_value = values[t]
    returns = advantages + values
    return advantages, returns


def compute_cost_gae(costs, cost_values, dones, gamma=0.99, lam=0.95):
    """Cost 版本 GAE"""
    return compute_gae(costs, cost_values, dones, gamma, lam)


# ===== CPPO 主循环 =====
def cppo_train(env_name='SafetyHopper-v1', max_iters=200, seed=0):
    torch.manual_seed(seed); np.random.seed(seed)

    env = safety_gymnasium.make(env_name)
    state_dim = env.observation_space.shape[0]
    action_dim = env.action_space.shape[0]

    ac = ActorCritic(state_dim, action_dim)
    opt = torch.optim.Adam(ac.parameters(), lr=LR)
    lambda_lag = 0.0  # Lagrangian 乘子

    # 记录训练过程
    history = {'reward': [], 'cost': [], 'lambda': []}

    for it in range(max_iters):
        # ===== 1. Rollout =====
        states, actions, rewards, costs, dones, log_probs = [], [], [], [], [], []
        s, _ = env.reset(seed=seed + it)

        for t in range(N_STEPS):
            s_t = torch.FloatTensor(s)
            with torch.no_grad():
                a, log_p, _ = ac.sample(s_t)
            a_np = a.numpy()
            s_next, r, terminated, truncated, info = env.step(a_np)

            # Safety Gym 的 cost 在 info 中
            c = info.get('cost', 0.0)

            states.append(s); actions.append(a_np)
            rewards.append(r); costs.append(c); dones.append(terminated)
            log_probs.append(log_p.item())

            s = s_next
            if terminated or truncated:
                s, _ = env.reset(seed=seed + it + t)

        # ===== 2. 计算 Advantage =====
        states_t = torch.FloatTensor(np.array(states))
        actions_t = torch.FloatTensor(np.array(actions))
        old_log_probs_t = torch.FloatTensor(log_probs)
        rewards_t = torch.FloatTensor(rewards)
        costs_t = torch.FloatTensor(costs)
        dones_t = torch.FloatTensor(dones)

        with torch.no_grad():
            values_r = ac.get_value(states_t)
            values_c = ac.get_cost_value(states_t)
            # 最后一步的 value (简化: 用 0)
            next_value_r = 0.0
            next_value_c = 0.0

        # 用最后一个状态算 bootstrap (简化处理)
        values_r_with_next = torch.cat([values_r, torch.tensor([next_value_r])])
        values_c_with_next = torch.cat([values_c, torch.tensor([next_value_c])])

        adv_r, ret_r = compute_gae(rewards_t, values_r, dones_t, GAMMA, LAM)
        adv_c, ret_c = compute_cost_gae(costs_t, values_c, dones_t, GAMMA_C, LAM)

        # 标准化 (PPO 标准做法)
        adv_r = (adv_r - adv_r.mean()) / (adv_r.std() + 1e-8)
        adv_c = (adv_c - adv_c.mean()) / (adv_c.std() + 1e-8)

        # ===== 3. 更新 Lagrangian =====
        J_c = costs_t.sum().item() / N_STEPS  # 平均累积 cost
        lambda_lag = max(0, lambda_lag + LAMBDA_LR * (J_c - D_VELOCITY))
        lambda_lag = min(lambda_lag, LAMBDA_MAX)  # 上限

        # ===== 4. PPO 多 epoch 更新 =====
        n_samples = len(states)
        idx = np.arange(n_samples)

        for epoch in range(K_EPOCHS):
            np.random.shuffle(idx)
            for start in range(0, n_samples, BATCH_SIZE):
                end = start + BATCH_SIZE
                mb_idx = idx[start:end]

                mb_states = states_t[mb_idx]
                mb_actions = actions_t[mb_idx]
                mb_old_logp = old_log_probs_t[mb_idx]
                mb_adv_r = adv_r[mb_idx]
                mb_adv_c = adv_c[mb_idx]
                mb_ret_r = ret_r[mb_idx]
                mb_ret_c = ret_c[mb_idx]

                # 重新计算 log prob 和 value
                _, new_logp, entropy = ac.sample(mb_states)
                ratio = torch.exp(new_logp - mb_old_logp)

                # Task objective (标准 PPO clip)
                surr1_r = ratio * mb_adv_r
                surr2_r = torch.clamp(ratio, 1 - CLIP_EPS, 1 + CLIP_EPS) * mb_adv_r
                loss_task = -torch.min(surr1_r, surr2_r).mean()

                # Cost objective (CPPO 新增)
                surr1_c = ratio * mb_adv_c
                surr2_c = torch.clamp(ratio, 1 - CLIP_EPS, 1 + CLIP_EPS) * mb_adv_c
                loss_cost = torch.min(surr1_c, surr2_c).mean()

                # Lagrangian 组合 (核心)
                policy_loss = loss_task + lambda_lag * loss_cost

                # Value loss (reward)
                v_r_pred = ac.get_value(mb_states)
                loss_v_r = F.mse_loss(v_r_pred, mb_ret_r)

                # Value loss (cost)
                v_c_pred = ac.get_cost_value(mb_states)
                loss_v_c = F.mse_loss(v_c_pred, mb_ret_c)

                # 总损失
                loss = policy_loss + 0.5 * loss_v_r + 0.5 * loss_v_c - 0.01 * entropy.mean()

                opt.zero_grad()
                loss.backward()
                nn.utils.clip_grad_norm_(ac.parameters(), 0.5)
                opt.step()

        # ===== 5. 记录 =====
        ep_reward = rewards_t.sum().item() / max(1, dones_t.sum().item() + 1)
        history['reward'].append(ep_reward)
        history['cost'].append(J_c)
        history['lambda'].append(lambda_lag)

        if it % 10 == 0:
            print(f"Iter {it:3d} | R: {ep_reward:7.1f} | "
                  f"C: {J_c:.3f}/{D_VELOCITY} | λ: {lambda_lag:.3f}")

    return ac, history

# ===== 运行 =====
if __name__ == "__main__":
    ac, history = cppo_train(max_iters=200)
    print("训练完成")
```

### 5.3 实验 2: CBF 安全层可视化

```python
"""
CBF 安全层: 2D 平面机械臂
任务: 末端从 A 到 B, 避开圆形障碍
约束: d(末端, 障碍) >= 0.3 m
"""
import numpy as np
import matplotlib.pyplot as plt
from cvxpy import Variable, Problem, Minimize, quad_form, norm, PARAM

def cbf_2d_arm_demo():
    """2 自由度平面机械臂 + 圆形障碍 + CBF 投影"""

    # ===== 机械臂参数 =====
    L1, L2 = 1.0, 1.0  # 连杆长度
    target = np.array([1.5, 0.5])  # 目标点
    obstacle = np.array([0.8, 0.3])  # 障碍物中心
    r_obstacle = 0.3  # 障碍物半径

    # 仿真参数
    n_steps = 100
    dt = 0.05

    # 初始状态
    q = np.array([0.5, -0.5])  # 关节角

    # CBF 参数
    alpha_cbf = 1.0  # 类参数
    h_safe = 0.0  # 安全裕度
    h_recover = 0.5  # 触发恢复

    # 数据记录
    trajectory = []
    trajectory_safe = []
    violations = 0

    for t in range(n_steps):
        # 末端位置 (forward kinematics)
        x = L1 * np.cos(q[0]) + L2 * np.cos(q[0] + q[1])
        y = L1 * np.sin(q[0]) + L2 * np.sin(q[0] + q[1])
        x_ee = np.array([x, y])

        # 到障碍的距离
        d = np.linalg.norm(x_ee - obstacle)
        h = d - r_obstacle  # 屏障函数

        # ===== 策略: 简单 PD 控制器朝目标 =====
        # 计算雅可比 (2x2 矩阵)
        J = np.array([
            [-L1 * np.sin(q[0]) - L2 * np.sin(q[0] + q[1]), -L2 * np.sin(q[0] + q[1])],
            [ L1 * np.cos(q[0]) + L2 * np.cos(q[0] + q[1]),  L2 * np.cos(q[0] + q[1])]
        ])

        # 任务空间速度
        v_desired = 0.5 * (target - x_ee)  # 朝目标
        v_desired = np.clip(v_desired, -1.0, 1.0)

        # 关节空间速度 (逆运动学)
        dq_policy = np.linalg.pinv(J) @ v_desired

        # ===== CBF QP 投影 =====
        # h 的梯度 (对 qdot)
        # h = d - r, d = ||x_ee - obstacle||
        # dh/dq = (x_ee - obs)/d * J (用链式法则)
        if d > 1e-6:
            grad_d = (x_ee - obstacle) / d
            grad_h = grad_d @ J  # 1x2 向量
        else:
            grad_h = np.array([0.0, 0.0])

        # CBF 条件: h_next >= (1 - alpha*dt) * h
        # 简化: h + grad_h * dq * dt >= (1 - alpha*dt) * h
        # → grad_h * dq >= -(alpha * dt / dt) * h - (grad_h * dq_policy 的修正项)
        # 精确 QP (用 cvxpy):
        dq_var = Variable(2)
        objective = Minimize(quad_form(dq_var - dq_policy, np.eye(2)))
        # CBF 约束
        cbf_constraint = grad_h @ dq_var >= -(alpha_cbf * h)
        prob = Problem(objective, [cbf_constraint])
        try:
            prob.solve(solver='OSQP')
            dq_safe = dq_var.value if dq_var.value is not None else dq_policy
        except Exception:
            dq_safe = dq_policy  # QP 失败时回退

        # 记录
        trajectory.append(x_ee.copy())
        trajectory_safe.append(x_ee.copy())  # 这里简化为同轨迹
        if h < h_safe:
            violations += 1

        # 更新关节角
        q = q + dt * dq_safe

    # ===== 可视化 =====
    trajectory = np.array(trajectory)
    fig, ax = plt.subplots(figsize=(8, 8))

    # 机械臂终态
    ax.plot([0, L1 * np.cos(q[0])], [0, L1 * np.sin(q[0])], 'b-o', lw=3)
    ax.plot([L1 * np.cos(q[0]), L1 * np.cos(q[0]) + L2 * np.cos(q[0] + q[1])],
            [L1 * np.sin(q[0]), L1 * np.sin(q[0]) + L2 * np.sin(q[0] + q[1])],
            'b-o', lw=3)

    # 障碍
    circle = plt.Circle(obstacle, r_obstacle, color='red', alpha=0.3, label='Obstacle')
    ax.add_patch(circle)

    # 目标
    ax.plot(target[0], target[1], 'g*', markersize=20, label='Target')

    # 末端轨迹
    ax.plot(trajectory[:, 0], trajectory[:, 1], 'k--', alpha=0.5, label='EE Trajectory')

    ax.set_xlim(-0.5, 2.0); ax.set_ylim(-1.0, 1.5)
    ax.set_aspect('equal'); ax.grid(True); ax.legend()
    ax.set_title(f'CBF Safety Layer Demo (violations: {violations})')
    plt.savefig('cbf_demo.png', dpi=100)
    plt.show()

    print(f"完成, 违反次数: {violations} / {n_steps}")
    return violations

if __name__ == "__main__":
    cbf_2d_arm_demo()
```

**预期结果**: 末端轨迹平滑绕开障碍, **违反次数 = 0**。CBF 在末端接近障碍时自动减速, 远离后恢复正常速度。

真实机器人部署 demo (伪代码)
展示多层安全防护的实际集成
"""
import numpy as np

class RobotDeployment:
    """真实机器人安全部署的完整 pipeline"""
    def __init__(self):
        # 加载训练好的策略
        self.policy_task = load_policy('cppo_hopper.pt')
        self.policy_recover = load_policy('recovery_sac.pt')
        self.safety_filter = SafetyFilter(
            constraints=[
                joint_torque_cbf(tau_max=50.0),
                joint_velocity_cbf(qdot_max=2.0),
                end_effector_cbf(d_min=0.3),
                contact_force_cbf(F_max=65.0)
            ]
        )
        # 硬件接口
        self.hardware = RobotHardware()  # 真实机器人驱动
        self.logger = EventLogger()
        self.emergency_stop = False

    def step(self, state):
        """单步部署 (100 Hz)"""
        # ===== 检查硬件急停 =====
        if self.emergency_stop:
            return self.emergency_action()

        # ===== Layer 1: 策略输出 =====
        a_policy = self.policy_task(state)

        # ===== Layer 2: 主-恢复策略切换 =====
        h = compute_barrier(state)
        if h < 0.5:  # 接近危险区, 切换到恢复策略
            a_policy = self.policy_recover(state)
            self.logger.log('recovery_triggered', h=h)

        # ===== Layer 3: CBF 安全层 =====
        a_safe = self.safety_filter.filter(state, a_policy)
        if np.any(np.abs(a_safe - a_policy) > 0.1):
            self.logger.log('cbf_intervention', deviation=a_safe - a_policy)

        # ===== Layer 4: 物理限位 (硬件保护) =====
        a_final = np.clip(a_safe, -self.a_max, self.a_max)

        # ===== Layer 5: 平滑滤波 =====
        a_final = self.lowpass_filter(a_final, cutoff=20.0)

        # ===== 执行 + 监控 =====
        try:
            self.hardware.execute(a_final)
        except HardwareFault as e:
            self.logger.log('hardware_fault', error=str(e))
            self.emergency_stop = True
            return self.emergency_action()

        # ===== 日志 =====
        self.logger.log('step',
                        state=state, a_policy=a_policy, a_safe=a_safe,
                        a_final=a_final, barrier=h)

        return a_final

    def emergency_action(self):
        """紧急停止"""
        self.hardware.set_torque_zero()
        self.logger.log('emergency_stop')
        return np.zeros(self.action_dim)

    for t in range(1000):  # 1000 步 = 10 秒

        state = robot.hardware.get_state()  # 100 Hz 等待
        if robot.emergency_stop:
            print(f"Step {t}: 紧急停止触发")
            break

    robot.logger.save('deployment_log.json')
    print("部署结束")

if __name__ == "__main__":
    deploy_demo()

## 7. 与数学基础的关系

本章涉及 4 个数学分支, 列出关键概念和复用位置:

### 7.1 约束优化 (数学基础/6-最优化)

**Lagrangian 对偶** 是 CMDP 求解的核心工具:

$$
\min_{\lambda \ge 0} \max_\theta L(\theta, \lambda) = J_r(\theta) - \sum_i \lambda_i (J_{c_i}(\theta) - d_i)
$$

- **KKT 条件**: 收敛到约束满足 + 互补松弛 + Lagrangian 稳定
- **强对偶**: 在凸问题下, 对偶解 = 原问题解
- **CMDP 的非凸**: 策略 $\pi_\theta$ 是神经网络, $J_r, J_c$ 都非凸, 不能保证强对偶
- **工程妥协**: Lagrangian 在非凸问题下**仍可用**, 但只保证收敛到**驻点**而非全局最优

### 7.2 凸优化 (数学基础/6-最优化/第5章)

**CBF 的 QP 投影** 是凸优化:

$$
\min_a \|a - a_{\text{policy}}\|^2 \quad \text{s.t.} \quad h(s_{t+1}(a)) \ge (1 - \alpha \Delta t) h(s_t)
$$

- 目标函数是**凸二次**
- 约束是**线性** (h 对 a 的近似是线性的)
- 整体是**凸 QP**, 用 OSQP / quadprog 求解, < 1 ms

### 7.3 随机过程 (数学基础/3-概率论/第9章)

**CMDP 的状态转移** 是马尔可夫过程:

$$
P(s'|s, a) \text{ 与约束耦合: } \mathbb{E}_{s'} [\sum_t \gamma^t c(s_t, a_t)]
$$

- **Markov 性**: 当前状态 $s_t$ 包含所有历史信息
- **平稳策略**: $\pi(a|s)$ 与时间无关
- **折扣累积 cost**: $J_c(\pi) = \mathbb{E}_\pi [\sum_t \gamma^t c_t]$

### 7.4 动态规划 (数学基础/7-系统思维/案例9-DreamerV3-RSSM)

**HJ 到达性** 用动态规划:

$$
V(s, t) = \max_a V(s', t - \Delta t), \quad s' = f(s, a)
$$

- **反向递推**: 从 $t = T$ 到 $t = 0$
- **值函数拟合**: 神经网络近似 $V(s, t)$ (DeepReach, Hsu et al., 2023)
- **在线校验**: $V(s, 0) \ge 0$ 时, $T$ 步内安全

### 7.5 推荐阅读顺序

```text
约束优化基础 → CMDP 形式化 → Lagrangian 求解
            ↓
凸优化 (QP) → CBF 投影
            ↓
随机过程 → CMDP 的 Bellman 方程
            ↓
HJ PDE → 多步 reachability
```

## 8. 常见误区

### 误区 1: "把违反量作为 reward 惩罚就足够"

**错误**: 在 reward 里加 $-10 \cdot |a - a_{\text{safe}}|$, 期望策略自动学会不违反。

**正确做法**: 用 CMDP + Lagrangian 把违反作为**硬约束**, 不是 reward 的一部分。

**为什么 reward 惩罚不够**:
- 违反是"低概率事件", 训练初期探索时很少发生, reward 信号太稀疏
- 违反的代价**难以量化** (撞墙一次 = 5 万, 但无法换算成 reward scale)
- 训练稳定后, 策略在边界附近**反复横跳** (reward 抖动)

**工程验证**: 在 Safety Gym 上对比 "PPO + reward 惩罚" 和 "CPPO":
- PPO + 惩罚: 23% 违反率, 训练不稳定
- CPPO: 0.5% 违反率, 训练稳定

### 误区 2: "仿真训练 0% 违反, 真机也 0% 违反"

**错误**: 仿真里约束满足得很好, 真机直接上。

**正确做法**: **真机必须有独立的安全层 (CBF)**, 不能依赖训练时的策略。

**为什么仿真不能直接迁移**:
- 仿真器的物理模型与真机有 1-5% 误差
- 仿真里"刚超限", 真机可能"严重超限"
- 真机的传感器延迟、通信噪声未在仿真中模拟

**工程方案**: Sim-to-Real 部署时, **永远保留安全层**作为最后一道防线。

### 误区 3: "CBF 能处理所有安全约束"

**错误**: 装一个 CBF, 所有约束都搞定。

**正确做法**: CBF 适合**单步可预测**的约束, 多步约束需要 HJ 或 MPC。

**CBF 的局限**:
- 单步预测, 不能保证多步安全
- 需要知道系统动力学 $f(s, a)$, 不确定性大时不可靠
- 约束**凸**才好解, 非凸约束 (如"末端不能进入任意形状区域") 需要 HJ

**多约束组合**: 多个 CBF 投影链式应用可能冲突, 需要**统一 QP** (一次求解多个约束)。

### 误区 4: "Lagrangian λ 越大越好"

**错误**: 训练时把 $\lambda$ 调到 50 (上限), 期望更保守。

**正确做法**: $\lambda$ 应该让策略在**约束边界附近**, 不是越大越好。

**为什么 λ 太大有害**:
- 策略过度保守, 任务成功率暴跌 (从 80% → 20%)
- 训练不稳定, 探索被压制
- 收敛到局部最优 ("站着不动", 0 违反但 0 任务)

**正确值**: 让 $\lambda$ **自适应**到 $J_c \approx d$ (KKT 互补松弛条件)。

### 误区 5: "Recovery RL 等于备份控制器"

**错误**: 恢复策略 = 一个手写的"回原点"脚本。

**正确做法**: 恢复策略是**独立训练的策略**, 从"危险区域"采样起点学习。

**错误做法的危害**:
- "回原点"在复杂环境下不可行 (可能撞到障碍)
- 无法处理多种危险情况
- 没有泛化能力, 新场景失效

**正确做法**: 用 RL 在仿真里训出恢复策略, 数据从危险区域采样。

### 误区 6: "训练和部署可以分离"

**错误**: 训练团队只关心仿真 reward, 部署团队只关心真机。

**正确做法**: **训练时就考虑部署约束**, 把真机的安全约束写进仿真环境。

**为什么必须联合**:
- 仿真里的"安全"和真机不一样 (仿真没考虑传感器噪声、通信延迟)
- 训练时的 Lagrangian 阈值 $d$, 应该和真机的物理限位**一致**
- 训练时的安全裕度, 应该在真机上**留够 buffer** (例如真机用 80% 仿真阈值)

### 误区 7: "Lagrangian 收敛 = 训练完成"

**错误**: $\lambda$ 收敛到非零常数, 就认为训练完成。

**正确做法**: 还要验证**任务性能** (reward) 和**泛化能力** (测试环境)。

**为什么只看 λ 不够**:
- $\lambda$ 收敛但策略可能"保守无任务" (Lambda 5 但 reward 0)
- 测试环境 (unseen) 可能违反约束 (训练过拟合)
- 需要在测试集上**重新跑** Lagrangian, 看 $\lambda$ 是否仍小

## 9. L7/L8 面试 Q&A

### Q1: CMDP 的对偶变量 λ 怎么更新? 物理意义是什么?

**参考答案 (L7 水平)**:

λ 的更新规则:

$$
\lambda_i \leftarrow \max\left(0, \lambda_i + \eta_\lambda \cdot (J_{c_i}(\theta) - d_i)\right)
$$

**物理意义**:
- $\lambda_i$ 是**违反第 $i$ 个约束的"价格"**
- 违反越多 ($J_{c_i} > d_i$), $\lambda$ 越大, 策略更倾向避免违反
- 满足约束 ($J_{c_i} < d_i$), $\lambda$ 衰减到 0 (这个约束"不活跃")

**为什么需要 max(0, ·)**: 保证 $\lambda \ge 0$, 否则对偶问题无意义。

**为什么需要上限 $\lambda_{\max}$**: 防止数值爆炸 (训练初期 $J_c$ 可能远大于 $d$, 让 λ 失控)。

**L8 进阶**: 收敛后 $\lambda_i^* > 0$ 且 $J_{c_i}^* = d_i$ 满足 KKT **互补松弛条件**, 表示第 $i$ 个约束"恰好"在边界; 若 $\lambda_i^* = 0$, 表示该约束"不活跃", 训练目标没考虑它。

### Q2: Lagrangian PPO 收敛后, 约束还可能违反吗?

**参考答案 (L7 水平)**:

**理论上**: 收敛到 KKT 点时, $J_c \le d$, 约束满足。

**实际上**: 仍然可能违反。原因有 4 个:

1. **训练-测试 gap**: 测试环境与训练环境不同 (仿真 vs 真机)
2. **策略泛化**: 训练时的状态分布 ≠ 部署时的状态分布
3. **Lagrangian 收敛 ≠ 约束满足**: 实际策略可能"接近边界但偶尔越过"
4. **数值误差**: 浮点精度 + 仿真器实现, 边界可能 ±1% 浮动

**工程对策**:
- 训练时设 $d_{\text{train}} = 0.8 \cdot d_{\text{deploy}}$, 留 20% buffer
- 部署时加 CBF 安全层, 把违反率压到 < 0.01%
- 监控 + 日志, 每次违反记录根因

**L8 进阶**: Paternain et al. (2019) 证明, 在**强对偶**条件下, Lagrangian 收敛到**全局最优** + 约束满足。但 RL 的策略空间非凸, 只能保证**驻点**而非全局最优。实际工程中, 假设"驻点附近满足约束"是合理的。

### Q3: CBF 在关节速度约束下怎么求解? QP 优化的目标函数长什么样?

**参考答案 (L7 水平)**:

**单关节标量**:

屏障函数 $h(s) = v_{\max} - |q\dot|$, 梯度 $\nabla h = -\text{sign}(q\dot) \cdot J_v$, 其中 $J_v$ 是速度的雅可比。

QP 问题:

$$
\begin{aligned}
a^* = \arg\min_a \quad & \|a - a_{\text{policy}}\|^2 \\
\text{s.t.} \quad & h(s) + \nabla h \cdot (a \cdot \Delta t) \ge (1 - \alpha \Delta t) h(s)
\end{aligned}
$$

展开:

$$
\begin{aligned}
a^* = \arg\min_a \quad & (a - a_{\text{policy}})^2 \\
\text{s.t.} \quad & -\text{sign}(q\dot) \cdot v_a \cdot \Delta t \ge -\alpha \Delta t \cdot (v_{\max} - |q\dot|)
\end{aligned}
$$

其中 $v_a = a / \text{inertia}$ (简化)。

**多关节多约束** 用 cvxpy:

```python
import cvxpy as cp
a = cp.Variable(n_joints)
objective = cp.sum_squares(a - a_policy)
constraints = []
for h_i, grad_h_i in barriers:
    constraints.append(h_i + grad_h_i @ (a * dt) >= (1 - alpha * dt) * h_i)
prob = cp.Problem(cp.Minimize(objective), constraints)
prob.solve()
```

**L8 进阶**: QP 在**鲁棒 CBF** (Robust CBF) 下需要考虑模型不确定性:

$$
\dot{h}(s, a) \ge -\alpha h(s) + \gamma \cdot \|\nabla h \cdot \Delta f\|
$$

其中 $\Delta f$ 是动力学的不确定上界。这让 QP 变得**保守** (留 buffer 给不确定性), 但保证鲁棒。

### Q4: 恢复策略和主策略怎么协调? "接管"和"放松"的阈值怎么设?

**参考答案 (L7 水平)**:

**协调架构**: 主-恢复策略 + 滞回 (hysteresis) 切换:

```text
h_safe      : 切换回主策略的阈值 (如 0)
h_recover   : 切换到恢复策略的阈值 (如 0.5, 比 h_safe 大)

切换逻辑:
  if h < h_recover: in_recovery = True (切到恢复)
  if h >= h_safe: in_recovery = False (切回主)
```

**为什么用滞回**: 避免在边界附近反复切换 (chattering)。若 $h_{\text{safe}} = h_{\text{recover}} = 0$, 切换频率可达 100 Hz, 抖振严重; 滞回后 < 1 次/分钟。

**阈值工程取值**:

| 任务类型 | $h_{\text{recover}}$ | $h_{\text{safe}}$ | 理由 |
| :--- | :--- | :--- | :--- |
| 关节力矩 (硬约束) | 0.3 × τ_max | 0 | 保守, 提前触发 |
| 末端速度 (软约束) | 0.5 × v_max | 0 | 中等 |
| 碰撞力 (ISO 标准) | 0.5 × F_max | 0.2 × F_max | 法律层面, 必须保守 |

**L8 进阶**: 实际部署时, 阈值需要**自适应**: 用元学习 / Bayesian 优化, 根据任务难度和历史违反动态调整。Stanford 2023 的 Meta-Safe RL (Yu et al.) 用元学习训练 "何时切换" 的策略。

### Q5: 真机部署时安全层和真机控制器 (力矩环) 谁说了算?

**参考答案 (L7 水平)**:

**架构**: 安全层在**外环** (10-100 Hz), 真机控制器在**内环** (1-10 kHz)。

```text
位置: 策略 (10-100 Hz) → 安全层 (100 Hz) → 力矩环 (1 kHz) → 电机

外环: 策略输出"目标位置/速度"
内环: 力矩环把目标转换为电机力矩 (PD 控制 / 阻抗控制)
安全层: 在外环和内环之间, 修改"目标"
```

**谁说了算**:

- **正常情况**: 策略决定目标, 力矩环执行
- **CBF 触发**: CBF 修改目标, 力矩环执行修改后的目标
- **紧急情况**: 安全层直接给 0 力矩, 力矩环跟随

**冲突解决**:
- CBF 的优先级**永远高于**策略 (如果冲突, CBF 赢)
- 真机控制器 (内环) 不参与决策, 只执行外环指令
- 硬件急停 (物理按钮) 优先级最高, 完全切断力矩

**L8 进阶**: 现代架构是**双时间尺度**: 外环策略 + 内环力矩 + 安全监督。例如 Henny Herzog 的 "三层架构" (2022): 策略层 + 安全层 + 控制层, 每层独立运行, 通过 ROS2 通信。这种架构的好处是**单层失败不影响其他层**, 鲁棒性大幅提升。

### Q6 (附加): 工程上怎么平衡 "安全" 和 "任务性能"?

**参考答案**:

这是一个**帕累托前沿**问题。给定约束 $J_c \le d$, 在这条线上最大化 $J_r$。

**工程取舍**:
1. **$d$ 越小越安全**: $d = 0$ 时最保守, 但任务可能 0 完成
2. **$d$ 越大越激进**: $d \to \infty$ 时退化为无约束, 但违反率高
3. **工程最佳点**: $d$ 在**物理安全极限的 80-90%** 处 (留 10-20% buffer)

**Lagrangian 收敛后**, 策略自然在帕累托前沿上。如果训练时间够长, 不需要手动调 $d$。

**业务层决策**:
- 高风险场景 (医疗、协作): $d$ 取小, 任务性能换安全
- 低风险场景 (工业孤岛): $d$ 取大, 安全换效率

## 11. CMDP 的工程实现:从形式化到代码

### 11.1 CMDP 框架图:三层结构

形式化定义清楚了, 工程上要把 CMDP 落到一个**可训练的 gym 环境**里。下图是工程视角的 CMDP 框架, 也是 Safety Gymnasium (Ji et al., 2023) 和我们真机部署都采用的参考结构:

```text
CMDP 工程框架 (Safety Gymnasium 风格):

   ┌───────────────────────────────────────────────────────────────────┐
   │                       Episode Loop (单条轨迹)                      │
   │                                                                   │
   │   ┌─────────┐    ┌──────────────┐    ┌──────────────┐             │
   │   │  Reset  │───▶│  Step (a_t)  │───▶│  Safety      │──┐         │
   │   │  s_0    │    │              │    │  Check       │  │         │
   │   └─────────┘    │  s_{t+1} =   │    │              │  │         │
   │        ▲         │  P(·|s_t,a_t)│    │  c_i 累积    │  │         │
   │        │         │              │    │  J_c += c_i  │  │         │
   │        │         └──────────────┘    └──────────────┘  │         │
   │        │                  ▲                  │          │         │
   │        │                  │                  ▼          │         │
   │        │            ┌──────────┐      ┌──────────┐      │         │
   │        │            │  Policy  │      │ Episode  │◀─────┘         │
   │        │            │  π_θ     │      │ Done?    │                │
   │        │            │  (训练中) │      │ timeout  │                │
   │        │            │          │      │ /violate │                │
   │        │            └──────────┘      └──────────┘                │
   │        │                  ▲                                        │
   │        │                  │ Lagrangian 对偶变量 λ 来自外层         │
   │        │                  │ (constraint budget 反馈)               │
   │        │            ┌──────────────────┐                          │
   │        └────────────│  Lagrangian λ    │◀───── 违反 → λ ↑          │
   │                     │  更新器 (外层)    │      满足 → λ ↓          │
   │                     └──────────────────┘                          │
   │                              ▲                                    │
   │                              │                                    │
   │                              │ J_c(θ) 反馈 (constraint cost)       │
   │                              │                                    │
   └──────────────────────────────┼────────────────────────────────────┘
                                  │
                                  │ 单次 rollout 完成后回传
                                  ▼
                       ┌────────────────────┐
                       │ 训练 step          │
                       │ L_clip(θ)          │
                       │ - λ · J_c(θ)       │
                       │ + value loss       │
                       │ + entropy bonus    │
                       └────────────────────┘
```

**关键观察**:
- **内层** (Policy π_θ) 在约束参数化下做策略梯度, 目标函数里 $-\lambda J_c(\theta)$ 让策略"怕"违反
- **外层** (Lagrangian λ 更新) 是个独立更新器, 收到 episode 末的 $J_c(\theta)$ 后调 λ, 调速慢于内层
- **Episode Done** 条件 = `terminate when J_c > d` 或 `timeout`, 前者触发"硬终止", 后者触发"软终止"

### 11.2 Safety Gymnasium 环境的核心 cost 实现

下面这段是真实 Safety Gymnasium (`safety_gymnasium/tasks/safe_velocity/`) 风格的 cost 函数, 给定 `s` (机器人状态, 含位置/速度/关节角) 和 `a` (目标速度), 输出 cost 标量:

```python
import numpy as np

class SafeVelocityCost:
    """Velocity + Hazard + WorkSpace 复合 cost。Safety Gym 风格的工程实现."""

    def __init__(self, config):
        self.v_max = config["v_max"]              # 速度上限, 例如 0.5 m/s
        self.hazard_dist_min = config["hazard_dist_min"]  # 离 hazard 最小距离
        self.workspace_radius = config["workspace_radius"] # 工作空间半径
        self.hazard_penalty = config.get("hazard_penalty", 1.0)
        self.violation_bonus = config.get("violation_bonus", 1.0)

    def compute(self, s, a):
        """
        s: dict with keys 'base_pos', 'base_vel', 'joint_pos', 'joint_vel'
        a: dict 'command_vel' (vx, vy, wz)
        return: cost scalar in [0, c_max]
        """
        cost = 0.0

        # 1) 速度约束: ||base_vel|| <= v_max
        v = np.linalg.norm(s["base_vel"][:2])  # 只看水平速度
        cost += self.violation_bonus * max(0.0, v - self.v_max)

        # 2) Hazard 距离: 与所有 hazard 中心距离 < hazard_dist_min 触发 cost
        for h_pos, h_radius in s["hazards"]:
            d = np.linalg.norm(s["base_pos"][:2] - h_pos[:2])
            if d < (h_radius + self.hazard_dist_min):
                cost += self.hazard_penalty

        # 3) 工作空间: 出界
        r = np.linalg.norm(s["base_pos"][:2])
        if r > self.workspace_radius:
            cost += 1.0  # 强制计 1 次

        # 4) 关节力矩 (如果仿真器给了)
        if "tau" in s:
            tau_norm = np.linalg.norm(s["tau"])
            cost += 0.1 * max(0.0, tau_norm - 50.0)  # 50 N·m 是仿真阈值

        return float(cost)
```

**注意**: cost 是个**标量** (如果只有 1 个约束) 或**向量** (如果多个约束)。Lagrangian 训练时, 通常每个约束配一个独立 λ:

```python
# 多约束 Lagrangian: 每个 cost 一个 λ
costs = env.compute_costs(s, a)  # shape (m,)
lambdas = np.array([1.0, 0.5, 0.0])  # 初始 λ, 各自不同
J_c = discounted_costs.sum(axis=0)    # shape (m,)

# 独立更新
for i in range(m):
    lambdas[i] = max(0.0, lambdas[i] + lr_lambda * (J_c[i] - d[i]))
```

**工程坑**:
1. **cost 归一化**: 不同 cost 的尺度差很多 (速度是 m/s, 接触力是 N), 训练前要把每个 cost 除以其物理最大值, 否则 λ 学不到合理值
2. **discounted vs undiscounted**: 训练时一般用 undiscounted sum (`γ_c = 1`), 部署时用 discounted (`γ_c = 0.99`), 两者差距很大
3. **Hazard 几何**: Safety Gym 用圆盘 (距离约束), 真机可能是不规则形状 (人员位置多边形), 需要 R-tree 或 SDF 加速

### 11.3 Lagrangian PPO 的 PyTorch 实现 (生产级简化版)

下面是基于 [[第06章-02-PPO在机器人-从仿真到真实]] 的 PPO 加 Lagrangian 的**完整 PyTorch 实现**, 不到 60 行, 保留工程核心:

```python
import torch
import torch.nn as nn
import torch.optim as optim

class LagrangianPPO:
    """
    简化的 Lagrangian PPO。完整版:
    https://github.com/PKU-Alignment/safety-gymnasium
    """
    def __init__(self, state_dim, act_dim, cost_dim=1, hidden=64):
        self.policy = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, act_dim),
        )
        self.log_std = nn.Parameter(torch.zeros(act_dim))
        self.value = nn.Sequential(
            nn.Linear(state_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, 1),
        )
        self.cost_value = nn.Sequential(  # 独立 cost critic, 估计 J_c
            nn.Linear(state_dim, hidden), nn.Tanh(),
            nn.Linear(hidden, hidden), nn.Tanh(),
            nn.Linear(hidden, cost_dim),
        )
        self.opt_pi = optim.Adam(list(self.policy.parameters()) + [self.log_std], lr=3e-4)
        self.opt_v = optim.Adam(self.value.parameters(), lr=3e-4)
        self.opt_cv = optim.Adam(self.cost_value.parameters(), lr=3e-4)

        # Lagrangian 对偶变量
        self.log_lambda = nn.Parameter(torch.zeros(cost_dim), requires_grad=False)
        self.lr_lambda = 0.05
        self.d = torch.tensor([10.0] * cost_dim)  # 约束阈值
        self.lambda_max = torch.tensor([50.0] * cost_dim)

    def get_action(self, s):
        mean = self.policy(s)
        std = self.log_std.exp().expand_as(mean)
        dist = torch.distributions.Normal(mean, std)
        a = dist.sample()
        return a, dist.log_prob(a).sum(-1)

    def update_step(self, batch):
        """单次 PPO update + Lagrangian λ 更新。"""
        s, a, logp_old, adv_r, adv_c, ret_r, ret_c = batch

        # 1) 策略梯度: max E[adv_r - lambda * adv_c]
        mean = self.policy(s)
        std = self.log_std.exp().expand_as(mean)
        dist = torch.distributions.Normal(mean, std)
        logp = dist.log_prob(a).sum(-1)
        ratio = (logp - logp_old).exp()

        lam = self.log_lambda.exp().clamp(0, 50)
        adv_combined = adv_r - lam * adv_c
        L_clip = -torch.min(
            ratio * adv_combined,
            ratio.clamp(1 - 0.2, 1 + 0.2) * adv_combined,
        ).mean()

        self.opt_pi.zero_grad()
        L_clip.backward()
        self.opt_pi.step()

        # 2) Value function
        v_loss = ((self.value(s) - ret_r) ** 2).mean()
        self.opt_v.zero_grad(); v_loss.backward(); self.opt_v.step()

        # 3) Cost value function
        cv_loss = ((self.cost_value(s) - ret_c) ** 2).mean()
        self.opt_cv.zero_grad(); cv_loss.backward(); self.opt_cv.step()

        # 4) Lagrangian λ 更新 (外层, 用 cost_value 估计的 J_c)
        with torch.no_grad():
            J_c_hat = self.cost_value(s).mean(dim=0)
            new_lam = (self.log_lambda.exp() + self.lr_lambda * (J_c_hat - self.d)).clamp(0)
            new_lam = new_lam.clamp(max=self.lambda_max)
            self.log_lambda.copy_(new_lam.log())

    @property
    def lam(self):
        return self.log_lambda.exp().clamp(0, 50)
```

**关键设计点**:
- **独立 cost critic**: `cost_value` 估计 $J_c$, 不是用 reward critic 替代 (两者梯度方向相反, 不能共用)
- **λ 用 log 参数化**: `log_lambda` 保证 `λ > 0` 无需 clamp, 训练稳定
- **adv_combined**: 用 `adv_r - λ · adv_c`, 物理含义是"组合优势", 策略向"奖励高 + 成本低"的方向优化
- **L_clip**: PPO 的 ratio clipping 保持不变, Lagrangian 只是改了优势函数

### 11.4 Lagrangian 的收敛判据 (工程)

训练工程师需要监控 3 个量:

```python
def log_diagnostics(episode_idx, ep_rewards, ep_costs, lambdas, threshold):
    """每 10 个 episode 打日志, 用于判断训练是否健康."""
    avg_r = np.mean(ep_rewards[-100:])
    avg_c = np.mean(ep_costs[-100:])
    active = (lambdas > 1e-3).sum()
    print(f"[Ep {episode_idx}] R={avg_r:.1f}  C={avg_c:.3f}/{threshold:.3f}  λ_active={active}/{len(lambdas)}")

    # 3 个收敛判据
    if avg_c > threshold * 1.1:
        print("[WARN] Cost budget exceeded, training stuck")
    if avg_c < threshold * 0.5 and avg_r < 100:
        print("[WARN] Over-conservative, task not progressing")
    if active == 0 and avg_r > 200:
        print("[OK] All constraints satisfied with margin")
```

**3 个判据**:
1. **超预算** ($J_c > 1.1 d$): Lagrangian 没收敛, 可能 lr 太大或策略更新太慢
2. **过度保守** ($J_c < 0.5 d$ 且 $J_r$ 低): λ 太大, 任务失败, 需要降 λ 上限
3. **健康** ($J_c \approx d$, $J_r$ 高): 训练完成

### 11.5 Lagrangian 的"卡住"诊断

训练中常见的 3 种"卡住", 对应不同修法:

```text
症状                          根因                  修法
─────────────────────────────────────────────────────────────────
λ 单调上升 → 上限, R 崩       cost signal 太大      减小 lr_lambda, 或归一化 cost
C 一直 >> d, λ 卡上限         λ_max 太小            调大 lambda_max (例如 50→100)
R ≈ 0, C ≈ 0                 过度保守              减小初始 λ (例如 1→0.1)
C ≈ d 但 R 比 baseline 低 30%  约束太紧              放松 d (例如 10→15)
λ 剧烈震荡 (周期 100 ep)      lr_lambda 太大        减小 lr_lambda (0.05→0.01)
```

具体诊断流程:

```python
def diagnose_stuck(ep_history, lambdas):
    """ep_history: list of dicts {R, C}"""
    recent = ep_history[-50:]

    # 检查 R 是否崩溃
    if np.mean([e["R"] for e in recent]) < np.mean([e["R"] for e in ep_history[:-50]]) * 0.5:
        return "R collapsed: lambda too aggressive"

    # 检查 C 是否卡限
    if all(l > 30.0 for l in lambdas[-20:]) and np.mean([e["C"] for e in recent]) > 15.0:
        return "Lambda saturated: increase lambda_max"

    # 检查是否卡零
    if all(l < 0.1 for l in lambdas[-20:]):
        return "Lambda decayed to zero: cost budget too loose"

    return "OK"
```

### 11.6 与 [[第06章-04-Sim2Real-域随机化与域适应]] 的关系:安全约束的域随机化

Sim2Real 中一个常被忽视的点: **安全约束本身也要随机化**。

```python
# 在域随机化的物理参数中, 也加 cost 阈值扰动
class RandomizableSafeEnv(SafeEnv):
    def __init__(self, config):
        super().__init__(config)
        self.d_nominal = config["cost_threshold"]  # 训练时 nominal 阈值

    def randomize(self):
        # 物理参数随机化 (同 [[第06章-04-Sim2Real-域随机化与域适应]] §3.2)
        self.mass = np.random.uniform(8.0, 12.0)         # 机器人物理质量
        self.friction = np.random.uniform(0.5, 1.5)

        # 关键: cost 阈值也要扰动, 真机可能更严
        self.d_train = self.d_nominal * np.random.uniform(0.7, 1.0)
        # 真机阈值 d_deploy = 0.8 * d_nominal, 训练时 d_train 覆盖 [0.7, 1.0] 范围
```

**为什么**: 训练时 $d_{\text{train}}$ 覆盖 $[0.7 d_{\text{nom}}, d_{\text{nom}}]$ 区间, 真机取 $d_{\text{deploy}} = 0.8 d_{\text{nom}}$, 落在训练分布内 → 策略见过"更严"的情况, 真机部署时不会太激进。

**反例**: 真机 $d_{\text{deploy}}$ 比训练 $d_{\text{train}}$ 还小 (例如真机因为传感器更灵敏), 策略在真机上违反率会上升, 因为没训练过这种 $d$。

## 12. 真实机器人的安全 RL 部署案例

### 12.1 案例 1:ANYmal 四足的安全 Lagrangian RL (ETH Zurich, 2020)

**来源**: Lee et al., "Learning Quadrupedal Locomotion over Challenging Terrain" (Science Robotics, 2020) + Ha et al. 2020.

**工程配置**:
- **硬件**: ANYmal C, 12 关节, 单关节力矩上限 80 N·m
- **约束**: 单关节力矩 ≤ 80 N·m, 接触力 ≤ 200 N, base 高度 ≥ 0.25 m
- **预算**: $d_{\text{train}} = 5.0$, $d_{\text{deploy}} = 4.0$
- **训练**: 4096 个 Isaac Gym 并行环境, Lagrangian PPO, ~2 小时
- **真机**: 直接上 ANYmal C 跑, 无安全层 (无 CBF)

**踩坑记录**:
1. **第 1 次上真机**: 训练时 cost 归一化用 `[0, 1]`, 真机力矩范围 `[0, 80]`, 标量差 80 倍 → λ 在真机上学不到合理值, **直接腿软摔倒**
2. **修复**: 把 cost 改用物理单位, 重新训练 4 小时
3. **第 2 次上真机**: 训练 $d = 5.0$, 真机设 $d = 4.0$, 策略在草地上完美运行 30 分钟
4. **失败案例**: 遇到积水, 脚打滑, λ 突然飙到上限, 策略"冻住"不动, 触发急停

**L7 经验**: 真机的 cost 阈值必须和训练一致 (单位 + 数值), 否则 λ 校准直接失效。

### 12.2 案例 2:Spot 工业巡检的 CBF + RL 混合架构 (Boston Dynamics, 2022)

**来源**: Spot SDK 公开文档 + "Safety Filter for Legged Robots" (Hsu et al., 2023).

**工程配置**:
- **硬件**: Spot, 12 关节 + 4 腿, 工业巡检
- **约束**: 关节力矩 ≤ 80 N·m, base 高度 ≥ 0.30 m, 末端不超出围栏
- **架构**: 外环 50 Hz RL 策略 → 安全层 100 Hz CBF-QP → 内环 1 kHz PD + 力矩限幅
- **训练**: PPO + Lagrangian 6 小时, $J_c \approx 4.5$, $d = 5.0$
- **真机**: CBF 兜底, 部署时 $d = 3.0$

**关键设计**:
- **CBF 把"超出围栏"作为硬约束**: $h(s) = d_{\text{fence}} - \text{dist}(\text{base}, \text{fence})$, QP 保证 $h$ 单调不减
- **CBF 把"关节力矩"作为软约束**: $h(s) = \tau_{\max} - |\tau|$, 但允许暂时违反
- **两层 fallback**: 1) CBF 触发 → 修改 base 速度, 2) 力矩环过载 → 直接限流

**踩坑记录**:
1. **CBF 与策略冲突**: CBF 把"前进 1 m/s"改成"前进 0.5 m/s", 策略在低于 0.3 m/s 时**学不会绕过障碍** (经验分布偏了)
2. **修复**: 训练时加入 CBF 模拟器, 让策略**在 CBF 介入下**学习
3. **结果**: 真实部署违反率从 0.5% 降到 0.01%, 任务成功率保持 92%

**L7 经验**: 安全层不能"事后挂上", 训练时就必须考虑安全层的存在。

### 12.3 案例 3:Waymo 自动驾驶的 Multi-Modal Safe RL (2023)

**来源**: Waymo safety reports + "Foundational Safety for Autonomous Vehicles" (Fridman et al., 2023).

**工程配置**:
- **硬件**: Jaguar I-PACE + 5 lidar + 12 camera
- **约束**: 与前车距离 ≥ 2 s 反应时间, 横向加速度 ≤ 0.3 g, 路径不超 HD map 边界
- **架构**: 多个独立"安全 RL 策略" — 跟车 / 并线 / 行人横穿, 决策树切换, 每个 200 Hz
- **训练**: 每个策略 ~50 万 km 仿真 (Waymax), 真机 PID 兜底

**踩坑记录**:
1. **OOD 问题**: 真机遇到施工绕行, 5 个策略都没把握, 切换到 PID 但 PID 反应慢 0.5 s
2. **修复**: 加 ensemble disagreement 检测, 5 个策略意见不一致时**主动减速**
3. **结果**: OOD 场景事故率从 0.1 / 1000 km 降到 0.01 / 1000 km

**L7 经验**: 单个 RL 策略很难覆盖所有危险, **多策略 + 切换**比单策略更稳。

### 12.4 案例 4:Franka Panda 协作臂的 Recovery RL (Stanford, 2021)

**来源**: Thananjeyan et al., "Recovery RL" (IEEE RA-L, 2021).

**工程配置**:
- **硬件**: Franka Panda 7-DOF, 末端 1 kHz 力矩环
- **任务**: 桌面推动鸡蛋不打破
- **约束**: 末端接触力 ≤ 5 N, 关节力矩 ≤ 87 N·m
- **架构**: 主策略 PPO (推动) + 恢复策略 PPO (撤回), 独立训练
- **真机**: 100% 任务成功率, 0% 鸡蛋破裂

**关键设计**:
- **Recovery Zone**: 屏障函数 $h(s) = d_{\text{danger}} - \text{dist}(\text{ee}, \text{obstacle})$, $h < 0.1$ 时切换恢复
- **独立采样**: 恢复策略起点从"危险区域"采样, 不是主策略失败轨迹
- **滞回切换**: $h_{\text{safe}} = 0.0$ (回主), $h_{\text{recover}} = 0.05$ (去恢复), 避免抖动

**踩坑记录**:
1. **恢复策略"卡在恢复"**: 训得太保守, 切到恢复后永远回不来
2. **修复**: 恢复 reward 包含"成功恢复 + 切回主策略", 强制要求主动放手
3. **结果**: 100 次任务全部成功

**L7 经验**: Recovery RL 关键是**两个独立训练的策略 + 明确切换条件**, 不是"主策略 + 备份脚本"。

## 13. 模型化 Safe RL:世界模型 + 安全约束

### 13.1 为什么世界模型 + 安全?

基于模型的安全 RL (MB-Safe RL) 是 2023 年后的热点。它的核心思想:

```text
Model-Free Safe RL:                Model-Based Safe RL:
─────────────                      ─────────────

真实环境                            世界模型
  ┌──────────────┐                  ┌──────────────┐
  │  物理仿真/真机 │                  │  DreamerV3   │
  │  慢, 危险     │                  │  RSSM        │
  └──────────────┘                  │  快, 0 风险   │
       ▲                            └──────────────┘
       │                                  │
       │  步 0.1 s / 步                    │  步 0.001 s / 步
       │                                  │
       ▼                                  ▼
   策略 π_θ                          1) 在世界模型里"想象"危险
   ┌──────────────┐                  2) 计算"如果违反会怎样"
   │  PPO/SAC     │                  3) 投影回安全集合
   │              │                  4) 输出"安全动作"
   └──────────────┘                  └──────────────┘
                                           │
                                           ▼
                                    真机 (0.1 s 步)
```

**为什么更快 + 更安全**:
- 仿真成本: 模型推理 1000 步 = 真实仿真 1 步, **便宜 1000 倍**
- 危险探索: 在世界模型里试"撞墙"没事, 真机上不会撞
- 多步预测: 模型可以"想象"未来 100 步, CBF 只能管 1 步

**代表工作**:
- **DreamerV3** (Hafner et al., 2023): 通用世界模型
- **SafeDreamer** (Huang et al., 2023): DreamerV3 + Lagrangian
- **MB-PPO-Safety** (Thananjeyan et al., 2023): 模型预测 + CBF
- **Lipschitz-bounded World Models** (Ji et al., 2024): 保证模型的鲁棒性

### 13.2 SafeDreamer 的 PyTorch 简化实现

```python
import torch
import torch.nn as nn

class SafeDreamer:
    """简化版 SafeDreamer: 世界模型 + Lagrangian 在想象轨迹中更新."""

    def __init__(self, obs_dim, act_dim, hidden=200, cost_dim=1):
        self.encoder = nn.Sequential(
            nn.Linear(obs_dim, hidden), nn.ELU(),
            nn.Linear(hidden, hidden), nn.ELU(),
        )
        self.rnn = nn.GRUCell(hidden + act_dim, hidden)
        self.reward_head = nn.Linear(hidden, 1)
        self.cost_head = nn.Linear(hidden, cost_dim)
        self.actor = nn.Sequential(
            nn.Linear(hidden, hidden), nn.ELU(),
            nn.Linear(hidden, act_dim),
        )
        self.critic = nn.Linear(hidden, 1)
        self.cost_critic = nn.Linear(hidden, cost_dim)
        # Lagrangian
        self.log_lambda = nn.Parameter(torch.zeros(cost_dim), requires_grad=False)
        self.d = torch.tensor([10.0] * cost_dim)

    def imagine(self, h0, horizon=50):
        """在世界模型中想象 horizon 步."""
        h, rewards, costs = h0, [], []
        for t in range(horizon):
            a = torch.tanh(self.actor(h))  # 简化: 直接用 mean
            h = self.rnn(torch.cat([self.encoder(h.detach()), a], -1), h)
            rewards.append(self.reward_head(h))
            costs.append(self.cost_head(h).abs())  # cost >= 0
        return torch.stack(rewards), torch.stack(costs)

    def update_lambda(self, imagined_costs, gamma=0.99):
        """Lagrangian λ 更新, 用想象的 J_c."""
        J_c = sum((gamma ** t) * imagined_costs[t] for t in range(len(imagined_costs)))
        new_lam = (self.log_lambda.exp() + 0.05 * (J_c - self.d)).clamp(0, 50)
        self.log_lambda.copy_(new_lam.log())
        return new_lam
```

**关键点**:
- `imagine()` 跑在世界模型内部, 0 真机交互, 极快
- `update_lambda()` 用**想象的 cost**更新 λ, 训练时不需要真机违反
- 与 Model-Free 核心差异: cost 信号来自**想象**, 不是真机回放

**L7 经验**: 世界模型的"想象"质量决定 safe RL 的上限。模型误差 > 5% 时, 安全约束失效。

**L8 经验**: 世界模型需要**Lipschitz 连续** (Ji et al., 2024), 否则对抗输入会让模型"幻想"安全, 真机违反。

## 14. 常见失败模式 (Debugging Cheatsheet)

### 14.1 "策略训练时正常, 真机一跑就崩"

**症状**: 仿真违反率 0%, 真机违反率 30%, 硬件触发急停。

**根因**: 仿真-真机 gap, 常见 5 个:

```text
根因                  检测方法                          修复
─────────────────────────────────────────────────────────────────────
物理参数失配           仿真器参数 vs 真机 datasheet        重新校准 mass, friction, inertia
传感器噪声未建模       仿真用真值, 真机有噪声              训练时加 Gaussian noise σ=0.05
通信延迟未建模         真机有 5-50 ms 延迟                训练时加 latency buffer (5 ms)
驱动响应未建模         真机有 0.1-0.5 ms 滞后             训练时加 first-order lag filter
模型简化              真机有非线性 (coulomb friction)    加 LuGre friction 模型
```

**修复代码示例**:

```python
# 真机环境 wrapper: 加传感器噪声 + 延迟
class RealisticRobotEnv:
    def __init__(self, base_env):
        self.env = base_env
        self.latency_buffer = collections.deque(maxlen=5)  # 5 ms @ 1 kHz
        self.noise_scale = 0.02

    def step(self, a):
        # 1) 延迟
        if len(self.latency_buffer) > 0:
            a_delayed = self.latency_buffer.popleft()
        else:
            a_delayed = np.zeros_like(a)
        self.latency_buffer.append(a.copy())

        # 2) 真机步进
        s_next, r, done, info = self.env.step(a_delayed)

        # 3) 传感器噪声
        s_next["joint_pos"] += np.random.normal(0, self.noise_scale, size=s_next["joint_pos"].shape)
        s_next["joint_vel"] += np.random.normal(0, self.noise_scale * 0.1, size=s_next["joint_vel"].shape)

        return s_next, r, done, info
```

### 14.2 "Lagrangian 不收敛, λ 一直震荡"

**症状**: λ 从 1 跳到 30 再跳回 1, 周期 50 episode, cost 在阈值上下震荡。

**根因**: `lr_lambda` 太大, 单次更新步长过大。

**修复**: 用 **PID Lagrangian** (Stooke et al., 2020) — 把 λ 当成 PID 控制器, P/I/D 三项对应"现在/过去/未来"的 cost 误差, 收敛比朴素 Lagrangian 快 3 倍。开源实现见 `safe-rl` GitHub。

```python
class PIDLagrangian:
    def __init__(self, d, Kp=0.1, Ki=0.01, Kd=0.05):
        self.d, self.Kp, self.Ki, self.Kd = d, Kp, Ki, Kd
        self.integral, self.prev_err = 0.0, 0.0

    def update(self, J_c):
        err = J_c - self.d
        self.integral += err
        derivative = err - self.prev_err
        self.prev_err = err
        return max(0.0, self.Kp * err + self.Ki * self.integral + self.Kd * derivative)
```

### 14.3 "CBF 把策略的合理动作也拒绝"

**症状**: 策略给出 "前进 1 m/s", CBF 改成 "前进 0.1 m/s", 任务失败率从 5% 涨到 40%。

**根因**: 屏障函数 $h$ 选得太保守 (例如 $h(s) = 1.5 d_{\text{danger}} - \text{dist}$, 而不是 $h = d_{\text{danger}} - \text{dist}$)。

**修复**: 把"安全裕度"作为**可调参数**, `margin = 0.7` (比物理约束松 30%) 给 CBF 留 buffer 但不压制策略:

```python
class ConfigurableCBF:
    def __init__(self, h_func, h_threshold, margin=0.7):
        self.h_func, self.h_threshold, self.margin = h_func, h_threshold, margin

    def compute_constraint(self, s):
        return self.h_func(s) - self.margin * self.h_threshold
```

### 14.4 "训练 reward 高, 真机 reward 几乎为 0"

**症状**: 仿真 90% 成功率, 真机 5% 成功率。

**根因**: 仿真里奖励依赖 ground truth, 真机没有这个信号 (例如"物体在目标位置"在仿真里靠状态变量, 真机只有视觉)。

**修复**: 把奖励改造成**真机可观测的** — 仿真 reward 设计时, 先问自己"真机上这个信号能不能拿到", 不能的话换成可观测的传感器信号 (例如把 "object_in_target" 换成 "camera_detects_target")。

## 15. L7/L8 面试 Q&A (扩展)

### Q7: Lagrangian 训练中, cost value function 和 reward value function 有什么区别? 为什么必须独立?

**参考答案 (L7 水平)**:

**核心区别**: 两个 value function 估计**不同的期望累积**:

$$
V_r(s) = \mathbb{E}_\pi \left[ \sum_t \gamma^t r(s_t, a_t) \mid s_0 = s \right], \quad V_c(s) = \mathbb{E}_\pi \left[ \sum_t \gamma^t c(s_t, a_t) \mid s_0 = s \right]
$$

**为什么不能共用**: 梯度方向相反。$V_r$ 高 = 状态好, $V_c$ 高 = 状态危险。如果共用, 训练时网络学"哪个值高", 但这两个值的语义冲突。

**PyTorch 实现**:

```python
# 错误: 共用 value head
class BadLagrangianPPO(nn.Module):
    def __init__(self):
        super().__init__()
        self.value = nn.Linear(hidden, 2)  # 输出 [V_r, V_c]
    def forward(self, s):
        v = self.value(s)  # [V_r, V_c]
        return v[:, 0], v[:, 1]  # 拆开, 但共享 backbone

# 正确: 独立 value head
class GoodLagrangianPPO(nn.Module):
    def __init__(self):
        super().__init__()
        self.value_r = nn.Linear(hidden, 1)  # 独立
        self.value_c = nn.Linear(hidden, 1)  # 独立
    def forward(self, s):
        return self.value_r(s), self.value_c(s)
```

**L8 进阶**: 两个 value function 的**学习率**应该不同。一般 `lr_v_c = 0.5 * lr_v_r` (cost value 更难学, 因为 cost 信号稀疏)。

### Q8: CBF 屏障函数 $h(s)$ 怎么选? 有什么工程经验?

**参考答案 (L7 水平)**:

**原则**: $h(s)$ 应该满足 3 个性质:

1. **可微**: $h \in C^1$ (至少一次连续可微), 否则梯度不存在
2. **可行集**: $\{s : h(s) \ge 0\}$ 是"安全"集合, 包含所有期望的稳态
3. **不变性**: 在控制 $u \in U_{\text{safe}}$ 下, $h$ 单调不减

**常见构造**:

$$
h_{\text{distance}}(s) = d_{\text{obstacle}} - \|p_{\text{robot}} - p_{\text{obstacle}}\|_2
$$

$$
h_{\text{velocity}}(s) = v_{\max} - \|\dot{x}_{\text{robot}}\|_2
$$

$$
h_{\text{torque}}(s) = \tau_{\max} - \|\tau\|
$$

**工程经验**:

| 障碍类型 | $h$ 选择 | 注意 |
| :--- | :--- | :--- |
| 圆形障碍 | 距离 | 简单 |
| 多边形障碍 | SDF (符号距离函数) | 复杂, 预计算 |
| 移动障碍 | 距离 + 相对速度 | 加 CBF-CLF 组合 |
| 关节限制 | 余弦函数 | smooth, 可微 |

**反例** (常见错误):

```python
# 错: 用 ReLU 当屏障函数 (不可微)
def bad_h(s):
    return max(0, s["dist"] - 0.5)

# 对: 用线性或平方
def good_h(s):
    return 0.5 - s["dist"]  # 线性, 可微
```

**L8 进阶**: 屏障函数的**阶数** (relative degree) 决定 CBF 设计的难度。一阶 CBF (直接可表达 $\dot{h}$) 简单, 二阶 CBF (需要 $\ddot{h}$) 复杂, 需要高阶控制 (Higher-Order CBF, HOCBF)。

### Q9: 在多约束 (多个 cost) 场景下, 多个 Lagrangian λ 怎么协调? 会不会有冲突?

**参考答案 (L7 水平)**:

**架构**: 每个 cost $c_i$ 配一个独立 $\lambda_i$, 独立更新:

```python
for i in range(m):
    lambdas[i] = max(0, lambdas[i] + lr_lambda * (J_c[i] - d[i]))
```

**冲突场景**: 两个约束互相"打架"。例如:
- 约束 1: 关节力矩 ≤ 50 N·m
- 约束 2: 末端速度 ≤ 0.5 m/s
- 冲突: 想末端高速时, 力矩必然大 → 两个约束同时违反

**解决**:

1. **优先级排序**: 工程上给每个约束一个**优先级**, 高优先级先满足:
   ```python
   # 优先级: 1) 关节力矩 (高, 法律层面), 2) 末端速度 (中)
   # 训练时, 关节力矩的 cost 权重 × 2
   total_cost = 2.0 * c_torque + 1.0 * c_velocity
   ```

2. **Pareto Lagrangian** (多目标优化): 联合更新 λ, 找到 Pareto 前沿:
   ```python
   # 用加权 Chebyshev loss
   L = max(w_i * (J_c[i] - d[i]))  # 最小化最大违反
   ```

3. **Lexicographic 优化**: 先满足约束 1, 在约束 1 满足的前提下求约束 2 的最优点。

**L8 进阶**: 多约束 CMDP 的对偶空间维数是 $m$ (约束数), 训练时需要 $m$ 个独立 λ 协调更新。Stooke et al. (2020) 的 Responsive Safety 用 PID 把多个 λ 当作多变量控制系统, 收敛速度比独立更新快 3 倍。

### Q10: Recovery RL 中, 恢复策略的训练数据怎么采样?

**参考答案 (L7 水平)**:

**关键**: 恢复策略的起点必须**在危险区域**, 否则它学不到"如何从危险回来"。

```python
class RecoveryEnvWrapper:
    """Wrap 主环境, 让 reset() 从危险区域采样."""

    def __init__(self, base_env, main_policy, danger_zone_fn):
        self.env = base_env
        self.main_policy = main_policy  # 已经训好的主策略
        self.danger_zone_fn = danger_zone_fn  # 返回 s 是否在危险区域

    def reset(self):
        """从主策略 rollouts 中, 找到违反瞬间的状态作为起点."""
        s = self.env.reset()
        for _ in range(50):
            a = self.main_policy(s)
            s_next, r, done, info = self.env.step(a)
            if self.danger_zone_fn(s_next):  # 进入危险区域
                return s_next  # 把这个"危险起点"返回
            s = s_next
        return s

    def step(self, a):
        return self.env.step(a)

    def compute_cost(self, s, a):
        # 恢复策略的 cost = "还没回到安全区"
        return 1.0 if self.danger_zone_fn(s) else 0.0
```

**Reward 设计**: 恢复策略的 reward = "成功回到安全区" + "成本最小"。**禁止**用主策略的 reward (那是任务 reward, 不是恢复 reward)。

```python
# 恢复策略 reward
def recovery_reward(s, a, s_next):
    if not danger_zone_fn(s_next):
        return 10.0  # 回到安全区, 大奖励
    if danger_zone_fn(s_next) and not danger_zone_fn(s):
        return -5.0  # 进入危险区 (训练时不应该, 但要惩罚)
    return -0.1  # 还在危险区, 小负奖励 (鼓励快速离开)
```

**L8 进阶**: 恢复策略的训练数据最好**包含主策略的失败轨迹**, 而不是从"危险区域均匀采样"。后者会让恢复策略在主策略从未访问过的状态"迷航", 真机上反而失败。

### Q11: 仿真到真机时, 怎么验证 safe RL 策略在真机上的安全性? 有哪些"上线 checklist"?

**参考答案 (L7 水平)**:

**真机上线 checklist (10 项)**:

```python
checklist = {
    "1. 物理参数校准": "mass, friction, inertia 与 datasheet 一致 (±5%)",
    "2. 传感器噪声测试": "100 Hz 采样 5 分钟, 看 σ 是否在期望范围",
    "3. 通信延迟测试": "10 Hz 命令往返, 测 P99 延迟 < 50 ms",
    "4. 力矩限幅测试": "静置状态测每个关节, 不超过 datasheet",
    "5. CBF 单元测试": "障碍前 0.5 m 放目标点, CBF 必须触发减速",
    "6. Recovery RL 测试": "人为推机器人进入危险区, 恢复策略必须触发",
    "7. Lagrangian λ dump": "训练最终 λ 与真机初设 λ 偏差 < 20%",
    "8. 紧急急停测试": "硬件按钮触发, 系统响应 < 100 ms",
    "9. 仿真-真机对比": "同一脚本跑 100 episode, 行为偏差 < 10%",
    "10. 人在回路 (HITL)": "首次真机部署, 工程师手持急停, 100% 在线",
}
```

**L7 关键**: "上线前急停测试" 必须**物理执行** (不是软件模拟), 因为真机软件可能"看起来正常但实际没切断力矩"。

**L8 进阶**: 完整的 **SIL + HIL** 测试链 — SIL: 仿真里跑 1000 次; HIL: 真机控制板 + 仿真机器人模型, 验证控制链路; 真机: 人才是最后一道防线。

### Q12 (附加): Safe RL 和普通 RL 的部署架构有什么本质区别?

**参考答案**:

**普通 RL 部署** (单层):

```text
策略 π → 控制 → 电机
```

**Safe RL 部署** (三层):

```text
策略 π → 安全层 (CBF) → 控制 → 电机
   ↑         ↑
   │         │
训练阶段    部署阶段独立运行
```

**关键差异**:

1. **模块化**: 安全层是**独立模块**, 可以脱离 RL 策略单独维护
2. **时序不同**: 策略 50 Hz, 安全层 100 Hz, 控制 1 kHz (多时间尺度)
3. **决策优先级**: 安全层 > 策略 > 控制 (永远)
4. **可解释**: 安全层是**显式规则** (CBF + QP), 可以审计; RL 策略是黑盒

**L7 经验**: 写一个 Safe RL 系统时, 先**单独**实现安全层 (CBF), 再加上 RL 策略, 不要反过来。

**L8 进阶**: 现代架构是"安全层 + 多个策略" (Multi-Policy), 每个策略专门处理一种任务模式, 安全层兜底。这种架构的好处是**单策略失败不影响全局**, 因为安全层仍然有效。
