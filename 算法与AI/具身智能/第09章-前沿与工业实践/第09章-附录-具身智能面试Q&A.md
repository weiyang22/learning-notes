## 1. 基础概念

### Q1: 什么是具身智能 (Embodied AI)?

**标准答案**:

具身智能指智能体通过物理身体 (embodiment) 与环境交互来学习和执行任务的能力。核心三要素:

1. **本体 (Body)**: 物理载体, 形态多样 (人形/四足/机械臂/轮式)。
2. **感知 (Perception)**: 视觉/触觉/力觉/语言多模态输入。
3. **行动 (Action)**: 真实物理动作输出, 而非纯文本。

具身智能的关键假设是: **智能不能脱离身体存在**。Stanford 的曹鹏飞把这个观点总结为 "Moravec 悖论的正面回应": 让机器在物理世界做小事, 比下围棋难一万倍。

**经典引用**: "Embodied AI is the foundation of the next generation of AI" —— Yann LeCun

**常见追问**:

- Q: 具身智能和传统机器人有什么区别?
- A: 传统机器人按预编程轨迹执行, 具身智能用学习得到的策略应对环境变化。
- Q: 具身智能对硬件有什么要求?
- A: 不是必须, 但需要能跑 VLA/世界模型的算力 (GPU ≥ 4090 级)。

**工业参考**: Figure 02, Tesla Optimus, 宇树 G1, NVIDIA GR00T。

### Q2: 具身智能和 LLM 是什么关系?

**标准答案**:

LLM (大语言模型) 是具身智能的"大脑外挂", 但不是全部。两者的关系可以这样理解:

1. **LLM 提供高层规划**: 用 Chain-of-Thought 把复杂任务拆成子步骤 ("先找杯子, 再倒水")。
2. **VLM 提供视觉理解**: 解析场景, 识别物体, 理解空间关系。
3. **控制层是具身智能的核心**: VLA 模型生成连续动作, 控制关节/电机。

**关键区别**:

- LLM: 输入文本, 输出文本, 完全离线。
- 具身智能: 输入多模态 (视觉/触觉/语言), 输出物理动作, 实时反馈。

**2024-2026 的范式**:

$$\text{具身智能} = \text{LLM/VLM (规划)} + \text{VLA (动作生成)} + \text{控制系统 (执行)}$$

GR00T、π0、Helix 都遵循这个范式。

**常见追问**:

- Q: LLM 可以直接控制机器人吗?
- A: 可以 (如 SayCan), 但 1Hz 的决策速度不适合精细操作; VLA 输出 50Hz 连续动作。
- Q: 没有 LLM 能不能做具身智能?
- A: 能, 经典控制和模仿学习都不依赖 LLM; 但复杂任务必须借助语言先验。

### Q3: 什么是 Sim2Real Gap (仿真到真实差距)?

**标准答案**:

Sim2Real Gap 指仿真器和真实世界在物理/视觉/动力学上的差异,导致在仿真器里训练好的策略在真机上跑不起来。

**主要来源**:

1. **物理差异**: 摩擦/阻尼/弹性系数不可能精确建模。
2. **视觉差异**: 仿真渲染的颜色/光照/材质纹理偏理想。
3. **执行器差异**: 真实电机的延迟/抖动/死区。

**四种应对策略**:

| 策略 | 原理 | 代表 |
| :--- | :--- | :--- |
| 域随机化 (DR) | 随机化物理/视觉参数, 让策略学到鲁棒特征 | OpenAI Rubik's Cube |
| 域适应 (DA) | 用 CycleGAN 等做图像迁移 | NVIDIA Isaac |
| 真实数据微调 | 仿真预训练 + 真机调 | Tesla Optimus |
| 大规模真数据 | 跳过仿真, 直接学 | Physical Intelligence π0 |

**常见追问**:

- Q: 域随机化和域适应哪个更有效?
- A: 视觉任务 DA 更常见, 控制任务 DR 更常见; 现代 VLA 两者结合。
- Q: 仿真器没用了吗?
- A: 不是, Isaac Lab 提供 GPU 并行仿真, 单次训练可累积 100 年经验。

### Q4: VLA 和 VLM 有什么区别?

**标准答案**:

**VLM (Vision-Language Model)**: 输入图像 + 文本, 输出文本。例: GPT-4V, LLaVA。

**VLA (Vision-Language-Action)**: 输入图像 + 文本指令, 输出连续动作 (7-DOF/50Hz)。例: π0, Helix, OpenVLA。

**架构对比**:

```text
VLM: [图像] + [文本] → 编码器 → LLM → [文本输出]
VLA: [图像] + [文本] → 编码器 → LLM → 动作头 → [动作序列]
```

动作头可以是回归头、扩散头 (π0) 或离散化 tokenizer (RT-2)。

**为什么需要 VLA**:

- VLM 只能"看"和"说", 不能"做"。
- VLA 把语言理解和动作执行统一在一个模型里, 可以端到端训练。
- VLA 继承 VLM 的预训练数据, 零样本泛化能力强 (RT-2 的涌现行为)。

**2025 主流 VLA**: π0 (Physical Intelligence), Helix (Figure), GR00T N1 (NVIDIA), OpenVLA-7B (开源), SmolVLA (HuggingFace)。

**常见追问**:

- Q: VLA 是不是越大越好?
- A: 不是; OpenVLA-7B 在某些任务上优于大模型, 因为小模型推理快 10x。
- Q: VLA 的"涌现行为"是什么?
- A: 在没见过 (新物体+新指令) 的组合上能成功, 这是语言先验带来的泛化。

### Q5: 模仿学习和强化学习在具身智能里谁更强?

**标准答案**:

**模仿学习 (IL)**: 从专家示教数据学策略, 优点是稳定/快/数据效率高, 缺点是天花板受限于专家质量。

**强化学习 (RL)**: 通过环境反馈学策略, 优点是能超过专家, 缺点是稀疏奖励/训练不稳定。

**2024-2026 共识**:

$$\text{主流范式} = \text{IL 初始化} + \text{RL 微调}$$

即先在大规模示教数据上做行为克隆 (BC), 再用 RL (PPO/SAC) 在仿真/真实环境里微调。

**代表案例**:

- **OpenAI Rubik's Cube**: 完全 RL, 域随机化是关键。
- **Tesla Optimus**: IL 为主, 用人类演示视频。
- **DeepMind RT-H**: IL + RL 结合, 用语言条件。
- **Physical Intelligence π0**: 纯 IL, 但用大规模高质量数据 (10^3 小时)。

**常见追问**:

- Q: RL 和 IL 哪个对硬件要求高?
- A: RL 需要仿真器, IL 需要数据采集系统; 真机 RL 比真机 IL 更危险。
- Q: 仿真 RL 能不能直接迁移到真机?
- A: 能, 但需要解决 Sim2Real Gap (见 Q3)。

## 2. 技术细节

### Q6: DH 参数 (Denavit-Hartenberg) 怎么用?

**标准答案**:

DH 参数是一种用 4 个标量描述相邻两个关节坐标系相对位姿的约定, 用于串联机械臂的正逆运动学。

**4 个参数**:

| 参数 | 含义 |
| :--- | :--- |
| $a_i$ | 连杆长度 (沿 $x_{i-1}$ 轴) |
| $\alpha_i$ | 连杆扭角 (绕 $x_{i-1}$ 轴) |
| $d_i$ | 关节偏距 (沿 $z_{i-1}$ 轴) |
| $\theta_i$ | 关节转角 (绕 $z_{i-1}$ 轴) |

**变换矩阵** (每个关节):

$$
A_i = \begin{pmatrix}
\cos\theta_i & -\sin\theta_i\cos\alpha_i & \sin\theta_i\sin\alpha_i & a_i\cos\theta_i \\
\sin\theta_i & \cos\theta_i\cos\alpha_i & -\cos\theta_i\sin\alpha_i & a_i\sin\theta_i \\
0 & \sin\alpha_i & \cos\alpha_i & d_i \\
0 & 0 & 0 & 1
\end{pmatrix}
$$

总变换 $T = A_1 A_2 \ldots A_n$。

**两种约定**:

- **标准 DH (Craig)**: $i$ 是当前连杆坐标系。
- **改进 DH (Khalil)**: $i$ 是下一连杆坐标系。NVIDIA Isaac 用改进版。

**实战建议**: 手算不超过 3 自由度, 6+ 自由度用 Pinocchio 或 IKFast 自动推导。

**常见追问**:

- Q: DH 参数有什么局限性?
- A: 不能描述闭链/并联机构, 也难以处理奇异构型。
- Q: 现代机器人还用手写 DH 吗?
- A: 越来越自动化, URDF 文件直接包含 DH 参数。

### Q7: 简述 PID 控制

**标准答案**:

PID (比例-积分-微分) 是工业界用了 100 年的反馈控制器, 输出是三项加权和:

$$
u(t) = K_p e(t) + K_i \int e(t) dt + K_d \frac{de(t)}{dt}
$$

- **P**: 比例项, 当前误差。
- **I**: 积分项, 累积误差 (消除稳态误差)。
- **D**: 微分项, 误差变化率 (抑制超调)。

**具身智能里的角色**:

- PID 是最底层的关节控制器, 接收目标位置/速度, 输出力矩。
- 上层 (VLA) 50Hz 输出动作; 中层 MPC 100-1000Hz 输出轨迹; 底层 PID 1000-10000Hz 输出力矩。

**调参经验**:

| 参数 | 太小 | 太大 |
| :--- | :--- | :--- |
| $K_p$ | 反应慢 | 振荡 |
| $K_i$ | 有稳态误差 | 积分饱和 |
| $K_d$ | 超调大 | 抖振 |

**常见追问**:

- Q: PID 在四足/人形机器人里够用吗?
- A: 单独不够。宇树 H1 用 MPC + PID 级联; 强化学习端到端策略可以替代 PID。
- Q: PID 和 LQR 怎么选?
- A: PID 调参简单, LQR 控制多变量更优; 工业上 PID 仍是主力。

### Q8: PPO 和 SAC 怎么选?

**标准答案**:

PPO (Proximal Policy Optimization) 和 SAC (Soft Actor-Critic) 是两个最主流的 RL 算法。

**对比**:

| 维度 | PPO | SAC |
| :--- | :--- | :--- |
| 类别 | On-policy | Off-policy |
| 样本效率 | 低 | 高 |
| 稳定性 | 高 | 中等 |
| 适用场景 | 大规模并行 (Isaac Lab) | 样本昂贵的真机任务 |

**核心机制**:

- **PPO**: 限制策略更新幅度, 通过 clip 目标函数防止崩塌。适合仿真器大规模并行。
- **SAC**: 最大熵框架, 同时优化奖励和策略随机性。样本复用率高, 适合样本贵的场景。

**具身智能的选择**:

- **大规模仿真 (Isaac Lab/Isaac Gym)**: PPO。原因: 仿真廉价, on-policy 稳定。
- **真机训练 (Locomotion)**: SAC。原因: 真机样本昂贵, off-policy 复用历史数据。
- **VLA 微调 (GR00T 等)**: PPO。原因: 大模型对更新幅度敏感。

**常见追问**:

- Q: PPO 的 clip 参数怎么设?
- A: 默认 0.1-0.2; 在策略剧烈波动时减小, 进展慢时增大。
- Q: SAC 的温度参数 α 怎么调?
- A: 自动调节 (auto-tune) 是主流; 固定 α 在 0.1-1.0 之间。

### Q9: 什么是 Diffusion Policy?

**标准答案**:

Diffusion Policy 是 2023 年由 Chelsea Finn 团队 (Stanford) 提出的,用扩散模型生成机器人动作序列的方法。

**核心思想**:

把动作生成看成"去噪过程":
1. 从高斯噪声开始 (动作序列)。
2. 通过 K 次去噪步骤, 生成连续动作序列。
3. 每步去噪用 Transformer 或 UNet, 输入当前观测 + 指令。

**相比传统方法的优点**:

- **多模态动作**: 同一观测可能对应多种合法动作 ("拿杯子" 可以从左/右/上三种方向拿), 扩散模型天然支持。
- **长序列一致**: 一次去噪出整段动作, 不是逐步决策, 避免累积误差。
- **训练稳定**: 去噪是回归任务, 不需要 reward。

**代表工作**:

- **Diffusion Policy (RSS 2023)**: 12 种任务上 SOTA。
- **Octo (Berkeley, 2024)**: 开源通用策略, 支持 Diffusion 和 Transformer。
- **π0 (Physical Intelligence, 2024)**: VLA + 扩散动作头, 50Hz 输出。

**常见追问**:

- Q: Diffusion Policy 推理速度够吗?
- A: K=100 步太慢, π0 用 K=10 + 流匹配 (Flow Matching) 加速到 50Hz。
- Q: Diffusion Policy 需要什么数据?
- A: 专家示教 (人类遥操), 100-1000 条轨迹每任务。

### Q10: 什么是域随机化 (Domain Randomization)?

**标准答案**:

域随机化是在仿真训练时随机扰动物理/视觉参数,让策略在变化中学会鲁棒特征, 从而克服 Sim2Real Gap。

**随机化的对象**:

1. **物理参数**: 质量、摩擦、阻尼、电机强度。
2. **视觉参数**: 颜色、光照、纹理、相机位姿。
3. **动力学**: 延迟、噪声、地面平整度。

**实现方式**:

```python
# 伪代码示例 (Isaac Lab)
def randomize_physics(robot):
    robot.set_mass(scale=uniform(0.8, 1.2))
    robot.set_friction(coef=uniform(0.5, 1.5))
    robot.set_motor_strength(scale=uniform(0.9, 1.1))
    lighting.set_brightness(uniform(0.5, 1.5))
    camera.set_position(jitter=normal(0, 0.02))
```

**代表案例**:

- **OpenAI Rubik's Cube (2019)**: 2000+ 参数随机化, 单手解魔方。
- **ANYmal 四足 (ETH, 2019)**: 地形+摩擦随机化, 仿真到真机一步到位。
- **Isaac Lab (NVIDIA)**: 提供 libdrandom, 标准化随机化配置。

**现代观点**: 大规模随机化 + 真实数据微调, 比单一 DR 更鲁棒。Figure 的 Helix 即两者结合。

**常见追问**:

- Q: 随机化范围怎么选?
- A: 经验法则: 覆盖真实世界物理量的 ±20%; 过大会欠拟合。
- Q: 域随机化和域适应哪个更优?
- A: DR 不需要真实数据, 但要求仿真器足够好; DA 需要少量真实数据。

## 3. 工业应用

### Q11: NVIDIA GR00T 和 Physical Intelligence π0 有什么不同?

**标准答案**:

GR00T 和 π0 都是 2024 年推出的 VLA 基础模型, 但定位和实现有显著差异。

**对比维度**:

| 维度 | GR00T N1 | π0 |
| :--- | :--- | :--- |
| 发布时间 | 2024.03 | 2024.10 (Science Robotics) |
| 训练数据 | 人类视频 + 仿真 | 大规模高质量遥操 |
| 模型规模 | 多规模 (1B/3B/7B) | 3B 通用 + 70B 蒸馏 |
| 动作头 | 流匹配 (Flow Matching) | 扩散 + 流匹配 |
| 控制频率 | 50Hz | 50Hz |
| 主要场景 | 人形 (GR00T N1) | 通用 (7 家公司机器人) |
| 开源 | 部分 (N1) | π0-OPENWEIGHTED 开源 |

**GR00T 特色**: NVIDIA Isaac Lab 仿真数据 + 互联网视频, 强调"用 GPU 算力换数据"。

**π0 特色**: 7 家创业公司联合, 共享 10^5 小时示教数据; 单一模型跨硬件部署。

**设计哲学**:

- GR00T: "GPU 即仿真器"; 算力是核心壁垒。
- π0: "数据是核心"; 跨硬件一致性是核心壁垒。

**常见追问**:

- Q: π0 比 GR00T 强在哪?
- A: 跨硬件泛化 (一种模型, 7 种机器人); 真实数据为主。
- Q: GR00T 比 π0 强在哪?
- A: 仿真规模 (Isaac Lab GPU 并行 1000x), 视频数据扩展性。

### Q12: Figure 02 的 Helix 架构有什么独特之处?

**标准答案**:

Helix 是 Figure AI 在 2025.02 发布的 VLA 模型, 首次实现"双系统协同"控制 100+ 自由度机器人。

**双系统架构**:

```text
System 2 (慢思考, VLA, 7-9 Hz):
  - 输入: 多视角图像 + 指令
  - 输出: 高级语义动作 (语义子目标)
  - 模型: 7B 参数 VLA

System 1 (快反应, 控制, 200 Hz):
  - 输入: 状态 + System 2 输出
  - 输出: 关节力矩 (50Hz) + 手指控制 (200Hz)
  - 模型: 小型 Transformer
```

**核心创新**:

1. **速度解耦**: 慢系统处理语义, 快系统处理反应。
2. **统一控制**: 一种模型同时控制躯干 (50Hz) 和手 (200Hz)。
3. **零样本泛化**: 没见过 (物体+指令) 组合也能做。

**数据规模**: 60-90 美元/小时的人类示教数据, 数百小时训练。

**工业里程碑**: 在 BMW Spartanburg 工厂 400+ 小时连续作业。

**常见追问**:

- Q: Helix 的 System 2 用什么 VLM?
- A: 自研 + Open-source VLM 蒸馏, 不完全公开。
- Q: 双系统是必须的吗?
- A: 简化控制必须; 但 Tesla Optimus 是单系统 (端到端 Transformer)。

### Q13: Tesla Optimus 的优势是什么?

**标准答案**:

Tesla Optimus 是 2022 年开始的 Tesla 人形机器人项目, 核心优势是"造车思维 + 大规模制造能力"。

**核心优势**:

1. **垂直整合**: 自研关节执行器 (谐波减速器 + 力矩电机), 自研芯片, 自研软件栈。
2. **真实数据**: 工厂员工示教 + 自动数据采集 (手套 + 多视角相机)。
3. **大规模制造**: Musk 目标年产 10 亿台 (终局), 2025 年目标 1-10 万台。
4. **自动驾驶迁移**: FSD 视觉感知、规划算法可直接复用。

**硬件参数 (Gen 2, 2024)**:

- 身高: 173 cm, 体重: 57 kg。
- 自由度: 28 (含双手各 11 个)。
- 负载: 20 kg, 行走速度: 8 km/h。
- 电池: 2.3 kWh, 续航约 8 小时。

**软件栈**:

## 4. 决策题

### Q16: 该用仿真数据还是真实数据?

**标准答案**:

**仿真数据**:

- 优点: 廉价、可大规模并行、可精确控制。
- 缺点: Sim2Real Gap, 物理建模不准。

**真实数据**:

- 优点: 分布一致, 性能天花板高。
- 缺点: 昂贵 (人类示教 $60-90/h), 规模化难。

**最佳实践**: 仿真预训练 + 真实数据微调。

**决策框架**:

```text
任务难度低 (拾取/放置)
  + 物体单一 → 仿真为主

任务难度中 (叠衣服/插花)
  + 物体多样 → 仿真+真实混合

任务难度高 (外科缝合/精密装配)
  + 严格安全 → 真实为主
```

**工业参考**: GR00T = 仿真 70% + 真实 30%; π0 = 真实 90% + 仿真 10%。

**常见追问**:

- Q: 仿真器哪个最好?
- A: Isaac Lab (NVIDIA) + MuJoCo (开源) 是 2024-2025 主流。Genesis 是新晋挑战者。
- Q: 纯仿真能不能搞定所有问题?
- A: 不能; 仿真 + 真数据是行业共识。

### Q17: 单一任务模型 vs 通用基础模型?

**标准答案**:

**单一任务模型**:

- 优点: 性能上限高 (任务级 SOTA)。
- 缺点: 不能跨任务, 不跨硬件。

**通用基础模型 (VLA)**:

- 优点: 跨任务/跨硬件, 零样本泛化。
- 缺点: 单任务性能略低, 训练资源要求高。

**决策维度**:

| 场景 | 建议 |
| :--- | :--- |
| 工厂 (固定任务/高吞吐) | 单一任务模型 |
| 家庭 (多样任务/低复用) | 通用基础模型 |
| 服务业 (固定但多变) | 混合: 通用预训练 + 单任务微调 |
| 科研/早期验证 | 通用基础模型 |

**趋势**: 通用基础模型主导 (GR00T/π0/Helix 都是通用); 单任务模型仍是工厂部署主流。

**常见追问**:

- Q: 通用模型时代小公司还有机会吗?
- A: 有, 垂直数据 + 领域适配是护城河。
- Q: 数据集谁主导?
- A: Open X-Embodiment (Google/DeepMind 联合) 主导公开数据。

### Q18: 人形 vs 轮式, 商业路径怎么选?

**标准答案**:

**人形机器人**:

- 优点: 适配人类环境 (楼梯/门把手), 通用性强。
- 缺点: 复杂 (>28 DoF), 控制难, 能耗高。

**轮式机器人**:

- 优点: 简单, 稳定, 寿命长。
- 缺点: 不能上楼梯, 受地形限制。

**决策框架**:

| 场景 | 推荐 |
| :--- | :--- |
| 工厂 (平整地面) | 轮式或人形均可 |
| 物流 (仓库) | 轮式主导 (Agility Digit 例外) |
| 家庭 (复杂地形) | 人形 |
| 商业空间 (平整 + 美观) | 取决于品牌定位 |

**经济性对比**:

- 人形: 造价 5-30 万美元, 能耗 500-1000W。
- 轮式: 造价 1-5 万美元, 能耗 100-300W。

**常见追问**:

- Q: 人形是不是过度设计?
- A: 部分是 (80% 工厂场景不需要); 但通用具身智能必须考虑环境兼容性。
- Q: 中国为什么押注人形?
- A: 国家战略 + 视觉冲击 + 资本热度; 长期合理性存疑。

### Q19: 大模型 vs 小模型, 该用哪种?

**标准答案**:

**大模型 (≥7B)**:

- 优点: 涌现行为, 多任务共享。
- 缺点: 推理慢 (50ms+), 显存大 (≥16GB)。

**小模型 (<1B)**:

- 优点: 实时 (5ms), 轻量 (单 GPU)。
- 缺点: 任务单一, 零样本差。

**选择决策**:

| 场景 | 推荐规模 |
| :--- | :--- |
| 工厂单任务 | 小模型 (100M-500M) |
| 多任务通用 | 中等 (1B-3B) |
| 家庭服务 | 大模型 (7B+) |
| 边缘部署 | 小模型 |

**2025-2026 趋势**:

- 大模型蒸馏到小模型 (GR00T N1 → Nano)。
- 端云协同: 云端大模型规划, 端侧小模型执行。
- 专用芯片: 英伟达 Thor, 华为 MDC, 特斯拉 AI4。

**常见追问**:

- Q: 7B 模型在 RTX 4090 上能跑吗?
- A: 能跑推理 (3-5 FPS), 训练需要 ≥80GB (H100/A100)。
- Q: 量化能加速多少?
- A: INT8 减少 4x 显存, 速度提升 1.5-2x; 精度损失 < 2%。

### Q20: 开源 vs 闭源, 谁会赢?

**标准答案**:

**开源派** (优势):

- 学术界认可 (OpenVLA, Octo, GR00T N1)。
- 社区贡献快 (RDX 反馈)。
- 数据/代码透明 (利于监管)。

**闭源派** (优势):

- 商业护城河 (Figure Helix, Tesla FSD)。
- 数据积累 (Tesla 工厂视频, Figure BMW 视频)。
- 商业回报闭环。

**当前格局**:

- VLA 模型层: 开源 (OpenVLA, π0 OPENWEIGHTED)。
- 数据集: 开源 (Open X-Embodiment, DROID)。
- 应用层: 闭源 (Figure Helix, Optimus)。

**预测**:

| 时间 | 模型层 | 应用层 |
| :--- | :--- | :--- |
| 2025 | 开源主导 | 闭源 |
| 2027 | 开源 + 大厂分化 | 闭源为主 |
| 2030 | 闭源为主 (类似 LLM) | 闭源 + 垂直开源 |

**类比**: LLM 行业也经历过类似分化 (Meta Llama 开源, OpenAI/Anthropic 闭源)。

**常见追问**:

- Q: 开源 VLA 哪个最好用?
- A: OpenVLA-7B (Berkeley) + Octo (Stanford) 是 2025 主流。
- Q: 中国公司会主导开源吗?
- A: 部分可能 (智元 GO-1, 银河通用); 但国际社区更通用。

## 5. 实战题

### Q21: 如何开始一个具身智能项目?

**标准答案 (5 步法)**:

**第 1 步: 选场景** (1 周)。

- 推荐简单场景 (叠衣服 / 拾取物体)。
- 评估环境约束 (光照/物体多样性)。

**第 2 步: 选硬件** (1-2 周)。

- 推荐平台: 宇树 G1 (研发) + Franka Panda (学术) + Hey5 (消费)。
- 算力: 单 RTX 4090 起步 (≥16GB) 是最低门槛。

**第 3 步: 选数据集** (2-4 周)。

- 公开: Open X-Embodiment (大), DROID (多任务)。
- 自采集: 人类示教 ($60-90/h)。

**第 4 步: 选基模** (1 周)。

- 通用基模: OpenVLA-7B / π0-OPENWEIGHTED / GR00T N1。
- 训练: Isaac Lab 仿真 + 真实微调。

**第 5 步: 部署与评估** (4-8 周)。

- 仿真评估: 1000+ 场景覆盖率。
- 真机评估: 10+ 真实测试, 视频记录。

**项目估算**:

| 任务难度 | 团队规模 | 时间 | 预算 |
| :--- | :--- | :--- | :--- |
| 简单拾放 | 3 人 | 2-3 月 | $50-100K |
| 中等装配 | 5 人 | 6 月 | $300K-1M |
| 通用家庭 | 10 人 | 18 月 | $3M+ |

**常见追问**:

- Q: 学校实验室怎么做?
- A: 用开源基模 + 公开数据集, 单 GPU 够学术 demo。
- Q: 工业团队怎么做?
- A: 垂直数据是护城河, 自研/采购基模均可。

### Q24: Figure Helix 双系统的损失函数如何设计?

**标准答案**:

Helix 是 2025.02 Figure AI 发布的高频 VLA (S2 7-9Hz + S1 200Hz)。面试重点在于双系统的协同训练目标。

**双系统分解**:

```text
┌─────────────────────────────────────────────────────────┐
│  System 2 (慢语义, VLA, 7-9 Hz)                         │
│  输出: 语义动作子目标 z ∈ R^7 (位置 + 6D 旋转)          │
│  损失: L_S2 = ||z_pred - z_gt||_2 + λ_smooth ||Δz||_1   │
└─────────────────────┬───────────────────────────────────┘
                      │ 每 12 个 S2 步 (= 200ms)
                      ▼
┌─────────────────────────────────────────────────────────┐
│  System 1 (快反应, 小 Transformer, 200 Hz)               │
│  输入: 关节状态 + S2 子目标 z_t                          │
│  输出: 关节力矩 τ ∈ R^28 + 手指增量 Δf                   │
│  损失: L_S1 = ||τ_pred - τ_demo||_2 + α * 阻抗一致性项  │
└─────────────────────────────────────────────────────────┘
```

**关键设计点**: S2 跑大模型 (7B), S1 跑小模型 (~80M), 各自反向传播; S2 预测"中间意图", S1 学"达到意图的轨迹"; 数据 BMW 工厂 + 遥操 7:3。

### Q28: 1X Technologies 家用机器人的安全 RL

**标准答案**:

1X Technologies (挪威, OpenAI 投资) 主攻家用, 强调安全约束。2025 发布 NEO Beta。面试重点是"Lagrangian 安全约束"。

**安全 RL 公式**:

$$\max_\pi \mathbb{E}_{\tau \sim \pi} \left[ \sum_t r(s_t, a_t) \right] \quad \text{s.t.} \quad \mathbb{E}_{\tau \sim \pi} \left[ \sum_t c(s_t, a_t) \right] \leq d$$

其中 $c$ 是成本函数 (如"接近人体 < 0.3m 时为 1"), $d$ 是阈值。

**Lagrangian 解法**:

$$\min_{\lambda \geq 0} \max_\pi \mathbb{E} \left[ \sum_t r_t - \lambda (c_t - d) \right]$$

对偶变量 $\lambda$ 自动调整约束严格度。

**1X 的成本函数示例**:

```python
def cost_fn(state, action):
    cost = 0
    if state['human_dist'] < 0.3:  cost += 1.0   # 接近人体
    if abs(action['torque']).max() > 50: cost += 0.5  # 力矩超限
    if state['base_vel'] > 1.5: cost += 0.3   # 速度过大
    return cost
```

**常见追问**:

- Q: Lagrangian 在 GPU 仿真上能跑吗?
  - A: 能, 但 $\lambda$ 更新频率要慢 (10x policy), 否则震荡。
- Q: 家用机器人最大风险?
  - A: 物体掉落砸人 (数据里 80% 故障来自此), 而非碰撞。

### 14.1 Diffusion Policy 简化版 (80 行核心)

```python
"""
Diffusion Policy 极简实现: 面试手撕版
核心: 条件去噪 UNet, 输入 obs+action 序列, K 步去噪
"""
import torch
import torch.nn as nn
import torch.nn.functional as F
from torch import Tensor

class SinusoidalPosEmb(nn.Module):
    """时间步 t 的位置编码"""
    def __init__(self, dim): super().__init__(); self.dim = dim
    def forward(self, t):
        half = self.dim // 2
        emb = torch.exp(-torch.arange(half) * 4 * torch.log(torch.tensor(10000.0)) / half)
        emb = t[:, None] * emb[None].to(t.device)
        return torch.cat([emb.sin(), emb.cos()], dim=-1)

class DenoiseUNet1D(nn.Module):
    """1D UNet: 输入 (B, T, obs_dim+action_dim), 输出 (B, T, action_dim)"""
    def __init__(self, obs_dim, action_dim, horizon=16, hidden=128):
        super().__init__()
        self.time_emb = SinusoidalPosEmb(hidden)
        self.in_proj = nn.Linear(obs_dim + action_dim, hidden)
        self.down1 = nn.Conv1d(hidden, hidden*2, 3, padding=1)
        self.down2 = nn.Conv1d(hidden*2, hidden*4, 3, padding=1)
        self.mid   = nn.Conv1d(hidden*4, hidden*4, 3, padding=1)
        self.up1   = nn.Conv1d(hidden*4, hidden*2, 3, padding=1)
        self.up2   = nn.Conv1d(hidden*2, hidden, 3, padding=1)
        self.out   = nn.Linear(hidden, action_dim)
        self.horizon = horizon
    def forward(self, noisy_action: Tensor, t: Tensor, obs: Tensor) -> Tensor:
        # noisy_action: (B, T, action_dim), t: (B,), obs: (B, obs_dim)
        B, T, _ = noisy_action.shape
        x = torch.cat([noisy_action, obs[:, None].expand(-1, T, -1)], dim=-1)
        x = self.in_proj(x).transpose(1, 2)  # (B, hidden, T)
        x = F.relu(self.down1(x))
        x = F.relu(self.down2(x))
        x = F.relu(self.mid(x) + self.time_emb(t)[:, :, None])
        x = F.relu(self.up1(x))
        x = F.relu(self.up2(x)).transpose(1, 2)
        return self.out(x)

class DiffusionPolicy(nn.Module):
    def __init__(self, obs_dim, action_dim, horizon=16, n_diff=100):
        super().__init__()
        self.net = DenoiseUNet1D(obs_dim, action_dim, horizon)
        self.n_diff = n_diff
        self.betas = torch.linspace(1e-4, 2e-2, n_diff)  # DDPM schedule
        self.alphas = 1.0 - self.betas
        self.alpha_bars = torch.cumprod(self.alphas, dim=0)

    def loss(self, action: Tensor, obs: Tensor) -> Tensor:
        B = action.shape[0]
        t = torch.randint(0, self.n_diff, (B,), device=action.device)
        noise = torch.randn_like(action)
        a_bar = self.alpha_bars[t][:, None, None]
        noisy = torch.sqrt(a_bar) * action + torch.sqrt(1 - a_bar) * noise
        pred = self.net(noisy, t, obs)
        return F.mse_loss(pred, noise)

    @torch.no_grad()
    def sample(self, obs: Tensor) -> Tensor:
        B = obs.shape[0]
        a = torch.randn(B, self.net.horizon, action_dim := self.net.out.out_features, device=obs.device)
        for t in reversed(range(self.n_diff)):
            pred = self.net(a, torch.full((B,), t, device=obs.device), obs)
            alpha = self.alphas[t]; ab = self.alpha_bars[t]
            a = (a - (1 - alpha) / torch.sqrt(1 - ab) * pred) / torch.sqrt(alpha)
            if t > 0:
                a += torch.sqrt(self.betas[t]) * torch.randn_like(a)
        return a

# ponytail: K=100 步去噪是面试常考点; 工业版用 DDIM 加速到 K=10
```

**面试追问**:

- Q: 为什么 K=100 步太慢?
  - A: π0/GR00T 用 DDIM + Flow Matching 加速到 K=10。
- Q: 训练时 t 怎么采样?
  - A: 均匀采样最常用; loss-weighted 采样能加速收敛 2x。

```python
"""
RoPE (Rotary Position Embedding) 面试手撕版
核心: 把位置信息编码成 query/key 的旋转变换
"""
import torch
import math

def precompute_freqs(dim: int, max_seq: int, base: float = 10000.0):
    """预计算 cos/sin 表: (max_seq, dim/2)"""
    # θ_i = 1 / (base^(2i/dim))
    freqs = 1.0 / (base ** (torch.arange(0, dim, 2)[: dim // 2].float() / dim))
    t = torch.arange(max_seq, device=freqs.device)
    angles = torch.outer(t, freqs)  # (max_seq, dim/2)
    return torch.cos(angles), torch.sin(angles)

def apply_rope(x, cos, sin):
    """
    x: (B, n_heads, seq_len, head_dim)
    cos/sin: (seq_len, head_dim/2)
    """
    x1, x2 = x[..., 0::2], x[..., 1::2]  # (B, h, T, d/2)
    cos = cos[None, None, :, :]
    sin = sin[None, None, :, :]
    rot1 = x1 * cos - x2 * sin
    rot2 = x1 * sin + x2 * cos
    out = torch.stack([rot1, rot2], dim=-1).flatten(-2)
    return out

# ponytail: 关键考点是证明 <R(a,m), R(b,n)> = g(a,b,m-n), 即相对位置性
```

### 14.3 PPO clipped objective

```python
"""
PPO clipped surrogate objective
L_clip = E[min(r(θ)A, clip(r(θ), 1-ε, 1+ε)A)]
"""
def ppo_loss(logp_new, logp_old, advantages, clip=0.2):
    ratio = (logp_new - logp_old).exp()  # π_new / π_old
    surr1 = ratio * advantages
    surr2 = ratio.clamp(1 - clip, 1 + clip) * advantages
    return -torch.min(surr1, surr2).mean()
```

## 15. 数学推导补充 (L7/L8 深度)

### 15.1 Flow Matching 推导

**问题**: 给定源分布 $p_0(x)$ (高斯) 和目标分布 $p_1(x)$ (动作), 求 ODE 把 $p_0$ 推到 $p_1$。

**Linear interpolation**: $x_t = (1-t) x_0 + t x_1$, 速度场 $v_t = x_1 - x_0$。

**学习目标**:

$$L = \mathbb{E}_{t, x_0, x_1} \left[ \| v_\theta(x_t, t) - (x_1 - x_0) \|^2 \right]$$

**采样 (Euler ODE)**: $x_{t + \Delta t} = x_t + \Delta t \cdot v_\theta(x_t, t)$。

**对比 Diffusion**: DDPM K=100 步随机漫步, Flow Matching K=10 步直线; 训练目标 Flow Matching 精确匹配, DDPM 是 ELBO 下界。π0 用 Flow Matching K=10 生成 50Hz 动作。

### 15.2 3D Gaussian Splatting 在具身的应用

**3DGS 体渲染**: $C = \sum_{i=1}^{N} T_i \alpha_i c_i$, $T_i = \prod_{j=1}^{i-1} (1 - \alpha_j)$。每个高斯有均值 $\mu$, 协方差 $\Sigma$, 不透明度 $\alpha$。

**具身应用** (2024-2026): 1) 重建 + 抓取采样; 2) Sim2Real 桥接; 3) 世界模型记忆。

**代表**: SplAt (NeurIPS 2024), Gaussian Splatting Manipulation (RSS 2024)。

### 15.3 IK 闭式解 (6-DoF Pieper)

**腕心位置**: $p_w = p_{target} - d_6 \cdot R_{target} \cdot \hat{z}$。

**三角法求 $\theta_3$** (余弦定理):

$$\cos\theta_3 = \frac{\|p_w\|^2 - a_2^2 - a_3^2 - d_4^2}{2 a_2 \sqrt{a_3^2 + d_4^2}}$$

姿态求 $\theta_4, \theta_5, \theta_6$ 从 $R_{0,3}^{-1} R_{target}$ 解 ZYZ 欧拉角。

**面试考点**: 多解 (8 组), 选最优 (最小关节位移)。

### 23.1 SAC 简化版 (Soft Actor-Critic)

```python
"""SAC: 最大熵 Off-Policy Actor-Critic"""
import torch, torch.nn as nn, torch.nn.functional as F

class GaussianPolicy(nn.Module):
    def __init__(self, od, ad, h=256):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(od, h), nn.ReLU(),
                                 nn.Linear(h, h), nn.ReLU())
        self.mu = nn.Linear(h, ad); self.ls = nn.Linear(h, ad)
    def forward(self, x):
        h = self.net(x); return self.mu(h), self.ls(h).clamp(-20, 2)
    def sample(self, x):
        mu, ls = self.forward(x); std = ls.exp()
        a = mu + std * torch.randn_like(mu)
        lp = -0.5 * (((a-mu)/(std+1e-8))**2 + 2*ls).sum(-1)
        return a.tanh(), lp

class QNet(nn.Module):
    def __init__(self, od, ad, h=256):
        super().__init__()
        self.net = nn.Sequential(nn.Linear(od+ad, h), nn.ReLU(),
                                 nn.Linear(h, h), nn.ReLU(),
                                 nn.Linear(h, 1))
    def forward(self, o, a):
        return self.net(torch.cat([o, a], -1)).squeeze(-1)

def sac_loss(q1, q2, tq, lp, a=0.2):
    soft = tq - a * lp
    ql = F.mse_loss(q1, soft.detach()) + F.mse_loss(q2, soft.detach())
    pl = (a * lp - torch.min(q1, q2)).mean()
    return ql + pl

# ponytail: alpha auto-tune 是工业默认; 上面用固定 α 演示
```

### 23.2 GAE (简化版)

```python
"""GAE: 倒序累加 (gamma*lambda)^l 加权 delta"""
def gae(r, v, d, g=0.99, l=0.95):
    T, B = r.shape
    A = torch.zeros(T, B); last = torch.zeros(B)
    for t in reversed(range(T)):
        delta = r[t] + g*v[t+1]*(1-d[t]) - v[t]
        last = delta + g*l*(1-d[t])*last
        A[t] = last
    return A, A + v[:-1]
# ponytail: dones 是 t 时刻 (环境是否已终止)
```

## 📚 深度扩展: 具身智能面试 Q&A

> 本节对正文做工业落地向的纵深扩展, 兼顾理论与 PyTorch 实现.

### 一、理论深耕 — 公式与可证伪假设

#### 1.1 具身控制的统一范式

把具身决策视为在状态 $s \in \mathcal{S}$, 动作 $a \in \mathcal{A}$, 奖励 $r \in \mathbb{R}$ 上的 POMDP:

$$
\pi_\theta(a\mid s)=\arg\max_\theta \mathbb{E}_{a\sim\pi_\theta}\!\Big[\sum_{t}\gamma^t r(s_t,a_t)\Big]
$$

其中 $s_t$ 通常是部分可观测的, 因此常用**历史观测编码** $h_t=\text{Enc}(o_{1:t})$ 替代状态. 现代 VLA 用 LLM Tokenizer 编码 $h_t$, 由下一个 token 解码动作.

#### 1.2 模仿学习的 DAgger 修正

设 expert policy $\pi^*$ 与 imitator $\pi_\theta$, BC 损失:

$$
\mathcal{L}_\text{BC}(\theta) = -\mathbb{E}_{(s,a)\sim\pi^*}\!\big[\log \pi_\theta(a\mid s)\big]
$$

DAgger 引入 on-policy 状态分布:

$$
\mathcal{L}_\text{DAgger}(\theta) = -\mathbb{E}_{s\sim\pi_\theta}\!\big[\log \pi_\theta(a\mid s)\big]
$$

实践 DAgger 在长尾状态上更鲁棒, 但工程上需要 online rollout, 开销大.

#### 1.3 Sim2Real 域随机化的理论支持

设仿真器环境 $\mathcal{E}_\text{sim}$ 与真实环境 $\mathcal{E}_\text{real}$ 的差距 $\Delta(\cdot,\cdot)$ 度量 (常用 FID 或物理量误差), 域随机化目标:

$$
\min_\theta \max_\phi \mathbb{E}_{\xi\sim\Omega_\phi}\!\big[\mathcal{L}(\pi_\theta;\mathcal{E}_\text{sim}(\xi))\big] \quad\text{s.t.}\ \Delta\big(\mathcal{E}_\text{sim}(\xi),\mathcal{E}_\text{real}\big)\le\epsilon
$$

实践中 `xi` 涵盖视觉 (光照/纹理) + 物理 (摩擦/质量) + 传感器噪声; 增加到 `xi` 维度虽多, 但每个取值域不必连续 (离散化即可).

#### 1.4 VLA 的 token 化动作表征

把连续动作 $a \in \mathbb{R}^n$ 离散化为 $K$ 个 token:

$$
a \mapsto (t_1,\dots,t_K), \quad t_i=\arg\min_{k}\|\frac{2k-K-1}{K-1}-a_i/d\|_2
$$

再以自回归 Transformer 学习 $p(t_i \mid t_{<i}, h_t)$. 该表征与文本/视觉 token 同构, 是 VLA 复用 LLM 主干的物理基础.

### 二、PyTorch 完整实现

#### 2.1 一个最小 VLA 决策头

```python
import torch
import torch.nn as nn
import torch.nn.functional as F

class ActionTokenizer(nn.Module):
    def __init__(self, action_dim, num_bins=256):
        super().__init__()
        self.num_bins = num_bins
        self.action_dim = action_dim
        self.bin_centers = torch.linspace(-1.0, 1.0, num_bins)

    def encode(self, a):
        centers = self.bin_centers.to(a.device)
        a_exp = a.unsqueeze(-1)
        c_exp = centers.view(1, 1, -1)
        idx = (a_exp - c_exp).abs().argmin(-1)
        return idx

    def decode(self, idx):
        centers = self.bin_centers.to(idx.device)
        return centers[idx]


class MinimalVLA(nn.Module):
    def __init__(self, d_llm=512, action_dim=7, num_bins=256, num_layers=2, nhead=8):
        super().__init__()
        self.action_tok = ActionTokenizer(action_dim, num_bins)
        self.token_emb = nn.Embedding(num_bins, d_llm)
        self.in_proj = nn.Linear(d_llm * 2, d_llm)
        layer = nn.TransformerDecoderLayer(
            d_model=d_llm, nhead=nhead, dim_feedforward=d_llm * 4,
            dropout=0.1, batch_first=True, activation='gelu')
        self.decoder = nn.TransformerDecoder(layer, num_layers=num_layers)
        self.out = nn.Linear(d_llm, num_bins)

    def forward(self, text_emb, vision_emb, prev_action=None):
        B = text_emb.shape[0]
        if prev_action is None:
            prev_action = torch.zeros(B, 7, dtype=torch.long, device=text_emb.device)
        prev_tok = self.token_emb(prev_action)
        ctx = self.in_proj(torch.cat([text_emb, vision_emb], dim=1))
        tgt = prev_tok
        causal = torch.triu(torch.ones(tgt.size(1), tgt.size(1), device=tgt.device), 1).bool()
        h = self.decoder(tgt, ctx, tgt_mask=causal)
        return self.out(h)
```

```python
    logits = model(text_emb, vision_emb, prev_action=action[:, :-1])
    targets = action[:, 1:]
    loss = F.cross_entropy(logits.reshape(-1, logits.size(-1)), targets.reshape(-1))
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    return loss.item()
```

#### 2.3 PPO 在仿真器中的训练循环骨架

```python
import torch
from torch.distributions import Categorical

def ppo_step(actor, critic, optimizer, batch_obs, batch_act, batch_adv, batch_old_logp, batch_ret,
             eps_clip=0.2, vf_coef=0.5, ent_coef=0.01):
    logits = actor(batch_obs)
    dist = Categorical(logits=logits)
    logp = dist.log_prob(batch_act)
    ratio = (logp - batch_old_logp).exp()
    surr1 = ratio * batch_adv
    surr2 = torch.clamp(ratio, 1 - eps_clip, 1 + eps_clip) * batch_adv
    policy_loss = -torch.min(surr1, surr2).mean()
    value_loss = ((critic(batch_obs) - batch_ret) ** 2).mean()
    ent = dist.entropy().mean()
    loss = policy_loss + vf_coef * value_loss - ent_coef * ent
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    return loss.item(), policy_loss.item(), value_loss.item(), ent.item()
```

### 三、工业 / 学术案例 — Google RT-2 / OpenVLA / Diffusion Policy / π0

#### 3.1 RT-2 (Google, 2023)

- **思路**: 直接 fine-tune PaLM-E / PaLM-XS 在机器人轨迹 + 文本指令上, 共享 token 表.
- **优势**: 零样本迁移到新指令; 大模型预训练知识继承.
- **限制**: 推理贵, 延迟 200-500ms, 不适合实时闭环.
- **可借鉴**: 视觉-语言联合 token 化, 多个模态共用 transformer 解码器.

#### 3.2 OpenVLA (2024)

- **思路**: 7B 参数开源 VLA, 用 SigLIP + Llama 2 7B 拼装.
- **数据**: Open X-Embodiment, 800k+ episodes.
- **结果**: 单 GPU 推理 < 100ms, 在多个桌面操作任务上击败 RT-2.
- **可借鉴**: 数据混合策略, 训练用 cosine LR + 2 epoch warmup.

#### 3.3 Diffusion Policy (2024)

- **思路**: 把动作序列视为 $T_a$ 步的扩散过程, DDPM 训练; 在线 5-step DDIM 推理.
- **优势**: 多模态动作分布自然建模; 长 horizon 稳定.
- **限制**: 推理需多次 UNet forward, 仿真器训练时间约为 VLA 的 4 倍.
- **可借鉴**: 把 action chunking (16 步) 用 diffusion 一次输出, 闭环稳定性提高.

#### 3.4 π0 (Physical Intelligence, 2024)

- **思路**: VLM 主干 + flow matching 动作输出, 在 5+ 真实家庭任务上 90%+ 成功率.
- **数据**: 跨 embodiment 混合 + 仿真-真实联合.
- **可借鉴**: flow matching 替代 diffusion, 推理次数从 5-10 降到 1-3.

### 五、常见陷阱与最佳实践

1. **仿真-真实差距**: 仿真里成功率 95% 不代表现实 60%; 必须做域随机化.
2. **动作归一化**: 训练时务必把连续动作除以最大动作范围 + clip 到 `+-1`, 否则 loss 数值不稳.
3. **VLA 长尾**: VLA 在训练集之外的指令上可能"瞎做"; 至少保留 10% 真实人类指令测试.
4. **PPO 数值不稳定**: reward scale 影响极大, 推荐 `r / std(recent_rewards)`.
5. **域随机化调参**: 物理参数采样范围太宽会导致策略不收敛; 推荐逐步扩大.
6. **VLA 显存**: 7B 模型 + 20 帧视觉序列在 A100 上 30GB+; 推荐 gradient checkpointing + fp16.
7. **Diffusion Policy 推理**: DDIM 步数从 100 降到 5 时, 性能略有下降但速度飞快, 工业首选.
8. **数据混合**: 多 embodiment 训练时, 数据量占比应大致按"1/N"稀释.

### 一、完整训练管线 (PyTorch Lightning 风格, 不依赖 Lightning)

```python
import torch
import torch.nn as nn
from torch.utils.data import DataLoader, Dataset
from torch.cuda.amp import autocast, GradScaler

class NPZDataset(Dataset):
    # numpy / parquet 通用 dataset
    def __init__(self, path, columns, label_col, length=1024):
        import numpy as np
        arr = np.load(path)
        self.x = {c: arr[c] for c in columns}
        self.y = arr[label_col]
        self.length = length
    def __len__(self):
        return self.length
    def __getitem__(self, i):
        return ({k: torch.as_tensor(v[i]) for k, v in self.x.items()},
                torch.as_tensor(self.y[i], dtype=torch.float32))


def train_one_epoch(model, loader, optimizer, scaler, device, log_every=200, max_step=10000):
    model.train()
    total_loss, n_seen, n_step = 0.0, 0, 0
    for x, y in loader:
        x = {k: v.to(device, non_blocking=True) for k, v in x.items()}
        y = y.to(device, non_blocking=True)
        optimizer.zero_grad(set_to_none=True)
        with autocast(dtype=torch.bfloat16):
            logits = model(**x)
            loss = nn.functional.binary_cross_entropy_with_logits(logits, y)
        scaler.scale(loss).backward()
        scaler.unscale_(optimizer)
        torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        scaler.step(optimizer); scaler.update()
        total_loss += loss.item() * y.size(0); n_seen += y.size(0); n_step += 1
        if n_step % log_every == 0:
            print(f"step={n_step} loss={total_loss/max(n_seen,1):.4f}")
        if n_step >= max_step:
            break
    return total_loss / max(n_seen, 1)


def evaluate(model, loader, device):
    model.eval()
    preds, labels = [], []
    with torch.no_grad(), autocast(dtype=torch.bfloat16):
        for x, y in loader:
            x = {k: v.to(device, non_blocking=True) for k, v in x.items()}
            p = torch.sigmoid(model(**x)).cpu().numpy()
            preds.append(p); labels.append(y.numpy())
    import numpy as np
    p = np.concatenate(preds); l = np.concatenate(labels)
    from sklearn.metrics import roc_auc_score, log_loss
    return {"auc": roc_auc_score(l, p), "logloss": log_loss(l, p)}
```

#### 1.2 AdamW + cosine LR with warmup

```python
from torch.optim.lr_scheduler import LambdaLR
import math

def cosine_warmup(optimizer, warmup_steps, total_steps):
    def fn(step):
        if step < warmup_steps:
            return step / max(1, warmup_steps)
        progress = (step - warmup_steps) / max(1, total_steps - warmup_steps)
        return 0.5 * (1.0 + math.cos(math.pi * progress))
    return LambdaLR(optimizer, fn)

optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4, betas=(0.9, 0.95), weight_decay=0.05)
```

#### 3.3 显著性检验 (z-test for CTR)

```python
import math
def z_test(p1, n1, p2, n2):
    p_pool = (p1*n1 + p2*n2) / (n1 + n2)
    se = math.sqrt(p_pool * (1 - p_pool) * (1/n1 + 1/n2))
    z = (p2 - p1) / se
    from math import erf, sqrt
    pval = 2 * (1 - 0.5 * (1 + erf(abs(z) / sqrt(2))))
    return z, pval
```

### 五、Debug 与故障排查

#### 5.1 Loss = NaN 排查清单

1. bf16 下溢出: 切换 fp32 验证.
2. 学习率太大: 降 10x 再试.
3. 标签有 -1 / 异常值: print 唯一值.
4. 注意力 mask 反转: 用浮点加性 mask (`(1-m)*-1e4`).
5. 类别不平衡: focal loss 或 class weight.

#### 5.2 AUC 不涨 / 降

1. 训练/测试 leakage: 检查 train/eval pipeline 一致性.
2. 标签错位: 检查 time-based split.
3. 特征漂移: 监控 PSI, 加回旧域样本.
4. 模型容量不够: 加宽 / 加深.

#### 5.3 推理延迟高

1. ONNX 算子: 用 TRT 替代部分 cuda kernel.
2. 动态 shape: 用 dynamic_axes + 静态 shape 预热.
3. cache miss: Faiss HNSW 改 IVF + PQ.
4. 序列化: pickle vs msgpack, 序列化占比 30% 时该压缩.
