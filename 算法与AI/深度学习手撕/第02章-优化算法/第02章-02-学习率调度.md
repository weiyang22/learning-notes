# 第02章-02-学习率调度

绍

学习率 $\eta$ 是最重要的超参。固定 LR 往往不是最优: 训练初期需要小 LR **预热(warmup)** 稳住, 中期大 LR 快速下降, 后期小 LR **退火(decay)** 精细收敛。Scheduler 就是按 step/epoch 动态调整 $\eta$ 的策略。

---

## 2. 为什么要 Warmup + Decay

**Warmup(线性升温)**: 训练初期参数随机、梯度方向噪声大, 尤其 Adam 的二阶动量估计还不稳。直接大 LR 会震荡甚至发散。先用几百~几千步把 LR 从 0 线性升到峰值, 让统计量"热身"。

**Decay(退火)**: 接近最优点时, 大步长会在最小值附近来回跳。逐步减小 LR 让模型稳定收敛到更平坦的极小值(泛化更好)。

> Transformer 训练几乎必用 **warmup + cosine/inverse-sqrt decay**, 否则很难训稳。

---

## 3. 方案对比

| 调度器 | 曲线 | 适用 |
|---|---|---|
| StepLR | 阶梯下降 | CV 传统(ResNet) |
| Cosine Annealing | 余弦平滑降到 0 | 通用, LLM/CV 主流 |
| Linear Warmup + Cosine | 先升后余弦降 | **LLM 预训练标配** |
| Inverse Sqrt | $1/\sqrt{step}$ | 原始 Transformer |
| OneCycle | 升到峰再降 | 快速训练(super-convergence) |

## 4. 手撕实现

### 4.1 Warmup + Cosine(最常用, 手动实现)

```python
import math

def lr_lambda(step, warmup, total, base_lr, min_lr=0.0):
    if step < warmup:                                  # 线性预热
        return base_lr * step / max(1, warmup)
    # 余弦退火: 从 base_lr 平滑降到 min_lr
    progress = (step - warmup) / max(1, total - warmup)
    cos = 0.5 * (1 + math.cos(math.pi * progress))     # 1 -> 0
    return min_lr + (base_lr - min_lr) * cos

# 手动写进训练循环:
for step in range(total_steps):
    lr = lr_lambda(step, warmup=2000, total=total_steps, base_lr=3e-4)
    for g in optimizer.param_groups:
        g["lr"] = lr
    # ... forward / backward / step ...
```

### 4.2 用 PyTorch LambdaLR 封装

```python
from torch.optim.lr_scheduler import LambdaLR

def make_scheduler(opt, warmup, total):
    def f(step):                                       # 返回相对 base_lr 的倍率
        if step < warmup:
            return step / max(1, warmup)
        progress = (step - warmup) / max(1, total - warmup)
        return 0.5 * (1 + math.cos(math.pi * progress))
    return LambdaLR(opt, f)

sched = make_scheduler(optimizer, 2000, 100000)
# 每个 step 后: optimizer.step(); sched.step()
```

### 4.3 手撕 OneCycle 核心

```python
def onecycle(step, total, max_lr, pct_up=0.3):
    up = int(total * pct_up)
    if step < up:                                      # 升: 从 max/25 到 max
        return max_lr/25 + (max_lr - max_lr/25) * step / up
    progress = (step - up) / (total - up)              # 降: 余弦到极小
    return max_lr * 0.5 * (1 + math.cos(math.pi * progress))
```

## 5. 实战要点

- **LR 与 batch size 同增**: batch ×k, LR ≈ ×k(线性缩放法则)。
- **warmup 步数**: 通常总步数的 1-5%, 或固定 2000 步。
- **AdamW + cosine** 是 LLM 黄金组合; scheduler 必须每 step 调用并存进 checkpoint(见 [7.4 检查点策略](../第07章-训练技术/第07章-04-检查点策略.md))。

## 6. 面试高频

1. 为什么 Transformer 一定要 warmup? → 初期 Adam 二阶矩不稳, 大 LR 易发散。
2. Cosine 为什么比 Step 好? → 平滑无突变, 末期 LR 趋 0 收敛更细。
3. LR 和 batch size 的关系? → 线性缩放, 大 batch 配大 LR + 更长 warmup。

## 7. 理论基础：学习率为什么决定优化动力学

学习率是离散优化系统的时间步长。调度器不是装饰，而是在“探索速度、稳定性、最终精度、训练预算”之间分配步长。

### 7.1 二次函数上的稳定条件

对 $f(w)=\frac12aw^2$，梯度下降为：

$$w_{t+1}=w_t-\eta aw_t=(1-\eta a)w_t.$$

收敛要求 $|1-\eta a|<1$，即：

$$0<\eta<\frac{2}{a}.$$

多维二次函数 $f(w)=\frac12w^THw$ 的最严格方向由最大特征值 $\lambda_{max}$ 决定：$0<\eta<2/\lambda_{max}$。训练中曲率随位置变化，因此固定 LR 很难兼顾全程。

### 7.2 随机梯度的噪声—步长权衡

设随机梯度 $g_t=\nabla f(w_t)+\xi_t$，噪声协方差随 batch 增大而下降。较大 LR 能快速移动并跨越尖锐 basin，但噪声项的更新幅度也随 LR 放大；后期衰减可降低稳态误差。

### 7.3 Warmup 的三个解释

1. **统计量解释**：Adam 的一、二阶动量刚开始估计不稳。
2. **曲率解释**：初始化附近可能出现大曲率与激活异常，大步长越过稳定域。
3. **大 batch 解释**：线性缩放后的峰值 LR 很大，需要渐进过渡。

Warmup 不是修复坏数据或错误 loss 的万能药；若 warmup 结束必爆，先检查 peak LR、梯度范数、初始化和数据。

### 7.4 Decay 的优化含义

退火降低最优点附近的离散振荡与梯度噪声，使参数能在固定预算末段做细粒度更新。floor 非零表示系统仍保留适应能力；降到零表示明确终止学习。

### 7.5 调度器时钟

- **epoch clock**：适合固定数据集与传统 CV recipe。
- **optimizer-update clock**：适合梯度累积、OneCycle、Transformer。
- **sample clock**：适合 global batch 改变的训练。
- **token clock**：适合动态 packing 与变长序列的大模型。

任何公式都必须同时写清时钟单位，否则超参无法复现。

## 8. 调度器图谱：34 种策略

### 8.1 调度卡 01：Constant

- **公式**：$η_t=η_0$
- **曲线**：全程固定。
- **论文/来源**：Robbins–Monro 1951 随机逼近背景。
- **适用**：短程微调、作为消融基线。
- **时钟**：step 或 epoch 均可，但必须固定语义。
- **关键陷阱**：后期围绕最优点震荡。

**实现验收**：

1. 离线采样首点、warmup 边界、峰值、衰减起点和终点。
2. 断言所有 LR 有限且非负。
3. 明确 scheduler.step 与 optimizer.step 的调用次数。
4. 模拟 checkpoint 恢复，下一步 LR 与连续训练一致。

### 8.2 调度卡 02：Step Decay

- **公式**：$η_t=η_0γ^{⌊t/s⌋}$
- **曲线**：每隔 s 步乘 γ。
- **论文/来源**：经典 CNN 训练配方。
- **适用**：ResNet/CIFAR/ImageNet 传统训练。
- **时钟**：通常按 epoch。
- **关键陷阱**：里程碑处突变导致 loss 抖动。

### 9.1 实验 01：纯函数 warmup+cosine

```python
def warmup_cosine(step, warmup, total, peak, floor=0.0):
    if not 0 <= step <= total:
        raise ValueError("step out of range")
    if step < warmup:
        return peak * (step + 1) / max(1, warmup)
    p = (step - warmup) / max(1, total - warmup)
    return floor + 0.5 * (peak-floor) * (1 + math.cos(math.pi*p))
```

**验收**：首个更新非零；若要求从 0 开始，把 step+1 改为 step 并明确语义。

### 9.18 实验 18：WSD 纯函数

```python
def wsd(step, warmup, stable_end, total, peak, floor):
    if step < warmup:
        return peak * (step + 1) / warmup
    if step < stable_end:

    p = (step - stable_end) / max(1, total - stable_end)
    return floor + 0.5*(peak-floor)*(1+math.cos(math.pi*p))
```

**验收**：适合终点可能延长的训练：延长 stable，再单独规划 decay。

**工业补充**：把公式参数、总预算、时钟单位与调用位置写入训练配置和日志。

### 9.19 实验 19：Plateau 去噪

```python
ema = beta * ema + (1-beta) * val_loss
ema_corrected = ema / (1 - beta**num_validations)
scheduler.step(ema_corrected)
```

**验收**：高噪声指标可平滑，但 patience 与平滑延迟要一起调。

**工业补充**：把公式参数、总预算、时钟单位与调用位置写入训练配置和日志。

### 9.20 实验 20：断点 LR 一致性测试

```python
before = scheduler.get_last_lr()
state = scheduler.state_dict()
clone.load_state_dict(state)
assert clone.last_epoch == scheduler.last_epoch
assert clone.get_last_lr() == before
```

**验收**：在小模型上模拟保存/恢复，恢复后的下一步 LR 必须与连续训练一致。

**工业补充**：把公式参数、总预算、时钟单位与调用位置写入训练配置和日志。

- `global_update`、`micro_step`、`samples_seen`、`tokens_seen`。
- AMP scaler、随机数状态、数据采样器 epoch。

### 12.2 恢复不变量

恢复后的下一批数据、下一次 LR、optimizer state、随机增强与连续训练应尽可能一致。最小测试是在第 N 步保存，分别连续跑一步和重启跑一步，比较 LR 与参数差异。

### 12.3 分布式 reduction

每个 rank 都应执行相同次数的 optimizer/scheduler step。若存在空 batch、OOM 跳步或 AMP overflow，必须用一致决策，否则各 rank 的 LR 状态分叉。

### 12.4 弹性训练

world size 改变时，epoch 与 local batch 不再可靠。优先以全局 update、样本或 token 作为 schedule 时钟，并将其持久化。

### 12.5 配方版本化

一个可复现调度配置至少包含：公式名、peak/floor、warmup、总预算、时钟单位、step 调用位置、参数组倍率、恢复策略与代码版本。

## 16. 最小可运行自检

```python
import math
import torch


def cosine_lr(step, warmup, total, peak, floor=0.0):
    if total <= warmup:
        raise ValueError("total must exceed warmup")
    if not 0 <= step < total:
        raise ValueError("step out of range")
    if step < warmup:
        return peak * (step + 1) / warmup
    progress = (step - warmup) / (total - warmup - 1)
    progress = min(max(progress, 0.0), 1.0)
    return floor + 0.5 * (peak - floor) * (1 + math.cos(math.pi * progress))


def scheduler_self_check():
    values = [cosine_lr(s, 10, 100, 1e-3, 1e-5) for s in range(100)]
    assert all(math.isfinite(v) and v >= 0 for v in values)
    assert math.isclose(values[9], 1e-3)
    assert math.isclose(values[-1], 1e-5)
    assert values[:10] == sorted(values[:10])
    assert values[10:] == sorted(values[10:], reverse=True)
    return values

# 在独立练习环境运行：curve = scheduler_self_check()
```

## 17. 选型决策树

```text
训练预算是否固定？
├─ 否 → WSD / constant with warmup，按 token 持久化进度
└─ 是
   ├─ Transformer/LLM → warmup + cosine/linear/inverse-sqrt
   ├─ 传统 CNN recipe → step/multistep 或 warmup+cosine
   ├─ 快速中小模型 → OneCycle（先做 LR range test）
   ├─ 验证指标驱动 → ReduceLROnPlateau
   └─ 在线持续适应 → 小常数/inverse-time，保留非零 floor
```

## 18. 最终检查清单

- [ ] 公式写清 absolute LR 还是 multiplier。
- [ ] 时钟写清 epoch、update、sample 或 token。
- [ ] 梯度累积下只在 optimizer update 后推进。
- [ ] AMP overflow 跳步策略在所有 rank 一致。
- [ ] 训练前离线画全曲线并检查边界。
- [ ] 每个参数组 LR 与倍率写入日志。
- [ ] model/optimizer/scheduler/progress 同 checkpoint 保存。
- [ ] 断点恢复下一步与连续训练一致。
- [ ] peak、warmup、floor 与 batch/optimizer 联合调优。
- [ ] 选择以最终业务指标为准，不以曲线“好看”为准。

**一句话总结**：学习率调度的本质，是在有限更新预算内安排每一步能走多远；工程正确性首先取决于时钟、调用顺序与恢复语义。
