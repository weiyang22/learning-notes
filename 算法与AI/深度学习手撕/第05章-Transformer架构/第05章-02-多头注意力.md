## 5.2 Multi-Head Attention (多头注意力)

---

## 1. 内容介绍

**Multi-Head Attention (MHA)**: 把 Self-Attention 的 Q/K/V 拆成 $h$ 个头, 每个头独立算注意力, 最后拼接.

**论文**: Attention Is All You Need (Vaswani et al., 2017).

### 1.1 一句话定义

**Multi-Head Attention** 通过 $h$ 个独立的"投影 + 注意力 + 拼接", 让模型在**多个子空间**并行学习不同层次的 token 关系. 这是 Transformer 区别于 RNN/CNN 的核心创新.

### 1.2 历史背景

- **2014**: Bahdanau Attention (Seq2Seq + Attention), 用于机器翻译.
- **2017**: Transformer 论文提出 Multi-Head, 成为后续 7 年所有主流 NLP / 多模态模型的 backbone.
- **2019-2020**: GPT-2 / BERT 全面采用.
- **2023+**: LLaMA-2/3, Mistral, Qwen-2 等加入 GQA (降低 KV Cache).

### 1.3 与 Self-Attention 的关系

Self-Attention 是 MHA 的"单头版本". MHA = $h$ 个 Self-Attention 并行.

数学形式:
$$\text{MHA}(Q,K,V) = \text{Concat}(\text{head}_1,\ldots,\text{head}_h)W^O$$
$$\text{head}_i = \text{Attn}(QW_i^Q, KW_i^K, VW_i^V)$$

---

## 2. 为什么这么做

**问题**:
- 单头 Self-Attention 只能在一个子空间里学相关性
- 不同位置 / 语法 / 语义关系需要不同的"关注模式"
- 单头容量有限

**核心洞察**:
- 就像 CNN 用多个卷积核提取不同特征
- 不同头可以学不同的"关注模式" (句法 / 语义 / 指代等)
- **表达力**: $h$ 个不同子空间, 比单头容量大 $h$ 倍

### 2.1 为什么"多头"有效: 三种解释

**解释 1: 子空间多样性**

每个 head 学一个不同的"关注维度":
- Head 1: 主语-动词关系 (语法)
- Head 2: 指代关系 (代词→名词)
- Head 3: 局部依赖 (相邻 token)
- Head 4: 全局依赖 (句子级)

**解释 2: 增加非线性**

单头 attention 输出 = 单个 softmax 分布加权. 多头 = 多种分布的凸组合, 表达力更强.

数学上, 假设我们学到 attention 矩阵 $A_i$, 多头输出:
$$O = \sum_{i=1}^h \alpha_i A_i V$$

这是 $h$ 个 attention distribution 的加权组合, 表达力 $\supset$ 单头.

**解释 3: 防止 attention collapse**

经验观察: 训练初期, 单头 attention 容易"塌陷"到几行 (over-smoothing). 多头让每个 head 专注于不同模式, 防止彼此干扰.

### 2.2 多头的代价

- 训练时: 与单头 $d$ 维同 FLOPs (拆解后总参数不变)
- 推理时: $h$ 个 KV 头要缓存, **显存 $h$ 倍** (KV Cache 问题)
- 工程复杂度: 拆头 (reshape + permute), mask 应用, 拼接

---

## 3. 这么做的原因 (方案对比)

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| 单头 | 一个 QKV | 简单 | 容量小 |
| **MHA** (原版) | h 头, 每个头独立 | 多视角 | 推理 KV 缓存大 |
| **MQA** (Multi-Query) | Q 多头, KV 1 头 | 推理快 10x+ | 质量略降 |
| **GQA** (Grouped-Query) | Q 多头, KV 分组 (LLaMA-2/3) | 推理 + 质量平衡 | 工程稍复杂 |

**为什么 GQA 流行?**
- LLaMA-2 / Mistral 都在用
- 推理时 KV 缓存从 MHA 的 $n_h \cdot d$ 降到 $n_{kv} \cdot d$
- 质量接近 MHA, 速度接近 MQA

---

## 4. 解决了什么问题

- **多视角关注**: h 个头学不同模式
- **表达能力强**: $h$ 个不同子空间, 比单头容量大 $h$ 倍
- **GQA 平衡**: 推理加速 + 质量保持

---

## 5. 意义

- MHA 是 Transformer 的标配
- GQA 是 2023+ LLM 的标准 (LLaMA-2, Mistral, Qwen, GLM)
- 多查询 / 分组查询 = 推理优化的关键

## 6. 公式表达

### 6.1 标准 MHA 公式

```text
MHA:
  Q, K, V: (B, n, d_model)
  W_Q, W_K, W_V: (d_model, d_model)
  W_O: (d_model, d_model)

  Q_h = reshape(Q @ W_Q, (B, h, n, d_k))  # 拆头
  K_h = reshape(K @ W_K, (B, h, n, d_k))
  V_h = reshape(V @ W_V, (B, h, n, d_v))

  attn_h = softmax(Q_h K_h^T / √d_k)  # (B, h, n, n)
  out_h = attn_h @ V_h                   # (B, h, n, d_v)

  out = reshape(out_h, (B, n, h*d_v)) @ W_O  # (B, n, d_model)
```

### 6.2 注意力分数维度变化

| 张量 | 形状 | 备注 |
|---|---|---|
| $X$ | $(B, n, d)$ | 输入 |
| $Q = X W_Q$ | $(B, n, d)$ | 投影 |
| $Q$ reshape | $(B, h, n, d/h)$ | 拆头 |
| $Q K^\top$ | $(B, h, n, n)$ | attention scores |
| $\text{softmax}(\cdot/\sqrt{d/h})$ | $(B, h, n, n)$ | attention weights |
| $\text{attn} \cdot V$ | $(B, h, n, d/h)$ | 加权 |
| reshape 回 | $(B, n, d)$ | 合并头 |
| 乘 $W_O$ | $(B, n, d)$ | 输出投影 |

### 6.3 缩放因子 $\sqrt{d_k}$ 的来源

**数学推导**: 设 $q, k$ 独立, 各分量 $N(0, 1)$. 则 $q \cdot k = \sum_i q_i k_i$, 方差:
$$\text{Var}(q \cdot k) = \sum_i \text{Var}(q_i k_i) = \sum_i \mathbb{E}[q_i^2] \mathbb{E}[k_i^2] = d_k$$

数值过大时, softmax 趋于 one-hot, 梯度消失. 除以 $\sqrt{d_k}$ 让方差归 1.

### 6.4 GQA 公式

```text
GQA:
  Q: (B, n, d) 投影到 h_q 头
  K, V: (B, n, d) 投影到 g 个头  (g < h_q)
  每 g 个 Q 头共享 1 个 KV 头
  repeat_interleave(K, n_groups=h_q/g, dim=1) → 变成 MHA
```

LLaMA-2 7B: $h_q = 32$, $g = 8$, 即每 4 个 Q 头共享 1 个 KV 头.

### 题目 4 (进阶): MLA 实现思路

```text
MLA (Multi-Head Latent Attention, DeepSeek-V2):
1. 把 K, V 联合压缩到低秩潜向量 c (d_c 维, 远小于 h*d_k)
2. 推理时只缓存 c, 不缓存 K/V 的展开
3. 推理时: K = c @ W^UK, V = c @ W^UV (按需展开)
4. KV Cache: h*d_c 而非 h*d_k*n, 节省 ~95%
```

## 9. 答案

### 答案 1: Multi-Head Attention (NumPy 版)

```python
import numpy as np

class MultiHeadAttention:
    def __init__(self, d_model, n_heads):
        assert d_model % n_heads == 0
        self.d_model = d_model
        self.n_heads = n_heads
        self.d_k = d_model // n_heads

        # W_Q, W_K, W_V: (d_model, d_model)
        self.W_Q = np.random.randn(d_model, d_model) * 0.01
        self.W_K = np.random.randn(d_model, d_model) * 0.01
        self.W_V = np.random.randn(d_model, d_model) * 0.01
        self.W_O = np.random.randn(d_model, d_model) * 0.01

    def forward(self, x, mask=None):
        B, n, d = x.shape

        # 线性投影
        Q = x @ self.W_Q  # (B, n, d_model)
        K = x @ self.W_K
        V = x @ self.W_V

        # 拆多头: (B, n, d) → (B, n, h, d_k) → (B, h, n, d_k)
        Q = Q.reshape(B, n, self.n_heads, self.d_k).transpose(0, 2, 1, 3)
        K = K.reshape(B, n, self.n_heads, self.d_k).transpose(0, 2, 1, 3)
        V = V.reshape(B, n, self.n_heads, self.d_k).transpose(0, 2, 1, 3)
        # 现在 Q, K, V: (B, h, n, d_k)

        # 注意力: (B, h, n, d_k) @ (B, h, d_k, n) → (B, h, n, n)
        scores = Q @ K.transpose(0, 1, 3, 2) / np.sqrt(self.d_k)
        if mask is not None:
            scores = scores + mask * (-1e9)
        attn = np.exp(scores - scores.max(axis=-1, keepdims=True))
        attn = attn / attn.sum(axis=-1, keepdims=True)

        # 加权求和: (B, h, n, n) @ (B, h, n, d_k) → (B, h, n, d_k)
        out = attn @ V
        # 合并头: (B, h, n, d_k) → (B, n, h, d_k) → (B, n, d_model)
        out = out.transpose(0, 2, 1, 3).reshape(B, n, d)

        # 输出投影
        return out @ self.W_O
```

### 答案 2: Grouped-Query Attention (GQA) (NumPy 版)

```python
class GroupedQueryAttention:
    def __init__(self, d_model, n_q_heads, n_kv_heads):
        assert n_q_heads % n_kv_heads == 0
        self.n_q = n_q_heads
        self.n_kv = n_kv_heads
        self.n_groups = n_q_heads // n_kv_heads  # 每组 Q 头共享 1 个 KV 头
        self.d_model = d_model
        self.d_k = d_model // n_q_heads

        self.W_Q = np.random.randn(d_model, d_model) * 0.01
        self.W_K = np.random.randn(d_model, n_kv_heads * self.d_k) * 0.01
        self.W_V = np.random.randn(d_model, n_kv_heads * self.d_k) * 0.01
        self.W_O = np.random.randn(d_model, d_model) * 0.01

    def forward(self, x, mask=None):
        B, n, d = x.shape

        Q = x @ self.W_Q
        K = x @ self.W_K
        V = x @ self.W_V

        # Q 拆 h 个头
        Q = Q.reshape(B, n, self.n_q, self.d_k).transpose(0, 2, 1, 3)  # (B, h, n, d_k)
        # K/V 拆 g 个头
        K = K.reshape(B, n, self.n_kv, self.d_k).transpose(0, 2, 1, 3)  # (B, g, n, d_k)
        V = V.reshape(B, n, self.n_kv, self.d_k).transpose(0, 2, 1, 3)  # (B, g, n, d_k)

        # 关键: 把 K/V 复制 n_groups 次, 让每个 Q 头都有对应的 KV
        # (B, g, n, d_k) → (B, h, n, d_k)
        K = np.repeat(K, self.n_groups, axis=1)
        V = np.repeat(V, self.n_groups, axis=1)

        # 现在是标准的 MHA
        scores = Q @ K.transpose(0, 1, 3, 2) / np.sqrt(self.d_k)
        if mask is not None:
            scores = scores + mask * (-1e9)
        attn = np.exp(scores - scores.max(axis=-1, keepdims=True))
        attn = attn / attn.sum(axis=-1, keepdims=True)
        out = attn @ V

        out = out.transpose(0, 2, 1, 3).reshape(B, n, d)
        return out @ self.W_O
```

**关键技巧**: `np.repeat(K, n_groups, axis=1)` 把 KV 头复制, 让多个 Q 头共享同一 KV.

### 答案 3: KV 缓存对比

```text
假设: n=4096 (序列长), d_k=128, 字节=float16=2
KV 缓存 = (KV 头数) × n × d_k × 2 (K + V) × 2 bytes

LLaMA-2 7B: 32 Q heads, 8 KV heads
  MHA (32 KV): 32 × 4096 × 128 × 2 × 2 = 67 MB / token
  MQA (1 KV):  1 × 4096 × 128 × 2 × 2 = 2 MB / token
  GQA (8 KV):  8 × 4096 × 128 × 2 × 2 = 16 MB / token
```

**结论**: GQA 节省 ~75% KV 缓存, 接近 MHA 的质量.

---

### 答案 4: MLA (DeepSeek-V2 风格)

MLA 的核心是把 K/V 联合压缩到低秩潜向量 $c$:

$$\text{KV Cache 总量} = h_q \cdot d_c \cdot n \cdot 2 \text{ bytes}$$

DeepSeek-V2 设置: $d_c = 4$ (latent dim), 大约 KV Cache 减少 93.3%.

```text
KV Cache 大小对比 (LLaMA-2 70B @ 4K 序列, 假设 bfloat16):
  MHA:  32 × 4 × 128 × 1024 × 2 B = 32 MB
  GQA-8: 8 × 4 × 128 × 1024 × 2 B = 8 MB
  MLA:  32 × 4 × 4 × 1024 × 2 B = 1 MB   (latent dim 4)
```

注意 MLA 的 KV Cache 不随头维度增长, 只随 latent dim. 这是压缩 KV 的关键.

## 10. 深入: PyTorch 高效实现 (生产级)

### 10.1 SDPA + 一次合并 QKV

```python
import torch.nn as nn
import torch.nn.functional as F

class MHA(nn.Module):
    """PyTorch nn.MultiheadAttention 简化版 + SDPA (Flash Attention)."""
    def __init__(self, d, h, dropout=0.0):
        super().__init__()
        assert d % h == 0, f'd={d} must be divisible by h={h}'
        self.d_model = d
        self.n_heads = h
        self.d_k = d // h

        # 合并为一次 Linear (效率更高)
        self.qkv = nn.Linear(d, 3 * d, bias=False)
        self.proj = nn.Linear(d, d)
        self.dropout = dropout

    def forward(self, x, mask=None, is_causal=False):
        B, T, d = x.shape
        # 一次性算 Q, K, V
        qkv = self.qkv(x)  # (B, T, 3*d)
        # 拆 3 份, 每份 (B, h, T, d_k)
        qkv = qkv.reshape(B, T, 3, self.n_heads, self.d_k).permute(2, 0, 3, 1, 4)
        q, k, v = qkv[0], qkv[1], qkv[2]
        # 现在 q, k, v 都是 (B, h, T, d_k)

        # SDPA (自动选 backend: Flash / Memory-Efficient / Math)
        out = F.scaled_dot_product_attention(
            q, k, v,
            attn_mask=mask,
            dropout_p=self.dropout if self.training else 0.0,
            is_causal=is_causal,
        )
        # (B, h, T, d_k) → (B, T, h, d_k) → (B, T, d)
        out = out.transpose(1, 2).contiguous().reshape(B, T, d)
        return self.proj(out)
```

### 10.2 GQA PyTorch 版

```python
class GQA(nn.Module):
    """Grouped-Query Attention (LLaMA-2 风格)."""
    def __init__(self, d, n_q, n_kv, dropout=0.0):
        super().__init__()
        assert n_q % n_kv == 0, f'n_q={n_q} not divisible by n_kv={n_kv}'
        self.d_model = d
        self.n_q = n_q
        self.n_kv = n_kv
        self.n_groups = n_q // n_kv
        self.d_k = d // n_q

        self.w_q = nn.Linear(d, n_q * self.d_k, bias=False)
        self.w_k = nn.Linear(d, n_kv * self.d_k, bias=False)
        self.w_v = nn.Linear(d, n_kv * self.d_k, bias=False)
        self.w_o = nn.Linear(d, d, bias=False)
        self.dropout = dropout

    def forward(self, x, mask=None, is_causal=False, freqs=None):
        B, T, d = x.shape
        # Q: (B, T, n_q * d_k) → (B, n_q, T, d_k)
        q = self.w_q(x).view(B, T, self.n_q, self.d_k).transpose(1, 2)
        # K, V: (B, T, n_kv * d_k) → (B, n_kv, T, d_k)
        k = self.w_k(x).view(B, T, self.n_kv, self.d_k).transpose(1, 2)
        v = self.w_v(x).view(B, T, self.n_kv, self.d_k).transpose(1, 2)

        # RoPE (可选)
        if freqs is not None:
            q, k = apply_rope(q, k, freqs)

        # GQA: 把 KV repeat 到 Q 头数
        # repeat_interleave 比 repeat 在 PyTorch 更高效
        k = k.repeat_interleave(self.n_groups, dim=1)  # (B, n_q, T, d_k)
        v = v.repeat_interleave(self.n_groups, dim=1)

        # SDPA
        out = F.scaled_dot_product_attention(
            q, k, v,
            attn_mask=mask,
            dropout_p=self.dropout if self.training else 0.0,
            is_causal=is_causal,
        )
        out = out.transpose(1, 2).contiguous().view(B, T, d)
        return self.w_o(out)


def apply_rope(q, k, freqs):
    """RoPE 旋转位置编码 (用于 Q, K)."""
    # q, k: (B, n_heads, T, d_k)
    # freqs: (T, d_k // 2, 2) — 预计算的 cos, sin

    # 把 q, k 拆成 (B, n_heads, T, d_k // 2, 2) 对
    q_pairs = q.float().reshape(*q.shape[:-1], -1, 2)
    k_pairs = k.float().reshape(*k.shape[:-1], -1, 2)

    cos = freqs[..., 0]  # (T, d_k // 2)
    sin = freqs[..., 1]

    q_rot = torch.stack([
        q_pairs[..., 0] * cos - q_pairs[..., 1] * sin,
        q_pairs[..., 0] * sin + q_pairs[..., 1] * cos,
    ], dim=-1).reshape_as(q).to(q.dtype)

    k_rot = torch.stack([
        k_pairs[..., 0] * cos - k_pairs[..., 1] * sin,
        k_pairs[..., 0] * sin + k_pairs[..., 1] * cos,
    ], dim=-1).reshape_as(k).to(k.dtype)

    return q_rot, k_rot
```

### 10.3 MLA PyTorch 简化版

```python
class MLA(nn.Module):
    """Multi-Head Latent Attention (DeepSeek-V2).

    把 KV 联合压缩到低秩潜向量 c, KV Cache 减少 ~95%.
    """
    def __init__(self, d, n_heads, latent_dim, d_k=None):
        super().__init__()
        self.n_heads = n_heads
        self.d_k = d_k or d // n_heads
        self.latent_dim = latent_dim

        self.w_q = nn.Linear(d, n_heads * self.d_k, bias=False)
        # 把 KV 压缩到 latent_dim 维
        self.w_kv_down = nn.Linear(d, latent_dim, bias=False)
        # 再展开回 (n_heads * d_k)
        self.w_k_up = nn.Linear(latent_dim, n_heads * self.d_k, bias=False)
        self.w_v_up = nn.Linear(latent_dim, n_heads * self.d_k, bias=False)
        self.w_o = nn.Linear(n_heads * self.d_k, d, bias=False)

    def forward(self, x, freqs=None):
        B, T, d = x.shape

        # Q 直接投到多头
        q = self.w_q(x).view(B, T, self.n_heads, self.d_k).transpose(1, 2)

        # K, V: 通过 latent 压缩
        c_kv = self.w_kv_down(x)  # (B, T, latent_dim)
        k = self.w_k_up(c_kv).view(B, T, self.n_heads, self.d_k).transpose(1, 2)
        v = self.w_v_up(c_kv).view(B, T, self.n_heads, self.d_k).transpose(1, 2)

        if freqs is not None:
            q, k = apply_rope(q, k, freqs)

        out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        out = out.transpose(1, 2).contiguous().view(B, T, d)
        return self.w_o(out)

    # 推理时: 只缓存 c_kv (latent_dim), 不缓存 K, V
    def step_inference(self, x_t, c_kv_cache=None):
        """单步推理, c_kv 是当前步的 latent."""
        c_kv_new = self.w_kv_down(x_t)  # (B, 1, latent_dim)
        if c_kv_cache is not None:
            c_kv = torch.cat([c_kv_cache, c_kv_new], dim=1)
        else:
            c_kv = c_kv_new
        # 缓存 c_kv, 不缓存 K, V
        ...
```

## 11. 深入: MHA → MQA → GQA → MLA 完整演进

### 11.1 演进谱

| 方案 | KV 头 | KV Cache | 质量 | 代表 |
| :--- | :--- | :--- | :--- | :--- |
| MHA | $h$ | 1× | 最好 | 原始 Transformer |
| MQA | 1 | $1/h$ | 略降 | PaLM, Falcon |
| GQA | $g$ | $g/h$ | ≈MHA | LLaMA-2/3, Mistral |
| MLA | 低秩潜向量 | 更低 | ≈MHA | DeepSeek-V2/V3 |

演进动机始终是**压缩推理时的 KV Cache** (推理显存瓶颈, 见 [工程能力第03章](../../../基础/工程基础/工程能力/第03章-参数量与显存预估.md)). MLA 用低秩压缩把 KV 再降一档 (见 [LLM发展第04章](../../LLM发展/第04章-注意力与效率演进.md)).

### 11.2 KV Cache 显存速算

**公式**:
$$\text{KV Cache 字节} = 2 \times B \times n \times h_{kv} \times d_k \times \text{sizeof(dtype)}$$

**对比** (LLaMA-2 7B: 32 Q, 8 KV, $d_k = 128$, 序列 4096, fp16):
| 方案 | KV 头数 | KV Cache 大小 |
|---|---|---|
| MHA | 32 | 67 MB |
| MQA | 1 | 2 MB |
| GQA-8 | 8 | 16 MB |
| MLA ($d_c=4$) | — | 0.32 MB |

**优化潜力**: MLA 将 KV Cache 降低到 MQA 的 ~16% (相比 GQA 8 进一步降低 50x).

## 12. 深入: 为什么"多头"比"单头大注意力"好 (理论)

### 12.1 多样性: 不同 head 学不同模式

经验观察 (Clark et al. 2019, BERT attention analysis):
- BERT 12 层 12 头中, 有明显:
  - "语法头" (attend to verb 附近)
  - "指代头" (attend to 主语/宾语)
  - "位置头" (attend to 特定相对位置)
  - "BPE 头" (attend to subword 内部)

- 实际很多 head 是冗余的, 部分 head 可被剪枝.

### 12.2 表达力理论

**定理 (informal)**: 在 sufficient $d_k$ 下, 多头的表达力严格强于单头.

**直觉**: 多头是多个 attention distribution 的凸组合. 假设我们学到 5 个不同的 attention 模式 (局部、远距离、语法等), 单头只能选 1 个, 多头可以加权混合.

**反例**: 如果 $d_k$ 太小 (e.g. < 16), 多头也退化. 经验: $d_k \geq 64$.

### 12.3 多头的代价

- 训练: 与单头 (一个 $d$ 维) 同 FLOPs.
  - 单头 attention: $O(n^2 d)$
  - 多头 attention: $h \times O(n^2 \cdot d/h) = O(n^2 d)$
  - 总和相同!

- 推理: KV cache 是 $h$ 倍. 这是 GQA / MLA 要解决的问题.

## 13. 深入: MHA 计算复杂度详解

### 13.1 前向时间

设 batch $B$, 序列 $n$, 头数 $h$, 头维 $d_k$:

- Q, K, V 投影: $O(B \cdot n \cdot d^2)$ (1 次 Linear)
- QK^T: $O(B \cdot h \cdot n^2 \cdot d_k)$
- Softmax: $O(B \cdot h \cdot n^2)$
- attn @ V: $O(B \cdot h \cdot n^2 \cdot d_k)$
- 输出投影: $O(B \cdot n \cdot d^2)$

总: $O(B \cdot n \cdot d^2 + B \cdot h \cdot n^2 \cdot d_k)$

对于 $n \gg d$, 第二项主导: $O(n^2)$.

### 13.2 前向显存

- KV Cache: $O(B \cdot h \cdot n \cdot d_k)$ (per layer)
- 输入 / 输出: $O(B \cdot n \cdot d)$
- Attention matrix: $O(B \cdot h \cdot n^2)$ (训练时)

KV Cache 是推理瓶颈.

### 13.3 反向时间

约前向 2x (反向链式法则): $O(B \cdot n \cdot d^2 + B \cdot h \cdot n^2 \cdot d_k)$ 同阶.

### 13.4 FlashAttention 优化

FlashAttention (Tri Dao, 2022) 解决 attention 显存瓶颈:
- 算法: 分块计算 + online softmax, 避免显式构造 $n \times n$ 矩阵
- 显存: $O(n)$ 而非 $O(n^2)$
- 时间: 同阶 (或略快, 因内存访问优化)

FlashAttention-2 (2023) 进一步提升并行度.
FlashAttention-3 (2024) 支持 FP8 + 异步.

### 13.5 FlashAttention 内核伪代码

```text
输入: Q, K, V (分块)
输出: O

for each block Q_i (i 从 1 到 n/B):
    O_i = 0, l_i = 0, m_i = -inf

    for each block K_j, V_j:
        S_ij = Q_i @ K_j^T / sqrt(d)
        m_new = max(m_i, row_max(S_ij))
        P_ij = exp(S_ij - m_new)
        l_new = exp(m_i - m_new) * l_i + row_sum(P_ij)
        O_i = exp(m_i - m_new) * O_i + P_ij @ V_j
        m_i = m_new
        l_i = l_new

    O_i = O_i / l_i
```

**关键**: online softmax (Milakov & Gimelshein 2018), 不需要把 $n \times n$ 完全存入显存.

## 14. 论文解读 (重点 4 篇)

### 14.1 Attention Is All You Need (Vaswani 2017)

**摘要原文翻译**: "基于encoder-decoder架构的主流序列转换模型, 通过注意力机制连接 encoder 和 decoder. 我们提出一种新的简单网络架构——Transformer, 完全基于注意力机制, 不使用循环和卷积, 在两个机器翻译任务上取得 SOTA."

**关键贡献**:
1. 提出 **Scaled Dot-Product Attention**: $\text{softmax}(QK^\top/\sqrt{d_k}) V$
2. 提出 **Multi-Head Attention**: $h$ 个独立 head 并行
3. 提出 **Sinusoidal Positional Encoding**
4. 展示 Transformer 在 WMT 14 EN-DE / EN-FR 上 BLEU 28.4 / 41.8, 超过 LSTM

**图 1 (架构)**: 左侧 Encoder, 右侧 Decoder, 二者均堆叠 6 个 Block.

**图 2 (Scaled Dot-Product)**: 展示 QK^T / sqrt(d_k) 后 softmax, 再乘 V.

**作者注释**: 缩放因子 $\sqrt{d_k}$ 是因为 $d_k$ 大时点积值大, softmax 梯度消失.

### 14.2 Fast Transformer Decoding: One Write-Head is All You Need (Shazeer 2019, MQA)

**摘要**: 提出 Multi-Query Attention, 把 K/V 头数从 $h$ 降到 1, 推理加速 10x+, 微小质量下降.

**结论**: 解码阶段 KV 缓存占主要显存, 减到 1 个头大幅加速.

**应用**: PaLM, Falcon, StarCoder 等都用了 MQA 或 GQA.

### 14.3 GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints (Ainslie et al. 2023)

**摘要**: 提出 Grouped-Query Attention, 把 KV 头数从 $h$ 降到 $g$ (e.g. 8).

**贡献**:
1. 从 MHA checkpoint "upcycling" 到 GQA, 大幅减少重训成本
2. 实验证明 GQA (8 KV heads) 比 MQA 更接近 MHA 质量
3. LLaMA-2 / Mistral 都用 GQA, 成为 2023+ 标准

### 14.4 DeepSeek-V2 / MLA (DeepSeek-AI 2024)

**摘要**: Multi-Head Latent Attention, 把 K, V 联合压缩到低秩 latent 向量.

**贡献**:
1. KV Cache 减少 93.3% (相比 GQA)
2. 推理吞吐量提升 5.76x
3. 训练保持类似 MHA 的质量

**核心思想**:
$$c_t^{KV} = W^{DKV} x_t, \quad K_t = W^{UK} c_t^{KV}, \quad V_t = W^{UV} c_t^{KV}$$

推理时只缓存 $c^{KV}$, 不缓存 $K, V$ 的展开. 完全重建时按需展开.

## 16. 进阶: Sliding Window Attention (Mistral)

### 16.1 概念

Mistral 7B 用 **Sliding Window** + GQA:
- 局部 attention 窗口: 4096 tokens (rolling)
- Global attention 隔层使用

**计算节省**: 局部窗口只算 $w$ 个 token 而非全部 $n$ 个, FLOPs 减少 $n/w$ 倍.

### 16.2 PyTorch 简化

```python
class SlidingWindowMHA(nn.Module):
    def __init__(self, d, h, window_size=4096):
        super().__init__()
        self.mha = MHA(d, h)
        self.window_size = window_size

    def forward(self, x):
        B, T, d = x.shape
        # 每个 query 只和最近 window_size 个 key 算 attention
        # 用 mask 实现
        mask = torch.triu(torch.ones(T, T, device=x.device), diagonal=-(self.window_size - 1))
        mask = mask.masked_fill(mask == 0, float('-inf')).masked_fill(mask == 1, 0)
        return self.mha(x, mask=mask)
```

### 16.3 Ring Attention (跨设备)

对于超长序列 (32K+), 单个 GPU 放不下 attention. Ring Attention 把 attention 分布到多设备:

```text
GPU 1: Q[i], K/V[i] 本地
GPU 2: 接收 GPU 1 的 K/V[i] 计算 Q[i+1]
循环: 沿环形传递 K/V 块
```

每个 GPU 显存 $O(n/P)$, 总 $O(n)$ 但分布.

## 18. 常见陷阱与调试清单

### 18.1 实现陷阱

1. **忘记 scale**: $QK^\top / \sqrt{d_k}$ 不写必错.
2. **mask 位置**: 加在 softmax 前 (`-inf`), 不是后 (`×0`).
3. **多头 permute 后忘 contiguous**: `.permute().contiguous()` 防止 reshape 失败.
4. **softmax 数值溢出**: 减 max 后再 exp. PyTorch 内部会自动, NumPy 必须手写.
5. **GQA `repeat` vs `repeat_interleave`**: 轴对齐, 推荐后者.
6. **多余 transpose**: QK^T 用 `.transpose(-2, -1)` 而不是 `.permute()` (后者维度交换后影响 batch).

### 18.2 性能陷阱

1. **head_dim 过小**: < 32 退化. 经验 64-128.
2. **head 数过多**: > 64 边际效益递减, 工程复杂度增加.
3. **不合并 QKV**: 三次 Linear 比一次慢 3x. 用合并 Linear.
4. **训练不用 FlashAttn**: 比 eager 快 4-8x. 必开.
5. **推理不用 SDPA**: 同样慢. 必开.

### 18.3 KV Cache 调试

```python
def check_kv_cache(model, batch_size, seq_len, dtype=torch.float16):
    """诊断 KV Cache 显存."""
    bytes_per_token = 0
    for layer in model.model.layers:
        n_kv = layer.self_attn.num_key_value_heads
        d_k = layer.self_attn.head_dim
        bytes_per_token += 2 * n_kv * d_k * 2  # K + V, bf16
    print(f'每 token KV Cache: {bytes_per_token} B')
    print(f'batch={batch_size} seq_len={seq_len}: {bytes_per_token * batch_size * seq_len / 1e9:.2f} GB')
```

### 23.2 Attention Map 解读经验

观察到的常见 head 模式:
- **Broad attention**: 关注所有 token (类似平均), 接近冗余.
- **Local attention**: 仅关注邻近 1-3 token (BPE / 词边界).
- **Syntactic attention**: 主谓一致、代词→名词.
- **Next-token attention**: attention 给 diagonal+1 (degenerate).
- **Sink attention**: 第 1 个 token 接收大部分 attention (LLaMA 等注意到的 "attention sink" 现象).

## 24. 深入: 数学推导 — Self-Attention 的可微性

### 24.1 Softmax 的梯度

设 $a_i$ 为 logits, $p_i = e^{a_i} / \sum_j e^{a_j}$. 对 $a_j$ 求导:

$$\frac{\partial p_i}{\partial a_j} = \begin{cases} p_i (1 - p_i) & \text{if } i = j \\ -p_i p_j & \text{if } i \ne j \end{cases}$$

合并为雅可比矩阵:
$$\frac{\partial p}{\partial a} = p \cdot (I - p^\top)$$

### 24.2 Attention 的梯度

设 $S = QK^\top / \sqrt{d_k}$, $P = \text{softmax}(S)$ (按行), $O = PV$.

$$\frac{\partial L}{\partial V} = P^\top \frac{\partial L}{\partial O}$$

$$\frac{\partial L}{\partial S} = P \odot (\frac{\partial L}{\partial P} - \text{diag}(P^\top \frac{\partial L}{\partial P}))$$

更直观: $\frac{\partial L}{\partial S} = P - P \odot (P \frac{\partial L}{\partial P})$, 但写成 Jacobian 更紧凑.

### 24.3 为什么 attention 不溢出

- $QK^\top$ 的方差 $\sim d_k$. 除 $\sqrt{d_k}$ 让方差归 1.
- Softmax 输出归一化, 不依赖于 $Q, K, V$ 的绝对大小.
- Attention 输出 $O$ 的 norm $\le \|V\|$, 通过 QK 不放大.

### 24.4 Multi-Head 梯度

$$ \frac{\partial L}{\partial W_i^Q} = x_i^\top \frac{\partial L}{\partial Q_i} $$

各 head 间无直接梯度耦合 (除了 $W^O$). 这意味着各 head 可独立训练, 实际上 DeepSeek 等展示了 head 间的稀疏化.

### 25.1 HuggingFace LLaMA Modeling (生产级)

```python
class LlamaAttention(nn.Module):
    """HuggingFace transformers.models.llama.modeling_llama.LlamaAttention.

    关键点:
    1. 显式使用 repeat_kv 模拟 GQA
    2. SDPA backend (auto-detect FlashAttn)
    3. RoPE 在 attention 之前应用
    """
    def __init__(self, config):
        super().__init__()
        self.config = config
        self.attention_dropout = config.attention_dropout
        self.hidden_size = config.hidden_size
        self.num_heads = config.num_attention_heads
        self.head_dim = self.hidden_size // self.num_heads
        self.num_key_value_heads = config.num_key_value_heads
        self.num_key_value_groups = self.num_heads // self.num_key_value_heads
        self.max_position_embeddings = config.max_position_embeddings
        self.rope_theta = config.rope_theta

        self.q_proj = nn.Linear(self.hidden_size, self.num_heads * self.head_dim, bias=False)
        self.k_proj = nn.Linear(self.hidden_size, self.num_key_value_heads * self.head_dim, bias=False)
        self.v_proj = nn.Linear(self.hidden_size, self.num_key_value_heads * self.head_dim, bias=False)
        self.o_proj = nn.Linear(self.num_heads * self.head_dim, self.hidden_size, bias=False)

    def forward(self, hidden_states, attention_mask=None, position_ids=None,
                past_key_value=None, output_attentions=False, use_cache=False,
                cache_position=None, position_embeddings=None):
        bsz, q_len, _ = hidden_states.size()

        query_states = self.q_proj(hidden_states)
        key_states = self.k_proj(hidden_states)
        value_states = self.v_proj(hidden_states)

        query_states = query_states.view(bsz, q_len, self.num_heads, self.head_dim).transpose(1, 2)
        key_states = key_states.view(bsz, q_len, self.num_key_value_heads, self.head_dim).transpose(1, 2)
        value_states = value_states.view(bsz, q_len, self.num_key_value_heads, self.head_dim).transpose(1, 2)

        # RoPE
        cos, sin = position_embeddings
        query_states, key_states = apply_rotary_pos_emb(query_states, key_states, cos, sin)

        # KV Cache 更新
        if past_key_value is not None:
            cache_kwargs = {"sin": sin, "cos": cos, "cache_position": cache_position}
            key_states, value_states = past_key_value.update(key_states, value_states, self.layer_idx, cache_kwargs)

        # GQA: repeat KV 到 Q 头数
        key_states = repeat_kv(key_states, self.num_key_value_groups)
        value_states = repeat_kv(value_states, self.num_key_value_groups)

        # SDPA
        attn_output = torch.nn.functional.scaled_dot_product_attention(
            query_states, key_states, value_states,
            attn_mask=attention_mask,
            dropout_p=self.attention_dropout if self.training else 0.0,
            is_causal=(attention_mask is None and q_len > 1),
        )

        attn_output = attn_output.transpose(1, 2).contiguous().reshape(bsz, q_len, self.hidden_size)
        attn_output = self.o_proj(attn_output)

        return attn_output, None, past_key_value
```

### 27.2 MLA Forward (PyTorch)

```python
class DeepSeekMLAAttention(nn.Module):
    def __init__(self, config):
        super().__init__()
        self.n_heads = config.num_attention_heads
        self.qk_nope_dim = config.qk_nope_head_dim
        self.qk_rope_dim = config.qk_rope_head_dim
        self.latent_dim = config.latent_dim
        self.v_head_dim = config.v_head_dim
        self.q_head_dim = self.qk_nope_dim + self.qk_rope_dim

        # Q 投影 (输出包含 nope + rope 部分)
        self.w_q_a = nn.Linear(config.hidden_size, 1536, bias=False)
        self.w_q_b = nn.Linear(1536, self.n_heads * self.q_head_dim, bias=False)

        # KV 压缩到 latent
        self.w_kv_a = nn.Linear(config.hidden_size, self.latent_dim, bias=False)
        self.w_kv_b = nn.Linear(self.latent_dim,
                                 self.n_heads * (self.qk_nope_dim + self.v_head_dim),
                                 bias=False)

        # 单独的 k_rope 投影 (用于 RoPE)
        self.w_k_r = nn.Linear(self.latent_dim, self.qk_rope_dim, bias=False)
        self.w_o = nn.Linear(self.n_heads * self.v_head_dim, config.hidden_size, bias=False)

    def forward(self, x, freqs):
        B, T, _ = x.shape

        # Q: down → up
        q_a = self.w_q_a(x)
        q = self.w_q_b(q_a)  # (B, T, n_heads * q_head_dim)
        q = q.view(B, T, self.n_heads, self.q_head_dim).transpose(1, 2)
        q_nope, q_rope = q.split([self.qk_nope_dim, self.qk_rope_dim], dim=-1)

        # KV: down → up
        c_kv = self.w_kv_a(x)  # (B, T, latent_dim)
        kv_up = self.w_kv_b(c_kv)  # (B, T, n_heads * (nope + v))
        kv_up = kv_up.view(B, T, self.n_heads, self.qk_nope_dim + self.v_head_dim)
        k_nope, v = kv_up.split([self.qk_nope_dim, self.v_head_dim], dim=-1)
        k_nope = k_nope.transpose(1, 2)
        v = v.transpose(1, 2)

        # k_rope 单独从 latent 投影
        k_rope = self.w_k_r(c_kv).view(B, T, 1, self.qk_rope_dim).transpose(1, 2)
        # 扩展到所有 head
        k_rope = k_rope.expand(B, self.n_heads, T, self.qk_rope_dim)

        # RoPE 应用到 q_rope 和 k_rope
        q_rope, k_rope = apply_rope(q_rope, k_rope, freqs)

        # 拼回 Q, K
        q = torch.cat([q_nope, q_rope], dim=-1)
        k = torch.cat([k_nope, k_rope], dim=-1)

        # SDPA
        out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        out = out.transpose(1, 2).contiguous().view(B, T, -1)

        return self.w_o(out)
```

### 27.3 MLA 的"特殊之处"

**关键**: KV Cache 时只缓存 `c_kv` (`latent_dim = 4`), 不缓存 `k_nope, v, k_rope`. 需要时通过 `w_kv_b` 和 `w_k_r` 重新展开.

**节省**: 相比 GQA-8 进一步节省 ~50x KV Cache (DeepSeek 报告).

|---|---|---|

| **State Space** | $O(n)$ | Mamba, S4 |
| **Chunk-wise** | $O(c \cdot n)$ | Mega (chunk + global) |

### 31.2 Sparse Attention 详解

**Longformer** (Beltagy et al. 2020):
- Global attention: 部分 token (e.g., [CLS]) 看全部
- Local attention: 每个 token 看周围 $w$ 个
- 复杂度: $O(n \cdot w)$, $w \ll n$

```python
def longformer_attention(q, k, v, window_size=512, global_indices=None):
    # q: (B, h, T, d_k)
    B, h, T, d_k = q.shape

    # Local attention: 每个 query 和周围 window_size 个 key 算
    scores_local = compute_local_scores(q, k, window_size)

    # Global attention (optional): 某些 token 看全部
    if global_indices is not None:
        scores_global = compute_global_scores(q, k, global_indices)

    return combine_local_global(scores_local, scores_global) @ v
```

**BigBird** (Zaheer et al. 2020):
- Random attention: 每个 query 随机选 $r$ 个 key
- Window attention: 同 Longformer
- Global attention: 少数 token 全局

### 31.3 Hybrid Attention (Transformer + Mamba)

Jamba (AI21, 2024): 7:1 Transformer:Mamba 比例 (8 层中 7 Transformer + 1 Mamba).

```python
class HybridBlock(nn.Module):
    def __init__(self, d, n_heads, is_mamba_layer=False):
        super().__init__()
        if is_mamba_layer:
            self.attn = MambaBlock(d)
        else:
            self.attn = LlamaAttention(d, n_heads)
        self.norm = RMSNorm(d)
        self.ffn = SwiGLU(d)

    def forward(self, x, freqs=None):
        x = x + self.attn(self.norm(x), freqs=freqs)
        x = x + self.ffn(self.norm(x))
        return x
```

```python
        # repeat KV
        key_states = repeat_kv(key_states, self.num_key_value_groups)
        value_states = repeat_kv(value_states, self.num_key_value_groups)

        # Causal mask
        causal_mask = attention_mask if (attention_mask is not None and q_len > 1) else None

        is_causal = True if q_len > 1 else False

        attn_output = torch.nn.functional.scaled_dot_product_attention(
            query_states, key_states, value_states,
            attn_mask=causal_mask,
            dropout_p=self.attention_dropout if self.training else 0.0,
            is_causal=is_causal,
        )

        attn_output = attn_output.transpose(1, 2).contiguous().reshape(bsz, q_len, self.hidden_size)
        attn_output = self.o_proj(attn_output)

        return attn_output, None, past_key_value


def repeat_kv(hidden_states, num_groups):
    """把 KV 从 n_kv 头扩展到 n_q 头 (GQA 模拟)."""
    bsz, num_kv, seqlen, head_dim = hidden_states.shape
    if num_groups == 1:
        return hidden_states
    hidden_states = hidden_states[:, :, None, :, :].expand(bsz, num_kv, num_groups, seqlen, head_dim)
    return hidden_states.reshape(bsz, num_kv * num_groups, seqlen, head_dim)


class LlamaRotaryEmbedding(nn.Module):
    def __init__(self, dim, max_position=4096, base=10000):
        super().__init__()
        inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
        self.register_buffer('inv_freq', inv_freq)
        self.max_seq_len_cached = max_position
        self._set_cos_sin_cache(max_position)

    def _set_cos_sin_cache(self, seq_len):
        t = torch.arange(seq_len, dtype=torch.float32)
        freqs = torch.outer(t, self.inv_freq)
        emb = torch.cat([freqs, freqs], dim=-1)
        self.register_buffer('cos_cached', emb.cos().to(torch.bfloat16), persistent=False)
        self.register_buffer('sin_cached', emb.sin().to(torch.bfloat16), persistent=False)

    def forward(self, x, seq_len=None):
        if seq_len > self.max_seq_len_cached:
            self._set_cos_sin_cache(seq_len)
        return (
            self.cos_cached[:seq_len].to(dtype=x.dtype),
            self.sin_cached[:seq_len].to(dtype=x.dtype),
        )
```

## 35. 附录 E: 经典面试题详解 (10 题)

### Q1: 默写 Self-Attention 公式

```python
def attn(Q, K, V, mask=None):
    d_k = Q.shape[-1]
    scores = (Q @ K.transpose(-2, -1)) / d_k ** 0.5
    if mask is not None:
        scores = scores.masked_fill(~mask, -1e9)
    weights = scores.softmax(-1)
    return weights @ V
```

### Q2: 为何除以 $\sqrt{d_k}$ (推导)

设 $q_i, k_j$ 各分量独立 $N(0,1)$.

$$\text{Var}(q \cdot k) = \sum_{i=1}^{d_k} \text{Var}(q_i k_i) = \sum_{i=1}^{d_k} \mathbb{E}[q_i^2] \mathbb{E}[k_i^2] = d_k$$

未缩放时, softmax logits 方差 $= d_k$, softmax 趋近 one-hot, 梯度消失.

### Q3: 多头"分头"为什么是 reshape

矩阵乘天然 batch 友好:
- 多头拆开是 $(B, h, n, d_k)$, 但实际矩阵乘可以一次性算 $(B, n, h, d_k) → (B, h, n, d_k)$ 直接用 reshape + permute, 避免显式循环.

### Q4: GQA KV 头 vs Q 头的关系

$n_q = g \cdot n_{kv}$, 其中 $g$ 是"分组数". LLaMA-2: $g = 4$.

### Q5: KV Cache 显存公式 (LLaMA-2 7B @ 4096)

$\text{KV Cache} = 2 \times n_q \times n_{seq} \times d_k \times \text{sizeof(bf16)}$ (GQA-8)

$= 2 \times 8 \times 4096 \times 128 \times 2 \text{ bytes}$
$= 16,777,216 \text{ bytes} = 16 \text{ MB per token}$

注意这是 per layer, 共 32 layer: $16 \times 32 = 512 \text{ MB}$.

### Q6: MLA 与 GQA 的本质区别

GQA: KV 头数减少, 但每个 KV 仍存完整向量.
MLA: KV 联合压缩到低位 latent, 推理时按需展开. 进一步节省 5-10x.

### Q7: FlashAttention vs 标准 attention

| | 标准 | FlashAttn |
|---|---|---|
| 显存 | $O(n^2)$ | $O(n)$ |
| 时间 | $O(n^2)$ | $O(n^2)$ (但 IO 优化) |
| 实现 | 简单 | 复杂 (online softmax) |

### Q8: 为什么 $d_k = 128$ 是 LLaMA-2 默认值

经验值, 在表达力与速度的折中:
- 太大 (256+): 训练慢, 模型小
- 太小 (32-): 表达力退化
- 64-128 是主流选择

### Q9: GQA-LLaMA-2 为什么选 8 (而不是 4 或 16)

经验:
- $g = 1$: MQA, 速度最快, 质量略降
- $g = 4$: GQA-8, 平衡
- $g = 8$ (即 4 KV 头): 更接近 MHA, 但速度慢
- **8 KV 头** 是 LLaMA-2 经验值

### Q10: 长上下文 (>128K) 优化

1. **RoPE 缩放**: NTK-aware / PI / YaRN
2. **Position Interpolation**: 把位置编码按比例缩放
3. **Ring Attention**: 跨设备长序列
4. **StreamingLLM**: 滑动 KV cache + attention sink
5. **LongNet**: dilated attention

## 37. 实战: FlashAttention 简化实现 (200 行)

```python
"""FlashAttention 简化版 (educational)."""

def flash_attention_forward(Q, K, V, block_size=64):
    """简化版 FlashAttention.

    Q, K, V: (B, h, n, d_k)
    返回: (B, h, n, d_k)
    """
    B, H, N, D = Q.shape
    scale = 1.0 / D ** 0.5

    O = torch.zeros_like(V)
    L = torch.zeros(B, H, N, 1, device=V.device, dtype=torch.float32)

    # 把 K, V 分成大小为 block_size 的块
    n_blocks = (N + block_size - 1) // block_size

    for i in range(n_blocks):  # query 块
        Q_i = Q[:, :, i*block_size:(i+1)*block_size] * scale

        # 在线累积
        m_i = torch.full((B, H, block_size, 1), -float('inf'), device=Q.device)
        l_i = torch.zeros(B, H, block_size, 1, device=Q.device)
        O_i = torch.zeros_like(Q_i)

        for j in range(n_blocks):  # key 块
            K_j = K[:, :, j*block_size:(j+1)*block_size]
            V_j = V[:, :, j*block_size:(j+1)*block_size]

            # 当前块的 attention scores
            S_ij = Q_i @ K_j.transpose(-1, -2)  # (B, H, block, block)

            # 在线 softmax
            m_new = torch.maximum(m_i, S_ij.max(dim=-1, keepdim=True).values)
            P_ij = torch.exp(S_ij - m_new)
            l_new = torch.exp(m_i - m_new) * l_i + P_ij.sum(dim=-1, keepdim=True)

            # 更新 O
            O_i = torch.exp(m_i - m_new) * O_i + P_ij @ V_j

            m_i = m_new
            l_i = l_new

        # 归一化
        O[:, :, i*block_size:(i+1)*block_size] = O_i / l_i
        L[:, :, i*block_size:(i+1)*block_size] = m_i + torch.log(l_i)

    return O
```

**性能**: 标准 attention $O(n^2)$ 显存; FlashAttention $O(n)$ 显存.

### 38.1 注意: repeat_kv vs expand vs broadcast

```python
# 三种方式
# 1. expand (视图, 内存零拷贝)
k_expanded = k[:, :, None, :, :].expand(B, n_kv, n_groups, T, d_k)

k_repeated_v2 = k.repeat_interleave(n_groups, dim=1)
```

PyTorch 推荐 `repeat_interleave`, 因为底层 contiguous 优化.

### 38.2 GQA 与 RoPE 的兼容性

GQA 共享 KV, 但 RoPE 应用到 K 上时, 每个 KV 头独立旋转 (因为不同 head 关注不同维度). 这是 fine.

MLP 中: K 头共享意味着多 Q 头用同一 RoPE 旋转结果. 实验没有质量问题.

### 38.3 GQA + LoRA 兼容性

LoRA (low-rank adaptation) 应用到 GQA 时, $W^Q$ 仍是 $d \times n_q d_k$, $W^K, W^V$ 是 $d \times n_{kv} d_k$. LoRA 在每个投影矩阵上加低秩旁路.

工程实现:
```python
class LoRAQ(nn.Module):
    def __init__(self, in_dim, out_dim, rank=16):
        self.lora_A = nn.Parameter(torch.randn(rank, in_dim) * 0.01)
        self.lora_B = nn.Parameter(torch.zeros(out_dim, rank))

    def forward(self, x):
        return (x @ self.lora_A.T) @ self.lora_B.T
```

应用于 Q, K, V 投影, 节省训练参数 (微调 7B 只需 ~10MB).

### 110. Multi-Head Attention (多头注意力) - 优化视角 视角

**核心议题**: 本节从优化视角视角切入,系统展开 "Multi-Head Attention (多头注意力)" 的相关讨论。

**1. 背景与动机**

任何技术或方法的出现都不是孤立的,而是回应特定历史条件下的具体问题。"Multi-Head Attention (多头注意力)" 的发展也不例外。要理解它,必须回到它出现的那个时间点,看清它要解决的真实问题是什么。当时的主流方案有哪些不足? 它的提出填补了哪些空白? 这些问题的回答,决定了我们今天该如何使用它。

从知识论角度看,**技术演进是问题驱动的**——不是先有方案再找问题,而是先有问题再有方案。这个观察可以帮助我们避免"拿着锤子找钉子"的陷阱,真正把方法用对地方。

历史维度上,我们看到三个规律:

1. **从特殊到一般**: 早期方法往往针对特定场景,后期抽象出通用框架。学习的认知规律也是先掌握具体案例,再抽象出一般模式。这种"自下而上"的学习方式,在机器学习模型的设计里反复出现。

2. **从手工到自动**: 经验规则逐步被数据驱动的方法取代。在早期,很多 AI 系统依赖人工编写的规则。统计学习方法的崛起让"从数据中学习"成为可能。深度学习进一步把特征工程也自动化了。今天的大模型时代,我们看到端到端学习从感知扩展到了推理与生成。

3. **从局部到全局**: 关注单个组件,演进到关注整个系统。早期模型评估只关注单点指标,现在更关注全链路的协同效应。这种"系统视角"的转变,与软件工程从单体架构到微服务架构的演进高度相似。

**2. 优化视角视角的展开**

从优化视角视角出发,我们可以把 "Multi-Head Attention (多头注意力)" 拆解为以下几个层次:

**第一层: 概念层** —— 这是最抽象的层次,定义了我们要研究的对象是什么。例如,"推荐系统"在概念层是一个"为用户从物品集合中筛选合适物品"的问题。这个层次的特点是清晰、稳定、不易变化。一个好的概念定义应该具备几个特征:可操作性、可测量性、可扩展性。

**第二层: 模型层** —— 把概念实例化为数学模型。同一概念可以有不同的模型化方式,例如"推荐系统"可以是协同过滤、矩阵分解、深度学习等。模型的选择决定了后续算法的空间,也决定了能利用的归纳偏置(比如序列模型擅长捕捉时序依赖,图模型擅长建模关系结构)。模型选型是工程实践中最重要的决策之一。

**第三层: 算法层** —— 在选定模型下,具体的求解方法。这一层最活跃,新算法层出不穷。同一模型往往有多种算法,各有优劣。例如同样是优化深度网络,可以选择 SGD、Adam、L-BFGS 等不同算法。算法的选择要考虑收敛速度、数值稳定性、计算成本等多个维度。

**第四层: 工程层** —— 算法落地的实现细节,包括数据流水线、训练框架、推理优化、监控告警等。工程层是研究到生产的桥梁,决定了一个方法能否真正用起来。一个在论文里表现很好的算法,如果不能高效实现、不能稳定运行、不能快速迭代,就没有实际价值。工程能力是把研究转化为生产力的关键。

**第五层: 业务层** —— 在具体业务场景中的表现。同一技术在不同业务里效果差异巨大,因为业务目标、数据分布、用户行为都有差异。从业务视角看技术,我们必须回答几个问题:这个技术解决了什么业务问题?投入产出比如何?长期可持续吗?技术评估必须与业务目标对齐,否则容易陷入"技术自嗨"的陷阱。

**3. 数学形式化(简洁版)**

虽然我们强调优化视角视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

偏差-方差分解是另一个核心框架:误差可以分解为模型偏差(欠拟合)、方差(过拟合)和不可约噪声三部分。理解这个分解有助于诊断模型表现、选择合适复杂度。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

信息论为"Multi-Head Attention (多头注意力)" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。

互信息衡量知道一个变量后,另一个变量不确定性减少的量。在机器学习中,它被广泛用于特征选择、表示学习、多模态对齐等场景。

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

信息瓶颈原则指出,我们应该寻找既紧凑又预测性强的表示。这一思想影响了大量表示学习方法的设计,包括对比学习、自监督学习、多模态预训练等。

**5. 算法实现(骨架)**

虽然我们强调"优化视角" 视角,但落到代码层面是类似的骨架:

```python
def train_model(data, model_class, config):
    """通用训练函数骨架"""
    model = model_class(config)
    optimizer = create_optimizer(model, config)
    scheduler = create_scheduler(optimizer, config)
```

**7. 实践建议**

结合 "Multi-Head Attention (多头注意力)" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "Multi-Head Attention (多头注意力)" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
