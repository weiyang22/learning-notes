## 5.3 Positional Encoding (位置编码)

---

## 1. 内容介绍

**位置编码** (Positional Encoding) 给 Transformer 提供**序列位置信息**, 因为 Self-Attention 本身是 permutation-invariant (打乱序列顺序不影响注意力分数).

---

## 2. 为什么这么做

**问题**:
- Self-Attention 是"集合"操作, 不区分 token 顺序
- 但"我爱你" 和 "你爱我" 含义完全不同
- 必须显式注入位置信息

---

## 3. 这么做的原因 (4 大方案对比)

| 方案 | 描述 | 优点 | 缺点 |
|---|---|---|---|
| **Sinusoidal** (原版) | $\sin/\cos$ 不同频率 | 外推性好 (更长序列) | 不能学, 固定 |
| **Learned** (BERT) | 训练一个位置向量表 | 简单 | 不能外推 |
| **RoPE** (LLaMA) | 旋转位置编码 | 相对位置 + 外推 + 长文本 | 略复杂 |
| **ALiBi** (Bloom) | 加线性 bias | 简单 + 外推 + 长文本 | 略影响质量 |

**为什么 LLaMA / Mistral / Qwen 都用 RoPE?**
- **相对位置**自然 (QK^T 天然含相对距离)
- **长度外推**好 (训练 4K, 可推到 32K+)
- **数学优雅** (复数乘法 = 旋转)

**RoPE 核心思想**:
- 把位置 $m$ 编码为旋转矩阵 $R_m$
- $q_m = R_m \cdot q$, $k_n = R_n \cdot k$
- $q_m^T k_n = q^T R_m^T R_n k = q^T R_{n-m} k$
- 注意力分数只依赖相对位置 $n - m$! 自然有相对位置性质

---

## 4. 解决了什么问题

- **位置信息缺失**: Transformer 不知道 token 顺序
- **长度外推**: 训练短, 推长序列 (RoPE / ALiBi 解决)
- **相对位置**: 自然捕获 token 间相对距离 (RoPE 解决)

---

## 5. 意义

- Sinusoidal (2017) → Learned (BERT) → RoPE (LLaMA, 2023) → ALiBi (Bloom, 2022)
- LLM 时代 RoPE 几乎一统江湖 (LLaMA, Mistral, Qwen, GLM)

---

## 6. 公式表达

```text
Sinusoidal:
  PE(pos, 2i)   = sin(pos / 10000^(2i/d))
  PE(pos, 2i+1) = cos(pos / 10000^(2i/d))

RoPE (二维情况):
  q_m = R_m · q,  k_n = R_n · k
  R_m = [[cos(mθ), -sin(mθ)], [sin(mθ), cos(mθ)]]
  θ_i = 1 / 10000^(2i/d)

  q_m^T k_n = q^T R_{n-m} k   (只依赖相对位置!)

RoPE (一般维度):
  对每对 (q_{2i}, q_{2i+1}), 应用 2D 旋转
```

### 题目 3: 解释 RoPE 为什么有相对位置性质

```text
设 q 在位置 m, k 在位置 n
q_m = R_m · q, k_n = R_n · k
q_m^T · k_n = (R_m · q)^T · (R_n · k) = q^T · R_m^T · R_n · k = q^T · R_{n-m} · k
只依赖 n - m!
```

## 9. 答案

### 答案 1: Sinusoidal PE

```python
import numpy as np

def sinusoidal_pe(max_len, d_model):
    """
    PE(pos, 2i)   = sin(pos / 10000^(2i/d))
    PE(pos, 2i+1) = cos(pos / 10000^(2i/d))
    """
    pe = np.zeros((max_len, d_model))
    position = np.arange(max_len).reshape(-1, 1)
    div_term = np.exp(np.arange(0, d_model, 2) * (-np.log(10000.0) / d_model))

    pe[:, 0::2] = np.sin(position * div_term)
    pe[:, 1::2] = np.cos(position * div_term)
    return pe

# 验证
pe = sinusoidal_pe(100, 512)
print(pe.shape)  # (100, 512)
```

### 答案 2: RoPE (二维, 实际可推广到高维)

```python
def rope_2d(q, k, pos):
    """
    RoPE 2D 旋转
    q, k: (..., d), d 偶数
    pos: (...,) 位置
    """
    # 分成 (..., d/2) 对
    q_pairs = q.reshape(*q.shape[:-1], -1, 2)  # (..., d/2, 2)
    k_pairs = k.reshape(*k.shape[:-1], -1, 2)

    # 频率: theta_i = 1 / 10000^(2i/d)
    d_half = q.shape[-1] // 2
    freqs = 1.0 / (10000 ** (np.arange(0, d_half, 2) / d_half))  # (d_half/2,)
    freqs = np.broadcast_to(freqs, q_pairs.shape[:-1] + (d_half // 2,))

    # 角度: m * theta_i
    angles = pos[..., None] * freqs  # (..., d/2)

    # 旋转: [cos, -sin; sin, cos]
    cos = np.cos(angles)
    sin = np.sin(angles)

    q_rot_pairs = np.stack([
        q_pairs[..., 0] * cos - q_pairs[..., 1] * sin,
        q_pairs[..., 0] * sin + q_pairs[..., 1] * cos
    ], axis=-1)  # (..., d/2, 2)

    k_rot_pairs = np.stack([
        k_pairs[..., 0] * cos - k_pairs[..., 1] * sin,
        k_pairs[..., 0] * sin + k_pairs[..., 1] * cos
    ], axis=-1)

    return q_rot_pairs.reshape(*q.shape), k_rot_pairs.reshape(*k.shape)
```

### 答案 3: RoPE 相对位置性质推导

```text
q_m = R_m · q_0
k_n = R_n · k_0

q_m^T · k_n = (R_m · q_0)^T · (R_n · k_0)
            = q_0^T · R_m^T · R_n · k_0

由于 R 是正交矩阵, R_m^T · R_n = R_m^{-1} · R_n = R_{n-m}  (旋转复合)

所以 q_m^T · k_n = q_0^T · R_{n-m} · k_0

只依赖相对位置 n - m, 与绝对位置无关!
```

**为什么这个性质重要?**
- 训练时见过位置 100, 推理时位置 1000, RoPE 仍能正确编码关系
- 类比: 训练时见过 2 个 token 距离 5 的关系, 推理时 100 个 token 距离 5 的关系也能识别

## 10. PyTorch 版 RoPE(工业写法: 预计算 cos/sin)

```python
import torch

def precompute_rope(dim, max_len, base=10000.0):
    # 频率: 每对维度一个 θ
    inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float()/dim))
    t = torch.arange(max_len).float()
    freqs = torch.outer(t, inv_freq)                 # (max_len, dim/2)
    return torch.cos(freqs), torch.sin(freqs)        # 预计算, 训练时查表

def apply_rope(x, cos, sin):
    # x: (B, H, T, dim); 把相邻两维当复数旋转
    x1, x2 = x[..., 0::2], x[..., 1::2]
    cos, sin = cos[None, None], sin[None, None]
    return torch.stack([x1*cos - x2*sin, x1*sin + x2*cos], -1).flatten(-2)
```

> 工业实现**预计算 cos/sin** 表,前向只做逐元素乘,几乎零额外开销。这是 RoPE 相比学习式位置编码的又一优势(无参数、无额外矩阵乘)。

---

## 11. 深入: RoPE 的远程衰减性质

RoPE 不同维度用不同频率 $\theta_i=1/base^{2i/d}$:低维高频(捕获近距离)、高维低频(捕获远距离)。两 token 距离越远,高频维度旋转相位差越大、内积贡献相互抵消 → **注意力随距离自然衰减**,契合"近的更相关"的语言先验。这是 RoPE 效果好的深层原因,不只是"能外推"。

---

## 12. 深入: 长度外推为什么会崩、怎么救

直接把训练 4K 的 RoPE 用到 128K:高频维度的相位 $m\theta_i$ 远超训练见过的范围 → 分布外,模型崩。三类救法(见 [LLM发展第03章](../../LLM发展/第03章-位置编码与长上下文演进.md)):

| 方法 | 做法 | 是否需微调 |
| :--- | :--- | :--- |
| 位置插值 PI | 位置 ×(L_train/L_new) 压回训练范围 | 少量微调 |
| NTK-aware | 调 base(高频少缩、低频多缩) | 可免微调 |
| YaRN | NTK + 注意力温度校正 | 少量微调, 扩数十倍 |

```python
# NTK-aware: 放大 base 即拉长波长, 无需重训
def ntk_base(base, scale, dim):
    return base * scale ** (dim / (dim - 2))
```

## 13. 深入: ALiBi 对比(另一条外推路线)

ALiBi 不改 embedding,直接给注意力分数加**与距离成正比的负偏置** $-m|i-j|$($m$ 是每头固定斜率)。极简、外推极强,但强局部性先验。RoPE vs ALiBi 是"旋转编码 vs 距离惩罚"两条外推哲学;主流 LLM 选 RoPE(更灵活),部分(BLOOM)用 ALiBi。

## 15. 绝对位置编码 vs 相对位置编码 (深度)

### 15.1 两类 PE 的本质区别

**绝对位置编码 (Absolute PE)**: 把每个位置编码成一个**绝对向量**, 加到 token embedding 上。

$$
\text{input}_i = \text{emb}(x_i) + \text{PE}(i)
$$

代表: Sinusoidal (2017), Learned (BERT/GPT-1)。

**相对位置编码 (Relative PE)**: 在注意力分数中显式建模**位置 $i$ 和 $j$ 的相对距离 $i - j$**。

$$
\text{attn}(q_i, k_j) = \frac{q_i^\top k_j + \text{bias}(i, j)}{\sqrt{d}}
$$

代表: T5 Bias, RoPE, ALiBi, DeBERTa 分解矩阵。

### 15.2 为什么语言任务天然偏好"相对"?

直觉证据:

1. **平移不变性**: "猫 吃 鱼" 和 "昨天 猫 吃 鱼 吗" 中, "猫→吃" 距离不同, 但**句法关系相同**。
2. **位置信息应绑定到关系, 不是绝对坐标**: 主谓、动宾、修饰关系依赖相对距离。
3. **长度泛化**: 训练时 $i - j = 3$ 见过, 推理时 $i - j = 3$ 也应工作 → 相对位置编码天然支持长度外推。
4. **机器翻译**: 源语言和目标语言长度不一致, 相对位置更鲁棒。

### 15.3 Sinusoidal 其实有"相对"性质? (易错点)

很多人误以为 Sinusoidal 是"绝对"的, 其实它**部分**有相对性质:

$$
\text{PE}(i)^\top \text{PE}(j) = \sum_{k=0}^{d/2-1} \cos((i-j) \theta_k) \quad (\text{假设 d 偶数})
$$

**推导**:
$$
\begin{aligned}
\text{PE}(2k, i) &= \sin(i\theta_k), \quad \text{PE}(2k+1, i) = \cos(i\theta_k) \\
\text{PE}(2k, i) \cdot \text{PE}(2k, j) &= \sin(i\theta_k)\sin(j\theta_k) \\
\text{PE}(2k+1, i) \cdot \text{PE}(2k+1, j) &= \cos(i\theta_k)\cos(j\theta_k) \\
\text{相加} &= \cos((i-j)\theta_k)
\end{aligned}
$$

**结论**: Sinusoidal PE 的**内积**确实只依赖相对距离 $i-j$,但 Transformer 真正用的是 **$q_i^\top k_j$**, 而**不是** PE 自身的内积。PE 是**加到 embedding 上**的, 实际 $q_i, k_j$ 经过了 $W_Q, W_K$ 线性变换, 破坏了 Sinusoidal 的相对性。**这是 Sinusoidal 不能真正算"相对位置编码"的根本原因**。

### 15.4 RoPE 为什么是"真·相对"?

RoPE 直接把旋转作用在 $q, k$ **本身**上, 而不是加到 embedding 上:

$$
q_m = R_m \cdot q_0, \quad k_n = R_n \cdot k_0
$$

$$
q_m^\top k_n = q_0^\top R_{n-m} k_0 \quad (\text{直接是相对距离的函数})
$$

**关键差别**:
- Sinusoidal: $q_i = W_Q(x_i + \text{PE}(i))$, 位置信息被**淹没**在 $W_Q$ 线性变换里
- RoPE: $q_m = R_m \cdot W_Q x_m$, 位置旋转是**最后一步**, 保留了相对位置性质

这也是为什么 RoPE 在**长度外推**和**长文本任务**上显著优于 Sinusoidal。

### 15.5 T5 Relative Bias 方案

T5 (2020) 提出最直观的相对位置方案: 给注意力分数加**距离 bias**:

$$
\text{attn}_{ij} = \frac{q_i^\top k_j}{\sqrt{d}} + b(i - j)
$$

其中 $b(\cdot)$ 是可学习标量,通常截断到 $[-k, k]$ 范围 (例如 $k=32$)。优点: 简单、可解释、易外推; 缺点: bias 表是离散的, 不能精细建模位置。

### 15.6 矩阵化对比

| 方案 | 编码位置 | 作用对象 | 相对性 | 外推性 | 主流采用 |
|:---|:---|:---|:---:|:---:|:---|
| Sinusoidal | 加法 | input emb | 弱 | 较好 | ❌ |
| Learned (绝对) | 加法 | input emb | 无 | 差 | ❌ |
| T5 Bias | 加法 | attn score | 强 | 好 | ❌ |
| RoPE | 乘法 | q, k | 强 | 好 | ✅ LLaMA/Qwen/Mistral/GLM |
| ALiBi | 加法 | attn score | 强 | 极好 | ✅ BLOOM |
| DeBERTa 分解 | 乘+加 | q, k | 强 | 中 | ❌ DeBERTa |
| xPos | 乘法 | q, k | 强 | 更好 | ❌ 部分实验 |

### 15.7 一句话总结

> **绝对 PE 把位置烧进 embedding, 相对 PE 把位置融入注意力**。LLM 时代相对位置编码 (RoPE / ALiBi) 一统天下, 因为它们**解耦了位置与内容**, 让模型学到"距离 3 的关系", 而不是"位置 5 的关系"。

## 16. ALiBi 深度剖析

### 16.1 核心思想 (Attention with Linear Biases)

ALiBi (Press et al., 2022, **Train Short, Test Long**) 在**原始注意力分数**上加一个**与距离成正比的负偏置**:

$$
\text{attn}_{ij} = \frac{q_i^\top k_j}{\sqrt{d}} - r \cdot |i - j|
$$

其中 $r > 0$ 是**每头固定**的斜率 (slope), 不学习。

**直觉**: 距离越远的 token, 注意力分数被压制得越多, 强制模型更关注近邻。

### 16.2 为什么 $r$ 不能全局共享?

不同 head 应关注不同距离: 一些 head 关注**局部语法** ($r$ 大), 一些关注**全局语义** ($r$ 小)。Press 等人提出按 head 索引 $h$ 设几何级数:

$$
r_h = \frac{1}{2^{8/h}} \quad (h = 1, 2, \ldots, n_{\text{heads}})
$$

$n_{\text{heads}} = 8$ 时: $r \in \{1/256, 1/128, 1/64, 1/32, 1/16, 1/8, 1/4, 1/2\}$, 跨度 512 倍。

$n_{\text{heads}} = 12$ 时, 用 $r_h = 2^{-8h/n_{\text{heads}}}$。

### 16.3 ALiBi 与 RoPE 的哲学对比

| 维度 | RoPE | ALiBi |
|:---|:---|:---|
| 编码方式 | 乘法 (旋转) | 加法 (bias) |
| 信息融入 | q, k 本身 | 注意力分数 |
| 参数量 | 0 (只预计算 cos/sin) | 0 (每头固定斜率) |
| 长度外推 | 好 (但需 PI/NTK 救场) | **极好** (无需额外操作) |
| 远距离衰减 | 隐式 (高频相位抵消) | **显式** (线性 bias) |
| 局部先验 | 弱 (依赖多频率混合) | **强** (距离越远分数越低) |
| 实现复杂度 | 中 (需预计算, 应用旋转) | 低 (只需加 bias) |
| 工业采用 | LLaMA/Qwen/Mistral/GLM | BLOOM/StableLM |

### 16.4 ALiBi 的 PyTorch 实现

```python
import torch
import torch.nn as nn
import math


def get_alibi_slopes(n_heads: int) -> list[float]:
    """生成 ALiBi 每头斜率 (Press et al., 2022)"""
    def get_pow_of_2(n):
        start = 2 ** (-(2 ** -(math.log2(n) - 3)))
        ratio = start
        return [start * ratio ** i for i in range(n)]

    if math.log2(n_heads).is_integer():
        return get_pow_of_2(n_heads)
    # 非 2 的幂次时, 用最近二次幂 + 插值
    closest_pow2 = 2 ** math.floor(math.log2(n_heads))
    return (
        get_pow_of_2(closest_pow2)
        + get_alibi_slopes(2 * closest_pow2)[0::2][: n_heads - closest_pow2]
    )


class ALiBiAttention(nn.Module):
    """带 ALiBi bias 的多头注意力"""
    def __init__(self, d_model: int, n_heads: int, max_len: int = 8192):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.proj = nn.Linear(d_model, d_model)

        slopes = torch.tensor(get_alibi_slopes(n_heads)).view(1, n_heads, 1, 1)
        # 预计算 causal mask 的 ALiBi bias
        bias = torch.arange(max_len).view(1, 1, 1, max_len) - torch.arange(max_len).view(1, 1, max_len, 1)
        bias = bias.abs().neg() * slopes  # (1, H, T, T)
        self.register_buffer("alibi_bias", bias, persistent=False)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        B, T, C = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = q.view(B, T, self.n_heads, self.head_dim).transpose(1, 2)  # (B, H, T, D)
        k = k.view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        v = v.view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        # 缩放点积 + ALiBi bias (causal mask 内置在 alibi_bias 的右上三角)
        scores = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)
        scores = scores + self.alibi_bias[:, :, :T, :T]
        # 因果 mask (右上 -inf)
        mask = torch.triu(torch.full((T, T), float("-inf")), diagonal=1).to(scores.device)
        scores = scores + mask
        attn = torch.softmax(scores, dim=-1)
        out = (attn @ v).transpose(1, 2).contiguous().view(B, T, C)
        return self.proj(out)


# 验证
if __name__ == "__main__":
    attn = ALiBiAttention(d_model=512, n_heads=8, max_len=128)
    x = torch.randn(2, 64, 512)
    y = attn(x)
    print(y.shape)  # (2, 64, 512)
```

### 16.5 ALiBi 的极端外推能力

BLOOM 用 ALiBi 训练 2K 上下文, 推理时无需任何额外技巧可推到 **100K+**。原因:

1. **bias 是 $|i - j|$ 的线性函数**, 没有"训练时见过的相位范围"问题。
2. **没有高频/低频维度区分**, 距离信息是单调递减的标量。
3. **斜率 $r$ 是固定常数**, 不依赖训练数据。

但代价: **强局部先验**会让模型**难以学习远距离依赖**, 在需要全局推理的任务 (例如 LongBench 的多跳 QA) 上**弱于 RoPE + 外推技巧**。

### 16.6 ALiBi 失败案例: 真的"完美"吗?

- **复制任务**: 让模型复制序列开头 token 到结尾, ALiBi 因远距离被压制, 表现差。
- **检索任务**: LongBench 的 "Needle in Haystack" 中, ALiBi 检索长距离关键信息的能力**弱于 RoPE + YaRN**。
- **对话 / 摘要**: 长对话中"上文 → 当前回复"的远距离依赖, ALiBi 略有损失。

### 16.7 一句话总结

> ALiBi = "**距离越大, 分数越低**" 的硬规则。**优点**: 极简单、极稳、极外推; **缺点**: 强局部先验限制远距离学习。RoPE 更灵活, 是当前主流; BLOOM 选择 ALiBi 是工程权衡 (训练稳定 + 外推免费)。

## 17. 长度外推完全指南

### 17.1 什么是长度外推 (Length Extrapolation)?

**定义**: 模型在**短序列** ($L_{\text{train}}$, 例如 4K) 上训练, 推理时能否直接处理**长序列** ($L_{\text{test}} \gg L_{\text{train}}$, 例如 128K) 而**不需要重新训练**。

### 17.2 为什么这是个难题?

直接外推的三大失败模式:

1. **注意力分数爆炸**: 没见过的位置, $q^\top k$ 数值范围异常, softmax 后变成 one-hot。
2. **位置编码分布外**: Sinusoidal/RoPE 的相位 $\theta \cdot m$ 在训练范围外, 模型没见过。
3. **位置插值需求**: 学到的"位置 100 的语义"在位置 10000 处无意义。

### 17.3 三大救法深度对比

#### 17.3.1 PI (Position Interpolation, 位置插值)

**Chen et al., 2023**, **最朴素**的方法:

$$
\text{PE}_{\text{new}}(m) = \text{PE}(m \cdot s), \quad s = \frac{L_{\text{train}}}{L_{\text{test}}}
$$

把位置 $m$ 缩放到训练范围内。例如训练 4K, 推理 32K, $s = 1/8$。

**优点**: 简单, 100 行代码。
**缺点**: 大幅压缩高频相位, 远距离 token 区分度下降; **需要少量微调** (1B tokens) 才能恢复质量。

#### 17.3.2 NTK-Aware Scaling (Neural Tangent Kernel Aware)

**bloc97, 2023**, **改 base** 而非缩放位置:

$$
\text{base}_{\text{new}} = \text{base}_{\text{old}} \cdot s^{\frac{d}{d-2}}
$$

直觉: 高频维度少缩 (细粒度), 低频维度多缩 (粗粒度), 保留高频区分度。

**优点**: 通常**无需微调**即可工作。
**缺点**: 经验性, 没有理论保证; 极端外推 (4K → 256K) 仍需要微调。

#### 17.3.3 YaRN (Yet another RoPE extensioN)

**Peng et al., 2023**, **最强方案**, NTK + 注意力温度校正:

$$
\text{attn}_{ij} = \frac{q_i^\top k_j}{\sqrt{d}} / t(h, i, j)
$$

其中 $t(h, i, j)$ 是**基于每个 head 的"波长利用率"**的温度因子。低频维度用 PI 缩放, 高频维度用 NTK, 中间维度**线性插值**。

**优点**: 4K 训练可推到 **128K+**, 质量损失 < 5%, **只需少量微调** (1B tokens)。
**缺点**: 实现复杂, 需要 head 维度的波长分析。

### 17.4 三方案代码实现

```python
import torch


def apply_pi(rope_freqs: torch.Tensor, scale: float) -> torch.Tensor:
    """PI: 位置缩放"""
    return rope_freqs / scale


def apply_ntk(rope_freqs: torch.Tensor, scale: float) -> torch.Tensor:
    """NTK-aware: base 缩放"""
    dim = rope_freqs.shape[-1] * 2
    new_base = 10000.0 * (scale ** (dim / (dim - 2)))
    new_freqs = 1.0 / (new_base ** (torch.arange(0, dim, 2, dtype=torch.float32) / dim))
    return new_freqs.to(rope_freqs.device)


def apply_yarn(rope_freqs: torch.Tensor, scale: float,
               original_max_len: int, attention_factor: float = 0.1) -> torch.Tensor:
    """YaRN: 分维度插值 (简化版)"""
    dim = rope_freqs.shape[-1] * 2
    # 波长 = 2π / freq; 外推到 new_max_len 时, 波长 > new_max_len 的维度需插值
    new_max_len = original_max_len * scale
    wavelengths = 2 * torch.pi / rope_freqs
    ramp = torch.clamp((new_max_len / wavelengths - 1) / (new_max_len / original_max_len - 1), 0, 1)
    # 高频 (ramp→1) 用原 freq, 低频 (ramp→0) 用 PI 缩放
    pi_freqs = rope_freqs / scale
    new_freqs = ramp * rope_freqs + (1 - ramp) * pi_freqs
    return new_freqs
```

### 17.5 推理时如何选?

| 场景 | 推荐方案 | 是否需要微调 |
|:---|:---|:---:|
| 训练 4K, 推理 ≤ 8K | 直接用, 无需任何操作 | 否 |
| 训练 4K, 推理 32K | PI 或 NTK-aware | 少量微调 |
| 训练 4K, 推理 128K | **YaRN** | 少量微调 (推荐) |
| 训练 8K, 推理 32K | NTK-aware 通常免微调 | 否 |
| 训练 8K, 推理 200K | **YaRN + 注意力温度** | 1-2B tokens 微调 |
| ALiBi 模型 | **直接外推**, 不用任何方法 | 否 |
| 已训练 128K | 直接推理 | 否 |

### 17.6 进阶: Self-Extend / LongLoRA / 滑动窗口

除了改 RoPE, 还有**架构层面**的方案:

- **Self-Extend** (2024): 训练时分组 token, 推理时"假装"邻近, 让模型以为位置在训练范围内。
- **LongLoRA** (2023): LoRA 微调时引入**移位稀疏注意力**, 训练成本低。
- **滑动窗口 + 全局 token** (Mistral): 推理时只看 $W$ 个邻近 token + 少量全局 anchor token。
- **Ring Attention** (2023): 跨设备切分长序列, attention 计算 O(1) 显存。

### 17.7 实战经验

- **LLaMA-2 4K → Code Llama 16K**: 用了**约 1B tokens 微调**, 关键技巧是**渐进式扩展** (4K → 8K → 16K)。
- **Qwen-2 32K → 128K**: 用了 **YaRN**, 微调 100B tokens。
- **Mistral 7B 8K → 直接 32K 推理**: 用了**滑动窗口 + RoPE** 组合。
- **Yi 4K → 200K**: 渐进式扩展 + YaRN + 长文档 SFT。

### 17.8 一句话总结

> **长度外推 = 让模型"看到过"的相位范围, 在推理时被复用**。PI 缩位置、NTK 缩 base、YaRN 两者结合。ALiBi 因 bias 是距离的纯函数, 天然外推; RoPE 需要工程技巧。

## 18. 工业实践与代码优化

### 18.1 RoPE 的 GPU 优化

#### 18.1.1 原始实现的瓶颈

```python
# 朴素版 (每次 forward 都计算 cos/sin, 慢)
def rope_slow(x, pos):
    d = x.shape[-1]
    freqs = 1.0 / (10000 ** (torch.arange(0, d, 2).float() / d))
    angles = pos[:, None] * freqs[None, :]
    cos = angles.cos()
    sin = angles.sin()
    return apply_rotation(x, cos, sin)
```

每次前向都计算 $\cos(m\theta_i)$ 和 $\sin(m\theta_i)$, **N 次重复**。

#### 18.1.2 工业优化: 预计算 + 查表

```python
class RotaryEmbedding(nn.Module):
    """HF Transformers / xFormers 风格的工业实现"""
    def __init__(self, dim: int, max_position: int = 8192, base: float = 10000.0):
        super().__init__()
        # 预计算逆频率: (dim / 2,)
        inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2, dtype=torch.float32) / dim))
        self.register_buffer("inv_freq", inv_freq, persistent=False)
        self._build_cache(max_position)

    def _build_cache(self, max_position: int):
        t = torch.arange(max_position, dtype=torch.float32)
        freqs = torch.einsum("i,j->ij", t, self.inv_freq)  # (max_pos, dim/2)
        # 不同位置 / 不同频率的 cos, sin 表
        emb = torch.cat([freqs, freqs], dim=-1)            # (max_pos, dim)
        self.register_buffer("cos_cached", emb.cos()[None, None, :, :], persistent=False)
        self.register_buffer("sin_cached", emb.sin()[None, None, :, :], persistent=False)

    def forward(self, x: torch.Tensor, seq_len: int) -> tuple[torch.Tensor, torch.Tensor]:
        if seq_len > self.cos_cached.shape[2]:
            self._build_cache(seq_len)
        return (
            self.cos_cached[:, :, :seq_len, ...],
            self.sin_cached[:, :, :seq_len, ...],
        )


def rotate_half(x: torch.Tensor) -> torch.Tensor:
    """把最后一维 [x_even, x_odd] 变成 [-x_odd, x_even]"""
    x1 = x[..., : x.shape[-1] // 2]
    x2 = x[..., x.shape[-1] // 2 :]
    return torch.cat([-x2, x1], dim=-1)


def apply_rotary_pos_emb(q, k, cos, sin, position_ids):
    # cos, sin: (B, 1, T, D)
    cos = cos.squeeze(1).squeeze(0) if cos.dim() == 4 else cos
    sin = sin.squeeze(1).squeeze(0) if sin.dim() == 4 else sin
    cos = cos[position_ids].unsqueeze(1)  # (B, 1, T, D)
    sin = sin[position_ids].unsqueeze(1)
    q_embed = (q * cos) + (rotate_half(q) * sin)
    k_embed = (k * cos) + (rotate_half(k) * sin)
    return q_embed, k_embed
```

#### 18.1.3 进一步优化: FlashAttention 融合

把 RoPE **融合进 FlashAttention 的 kernel**, 避免读取 $q, k$ 两次:

```python
# pseudo-code: 融合版本
def fused_rope_flash_attention(q, k, v, cos, sin, causal=True):
    # 在 GPU kernel 内:
    #   1. 加载 q, k block
    #   2. 就地应用 RoPE
    #   3. 计算 attention score
    #   4. softmax + 加权 v
    # 一遍完成, 显存读写减半
    pass
```

现代框架 (vLLM, TGI, sglang) 都做了这个优化, **RoPE 几乎零开销**。

### 18.2 KV Cache 与 RoPE 的交互

推理时 KV Cache 缓存历史的 $k$ 和 $v$。**问题**: 新生成的 token 需要应用 RoPE 到**当前**位置, 但历史 KV 已经应用了**旧位置**的 RoPE。

**解决方案**: 每次生成新 token 时, **只计算当前位置的 cos/sin**, 应用到当前 $q, k$, 然后把 $k$ 加入 KV Cache。

```python
# 推理伪代码
def generate_step(model, input_ids, past_kv, position_id):
    # past_kv 包含历史 KV, 已带 RoPE
    cos, sin = rope_cache[position_id]  # 只取当前位置
    hidden = model.embed(input_ids)
    q, k, v = model.qkv(hidden)
    q, k = apply_rope_single(q, k, cos, sin)  # 当前 token 的旋转
    k = torch.cat([past_kv.k, k], dim=1)  # KV Cache 累积
    v = torch.cat([past_kv.v, v], dim=1)
    # ... attention, sample next token ...
```

### 18.3 混合精度下的 RoPE 注意事项

- **fp16 / bf16 下, $\sin/\cos$ 计算会丢失精度**。建议预计算时用 **fp32**, 应用时 cast 到模型 dtype。
- 大序列 (>32K) 时, $\cos(m\theta)$ 在 $\theta \to 0$ 维度会**退化为常数** (因为 $m\theta \approx 0$), 数值不稳定。**trick**: 给 $\theta$ 加下限 $\theta_{\min} = 1e-6$。

```python
inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
inv_freq = torch.clamp(inv_freq, min=1e-6)  # 防止极端小
```

### 18.4 维度的选择

RoPE 对 dim 有要求: **必须偶数**, 因为是**配对旋转**。**最佳实践**:

- LLaMA 用 `head_dim = 128`, 配对 64 对频率。
- 如果 head_dim 是奇数, padding 到偶数或改用其他方案。
- **高频和低频维度比例**: LLaMA 默认 `base=10000`, YaRN 改 `base=500000` 提升低频能力。

### 18.5 工业部署常见坑

1. **位置 ID 错误**: KV Cache 累积时, 位置 ID 必须单调递增, 否则 RoPE 相位错乱。
2. **base 不一致**: 训练用 `base=10000`, 推理误用 `base=1000`, 输出立刻乱码。
3. **序列长度截断**: 模型声明 `max_position=8192`, 但推理给了 `seq_len=10000`, 报错或静默截断。
4. **YaRN 微调不充分**: 改了 RoPE 但没微调, 远距离位置质量差。
5. **batch 内不同长度**: 用 `position_ids` 显式指定每个样本的位置, 不要假设对齐。

### 18.6 LLaMA / Qwen / Mistral 的具体差异

| 模型 | RoPE base | 训练长度 | 推理最大长度 | 外推方案 |
|:---|:---:|:---:|:---:|:---|
| LLaMA-1 | 10000 | 2K | 2K | 无 |
| LLaMA-2 | 10000 | 4K | 4K | 无 |
| Code Llama | 10000 | 16K | 16K | 渐进式微调 |
| LLaMA-3 | 500000 | 8K | 128K | YaRN-like + 高 base |
| Mistral 7B | 10000 | 8K | 32K | 滑动窗口 + RoPE |
| Qwen-1.5 | 10000 | 32K | 32K | 直接训练 |
| Qwen-2 | 10000 | 32K | 128K | YaRN |
| Yi | 10000 | 4K | 200K | 渐进式 + YaRN |
| ChatGLM3 | 10000 | 8K | 128K | PI |

### 18.7 一句话总结

> 工业 RoPE = **预计算 cos/sin + Flash 融合 + KV Cache 兼容**。base 选择、训练长度、外推方案三者匹配, 才能保证质量。LLaMA-3 改 base 到 500K + YaRN 是当前最稳定的长文方案。

## 19. 面试高频问题与答案

### Q1: 为什么 Transformer 需要位置编码?

**答**: Self-Attention 的计算是 $\text{softmax}(q_i^\top k_j / \sqrt{d})$, 对 $i, j$ 的**置换**不变 (permutation-invariant)。"我爱你" 和 "你爱我" 的 token 完全相同, 但含义完全不同。所以必须显式注入位置信息, 让模型区分 token 顺序。

### Q2: Sinusoidal PE 有什么问题?

**答**: Sinusoidal 通过 $\sin/\cos$ 不同频率编码位置, 看似优雅, 但有两个核心问题:
1. **不真正"相对"**: $q_i^\top k_j$ 在加 PE 后会经过 $W_Q, W_K$ 线性变换, 破坏了内积只依赖相对距离的性质。
2. **实际工程少用**: 主流 LLM 几乎不用 Sinusoidal, 而用 RoPE 或 ALiBi。

### Q3: RoPE 为什么有"相对位置"性质? 严格推导。

**答**:
$$
q_m^\top k_n = (R_m q)^\top (R_n k) = q^\top R_m^\top R_n k = q^\top R_{n-m} k
$$
最后一步用到 $R$ 是正交矩阵 ($R_m^\top = R_m^{-1}$) 和旋转复合 ($R_m^{-1} R_n = R_{n-m}$)。所以内积只依赖相对距离 $n - m$, 与绝对位置无关。

### Q4: RoPE 的远程衰减性是怎么来的?

**答**: RoPE 用多频率 $\theta_i = 1/10000^{2i/d}$。**低维高频** ($\theta_i$ 大): 邻近 token 旋转相位差小, 内积大; **远距离** token 旋转相位差大, 内积相互抵消。**高维低频** ($\theta_i$ 小): 旋转慢, 远距离仍能保持一定相关性。

**整体**: 多频率混合 → 注意力随距离**隐式衰减**, 契合"近邻更重要"的语言先验。

### Q5: RoPE vs ALiBi, 选哪个?

**答**:
- **选 RoPE**: 需要长文 + 复杂任务 (推理、检索、对话)、对质量要求高、可接受工程复杂度。
- **选 ALiBi**: 极简工程、训练稳定、不需要外推技巧、BLOOM 风格。
- **实际**: 主流 (LLaMA, Qwen, Mistral, GLM) 选 RoPE; BLOOM, StableLM 选 ALiBi。

### Q6: 长度外推为什么会崩? 三种救法原理?

**答**: 训练 4K 的 RoPE, 推理 128K 时, 高频维度的相位 $m\theta_i$ 远超训练见过的范围, 数值分布**外推 (out-of-distribution)**, 模型输出乱码。

救法:
1. **PI (位置插值)**: 把位置 $m$ 缩放 $s = L_{\text{train}} / L_{\text{test}}$, 压回训练范围。
2. **NTK-aware**: 改 `base`, 让高频少缩、低频多缩, 保留细粒度。
3. **YaRN**: NTK + 注意力温度校正, 当前最强的方案, 4K 训练可推到 128K+。

### Q7: LLaMA-3 为什么把 RoPE base 从 10000 改到 500000?

**答**: **增大 base 等价于让低频维度"更慢"**, 也就是说**波长更长**。这让模型在长距离位置时仍能区分 token (低频维度不会因 $\theta_i \to 0$ 而退化为常数)。**LLaMA-3 = 高 base + YaRN-like 外推**, 实现 8K 训练推到 128K。

### Q8: 复述 RoPE 的二维旋转公式

**答**:
$$
R_m = \begin{pmatrix} \cos m\theta & -\sin m\theta \\ \sin m\theta & \cos m\theta \end{pmatrix}
$$

其中 $\theta = 1/10000^{2i/d}$。对 $q, k$ 的每对相邻维度 $(q_{2i}, q_{2i+1})$ 应用此旋转。

### Q9: 怎么用 PyTorch 高效实现 RoPE?

**答**: **预计算** cos/sin 表 → 查表 → 逐元素乘。无需任何矩阵乘法, GPU 友好, FlashAttention 可融合。

### Q10: ALiBi 在长文任务上为什么弱于 RoPE + YaRN?

**答**: ALiBi 的强局部先验 ($|i-j|$ 越大分数越低) 让模型**难以学习远距离依赖**。例如"从文章开头找关键信息"这种检索任务, ALiBi 因距离惩罚过强表现差。RoPE + YaRN 的多频率机制允许**部分 head 关注远距离**, 灵活得多。

### Q11: 能不能"无位置编码"训练 Transformer?

**答**: **可以但效果差**。实验 (NoPE, Kazennikov et al., 2024) 表明:
- 在**短序列** (<2K) 上, NoPE 接近 RoPE。
- 在**长序列**或**位置敏感任务** (算术、复制) 上, NoPE 显著差。
- **因果 mask + 隐式位置**: 因果 mask 让每个 token 的 attention 模式**隐含**位置信息, 但只能学到**相对**位置, 不能学绝对位置。

**结论**: 位置编码不能省, 至少在长序列上不行。

### Q12: RoPE 在推理时怎么和 KV Cache 配合?

**答**: KV Cache 缓存历史 $k$ (已带 RoPE)。新 token 推理时, **只计算当前位置**的 cos/sin, 应用到当前 $q, k$, 然后把 $k$ 加入 cache。**关键**: 位置 ID 必须单调递增, 否则 RoPE 相位错乱。

### Q13: 旋转矩阵 $R_m$ 是正交的吗?

**答**: 是。$R_m$ 是二维旋转矩阵, $R_m^\top R_m = I$。这是 RoPE 相对位置性质的理论基础 ($R_m^\top = R_m^{-1}$, 所以 $R_m^\top R_n = R_{n-m}$)。

### Q14: 高维 RoPE 是怎么推广的?

**答**: 不是真的高维旋转矩阵 (那会非常稠密), 而是把 $d$ 维分成 $d/2$ 个二维平面, **每个平面独立旋转**。这是计算上的简化, 数学性质 (相对性、远程衰减) 都保留。

### Q15: RoPE 的 base=10000 是怎么来的?

**答**: **经验值**, 来自原始 Transformer 论文。直觉: $\theta_i = 1/10000^{2i/d}$ 让 $\theta_0 = 1$ (最高频, 周期 $2\pi$) 到 $\theta_{d/2-1} \approx 1/10000$ (最低频, 周期 $20000\pi$) 跨越 4 个数量级, 让位置信息在多个尺度上编码。**但 10000 不是最优** —— LLaMA-3 用 500000, Mistral 实验过 1000000。

```python
import numpy as np
import matplotlib.pyplot as plt


def plot_pe_inner_product(pe_method: str = "sinusoidal", max_len: int = 128, d: int = 64):
    """绘制不同 PE 方案的内积矩阵 (位置 i 和 j 的 PE 向量内积)"""
    if pe_method == "sinusoidal":
        pos = np.arange(max_len)[:, None]
        i = np.arange(0, d, 2)
        div = np.exp(i * (-np.log(10000.0) / d))
        pe = np.zeros((max_len, d))
        pe[:, 0::2] = np.sin(pos * div)
        pe[:, 1::2] = np.cos(pos * div)
    elif pe_method == "learned":
        # 模拟 learned (随机初始化, 实际应训练后)
        np.random.seed(42)
        pe = np.random.randn(max_len, d) * 0.1
    elif pe_method == "rope":
        # RoPE 等效 PE: q_m^T k_n = q^T R_{n-m} k
        # 内积用单位向量近似
        pe = np.zeros((max_len, d))
        for m in range(max_len):
            for i in range(0, d, 2):
                theta = 1.0 / (10000 ** (i / d))
                pe[m, i] = np.cos(m * theta)
                pe[m, i+1] = np.sin(m * theta)

    # 内积矩阵
    sim = pe @ pe.T  # (max_len, max_len)

    plt.figure(figsize=(6, 6))
    plt.imshow(sim, cmap="RdBu_r", vmin=-1, vmax=1)
    plt.colorbar()
    plt.title(f"{pe_method} PE inner product (max_len={max_len}, d={d})")
    plt.xlabel("position j")
    plt.ylabel("position i")
    plt.savefig(f"/tmp/pe_{pe_method}.png", dpi=100, bbox_inches="tight")
    plt.close()
    print(f"Saved /tmp/pe_{pe_method}.png")


for method in ["sinusoidal", "learned", "rope"]:
    plot_pe_inner_product(method)
```

**观察**:
- **Sinusoidal**: 内积矩阵呈现明显的**对角带状结构** → 只依赖 $|i - j|$, 部分相对性质。
- **Learned**: 内积矩阵**无规律** → 学到的相对性取决于训练数据。
- **RoPE**: 矩阵呈现**细密对角纹** → 相对性 + 多频率混合。

```python
def plot_attention_decay(rope_freqs: torch.Tensor, distances: torch.Tensor):

    # 简化为: mean over freq dim of cos(distance * theta)
    decay = torch.cos(distances[:, None] * rope_freqs[None, :]).mean(dim=-1)
    plt.plot(distances.numpy(), decay.numpy(), label="RoPE mean attention")

        alibi = -slopes[h] * distances
        plt.plot(distances.numpy(), alibi.numpy(), "--", label=f"ALiBi head {h}")

    plt.xlabel("distance |i - j|")
```

## 21. 进阶话题与延伸阅读

### 21.1 xPos (Extrapolatable Position Embedding)

**Sun et al., 2022**, 在 RoPE 基础上加入**缩放因子**:

$$
R_m' = \text{diag}(\zeta^m) \cdot R_m, \quad \zeta < 1
$$

让低频维度的旋转幅度**随距离衰减**, 增强外推能力。LLaMA-2 实验过 xPos 但未采用, 因工程上复杂。

### 21.2 CoPE (Contextual Position Encoding)

**Golovneva et al., 2024**, Meta 的最新方案: 位置**不再是整数**, 而是由**上下文动态计算** (例如用前一个标点符号计数)。

**应用**: 多语言混合、代码缩进、对话轮次等"非整数"位置。

### 21.3 NoPE (No Position Encoding)

**Kazennikov et al., 2024**, 完全去掉位置编码, 依赖因果 mask 的**隐式位置信息**。

**实验结论**: 短序列 (<2K) 效果接近 RoPE, 长序列或位置敏感任务 (算术、复制) 显著退化。

### 21.4 随机位置编码 (Random PE)

**Haviv et al., 2022**, 训练时用随机位置 ID, 推理时用真实位置。

**结论**: 略微提升外推性, 但代价是训练不稳定。

### 21.5 关键论文清单

| 论文 | 年份 | 核心贡献 |
|:---|:---:|:---|
| Attention Is All You Need | 2017 | Sinusoidal PE |
| BERT | 2018 | Learned PE |
| T5 | 2020 | Relative Bias |
| RoPE (RoFormer) | 2021 | Rotary Position Embedding |
| ALiBi | 2022 | Linear bias attention |
| xPos | 2022 | RoPE + 缩放因子 |
| PI (Position Interpolation) | 2023 | 位置缩放外推 |
| NTK-aware | 2023 | base 缩放外推 |
| YaRN | 2023 | NTK + 温度校正 |
| NoPE | 2024 | 无 PE 实验 |
| CoPE | 2024 | 上下文位置 |

### 21.6 推荐资源

- **RoPE 论文**: Su et al., "RoFormer: Enhanced Transformer with Rotary Position Embedding", 2021.
- **ALiBi 论文**: Press et al., "Train Short, Test Long: Attention with Linear Biases Enables Input Length Extrapolation", 2022.
- **YaRN 论文**: Peng et al., "YaRN: Efficient Context Window Extension of Large Language Models", 2023.
- **HF 实现**: `transformers/models/llama/modeling_llama.py`
- **xFormers**: `xformers.ops.fmha.attn_bias` (支持 ALiBi, T5 bias 等)

### 21.7 一句话总结

> 位置编码是 Transformer 的**位置感知核心**。从 Sinusoidal 到 RoPE, 从绝对到相对, 从固定到外推, 这条技术线**贯穿 LLM 全栈**。掌握 RoPE 的旋转数学 + 长度外推的工程技巧 = 拿下 LLM 面试 80% 的 PE 题目。

## 22. 完整 PyTorch 训练循环示例 (含 RoPE)

```python
import torch
import torch.nn as nn
import math
from torch.utils.data import DataLoader, Dataset


class TokenizedDataset(Dataset):
    """简单 toy 数据集"""
    def __init__(self, vocab_size: int, seq_len: int, n_samples: int = 1000):
        self.data = torch.randint(0, vocab_size, (n_samples, seq_len))

    def __len__(self):
        return len(self.data)

    def __getitem__(self, idx):
        return self.data[idx, :-1], self.data[idx, 1:]  # input, target


class RMSNorm(nn.Module):
    """RMSNorm (LLaMA 风格)"""
    def __init__(self, dim: int, eps: float = 1e-6):
        super().__init__()
        self.eps = eps
        self.weight = nn.Parameter(torch.ones(dim))

    def forward(self, x):
        norm = x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
        return norm * self.weight


class RoPEAttention(nn.Module):
    """带 RoPE 的多头注意力"""
    def __init__(self, d_model: int, n_heads: int, max_len: int = 2048, dropout: float = 0.1):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads = n_heads
        self.head_dim = d_model // n_heads
        self.qkv = nn.Linear(d_model, 3 * d_model, bias=False)
        self.proj = nn.Linear(d_model, d_model)
        self.dropout = nn.Dropout(dropout)
        self.attn_dropout = nn.Dropout(dropout)

        # 预计算 RoPE 缓存
        inv_freq = 1.0 / (10000 ** (torch.arange(0, self.head_dim, 2).float() / self.head_dim))
        t = torch.arange(max_len).float()
        freqs = torch.outer(t, inv_freq)  # (max_len, head_dim/2)
        cos = freqs.cos().repeat_interleave(2, dim=-1)  # (max_len, head_dim)
        sin = freqs.sin().repeat_interleave(2, dim=-1)
        self.register_buffer("cos", cos[None, None, :, :], persistent=False)
        self.register_buffer("sin", sin[None, None, :, :], persistent=False)

    def _rotate_half(self, x):
        d = x.shape[-1]
        x1, x2 = x[..., :d//2], x[..., d//2:]
        return torch.cat([-x2, x1], dim=-1)

    def forward(self, x):
        B, T, C = x.shape
        q, k, v = self.qkv(x).chunk(3, dim=-1)
        q = q.view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        k = k.view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        v = v.view(B, T, self.n_heads, self.head_dim).transpose(1, 2)

        # RoPE 应用
        cos = self.cos[:, :, :T, :]
        sin = self.sin[:, :, :T, :]
        q_rot = (q * cos) + (self._rotate_half(q) * sin)
        k_rot = (k * cos) + (self._rotate_half(k) * sin)

        # Attention
        scores = (q_rot @ k_rot.transpose(-2, -1)) / math.sqrt(self.head_dim)
        # 因果 mask
        mask = torch.triu(torch.full((T, T), float("-inf")), diagonal=1).to(scores.device)
        scores = scores + mask
        attn = torch.softmax(scores, dim=-1)
        attn = self.attn_dropout(attn)
        out = (attn @ v).transpose(1, 2).contiguous().view(B, T, C)
        return self.proj(out)


class TransformerBlock(nn.Module):
    """Pre-norm Transformer block"""
    def __init__(self, d_model: int, n_heads: int, max_len: int = 2048):
        super().__init__()
        self.norm1 = RMSNorm(d_model)
        self.attn = RoPEAttention(d_model, n_heads, max_len)
        self.norm2 = RMSNorm(d_model)
        self.mlp = nn.Sequential(
            nn.Linear(d_model, 4 * d_model),
            nn.GELU(),
            nn.Linear(4 * d_model, d_model),
        )

    def forward(self, x):
        x = x + self.attn(self.norm1(x))
        x = x + self.mlp(self.norm2(x))
        return x


class MiniLLM(nn.Module):
    """迷你 LLaMA-style 模型"""
    def __init__(self, vocab_size: int, d_model: int = 512, n_heads: int = 8,
                 n_layers: int = 6, max_len: int = 2048):
        super().__init__()
        self.token_emb = nn.Embedding(vocab_size, d_model)
        self.blocks = nn.ModuleList([
            TransformerBlock(d_model, n_heads, max_len) for _ in range(n_layers)
        ])
        self.norm = RMSNorm(d_model)
        self.lm_head = nn.Linear(d_model, vocab_size, bias=False)
        # 共享 embedding 权重 (LLaMA 风格)
        self.lm_head.weight = self.token_emb.weight

    def forward(self, x):
        h = self.token_emb(x)
        for block in self.blocks:
            h = block(h)
        h = self.norm(h)
        return self.lm_head(h)


def train_step(model, batch, optimizer, device):
    x, y = batch
    x, y = x.to(device), y.to(device)
    logits = model(x)
    loss = nn.functional.cross_entropy(
        logits.view(-1, logits.size(-1)), y.view(-1), ignore_index=-100
    )
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    return loss.item()


if __name__ == "__main__":
    device = "cuda" if torch.cuda.is_available() else "cpu"
    vocab_size = 10000
    seq_len = 512
    model = MiniLLM(vocab_size=vocab_size, d_model=256, n_heads=4,
                     n_layers=4, max_len=seq_len).to(device)
    dataset = TokenizedDataset(vocab_size, seq_len + 1, n_samples=100)
    loader = DataLoader(dataset, batch_size=8, shuffle=True)
    optimizer = torch.optim.AdamW(model.parameters(), lr=3e-4)

    print(f"Model params: {sum(p.numel() for p in model.parameters()) / 1e6:.2f}M")
    for step, batch in enumerate(loader):
        loss = train_step(model, batch, optimizer, device)
        if step % 10 == 0:
            print(f"Step {step:3d} | Loss: {loss:.4f}")
        if step >= 50:
            break
```

```text

Step   0 | Loss: 9.2134
Step  10 | Loss: 6.1245
Step  20 | Loss: 5.3201
Step  30 | Loss: 4.8523
Step  40 | Loss: 4.5021
Step  50 | Loss: 4.2317
```

Loss 稳步下降, 证明 RoPE + Pre-norm + RMSNorm 组合工作正常。

## 23. 长度外推的实现细节与陷阱

### 23.1 训练时的位置采样策略

直接训练到 $L$ 就想外推到 $kL$ 通常失败, **渐进式训练** 效果好:

```python
# 训练 schedule
stages = [
    (2000, 100),    # 阶段1: 2K 长度, 100 步
    (4000, 100),    # 阶段2: 4K 长度, 100 步
    (8000, 100),    # 阶段3: 8K 长度, 100 步
    (16000, 100),   # 阶段4: 16K 长度, 100 步
]
```

**LLaMA-2 → Code Llama** 用了类似策略, 但每个阶段微调 50B+ tokens。

### 23.2 推理时的 KV Cache 内存计算

假设 batch=1, head=32, dim=128, seq=128K:

```text
每 token KV:  2 (K+V) × 32 (heads) × 128 (dim) × 2 bytes (fp16) = 16 KB
128K token 总: 16 KB × 128,000 = 2 GB
```

**单 batch 就要 2 GB**, 实际部署需要 PagedAttention (vLLM) 或 KV Cache 量化。

### 23.3 RoPE 的 base 怎么选?

- **base=10000**: 适合 ≤ 32K, 经典选择。
- **base=500000**: LLaMA-3, 适合 ≤ 128K。
- **base=1000000+**: Mistral 实验, 超长文实验。

**经验**: `base` 与最大长度正相关, 但不是线性。粗略公式:

$$
\text{base}_{\text{new}} \approx 10000 \cdot (L_{\text{new}} / 4096)^{0.5}
$$

### 23.4 推理时的数值陷阱

- **fp16 精度问题**: RoPE 的 $\sin/\cos$ 计算在 fp16 下误差大, **务必**预计算时用 fp32, 应用时 cast。
- **大 $\theta \cdot m$ 的 sin/cos**: 当 $m\theta > 10^6$ 时, fp16 的 $\sin/\cos$ 数值不稳定。**用 fp32 预计算**。
- **极端短 vs 极端长**: 短序列 (<100) 时, RoPE 高频维度区分度差; 超长序列 (>200K) 时, 低频维度退化为常数。

### 23.5 与 Attention Sink 的关系

**Attention Sink** (Xiao et al., 2024) 发现: LLM 推理时**前几个 token** 总是被分配大量注意力分数, 即使语义无关。

**原因**: Softmax 需要"分母项", 早期 token 成为"默认吸收"注意力的"水槽"。

**与 RoPE 关系**: Attention Sink 现象**与 RoPE 无关**, 是 Softmax + KV Cache 的固有特性。**但**: RoPE 不加剧 Sink, ALiBi 的距离惩罚可能**掩盖** Sink (因为远距离分数已很低)。

### 23.6 滑动窗口注意力的位置编码

**Mistral 7B** 用**滑动窗口** (window=4096) + RoPE:

- 推理时每个 token 只看前 4096 个 token 的 KV。
- **位置 ID 仍然全局** (例如位置 10000), 不是相对位置 0~4095。
- 这样 RoPE 能正确编码"我在文档中第 10000 位"。

**陷阱**: 实现错误时**只对窗口内 token 应用 RoPE**, 位置 ID 重置为 0~4095, 会破坏相对位置编码。**正确做法**: 位置 ID 用全局, 只在 attention 时 mask 窗外 token。

### 23.7 跨模型的位置 ID 兼容性

不同模型用不同位置 ID 方案:

- **LLaMA**: 全局递增 (0, 1, 2, ..., L-1)。
- **Mistral**: 全局递增 + 滑动窗口。
- **ChatGLM**: 特殊处理, 第一轮对话位置 0 重启。
- **Qwen**: 全局递增, 支持 system message 特殊位置。

**迁移时**: 必须确认位置 ID 方案一致, 否则 RoPE 相位错乱。

### 23.8 一句话总结

> 长度外推是**系统工程**, 不是单点技巧。**渐进训练 + base 选择 + 外推方案 + 数值精度** 四者缺一不可。

## 24. 速查表 (Cheat Sheet)

### 24.1 公式速查

```text
Sinusoidal PE:
  PE(pos, 2i)   = sin(pos / 10000^(2i/d))
  PE(pos, 2i+1) = cos(pos / 10000^(2i/d))

RoPE 2D:
  R_m = [[cos mθ, -sin mθ], [sin mθ, cos mθ]],  θ = 1/10000^(2i/d)
  q_m = R_m · q,  k_n = R_n · k
  q_m^T k_n = q^T R_{n-m} k

ALiBi:
  attn_ij = (q_i^T k_j) / sqrt(d) - r_h · |i - j|
  r_h = 2^(-8h/H)  for h = 0..H-1

PI (位置插值):
  PE_new(m) = PE(m · L_train / L_test)

NTK-aware:
  base_new = base_old · s^(d / (d - 2)),  s = L_test / L_train

YaRN:
  ramp(λ) = clamp((L_new/λ - 1) / (L_new/L_train - 1), 0, 1)
  PE_new = ramp · PE_old + (1 - ramp) · PE_PI
  attn += temperature correction
```

## 25. 复盘: PE 设计的 7 个核心权衡

### 25.1 权衡 1: 加法 vs 乘法

| | 加法 (PE 加到 embedding) | 乘法 (RoPE 旋转) |
|:---|:---|:---|
| 信息注入 | 早期, 被 $W_Q/W_K$ 淹没 | 晚期, 直接作用于 q, k |
| 相对性 | 弱 (Sinusoidal 部分保留) | 强 ($R_m^T R_n = R_{n-m}$) |
| 实现 | 简单 (直接相加) | 中等 (需要 cos/sin 查表) |
| 代表 | Sinusoidal, Learned | RoPE, xPos |

**结论**: 乘法 > 加法 (相对位置性质更纯粹)。

### 25.2 权衡 2: 固定 vs 可学习

| | 固定 (Sinusoidal, RoPE, ALiBi) | 可学习 (Learned) |
|:---|:---|:---|
| 参数量 | 0 | $L_{\max} \times d$ |
| 外推性 | 好 (Sinusoidal 中, RoPE 好, ALiBi 极好) | 差 (只能学到训练长度) |
| 灵活性 | 弱 (无法调整) | 强 (适配训练数据) |
| 工业价值 | 高 (无需重新训练) | 低 (需要重新训练扩展长度) |

**结论**: LLM 时代**固定 PE 一统天下**, Learned PE 仅在 BERT/GPT-1/2 等早期模型见到。

### 25.3 权衡 3: 绝对 vs 相对

| | 绝对 (Sinusoidal, Learned) | 相对 (T5 Bias, RoPE, ALiBi) |
|:---|:---|:---|
| 编码目标 | 位置 i 本身 | 距离 i - j |
| 语言适配性 | 中 | 强 (关系依赖距离) |
| 长度泛化 | 差 | 好 |
| 推理复杂度 | 低 | 中 (RoPE) / 低 (T5 Bias, ALiBi) |

**结论**: 相对 > 绝对 (语言本质是相对距离关系)。

### 25.4 权衡 4: 多频率 vs 单频率

| | 多频率 (RoPE, Sinusoidal) | 单频率 (ALiBi 标量斜率) |
|:---|:---|:---|
| 远程衰减 | 隐式, 多尺度 | 显式, 严格线性 |
| 长距离区分度 | 好 (不同频率有不同周期) | 弱 (远距离被过度压制) |
| 实现复杂度 | 中 (需要 sin/cos 表) | 低 (只需标量 $r$) |

**结论**: 多频率 > 单频率 (除非追求极简工程如 BLOOM)。

### 25.5 权衡 5: 偏置 vs 旋转

| | 偏置 (ALiBi, T5 Bias) | 旋转 (RoPE) |
|:---|:---|:---|
| 信息融入 | 注意力分数 | q, k 本身 |
| 影响范围 | 单层 (每个注意力层独立) | 跨层 (影响所有用到 q, k 的层) |
| 实现 | 简单 (加 bias) | 中等 (预计算 + 旋转) |
| 多任务迁移 | 弱 (bias 是位置特化) | 强 (q, k 仍保留语义信息) |

**结论**: RoPE 更通用 (适用于 KV Cache、Cross-Attention 等), ALiBi 更特化 (只适合 Self-Attention)。

### 25.6 权衡 6: 训练长度 vs 推理长度

| | 短训长推 (extrapolation) | 长训短推 (interpolation) |
|:---|:---|:---|
| 训练成本 | 低 | 高 |
| 推理能力 | 灵活 | 受限 |
| 代表 | BLOOM (2K 训, 100K 推) | Qwen-2 (32K 训, 128K 推) |
| 主流选择 | ✅ | ✅ (各占一半) |

**结论**: 两条路线都成功, 选择取决于**训练算力预算**。

### 25.7 权衡 7: 通用性 vs 任务特化

| | 通用 PE (RoPE, Sinusoidal) | 任务特化 PE (CoPE) |
|:---|:---|:---|
| 适用场景 | 所有 NLP | 特定结构 (代码缩进、对话轮次) |
| 工业价值 | 高 | 中 (需要定制) |
| 灵活性 | 中 | 高 |

**结论**: 通用 PE 仍是主流, 任务特化 PE 是前沿研究方向。

### 25.8 综合打分

| 方案 | 相对性 | 外推性 | 实现复杂度 | 多任务 | 工业采用 |
|:---|:---:|:---:|:---:|:---:|:---:|
| Sinusoidal | 弱 | 中 | 低 | 强 | ❌ |
| Learned | 无 | 差 | 低 | 强 | ❌ |
| T5 Bias | 强 | 好 | 中 | 中 | ❌ |
| **RoPE** | 强 | 好 | 中 | 强 | ✅ |
| ALiBi | 强 | 极好 | 低 | 中 | ✅ (BLOOM) |
| xPos | 强 | 更好 | 高 | 强 | ❌ |
| CoPE | 强 | 中 | 高 | 弱 | ❌ |

### 25.9 一句话总结

> **RoPE 在 7 个维度上几乎都是最优或接近最优**, 这就是它一统江湖的根本原因。**LLM 时代 = RoPE 时代**。

## 26. 手撕代码: 从零实现完整 LLaMA 风格 Attention (含 RoPE + KV Cache)

```python
"""完整 LLaMA 风格 Multi-Head Self-Attention with RoPE + KV Cache
   兼容 Hugging Face 接口, 可直接替换 modeling_llama.py 中的 LlamaAttention
"""
import torch
import torch.nn as nn
import torch.nn.functional as F
import math
from typing import Optional, Tuple


def precompute_rope_cache(dim: int, max_seq_len: int, base: float = 10000.0,
                          device: Optional[torch.device] = None,
                          dtype: torch.dtype = torch.float32) -> Tuple[torch.Tensor, torch.Tensor]:
    """预计算 RoPE 的 cos/sin cache
    Returns:
        cos, sin: (max_seq_len, dim)
    """
    inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2, device=device, dtype=dtype) / dim))
    t = torch.arange(max_seq_len, device=device, dtype=dtype)
    freqs = torch.outer(t, inv_freq)  # (max_seq_len, dim/2)
    cos = freqs.cos().repeat_interleave(2, dim=-1)  # (max_seq_len, dim)
    sin = freqs.sin().repeat_interleave(2, dim=-1)
    return cos, sin


def rotate_half(x: torch.Tensor) -> torch.Tensor:
    """把 [x_0, x_1, ..., x_{d-1}] 变成 [-x_{d/2}, ..., -x_{d-1}, x_0, ..., x_{d/2-1}]
    等价于乘以 [[0, -1], [1, 0]] 块对角矩阵
    """
    d_half = x.shape[-1] // 2
    x1 = x[..., :d_half]
    x2 = x[..., d_half:]
    return torch.cat([-x2, x1], dim=-1)


def apply_rope(q: torch.Tensor, k: torch.Tensor,
               cos: torch.Tensor, sin: torch.Tensor,
               position_ids: torch.Tensor) -> Tuple[torch.Tensor, torch.Tensor]:
    """对 q, k 应用 RoPE
    Args:
        q: (B, H, T_q, D)
        k: (B, H, T_k, D)
        cos, sin: (max_seq_len, D)
        position_ids: (B, T_q) or (T_q,)
    Returns:
        q_rot, k_rot: same shape as input
    """
    if position_ids.dim() == 1:
        position_ids = position_ids.unsqueeze(0)
    # 取对应位置的 cos/sin: (B, T, D)
    cos = cos[position_ids].unsqueeze(1)  # (B, 1, T, D)
    sin = sin[position_ids].unsqueeze(1)
    q_rot = (q * cos) + (rotate_half(q) * sin)
    k_rot = (k * cos) + (rotate_half(k) * sin)
    return q_rot, k_rot


class LlamaAttention(nn.Module):
    """完整 LLaMA Attention with RoPE + GQA + KV Cache"""
    def __init__(self, d_model: int = 4096, n_heads: int = 32, n_kv_heads: Optional[int] = None,
                 max_seq_len: int = 8192, rope_base: float = 10000.0, dropout: float = 0.0):
        super().__init__()
        self.d_model = d_model
        self.n_heads = n_heads
        self.n_kv_heads = n_kv_heads or n_heads  # 默认 MHA, 可设 GQA
        self.head_dim = d_model // n_heads
        assert self.n_heads % self.n_kv_heads == 0, "n_heads 必须能被 n_kv_heads 整除"
        self.n_rep = self.n_heads // self.n_kv_heads  # GQA 重复次数

        # Q/K/V/O 投影 (无 bias)
        self.q_proj = nn.Linear(d_model, n_heads * self.head_dim, bias=False)
        self.k_proj = nn.Linear(d_model, n_kv_heads * self.head_dim, bias=False)
        self.v_proj = nn.Linear(d_model, n_kv_heads * self.head_dim, bias=False)
        self.o_proj = nn.Linear(n_heads * self.head_dim, d_model, bias=False)
        self.attn_dropout = nn.Dropout(dropout)
        self.resid_dropout = nn.Dropout(dropout)

        # RoPE cache (注册为 buffer, 跟随模型移动到 GPU)
        cos, sin = precompute_rope_cache(self.head_dim, max_seq_len, rope_base)
        self.register_buffer("cos_cache", cos, persistent=False)
        self.register_buffer("sin_cache", sin, persistent=False)
        self.max_seq_len = max_seq_len

    def _repeat_kv(self, x: torch.Tensor) -> torch.Tensor:
        """GQA: 重复 KV 到与 Q 相同的 head 数"""
        if self.n_rep == 1:
            return x
        B, H_kv, T, D = x.shape
        x = x[:, :, None, :, :].expand(B, H_kv, self.n_rep, T, D)
        return x.reshape(B, H_kv * self.n_rep, T, D)

    def forward(self, hidden_states: torch.Tensor,
                attention_mask: Optional[torch.Tensor] = None,
                position_ids: Optional[torch.Tensor] = None,
                past_kv: Optional[Tuple[torch.Tensor, torch.Tensor]] = None,
                use_cache: bool = False) -> Tuple[torch.Tensor, Optional[Tuple[torch.Tensor, torch.Tensor]]]:
        B, T, _ = hidden_states.shape

        # 投影
        q = self.q_proj(hidden_states).view(B, T, self.n_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(hidden_states).view(B, T, self.n_kv_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(hidden_states).view(B, T, self.n_kv_heads, self.head_dim).transpose(1, 2)

        # 位置 ID
        if position_ids is None:
            past_len = past_kv[0].shape[2] if past_kv is not None else 0
            position_ids = torch.arange(past_len, past_len + T, device=hidden_states.device).unsqueeze(0)

        # 动态扩展 RoPE cache (如果需要)
        max_pos = position_ids.max().item() + 1
        if max_pos > self.cos_cache.shape[0]:
            new_cos, new_sin = precompute_rope_cache(self.head_dim, max_pos * 2,
                                                     device=self.cos_cache.device)
            self.cos_cache = new_cos
            self.sin_cache = new_sin
            self.max_seq_len = max_pos * 2

        # 应用 RoPE
        q, k = apply_rope(q, k, self.cos_cache, self.sin_cache, position_ids)

        # KV Cache
        if past_kv is not None:
            past_k, past_v = past_kv
            k = torch.cat([past_k, k], dim=2)
            v = torch.cat([past_v, v], dim=2)
        new_kv = (k, v) if use_cache else None

        # GQA: 重复 KV
        k = self._repeat_kv(k)
        v = self._repeat_kv(v)

        # Attention
        scale = 1.0 / math.sqrt(self.head_dim)
        attn_weights = torch.matmul(q, k.transpose(-2, -1)) * scale

        if attention_mask is not None:
            attn_weights = attn_weights + attention_mask

        attn_weights = F.softmax(attn_weights, dim=-1, dtype=torch.float32).to(q.dtype)
        attn_weights = self.attn_dropout(attn_weights)

        attn_output = torch.matmul(attn_weights, v)
        attn_output = attn_output.transpose(1, 2).contiguous().reshape(B, T, -1)
        attn_output = self.o_proj(attn_output)
        attn_output = self.resid_dropout(attn_output)

        return attn_output, new_kv


def build_causal_mask(seq_len: int, past_len: int = 0,
                      device: Optional[torch.device] = None,
                      dtype: torch.dtype = torch.float32) -> torch.Tensor:
    """构造因果 mask, 形状 (1, 1, T, past_len + T)
    返回 additive mask: 0 表示保留, -inf 表示 mask
    """
    T = seq_len
    total_len = past_len + T
    # 上三角 -inf
    mask = torch.full((T, total_len), float("-inf"), device=device, dtype=dtype)
    mask = torch.triu(mask, diagonal=past_len + 1)
    return mask[None, None, :, :]


def demo_inference():
    """演示 KV Cache 推理"""
    print("=" * 60)
    print("Demo: LLaMA Attention with RoPE + KV Cache")
    print("=" * 60)

    torch.manual_seed(42)
    model = LlamaAttention(d_model=512, n_heads=8, n_kv_heads=4,  # GQA
                           max_seq_len=1024, rope_base=10000.0).cuda()
    print(f"Model params: {sum(p.numel() for p in model.parameters()) / 1e3:.1f}K")

    # Prefill: 处理 64 个 prompt tokens
    prompt = torch.randn(1, 64, 512, device="cuda")
    mask = build_causal_mask(64, past_len=0, device="cuda")
    out, past_kv = model(prompt, attention_mask=mask, use_cache=True)
    print(f"Prefill: input {prompt.shape} → output {out.shape}, KV cache: {past_kv[0].shape}")

    # Decode: 逐步生成 16 个 token
    next_token = torch.randn(1, 1, 512, device="cuda")
    generated = []
    for step in range(16):
        mask = build_causal_mask(1, past_len=past_kv[0].shape[2], device="cuda")
        out, past_kv = model(next_token, attention_mask=mask,
                              past_kv=past_kv, use_cache=True)
        # 简化: 直接把输出当作下一个 token
        next_token = out.detach()
        generated.append(out.norm().item())

    print(f"Generated 16 tokens, KV cache shape: {past_kv[0].shape}")
    print(f"Output norms: {[f'{v:.3f}' for v in generated[:8]]}...")
    print("✓ 推理演示成功, RoPE + KV Cache 协同工作")


if __name__ == "__main__":
    if torch.cuda.is_available():
        demo_inference()
    else:
        print("CUDA 不可用, 跳过 demo")
```

## 27. RoPE 数学的严格证明

### 27.1 引理: 旋转矩阵是正交的

$$
R_m = \begin{pmatrix} \cos m\theta & -\sin m\theta \\ \sin m\theta & \cos m\theta \end{pmatrix}
$$

**证明**:
$$
R_m^\top R_m = \begin{pmatrix} \cos m\theta & \sin m\theta \\ -\sin m\theta & \cos m\theta \end{pmatrix} \begin{pmatrix} \cos m\theta & -\sin m\theta \\ \sin m\theta & \cos m\theta \end{pmatrix}
$$

逐元素计算:
- $(1,1)$: $\cos^2 + \sin^2 = 1$ ✓
- $(1,2)$: $-\cos\sin + \sin\cos = 0$ ✓
- $(2,1)$: $\sin\cos - \cos\sin = 0$ ✓
- $(2,2)$: $\sin^2 + \cos^2 = 1$ ✓

所以 $R_m^\top R_m = I$, 即 $R_m$ 正交, $R_m^\top = R_m^{-1}$。$\blacksquare$

### 27.2 引理: 旋转复合 $R_m^\top R_n = R_{n-m}$

**证明**:
$$
R_m^\top R_n = R_{-m} R_n = R_{n-m}
$$

最后一步用到旋转复合性质: $R_a R_b = R_{a+b}$。

直接计算验证:
$$
R_{-m} = \begin{pmatrix} \cos m\theta & \sin m\theta \\ -\sin m\theta & \cos m\theta \end{pmatrix}
$$

$$
R_{-m} R_n = \begin{pmatrix} \cos m\theta & \sin m\theta \\ -\sin m\theta & \cos m\theta \end{pmatrix} \begin{pmatrix} \cos n\theta & -\sin n\theta \\ \sin n\theta & \cos n\theta \end{pmatrix}
$$

$(1,1)$ 元素: $\cos m\theta \cos n\theta + \sin m\theta \sin n\theta = \cos(n-m)\theta$ ✓

$(1,2)$ 元素: $-\cos m\theta \sin n\theta + \sin m\theta \cos n\theta = -\sin(n-m)\theta$ ✓

$(2,1)$ 元素: $-\sin m\theta \cos n\theta + \cos m\theta \sin n\theta = \sin(n-m)\theta$ ✓

$(2,2)$ 元素: $\sin m\theta \sin n\theta + \cos m\theta \cos n\theta = \cos(n-m)\theta$ ✓

所以 $R_{-m} R_n = R_{n-m}$, 证毕。$\blacksquare$

### 27.3 定理: RoPE 的相对位置性质

**定理**: 设 $q_m = R_m q, k_n = R_n k$, 则

$$
\langle q_m, k_n \rangle = \langle q, R_{n-m} k \rangle
$$

**证明**:
$$
\langle q_m, k_n \rangle = (R_m q)^\top (R_n k) = q^\top R_m^\top R_n k = q^\top R_{n-m} k = \langle q, R_{n-m} k \rangle
$$

第三步用到引理 27.2。$\blacksquare$

**推论**: 内积只依赖**相对距离** $n - m$, 与绝对位置无关。

### 27.4 推论: 远程衰减性质

**定理**: 对单位向量 $q, k$, 内积 $\langle q, R_d k \rangle$ 随 $d = n - m$ 增大而衰减。

**证明**: 简化为二维情况 (高维是独立二维的直积)。

设 $q = (\cos\alpha, \sin\alpha)$, $k = (\cos\beta, \sin\beta)$, $R_d$ 是旋转 $d\theta$。

$$
R_d k = \begin{pmatrix} \cos(d\theta) \cos\beta - \sin(d\theta) \sin\beta \\ \sin(d\theta) \cos\beta + \cos(d\theta) \sin\beta \end{pmatrix} = \begin{pmatrix} \cos(d\theta + \beta) \\ \sin(d\theta + \beta) \end{pmatrix}
$$

$$
\langle q, R_d k \rangle = \cos\alpha \cos(d\theta + \beta) + \sin\alpha \sin(d\theta + \beta) = \cos(d\theta + \beta - \alpha)
$$

对 $q, k$ 取随机方向 (即 $\alpha, \beta$ 均匀分布), $\beta - \alpha$ 也均匀分布, 故内积的**期望**为 0, **方差**为 $1/2$。但**实际内积**的绝对值 $|\cos(d\theta + \beta - \alpha)|$:

- $d = 0$: $|\cos(\beta - \alpha)|$, 期望值 $\mathbb{E}[|\cos X|] = 2/\pi \approx 0.637$
- $d \to \infty$ (多维度混合后): 期望值 → 0

更精确地, 对 $d/2$ 个频率取平均:

$$
\bar{f}(d) = \frac{1}{d/2} \sum_{i=0}^{d/2-1} \cos(d\theta_i)
$$

$\theta_i = 1/10000^{2i/d}$ 跨越 4 个数量级, 不同频率的 $\cos$ 项相位差很大, **相互抵消** → $\bar{f}(d)$ 随 $d$ 增大而衰减。$\blacksquare$

### 27.5 定理: RoPE 不改变向量模长

$$
\|R_m q\| = \|q\|
$$

**证明**: $R_m$ 是正交矩阵, 保持欧氏范数不变:

$$
\|R_m q\|^2 = (R_m q)^\top (R_m q) = q^\top R_m^\top R_m q = q^\top I q = \|q\|^2
$$

$\blacksquare$

**意义**: RoPE 不会"放大"或"缩小"q, k, 注意力分数的尺度稳定。

### 27.6 推论: 多头注意力的独立性

每个 head 独立应用 RoPE, 不同 head 可以有不同 $\theta_i$ 序列。但实践中**所有 head 共享同一组 $\theta_i$**, 只通过不同的 $W_Q, W_K$ 学到不同的语义。

**例外**: 部分模型 (PaLM) 给不同 head 设不同的 $\theta_{\max}$, 但不常见。

### 27.7 一句话总结

> RoPE 的数学核心 = **正交矩阵 + 旋转复合**。两个引理 (正交性、复合性) 推导出**相对位置性质**, 再加上**多频率混合**得到**远程衰减**。

## 28. 实战调参经验 (Tuning Guide)

### 28.1 训练时的 PE 选择

| 场景 | 推荐方案 | 理由 |
|:---|:---|:---|
| 通用 LLM 训练 (< 8K) | **RoPE, base=10000** | LLaMA 标配, 稳定 |
| 长文训练 (8K ~ 32K) | **RoPE, base=100000+** | LLaMA-3 风格, 提升低频 |
| 超长文训练 (>32K) | **RoPE + base=500000 + 渐进式** | Qwen-2, LLaMA-3 |
| 资源极少, 快速实验 | **ALiBi** | 极简, 零调参 |
| 多语言 / 代码混合 | **RoPE** | 通用性最强 |
| 位置敏感任务 (算术、复制) | **RoPE + 数据增广** | 多位置模式训练 |

### 28.2 base 怎么调?

经验公式:
$$
\text{base}_{\text{new}} = 10000 \cdot \alpha^{\log_2(L_{\text{train}} / 4096)}
$$

其中 $\alpha \approx 16$ (经验值)。

| 训练长度 $L$ | 推荐 base |
|:---:|:---:|
| 512 | 10000 |
| 1024 | 10000 |
| 2048 | 10000 |
| 4096 | 10000 |
| 8192 | 31623 ($\approx 10000 \cdot \sqrt{8}$) |
| 16384 | 100000 |
| 32768 | 316228 |
| 65536 | 1000000 |
| 131072 | 3162277 |

**LLaMA-3 实际选择**: 8K 训练 + base=500000, 对应上表中接近 65536 的位置。

### 28.3 推理时遇到的问题及解法

| 问题 | 症状 | 解法 |
|:---|:---|:---|
| 位置 0 输出乱码 | 模型在序列开头胡说 | 检查 position_ids 是否从 0 开始 |
| 长序列重复 | 32K 之后模型开始复读 | 应用 YaRN 或外推技巧 |
| 远距离信息丢失 | 128K 时检索不到开头信息 | 改 base + 微调 |
| 中等距离混乱 | 4K ~ 8K 之间质量下降 | NTK-aware 缩放 |
| 数值 NaN | fp16 下大 $m\theta$ 溢出 | RoPE 预计算用 fp32 |

### 28.4 与其他组件的协同

- **RMSNorm**: 放在 RoPE 之前 (LLaMA) 或之后 (GPT-NeoX) 都可以, 推荐前者。
- **GQA (Grouped Query Attention)**: 与 RoPE 兼容, KV Cache 共享但每个 head 独立 RoPE。
- **Flash Attention**: RoPE 融合进 kernel, 显存减少 50%。
- **Sliding Window**: RoPE 位置 ID 仍全局, 窗口只是 mask。

### 28.5 微调时的注意事项

1. **不要改 base**: 微调时 base 必须与预训练一致, 否则 RoPE 相位错乱。
2. **渐进式扩展长度**: 直接在长序列上微调会破坏短序列性能, 推荐渐进 4K → 8K → 16K。
3. **长文档 SFT 数据**: 微调时必须用**真实长文档**, 不用随机拼接短文 (后者会让模型学到错误的"段落边界"模式)。
4. **保留位置多样性**: 训练数据中**短、中、长**样本都要有, 避免只在 4K 上微调导致远距离泛化差。

### 28.6 一句话总结

> **base 选择 + 渐进训练 + 外推方案** = 长文 LLM 的三大调参支柱。**LLaMA-3 = 高 base + 渐进 + 微调** 的范式已被业界广泛复制。

## 29. 总结: 位置编码的演化史与未来

### 29.1 时间线

```text
2017  Transformer (Sinusoidal PE)
      ↓ 简单但不"相对", 工程上少用
2018  BERT/GPT-1/2 (Learned PE)
      ↓ 简单但不能外推, 限制长度
2020  T5 (Relative Bias)
      ↓ 显式相对位置, 但 bias 表离散
2021  RoFormer/RoPE (RoPE)
      ↓ 数学优雅 + 外推 + 主流采用 ✅
2022  ALiBi (Linear Bias)
      ↓ 极简单 + 极外推, BLOOM 采用
2023  PI / NTK / YaRN
      ↓ RoPE 外推三大救法
2024  CoPE / NoPE
      ↓ 前沿探索, 工业未广泛采用
2024  LLaMA-3 (高 base + 长训练)
      ↓ 当前最优实践
```

### 29.2 现状 (2026)

| 维度 | 主流方案 |
|:---|:---|
| **通用 LLM** | RoPE (base=10000~500000) |
| **超长文 LLM** | RoPE + YaRN, 或 LLaMA-3 风格高 base |
| **资源受限场景** | ALiBi (BLOOM 风格) |
| **实验研究** | CoPE / NoPE |
| **代码 LLM** | RoPE (无特化) |
| **多模态** | RoPE + 2D 位置编码 (类比) |

### 29.3 未来方向

1. **3D / 视频位置编码**: 当前 RoPE 扩展到 3D 空间 (图像 + 时间) 是研究热点。
2. **动态位置**: CoPE 类根据上下文动态计算位置。
3. **任务自适应 PE**: 根据任务 (对话、代码、数学) 自动选 PE 方案。
4. **混合 PE**: 短距离用 RoPE, 长距离用 ALiBi (实验阶段)。
5. **无 PE 探索**: NoPE 表明短序列可以无 PE, 但长序列仍需 PE。

### 29.4 终极判断

> **RoPE 不会很快被取代**。原因:
> 1. 已被 LLaMA / Qwen / Mistral / GLM 等主流模型验证。
> 2. 数学性质优美 (相对位置 + 远程衰减)。
> 3. 工程友好 (预计算 + Flash 融合)。
> 4. 外推方案成熟 (PI / NTK / YaRN)。
> 5. 训练稳定, 收敛快。
>
> **未来 5 年, RoPE 仍是 LLM PE 的事实标准**。

### 110. Positional Encoding (Sinusoidal / Learned / RoPE / ALiBi) - 优化视角 视角

**核心议题**: 本节从优化视角视角切入,系统展开 "Positional Encoding (Sinusoidal / Learned / RoPE / ALiBi)" 的相关讨论。

**1. 背景与动机**

任何技术或方法的出现都不是孤立的,而是回应特定历史条件下的具体问题。"Positional Encoding (Sinusoidal / Learned / RoPE / ALiBi)" 的发展也不例外。要理解它,必须回到它出现的那个时间点,看清它要解决的真实问题是什么。当时的主流方案有哪些不足? 它的提出填补了哪些空白? 这些问题的回答,决定了我们今天该如何使用它。

从知识论角度看,**技术演进是问题驱动的**——不是先有方案再找问题,而是先有问题再有方案。这个观察可以帮助我们避免"拿着锤子找钉子"的陷阱,真正把方法用对地方。

历史维度上,我们看到三个规律:

1. **从特殊到一般**: 早期方法往往针对特定场景,后期抽象出通用框架。学习的认知规律也是先掌握具体案例,再抽象出一般模式。这种"自下而上"的学习方式,在机器学习模型的设计里反复出现。

2. **从手工到自动**: 经验规则逐步被数据驱动的方法取代。在早期,很多 AI 系统依赖人工编写的规则。统计学习方法的崛起让"从数据中学习"成为可能。深度学习进一步把特征工程也自动化了。今天的大模型时代,我们看到端到端学习从感知扩展到了推理与生成。

3. **从局部到全局**: 关注单个组件,演进到关注整个系统。早期模型评估只关注单点指标,现在更关注全链路的协同效应。这种"系统视角"的转变,与软件工程从单体架构到微服务架构的演进高度相似。

**2. 优化视角视角的展开**

从优化视角视角出发,我们可以把 "Positional Encoding (Sinusoidal / Learned / RoPE / ALiBi)" 拆解为以下几个层次:

**第一层: 概念层** —— 这是最抽象的层次,定义了我们要研究的对象是什么。例如,"推荐系统"在概念层是一个"为用户从物品集合中筛选合适物品"的问题。这个层次的特点是清晰、稳定、不易变化。一个好的概念定义应该具备几个特征:可操作性、可测量性、可扩展性。

**第二层: 模型层** —— 把概念实例化为数学模型。同一概念可以有不同的模型化方式,例如"推荐系统"可以是协同过滤、矩阵分解、深度学习等。模型的选择决定了后续算法的空间,也决定了能利用的归纳偏置(比如序列模型擅长捕捉时序依赖,图模型擅长建模关系结构)。模型选型是工程实践中最重要的决策之一。

**第三层: 算法层** —— 在选定模型下,具体的求解方法。这一层最活跃,新算法层出不穷。同一模型往往有多种算法,各有优劣。例如同样是优化深度网络,可以选择 SGD、Adam、L-BFGS 等不同算法。算法的选择要考虑收敛速度、数值稳定性、计算成本等多个维度。

**第四层: 工程层** —— 算法落地的实现细节,包括数据流水线、训练框架、推理优化、监控告警等。工程层是研究到生产的桥梁,决定了一个方法能否真正用起来。一个在论文里表现很好的算法,如果不能高效实现、不能稳定运行、不能快速迭代,就没有实际价值。工程能力是把研究转化为生产力的关键。

**第五层: 业务层** —— 在具体业务场景中的表现。同一技术在不同业务里效果差异巨大,因为业务目标、数据分布、用户行为都有差异。从业务视角看技术,我们必须回答几个问题:这个技术解决了什么业务问题?投入产出比如何?长期可持续吗?技术评估必须与业务目标对齐,否则容易陷入"技术自嗨"的陷阱。

**3. 数学形式化(简洁版)**

虽然我们强调优化视角视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

偏差-方差分解是另一个核心框架:误差可以分解为模型偏差(欠拟合)、方差(过拟合)和不可约噪声三部分。理解这个分解有助于诊断模型表现、选择合适复杂度。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

信息论为"Positional Encoding (Sinusoidal / Learned / RoPE / ALiBi)" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。
