# 第06章-02-旋转位置编码

## 6.2 RoPE (旋转位置编码) 深入

---

## 1. 内容介绍

**RoPE (Rotary Position Embedding)** 是 2021 年提出的位置编码方案, 通过**旋转矩阵**注入相对位置信息. LLaMA, Mistral, Qwen, GLM, DeepSeek 等几乎所有主流 LLM 都用 RoPE.

详见 [5.3 位置编码](../第05章-Transformer架构/第05章-03-位置编码.md) 基础部分. 本节深入实现 + 长度外推.

---

## 2. 为什么这么做

**问题**:
- Sinusoidal: 外推性有限
- Learned (BERT): 完全不能外推, 训练多长就只能处理多长
- LLM 时代: 训练 4K, 推理要 32K/128K, 必须有外推性
- RoPE: 通过旋转, 相对位置自然, 外推性好

---

## 3. 这么做的原因 (RoPE vs 其他 PE)

| 方案 | 相对位置 | 长度外推 | 复杂度 | LLM 应用 |
|---|---|---|---|---|
| Sinusoidal | ✗ | 有限 | $O(d)$ | 原 Transformer |
| Learned | ✗ | ✗ | $O(d)$ | BERT |
| ALiBi | ✓ (线性) | ✓ | $O(1)$ | Bloom |
| **RoPE** | ✓ | ✓ | $O(d)$ | **LLaMA, Qwen, GLM, DeepSeek** |

**RoPE 的核心数学性质**:
- $q_m^T k_n = q^T R_{n-m} k$ → 注意力分数只依赖相对位置 $n - m$
- 类比: 旋转 $\to$ 复数乘法 → 相对位移
- 数学优雅, 工程友好

---

## 4. 解决了什么问题

- **长度外推**: 训练 4K, 推理 32K+
- **相对位置**: 自然捕获
- **多分辨率**: 不同频率对应不同距离

---

## 5. 意义

- LLM 时代标准 PE
- 衍生: NTK-aware scaling / YaRN / Dynamic NTK (长度外推的"补丁")

---

## 6. 公式表达

```text
RoPE (二维情况):
  R(θ) = [[cos θ, -sin θ], [sin θ, cos θ]]
  q_m = R(mθ) · q
  k_n = R(nθ) · k
  q_m^T k_n = q^T R((n-m)θ) k  ← 相对位置

RoPE (一般维度):
  对每对 (q_{2i}, q_{2i+1}) 应用 2D 旋转
  θ_i = 1 / 10000^(2i/d)

  q = (q_0, q_1, q_2, q_3, ..., q_{d-1})
  q_rot = ((q_0 cos mθ_0 - q_1 sin mθ_0), (q_0 sin mθ_0 + q_1 cos mθ_0),
            (q_2 cos mθ_1 - q_3 sin mθ_1), (q_2 sin mθ_1 + q_3 cos mθ_1), ...)
```

**长度外推 - NTK-aware scaling** (bloc97):
- 缩放 base: 10000 → 10000 * α
- $\alpha = s^{d / (d-2)}$, s 是目标长度 / 训练长度
- 等价于把高频维度的波长"拉长"

**长度外推 - YaRN**:
- 组合 NTK-aware + 注意力温度缩放
- LLaMA-2 32K, Code Llama 100K 都用

## 9. 答案

### 答案 1: RoPE 多维完整实现

```python
import numpy as np

def apply_rope(x, positions, base=10000):
    """
    RoPE 完整实现
    x: (B, n, d), d 必须偶数
    positions: (B, n)
    返回: 旋转后的 x
    """
    B, n, d = x.shape
    assert d % 2 == 0, "d must be even"

    # 1. 频率: θ_i = 1 / base^(2i/d), 对每对 (2i, 2i+1)
    half_d = d // 2
    freqs = 1.0 / (base ** (np.arange(0, half_d, 2) * 2 / d))  # (half_d/2,)

    # 2. 角度: m * θ_i, 形状 (B, n, half_d/2)
    angles = positions[..., None] * freqs  # (B, n, half_d/2)

    # 3. cos, sin: 复制, 让每对 (2i, 2i+1) 用同一个频率
    cos = np.cos(angles).repeat(2, axis=-1)  # (B, n, d/2)
    sin = np.sin(angles).repeat(2, axis=-1)

    # 4. 应用旋转: x_rot = x * cos + rotate_half(x) * sin
    # rotate_half: 把 (x_0, x_1, x_2, x_3) 变成 (-x_1, x_0, -x_3, x_2)
    def rotate_half(x):
        # 拆成 (..., d/2, 2), 调换, 符号
        x_pairs = x.reshape(*x.shape[:-1], -1, 2)
        rotated = np.stack([-x_pairs[..., 1], x_pairs[..., 0]], axis=-1)
        return rotated.reshape(*x.shape)

    return x * cos + rotate_half(x) * sin
```

### 答案 2: NTK-aware scaling

```python
def apply_rope_with_ntk(x, positions, base=10000, scaling_factor=4.0):
    """
    NTK-aware scaling: base → base * α, α = s^(d/(d-2))
    """
    d = x.shape[-1]
    # NTK 缩放因子
    alpha = scaling_factor ** (d / (d - 2))
    new_base = base * alpha
    return apply_rope(x, positions, base=new_base)
```

**为什么这样?**
- RoPE 频率 $1 / 10000^{2i/d}$ 中, 高 $i$ (高频) 对应短距离, 低 $i$ (低频) 对应长距离
- 把 base 放大, 等价于把高频的"周期"拉长
- 短距离 (高频) 的相对编码被拉长, 长距离 (低频) 几乎不变
- 训练时见过的短距离模式, 推理时能匹配更长的相对位置

### 答案 3: LLaMA 完整 Attention

```python
class LlamaAttentionWithRoPE:
    """LLaMA 风格: RoPE + GQA + Causal Mask + SwiGLU"""
    def __init__(self, d_model, n_q_heads, n_kv_heads):
        self.d_model = d_model
        self.n_q = n_q_heads
        self.n_kv = n_kv_heads
        self.n_groups = n_q_heads // n_kv_heads
        self.d_k = d_model // n_q_heads

        self.W_Q = np.random.randn(d_model, d_model) * 0.02
        self.W_K = np.random.randn(d_model, n_kv_heads * self.d_k) * 0.02
        self.W_V = np.random.randn(d_model, n_kv_heads * self.d_k) * 0.02
        self.W_O = np.random.randn(d_model, d_model) * 0.02

    def forward(self, x, start_pos=0):
        """
        x: (B, n, d_model)
        start_pos: 推理时 KV cache 的起始位置
        """
        B, n, d = x.shape

        Q = x @ self.W_Q
        K = x @ self.W_K
        V = x @ self.W_V

        # 多头拆分
        Q = Q.reshape(B, n, self.n_q, self.d_k).transpose(0, 2, 1, 3)  # (B, h, n, d_k)
        K = K.reshape(B, n, self.n_kv, self.d_k).transpose(0, 2, 1, 3)
        V = V.reshape(B, n, self.n_kv, self.d_k).transpose(0, 2, 1, 3)

        # GQA: K/V 重复
        K = np.repeat(K, self.n_groups, axis=1)
        V = np.repeat(V, self.n_groups, axis=1)

        # RoPE (关键!)
        positions = np.arange(start_pos, start_pos + n)[None, :]  # (1, n)
        Q = apply_rope(Q, positions)
        K = apply_rope(K, positions)

        # 因果 mask
        scores = Q @ K.transpose(0, 1, 3, 2) / np.sqrt(self.d_k)
        mask = np.triu(np.ones((n, n)), k=1).astype(bool)
        scores = scores + mask * (-1e9)

        attn = np.exp(scores - scores.max(axis=-1, keepdims=True))
        attn = attn / attn.sum(axis=-1, keepdims=True)
        out = (attn @ V).transpose(0, 2, 1, 3).reshape(B, n, d)
        return out @ self.W_O
```

## 10. RoPE 数学推导 (完整版)

> 本节目标:从相对位置编码的"目标方程"出发,一步一步推导出 RoPE 旋转矩阵的封闭形式。

### 10.1 目标方程:相对位置编码的内禀要求

位置编码的**核心需求**: 给定 query 向量 $\mathbf{q}$、key 向量 $\mathbf{k}$、以及它们在序列中的位置 $m$ 和 $n$,我们希望注意力分数 $\langle f_q(\mathbf{q}, m), f_k(\mathbf{k}, n) \rangle$ **仅依赖于相对位置 $n - m$**,而非绝对位置 $m, n$。

设存在函数 $g$ 使得:

$$\langle f_q(\mathbf{q}, m), f_k(\mathbf{k}, n) \rangle = g(\mathbf{q}, \mathbf{k}, n - m)$$

RoPE 论文 (RoFormer, Su et al. 2021) 提出**一族简单解**:
- $f_q(\mathbf{q}, m) = R_m \mathbf{q}$
- $f_k(\mathbf{k}, n) = R_n \mathbf{k}$
- 其中 $R_m$ 是与位置 $m$ 相关的正交矩阵(旋转矩阵)
- 满足 $\langle R_m \mathbf{q}, R_n \mathbf{k} \rangle = \mathbf{q}^T R_{n-m} \mathbf{k}$

由正交性 $R_m^T R_n = R_n^T R_m$ 可得 $R_m^T R_n = R_{n-m}$,这正是相对位置编码的代数表达。

### 10.2 二维情形的推导

考虑二维向量 $\mathbf{q} = (q_0, q_1)$,寻找形如:

$$f_q(\mathbf{q}, m) = R(m\theta) \mathbf{q} = \begin{pmatrix} \cos m\theta & -\sin m\theta \\ \sin m\theta & \cos m\theta \end{pmatrix} \begin{pmatrix} q_0 \\ q_1 \end{pmatrix}$$

验证相对位置性质:

$$
\begin{aligned}
\langle f_q(\mathbf{q}, m), f_k(\mathbf{k}, n) \rangle &= (R(m\theta)\mathbf{q})^T R(n\theta) \mathbf{k} \\
&= \mathbf{q}^T R(m\theta)^T R(n\theta) \mathbf{k} \\
&= \mathbf{q}^T R((n-m)\theta) \mathbf{k} \quad \text{(旋转矩阵相乘)} \\
&= g(\mathbf{q}, \mathbf{k}, n-m) \quad \blacksquare
\end{aligned}
$$

二维情形的关键观察:**二维平面上的旋转天然满足相对位置编码**。

### 10.3 复数视角 (直观理解)

把二维向量视为复数 $\mathbf{q} = q_0 + i q_1$,旋转等价于**乘以单位复数**:

$$f_q(\mathbf{q}, m) = \mathbf{q} \cdot e^{i m \theta}$$

复数乘法的代数性质:

$$\overline{f_q(\mathbf{q}, m)} \cdot f_k(\mathbf{k}, n) = \overline{\mathbf{q}} \cdot \overline{e^{i m \theta}} \cdot \mathbf{k} \cdot e^{i n \theta} = \overline{\mathbf{q}} \mathbf{k} \cdot e^{i (n-m) \theta}$$

注意:**复数视角对应内积的实部**,即 $\langle \mathbf{q}, \mathbf{k} \rangle = \text{Re}(\overline{\mathbf{q}} \mathbf{k})$。所以相对位置编码在复数乘法下**自然涌现**。

### 10.4 推广到高维:分块独立旋转

$d$ 维(偶数)向量无法整体旋转(高维旋转不止依赖单一角度),但可**分块独立旋转**:

$$\mathbf{q} = (q_0, q_1, q_2, q_3, \ldots, q_{d-2}, q_{d-1})$$

把每对 $(q_{2i}, q_{2i+1})$ 视作独立的二维平面,在该平面内旋转 $\theta_i$:

$$R_m = \text{diag}\left( R(m\theta_0), R(m\theta_1), \ldots, R(m\theta_{d/2 - 1}) \right)$$

其中 $\theta_i$ 是第 $i$ 个旋转平面对应的基频。

### 10.5 频率的选择

为什么选 $\theta_i = b^{-2i/d}$(或等价地 $\theta_i = 10000^{-2i/d}$)?

**类比 Sinusoidal PE**: 原 Transformer 用

$$PE(pos, 2i) = \sin(pos / 10000^{2i/d})$$

其频率从 $\theta_0 = 1$ 到 $\theta_{d/2-1} = 10000^{-(d-2)/d}$ 跨越 4 个数量级。RoPE 选择**同样的频率谱**,以保证:
- 高频维度 ($\theta_i$ 大) 编码**短距离**位置(0~100 tokens)
- 低频维度 ($\theta_i$ 小) 编码**长距离**位置(>1000 tokens)
- 不同频率组合形成**多分辨率**位置表示

数学表达:

$$\theta_i = b^{-2i/d}, \quad b = 10000, \quad i = 0, 1, \ldots, d/2 - 1$$

**注意**: $\theta_i$ 指数是 $2i/d$ 而非 $i/d$,因为每对 $(2i, 2i+1)$ 共享同一个 $\theta_i$。

### 10.6 完整推导链 (从目标到公式)

**步骤 1**: 目标 → 找到 $f_q, f_k$ 使 $\langle f_q(\mathbf{q}, m), f_k(\mathbf{k}, n) \rangle = g(\mathbf{q}, \mathbf{k}, n-m)$。

**步骤 2**: 取 $f_q(\mathbf{q}, m) = R_m \mathbf{q}, f_k(\mathbf{k}, n) = R_n \mathbf{k}$,则要求 $R_m^T R_n = R_{n-m}$。

**步骤 3**: 二维情形取 $R_m = R(m\theta)$ (旋转矩阵),直接验证成立。

**步骤 4**: 高维分块,每块独立旋转,$\theta_i = b^{-2i/d}$ 给出多分辨率。

**步骤 5**: 工程实现用「复数乘法」或「实数坐标旋转」。

### 10.7 显式公式展开

对 $d$ 维向量 $\mathbf{q} = (q_0, q_1, \ldots, q_{d-1})$,位置 $m$:

$$
f_q(\mathbf{q}, m)_{2i} = q_{2i} \cos(m\theta_i) - q_{2i+1} \sin(m\theta_i)
$$

$$
f_q(\mathbf{q}, m)_{2i+1} = q_{2i} \sin(m\theta_i) + q_{2i+1} \cos(m\theta_i)
$$

其中 $\theta_i = 10000^{-2i/d}$。

用「rotate_half」记号简洁表达:

$$\text{rotate\_half}(\mathbf{q}) = (-q_1, q_0, -q_3, q_2, -q_5, q_4, \ldots)$$

那么:

$$f_q(\mathbf{q}, m) = \mathbf{q} \odot \cos(m\Theta) + \text{rotate\_half}(\mathbf{q}) \odot \sin(m\Theta)$$

其中 $\Theta = (\theta_0, \theta_0, \theta_1, \theta_1, \ldots, \theta_{d/2-1}, \theta_{d/2-1})$。

### 10.8 完整 PyTorch 实现 (带数学注释)

```python
import torch
import torch.nn as nn

class RotaryPositionalEmbedding(nn.Module):
    """
    RoPE 完整 PyTorch 实现
    公式:
      q_rot = q * cos(mθ) + rotate_half(q) * sin(mθ)
    其中:
      θ_i = base^(-2i/d), i = 0, ..., d/2-1
    """
    def __init__(self, dim, base=10000, max_seq_len=2048):
        super().__init__()
        assert dim % 2 == 0, "dim must be even"
        self.dim = dim
        self.base = base
        self.max_seq_len = max_seq_len

        # 预计算频率 θ_i = base^(-2i/d), 形状 (dim/2,)
        inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
        self.register_buffer("inv_freq", inv_freq)

        # 预计算 cos/sin 缓存, 形状 (max_seq_len, dim)
        self._build_cache(max_seq_len)

    def _build_cache(self, max_seq_len):
        t = torch.arange(max_seq_len, dtype=torch.float32)
        # freqs: (max_seq_len, dim/2)
        freqs = torch.einsum("i,j->ij", t, self.inv_freq)
        # 拼接成 (max_seq_len, dim), 每对共享频率
        emb = torch.cat([freqs, freqs], dim=-1)
        self.register_buffer("cos_cached", emb.cos()[None, None, :, :], persistent=False)
        self.register_buffer("sin_cached", emb.sin()[None, None, :, :], persistent=False)

    @staticmethod
    def rotate_half(x):
        """把 (..., dim) 拆成 (..., dim/2, 2), 旋转 90 度"""
        x1 = x[..., 0::2]   # 偶数下标
        x2 = x[..., 1::2]   # 奇数下标
        # 交错还原: (-x2, x1) 在交错位置
        rotated = torch.stack([-x2, x1], dim=-1)
        return rotated.flatten(-2)

    def forward(self, q, k, positions=None):
        """
        q, k: (B, n_heads, seq_len, head_dim)
        positions: (seq_len,) 绝对位置, 推理时用于 KV cache
        """
        if positions is None:
            seq_len = q.shape[-2]
            positions = torch.arange(seq_len, device=q.device)

        # 取对应位置的 cos/sin
        cos = self.cos_cached[:, :, positions, :]
        sin = self.sin_cached[:, :, positions, :]

        q_rot = q * cos + self.rotate_half(q) * sin
        k_rot = k * cos + self.rotate_half(k) * sin
        return q_rot, k_rot
```

### 10.9 相对位置性的形式化证明

**定理**: 对任意 query $\mathbf{q}$, key $\mathbf{k}$, 位置 $m, n$:

$$\langle \text{RoPE}(\mathbf{q}, m), \text{RoPE}(\mathbf{k}, n) \rangle = \sum_{i=0}^{d/2-1} [q_{2i} k_{2i} + q_{2i+1} k_{2i+1}] \cos((n-m)\theta_i) + [q_{2i+1} k_{2i} - q_{2i} k_{2i+1}] \sin((n-m)\theta_i)$$

**证明** (展开):

$$
\begin{aligned}
\langle R_m \mathbf{q}, R_n \mathbf{k} \rangle &= \sum_{i=0}^{d/2-1} \begin{pmatrix} q_{2i} \cos m\theta_i - q_{2i+1} \sin m\theta_i \\ q_{2i} \sin m\theta_i + q_{2i+1} \cos m\theta_i \end{pmatrix}^T \begin{pmatrix} k_{2i} \cos n\theta_i - k_{2i+1} \sin n\theta_i \\ k_{2i} \sin n\theta_i + k_{2i+1} \cos n\theta_i \end{pmatrix}
\end{aligned}
$$

对第 $i$ 块展开:

$$
\begin{aligned}
&(q_{2i} \cos m\theta_i - q_{2i+1} \sin m\theta_i)(k_{2i} \cos n\theta_i - k_{2i+1} \sin n\theta_i) \\
+& (q_{2i} \sin m\theta_i + q_{2i+1} \cos m\theta_i)(k_{2i} \sin n\theta_i + k_{2i+1} \cos n\theta_i)
\end{aligned}
$$

合并 $q_{2i} k_{2i}$ 项的系数:
$$\cos m\theta_i \cos n\theta_i + \sin m\theta_i \sin n\theta_i = \cos((n-m)\theta_i)$$

合并 $q_{2i+1} k_{2i+1}$ 项的系数: 同理 $= \cos((n-m)\theta_i)$

合并 $q_{2i+1} k_{2i}$ 项的系数: $-\sin m\theta_i \cos n\theta_i + \cos m\theta_i \sin n\theta_i = \sin((n-m)\theta_i)$

合并 $q_{2i} k_{2i+1}$ 项的系数: $-\cos m\theta_i \sin n\theta_i + \sin m\theta_i \cos n\theta_i = -\sin((n-m)\theta_i)$

加起来,得到定理中的等式 $\blacksquare$

**推论 1**: 注意力分数仅依赖 $n - m$,**绝对位置被吸收**。
**推论 2**: 当 $n = m$ 时, $\sin(0) = 0$,注意力分数退化为 $\sum_i (q_{2i} k_{2i} + q_{2i+1} k_{2i+1})$,即标准点积。
**推论 3**: $|n - m|$ 越大, $\cos((n-m)\theta_i)$ 在高频维度上**震荡得越快**,意味着这些维度对远距离 token 的贡献**趋于零**——这正是 RoPE 的「远距离衰减」性质。

## 11. RoPE 远距离衰减与频谱分析

### 11.1 现象:为什么 RoPE 自然衰减

观察 §10.9 中的相对位置公式:

$$\langle R_m \mathbf{q}, R_n \mathbf{k} \rangle = \sum_i [\text{...}] \cos((n-m)\theta_i) + [\text{...}] \sin((n-m)\theta_i)$$

每个维度对相对位置 $\Delta = n - m$ 的贡献都被 $\cos(\Delta \theta_i)$ 或 $\sin(\Delta \theta_i)$ 调制。

考虑一个简化场景: $\mathbf{q} = \mathbf{k}$(自注意力),且 $\mathbf{q}, \mathbf{k}$ 各分量独立同分布。

当 $\Delta = 0$: 所有 $\cos(0) = 1$,得到完整点积 $\sim \|\mathbf{q}\|^2$。
当 $\Delta \to \infty$: 高频 $\theta_i$ 维度上 $\cos(\Delta \theta_i)$ 快速震荡,**期望值为零**。

**数学直觉**: 高频维度对远距离位置**「互相抵消」**,只留下低频维度贡献——而低频维度数量有限(只有 $d/2$ 个),所以长距离注意力分数**自然衰减**。

### 11.2 周期与频率

第 $i$ 个旋转平面的**周期**:

$$T_i = \frac{2\pi}{\theta_i} = 2\pi \cdot b^{2i/d}$$

| 维度 $i$ | 频率 $\theta_i$ | 周期 $T_i$ |
|---|---|---|
| 0 | $1$ | $2\pi \approx 6.28$ |
| 16 | $10000^{-32/128} \approx 0.01$ | $\approx 628$ |
| 32 | $10000^{-64/128} = 1/10000$ | $\approx 62832$ |
| 63 | $10000^{-126/128} \approx 1/79000$ | $\approx 5 \times 10^5$ |

(假设 $d = 128$)

高频维度 $i = 0$ 的周期仅 $\sim 6$ tokens,意味着相对位置差 6 个 token,该维度就完成一次完整旋转——对超过 6 的距离,贡献开始震荡衰减。

低频维度 $i = 63$ 的周期达 $\sim 5 \times 10^5$ tokens,即使相对位置差 10000,该维度仍在「同一象限」内,贡献稳定。

**结论**: RoPE 自带**多尺度衰减**——短距离由高频维度编码,长距离由低频维度编码,中间的「频段过渡」平滑。

### 11.3 实验验证:注意力分数随距离变化

```python
import numpy as np
import matplotlib.pyplot as plt

def rope_attention_score(q, k, dim=128, base=10000, max_dist=200):
    """
    模拟 RoPE 下, 固定 query/key, 观察相对距离 vs 注意力分数
    """
    inv_freq = 1.0 / (base ** (np.arange(0, dim, 2) * 2 / dim))
    scores = []
    for dist in range(0, max_dist):
        # q 在位置 0, k 在位置 dist
        angles_q = 0 * inv_freq
        angles_k = dist * inv_freq
        cos_q = np.cos(angles_q); sin_q = np.sin(angles_q)
        cos_k = np.cos(angles_k); sin_k = np.sin(angles_k)

        # 旋转 q 和 k (每对共享频率)
        q_rot = np.concatenate([q[0::2]*cos_q - q[1::2]*sin_q,
                                q[0::2]*sin_q + q[1::2]*cos_q])
        k_rot = np.concatenate([k[0::2]*cos_k - k[1::2]*sin_k,
                                k[0::2]*sin_k + k[1::2]*cos_k])
        scores.append(np.dot(q_rot, k_rot))
    return np.array(scores)

# 随机 q, k
np.random.seed(42)
q = np.random.randn(128)
k = np.random.randn(128)

scores = rope_attention_score(q, k, dim=128, max_dist=200)
plt.figure(figsize=(10, 4))
plt.plot(scores)
plt.xlabel("relative distance")
plt.ylabel("attention score")
plt.title("RoPE: attention score vs relative distance")
plt.grid(True)
plt.savefig("rope_decay.png", dpi=120)
# 观察: 距离越大, 分数震荡且均值下降
```

**预期曲线**: 距离 0 处分数最大,距离增大时震荡**且震荡包络下降**。

### 11.4 与 ALiBi 的对比

**ALiBi (Attention with Linear Biases)** 用**显式线性偏置**实现远距离衰减:

$$\text{score}(m, n) = \mathbf{q}_m^T \mathbf{k}_n - r \cdot |m - n|$$

其中 $r$ 是头相关的斜率。ALiBi 的衰减是**单调、确定性**的。

**RoPE 的衰减是「隐式 + 震荡」**:
- 衰减:来自高频维度的互相抵消
- 震荡:每个维度的 $\cos(\Delta \theta_i)$ 都有周期

RoPE 在长距离上仍有非零贡献(来自低频维度),但震荡行为可能让训练不稳定——这是 §12 中 YaRN 要解决的问题。

### 11.5 频谱视角:RoPE 是 Fourier 基

从频谱角度,RoPE 等价于**对 query/key 在 Fourier 基下分解**:

$$\mathbf{q}_m = \sum_{i} \hat{q}_i e^{i m \theta_i}, \quad \mathbf{k}_n = \sum_j \hat{k}_j e^{i n \theta_j}$$

注意力分数:

$$\mathbf{q}_m^T \mathbf{k}_n = \sum_i \hat{q}_i \hat{k}_i \cos((n-m)\theta_i) + \cdots$$

**Fourier 视角**揭示:
- 高频 $\theta_i$ 大 → 短距离敏感
- 低频 $\theta_i$ 小 → 长距离敏感
- 整个频谱覆盖所有距离尺度

这与**小波分析**的 multi-resolution 思想同构。

### 11.6 衰减「不够快」会导致的问题

训练在 4K context 上,如果 RoPE 衰减不够快,模型可能在测试 32K 时:
- 远距离 token 的注意力权重仍然较高
- 模型被无关 token「分心」
- 性能下降 → 这就是为什么需要外推技术(§12)

实验观察: LLaMA-2-7B 在 32K context 时,即使不外推,**PPL 也不会灾难性爆炸**(因为 RoPE 的衰减已经在工作),但下游任务(检索、阅读理解)明显下降。

## 12. YaRN / LongRoPE / Dynamic NTK 长度外推

### 12.1 外推问题回顾

**问题**: 训练在 $L_{\text{train}} = 4096$ context,推理需要 $L_{\text{test}} = 32768$ 或 $131072$。

**直接后果**: 训练时未见的相对位置 $\Delta = n - m > L_{\text{train}}$ 出现,模型「没见过」这些位置,泛化失败。

**根本原因** (RoFormer 论文 + 后续工作):
1. 训练时每个相对距离 $\Delta$ 对应的频率响应**未充分学习**
2. 高频维度的周期可能 $< L_{\text{train}}$,但外推到 $> L_{\text{train}}$ 后,该维度进入「未训练过的相空间」
3. 低频维度虽然周期 $> L_{\text{train}}$,但权重未被优化到充分利用

### 12.2 位置插值 PI (Position Interpolation)

**Chen et al. 2023** 提出最简单的方法:

**核心思想**: 把超出训练长度的位置**线性压缩**到训练范围内。

$$\tilde{m} = m \cdot \frac{L_{\text{train}}}{L_{\text{target}}} = \frac{m}{s}$$

其中 $s = L_{\text{target}} / L_{\text{train}}$。

**等价**: 缩小所有相对距离 — $m \to m/s$, $\theta \to \theta$ 不变。

**问题**:
- 高频维度依然过密(短距离过敏感)
- 需要 ~1000 步微调才能恢复性能
- 长距离衰减「过快」,影响 retrieval 任务

### 12.3 NTK-aware Scaling (bloc97, 2023)

**核心观察**: PI 改变了所有频率的相对位置,**破坏了高频维度的短距离敏感性**。

**改进**: 只**缩放基频 $b$**,不缩放位置:

$$\theta_i^{\text{new}} = (b \cdot \alpha)^{-2i/d}, \quad \alpha = s^{d/(d-2)}$$

**直觉**: 把 base 从 10000 放大到 $10000 \cdot \alpha$,等价于把所有频率**整体压低**(高频变中频,中频变低频),从而让原本的高频维度现在编码「中距离」——训练过的模式可以继续工作。

**优势**:
- 无需微调(或仅需 ~50 步)
- 短距离性能保持良好

**劣势**:
- 中间距离性能可能下降
- 对极长距离($128K \to 1M$)仍不够

**完整实现**:

```python
def apply_ntk_rope(q, k, positions, base=10000, scaling_factor=4.0, dim=None):
    """
    NTK-aware RoPE: 缩放 base 而非位置
    """
    if dim is None:
        dim = q.shape[-1]
    # α = s^(d/(d-2)), 让低频维度变化小, 高频维度变化大
    alpha = scaling_factor ** (dim / (dim - 2))
    new_base = base * alpha

    return apply_rope(q, k, positions, base=new_base)
```

### 12.4 Dynamic NTK (emozilla, 2023)

**问题**: 训练 4K,推理时遇到 8K、16K、32K 不同长度——NTK 的 $\alpha$ 该如何选?

**Dynamic NTK 的解法**: 根据**实际序列长度**动态调整 $\alpha$:

$$\alpha(s) = s^{d/(d-2)}, \quad s = \max\left(1, \frac{\text{current\_seq\_len}}{L_{\text{train}}}\right)$$

**实现要点**:
- 推理时若 seq_len 变化,实时重新计算 cos/sin 缓存
- LLaMA 的 Hugging Face 实现默认支持

```python
class DynamicNTKRoPE:
    def __init__(self, dim, base=10000, max_seq_len=32768, training_len=4096):
        self.dim = dim
        self.base = base
        self.max_seq_len = max_seq_len
        self.training_len = training_len
        self._cache = {}

    def get_freqs(self, current_seq_len):
        if current_seq_len in self._cache:
            return self._cache[current_seq_len]
        # 动态计算 scaling factor
        scaling = max(1.0, current_seq_len / self.training_len)
        alpha = scaling ** (self.dim / (self.dim - 2))
        new_base = self.base * alpha

        inv_freq = 1.0 / (new_base ** (torch.arange(0, self.dim, 2).float() / self.dim))
        t = torch.arange(current_seq_len)
        freqs = torch.einsum("i,j->ij", t, inv_freq)
        emb = torch.cat([freqs, freqs], dim=-1)
        self._cache[current_seq_len] = emb
        return emb
```

### 12.5 YaRN (Peng et al. 2023)

**YaRN = NTK-aware + 注意力温度缩放 + 分段频率**

#### 12.5.1 三段频率策略

观察: 不同频率维度应该用**不同的外推策略**:

| 频率段 | 周期 | 策略 |
|---|---|---|
| 高频 (短距离) | $T_i < \alpha L_{\text{train}}$ | 不变 (保留短距离敏感) |
| 低频 (长距离) | $T_i > \beta L_{\text{train}}$ | 插值 (PI) |
| 中频 | $\alpha L_{\text{train}} < T_i < \beta L_{\text{train}}$ | NTK-aware |

其中 $\alpha, \beta$ 是超参,典型值 $\alpha = 1, \beta = 32$。

**数学表达**: 对每个维度 $i$,计算其「外推策略权重」$\lambda_i$:

$$\lambda_i = \begin{cases} 0 & T_i < \alpha L \\ 1 & T_i > \beta L \\ \frac{T_i - \alpha L}{\beta L - \alpha L} & \text{otherwise} \end{cases}$$

新频率:

$$\theta_i^{\text{new}} = (1 - \lambda_i) \theta_i^{\text{NTK}} + \lambda_i \theta_i^{\text{PI}}$$

#### 12.5.2 注意力温度缩放

**观察**: RoPE 在长距离上衰减不够快,导致注意力分布「过平」。YaRN 加一个**温度因子** $t$:

$$\text{Attention}(Q, K) = \text{softmax}\left(\frac{Q^T K}{t \sqrt{d}}\right)$$

其中 $t = 0.1 \ln(s) + 1$(经验公式)。

直觉: $t > 1$ 让 softmax 更「尖锐」,远距离 token 权重被压低,模型更专注于近处。

#### 12.5.3 完整 YaRN 实现

```python
class YaRNRoPE(nn.Module):
    def __init__(self, dim, base=10000,
                 training_len=4096, target_len=32768,
                 alpha=1.0, beta=32.0):
        super().__init__()
        self.dim = dim
        self.base = base
        self.training_len = training_len
        self.target_len = target_len
        self.scaling_factor = target_len / training_len
        self.alpha = alpha
        self.beta = beta

        # 注意力温度
        self.attn_scale = 0.1 * np.log(self.scaling_factor) + 1.0

        # 预计算混合频率
        self._build_freqs()

    def _build_freqs(self):
        dim = self.dim
        # 原始频率
        orig_freq = 1.0 / (self.base ** (torch.arange(0, dim, 2).float() / dim))
        # NTK 频率 (缩放 base)
        ntk_alpha = self.scaling_factor ** (dim / (dim - 2))
        ntk_freq = orig_freq / ntk_alpha
        # PI 频率 (缩放位置, 等价于把频率除以 s)
        pi_freq = orig_freq / self.scaling_factor

        # 周期
        periods = 2 * np.pi / orig_freq

        # 混合权重 lambda
        ramp = (periods - self.alpha * self.training_len) / \
               (self.beta * self.training_len - self.alpha * self.training_len)
        ramp = torch.clamp(ramp, 0, 1)

        # 高频 (ramp=0): 用 NTK; 低频 (ramp=1): 用 PI
        self.mixed_freq = (1 - ramp) * ntk_freq + ramp * pi_freq

        # 预计算缓存
        t = torch.arange(self.target_len, dtype=torch.float32)
        freqs = torch.einsum("i,j->ij", t, self.mixed_freq)
        emb = torch.cat([freqs, freqs], dim=-1)
        self.register_buffer("cos_cached", emb.cos()[None, None, :, :])
        self.register_buffer("sin_cached", emb.sin()[None, None, :, :])

    def forward(self, q, k, attn_scores):
        """
        q, k: 标准 RoPE 输入
        attn_scores: softmax 前的注意力 logits
        返回: 旋转后的 q, k 和温度缩放后的 scores
        """
        seq_len = q.shape[-2]
        cos = self.cos_cached[:, :, :seq_len, :]
        sin = self.sin_cached[:, :, :seq_len, :]

        q_rot = q * cos + self._rotate_half(q) * sin
        k_rot = k * cos + self._rotate_half(k) * sin

        # 温度缩放
        attn_scores = attn_scores / self.attn_scale

        return q_rot, k_rot, attn_scores
```

#### 12.5.4 YaRN 的实验效果

- **LLaMA-2-7B**: 训练 4K, YaRN 推到 128K,PPL 从 5.5 (4K) → 5.9 (128K),仅 +0.4
- **Code Llama**: 训练 16K, YaRN 推到 100K,HumanEval 几乎不掉点
- **微调成本**: 只需 ~400 步 vs PI 的 1000+ 步

### 12.6 LongRoPE (Ding et al. 2024, Microsoft)

**核心创新**: 不靠「解析公式」,而是**搜索**最优频率。

**算法**:
1. 在两个目标长度(如 4K 和 8K)上**演化搜索**(evolutionary search),找最优的 $\theta_i$ 缩放因子
2. 把搜索结果**插值**到任意目标长度
3. 微调 ~1000 步

**优势**:
- 比 YaRN 更灵活(每个维度的缩放因子独立)
- 在 2M context 上保持稳定 (Phi-3-mini-128K 的核心)

**劣势**:
- 搜索成本高(数 GPU-小时)
- 不同模型需要重新搜索

### 12.7 ABF (Adjusted Base Frequency, ReBase)

简单有效的方法: **直接调整 RoPE 公式**为

$$\theta_i = (b \cdot s)^{-2i/d}, \quad s = 1.0$$

不改变公式,只把 $b$ 从 10000 改到 $b \cdot s$——**最简 NTK-aware 形式**。

```python
def apply_abf_rope(q, k, positions, base=10000 * 8, dim=None):
    """ABF: 直接把 base 放大"""
    return apply_rope(q, k, positions, base=base, dim=dim)
```

Code Llama 用 ABF 实现 100K context。

### 12.9 工业选择指南

- **< 32K context, 模型不大**: NTK-aware 即可
- **32K-128K, 模型中等**: YaRN 是性价比首选
- **128K-1M, 模型关键**: LongRoPE,准备 GPU 时间
- **生产环境, 不确定长度**: Dynamic NTK (按需扩展)
- **完全免微调**: PI + LongRoPE 预训练的版本 (如 Code Llama-100K)

```python
class LlamaRotaryEmbedding(nn.Module):
    def __init__(self, dim, max_position_embeddings=2048, base=10000, ...):
        self.dim = dim
        self.max_position_embeddings = max_position_embeddings

        inv_freq = 1.0 / (self.base ** (torch.arange(0, self.dim, 2, dtype=torch.int64).float() / self.dim))
```

### 13.5 DeepSeek-V2/V3

**DeepSeek 创新**: Multi-Head Latent Attention (MLA) + Decoupled RoPE

**Decoupled RoPE**: 把 query 和 key 拆成两部分:

$$q = [q^{(\text{rope})}, q^{(\text{nope})}]$$

只有 $q^{(\text{rope})}$ 应用 RoPE,$q^{(\text{nope})}$ 不参与位置编码——可以**共享 KV cache**。

```python
class MLAWithDecoupledRoPE(nn.Module):
    def __init__(self, d_model, n_heads, kv_rank, q_rope_rank):
        # q 分两部分: rope 部分 + nope 部分
        self.q_a = nn.Linear(d_model, q_rope_rank + (d_model - q_rope_rank), bias=False)
        self.q_b_rope = nn.Linear(q_rope_rank, n_heads * q_rope_head_dim, bias=False)
        self.q_b_nope = nn.Linear(d_model - q_rope_rank, n_heads * (d_head - q_rope_head_dim), bias=False)
        # k 类似
        self.k_a = nn.Linear(d_model, kv_rank, bias=False)
        self.k_b_rope = nn.Linear(kv_rank, n_heads * q_rope_head_dim, bias=False)

    def forward(self, x, positions):
        q_a = self.q_a(x)
        q_rope = self.q_b_rope(q_a[..., :self.q_rope_rank])
        q_nope = self.q_b_nope(q_a[..., self.q_rope_rank:])
        # 只对 q_rope, k_rope 应用 RoPE
        q_rope, k_rope = self.rope(q_rope, k_rope, positions)
        # 拼接
        q = torch.cat([q_rope, q_nope], dim=-1)
        # ...
```

**优势**:
- 显著压缩 KV cache (kv_rank << d_model)
- RoPE 只作用在小维度上,计算开销低

### 13.6 GPT-NeoX / Pythia / Falcon

- **GPT-NeoX / Pythia**: RoPE, base=10000, 无特殊外推
- **Falcon**: Refined Web 训练数据, RoPE, 多 query attention (MQA)

### 13.7 实际部署注意事项

#### 13.7.1 bfloat16 的精度问题

RoPE 计算中的 $\cos, \sin$ 在大 position 时可能 < 1e-3,bfloat16 精度不足。

**解决**: 用 float32 计算 cos/sin,然后 cast 回 bfloat16:

```python
# 错误: 全 bfloat16
cos = (positions[:, None] * inv_freq[None, :]).cos()  # 可能溢出/精度差

# 正确
cos = (positions[:, None].float() * inv_freq[None, :].float()).cos().to(q.dtype)
```

#### 13.7.2 长序列显存

KV cache 中 RoPE 不占额外显存(已经包含在 K 中),但 cos/sin cache 与 seq_len 线性增长:

$$\text{cache} = 2 \times \text{seq\_len} \times \text{head\_dim} \times \text{sizeof(dtype)}$$

32K context, head_dim=128, fp16: ~16 MB per layer——可忽略。

#### 13.7.3 Flash Attention 集成

Flash Attention v2 直接支持 RoPE,无需在 HBM 中显式存储旋转后的 Q/K:

```python
# Flash Attention 2 with RoPE
flash_attn_func(q, k, v,
                causal=True,
                rotary_emb=rope_module,  # 内部应用 RoPE
                softmax_scale=1.0/torch.sqrt(head_dim))
```

#### 13.7.4 训练与推理一致性

**关键**: 训练和推理的 RoPE 参数必须**完全一致**:
- 相同的 base
- 相同的 head_dim
- 相同的频率计算方式

否则 KV cache 不能复用,或注意力模式错乱。

## 14. 进阶变体:ALiBi / CoPE / 其他位置编码

### 14.1 ALiBi (Attention with Linear Biases)

**Press et al. 2022** 提出:

$$\text{score}(m, n) = \mathbf{q}_m^T \mathbf{k}_n - r \cdot |m - n|$$

其中 $r$ 是 head-specific 斜率,通常设为 $r = 2^{-8/n_{\text{heads}} \cdot i}$。

**特点**:
- O(1) 额外参数 (只需 n_heads 个 r)
- 远距离**单调衰减**,无震荡
- BLOOM/Zephyr 使用

**对比 RoPE**:

| 性质 | ALiBi | RoPE |
|---|---|---|
| 远距离衰减 | 单调、确定 | 震荡、包络衰减 |
| 实现复杂度 | O(1) 极简 | O(d) 旋转 |
| 长度外推 | 较好 | 需外推技术 |
| 多分辨率 | 头间不同 r | 维度间不同频率 |
| 短距离性能 | 略差 | 优秀 |

### 14.2 CoPE (Contextual Position Encoding)

**Microsoft 2024** 的创新: **位置由上下文决定,而非绝对计数**。

核心: 用一个**门控函数**对每个 token 计算「位置值」:

$$p_i = \sum_{j=1}^{i} g(x_j, x_{j-1}, \ldots)$$

例如:
- 普通文本: $p_i = i$ (退化为 RoPE)
- 代码: $p_i$ 按缩进层级跳 (而非按字符)
- 对话: $p_i$ 按 turn 跳

```python
class CoPE(nn.Module):
    def __init__(self, dim, max_pos=2048):
        super().__init__()
        self.dim = dim
        self.max_pos = max_pos
        # 门控函数, 输入上下文特征, 输出位置增量
        self.gate = nn.Linear(dim, 1)

    def forward(self, x, positions):
        # positions: (B, n) 整数或浮点
        # 计算每个位置的相对偏移
        rel_pos = positions[..., None] - positions[..., None, :]
        rel_pos = rel_pos.clamp(-self.max_pos, self.max_pos)

        # 频率
        inv_freq = 1.0 / (10000 ** (torch.arange(0, self.dim, 2).float() / self.dim))
        angles = rel_pos[..., None] * inv_freq
        cos = angles.cos()
        sin = angles.sin()
        # ... 应用旋转
```

**适用场景**:
- 代码 (按缩进)
- 文档 (按章节)
- 多轮对话 (按 turn)
- 视频/语音 (按时长)

### 14.3 Position Interpolation 改进版

一些改进 PI 的工作:
- **Randomized PI**: 在训练时随机缩放位置($\alpha \sim U[0.5s, 1.5s]$)
- **YALi**: 同时缩放 embedding 和 attention
- **xPos**: 指数衰减的旋转角度

### 14.4 NoPE (No Position Encoding)

**意外发现**: 部分 Transformer 不需要显式 PE——**因果 mask + 充分训练**就够了。

$$\text{score}(m, n) = \begin{cases} \mathbf{q}_m^T \mathbf{k}_n & n \le m \\ -\infty & n > m \end{cases}$$

原因: 因果 mask 让每个 token 只能「看到之前的位置」,这本身提供了**隐式位置信息**。

**适用**:
- Decoder-only 模型, 训练足够长
- Llama-3 的某些实验
- 缺点: 推理时无位置先验,微调困难

### 14.5 3D RoPE (Video / 3D Vision)

对 3D 输入(视频、点云、3D 场景),把位置编码扩展到三维:

$$R_m^{(3D)} = \text{diag}(R(m_x \theta), R(m_y \theta), R(m_z \theta))$$


## 15. 面试题集 (精选 20 题)

### Q1: RoPE 为什么是「旋转」而不是「加法」或「乘法」?

**答**:
- **加法**(Sinusoidal / Learned PE): $\text{output} = \mathbf{x} + PE$,然后与 $\mathbf{q}, \mathbf{k}$ 计算注意力
  - 缺点: 位置信息和语义信息**耦合**,模型难以解耦
  - 外推性差
- **乘法**(ALiBi 风格): $\text{output} = \mathbf{q}^T \mathbf{k} - r|m-n|$,把位置信息作为**偏置**
  - 缺点: 远距离衰减**过强**,近处表达力不足
- **旋转**(RoPE): 用正交矩阵**变换** $\mathbf{q}, \mathbf{k}$,几何上等价于**复数乘法**
  - 优点:
    1. 天然满足相对位置编码(数学优雅)
    2. 不增加参数(用 $\cos, \sin$ 即可)
    3. 远距离「自然衰减」(高频维度互相抵消)
    4. 可外推(基频缩放)

**关键数学性质**: $R(\theta)^T R(\phi) = R(\phi - \theta)$, 旋转矩阵的差等于相对角度。

### Q2: 详细推导 $\langle R_m q, R_n k \rangle = q^T R_{n-m} k$。

**答**: 见 §10.1-§10.2。
- 二维情形: $R_m = \begin{pmatrix} \cos m\theta & -\sin m\theta \\ \sin m\theta & \cos m\theta \end{pmatrix}$
- 验证: $R_m^T R_n = \begin{pmatrix} \cos m\theta & \sin m\theta \\ -\sin m\theta & \cos m\theta \end{pmatrix} \begin{pmatrix} \cos n\theta & -\sin n\theta \\ \sin n\theta & \cos n\theta \end{pmatrix} = R((n-m)\theta)$
- 直接代入: $\langle R_m q, R_n k \rangle = (R_m q)^T (R_n k) = q^T R_m^T R_n k = q^T R_{n-m} k$ ✓

### Q3: RoPE 中 base=10000 是怎么来的?能改吗?

**答**:
- **来源**: 沿用原 Transformer 的 Sinusoidal PE 的 base (Vaswani et al. 2017)
- **物理意义**: base 越大 → 频率范围越大 → 能编码的最长周期越长
  - 最大周期 $T_{\max} = 2\pi \cdot 10000^{(d-2)/d}$
  - $d=128$: $T_{\max} \approx 500000$
- **能改吗**: 能,而且实际工程中常常改:
  - **ABF (Code Llama)**: base=1000000,训练 100K
  - **DeepSeek**: base=10000 * 1.1 ≈ 11000
  - **Qwen-2**: 训练 32K 时动态调整 base

**经验法则**: 训练长度越长,base 应该越大。

### Q4: 实现一个生产级 RoPE forward (支持 GQA + KV cache)。

```python
class ProductionRoPEAttention(nn.Module):
    def __init__(self, d_model, n_q_heads, n_kv_heads, max_seq_len=32768, base=10000):
        super().__init__()
        self.n_q = n_q_heads
        self.n_kv = n_kv_heads
        self.n_groups = n_q_heads // n_kv_heads
        self.head_dim = d_model // n_q_heads

        self.wq = nn.Linear(d_model, n_q_heads * self.head_dim, bias=False)
        self.wk = nn.Linear(d_model, n_kv_heads * self.head_dim, bias=False)
        self.wv = nn.Linear(d_model, n_kv_heads * self.head_dim, bias=False)
        self.wo = nn.Linear(n_q_heads * self.head_dim, d_model, bias=False)

        # RoPE 缓存
        inv_freq = 1.0 / (base ** (torch.arange(0, self.head_dim, 2).float() / self.head_dim))
        self.register_buffer("inv_freq", inv_freq)
        self._build_cache(max_seq_len)

    def _build_cache(self, max_seq_len):
        t = torch.arange(max_seq_len)
        freqs = torch.einsum("i,j->ij", t, self.inv_freq)
        emb = torch.cat([freqs, freqs], dim=-1)
        self.register_buffer("cos", emb.cos()[None, None, :, :], persistent=False)
        self.register_buffer("sin", emb.sin()[None, None, :, :], persistent=False)

    def forward(self, x, positions, kv_cache=None):
        B, n, _ = x.shape
        q = self.wq(x).view(B, n, self.n_q, self.head_dim).transpose(1, 2)
        k = self.wk(x).view(B, n, self.n_kv, self.head_dim).transpose(1, 2)
        v = self.wv(x).view(B, n, self.n_kv, self.head_dim).transpose(1, 2)

        # 取对应位置的 cos/sin
        cos = self.cos[:, :, positions, :].to(q.dtype)
        sin = self.sin[:, :, positions, :].to(q.dtype)

        # RoPE
        q = q * cos + self._rotate_half(q) * sin
        k = k * cos + self._rotate_half(k) * sin

        # KV cache 更新
        if kv_cache is not None:
            k = torch.cat([kv_cache[0], k], dim=2)
            v = torch.cat([kv_cache[1], v], dim=2)
            kv_cache[0] = k
            kv_cache[1] = v

        # GQA: 重复 K/V
        k = k.repeat_interleave(self.n_groups, dim=1)
        v = v.repeat_interleave(self.n_groups, dim=1)

        # Attention (用 SDPA 自动选择最优 kernel)
        out = F.scaled_dot_product_attention(q, k, v, is_causal=True)
        out = out.transpose(1, 2).contiguous().view(B, n, -1)
        return self.wo(out), kv_cache

    @staticmethod
    def _rotate_half(x):
        x1, x2 = x[..., 0::2], x[..., 1::2]
        return torch.cat([-x2, x1], dim=-1)
```

### Q5: 为什么 RoPE 在训练 4K,测试 32K 时会失效?

**答**:
- 训练时, query/key 的相对位置 $\Delta = n - m$ 最多 $\le L_{\text{train}} = 4096$
- 模型只见过这个范围内的 $\cos(\Delta \theta_i)$
- 测试时 $\Delta$ 可能 $>> 4096$,对于高频维度 ($\theta_i$ 大),$\cos(\Delta \theta_i)$ 进入「未训练」的相空间
- 注意力模式**不一致**,模型困惑

**解法**: §12 中的 PI / NTK-aware / YaRN / LongRoPE。

### Q6: NTK-aware 的 $\alpha = s^{d/(d-2)}$ 是怎么推出来的?

**答**:
- 目标: 让最小周期维度(对应最大 $\theta$,即高频)的**新周期** = 原始周期的 $s$ 倍
- 最小周期: $T_{\min} = 2\pi / \theta_{\max} = 2\pi \cdot b^{(d-2)/d}$
- 我们希望新周期 $T_{\min}' = s \cdot T_{\min}$
- 对应新 base: $T_{\min}' = 2\pi \cdot b_{\text{new}}^{(d-2)/d}$
- 解: $b_{\text{new}}^{(d-2)/d} = s \cdot b^{(d-2)/d}$, 所以 $b_{\text{new}} = b \cdot s^{d/(d-2)}$

### Q7: YaRN 的「温度缩放」为什么能让长文本性能变好?

**答**:
- RoPE 在长距离上**衰减不够快**,导致 softmax 分布**过平**
- 温度因子 $t > 1$ 让 $\text{softmax}(\cdot / t)$ 更**尖锐**,远距离 token 权重被压低
- 经验公式: $t = 0.1 \ln(s) + 1$,$s$ 是 scaling factor
- 注意: 训练时也要用这个温度(否则推理/训练不一致)

### Q8: LongRoPE 和 YaRN 的核心区别?

| 维度 | YaRN | LongRoPE |
|---|---|---|
| 频率修改 | 解析公式(分段插值) | 演化搜索(数值优化) |
| 每个维度 | 同一规则 | **独立缩放因子** |
| 搜索成本 | 0 (无需搜索) | ~GPU-小时 |
| 上限 | ~128K 稳定 | 2M+ 稳定 |
| 通用性 | 一份公式适用所有模型 | 不同模型要重新搜索 |

**LongRoPE 创新**: 找到「不均匀」的缩放(中间维度可能比边缘维度更激进)。

### Q9: RoPE 和 ALiBi 哪个更适合长文本?

**答**: 视场景而定。

- **检索 / 精确匹配**: RoPE (因为频率结构提供多分辨率)
- **整体理解 / 摘要**: ALiBi (因为单调衰减让远距离信息均匀混合)
- **超长 (1M+)**: LongRoPE + RoPE
- **训练稳定 / 易部署**: ALiBi (实现简单,无缓存)

实践中 **RoPE 主导**(LLaMA, Mistral, Qwen, GLM, DeepSeek 全用),ALiBi 主要在 BLOOM。

### Q10: 如何把 RoPE 应用到视觉 Transformer?

**答**: 2D RoPE。
- 把图像分成 patch, 每个 patch 有 $(x, y)$ 坐标
- 一半维度编码 $x$, 一半编码 $y$
- 公式: $R_m = \text{diag}(R(m_x \theta), R(m_y \theta))$
- 应用: ViT-22B, InternImage 等大模型

### Q11: RoPE 真的「不增加参数」吗?

**答**:
- 对模型本身的参数: 是,0 额外参数(只是对 Q/K 做一个固定变换)
- 对**计算缓存**: 是,**需要**预计算 cos/sin cache,大小 $O(L \cdot d)$
- 对**推理**: 是,只需一次乘加

**关键**: cos/sin 可以**离线预计算**,推理时只是查表。

### Q12: 训练时 RoPE 应用在哪个向量?

**答**:
- **Q 和 K**: ✓ 必须
- **V**: ✗ 不需要 (Value 不参与位置编码,只承载语义)
- **Attention bias**: ✗ 不需要 (RoPE 已经是「soft bias」)

错误应用 V 的代码:

```python
# 错误
q, k, v = self.wq(x), self.wk(x), self.wv(x)
q, k, v = rope(q), rope(k), rope(v)  # ❌ V 不需要 RoPE

# 正确
q, k, v = self.wq(x), self.wk(x), self.wv(x)
q = rope(q, positions)
k = rope(k, positions)
# v 保持不变
```

### Q13: RoPE 和 KV cache 怎么配合?

**答**:
- **关键**: KV cache 中存的是**已经旋转过的 K**
- 推理时,新 query 也要旋转(用其绝对位置)
- 旋转是**位置相关的**,所以每次新 token 进入,都要重新旋转它对应的 q 和 k
- 但是 cache 中**已经旋转过的旧 k 不需要重新旋转**

```python
# 推理时
def inference_step(new_token, position, kv_cache):
    q = self.wq(new_token)
    k = self.wk(new_token)
    v = self.wv(new_token)

    # 旋转 (用绝对位置)
    q = rope(q, position)
    k = rope(k, position)

    # 拼接到 cache
    kv_cache['k'] = torch.cat([kv_cache['k'], k], dim=2)
    kv_cache['v'] = torch.cat([kv_cache['v'], v], dim=2)

    # 注意力: 旋转后的 q 和 cache 中的 k (已经旋转过)
    return attention(q, kv_cache['k'], kv_cache['v'])
```

### Q14: GQA (Grouped Query Attention) 下 RoPE 怎么工作?

**答**:
- GQA 让多个 Q head 共享一个 K/V head
- RoPE **仍然应用在共享的 K/V 上**(不是每个 Q head 各自旋转)
- 节省: KV cache 减少到原来的 $1/n_{\text{groups}}$

```python
# GQA 下的 RoPE
q = rope(q, positions)  # (B, n_q_heads, n, d)
k = rope(k, positions)  # (B, n_kv_heads, n, d) ← 共享
v = v                  # (B, n_kv_heads, n, d)
# K/V 扩展到 Q 的 head 维度
k = k.repeat_interleave(n_q_heads // n_kv_heads, dim=1)
v = v.repeat_interleave(n_q_heads // n_kv_heads, dim=1)
```

### Q16: bfloat16 下 RoPE 训练不稳定,怎么解决?

**答**:
- **问题**: $\sin(m\theta)$ 在大 $m$ 时 < 1e-3,bf16 精度不足 → 训练后期 loss spike
- **解法 1**: cos/sin 计算用 fp32,cast 回 bf16 用于乘法
  ```python
  cos = cos.float().to(q.dtype)
  sin = sin.float().to(q.dtype)
  ```
- **解法 2**: 减小 base (但牺牲长距离)
- **解法 3**: 训练后期切到 fp32 (代价高)
- **解法 4**: 用「RoPE-Lite」替代 (Qwen 用过)

### Q17: RoPE 和 Sinusoidal PE 性能对比?

**答**: 在 LLM 任务上(语言建模、长文本理解、检索):
- 短距离 (< 1K): RoPE ≈ Sinusoidal (略好)
- 长距离 (> 4K): RoPE 显著优于 Sinusoidal
- 外推性: RoPE 远优于 Sinusoidal
- 收敛速度: RoPE 略快 (因为多分辨率结构作为强归纳偏置)

### Q18: DeepSeek 的 Decoupled RoPE 为什么能加速推理?

**答**:
- 标准 MHA: KV cache 大小 = $2 \cdot n_{\text{layers}} \cdot n_{\text{kv}} \cdot L \cdot d_{\text{head}}$
- Decoupled RoPE + MLA: KV cache 只存**压缩的 latent** + **rope 部分的 K**
  - 压缩比: $d_{\text{latent}} / d_{\text{model}} \approx 1/4$ (DeepSeek-V2)
- 计算注意力时:
  - 把 latent 还原成 full K (用一次矩阵乘)
  - 拼接 rope-K 部分
  - 但**只有 rope-K 部分**参与 RoPE 计算
- 显存节省 ~4-8x,长上下文推理显著加速

### Q19: RoPE 在 MoE 模型中有什么特殊考虑?

**答**:
- RoPE 应用在 **attention** 中,与 MoE 路由**无关**
- 但 MoE 模型有更多层,每个 attention 都要算 RoPE → 计算量 × n_layers
- 优化: RoPE 计算可以 **kernel fusion**(与 QKV 投影合并)
- DeepSeek-V3 的 MLA + Decoupled RoPE 让 MoE 在长上下文下也能高效推理

### Q20: 用 RoPE 训练 1M context 的关键挑战是什么?

**答**: 5 大挑战:
1. **显存**: 1M × 4096 hidden × 80 layers × 2 (KV) × 2 bytes ≈ 5 TB —— 必须用 MLA / GQA / Sliding Window
2. **计算**: Attention 是 $O(L^2)$,1M² 单 attention 已经 10^12,完全不可行 —— 必须稀疏 / 线性 attention
3. **训练成本**: 1M context 训练 1T tokens = 10^18 FLOPs,需要 ~1000 H100-天
4. **位置外推**: 必须用 YaRN / LongRoPE 等外推技术,否则 PPL 爆炸
5. **数据**: 需要大量长文档数据(books, code repos, long conversations)—— 数据稀缺点

**目前最强**: Gemini-1.5 (10M 实验), 但实用 1M 主要还是 Phi-3-mini (3.8B 参数, 128K)。

## 5. RoPE 数学推导（复数视角）

### 5.1 从二维旋转开始

RoPE 的最小单元是二维向量。

设一个向量为 $x=(x_0,x_1)^T$。

给定旋转角度 $heta$，二维旋转矩阵为：

$$
R(\theta)=
\begin{bmatrix}
\cos\theta & -\sin\theta\\
\sin\theta & \cos\theta
\end{bmatrix}
$$

旋转后的向量记作 $R(\theta)x$。

矩阵的第一行给出新的横坐标。

矩阵的第二行给出新的纵坐标。

展开可得：

$$
x'_0=x_0\cos\theta-x_1\sin\theta
$$

$$
x'_1=x_0\sin\theta+x_1\cos\theta
$$

这正是代码中 `rotate_half` 与 `cos/sin` 的组合。

旋转不改变向量的二范数。

$$
\|R(\theta)x\|_2^2=x^TR(\theta)^TR(\theta)x=\|x\|_2^2
$$

因为旋转矩阵满足正交性：

$$
R(\theta)^TR(\theta)=I
$$

所以 RoPE 不会单独放大或缩小每个 token 的 query/key 范数。

这也是它比任意可学习位置投影更容易稳定训练的原因之一。

### 5.2 复数表示

把二维向量映射成一个复数：

$$
z=x_0+ix_1
$$

根据欧拉公式：

$$
e^{i\theta}=\cos\theta+i\sin\theta
$$

二维旋转可以写成一次复数乘法：

$$
z'=ze^{i\theta}
$$

展开乘法：

$$
(x_0+ix_1)(\cos\theta+i\sin\theta)
$$

实部为：

$$
x_0\cos\theta-x_1\sin\theta
$$

虚部为：

$$
x_0\sin\theta+x_1\cos\theta
$$

因此，矩阵视角和复数视角完全等价。

复数形式的优势是乘法的结合律非常直观。

连续旋转两次满足：

$$
(z e^{im\theta})e^{in\theta}=z e^{i(m+n)\theta}
$$

逆旋转满足：

$$
(e^{im\theta})^{-1}=e^{-im\theta}
$$

### 5.3 位置注入

假设 token 的绝对位置为 $m$。

定义位置相关的旋转：

$$
f_m(z)=ze^{im\theta}
$$

query 在位置 $m$ 的表示为：

$$
q_m=q e^{im\theta}
$$

key 在位置 $n$ 的表示为：

$$
k_n=k e^{in\theta}
$$

注意力中需要计算实向量内积。

复数表示下，内积可以写成共轭乘积的实部：

$$
\langle q_m,k_n\rangle=\operatorname{Re}(q_m\overline{k_n})
$$

代入位置旋转：

$$
q_m\overline{k_n}=q e^{im\theta}\overline{k e^{in\theta}}
$$

因为 $\overline{e^{in\theta}}=e^{-in\theta}$，所以：

$$
q_m\overline{k_n}=q\overline{k}e^{i(m-n)\theta}
$$

最终得到：

$$
\langle q_m,k_n\rangle=\operatorname{Re}(q\overline{k}e^{i(m-n)\theta})
$$

绝对位置 $m,n$ 只通过差值 $m-n$ 出现。

这就是 RoPE 相对位置性质的复数证明。

它没有额外构造相对位置表。

也没有在每个 attention score 上显式加一个 bias。

相对位置信息已经被编码进 query 和 key 的内积。

### 5.4 多维向量的复数分块

设 head dimension 为 $d$，且 $d$ 为偶数。

把 $d$ 维实向量分成 $d/2$ 个二维块：

$$
x=(x_0,x_1),(x_2,x_3),\ldots,(x_{d-2},x_{d-1})
$$

第 $j$ 个二维块对应复数：

$$
z_j=x_{2j}+ix_{2j+1}
$$

每个二维块使用自己的基础频率 $\theta_j$。

常见定义是：

$$
\theta_j=\operatorname{base}^{-2j/d}
$$

位置 $m$ 的旋转角度为：

$$
\phi_{m,j}=m\theta_j
$$

因此多维 RoPE 为：

$$
z_{m,j}=z_j e^{im\theta_j}
$$

低维块的频率更高。

高维块的频率更低。

高频分量在短距离变化更快。

低频分量在长距离变化更慢。

多频率的组合形成多尺度的位置表示。

这类似于用一组不同波长的信号描述位置。

### 5.5 周期与可辨识距离

第 $j$ 个频率的周期约为：

$$
T_j=\frac{2\pi}{\theta_j}
$$

当 $m$ 增加一个周期时：

$$
e^{i(m+T_j)\theta_j}=e^{im\theta_j}
$$

单个频率不能区分相差一个周期的位置。

但多个互不相同的频率联合后，位置别名会被显著推迟。

这可以理解为多频率的相位编码。

短波长通道负责精细的局部顺序。

长波长通道负责远距离的粗粒度顺序。

如果所有维度使用相同频率，位置表示会很快重复。

如果频率跨度合理，表示可以覆盖更长上下文。

因此 `base` 不只是一个任意超参数。

它决定频率谱的分布。

### 5.6 旋转矩阵的块对角形式

完整的 $d$ 维旋转矩阵是块对角矩阵：

$$
R_m=\operatorname{diag}(R(m\theta_0),R(m\theta_1),\ldots,R(m\theta_{d/2-1}))
$$

其维度为 $d\times d$。

矩阵乘法形式为：

$$
q_m=R_mq
$$

$$
k_n=R_nk
$$

由于每个二维块都是正交矩阵，整体矩阵也正交。

$$
R_m^TR_m=I
$$

块对角结构让实现可以避免显式构造 $d\times d$ 矩阵。

实际实现只需要逐元素计算 cos 和 sin。

显式矩阵乘法会带来不必要的显存和计算开销。

### 5.7 相对旋转的矩阵证明

注意力分数中的核心项是：

$$
q_m^Tk_n=(R_mq)^T(R_nk)
$$

利用转置规则：

$$
q_m^Tk_n=q^TR_m^TR_nk
$$

旋转矩阵满足群性质：

$$
R_m^TR_n=R_{n-m}
$$

因此：

$$
q_m^Tk_n=q^TR_{n-m}k
$$

这个结果说明，query/key 的共同绝对位移不会改变分数结构。

如果把两个位置同时向右移动 $c$：

$$
(m,n)\rightarrow(m+c,n+c)
$$

则相对距离不变：

$$
(n+c)-(m+c)=n-m
$$

对应的旋转关系也不变。

### 5.8 反向旋转与方向信息

当 $n>m$ 时，key 相对于 query 位于后方。

相对旋转角度可以是正值或负值。

$$
R_{n-m}=R_{-(m-n)}^T
$$

因此 RoPE 不仅编码距离大小，也编码方向。

这点与只使用 $|m-n|$ 的位置 bias 不同。

在因果 attention 中，方向信息尤其重要。

模型可以区分“前面的 token”和“后面的 token”。

即使未来 token 被 mask，位置表示仍然保留方向结构。

### 5.9 为什么只在 Q/K 上应用

attention score 是 $QK^T$。

相对位置性质依赖 Q 和 K 共同旋转。

Value 不参与位置匹配，只负责携带被聚合的内容。

所以常见实现只对 Q、K 应用 RoPE。

对 V 旋转会改变被聚合的内容基底。

这不是标准 RoPE 的必要部分。

部分研究会探索 V 的位置变换。

但工程实现通常保持 Q/K-only。

### 5.10 PyTorch 基础实现

下面的实现使用相邻维度配对。

```python
import torch


def precompute_freqs_cis(dim, max_seq_len, base=10000.0, device=None):
    """返回复数形式的 cos+i*sin，形状为 (max_seq_len, dim//2)。"""
    if dim % 2 != 0:
        raise ValueError("head dimension must be even")
    index = torch.arange(0, dim, 2, device=device, dtype=torch.float32)
    inv_freq = 1.0 / (base ** (index / dim))
    positions = torch.arange(max_seq_len, device=device, dtype=torch.float32)
    angles = torch.outer(positions, inv_freq)
    return torch.polar(torch.ones_like(angles), angles)
```

`torch.polar(r, theta)` 构造复数 $r e^{i\theta}$。

这里半径固定为 1，所以只保留相位。

复数张量的最后一维对应二维旋转块。

### 5.11 复数版 apply_rope

```python
def apply_rope_complex(x, freqs_cis, positions=None):
    """x: (batch, heads, seq, dim)，freqs_cis: (max_seq, dim//2)。"""
    batch, heads, seq_len, dim = x.shape
    if dim % 2 != 0:
        raise ValueError("dim must be even")
    x_pairs = x.float().reshape(batch, heads, seq_len, dim // 2, 2)
    x_complex = torch.view_as_complex(x_pairs.contiguous())
    if positions is None:
        freqs = freqs_cis[:seq_len]
    else:
        freqs = freqs_cis[positions]
    freqs = freqs.to(device=x.device, dtype=x_complex.dtype)
    rotated = x_complex * freqs[None, None, :, :]
    return torch.view_as_real(rotated).flatten(-2).to(dtype=x.dtype)
```

`view_as_complex` 要求最后两个元素在内存中连续。

因此示例中显式调用 `contiguous()`。

训练时如果输入是 bfloat16，频率通常保持 float32 计算。

最后再转换回输入 dtype。

### 5.12 实数版实现

```python
def rotate_half(x):
    """把每个二维块 (a,b) 变为 (-b,a)。"""
    x = x.reshape(*x.shape[:-1], -1, 2)
    x0, x1 = x.unbind(dim=-1)
    return torch.stack((-x1, x0), dim=-1).flatten(-2)


def apply_rope_real(x, cos, sin):
    """cos/sin 可广播到 x 的形状。"""
    return x * cos + rotate_half(x) * sin
```

实数版通常更容易与 fused kernel 对接。

复数版更容易说明数学含义。

两者结果应在浮点误差范围内一致。

### 5.13 一个可运行的等价性检查

```python
def check_real_complex_equivalence():
    torch.manual_seed(0)
    x = torch.randn(2, 3, 5, 8)
    freqs = precompute_freqs_cis(8, 5)
    angles = torch.angle(freqs)
    cos = angles.cos()[None, None, :, :].repeat_interleave(2, -1)
    sin = angles.sin()[None, None, :, :].repeat_interleave(2, -1)
    y_real = apply_rope_real(x, cos, sin)
    y_complex = apply_rope_complex(x, freqs)
    torch.testing.assert_close(y_real, y_complex, rtol=1e-5, atol=1e-5)
```

这个检查同时覆盖 shape、配对顺序和符号方向。

如果符号写反，误差会明显增大。

如果维度交错方式不同，测试也会失败。

### 5.14 交错布局与分块布局

交错布局把维度组织为：

$$
(x_0,x_1),(x_2,x_3),\ldots
$$

分块布局可能组织为：

$$
(x_0,x_{d/2}),(x_1,x_{d/2+1}),\ldots
$$

这两种布局都可以实现旋转。

但 cos、sin 的排列必须与布局匹配。

LLaMA 系列常见代码需要仔细确认 `rotate_half` 的约定。

不能只复制公式而忽略张量布局。

模型权重与 RoPE 布局必须保持一致。

### 5.15 数值稳定性

位置越大，角度 $m\theta_j$ 越大。

直接用低精度计算角度可能产生相位误差。

预计算频率时通常使用 float32。

在超长上下文下，频率 cache 也可能占用显存。

可以按需分块生成 cos/sin。

也可以把频率 cache 放在 CPU，在需要时搬运。

但 CPU 搬运会影响 decode latency。

生产系统会在显存、算力和延迟之间取平衡。

### 5.16 小结

RoPE 的本质不是记忆绝对位置表。

它是把每个位置映射为一个相位旋转。

二维旋转等价于复数乘法。

Q/K 的共轭乘积自动产生相对位置差。

多维频率提供从局部到全局的多尺度信息。

块对角结构让工程实现避免显式矩阵。

理解复数证明后，NTK scaling 和 YaRN 的动机更容易掌握。

## 6. RoPE 与相对位置的关系

### 6.1 绝对位置与相对位置的区分

绝对位置编码为每个位置生成一个独立向量。

例如加法式编码写成：

$$
h_m=x_m+p_m
$$

其中 $p_m$ 只表示位置 $m$。

attention 分数由 $h_m^Th_n$ 产生。

展开后会出现内容项、位置项和交叉项。

相对位置信息不是天然独立出现的。

RoPE 则把位置施加在 Q/K 的坐标系上。

因此分数直接包含 $n-m$。

这不是简单地把绝对位置换了一个表。

### 6.2 平移等变性

设所有 token 的位置都加上同一个常数 $c$。

RoPE 后的 query/key 为：

$$
q_{m+c}=R_{m+c}q
$$

$$
k_{n+c}=R_{n+c}k
$$

分数为：

$$
q^TR_{m+c}^TR_{n+c}k
$$

根据群性质：

$$
R_{m+c}^TR_{n+c}=R_{n-m}
$$

所以共同平移不改变相对注意力结构。

这称为对平移的等变性。

它并不意味着模型完全不感知文档开头。

因果 mask、边界、训练数据分布仍然会提供绝对上下文。

### 6.3 从 score kernel 看 RoPE

固定内容向量 $q,k$，RoPE 产生一个位置核：

$$
K_{q,k}(m,n)=q^TR_{n-m}k
$$

该核只依赖相对位置 $r=n-m$。

可以把它看成内容相关的相对位置函数。

与 ALiBi 的固定线性 bias 不同，RoPE 的幅度取决于 q/k 的方向。

不同 attention head 可以学习不同的内容-位置耦合。

这解释了为什么不同 head 会表现出局部或长程模式。

### 6.4 与显式相对位置 bias 的比较

显式相对位置 bias 常写成：

$$
S_{m,n}=q_m^Tk_n+b_{n-m}
$$

其中 $b_{n-m}$ 是查表或函数生成的偏置。

RoPE 的形式是：

$$
S_{m,n}=(R_mq_m^0)^T(R_nk_n^0)
$$

两者都可以表达相对距离。

但 RoPE 不需要为每个距离维护额外 bias 参数。

RoPE 也不会直接改变 softmax 前的分数基线。

它改变的是 Q/K 的方向关系。

相对 bias 更容易解释。

RoPE 更容易融入现有矩阵乘法路径。

### 6.5 与 ALiBi 的比较

ALiBi 通常为第 $h$ 个 head 加上线性斜率：

$$
S_{m,n}=q_m^Tk_n-s_h|m-n|
$$

因果场景中常只使用可见方向的距离。

ALiBi 的长距离惩罚是显式且单调的。

RoPE 的相位变化是周期性的。

因此 RoPE 更有表达力，但长距离外推需要小心相位分布。

ALiBi 的计算路径较简单。

RoPE 与预训练权重的兼容性更依赖频率定义。

选择哪一种要看训练目标和模型架构。

### 6.6 相对距离的多频率编码

对一个距离 $r$，第 $j$ 个二维块产生相位：

$$
\phi_j(r)=r\theta_j
$$

对应特征为：

$$
(\cos(r\theta_j),\sin(r\theta_j))
$$

多维拼接相当于一组 Fourier features。

短距离改变时，高频维度提供敏感响应。

长距离改变时，低频维度保持缓慢变化。

如果只保留高频，远距离容易快速混叠。

如果只保留低频，局部顺序难以区分。

`base` 和 head dimension 共同决定频率带宽。

### 6.7 相位差与距离差

两个相对距离 $r_1,r_2$ 的第 $j$ 个相位差为：

$$
\Delta\phi_j=(r_1-r_2)\theta_j
$$

当所有维度的相位差都接近 $2\pi$ 的整数倍时，位置表示相似。

这就是长上下文外推中的相位混叠来源。

扩大 base 会降低部分维度的角频率。

降低角频率会推迟混叠。

但也会压缩短距离的分辨率。

所以长上下文 scaling 不是无代价操作。

### 6.8 局部注意力的行为

对于相邻 token，$r$ 很小。

高频维度的相位变化最明显。

模型可以通过这些维度识别邻接、标点和局部语法。

低频维度的变化很小。

它们更适合表示段落、主题和远距离依赖。

不同 head 的 Q/K 投影会选择性使用这些维度。

因此 head specialization 不完全由频率决定。

频率只是可供模型利用的坐标系。

### 6.9 因果 mask 与相对位置

RoPE 本身不负责因果性。

因果性由 attention mask 保证：

$$
M_{m,n}=\begin{cases}0,&n\le m\\-\infty,&n>m\end{cases}
$$

RoPE 负责在可见位置之间提供相对位置信息。

把 RoPE 和 mask 混为一谈会导致实现错误。

在 prefix-LM 或 bidirectional attention 中，RoPE 仍然可以使用。

变化的是可见性规则，而不是旋转公式。

### 6.10 KV cache 中的相对位置

自回归 decode 时，旧 K 已经在其原始位置旋转。

新 query 要使用当前绝对位置旋转。

例如 cache 中最后一个 key 位于位置 $t-1$。

当前 query 位于位置 $t$。

两者内积天然包含距离 1 的旋转差。

不能把缓存的 K 再次按当前步旋转。

否则会发生重复位置编码。

`start_pos` 必须与 cache 长度一致。

### 6.11 Prefix cache 的位置一致性

如果复用一段 prefix 的 KV cache，必须固定 prefix 的位置编号。

同一段 token 在不同请求中采用不同起始位置时，旋转后的 K 不再相同。

可以采用共享的绝对位置协议。

也可以在特殊架构中使用位置重映射。

但重映射需要同时作用于 Q/K。

生产系统通常将 cache key 与位置策略绑定。

不能只以 token 文本作为 cache key。

### 6.12 Packed sequence 与 position_ids

多个样本打包到一个 batch 时，position_ids 可能不是全局递增。

每个独立序列通常从 0 重新编号。

如果序列之间不允许互相注意，还要配合 block-diagonal mask。

只重置 position_ids 而不重置 mask 会产生串样本注意力。

只重置 mask 而不重置 position_ids 会破坏相对距离。

RoPE 的 position_ids 是计算图中的真实输入。

调试时必须打印实际 position_ids。

### 6.13 位置插值的直觉

训练长度为 $L$，推理长度为 $sL$。

线性位置插值把推理位置压回训练范围：

$$
\tilde m=m/s
$$

再使用原始频率计算角度：

$$
\phi=\tilde m\theta_j
$$

优点是不会立即超出训练相位范围。

缺点是所有频率都被同样压缩。

局部相对位置的分辨率会下降。

YaRN 和 LongRoPE 的动机之一就是按频率选择性处理。

### 6.14 长度外推的本质风险

训练分布只覆盖位置对 $|m-n|\le L$。

推理时可能出现远大于 $L$ 的相对距离。

这些距离的相位组合没有被模型充分优化。

即使公式可以计算，模型也未必能正确使用。

因此“数学上可外推”不等于“任务上能外推”。

需要继续训练、位置微调或专门的 scaling。

还要验证检索、长文问答和 needle-in-a-haystack。

### 6.15 远距离衰减不是 RoPE 的显式保证

有人把 RoPE 误解为距离越远分数越小。

实际上 RoPE 只改变相对旋转。

内积不会必然随距离单调衰减。

多个频率叠加后可能出现周期性增强或抵消。

模型可以通过内容投影和 softmax 学习偏好的距离。

如果需要严格的距离衰减，应使用显式 bias 或结构化 mask。

### 6.16 位置编码与内容的耦合

RoPE 作用于内容生成的 Q/K。

所以位置效应与内容方向耦合。

同一距离对不同内容向量的影响可能不同。

这比固定位置 bias 更灵活。

但也让行为更难解释。

分析 attention map 时应区分内容相似度和位置相位。

单独观察距离分布不能完整解释 RoPE。

### 6.17 可视化相位

可以画出不同频率的相位随位置变化：

```python
import matplotlib.pyplot as plt

positions = torch.arange(512, dtype=torch.float32)
inv_freq = 1.0 / (10000 ** (torch.arange(0, 64, 2) / 64))
angles = positions[:, None] * inv_freq[None, :]
plt.plot(positions, angles[:, 0], label="high frequency")
plt.plot(positions, angles[:, -1], label="low frequency")
plt.legend()
plt.title("RoPE phase growth")
plt.show()
```

高频通道的斜率更大。

低频通道的斜率更小。

绘图时注意角度未取模。

取模后可以观察相位循环。

### 6.18 诊断相对位置实现

第一步检查位置 0 的旋转。

位置 0 的角度都为 0。

因此输出必须等于输入。

第二步检查范数保持。

第三步检查共同平移前后的分数。

第四步检查 Q/K 的位置差是否正确。

第五步检查 cache 增量和全量计算是否一致。

### 6.19 平移不变性单元测试

```python
def check_translation_equivariance():
    torch.manual_seed(1)
    d = 16
    q = torch.randn(d)
    k = torch.randn(d)
    freqs = precompute_freqs_cis(d, 128)
    def score(m, n):
        q_rot = apply_rope_complex(q.view(1, 1, 1, d), freqs[m:m+1]).view(-1)
        k_rot = apply_rope_complex(k.view(1, 1, 1, d), freqs[n:n+1]).view(-1)
        return q_rot @ k_rot
    torch.testing.assert_close(score(3, 11), score(20, 28), atol=1e-5, rtol=1e-5)
```

这里两个位置对的距离都是 8。

测试能发现频率索引和广播维度错误。

浮点误差允许使用小容差。

### 6.20 小结

RoPE 是一种相对位置友好的绝对位置变换。

它输入绝对 position_ids，却在 Q/K 内积中产生相对距离。

平移等变性来自旋转群的结合律。

多频率 Fourier 特征决定距离分辨率和混叠边界。

KV cache 要保留每个 K 的原始位置。

长上下文的主要难点是训练分布外的相位组合。

## 7. RoPE 扩展到长上下文（YaRN / LongRoPE）

### 7.1 为什么需要 scaling

假设模型训练上下文是 4K。

直接把 position_ids 推到 32K 会让角度扩大 8 倍。

高频通道会在很短范围内多次绕圈。

模型在训练时没有见过这种相位排列。

结果可能是困惑度上升、检索失败和局部重复。

RoPE scaling 的目标是把长位置映射到更可学习的相位范围。

它不是单纯扩大 KV cache。

### 7.2 线性位置插值

设扩展倍率为 $s=L_{target}/L_{train}$。

线性插值使用：

$$
m'=m/s
$$

新的角度为：

$$
\phi_{m,j}=m'\theta_j
$$

等价于把所有频率统一除以 $s$。

实现非常简单。

```python
def linear_position_scaling(position_ids, factor):
    return position_ids.float() / factor
```

它通常能快速提升基本长文稳定性。

但所有维度被同等压缩。

短程关系会损失一部分精度。

### 7.3 线性 scaling 的局限

低频通道本来就变化慢。

再除以 $s$ 后，长距离信息可能过度平滑。

高频通道的压缩又可能让局部顺序变得不够敏感。

同一个缩放因子难以同时满足局部和全局需求。

这促使研究者采用按维度或按波长的非线性 scaling。

长上下文方法通常会在频率谱上进行选择性调整。

### 7.4 NTK-aware scaling

NTK-aware 方法通过改变 `base` 调整频率谱。

常用形式为：

$$
\operatorname{base}'=\operatorname{base}\cdot s^{d/(d-2)}
$$

其中 $d$ 是 head dimension。

它不是简单地对 position_ids 除以 $s$。

低频和高频受到不同程度的影响。

优点是可以在不重写 position_ids 的情况下接入模型。

缺点是不同模型、不同维度下效果不一定稳定。

### 7.5 Dynamic NTK

Dynamic NTK 根据当前序列长度动态调整 base。

当序列长度不超过训练长度时，保持原始 base。

超过训练长度后再逐步增大 base。

一种常见形式是：

$$
\operatorname{base}'=\operatorname{base}\left(\alpha\frac{n}{L}-(\alpha-1)\right)^{d/(d-2)}
$$

其中 $n$ 是当前长度，$L$ 是训练长度。

不同实现的具体公式和 clamp 规则可能不同。

不能把论文公式直接当成所有框架的实现。

### 7.6 YaRN 的动机

YaRN 可以看作更细致的频率插值策略。

它根据波长把维度分为不同区域。

对需要插值的维度进行压缩。

对已经足够低频的维度尽量保持原状。

同时引入 attention temperature scaling。

目的是修复长上下文下 attention 分布的尺度变化。

它通常配合少量长上下文继续训练。

### 7.7 波长定义

第 $j$ 个频率的波长为：

$$
\lambda_j=\frac{2\pi}{\theta_j}
$$

令训练长度为 $L$。

当 $\lambda_j$ 远小于 $L$ 时，该维度在训练窗口内已经多次循环。

它可以被视为局部频率。

当 $\lambda_j$ 远大于 $L$ 时，该维度变化很慢。

它更适合作为全局位置坐标。

按照波长分类可以减少无差别压缩。

### 7.8 YaRN 的 ramp 函数

工程中常用一个平滑 ramp 在频率维度之间过渡。

可以定义：

$$
 r_j=\operatorname{clip}\left(\frac{j-j_{low}}{j_{high}-j_{low}},0,1\right)
$$

再把原始频率与插值频率混合：

$$
\theta'_j=(1-r_j)\theta_j+r_j\tilde\theta_j
$$

这样相邻维度的缩放不会突然跳变。

平滑过渡有利于训练稳定。

边界参数需要根据训练长度和目标倍率估计。

### 7.9 YaRN attention scaling

位置 scaling 会改变 Q/K 的相位统计。

长序列下 attention logits 的有效尺度可能变化。

YaRN 使用额外的 attention factor 调整 logits：

$$
S' = S\cdot t
$$

或等价地调整 softmax 前的温度。

具体系数通常与扩展倍率的对数相关。

不同代码库对 factor 的定义可能相反。

阅读配置时要确认它乘在 logits 还是 temperature 上。

### 7.10 LongRoPE 的基本思路

LongRoPE 进一步对不同维度使用非均匀缩放。

它可能同时考虑短上下文和长上下文两个目标。

某些维度采用不同的缩放向量。

位置映射可以写成：

$$
m'_j=m/s_j
$$

其中 $s_j$ 随维度变化。

这样局部高频与全局低频可以分别优化。

实践中通常通过搜索或训练确定这些缩放参数。

### 7.11 非均匀缩放的实现接口

```python
def apply_dimension_scaling(position_ids, inv_freq, scales):
    """inv_freq: (dim//2,), scales: (dim//2,)。"""
    pos = position_ids.float()[..., None]
    angles = pos * inv_freq[None, :] / scales[None, :]
    return angles.cos(), angles.sin()
```

`scales` 不是模型输入 token 的缩放。

它只作用于位置频率。

如果把它误乘到 hidden state，会改变内容幅度。

### 7.12 训练长度与推理长度

训练长度 $L_{train}$ 是模型看到的最大 position_ids。

目标长度 $L_{target}$ 是部署时的最大上下文。

扩展倍率为：

$$
s=L_{target}/L_{train}
$$

倍率越大，分布偏移通常越明显。

从 4K 扩到 8K 往往比直接扩到 128K 容易。

超过一个数量级后，通常需要长文本继续训练。

只改配置不训练可能只适合实验性使用。

### 7.13 继续训练的两种策略

一种策略是全量长上下文训练。

优点是模型可以重新适应所有层。

缺点是显存、数据和时间成本高。

另一种策略是冻结大部分参数，只训练位置相关模块。

优点是成本低。

缺点是模型对新长度的适应能力有限。

也可以用 LoRA 进行低成本适配。

### 7.14 长上下文数据配比

长上下文训练不能只拼接随机文本。

需要包含跨段落依赖。

需要包含文档开头到结尾的引用。

需要包含多页代码和长表格。

还需要保留一部分短样本。

短样本能防止局部语言建模能力退化。

长度分布应覆盖部署中的常见区间。

### 7.15 长上下文评测维度

第一类是困惑度。

困惑度可以观察整体语言建模退化。

第二类是 needle-in-a-haystack。

它测试模型能否在长噪声中找到一个事实。

第三类是长文档问答。

第四类是多跳检索和跨章节推理。

第五类是代码仓库级别的引用解析。

单一指标不能代表真实长上下文能力。

### 7.16 位置外推与注意力稀疏

RoPE scaling 只改变位置坐标。

它不会自动减少 $O(n^2)$ 的 attention 计算。

32K 变成 128K 后，显存和算力仍然显著增加。

需要结合 sliding window、block attention 或稀疏 attention。

如果采用局部窗口，position_ids 仍然可以是全局递增。

如果采用 chunk attention，要明确 chunk 边界的相对位置。

### 7.17 KV cache 的长度扩展

长上下文 decode 的瓶颈常是 KV cache。

RoPE scaling 不会压缩 K/V 的存储大小。

可以使用 GQA 或 MQA 降低 KV 头数。

也可以使用量化 KV cache。

还可以分层存储远端 token。

这些是内存优化，不是位置编码优化。

工程设计应区分算法能力和系统容量。

### 7.18 FlashAttention 兼容性

FlashAttention 负责高效计算 attention。

RoPE 通常在 Q/K 进入 kernel 前应用。

某些实现会在 fused attention kernel 内完成旋转。

两种方式的数学结果应一致。

融合实现需要确认 position_ids 的广播维度。

还要确认不同 query offset 的 decode 语义。

不要因为使用 FlashAttention 就省略位置验证。

### 7.19 长度 scaling 配置示例

```python
rope_config = {
    "rope_type": "yarn",
    "factor": 8.0,
    "original_max_position_embeddings": 4096,
    "max_position_embeddings": 32768,
    "attention_factor": 1.0,
}
```

配置字段名称由模型框架决定。

`factor` 可能表示长度倍率，也可能表示 base scaling。

`original_max_position_embeddings` 不能随意写成目标长度。

加载 checkpoint 后要检查实际生效的 config。

### 7.20 从配置反推频率

```python
def inspect_inv_freq(dim, base, device="cpu"):
    index = torch.arange(0, dim, 2, device=device, dtype=torch.float32)
    inv_freq = 1.0 / (base ** (index / dim))
    wavelength = 2 * torch.pi / inv_freq
    return inv_freq, wavelength
```

打印最短和最长波长。

检查目标长度是否远超所有波长。

观察 scaling 前后的比值。

如果频率顺序反了，说明 index 或公式写错。

### 7.21 误差与 dtype

长位置下角度计算建议使用 float32。

即使模型主体是 bfloat16，频率 cache 也可保留 float32。

cos/sin 结果再按需要转换 dtype。

float16 在极大 position 下更容易积累误差。

如果使用 int64 position_ids，乘法前要显式转换。

不要让 base 的 Python 整数触发意外 dtype promotion。

### 7.22 长度扩展的回归测试

```python
def check_short_context_regression(original, scaled, length):
    x = torch.randn(1, 2, length, 64)
    pos = torch.arange(length)
    y0 = original(x, pos)
    y1 = scaled(x, pos)
    torch.testing.assert_close(y0, y1, rtol=1e-4, atol=1e-4)
```

当目标长度不超过训练长度时，某些 dynamic scaling 应保持原逻辑。

如果短上下文也发生大变化，需要确认配置是否错误。

### 7.23 Cache 与 full attention 对齐

```python
def compare_full_and_incremental(model, tokens):
    full_logits = model(tokens, use_cache=False)
    past = None
    pieces = []
    for t in range(tokens.size(1)):
        out, past = model(tokens[:, t:t+1], past_key_values=past, use_cache=True)
        pieces.append(out)
    incremental = torch.cat(pieces, dim=1)
    torch.testing.assert_close(full_logits, incremental, rtol=1e-3, atol=1e-3)
```

位置 scaling 的 bug 往往在这里暴露。

特别要检查 `cache_position`、`position_ids` 和 `start_pos` 是否重复偏移。

### 7.24 长上下文常见失败模式

失败模式一：只把 `max_position_embeddings` 改大。

失败模式二：把 position_ids 截断到训练长度。

失败模式三：训练使用一种 scaling，推理使用另一种 scaling。

失败模式四：忘记调整 attention temperature。

失败模式五：扩展后 tokenizer 或数据分布发生变化却归因于 RoPE。

失败模式六：评测只测短 prompt。

### 7.25 选择方法的经验矩阵

短期实验可以先使用线性插值。

希望保留短上下文质量，可以考虑 Dynamic NTK。

需要更大扩展倍率，可以使用 YaRN 或 LongRoPE。

需要稳定生产质量，应配合长上下文继续训练。

需要极低延迟，应同时优化 KV cache 和 attention kernel。

没有统一方法在所有模型上最优。

### 7.26 小结

长上下文 scaling 的核心是控制相位分布。

线性插值简单但会牺牲部分局部分辨率。

NTK-aware 通过 base 调整频率谱。

YaRN 使用频率分段和 attention scaling。

LongRoPE 允许不同维度使用不同缩放。

最终质量仍取决于继续训练和真实长文评测。

## 8. 工业实践（LLaMA / Qwen / DeepSeek）

### 8.1 工业实现的共同骨架

主流 decoder-only LLM 的 attention 通常包含以下步骤。

第一步，对 hidden states 做 Q/K/V 投影。

第二步，将 Q/K/V reshape 为 head 维度。

第三步，按 position_ids 生成或读取 cos/sin。

第四步，只对 Q 和 K 应用 RoPE。

第五步，执行 GQA/MQA 的 KV 头扩展。

第六步，结合 causal mask 和 KV cache 计算 attention。

具体顺序可能因 kernel 和 cache 布局不同而变化。

### 8.2 LLaMA 风格的 RoPE

LLaMA 系列使用每个 attention head 内的二维旋转。

经典实现通过 `inv_freq` 预计算频率。

Q/K 的 head dimension 通常是偶数。

position_ids 通常从 0 开始递增。

模型层之间共享相同的旋转频率定义。

不同层不一定使用不同 base。

实现时要以 checkpoint config 和源码为准。

### 8.3 LLaMA 的 GQA 配合

GQA 让多个 query heads 共享一个 KV head。

RoPE 应用在 KV head 的 K 上，然后再按组复制。

也可以先复制再旋转，数学结果相同但显存路径不同。

Q 使用 query head 数量。

K/V 使用较少的 KV head 数量。

KV cache 因此显著变小。

RoPE 不改变 GQA 的头共享关系。

### 8.4 LLaMA 风格伪代码

```python
def llama_attention(x, position_ids, cache=None):
    q = q_proj(x).view(batch, seq, n_q_heads, head_dim).transpose(1, 2)
    k = k_proj(x).view(batch, seq, n_kv_heads, head_dim).transpose(1, 2)
    v = v_proj(x).view(batch, seq, n_kv_heads, head_dim).transpose(1, 2)
    cos, sin = rotary_emb(v, position_ids)
    q, k = apply_rotary_pos_emb(q, k, cos, sin)
    k, v = update_cache(k, v, cache)
    k = repeat_kv(k, n_q_heads // n_kv_heads)
    v = repeat_kv(v, n_q_heads // n_kv_heads)
    return scaled_dot_product_attention(q, k, v)
```

这里只展示数据流，不代表所有版本的实际顺序。

### 8.5 Qwen 系列的关注点

Qwen 家族同样使用 RoPE，但具体配置会变化。

需要检查 `rope_theta` 或等价 base 参数。

需要检查是否启用 rope scaling。

需要检查 head dimension 和 query/key 的旋转维度。

某些模型会对部分维度应用旋转。

某些实现会使用不同的 position interpolation 方案。

迁移代码时不要只复制 LLaMA 的默认值。

### 8.6 Qwen 的配置检查

```python
from transformers import AutoConfig

config = AutoConfig.from_pretrained("your-model")
print(config.rope_theta)
print(config.max_position_embeddings)
print(getattr(config, "rope_scaling", None))
print(config.num_attention_heads)
print(config.num_key_value_heads)
```

配置打印是排查位置错误的第一步。

还应打印实际的 `position_ids`。

模型名称不能替代配置读取。

同一系列不同尺寸可能有不同 RoPE 参数。

### 8.7 DeepSeek 的工程语境

DeepSeek 系列通常也使用 RoPE 作为基础位置机制。

但现代模型可能结合 MLA、稀疏结构或特殊 KV 压缩。

此时不能假设 KV cache 形状与普通 MHA 相同。

RoPE 可能作用于压缩后的 latent 或特定子空间。

读取论文和实现时要区分“旋转位置编码”与“KV 表示压缩”。

两者可以同时存在，但职责不同。

### 8.8 MLA 场景下的注意事项

如果 key/value 先被压缩为 latent，缓存的对象可能不是标准 K/V。

RoPE 的施加位置取决于模型的分解方式。

有的实现只对 query 和部分 key 子空间旋转。

有的实现把可旋转部分与非旋转部分拼接。

必须追踪张量的最后一维语义。

不能看到 `rotate_half` 就认为整个 head 都被旋转。

### 8.9 partial rotary factor

部分旋转常用 `rotary_dim` 表示旋转维度。

若 head dimension 为 $d$，旋转维度为 $d_r$：

$$
d_r=\lfloor d\cdot r\rfloor
$$

其中 $r$ 是 rotary percentage。

只有前 $d_r$ 个维度应用 RoPE。

剩余维度保持原状。

`d_r` 必须为偶数。

实现时要把旋转部分与 passthrough 部分拼回去。

### 8.10 partial rotary 的代码

```python
def apply_partial_rope(x, cos, sin, rotary_dim):
    if rotary_dim % 2:
        raise ValueError("rotary_dim must be even")
    x_rot = x[..., :rotary_dim]
    x_pass = x[..., rotary_dim:]
    y_rot = x_rot * cos + rotate_half(x_rot) * sin
    return torch.cat((y_rot, x_pass), dim=-1)
```

cos/sin 的最后一维应等于 `rotary_dim`。

不能把完整 head 的 cos/sin 直接广播到部分旋转张量。

### 8.11 position_ids 的来源

训练时 position_ids 通常由 batch 构造器生成。

普通样本是 `[0,1,2,...,n-1]`。

packed sample 可能包含多个局部序列。

推理时 position_ids 来自 cache position。

左 padding 场景下，position_ids 可能从 0 或有效 token 起点开始。

不同框架对 padding 处理不同。

必须让 mask 和 position_ids 的语义一致。

### 8.12 左 padding 的陷阱

假设 batch 中两个样本长度分别为 3 和 5。

左 padding 后它们在张量中对齐到长度 5。

如果直接使用 `[0,1,2,3,4]`，短样本的有效 token 位置会被错误偏移。

可以为有效 token 单独构造 position_ids。

也可以使用 attention mask 推导累积位置。

位置编号错误会影响所有后续 Q/K 分数。

这类问题通常不会触发 shape error。

### 8.13 cache_position 与 position_ids

现代 Transformers 实现可能同时传入两者。

`position_ids` 常用于 RoPE。

`cache_position` 常用于确定写入 KV cache 的索引。

二者通常相关，但不一定完全等价。

滑动窗口 cache 下写入索引可能循环。

绝对位置仍然可能继续递增。

不要把环形 cache index 当成旋转位置。

### 8.14 Prefill 与 decode

Prefill 一次处理整段 prompt。

Decode 每次只处理一个或少量新 token。

Prefill 的 position_ids 常是连续区间。

Decode 的 position_ids 从已有 cache 长度继续。

两条路径必须使用同一套 RoPE 参数。

如果 decode 重新从 0 编号，会导致生成质量明显异常。

可以通过 full-vs-incremental 对齐测试发现。

### 8.15 fused rotary kernel

大型推理框架常使用 fused rotary kernel。

kernel 会同时读取 x、cos、sin 和 position index。

它可能支持 interleaved 与 non-interleaved 两种布局。

参数名称相似不代表语义相同。

接入前应使用小张量与 PyTorch 参考实现对比。

还要测试不同 batch、不同 offset 和奇偶维度。

性能优化不能替代数学回归。

### 8.16 PyTorch 参考模块

```python
class RotaryEmbedding(torch.nn.Module):
    def __init__(self, dim, max_position_embeddings=4096, base=10000.0):
        super().__init__()
        inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
        self.register_buffer("inv_freq", inv_freq, persistent=False)
        self.max_seq_len_cached = 0
        self._set_cache(max_position_embeddings)

    def _set_cache(self, seq_len):
        pos = torch.arange(seq_len, device=self.inv_freq.device).float()
        freqs = torch.outer(pos, self.inv_freq)
        self.register_buffer("cos_cached", freqs.cos(), persistent=False)
        self.register_buffer("sin_cached", freqs.sin(), persistent=False)
        self.max_seq_len_cached = seq_len

    def forward(self, x, position_ids):
        max_pos = int(position_ids.max().item()) + 1
        if max_pos > self.max_seq_len_cached:
            self._set_cache(max_pos)
        cos = self.cos_cached[position_ids]
        sin = self.sin_cached[position_ids]
        return cos.to(dtype=x.dtype), sin.to(dtype=x.dtype)
```

生产版本通常会避免在 forward 中频繁 register buffer。

这里的代码用于展示 cache 逻辑。

### 8.17 cache 重新增长

动态扩展 cache 时要注意设备。

新的 position tensor 应与 `inv_freq` 位于同一 device。

多卡环境下不能默认使用当前 CUDA device。

扩展后要检查 dtype 和 shape。

如果目标序列长度突然很大，一次性生成 cos/sin 可能造成显存峰值。

可以采用分块或预估最大长度。

### 8.18 与 torch SDPA 的结合

```python
q = apply_rope_real(q, cos, sin)
k = apply_rope_real(k, cos_k, sin_k)
out = torch.nn.functional.scaled_dot_product_attention(
    q, k, v, is_causal=True
)
```

如果使用 KV cache，`cos_k` 的位置区间与 `q` 可能不同。

在 decode 中，K 只对应新 token 的位置。

历史 K 已在 cache 中完成旋转。

`is_causal=True` 对单 token decode 的语义也要确认。

### 8.19 MQA/GQA 与 RoPE 的顺序

对 K 先旋转再复制，与复制后对每个副本旋转结果相同。

工程上通常先在较小的 KV 头数上旋转。

这样可以减少 cos/sin 应用的元素数量。

Q 仍然按 query head 旋转。

如果 KV 头在 cache 中已经复制，不能再次复制。

重复复制会造成 head 数不匹配或显存浪费。

### 8.20 量化模型的注意事项

权重量化不等于 RoPE 也要量化。

cos/sin 通常保持较高精度。

Q/K 激活可能在旋转前后使用不同量化策略。

旋转是线性正交变换，理论上不改变二范数。

但量化误差会改变坐标分布。

需要对量化前后 attention logits 做回归。

### 8.21 训练时的 dropout 与 RoPE

RoPE 本身没有 dropout。

attention dropout 作用在 softmax 后的权重。

不要把位置旋转随机化来模拟 dropout。

训练和推理只应在 dropout 等模块上切换模式。

频率 cache 在 eval 和 train 中应保持一致。

### 8.22 分布式训练

频率 cache 可以每个 rank 本地生成。

它不需要梯度，也不需要 all-reduce。

position_ids 需要与对应 batch shard 对齐。

sequence parallel 场景下，局部 shard 可能从非零全局位置开始。

不能在每个 shard 内都从 0 重新生成，除非模型明确采用局部位置。

### 8.23 单元测试清单

测试 `dim` 为奇数时抛错。

测试位置 0 输出等于输入。

测试旋转保持二范数。

测试相对距离分数与共同平移一致。

测试 Q/K 不同 position_ids 的广播。

测试 partial rotary 的 passthrough。

测试 prefill 和 decode 一致。

### 8.24 生产监控指标

监控实际最大 position_id。

监控每请求的 cache 长度。

监控 RoPE scaling factor 是否符合配置。

监控 attention logits 的均值和方差。

监控长请求的困惑度代理指标。

监控超长请求的生成重复率。

异常位置编号应尽早报警。

### 8.25 常见代码审查问题

`inv_freq` 是否包含了错误的偶数索引。

`cos/sin` 是否复制了两次。

`rotate_half` 是否和布局匹配。

Q/K 是否都应用了相同的旋转 convention。

历史 K 是否被重复旋转。

训练与推理的 base 是否一致。

scaling factor 是否被重复应用。

### 8.26 小结

工业实践的难点不在写出二维旋转。

真正容易出错的是 layout、cache、padding 和 scaling 配置。

LLaMA 提供了清晰的标准骨架。

Qwen 需要认真读取每个 checkpoint 的配置。

DeepSeek 等结构可能把 RoPE 放在压缩子空间中。

任何 fused kernel 都应与参考实现做数值对齐。

## 9. 面试题（18 题）

### 9.1 题目 1：RoPE 解决什么问题？

**问题**：请用一句话说明 RoPE 的核心价值。

**答案**：RoPE 通过对 Q/K 的二维子空间进行位置相关旋转，使 attention 内积自然依赖相对位置差，同时保留多频率位置表示。

**追问**：它是绝对位置编码还是相对位置编码？

**答案**：输入使用绝对 position_ids，但内积性质体现为相对位置，因此通常称为具有相对位置性质的旋转位置编码。

**易错点**：不要说 RoPE 直接把相对距离加到 attention score 上。

### 9.2 题目 2：写出二维旋转公式

**问题**：给出二维旋转矩阵和逐元素公式。

**答案**：

$$
R(\theta)=\begin{bmatrix}\cos\theta&-\sin\theta\\\sin\theta&\cos\theta\end{bmatrix}
$$

$$
x'_0=x_0\cos\theta-x_1\sin\theta
$$

$$
x'_1=x_0\sin\theta+x_1\cos\theta
$$

**检查点**：第二行的符号不能写反。

### 9.3 题目 3：证明相对位置性质

**问题**：证明 $q_m^Tk_n$ 只依赖 $n-m$。

**答案**：

$$
q_m^Tk_n=(R_mq)^T(R_nk)=q^TR_m^TR_nk=q^TR_{n-m}k
$$

关键是 $R_m^T=R_{-m}$，以及旋转矩阵的群性质。

**追问**：共同平移两个位置会怎样？

**答案**：$(m,n)\to(m+c,n+c)$ 后差值不变，因此相对旋转不变。

### 9.4 题目 4：为什么使用复数视角？

**问题**：复数解释比矩阵解释有什么优势？

**答案**：二维旋转等价于乘以 $e^{i\theta}$，位置组合变成复数乘法，结合律和共轭关系可以直接展示相对相位。

**追问**：内积如何表示？

**答案**：使用复数乘积的实部，例如 $\operatorname{Re}(q\overline{k})$。

### 9.5 题目 5：频率公式是什么？

**问题**：RoPE 中第 $j$ 个二维块的频率如何定义？

**答案**：常用定义为 $\theta_j=\operatorname{base}^{-2j/d}$，代码中常通过 `arange(0, dim, 2) / dim` 计算 `inv_freq`。

**易错点**：`theta`、`inv_freq` 的命名在代码中可能互为倒数，要看实际使用方式。

### 9.6 题目 6：为什么 d 必须是偶数？

**问题**：为什么 head dimension 通常要求偶数？

**答案**：RoPE 把相邻两个实数视为一个二维旋转块，奇数维无法完整配对。

**追问**：partial rotary 怎么办？

**答案**：只需确保 `rotary_dim` 为偶数，剩余维度保持不变。

### 9.7 题目 7：为什么只旋转 Q 和 K？

**问题**：为什么不默认旋转 V？

**答案**：Q/K 决定 attention 匹配分数，旋转它们即可引入相对位置；V 负责传递内容，旋转 V 会改变内容聚合的坐标基，不是标准 RoPE 的必要操作。

### 9.8 题目 8：RoPE 与 sinusoidal PE 的区别

**问题**：两者都包含 sin/cos，有什么根本区别？

**答案**：sinusoidal PE 通常加到 hidden states；RoPE 把 sin/cos 作为旋转系数作用在 Q/K 上，位置差会在内积中自然出现。

**追问**：两者是否都使用多频率？

**答案**：通常都使用多频率，但注入位置和代数性质不同。

### 9.9 题目 9：RoPE 与 ALiBi 的区别

**问题**：RoPE 和 ALiBi 各自怎样编码相对位置？

**答案**：RoPE 通过旋转 Q/K 改变内积方向；ALiBi 直接向 logits 添加与距离相关的线性 bias。

**对比**：ALiBi 距离惩罚更直接，RoPE 的内容-位置耦合更灵活。

### 9.10 题目 10：为什么 base 越大可以帮助长上下文？

**问题**：解释增大 base 的直觉。

**答案**：增大 base 会降低部分维度的角频率、拉长波长，使长位置下相位变化更慢，推迟相位混叠。

**代价**：局部高频分辨率可能下降。

### 9.11 题目 11：什么是线性位置插值？

**问题**：训练 4K、推理 32K 时如何做线性插值？

**答案**：扩展倍率 $s=8$，将 position_ids 或相位对应的位置压缩为 $m/s$，再使用原始频率计算 cos/sin。

**缺点**：所有频率统一压缩，可能损失局部位置精度。

### 9.12 题目 12：什么是 NTK-aware scaling？

**问题**：给出常见公式并说明作用。

**答案**：常见形式为 $base'=base\cdot s^{d/(d-2)}$，通过改变频率谱而不是简单缩放所有位置，改善长上下文相位分布。

**易错点**：不要把 scaling factor 直接当成新的 base，公式中通常还包含维度指数。

### 9.13 题目 13：YaRN 做了什么？

**问题**：YaRN 相比简单插值增加了什么？

**答案**：它通常按波长对维度进行分段或平滑插值，并结合 attention temperature scaling，配合少量继续训练提升长上下文能力。

**追问**：为什么需要 temperature？

**答案**：位置变换会改变 logits 的统计尺度，温度修正有助于保持 attention 分布稳定。

### 9.14 题目 14：LongRoPE 的核心思想

**问题**：LongRoPE 为什么采用维度相关缩放？

**答案**：不同频率承载不同距离尺度，使用 $s_j$ 为每个频率单独缩放，可以同时保护局部高频和全局低频信息。

**注意**：具体缩放向量依赖模型和训练方案，不能凭空套固定数值。

### 9.15 题目 15：KV cache 中如何使用 RoPE？

**问题**：decode 时新 query 和历史 key 怎样旋转？

**答案**：历史 key 在写入 cache 前按各自位置旋转；新 query 按当前绝对位置旋转；历史 K 不应在每一步重复旋转。

**追问**：`start_pos` 是什么？

**答案**：它表示当前输入 token 在全局序列中的起始位置，必须与 cache 长度或 position_ids 协议一致。

### 9.16 题目 16：如何验证 prefill 与 decode 一致？

**问题**：给出最小测试方案。

**答案**：固定模型和输入，分别用一次性 full forward 与逐 token KV cache forward，比较每个位置的 logits，允许小范围浮点误差。

**必须覆盖**：非零起始位置、长序列、不同 batch 长度和 rope scaling。

### 9.17 题目 17：代码中 cos/sin shape 如何广播？

**问题**：Q 的形状为 `(B,H,S,D)`，position_ids 为 `(B,S)`，cos/sin 形状应如何组织？

**答案**：常见组织为 `(B,1,S,D)`，在 head 维广播；也有实现先得到 `(B,S,D)` 再 `unsqueeze(1)`。

**易错点**：不要让 batch 维和 head 维错位广播。

### 9.18 题目 18：发现长文本质量下降怎么排查？

**问题**：列出排查顺序。

**答案**：

1. 打印训练长度、目标长度和实际最大 position_id。

2. 检查 `rope_theta/base` 是否与 checkpoint 一致。

3. 检查 scaling 是否被重复应用。

4. 检查 Q、K 的旋转维度和 layout。

5. 检查 prefill/decode 的位置连续性。

6. 检查 attention logits 的均值、方差和 softmax 熵。

7. 用短上下文回归测试确认基础能力没有退化。

8. 用长文检索和 needle 测试定位能力边界。

### 9.19 手写题：实现 rotate_half

```python
def rotate_half_interleaved(x):
    d = x.size(-1)
    assert d % 2 == 0
    pairs = x.view(*x.shape[:-1], d // 2, 2)
    a, b = pairs.unbind(-1)
    return torch.stack((-b, a), dim=-1).flatten(-2)
```

需要说明 `view` 前的连续性要求。

如果输入来自 transpose，可能需要 `contiguous()`。

### 9.20 手写题：实现 RoPE

```python
def apply_rope_torch(x, position_ids, base=10000.0):
    d = x.size(-1)
    assert d % 2 == 0
    inv_freq = 1.0 / (base ** (torch.arange(0, d, 2, device=x.device).float() / d))
    angles = position_ids.float()[..., None] * inv_freq
    cos = angles.cos().repeat_interleave(2, dim=-1).unsqueeze(1)
    sin = angles.sin().repeat_interleave(2, dim=-1).unsqueeze(1)
    return x * cos + rotate_half_interleaved(x) * sin
```

这个版本假设 `x` 的形状为 `(B,H,S,D)`。

如果 position_ids 是 `(S,)`，需要额外扩展 batch 维。

### 9.21 手写题：实现 dynamic NTK

```python
def dynamic_base(base, factor, seq_len, original_len, dim):
    if seq_len <= original_len:
        return base
    ratio = factor * seq_len / original_len - (factor - 1.0)
    return base * ratio ** (dim / (dim - 2.0))
```

面试时要声明这是常见形式。

不同库可能有不同 factor 定义和边界处理。

### 9.22 系统设计题：支持 128K 上下文

**问题**：如何从 4K 模型扩展到 128K？

**答案框架**：

第一，选择 YaRN、LongRoPE 或 Dynamic NTK 作为位置方案。

第二，准备覆盖多种长度和跨段依赖的继续训练数据。

第三，优化 KV cache、GQA 和 attention kernel。

第四，加入短上下文回归，防止原能力退化。

第五，使用困惑度、检索、长文问答和生成稳定性评测。

第六，监控显存、吞吐、首 token 延迟和 decode 延迟。

### 9.23 反问陷阱：改 max_position_embeddings 就够了吗？

**答案**：不够。

它通常只是允许框架接受更大的 position_id。

如果频率仍按原训练长度使用，模型会遇到未训练的相位分布。

如果只改频率而不做继续训练，能力也可能不稳定。

还需要确认显存和 attention 计算是否能够支持新长度。

### 9.24 反问陷阱：RoPE 能解决复杂度问题吗？

**答案**：不能。

RoPE 是位置编码机制，常规 attention 复杂度仍是 $O(n^2)$。

它不会自动减少 KV cache，也不会自动变成线性 attention。

长上下文系统需要单独的稀疏 attention、压缩和缓存策略。

### 9.25 反问陷阱：相对位置意味着没有绝对位置信息吗？

**答案**：不是。

RoPE 使用绝对位置计算旋转角度。

相对位置性质指的是 Q/K 内积可以化为位置差。

mask、边界、训练分布和 position_ids 仍然会让模型感知序列的绝对结构。

### 9.26 一页速记

二维：$R(\theta)$ 旋转一个 pair。

频率：$\theta_j=base^{-2j/d}$。

位置：角度为 $m\theta_j$。

相对性：$R_m^TR_n=R_{n-m}$。

实现：`x * cos + rotate_half(x) * sin`。

对象：标准 RoPE 旋转 Q、K，不旋转 V。

缓存：K 按原位置旋转一次，不能重复旋转。

长文：linear、NTK-aware、Dynamic NTK、YaRN、LongRoPE。

验证：位置 0、范数、平移、full/decode 对齐。

生产：检查 layout、padding、cache_position、dtype 和 scaling。
