# 6.8 长上下文与注意力变体

---

## 1. 长上下文的两大瓶颈

1. **计算/显存**: 注意力 $O(n^2)$, KV Cache 随序列线性增长(见 [6.3 KV Cache](第06章-03-KV-Cache.md))。
2. **外推**: 训练时短(如 4K), 推理时长(如 128K), 位置编码没见过 → 性能崩。

---

## 2. 稀疏与滑动窗口注意力

不让每个 token 关注全部, 只关注局部/少量全局:

| 变体 | 关注范围 | 复杂度 |
| :--- | :--- | :--- |
| 滑动窗口(Mistral) | 前 $w$ 个 | $O(nw)$ |
| Dilated/Longformer | 局部 + 少量全局 | $O(n)$ |
| BigBird | 局部+随机+全局 | $O(n)$ |
| Streaming(StreamingLLM) | 起始 sink + 近窗 | $O(nw)$ |

### 手撕滑动窗口掩码

```python
import torch
def sliding_window_mask(n, w):
    """每个位置只能看前 w 个 (含自己) 的因果滑窗掩码"""
    i = torch.arange(n).unsqueeze(1)
    j = torch.arange(n).unsqueeze(0)
    mask = (j <= i) & (j > i - w)          # 因果 + 窗口下界
    return mask                             # True 为可见
```

> **Attention Sink**: StreamingLLM 发现保留最初几个 token(sink)对稳定长生成很关键——它们吸收了大量注意力。

## 3. RoPE 位置外推

RoPE(见 [6.2 旋转位置编码](第06章-02-旋转位置编码.md))按频率旋转。直接外推到更长会因高频项"转过头"而崩。解法:

| 方法 | 思想 |
| :--- | :--- |
| **位置插值(PI)** | 把位置线性压缩到训练范围内 |
| **NTK-aware** | 按频率非均匀缩放, 高频少缩、低频多缩 |
| **YaRN** | NTK + 温度校正, 少量微调即可扩到数十倍 |

```python
def ntk_scaled_rope_base(base, orig_len, new_len, dim):
    """NTK-aware: 调整 RoPE 底数以外推 (无需重训)"""
    scale = new_len / orig_len
    return base * scale ** (dim / (dim - 2))   # 放大底数 = 拉长波长
```

---

## 4. 分布式长上下文: Ring Attention

单卡放不下超长序列的 KV。**Ring Attention** 把序列分块到多卡, 各卡算局部注意力, KV 块在卡间**环形传递**, 计算与通信重叠, 支持百万级上下文。与 FlashAttention 的分块思想一脉相承(见 [6.4 Flash Attention](第06章-04-Flash-Attention.md))。

---

## 5. 方案选型

- **中等长度(≤32K)**: FlashAttention + RoPE 插值/YaRN 足够。
- **长(128K+)**: 滑窗/稀疏 + StreamingLLM sink。
- **超长(1M+)**: Ring Attention 多卡分块。
- **推理省显存**: GQA + KV 量化 + PagedAttention(见 [9.4](../第09章-推理优化/第09章-04-PagedAttention.md))。

---

## 6. 面试高频

1. 长上下文两大难点? → $O(n^2)$ 成本 + 位置外推。
2. 滑动窗口注意力复杂度? → $O(nw)$。
3. RoPE 如何外推不重训? → PI/NTK/YaRN 缩放频率。
4. Ring Attention 解决什么? → 单卡放不下超长 KV, 环形传递分块。
5. Attention Sink 是什么? → 起始 token 吸收大量注意力, 保留可稳定长生成。

## 7. 长上下文: 详细背景与动机

### 7.1 为什么长上下文重要?

**应用场景**:
- 长文档问答 (PDF, books, code)
- 多轮对话 (历史累积)
- 代理任务 (RAG + 长历史)
- 代码仓库级理解 (10万+ 行代码)
- 长视频/音频理解
- 推理链 (Reasoning, CoT)

**工业里程碑**:
- GPT-3 (2020): 2K context
- LLaMA-1 (2022): 2K
- LLaMA-2 (2023): 4K
- Claude-2 (2023): 100K
- GPT-4 Turbo (2023): 128K
- LLaMA-3 (2024): 128K (训练), 1M (外推)
- Claude-3 (2024): 200K
- Gemini-1.5 (2024): 1M (稀疏)
- Magic (2024): 100M (实验)

### 7.2 长上下文的"三大难题"

#### 难题 1: 计算复杂度 $O(n^2)$

**例**: 128K 上下文的 attention 矩阵 = $128K \times 128K = 16G$ 元素 (FP16 32GB)
- 单卡放不下
- 计算量 = 16T FLOPS per token
- 即使 H100 (989 TFLOPS), 也要 16s 才能算完一次 (单 token)

#### 难题 2: KV Cache 显存

**公式**: $\text{KV 显存} = 2 \times L \times H \times D \times N \times \text{bytes}$

**例**: LLaMA-7B (32 layers, 32 heads, head_dim=128), 128K context, batch=1, FP16
$$2 \times 32 \times 32 \times 128 \times 128K \times 2 = 17.2 \text{ GB}$$
> 超过模型权重 (14 GB)!

#### 难题 3: 位置外推

RoPE 训练在 4K, 推理在 128K → 位置编码从未见过的"位置模式" → attention 输出崩坏。

## 8. 稀疏注意力家族 (Sparse Attention)

### 8.1 滑动窗口注意力 (Sliding Window Attention)

**核心思想**: 每个 token 只看前 $w$ 个 token (包括自己)。

**复杂度**: $O(nw)$, 与序列长度 $n$ **线性**, 但与窗口大小 $w$ 相关。

**代表**: Mistral-7B (w=4096, 推理时有效感受野 4096 但通过多层堆叠可达更远)

```python
def sliding_window_mask(n, w, causal=True):
    """
    n: 序列长度
    w: 窗口大小
    causal: 是否因果 (默认 True)
    返回: [n, n] bool mask, True 表示可见
    """
    i = torch.arange(n).unsqueeze(1)
    j = torch.arange(n).unsqueeze(0)
    if causal:
        # 因果 + 窗口下界
        mask = (j <= i) & (j > i - w)
    else:
        # 非因果 (encoder)
        mask = (j > i - w) & (j <= i + w - 1)
    return mask

# 例
mask = sliding_window_mask(10, 3)
# 输出 (True=可见):
# [[T, F, F, F, F, F, F, F, F, F],
#  [T, T, F, F, F, F, F, F, F, F],
#  [T, T, T, F, F, F, F, F, F, F],
#  [F, T, T, T, F, F, F, F, F, F],
#  [F, F, T, T, T, F, F, F, F, F],
#  ...]
```

### 8.2 滑动窗口 + 多层堆叠

**关键洞察**: 单层只看 $w$ 个 token,但 $L$ 层堆叠后, 顶层 token 看到 $L \times w$ 个 token。

**例**: Mistral 32 layers, w=4096 → 顶层 token 感受野 = 128K。

```python
def sliding_window_attention(q, k, v, w, num_layers):
    """
    多层滑动窗口, 每层保持窗口大小 w
    """
    effective_receptive_field = num_layers * w
    return effective_receptive_field
```

### 8.3 Mistral 7B 案例

**架构**:
- 32 layers, 32 heads, head_dim=128
- Sliding Window Attention (w=4096)
- GQA (8 KV heads)

**KV Cache 节省**:
- 标准 attention: KV cache = $32 \times 32 \times 128 \times N$ = 128 MB / 1K tokens
- Sliding Window (w=4096): KV cache = $32 \times 32 \times 128 \times 4096$ = 512 MB (常数!)

**结论**: KV cache 与序列长度**无关**, 仅与窗口大小相关。

### 8.4 Dilated Attention (Longformer 风格)

**核心思想**: 类似 CNN 的 dilated conv, 跳跃式关注。

```python
def dilated_attention_mask(n, w, dilation, causal=True):
    """
    滑动窗口 + dilation (每隔 d 个 token 关注一个)
    """
    i = torch.arange(n).unsqueeze(1)
    j = torch.arange(n).unsqueeze(0)
    # 注意 dilation: 不是 j > i-w, 而是 j ≡ i mod d, j > i - w
    mask = ((j <= i) if causal else True) & ((j > i - w)) & ((j - i) % dilation == 0)
    return mask
```

**复杂度**: $O(n \cdot w / d)$, 等效感受野 $w$, 关注点更稀疏。

### 8.5 Longformer (Beltagy et al., 2020)

**架构**: 局部窗口 + 全局 token (e.g., [CLS])

```python
class LongformerAttention(nn.Module):
    """Longformer 的双注意力模式: 局部 + 全局"""
    def __init__(self, d_model, num_heads, window_size):
        super().__init__()
        self.window = window_size
        # 两套投影
        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_model)
        self.v_proj = nn.Linear(d_model, d_model)
        # 全局 token 标记
        self.is_global = nn.Parameter(torch.zeros(d_model))

    def forward(self, x, global_indices):
        q, k, v = self.q_proj(x), self.k_proj(x), self.v_proj(x)
        B, T, D = q.shape

        # 构建 mask
        i = torch.arange(T).unsqueeze(1)
        j = torch.arange(T).unsqueeze(0)
        window_mask = (j <= i) & (j > i - self.window)
        # 全局 token 总是可见
        is_global_pos = torch.zeros(T, dtype=torch.bool)
        is_global_pos[global_indices] = True
        global_mask = is_global_pos.unsqueeze(0).expand(T, -1)
        mask = window_mask | global_mask  # 局部 OR 全局

        # 标准 attention (带 mask)
        attn = (q @ k.transpose(-1, -2)) / (D ** 0.5)
        attn = attn.masked_fill(~mask.unsqueeze(0).unsqueeze(0), float('-inf'))
        return F.softmax(attn, dim=-1) @ v
```

### 8.6 BigBird (Zaheer et al., 2020)

**三种 attention 模式**:
1. **Window**: 局部窗口
2. **Random**: 每个 token 随机关注 r 个
3. **Global**: 全局 token (cls 等)

**复杂度**: $O(n)$, 理论证明可近似 full attention。

```python
def bigbird_mask(n, w, r, n_global):
    """
    BigBird 三种 attention 的 mask
    """
    i = torch.arange(n).unsqueeze(1)
    j = torch.arange(n).unsqueeze(0)
    mask = torch.zeros(n, n, dtype=torch.bool)

    # 1. Window
    window_mask = (j <= i) & (j > i - w)
    mask |= window_mask

    # 2. Random
    for idx in range(n):
        random_idx = torch.randperm(n)[:r]
        mask[idx, random_idx] = True

    # 3. Global
    global_pos = torch.zeros(n, dtype=torch.bool)
    global_pos[:n_global] = True
    mask |= global_pos.unsqueeze(0) | global_pos.unsqueeze(1)  # 全局 token 互相 + 全部看

    return mask
```

## 9. Attention Sink 与 StreamingLLM

### 9.1 现象

**实验发现** (Xiao et al., 2023):
- 即使 Sliding Window 把窗口设得很小 (e.g., 512), 推理质量也会崩塌
- 但如果保留**最初几个 token** (sink), 推理质量显著恢复
- 原因: 注意力集中在初始 token (无论它们的内容)

**直觉解释**:
- Softmax 的 sum-to-1 约束强迫所有 query 关注某些 token
- 没有明显"语义"目标时, 倾向于关注"通用" token (起始符、句号)
- 这些 token 像"吸水池", 吸收了无目标的注意力

### 9.2 StreamingLLM 架构

**核心思想**: 滑动窗口 + 保留起始 N 个 sink token

```python
class StreamingLLMKVCache:
    """StreamingLLM: sink + 滑动窗口"""
    def __init__(self, num_sink=4, window_size=2048):
        self.num_sink = num_sink
        self.window_size = window_size
        self.k_cache = []  # 累积的 K
        self.v_cache = []

    def append(self, k_new, v_new):
        """每生成 1 个 token 调用"""
        self.k_cache.append(k_new)
        self.v_cache.append(v_new)

    def get(self):
        """返回用于 attention 的 KV"""
        if len(self.k_cache) <= self.num_sink + self.window_size:
            return self.k_cache, self.v_cache

        # 保留 sink + 最近 window
        k_sink = self.k_cache[:self.num_sink]
        k_window = self.k_cache[-self.window_size:]
        v_sink = self.v_cache[:self.num_sink]
        v_window = self.v_cache[-self.window_size:]

        return k_sink + k_window, v_sink + v_window

    def trim(self):
        """修剪过老的非 sink token"""
        if len(self.k_cache) > self.num_sink + self.window_size:
            # 只保留 sink + window
            self.k_cache = (
                self.k_cache[:self.num_sink] +
                self.k_cache[-self.window_size:]
            )
            self.v_cache = (
                self.v_cache[:self.num_sink] +
                self.v_cache[-self.window_size:]
            )
```

**复杂度**: $O(n)$ (window_size 不变), 实测可处理 4M+ tokens。

### 9.3 为什么 Sink 有效 (数学解释)

**Theorem (Xiao et al., 2023)**: 在 softmax attention 中, 总是存在"attractor" token, 它们聚集大量注意力。

**证明草图**:
- Softmax sum-to-1: $\sum_j \alpha_{ij} = 1$
- 如果 query $i$ 没有明确目标, 它的 attention 会"溢出"到少数几个 token
- 这些 token 累积了所有 query 的"溢出", 成为 attractor
- 训练时初始 token (BOS, EOS 等) 经常是 attractor

**实践含义**: 推理时保留 sink = 维持"attractor"存在, 防止新生成的 token 成为无意义的 attractor。

## 10. RoPE 外推深度

### 10.1 为什么 RoPE 外推难?

**RoPE 频率**: $\theta_i = 1/10000^{2i/d}$, $i \in [0, d/2)$

**关键观察**:
- 高频 (小 $i$): 波长短, 表征近距离相对位置
- 低频 (大 $i$): 波长长, 表征远距离相对位置

**外推问题**:
- 训练 4K, 推理 128K
- 位置 128K 的高频项转过 $128K \cdot \theta_0 \approx 128K / 10000^{0/64} = 128K$ 圈
- 已经"转晕", 无法区分不同位置

### 10.2 位置插值 (Position Interpolation, PI)

**Chen et al. (Meta, 2023) 论文**: arxiv.org/abs/2306.15595

**核心思想**: 把位置线性缩放到训练范围
$$m' = m \cdot \frac{L_{\text{orig}}}{L_{\text{new}}}$$

**实现**:
```python
def position_interpolation(m, orig_len=4096, new_len=32768):
    """把绝对位置 m 缩放到 orig_len 范围内"""
    return m * (orig_len / new_len)

# 等价: 在 RoPE 计算时缩放 freqs
def precompute_freqs_cis_pi(dim, seq_len, orig_len=4096, base=10000.0):
    """PI 版本 RoPE"""
    scale = orig_len / seq_len  # 缩放因子 < 1
    freqs = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
    t = torch.arange(seq_len) * scale  # 关键: 缩放位置
    freqs = torch.outer(t, freqs)
    return torch.polar(torch.ones_like(freqs), freqs)
```

**优点**: 简单, 不需重训 (仅 inference 时改 freqs)。
**缺点**: 高频位置"过密", 短距离相对位置分辨率下降。

### 10.3 NTK-aware Scaling

**bloc97 (2023)** 提出, 改进 PI 的问题。

**核心思想**: 缩放**底数 base** 而非位置, 让低频项拉长波长, 高频项几乎不变。

```python
def ntk_scaled_rope_base(orig_base, orig_len, new_len, dim):
    """
    NTK-aware: 调整 base, 让低频拉长, 高频不变
    公式: new_base = orig_base * scale^(dim/(dim-2))
    """
    scale = new_len / orig_len
    if scale <= 1.0:
        return orig_base
    return orig_base * scale ** (dim / (dim - 2))

def precompute_freqs_cis_ntk(dim, seq_len, orig_seq_len=4096, base=10000.0):
    new_base = ntk_scaled_rope_base(base, orig_seq_len, seq_len, dim)
    freqs = 1.0 / (new_base ** (torch.arange(0, dim, 2).float() / dim))
    t = torch.arange(seq_len)
    freqs = torch.outer(t, freqs)
    return torch.polar(torch.ones_like(freqs), freqs)
```

**直觉**:
- 新 base > 原 base
- 公式 $\theta_i = 1/\text{base}^{2i/d}$, base 大 → $\theta_i$ 小
- $\theta_i$ 小 → 波长 $2\pi / \theta_i$ 大 → 低频项拉长
- 高频项 ($i$ 小) 几乎不受影响

**优点**: 高频保留, 短距离相对位置精确。
**缺点**: 中频段可能有"gap", 长距离不如 YaRN。

### 10.4 YaRN (Yet another RoPE extensioN)

**Peng et al. (Nous Research, 2023)** 论文: arxiv.org/abs/2309.00071

**核心思想**: NTK-aware + 温度缩放 + attention scaling 的组合。

**两个关键技术**:

#### 1. NTK-by-parts (分频段处理)

不同频段用不同策略:
```python
def yarn_find_correction_dim(num_rotations, dim, base=10000.0, max_position_embeddings=2048):
    """
    找到哪些维度需要"插值", 哪些需要"外推", 哪些保持
    """
    inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
    inv_freq_extrapolation = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
    inv_freq_interpolation = 1.0 / (
        base * ((max_position_embeddings / num_rotations) ** (dim / (dim - 2)))
    ) ** (torch.arange(0, dim, 2).float() / dim)

    # 哪些维度需要插值 (波长 > orig_len / 2)
    # 哪些维度需要外推 (波长 < orig_len / 2)
    # 哪些维度保持 (波长 = orig_len / 2)
    extraporate_factor = 1 - find_correction_range(...)
    interpolate_factor = 1 - extraporate_factor

    return interpolate_factor  # 0=外推, 1=插值
```

#### 2. 温度 (Attention Scaling)

```python
def yarn_get_mscale(scale=1.0, mscale=1.0):
    """YaRN 的 attention temperature 缩放"""
    if scale <= 1:
        return 1.0
    return 0.1 * math.log(scale) * mscale
```

**应用方式**: 把 attention logits 乘以 $1/t$
$$S = \frac{QK^T}{t \sqrt{d}}$$

**直觉**: 长上下文时, attention 分布趋于平 (因为 token 多了), 缩放让它更尖锐。

#### 完整 YaRN 实现

```python
class YaRNScaledRotaryEmbedding(nn.Module):
    def __init__(self, dim, max_position_embeddings=2048, base=10000.0,
                 scale=1.0, original_max_position_embeddings=2048,
                 extrapolation_factor=1, attn_factor=1.0, beta_fast=32, beta_slow=1):
        super().__init__()
        self.dim = dim
        self.base = base
        self.scale = scale
        self.original_max_position_embeddings = original_max_position_embeddings

        # NTK-by-parts
        inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2).float() / dim))
        inv_freq_extrap = inv_freq
        inv_freq_interp = self._yarn_find_correction_freq(
            inv_freq, original_max_position_embeddings, beta_fast, beta_slow
        )

        # 按维度混合
        low = max(0, self._yarn_find_correction_dim(
            beta_fast, dim, original_max_position_embeddings))
        high = min(dim - 1, self._yarn_find_correction_dim(
            beta_slow, dim, original_max_position_embeddings))
        inv_freq_mask = (torch.arange(dim // 2) < low).float() * 0 + \
                        (torch.arange(dim // 2) > high).float() * 1
        inv_freq = inv_freq_interp * (1 - inv_freq_mask) + inv_freq_extrap * inv_freq_mask

        self.register_buffer("inv_freq", inv_freq)
        self.mscale = float(self._yarn_get_mscale(scale) * attn_factor)

    def forward(self, x, seq_len):
        t = torch.arange(seq_len, device=x.device, dtype=self.inv_freq.dtype)
        freqs = torch.outer(t, self.inv_freq)
        emb = torch.cat((freqs, freqs), dim=-1)
        return (emb.cos() * self.mscale, emb.sin() * self.mscale)
```

**优点**: 综合 NTK + 温度, 实测可扩展 16-100x。
**缺点**: 超参数较多 (beta_fast, beta_slow, mscale)。

### 10.5 LongRoPE (Microsoft, 2024)

**核心思想**: 用**搜索算法**而非公式, 找最优的 per-dimension 缩放因子。

```python
def longrope_search(original_freqs, target_seq_len, max_search_iters=100):
    """
    进化搜索最优 per-dim 缩放因子
    """
    # 初始化: 每个维度独立的缩放因子
    scales = torch.ones(original_freqs.shape[0])

    # 迭代搜索
    for iter in range(max_search_iters):
        # 用当前 scales 生成外推 freqs
        new_freqs = original_freqs / scales

        # 评估 perplexity (在验证集)
        ppl = evaluate_ppl(new_freqs, target_seq_len)

        # 调整 scales
        scales = mutate(scales, ppl_gradient)

    return scales
```

**优势**: 灵活, 可达 200x 扩展。
**劣势**: 搜索成本高, 每次新模型要重新搜索。

## 11. Ring Attention 深度

### 11.1 核心问题

**单卡放不下超长序列的 KV**:
- LLaMA-7B, 1M context, KV cache = 134 GB (FP16)
- 即使 8 卡 (1TB 总显存), 单卡也不够

### 11.2 Ring Attention 思想

**Liu et al. (UC Berkeley, 2023)** 论文: arxiv.org/abs/2310.01889

**核心思想**:
1. 把 $N$ 长序列切到 $P$ 张卡, 每卡 $N/P$ 段
2. Q 在自己卡上, K/V 在卡间**环形传递**
3. 每步每卡算一段 attention, 累积结果
4. 计算与通信重叠 (compute-comm overlap)

### 11.3 算法流程

```text
设备 P0: Q0, K0, V0, O0 (各 N/P)
设备 P1: Q1, K1, V1, O1
设备 P2: Q2, K2, V2, O2
设备 P3: Q3, K3, V3, O3

Step 0:
  P0: 计算 Q0 @ K0^T, partial softmax
  P1: 计算 Q1 @ K1^T, partial softmax
  P2: 计算 Q2 @ K2^T, partial softmax
  P3: 计算 Q3 @ K3^T, partial softmax
  通信: P0 → P1: K1, V1; P1 → P2: K2, V2; ...

Step 1:
  P0: 计算 Q0 @ K1^T (received from P1)
  ...
```

### 11.4 实现 (简化)

```python
import torch
import torch.distributed as dist

def ring_attention(Q_local, K_ring, V_ring, block_size=128):
    """
    Q_local: 本卡的 Q, [1, H, N/P, D]
    K_ring, V_ring: 环形 buffer, [P, 1, H, N/P, D]
    """
    rank = dist.get_rank()
    world_size = dist.get_world_size()
    H, N_local, D = Q_local.shape[1:]

    # 输出累加器
    O = torch.zeros_like(Q_local)
    m = torch.full((H, N_local), float('-inf'), device=Q_local.device)
    l = torch.zeros(H, N_local, device=Q_local.device)

    send_kv = None
    recv_kv = None

    for step in range(world_size):
        # 1. 等待上一轮 K, V
        if step > 0:
            recv_kv.wait()
        cur_k = K_ring[step]  # 当前轮处理的 K
        cur_v = V_ring[step]

        # 2. 分块计算 attention
        for k_start in range(0, cur_k.shape[2], block_size):
            k_block = cur_k[:, :, k_start:k_start+block_size]
            v_block = cur_v[:, :, k_start:k_start+block_size]

            S = (Q_local @ k_block.transpose(-1, -2)) / (D ** 0.5)
            # 因果 mask (跨卡时需要仔细处理)

            # Online softmax 更新
            m_new = torch.maximum(m.unsqueeze(-1), S.amax(dim=-1, keepdim=True))
            P = torch.exp(S - m_new)
            l_new = torch.exp(m.unsqueeze(-1) - m_new) * l.unsqueeze(-1) + P.sum(dim=-1, keepdim=True)
            O = torch.exp(m.unsqueeze(-1) - m_new) * O + P @ v_block
            m = m_new.squeeze(-1)
            l = l_new.squeeze(-1)

        # 3. 异步发送 K, V 到下一卡
        if step < world_size - 1:
            send_kv = dist.isend(K_ring[(step + 1) % world_size], (rank + 1) % world_size)
            recv_kv = dist.irecv(K_ring[(step + 1) % world_size], (rank - 1) % world_size)

    # 归一化
    O = O / l.unsqueeze(-1)
    return O
```

### 11.5 通信-计算重叠

**关键**: 异步发送 + 同步计算 = 通信时间"隐藏"在计算时间里。

**优化技巧**:
```python
# 双 buffer
K_buf_a, K_buf_b = ...
for step in range(...):
    # 计算用 K_buf_a
    cur_k = K_buf_a
    # 同时异步发 K_buf_b 给下一卡
    async_send(K_buf_b, dst=next_rank)
    # 异步收 K_buf_a 的下一段
    async_recv(K_buf_a, src=prev_rank)
    # 计算...
```

### 11.6 复杂度分析

| 项 | 单卡 | Ring Attention (P 卡) |
|---|---|---|
| 计算量 | $O(n^2)$ | $O(n^2 / P)$ |
| 单卡显存 (KV) | $O(nd)$ | $O(nd/P)$ |
| 通信量 | 0 | $O(nd)$ (总) |

**理想情况**: 通信 < 计算时, 总时间 ~ 单卡时间。

### 11.7 与 Sequence Parallel 的区别

| | Ring Attention | Sequence Parallel |
|---|---|---|
| 切分维度 | KV (序列维) | 输入/输出 |
| 通信模式 | 环形 (KV 流动) | All-Gather / Reduce-Scatter |
| 适用 | 超长序列 attention | 标准 transformer |
| 复杂度 | $O(n^2 / P)$ | $O(n^2)$ (但内存 $O(nd/P)$) |

## 12. 线性注意力与 SSM

### 12.1 线性注意力动机

**目标**: 把 attention 复杂度从 $O(n^2)$ 降到 $O(n)$。

**核心思想**: 用核函数 $\phi$ 替换 softmax, 让计算顺序可交换:
$$\text{Attention}(Q, K, V)_i = \frac{\sum_j \phi(q_i)^T \phi(k_j) v_j}{\sum_j \phi(q_i)^T \phi(k_j)}$$

由于 $(\sum_j \phi(q_i)^T \phi(k_j) v_j) = \phi(q_i)^T (\sum_j \phi(k_j) v_j^T)^T$, 关键是可以**先算 K @ V 再算 Q @ (KV)**, 复杂度 $O(n)$。

### 12.2 Performer (Choromanski et al., 2021)

**核心**: 用随机特征 $\phi$ 近似 softmax。

```python
import torch

def performer_attention(Q, K, V, num_features=256):
    """
    Performer: 随机特征近似 softmax attention
    """
    # 1. 随机特征映射 (FAVOR+)
    # φ(x) = sqrt(1/D) * [exp(g_1 · x), ..., exp(g_D · x)]  (g_i 随机高斯)
    # 或用 ReLU 近似
    random_matrix = torch.randn(Q.shape[-1], num_features)
    Q_prime = torch.relu(Q @ random_matrix) / (num_features ** 0.5)
    K_prime = torch.relu(K @ random_matrix) / (num_features ** 0.5)

    # 2. 计算 K' @ V'  (累积)
    KV = K_prime.transpose(-1, -2) @ V  # [B, H, num_features, D]
    # 3. 计算 Q' @ (K' @ V')
    O = Q_prime @ KV  # [B, H, N, D]

    # 4. 归一化
    K_sum = K_prime.sum(dim=-2, keepdim=True)  # [B, H, 1, num_features]
    Z = (Q_prime @ K_sum.transpose(-1, -2))  # [B, H, N, 1]
    return O / (Z + 1e-6)
```

**复杂度**: $O(N \cdot D^2)$, 与 $N$ 线性。

### 12.3 Linformer

**核心**: 用低秩投影把 K, V 投影到短序列维度。

```python
def linformer_attention(Q, K, V, projection_dim=128):
    """
    Linformer: 投影 K, V 到低维
    """
    # K, V: [B, H, N, D]
    # 投影矩阵: [N, projection_dim] (learned)
    E = torch.randn(Q.shape[2], projection_dim)
    F = torch.randn(Q.shape[2], projection_dim)

    K_proj = K @ E  # [B, H, N, projection_dim]
    V_proj = V @ F
    # 标准 attention
    return (Q @ K_proj.transpose(-1, -2) @ V_proj) / (Q.shape[-1] ** 0.5)
```

**复杂度**: $O(N \cdot D \cdot projection\_dim)$, 线性。

### 12.4 RetNet (Microsoft, 2023)

**核心**: 用指数衰减替代 softmax attention, 维护固定大小状态。

```python
class RetNetBlock(nn.Module):
    """RetNet 的 chunkwise recurrence"""
    def __init__(self, d_model):
        super().__init__()
        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_model)
        self.v_proj = nn.Linear(d_model, d_model)
        self.gate_proj = nn.Linear(d_model, d_model)
        self.out_proj = nn.Linear(d_model, d_model)
        self.gamma = nn.Parameter(torch.tensor(0.999))  # 衰减

    def parallel_forward(self, x):
        """并行模式 (训练)"""
        q = self.q_proj(x)
        k = self.k_proj(x)
        v = self.v_proj(x)
        g = torch.sigmoid(self.gate_proj(x))

        # 衰减矩阵
        N = x.shape[1]
        decay = self.gamma ** torch.arange(N).flip(0).to(x.device)  # [N]
        # Retention: (Q K^T) * decay_mask
        retention = q @ k.transpose(-1, -2) * decay.unsqueeze(0)
        # 因果归一化
        retention = retention / retention.sum(dim=-1, keepdim=True)
        return self.out_proj(retention @ v) * g

    def recurrent_forward(self, x, prev_state):
        """循环模式 (推理)"""
        q = self.q_proj(x[:, -1:])  # 只取最新 token
        k = self.k_proj(x[:, -1:])
        v = self.v_proj(x[:, -1:])

        # 更新状态
        new_state = self.gamma * prev_state + k.transpose(-1, -2) @ v
        # 输出
        output = (q @ new_state) / ((q @ k.cumsum(dim=-2)).sum(dim=-1, keepdim=True) + 1e-6)
        return output, new_state
```

**优势**: 训练时并行 (像 transformer), 推理时 O(1) per step (像 RNN)。

### 12.5 Mamba (Gu & Dao, 2023)

**核心**: 选择性状态空间模型 (Selective SSM), **不依赖 attention**。

```python
class MambaBlock(nn.Module):
    """Mamba block: SSM + 门控"""
    def __init__(self, d_model, d_state=16, expand=2):
        super().__init__()
        d_inner = d_model * expand
        self.in_proj = nn.Linear(d_model, 2 * d_inner)  # 双向 (gate + value)
        self.conv1d = nn.Conv1d(d_inner, d_inner, 3, padding=1, groups=d_inner)
        self.x_proj = nn.Linear(d_inner, d_state * 2 + d_inner)  # delta, B, C
        self.A_log = nn.Parameter(torch.log(torch.arange(1, d_state + 1).float()))
        self.D = nn.Parameter(torch.ones(d_inner))
        self.dt_proj = nn.Linear(d_inner, d_inner)
        self.out_proj = nn.Linear(d_inner, d_model)

    def ssm_scan(self, x, delta, A, B, C, D):
        """
        选择性 SSM 扫描
        x: [B, L, d_inner]
        delta: [B, L, d_inner]
        A: [d_inner, d_state]
        B: [B, L, d_state]
        C: [B, L, d_state]
        """
        # 离散化
        dA = torch.exp(delta.unsqueeze(-1) * A)  # [B, L, d_inner, d_state]
        dB = delta.unsqueeze(-1) * B.unsqueeze(-2)  # [B, L, d_inner, d_state]

        # 选择性扫描 (并行)
        # h_t = dA_t * h_{t-1} + dB_t * x_t
        h = torch.zeros_like(dA[:, 0])
        outputs = []
        for t in range(x.shape[1]):
            h = dA[:, t] * h + dB[:, t] * x[:, t].unsqueeze(-1)
            outputs.append((h * C[:, t].unsqueeze(-2)).sum(-1))
        return torch.stack(outputs, dim=1)

    def forward(self, x):
        B, L, D = x.shape
        xz = self.in_proj(x)  # [B, L, 2*d_inner]
        x, z = xz.chunk(2, dim=-1)

        # Conv1d
        x = self.conv1d(x.transpose(-1, -2)).transpose(-1, -2)[:, :L]

        # SSM 参数
        x_proj = self.x_proj(x)
        delta, B_ssm, C_ssm = x_proj.split([self.d_inner // 4, self.d_state, self.d_state], dim=-1)
        delta = F.softplus(self.dt_proj(delta))

        # SSM 扫描
        A = -torch.exp(self.A_log)  # [d_inner, d_state]
        y = self.ssm_scan(x, delta, A, B_ssm, C_ssm, self.D)

        # 门控
        y = y * F.silu(z)
        return self.out_proj(y)
```

**优势**:
- **O(n)** 训练 (并行扫描)
- **O(1)** 推理 (固定状态)
- 性能匹配 Transformer
- 长序列优势明显

**劣势**:
- 缺乏精确检索能力 (vs attention)
- 生态不成熟
- 难与现有 transformer 工具链兼容

### 12.6 Mamba-2 (Dao & Gu, 2024)

**核心**: 把 SSM 与 Attention 统一在 SSD (State Space Duality) 框架下, 性能提升 2-8x。

```python
class Mamba2Block(nn.Module):
    """Mamba-2: SSD 框架"""
    def __init__(self, d_model, d_state=64, chunk_size=256):
        super().__init__()
        self.chunk_size = chunk_size
        self.in_proj = nn.Linear(d_model, 2 * d_model)
        self.conv1d = nn.Conv1d(d_model, d_model, 3, padding=1, groups=d_model)
        self.out_proj = nn.Linear(d_model, d_model)
        # SSD 简化: A 标量化, B/C 仍依赖输入

    def forward(self, x):
        # 1. 投影
        xz = self.in_proj(x)
        x, z = xz.chunk(2, dim=-1)
        x = self.conv1d(x.transpose(-1, -2)).transpose(-1, -2)

        # 2. 分 chunk, 每个 chunk 内用 SSD (类似 attention)
        chunks = x.split(self.chunk_size, dim=1)
        outputs = []
        state = None
        for chunk in chunks:
            # SSD: 块内 attention + 块间 recurrence
            Q, K, V = chunk.chunk(3, dim=-1)
            # 块内 attention (用 chunk 级参数)
            attn = F.softmax(Q @ K.transpose(-1, -2), dim=-1)
            intra = attn @ V
            # 块间通过 state
            if state is not None:
                inter = state
            outputs.append(intra + inter)
            # 更新 state
            state = state * decay + K.transpose(-1, -2) @ V

        return self.out_proj(torch.cat(outputs, dim=1) * F.silu(z))
```

## 13. MoBA: Mixture of Block Attention

**Lu et al. (2024)** 论文: arxiv.org/abs/2402.17427

**核心思想**: 让模型**自己选**关注哪些 block, 而非固定稀疏模式。

```python
class MoBAAttention(nn.Module):
    """MoBA: 每个 query 选 top-k 个 KV block"""
    def __init__(self, d_model, num_heads, block_size=1024, top_k_blocks=3):
        super().__init__()
        self.block_size = block_size
        self.top_k = top_k_blocks
        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_model)
        self.v_proj = nn.Linear(d_model, d_model)

    def forward(self, x, kv_cache=None):
        B, L, D = x.shape
        q = self.q_proj(x).view(B, L, -1, D // (D // 64))
        # 这里简化, 假设所有 token 在一个 head

        # 1. 把 K, V 分 block
        if kv_cache is not None:
            k_full = torch.cat([kv_cache['k'], self.k_proj(x)], dim=1)
            v_full = torch.cat([kv_cache['v'], self.v_proj(x)], dim=1)
        else:
            k_full = self.k_proj(x)
            v_full = self.v_proj(x)

        n_blocks = (k_full.shape[1] + self.block_size - 1) // self.block_size
        # 每 block 的 "代表" (e.g., mean of K)
        block_reps = k_full.view(B, n_blocks, self.block_size, -1).mean(dim=2)

        # 2. 每个 query 选 top-k blocks (基于 query 与 block rep 的相似度)
        scores = q @ block_reps.transpose(-1, -2)  # [B, L, n_blocks]
        top_k_blocks = scores.topk(self.top_k, dim=-1).indices  # [B, L, k]

        # 3. 只对选中的 block 做 attention
        # (这里简化, 实际需要 gather/scatter)
        mask = torch.zeros(B, L, k_full.shape[1])
        for b_idx in range(n_blocks):
            is_selected = (top_k_blocks == b_idx).any(dim=-1)  # [B, L]
            mask[:, :, b_idx*self.block_size:(b_idx+1)*self.block_size] = is_selected.unsqueeze(-1).float()
        # 因果: 不能看未来
        causal_mask = torch.tril(torch.ones(L, k_full.shape[1]))
        mask = mask * causal_mask

        # 标准 attention (带 mask)
        attn = (q @ k_full.transpose(-1, -2)) / (D ** 0.5)
        attn = attn.masked_fill(mask.unsqueeze(1) == 0, float('-inf'))
        return F.softmax(attn, dim=-1) @ v_full
```

**优势**: 数据驱动的稀疏, 比固定模式更灵活。

## 19. 长上下文面试题精选

### Q1: 长上下文两大难点?

**答**:
- **$O(n^2)$ 计算/显存**: attention 矩阵随序列长度平方增长
- **位置外推**: 训练短推理长, 位置编码没见过

### Q2: 滑动窗口注意力复杂度? 多层堆叠后感受野?

**答**:
- 单层: $O(nw)$ ($w$ 窗口大小)
- 多层 (L 层): 顶层 token 感受野 $L \times w$
- 例: Mistral 32 layers, w=4096, 顶层感受野 = 128K

### Q3: Attention Sink 是什么? 为什么有效?

**答**:
- **现象**: 训练后的 attention 集中在起始几个 token
- **原因**: softmax sum-to-1 约束, 无目标 query 注意力"溢出"到 attractor
- **应用**: StreamingLLM 保留前 N 个 sink token, 稳定长生成
- **实测**: 4M+ tokens 仍稳定

### Q4: RoPE 外推方法对比?

**答**:

| 方法 | 训练 | 公式 | 适用 |
|---|---|---|---|
| PI | 无 | $m \cdot s^{-1}$ | 简单场景 |
| NTK-aware | 无 | base × s^(d/(d-2)) | 8-16x 扩展 |
| YaRN | 少量 | NTK + 温度 + attention | 16-100x |
| LongRoPE | 1-10B tokens | per-dim 搜索 | 100x+ |

### Q5: Ring Attention 解决什么?通信模式?

**答**:
- **解决**: 单卡放不下超长 KV
- **方法**: 序列切到多卡, KV 块环形传递, 计算与通信重叠
- **复杂度**: 计算 $O(n^2/P)$, 通信 $O(nd)$
- **应用**: 1M+ context 训练/推理

### Q6: Mamba 比 Transformer 优势? 局限?

**答**:
- **优势**:
  - 推理 O(1) (vs O(n))
  - 训练 O(n) (并行扫描)
  - 长序列天然友好 (无位置编码问题)
- **局限**:
  - **检索能力弱**: 无法精确检索早期 token
  - 生态不成熟
  - 训练难 (parallel scan 复杂)

### Q7: Linear Attention 如何做到 O(n)?

**答**:
- 把 softmax 替换为可分解的核函数 $\phi$
- 利用 $(\sum_j \phi(q)^T \phi(k_j) v_j) = \phi(q)^T (\sum_j \phi(k_j) v_j^T)^T$
- 计算顺序变为: 先算 K@V (累积), 再算 Q@(KV)
- 复杂度 $O(ND^2)$

### Q8: StreamingLLM 与 Sliding Window 区别?

**答**:
- **Sliding Window**: 丢弃早期 token, KV 缓存有限
- **StreamingLLM**: 保留前 N 个 sink + 滑动窗口
- **StreamingLLM 优势**: 保留 sink 避免 attention 崩塌
- **实测**: StreamingLLM 可处理 4M+ tokens, Sliding Window 仅 16K-64K

### Q9: GQA 为什么能省 KV? 与 MQA 区别?

**答**:
- **MQA**: 所有 query head 共享 1 个 KV
- **GQA**: query 分组, 每组共享 1 个 KV (e.g., 8:1)
- **节省**: KV 减少到 $n_{kv}/n_q$
- **GQA 优势**: 比 MQA 质量好, 比 MHA 省显存

### Q10: 如何评测长上下文模型?

**答**:
- **Needle-in-a-Haystack**: 检索能力
- **RULER**: 综合 (检索 + 推理 + 多跳)
- **LongBench**: 多任务
- **真实任务**: 摘要, 问答
- **评测发现**: 检索容易, 多跳推理难

## 26. 长上下文实验代码

### 26.1 实验: 滑动窗口 vs 全 attention 速度

```python
import torch
import torch.nn.functional as F
import time

def full_attention(q, k, v):
    """标准 O(n²) attention"""
    scale = q.shape[-1] ** -0.5
    attn = (q @ k.transpose(-1, -2)) * scale
    return F.softmax(attn, dim=-1) @ v

def sliding_window_attention(q, k, v, w=512):
    """O(nw) 滑窗 attention"""
    B, H, N, D = q.shape
    O = torch.zeros_like(q)
    for i in range(N):
        start = max(0, i - w + 1)
        k_win = k[:, :, start:i+1]
        v_win = v[:, :, start:i+1]
        scale = D ** -0.5
        attn = (q[:, :, i:i+1] @ k_win.transpose(-1, -2)) * scale
        O[:, :, i:i+1] = F.softmax(attn, dim=-1) @ v_win
    return O

# 对比
for n in [1024, 2048, 4096, 8192]:
    q = torch.randn(1, 4, n, 64, device='cuda')
    k = torch.randn(1, 4, n, 64, device='cuda')
    v = torch.randn(1, 4, n, 64, device='cuda')

    torch.cuda.synchronize()
    t0 = time.time()
    full_attention(q, k, v)
    torch.cuda.synchronize()
    t_full = time.time() - t0

    torch.cuda.synchronize()
    t0 = time.time()
    sliding_window_attention(q, k, v, w=512)
    torch.cuda.synchronize()
    t_window = time.time() - t0

    print(f"n={n}: full={t_full*1000:.2f}ms, window={t_window*1000:.2f}ms, "
          f"speedup={t_full/t_window:.2f}x")
```

### 26.4 实验: Ring Attention 模拟

```python
def simulate_ring_attention(num_devices=4, seq_len=4096, head_dim=64):
    """模拟 Ring Attention (单进程模拟)"""
    H = 8
    N_per = seq_len // num_devices

    # 模拟数据
    Qs = [torch.randn(1, H, N_per, head_dim) for _ in range(num_devices)]
    Ks = [torch.randn(1, H, N_per, head_dim) for _ in range(num_devices)]
    Vs = [torch.randn(1, H, N_per, head_dim) for _ in range(num_devices)]

    Os = []
    for rank in range(num_devices):
        Q = Qs[rank]
        # 本卡 Q + 接收到的 K/V
        K_ring = [Ks[(rank + step) % num_devices] for step in range(num_devices)]
        V_ring = [Vs[(rank + step) % num_devices] for step in range(num_devices)]

        # 累加 attention
        O = torch.zeros_like(Q)
        m = torch.full((H, N_per), float('-inf'))
        l = torch.zeros(H, N_per)

        for step, (k, v) in enumerate(zip(K_ring, V_ring)):
            S = (Q @ k.transpose(-1, -2)) / (head_dim ** 0.5)
            m_new = torch.maximum(m.unsqueeze(-1), S.amax(dim=-1, keepdim=True))
            P = torch.exp(S - m_new)
            l_new = torch.exp(m.unsqueeze(-1) - m_new) * l.unsqueeze(-1) + P.sum(dim=-1, keepdim=True)
            O = torch.exp(m.unsqueeze(-1) - m_new) * O + P @ v
            m = m_new.squeeze(-1)
            l = l_new.squeeze(-1)

        O = O / l.unsqueeze(-1)
        Os.append(O)

    # 拼接
    return torch.cat(Os, dim=2)
```

1. **Flash Attention**: 降低 IO
2. **Sliding Window**: KV cache 与序列长度无关
3. **GQA / MLA**: 减少 KV
4. **Ring Attention**: 多卡并行
5. **量化**: 减少权重读时间
6. **Prefix Caching**: 复用 system prompt

### Q: 训练长上下文模型的关键?

**答**:
1. **位置编码**: RoPE 缩放 (NTK/YaRN)
2. **数据**: 长文档训练数据
3. **优化器**: 降低显存 (gradient checkpointing)
4. **分布式**: Ring Attention / Sequence Parallel
5. **评测**: LongBench, RULER, 真实任务

### Q: 长上下文 vs RAG, 如何选?

**答**:
- **RAG**: 检索效率高, 但丢失全局结构
- **长上下文**: 全局理解, 但推理慢
- **混合**: RAG 粗筛 + 长 context 精读 (前沿方向)

### Q: 128K vs 1M context 差距大吗?

**答**:
- 128K: 已成熟 (LLaMA-3, Qwen)
- 1M: 外推 (Gemini 1.5, LLaMA-3.1) 质量仍下降
- 实际应用 32K-128K 居多

### Q: 长上下文一定会用到全部信息吗?

**答**:
- **Lost in the Middle** (Liu et al., 2023): 中间信息丢失
- 模型对开头/结尾更敏感
- 多跳推理仍差 (RULER benchmark)
- "长 ≠ 全部用上"

1. **长上下文难题**: $O(n^2)$ + 位置外推

## 32. 注意力稀疏性深入

### 32.1 稀疏 vs 稠密

**稠密 attention**: 每个 query 看所有 key
$$\text{Attn}(q, K, V)_i = \sum_j \alpha_{ij} v_j, \quad \alpha_{ij} = \text{softmax}(q_i k_j)$$

**稀疏 attention**: 每个 query 只看部分 key
$$\text{Attn}(q, K, V)_i = \sum_{j \in S_i} \alpha_{ij} v_j$$
其中 $S_i$ 是 query $i$ 的可见集合。

### 32.2 稀疏模式分类

#### 按模式分

| 模式 | 描述 | 例子 |
|---|---|---|
| **局部 (Local)** | 看邻近 token | Sliding Window |
| **Dilated (扩张)** | 每隔 d 个看一个 | Longformer |
| **块稀疏 (Block)** | 看整块 | BigBird, Longformer |
| **随机 (Random)** | 随机抽样 | BigBird |
| **全局 (Global)** | 看特定 token (e.g., CLS) | Longformer, BigBird |
| **Strided** | 跳着看 | Sparse Transformer |

#### 按 token 类型分

| 类型 | 谁看谁 | 例子 |
|---|---|---|
| **Sink** | 所有 query 看 sink | StreamingLLM |
| **Global** | 全部 token 看 global token | Longformer |
| **Random** | 随机 attention | BigBird |

### 32.3 稀疏模式的理论基础

**Theorem (BigBird, Zaheer et al., 2020)**: Local + Global + Random 足够近似 full attention。

**证明思路**:
- Local 保证相邻 token 充分通信
- Random 保证长距离信息可以传递 (with high probability)
- Global token 作为"信息汇聚点"

**复杂度**: $O(L \cdot w + L \cdot r + g \cdot L)$, 其中 $w$ 窗口, $r$ 随机数, $g$ 全局数。
- 选 $w = r = g = O(\sqrt{L})$ → 总 $O(L \cdot \sqrt{L})$
- 选 $w$ 固定, $r = g = O(1)$ → 总 $O(L \cdot w)$

### 32.4 滑动窗口 + 跨层信息流

**问题**: 单层 sliding window 感受野有限, 如何让它能"看到"远方?

**解法 1: 多层堆叠**
- L 层, 每层 w 窗口
- 顶层感受野 = L × w
- 例: Mistral 32 layers × 4096 window = 128K 顶层感受野

**解法 2: 偶尔插入全 attention**
- 每 N 层插入 1 层 full attention
- 提供"信息汇总"能力

**解法 3: 跨层 attention (LongLLaMA)**
- 短层用 sliding window
- 长层用 full attention
- 顶层 token 可看到全部

## 33. RoPE 数学深度

### 33.1 复数表示

**RoPE 用复数乘法表示旋转**:
$$\text{RoPE}(q, m) = q \cdot e^{im\theta}$$
其中 $q, e^{im\theta} \in \mathbb{C}$, 乘法是复数乘法。

**实现 (PyTorch)**:
```python
def rope_complex(q, m, theta):
    """复数版 RoPE"""
    # q 是复数张量
    rot = torch.exp(1j * m * theta)
    return q * rot
```

### 33.2 矩阵表示

**多维 RoPE 用块对角矩阵**:
$$R_m = \begin{pmatrix} R(\theta_0 m) & 0 & \cdots & 0 \\ 0 & R(\theta_1 m) & \cdots & 0 \\ \vdots & \vdots & \ddots & \vdots \\ 0 & 0 & \cdots & R(\theta_{d/2-1} m) \end{pmatrix}$$

其中每个 $R(\theta_i m)$ 是 $2 \times 2$ 旋转矩阵:
$$R(\theta m) = \begin{pmatrix} \cos(\theta m) & -\sin(\theta m) \\ \sin(\theta m) & \cos(\theta m) \end{pmatrix}$$

### 33.3 相对位置性质证明

**Claim**: $\langle \text{RoPE}(q, m), \text{RoPE}(k, n) \rangle = g(q, k, m - n)$, 即只依赖相对位置。

**证明**:
$$\langle \text{RoPE}(q, m), \text{RoPE}(k, n) \rangle = (\text{RoPE}(q, m))^T \cdot \text{RoPE}(k, n)$$
$$= (R_m q)^T (R_n k)$$
$$= q^T R_m^T R_n k$$

利用 $R_m^T R_n = R_{m-n}$ (旋转矩阵的转置-乘法性质):
$$= q^T R_{m-n} k = g(q, k, m - n)$$

**验证**: 旋转矩阵 $R(\theta)$ 是正交矩阵, $R(\theta)^T = R(-\theta)$, $R(\theta)^T R(\phi) = R(\phi - \theta)$。

### 33.4 RoPE 与远程衰减 (Remote Decay)

**现象**: RoPE 训练后, attention 权重随相对距离增加而衰减。

**原因**:
- 高频项 ($i$ 小) → 旋转快 → 不同时刻 $q, k$ 的相位差大 → 注意力低
- 低频项 ($i$ 大) → 旋转慢 → 不同时刻 $q, k$ 的相位差小 → 注意高

**后果**: RoPE 天然倾向于关注"中等距离" token, 这是 transformer 的归纳偏置之一。

### 33.5 RoPE 与 Long Context

**训练 4K, 推理 32K 的具体表现**:
- 位置 $m > 4K$ 的 RoPE 输出, 在训练时从未见过
- 旋转角度 $m \theta_i$ 可能很大, 导致数值不稳定
- 频率"转过头", 不同位置编码混淆

**NTK-aware 原理**:
- 增大 base = 减小 $\theta_i$ = 减小旋转角度
- 高频 ($i$ 小) 几乎不变, 低频 ($i$ 大) 拉长
- 类似时间尺度重整化

**YaRN 原理 (补充)**:
- NTK-by-parts: 不同频段用不同策略
- 温度: 把 attention logits 除以 $t > 1$, 让分布更尖锐
- attention scaling: 给 attention 加 scale, 平衡长距离 attention

## 34. Ring Attention 深度补充

### 34.1 因果 mask 跨卡处理

**问题**: 因果 mask 要求每个 token 只看自己之前的 token。跨卡时怎么处理?

**解决方案**: Block-diagonal causal mask
```text
Q0 (rank 0) 只能看 K0/K1/K2/K3 中 "位置 <= 自己位置" 的 token
```

**实现**:
```python
def ring_causal_mask(num_devices, seq_len_per, total_seq_len):
    """
    返回 Ring Attention 的因果 mask
    """
    n = total_seq_len
    mask = torch.zeros(n, n, dtype=torch.bool)
    for i in range(n):
        for j in range(n):
            if j <= i:
                mask[i, j] = True
    return mask
```

**优化**: 实际上只需要判断 $j \leq i$, 直接:
```python
def causal_mask_fast(n):
    i = torch.arange(n).unsqueeze(1)
    j = torch.arange(n).unsqueeze(0)
    return j <= i
```

### 34.2 通信-计算重叠优化

**关键**: 让通信时间"藏在"计算时间里。

**双缓冲策略**:
```python
class DoubleBufferRingAttention:
    def __init__(self):
        self.k_buf = [None, None]
        self.v_buf = [None, None]

    def step(self, q_block, rank, world_size, compute_fn):
        for step in range(world_size):
            # 计算用当前 buf
            cur_buf = step % 2
            next_buf = (step + 1) % 2

            # 异步发下一卡的 KV
            if step < world_size - 1:
                self.send_handle = dist.isend(
                    self.k_buf[next_buf], dst=(rank + 1) % world_size
                )
                self.recv_handle = dist.irecv(
                    self.k_buf[cur_buf],  # 覆盖
                    src=(rank - 1) % world_size,
                )

            # 计算 (与通信重叠)
            output = compute_fn(q_block, self.k_buf[cur_buf])

            # 等待通信完成
            self.recv_handle.wait()

        return output
```

### 34.3 跨卡 softmax 同步

**问题**: 在线 softmax 需要知道全局 max 和 sum, 但每个卡只看到部分数据。

**解法**: 跨卡同步 max 和 sum
```python
def cross_device_online_softmax(local_m, local_l, world_size):
    """合并多个设备的 m, l"""
    # All-Reduce max
    global_m = local_m.clone()
    dist.all_reduce(global_m, op=dist.ReduceOp.MAX)

    # All-Reduce sum (with correction)
    correction = torch.exp(local_m - global_m)
    global_l = (local_l * correction).clone()
    dist.all_reduce(global_l, op=dist.ReduceOp.SUM)

    return global_m, global_l
```

**代价**: 每次 K-block 迭代都要 all-reduce, 但因通信与计算重叠, 总开销不大。

### 34.4 与 Sequence Parallel 关系

| | Ring Attention | Sequence Parallel |
|---|---|---|
| 主要优化目标 | 注意力计算的内存 | 一般 transformer 的内存 |
| 通信模式 | 环形 (KV 流动) | AllGather / ReduceScatter |
| 适用阶段 | 长序列 attention | 整层 (attn + ffn) |
| 通信复杂度 | $O(nd)$ per layer | $O(bs \cdot h)$ per layer |
| 计算复杂度 | $O(n^2 / P)$ | $O(bs^2 / P + bs \cdot h / P)$ |

**注意**: 这两者**正交**, 可以组合使用 (Ring Attention + Sequence Parallel for FFN)。

## 35. SSM 数学补充

### 35.1 状态空间模型 (SSM) 基础

**连续 SSM**:
$$h'(t) = A h(t) + B x(t)$$
$$y(t) = C h(t)$$

其中:
- $x(t) \in \mathbb{R}$: 输入
- $h(t) \in \mathbb{R}^N$: 隐藏状态
- $y(t) \in \mathbb{R}$: 输出
- $A \in \mathbb{R}^{N \times N}$, $B \in \mathbb{R}^{N \times 1}$, $C \in \mathbb{R}^{1 \times N}$

**离散化** (Euler):
$$h_t = \bar{A} h_{t-1} + \bar{B} x_t, \quad \bar{A} = e^{\Delta A}, \bar{B} = (\Delta A)^{-1}(e^{\Delta A} - I) \Delta B$$

### 35.2 S4 (Structured State Space)

**核心**: 让 $A$ 是对角加低秩 (DPLR) 矩阵, 计算高效。

**复杂度**: $O(N \log N)$ (用 FFT 卷积)

### 35.3 Mamba 的"选择性"机制

**关键改进**: 让 $B, C, \Delta$ **依赖输入** (之前是固定的)。

```python
# 旧: 固定 B, C, Δ
B = self.B_proj.weight  # [d_state, d_inner]
C = self.C_proj.weight

# 新 (Mamba): B, C, Δ 都是输入依赖
x_proj = self.x_proj(x)  # [B, L, d_state * 2 + d_inner]
delta = x_proj[..., -d_inner:]  # [B, L, d_inner]
B_input = x_proj[..., :d_state]  # [B, L, d_state]
C_input = x_proj[..., d_state:2*d_state]
```

**效果**:
- 选择性: 模型可以"决定"哪些信息保留到状态
- 解决 S4 的"内容无关"问题
- 性能追平 Transformer

### 35.4 SSD 框架 (State Space Duality)

**Mamba-2 (Dao & Gu, 2024)**: 把 SSM 和 Attention 统一在 SSD 下。

**核心洞察**: 选择性 SSM 可以写成类似 attention 的形式:
$$y_t = \sum_{s \leq t} \text{exp}(\sum_{u=s+1}^{t} a_u) \cdot \text{exp}(b_s x_s) \cdot c_t$$

其中 $a_u = \log(\bar{A}_u)$, $b_s, c_t$ 是输入依赖的系数。

**复杂度**: $O(L^2)$ 但常数小, 实际 $O(L)$ 用 chunked 算法。

### 35.5 SSM vs Transformer 性能对比

| 维度 | Transformer | Mamba | Mamba-2 |
|---|---|---|---|
| 训练 FLOPs | $O(L^2 d)$ | $O(L d N)$ | $O(L d N)$ |
| 训练内存 | $O(L^2 + Ld)$ | $O(Ld + LN)$ | $O(Ld + LN)$ |
| 推理 FLOPs | $O(L d^2)$ | $O(d^2 N)$ | $O(d^2 N)$ |
| 推理内存 | $O(Ld)$ | $O(dN)$ | $O(dN)$ |
| 检索能力 | ✓ | ✗ | ✗ (基本) |
| 长序列 | 慢 | 快 | 快 |

def needle_in_haystack(model, tokenizer, needle, context_length, position_percent):
    """
    Needle-in-a-Haystack 评测
    """
    # 1. 生成 context
    base_text = "The grass is green. The sky is blue. The sun is yellow. Here we go. There and back again. "
    context = base_text * (context_length // len(base_text))

    # 2. 在指定位置插入 needle
    insert_pos = int(len(context) * position_percent)
    context = context[:insert_pos] + needle + context[insert_pos:]

    # 3. 让模型找 needle
    prompt = f"\n\nWhat is the magic number mentioned in the text?"
    inputs = tokenizer(context + prompt, return_tensors="pt").to(model.device)

    # 4. 生成
    output = model.generate(**inputs, max_new_tokens=50)
    response = tokenizer.decode(output[0], skip_special_tokens=True)

    # 5. 检查
    needle_value = "42"
    return needle_value in response

# 测试
for ctx_len in [1024, 4096, 16384, 65536, 131072]:

        print(f"len={ctx_len}, pos={pos_pct:.2f}: {'HIT' if hit else 'MISS'}")

class DocumentEncoder:

```python
class SparseAttention(nn.Module):
    """统一的稀疏 attention 接口"""
    def __init__(self, d_model, num_heads, mode='sliding_window', window=512, n_global=4, n_random=2):
        super().__init__()
        self.mode = mode
        self.window = window
        self.n_global = n_global
        self.n_random = n_random
        self.num_heads = num_heads
        self.d_model = d_model
        self.head_dim = d_model // num_heads

        self.q_proj = nn.Linear(d_model, d_model)
        self.k_proj = nn.Linear(d_model, d_model)
        self.v_proj = nn.Linear(d_model, d_model)
        self.out_proj = nn.Linear(d_model, d_model)

    def get_mask(self, seq_len):
        """根据模式返回 mask"""
        i = torch.arange(seq_len).unsqueeze(1)
        j = torch.arange(seq_len).unsqueeze(0)
        device = i.device

        if self.mode == 'sliding_window':
            mask = (j <= i) & (j > i - self.window)
        elif self.mode == 'longformer':
            # 局部 + 全局
            local = (j <= i) & (j > i - self.window // 2)
            is_global = torch.zeros(seq_len, dtype=torch.bool, device=device)
            is_global[:self.n_global] = True
            global_mask = is_global.unsqueeze(0) | is_global.unsqueeze(1)
            mask = local | global_mask
        elif self.mode == 'bigbird':
            # 局部 + 全局 + 随机
            local = (j <= i) & (j > i - self.window // 3)
            is_global = torch.zeros(seq_len, dtype=torch.bool, device=device)
            is_global[:self.n_global] = True
            global_mask = is_global.unsqueeze(0) | is_global.unsqueeze(1)
            # 随机
            random_mask = torch.zeros(seq_len, seq_len, dtype=torch.bool, device=device)
            for idx in range(seq_len):
                rand = torch.randperm(seq_len, device=device)[:self.n_random]
                random_mask[idx, rand] = True
            mask = local | global_mask | random_mask
        elif self.mode == 'streaming':
            # sink + 滑窗
            sink = (j < self.n_global)
            window_mask = (j <= i) & (j > i - self.window)
            mask = sink | window_mask
        else:
            mask = torch.ones(seq_len, seq_len, dtype=torch.bool, device=device)
        return mask

    def forward(self, x):
        B, L, D = x.shape
        q = self.q_proj(x).view(B, L, self.num_heads, self.head_dim).transpose(1, 2)
        k = self.k_proj(x).view(B, L, self.num_heads, self.head_dim).transpose(1, 2)
        v = self.v_proj(x).view(B, L, self.num_heads, self.head_dim).transpose(1, 2)

        # Attention
        scale = self.head_dim ** -0.5
        attn = (q @ k.transpose(-1, -2)) * scale  # [B, H, L, L]

        # 应用 mask
        mask = self.get_mask(L)
        attn = attn.masked_fill(~mask.unsqueeze(0).unsqueeze(0), float('-inf'))

        attn = F.softmax(attn, dim=-1)
        out = (attn @ v).transpose(1, 2).contiguous().view(B, L, D)
        return self.out_proj(out)
```

### 39.2 完整 YaRN 实现

```python
class YaRNRoPE(nn.Module):
    """完整的 YaRN RoPE 实现"""
    def __init__(self, dim, max_position_embeddings=2048, base=10000.0,
                 scale=1.0, original_max_position_embeddings=2048,
                 extrapolation_factor=1, attn_factor=1.0,
                 beta_fast=32, beta_slow=1, finetuned=False):
        super().__init__()
        self.dim = dim
        self.base = base
        self.scale = scale
        self.original_max_position_embeddings = original_max_position_embeddings
        self.extrapolation_factor = extrapolation_factor
        self.attn_factor = attn_factor
        self.beta_fast = beta_fast
        self.beta_slow = beta_slow
        self.finetuned = finetuned

        # 计算修正后的 inv_freq (NTK-by-parts)
        inv_freq = 1.0 / (base ** (torch.arange(0, dim, 2, dtype=torch.float32) / dim))

        if scale != 1.0:
            # 计算需要插值的维度
            low = self._find_correction_dim(beta_fast, dim, original_max_position_embeddings)
            high = self._find_correction_dim(beta_slow, dim, original_max_position_embeddings)

            inv_freq_mask = (
                (torch.arange(dim // 2, dtype=torch.float32) < low).float() * 0.0 +
                (torch.arange(dim // 2, dtype=torch.float32) > high).float() * 1.0
            )

            # 插值部分
            inv_freq_interpolation = 1.0 / (
                scale * (base ** (torch.arange(0, dim, 2, dtype=torch.float32) / dim))
            )
            inv_freq_extrapolation = inv_freq

            # 合并
            inv_freq = inv_freq_interpolation * (1 - inv_freq_mask) + inv_freq_extrapolation * inv_freq_mask

        self.register_buffer("inv_freq", inv_freq)
        self.mscale = float(self._yarn_get_mscale(scale) * attn_factor)

    def _yarn_get_mscale(self, scale=1):
        if scale <= 1:
            return 1.0
        return 0.1 * math.log(scale) + 1.0

    def _find_correction_dim(self, num_rotations, dim, base=10000, max_position_embeddings=2048):
        return (dim * math.log(max_position_embeddings / (num_rotations * 2 * math.pi))) / (
            2 * math.log(base)
        )

    def forward(self, x, seq_len=None):
        if seq_len is None:
            seq_len = x.shape[-2]
        t = torch.arange(seq_len, device=x.device, dtype=self.inv_freq.dtype)
        freqs = torch.outer(t, self.inv_freq)
        emb = torch.cat((freqs, freqs), dim=-1)
        return emb * self.mscale
```

### 39.3 完整 StreamingLLM

```python
class StreamingLLMGenerator:
    """StreamingLLM 风格的流式生成"""
    def __init__(self, model, tokenizer, num_sink=4, window_size=2048):
        self.model = model
        self.tokenizer = tokenizer
        self.num_sink = num_sink
        self.window_size = window_size
        self.reset()

    def reset(self):
        """重置状态"""
        self.k_cache = []
        self.v_cache = []
        self.generated = []

    def trim_cache(self):
        """修剪 cache, 保留 sink + 最近 window"""
        total_len = len(self.k_cache)
        if total_len <= self.num_sink + self.window_size:
            return

        # 保留 sink + window
        keep_sink = self.num_sink
        keep_window = self.window_size
        self.k_cache = self.k_cache[:keep_sink] + self.k_cache[-keep_window:]
        self.v_cache = self.v_cache[:keep_sink] + self.v_cache[-keep_window:]

    def step(self, input_ids):
        """单步生成"""
        # 1. 用 cache 算 attention
        k_used = torch.cat(self.k_cache, dim=2) if self.k_cache else None
        v_used = torch.cat(self.v_cache, dim=2) if self.v_cache else None

        # 2. 模型 forward
        with torch.no_grad():
            outputs = self.model(
                input_ids,
                past_key_values=(k_used, v_used) if k_used is not None else None,
                use_cache=True,
            )

        # 3. 取出新 KV
        new_k = outputs.past_key_values[0][:, :, -1:]  # 最新一 token 的 K
        new_v = outputs.past_key_values[1][:, :, -1:]

        # 4. 更新 cache
        self.k_cache.append(new_k)
        self.v_cache.append(new_v)
        self.trim_cache()

        # 5. 采样
        logits = outputs.logits[:, -1, :]
        next_token = torch.argmax(logits, dim=-1, keepdim=True)
        self.generated.append(next_token)

        return next_token

    def generate(self, prompt, max_new_tokens=10000):
        """生成完整序列"""
        self.reset()
        input_ids = self.tokenizer(prompt, return_tensors='pt').input_ids.to(self.model.device)
        generated = input_ids

        for _ in range(max_new_tokens):
            next_token = self.step(generated[:, -1:])
            generated = torch.cat([generated, next_token], dim=-1)
            if next_token.item() == self.tokenizer.eos_token_id:
                break

        return self.tokenizer.decode(generated[0], skip_special_tokens=True)
```

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**7. 实践建议**

结合 "长上下文与注意力变体" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "长上下文与注意力变体" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
