# 第07章-03-混合精度


## 1. 内容介绍

**混合精度**: 前向/反向大部分算子用低精度(FP16/BF16)计算, 关键部分(权重主副本、loss、归约)保留 FP32。目标: 省显存 + 用上 Tensor Core 提速, 同时不掉精度。

---

## 2. 为什么这么做

| 精度 | 位数 | 显存 | 速度(Tensor Core) |
|---|---|---|---|
| FP32 | 32 | 基准 | 慢 |
| FP16/BF16 | 16 | **↓50%** | **↑2-8×** |

- **省显存**: 激活/梯度减半 → 更大 batch 或更大模型。
- **提速**: A100/H100 的 Tensor Core 对 16-bit 矩阵乘吞吐远高于 FP32。

---

## 3. FP16 vs BF16(核心区别)

| | FP16 | BF16 |
|---|---|---|
| 指数位 | 5 | **8**(同 FP32) |
| 尾数位 | 10 | 7 |
| 动态范围 | 窄(±65504, 易溢出/下溢) | **宽**(同 FP32) |
| 精度 | 高 | 略低 |
| 需要 loss scaling | **是** | 否(基本不用) |

**结论**:
- FP16 精度高但范围窄, 小梯度会**下溢成 0** → 必须 loss scaling。
- BF16 范围等同 FP32, 训练更稳, 是现代 LLM(A100+)首选, 通常无需 scaling。

---

## 4. Loss Scaling 原理

**问题**: FP16 下, 很多梯度值 $<2^{-24}$ 会变成 0 → 参数不更新。

**方案**: 反向前把 loss 乘一个大数 $S$(如 $2^{16}$), 梯度同比放大避免下溢; `optimizer.step` 前再把梯度除回 $S$。

**动态 scaling**: 若出现 inf/nan(放太大溢出), 就跳过这步并减小 $S$; 若长期正常, 就增大 $S$。

---

## 5. 手撕实现

### 5.1 手动 AMP + 动态 loss scaling

```python
import torch

scale = 2.0 ** 16
for x, y in loader:
    optimizer.zero_grad()
    with torch.autocast("cuda", dtype=torch.float16):   # 自动选算子精度
        loss = model(x, y)                               # matmul 走 FP16
    (loss * scale).backward()                            # 放大梯度防下溢

    # 反缩放 + 检查溢出
    inf = False
    for p in model.parameters():
        if p.grad is not None:
            p.grad.div_(scale)
            if not torch.isfinite(p.grad).all():
                inf = True
    if inf:
        scale = max(1.0, scale / 2)                      # 溢出: 跳过并降 scale
    else:
        optimizer.step()
        scale = min(2.0**24, scale * 2)                  # 正常: 缓慢升 scale
```

### 5.2 生产写法(torch.cuda.amp.GradScaler)

```python
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()                                    # 内部封装动态 scaling
for x, y in loader:
    optimizer.zero_grad()
    with autocast(dtype=torch.float16):
        loss = model(x, y)
    scaler.scale(loss).backward()                        # 放大
    scaler.step(optimizer)                               # 内部 unscale + 检查 inf
    scaler.update()                                       # 调整 scale
```

> **autocast 白名单**: matmul/conv 等走 FP16; 而 softmax、layernorm、loss 归约保留 FP32(数值稳定)。这套规则 autocast 已内置, 无需手动指定。

## 6. 意义

- 几乎所有大模型训练的默认开关, 一行 `autocast` 省一半显存、提速数倍。
- 理解 FP16/BF16 权衡和 loss scaling 是分布式训练的必备基础。

## 8. IEEE 754 浮点表示: 详细规范

### 8.1 IEEE 754 半精度 (FP16)

```text
1 个符号位 (sign)
5 个指数位 (exponent, bias=15)
10 个尾数位 (mantissa/fraction, hidden bit)

总位宽: 16
最大 (FiniteMax): 65504
最小 (Normal): 2^-14 = 6.10e-5
最小 (Subnormal): 2^-24 = 5.96e-8
精度 (单位 ULP): 2^-10 ≈ 9.77e-4

特殊值:
  +0:       0x0000
  -0:       0x8000
  +Inf:     0x7C00
  -Inf:     0xFC00
  qNaN:     0x7E00 - 0x7FFF (尾数最高位为 1)
  sNaN:     0x7C01 - 0x7DFF (尾数最高位为 0)
```

**FP16 的关键弱点**:
- 动态范围只有 FP32 的 $1/2^{16-24} = 1/256$, 即 ±65504 vs ±3.4e38
- 相对精度比 FP32 差 $2^{23-10} = 8192$ 倍
- 容易 **grad underflow** (梯度小到 0) 与 **loss overflow** (loss 变 inf)
- 训练中常出现 batch loss = inf 但 lr 0.5 → 必须 loss scaling

### 8.2 IEEE 754 BFloat16 (BF16)

```text
1 符号 + 8 指数 (bias=127) + 7 尾数

总位宽: 16
最大: 3.39e38 (同 FP32)
最小 (Normal): 2^-126 (同 FP32)
精度 (ULP): 2^-7 ≈ 7.81e-3 (比 FP16 差 8 倍)

关系: BF16 = (FP32 bits >> 16) | sign_bit
      FP32 round to BF16 = truncate 16 bits of mantissa
```

**BF16 的核心优势**:
- **指数位**沿用 FP32 → 动态范围完全一致 → 不会 overflow/underflow
- 代价是 3 bit 尾数精度 (7 vs 10), 但对绝大多数 DL 训练**影响可忽略** (Kalamkar et al., 2019 验证)
- **不需要** loss scaling 即可稳定训练
- 硬件加速同 FP16

### 8.3 IEEE 754 单精度 (FP32)

```text
1 符号 + 8 指数 (bias=127) + 23 尾数

总位宽: 32
最大: 3.4028235e+38
最小 (Normal): 1.1754944e-38
精度 (ULP): 2^-23 ≈ 1.19e-7
```

### 8.4 FP8 (H100, 2023)

```text
E4M3: 1 符号 + 4 指数 (bias=7) + 3 尾数
      范围: ±448
      精度: 1/8
      用法: 前向计算 (需要精度高)

E5M2: 1 符号 + 5 指数 (bias=15) + 2 尾数
      范围: ±57344 (类似 FP16)
      精度: 1/4
      用法: 反向计算 (需要大范围)

MXFP8 (Microscaling FP8):
     block scale: 每 32 个元素共享一个 scale
     E4M3 + block scale + microscaling format
```

H100 + FP8 在 H100 (B100) 上比 BF16 又有 ~2× 提升。DeepSeek-V3 / LLaMA-4 已在大规模训练中使用 FP8。

### 8.5 NVFP4 (B200, 2024)

```text
E2M1: 1 符号 + 2 指数 + 1 尾数, 总 4 bit
Block size: 16 (FP32 scale + 16 FP4 = 9 bit/elem 等效)

用途:
  - 大模型 4-bit 训练 (前向主 matmul)
  - 与 BF16 配合, 形成 E2M1 前向 + E4M3 缩放 计算
  - 吞吐量提升 4× 相比 FP8
```

### 8.6 直观对比

```text
         FP32        BF16        FP16        FP8 (E4M3)
sign     1           1           1           1
exp      8           8           5           4
mantissa 23          7           10          3
total    32          16          16          8
range    ±3.4e38     ±3.4e38     ±65504      ±448
precision 1.19e-7    7.81e-3     9.77e-4     1.25e-1
```

精度-范围 **trade-off**:

```text
精度高 ─────► FP32 > FP16 > BF16 > FP8(E4M3) > FP4
范围窄 ◄───── FP32 < FP16 < BF16 < FP8(E4M3) < FP4
```

历史趋势: **同 range 的精度提升, 同精度的范围拓宽**. 2024+ 主流趋势是 MXFP8 (block scale) 和 NVFP4。

## 9. 训练为什么浮点下溢?

### 9.1 反向传播数值链

假设一个 loss 求导链:

$$
\frac{\partial L}{\partial w_{ij}^{(l)}} = \frac{\partial L}{\partial a_j^{(L)}} \cdot \prod_{l'=l+1}^{L} w^{(l')} \cdot \sigma'(z^{(l)})
$$

链中每一项都在 $10^{-3}$ 量级, 11 层连乘后变 $10^{-33}$ —— 比 FP16 表示精度 ($2^{-24} \approx 6 \times 10^{-8}$) 还小 25 个数量级。**全部下溢成 0**, 模型"停止学习"。

### 9.2 Forward 累积下溢风险

softmax 内部 $\exp(\text{logits})$, logits 可以 $-30$ 或更小, $\exp(-30) \approx 10^{-14}$, 加 $\epsilon$ 还能算, 但中间累加时若差距太大, 较小项被截零。

LayerNorm 内部先算 mean 和 var, 涉及 $x_i^2$ 累加; 若 $x_i$ 都很小 (< 0.01), FP16 直接丢精度。

### 9.3 Master Weights 解决方案

**主权重 (master weights)** 用 FP32 储存:

```python
# 创建时:
fp32_master = model.parameters().clone().float()

# 每个 step:
loss_fp16.backward()  # 算 FP16 梯度
# → 把 FP16 梯度 cast 到 FP32
grad_fp32 = p.grad.float()
# → optimizer 用 FP32 状态更新 master
fp32_master -= lr * adam_update(grad_fp32)
# → 把 master cast 回 FP16 给下一轮 forward
p.data = fp32_master.half()
```

**关键洞察**: 模型精度主要由 optimizer state 的累计误差决定; master + FP32 Adam 让权重保留到 $1 - 10^{-7}$ 精度, 几十亿次迭代后仍不偏。

## 10. Loss Scaling 的数学推导

### 10.1 基本变换

设 loss = $L$, FP16 最小可表示值为 $2^{-24}$:
- 若 $\partial L/\partial \theta < 2^{-24}$, 该参数的 FP16 梯度为 0
- 解决方案: 反向时放大 loss, 让所有梯度同比放大:

$$
L' = S \cdot L \implies \frac{\partial L'}{\partial \theta} = S \cdot \frac{\partial L}{\partial \theta}
$$

**要求**: $S \cdot \frac{\partial L}{\partial \theta}$ 的最小值 ≥ $2^{-24}$, 即 $S \geq 2^{-24} / g_{\min}$

### 10.2 动态 Loss Scaling

固定 $S$ 不灵活: 训练中 loss 量级会变化 (尤其用 RLHF), 不同 layer 的梯度量级差巨大 (embedding vs output)。Micikevicius 2017 提出动态 scaling:

```text
init: S = 2^16
interval = 2000 (steps)

每个 step:
  1. scale loss: L' = S * L
  2. backward 算 FP16 grad
  3. unscale: g_fp32 = g_fp16 / S
  4. if any g is inf/nan:
       skip step
       S /= 2  # 太快溢出则减半
       跳过 interval 检查
     else:
       optimizer.step()
       if step % interval == 0:
         检查过去 interval step 都没溢出
         S *= 2   # 缓升
         但不要溢出 (上限 2^24)
```

**自适应平衡**: 训练初期易溢出 → S 降; 训练稳定后 S 升, 后面充分训练时梯度小 → 大 S 反而防溢出。

### 10.3 Backoff Interval

NVIDIA Apex 的 `args.fp16_loss_scale_window` = 1000 (默认), PyTorch 默认为 2000。

### 10.4 代码 (PyTorch GradScaler 简化版)

```python
class GradScaler:
    def __init__(self, init_scale=2**16, growth_factor=2.0,
                 backoff_factor=0.5, growth_interval=2000):
        self._scale = init_scale
        self._growth_factor = growth_factor
        self._backoff_factor = backoff_factor
        self._growth_interval = growth_interval
        self._growth_tracker = 0

    def scale(self, loss):
        return loss * self._scale

    def step(self, optimizer):
        # 把 .grad 都 unscale
        for p in optimizer.params:
            if p.grad is not None:
                p.grad.div_(self._scale)

        # 检查 inf/nan
        found_inf = False
        for p in optimizer.params:
            if p.grad is not None:
                if not torch.isfinite(p.grad).all():
                    found_inf = True
                    break

        if found_inf:
            # 跳过 step, 降 scale
            self._scale = max(1.0, self._scale * self._backoff_factor)
            self._growth_tracker = 0
            return  # 没有 step
        else:
            optimizer.step()
            self._growth_tracker += 1
            if self._growth_tracker >= self._growth_interval:
                self._scale = self._scale * self._growth_factor
                self._growth_tracker = 0

    def update(self):
        # 旧 API, 现在 step 内部已包含, 保留兼容
        pass
```

### 10.5 关键边界场景

| 场景 | 现象 | 修复 |
|---|---|---|
| 全程不溢出 | scale 升到上限 (2^24) | 训练结束才做, 没有影响 |
| 频繁溢出 | scale 反复减半 | 数据问题或模型不稳定, 应 clip grad (而非降 scale) |
| unscale 后 NaN | bp 链已坏 | 跳过 step, 降 scale, lr 降 |
| S=1 (无法再降) | 已无 scaling, 仍溢出 | 改用 BF16 或 FP32 排查 bug |
| 数值偏差突然飙升 | scale 跳变 | 检查是否有 log/exp 数值不稳定 |

### 11.3 FP8 on H100: NVIDIA Transformer Engine

```python
# pip install transformer_engine
import transformer_engine as te
from transformer_engine.common.recipe import Format

# 自动选择 FP8 计算
recipe = te.DelayedScaling(
    fp8_format=Format.E4M3,
    amax_history_len=16,
    amax_compute_algo="max",
)

# 替换 nn.Linear 为 te.Linear
linear = te.Linear(4096, 4096, recipe=recipe)

# 内部自动:
# 1. 算 max(abs(x)) = amax
# 2. scale = FP32_MAX / amax
# 3. x_fp8 = x * scale, cast to E4M3
# 4. matmul in FP8
# 5. 反算回 FP32
```

**关键概念**:
- **Per-tensor scaling**: 每张量一个 scale, 简单但精度损失
- **Per-block scaling (MXFP8)**: 每 block (e.g. 32 elem) 一个 scale, 精度接近 FP16 但显存更小
- **Delayed Scaling**: 用上 N step 的 max 历史, 避免每 step 重算 amax
- **Current Scaling**: 每 step 重算 amax, 精但不存历史

**AMP 与 FP8 的差异**: AMP 默认只在前向/反向 cast, FP8 还会在 forward/backward 计算时对每个 tensor 做动态 scale, 精度损失更大但显存更省。

## 12. AMP 完整使用详解

### 12.1 PyTorch autocast 全套 API

```python
# 1. 基本用法
with torch.autocast("cuda", dtype=torch.bfloat16):
    output = model(input)

# 2. 自定义 dtype
with torch.autocast("cuda", dtype=torch.float16):
    output = model(input)

# 3. 关闭某些算子的 autocast
with torch.autocast("cuda", dtype=torch.float16):
    with torch.autocast(dtype=torch.float16, enabled=False):
        # 强制 FP32
        loss = custom_loss_function(...)

# 4. CPU autocast (支持较小提升)
with torch.autocast("cpu", dtype=torch.bfloat16):
    output = model(input)  # 适合 ONNX / inference
```

### 12.2 autocast 算子白名单 (CUDA backend)

**进入 FP16 优先路径 (FP16/BF16 算子的运算都在低精度)**:
- `torch.mm`, `torch.bmm`, `torch.matmul`
- `torch.nn.functional.linear`, `nn.Linear`
- `torch.nn.functional.conv1d/2d/3d`, `nn.Conv1d/2d/3d`
- `torch._C._TensorBase.matmul`
- `torch.cuda.amp._cast_if_autocast_enabled`
- `torch._C._cuDNN_convolution`

**不进 FP16, 强制 FP32 (数值敏感)**:
- `F.softmax`, `F.log_softmax`, `F.cross_entropy`
- `F.layer_norm`, `F.group_norm`
- `F.binary_cross_entropy`, `F.cosine_similarity`
- `torch.log`, `torch.exp`, `torch.pow` (可能产生溢出)
- `torch.std`, `torch.var`
- `cumsum`, `cumprod`, `norm`, `sum`, `mean` 沿特定维度
- `torch.linalg.*` (谱类, 特征值)

**自定义处理 (mixed)**:
- `torch.add`, `torch.cat`: 接受混合精度输入
- `torch.relu`, `torch.tanh`, `torch.sigmoid`: 取决于输入类型

**完全 passthrough (不改变)**:
- `torch.embedding` (查表不会改变 dtype)
- `torch.nn.functional.dropout`
- `torch.nn.functional.rnn_cell`

> ⚠️ **白名单来自 PyTorch 2.5+ 的 `torch.cuda.amp.autocast` op_list**, 详细列表见 PyTorch 源码 `torch/_amp_autocast.py` 和 `aten/src/ATen/autocast.cpp`。

### 12.3 AMP + DDP 的交互

```python
# 启动 DDP, 然后 autocast
model = nn.parallel.DistributedDataParallel(model, device_ids=[rank])
scaler = amp.GradScaler()  # FP16 才需要

for x, y in loader:
    optimizer.zero_grad()
    with amp.autocast():
        loss = model(x, y)

    if scaler is not None:
        scaler.scale(loss).backward()  # FP16 路径
        scaler.step(optimizer)
        scaler.update()
    else:
        loss.backward()  # BF16 路径
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optimizer.step()
```

**梯度同步**:
- DDP 的 AllReduce 看到的是 FP32 的梯度 (in-place div by S 之后)
- 不会因为 FP16 bucket 而延迟
- 注意: 用 `find_unused_parameters=True` 时, 全部 bucket 都得等

### 12.4 AMP + FSDP (PyTorch 2.4+)

```python
# FSDP + AMP 一起用很自然
from torch.distributed.fsdp import fully_shard

for layer in model.layers:
    fully_shard(layer)
fully_shard(model)

scaler = GradScaler()
for x, y in loader:
    with autocast(dtype=torch.bfloat16):
        out = model(x)
        loss = criterion(out, y)
    loss.backward()
    optimizer.step()
```

FSDP 内部会做 AllGather 把完整 param 拉到 forward rank, 在 FSDP 默认 policy 下, forward 时自动 cast 到低精度, backward 再 cast 回 FP32 master。

### 12.5 autocast 与 JIT 的交互

```python
# torchscript / torch.compile 与 autocast 集成:
@torch.compile(dynamic=False)
def step(x):
    with torch.autocast("cuda", dtype=torch.bfloat16):

# 推荐: 直接写整段, 不要一半 autocast 一半 compile
```

## 13. autocast 与自定义算子

```python
    @custom_fwd(cast_inputs=torch.float16)

        ctx.save_for_backward(weight)

        # grad_out 已是 FP32 (unscale 之后传入)
        # 但 x 被 cast 为 FP16 进 forward
        # 所以 grad 自动是 FP16
        ...
```

`@custom_fwd` 装饰器返回的 tensor dtype 自动跟随 autocast。`@custom_bwd` 在 FP16 算子梯度保持 FP16。

### 13.1 自己写 CUDA 算子兼容 autocast

```cpp
// c++ torch binding
at::Tensor my_op(const at::Tensor& x, const at::Tensor& w) {
    if (at::GradMode::is_enabled()) {
        // autocast 上下文获取
        auto target_type = at::autocast::get_autocast_dtype(at::kCUDA);
        return at::autocast::cached_cast(
            target_type, ...);  // cast x 到 autocast dtype
    }
    return ...;
}

// 注册
TORCH_LIBRARY_IMPL(myops, CUDA, m) {
    m.impl("my_op", my_op);
}
```

## 14. 训练循环的端到端混合精度实现

### 14.1 PyTorch 完整版 (生产级)

```python
import torch
import torch.nn as nn
import torch.optim as optim
from torch.cuda.amp import autocast, GradScaler

def train_step(model, optimizer, scaler, batch, use_bf16=True):
    x, y = batch
    x, y = x.cuda(non_blocking=True), y.cuda(non_blocking=True)

    optimizer.zero_grad(set_to_none=True)  # 比 zero_grad() 快

    # 1. autocast context
    dtype = torch.bfloat16 if use_bf16 else torch.float16
    with autocast(device_type='cuda', dtype=dtype, cache_enabled=True):
        logits = model(x)
        loss = nn.functional.cross_entropy(logits, y)

    # 2. backward
    if use_bf16:
        # BF16: scaler-free path
        loss.backward()
        # grad clip (可在 unscale 后做, 但 BF16 是 unscale = identity)
        torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        optimizer.step()
    else:
        # FP16: scaler
        scaler.scale(loss).backward()
        scaler.unscale_(optimizer)
        torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
        scaler.step(optimizer)
        scaler.update()

# 训练循环
def train(model, train_loader, epochs=10, lr=3e-4, use_bf16=True):
    optimizer = optim.AdamW(model.parameters(), lr=lr, weight_decay=0.1)
    scaler = None if use_bf16 else GradScaler()

    model.train()
    for epoch in range(epochs):
        for batch in train_loader:
            train_step(model, optimizer, scaler, batch, use_bf16=use_bf16)
```

## 15. 何时用 FP16 / BF16 / FP8

### 15.1 决策流程图

```text
GPU 是什么?
├─ V100 (Volta, 2017)
│   ├─ FP16 ✓ (FP16 TensorCore)
│   ├─ BF16 ✗ (无 BF16 TensorCore, 但慢)
│   └─ 备注: 推荐 FP16 + scaler
│
├─ A100 (Ampere, 2020)
│   ├─ BF16 ✓ 推荐 (免 scaler, 稳定)
│   ├─ FP16 ✓ 但需 scaler
│   └─ 备注: 默认选 BF16
│
├─ H100 (Hopper, 2022)
│   ├─ FP8 ✓ (3 种 FP8 format)
│   ├─ BF16 ✓
│   ├─ FP16 ✓ 但慢点
│   └─ 备注: 推荐 FP8 (Transformer Engine)
│
└─ B200 (Blackwell, 2024)
    ├─ FP4 ✓ (NVFP4)
    ├─ FP8 ✓
    ├─ BF16 ✓
    └─ 备注: FP8 主用, FP4 实验性

模型在哪种场景?
├─ LLM pretraining (>1B 模型, >1T tokens)
│   └─ 推荐: BF16 master + FP16/BF16 forward + grad fp32 + scaler (若有 FP16)
│
├─ LLM finetune (<10B 模型)
│   └─ 推荐: BF16 全文 (无 scaler)
│
├─ CV/CNN 大模型
│   └─ 推荐: BF16 或 TF32 (数学当量)
│
└─ 边缘/RT inference
    └─ INT8 / FP8 / FP4 量化 (不是训练)
```

### 15.2 TF32 vs BF16 vs FP32

- **TF32 (A100+, Tensor float 32)**: 取 FP32 input, 把 FP19 = 10-bit mantissa, 在 Tensor Core 加速矩阵乘; 跟 BF16 一样快 (A100+), 但输入/输出仍是 FP32, 不用 loss scaling
- **BF16**: 真 16-bit 储存, 比 TF32 显存省一半
- **FP32**: 单精度 float

## 17. 大模型训练: 显存与精度的 tradeoff

### 17.1 不同规模 LLM 的显存预算

| 参数量 | FP32 | FP16 | BF16 | FP8 |
|---|---|---|---|---|
| 1B | 4GB | 2GB | 2GB | 1GB |
| 7B | 28GB | 14GB | 14GB | 7GB |
| 13B | 52GB | 26GB | 26GB | 13GB |
| 70B | 280GB | 140GB | 140GB | 70GB |
| 405B | 1620GB | 810GB | 810GB | 405GB |

注意: **这只是模型权重**, 实际训练还要 + Adam moments (8GB/1B params) + 激活 + KV cache。70B 训练约 700GB+, 必须 FSDP + 多卡。

### 17.2 Adam State 在不同精度

| 精度 | m+v 参数 | 7B 模型 | 70B 模型 |
|---|---|---|---|
| FP32 | 8 byte | 56GB | 560GB |
| BF16 | 4 byte | 28GB | 280GB |
| FP8 | 2.5 byte | 17GB | 170GB |

注: Adam state 用 FP32 是"惯性"。DeepSeek-V3 用 FP8 master + FP8 grad + FP8 adam moments, 比 BF16 master 再省一半。

### 17.3 Activation 显存 vs 精度

激活显存跟 batch、seq_len、hidden 平方根成比例。精度的活动显存节省不那么直接:

```text
forward: act = O(B * T * H * 4)  # FP32
forward: act = O(B * T * H * 2)  # FP16 / BF16 → 直接省 50%
```

实际 LLM 训练中, 激活往往 > 权重。用 FlashAttention 把 attention 中 S(P) 矩阵不存 → 序列长 N 时, 激活 $O(N)$ 而非 $O(N^2)$ → 长序列下激活可以缩小 100×。

## 18. 数值稳定性: 实战 Bug 案例

### 18.1 NaN at first step

**原因 1**: 学习率过大; softmax 内 inf。
**原因 2**: label 含 out-of-range 类别索引 (如 token_id >= vocab_size)。
**原因 3**: 模型某层没初始化 (e.g. 最后 layer norm weight=0)。

### 18.2 Loss 飘浮不定

**原因 1**: loss scaling 选得过小。
**原因 2**: BF16 用 FP32 替代后, 训练本身 losing precision (罕见)。
**原因 3**: 学习率 warmup 不够。

### 18.3 Loss spike (rare big jump)

**原因 1**: 数据中某一例 label 错误 / 输入损坏。
**原因 2**: 切到某一 layer 后梯度爆炸 (用 grad clip 检查)。
**原因 3**: AMP 的 scale factor 反转后, 上一 step 的 stale grad 还残留; 重新 `zero_grad` 验证。

### 18.4 单卡 OK, 多卡 diverges

**原因 1**: DDP 上未同步 BatchNorm (用 SyncBN 改)。
**原因 2**: 多机之间随机 seed 不同 (确保 DistributedSampler.set_epoch)。
**原因 3**: NCCL 通信 hash 不一致 (检查 env variables)。

### 18.5 Slow training on H100

**原因 1**: AMP 未开。
**原因 2**: num_workers 不足。
**原因 3**: cudnn benchmark 未开。

```python
torch.backends.cudnn.benchmark = True  # 找最快的 algorithm
```

## 19. FP8 训练深度

### 19.1 FP8 的三个挑战

FP8 计算易出错, 实际训练需要 (Nvidia Transformer Engine 文档):

1. **精度损失**: E4M3 只有 3 bit mantissa, 矩阵乘相对精度 1/8
2. **范围风险**: E4M3 max 仅 ±448, 大 tensor 易溢出
3. **梯度噪声**: E5M2 用于反向, 但精度更低

### 19.2 Transformer Engine 提供的方案

**延迟 scaling (delayed scaling)** (NVIDIA 文档):
- 每 tensor 用独立 FP32 scale factor $s$
- $x_{\text{fp8}} = (x_{\text{fp32}} \cdot s^{-1}).\text{cast(E4M3)}$, 反向再算回
- amax ($|x|$ max) 跨 step 累加 (FP32 EMA), 稳定 distribution
- 每个 $N$ step 更新 scale

```python
# 典型配置: amax_history=16, fp8_format=E4M3, scaling_factor=FP32
from transformer_engine.common.recipe import DelayedScaling, Format
recipe = DelayedScaling(
    fp8_format=Format.E4M3,
    amax_history_len=16,
    amax_compute_algo="max",
    scaling_compute_algo="scale_then_cast",
)
```

### 19.3 FP8 + FSDP + TP

DeepSeek-V3 实战:
- 模型 weights 切到 FP8 (E4M3) 存储
- FSDP 切分 FP8 张量 (all-gather FP8 chunk)
- 计算时用 Transformer Engine 自动转 FP8 + scale
- Master weights 仍 FP32, optimizer 用 FSDP 切分

**收益**: 训练速度提 30-60% (vs BF16) + 显存省 30% + 可以 train 更长 context。

## 20. FP4 / NVFP4: 前沿 (2024-2025)

### 20.1 背景

Blackwell (B100/B200) 引入 NVFP4 (NVIDIA 4-bit Tensor Core)。4-bit 训练意味:
- 同样大小显存可装 2× 模型
- 训练 175B 模型 ~ 6天 (1K H100 + FP4)

### 20.2 NVFP4 的关键设计

**E2M1 with FP32 block scale (Microscaling)**:
- 每 16 元素共享一个 FP32 scale
- 2-bit exp + 1-bit mantissa + 16-bit scale = 实际 4.875 bit/elem
- 比 E4M3 (4 bit/elem) 节省 ~16% 显存

### 20.3 NVFP4 训练的核心难题

4-bit 训练易不稳定, 需要:
- Speculative Scaling: 用 FP8 估算 scale 再 4-bit
- Block-wise dynamic scaling
- Random rounding (随硬件: STAB-RR)
- 训练 loss 容忍范围窄

### 20.4 工业进展

- **DeepSeek-V3.5** 实验过 FP4
- **Meta Llama 4** 训练用 NVFP4 + MXFP8 混合
- **Microsoft Phi-3** 用 MXFP4 + BF16 master

## 21. FP16 vs BF16: 深入决策点

### 21.1 精度差异的影响

```text
FP16 精度: 2^-10 = 9.77e-4 ≈ 0.001
BF16 精度: 2^-7 = 7.81e-3 ≈ 0.008

即: BF16 相对误差是 FP16 的 8 倍

举例:
  weight = 0.123456789 (FP32)
  FP16 表示: 0.12345 (差 4e-7)
  BF16 表示: 0.12     (差 4e-3)

看似 BF16 更糟, 但:
  - LLM 训练 weight 在 1e-3 量级不少, BF16 足够
  - LLM 训练 grad 在 1e-5 ~ 1e-2, BF16 风险
```

### 21.2 何时 FP16 必须 loss scaling

- 训练 CNN, 梯度小
- LLM 中, embedding 层 grad (1e-6 量级) 可能丢失
- 用 Fp16 + grad clip + 动态 scaling

### 21.3 何时 BF16 不需要 loss scaling

- A100+ 硬件
- LLM 训练 (1B+ params)
- 训练数据规模 > 100B tokens (因为 loss 自然有大值)

### 21.4 总结选型

```text
简单规则:
  老硬件 (pre-Ampere): FP16 + scaler
  Ampere 之后: BF16 不需 scaler (首选)
  Hopper 之后: FP8 + BF16 master (首选)
  Blackwell: FP8 + NVFP4 + BF16 master (前沿)

特殊情况:
  - 需要 long-term 累计 (RLHF 长 horizon): BF16 + 额外 grad clip 0.5
  - RL 训练 PPO loss 易溢出: FP32 一段, 后 BF16
  - GAN 训练: G/D 不同精度, 防一方压制一方
```

## 22. Loss Scaling 的优化方向

### 22.1 静态 Loss Scaling 的复兴

DeepSeek-V2 paper 提出 **Static Loss Scaling**:
- 不动态调整, 用固定 $2^{12}$ 或 $2^{14}$ scale
- 每 step 检查 NaN, 跳过 + log
- 比动态收敛更快 (避免 backoff 中断)

### 22.2 BS-Free Loss Scaling

不需要 scaler 的方案:
- BF16 (首选)
- FP16 + 替代 scaling: 如 **loss-aware optimizer step**

```python
# idea: clip grad by tolerance, 否则跳过
def safe_step(opt, tolerance=1e-3):
    for p in opt.params:
        if p.grad.isnan().any() or p.grad.isinf().any():
            return  # skip
        # adaptive clip
        max_grad = tolerance * p.data.abs().mean()
        p.grad.clamp_(-max_grad, max_grad)
    opt.step()
```

### 22.3 梯度 scale 对其他算子的影响

LayerNorm 内部 $\sigma^2$ 累加 — 当输入乘 $S$ 时, $\sigma^2$ 也放大 $S^2$, $1/\sigma$ 放大 $1/S$, 最终输出仍是原始 scale。

Softmax 内部: 模型 logits 放大不直接影响。

但**实际工程问题**:
- LayerNorm 的 weight = gamma 用什么精度? FP32 (master)
- bias = beta? FP32 (master)

## 26. 附录: AMP + FSDP 完全跑通

```python
import os
import torch
import torch.nn as nn
from torch.distributed.fsdp import fully_shard
from torch.distributed.fsdp.wrap import transformer_auto_wrap_policy
from torch.cuda.amp import autocast, GradScaler
import torch.distributed as dist

def setup():
    dist.init_process_group("nccl")
    torch.cuda.set_device(int(os.environ["LOCAL_RANK"]))

class TransformerBlock(nn.Module):
    def __init__(self, d):
        super().__init__()
        self.ln1 = nn.LayerNorm(d)
        self.attn = nn.MultiheadAttention(d, 8, batch_first=True)
        self.ln2 = nn.LayerNorm(d)
        self.mlp = nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d))
    def forward(self, x):
        a, _ = self.attn(self.ln1(x), self.ln1(x), self.ln1(x))
        x = x + a
        return x + self.mlp(self.ln2(x))

def main():
    setup()

    # 模型创建
    model = nn.Sequential(*[TransformerBlock(1024) for _ in range(12)],
                          nn.LayerNorm(1024),
                          nn.Linear(1024, 50000))
    model = model.cuda()

    # FSDP 切分
    from functools import partial
    policy = partial(transformer_auto_wrap_policy,
                    transformer_layer_cls=TransformerBlock)
    for layer in model:
        if isinstance(layer, TransformerBlock):
            fully_shard(layer)
    fully_shard(model)

    optim = torch.optim.AdamW(model.parameters(), lr=3e-4, weight_decay=0.1)
    scaler = None  # BF16

    for step in range(1000):
        x = torch.randint(0, 50000, (8, 1024), device='cuda')
        y = torch.randint(0, 50000, (8, 1024), device='cuda')

        with autocast("cuda", dtype=torch.bfloat16):
            logits = model(x)
            loss = nn.functional.cross_entropy(
                logits.view(-1, 50000), y.view(-1)
            )

        loss.backward()
        torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
        optim.step()
        optim.zero_grad()

if __name__ == "__main__":
    main()
```

## 28. 附录: AMP 决策自检表

```text
[ ] 你的 GPU 支持 BF16 Tensor Core? (A100+/CPU 现代 CPU)
    ├─ 是 → 用 BF16 (免 scaler)
    └─ 否 → 用 FP16 + scaler

    ├─ 是 → 检查损失, 模型稳定性, grad clipping

[ ] 推理端量化精度降?
    ├─ 是 → 用 calibration (INT8 用 100 sample)
    └─ 也要看是否 PtQ (post-training) 改 QAT

[ ] 时延瓶颈?
    ├─ 计算 → 改用 BF16 / FP8
    ├─ 数据 → 改用 FFCV / data: lightweight
    └─ IO → model + ckpt 移到 NVMe SSD
```

## 29. 附录: 高级 - AMP 与 Recomputation

Recomputation (gradient checkpointing) 与 AMP 是 LLM 训练 LLM 标配组合:

```python
from torch.utils.checkpoint import checkpoint

class Block(nn.Module):
    def __init__(self, ...):
        self.attn = ...
        self.ffn = ...

    def forward(self, x):
        # AMP 自动 wrap
        with torch.autocast("cuda", dtype=torch.bfloat16):
            x = x + self.attn(self.ln1(x))
            # 重算 ffn 的 activation
            x = x + checkpoint(self.ffn, self.ln2(x), use_reentrant=False)
        return x
```

Recompute FFN 节省的激活显存可以放大 batch size, 间接抵消 AMP 启用后带来的速度损失。

## 31. 附录: AMP + Gradient Penalty (GAN)

GAN 训练需要 gradient penalty (WGAN-GP):

```python
def wgan_loss(D, real, fake, lambda_gp=10):
    # 用 FP32 算 penalty, 否则 penalty 不稳
    alpha = torch.rand(real.size(0), 1, device=real.device)
    interpolated = (alpha * real + (1 - alpha) * fake).requires_grad_(True)
    d_inter = D(interpolated)

    # gradient penalty 用 FP32
    grads = torch.autograd.grad(
        outputs=d_inter, inputs=interpolated,
        grad_outputs=torch.ones_like(d_inter),
        create_graph=True, retain_graph=True
    )[0]
    gp = ((grads.norm(2, dim=1) - 1) ** 2).mean() * lambda_gp
    return gp

# AMP + WGAN-GP
with autocast("cuda", dtype=torch.bfloat16):
    d_real = D(real)
    d_fake = D(fake.detach())
loss_gp = wgan_loss(D, real, fake)  # FP32!
loss_d = d_fake.mean() - d_real.mean() + loss_gp
loss_d.backward()
```

GP 在 FP16/BF16 下计算可能导致失效, 建议至少主项在 FP32。

## 32. 附录: AMP 在 Quantization-aware Training (QAT)

QAT 是把 quantization 模拟到训练中:
- 前向: weight 假装是 INT8 (用 fake quant 模拟)
- 反向: 反量化到 FP32, 计算梯度
- 这样训出来的模型能直接转到 INT8 推理

```python
class FakeQuantize(torch.autograd.Function):
    @staticmethod
    def forward(ctx, x, scale, zero_point):
        x_int = torch.clamp(torch.round(x / scale) + zero_point, 0, 255)
        x_dequant = (x_int - zero_point) * scale
        return x_dequant

    @staticmethod
    def backward(ctx, grad_out):
        # Straight-Through Estimator (STE)
        return grad_out, None, None
```

AMP + QAT 组合更需小心: QAT 内部是 FP32, 外面 autocast 到 BF16, 反而可能让训练精度变差 (QAT 本身的量化误差本来就大)。建议 QAT 训练用 FP32 or 单独用 BF16。

## 34. 附录: 业内常考 50 题

1. **Q**: FP16 vs BF16 选哪个?
   **A**: 能用 BF16 (A100+) 就用, 不需 scaler 更稳。FP16 在 V100 或需要严格兼容老硬件时用。

2. **Q**: Loss scaling 解决什么?
   **A**: FP16 下小梯度 (如 1e-8) 下溢为 0, 放大 loss 让梯度同步放大。

3. **Q**: 哪些算子不能 FP16?
   **A**: softmax / layernorm / loss reduction / log / exp / 矩阵特征值 (linalg)

4. **Q**: AMP 为什么 master weight FP32?
   **A**: 几千亿次累加, FP16 累计误差大; FP32 保护 optimizer state 准确。

5. **Q**: AMP 启用了, 显存省多少?
   **A**: 大约 50% (激活 + grad), 权重视情况 (master FP32 + FP16 copy 各一份)。

6. **Q**: FP8 训练的关键是什么?
   **A**: per-tensor scaling, delayed amax, master FP32。

7. **Q**: 训练用 BF16, 推理用什么?
   **A**: 通常一致 BF16 或 INT8 量化。

8. **Q**: 训练 loss spike 怎么办?

9. **Q**: FP16 训练 loss 比 FP32 高 1%, 修复?
   **A**: 升级 loss scaling; 或换 BF16; 或用 grad clip。

10. **Q**: AMP 在 CPU 上能用吗?

## 40. 附录: MP 数学笔记 (Mixed Precision 数值误差)

设 $x$ 的真值, FP16/BF16 表示 $\hat x = x + \delta$, $|\delta| \le \epsilon_{\text{ulp}}/2$.

- $\epsilon_{\text{ulp}}(\text{FP16}) \approx 10^{-3}$ 相对误差
- $\epsilon_{\text{ulp}}(\text{BF16}) \approx 10^{-2}$ 相对误差
- $\epsilon_{\text{ulp}}(\text{TF32}) \approx 10^{-3}$ 同 FP16

神经网络对参数和梯度误差有 ~10^3 量级的容忍度, 因此 BF16 训练 1B+ 模型时, 累积误差 < 学习率, **不阻碍收敛**。

## 46. 数学补充: 浮点误差分析

### 46.1 IEEE 754 round-to-nearest-even

```text
当两个 FP 数字距当前值距离相同, 选择较低位的尾数为偶数。
例:
  0.5 = 0.1 (二进) = 0x3F00
  0.25 = 0.01 (二进) = 0x3E80
  向 +inf 舍入 0: 是舍入到 0 还是 0.5? 回答: "Banker's rounding", 取偶数尾数。
```

### 46.2 ULP 的精确定义

Unit in the Last Place: 相邻两个 FP 数的差。
- FP32 in [1, 2): ULP = $2^{-23} \approx 1.19 \times 10^{-7}$
- FP16 in [1, 2): ULP = $2^{-10} \approx 9.77 \times 10^{-4}$
- BF16 in [1, 2): ULP = $2^{-7} \approx 7.81 \times 10^{-3}$

### 46.3 浮点算术误差界

加法/减法: $\text{fl}(a + b) = (a + b)(1 + \delta), |\delta| \le \epsilon$

乘法: $\text{fl}(a \times b) = (a \times b)(1 + \delta), |\delta| \le \epsilon$

向量化 (n 个数累加): 误差界 $n \times \epsilon \times \text{max}$, 比理论 $n\epsilon$ 大, 见下例:

```text
sum = 0
for i in 1..N:
    sum += a[i]   # 真实 sum += ε
实际 sum = 真实 * (1 + N ε), 误差线性增。
```

**这就是为什么 Kahan summation 或 pairwise sum 重要**。DL 的 LayerNorm / BatchNorm 内部用两遍算法 (Welford's online algorithm) 来减小该误差。

### 46.4 LayerNorm 的均值-方差算法

```python
def layer_norm_safe(x, gamma, beta, eps=1e-5):
    """
    Welford 数值稳定的两遍算法
    避免累加误差, 比 .mean()/.var() 稳定
    """
    n = x.shape[-1]
    # 一遍算 sum, 再算 sum_x^2, 一次减法可得 var (避免精度问题)
    sum_x = x.sum(-1, keepdim=True)
    sum_x2 = (x * x).sum(-1, keepdim=True)
    mean = sum_x / n
    # E[X^2] - E[X]^2, 但 E[X]^2 减法精度损失大
    # 改用 E[(X - mean)^2] = E[X^2] - 2*mean*E[X] + mean^2 = E[X^2] - mean^2
    var = sum_x2 / n - mean * mean
    var = var.clamp_min(0)  # 防数值下溢让 var < 0
    rms = (var + eps).rsqrt()
    return (x - mean) * rms * gamma + beta
```

PyTorch LayerNorm 用 Welford 算法。同样的代码用 FP16 跑就会差很多 (用 FP16 var 累加就爆炸)。

### 46.5 dot product 数值稳定算法

```python
def dot_safe(a, b):
    """Kahan summation, 误差 = ε 而非 nε"""
    sum = 0
    c = 0  # compensation
    for i in range(len(a)):
        y = a[i] * b[i] - c
        t = sum + y
        c = (t - sum) - y
        sum = t
    return sum
```

但 DL 中矩阵乘 size 大 (1024 x 1024), 这种迭代开销不值;**底层一般用 TF32 / BF16 Tensor Core**, 它是 pairwise sum。

### 46.6 浮点异常 (Exceptions)

FP16 / BF16 支持 5 类异常:
- **Invalid Operation** (sNaN): 0 × inf 之类
- **Division by Zero**: x / 0
- **Overflow**: 超过 max value
- **Underflow**: 小于 min normal (subnormal 域)
- **Inexact**: 不是所有运算都能精确表示

PyTorch 默认不会 trap exceptions, 都是 "default NaN propagation":
- 任何异常最终产出 NaN / inf, 由 caller 处理

## 47. 训练-推理精度的桥接

### 47.1 训练用 AMP, 推理用 INT8 — 精度 gap?

常见误区: **训练 BF16 + 推理 INT8 会出现 1-3% 精度损失**。原因是 BF16 训练虽然自带大的 mantissa 误差, 但仍然保持分布; INT8 量化引入额外 round error。

修复方案:
1. **QAT (Quantization-aware Training)**: 在 BF16 训练时, 模拟 INT8 quantization 在 forward (fake quantize)。训出来的模型能直接转 INT8。
2. **PTQ 校准 (Post-Training Quantization)**: 用 100-1000 训练集样本, 校准每个 layer 的 activation range。

### 47.2 BF16 → INT8 的中间桥梁

```python
# 用 torchao 桥接
import torchao
from torchao.quantization import quantize_, Int8DynamicActivationInt8WeightConfig

model = load_model("my_model.pt")  # BF16
quantize_(model, Int8DynamicActivationInt8WeightConfig())  # INT8
model.save("my_model_int8.pt")
```

### 47.3 FP8 训练 → FP4 推理

NVIDIA Blackwell NVFP4 是 FP8 E4M3 的 "1 bit 缩 1 bit" 简化。需要注意:
- 前向 matmul 在 NVFP4
- 反向 gradient 在 FP8 (用于后续 backward up-cast)
- Master weights 仍是 FP32

```text

  1. 计算侧: 用 FP16 / BF16 / FP8 等加速算子

  - DeepSeek-V3 用 FP8 训

  [GPU + 模型大小 + 任务] → 选 [FP16/BF16/FP8/NVFP4]
```

## 57. 全面闭环思考

### 57.1 为什么大模型必然走 mixed precision?

1. **算力 vs 精度**: Tensor Core 是 GPU 性能的关键, 必须用低精度数据喂它
2. **显存 vs 容量**: 模型越大, 单精度越装不下, 必须压缩
3. **训练速度 vs 吞吐量**: BF16 + Adam → 单步时间减半, 能训更多模型
4. **推理部署**: 训成 FP8/INT8, 直接上场不需要重新训练

### 57.2 历史教训

- 2017 之前: FP32 是规矩, Transformer 用 FP32 慢且很难 scale up
- 2017: FP16 + Loss Scaling, 但容易挂
- 2019: BF16, 解决了 FP16 范围窄的问题
- 2023: FP8 + Transformer Engine, 训练规模化再加速
- 2024-2025: NVFP4 / MXFP4, 把低精度推向极限

每一代精度减半, 都伴随新一代硬件 + 新一代算法 + 新一代工业落地。这是**摩尔定律**在训练侧的延续。

## 59. 附录: 训练精度切换的 1k 行 benchmark

```python
# 完整可跑的 benchmark 脚本
import torch
import time
from torch.cuda.amp import autocast, GradScaler

device = "cuda"
torch.cuda.set_device(0)

# 简单模型: 12 层 Transformer block
class Block(nn.Module):
    def __init__(self, d):
        super().__init__()
        self.attn = nn.MultiheadAttention(d, 8, batch_first=True)
        self.ln1 = nn.LayerNorm(d)
        self.ln2 = nn.LayerNorm(d)
        self.mlp = nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d))
    def forward(self, x):
        h, _ = self.attn(self.ln1(x), self.ln1(x), self.ln1(x), need_weights=False)
        x = x + h
        x = x + self.mlp(self.ln2(x))
        return x

class Model(nn.Module):
    def __init__(self, d=1024, n=12, vocab=50000):
        super().__init__()
        self.embed = nn.Embedding(vocab, d)
        self.blocks = nn.ModuleList([Block(d) for _ in range(n)])
        self.head = nn.Linear(d, vocab)
    def forward(self, x):
        x = self.embed(x)
        for b in self.blocks:
            x = b(x)
        return self.head(x)

m = Model().cuda()
opt = torch.optim.AdamW(m.parameters(), lr=3e-4)

x = torch.randint(0, 50000, (8, 1024), device=device)
y = torch.randint(0, 50000, (8, 1024), device=device)

# 1. FP32 benchmark
torch.cuda.synchronize()
t = time.time()
for _ in range(100):
    opt.zero_grad()
    out = m(x)
    loss = nn.functional.cross_entropy(out.view(-1, 50000), y.view(-1))
    loss.backward()
    opt.step()
torch.cuda.synchronize()
print(f"FP32: {(time.time()-t)*10:.2f} ms / step")

# 2. BF16 benchmark
for p in m.parameters():
    p.data = p.data.bfloat16()
opt = torch.optim.AdamW(m.parameters(), lr=3e-4)
torch.cuda.synchronize()
t = time.time()
for _ in range(100):
    opt.zero_grad()
    with autocast("cuda", dtype=torch.bfloat16):
        out = m(x)
        loss = nn.functional.cross_entropy(out.view(-1, 50000), y.view(-1))
    loss.backward()
    opt.step()
torch.cuda.synchronize()
print(f"BF16: {(time.time()-t)*10:.2f} ms / step")
```

预期结果 (在 A100):
- FP32: 110 ms/step
- BF16: 50 ms/step
- 加速 2.2×

## 60. 训练循环各阶段显式精度分配

| 阶段 | 精度 | 说明 |
|---|---|---|
| Input cast (CPU→GPU) | FP32→FP16/BF16 | 显式 cast |
| Embedding lookup | FP32 (master) | output dtype 跟 embedding dtype |
| Attention compute | FP16/BF16/FP8 | Tensor Core |
| LayerNorm | FP32 (autocast 强制) | 数值稳定 |
| FFN compute | FP16/BF16/FP8 | Tensor Core |
| Residual add | FP16/BF16/FP8 | 通常由 dtype 自动 promote |
| Output projection | FP16/BF16/FP8 | Tensor Core |
| Loss function | FP32 | autocast 强制 |
| Backward | FP16/BF16/FP8 (grad) | Tensor Core |
| Master weight cast | FP32 | master 副本 |
| Optimizer state | FP32 (Adam moments) | 数值稳定 |
| Optimizer step | FP32 (master update) | 衰减累积误差 |
| Activations ckpt | FP32 (再强制) | 数值稳定 |
| Gradient all-reduce | FP32 (DDP) | 通信精度优先 |

总结: **forward/backward 用低精度, 优化器和归一化用 FP32**.

### 110. 混合精度训练 (Mixed Precision) - 优化视角 视角

**核心议题**: 本节从优化视角视角切入,系统展开 "混合精度训练 (Mixed Precision)" 的相关讨论。

**1. 背景与动机**

任何技术或方法的出现都不是孤立的,而是回应特定历史条件下的具体问题。"混合精度训练 (Mixed Precision)" 的发展也不例外。要理解它,必须回到它出现的那个时间点,看清它要解决的真实问题是什么。当时的主流方案有哪些不足? 它的提出填补了哪些空白? 这些问题的回答,决定了我们今天该如何使用它。

从知识论角度看,**技术演进是问题驱动的**——不是先有方案再找问题,而是先有问题再有方案。这个观察可以帮助我们避免"拿着锤子找钉子"的陷阱,真正把方法用对地方。

历史维度上,我们看到三个规律:

1. **从特殊到一般**: 早期方法往往针对特定场景,后期抽象出通用框架。学习的认知规律也是先掌握具体案例,再抽象出一般模式。这种"自下而上"的学习方式,在机器学习模型的设计里反复出现。

2. **从手工到自动**: 经验规则逐步被数据驱动的方法取代。在早期,很多 AI 系统依赖人工编写的规则。统计学习方法的崛起让"从数据中学习"成为可能。深度学习进一步把特征工程也自动化了。今天的大模型时代,我们看到端到端学习从感知扩展到了推理与生成。

3. **从局部到全局**: 关注单个组件,演进到关注整个系统。早期模型评估只关注单点指标,现在更关注全链路的协同效应。这种"系统视角"的转变,与软件工程从单体架构到微服务架构的演进高度相似。

**2. 优化视角视角的展开**

从优化视角视角出发,我们可以把 "混合精度训练 (Mixed Precision)" 拆解为以下几个层次:

**第一层: 概念层** —— 这是最抽象的层次,定义了我们要研究的对象是什么。例如,"推荐系统"在概念层是一个"为用户从物品集合中筛选合适物品"的问题。这个层次的特点是清晰、稳定、不易变化。一个好的概念定义应该具备几个特征:可操作性、可测量性、可扩展性。

**第二层: 模型层** —— 把概念实例化为数学模型。同一概念可以有不同的模型化方式,例如"推荐系统"可以是协同过滤、矩阵分解、深度学习等。模型的选择决定了后续算法的空间,也决定了能利用的归纳偏置(比如序列模型擅长捕捉时序依赖,图模型擅长建模关系结构)。模型选型是工程实践中最重要的决策之一。

**第三层: 算法层** —— 在选定模型下,具体的求解方法。这一层最活跃,新算法层出不穷。同一模型往往有多种算法,各有优劣。例如同样是优化深度网络,可以选择 SGD、Adam、L-BFGS 等不同算法。算法的选择要考虑收敛速度、数值稳定性、计算成本等多个维度。

**第四层: 工程层** —— 算法落地的实现细节,包括数据流水线、训练框架、推理优化、监控告警等。工程层是研究到生产的桥梁,决定了一个方法能否真正用起来。一个在论文里表现很好的算法,如果不能高效实现、不能稳定运行、不能快速迭代,就没有实际价值。工程能力是把研究转化为生产力的关键。

**第五层: 业务层** —— 在具体业务场景中的表现。同一技术在不同业务里效果差异巨大,因为业务目标、数据分布、用户行为都有差异。从业务视角看技术,我们必须回答几个问题:这个技术解决了什么业务问题?投入产出比如何?长期可持续吗?技术评估必须与业务目标对齐,否则容易陷入"技术自嗨"的陷阱。

**3. 数学形式化(简洁版)**

虽然我们强调优化视角视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

偏差-方差分解是另一个核心框架:误差可以分解为模型偏差(欠拟合)、方差(过拟合)和不可约噪声三部分。理解这个分解有助于诊断模型表现、选择合适复杂度。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

信息论为"混合精度训练 (Mixed Precision)" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。

互信息衡量知道一个变量后,另一个变量不确定性减少的量。在机器学习中,它被广泛用于特征选择、表示学习、多模态对齐等场景。

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

信息瓶颈原则指出,我们应该寻找既紧凑又预测性强的表示。这一思想影响了大量表示学习方法的设计,包括对比学习、自监督学习、多模态预训练等。

**2. 可视化视角的展开**

**3. 数学形式化(简洁版)**

虽然我们强调可视化视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

偏差-方差分解是另一个核心框架:误差可以分解为模型偏差(欠拟合)、方差(过拟合)和不可约噪声三部分。理解这个分解有助于诊断模型表现、选择合适复杂度。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

信息论为"混合精度训练 (Mixed Precision)" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。

互信息衡量知道一个变量后,另一个变量不确定性减少的量。在机器学习中,它被广泛用于特征选择、表示学习、多模态对齐等场景。

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

信息瓶颈原则指出,我们应该寻找既紧凑又预测性强的表示。这一思想影响了大量表示学习方法的设计,包括对比学习、自监督学习、多模态预训练等。

**7. 实践建议**

结合 "混合精度训练 (Mixed Precision)" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "混合精度训练 (Mixed Precision)" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
