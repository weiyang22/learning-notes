# 第07章-04-检查点策略

> 面试常混淆:
> 1. **激活检查点 (Activation/Gradient Checkpointing)**: 训练时用时间换显存。
> 2. **模型检查点 (Model Checkpoint)**: 保存权重, 断点续训/容错。

---

## 1. 激活重计算(用时间换显存)

### 1.1 为什么

反向传播需要前向的**中间激活**来算梯度。默认全部缓存, 显存 $O(L)$(层数)。大模型/长序列时激活占用远超参数本身。

**思路**: 前向时**丢弃**大部分激活, 反向时**重新前向计算**需要的那段。显存降到 $O(\sqrt{L})$, 代价是多一次前向(约 +33% 计算)。

### 1.2 手撕实现

```python
import torch

class CheckpointFn(torch.autograd.Function):
    @staticmethod
    def forward(ctx, run_fn, *args):
        ctx.run_fn = run_fn
        ctx.save_for_backward(*args)
        with torch.no_grad():                    # 关键: 前向不建图, 不存中间激活
            out = run_fn(*args)
        return out

    @staticmethod
    def backward(ctx, *grad_out):
        inputs = ctx.saved_tensors
        inputs = [x.detach().requires_grad_(True) for x in inputs]
        with torch.enable_grad():                # 反向时重新前向, 这次建图
            out = ctx.run_fn(*inputs)
        grads = torch.autograd.grad(out, inputs, grad_out)
        return (None, *grads)

def checkpoint(run_fn, *args):
    return CheckpointFn.apply(run_fn, *args)

# 用法: 只在每个 Transformer block 外包一层
# h = checkpoint(block, h)   # 等价 torch.utils.checkpoint.checkpoint(block, h)
```

**权衡**: 显存 ↓ 30-50%, 训练时间 ↑ ~20-33%。大模型标配, 常与 ZeRO/FSDP 配合。

## 2. 模型检查点(断点续训 / 容错)

### 2.1 为什么

千卡训练几天, 硬件必然会挂。必须周期性保存 **完整训练态**, 才能从断点恢复而非从头再来。

**要保存的不只是权重**: 还有优化器状态(Adam 的 m/v)、LR scheduler、当前 step、RNG 种子、AMP scaler。

### 2.2 手撕实现

```python
def save_ckpt(path, step, model, opt, sched, scaler):
    torch.save({
        "step": step,
        "model": model.state_dict(),
        "opt": opt.state_dict(),          # 缺了它 Adam 动量丢失, loss 会抖
        "sched": sched.state_dict(),
        "scaler": scaler.state_dict(),    # 混合精度的 loss scale
        "rng": torch.get_rng_state(),     # 保证数据顺序可复现
    }, path)

def load_ckpt(path, model, opt, sched, scaler):
    # 安全: 仅加载可信来源的 ckpt; torch.load 默认会 unpickle 任意对象(可 RCE).
    # 若 ckpt 只含张量/简单结构, 用 weights_only=True 更安全.
    ck = torch.load(path, map_location="cpu", weights_only=False)
    model.load_state_dict(ck["model"])
    opt.load_state_dict(ck["opt"])
    sched.load_state_dict(ck["sched"])
    scaler.load_state_dict(ck["scaler"])
    torch.set_rng_state(ck["rng"])
    return ck["step"]                     # 从这一步继续
```

### 2.3 大规模工程要点

| 技术 | 作用 |
|---|---|
| **异步/分片 save** | 各 rank 只存自己那片参数(FSDP/ZeRO), 避免单点 OOM |
| **原子写入** | 先写临时文件再 `rename`, 防止写一半崩溃留下损坏 ckpt |
| **保留最近 N + 里程碑** | 省磁盘, 又不丢关键节点 |
| **异步上传对象存储** | 训练不阻塞在 IO |

## 5. 激活重计算深度推导 (数学 + 内存分析)

### 5.1 反向传播的显存消耗

设一个 $L$ 层 Transformer (每层类似), 输入 batch size $B$, 序列长度 $N$, hidden dim $H$。

**每层激活的显存占用** (近似):
- 输入 $X$: $B \times N \times H$ (BF16: $2BNH$ bytes)
- Attention 输出: $B \times N \times H$
- Attention 的 $QK^T$ 矩阵: $B \times N \times N$ (这是显存大头!)
- FFN 中间激活: $B \times N \times 4H$ (典型 FFN 扩展 4 倍)

如果不优化, **总激活显存**:
$$M_{\text{naive}} = O(L \cdot B \cdot N \cdot (H + 4H + N))$$
对于 $B=8, N=4096, H=4096, L=32$:
$$M_{\text{naive}} \approx 32 \times 8 \times 4096 \times (4096 \times 5 + 4096) \approx 18 \text{ GB}$$

这只是激活, 模型权重 + 优化器 + 梯度还要几十 GB, 单卡 80GB A100 根本不够。

### 5.2 Gradient Checkpointing 的核心思想

**关键观察**: 反向传播时, 计算 $\frac{\partial L}{\partial x_i}$ 只需要 $x_i$ 和 $x_{i+1}$ 这两个连续层的激活, 而不需要所有层的激活。

**策略**:
- 前向时, **丢弃**大部分中间激活, 只在选定的"检查点"位置保留激活。
- 反向时, 从最近的检查点开始**重新前向**到需要的位置, 然后算梯度。

### 5.3 $\sqrt{L}$ 策略的数学证明

设检查点之间间隔 $k$ 层 (即每隔 $k$ 层保存一次完整激活), 共 $L/k$ 个检查点。

**显存占用**:
- 保存的检查点: $L/k \times M_{\text{per-layer}}$
- 反向时重新计算一个 segment (k 层) 的激活: $k \times M_{\text{per-layer}}$
- 总显存: $M_{\text{total}} = \frac{L}{k} \cdot M_{\text{per-layer}} + k \cdot M_{\text{per-layer}} = \left(\frac{L}{k} + k\right) \cdot M_{\text{per-layer}}$

最小化 $f(k) = \frac{L}{k} + k$:

$$\frac{df}{dk} = -\frac{L}{k^2} + 1 = 0 \implies k = \sqrt{L}$$

此时 $f(\sqrt{L}) = 2\sqrt{L}$, 即 **总激活显存降到 $O(\sqrt{L})$**。

**额外计算量**: 反向时需要重新前向 $\sqrt{L}$ 层, 相比正常的 1 次前向, 总计算变为 1 (前向) + 1 (重算的 $\sqrt{L}$ 层) = 大约 $1 + \sqrt{L}/L \approx 1.03 \sim 1.10$ 倍, 即**计算增加 ~30%**。

实际上每个 segment 都需要重算, 所以总计算量约为原始的 $\frac{2}{3} \cdot L + \sqrt{L}$ 层 (因每层重算一次再加原始前向), 实际开销 ~30-40%。

### 5.4 数值例子

| 模型 | $L$ | $\sqrt{L}$ | 朴素显存 | 检查点后显存 | 计算开销 |
|---|---|---|---|---|---|
| GPT-2 | 12 | 3.5 | 6 GB | 1.8 GB | ~30% |
| LLaMA-7B | 32 | 5.7 | 18 GB | 3.2 GB | ~30% |
| LLaMA-13B | 40 | 6.3 | 25 GB | 4.0 GB | ~30% |
| LLaMA-70B | 80 | 8.9 | 60 GB | 6.7 GB | ~30% |

## 6. PyTorch checkpoint 源码剖析

### 6.1 torch.utils.checkpoint.checkpoint 实现

```python
# torch/utils/checkpoint.py 简化版
def checkpoint(function, *args, use_reentrant=False, **kwargs):
    """检查点前向, 用自定义 autograd.Function 实现"""
    if use_reentrant:
        return CheckpointFunction.apply(function, preserve_rng_state, *args)
    else:
        # 新版 (PyTorch 2.0+) 默认 use_reentrant=False
        return _checkpoint_without_reentrant(function, preserve_rng_state, *args)


class CheckpointFunction(torch.autograd.Function):
    @staticmethod
    def forward(ctx, run_function, preserve_rng_state, *args):
        # 1. 保存 rng 状态 (保数据增强一致)
        if preserve_rng_state:
            ctx.fwd_cpu_state = torch.get_rng_state()
            if torch.cuda.is_available():
                ctx.fwd_gpu_states = torch.cuda.get_rng_state_all()

        # 2. 保存输入 (args 是输入 tensor, 不是激活)
        ctx.run_function = run_function
        ctx.preserve_rng_state = preserve_rng_state

        with torch.no_grad():  # 关键: 前向时不建图
            outputs = run_function(*args)

        # 3. 保存输入用于反向
        ctx.save_for_backward(*args)

        return outputs

    @staticmethod
    def backward(ctx, *args):
        # 1. 恢复 rng 状态 (确保重新前向一致)
        if ctx.preserve_rng_state:
            torch.set_rng_state(ctx.fwd_cpu_state)
            if torch.cuda.is_available():
                torch.cuda.set_rng_state_all(ctx.fwd_gpu_states)

        # 2. 让输入重新可求导
        inputs = ctx.saved_tensors
        inputs = [x.detach().requires_grad_(True) for x in inputs]

        # 3. 重新前向, 这次建图
        with torch.enable_grad():
            outputs = ctx.run_function(*inputs)

        # 4. 算梯度
        outputs_with_grad = [o for o in outputs if o.requires_grad]
        inputs_with_grad = [i for i in inputs if i.requires_grad]

        grad_inputs = torch.autograd.grad(
            outputs_with_grad, inputs_with_grad, grad_outputs=args,
            allow_unused=True,
        )

        # 5. 返回: (None, None, *grad_inputs) - run_function 和 preserve_rng_state 无梯度
        return (None, None, *grad_inputs)
```

### 6.2 use_reentrant 的区别

```python
# 旧版 (PyTorch 1.x 默认): use_reentrant=True
# 问题: 重入 autograd, 与某些算子不兼容 (如 torch.compile, FlashAttention 早期版本)

# 新版 (PyTorch 2.0+): use_reentrant=False
# 改进: 不重入, 用更稳定的 autograd 机制
# 推荐: 永远用 use_reentrant=False

torch.utils.checkpoint.checkpoint(
    block, hidden_states,
    use_reentrant=False,  # 必须 False
)
```

### 6.3 checkpoint 的正确使用姿势

```python
# 错误 1: 不在 block 边界用 checkpoint
class TransformerBlock(nn.Module):
    def __init__(self):
        super().__init__()
        self.attn = Attention()
        self.ffn = FeedForward()

    def forward(self, x):
        # checkpoint 包整个 block (推荐)
        # h = checkpoint(self._forward, x, use_reentrant=False)

        # 不要把 checkpoint 放在更细粒度的算子里
        # 错误: h = checkpoint(self.attn, x)  # 包整个 attention
        # 然后又包 ffn, 反而增加开销
        return self._forward(x)

# 错误 2: 输入包含不需要梯度的 tensor
def forward_with_extra_params(self, x, mask):
    # mask 通常不需要梯度, 应该用 kwargs 而不是 args
    return checkpoint(self._forward, x, mask=mask, use_reentrant=False)

# 错误 3: 输出包含 non-tensor
def forward_with_dict(self, x):
    # 如果输出 dict/list, 需要包装
    out = checkpoint(self._forward, x, use_reentrant=False)
    return out  # 必须是 tensor 或 tuple of tensors
```

## 7. 多种 Checkpoint 策略对比

### 7.1 Naive (无 Checkpoint)

```text
每层都保留所有激活
前向: 1×
反向: 1× backward pass
显存: O(L)
```

### 7.2 Full Checkpoint

```text
全部丢弃, 反向时从输入重新前向
前向: 1×
反向: 1 次完整重算 (1× 前向)
显存: O(1) (几乎不存)
计算: 2× (前向 + 反向重算)
```

### 7.3 Sqrt-L Checkpoint (默认)

```text
每隔 √L 层保留激活, 其余反向时重算
前向: 1×
反向: 重算 √L 段, 共约 0.5L 次前向
显存: O(√L)
计算: 1.5×
```

### 7.4 Selective Checkpoint (只重算部分层)

```text
策略: 只对 attention 重算 (显存大, 计算相对便宜)
FFN 层保留 (因为重算 FFN 的计算开销高)

class SelectiveCheckpointBlock(nn.Module):
    def forward(self, x):
        # FFN 保留激活 (不重算)
        x = self.attn(x)
        # attention 重算 (省 N×N 矩阵)
        x = torch.utils.checkpoint.checkpoint(
            lambda x: self.ffn(x), x, use_reentrant=False,
        )
        return x
```

### 7.5 策略对比

| 策略 | 显存 | 计算开销 | 适用场景 |
|---|---|---|---|
| Naive | $O(L)$ | 1× | 小模型 / 短序列 |
| Full | $O(1)$ | 2× | 显存极小 (例如 16GB 跑 7B) |
| Sqrt-L | $O(\sqrt{L})$ | 1.3-1.5× | 默认推荐 |
| Selective | $O(L \cdot \alpha)$ | 1.1× | 极致优化 (Megatron-LM 用) |

## 8. Selective Activation Checkpointing (Megatron-LM 风格)

### 8.1 Megatron 的策略

Megatron-LM 论文 (2021) 发现: 显存主要被 self-attention 的 $QK^T$ 矩阵占用 ($B \times N \times N$)。但 FFN 的前向重算开销更大 (因为有 GeLU 等)。

**Megatron 策略**: 重算 attention 段 (省 $N^2$ 显存, 计算便宜), 保留 FFN 段 (计算贵)。

```python
class MegatronCheckpointBlock(nn.Module):
    def __init__(self):
        super().__init__()
        self.attn = SelfAttention()
        self.ffn = FeedForward()

    def forward(self, x):
        # 1. Attention 段: 重算
        # (因为 attention 显存是 N^2, 重算开销相对小)
        x = torch.utils.checkpoint.checkpoint(
            self.attn, x, use_reentrant=False,
        )

        # 2. FFN 段: 保留激活
        # (FFN 中间激活是 N*H*4, 但重算开销大: 4×H^2 计算)
        x = self.ffn(x)

        return x
```

### 8.2 实测对比 (LLaMA-7B, seq=4096, batch=8)

```text
策略                  显存   时间/epoch
无 checkpoint:        35 GB  100 min
Sqrt-L checkpoint:    18 GB  130 min  (1.3×)
Selective (attn):     22 GB  115 min  (1.15×)
Selective (ffn):      26 GB  120 min  (1.2×)
Full checkpoint:      12 GB  180 min  (1.8×)
```

**结论**: Selective (重算 attention) 性价比最高。

## 9. 模型 Checkpoint (分布式版本)

### 9.1 DDP 的 Checkpoint (简单)

DDP (Distributed Data Parallel) 每张卡保存完整模型, 保存逻辑与单机相同, 但需要协调:

```python
import torch.distributed as dist

def save_ckpt_ddp(path, step, model, opt, sched, scaler=None):
    """DDP 下的 checkpoint (每张卡都执行, 但只有 rank 0 写入)"""
    # 1. 同步所有 rank
    dist.barrier()

    # 2. 只有 rank 0 写入
    if dist.get_rank() == 0:
        state = {
            "step": step,
            "model": model.module.state_dict() if hasattr(model, 'module') else model.state_dict(),
            "opt": opt.state_dict(),
            "sched": sched.state_dict(),
            "scaler": scaler.state_dict() if scaler else None,
            "rng": torch.get_rng_state(),
        }
        torch.save(state, path)

    # 3. 再次同步
    dist.barrier()


def load_ckpt_ddp(path, model, opt, sched, scaler=None, map_location=None):
    """DDP 下加载: 每张卡都需要加载"""
    if map_location is None:
        map_location = {"cuda:%d" % 0: "cuda:%d" % dist.get_rank()}

    state = torch.load(path, map_location=map_location)

    if hasattr(model, 'module'):
        model.module.load_state_dict(state["model"])
    else:
        model.load_state_dict(state["model"])

    opt.load_state_dict(state["opt"])
    sched.load_state_dict(state["sched"])
    if scaler and state["scaler"]:
        scaler.load_state_dict(state["scaler"])

    torch.set_rng_state(state["rng"])
    return state["step"]
```

### 9.2 FSDP 的 Checkpoint (复杂)

FSDP (Fully Sharded Data Parallel) 把模型分片到多卡, 保存时需要 gather 或保留分片。

#### 方式 1: Full State Dict (推荐, 兼容性好)

```python
from torch.distributed.fsdp import FullyShardedDataParallel as FSDP
from torch.distributed.fsdp import StateDictType, FullStateDictConfig

def save_ckpt_fsdp(model, path, rank):
    """保存完整 state_dict (gather 到 rank 0)"""
    save_policy = FullStateDictConfig(offload_to_cpu=True, rank0_only=True)

    with FSDP.state_dict_type(model, StateDictType.FULL_STATE_DICT, save_policy):
        state = model.state_dict()
        if rank == 0:
            torch.save(state, path)


def load_ckpt_fsdp(model, path, rank):
    """加载完整 state_dict (PyTorch 自动重新分片)"""
    with FSDP.state_dict_type(model, StateDictType.FULL_STATE_DICT):
        state = torch.load(path, map_location="cpu")
        model.load_state_dict(state)
```

#### 方式 2: Sharded State Dict (高效)

```python
from torch.distributed.fsdp import ShardedStateDictConfig

def save_ckpt_sharded(model, path, rank, world_size):
    """每张卡保存自己分片, 总体积小, 加载快"""
    save_policy = ShardedStateDictConfig(offload_to_cpu=True)

    with FSDP.state_dict_type(model, StateDictType.SHARDED_STATE_DICT, save_policy):
        state = model.state_dict()
        # 每张卡写自己的分片
        # 文件命名: model-00000-of-00008.bin, model-00001-of-00008.bin, ...
        for name, tensor in state.items():
            shard_path = f"{path}/{name}-shard{rank:05d}-of-{world_size:05d}.bin"
            torch.save(tensor, shard_path)


def load_ckpt_sharded(model, path):
    """从分片加载 (每张卡只加载自己那片)"""
    with FSDP.state_dict_type(model, StateDictType.SHARDED_STATE_DICT):
        state = {}
        # 每张卡遍历自己的分片
        for shard_file in glob.glob(f"{path}/*-shard*.bin"):
            tensor = torch.load(shard_file)
            # 提取参数名 (去掉 shard 后缀)
            name = shard_file.split('/')[-1].split('-shard')[0]
            state[name] = tensor
        model.load_state_dict(state)
```

#### 方式 3: Meta Device Init (初始化优化)

```python
def init_model_meta(model_cls, model_args):
    """在 meta device 上初始化模型, 不占显存"""
    with torch.device("meta"):
        model = model_cls(*model_args)
    return model

def load_ckpt_to_meta(model, path):
    """把 checkpoint 直接加载到 meta 模型, 然后 materialize 到 GPU"""
    state = torch.load(path, map_location="meta")
    model.load_state_dict(state, assign=True)  # assign=True 保留 meta
    return model
```

### 9.3 DeepSpeed Checkpoint

DeepSpeed 的 checkpoint 包含 ZeRO 优化器状态分片:


## 10. 断点续训完整工业实践

### 10.1 完整 Checkpoint 训练循环

```python
class Trainer:
    """带 checkpoint 的完整 trainer"""
    def __init__(self, model, opt, sched, save_dir, log_steps=100, save_steps=1000):
        self.model = model
        self.opt = opt
        self.sched = sched
        self.save_dir = save_dir
        self.log_steps = log_steps
        self.save_steps = save_steps
        self.scaler = torch.cuda.amp.GradScaler()
        self.global_step = 0
        self.epoch = 0

    def save(self):
        """原子保存: 先写临时文件, 再 rename"""
        path = f"{self.save_dir}/step_{self.global_step}.pt"
        tmp_path = path + ".tmp"

        # 1. 写临时文件
        torch.save({
            "global_step": self.global_step,
            "epoch": self.epoch,
            "model": self.model.state_dict(),
            "opt": self.opt.state_dict(),
            "sched": self.sched.state_dict(),
            "scaler": self.scaler.state_dict(),
            "rng_cpu": torch.get_rng_state(),
            "rng_gpu": torch.cuda.get_rng_state_all() if torch.cuda.is_available() else None,
        }, tmp_path)

        # 2. 原子 rename
        os.rename(tmp_path, path)

        # 3. 清理旧 checkpoint (保留最近 3 个 + best)
        self._cleanup_old_ckpts()

        print(f"[step {self.global_step}] Saved checkpoint to {path}")

    def _cleanup_old_ckpts(self):
        """保留最近 3 个 step checkpoint, 加 best"""
        ckpts = sorted(glob.glob(f"{self.save_dir}/step_*.pt"))
        # 保留最近 3 个
        if len(ckpts) > 3:
            for old in ckpts[:-3]:
                if "best" not in old:
                    os.remove(old)

    def load(self, path=None):
        """加载 checkpoint, 自动找最新"""
        if path is None:
            ckpts = sorted(glob.glob(f"{self.save_dir}/step_*.pt"))
            if not ckpts:
                print("No checkpoint found, starting from scratch")
                return
            path = ckpts[-1]

        print(f"Loading checkpoint from {path}")
        state = torch.load(path, map_location="cpu")

        self.model.load_state_dict(state["model"])
        self.opt.load_state_dict(state["opt"])
        self.sched.load_state_dict(state["sched"])
        self.scaler.load_state_dict(state["scaler"])
        torch.set_rng_state(state["rng_cpu"])
        if state.get("rng_gpu") is not None and torch.cuda.is_available():
            torch.cuda.set_rng_state_all(state["rng_gpu"])

        self.global_step = state["global_step"]
        self.epoch = state["epoch"]
        print(f"Resumed from step {self.global_step}, epoch {self.epoch}")

    def train(self, train_loader, n_epochs):
        """训练循环"""
        for epoch in range(self.epoch, n_epochs):
            self.epoch = epoch
            for batch in train_loader:
                self.global_step += 1

                # 训练一步
                loss = self._train_step(batch)

                # 日志
                if self.global_step % self.log_steps == 0:
                    print(f"[step {self.global_step}] loss={loss:.4f}")

                # 保存
                if self.global_step % self.save_steps == 0:
                    self.save()

        # 训练结束保存最终 checkpoint
        self.save()

    def _train_step(self, batch):
        """单步训练"""
        self.opt.zero_grad()

        with torch.cuda.amp.autocast(dtype=torch.bfloat16):
            outputs = self.model(**batch)
            loss = outputs.loss

        self.scaler.scale(loss).backward()
        self.scaler.step(self.opt)
        self.scaler.update()
        self.sched.step()

        return loss.item()


# 使用
trainer = Trainer(model, opt, sched, save_dir="./ckpts")
trainer.load()  # 自动恢复或从零开始
trainer.train(train_loader, n_epochs=3)
```

### 10.2 异常恢复 (Crash Recovery)

```python
import signal
import sys

class CrashSafeTrainer(Trainer):
    """带异常处理的 trainer (Ctrl+C / OOM / 节点故障 都能恢复)"""

    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        # 注册信号处理器
        signal.signal(signal.SIGINT, self._handle_signal)
        signal.signal(signal.SIGTERM, self._handle_signal)

    def _handle_signal(self, signum, frame):
        print(f"\nReceived signal {signum}, saving checkpoint...")
        self.save()
        sys.exit(0)

    def train(self, train_loader, n_epochs):
        while self.epoch < n_epochs:
            try:
                for batch in train_loader:
                    self.global_step += 1
                    loss = self._train_step(batch)

                    if self.global_step % self.save_steps == 0:
                        self.save()

                self.epoch += 1

            except torch.cuda.OutOfMemoryError as e:
                # OOM: 跳过当前 batch, 保存 checkpoint
                print(f"OOM at step {self.global_step}: {e}")
                torch.cuda.empty_cache()
                self.save()
                # 可选: 重启训练 (在 launch 脚本里检测后自动拉起)
                raise

            except Exception as e:
                # 其他错误: 保存, 然后 re-raise
                print(f"Error at step {self.global_step}: {e}")
                self.save()
                raise
```

## 11. 异步保存 / 分布式 Checkpoint

### 11.1 异步保存 (不阻塞训练)

```python
import threading
import queue

class AsyncCheckpointWriter:
    """异步写盘, 不阻塞训练 step"""
    def __init__(self, save_dir, max_queue=2):
        self.save_dir = save_dir
        self.queue = queue.Queue(maxsize=max_queue)
        self.worker = threading.Thread(target=self._worker, daemon=True)
        self.worker.start()

    def _worker(self):
        while True:
            item = self.queue.get()
            if item is None:
                break
            step, state, path = item
            try:
                tmp_path = path + ".tmp"
                torch.save(state, tmp_path)
                os.rename(tmp_path, path)
                print(f"[async] Saved step {step} to {path}")
            except Exception as e:
                print(f"[async] Save failed: {e}")
            finally:
                self.queue.task_done()

    def save_async(self, step, state, path):
        """异步保存, 不阻塞训练"""
        try:
            self.queue.put_nowait((step, state, path))
        except queue.Full:
            print("Queue full, skipping async save")
```

```python
def save_sharded(state_dict, save_dir, max_shard_size_gb=5):
    """分片保存, 每片 5GB"""
    max_size = max_shard_size_gb * 1024 ** 3
    shards = {}
    current_shard = {}
    current_size = 0
    shard_id = 1

    for name, tensor in state_dict.items():
        size = tensor.element_size() * tensor.nelement()
        if current_size + size > max_size and current_shard:
            shards[f"model-{shard_id:05d}.safetensors"] = current_shard
            current_shard = {}
            current_size = 0
            shard_id += 1
        current_shard[name] = tensor
        current_size += size

    if current_shard:
        shards[f"model-{shard_id:05d}.safetensors"] = current_shard

    for fname, shard in shards.items():
        save_file(shard, f"{save_dir}/{fname}")

    # 保存 index
    index = {
        "metadata": {"total_size": sum(t.nelement() * t.element_size() for t in state_dict.values())},
        "weight_map": {name: fname for fname, shard in shards.items() for name in shard},
    }
    with open(f"{save_dir}/model.safetensors.index.json", "w") as f:
        json.dump(index, f)
```

### 13.3 Checkpoint 完整性校验

```python
import hashlib

def save_with_checksum(state, path):
    """保存时计算 SHA256 校验"""
    tmp_path = path + ".tmp"
    torch.save(state, tmp_path)

    # 计算 SHA256
    sha256 = hashlib.sha256()
    with open(tmp_path, "rb") as f:
        for chunk in iter(lambda: f.read(8192), b""):
            sha256.update(chunk)

    # 保存校验文件
    with open(f"{path}.sha256", "w") as f:
        f.write(sha256.hexdigest())

    os.rename(tmp_path, path)


def verify_checkpoint(path):
    """验证 checkpoint 完整性"""
    expected_sha = open(f"{path}.sha256").read().strip()
    actual_sha = hashlib.sha256(open(path, "rb").read()).hexdigest()

    if expected_sha != actual_sha:
        raise ValueError(f"Checkpoint corrupted: {path}")
    return True
```

## 16. 面试高频 + 答案

### Q1: 激活重计算和梯度检查点是同一个东西吗?

```text
答: 是同一个东西, 中文/英文不同叫法。
- 英文: gradient checkpointing / activation checkpointing / rematerialization
- 中文: 梯度检查点 / 激活重计算 / 激活重物化
- 原理: 用前向重算换取激活显存
- 实现: torch.utils.checkpoint.checkpoint
```

### Q2: 为什么 √L 是最优的检查点间隔?

```text
答: 数学最优解。
设间隔 k 层, 共 L/k 个检查点, 每个 segment 重算 k 层。
显存: (L/k + k) × M_per_layer
最小化: d/dk [(L/k + k)] = 0 → k = √L
此时总显存: 2√L × M_per_layer = O(√L)
```

### Q3: 全参数微调需要保存什么?

```text
必存:
- model.state_dict()  -- 模型权重
- optimizer.state_dict()  -- Adam 的 m / v, 缺了训练会抖
- scheduler.state_dict()  -- LR 调度状态

可选但推荐:
- scaler.state_dict()  -- AMP 的 loss scale, 缺了 FP16 训练不稳定
- step / epoch  -- 进度跟踪
- torch.get_rng_state()  -- 数据顺序可复现
- torch.cuda.get_rng_state_all()  -- GPU 端 RNG
- best_metric  -- best checkpoint 标记
- args  -- 配置 (方便复现)

不存:
- 数据集 (太大, 从原始文件读)
- 激活 (不需要存, 反向时重算)
```

### Q4: ZeRO-3 的 checkpoint 为什么慢? 怎么优化?

```text
慢的原因:
1. gather: 每张卡只存 1/N 参数, 保存时要 all-gather 到 rank 0
2. 写盘: 单卡写 70B 模型要 5+ 分钟

优化:
1. Sharded save: 每张卡只存自己分片 (推荐, DeepSpeed 0.10+)
2. Async save: 后台线程写, 训练不阻塞
3. 增量保存: 只存变更部分 (大模型微调, LoRA 场景)
4. 上传到对象存储: 用 S3 multi-part upload
```

### Q5: 节点故障后如何快速恢复训练?

```text
答: 集群容错的标准流程:

1. Slurm 调度层:
   - --requeue: 节点故障后自动重新排队
   - --signal=B:@60: 发送 SIGTERM 给训练进程, 60s 后强杀
   - 让训练脚本收到信号时保存 checkpoint

2. 训练脚本:
   - 注册 signal handler
   - 收到 SIGTERM → save → exit(0)
   - 重启后 → --resume=auto → 自动从最新 ckpt 恢复

3. 检查点策略:
   - 每 1000 步保存 (5-10 分钟一次)
   - 最多损失 5-10 分钟训练 (可接受)
   - 保留最近 3-5 个 (防止 ckpt 损坏)

4. 通信层:
   - NCCL_ASYNC_ERROR_HANDLING=1
   - TORCH_DISTRIBUTED_DEBUG=DETAIL
```

### Q6: Selective Activation Checkpoint 为什么只重算 attention?

```text
答: 显存 vs 计算的权衡。
Attention:
- 显存: B*N*N (QK^T 矩阵), 占用大头
- 计算: O(B*N*N*H) (attention 本身)
- 重算开销: N/N*H 倍, 即 H 倍

FFN:
- 显存: B*N*4H (中间激活), 中等
- 计算: O(B*N*H^2) (两个大矩阵乘)
- 重算开销: 4H*H/H = 4 倍

Attention 的"显存/计算"比更高, 重算更划算。
```

### Q7: 为什么分布式 checkpoint 需要保留 RNG 状态?

```text
答: 数据 shuffle 一致性。

场景:
- 训练用 DistributedSampler, 每个 epoch 自动 shuffle
- 假设 step 5000 时崩溃
- 重启后如果 RNG 没恢复, 数据顺序变了
- → 模型学到的"信息"不一样 → 复现失败

解决:
- 保存 torch.get_rng_state() (CPU)
- 保存 torch.cuda.get_rng_state_all() (所有 GPU)
- 加载时 set_rng_state 恢复
```

## 17. Checkpoint 与分布式训练的关系

### 17.1 三种并行策略对 Checkpoint 的影响

| 并行策略 | 模型分片 | Checkpoint 复杂度 |
|---|---|---|
| **DDP** | 不分片 (每卡复制) | 简单: 每卡都存完整模型 |
| **FSDP / ZeRO-3** | 完全分片 | 中等: 分片 save/load |
| **TP (Megatron)** | 层内分片 | 复杂: 转换 rank 顺序 |
| **PP (Pipeline)** | 层间分片 | 复杂: 不同 stage 存不同层 |
| **TP+PP+DP** | 三维分片 | 复杂: 需重映射 |

### 17.2 跨并行策略迁移 Checkpoint

有时需要把 TP=8 的 checkpoint 转成 TP=4:

```python
def merge_tp_checkpoints(tp_paths, output_path):
    """合并 TP=8 的 8 个分片为一个完整模型"""
    full_state = {}

    # TP=8 中, 列并行层 (output 分片) 沿 dim=0 拼接
    # 行并行层 (input 分片) 沿 dim=1 拼接

    for tp_rank in range(8):
        state = torch.load(f"{tp_paths}/mp_rank_{tp_rank:02d}/model.pt")
        for name, tensor in state.items():
            if "linear_fc1.weight" in name:  # 列并行
                # 沿 dim=0 拼接
                full_state.setdefault(name, []).append(tensor)
            elif "linear_fc1.bias" in name:
                # bias 不分片, 直接覆盖
                full_state[name] = tensor
            elif "linear_fc2.weight" in name:  # 行并行
                # 沿 dim=1 拼接
                full_state.setdefault(name, []).append(tensor)

    # 拼接
    for name, tensors in full_state.items():
        if isinstance(tensors, list):
            if "linear_fc1.weight" in name:
                full_state[name] = torch.cat(tensors, dim=0)
            elif "linear_fc2.weight" in name:
                full_state[name] = torch.cat(tensors, dim=1)

    torch.save(full_state, output_path)
```

## 19. 完整代码: 工业级 Checkpoint Manager

```python
import os
import glob
import json
import hashlib
import shutil
import threading
import torch
from typing import Optional, Dict, Any


class CheckpointManager:
    """工业级 checkpoint 管理器"""

    def __init__(
        self,
        save_dir: str,
        max_keep: int = 3,
        save_async: bool = True,
        verify: bool = True,
    ):
        self.save_dir = save_dir
        self.max_keep = max_keep
        self.save_async = save_async
        self.verify = verify
        os.makedirs(save_dir, exist_ok=True)
        self._async_queue = []
        self._async_thread = None

    def save(
        self,
        step: int,
        model: torch.nn.Module,
        optimizer: torch.optim.Optimizer,
        scheduler: Any,
        scaler: Optional[torch.cuda.amp.GradScaler] = None,
        extra_state: Optional[Dict] = None,
        is_best: bool = False,
        tag: Optional[str] = None,
    ):
        """保存 checkpoint"""
        if tag is None:
            tag = f"step_{step:07d}"

        # 1. 构造 state
        state = {
            "step": step,
            "model": self._get_model_state(model),
            "opt": optimizer.state_dict(),
            "sched": scheduler.state_dict() if scheduler else None,
            "scaler": scaler.state_dict() if scaler else None,
            "rng_cpu": torch.get_rng_state(),
            "rng_gpu": torch.cuda.get_rng_state_all() if torch.cuda.is_available() else None,
            "extra": extra_state or {},
        }

        # 2. 同步 or 异步保存
        if self.save_async:
            self._save_async(state, tag, is_best)
        else:
            self._save_sync(state, tag, is_best)

        # 3. 清理旧 checkpoint
        self._cleanup()

    def _get_model_state(self, model):
        """获取 model state (处理 DDP / FSDP)"""
        if hasattr(model, 'module'):
            return model.module.state_dict()
        return model.state_dict()

    def _save_sync(self, state, tag, is_best):
        path = os.path.join(self.save_dir, f"{tag}.pt")
        tmp_path = path + ".tmp"

        # 写临时文件
        torch.save(state, tmp_path)

        # 校验
        if self.verify:
            self._verify(tmp_path)

        # 原子 rename
        os.rename(tmp_path, path)

        # best 副本
        if is_best:
            best_path = os.path.join(self.save_dir, "best.pt")
            shutil.copy(path, best_path)

        print(f"[ckpt] Saved {tag} ({os.path.getsize(path)/1e9:.2f} GB)")

    def _save_async(self, state, tag, is_best):
        # 把 state 复制到 CPU, 异步线程写
        cpu_state = {
            k: (v.cpu() if isinstance(v, torch.Tensor) else v)
            for k, v in state.items()
        }
        self._async_queue.append((cpu_state, tag, is_best))

        if self._async_thread is None or not self._async_thread.is_alive():
            self._async_thread = threading.Thread(target=self._async_worker, daemon=True)
            self._async_thread.start()

    def _async_worker(self):
        while self._async_queue:
            state, tag, is_best = self._async_queue.pop(0)
            try:
                self._save_sync(state, tag, is_best)
            except Exception as e:
                print(f"[ckpt] Async save failed: {e}")

    def _verify(self, path):
        """校验 checkpoint 完整性"""
        sha256 = hashlib.sha256()
        with open(path, "rb") as f:
            for chunk in iter(lambda: f.read(8192), b""):
                sha256.update(chunk)
        with open(f"{path}.sha256", "w") as f:
            f.write(sha256.hexdigest())

    def load(
        self,
        path: Optional[str] = None,
        model: Optional[torch.nn.Module] = None,
        optimizer: Optional[torch.optim.Optimizer] = None,
        scheduler: Optional[Any] = None,
        scaler: Optional[torch.cuda.amp.GradScaler] = None,
        strict: bool = True,
    ) -> int:
        """加载 checkpoint, 返回 step"""
        if path is None:
            path = self._find_latest()
            if path is None:
                print("[ckpt] No checkpoint found, starting from scratch")
                return 0

        if not os.path.exists(path):
            raise FileNotFoundError(f"Checkpoint not found: {path}")

        # 校验
        if self.verify and os.path.exists(f"{path}.sha256"):
            expected = open(f"{path}.sha256").read().strip()
            actual = hashlib.sha256(open(path, "rb").read()).hexdigest()
            if expected != actual:
                raise ValueError(f"Checkpoint corrupted: {path}")

        print(f"[ckpt] Loading {path}")
        state = torch.load(path, map_location="cpu")

        if model is not None:
            target = model.module if hasattr(model, 'module') else model
            target.load_state_dict(state["model"], strict=strict)

        if optimizer is not None and state.get("opt"):
            try:
                optimizer.load_state_dict(state["opt"])
            except Exception as e:
                if strict:
                    raise
                print(f"[ckpt] Optimizer state load failed: {e}")

        if scheduler is not None and state.get("sched"):
            try:
                scheduler.load_state_dict(state["sched"])
            except Exception as e:
                if strict:
                    raise
                print(f"[ckpt] Scheduler state load failed: {e}")

        if scaler is not None and state.get("scaler"):
            scaler.load_state_dict(state["scaler"])

        if state.get("rng_cpu") is not None:
            torch.set_rng_state(state["rng_cpu"])
        if state.get("rng_gpu") is not None and torch.cuda.is_available():
            torch.cuda.set_rng_state_all(state["rng_gpu"])

        step = state.get("step", 0)
        print(f"[ckpt] Resumed from step {step}")
        return step

    def _find_latest(self):
        """找最新的 step checkpoint"""
        ckpts = sorted(glob.glob(os.path.join(self.save_dir, "step_*.pt")))
        return ckpts[-1] if ckpts else None

    def _cleanup(self):
        """保留最近 N 个 step checkpoint"""
        ckpts = sorted(glob.glob(os.path.join(self.save_dir, "step_*.pt")))
        if len(ckpts) > self.max_keep:
            for old in ckpts[:-self.max_keep]:
                os.remove(old)
                sha_path = old + ".sha256"
                if os.path.exists(sha_path):
                    os.remove(sha_path)

    def list_ckpts(self):
        """列出所有 checkpoint"""
        ckpts = sorted(glob.glob(os.path.join(self.save_dir, "*.pt")))
        return [(c, os.path.getsize(c) / 1e9) for c in ckpts]
```

```python
def health_check(path):
    """检查 checkpoint 是否可加载, 无损坏"""
    try:
        state = torch.load(path, map_location="cpu")

        # 1. 必须包含的字段
        required = ["model", "opt", "step"]
        for k in required:
            if k not in state:
                return False, f"Missing key: {k}"

        # 2. model state_dict 必须有 tensor
        if not isinstance(state["model"], dict):
            return False, "Model state not a dict"

        for name, tensor in state["model"].items():
            if not isinstance(tensor, torch.Tensor):
                return False, f"{name} is not a tensor"
            if torch.isnan(tensor).any():
                return False, f"{name} has NaN"

        return True, "OK"

    except Exception as e:
        return False, str(e)
```

## 24. Checkpoint 与训练恢复的故障案例

### 24.1 经典故障案例 1: OOM 后无法恢复

**场景**: LLaMA-7B 训练, 某条超长样本导致 OOM, 整个 DDP 进程崩溃。

**问题**:
- PyTorch 默认行为: 进程直接崩溃, 不保存 checkpoint
- 重启后, 从头开始训, 浪费几小时

**解决**:
```python
# 注册 CUDA 异常处理器
def cuda_oom_handler(signum, frame):
    """捕获 OOM 后, 保存 checkpoint 然后退出"""
    print("OOM detected, saving checkpoint...")
    save_ckpt(...)
    os._exit(1)

# PyTorch hook (PyTorch 2.0+)
torch.cuda.memory._record_memory_history(max_entries=100000)
# 训练循环中
try:
    loss.backward()
except torch.cuda.OutOfMemoryError as e:
    # 保存 checkpoint + 打印内存快照
    torch.cuda.memory._dump_snapshot(f"oom_step_{step}.pickle")
    save_ckpt(...)
    raise
```

### 24.2 经典故障案例 2: 节点硬件故障

**场景**: 1024 卡集群训练, 第 3 天其中一台机器的 GPU 4 硬件损坏。

**问题**:
- Slurm 默认: 整 job 失败, 损失 3 天训练
- 重启后: 训练随机性、数据顺序与原状态不完全一致

**解决**:
1. Slurm 容错配置 (`--requeue`, `--signal`)
2. 训练脚本 signal handler (save + exit)
3. 自动重启脚本: `--restart-on-failure`

```bash
#!/bin/bash
# restart.sh: 检测到失败自动重启, 最多 N 次
MAX_RESTARTS=10
RESTART_COUNT=0

while [ $RESTART_COUNT -lt $MAX_RESTARTS ]; do
    echo "Training attempt $((RESTART_COUNT+1))/$MAX_RESTARTS"
    srun --signal=SIGTERM@120 --kill-on-bad-exit=1 \
        python train.py --resume=auto
    EXIT_CODE=$?

    if [ $EXIT_CODE -eq 0 ]; then
        echo "Training completed successfully"
        break
    fi

    RESTART_COUNT=$((RESTART_COUNT+1))
    echo "Restart $RESTART_COUNT due to exit code $EXIT_CODE"
    sleep 10
done
```

### 24.3 经典故障案例 3: 磁盘写满

**场景**: 训练时磁盘满了, checkpoint 保存失败, 静默丢失进度。

**解决**:
```python
def save_with_disk_check(state, path, min_free_gb=10):
    """保存前检查磁盘空间"""
    save_dir = os.path.dirname(path)
    stat = shutil.disk_usage(save_dir)
    free_gb = stat.free / 1024 ** 3

    if free_gb < min_free_gb:
        # 清理最旧的 checkpoint
        ckpts = sorted(glob.glob(f"{save_dir}/step_*.pt"))
        while ckpts and shutil.disk_usage(save_dir).free / 1024**3 < min_free_gb:
            os.remove(ckpts.pop(0))

    torch.save(state, path)
```

### Q: 如何设计一个生产级 checkpoint 系统?

```text
答案框架:

   - FSDP/DeepSpeed 分片保存
   - 每张卡只存自己分片
   - 加载时自动重新分片

4. 安全 (Security):
   - 用 safetensors 而非 pickle
   - SHA256 校验
   - 加密存储 (敏感模型)

5. 可观测性 (Observability):
   - WandB/MLflow 记录 checkpoint 元数据
```

### 110. 检查点与容错策略 - 优化视角 视角

**核心议题**: 本节从优化视角视角切入,系统展开 "检查点与容错策略" 的相关讨论。

**1. 背景与动机**

任何技术或方法的出现都不是孤立的,而是回应特定历史条件下的具体问题。"检查点与容错策略" 的发展也不例外。要理解它,必须回到它出现的那个时间点,看清它要解决的真实问题是什么。当时的主流方案有哪些不足? 它的提出填补了哪些空白? 这些问题的回答,决定了我们今天该如何使用它。

从知识论角度看,**技术演进是问题驱动的**——不是先有方案再找问题,而是先有问题再有方案。这个观察可以帮助我们避免"拿着锤子找钉子"的陷阱,真正把方法用对地方。

历史维度上,我们看到三个规律:

1. **从特殊到一般**: 早期方法往往针对特定场景,后期抽象出通用框架。学习的认知规律也是先掌握具体案例,再抽象出一般模式。这种"自下而上"的学习方式,在机器学习模型的设计里反复出现。

2. **从手工到自动**: 经验规则逐步被数据驱动的方法取代。在早期,很多 AI 系统依赖人工编写的规则。统计学习方法的崛起让"从数据中学习"成为可能。深度学习进一步把特征工程也自动化了。今天的大模型时代,我们看到端到端学习从感知扩展到了推理与生成。

3. **从局部到全局**: 关注单个组件,演进到关注整个系统。早期模型评估只关注单点指标,现在更关注全链路的协同效应。这种"系统视角"的转变,与软件工程从单体架构到微服务架构的演进高度相似。

**2. 优化视角视角的展开**

从优化视角视角出发,我们可以把 "检查点与容错策略" 拆解为以下几个层次:

**第一层: 概念层** —— 这是最抽象的层次,定义了我们要研究的对象是什么。例如,"推荐系统"在概念层是一个"为用户从物品集合中筛选合适物品"的问题。这个层次的特点是清晰、稳定、不易变化。一个好的概念定义应该具备几个特征:可操作性、可测量性、可扩展性。

**第二层: 模型层** —— 把概念实例化为数学模型。同一概念可以有不同的模型化方式,例如"推荐系统"可以是协同过滤、矩阵分解、深度学习等。模型的选择决定了后续算法的空间,也决定了能利用的归纳偏置(比如序列模型擅长捕捉时序依赖,图模型擅长建模关系结构)。模型选型是工程实践中最重要的决策之一。

**第三层: 算法层** —— 在选定模型下,具体的求解方法。这一层最活跃,新算法层出不穷。同一模型往往有多种算法,各有优劣。例如同样是优化深度网络,可以选择 SGD、Adam、L-BFGS 等不同算法。算法的选择要考虑收敛速度、数值稳定性、计算成本等多个维度。

**第四层: 工程层** —— 算法落地的实现细节,包括数据流水线、训练框架、推理优化、监控告警等。工程层是研究到生产的桥梁,决定了一个方法能否真正用起来。一个在论文里表现很好的算法,如果不能高效实现、不能稳定运行、不能快速迭代,就没有实际价值。工程能力是把研究转化为生产力的关键。

**第五层: 业务层** —— 在具体业务场景中的表现。同一技术在不同业务里效果差异巨大,因为业务目标、数据分布、用户行为都有差异。从业务视角看技术,我们必须回答几个问题:这个技术解决了什么业务问题?投入产出比如何?长期可持续吗?技术评估必须与业务目标对齐,否则容易陷入"技术自嗨"的陷阱。

**3. 数学形式化(简洁版)**

虽然我们强调优化视角视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

偏差-方差分解是另一个核心框架:误差可以分解为模型偏差(欠拟合)、方差(过拟合)和不可约噪声三部分。理解这个分解有助于诊断模型表现、选择合适复杂度。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

信息论为"检查点与容错策略" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。

互信息衡量知道一个变量后,另一个变量不确定性减少的量。在机器学习中,它被广泛用于特征选择、表示学习、多模态对齐等场景。

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

信息瓶颈原则指出,我们应该寻找既紧凑又预测性强的表示。这一思想影响了大量表示学习方法的设计,包括对比学习、自监督学习、多模态预训练等。

**7. 实践建议**

结合 "检查点与容错策略" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "检查点与容错策略" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

对 "检查点与容错策略" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。

**7. 实践建议**

结合 "检查点与容错策略" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "检查点与容错策略" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
