# 第08章-01-LoRA


## 2. 为什么这么做

**问题**:
- 全参数微调 LLaMA-7B 需要 28GB 显存 (FP32 优化器 + 梯度)
- 普通用户无法负担
- 多任务: 每个任务都要存一份全量微调 (70GB/task)

**核心洞察** (Intrinsic SAID):
- 预训练权重的"更新" $\Delta W$ 其实是**低秩**的
- $\Delta W = BA$, $B \in \mathbb{R}^{d \times r}$, $A \in \mathbb{R}^{r \times d}$, $r \ll d$

---

## 3. 这么做的原因 (方案对比)

| 微调方法 | 可训练参数 | 显存 (7B) | 质量 |
|---|---|---|---|
| 全参数微调 | 7B | ~28GB | ★★★★★ |
| **LoRA** (r=8) | ~4M | ~16GB | ★★★★★ |
| **QLoRA** (4bit) | ~4M | ~6GB | ★★★★ |
| Prefix Tuning | 0.1% | 低 | ★★★ |
| Adapter | 1-5% | 中 | ★★★★ |

**为什么 LoRA 有效?**
- 经验发现: 预训练模型的"重要方向"维度很低
- 低秩矩阵 $BA$ 足以表达"任务特定"的修改
- 训练后, 可以合并 $W + BA$ 到原模型, **零推理延迟**

---

## 4. 解决了什么问题

- **显存**: 7B 模型从 28GB → 6GB (QLoRA)
- **多任务**: 每个任务只存几 MB LoRA 权重
- **推理**: LoRA 合并后零延迟
- **质量**: 接近全参数微调

---

## 5. 意义

- LLM 微调的事实标准 (2023+)
- HuggingFace PEFT 库内置
- QLoRA 让消费级 GPU 微调 7B 模型

---

## 6. 公式表达

```text
原始权重更新:
  W_new = W + ΔW,  ΔW ∈ R^(d × d)

LoRA:
  W_new = W + BA,  B ∈ R^(d × r), A ∈ R^(r × d)

  参数量: 2 × d × r (B + A)
  对 r=8, d=4096: 2 × 4096 × 8 = 65,536 (约 65K)
  原始: d² = 4096² ≈ 16M
  压缩比: 16M / 65K = 256 倍

QLoRA (NF4 + 双重量化 + 分页):
  1. NF4 量化预训练模型到 4 bit (≈ 1/4 显存)
  2. LoRA 适配器仍保持 FP16
  3. 双重量化: 量化常数再量化
  4. 分页优化器: 优化器状态分页到 CPU
```

## 9. 答案

### 答案 1: LoRA 层

```python
import numpy as np

class LoRALayer:
    def __init__(self, in_dim, out_dim, r=8, alpha=16):
        # A: 高斯初始化 (Kaiming)
        self.A = np.random.randn(r, in_dim) * (1 / np.sqrt(r))
        # B: 零初始化 (保证初始 ΔW = 0)
        self.B = np.zeros((out_dim, r))
        self.r = r
        self.alpha = alpha
        self.scaling = alpha / r

    def forward(self, x, W):
        """
        x: (B, n, in_dim)
        W: (out_dim, in_dim) 预训练权重 (冻结)
        """
        # 原始: x @ W.T
        original = x @ W.T
        # LoRA: x @ A.T @ B.T * scaling
        lora = (x @ self.A.T) @ self.B.T * self.scaling
        return original + lora
```

**关键**: $B$ 初始化为 0, 所以训练开始时 LoRA 输出 = 0, 模型等于预训练.

### 答案 2: 参数量

```python
def count_lora_params(d, r):
    """
    LoRA 参数量: A (r × d) + B (d × r) = 2 × d × r
    原始参数量: W (d × d) = d²
    压缩比: d / (2r)
    """
    return 2 * d * r

# LLaMA-7B (d=4096, r=8)
d, r = 4096, 8
params = count_lora_params(d, r)
print(f"LoRA 参数量: {params:,}")  # 65,536
print(f"压缩比: {d*d/params:.1f}x")  # 256x
```

### 答案 3: 零推理延迟

```text
训练时:  推理 = x @ (W + BA).T
       = x @ W.T + (x @ A.T) @ B.T  ← 两步矩阵乘法

推理时:  合并!  W_new = W + BA  (一个矩阵)
        推理 = x @ W_new.T  (一步)
```

**关键**: 训练后, 可以选择:
- 保持 W + BA 两个矩阵 → 推理时多一步矩阵乘法
- **合并 W_new = W + BA** → 推理时只一个矩阵, **零额外延迟**

合并公式: `W_new.data = W.data + (B @ A) * scaling`

## 深入: 为什么低秩就够 —— 本征维度假设

LoRA 的理论依据是**"微调更新是低秩的"**:预训练模型已在通用空间学好,适配下游任务只需在一个**很低维的子空间**里移动。研究(Aghajanyan et al.)发现大模型的"本征维度(intrinsic dimension)"很低,几百维就能微调好。所以用秩 $r=8\sim64$ 的 $\Delta W=BA$ 近似全参更新,几乎不掉效果。

- $A$ 高斯初始化、$B$ 零初始化 → 训练起点 $\Delta W=0$,不扰动预训练。
- $\alpha/r$ 缩放:解耦"秩"与"更新幅度",换 $r$ 时不用重调 LR。

---

## 深入: LoRA 变体家族

| 变体 | 改进 | 场景 |
| :--- | :--- | :--- |
| **QLoRA** | 4-bit 量化基座 + LoRA | 单卡微调 65B(省显存) |
| **DoRA** | 分解幅度+方向,方向用 LoRA | 更接近全参微调质量 |
| **rsLoRA** | 修正缩放为 $\alpha/\sqrt{r}$ | 大 $r$ 更稳 |
| **AdaLoRA** | 按重要性动态分配秩 | 参数预算下更优 |
| **LoRA+** | A/B 用不同 LR | 收敛更快 |

**QLoRA** 尤其关键:把冻结基座量化到 NF4(4-bit),显存骤降,让"单张消费级卡微调大模型"成为可能——见 [9.1 量化](../第09章-推理优化/第09章-01-量化.md)。

---

## 深入: LoRA 的工程价值(多租户服务)

LoRA 只存 $A,B$(几十 MB),这带来一个杀手级应用:**一个基座 + N 个 LoRA 适配器**。服务时按请求动态加载不同 LoRA(甚至一个 batch 内混合不同 adapter,如 S-LoRA/Punica),用一份基座显存服务成百上千个定制模型。这是 LoRA 相对全参微调的独特工程优势。

> 权衡:合并进基座 → 零延迟但失去多租户灵活性;不合并 → 保留切换能力但多一步矩阵乘。生产按场景选。

## 10. LoRA 数学推导详解

### 10.1 问题的严格数学刻画

给定一个预训练线性层 (Transformer 中的 $W_q, W_k, W_v, W_o, W_{\text{ffn}_1}, W_{\text{ffn}_2}$ 之一):

$$
h = W_0 x, \quad W_0 \in \mathbb{R}^{d \times k}
$$

其中 $W_0$ 已经被预训练固定, 我们要在下游任务上微调, 损失为:

$$
\mathcal{L}(W) = \mathbb{E}_{(x, y) \sim \mathcal{D}} \left[ \ell(W x, y) \right]
$$

全参数微调: 学习 $\Delta W = W - W_0$, 参数量 $d \times k$ (对 attention 通常 $d=k=4096$).

LoRA 假设: $\Delta W$ 的"有效秩"很低, 可以用低秩分解近似:

$$
W = W_0 + \Delta W = W_0 + \frac{\alpha}{r} B A
$$

其中:

- $B \in \mathbb{R}^{d \times r}$
- $A \in \mathbb{R}^{r \times k}$
- 秩 $r \ll \min(d, k)$
- $\alpha$ 是缩放超参数 (LoRA 论文中 $\alpha$ 与 $r$ 解耦, 让调参更灵活)

最终前向:

$$
h = W_0 x + \frac{\alpha}{r} B A x
$$

---

### 10.2 参数量与显存分析

#### 10.2.1 参数量

| 项 | 维度 | 参数量 |
|---|---|---|
| $W_0$ (冻结) | $d \times k$ | $dk$ (不可训练) |
| $A$ | $r \times k$ | $rk$ |
| $B$ | $d \times r$ | $dr$ |
| **可训练参数总计** | — | **$r(d+k)$** |
| 不可训练 | — | $dk$ |

对 attention 的 Q/V 投影 ($d=k=4096, r=8$):

$$
r(d+k) = 8 \times (4096 + 4096) = 65{,}536
$$

压缩比:

$$
\frac{dk}{r(d+k)} = \frac{4096^2}{65536} = \frac{16\text{M}}{65\text{K}} \approx 256 \text{x}
$$

对 LLaMA-7B 全部 attention + FFN 注入 LoRA (每层 Q/K/V/O + 3 个 FFN, 共 7 个矩阵), 隐藏维 $d=4096$:

$$
\text{Total LoRA} = 7 \times 65{,}536 \approx 458{,}752 \approx 0.45\text{M}
$$

加上 embedding/head 不注入, 总可训练参数占 7B 的 $\approx 0.006\%$.

#### 10.2.2 显存 (训练时, FP32 AdamW)

| 状态 | 全参微调 (7B) | LoRA (r=8) |
|---|---|---|
| 模型权重 (FP16) | 14 GB | 14 GB |
| 优化器状态 (AdamW: m+v, FP32) | 56 GB | $\sim 0.01$ GB |
| 梯度 (FP32) | 28 GB | $\sim 0.01$ GB |
| LoRA 前向中间激活 | — | 略增 |
| **总计** | $\sim 100$ GB | $\sim 14$ GB |

LoRA 主要省在 **优化器状态 + 梯度**. QLoRA 进一步省 **模型权重** 显存 (量化到 4-bit).

---

### 10.3 初始化策略的数学动机

LoRA 初始化:

$$
A \sim \mathcal{N}\left(0, \sigma_A^2\right), \quad B = 0
$$

其中 $\sigma_A = 1/\sqrt{r}$ (等价 Kaiming).

**动机 1**: 训练开始时 $\Delta W = BA = 0$, 模型输出与预训练完全一致, 不会破坏预训练知识.

**动机 2**: 训练起点即最优 (若预训练完美), 学习器只需小步调整, 收敛更稳.

**动机 3**: 反过来如果 $A$ 和 $B$ 都高斯初始化, 训练起点 $\Delta W \neq 0$, 会引入噪声, 微调初期 loss 会上升.

**等价性**: 把 $B$ 初始化为 0 或把 $A$ 初始化为 0 都行 (对称). 约定俗成是 $B = 0$.

---

### 10.4 缩放因子 $\alpha/r$ 的设计

LoRA 输出:

$$
\Delta h = \frac{\alpha}{r} B A x
$$

如果直接用 $BAx$ 不缩放, 改 $r$ 时, 输出尺度会变 (因为 $A$ 用 $1/\sqrt{r}$ 初始化, $A$ 的 Frobenius 范数 $\propto \sqrt{r}$), 训练不稳定.

引入 $\alpha/r$ 后, 当 $\alpha$ 固定, 改 $r$ 不改变输出的"期望尺度" (因为 $B$ 是从 0 学出来的, 其尺度与 $r$ 无关).

论文默认 $\alpha = 2r$ (即 $\alpha/r = 2$), 但实践中:

- 小模型 / 简单任务: $\alpha = r$ (更新幅度小)
- 大模型 / 复杂任务: $\alpha = 2r$ 或 $4r$
- 经验法则: 改 $r$ 时保持 $\alpha/r$ 不变

---

### 10.5 与全参数微调的关系 (Universal approximation)

**定理 (Universal approximation with LoRA)**: 对任意 $\epsilon > 0$ 和任意矩阵 $\Delta W^* \in \mathbb{R}^{d \times k}$, 当 $r \geq \text{rank}(\Delta W^*)$ 时, 存在 $A, B$ 使得 $\|BA - \Delta W^*\|_F < \epsilon$.

即 LoRA 在 $r$ 足够大时表达能力等价于全参微调. 但实践发现 $\text{rank}(\Delta W^*)$ 远小于 $\min(d, k)$, 所以 $r$ 很小就够.

---

### 10.6 训练动力学

LoRA 训练时, 梯度回传:

$$
\frac{\partial \mathcal{L}}{\partial A} = \frac{\alpha}{r} B^\top \frac{\partial \mathcal{L}}{\partial h} x^\top
$$

$$
\frac{\partial \mathcal{L}}{\partial B} = \frac{\alpha}{r} \frac{\partial \mathcal{L}}{\partial h} x^\top A^\top
$$

注意:

1. $A$ 和 $B$ 通过彼此的梯度耦合 (非线性), 但可以用 AdamW 等标准优化器.
2. 由于 $r$ 很小, 梯度计算量很小 ($O(r(d+k))$ vs $O(dk)$).
3. 实践中 $\frac{\alpha}{r}$ 在前向和反向都出现, 不影响梯度方向, 只影响步长.

---

### 10.7 实战: 选哪些层注入 LoRA?

经验法则:

| 注入策略 | 参数量 | 效果 | 场景 |
|---|---|---|---|
| 仅 Q | 最小 | 一般 | 极限显存 |
| 仅 V | 较小 | 一般 | 早期论文 |
| **Q + V** | 中 | **★★★★** | 推荐起点 |
| Q + K + V + O | 较大 | ★★★★ | 默认 PEFT |
| 所有线性 (Q/K/V/O + FFN) | 大 | ★★★★★ | 充足显存 |
| **全部 + Embedding/Head** | 最大 | ★★★★★+ | 全参替代 |

经验: Q+V 是一个性价比很高的甜蜜点. 现代 (LLaMA-2/3, Mistral) 推荐 `target_modules = ["q_proj", "v_proj"]` 作为起点.

---

### 10.8 LoRA 的局限

1. **秩的选择**: 太小欠拟合, 太大不省钱. 业界 $r \in \{4, 8, 16, 32, 64\}$ 居多.
2. **新任务, 新领域**: 域偏移 (domain shift) 大时, 低秩可能不够, 考虑 LoRA + 部分层全参.
3. **持续学习 (Continual Learning)**: 多个 LoRA 适配器顺序训练, 容易灾难遗忘. 解决: 冻结旧 LoRA, 加新 LoRA, 或用正交约束.
4. **推理合并**: 合并后失去多租户灵活性 (见 12 章).

(虚构数据, 用于直觉)

| $r$ | 可训练参数 | 最终 loss | 备注 |

## 11. LoRA 变体家族 (QLoRA / AdaLoRA / DoRA / ...)

### 11.1 QLoRA: 4-bit 量化 + LoRA

#### 11.1.1 核心贡献

论文: *QLoRA: Efficient Finetuning of Quantized LLMs* (Dettmers et al., 2023)

QLoRA = **NF4 量化** + **双重量化 (Double Quantization)** + **分页优化器 (Paged Optimizer)**

目标: 单卡 (24GB) 微调 65B 模型.

#### 11.1.2 NF4 (4-bit NormalFloat)

传统 4-bit 量化: 把 FP16 的值映射到 $2^4 = 16$ 个 bin, 用 FP16 存储 scale/zero-point.

NF4 的洞察: 神经网络权重近似**正态分布** $W \sim \mathcal{N}(0, \sigma^2)$. 因此量化 bin 应该按正态分位数布置, 而不是均匀布置.

NF4 的 16 个量化值 (论文给出, 用 $\sigma = 1$ 归一化后):

$$
\text{NF4 bins} = \{-1.0, -0.6961, -0.5251, -0.3949, -0.2844, -0.1848, -0.0911, 0, \\
0.0796, 0.1609, 0.2461, 0.3379, 0.4407, 0.5626, 0.7229, 1.0\}
$$

直觉: 0 附近 bin 密集 (权重多在 0 附近), 远离 0 bin 稀疏.

#### 11.1.3 分块量化 (Block-wise Quantization)

将权重矩阵分成 64 元素的小块, 每块独立计算 scale/zero-point. 比整张矩阵共享 scale 精度更高.

存储:

$$
\text{每个块: } 64 \times 4\text{bit} + 16\text{bit (FP16 scale)} \approx 36 \text{ bytes/64 元素}
$$

有效位宽: $36 \times 8 / 64 = 4.5$ bit/参数. 比纯 4-bit 多一点 (因 scale 开销), 比 FP16 省 3.5x.

#### 11.1.4 双重量化 (Double Quantization)

对量化常数本身再做一次量化:

$$
\text{外层 block size} = 256 \text{ 个内层 block}
$$

外层: 256 个 FP16 scale 再量化到 FP8. 进一步省 $\sim 0.5$ bit/参数.

节省: 65B 模型从 ~48GB → ~32GB (NF4 alone) → ~32GB-3GB = 29GB (Double Quant).

#### 11.1.5 分页优化器 (Paged Optimizer)

优化器状态 (AdamW 的 m, v) 在显存不足时, **分页到 CPU 内存**, 用 NVIDIA CUDA unified memory 或类似机制.

当 LoRA 梯度 spike, 显存临时不足时, 优化器状态自动换出到 CPU, 显存恢复后再换回. **无性能损失 (只是偶尔慢一点)**.

#### 11.1.6 反量化前向

NF4 权重在前向时**动态反量化到 FP16**:

$$
\text{forward: } h = \text{dequant}(W_0^{\text{NF4}}) x + \frac{\alpha}{r} B A x
$$

反量化逐块进行, 算完即丢, 显存不留 FP16 副本 (除非 cache).

#### 11.1.7 QLoRA 训练代码 (HuggingFace PEFT)

```python
from transformers import AutoModelForCausalLM, BitsAndBytesConfig
from peft import LoraConfig, get_peft_model, prepare_model_for_kbit_training

# 1. 4-bit 量化配置
```

### 11.2 AdaLoRA: 自适应秩分配

论文: *AdaLoRA: Adaptive Budget Allocation for Parameter-Efficient Fine-Tuning* (Zhang et al., 2023)

**问题**: LoRA 所有层用同样 $r$, 但不同层重要性不同. AdaLoRA 让模型**自动分配秩**.

#### 11.2.1 参数化

把 LoRA 改为 SVD 形式:

$$
\Delta W = P \Lambda Q
$$

其中 $P \in \mathbb{R}^{d \times r}$, $\Lambda \in \mathbb{R}^{r \times r}$ (对角, 非负), $Q \in \mathbb{R}^{r \times k}$.

每个奇异值 $\lambda_i \in \Lambda$ 表征第 $i$ 个"方向"的重要性.

#### 11.2.2 动态剪枝

每 $T$ 步 (论文 $T=100$):

1. 计算每个 $\lambda_i$ 的重要性分数: $s_i = \|\lambda_i\|_1 \cdot (\|P_i\|_F + \|Q_i\|_F)$
2. 按 $s_i$ 排序, 把低于阈值的 $\lambda_i$ 置零 (剪掉对应维度)
3. 修剪后, 剩余维度的秩变成新的有效 $r_i$ (每层可能不同)

#### 11.2.3 效果

- 同样参数预算 (总 $r$ 固定), AdaLoRA > LoRA
- 显存一样, 效果更好
- 缺点: 实现复杂, 不支持合并推理 (合并时秩变了)

---

### 11.3 DoRA: 分解幅度与方向

论文: *DoRA: Weight-Decomposed Low-Rank Adaptation* (Liu et al., 2024)

**问题**: LoRA 直接学 $\Delta W = BA$, 但更新有"幅度"和"方向"两部分. 全参微调中两者都可以自由调整.

#### 11.3.1 参数化

$$
W = m \cdot \frac{V + \Delta V}{\|V + \Delta V\|_c}
$$

其中:

- $m \in \mathbb{R}^{1 \times k}$: 幅度向量 (可学习)
- $V \in \mathbb{R}^{d \times k}$: 方向矩阵 (预训练权重的方向)
- $\Delta V = BA$: 方向上的 LoRA 更新
- $\|\cdot\|_c$: 列方向 L2 范数

#### 11.3.2 直觉

- $m$ 控制每列输出的"强度" (类似 LayerNorm 的可学习 scale)
- $V + \Delta V$ 控制"方向"
- 把幅度和方向解耦, 减少训练自由度, 反而泛化更好

#### 11.3.3 效果

论文: 在 LLaMA-7B/13B, DoRA 比 LoRA 在多个 benchmark 高 0.5-2.0 点, 接近全参微调.

---

### 11.4 其他变体 (速览)

| 变体 | 论文 | 核心改动 | 场景 |
|---|---|---|---|
| **rsLoRA** | 2023 | 缩放改成 $\alpha/\sqrt{r}$ | 大 $r$ 更稳 |
| **LoRA+** | 2024 | $A$ 用 LR $\eta_A$, $B$ 用 $\eta_B$, $\eta_B / \eta_A \in \{16, 32\}$ | 收敛更快 |
| **VeRA** | 2023 | 共享冻结随机矩阵, 只学 scaling | 超低参数 (< 0.1%) |
| **GaLore** | 2024 | 不学 LoRA, 学梯度的低秩投影 | 内存省, 接近全参 |
| **LoRA-FA** | 2023 | 冻结 $A$, 只学 $B$ | 进一步省 |
| **LongLoRA** | 2023 | Shifted sparse attention + LoRA | 长上下文 (32k+) |
| **MultiLoRA** | 2024 | 多任务同时学多组 LoRA | 多租户 |

#### 11.4.1 GaLore (Gradient Low-Rank Projection)

**核心洞察**: 梯度也低秩, 可以把优化器状态也低秩存储.

```text
标准 AdamW: m, v ∈ R^(d×k), 各 2×4=8 bytes/param (FP32)
GaLore: m, v ∈ R^(r×k), 各 2×4=8 bytes/param, 但 r≪d, 省 r/d 倍
```

训练: 每步把梯度投影到低秩空间, 在低秩空间做 AdamW, 再投影回去更新.

效果: LLaMA-7B 全参训练, 显存接近 LoRA, 效果接近全参 (比 LoRA 好).

### 11.5 LoRA 选择决策树

```text
任务?
├─ 数据少 (≤10K)
│   ├─ 显存紧 → QLoRA + DoRA
│   └─ 显存够 → LoRA r=8
├─ 数据中 (10K-100K)
│   ├─ 显存紧 → QLoRA + AdaLoRA
│   └─ 显存够 → LoRA r=16-32, target=all
├─ 数据多 (≥100K)
│   ├─ 想接近全参 → DoRA / GaLore
│   └─ 资源允许 → LoRA + 全参部分层 (如 embedding)
└─ 多任务多租户
    └─ LoRA + 服务时动态切换 (S-LoRA)
```

### 12.3 推理时切换 LoRA (多租户)

**场景**: 一个基座 + N 个 LoRA (每个 LoRA 对应一个客户/任务), 按请求动态切换.

```python
from peft import PeftModel

base = AutoModelForCausalLM.from_pretrained("...", torch_dtype=torch.bfloat16)

# 切换 LoRA A
model = PeftModel.from_pretrained(base, "./lora-A")
out_A = model.generate(...)

# 切到 LoRA B (卸载 A, 加载 B)
model.unload()  # 卸载所有 LoRA
model = PeftModel.from_pretrained(base, "./lora-B")
out_B = model.generate(...)
```

**问题**: 每次切换都要 I/O + GPU 内存加载, 慢 (几秒).

**优化: S-LoRA / Punica**

**S-LoRA** (2024): 让基座同时容纳 N 个 LoRA, 一次 forward 中不同请求用不同 LoRA.

实现:

- 把所有 LoRA 的 $A$ 拼接成一个大矩阵 $A_{\text{all}} \in \mathbb{R}^{(N \cdot r) \times k}$
- $B$ 类似拼接
- 用 `torch.bmm` 或专门 kernel 做 batch 矩阵乘
- KV cache 按 LoRA 分桶

效果: 单 A100 服务 100+ 不同 LoRA, 延迟 < 10ms 切换.

### 12.4 推理服务代码 (FastAPI + LoRA)

```python
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from transformers import AutoModelForCausalLM, AutoTokenizer
from peft import PeftModel
import torch

app = FastAPI()

# 全局: 基座只加载一次, LoRA 按需
BASE_PATH = "meta-llama/Llama-2-7b-hf"
LORA_REGISTRY = {
    "customer-A": "./lora-A",
    "customer-B": "./lora-B",
    "customer-C": "./lora-C",
}

tokenizer = AutoTokenizer.from_pretrained(BASE_PATH)
base = AutoModelForCausalLM.from_pretrained(
    BASE_PATH, torch_dtype=torch.bfloat16, device_map="auto"
)
# 预加载 (或按需)
loaded_loras = {}
for name, path in LORA_REGISTRY.items():
    loaded_loras[name] = PeftModel.from_pretrained(base, path, adapter_name=name)

class GenRequest(BaseModel):
    prompt: str
    lora_name: str = "customer-A"
    max_new_tokens: int = 200

@app.post("/generate")
def generate(req: GenRequest):
    if req.lora_name not in loaded_loras:
        raise HTTPException(404, "LoRA not found")

    model = loaded_loras[req.lora_name]
    inputs = tokenizer(req.prompt, return_tensors="pt").to("cuda")
    with torch.no_grad():
        out = model.generate(**inputs, max_new_tokens=req.max_new_tokens)
    return {"text": tokenizer.decode(out[0])}
```

## 13. 面试题精选 50 问 (含答案)

> 高频面试题汇总, 每题先答后解释.

---

### Q1: LoRA 的核心思想是什么? 为什么低秩就够?

**答**: LoRA 冻结预训练权重 $W_0$, 注入可训练低秩分解 $W_0 + BA$, 其中 $B \in \mathbb{R}^{d \times r}, A \in \mathbb{R}^{r \times k}, r \ll \min(d, k)$.

低秩就够的原因: 预训练模型的"任务特定更新" $\Delta W$ 本征维度 (intrinsic dimension) 很低, Aghajanyan et al. (2020) 证明大模型只需几百维就能微调到全参效果. 所以用 $r \in \{4, 64\}$ 就能捕获几乎所有有效更新.

---

### Q2: 参数量怎么算? 7B 模型 $r=8$ 可训练参数多少?

**答**: 每层注入 $Q, V$ (或更多): 单层 LoRA 参数量 $= r \times (d + k)$ (若 $d = k$ 即 $2dr$).

LLaMA-7B ($d = 4096$, 32 层, 注入 Q+V):
$$
32 \times 2 \times (8 \times 4096) = 32 \times 65536 = 2{,}097{,}152 \approx 2\text{M}
$$

占 7B 的 $\frac{2\text{M}}{7\text{B}} \approx 0.03\%$.

---

### Q3: 推理时 LoRA 怎么合并? 延迟多少?

**答**:
$$
W_{\text{merged}} = W_0 + \frac{\alpha}{r} B A \in \mathbb{R}^{d \times k}
$$

合并成一个矩阵, 推理时与普通模型完全一致, **零额外延迟**.

合并代码: `W_0.data += (B @ A) * (alpha / r)`.

---

### Q4: QLoRA 和 LoRA 的关键区别?

**答**:

| 项 | LoRA | QLoRA |
|---|---|---|
| 基座精度 | FP16/BF16 | **NF4 (4-bit)** |
| 基座显存 (7B) | 14 GB | ~3.5 GB |
| 优化器 | 标准 AdamW | **Paged AdamW** (可换出到 CPU) |
| 适用场景 | 中等模型 | 超大模型 / 单卡 |

QLoRA 让**单张 24GB 消费级卡**微调 65B 模型.

---

### Q5: 为什么 B 初始化为 0, A 用高斯?

**答**: 训练起点 $\Delta W = BA = 0$, 模型与预训练完全一致, 不破坏预训练知识. 若 $A, B$ 都高斯, 训练起点 $\Delta W \neq 0$, 会引入噪声, loss 初期会上升.

---

### Q6: $\alpha / r$ 缩放因子的作用?

**答**: 解耦"秩"和"更新幅度". 改 $r$ 时若不缩放, 输出尺度变, 训练不稳定. 引入 $\alpha/r$ 后, 保持 $\alpha/r$ 不变, 改 $r$ 训练动力学一致.

---

### Q7: LoRA 注入哪些层最好?

**答**:

- **仅 Q**: 显存最少, 效果一般.
- **Q+V** (推荐): 性价比甜蜜点.
- **Q+K+V+O**: 默认 PEFT 配置.
- **所有线性 + FFN**: 显存多时.

经验: Q+V 已经是 80% 效果.

---

### Q8: LoRA 训练学习率多少合适?

**答**: $1e^{-4} \sim 3e^{-4}$, 远高于全参 ($1e^{-5} \sim 2e^{-5}$).

原因: LoRA 可训练参数少, 等效 batch size 相对较大, 需要更大 LR.

---

### Q9: LoRA 与 Adapter 的区别?

**答**: Adapter 是"插入新层" (bottleneck: down-proj → non-linear → up-proj + residual), 改变模型结构. LoRA 是"加性低秩更新", 推理时可合并, 不改变原模型结构.

---

### Q10: LoRA 与 Prefix Tuning 的区别?

**答**: Prefix Tuning 加可训练 prefix 到 K/V, 不改 $W$; LoRA 改 $W$. Prefix 不影响模型权重, 可训练参数集中在输入侧. LoRA 更灵活, 效果一般更好.

---

### Q11: LoRA 的训练阶段冻结了什么?

**答**:

- 冻结: 整个基座 $W_0$ (所有 attention + FFN 权重)
- 训练: 仅 $A, B$ 两个低秩矩阵
- 额外: LayerNorm / Embedding 可选训练

---

### Q12: DoRA 是什么? 比 LoRA 好在哪?

**答**: DoRA 把权重分解为**幅度 $m$** 和**方向 $V$**, 方向上用 LoRA 更新. 论文报告比 LoRA 在多项基准高 0.5-2.0 点, 更接近全参微调.

---

### Q13: AdaLoRA 的核心思想?

**答**: 每层自适应分配秩. 不重要的层 $r$ 小, 重要的层 $r$ 大, 总参数预算固定. 用 SVD 参数化 $\Delta W = P\Lambda Q$, 训练中剪掉小的奇异值.

---

### Q14: NF4 是什么? 为什么优于普通 4-bit?

**答**: NormalFloat 4-bit. 量化 bin 按正态分位数布置 (而非均匀), 因为神经网络权重近似正态. 经验上 NF4 比 FP4 误差低 30-50%.

---

### Q15: 双重量化 (Double Quantization) 是什么?

**答**: 把每个块的 FP16 scale 再量化到 FP8, 进一步省 $\sim 0.5$ bit/参数. 65B 模型省约 3GB 显存.

---

### Q16: 分页优化器 (Paged Optimizer) 是什么?

**答**: 优化器状态 (AdamW 的 m, v) 在显存不足时分页到 CPU 内存, 用 NVIDIA unified memory. 显存 spike 时自动换出, 恢复时换回. 性能损失几乎为 0.

---

### Q17: LoRA 可以用于 Embedding 层吗?

**答**: 可以, 用 `LoraConfig(modules_to_save=["embed_tokens", "lm_head"])`. 但 embedding/head 参数量通常很大 (vocab × d), 训练成本高, 不一定划算.

---

### Q18: LoRA 合并后, 还能恢复多租户能力吗?

**答**: 不能. 合并 = 单租户. 想恢复多租户, 必须**保留 BA 不合并**, 推理时动态加载 (用 S-LoRA / Punica 高效切换).

---

### Q19: LoRA 与全参微调在效果上的差距?

**答**: 经验上 $r \geq 8$ 注入所有 attention + FFN, 效果差距 < 1% (下游任务 accuracy). 域偏移大时差距更大.

---

### Q20: LoRA 如何处理多任务学习?

**答**: 每个任务一个 LoRA 适配器, 共用基座. 推理时按任务 ID 切换 LoRA. S-LoRA 让 batch 内混合不同 LoRA, 服务上千任务.

---

### Q21: LoRA 的 batch size 怎么选?

**答**: 受限于显存. 梯度累积 (gradient accumulation) 等效放大 batch:

```python
per_device_train_batch_size = 2
gradient_accumulation_steps = 8
# 有效 batch = 2 × 8 × num_gpus = 16 (单卡)
```

---

### Q22: LoRA 训练多少 epochs?

**答**: 数据少 (10K): 3-5 epochs; 数据中 (100K): 2-3 epochs; 数据多 (1M+): 1-2 epochs.

---

### Q23: LoRA 的 dropout 设置?

**答**: 默认 0.05-0.1. 数据少 / 易过拟合时取大 (0.1), 数据多取小 (0.05) 或 0.

注意: LoRA dropout 在 $BAx$ 上, 不是 $x$ 上.

---

### Q24: r 越大越好吗?

**答**: 不是. $r \geq 16$ 后边际收益极低, 但显存线性增. 推荐 $r \in \{8, 16, 32\}$, 按显存选.

---

### Q25: LoRA 训练用 FP16 还是 BF16?

**答**: 推荐 BF16. BF16 动态范围与 FP32 同 (8-bit 指数), 不易 overflow; FP16 易 loss spike. LoRA 训练梯度小, FP16 容易下溢为 0.

---

### Q26: LoRA 权重文件多大?

**答**: $A + B$ 参数量 × 精度. 7B + r=16 + Q/V/O + FFN (1+3 个矩阵): 约 80M 参数 × 4 bytes (FP32) ≈ 320 MB. 实际保存为 safetensors 后约 300-400 MB.

---

### Q27: 推理时 LoRA 在哪加载?

**答**: 加载流程: base → PeftModel.from_pretrained(base, lora_path) → forward. 实际显存占用: base + LoRA ($A$ + $B$) + KV cache.

---

### Q28: LoRA 可以和 RLHF 一起用吗?

**答**: 可以. RLHF 第一阶段 (SFT) 用 LoRA 微调; 第二阶段 (PPO/DPO) 同样用 LoRA 训练 reward model + policy. LLaMA-2 Chat 即用此方法.

---

### Q29: 什么是 rsLoRA? 优势?

**答**: 缩放因子改成 $\alpha / \sqrt{r}$ 而非 $\alpha / r$. 原因: 论文指出 $\alpha/r$ 在大 $r$ 时更新幅度过小. $\alpha/\sqrt{r}$ 在大 $r$ 时仍保持合理尺度.

---

### Q30: LoRA-FA 是什么?

**答**: Freeze A. 只训练 $B$, 冻结 $A$ (初始化一次). 进一步省一半可训练参数, 效果相当.

---

### Q31: 什么是 VeRA?

**答**: Shared matrices. 所有层共享冻结随机矩阵 $A_{\text{shared}}, B_{\text{shared}}$, 只训练 per-layer 的 scaling 向量. 参数量 < 0.1% 但效果接近 LoRA.

---

### Q32: LoRA 与 Prefix-Tuning 哪个更适合生成?

**答**: LoRA. Prefix-Tuning 在小模型表现一般, LoRA 在各种规模表现稳定. 现代 LLM 默认用 LoRA.

---

### Q33: 为什么 LoRA 不注入 Embedding?

**答**: Embedding 参数量大 (vocab × d, 如 32K × 4096 = 128M), 注入 LoRA 后可训练参数爆炸, 失去 PEFT 意义. 实践中用 `modules_to_save=["embed_tokens"]` 全训练或冻结.

---

### Q34: LoRA 微调 LLaMA 用什么 prompt template?

**答**: 取决于任务. 通用对话:

```text
<s>[INST] <<SYS>>
You are a helpful assistant.
<</SYS>>

{user_message} [/INST] {response} </s>
```

或 Alpaca 格式:

```text
Below is an instruction that describes a task. Write a response that appropriately completes the request.

### Instruction:
{instruction}

### Response:
{response}
```

---

### Q35: LoRA 推理合并后, 还能继续训练吗?

**答**: 可以. 加载合并后的模型作为新的 base, 再注入新的 LoRA. 但失去原 LoRA 的"知识". 想要保留, 必须不合并, 加载多个 adapter.

---

### Q36: 推理 batch 内混合不同 LoRA 怎么实现?

**答**: S-LoRA / Punica.

- 把所有 LoRA 的 $A$ 拼成 $(N \cdot r) \times k$ 大矩阵
- 用 `torch.bmm` (batched matmul) 一次性算所有 LoRA 的输出
- 每个请求选对应输出

实现库: `s-lora`, `punica`, `lorax`.

---

### Q37: LoRA 与 IA3 的区别?

**答**: IA3 (T-Few 论文) 用**可学习向量** (不是矩阵) 乘到 K/V/FFN 中间激活上, 参数量比 LoRA 还少. 但效果弱于 LoRA, 不如 LoRA 通用.

---

### Q38: 训练 LoRA 时, base model 也要前向吗?

**答**: 要. base 不算梯度 (requires_grad=False), 但参与前向. 显存省在**梯度**和**优化器状态**, 不是前向.

---

### Q39: LoRA 适用于所有任务吗?

**答**: 适合: NLU, NLG, 分类, 翻译, 摘要, 对齐. 不太适合: 极大规模域偏移 (如医学 LLM 训练从法律 LLM), 此时考虑全参或继续预训练 + LoRA.

---

### Q40: LoRA 的 alpha 一般设多少?

**答**: $\alpha = 2r$ (论文默认). 实践中 $r=8$ 时 $\alpha=16$, $r=16$ 时 $\alpha=32$, 等等.

也有论文/实践用 $\alpha = r$, 更新幅度更小, 适合微调基础模型.

---

### Q41: 怎么验证 LoRA 训练效果?

**答**:

1. 看 train/eval loss 曲线 (eval 不应过早上升)
2. 在 held-out 测试集上跑标准 benchmark (MMLU, GSM8K, HumanEval 等)
3. 人工评估生成质量 (尤其对齐任务)
4. 与全参微调对比 (同超参)

---

### Q42: LoRA 能用于 Diffusion Model 吗?

**答**: 能. Stable Diffusion XL (SDXL) 默认支持 LoRA, 用 `diffusers` + `peft` 库. 训练 LoRA 几小时就能学会一种风格/角色.

```python
from diffusers import StableDiffusionXLPipeline
from peft import LoraConfig

pipe = StableDiffusionXLPipeline.from_pretrained("stabilityai/stable-diffusion-xl-base-1.0")
pipe.unet.add_adapter(LoraConfig(r=32, target_modules=["to_q", "to_v"]))
```

---

### Q43: LoRA 与 MoE 的关系?

**答**: 不同概念. MoE (Mixture of Experts) 是"多个专家网络 + 路由器", 每个 token 走部分专家. LoRA 是"低秩适配". 二者可叠加 (如 MoLE: MoE + LoRA).

---

### Q44: LoRA 推理时, base 和 LoRA 怎么存?

**答**:

- 单租户: 合并存 base + (W + BA).
- 多租户: 存 base + N 个 LoRA 文件.
- 存储量: base 14GB + N × 300MB. N=100 时 14GB + 30GB = 44GB.

---

### Q45: LoRA 与 BitFit 的关系?

**答**: BitFit 只训练 bias (参数量 ~0.1%), 比 LoRA 还省, 但效果弱. LoRA 一般优于 BitFit.

---

### Q46: 训练 LoRA 时, 怎么选 target_modules?

**答**:

```python
# 方法 1: 名字匹配
target_modules=["q_proj", "v_proj"]

# 方法 2: 正则匹配
target_modules=".*decoder.*(q_proj|v_proj)$"

# 方法 3: 全部线性
target_modules="all-linear"
```

PEFT 库支持.

---

### Q47: LoRA 训练完, 怎么部署?

**答**:

- **小流量**: 合并 + HF Transformers + FastAPI
- **中流量**: vLLM + merged model
- **大流量 / 多租户**: vLLM + LoRA (支持动态加载, 或 S-LoRA)
- **极低延迟**: TensorRT-LLM + merged model

---

### Q48: LoRA 推理用什么推理框架最好?

**答**:

- vLLM: 默认支持 LoRA (单卡或多卡, 动态切换)
- TensorRT-LLM: 高吞吐, 需要先合并或用 LoRA plugin
- SGLang: 多 LoRA 批处理
- llama.cpp (GGUF): 支持 CPU/Apple Silicon 推理 LoRA

---

### Q49: LoRA 训练 vs 全参微调的工业 ROI?

**答**: 7B 模型微调, 单 A100 (80GB):

- 全参: 显存不够 (需 ≥ 4 卡 A100 80GB), 训练 ~20 小时, 成本 ~$400.
- LoRA (r=16): 单 A100 够, 训练 ~6 小时, 成本 ~$60.
- QLoRA: 单 A100/4090/3090 够, 训练 ~10 小时, 成本 ~$80 (但消费级卡单价便宜).

ROI: LoRA 省 70% 成本 + 时间.

---

### Q50: LoRA 还有哪些未解决的问题?

**答**:

1. **最优秩选择**: 没有公式, 只能 sweep
2. **持续学习遗忘**: 多个 LoRA 顺序训练, 旧任务遗忘
3. **域偏移极大时**: 低秩不够, 需要全参
4. **理论保证弱**: 低秩假设经验成立, 理论上 $r$ 应 ≥ intrinsic dim 但我们不知道 dim
5. **与量化干扰**: NF4 + LoRA 组合的精度损失难以预测

## 14. 实战案例 (Case Studies)

### 14.1 Case 1: 用 LoRA 微调 LLaMA-3-8B 做客服对话

**目标**: 把通用 LLaMA-3 微调成"电商客服", 回答退款、物流、订单问题.

**数据**: 5000 条人工标注的客服对话 (instruction, response).

**配置**:

```python
lora_config = LoraConfig(
    r=16,
    lora_alpha=32,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_dropout=0.05,
    bias="none",
    task_type="CAUSAL_LM",
)
```

训练: 单 A100 80GB, 3 epochs, LR 2e-4, 总时长 4 小时.

**结果**:

- HumanEval: 62 → 58 (微调后略降, 但客服场景是核心)
- 内部客服准确率: 73% (base) → 91% (LoRA)
- 显存峰值: 24 GB (BF16 base + LoRA)

---

### 14.2 Case 2: QLoRA 微调 65B 模型在 3090 上

**目标**: 在单卡 24GB 3090 上微调 LLaMA-2-65B.

**配置**:

```python
bnb_config = BitsAndBytesConfig(
    load_in_4bit=True,
    bnb_4bit_quant_type="nf4",
    bnb_4bit_use_double_quant=True,
    bnb_4bit_compute_dtype=torch.bfloat16,
)
```

训练: 单 3090 24GB, batch_size=1, grad_accum=16, 1 epoch, 24 小时.

**结果**: 显存峰值 22 GB, 速度 ~1 sample/sec.

**关键**: LoRA r=8 + 4-bit base 让 65B 在消费级卡微调成为可能.

### 14.3 Case 3: SDXL + LoRA 学画风

**目标**: 用 Stable Diffusion XL 学一种新画风 (如赛博朋克风格).

**数据**: 100 张赛博朋克风格图片 + 文本描述.

**配置**:

```python
lora_config = LoraConfig(
    r=32,
    lora_alpha=32,
    target_modules=["to_q", "to_v", "to_k", "to_out.0"],
    init_lora_weights="gaussian",

```

训练: 单 A6000 48GB, 1000 steps, 30 分钟.

**结果**: 推理时加载 LoRA, 风格一致性提升明显, 文件仅 60MB, 可分享.

### 14.4 Case 4: 多任务 LoRA (S-LoRA 服务)

**场景**: 100 个客户, 每个客户一个 LoRA, 共用一份 LLaMA-3-70B 基座.

**架构**:

- 单 A100 80GB, base 加载一次 (40GB)
- 100 LoRA 总大小 100 × 400MB = 40GB
- KV cache 和动态 batch

**实现**: vLLM + LoRA plugin

```python
from vllm import LLM, SamplingParams
from vllm.lora.request import LoRARequest

llm = LLM(model="meta-llama/Meta-Llama-3-70B", enable_lora=True, max_loras=4)

outputs = llm.generate(
    prompts,
    [LoRARequest("customer-1", lora_int_id=1), LoRARequest("customer-2", lora_int_id=2)],
    sampling_params,
)
```

**吞吐**: 单卡支持 100+ LoRA, 平均延迟 < 50ms.

### 15.2 怎么选?

**决策树**:

```text
Q1: 显存够吗?
├─ 不够 → QLoRA (NF4 + LoRA)
```

## 17. 常见误区 (Pitfalls)

### 17.1 误区 1: "LoRA 可以替代全参微调"

LoRA 在**大多数**任务上逼近全参, 但不是 100%. 极端任务 (极大域偏移、极复杂推理) 仍可能掉点. 论文报告 LoRA 在 GSM8K、BBH 等复杂任务上仍落后 1-3 点.

### 17.2 误区 2: "r 越大越好"

错. $r \geq 32$ 后边际收益极低. $r=8$ vs $r=128$ 效果差 < 1%, 但后者显存多 16x.

### 17.3 误区 3: "QLoRA 比 LoRA 慢"

不一定. QLoRA 反量化有开销, 但可以用更激进的 batch size 抵消. 实测 QLoRA 训练速度约 LoRA 的 90-95%.

### 17.4 误区 4: "LoRA 训练不需要 warmup"

错. LoRA 训练初期 (前 100-500 步) 梯度方向尚不稳定, 必须 warmup. 推荐 `warmup_ratio=0.03`.

### 17.5 误区 5: "LoRA 合并后无法恢复"

技术上无法"反合并" (浮点精度损失), 但可以**重新加载 LoRA + base**, 重新合并. 训练时一定要**保留 LoRA 权重文件**!

### 17.6 误区 6: "LoRA 越多越好"

每个 LoRA 增加推理开销 (如果不合并). 100+ LoRA 需要 S-LoRA 等专门优化, 否则显存爆炸.

## 19. 一页纸总结 (Cheatsheet)

```text
LoRA = 冻结 base + 低秩 BA 更新
公式: W = W₀ + (α/r)·B·A,  B∈R^(d×r), A∈R^(r×k), r≪d
初始化: A 高斯, B 零 (起点 ΔW=0)
参数量: r(d+k), 压缩比 d²/r(d+k)
推理合并: W_new = W₀ + (α/r)·B·A → 零延迟

QLoRA = NF4 (4-bit) + Double Quant + Paged Optim
NF4: 正态分位 bin, 4-bit 量化 base
效果: 65B 单卡 24GB, 几乎不损质量

推荐配置:
- r=16, α=32, target=[q,v], dropout=0.05
- LR 2e-4, epochs 2-3, BF16
- 8bit AdamW + grad checkpoint

优势:
- 显存省 10x, 训练快 3x
- 多租户 (S-LoRA 一基座 N 适配器)
- 合并后零推理延迟
- 接近全参 (1-2% gap)
```

## 21. LoRA 数值稳定性与初始化细节

### 21.1 数值范围与缩放

LoRA 中 $A$ 用 $\mathcal{N}(0, 1/r)$ (即 Kaiming uniform / Gaussian scaled), $B = 0$. 训练起点 $\Delta W = 0$, 但前向过程中梯度计算仍依赖 $A$ 的尺度.

设 $A$ 的 Frobenius 范数:

$$
\|A\|_F = \sqrt{\sum_{i,j} A_{ij}^2} = \sqrt{r \cdot k \cdot \sigma_A^2} = \sqrt{r \cdot k} \cdot \sigma_A
$$

取 $\sigma_A = 1/\sqrt{r}$:

$$
\|A\|_F = \sqrt{r \cdot k} \cdot \frac{1}{\sqrt{r}} = \sqrt{k}
$$

即 $\|A\|_F = \sqrt{k}$, 与 $r$ 无关. 这是**秩不变的初始化**.

### 21.2 梯度范数估计

训练一步:

$$
\Delta A \propto \frac{\partial \mathcal{L}}{\partial A} = \frac{\alpha}{r} B^\top \frac{\partial \mathcal{L}}{\partial h} x^\top
$$

因 $B$ 起点为 0, $\partial A = 0$ (第一步). 但经过几步后, $B$ 学到非零, $\partial A$ 非零.

经验: $\Delta A$ 范数 $\propto \sqrt{r}$ (因 $\partial A$ 含 $B^\top$, 而 $B \in \mathbb{R}^{d \times r}$), 所以 $\Delta A / A$ 的相对更新幅度与 $\sqrt{r}$ 相关.

引入 $\alpha / r$ 缩放后, 等效更新步长 $\propto \alpha / r$, 让训练动力学对 $r$ 不敏感.

### 21.3 数值精度选择

| 精度 | base | LoRA | 备注 |
|---|---|---|---|
| FP32 | FP32 | FP32 | 慢, 显存大, 不用 |
| **BF16 + FP32 master** | BF16 | FP32 | 推荐: 训练时 |
| FP16 + FP32 master | FP16 | FP32 | 易 loss spike |
| NF4 + BF16 | NF4 | BF16 | QLoRA |

**最佳实践**: base 用 BF16 (训练时动态反量化到 BF16), LoRA 参数和 master weights 用 FP32. 优化器状态用 FP32 或 8-bit.

### 21.4 混合精度训练模板

```python
from torch.cuda.amp import autocast

model = model.to(torch.bfloat16)  # base in BF16
# LoRA params in FP32 (default in PEFT)

for batch in dataloader:
    with autocast(dtype=torch.bfloat16):
        out = model(**batch)
        loss = out.loss
    loss.backward()  # grads in FP32 for LoRA
    optimizer.step()
```

## 22. LoRA 推理优化技术

### 22.1 量化推理 (INT8/INT4)

LoRA 合并后, 模型仍是 FP16, 可进一步量化:

```python
from transformers import AutoModelForCausalLM, BitsAndBytesConfig

bnb_config = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_compute_dtype=torch.bfloat16)
quantized = AutoModelForCausalLM.from_pretrained("./merged-model", quantization_config=bnb_config)
```

效果: 7B 模型 FP16 14GB → INT4 4GB, 速度损失 < 10% (取决于实现).

### 22.2 KV Cache 优化

推理时 KV cache 占用 $O(n \cdot d \cdot L)$, 长上下文时是瓶颈.

优化:

- **PagedAttention** (vLLM): 分块管理 KV cache, 减少碎片
- **GQA / MQA**: 多 Q 头共享 K/V 头, KV 减少 4-8x
- **Flash Decoding**: 长序列 decode 优化

### 22.3 Speculative Decoding + LoRA

用小模型 draft, 大模型 verify. LoRA 切换 + speculative 加速:

```python
# 小模型 draft LoRA, 大模型 target LoRA
draft_outputs = draft_model.generate(prompt, max_new_tokens=10)
target_outputs = target_model.generate(prompt, max_new_tokens=1, draft=draft_outputs)
```

加速比: 2-3x.

### 22.4 Continuous Batching (vLLM)

```python
from vllm import LLM, SamplingParams

llm = LLM(
```

### 23.2 LoRA + 蒸馏

**教师**: 全参微调的大模型. **学生**: LoRA 微调的小模型.

```python
def distillation_loss(student_logits, teacher_logits, temperature=4.0):
    soft_teacher = F.softmax(teacher_logits / temperature, dim=-1)
    soft_student = F.log_softmax(student_logits / temperature, dim=-1)
    return F.kl_div(soft_student, soft_teacher, reduction='batchmean') * (temperature ** 2)

loss = 0.5 * ce_loss(student_logits, labels) + 0.5 * distillation_loss(student_logits, teacher_logits)
```

效果: 学生模型可压缩到教师的 30-50%, 保留 90%+ 性能.

```python
# 每个 expert 是一个 LoRA
```

## 24. LoRA 在生产环境的踩坑记录

### 24.1 坑 1: tokenizer 不匹配

**症状**: 训练 loss 正常, 推理输出乱码.

**原因**: base 和 LoRA 用了不同 tokenizer.

**解决**:

```python
# 训练时, tokenizer 必须与 base 一致
tokenizer = AutoTokenizer.from_pretrained(base_model_path)
# 推理时同样路径
```

### 24.2 坑 2: chat template 不一致

**症状**: SFT 训练时 loss 下降, 但部署后输出格式不对.

**原因**: 训练时用了 `<s>[INST] ... [/INST]` 格式, 推理时漏掉 system prompt.

**解决**: 把 chat template 写进代码, 不依赖人工:

```python
def apply_chat_template(messages):
    return tokenizer.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
```

### 24.3 坑 3: LoRA 与 bfloat16 兼容性

**症状**: 训练时 loss = NaN.

**原因**: 部分 GPU (老 V100) 不支持 BF16.

**解决**:

```python
if not torch.cuda.is_bf16_supported():
    args.fp16 = True  # fallback
```

### 24.4 坑 4: padding side 错误

**症状**: 训练 loss 不下降, 生成内容截断.

**原因**: 训练用了 right padding, 推理 left padding; 或者反过来.

**解决**: 训练用 right padding (适合并行), 推理用 left padding (适合生成).

```python
# 训练
tokenizer.padding_side = "right"

# 推理
tokenizer.padding_side = "left"
```

### 24.5 坑 5: 多卡训练时 LoRA 不收敛

**症状**: DDP/FSDP 训练, loss 抖动.

**原因**: LoRA 参数量小, DDP 的 all-reduce 引入方差.

**解决**:

```python
# 用 gradient_as_bucket_view=True (PyTorch ≥ 2.0)
# 或者用 DeepSpeed Zero-2 而非 DDP
```

## 25. 高级话题: LoRA 的理论分析

### 25.1 本征维度 (Intrinsic Dimension)

Aghajanyan et al. (2020) 发现, 大模型微调到一个随机子空间 (随机投影到 $d_0$ 维) 也能达到全参效果, $d_0$ 称为"本征维度".

实验: GPT-2 / RoBERTa, 本征维度 100-1000, 比模型维度 768-1600 还低!

LoRA 的 $r$ 直接控制"有效本征维度". $r=8$ 对应 8 维子空间, 在很多任务上足够.

### 25.2 谱分析 (Spectral Analysis)

观察 LoRA 训练后的 $BA$ 矩阵, 奇异值分布:

$$
BA = U \Sigma V^\top, \quad \Sigma = \text{diag}(\sigma_1, \sigma_2, ..., \sigma_r)
$$

实验发现:

- $\sigma_1 \gg \sigma_2 \gg ... \gg \sigma_r$ (近似指数衰减)
- 实际有效秩 $\text{rank}_{\epsilon}(BA)$ 远小于 $r$
- 这说明: **理论 $r$ 是上界, 实际有效秩更低**

启示: 可以用更小的 $r$ 而不损效果 (例如 $r=4$ 实际有效秩约 2).

### 25.3 与全参微调的等价性条件

**定理 (LoRA vs Full FT)**: 当 $\text{rank}(\Delta W_{\text{full}}) \leq r$ 时, LoRA 可以完美匹配全参微调.

但实际 $\text{rank}(\Delta W_{\text{full}})$ 往往较高 (虽然主成分只占少量能量), 所以 LoRA 是**近似**.

### 25.4 LoRA 与 Nuclear Norm 约束

LoRA 的 $BA$ 等价于加了 nuclear norm 约束:

$$
\min \|W - W_0\|_* \quad \text{s.t.} \quad \mathcal{L}(W) \approx 0
$$

其中 $\|\cdot\|_*$ 是核范数 (奇异值之和). 这隐式鼓励 $\Delta W$ 低秩.

## 27. LoRA 的局限与未来

### 27.1 当前局限

1. **秩选择无理论指导**: 靠 sweep, 没有公式预测最优 $r$
2. **域偏移大时退化**: 法律 LLM → 医学 LLM, 域偏移极大, LoRA 不够
3. **持续学习**: 多 LoRA 顺序训练会灾难遗忘
4. **理论空白**: 为什么 $r=8$ 在大多数任务够, 没有严格解释
5. **多模态对齐**: VLM/ALM 中 LoRA 注入位置无定论

### 27.2 未来方向

1. **自适应架构**: 自动决定 $r$ 和注入位置 (AdaLoRA 是初步尝试)
2. **持续学习集成**: 让 LoRA 不遗忘 (EWC + LoRA, O-LoRA 等)
3. **理论统一**: 把 LoRA 与 nuclear norm / 矩阵分解理论统一
4. **多模态专用**: 针对 VLM 的结构化 LoRA
5. **稀疏 + 低秩**: 剪枝 + LoRA 组合

### 27.3 LoRA 与 AGI 的关系 (哲学)

LoRA 的核心洞察: **大模型已经"知道一切", 微调只是"唤起"特定子能力**.

这与人类大脑的"突触可塑性" 类似——成年后学新东西, 大脑不是长出新神经元, 而是修改现有突触强度. LoRA 就是"修改突触强度" 的工程实现.

未来: 如果 AGI 真的存在, 它很可能有"LoRA 化的学习" 机制——主网络固定, 用低秩适配器快速学习新任务.
