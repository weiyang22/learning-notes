# 第08章-03-DPO


## 1. 内容介绍

**DPO (Direct Preference Optimization)** 是 2023 年 Stanford 提出的 RLHF 简化方法. **不需要训练奖励模型**, 直接用偏好数据 (chosen, rejected) 对训练 LLM.

后续改进: **KTO** (Kahneman-Tversky Optimization), **ORPO** (Odds Ratio Preference Optimization).

---

## 2. 为什么这么做

**RLHF 的痛点** (见 8.2):
- 训练 Reward Model 复杂
- PPO 训练不稳定, 4 个模型 (ref, actor, critic, reward)
- 超参数多, 难调

**DPO 的核心洞察**:
- RLHF 的"奖励函数" $r(x, y) = \beta \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)$
- **闭式解**: 把奖励代入 PPO, 可以直接优化 LLM
- 不需要训练 RM, 不需要 PPO
- 一阶段: 直接从偏好数据优化

---

## 3. 这么做的原因 (DPO vs RLHF)

| 维度 | RLHF | DPO |
|---|---|---|
| 训练阶段 | 3 (SFT + RM + PPO) | 1 (直接训练) |
| 模型数 | 4 (SFT + RM + ref + policy) | 2 (ref + policy) |
| 稳定性 | 差 (PPO 敏感) | 好 (SFT-like) |
| 显存 | 高 | 低 |
| 质量 | ★★★★★ | ★★★★ (略低) |
| 实现复杂度 | 高 | 低 |

---

## 4. 解决了什么问题

- **RM 训练**: 跳过
- **PPO 不稳定**: 跳过
- **超参数调优**: 简化 (主要是 β)

---

## 5. 意义

- 2023+ 开源 LLM 主流对齐方法 (Mistral, Qwen, GLM 等很多用 DPO)
- 简化流程, 民主化对齐

---

## 6. 公式表达

```text
DPO 目标:
  L_DPO = -E_{(x, y_w, y_l) ~ D} [log σ(
    β · log(π_θ(y_w|x) / π_ref(y_w|x))
    - β · log(π_θ(y_l|x) / π_ref(y_l|x))
  )]

  直觉: 拉大 chosen vs rejected 的"对数概率比"差

KTO (行为经济学):
  - 不需要成对数据, 只需 (x, y, good/bad)
  - 借鉴 Kahneman-Tversky 的"损失厌恶"理论
  - L_KTO = λ_D · E[r_w] + λ_U · E[r_l]
  - r = β · log(π_θ(y|x) / π_ref(y|x)) - z_ref
  - z_ref = E[KL ref || π_θ] (参考散度)

ORPO (无 Reference):
  - 不用 reference 模型, 节省显存
  - L_ORPO = L_SFT + λ · L_odds
  - L_odds = -log σ(log odds(θ_w) - log odds(θ_l))
  - odds = π(y) / (1 - π(y))
```

## 9. 答案

### 答案 1: DPO 损失

```python
import numpy as np

def dpo_loss(policy_chosen_logps, policy_rejected_logps,
             ref_chosen_logps, ref_rejected_logps, beta=0.1):
    """
    DPO 损失
    L = -E[log σ(β · (log π_θ(y_w)/π_ref(y_w) - log π_θ(y_l)/π_ref(y_l)))]
    """
    # π_θ / π_ref 的对数比
    chosen_logratios = policy_chosen_logps - ref_chosen_logps
    rejected_logratios = policy_rejected_logps - ref_rejected_logps

    # DPO logits
    logits = beta * (chosen_logratios - rejected_logratios)

    # log σ(x) = -log(1 + exp(-x)) = -softplus(-x)
    loss = -np.log(1 / (1 + np.exp(-logits)))  # log σ
    return loss.mean()
```

**复杂度**: $O(B)$, 简单稳定.

### 答案 2: DPO 不需要 RM 的原因

```text
RLHF 奖励函数:
  r(x, y) = β · log(π_θ(y|x) / π_ref(y|x)) + β · log Z(x)

  Z(x) = partition function, 不依赖 y

代入 PPO 目标:
  L_PPO = -E[π_θ · A]  其中 A = r - V(s)

  关键是 r 由 π_θ 自己提供, 不用 RM
  V(s) 用 GAE 估计
```

**关键推导**:
```text
Bradley-Terry 模型: P(y_w > y_l) = σ(r(y_w) - r(y_l))
代入 r = β · log(π_θ/π_ref) + 常数:
P(y_w > y_l) = σ(β · log(π_θ(y_w)/π_ref(y_w)) - β · log(π_θ(y_l)/π_ref(y_l)))
取负对数 → DPO loss
```

**结论**: DPO 损失 = RLHF 优化目标的闭式解, 等价但简单.

### 答案 3: DPO 局限性

```text
1. 依赖 reference 模型:
   - 需要保留 SFT 后的 ref 模型, 增加显存
   - ORPO / KTO 改进: 不需要 ref

2. 质量略低于 RLHF:
   - 闭式解失去了"过程控制"
   - RLHF 可以用 PPO 的 clip, DPO 不能
   - 实际差距 < 1%

3. 数据需求:
   - 需要成对 (chosen, rejected)
   - KTO 改进: 不需要成对, 只需 (x, y, label)
   - 降低数据标注成本

4. 多样性:
   - DPO 容易"模式坍缩" (总是选 chosen 的开头)
   - 改进: 加熵正则 / SimPO
```

## 深入: 从 RLHF 目标到 DPO 损失(完整推导链)

RLHF 的优化目标(KL 约束下最大化奖励)有**解析最优解**:

$$\pi^*(y|x) = \frac{1}{Z(x)}\pi_{ref}(y|x)\exp\!\Big(\tfrac{1}{\beta}r(x,y)\Big)$$

反解出奖励:$r(x,y)=\beta\log\frac{\pi^*(y|x)}{\pi_{ref}(y|x)}+\beta\log Z(x)$。代入 Bradley-Terry 偏好模型 $P(y_w\succ y_l)=\sigma(r_w-r_l)$,配分函数 $Z(x)$ **在差里抵消** → 得到 DPO 损失。

> 三步链:**KL-RL 最优解 → 反解奖励 → 代入 BT 模型(Z 抵消)**。理解这条链 = 理解 DPO 为什么"不需要 RM、不需要采样"。

---

## 深入: 免 reference 与免成对的后继方法

DPO 仍需 reference 模型 + 成对数据。后继工作各去掉一个约束:

| 方法 | 去掉了 | 机制 |
| :--- | :--- | :--- |
| **DPO** | RM + RL | 偏好分类损失 |
| **IPO** | (修正 DPO 过拟合) | 换损失防偏好确定性过强 |
| **KTO** | 成对约束 | 只需 (x,y,好/坏) 单点标签(前景理论) |
| **ORPO** | reference 模型 | SFT 阶段加 odds-ratio 惩罚,一步到位 |
| **SimPO** | reference 模型 | 用平均对数概率 + 长度归一 |

趋势:**越来越轻**——从 RLHF(4 模型)→ DPO(2 模型)→ ORPO/SimPO(1 模型)。

---

## 深入: DPO vs GRPO(两条对齐路线)

| | DPO 系 | GRPO/RL 系 |
| :--- | :--- | :--- |
| 数据 | 静态偏好对 | 在线采样 + 奖励 |
| 探索 | 无 | 有(采样新回答) |
| 适合 | 偏好对齐(HHH) | **可验证推理**(数学/代码) |
| 成本 | 低 | 高 |

**分工**:一般对齐(有用无害)用 DPO 轻量搞定;**激励推理**(需要探索 + 可验证奖励)用 GRPO(见 [LLM发展第05章](../../LLM发展/第05章-对齐技术演进.md))。2025 的推理模型(R1)走 GRPO 而非 DPO,正因为 DPO 无探索。

## 10. DPO 损失推导：从 Bradley-Terry 到可训练目标

### 10.1 问题设定

给定 prompt $x$，偏好数据集中包含两个回答：

- $y_w$：标注者更偏好的 chosen response；
- $y_l$：标注者较不偏好的 rejected response；
- $\pi_\theta$：正在优化的策略（policy）；
- $\pi_{\text{ref}}$：参考策略（reference model，通常为 SFT 模型）；
- $\beta$：KL 散度约束的权重（温度参数）。

DPO 的目标：让策略 $\pi_\theta$ **增加** chosen 的相对概率，**降低** rejected 的相对概率，同时**不过分偏离** $\pi_{\text{ref}}$。

### 10.2 Bradley-Terry 偏好模型

Bradley-Terry (1952) 模型是处理"成对比较"数据的经典概率模型。它假设每个回答 $y$ 有一个隐式得分 $r(x, y)$，那么 $y_w$ 优于 $y_l$ 的概率为：

$$
P(y_w \succ y_l \mid x) = \frac{\exp(r(x, y_w))}{\exp(r(x, y_w)) + \exp(r(x, y_l))} = \sigma(r(x, y_w) - r(x, y_l))
$$

其中 $\sigma(z) = 1 / (1 + e^{-z})$ 是 sigmoid 函数。

**直觉**：sigmoid 把"得分差"映射到 0~1 之间的偏好概率。差越大，越偏好 $y_w$。

### 10.3 RLHF 的最优策略

RLHF 的目标是：在 KL 散度约束下，最大化期望奖励：

$$
\max_{\pi} \; \mathbb{E}_{x \sim \mathcal{D}, y \sim \pi(y|x)} \big[ r(x, y) \big] - \beta \cdot \mathbb{KL}\big[\pi(\cdot|x) \,\|\, \pi_{\text{ref}}(\cdot|x)\big]
$$

用变分法可以证明**闭式最优解**为：

$$
\pi^*(y|x) = \frac{1}{Z(x)} \pi_{\text{ref}}(y|x) \exp\!\left( \frac{1}{\beta} r(x, y) \right)
$$

其中 $Z(x) = \sum_y \pi_{\text{ref}}(y|x) \exp(r(x,y)/\beta)$ 是配分函数（partition function），与 $y$ 无关，只与 $x$ 有关。

### 10.4 反解奖励函数

把上式两边取对数并整理：

$$
\log \frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} = \frac{1}{\beta} r(x, y) - \log Z(x)
$$

移项得到奖励函数的**闭式表达**：

$$
r(x, y) = \beta \log \frac{\pi^*(y|x)}{\pi_{\text{ref}}(y|x)} + \beta \log Z(x)
$$

**关键观察**：
- 奖励完全由 $\pi^*$ 自己提供，不需要单独的 RM。
- $\log Z(x)$ 项只依赖于 $x$，不依赖于具体的 $y$。

### 10.5 代入 Bradley-Terry

把奖励代入偏好模型：

$$
P(y_w \succ y_l \mid x) = \sigma\Big( r(x, y_w) - r(x, y_l) \Big)
$$

由于 $\log Z(x)$ 在差里抵消：

$$
\begin{aligned}
r(x, y_w) - r(x, y_l) &= \beta \log \frac{\pi^*(y_w|x)}{\pi_{\text{ref}}(y_w|x)} + \beta \log Z(x) \\
&\quad - \beta \log \frac{\pi^*(y_l|x)}{\pi_{\text{ref}}(y_l|x)} - \beta \log Z(x) \\
&= \beta \log \frac{\pi^*(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi^*(y_l|x)}{\pi_{\text{ref}}(y_l|x)}
\end{aligned}
$$

所以：

$$
P(y_w \succ y_l \mid x) = \sigma\!\left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} \right)
$$

### 10.6 DPO 损失

取负对数似然：

$$
\mathcal{L}_{\text{DPO}}(\theta) = -\mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma\!\left( \beta \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \beta \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} \right) \right]
$$

用对数比的对数改写更简洁。定义隐式奖励 $r_\theta(x, y) = \beta \log \frac{\pi_\theta(y|x)}{\pi_{\text{ref}}(y|x)}$，那么：

$$
\mathcal{L}_{\text{DPO}}(\theta) = -\mathbb{E}\big[ \log \sigma\big( r_\theta(x, y_w) - r_\theta(x, y_l) \big) \big]
$$

**梯度直觉**：当 chosen 的隐式奖励 > rejected 的隐式奖励时，$\sigma$ 输出接近 1，损失接近 0；反之输出接近 0，损失很大，梯度会推动 $\pi_\theta$ 提升 chosen、降低 rejected。

### 10.7 PyTorch 实现（生产级）

```python
import torch
import torch.nn as nn
import torch.nn.functional as F


def compute_logps(policy_model, input_ids, attention_mask, labels):
    """
    给定 prompt+response 的 token 序列, 返回 response 部分的对数概率和。
    """
    outputs = policy_model(input_ids=input_ids, attention_mask=attention_mask)
    logits = outputs.logits  # [B, T, V]

    # labels: [B, T], 真实 token id, prompt 部分设为 -100
    shift_logits = logits[:, :-1, :].contiguous()
    shift_labels = labels[:, 1:].contiguous()

    # 收集 response token 的 log-prob
    log_probs = F.log_softmax(shift_logits, dim=-1)
    per_token_logp = log_probs.gather(2, shift_labels.unsqueeze(-1)).squeeze(-1)  # [B, T-1]

    mask = (shift_labels != -100).float()
    return (per_token_logp * mask).sum(dim=-1)  # [B], 每条样本 response 的总对数概率


class DPOLoss(nn.Module):
    """
    标准 DPO 损失（reference-free forward, 但内部需要 ref 的 logp）
    """
    def __init__(self, beta: float = 0.1, label_smoothing: float = 0.0,
                 loss_type: str = "sigmoid"):
        super().__init__()
        self.beta = beta
        self.label_smoothing = label_smoothing
        self.loss_type = loss_type

    def forward(self, policy_chosen_logps, policy_rejected_logps,
                ref_chosen_logps, ref_rejected_logps):
        # 隐式奖励: r_theta = beta * log(pi_theta / pi_ref)
        chosen_logratios = policy_chosen_logps - ref_chosen_logps
        rejected_logratios = policy_rejected_logps - ref_rejected_logps

        # DPO logits
        logits = self.beta * (chosen_logratios - rejected_logratios)

        if self.loss_type == "sigmoid":
            # 标准 DPO
            loss = -F.logsigmoid(logits) * (1 - self.label_smoothing) \
                   - F.logsigmoid(-logits) * self.label_smoothing
        elif self.loss_type == "hinge":
            # 当 chosen 不显著优于 rejected 时不再优化
            loss = torch.relu(1 - logits)
        elif self.loss_type == "ipo":
            # IPO 损失, 见 11.2
            loss = (logits - 1) ** 2
        elif self.loss_type == "kto":
            # KTO 近似, 见 11.3
            chosen_KL = chosen_logratios.sum()  # 实际是期望
            loss = ...
        else:
            raise ValueError(f"Unknown loss_type: {self.loss_type}")

        # 额外: chosen reward 偏离 ref 太多时, 加一个 ref 锚定项
        chosen_reward = self.beta * chosen_logratios.detach()
        rejected_reward = self.beta * rejected_logratios.detach()
        # 指标: chosen reward 应该 > rejected reward
        reward_margin = (chosen_reward - rejected_reward).mean()

        return loss.mean(), {
            "reward_margin": reward_margin.item(),
            "chosen_reward": chosen_reward.mean().item(),
            "rejected_reward": rejected_reward.mean().item(),
        }


class DPOTrainer:
    """
    极简版 DPO 训练循环示意 (HuggingFace TRL 风格)
    """
    def __init__(self, policy_model, ref_model, tokenizer, beta=0.1, lr=1e-6):
        self.policy = policy_model
        self.ref = ref_model  # 通常冻结
        self.tokenizer = tokenizer
        self.beta = beta
        self.optimizer = torch.optim.AdamW(policy_model.parameters(), lr=lr)
        self.loss_fn = DPOLoss(beta=beta)

    def compute_batch_logps(self, model, batch):
        # batch: dict with chosen_input_ids, chosen_labels, rejected_*, attention_mask
        chosen_logps = compute_logps(
            model, batch["chosen_input_ids"],
            batch["chosen_attention_mask"], batch["chosen_labels"]
        )
        rejected_logps = compute_logps(
            model, batch["rejected_input_ids"],
            batch["rejected_attention_mask"], batch["rejected_labels"]
        )
        return chosen_logps, rejected_logps

    def train_step(self, batch):
        # 1. 策略模型前向
        policy_chosen_logps, policy_rejected_logps = self.compute_batch_logps(
            self.policy, batch
        )
        # 2. 参考模型前向 (无梯度)
        with torch.no_grad():
            ref_chosen_logps, ref_rejected_logps = self.compute_batch_logps(
                self.ref, batch
            )
        # 3. 计算损失
        loss, metrics = self.loss_fn(
            policy_chosen_logps, policy_rejected_logps,
            ref_chosen_logps, ref_rejected_logps
        )
        # 4. 反向传播
        self.optimizer.zero_grad()
        loss.backward()
        torch.nn.utils.clip_grad_norm_(self.policy.parameters(), 1.0)
        self.optimizer.step()
        return loss.item(), metrics
```

### 10.8 数值稳定技巧

实际实现中常见的**坑**：

1. **prompt 部分的 log-prob 必须 mask 掉**：只对 response 部分求和；
2. **过长序列截断**：超长 chosen/rejected 会让 log-prob 偏小，DPO 倾向于偏好短答案（length bias），需要长度归一或加 $\gamma$ 长度惩罚；
3. **数值下溢**：当 $\log p$ 极小时 $\exp(\cdot)$ 会下溢，用 `log_sigmoid` 而非 `sigmoid + log`；
4. **reference 模型用同一 batch 前向**：ref 占用显存 ≈ policy 的 100%，生产中常用 LoRA + 共享 base 来省显存；
5. **chosen/rejected 不平衡**：某些 prompt 多个 rejected，DPO 支持 N 对 1 的扩展（IPO 一致性更好）。

### 10.9 DPO 与 RLHF 的等价性

**定理**（Rafailov et al., 2023）：在配分函数 $Z(x)$ 一致的前提下，DPO 损失 $\mathcal{L}_{\text{DPO}}$ 与 RLHF 的 KL 约束奖励最大化**梯度等价**。

**证明思路**：

1. RLHF 优化 $\max_\pi \mathbb{E}[r] - \beta \text{KL}(\pi \| \pi_{\text{ref}})$；
2. 闭式最优解 $\pi^* \propto \pi_{\text{ref}} \exp(r/\beta)$；
3. 在偏好数据上对 $\pi^*$ 做最大似然，等价于 $\min_\theta -\mathbb{E}[\log P_\theta(y_w \succ y_l)]$；
4. 展开概率即得 $\mathcal{L}_{\text{DPO}}$。

**意义**：DPO 不是"近似"或"简化版"，而是在**偏好数据 + KL 约束**这一设定下的**精确解**。RM + PPO 的多阶段优化之所以有效，本质上也是在逼近这个解。

### 10.10 局限与缓解

| 局限 | 原因 | 缓解 |
|---|---|---|
| **模式坍缩** | chosen 总以相同前缀开头，模型学到"幻觉的捷径" | 加熵正则、增大 reference 更新频率 |
| **长度偏置** | 短 rejected → log-prob 差异被放大 | SimPO 的长度归一 |
| **参考模型依赖** | ref 占用大量显存 | ORPO / SimPO 去掉 ref |
| **成对数据** | 需要 (x, y_w, y_l) | KTO / DPO 扩展到 unpaired |
| **过拟合偏好** | DPO 倾向于把 chosen 概率推到 1 | IPO（用 1/(2β) 损失）|

### 10.11 数学练习

**习题 1**：证明 DPO 损失对 $\theta$ 的梯度可以写成

$$
\nabla_\theta \mathcal{L}_{\text{DPO}} = -\beta \, \mathbb{E} \left[ \sigma\big( -(\hat{r}_\theta(x, y_w) - \hat{r}_\theta(x, y_l)) \big) \cdot \nabla_\theta \log \frac{\pi_\theta(y_w|x)}{\pi_\theta(y_l|x)} \right]
$$

其中 $\hat{r}_\theta = \beta \log(\pi_\theta / \pi_{\text{ref}})$。

**提示**：对 $\log \sigma(z) = -\log(1 + e^{-z})$ 求导，再用链式法则。注意 $d\sigma/dz = \sigma(1-\sigma) = \sigma(z)\sigma(-z)$。

**习题 2**：如果把 BT 模型换成 Thurstonian 模型（$P = \Phi(\cdot)$，高斯 CDF），DPO 损失会变成什么形式？

**答**：
$$
\mathcal{L}_{\text{Thurstone-DPO}} = -\mathbb{E}\left[ \log \Phi\!\left( \frac{r_\theta(y_w) - r_\theta(y_l)}{\sqrt{2}\sigma} \right) \right]
$$
其中 $\Phi$ 是标准正态 CDF，$\sigma$ 是感知噪声的标准差。当 $\sigma \to 0$，$\Phi$ 退化为阶跃函数，损失退化为 hinge loss。

**习题 3**：证明当 $\beta \to \infty$ 时，DPO 训练等价于普通 SFT（即只模仿 chosen，忽略 rejected）。

**提示**：当 $\beta \to \infty$，$Z(x)$ 必须同步放大以保持 $\pi^*$ 有限，BT 概率近似为 $y_w$ 优势程度。实际上 $\beta$ 极大时 $r_\theta$ 的差几乎被 1/$\beta$ 抹平，$\sigma$ 输入趋近 0，梯度消失。

## 11. IPO / KTO / SimPO 对比：DPO 家族的三个分支

### 11.1 为什么 DPO 不够？

DPO 虽然简洁，但有三个**固有问题**：

1. **过拟合偏好**：DPO 优化 $\log \sigma$ 会让 chosen 概率趋于 1，rejected 趋于 0，模型"饱和"，失去多样性；
2. **参考模型依赖**：必须保留 SFT 后的 ref 模型，显存翻倍；
3. **长度偏置**：chosen 通常更长，DPO 会奖励长答案。

后继工作**各解决一个**：

| 方法 | 解决问题 | 关键 trick |
|---|---|---|
| **IPO** (2023) | 偏好过拟合 | 用 L2 损失替代 log-sigmoid |
| **KTO** (2024) | 成对数据需求 | 借鉴 Kahneman-Tversky 前景理论 |
| **SimPO** (2024) | 参考模型 + 长度 | 去掉 ref，用平均 log-prob |

### 11.2 IPO（Identity Preference Optimization）

**核心问题**：DPO 的 $\log \sigma$ 损失是 **deterministic** 的——只要 chosen 概率持续 > rejected 概率，损失会无限趋于 0 但梯度永远不消失，导致模型**持续拟合**直到 chosen 概率 = 1。

**解决方案**（Azar et al., 2023）：把损失从"无限压缩"改成"目标驱动"：

$$
\mathcal{L}_{\text{IPO}}(\theta) = \mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \left( \log \frac{\pi_\theta(y_w|x)}{\pi_{\text{ref}}(y_w|x)} - \log \frac{\pi_\theta(y_l|x)}{\pi_{\text{ref}}(y_l|x)} - \frac{1}{2\beta} \right)^2 \right]
$$

**直觉**：让 chosen 和 rejected 的隐式奖励差**趋近** $1/(2\beta)$，而不是"无限大"。

**优点**：
- 损失下有界（$\geq 0$），避免过拟合；
- 证明在正则化条件下是 BT 模型的最大似然解；
- 对噪声标注更鲁棒。

**缺点**：
- 训练目标"克制"，对齐力度通常比 DPO 弱；
- 仍需 reference 模型。

### 11.3 KTO（Kahneman-Tversky Optimization）

**核心问题**：偏好数据标注昂贵（要标注者两两比较）。能不能只标"好/坏"单点标签？

**灵感**：Kahneman & Tversky (1979) 的**前景理论**：
- 人对"损失"比对"同等大小的收益"更敏感（损失厌恶系数 $\lambda \approx 2.25$）；
- 参考点依赖（不是绝对值，而是相对参考点的偏离）。

**KTO 损失**（Ethayarajh et al., 2024）：

$$
\mathcal{L}_{\text{KTO}}(\theta) = \mathbb{E}_{(x, y) \sim \mathcal{D}} \big[ w(y) \cdot (1 - \sigma(\beta \cdot (r_\theta(x, y) - z_{\text{ref}})) \cdot \text{sign}_{\text{desirable}}(y)) \big]
$$

其中：
- $r_\theta(x, y) = \log(\pi_\theta(y|x) / \pi_{\text{ref}}(y|x))$ 是隐式奖励；
- $z_{\text{ref}} = \mathbb{E}_{(x', y') \sim \mathcal{D}}[\beta \cdot r_\theta(x', y')]$ 是参考点（batch 内隐式奖励的均值）；
- $\text{sign}_{\text{desirable}}(y) = +1$（好）或 $-1$（坏）；
- $w(y) = \lambda_D$（好样本权重）或 $\lambda_U$（坏样本权重，$\lambda_D \neq \lambda_U$ 模拟损失厌恶）。

**代码骨架**：

```python
class KTOLoss(nn.Module):
    def __init__(self, beta=0.1, desirable_weight=1.0, undesirable_weight=1.0):
        super().__init__()
        self.beta = beta
        self.lambda_d = desirable_weight
        self.lambda_u = undesirable_weight

    def forward(self, policy_logps, ref_logps, labels):
        # labels: 1=desirable, 0=undesirable
        logratios = policy_logps - ref_logps
        rewards = self.beta * logratios

        # 参考点 z_ref: 整个 batch 奖励的均值 (detached)
        with torch.no_grad():
            z_ref = rewards.mean()

        # 损失项
        # 对 desirable: -lambda_d * (1 - sigmoid(r - z_ref))
        # 对 undesirable: -lambda_u * (1 - sigmoid(z_ref - r))
        # 注意: 对 undesirable 损失取 max(...,0) 以实现 "asymmetric"
        loss = torch.where(
            labels == 1,
            1 - torch.sigmoid(rewards - z_ref),
            1 - torch.sigmoid(z_ref - rewards),
        )
        weights = torch.where(labels == 1, self.lambda_d, self.lambda_u)
        return (loss * weights).mean()
```

**优点**：
- 不需要成对数据，只需 (x, y, label)；
- 标注成本降低 ~50%；
- 对长尾数据（大量负样本+少量正样本）特别有效。

**缺点**：
- 仍需 ref 模型；
- 调参更多（$\lambda_D, \lambda_U$）；
- 收敛比 DPO 慢。

### 11.4 SimPO（Simple Preference Optimization）

**核心问题**：能不能完全去掉 reference 模型？同时解决长度偏置？

**答案**（Meng et al., 2024）：用**平均对数概率**代替总对数概率 + 引入**目标 margin** $\gamma$：

$$
\mathcal{L}_{\text{SimPO}}(\theta) = -\mathbb{E}_{(x, y_w, y_l) \sim \mathcal{D}} \left[ \log \sigma\!\left( \frac{\beta}{|y_w|} \log \pi_\theta(y_w|x) - \frac{\beta}{|y_l|} \log \pi_\theta(y_l|x) - \gamma \right) \right]
$$

其中：
- $|y|$ 是 response 的 token 数；
- $\gamma > 0$ 是目标 margin，强制 chosen 比 rejected 好"足够多"；
- **没有 ref 模型**（$\pi_{\text{ref}}$ 隐式为 1）。

**直觉**：
- 除以 $|y|$ 等价于**每 token 的平均对数概率**，消除了"长答案自然概率低"的长度偏置；
- $\gamma$ margin 防止 chosen 概率被无限推高。

**PyTorch 实现**：

```python
class SimPOLoss(nn.Module):
    def __init__(self, beta=2.0, gamma=1.0):
        super().__init__()
        self.beta = beta
        self.gamma = gamma

    def forward(self, policy_chosen_logps, policy_rejected_logps,
                chosen_lengths, rejected_lengths):
        # 长度归一: 平均对数概率
        policy_chosen_logps_avg = policy_chosen_logps / chosen_lengths
        policy_rejected_logps_avg = policy_rejected_logps / rejected_lengths

        # SimPO logits
        logits = self.beta * (policy_chosen_logps_avg - policy_rejected_logps_avg) - self.gamma

        loss = -F.logsigmoid(logits)
        return loss.mean()
```

**优点**：
- **1 个模型**（无需 ref），显存节省 50%；
- 长度归一有效，长答案不会"被偏爱"；
- 实践中在 AlpacaEval 2 / Arena-Hard 上**经常超过 DPO**。

**缺点**：
- 失去 ref 锚定，模型可能偏离 SFT 太远（KL 约束消失）；
- 需要调 $\gamma$。

### 11.8 关键 trick：N 选 1 推广

DPO 家族都可以从"1 对 1"推广到"1 对 N"——一个 chosen 对 N 个 rejected：

$$
\mathcal{L}_{\text{DPO-N}} = -\log \frac{\exp(r_\theta(y_w|x))}{\exp(r_\theta(y_w|x)) + \sum_{i=1}^N \exp(r_\theta(y_{l,i}|x))}
$$

这种推广在 rejection sampling 场景中很有用：从同一 prompt 用 SFT 模型采样 N 个回答，标 1 个 chosen + N-1 个 rejected，训练后**比 DPO 更鲁棒**。

### 11.9 习题

**习题 1**：为什么 IPO 的损失函数下有界（$\geq 0$），而 DPO 没有？

**提示**：DPO 损失是 $-\log \sigma(z)$，当 $z \to \infty$ 时 $\log \sigma(z) \to 0$ 但**梯度不消失**（梯度 $\propto \sigma(-z)$ 永远 > 0）。IPO 是 $(z - 1/(2\beta))^2$，当 $z$ 达到目标值时梯度为 0。

**习题 2**：SimPO 去掉 ref 模型后，为什么仍能保持对齐质量？

**答**：SimPO 用**平均对数概率**和 $\gamma$ margin 隐式地起到了 KL 约束的作用。
- 平均化：等价于"每个 token 的概率要被拉到 1"，但因有 $\gamma$ 不会完全过拟合；
- margin $\gamma$：阻止 chosen 概率推太高，相当于把 KL 距离限制在 $O(1/\gamma)$ 量级。
- 实践中 SimPO 在长度归一后偏置更小，所以"省 ref"在数据质量好的情况下不损失质量。

**习题 3**：KTO 在数据集中正负样本极不平衡（如 1:100）时如何调参？

**答**：
- 设置 $\lambda_U \gg \lambda_D$（如 5:1）以平衡梯度量级；
- 用 class-weighted sampling 让每个 batch 内正负比例接近 1:1；
- 增大 $\beta$（如 0.3）以放大奖励差异；
- 监控 undesirable 样本的**绝对奖励**是否持续下降。

## 12. ORPO 与 RLOO：去掉 SFT 的极简对齐

### 12.1 ORPO（Odds Ratio Preference Optimization）

**核心洞察**（Hong et al., 2024）：能不能把 SFT 和偏好对齐**合并成一个阶段**？

- 传统 pipeline：SFT → DPO（两阶段）；
- ORPO：单阶段联合训练，同时学"模仿"和"偏好"。

### 12.2 Odds Ratio 的定义

对给定 prompt $x$ 和 response $y$（token 序列 $y_1, ..., y_T$），ORPO 定义：

$$
\text{odds}_\theta(y|x) = \frac{P_\theta(y|x)}{1 - P_\theta(y|x)}
$$

其中 $P_\theta(y|x) = \prod_{t=1}^T \pi_\theta(y_t|x, y_{<t})$ 是整条 response 的联合概率。

**优势**：
- $P_\theta \in (0, 1)$，所以 $\text{odds} \in (0, +\infty)$；
- $\log \text{odds} \in (-\infty, +\infty)$，范围更广，比单纯 $\log P$ 表达力强；
- 当 $P$ 接近 1，odds 接近 $\infty$，信号"放大"。

### 12.3 ORPO 损失

$$
\mathcal{L}_{\text{ORPO}}(\theta) = \mathcal{L}_{\text{SFT}}(\theta) + \lambda \cdot \mathcal{L}_{\text{OR}}(\theta)
$$

其中：

**SFT 损失**（负对数似然）：
$$
\mathcal{L}_{\text{SFT}}(\theta) = -\frac{1}{|y_w|} \sum_{t=1}^{|y_w|} \log \pi_\theta(y_{w,t}|x, y_{w,<t})
$$

**Odds Ratio 损失**：
$$
\mathcal{L}_{\text{OR}}(\theta) = -\log \sigma\!\left( \log \frac{\text{odds}_\theta(y_w|x)}{1 - \text{odds}_\theta(y_w|x)} - \log \frac{\text{odds}_\theta(y_l|x)}{1 - \text{odds}_\theta(y_l|x)} \right)
$$

注意 odds ratio loss 用的是 $\log(\text{odds}) = \log P - \log(1-P)$，而 DPO 用 $\log P$（与 ref 的差）。

**关键差别**：
- **不用 reference 模型**（ref 隐式为均匀分布）；
- **不用单独 SFT 阶段**（SFT 损失作为正则项同时优化）；
- $\lambda$ 控制偏好对齐的强度（典型值 0.1~1.0）。

### 12.4 PyTorch 实现

```python
class ORPOLoss(nn.Module):
    def __init__(self, beta=0.1, lambda_or=0.1):
        super().__init__()
        self.beta = beta
        self.lambda_or = lambda_or

    def forward(self, policy_chosen_logps, policy_rejected_logps,
                chosen_token_mask, rejected_token_mask):
        # 1. SFT 损失 (per-token 平均)
        sft_loss = -(policy_chosen_logps * chosen_token_mask).sum() / chosen_token_mask.sum()

        # 2. Odds Ratio
        # odds = p / (1 - p), log_odds = logp - log(1-p)
        # 但我们只有 logp, 没有 log(1-p), 用 log(p) = logps
        # log(1 - p) ≈ -p 在 p 小时, 但这里需要数值稳定做法:
        # log_odds = logp - log(1 - exp(logp))  (仅当 logp < 0)
        # 稳定做法:  log_odds = logp - log1p(-exp(logp))  when logp <= 0
        # 当 logp > 0 (罕见), 用 log(exp(logp) - 1) - logp
        def log_odds(logp_seq, mask):
            # logp_seq: [B, T], mask: [B, T]
            # 总对数概率
            logp = (logp_seq * mask).sum(dim=-1)  # [B]
            # log(1 - p) = log1p(-p)
            # 数值稳定: p = exp(logp) 可能下溢
            # 用 log1p(-exp(logp)) 但要小心 logp > 0
            p = torch.exp(logp).clamp(max=1 - 1e-7)
            log_one_minus_p = torch.log(1 - p)
            return logp - log_one_minus_p

        chosen_logodds = log_odds(policy_chosen_logps_seq, chosen_token_mask)
        rejected_logodds = log_odds(policy_rejected_logps_seq, rejected_token_mask)

        # 3. OR 损失
        odds_diff = chosen_logodds - rejected_logodds
        or_loss = -F.logsigmoid(odds_diff)

        # 4. 总损失
        total_loss = sft_loss + self.lambda_or * or_loss
        return total_loss, {"sft_loss": sft_loss.item(),
                            "or_loss": or_loss.item()}
```

### 12.5 ORPO vs DPO

| 维度 | DPO | ORPO |
|---|---|---|
| **训练阶段** | SFT → DPO（2 阶段） | 单阶段 |
| **模型数** | 2（policy + ref） | **1（policy）** |
| **显存** | 2x | **1x** |
| **数据** | (x, y_w, y_l) | (x, y_w, y_l) |
| **对齐力度** | 强 | 中（弱于 DPO） |
| **训练时间** | 长 | **短 ~30%** |
| **AlpacaEval 2** | 50%+ | 50%+（持平） |
| **代码复杂度** | ★★ | ★ |

**ORPO 的优势**：
1. 流程极简，省去 SFT 步骤；
2. 显存省一半；
3. 训练时间缩短（少了一个阶段）。

**ORPO 的劣势**：
1. 单一阶段意味着无法复用 SFT 后的模型（要重新训）；
2. 对齐力度有时弱于 DPO（因为 SFT 损失 + OR 损失互相影响）；
3. 实际中常需要先 SFT 一段时间再切到 ORPO。

### 12.6 RLOO（REINFORCE Leave-One-Out）

**动机**：回到 RL 路线，能不能用最简单的 REINFORCE 做到 PPO 的效果？

RLOO（Kool et al., 2019，应用于 LLM by Ahmadian et al., 2024）：

- **去掉 critic**（值函数模型）；
- **用 leave-one-out baseline** 替代 GAE。

### 12.7 RLOO 算法

对每个 prompt $x$：
1. 用当前策略采样 $K$ 个回答 $y_1, ..., y_K$；
2. 用 reward model 给每个 $y_i$ 打分 $r_i$；
3. **留一法 baseline**：$\text{baseline}_i = \frac{1}{K-1} \sum_{j \neq i} r_j$；
4. 优势估计：$A_i = r_i - \text{baseline}_i$；
5. **REINFORCE 更新**：

$$
\nabla_\theta J(\theta) \approx \frac{1}{K} \sum_{i=1}^K A_i \cdot \nabla_\theta \log \pi_\theta(y_i|x)
$$

### 12.8 为什么 Leave-One-Out？

**问题**：单条样本没有 baseline。如果用全 batch 平均做 baseline，方差高、收敛慢。

**直觉**：$K$ 条样本中，其余 $K-1$ 条的奖励均值是当前样本的"自然 baseline"——如果当前样本奖励 > 其他样本均值，说明它"好"，应该增大概率。

**数学**：在 $K \to \infty$ 时，LOO baseline 是无偏的，方差 $O(1/K)$。

### 12.9 PyTorch 实现

```python
def rloo_loss(policy_model, ref_model, prompts, K=4, kl_coef=0.05):
    """
    prompts: list of str, 每个 prompt 采样 K 个回答
    """
    total_loss = 0.0
    for prompt in prompts:
        # 1. 采样 K 个回答
        with torch.no_grad():
            responses = policy_model.generate(
                prompt, num_return_sequences=K,
                do_sample=True, temperature=1.0
            )

        # 2. 计算 reward (用 reward model)
        rewards = reward_model(prompt, responses)  # [K]

        # 3. Leave-one-out baseline
        rewards_sum = rewards.sum()
        baselines = (rewards_sum - rewards) / (K - 1)  # [K]
        advantages = rewards - baselines  # [K]

        # 4. 标准化 advantages (稳定训练)
        advantages = (advantages - advantages.mean()) / (advantages.std() + 1e-8)

        # 5. 计算 log-prob (对每个 response)
        log_probs = []
        for response in responses:
            tokens = tokenize(prompt + response)
            logp = compute_logp(policy_model, tokens)
            log_probs.append(logp)
        log_probs = torch.stack(log_probs)  # [K]

        # 6. Ref policy log-prob (用于 KL 惩罚)
        with torch.no_grad():
            ref_log_probs = []
            for response in responses:
                tokens = tokenize(prompt + response)
                ref_logp = compute_logp(ref_model, tokens)
                ref_log_probs.append(ref_logp)
            ref_log_probs = torch.stack(ref_log_probs)  # [K]

        # 7. KL 惩罚
        kl = log_probs - ref_log_probs  # [K]

        # 8. RLOO 损失
        # -advantages * log_probs + kl_coef * kl^2
        loss = (-advantages * log_probs + kl_coef * (kl ** 2)).mean()
        total_loss = total_loss + loss

    return total_loss / len(prompts)
```

### 12.10 RLOO vs PPO

| 维度 | PPO | RLOO |
|---|---|---|
| **Critic 模型** | ✅（值函数网络） | ❌（用 LOO baseline） |
| **GAE** | ✅（λ-return） | ❌（单步 REINFORCE） |
| **Clip ratio** | ✅（0.1~0.3） | ❌ |
| **显存** | 高（4 模型） | **中**（2 模型） |
| **稳定性** | 高（clip 保护） | 中（方差大） |
| **采样数 K** | 1（per roll-out） | 4~8 |
| **实现复杂度** | ★★★★ | ★★ |
| **AlpacaEval 2** | 60%+ | 55%+（弱于 PPO） |
| **适合** | 长任务 / 复杂 RL | 短任务 / 快速实验 |

### 12.11 何时用 RLOO 而非 DPO？

**用 RLOO 的场景**：
1. 任务有**可验证奖励**（数学、代码、指令遵循），RM 可以是 deterministic 规则；
2. 想要在线探索（DPO 只能利用已有偏好对）；
3. 计算资源允许 K 次采样。

**用 DPO 的场景**：
1. 已有高质量偏好数据集；
2. 对齐任务以"风格/安全"为主（无明确 reward）；
3. 训练成本敏感。

### 12.12 工业实践：Tulu 3 的混合策略

**Tulu 3**（Allen AI, 2024）的对齐 pipeline：

```text
阶段 1: SFT (高质量指令数据)
阶段 2: Online DPO (用 SFT 模型采样, RM 标注)
阶段 3: RLOO 精调 (在 DPO 基础上, 用可验证奖励 RL)
阶段 4: 合并 + DPO 再训
```

**关键观察**：单一方法都不够，**组合拳**最强。
- DPO 给"风格偏好"；
- RLOO 给"任务能力"；
- 两者结合在多个 benchmark 上超过任一单方法。

### 12.13 习题

**习题 1**：ORPO 的 $\lambda$ 太小或太大分别会怎样？

**答**：
- $\lambda \to 0$：ORPO 退化为纯 SFT，无对齐；
- $\lambda \to \infty$：SFT 损失被忽略，模型崩溃到"高 odds 概率的极端分布"（模式坍缩）；
- 经验值：$\lambda \in [0.1, 1.0]$，通常 0.1 起步 grid search。

**习题 2**：RLOO 的 K=4 比 K=8 总是差吗？为什么？

**答**：
- K 越大，baseline 越准、方差越小 → 训练越稳定；
- 但 K 越大，每步计算量 K 倍增长；
- 实际中 K=4 是性价比甜点，K=16+ 边际收益递减。
- 改进：可对 K=4 的 LOO baseline 加 EMA 平滑。

**习题 3**：ORPO 训练中如果 chosen 序列比 rejected 短很多，会出现什么现象？如何修正？

**答**：
- SFT 损失中 chosen 平均 log-prob 可能比 rejected 高（短序列每个 token 学得更精）；
- 但 OR 损失**仍然正确**——OR 用的是整条序列的 odds，不直接受长度影响；
- 然而如果 chosen 太短，模型会学到"答短 = 高 OR 偏好"；
- 修正：在 SFT 损失中也用 per-token 平均（已经是），加 length penalty，或在数据预处理时**长度对齐** chosen/rejected。

## 13. 工业实践：LLaMA-3 / Zephyr / Mistral 的对齐配方

### 13.1 LLaMA-3 的 RLHF 流程

LLaMA-3（Meta, 2024）采用经典 RLHF，但做了几处工程优化：

```text
阶段 1: SFT (instruction tuning)
  - 数据: ~180K 高质量 SFT 数据
  - 模型: LLaMA-3-70B
  - 训练: 6 epochs, lr=2e-5, cosine schedule

阶段 2: Preference Data Collection
  - 标注: chosen/rejected 由人类标注 4 次
  - 规模: ~1M 偏好对

阶段 3: Reward Model
  - 模型: LLaMA-3-70B 加 regression head
  - 训练: 2 epochs, pairwise loss
  - 数据: 1M 偏好对

阶段 4: PPO
  - 4 模型: actor, ref, critic, reward
  - 训练: 1 epoch
  - KL coef: 0.01
  - 关键 trick: rejection sampling 微调
```

**关键创新**：LLaMA-3 在 PPO 之前先做**拒绝采样微调**（Rejection Sampling Fine-Tuning, RFT）：

1. 用 SFT 模型对每个 prompt 采样 K=10 个回答；
2. 用 RM 选最优的 1~2 个；
3. 把这些"高质量回答"加入 SFT 数据，重新 SFT；
4. 再做 PPO。

**效果**：RFT 后的 PPO 比直接 PPO 强 5+ points on MT-Bench。

### 13.3 Mistral-7B-Instruct：DPO + 反向 KL

Mistral AI 的 DPO 配方（v0.2）：

- **forward KL**（DPO 默认）vs **reverse KL**：
  - Forward KL: $KL(\pi_\theta \| \pi_{\text{ref}})$，**mode-covering**（避免单点偏离）；
  - Reverse KL: $KL(\pi_{\text{ref}} \| \pi_\theta)$，**mode-seeking**（可能 mode collapse）；
- Mistral 用 forward KL + 较低的 $\beta$（0.05）以避免 overfitting；
- 数据：~50K 偏好对（自标 + HuggingFace 公开数据合并）。

# 3. 配置

### 13.11 常见失败模式

| 失败模式 | 症状 | 原因 | 修复 |
|---|---|---|---|
| **NLL 飙升** | 训到一半 loss NaN | SFT 能力被破坏 | 降 lr 至 1e-7，缩短 max_length |
| **chosen 概率饱和** | chosen logp → 0 | beta 太大 | 降 beta 至 0.05 |
| **rejected 概率不变** | reward margin = 0 | lr 太小或数据太相似 | 增 lr，或用 SimPO |
| **模式坍缩** | 总是同一句开头 | DPO 过拟合 | 换 IPO 或 KTO |
| **长度偏置** | 模型爱答长答案 | DPO 没长度归一 | 换 SimPO |
| **风格漂移** | 中文模型变英文 | 训练数据混杂 | 数据过滤，监控语言比例 |

### 13.12 习题

**习题 1**：为什么 LLaMA-3 在 PPO 之前先做 RFT（Rejection Sampling Fine-Tuning）？

**答**：
- PPO 起始点如果是"差的 SFT 模型"，早期探索会浪费在低质量回答上；
- RFT 用 SFT 模型 + RM 把"高质量回答"选出来再训，相当于"提纯 SFT 数据"；
- RFT 后的 PPO 起点更高，**收敛更快、最终更强**。
- 类比：RFT = 预习；PPO = 正式考试。

**习题 2**：Zephyr 训练中 $\beta$ 从 0.1 升到 0.5 有什么效果？

**答**：
- 前期 $\beta$ 小：模型自由偏离 SFT（探索），快速学到偏好模式；
- 后期 $\beta$ 大：模型被 ref 拉回（保守），避免 mode collapse；
- 模拟 PPO 的 clip：从激进到保守的训练过程。

**习题 3**：Tulu 3 为什么在 DPO 后还要做 RLVR？

**答**：
- DPO 只能利用**已有偏好对**（offline），学的是"风格"；
- RLVR 用**可验证奖励**（数学对错、代码通过）做 online RL，学的是"能力"；
- 两者正交：DPO 处理"做什么"，RLVR 处理"做得多好"；
- 实测 RLVR 后 GSM8K 从 65 → 78，HumanEval 从 50 → 65。

## 14. DPO 严格假设、稳健实现与工业专题

> 本专题补齐 DPO 的适用假设、梯度、稳健 PyTorch、论文边界与上线决策。

### 14.1 DPO 不是无条件等价

DPO 的推导依赖一组明确假设：

1. 偏好可由标量奖励差经 Bradley-Terry link 表达；
2. 目标策略围绕固定 reference 做 KL 正则；
3. 偏好数据能代表目标部署分布；
4. chosen/rejected 的差异主要来自质量，而不是长度、模板或语言泄漏；
5. 优化器能在参数化策略族中接近理论最优解。

因此更严谨的表述是：DPO 把 KL 正则奖励最大化问题重参数化为偏好分类目标；它避免显式 RM 和在线 RL，但不会自动消除数据偏差、模型错设和分布外失败。

### 14.2 从变分问题到最优策略

对固定 $x$：

$$
\max_\pi
\sum_y\pi(y|x)r(x,y)
-\beta\sum_y\pi(y|x)\log\frac{\pi(y|x)}{\pi_{ref}(y|x)}
$$

满足 $\sum_y\pi(y|x)=1$。加入乘子 $\eta$ 后，对 $\pi(y|x)$ 求偏导：

$$
r(x,y)-\beta\left(\log\frac{\pi(y|x)}{\pi_{ref}(y|x)}+1\right)+\eta=0.
$$

于是：

$$
\pi^*(y|x)=\frac{\pi_{ref}(y|x)\exp(r(x,y)/\beta)}{Z(x)}.
$$

反解：

$$
r(x,y)=\beta\log\frac{\pi^*(y|x)}{\pi_{ref}(y|x)}+\beta\log Z(x).
$$

同一个 prompt 的两个回答相减时，$\log Z(x)$ 抵消。

### 14.3 从奖励差到 DPO logit

定义：

$$
h_\theta(x,y)=\log\pi_\theta(y|x)-\log\pi_{ref}(y|x).
$$

DPO logit 为：

$$
z_\theta=\beta[h_\theta(x,y_w)-h_\theta(x,y_l)].
$$

损失：

$$
\ell_{DPO}(z)=-\log\sigma(z)=\operatorname{softplus}(-z).
$$

这是一个二分类 logistic loss；输入不是普通分类器分数，而是 policy 相对 reference 的 chosen/rejected 对数概率比差。

### 14.4 梯度方向

因为：

$$
\frac{d}{dz}[-\log\sigma(z)]=-\sigma(-z),
$$

所以：

$$
\nabla_\theta\ell=
-\beta\sigma(-z)
\left[
\nabla_\theta\log\pi_\theta(y_w|x)-
\nabla_\theta\log\pi_\theta(y_l|x)
\right].
$$

含义：

- 当前排序错误或 margin 小时，$\sigma(-z)$ 大，更新强；
- 当前排序已明显正确时，权重变小；
- 更新同时提升 chosen、压低 rejected；
- reference 不参与梯度，只改变样本的相对难度与锚点。

### 14.5 $\beta$ 的两种观察方式

理论目标中，$\beta$ 是 KL 正则权重；越大表示最优策略越靠近 reference。

训练损失中，$\beta$ 又直接缩放 logit 和梯度。固定数据、学习率和训练步数时，改变 $\beta$ 会同时改变：

1. 理论上的隐式奖励尺度；
2. logistic loss 的饱和速度；
3. 实际梯度量级；
4. 最终 KL 与 chosen/rejected margin。

因此不能只凭“$eta$ 大更保守”机械调参；必须联看 KL、chosen NLL、reward margin 与独立胜率。

### 14.6 标签噪声与 label smoothing

若偏好标签有概率 $\epsilon$ 被翻转，可用：

$$
\ell=(1-\epsilon)[-\log\sigma(z)]
+\epsilon[-\log\sigma(-z)].
$$

它不假设每个 chosen 都绝对正确，能减轻错误 pair 对模型的极端推动。

### 14.7 长度偏差从哪里来

序列 log-prob 是 token log-prob 之和：

$$
\log\pi(y|x)=\sum_{t=1}^{|y|}\log\pi(y_t|x,y_{<t}).
$$

每项通常为负，所以绝对值会随长度增加。若 chosen/rejected 长度分布不同，模型可能把长度当偏好捷径。

常见处理：

- 数据侧长度匹配或分桶；
- 报告长度条件下的 pair accuracy；
- 使用平均 log-prob；
- 在目标中加入显式长度 margin；
- 用长度平衡评测集做独立门禁。

### 14.8 Reference 的作用

reference 不是“多余副本”，它定义了隐式奖励的零点：

$$
r_\theta(x,y)=\beta\log\frac{\pi_\theta(y|x)}{\pi_{ref}(y|x)}.
$$

换 reference 会改变每个样本的隐式奖励与优化难度。使用不同 tokenizer、chat template 或 checkpoint 作为 reference，会让 log-ratio 失去可比性。

### 14.9 PyTorch：安全收集 token log-prob

```python
import torch
import torch.nn.functional as F


def sequence_logps(logits, labels, response_mask, average=False):
    """labels 可在非 response 位置为 -100；gather 前必须替换安全索引。"""
    shift_logits = logits[:, :-1].float()
    shift_labels = labels[:, 1:]
    shift_mask = response_mask[:, 1:].to(shift_logits.dtype)

    safe_labels = shift_labels.masked_fill(shift_mask == 0, 0)
    token_logps = F.log_softmax(shift_logits, dim=-1)
    token_logps = token_logps.gather(-1, safe_labels.unsqueeze(-1)).squeeze(-1)
    totals = (token_logps * shift_mask).sum(-1)

    if average:
        totals = totals / shift_mask.sum(-1).clamp_min(1)
    return totals
```

**关键勘误**：若 `labels` 中存在 `-100`，不能直接拿它做 `gather` 索引；应先替换为安全 token id，再用 mask 清零。

### 14.10 PyTorch：稳健 DPO loss

```python
def robust_dpo_loss(
    policy_chosen_logps,
    policy_rejected_logps,
    ref_chosen_logps,
    ref_rejected_logps,
    beta=0.1,
    label_smoothing=0.0,
):
    policy_ratio = policy_chosen_logps - policy_rejected_logps
    ref_ratio = ref_chosen_logps - ref_rejected_logps
    logits = beta * (policy_ratio - ref_ratio)

    positive = -F.logsigmoid(logits)
    negative = -F.logsigmoid(-logits)
    losses = (1 - label_smoothing) * positive + label_smoothing * negative

    chosen_rewards = beta * (policy_chosen_logps - ref_chosen_logps).detach()
    rejected_rewards = beta * (policy_rejected_logps - ref_rejected_logps).detach()
    return losses.mean(), {
        "reward_margin": (chosen_rewards - rejected_rewards).mean(),
        "pair_accuracy": (chosen_rewards > rejected_rewards).float().mean(),
        "chosen_reward": chosen_rewards.mean(),
        "rejected_reward": rejected_rewards.mean(),
        "logit_mean": logits.mean().detach(),
    }
```

### 14.11 PyTorch：concatenated forward

policy 对 chosen 和 rejected 分别前向会浪费 kernel launch，也可能在 dropout 下引入额外差异。可沿 batch 维拼接：

```python
def concatenated_forward(model, chosen_batch, rejected_batch):
    input_ids = torch.cat([chosen_batch["input_ids"], rejected_batch["input_ids"]])
    attention_mask = torch.cat([
        chosen_batch["attention_mask"],
        rejected_batch["attention_mask"],
    ])
    labels = torch.cat([chosen_batch["labels"], rejected_batch["labels"]])
    response_mask = torch.cat([
        chosen_batch["response_mask"],
        rejected_batch["response_mask"],
    ])

    logits = model(input_ids=input_ids, attention_mask=attention_mask).logits
    logps = sequence_logps(logits, labels, response_mask)
    batch_size = chosen_batch["input_ids"].size(0)
    return logps[:batch_size], logps[batch_size:]
```

### 14.12 PyTorch：缓存 reference log-prob

reference 固定时，可离线缓存 `ref_chosen_logps` 与 `ref_rejected_logps`：

```python
@torch.no_grad()
def cache_reference_logps(ref_model, dataloader):
    ref_model.eval()
    cached = []
    for chosen_batch, rejected_batch in dataloader:
        chosen, rejected = concatenated_forward(ref_model, chosen_batch, rejected_batch)
        cached.append({
            "ref_chosen_logps": chosen.cpu(),
            "ref_rejected_logps": rejected.cpu(),
        })
    return cached
```

缓存前必须冻结 tokenizer、模板、截断长度和数据顺序；任一项变化都需要重算。

### 14.13 PyTorch：梯度方向自检

```python
def _dpo_gradient_check():
    pi_w = torch.tensor([-3.0], requires_grad=True)
    pi_l = torch.tensor([-2.0], requires_grad=True)
    ref_w = torch.tensor([-2.5])
    ref_l = torch.tensor([-2.5])
    loss, _ = robust_dpo_loss(pi_w, pi_l, ref_w, ref_l, beta=0.1)
    loss.backward()
    assert pi_w.grad.item() < 0  # 梯度下降会增大 chosen logp
    assert pi_l.grad.item() > 0  # 梯度下降会减小 rejected logp
```

| reward margin | chosen NLL | 可能状态 | 动作 |
|---|---|---|---|
| 上升 | 稳定或下降 | 偏好与生成能力共同改善 | 继续并做独立评测 |
| 上升 | 明显上升 | 靠压低 rejected 或整体概率退化 | 降学习率，加入 chosen NLL 约束 |
| 不变 | 稳定 | 梯度太小、pair 太容易或实现有误 | 查 beta、mask、数据难度 |
| 剧烈上升 | 震荡 | 过拟合、长度捷径或数值不稳 | 早停、平滑标签、清洗数据 |

## 16. 综合练习与答案要点

### 16.1 推导题：配分函数为何抵消

因为同一 prompt $x$ 下 $Z(x)$ 不依赖回答 $y$。计算 $r(x,y_w)-r(x,y_l)$ 时，两个 $\beta\log Z(x)$ 符号相反，恰好抵消。若比较来自不同 prompt，则不能这样抵消。

### 16.2 梯度题：为什么难样本权重大

DPO 梯度前的标量权重是 $\sigma(-z)$。当 $z$ 小或为负，模型尚未正确拉开偏好，权重接近 1；当 $z$ 很大，权重接近 0。

### 16.3 代码题：为什么 prompt 必须 mask

DPO 比较的是“给定同一 prompt 后两个 response 的条件概率”。若把 prompt token 计入，两边虽然理论上相同，但截断、padding、模板差异会造成非预期信号，并浪费梯度。

### 16.4 数据题：如何处理 both-bad

可把两者都丢弃、补采更好回答，或在支持单点标签的目标中都标 undesirable。强行指定 chosen 会把低质量回答推高。

### 16.5 选型题

- 有高质量 pair 且显存够：DPO；
- 标签噪声高：cDPO/IPO；
- 只有单点好坏：KTO；
- 无 ref 显存且长度偏差明显：SimPO；
- 想单阶段联合 SFT：ORPO；
- 需要探索并有可验证奖励：RLOO/GRPO/PPO 路线。

### 16.6 故障题

若 reward margin 上升、chosen NLL 上升、人工胜率下降：

1. 检查模型是否只在压低 rejected；
2. 检查长度与模板泄漏；
3. 检查学习率、epoch 和 beta；
4. 加 chosen NLL 或 SFT replay；
5. 使用独立 judge 与人工盲测；
6. 早停并回滚到胜率最佳 checkpoint。

> DPO 的工程本质：用正确的条件 log-prob、可靠的偏好数据和独立评测，约束一次看似简单的二分类优化。
