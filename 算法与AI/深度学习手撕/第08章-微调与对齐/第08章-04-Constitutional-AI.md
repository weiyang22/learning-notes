## 8.4 Constitutional AI (Anthropic)

---

## 1. 内容介绍

**Constitutional AI (CAI)** 是 Anthropic 2022 年提出的对齐方法, 用**AI 反馈** (RLAIF) 替代人类反馈 (RLHF), 训练 Claude.

**核心思想**: LLM 遵守一组"原则" (Constitution), 违反原则时自我批评 + 修正.

---

## 2. 为什么这么做

**RLHF 的痛点**:
- 需要大量人类标注的偏好对比 (成本高)
- 人类标注有偏见 / 不一致
- 难以覆盖所有"有害"场景

**CAI 的洞察**:
- 可以用 LLM 替代人类评估 (RLAIF)
- 评估标准可以写成"原则" (宪法)
- LLM 自我批评 + 修正, 不需要人介入

---

## 3. 这么做的原因 (CAI vs RLHF)

| 维度 | RLHF | CAI (RLAIF) |
|---|---|---|
| 反馈来源 | 人类 | AI (LLM 自我评估) |
| 成本 | 高 (人标) | 低 (自动) |
| 一致性 | 有偏 | 严格按原则 |
| 扩展性 | 受人类限制 | 容易 |
| 质量 | 高 | 接近 RLHF |

**Anthropic 论文 (2022)**:
- "Constitutional AI: Harmlessness from AI Feedback"
- 2 阶段: SL (Supervised Learning) + RL (Reinforcement Learning)
- 都被 AI 反馈替代人类

---

## 4. 解决了什么问题

- **人类标注成本高**: 用 LLM 评估
- **人类不一致**: 严格按原则
- **难扩展**: 原则可以增加

---

## 5. 意义

- Claude 的核心训练方法
- 2023+ 主流 LLM 的"无害性"训练标准方法
- 开创 "Constitutional AI" / "AI Feedback" 范式

---

## 6. 公式表达

```text
CAI 2 阶段:

阶段 1: SL-CAI (Supervised Learning from CAI)
  对每个有害 prompt x:
    1. 采样: LLM 生成回答 y (有害)
    2. 批评: 给 LLM 一条原则 (如 "不要有害"), 让它批评 y
    3. 修正: 让 LLM 根据批评, 改写 y → y'
    4. 用 (x, y') 训练 LLM (SFT)

阶段 2: RL-CAI (RL from AI Feedback, RLAIF)
  对每个 prompt x:
    1. 采样: LLM 生成多个回答 y1, y2, ...
    2. AI 评估: 给 LLM 一条原则, 让它评估 (最有害 / 最无害)
    3. 训练 RM: 用 AI 评估作 label
    4. PPO 训练 (用 RM)

原则示例:
  - "请选择最无害 / 有帮助 / 真实的回答"
  - "请避免种族 / 性别 / 宗教歧视"
  - "如果回答有害, 请改写"
```

## 9. 答案

### 答案 1: 2 阶段流程

```text
阶段 1 (SL-CAI):
  对每个有害 prompt x:
    1. LLM 生成初始回答 y
    2. 给 LLM 一条原则 c, 让它批评 y: critique = LLM(prompt=c(x, y))
    3. 让 LLM 根据 critique 改写: y' = LLM(prompt=重写指令 + y + critique)
    4. 用 (x, y') SFT 训练 LLM

阶段 2 (RL-CAI / RLAIF):
  对每个 prompt x:
    1. LLM 采样多个回答 y1, y2, ..., yK
    2. 给 LLM 一条原则, 让它选最有用 / 最无害的
    3. 用 AI 评估的结果训练 RM
  然后用 PPO 训练
```

### 答案 2: SL-CAI 批评 + 改写

```python
def constitutional_rewrite(model, prompt, harmful_response, principle):
    """
    1. 批评: 让 LLM 用 principle 评价 harmful_response
    2. 改写: 让 LLM 根据批评改写
    """
    # 1. 批评
    critique_prompt = f"""
    以下回答: {harmful_response}
    原则: {principle}
    请根据原则批评这个回答。
    """
    critique = model.generate(critique_prompt)

    # 2. 改写
    rewrite_prompt = f"""
    原始回答: {harmful_response}
    批评: {critique}
    请根据批评改写这个回答, 严格遵守原则。
    """
    revised = model.generate(rewrite_prompt)

    return revised
```

### 答案 3: 5 条 Constitution 原则

```text
1. 请选择最有用、最诚实、最无害的回答。
2. 请避免任何形式的有害、歧视或冒犯内容。
3. 如果回答可能造成伤害, 请改写或拒绝回答。
4. 回答应基于事实, 不编造虚假信息。
5. 回答应尊重用户的隐私和自主性。
```

## 10. Constitutional AI 理论、论文和工业扩展

> 本扩展把 Constitutional AI 视为“显式原则 + 数据生成 + 偏好建模 + 策略优化 + 治理评测”的完整系统。
> RLAIF 不是取消人类责任，而是把人类从逐条标注转向原则制定、审计、红队、仲裁和风险所有权。

### 10.1 学习地图

1. 规范层：Constitution 的来源、层级、冲突和版本。
2. 数据层：响应、批评、修订、偏好对与审计元数据。
3. 模型层：SFT、奖励模型、PPO/DPO 与 KL 约束。
4. 评估层：helpfulness、harmlessness、honesty、拒答、偏差与鲁棒性。
5. 系统层：judge 集成、去偏、数据谱系、灰度和回滚。
6. 治理层：人类监督、申诉、隐私、法规、透明度和持续更新。

### 10.2 核心概念卡

#### 10.2.1 Constitution

- **定义**：可读、可审计的一组行为原则。
- **论文/方法对应**：Bai et al. 2022 Constitutional AI。
- **工业落点**：原则必须有来源、适用域、优先级和版本。
- **输入**：原则版本、prompt、候选回答、上下文与风险元数据。
- **输出**：修订文本、偏好标签、分数、置信度或升级人审决定。
- **主要风险**：反馈模型偏差会被训练放大，并可能与 policy 形成共模错误。
- **最小对照**：人工反馈基线、单 judge、judge ensemble 使用同一盲评集。
- **质量切片**：风险等级、语言、地区、身份群体、领域和请求类型。
- **安全切片**：明确有害、边界良性、可安全帮助、应拒绝与不确定样本。
- **指标**：帮助性、风险漏检、过度拒绝、校准、分歧率和人审升级率。
- **审计要求**：保留原则、judge prompt、模型 revision、随机种子和过滤原因。
- **面试追问**：该机制减少了哪类人力，又把哪类责任转移给人类？
- **回答要点**：自动化的是规模化反馈；原则制定、问责和风险接受仍是人的职责。
- **上线边界**：高风险、低置信和原则冲突样本默认升级，而不是强行自动决策。

### 10.3 理论推导

#### 10.3.1 监督微调目标

1. 修订数据为 $D=\{(x,y^*)\}$，其中 $y^*$ 是按原则改写后的目标回答。
2. 自回归策略为 $\pi_heta(y|x)=\prod_t\pi_heta(y_t|x,y_{<t})$。
3. SFT 最小化 token 负对数似然 $L_{SFT}=-E_D\sum_t\log\pi_heta(y_t^*|x,y_{<t}^*)$。
4. 如果批评文本不应由模型输出，就只对修订回答 token 计算 loss。
5. 该目标学习修订数据分布，也会继承 AI 生成数据的风格与遗漏。

**假设检查**：分数可比性、标签独立性和数据同分布都不能默认成立。
**治理解释**：公式给出优化手段，不替代价值判断与责任归属。

#### 10.3.2 Bradley-Terry 偏好模型

1. 奖励模型给出 $r_\phi(x,y)$。
2. 偏好 $y_w\succ y_l$ 的概率建模为 $P=\sigma(r_w-r_l)$。
3. 负对数似然为 $L=-\log\sigma(r_w-r_l)$。
4. 只有分数差可识别，给所有 reward 加相同常数不改变概率。
5. pair accuracy 高不代表置信度校准好，因此还需 Brier/ECE 或可靠性图。

**假设检查**：分数可比性、标签独立性和数据同分布都不能默认成立。
**治理解释**：公式给出优化手段，不替代价值判断与责任归属。

#### 10.3.3 标签噪声对偏好学习的影响

1. 假设真实偏好被 judge 以概率 $\epsilon$ 翻转。
2. 观测胜率为 $P_{obs}=(1-\epsilon)P_{true}+\epsilon(1-P_{true})$。
3. 化简为 $P_{obs}=\epsilon+(1-2\epsilon)P_{true}$。
4. 当 $\epsilono0.5$，反馈不再含偏好信息。
5. 多个高度相关 judge 不满足独立噪声假设，不能用数量掩盖同源偏差。

**假设检查**：分数可比性、标签独立性和数据同分布都不能默认成立。
**治理解释**：公式给出优化手段，不替代价值判断与责任归属。

#### 10.3.4 多数投票的独立假设

1. 若每个 judge 独立且正确率 $p>0.5$，奇数 $n$ 的多数正确率可由二项分布求和。
2. $P_{maj}=\sum_{k=\lceil n/2
ceil}^{n}{n\choose k}p^k(1-p)^{n-k}$。
3. 独立时增加 judge 通常提高可靠性。
4. 同架构、同训练数据、同 prompt 的错误往往相关，实际增益小于公式。
5. 因此集成应追求来源和提示多样性，并保留人类仲裁。

**假设检查**：分数可比性、标签独立性和数据同分布都不能默认成立。
**治理解释**：公式给出优化手段，不替代价值判断与责任归属。

#### 10.3.5 KL 约束策略优化

1. 常见目标为 $J(heta)=E_{y\sim\pi_heta}[r(x,y)]-eta KL(\pi_heta||\pi_{ref})$。
2. 第一项鼓励高奖励输出，第二项限制偏离参考模型。
3. $eta$ 大时策略保守，$eta$ 小时更易 reward hacking 或语言退化。
4. 训练中常根据目标 KL 自适应调节 beta。
5. KL 是分布约束，不替代独立质量和安全评测。

**假设检查**：分数可比性、标签独立性和数据同分布都不能默认成立。
**治理解释**：公式给出优化手段，不替代价值判断与责任归属。

#### 10.3.6 PPO clipped surrogate

1. 概率比 $
ho_t=\pi_heta(a_t|s_t)/\pi_{old}(a_t|s_t)$。
2. 代理目标使用 $min(
ho_tA_t,clip(
ho_t,1-\epsilon,1+\epsilon)A_t)$。
3. clip 限制单次更新过度改变策略。
4. 语言模型 PPO 还需 value loss、entropy、reward whitening 与 KL 控制。
5. 这些耦合超参数是 RLAIF 工程复杂度的重要来源。

**假设检查**：分数可比性、标签独立性和数据同分布都不能默认成立。
**治理解释**：公式给出优化手段，不替代价值判断与责任归属。

#### 10.3.7 DPO 目标

1. DPO 比较策略相对参考模型对 chosen/rejected 的 log-ratio。
2. 令 $\Delta=\log\pi_heta(y_w|x)-\log\pi_heta(y_l|x)-\log\pi_{ref}(y_w|x)+\log\pi_{ref}(y_l|x)$。
3. 损失为 $L_{DPO}=-\log\sigma(eta\Delta)$。
4. 它避免显式训练 reward model 和在线 PPO rollout。
5. 但偏好标签、原则冲突和 judge 偏差仍会直接影响结果。

**假设检查**：分数可比性、标签独立性和数据同分布都不能默认成立。
**治理解释**：公式给出优化手段，不替代价值判断与责任归属。

#### 10.3.8 多目标加权与 Pareto

1. 设帮助性 $h$、无害性 $s$、诚实性 $t$，加权目标为 $R=w_hh+w_ss+w_tt$。
2. 不同权重对应不同价值取舍，数学无法替治理者决定权重。
3. 如果一个策略至少不劣于另一个且某目标更优，则称其支配后者。
4. 不被其他策略支配的集合构成 Pareto frontier。
5. 安全关键目标可设置硬约束 $s\geau$，再在可行域优化帮助性。

**假设检查**：分数可比性、标签独立性和数据同分布都不能默认成立。
**治理解释**：公式给出优化手段，不替代价值判断与责任归属。

#### 10.3.9 过度拒绝的混淆矩阵

1. 把“应拒绝”视为正类。
2. 危险请求被允许是 FN，对应 under-refusal。
3. 良性请求被拒绝是 FP，对应 over-refusal。
4. 只提高拒答率可能降低 FN 却显著增加 FP。
5. 应分别报告风险召回、良性通过率和安全替代帮助质量。

#### 10.3.10 选择性预测与人审升级

1. 评估器输出风险概率 $p$ 和置信度。
2. 可设置低风险自动通过、高风险自动拦截、中间区间升级人审。
3. 覆盖率是自动处理样本比例，选择性风险是自动处理部分的错误率。
4. 扩大 abstain 区间通常降低选择性风险但增加运营成本。

import torch

def ppo_policy_loss(new_logp, old_logp, advantage, clip_eps=0.2):
    ratio = torch.exp(new_logp - old_logp)
    unclipped = ratio * advantage
    clipped = torch.clamp(ratio, 1 - clip_eps, 1 + clip_eps) * advantage

### 10.7 工业案例

#### 10.7.1 通用客服

- **风险结构**：大量可自动处理，但包含退款、投诉和隐私边界。
- **系统设计**：原则路由 + safe completion + 低置信人审。
- **核心指标**：解决率、过度拒绝、隐私事件、升级率。
- **数据设计**：真实分布、边界良性、明确风险、对抗样本与历史事故共同组成。
- **反馈设计**：AI 负责规模，人类负责原则、抽检、分歧、申诉和高风险仲裁。
- **模型外控制**：权限、沙箱、访问控制、速率限制和事务回滚不可省略。
- **上线流程**：离线门槛 → shadow → 小流量 → 分桶监控 → 逐级放量。
- **触发回滚**：高风险漏检、群体差异、异常拒答或 judge 漂移超过阈值。
- **事故复盘**：关联原则版本、模型版本、judge、数据谱系和当时上下文。
- **持续改进**：把申诉与事故转成测试，不直接把未经审计日志塞回训练。

#### 10.7.2 医疗信息助手

- **风险结构**：高影响、上下文不完整、需避免替代诊断。

### 10.8 生产治理检查清单

- [ ] 01. 每条原则有明确来源、所有者和适用范围。
- [ ] 02. 原则文本、解释、正反例和 rubric 同版本发布。
- [ ] 03. 冲突原则有优先级或升级规则。
- [ ] 04. 高风险边界不使用可被平均抵消的单一加权分。
- [ ] 05. 训练样本记录所用原则和版本。
- [ ] 06. 保留初答、批评、修订与过滤原因。
- [ ] 07. judge prompt 与 judge revision 可追溯。
- [ ] 08. A/B 候选顺序随机并测试 swap consistency。
- [ ] 09. 检查长度、风格和同源模型偏差。
- [ ] 10. 支持 tie、abstain 和低置信人审。
- [ ] 11. judge ensemble 关注错误相关性而非只看数量。
- [ ] 12. 偏好模型除准确率外报告 calibration。
- [ ] 13. 训练中监控 KL、熵、reward 和长度。
- [ ] 14. Best-of-N 检查奖励过优化。
- [ ] 15. DPO/PPO 使用同一独立盲评比较。
- [ ] 16. 帮助性、无害性、诚实性分别报告。
- [ ] 17. 风险漏检与过度拒绝分别报告。
- [ ] 18. 良性边界集覆盖敏感主题的安全用途。
- [ ] 19. 分语言、地区、群体和领域做切片。
- [ ] 20. 高影响领域由专业人员审查。
- [ ] 21. 工具动作有权限、确认、沙箱和回滚。
- [ ] 22. 隐私数据最小化并设置保留期限。
- [ ] 23. 训练和评测数据有许可与删除机制。
- [ ] 24. 线上日志避免保存不必要原始敏感内容。
- [ ] 25. 红队集与训练集隔离，防止测试泄漏。
- [ ] 26. 上线前运行 shadow 和人类盲评。
- [ ] 27. 灰度按风险等级而非只按随机流量。
- [ ] 28. 有 kill switch、稳定模型和政策回滚。
- [ ] 29. 模型/政策升级后旧指标不可直接沿用。
- [ ] 30. 事故可关联到完整数据与配置谱系。
- [ ] 31. 用户能获得适当解释和申诉渠道。
- [ ] 32. 自动反馈不被描述为客观或无偏。
- [ ] 33. 重大原则变更有治理审批。
- [ ] 34. 定期用新流量和新威胁更新测试。
- [ ] 35. 外部研究与事故会触发重新评估。
- [ ] 36. 任何自动化节省都不削弱最终责任归属。

### 10.11 小结

- CAI 的核心价值是把规范显式化、数据生成规模化、审计链路结构化。
- AI feedback 是带偏差的测量工具，不是最终价值来源，也不免除人类问责。
- 可靠落地依赖多目标评测、低置信升级、模型外权限控制、版本化与快速回滚。
- 成熟系统关注的不只是“拒绝了多少”，而是风险漏检、良性帮助、群体差异和用户可申诉性。
