# 第09章-01-量化

## 9.1 量化 (PTQ / QAT / GPTQ / AWQ)

---

## 1. 内容介绍

**量化** (Quantization) 把 FP32 权重 / 激活转为 INT8 / INT4, **减少 2-8 倍显存**, 推理速度提升 1.5-3x.

LLM 量化 (GPTQ / AWQ) 是部署到消费级 GPU 的关键技术.

---

## 2. 为什么这么做

**问题**:
- 7B 模型 FP16 推理需要 14GB 显存
- 消费级 GPU (RTX 4090 24GB) 装不下 70B
- 推理速度慢, 延迟高

**解决思路**:
- 把 FP16 (16 bit) 量化到 INT8 (8 bit) → 显存减半
- 进一步量化到 INT4 (4 bit) → 显存再减半 (总共 1/4)
- 量化需要校准, 让量化误差最小

---

## 3. 这么做的原因 (4 大方案对比)

| 方案 | 时间 | 精度损失 | 适用 |
|---|---|---|---|
| **PTQ** (训练后量化) | 推理前几分钟校准 | 1-3% | 通用, 简单 |
| **QAT** (训练中量化) | 训练几小时 | < 1% | 极致精度 |
| **GPTQ** | 几小时 | < 1% | LLM (大模型友好) |
| **AWQ** | 几小时 | < 1% | LLM (激活感知) |
| NF4 (QLoRA 用) | - | 1-2% | 4-bit 微调 |

**为什么 LLM 用 GPTQ / AWQ 而非传统 PTQ?**
- 传统 PTQ 在小模型 (CNN) 很好, 大模型 (LLM) 误差大
- LLM 有 outlier 权重, 传统方法放大误差
- **GPTQ** (2022) 用二阶信息 (Hessian) 选择性量化, 保护重要权重
- **AWQ** (2023) 保护"激活值大的权重" (重要), 量化其他, 效果更好

---

## 4. 解决了什么问题

- **显存**: FP16 → INT4 减 4 倍
- **速度**: 内存带宽减少 → 推理快
- **部署**: 70B 模型可以装进 24GB 消费级 GPU
- **能耗**: 整数运算比浮点省电

---

## 5. 意义

- LLM 部署的"必学"
- 2024+ 开源 LLM 几乎都提供 GPTQ / AWQ 量化版本
- vLLM, TGI, llama.cpp 等都集成量化

## 6. 公式表达

```text
对称量化:
  scale = max(|x|) / (qmax - qmin) / 2
  zero_point = (qmax + qmin) / 2
  x_int = round(x / scale) + zero_point
  x_dequant = (x_int - zero_point) * scale

非对称量化:
  scale = (max(x) - min(x)) / (qmax - qmin)
  zero_point = qmin - round(min(x) / scale)
  x_int = round(x / scale) + zero_point

INT8: qmin = -128, qmax = 127
INT4: qmin = -8, qmax = 7
NF4: 4-bit NormalFloat (正态分布分位)
```

## 9. 答案

### 答案 1: INT8 对称量化

```python
import numpy as np

def quantize_int8_symmetric(x):
    """
    对称量化: qmax = 127, qmin = -128
    scale = max(|x|) / 127
    """
    x_max = np.max(np.abs(x))
    scale = x_max / 127.0
    # 量化
    x_int = np.clip(np.round(x / scale), -128, 127).astype(np.int8)
    return x_int, scale

def dequantize_int8(x_int, scale):
    """反量化"""
    return x_int.astype(np.float32) * scale

# 验证
x = np.array([1.0, -2.5, 3.7, 0.5])
x_int, scale = quantize_int8_symmetric(x)
x_de = dequantize_int8(x_int, scale)
print(f"原始: {x}")
print(f"量化: {x_int}, scale: {scale:.3f}")
print(f"反量化: {x_de}")
print(f"误差: {np.abs(x - x_de).max():.4f}")  # < 0.05
```

### 答案 2: 量化显存

```python
def estimate_quantized_memory(n_params, bits=4):
    """
    量化后显存: 参数量 × 比特数 / 8 (字节) / 1024^3 (GB)
    """
    bytes_total = n_params * bits / 8
    return bytes_total / 1024 / 1024 / 1024

# LLaMA-7B
fp16_mem = estimate_quantized_memory(7e9, bits=16)  # 14 GB
int8_mem = estimate_quantized_memory(7e9, bits=8)   # 7 GB
int4_mem = estimate_quantized_memory(7e9, bits=4)   # 3.5 GB
print(f"LLaMA-7B:")
print(f"  FP16: {fp16_mem:.1f} GB")
print(f"  INT8: {int8_mem:.1f} GB")
print(f"  INT4: {int4_mem:.1f} GB")
```

### 答案 3: GPTQ 简化版

```python
def quantize_layer_gptq(W, H_inv, block_size=128):
    """
    GPTQ 核心思想:
    1. 逐列处理权重
    2. 每列量化后, 用 Hessian 逆矩阵更新剩余未量化列, 补偿误差
    3. 分块 (block_size) 处理, 平衡内存与精度

    W: (out_dim, in_dim)
    H_inv: (in_dim, in_dim)  H = 2 * X.T @ X / N (X 是输入)
    返回: W_quant (INT8 或 INT4)
    """
    Q = np.zeros_like(W)
    blocks = (W.shape[1] + block_size - 1) // block_size

    for block_idx in range(blocks):
        start = block_idx * block_size
        end = min((block_idx + 1) * block_size, W.shape[1])

        W_block = W[:, start:end]  # (out, block)
        H_block = H_inv[start:end, start:end]  # (block, block)

        for i in range(end - start):
            # 量化当前列
            w = W_block[:, i]
            scale = np.max(np.abs(w)) / 127
            q = np.clip(np.round(w / scale), -128, 127).astype(np.int8)
            Q[:, start + i] = q

            # 误差: 量化 - 原始
            err = (q.astype(np.float32) * scale) - w
            # 更新剩余列, 补偿误差
            # (err 外积) @ (H_block 的一列)
            for j in range(i + 1, end - start):
                W_block[:, j] -= err * (H_block[i, j] / H_block[i, i])

    return Q
```

**关键**: GPTQ 用 Hessian 指导量化方向, 让量化误差"传播"到不重要的列.

## 深入: PTQ vs QAT(两条量化路线)

| | PTQ(训练后量化) | QAT(量化感知训练) |
| :--- | :--- | :--- |
| 做法 | 训好后直接量化 + 少量校准数据 | 训练时模拟量化(fake quant) |
| 成本 | 低(无需重训) | 高(要训练) |
| 精度 | INT8 好、INT4 需技巧 | 更高,低比特更稳 |
| 代表 | GPTQ / AWQ / SmoothQuant | — |

LLM 因太大,**几乎都用 PTQ**(重训代价高)。QAT 多见于小模型/端侧。

---

## 深入: 离群值(outlier)—— LLM 量化的核心难点

LLM 激活里存在极少数**幅度极大的离群通道**,一刀切量化会让它们主导 scale、压死其余值 → 精度崩。三种主流解法:

| 方法 | 思路 |
| :--- | :--- |
| **LLM.int8()** | 离群通道保留 FP16,其余 INT8(混合精度分解) |
| **SmoothQuant** | 把激活的"难"迁移一部分到权重(数学等价缩放),让两者都好量化 |
| **AWQ** | 按激活重要性保护关键权重通道的精度 |
| **GPTQ** | 用 Hessian 指导逐列量化,误差传播到不重要列 |

> 核心洞察:**权重好量化,激活难量化**(离群值在激活)。SmoothQuant 的巧思是把难度在权重↔激活间"搬移"。

---

## 深入: 权重量化 vs KV Cache 量化 vs 激活量化

量化不止权重:
- **权重量化(W4/W8)**:省显存、省权重读取带宽 → decode 提速(见 [6.6 推理优化](../第06章-LLM核心技术/第06章-06-推理优化专题.md))。
- **KV Cache 量化(KV8)**:省长上下文 KV 显存(见 [6.3 KV-Cache](../第06章-LLM核心技术/第06章-03-KV-Cache.md))。
- **激活量化(W8A8)**:配合权重量化走 INT8 Tensor Core,进一步提速,但受离群值困扰。
- **QLoRA(NF4)**:量化基座 + LoRA 微调(见 [8.1 LoRA](../第08章-微调与对齐/第08章-01-LoRA.md))。

---

## 深入: 为什么量化能加速 decode

LLM decode 是**访存受限**(每步搬全部权重算 1 token,见 [6.3](../第06章-LLM核心技术/第06章-03-KV-Cache.md))。权重从 FP16→INT4,**权重读取带宽降 4×** → decode 直接快数倍。这是量化除省显存外的关键收益:不是算得快,是**读得快**。

### 10.2 核心概念卡：从公式到部署

#### 10.2.1 均匀仿射量化

- **定义**：均匀仿射量化 是量化设计空间中的一个独立决策点。
- **核心表达**：`$q=clip(round(x/s)+z,q_min,q_max)$`。
- **论文对应**：TensorRT / gemmlowp 的整数推理范式。
- **工业落点**：先明确 signed/unsigned 与舍入规则。
- **输入假设**：先确认张量轴语义、数据类型、分布和运行时算子支持。
- **精度问题**：误差既来自舍入，也来自截断、范围估计和跨层传播。
- **性能问题**：理论压缩比只有在低比特读取与计算 kernel 真正可用时才能兑现。
- **元数据问题**：scale、zero point、分组索引和码本都要计入显存。
- **校准问题**：代表性通常比样本数量更重要，长尾模板不可缺失。
- **验证问题**：同时检查张量重构误差、困惑度、下游任务与线上延迟。
- **常见误区**：只看模型文件大小，不看峰值显存、临时 workspace 和 KV Cache。
- **工程检查**：导出端和运行时必须采用相同舍入、饱和与符号约定。
- **回退策略**：敏感层可保留 BF16/FP16，避免为统一 bit-width 牺牲质量。
- **面试追问**：为什么局部 MSE 最优不一定带来端到端任务最优？
- **回答要点**：后续层 Jacobian 会放大不同方向的扰动，任务损失也不是均方误差。
- **实验变量**：bit-width、group size、校准范围、混合精度层、batch 和序列长度。
- **最小对照**：FP16、朴素 MinMax PTQ、候选算法三组使用同一评测集。
- **观测指标**：P50/P95 延迟、tokens/s、峰值显存、功耗、PPL 和任务分数。
- **结论记录**：报告硬件、驱动、kernel、模型 revision 与随机种子，保证可复现。

### 10.3 数学推导

#### 10.3.1 仿射量化参数

1. 设实数区间为 $[a,b]$，整数码域为 $[q_{min},q_{max}]$。
2. 要求端点近似对应：$approx s(q_{min}-z)$，$bpprox s(q_{max}-z)$。
3. 两式相减得到 $s=(b-a)/(q_{max}-q_{min})$。
4. 代回第一式得到 $z=q_{min}-a/s$，实现时把 $z$ 舍入并截断到码域。
5. 量化为 $q=clip(round(x/s)+z,q_{min},q_{max})$。
6. 反量化为 $\hat{x}=s(q-z)$。
7. 若 $x$ 未被截断，nearest rounding 的绝对误差上界约为 $s/2$。
8. 若发生截断，误差不再由 $s/2$ 控制，因此校准范围是核心超参数。

**推导检查**：写代码前确认维度、广播轴、有限值、空张量与全零张量。
**工程解释**：理论假设失效时，以可复现实验和端到端指标为准。

#### 10.3.2 量化噪声模型

1. 高分辨率假设下，可把量化误差 $e=\hat{x}-x$ 近似为均匀噪声。
2. 若 $e\sim U(-s/2,s/2)$，则 $E[e]=0$。
3. 其方差为 $Var(e)=s^2/12$。
4. 对独立零均值误差，线性层 $y=Wx$ 的输出噪声方差可近似相加。
5. 真实网络中误差与信号并不总独立，离群值和饱和会破坏该模型。
6. 因此 $s^2/12$ 适合解释趋势，不能替代端到端评测。

**推导检查**：写代码前确认维度、广播轴、有限值、空张量与全零张量。
**工程解释**：理论假设失效时，以可复现实验和端到端指标为准。

#### 10.3.3 逐通道优于逐张量的原因

1. 令第 $c$ 个输出通道最大幅值为 $m_c$，全局最大值为 $M=max_c m_c$。
2. 逐张量 scale 为 $s_t=M/Q$，逐通道 scale 为 $s_c=m_c/Q$。
3. 只要 $m_c<M$，就有 $s_c<s_t$。
4. 在无截断条件下误差方差近似与 $s^2$ 成正比。
5. 所以小幅值通道使用独立 scale 可显著降低舍入噪声。
6. 代价是每通道多一个 scale，并要求 kernel 支持对应广播轴。

#### 10.3.4 线性层误差分解

1. 原输出 $y=Wx$，量化后 $\hat{y}=(W+E_W)(x+e_x)$。
2. 展开得 $\hat{y}-y=E_Wx+We_x+E_We_x$。
3. 第一项是权重量化误差，第二项是激活量化误差，第三项通常是二阶小量。
4. 激活存在离群值时，$We_x$ 可能主导。
5. 仅做 W4A16 时 $e_x=0$，主要优化 $E_Wx$。
6. 二阶方法用输入协方差刻画不同权重方向对 $E_Wx$ 的影响。

#### 10.3.5 GPTQ 二阶目标

1. 层重构目标可写为 $min_{\hat W}\|WX-\hat WX\|_F^2$。
2. 令误差 $\Delta W=\hat W-W$，则目标为 $Tr(\Delta WXX^T\Delta W^T)$。
3. 因此与输入相关的 Hessian 近似为 $H=2XX^T$（常按样本数归一化）。
4. 量化一列后，通过 $H^{-1}$ 估计怎样更新未量化列以补偿输出误差。
5. 阻尼 $H+\lambda I$ 改善病态矩阵的 Cholesky 稳定性。
6. 分块处理减少内存和更新成本，同时保留主要相关性。

#### 10.3.6 SmoothQuant 等价缩放

1. 线性层为 $Y=XW$，对任意正对角矩阵 $S$ 有 $Y=(XS^{-1})(SW)$。
2. 该变换在精确算术下不改变输出。
3. 选择 $S$ 可缩小激活离群通道，同时把幅值迁移到相应权重通道。
4. 常见启发式为 $s_j=max|X_j|^lpha/max|W_j|^{1-lpha}$。
5. $lpha$ 越大越偏向平滑激活，但权重范围会变大。
6. 真正部署时把 $S$ 融入前置归一化和权重，避免额外运行时算子。

#### 10.3.7 NF4 码本动机

1. 若预训练权重近似零均值正态分布，均匀 4-bit 码本不是最优利用。
2. NF4 让码点近似对应标准正态分布的等概率分位区间。
3. 高密度中心区域分配更多表示点，低密度尾部点更稀疏。
4. 分块归一化后选择最近码点，再乘回块 scale。

### 10.4 PyTorch 手写实验

#### 10.4.1 安全的对称量化与反量化

```python
import torch

def symmetric_qdq(x: torch.Tensor, bits: int = 8):
    qmax = 2 ** (bits - 1) - 1
    amax = x.abs().amax()
    scale = torch.where(amax > 0, amax / qmax, torch.ones_like(amax))
    q = torch.clamp(torch.round(x / scale), -qmax, qmax).to(torch.int8)
    return q, scale

def dequant_symmetric(q: torch.Tensor, scale: torch.Tensor):
    return q.float() * scale

x = torch.tensor([-1.0, 0.0, 0.75, 2.0])
q, s = symmetric_qdq(x)
assert torch.max(torch.abs(dequant_symmetric(q, s) - x)) <= s / 2 + 1e-6
```

#### 10.4.4 INT4 nibble 打包与解包

```python
import torch

def pack_int4(q: torch.Tensor):
    assert q.dtype == torch.int8 and q.numel() % 2 == 0
    u = (q.to(torch.int16) & 0xF).flatten()
    return (u[0::2] | (u[1::2] << 4)).to(torch.uint8)

def unpack_int4(packed: torch.Tensor):
    lo = (packed & 0xF).to(torch.int8)
    hi = ((packed >> 4) & 0xF).to(torch.int8)
    u = torch.stack((lo, hi), dim=1).flatten()
    return torch.where(u >= 8, u - 16, u).to(torch.int8)
```

```python
class FakeQuantSTE(torch.autograd.Function):
```

```python
def hessian_inverse(inputs: torch.Tensor, damp_ratio: float = 0.01):
```

### 10.10 小结

- 量化首先是受约束的近似问题，其次才是模型文件压缩问题。
- 算法决定误差怎样分配，kernel 决定理论收益能否兑现。
- 最可靠流程是：高精度基线 → 分布诊断 → 低风险 INT8 → W4 搜索 → 分桶验收 → 灰度回滚。
- 任何“无损、四倍加速”的结论都必须附硬件、batch、序列长度、runtime 和质量指标。
