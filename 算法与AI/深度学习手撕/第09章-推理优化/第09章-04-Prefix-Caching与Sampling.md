## 1. Prefix Caching (前缀缓存)

### 1.1 内容介绍

**Prefix Caching**: 缓存**相同前缀**的 KV Cache, 避免重复计算.

**场景**: 多个请求有相同 system prompt / few-shot examples.

### 1.2 为什么这么做

**问题**:
- LLM 服务中, 大量请求共享 system prompt
- 例如: "你是一个有帮助的助手" 出现在所有请求
- 每次重新计算这个 system prompt 的 KV 浪费算力

**解决**:
- 计算 system prompt 的 KV, 缓存
- 后续请求的 system prompt 直接复用
- 节省 50%+ 推理成本 (对长 prompt)

### 1.3 公式

```text
请求 1: "你是一个助手. [Q1]"
请求 2: "你是一个助手. [Q2]"

传统: 两次计算完整 KV (2 × 完整长度)
Prefix Caching: 共享 "你是一个助手." 的 KV (节省 50%)
```

### 1.4 实现 (vLLM 的 Automatic Prefix Caching)

```python
class PrefixCache:
    """Prefix Caching 实现"""
    def __init__(self, block_size=16):
        self.block_size = block_size
        self.cache = {}  # (block_hash) -> (k_cache, v_cache)

    def get_kv(self, token_ids):
        """
        按 block 切分, 查找已缓存的 KV
        """
        matched_blocks = 0
        for i in range(0, len(token_ids), self.block_size):
            block = tuple(token_ids[i:i + self.block_size])
            if block in self.cache:
                matched_blocks += 1
            else:
                break
        return matched_blocks

    def store(self, token_ids, k, v):
        """存储新 block 的 KV"""
        for i in range(0, len(token_ids), self.block_size):
            block = tuple(token_ids[i:i + self.block_size])
            if block not in self.cache:
                # 模拟: 实际需要计算该 block 的 KV
                k_block = k[:, :, i:i + self.block_size, :]
                v_block = v[:, :, i:i + self.block_size, :]
                self.cache[block] = (k_block, v_block)
```

**复杂度**:
- 命中: $O(1)$ 查找 + 复用
- 未命中: 仍需计算

**效果**: 50-90% 推理加速 (长 prompt, 重复 system)

## 2. Token Repetition Penalty (重复惩罚)

### 2.1 问题

LLM 生成时, 常陷入"重复循环":
- "今天天气很好, 很好, 很好, 很好..."
- "我认为这个问题, 这个..."

### 2.2 解法 1: Repetition Penalty (OpenAI 风格)

**思想**: 已生成的 token 在后续采样时, 概率按指数衰减.

```python
def apply_repetition_penalty(logits, generated_tokens, penalty=1.2):
    """
    OpenAI 风格: 已出现 token 概率降低
    logits: (B, V)  词表大小 V
    generated_tokens: list[int]  已经生成的 token ids
    penalty: > 1 降低, < 1 增加
    """
    for tok in set(generated_tokens):  # 去重
        if logits[tok] > 0:
            logits[tok] = logits[tok] / penalty
        else:
            logits[tok] = logits[tok] * penalty  # 负数也处理
    return logits
```

**直观**: 若 `penalty=1.2`, 出现过的 token 概率除以 1.2 (降低 ~17%).

### 2.3 解法 2: Frequency Penalty

**思想**: 按出现频率惩罚, 出现越多惩罚越重.

```python
def apply_frequency_penalty(logits, generated_tokens, penalty=0.5):
    """
    出现次数 × penalty 累加
    """
    from collections import Counter
    freq = Counter(generated_tokens)
    for tok, count in freq.items():
        logits[tok] -= count * penalty
    return logits
```

### 2.4 解法 3: n-gram 惩罚 (更激进)

**思想**: 禁止出现 3-gram / 4-gram 重复.

```python
def apply_ngram_penalty(logits, generated_tokens, n=3):
    """
    禁止重复 n-gram
    """
    if len(generated_tokens) < n - 1:
        return logits

    # 当前 n-1 gram
    ngram = tuple(generated_tokens[-(n - 1):])

    # 找所有匹配的 n-gram, 排除下一个 token
    for i in range(len(generated_tokens) - n + 1):
        if tuple(generated_tokens[i:i + n - 1]) == ngram:
            next_tok = generated_tokens[i + n - 1]
            logits[next_tok] = -float('inf')  # 禁止

    return logits
```

## 3. Beam Search (束搜索)

### 3.1 内容介绍

**Beam Search**: 维护 top-k 个候选, 每步扩展, 取概率最大的 k 个. 比 Greedy 质量更高.

### 3.2 为什么这么做

**Greedy 缺点**: 每步选最大, 不一定全局最优.
- 例: 序列 ABC, 概率 0.5 × 0.4 × 0.3 = 0.06
- 但 ACD 概率 0.3 × 0.9 × 0.9 = 0.243 (Greedy 看不到)

**Beam Search 维护 top-k**, 概率最高的 k 个, 更可能找到全局最优.

### 3.3 实现

```python
def beam_search(log_probs, beam_size=3, max_len=20, end_token=0):
    """
    log_probs: (n_steps, V)  每步每个 token 的对数概率
    beam_size: 束宽
    max_len: 最大长度
    end_token: 终止 token
    """
    # 每个 beam 是 (log_prob, sequence)
    beams = [(0.0, [BOS_TOKEN])]

    for step in range(max_len):
        candidates = []
        for log_prob, seq in beams:
            if seq[-1] == end_token:
                candidates.append((log_prob, seq))
                continue
            # 扩展
            for v in range(V):
                new_log_prob = log_prob + log_probs[step, v]
                new_seq = seq + [v]
                candidates.append((new_log_prob, new_seq))

        # 选 top-k
        candidates.sort(key=lambda x: -x[0])
        beams = candidates[:beam_size]

    return beams[0][1]  # 返回最佳
```

### 3.4 改进

- **Length Normalization**: 长序列概率天然小, 除以长度
- **Diverse Beam Search**: 强制 beam 间差异
- **Sampling 混合**: Top-k + Beam Search

## 4. Sampling 策略

### 4.1 Temperature (温度)

```python
def apply_temperature(logits, temperature=1.0):
    """
    temperature < 1: 分布更尖 (更确定)
    temperature > 1: 分布更平 (更多样)
    temperature = 0: 退化为 greedy
    """
    if temperature == 0:
        return np.argmax(logits, axis=-1)
    return logits / temperature
```

### 4.2 Top-k Sampling

```python
def top_k_sampling(logits, k=50):
    """从概率最大的 k 个 token 中采样"""
    top_k_logits, top_k_idx = np.topk(logits, k)
    top_k_probs = softmax(top_k_logits)
    sampled = np.random.choice(top_k_idx, p=top_k_probs)
    return sampled
```

### 4.3 Top-p (Nucleus) Sampling

```python
def top_p_sampling(logits, p=0.9):
    """从累计概率 ≥ p 的最小集合中采样"""
    sorted_idx = np.argsort(-logits)
    sorted_logits = logits[sorted_idx]
    sorted_probs = softmax(sorted_logits)
    cumsum = np.cumsum(sorted_probs)

    # 找到累计概率 ≥ p 的最小集合
    n_keep = np.searchsorted(cumsum, p) + 1
    keep_idx = sorted_idx[:n_keep]

    # 重新归一化并采样
    keep_logits = logits[keep_idx]
    keep_probs = softmax(keep_logits)
    return np.random.choice(keep_idx, p=keep_probs)
```

### 4.4 组合策略

```python
def generate(model, prompt, max_new_tokens=100,
            temperature=0.7, top_k=50, top_p=0.9, repetition_penalty=1.1):
    """实际推理时的完整 sampling 流程"""
    for _ in range(max_new_tokens):
        logits = model(prompt)[:, -1, :]  # (1, V)

        # 1. Repetition Penalty
        logits = apply_repetition_penalty(logits[0], prompt.tolist())

        # 2. Temperature
        logits = logits / temperature

        # 3. Top-k
        if top_k > 0:
            top_k_logits, top_k_idx = np.topk(logits, top_k)
            mask = np.full_like(logits, -np.inf)
            mask[top_k_idx] = logits[top_k_idx]
            logits = mask

        # 4. Top-p
        if top_p < 1.0:
            sorted_idx = np.argsort(-logits)
            cumsum = np.cumsum(softmax(logits[sorted_idx]))
            n_keep = np.searchsorted(cumsum, top_p) + 1
            keep_idx = sorted_idx[:n_keep]
            mask = np.full_like(logits, -np.inf)
            mask[keep_idx] = logits[keep_idx]
            logits = mask

        # 5. Sample
        probs = softmax(logits)
        next_tok = np.random.choice(len(probs), p=probs)
        prompt = np.append(prompt, next_tok)

    return prompt
```

### 答案 1: Prefix Caching 的 KV 共享

```text
传统:
  请求 1: "你是一个助手. [Q1]" → 计算所有 token 的 KV (1× 完整)
```

### 答案 3: Greedy vs Beam Search

```text
例: V = {A:0.5, B:0.3, C:0.2}, 续接 概率:
  Greedy: A(0.5) → C(0.2) = 0.10
  Beam k=2:
    step 1: top-2 = {A:0.5, B:0.3} → beam = [A, B]
    step 2: 扩展
      A→A: 0.5×0.5 = 0.25
      A→B: 0.5×0.3 = 0.15
      B→A: 0.3×0.5 = 0.15

Greedy 选 A→C (0.10)
Beam 选 A→A (0.25)
Beam 更好!
```

## 7. Prefix Caching 与 Sampling 理论、论文和工程扩展

> 本扩展把“缓存是否正确”“缓存是否划算”“采样是否可控”拆成可验证问题。
> Prefix Caching 只复用完全相同计算语义的 KV；Sampling 则在 logits 上定义解码分布与约束。

### 7.1 总体学习地图

1. Attention 层：证明共享前缀的 KV 为什么可以复用。
2. 数据结构层：block hash、radix tree、引用计数、copy-on-write。
3. 调度层：continuous batching、chunked prefill、抢占和多租户隔离。
4. 采样层：temperature、top-k、top-p、typical、penalty 与 beam。
5. 评测层：命中率、节省计算量、TTFT、TPOT、质量与多样性。
6. 生产层：版本键、哈希安全、容量治理、灰度、监控和回滚。

### 7.2 核心概念卡

#### 7.2.1 Causal Attention 不变量

- **机制**：位置 i 的 K/V 仅依赖 token 0..i 与固定模型状态。
- **论文/系统对应**：这是前缀可复用的正确性基础。
- **工业动作**：先验证 full 与 incremental 输出一致。
- **正确性边界**：token、模型状态、位置、mask 或解码状态任一改变，都要重新审视是否可复用。
- **性能边界**：收益应扣除哈希、查找、引用管理、数据搬运和调度开销。
- **数据边界**：多租户、隐私、敏感 prompt 和保留周期必须在设计前确定。
- **指标**：同时记录命中率、命中 token 数、TTFT、TPOT、吞吐和峰值显存。
- **最小实验**：固定模型与请求集，只改变该策略，命中和未命中分桶比较。
- **负例**：语义相同但 token ids 不同，不属于 Prefix Cache 的精确命中。
- **故障模式**：错误复用常不崩溃，而是静默改变 logits，因此必须有一致性测试。
- **面试追问**：该机制改变的是计算量、内存量、候选分布还是调度顺序？
- **回答结构**：先定义，再给不变量/公式，最后给性能与产品取舍。
- **上线要求**：配置、runtime、模型版本和缓存命名空间使用不可变标识。

### 7.3 理论推导

#### 7.3.1 为什么完全相同前缀可以复用 KV

1. 第 $l$ 层位置 $i$ 的隐藏状态记为 $h_i^l$。
2. 在 causal mask 下，$h_i^l$ 只依赖同一层较早位置和前一层的 $h_{0:i}^{l-1}$。
3. $K_i^l=h_i^{l-1}W_K^l$，$V_i^l=h_i^{l-1}W_V^l$。
4. 若 token ids、模型参数、adapter、position ids、mask 和前处理完全相同，则归纳可得所有前缀隐藏状态相同。
5. 因此每层前缀 $K,V$ 相同，可以直接复用而不改变后续 logits。
6. 若任一条件改变，归纳前提失效，缓存键就必须区分。

**验证建议**：构造一个明确正例和一个违反前提的反例。
**工程解释**：理论节省必须经过目标硬件和调度器实测。

#### 7.3.2 Prefix Cache 节省的 prefill 计算

1. 设总 prompt 长度 $L=P+U$，其中共享前缀长度为 $P$，私有后缀为 $U$。
2. 无缓存时每请求需处理 $L$ 个 prefill token。
3. 命中时只需为 $U$ 个新 token 计算 Q/K/V 与后续层。
4. 粗略 token 计算节省比例为 $P/(P+U)$。
5. Attention prefill 的具体 FLOPs 还与序列长度二次项和 kernel 实现有关。
6. 线上应直接测 TTFT，不用 token 比例替代真实延迟。

#### 7.3.3 块级命中与最长公共前缀

2. 若只缓存完整块，可复用 token 数为 $B\lfloor P/B

5. 因此 block size 是碎片、查找和 kernel 效率的折中。

#### 7.3.4 token 加权命中率

1. 请求命中率定义为 $H_r=\sum I_i/N$。
2. 它把命中 16 token 与命中 8000 token 视为相同。
3. 更有意义的 token 命中率为 $H_t=\sum P_i^{hit}/\sum P_i^{total}$。

#### 7.3.5 Temperature 对赔率的影响

1. 采样分布为 $p_i(T)=exp(z_i/T)/\sum_j exp(z_j/T)$。
2. 两个 token 的概率比为 $p_i/p_j=exp((z_i-z_j)/T)$。
3. 当 $T<1$ 时，同一 logit 差被放大，分布更尖。
4. 当 $T>1$ 时，赔率差缩小，分布更平。
5. $To0^+$ 时极限趋向 argmax；实现应显式走 greedy，避免数值溢出。

#### 7.3.6 Top-p 候选集合

1. 将概率降序记为 $p_{(1)}\ge ...\ge p_{(V)}$。
2. 寻找最小 $m$ 使 $\sum_{i=1}^{m}p_{(i)}\ge p$。
3. 仅保留前 $m$ 个并重新归一化。
4. 在尖锐分布中 $m$ 很小，在平坦分布中 $m$ 较大。
5. 这解释了 nucleus sampling 相对固定 top-k 的自适应性。

#### 7.3.7 Repetition Penalty 的符号处理

1. 若出现过 token 的正 logit 除以 $r>1$，其值下降。
2. 负 logit 若也直接除以 $r$，会更接近零，反而概率上升。
3. 所以常用规则是正值除以 $r$，负值乘以 $r$。
4. 该变换不是直接“概率除以 r”，因为 softmax 会重新归一化所有候选。
5. penalty 的效果依赖其执行顺序和当前完整 logit 分布。

#### 7.3.8 Beam Search 的长度偏置

1. 序列分数常为 $S(y)=\sum_t\log p(y_t|y_{<t},x)$。
2. 每项通常非正，序列越长累计分数越低。
3. 因此未归一化 beam 容易偏向短序列和过早 EOS。
4. 可用 $S(y)/len(y)^lpha$ 或 GNMT 风格长度惩罚。
5. 归一化只改变搜索偏好，不能保证任务质量，alpha 必须验证。

#### 7.3.9 Sampling 熵与多样性

1. 分布熵为 $H(p)=-\sum_i p_i\log p_i$。
2. 升高 temperature 通常增大熵，但截断又会删除尾部概率。
3. 重复惩罚把质量从已出现 token 转移到其他 token，也可能增大局部熵。
4. 多样性不是越大越好，事实问答通常需要更低熵，创意写作容忍更高熵。
5. 产品应根据任务成功率而非单一熵值选择配置。

```python
        self.blocks = {}

        matched = 0
        parent = ()
        for start in range(0, len(token_ids), self.block_size):
            block = tuple(token_ids[start:start + self.block_size])
            if len(block) < self.block_size or (parent, block) not in self.blocks:

            parent = parent + block
            matched += len(block)

            if len(block) < self.block_size:
                break
            self.blocks[(parent, block)] = kv
            parent = parent + block
```

```python
import torch

def repetition_penalty_(logits, token_ids, penalty=1.2):
    assert logits.ndim == 2 and token_ids.ndim == 2
```

#### 7.4.7 Top-k / Top-p logits 过滤

```python
import torch

def top_k_top_p(logits, top_k=0, top_p=1.0):
    out = logits.clone()
    if top_k > 0:
        cutoff = torch.topk(out, min(top_k, out.shape[-1])).values[..., -1, None]
        out.masked_fill_(out < cutoff, float("-inf"))
    if top_p < 1.0:
        sorted_logits, idx = torch.sort(out, descending=True)
        cumulative = torch.softmax(sorted_logits, dim=-1).cumsum(dim=-1)
        remove = cumulative > top_p
        remove[..., 1:] = remove[..., :-1].clone()
        remove[..., 0] = False
        out.scatter_(1, idx, sorted_logits.masked_fill(remove, float("-inf")))
    return out
```

#### 7.4.8 Typical Sampling 过滤

```python
import torch

def typical_filter(logits, mass=0.9):
    logp = torch.log_softmax(logits, dim=-1)
    p = logp.exp()
    entropy = -(p * logp).sum(dim=-1, keepdim=True)
    shift = torch.abs(-logp - entropy)
    _, idx = torch.sort(shift, dim=-1)
    sorted_p = p.gather(-1, idx)
    remove = sorted_p.cumsum(-1) > mass
    remove[..., 1:] = remove[..., :-1].clone()
    remove[..., 0] = False
    mask = torch.zeros_like(remove).scatter(-1, idx, remove)
    return logits.masked_fill(mask, float("-inf"))
```

#### 7.4.11 长度归一化 Beam Search 骨架

```python
import torch

def beam_step(log_probs, beams, beam_size=3, alpha=0.7):
    candidates = []
    for score, seq in beams:
        for token, lp in enumerate(log_probs[len(seq)]):
            new_seq = seq + [token]
            raw = score + float(lp)
            rank = raw / (len(new_seq) ** alpha)
            candidates.append((rank, raw, new_seq))
    candidates.sort(key=lambda item: item[0], reverse=True)
    return [(raw, seq) for _, raw, seq in candidates[:beam_size]]
```

### 7.10 小结

- Prefix Caching 的第一原则是计算语义完全相同，第二原则才是命中率。
- 分页、哈希和 radix tree 解决存储与查找；版本键、隔离和一致性测试解决正确性。
- Sampling 是一串有顺序的 logits 变换，任何参数都应绑定任务指标而不是凭感觉设置。
- 上线必须同时具备缓存旁路、稳定解码 preset 和可复现请求记录。
