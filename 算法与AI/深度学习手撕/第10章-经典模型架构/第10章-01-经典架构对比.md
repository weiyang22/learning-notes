## 10.1 经典架构对比 (BERT / GPT / LLaMA / Mistral)

---

## 1. 内容介绍

**Transformer** (2017) 之后, 三大主流架构分支:
- **Encoder-only** (BERT 类): 理解任务
- **Decoder-only** (GPT/LLaMA 类): 生成任务
- **Encoder-Decoder** (T5/BART): 翻译/摘要

LLM 时代 **Decoder-only 一统天下**.

---

## 2. 为什么这么做

**3 大架构分支的诞生**:
- **BERT (2018, Google)**: Encoder-only, MLM + NSP 预训练, 适合理解
- **GPT (2018+, OpenAI)**: Decoder-only, 自回归 LM, 适合生成
- **T5 (2019, Google)**: Encoder-Decoder, 文本到文本统一

**为什么 LLM 选 Decoder-only?**
- 规模定律 (Scaling Laws) 显示, Decoder-only 的**生成能力强**
- 工程简洁 (只有 Decoder)
- 自回归统一, 适配任意任务 (生成式)

---

## 3. 主流架构对比

| 模型 | 年份 | 类型 | 参数量 | 关键创新 |
|---|---|---|---|---|
| **BERT-Base** | 2018 | Encoder | 110M | MLM + NSP, 双向注意力 |
| **BERT-Large** | 2018 | Encoder | 340M | 同上 |
| **GPT-1** | 2018 | Decoder | 117M | 第一个 Decoder-only 预训练 |
| **GPT-2** | 2019 | Decoder | 1.5B | 零样本学习 |
| **GPT-3** | 2020 | Decoder | 175B | In-context learning |
| **LLaMA-1** | 2023 | Decoder | 7-65B | 开放权重 + RoPE + SwiGLU + RMSNorm |
| **LLaMA-2** | 2023 | Decoder | 7-70B | + GQA + 长度扩展 |
| **LLaMA-3** | 2024 | Decoder | 8-70B | + 128K 上下文 + 15.6T tokens |
| **Mistral-7B** | 2023 | Decoder | 7B | + GQA + SWA (滑动窗口) |
| **Mixtral-8x7B** | 2024 | MoE | 47B 总 / 13B 激活 | 8 专家 MoE |

---

## 4. 解决了什么问题

- BERT 解决 "理解" 任务 (分类/QA)
- GPT 解决 "生成" 任务 (对话/创作)
- LLaMA 解决 "开放权重" 问题 (让学术能复现)
- Mistral 解决 "推理效率" 问题 (GQA + SWA)

---

## 5. 意义

- BERT 是 2018 NLP 革命
- GPT-3 (2020) 开启 LLM 时代
- LLaMA (2023) 开启开源 LLM 时代
- Mistral (2023+) 引领高效推理

---

## 6. 公式表达

### BERT (Encoder-only)
```text
输入: [CLS] + tokens + [SEP] + 句对
预训练: MLM (掩码 15% 词预测) + NSP (下句预测)
注意力: 双向 (每个 token 看所有)
应用: 分类, NER, QA
```

### GPT (Decoder-only)
```text
输入: prefix
预训练: 自回归 (预测下一个 token)
注意力: 单向 Causal Mask
应用: 生成, 对话, 创作
```

### LLaMA (Decoder-only + 优化)
```text
组成:
  1. Token Embedding
  2. N × [RMSNorm + Self-Attention (RoPE + GQA) + RMSNorm + SwiGLU FFN]
  3. RMSNorm
  4. LM Head

优化:
  - Pre-RMSNorm (vs GPT 的 Post-LN, 训练更稳)
  - RoPE (位置编码, 替代 Sinusoidal/Learned)
  - GQA (KV 头分组, 减少推理显存)
  - SwiGLU FFN (替代 ReLU/GELU, SOTA LLM 标配)
  - KV Cache (推理加速)
```

### Mistral-7B 创新
```text
在 LLaMA 基础上:
  + Grouped-Query Attention (GQA-8)
  + Sliding Window Attention (SWA) - 局部注意力, 节省 KV
  + Byte-Fallback BPE tokenizer
  + Rolling buffer cache
```

### Mixtral (MoE 8x7B)
```text
8 个专家 (Expert) 网络
每个 token 路由到 top-2 专家
总参数量 47B, 激活参数量 13B
推理速度接近 13B 模型, 容量接近 47B
```

## 9. 答案

### 答案 1: 4 大架构对比

```text
BERT  类型: Encoder-only  注意力: 双向          预训练任务: MLM + NSP
GPT    类型: Decoder-only  注意力: 单向 Causal    预训练任务: 自回归 LM
T5     类型: Encoder-Decoder 注意力: 双向 + 单向   预训练任务: 文本到文本
LLaMA  类型: Decoder-only  注意力: 单向 Causal    预训练任务: 自回归 LM
```

### 答案 2: LLaMA 四件套

```text
1. RMSNorm: 简化 LayerNorm, 去均值, 只缩放
   LN: (x - μ) / σ * γ + β
   RMS: x / RMS(x) * γ

2. RoPE: 旋转位置编码, 相对位置 + 长度外推
   详见 [5.3 位置编码]

3. SwiGLU: 替代 ReLU 的激活
   SwiGLU(a, b) = a * SiLU(b)
   FFN: out = (SiLU(x @ W_gate) * (x @ W_up)) @ W_down

4. GQA: 分组查询注意力, 减少 KV 缓存
   Q 多头, KV 头分组 (4-8 个)
   详见 [5.2 多头注意力]
```

### 答案 3: MoE 参数量

```text
总参数量: 8 × 7B = 56B (实际 Mistral 7B 是 ~7B, Mixtral 8x7B 总 47B)
激活参数量 (top-2): 2 × 7B = 14B (≈ 13B)
KV 缓存: 仅 1 个专家的 KV (类似 MQA)
```

**MoE 优势**:
- 总参数大 → 容量大 (知识多)
- 激活参数小 → 推理快 (类似小模型)
- 训练代价增加 (所有专家都要训)

## 10. 深度展开: 每个架构的细节

### 10.1 BERT 详解 (Encoder-only 巅峰)

**论文**: Devlin et al. "BERT: Pre-training of Deep Bidirectional Transformers for Language Understanding" (NAACL 2019)
**arXiv**: 1810.04805
**机构**: Google AI Language

**核心结构**:
- 12/24 层 Transformer Encoder
- 12/16 注意力头
- 隐藏维度 768/1024
- 参数量: Base=110M, Large=340M
- 最大序列长度: 512
- 词表: WordPiece, ~30K

**预训练任务**:
1. **MLM (Masked Language Modeling)**: 随机掩盖 15% token, 预测
   - 80% → `[MASK]`
   - 10% → 随机 token
   - 10% → 保持原 token
2. **NSP (Next Sentence Prediction)**: 预测两句话是否相邻
   - 后被 RoBERTa 证明无用

**输入表示**:
```text
[CLS] tokens_A [SEP] tokens_B [SEP]
   ↓        ↓
 Token    Segment
 Embed    Embed
   +        +
 Position Embedding
```

**下游应用**:
- 文本分类: [CLS] 向量 → softmax
- 序列标注: 每个 token 向量 → 分类
- 抽取式 QA: 两个向量预测 start/end position

**变体**:
- **RoBERTa** (Facebook, 2019): 去掉 NSP, 动态掩码, 更多数据 → 性能全面超越 BERT
- **ALBERT** (Google, 2019): 参数共享 + 嵌入分解 → 12M 参数
- **ELECTRA** (Stanford, 2020): Replaced Token Detection (RTD), 小模型也强
- **DeBERTa** (Microsoft, 2021): 解耦相对位置, SOTA GLUE

**工业部署**:
- Google Search: BERT 用于 query 理解 (2019)
- 百度 ERNIE: 知识增强 BERT
- 阿里 PAI: 多语言 BERT

**PyTorch 实现 (简化版)**:
```python
import torch
import torch.nn as nn

class BERTEmbedding(nn.Module):
    """BERT 三嵌入: token + segment + position"""
    def __init__(self, vocab_size, d_model, max_len, type_vocab_size=2):
        super().__init__()
        self.token_emb = nn.Embedding(vocab_size, d_model)
        self.position_emb = nn.Embedding(max_len, d_model)
        self.segment_emb = nn.Embedding(type_vocab_size, d_model)
        self.norm = nn.LayerNorm(d_model)
        self.dropout = nn.Dropout(0.1)

    def forward(self, token_ids, segment_ids=None):
        B, n = token_ids.shape
        positions = torch.arange(n, device=token_ids.device).unsqueeze(0).expand(B, n)
        if segment_ids is None:
            segment_ids = torch.zeros_like(token_ids)
        x = self.token_emb(token_ids) + self.position_emb(positions) + self.segment_emb(segment_ids)
        return self.dropout(self.norm(x))


class BERTEncoderLayer(nn.Module):
    """BERT 一层: Self-Attention + FFN (Post-LN)"""
    def __init__(self, d_model=768, n_heads=12, d_ff=3072, dropout=0.1):
        super().__init__()
        self.attn = nn.MultiheadAttention(d_model, n_heads, dropout=dropout, batch_first=True)
        self.norm1 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.GELU(),
            nn.Linear(d_ff, d_model),
            nn.Dropout(dropout),
        )
        self.norm2 = nn.LayerNorm(d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        # Self-Attention (双向)
        attn_out, _ = self.attn(x, x, x, attn_mask=mask)
        x = self.norm1(x + self.dropout(attn_out))   # Post-LN
        # FFN
        ffn_out = self.ffn(x)
        x = self.norm2(x + self.dropout(ffn_out))
        return x


class MiniBERT(nn.Module):
    def __init__(self, vocab_size=30000, d_model=768, n_layers=12, n_heads=12,
                 d_ff=3072, max_len=512, num_classes=2):
        super().__init__()
        self.embed = BERTEmbedding(vocab_size, d_model, max_len)
        self.encoder = nn.ModuleList([
            BERTEncoderLayer(d_model, n_heads, d_ff) for _ in range(n_layers)
        ])
        self.classifier = nn.Linear(d_model, num_classes)

    def forward(self, token_ids, segment_ids=None):
        x = self.embed(token_ids, segment_ids)
        for layer in self.encoder:
            x = layer(x)
        cls = x[:, 0]   # [CLS] 向量
        return self.classifier(cls)
```

### 10.2 GPT 详解 (Decoder-only 起点)

**论文**: Radford et al.
- GPT-1: "Improving Language Understanding by Generative Pre-Training" (2018)
- GPT-2: "Language Models are Unsupervised Multitask Learners" (2019)
- GPT-3: "Language Models are Few-Shot Learners" (NeurIPS 2020)
**机构**: OpenAI

**GPT 系列演进**:

| 模型 | 年份 | 参数量 | 上下文 | 关键能力 |
|---|---|---|---|---|
| GPT-1 | 2018 | 117M | 512 | 第一个 Decoder-only 预训练 |
| GPT-2 | 2019 | 1.5B | 1024 | Zero-shot, 怀疑能力上限 |
| GPT-3 | 2020 | 175B | 2048 | In-context learning |
| GPT-3.5 | 2022 | (未公开) | 4K | InstructGPT, RLHF |
| GPT-4 | 2023 | (未公开) | 8K-128K | 多模态 |

**GPT-2 论文金句**:
> "We show that language models begin to learn these tasks without any explicit supervision when trained on a new dataset of millions of webpages called WebText."

**GPT-3 论文金句**:
> "Few-shot learning via in-context learning: conditioning on a few examples in the prompt without any weight updates."

**GPT 的关键设计**:
1. **Causal Mask**: 上三角 mask, 每个 token 只能看自己和之前
2. **Post-LN**: 原始 GPT 用 Post-LayerNorm, 训练不稳定, 后续改 Pre-LN
3. **位置编码**: 学到的 absolute position embedding (GPT-1/2/3)
4. **Decoder Block**: Masked Self-Attention + FFN

**In-Context Learning (ICL)**:
- 不更新参数, 仅靠 prompt 给示例
- Few-shot: 给 K 个示例, 模型推理
- 涌现能力: 模型规模到一定程度才有

**RLHF (Reinforcement Learning from Human Feedback)**:
```text
Step 1: SFT (Supervised Fine-Tuning) on 标注数据
Step 2: RM (Reward Model) 学习人类偏好
Step 3: PPO (Policy Optimization) 微调
```

**PyTorch 实现 (Decoder Block)**:
```python
import torch
import torch.nn as nn
import math


class CausalSelfAttention(nn.Module):
    """GPT 的 Causal Self-Attention"""
    def __init__(self, d_model=768, n_heads=12, max_len=1024, dropout=0.1):
        super().__init__()
        assert d_model % n_heads == 0
        self.n_heads = n_heads
        self.d_k = d_model // n_heads
        self.W_qkv = nn.Linear(d_model, 3 * d_model)
        self.W_o = nn.Linear(d_model, d_model)
        self.attn_dropout = nn.Dropout(dropout)
        self.resid_dropout = nn.Dropout(dropout)

        # 因果 mask
        mask = torch.triu(torch.ones(max_len, max_len), diagonal=1).bool()
        self.register_buffer('mask', mask)

    def forward(self, x):
        B, n, d = x.shape
        # 合并 QKV
        qkv = self.W_qkv(x).reshape(B, n, 3, self.n_heads, self.d_k).permute(2, 0, 3, 1, 4)
        Q, K, V = qkv[0], qkv[1], qkv[2]   # (B, h, n, d_k)
        # Attention
        scores = Q @ K.transpose(-2, -1) / math.sqrt(self.d_k)
        scores = scores.masked_fill(self.mask[:n, :n], float('-inf'))
        attn = self.attn_dropout(torch.softmax(scores, dim=-1))
        # 合并头
        out = (attn @ V).transpose(1, 2).reshape(B, n, d)
        return self.resid_dropout(self.W_o(out))


class GPTBlock(nn.Module):
    """GPT 一个 Transformer Block"""
    def __init__(self, d_model, n_heads, d_ff, max_len=1024, dropout=0.1):
        super().__init__()
        self.ln1 = nn.LayerNorm(d_model)
        self.attn = CausalSelfAttention(d_model, n_heads, max_len, dropout)
        self.ln2 = nn.LayerNorm(d_model)
        self.ffn = nn.Sequential(
            nn.Linear(d_model, d_ff),
            nn.GELU(),
            nn.Linear(d_ff, d_model),
            nn.Dropout(dropout),
        )

    def forward(self, x):
        # Pre-LN (GPT-3 后改的, GPT-1/2 是 Post-LN)
        x = x + self.attn(self.ln1(x))
        x = x + self.ffn(self.ln2(x))
        return x


class MiniGPT(nn.Module):
    def __init__(self, vocab_size=50000, d_model=768, n_layers=12, n_heads=12,
                 d_ff=3072, max_len=1024):
        super().__init__()
        self.token_emb = nn.Embedding(vocab_size, d_model)
        self.pos_emb = nn.Embedding(max_len, d_model)
        self.blocks = nn.ModuleList([
            GPTBlock(d_model, n_heads, d_ff, max_len) for _ in range(n_layers)
        ])
        self.ln_f = nn.LayerNorm(d_model)
        self.lm_head = nn.Linear(d_model, vocab_size, bias=False)
        # 权重共享 (token_emb 与 lm_head)
        self.lm_head.weight = self.token_emb.weight
        self.max_len = max_len

    def forward(self, token_ids):
        B, n = token_ids.shape
        positions = torch.arange(n, device=token_ids.device).unsqueeze(0).expand(B, n)
        x = self.token_emb(token_ids) + self.pos_emb(positions)
        for block in self.blocks:
            x = block(x)
        x = self.ln_f(x)
        return self.lm_head(x)   # (B, n, vocab_size)
```

### 10.3 T5 详解 (Encoder-Decoder 统一)

**论文**: Raffel et al. "Exploring the Limits of Transfer Learning with a Unified Text-to-Text Transformer" (JMLR 2020)
**arXiv**: 1910.10683
**机构**: Google

**核心思想**: **把所有 NLP 任务统一为"文本到文本"**
- 分类: "classify: 这条评论是好评还是差评?" → "好评"
- 翻译: "translate English to German: That is good." → "Das ist gut."
- 摘要: "summarize: <长文>" → "<短摘要>"

**模型结构**:
- Encoder-Decoder
- 共享词表 SentencePiece (32K)
- T5-Base: 220M, T5-Large: 770M, T5-11B: 11B
- 相对位置编码 (T5 用 Simplified Relative Position)

**预训练任务**: Span Corruption (类似 BERT MLM 但生成)
- 掩盖 15% 的 token, 平均长度 3
- 用 sentinels 替换: `The doggy is cute` → `The <X> is <Y>.`
- 预测 sentinels 对应的 token

**变体**:
- **mT5**: 多语言版本, 101 种语言
- **T5 v1.1**: 去掉 "预训练任务对比实验" 部分, 用简化版
- **FLAN-T5**: Instruction tuning
- **UL2**: 统一不同预训练模式 (causal, prefix, span)

**为什么 T5 没成 LLM 主流?**
- Encoder-Decoder 训练成本高 (双倍)
- 推理时需要完整 prompt 才能 decoder, 不利于 ICL
- Decoder-only 已被证明更易 scale up

**PyTorch 实现**:
```python
import torch
import torch.nn as nn


class T5LayerSelfAttention(nn.Module):
    """T5 的 Self-Attention (Encoder 端, 双向)"""
    def __init__(self, d_model, n_heads, d_kv, dropout=0.1):
        super().__init__()
        self.W_q = nn.Linear(d_model, n_heads * d_kv)
        self.W_k = nn.Linear(d_model, n_heads * d_kv)
        self.W_v = nn.Linear(d_model, n_heads * d_kv)
        self.W_o = nn.Linear(n_heads * d_kv, d_model)
        self.n_heads = n_heads
        self.d_kv = d_kv
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        B, n, _ = x.shape
        Q = self.W_q(x).reshape(B, n, self.n_heads, self.d_kv).transpose(1, 2)
        K = self.W_k(x).reshape(B, n, self.n_heads, self.d_kv).transpose(1, 2)
        V = self.W_v(x).reshape(B, n, self.n_heads, self.d_kv).transpose(1, 2)
        scores = Q @ K.transpose(-2, -1) / (self.d_kv ** 0.5)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float('-inf'))
        attn = self.dropout(torch.softmax(scores, dim=-1))
        out = (attn @ V).transpose(1, 2).reshape(B, n, -1)
        return self.W_o(out)


class T5LayerCrossAttention(nn.Module):
    """T5 的 Cross-Attention (Decoder 端, 双向 K/V)"""
    def __init__(self, d_model, n_heads, d_kv, dropout=0.1):
        super().__init__()
        self.W_q = nn.Linear(d_model, n_heads * d_kv)
        self.W_k = nn.Linear(d_model, n_heads * d_kv)   # 来自 Encoder 输出
        self.W_v = nn.Linear(d_model, n_heads * d_kv)
        self.W_o = nn.Linear(n_heads * d_kv, d_model)
        self.n_heads = n_heads
        self.d_kv = d_kv
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, encoder_output, mask=None):
        B, n, _ = x.shape
        Q = self.W_q(x).reshape(B, n, self.n_heads, self.d_kv).transpose(1, 2)
        K = self.W_k(encoder_output).reshape(B, -1, self.n_heads, self.d_kv).transpose(1, 2)
        V = self.W_v(encoder_output).reshape(B, -1, self.n_heads, self.d_kv).transpose(1, 2)
        scores = Q @ K.transpose(-2, -1) / (self.d_kv ** 0.5)
        if mask is not None:
            scores = scores.masked_fill(mask == 0, float('-inf'))
        attn = self.dropout(torch.softmax(scores, dim=-1))
        out = (attn @ V).transpose(1, 2).reshape(B, n, -1)
        return self.W_o(out)


class T5FFN(nn.Module):
    """T5 的 Dense FFN (ReLU)"""
    def __init__(self, d_model, d_ff, dropout=0.1):
        super().__init__()
        self.fc1 = nn.Linear(d_model, d_ff)
        self.fc2 = nn.Linear(d_ff, d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x):
        return self.dropout(self.fc2(torch.relu(self.fc1(x))))


class T5Block(nn.Module):
    """T5 一个 Block (共享, Encoder/Decoder 都用)"""
    def __init__(self, d_model, n_heads, d_kv, d_ff, is_decoder=False, dropout=0.1):
        super().__init__()
        self.is_decoder = is_decoder
        self.ln1 = RMSNorm(d_model)   # T5 用 RMSNorm
        self.attn = T5LayerSelfAttention(d_model, n_heads, d_kv, dropout)
        self.ln2 = RMSNorm(d_model)
        self.ffn = T5FFN(d_model, d_ff, dropout)
        if is_decoder:
            self.ln3 = RMSNorm(d_model)
            self.cross_attn = T5LayerCrossAttention(d_model, n_heads, d_kv, dropout)
            self.ln4 = RMSNorm(d_model)

    def forward(self, x, encoder_output=None, mask=None, cross_mask=None):
        x = x + self.attn(self.ln1(x), mask)
        if self.is_decoder:
            x = x + self.cross_attn(self.ln3(x), encoder_output, cross_mask)
            x = x + self.ffn(self.ln4(x))
        else:
            x = x + self.ffn(self.ln2(x))
        return x
```

```python
import torch
import torch.nn as nn
import math


class RMSNorm(nn.Module):
    """LLaMA 的 RMSNorm"""
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(d))
        self.eps = eps

    def forward(self, x):
        # x: (..., d)
        norm = x * torch.rsqrt(x.pow(2).mean(-1, keepdim=True) + self.eps)
        return norm * self.weight


def precompute_rope(d_k, max_seq_len=8192, base=10000):
    """预计算 RoPE 的 cos/sin"""
    inv_freq = 1.0 / (base ** (torch.arange(0, d_k, 2).float() / d_k))
    t = torch.arange(max_seq_len)
    freqs = torch.outer(t, inv_freq)
    return torch.cos(freqs), torch.sin(freqs)


def apply_rope(x, cos, sin, positions):
    """对 x 应用 RoPE, x: (B, h, n, d_k)"""
    cos = cos[positions].unsqueeze(1)   # (B, 1, n, d_k/2)
    sin = sin[positions].unsqueeze(1)
    # rotate_half
    x1, x2 = x[..., 0::2], x[..., 1::2]
    rotated = torch.stack([-x2, x1], dim=-1).reshape(*x.shape)
    return (x * torch.cat([cos, cos], dim=-1)) + (rotated * torch.cat([sin, sin], dim=-1))


class LLaMAAttention(nn.Module):
    """LLaMA 的 GQA Attention"""
    def __init__(self, d_model, n_q_heads, n_kv_heads, max_seq_len=8192):
        super().__init__()
        assert n_q_heads % n_kv_heads == 0
        self.n_q = n_q_heads
        self.n_kv = n_kv_heads
        self.n_groups = n_q_heads // n_kv_heads
        self.d_k = d_model // n_q_heads

        self.W_q = nn.Linear(d_model, n_q_heads * self.d_k, bias=False)
        self.W_k = nn.Linear(d_model, n_kv_heads * self.d_k, bias=False)
        self.W_v = nn.Linear(d_model, n_kv_heads * self.d_k, bias=False)
        self.W_o = nn.Linear(n_q_heads * self.d_k, d_model, bias=False)

        cos, sin = precompute_rope(self.d_k, max_seq_len)
        self.register_buffer('cos', cos)
        self.register_buffer('sin', sin)

    def forward(self, x, positions, mask=None):
        B, n, d = x.shape
        Q = self.W_q(x).reshape(B, n, self.n_q, self.d_k).transpose(1, 2)
        K = self.W_k(x).reshape(B, n, self.n_kv, self.d_k).transpose(1, 2)
        V = self.W_v(x).reshape(B, n, self.n_kv, self.d_k).transpose(1, 2)
        # RoPE
        Q = apply_rope(Q, self.cos, self.sin, positions)
        K = apply_rope(K, self.cos, self.sin, positions)
        # GQA: K/V 重复
        K = K.repeat_interleave(self.n_groups, dim=1)
        V = V.repeat_interleave(self.n_groups, dim=1)
        # Attention
        scores = Q @ K.transpose(-2, -1) / math.sqrt(self.d_k)
        if mask is not None:
            scores = scores.masked_fill(mask, float('-inf'))
        attn = torch.softmax(scores, dim=-1)
        out = (attn @ V).transpose(1, 2).reshape(B, n, -1)
        return self.W_o(out)


class SwiGLU(nn.Module):
    """LLaMA 的 SwiGLU FFN"""
    def __init__(self, d_model, d_ff):
        super().__init__()
        self.W_gate = nn.Linear(d_model, d_ff, bias=False)
        self.W_up = nn.Linear(d_model, d_ff, bias=False)
        self.W_down = nn.Linear(d_ff, d_model, bias=False)

    def forward(self, x):
        return self.W_down(torch.nn.functional.silu(self.W_gate(x)) * self.W_up(x))


class LLaMABlock(nn.Module):
    """LLaMA 一个 Block (Pre-RMSNorm)"""
    def __init__(self, d_model, n_q_heads, n_kv_heads, d_ff, max_seq_len=8192):
        super().__init__()
        self.attn_norm = RMSNorm(d_model)
        self.attn = LLaMAAttention(d_model, n_q_heads, n_kv_heads, max_seq_len)
        self.ffn_norm = RMSNorm(d_model)
        self.ffn = SwiGLU(d_model, d_ff)

    def forward(self, x, positions, mask=None):
        h = x + self.attn(self.attn_norm(x), positions, mask)
        out = h + self.ffn(self.ffn_norm(h))
        return out


class LLaMA(nn.Module):
    """LLaMA 完整模型"""
    def __init__(self, vocab_size, d_model=4096, n_layers=32, n_q_heads=32,
                 n_kv_heads=32, d_ff=11008, max_seq_len=8192):
        super().__init__()
        self.token_emb = nn.Embedding(vocab_size, d_model)
        self.layers = nn.ModuleList([
            LLaMABlock(d_model, n_q_heads, n_kv_heads, d_ff, max_seq_len)
            for _ in range(n_layers)
        ])
        self.norm = RMSNorm(d_model)
        self.lm_head = nn.Linear(d_model, vocab_size, bias=False)
        # 权重共享
        self.lm_head.weight = self.token_emb.weight

    def forward(self, token_ids):
        B, n = token_ids.shape
        positions = torch.arange(n, device=token_ids.device).unsqueeze(0).expand(B, n)
        # 因果 mask
        mask = torch.triu(torch.ones(n, n, device=token_ids.device), diagonal=1).bool()
        x = self.token_emb(token_ids)
        for layer in self.layers:
            x = layer(x, positions, mask)
        x = self.norm(x)
        return self.lm_head(x)
```

### 10.5 Mistral 详解 (高效推理新标杆)

**论文**: Jiang et al. "Mistral 7B" (2023)
**arXiv**: 2310.06825
**机构**: Mistral AI (法国)

**核心创新**:
1. **GQA-8**: 8 组 KV 头, 推理 KV 缓存减少 4x
2. **SWA (Sliding Window Attention)**: 注意力窗口 W=4096
3. **Byte-Fallback BPE**: 罕见字符按字节 fallback, 编码任何字符
4. **Rolling Buffer Cache**: KV Cache 滚动保留 W 个最新

**Mistral-7B 配置**:
- 参数量: 7.3B
- 层数: 32
- d_model: 4096
- n_heads: 32 (Q), 8 (KV, GQA-8)
- d_k: 128
- 词表: 32K
- 上下文: 8K (SWA) / 32K (理论)

**GQA-8 详解**:
```text
传统 MHA (MQA):
  Q: 32 头, K: 1 头, V: 1 头
  KV 缓存: 1x

GQA-8 (Mistral):
  Q: 32 头, K: 4 头, V: 4 头 (8 个 Q 共用一个 KV)
  KV 缓存: 4x (vs MHA 的 32x)

MHA (传统):
  KV 缓存: 32x (最多)
```

**SWA (Sliding Window Attention) 详解**:
```text
每个 token 只看前 W=4096 个 token
KV Cache 只保留 W 个 token
→ 长序列推理 KV 不爆炸

实际有效感受野 (理论上): n_layers * W
  32 层 × 4096 = 131072 ≈ 128K 上下文
```

**PyTorch 实现 (Mistral)**:
```python
import torch
import torch.nn as nn
import math


class MistralAttention(nn.Module):
    """Mistral 的 GQA + SWA"""
    def __init__(self, d_model, n_q_heads=32, n_kv_heads=8, window_size=4096, max_seq_len=32768):
        super().__init__()
        self.n_q = n_q_heads
        self.n_kv = n_kv_heads
        self.n_groups = n_q_heads // n_kv_heads
        self.d_k = d_model // n_q_heads
        self.window_size = window_size
        self.max_seq_len = max_seq_len

        self.W_q = nn.Linear(d_model, n_q_heads * self.d_k, bias=False)
        self.W_k = nn.Linear(d_model, n_kv_heads * self.d_k, bias=False)
        self.W_v = nn.Linear(d_model, n_kv_heads * self.d_k, bias=False)
        self.W_o = nn.Linear(n_q_heads * self.d_k, d_model, bias=False)

        # RoPE
        inv_freq = 1.0 / (10000 ** (torch.arange(0, self.d_k, 2).float() / self.d_k))
        self.register_buffer('inv_freq', inv_freq)

    def forward(self, x, positions):
        B, n, d = x.shape
        Q = self.W_q(x).reshape(B, n, self.n_q, self.d_k).transpose(1, 2)
        K = self.W_k(x).reshape(B, n, self.n_kv, self.d_k).transpose(1, 2)
        V = self.W_v(x).reshape(B, n, self.n_kv, self.d_k).transpose(1, 2)

        # RoPE
        freqs = torch.outer(positions[0].float(), self.inv_freq)
        cos = freqs.cos().unsqueeze(0).unsqueeze(0)
        sin = freqs.sin().unsqueeze(0).unsqueeze(0)
        Q1, Q2 = Q[..., 0::2], Q[..., 1::2]
        K1, K2 = K[..., 0::2], K[..., 1::2]
        Q_rot = torch.stack([-Q2, Q1], dim=-1).reshape(*Q.shape)
        K_rot = torch.stack([-K2, K1], dim=-1).reshape(*K.shape)
        Q = Q * torch.cat([cos, cos], dim=-1) + Q_rot * torch.cat([sin, sin], dim=-1)
        K = K * torch.cat([cos, cos], dim=-1) + K_rot * torch.cat([sin, sin], dim=-1)

        # GQA: K/V 重复
        K = K.repeat_interleave(self.n_groups, dim=1)
        V = V.repeat_interleave(self.n_groups, dim=1)

        # 构造 SWA + Causal Mask
        # 位置 i 只能看 max(0, i-W+1) 到 i
        row_idx = torch.arange(n, device=x.device).unsqueeze(1)
        col_idx = torch.arange(n, device=x.device).unsqueeze(0)
        # causal AND within window
        mask = (row_idx < col_idx) | (col_idx < row_idx - self.window_size + 1)

        scores = Q @ K.transpose(-2, -1) / math.sqrt(self.d_k)
        scores = scores.masked_fill(mask, float('-inf'))
        attn = torch.softmax(scores, dim=-1)
        out = (attn @ V).transpose(1, 2).reshape(B, n, -1)
        return self.W_o(out)
```

### 10.6 Mixtral MoE 详解

**论文**: Jiang et al. "Mixtral of Experts" (2024)
**arXiv**: 2401.04088
**机构**: Mistral AI

**核心思想**: 8 个专家 FFN, 每个 token 路由到 top-2

**架构**:
```text
输入 x
  ↓
Attention (GQA-8 + SWA)
  ↓
Router (Linear, vocab_size=1, 输出 8 个 expert 权重)
  ↓
Top-2 权重 (softmax 后)
  ↓
Expert 1 (FFN) × w1 + Expert 5 (FFN) × w5
  ↓
输出
```

**Router 公式**:
```text
logits = x @ W_gate   # (B, n, n_experts)
weights = softmax(top_k(logits, k=2))
output = sum_i (weights[i] * Expert_i(x))
```

**参数量分析**:
- Embedding: ~2B
- 每层 Attention: ~250M
- 每层 Expert (SwiGLU): ~600M
- 每层 Router: ~16K
- 总 Expert: 8 × 600M = 4.8B / 层
- 32 层 × 4.8B = 153B ... 算重了, 实际总参数 46.7B

**激活参数量**:
- Top-2 专家: 2 × 600M = 1.2B / 层
- 32 层: 38.4B ... 但实际官方说 12.9B 激活
- 因为 Attention 只激活一次, 加 Embedding 共享

**Mixtral 优势**:
- 训练: 所有专家都被训, 但每次只更新部分
- 推理: 类似 13B 模型速度
- 容量: 类似 47B 模型质量

**Mixtral vs LLaMA-2-70B**:
| Benchmark | Mixtral-8x7B | LLaMA-2-70B |
|---|---|---|
| MMLU | 70.6 | 69.9 |
| HellaSwag | 84.4 | 85.4 |
| GSM8K | 58.4 | 69.6 |
| HumanEval | 40.2 | 32.3 |
| 推理速度 | ~13B | ~70B |

**PyTorch 实现**:
```python
import torch
import torch.nn as nn
import torch.nn.functional as F


class MoERouter(nn.Module):
    """MoE 路由层"""
    def __init__(self, d_model, n_experts=8, top_k=2):
        super().__init__()
        self.gate = nn.Linear(d_model, n_experts, bias=False)
        self.n_experts = n_experts
        self.top_k = top_k

    def forward(self, x):
        # x: (B, n, d)
        logits = self.gate(x)   # (B, n, n_experts)
        top_k_logits, top_k_indices = logits.topk(self.top_k, dim=-1)
        weights = top_k_logits.softmax(dim=-1)
        return weights, top_k_indices   # (B, n, top_k), (B, n, top_k)


class MoEFFN(nn.Module):
    """MoE FFN: 多个 SwiGLU 专家"""
    def __init__(self, d_model, d_ff, n_experts=8, top_k=2):
        super().__init__()
        self.router = MoERouter(d_model, n_experts, top_k)
        self.experts = nn.ModuleList([
            SwiGLU(d_model, d_ff) for _ in range(n_experts)
        ])
        self.n_experts = n_experts
        self.top_k = top_k

    def forward(self, x):
        # x: (B, n, d)
        B, n, d = x.shape
        weights, indices = self.router(x)   # (B, n, top_k), (B, n, top_k)

        # 每个 token 路由到 top_k 个专家
        out = torch.zeros_like(x)
        # 简化: 遍历专家, 对负责该专家的 token 计算
        for expert_id in range(self.n_experts):
            # 找出路由到该专家的 token
            expert_mask = (indices == expert_id).any(dim=-1)   # (B, n)
            if expert_mask.any():
                tokens = x[expert_mask]   # (N, d)
                expert_out = self.experts[expert_id](tokens)
                # 加权
                for k in range(self.top_k):
                    weight_mask = (indices[..., k] == expert_id) & expert_mask
                    if weight_mask.any():
                        out[weight_mask] += weights[..., k][weight_mask].unsqueeze(-1) * expert_out
        return out


class MixtralBlock(nn.Module):
    """Mixtral 一个 Block"""
    def __init__(self, d_model, n_q_heads, n_kv_heads, d_ff, n_experts=8, top_k=2, max_seq_len=32768):
        super().__init__()
        self.attn_norm = RMSNorm(d_model)
        self.attn = MistralAttention(d_model, n_q_heads, n_kv_heads, max_seq_len=max_seq_len)
        self.ffn_norm = RMSNorm(d_model)
        self.moe = MoEFFN(d_model, d_ff, n_experts, top_k)

    def forward(self, x, positions):
        x = x + self.attn(self.attn_norm(x), positions)
        x = x + self.moe(self.ffn_norm(x))
        return x
```

## 11. 注意力机制演化对比

### 11.1 MHA → MQA → GQA → SWA

**MHA (Multi-Head Attention) - 原始 Transformer**
- Q, K, V 头数相同 (n_heads)
- 每个头独立, KV 缓存最大
- 内存: O(B × n × d_k × n_layers × n_heads)

**MQA (Multi-Query Attention) - 2019**
- Q 多头, K/V 单头
- 论文: Shazeer "Fast Transformer Decoding"
- 优点: KV 缓存最小
- 缺点: 质量下降

**GQA (Grouped-Query Attention) - 2023**
- Q 多头, K/V 分组 (4-8 组)
- 论文: Ainslie et al. "GQA: Training Generalized Multi-Query Transformer Models from Multi-Head Checkpoints" (2023)
- 平衡 MHA (质量) 和 MQA (效率)
- LLaMA-2-70B 用 GQA-8, Mistral 用 GQA-8

**SWA (Sliding Window Attention) - Mistral**
- 每个 token 只看 W 个最近 token
- 长序列推理 KV 不爆炸
- W=4096, 32 层 → 有效感受野 131K

**Flash Attention - 训练加速**
- 论文: Dao et al. "FlashAttention: Fast and Memory-Efficient Exact Attention" (NeurIPS 2022)
- IO-aware 算法, 不存中间结果
- 训练速度 2-4x, 显存省 5-20x
- FlashAttention-2 (2023), FlashAttention-3 (2024, H100)

**Paged Attention - 推理加速**
- 论文: Kwon et al. "Efficient Memory Management for Large Language Model Serving with PagedAttention" (SOSP 2023)
- vLLM 用
- KV 缓存分页, 减少碎片
- 吞吐提升 14-24x

### 11.2 KV 缓存对比

```text
设:
  n_layers = 32
  n_heads = 32 (MHA) / 8 (GQA-8)
  d_k = 128
  seq_len = 4096
  batch = 1
  dtype = FP16 (2 bytes)

MHA: 32 × 32 × 128 × 4096 × 2 × 2 = 2.0 GB
GQA-8: 32 × 8 × 128 × 4096 × 2 × 2 = 512 MB  (减 4x)
MQA: 32 × 1 × 128 × 4096 × 2 × 2 = 64 MB
SWA (W=4096, 全部保留): 同 GQA
SWA (W=4096, 滚动): 32 × 8 × 128 × 4096 × 2 × 2 = 512 MB (但只需 1/8 滚动 → 64 MB)
```

| 位置编码 | 代表模型 | 优点 | 缺点 |

| Sinusoidal | 原始 Transformer | 无参数, 任意长 | 长度外推差 |

| ALiBi | BLOOM | 简单, 外推 | 性能一般 |
| RoPE | LLaMA, Mistral, ChatGLM | 相对+外推 | 计算稍复杂 |
| YaRN | Mistral-8x22B | 长上下文 | 需微调 |

**RoPE 原理**:
- 核心: 把位置信息编码为 "旋转"
- 二维: q_m = R(mθ) · q
- 多维: 不同维度对用不同频率 θ
- 性质: q^T_m · k_n = f(m-n, q, k) 仅依赖相对位置

**RoPE 在 LLaMA-1-65B 配置**:
- d_k = 128 (per head)
- base = 10000
- 高频维度 (前 64 维): 短距离敏感
- 低频维度 (后 64 维): 长距离敏感

**长度外推**:
- 训练 4K, 推理 8K: 直接失败
- 解决方案 1: Position Interpolation (PI) - 线性插值位置
- 解决方案 2: NTK-aware Scaling - 调整 base
- 解决方案 3: YaRN - 组合 PI + NTK + 注意力缩放
- 解决方案 4: 继续预训练 - 4K → 128K (LLaMA-3 用)

## 13. 归一化层对比

| 归一化 | 公式 | 代表模型 | 优点 |
|---|---|---|---|
| BatchNorm | (x - μ_B) / σ_B * γ + β | CNN, 早期 Transformer | 训练快 |
| LayerNorm | (x - μ_L) / σ_L * γ + β | GPT, BERT | 不依赖 batch |
| RMSNorm | x / RMS(x) * γ | LLaMA, Mistral | 计算快 ~7-10% |
| DeepNorm | αx + Sublayer(LN(x)) | 大模型 | 训练超深网络 |

**RMSNorm vs LayerNorm**:
- LayerNorm: 需要算 mean 和 variance
- RMSNorm: 只算 RMS (Root Mean Square), 省一个 reduction
- 性能几乎一致, 训练略快
- LLaMA, Mistral, ChatGLM 全部用 RMSNorm

**Pre-LN vs Post-LN**:
- Post-LN: x = LN(x + Sublayer(x)) — 原始 Transformer, BERT, GPT-1/2
- Pre-LN: x = x + Sublayer(LN(x)) — GPT-3, LLaMA, Mistral
- Pre-LN 训练更稳定, 不需要 learning rate warm-up 技巧
- Pre-LN 性能略差, 但训练大规模模型必须用 Pre-LN

## 14. 激活函数对比

| 激活函数 | 公式 | 代表模型 |
|---|---|---|
| ReLU | max(0, x) | 原始 Transformer |
| GELU | x · Φ(x) | BERT, GPT-2 |
| SiLU/Swish | x · sigmoid(x) | LLaMA, Mistral (SwiGLU 内部) |
| GEGLU | GELU(xW₁) ⊙ (xW₂) | 一些变体 |
| SwiGLU | SiLU(xW_gate) ⊙ (xW_up) | LLaMA, Mistral, PaLM |

**SwiGLU 详解**:
```text
FFN_SwiGLU(x) = (SiLU(x @ W_gate) ⊙ (x @ W_up)) @ W_down

3 个矩阵 (vs ReLU/GELU 的 2 个):
  W_gate: (d, d_ff) - 门控
  W_up: (d, d_ff) - 升维
  W_down: (d_ff, d) - 降维

参数增加: ~50%
性能提升: 显著 (尤其大模型)
```

**为什么 SwiGLU 更好?**
1. 门控机制: 允许网络选择性地通过信息
2. 平滑非线性: SiLU 在 0 附近平滑
3. 多项实验证明: PaLM, LLaMA, Mistral 全部采用

## 15. Scaling Laws 与涌现能力

### 15.1 Scaling Laws (规模定律)

**论文**: Kaplan et al. "Scaling Laws for Neural Language Models" (2020)
**arXiv**: 2001.08361

**核心结论**:
- Loss ∝ N^(-α), α ≈ 0.076 (N = 非嵌入参数)
- Loss ∝ D^(-β), β ≈ 0.095 (D = 数据量)
- Loss ∝ C^(-γ), γ ≈ 0.050 (C = 计算量)
- 三个变量可以单独 scale

**Chinchilla 论文** (Hoffmann et al. 2022, DeepMind):
- **修正**: 训练 token 数应与参数量成比例
- 最优: ~20 tokens / parameter
- GPT-3 (175B, 300B tokens): **训练不足**, 应该用更多数据
- 建议: 70B 模型用 1.4T tokens 训

**LLaMA 遵循 Chinchilla**:
- LLaMA-7B 训 1T tokens (vs 建议 140B, 多了 7x)
- LLaMA-65B 训 1.4T tokens (vs 建议 1.3T, 接近最优)

### 15.2 涌现能力 (Emergent Abilities)

**论文**: Wei et al. "Emergent Abilities of Large Language Models" (TMLR 2022)

**涌现能力列表**:
- In-Context Learning (Few-shot)
- Chain-of-Thought (CoT) Reasoning
- Instruction Following
- Code Generation

**关键点**:
- 能力在某个 scale 突然出现
- 不是连续改进, 是阶跃
- 但最近有论文质疑 (Schaeffer et al. "Are Emergent Abilities a Mirage?")

## 18. 面试高频问题

### 18.1 必会问题

**Q1: BERT 和 GPT 的本质区别?**
A: BERT 是 Encoder, 双向, MLM 预训练; GPT 是 Decoder, 单向, 自回归预训练。BERT 适合理解, GPT 适合生成。

**Q2: 为什么 LLM 都用 Decoder-only?**
A: (1) 生成任务统一; (2) 工程简洁; (3) In-context learning 能力强; (4) Scaling law 表现更好。

**Q3: LLaMA 的"四件套"是什么?**
A: RMSNorm + RoPE + SwiGLU + GQA

**Q4: Pre-LN vs Post-LN?**
A: Pre-LN 训练稳定, 大模型必选; Post-LN 性能略好但训练难。

**Q5: GQA 为什么能省 KV 缓存?**
A: 多 Q 头共享 K/V 头, KV 头数减少, 缓存减少 4-8x。

**Q6: SwiGLU 比 ReLU 强多少?**
A: 大模型上 perplexity 提升 5-10%, 但参数量增加 ~50%。

**Q7: MoE 的激活参数量怎么算?**
A: top_k × 专家参数量 + 共享部分 (Embedding, Attention)。

### 18.2 进阶问题

**Q8: RoPE 为什么能做长度外推?**
A: RoPE 把位置编码为相对旋转, attention 内积只依赖相对位置。延长上下文时, 高频维度会失效, 需 PI/YaRN。

**Q9: Mistral 的 SWA 实际感受野多大?**
A: 32 层 × 4096 窗口 = 131K, 但实际单层 SWA 限制单层感受野。

**Q10: Mixtral 路由不均衡怎么办?**
A: (1) Auxiliary loss 平衡; (2) Expert capacity 限制; (3) Router z-loss。

**Q11: LLaMA-3 128K 上下文怎么做?**
A: (1) 4D 并行训练; (2) 渐进式扩 context (4K → 128K); (3) GQA-8; (4) 继续预训练。

**Q12: Flash Attention 为什么快?**
A: IO-aware, 不存中间 attention matrix, 在线 softmax。

**Q13: KV Cache 在推理时占用多少显存?**
A: 见 §11.2 计算公式。

**Q14: 怎么估算训练成本?**
A: FLOPs ≈ 6ND, 美元 ≈ FLOPs / GPU_peak / 3600 × 电费 × GPU 价。

## 23. 模型架构设计模式

### 23.1 Decoder-Only 的统一性

**为什么 Decoder-only 一统天下?**

| 优势 | 解释 |
|---|---|
| **任务统一** | 所有任务都可以表述为"生成下一个 token" |
| **训练简洁** | 自回归 LM 目标唯一 |
| **推理灵活** | 无需 prompt 完整, 可任意长度 |
| **Scale 友好** | Loss 随规模平滑下降 |
| **ICL 涌现** | In-context learning 涌现能力强 |
| **工程统一** | 单一架构, 工程实现统一 |

**Decoder-only 适合什么任务?**
- 文本生成 (对话, 创作, 摘要, 翻译)
- 分类 (改写为生成)
- 信息抽取 (改写为生成)
- 代码生成 (CodeLlama, DeepSeek-Coder)
- 推理 (CoT)
- 多模态 (LLaVA, Qwen-VL)

**Decoder-only 不适合?**
- 高并发短文本分类 (BERT 蒸馏模型更快)
- 实时语音识别 (CTC 更合适)
- 序列标注 (NER, POS) — 可生成但效率低

### 23.2 Attention 模式演化

```text
MHA (原始):
  Q: 32 头, K: 32 头, V: 32 头
  O(n_q × n_kv) = 32×32 = 1024 个 pair
  质量: 高, 缓存: 大

MQA (2019):
  Q: 32 头, K: 1 头, V: 1 头
  O(n_q × 1) = 32
  质量: 中, 缓存: 小
  用法: PaLM, Falcon

GQA (2023):
  Q: 32 头, K: g 头, V: g 头
  O(n_q × g) = 32×8 = 256 (g=8)
  质量: 中高, 缓存: 中
  用法: LLaMA-2-70B, Mistral, Qwen

MLA (2024, DeepSeek):
  Q: 多头, K/V: 低秩压缩
  O(...)
  质量: 高, 缓存: 极小
  用法: DeepSeek-V2/V3
```

### 23.3 FFN 设计模式

```text
标准 FFN (ReLU):
  x → Linear(d, 4d) → ReLU → Linear(4d, d)
  参数: 8d²

GELU FFN:
  x → Linear(d, 4d) → GELU → Linear(4d, d)
  参数: 8d²

SwiGLU FFN (LLaMA):
  x → Linear(d, d_ff) ⊙ SiLU(Linear(d, d_ff))
  然后 Linear(d_ff, d)
  d_ff = 8d/3 ≈ 2.67d
  参数: 3 × d × d_ff ≈ 8d²
  注: 3 个矩阵 vs 2 个, 但 d_ff 较小

GeLU GLU:
  x → Linear(d, d_ff) ⊙ GELU(Linear(d, d_ff))
  然后 Linear(d_ff, d)

Expert FFN (MoE):
  N 个 SwiGLU 专家
  Top-K 路由
  参数: N × 8d²
  激活: K × 8d²
```

## 24. 常见误区澄清

### 24.1 误区 1: "BERT 已经被淘汰了"

**真相**: BERT 在特定任务上仍优于 LLM
- 短文本分类: BERT 微调 vs LLM prompt
- 抽取式 QA: BERT 比 LLM 更快更准
- 实时低延迟场景: TinyBERT 是首选
- **结论**: BERT 没死, 但 LLM 是通用趋势

### 24.2 误区 2: "模型越大越好"

**真相**: Chinchilla 定律
- 模型大小 vs 数据量要平衡
- 7B + 大量数据 > 70B + 少量数据
- 应用上, 小模型 + 微调可能更好

### 24.3 误区 3: "MoE 一定比 Dense 好"

**真相**: MoE 的优势取决于场景
- 优势: 训练时容量大, 推理时激活少
- 劣势: 工程复杂, 专家负载不均衡, 通信开销
- **结论**: MoE 适合大规模训练, 小模型没必要

### 24.4 误区 4: "GQA 总是比 MHA 好"

**真相**: GQA 主要是推理优化
- 训练时 GQA 质量略低于 MHA
- 推理时 GQA 省 KV 缓存
- **结论**: 大模型推理选 GQA, 小模型可选 MHA

### 24.5 误区 5: "RLHF 是训练 LLM 的必需步骤"

**真相**: RLHF 主要用于对齐人类偏好
- SFT 即可让 LLM 学会指令
- RLHF 让 LLM 更"有用, 无害, 诚实"
- 不做 RLHF, 模型也可能很强 (DeepSeek R1 用 RL 而非 RLHF)

## 29. 训练 Recipe 详解

### 29.1 训练目标函数

**CLM (Causal Language Modeling) - GPT/LLaMA 用**:
```text
L = -1/N × Σ_n Σ_t log P(x_t | x_<t)
N = token 总数
```

**MLM (Masked LM) - BERT 用**:
```text
L = -1/M × Σ_m log P(x_m | x_\m)
M = 被掩盖的 token 数
```

**Prefix LM - UniLM 用**:
```text
前缀部分: 双向 (encoder-like)
后缀部分: 单向 (decoder-like)
```

**Span Corruption - T5 用**:
```text
原句: The doggy is cute
改写: The <X> is <Y>.
目标: <X> = doggy, <Y> = cute
```

**ELECTRA - Replaced Token Detection**:
```text
L = L_disc + λ × L_gen
  L_disc: 判断每个 token 是否被替换
  L_gen: 生成器尝试填补原 token
```

### 29.2 训练超参数

| 超参 | LLaMA-7B | LLaMA-65B | Mistral-7B |
|---|---|---|---|
| Optimizer | AdamW | AdamW | AdamW |
| β1, β2 | 0.9, 0.95 | 0.9, 0.95 | 0.9, 0.95 |
| ε | 1e-8 | 1e-8 | 1e-8 |
| Peak LR | 3e-4 | 1.5e-4 | 1e-4 |
| Min LR | 3e-5 | 1.5e-5 | 1e-5 |
| LR Schedule | Cosine | Cosine | Cosine |
| Warmup | 2000 step | 1000 step | 1000 step |
| Weight Decay | 0.1 | 0.1 | 0.1 |
| Batch Size | 4M tokens | 4M tokens | 4M tokens |
| Sequence Length | 2048 | 2048 | 8192 |
| Precision | BF16 | BF16 | BF16 |
| Gradient Clip | 1.0 | 1.0 | 1.0 |
| Dropout | 0.0 | 0.0 | 0.0 |
| z-loss | 1e-4 | 1e-4 | (未公开) |
| Steps | 1T tokens | 1.4T tokens | 8T tokens |

### 29.3 学习率调度

**Cosine Schedule (LLaMA, Mistral)**:
```text
LR(t) = LR_min + 0.5 × (LR_max - LR_min) × (1 + cos(π × t / T))
  t: 当前 step
  T: 总 step
```

**Warmup**:
```text
LR(t) = LR_max × t / W   (t ≤ W)
W = 1000-2000 step
```

**为什么需要 Warmup?**
- 初期梯度不稳定
- Adam 二阶矩估计初期偏差大
- 大模型尤其需要

### 29.4 训练稳定性技巧

**1. Gradient Clipping**:
```text
g_norm = ||∇L||
if g_norm > clip:  g = g × clip / g_norm
clip = 1.0 (LLaMA)
```

**2. Z-loss**:
```text
L_z = log²(Z)
Z = exp(logits).sum()   # log-sum-exp
防止 logits 过大, 训练稳定
```

**3. Precision**:
- BF16 (Brain Float 16): 1 sign + 8 exp + 7 mantissa
- 比 FP16 范围大, 不易溢出
- LLaMA, Mistral, GPT-3 都用 BF16

**4. Tensor Parallel (TP)**:
- 把单个 matmul 切到多卡
- LLaMA-65B 用 8-way TP

**5. Pipeline Parallel (PP)**:
- 把不同层放到不同卡
- LLaMA-65B 用 pipeline (具体 stage 数未公开)

**6. Data Parallel (DP / FSDP)**:
- 把数据切分到多卡
- FSDP 把模型+优化器+梯度分片
- 4D 并行: TP + CP + PP + DP (LLaMA-3)

**7. ZeRO (Zero Redundancy Optimizer)**:
- Stage 1: 优化器状态分片
- Stage 2: + 梯度分片
- Stage 3: + 参数分片
- FSDP ≈ ZeRO-3

## 30. 推理优化

### 30.1 KV Cache 详解

**为什么需要 KV Cache?**
```text
无 KV Cache (重新计算):
  生成 100 个 token, 每个 token 都要重算 100 个
  总: 100 × 100 × 计算量 = 10000x

有 KV Cache:
  第 1 个 token: 计算 1 个
  第 2 个 token: 计算 2 个 (1 缓存 + 1 新)
  ...
  第 100 个 token: 计算 100 个 (99 缓存 + 1 新)
  总: 1 + 2 + ... + 100 = 5050x

加速: 2x
```

**KV Cache 占用显存估算**:
```text
KV Cache 显存 (bytes) = 2 × B × n_layers × n_kv_heads × n × d_k × sizeof(dtype)
  2: K + V
  B: batch size
  n_layers: 32
  n_kv_heads: 8 (GQA-8)
  n: 序列长度
  d_k: 128
  sizeof: 2 (FP16) / 1 (INT8) / 0.5 (INT4)

LLaMA-2-70B (GQA-8), B=1, n=4096, FP16:
  2 × 1 × 80 × 8 × 4096 × 128 × 2 = 1.3 GB

LLaMA-2-70B (若 MHA), B=1, n=4096, FP16:
  2 × 1 × 80 × 64 × 4096 × 128 × 2 = 10.7 GB
```

### 30.2 PagedAttention (vLLM)

**核心思想**: 把 KV 缓存分页, 减少碎片

**传统 KV Cache**:
```text
预分配连续显存: [token_1, token_2, ..., token_n]
问题: 序列长度变化, 显存浪费
```

**PagedAttention**:
```text
每个 token 的 KV 存到固定大小 page (类似 OS 虚拟内存)
非连续存储, 但逻辑连续
→ 显存利用率从 30% → 90%+
→ 吞吐量提升 14-24x
```

### 30.3 Speculative Decoding

**核心思想**: 小模型草拟, 大模型验证

```text
小模型 (Draft Model, e.g. 7B) 生成 K 个候选
大模型 (Target Model, e.g. 70B) 一次性验证
接受前缀, 拒绝部分

加速: 2-3x (单 batch)
不改变输出分布 (数学上严格)
```

### 30.4 量化

**GPTQ** (Frantar et al. 2022):
- Post-training quantization
- 4-bit / 3-bit / 2-bit
- LLaMA-2-70B 4-bit 可在单卡 A100 (80G) 推理

**AWQ** (Lin et al. 2023):
- Activation-aware Weight Quantization
- 保护重要权重 (激活值大的)
- 比 GPTQ 更快, 质量更好

**GGUF / llama.cpp**:
- CPU/GPU 混合推理
- 支持多种量化 (Q2_K, Q4_K_M, Q5_K_M, Q6_K, Q8_0)
- 适合本地部署

**KV Cache 量化**:
- FP16 → INT8 → INT4 → INT2
- 节省 2x / 4x / 8x KV 缓存
- 长上下文推理关键

### 30.5 Continuous Batching

**传统 Static Batching**:
```text
batch: [seq1_len=100, seq2_len=50, seq3_len=200]
完成时间: 200 (等所有序列完成)
GPU 利用率: 不均
```

**Continuous Batching** (vLLM, TGI):
```text
任意时刻, 把完成序列移除, 加入新序列
GPU 利用率: 一直高
吞吐量: 提升 10-30x
```

**3. 数学形式化(简洁版)**

虽然我们强调优化视角视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

**7. 实践建议**

结合 "BERT / GPT / LLaMA / Mistral 经典架构" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "BERT / GPT / LLaMA / Mistral 经典架构" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。
