# 04.04 贪心算法

> **本节定位**: 面试+竞赛的高频思想
> **对应 04 章 Day 10-12**
> **核心**: 局部最优 = 全局最优 (证明是难点)

---

## 1. 贪心是什么

**贪心**: 在每一步选择当前看起来最好的选项, 期望得到全局最优解.

**特点**:
- 不回溯
- 简单高效
- 但**不一定总能得到最优解** - 需要证明

**适用场景**:
- 问题具有"贪心选择性质" (局部最优能推出全局最优)
- 问题具有"最优子结构" (子问题的最优解能组成大问题的最优解)

### 1.1 贪心算法的本质

贪心 = "每一步做局部最优选择, 永不反悔, 期望全局最优". 它是最容易被想到, 也最容易被误用的算法范式.

直觉上, 如果你"能做对就做对", 自然应该是最优的. 但事实上: **局部最优 ≠ 全局最优** 是经典陷阱. 证明贪心的有效性是面试中的"加分项", 也是竞赛中的"决胜点".

### 1.2 贪心成立的"两个数学条件"

1. **贪心选择性质**: 通过局部最优选择, 可以达到全局最优. 也就是说, 存在一个最优解, 它包含每一步的贪心选择.
2. **最优子结构**: 一个问题的最优解包含其子问题的最优解.

这两个性质相互独立, 但常常同时成立. 例如: 最短路径 (Dijkstra), 区间调度, 最小生成树 (Kruskal) 都满足.

### 1.3 贪心的典型步骤

```text
1. 排序 / 建堆 (让选择有序)
2. 维护一个"当前最优"的状态
3. 遍历时做"局部选择", 更新状态
4. 累计代价 / 收集结果
```

### 1.4 贪心的复杂度优势

| 范式 | 时间复杂度 (典型) | 空间复杂度 |
|---|---|---|
| 贪心 | $O(n)$ / $O(n \log n)$ | $O(1)$ / $O(n)$ |
| DP | $O(n^2)$ / $O(n \cdot m)$ | $O(n)$ / $O(n \cdot m)$ |
| 回溯 | $O(2^n)$ / $O(n!)$ | $O(n)$ |

贪心通常比 DP 快一个数量级, 因为它"一次性"扫过去.

## 2. 贪心的证明方法

### 2.1 交换论证法 (最常用)

**思路**: 假设最优解和贪心解不同, 交换两者的某些步骤, 看是否能得到更好的解 (如果不能, 说明贪心正确).

**标准模板**:

1. 设贪心解为 G, 任取一个最优解 O.
2. 找到 G 与 O 的第一个不同选择.
3. **证明**: 把 O 在这一位的选择换成 G 的选择, 解不会变差.
4. 由归纳, G 不比 O 差, 所以 G 也是最优解.

**例子**: 区间调度 (无重叠区间):

> 设 G 是按 end 排序依次选的区间. 任取最优解 O.
> 设 G[i] ≠ O[i] 是第一个不一样的, 即 O[i] 的 end 比 G[i] 大 (因 G 选的是 end 最小的).
> 把 O[i] 换成 G[i], 由于 G[i] 的 end 更小, 不会让后面的 O[j] 无法加入 (因为 O[j] 与 O[i] 不重叠的约束是 O[i].start ≥ 上一个 end; 而 G[i] 的 end 更小, 后续能容纳更多区间, 不会变差).
> 故替换后解不退化. 反复执行直到 G = O', 此时 G = O, G 是最优解.

### 2.2 反证法

**思路**: 假设贪心不是最优, 推出矛盾.

**例子**: 跳跃游戏:

> 假设贪心在某点 i 之前都正确, 但在 i 处得到错误.
> 设 max_reach 是当前的"最远能到达", 而真正的最优应该能到 max_reach' > max_reach.
> 但 max_reach 是从所有 0..i 中"位置 + 跳数"取 max, 如果 max_reach' > max_reach, 那么必然存在某个 j ≤ i 使得 j + nums[j] ≥ max_reach', 矛盾. 故贪心正确.

### 2.3 数学归纳

**思路**: 证明前 k 步贪心都正确, 由 k → k+1.

**例子**: Kruskal 最小生成树: 每一步选择"当前最小的、安全的边", 由归纳可证最终是最小生成树.

### 2.4 数学归纳 vs 交换论证

| 方法 | 适用场景 | 难度 |
|---|---|---|
| 交换论证 | 步骤间有"顺序性" | 中等 |
| 反证 | 假设否定后推出矛盾 | 中等 |
| 数学归纳 | 步骤可递推 | 较难 |

业界更常用交换论证, 因为它最贴近"代码步骤".

### 2.5 贪心的反例构造

发现贪心错误时, 用**反例**证明:

```python
# 例: 错误贪心: 选最大面值找零
coins = [1, 3, 4]
amount = 6
# 贪心: 4 + 1 + 1 = 3 枚
# 最优: 3 + 3 = 2 枚
# 反例: 显然贪心失败
```

## 3. 区间调度类问题

### 3.1 LeetCode 435 - 无重叠区间 (Medium)

**题目**: 给定多个区间, 找最少移除几个区间使剩余无重叠.

**贪心**: 按 **end 升序** 排序, 每次选 end 最早的. 这样能给后面留最多空间.

```python
def eraseOverlapIntervals(intervals):
    if not intervals: return 0
    intervals.sort(key=lambda x: x[1])  # 按 end 排序

    count = 1  # 至少 1 个区间
    end = intervals[0][1]
    for i in range(1, len(intervals)):
        if intervals[i][0] >= end:
            count += 1
            end = intervals[i][1]
    return len(intervals) - count
```

**复杂度**: $O(n \log n)$ 排序 + $O(n)$ 扫描.

**证明** (交换论证):

设 G 是贪心解 (按 end 升序选), O 是最优解. 假设两者不同, 设第一个不同的区间是 i. 因 G 选 end 最小, O[i].end ≥ G[i].end. 把 O[i] 换成 G[i], 由于 G[i].end 更小, O[i+1..] 的合法性不受影响 (反而更容易放进去). 故替换不劣化. 反复替换后 G = O', G 是最优.

### 3.2 LeetCode 452 - 用最少数量的箭引爆气球 (Medium)

**题目**: 气球用区间表示, 一支箭能射穿同一垂直线上所有重叠的气球. 求最少箭数.

**贪心**: 按 end 排序, 同一组重叠的气球用一支箭.

```python
def findMinArrowShots(points):
    if not points: return 0
    points.sort(key=lambda x: x[1])

    arrows = 1
    end = points[0][1]
    for i in range(1, len(points)):
        if points[i][0] > end:  # 严格大于 (不重叠)
            arrows += 1
            end = points[i][1]
    return arrows
```

**复杂度**: $O(n \log n)$.

**与 435 题的区别**: 435 是 "≥ end" 才不重叠 (允许端点接触), 452 是 "> end" 才需要新箭 (不允许端点接触). 注意题目细节!

### 3.3 LeetCode 56 - 合并区间 (Medium)

详见 [06.04 - 高频题 38-50](../第06章-面试篇上-高频题1-50/第06章-04-高频题38-50.md)

```python
def merge(intervals):
    intervals.sort(key=lambda x: x[0])
    merged = []
    for cur in intervals:
        if not merged or merged[-1][1] < cur[0]:
            merged.append(cur)
        else:
            merged[-1][1] = max(merged[-1][1], cur[1])
    return merged
```

### 3.4 LeetCode 253 - 会议室 II (Medium)

**题目**: 给定会议时间区间, 求最少需要的会议室数.

**贪心**: 按 start 排序 + 用最小堆维护当前进行中的会议的 end.

```python
import heapq
def minMeetingRooms(intervals):
    if not intervals: return 0
    intervals.sort(key=lambda x: x[0])
    heap = []  # 维护结束时间
    for s, e in intervals:
        if heap and heap[0] <= s:
            heapq.heappop(heap)  # 该会议室可复用
        heapq.heappush(heap, e)
    return len(heap)
```

**复杂度**: $O(n \log n)$.

### 3.5 LeetCode 763 - 划分字母区间 (Medium)

**题目**: 把字符串划分成多个片段, 每种字符只出现在一个片段里.

**贪心**: 先遍历一遍, 记录每个字符最后出现的位置. 然后从前向后扫描, 当前片段的 right = max(字符的 end).

```python
def partitionLabels(s):
    last = {c: i for i, c in enumerate(s)}
    res = []
    start = end = 0
    for i, c in enumerate(s):
        end = max(end, last[c])
        if i == end:
            res.append(end - start + 1)
            start = i + 1
    return res
```

### 3.6 LeetCode 1029 - 两地调度 (Easy)

**题目**: 2N 个人, 各去 A 或 B, 每人去 A 或 B 的成本不同, 求总成本最低.

**贪心**: 排序 "去 A - 去 B" 的差值, 取前 N 个去 A, 后 N 个去 B.

```python
def twoCitySchedCost(costs):
    # costs[i] = [cost_A, cost_B]
    # 排序依据: 选 A 比选 B 多的"成本差"
    costs.sort(key=lambda x: x[0] - x[1])
    n = len(costs) // 2
    return sum(c[0] for c in costs[:n]) + sum(c[1] for c in costs[n:])
```

### 3.7 区间调度变种: LeetCode 986 - 区间列表的交集 (Medium)

```python
def intervalIntersection(A, B):
    i = j = 0
    res = []
    while i < len(A) and j < len(B):
        lo = max(A[i][0], B[j][0])
        hi = min(A[i][1], B[j][1])
        if lo <= hi:
            res.append([lo, hi])
        if A[i][1] < B[j][1]:
            i += 1
        else:
            j += 1
    return res
```

### 3.8 区间调度的统一框架

```python
def interval_problem(intervals, key=lambda x: x[1], overlap="non_overlap"):
    """通用框架: 按 key 排序, 扫描时根据 overlap 决定是否选."""
    intervals.sort(key=key)
    selected = []
    end = -float('inf')
    for itv in intervals:
        if overlap == "non_overlap" and itv[0] >= end:
            selected.append(itv)
            end = itv[1]
        elif overlap == "contain" and itv[0] > end:
            selected.append(itv)
            end = itv[1]
    return selected
```

## 4. 跳跃游戏

### 4.1 LeetCode 55 - 跳跃游戏 (Medium)

**题目**: 给非负整数数组, 初始在 index 0, nums[i] 表示可跳的最大长度. 判断能否到达最后.

**贪心**: 维护当前能到达的最远位置.

```python
def canJump(nums):
    max_reach = 0
    for i, x in enumerate(nums):
        if i > max_reach:  # 到不了 i
            return False
        max_reach = max(max_reach, i + x)
    return True
```

**复杂度**: $O(n)$ 时间, $O(1)$ 空间.

### 4.2 LeetCode 45 - 跳跃游戏 II (Medium)

**题目**: 返回最后一个位置所需的最少跳跃次数.

**贪心**: 在当前能到达的范围内, 选下一跳能到达最远的位置.

```python
def jump(nums):
    n = len(nums)
    if n <= 1: return 0

    jumps = 0
    current_end = 0  # 当前跳跃能到的最远
    farthest = 0     # 下一跳能到的最远

    for i in range(n - 1):
        farthest = max(farthest, i + nums[i])
        if i == current_end:  # 到了当前跳跃的边界
            jumps += 1
            current_end = farthest

    return jumps
```

**复杂度**: $O(n)$.

**证明**: 每次跳跃边界 end 是"当前跳跃能到的最远", 在区间内选 farthest 最大的位置做下一跳, 这样下一跳能到的最远 >= 任何其他选择. 由归纳可得最少跳跃次数.

### 4.3 LeetCode 1306 - 跳跃游戏 III (Medium)

**题目**: 在数组上, 从 start 出发, 可以从 i 跳到 i+arr[i] 或 i-arr[i], 能否到达值为 0 的位置.

**思路**: BFS / DFS.

```python
def canReach(arr, start):
    n = len(arr)
    visited = {start}
    q = [start]
    while q:
        i = q.pop()
        if arr[i] == 0:
            return True
        for j in (i + arr[i], i - arr[i]):
            if 0 <= j < n and j not in visited:
                visited.add(j)
                q.append(j)
    return False
```

### 4.4 LeetCode 1345 - 跳跃游戏 IV (Hard)

**题目**: 数组 arr, 从 0 出发, 可向左、向右、跳到同值位置, 求最少步数到末尾.

**思路**: BFS + 同值位置剪枝.

```python
from collections import defaultdict, deque
def minJumps(arr):
    n = len(arr)
    if n <= 1: return 0
    pos = defaultdict(list)
    for i, x in enumerate(arr):
        pos[x].append(i)
    visited = [False] * n
    visited[0] = True
    q = deque([(0, 0)])
    while q:
        i, steps = q.popleft()
        if i == n - 1: return steps
        for j in [i - 1, i + 1] + pos[arr[i]]:
            if 0 <= j < n and not visited[j]:
                visited[j] = True
                q.append((j, steps + 1))
        pos[arr[i]] = []  # 用过一次即可删, 防止重复访问同值
    return -1
```

### 4.5 跳跃游戏的统一视角

跳跃游戏本质上是"维护可达集合"的问题:

- 55: 维护 max_reach, 检查能否到达末尾.
- 45: 在当前可达区间内贪心, 算最少跳跃次数.
- 1306: 在图上 BFS, 求能否到达 0.
- 1345: 同值跳跃 - 用 BFS + 桶优化.

## 5. 其他经典贪心

### 5.1 LeetCode 134 - 加油站 (Medium)

**题目**: N 个加油站组成环形, 求从哪个出发能绕一圈.

**贪心**:
- 如果总油量 < 总消耗, 无解
- 否则一定有解. 从某个起点开始, 当油不够时, 跳到下一个起点.

```python
def canCompleteCircuit(gas, cost):
    if sum(gas) < sum(cost):
        return -1

    start = 0
    tank = 0
    for i in range(len(gas)):
        tank += gas[i] - cost[i]
        if tank < 0:
            start = i + 1  # 从下一个站开始
            tank = 0
    return start
```

**复杂度**: $O(n)$.

**证明**:

- 若 `sum(gas) < sum(cost)`, 显然无解.
- 若 `sum(gas) >= sum(cost)`, 设 G 是贪心找到的起点. 假设存在另一个 O 不在 G, 那么 G 失败时, [start, i] 全部尝试过, 总油 < 总消耗. 但 O 通过某段, 必须从 start 之前的某站开始 (因为 G 失败后跳到了 i+1). 由环形结构, O 等价于某段 [G_start, O_start] 的镜像, 这部分的总油耗刚好等于总油 (因为总 oil ≥ 总 cost). 矛盾.

### 5.2 LeetCode 135 - 分发糖果 (Hard)

**题目**: N 个孩子评分, 每个孩子至少 1 个糖果. 评分高的孩子比邻居多. 求最少糖果.

**两次贪心**: 从左到右一次 + 从右到左一次.

```python
def candy(ratings):
    n = len(ratings)
    candies = [1] * n

    # 从左到右: 右比左大, 右比左多
    for i in range(1, n):
        if ratings[i] > ratings[i-1]:
            candies[i] = candies[i-1] + 1

    # 从右到左: 左比右大, 左比右多
    for i in range(n - 2, -1, -1):
        if ratings[i] > ratings[i+1]:
            candies[i] = max(candies[i], candies[i+1] + 1)

    return sum(candies)
```

**证明**: 单次扫描只能满足"一边"的约束. 从左到右保证右比左大时右多, 从右到左保证左比右大时左多. 两次合并取 max 满足两边.

### 5.4 LeetCode 406 - 根据身高重建队列 (Medium)

**题目**: 数组 ``h, k``, h 是身高, k 是"前面身高 ≥ h 的人数". 重建队列.

**贪心**: 按身高降序 + k 升序, 依次插入第 k 个位置.

```python
def reconstructQueue(people):
    people.sort(key=lambda x: (-x[0], x[1]))
    res = []
    for h, k in people:
        res.insert(k, [h, k])
    return res
```

**证明**: 高个子先入队, 矮个子后插入. 先插高的不会影响矮的人前面的高度.

### 5.5 LeetCode 621 - 任务调度器 (Medium)

**题目**: 任务 A..Z, 相同任务间至少间隔 n. 求最短总时间.

**贪心**: 找出最大频率的任务数, 安排间隔.

```python
def leastInterval(tasks, n):
    from collections import Counter
    cnt = Counter(tasks)
    max_cnt = max(cnt.values())
    num_max = sum(1 for v in cnt.values() if v == max_cnt)
    # 间隔数 = (max_cnt - 1) * (n + 1) + num_max
    return max(len(tasks), (max_cnt - 1) * (n + 1) + num_max)
```

### 5.6 LeetCode 455 - 分发饼干 (Easy)

**题目**: 每个孩子有胃口 g[i], 每块饼干大小 s[j]. 一个孩子最多一块, 求最多满足孩子数.

**贪心**: 排序, 小饼干给小胃口.

```python
def findContentChildren(g, s):
    g.sort()
    s.sort()
    i = j = 0
    while i < len(g) and j < len(s):
        if s[j] >= g[i]:
            i += 1
        j += 1
    return i
```

### 5.7 LeetCode 860 - 柠檬水找零 (Easy)

**题目**: 5/10/20 元付款, 维护找零. 问能否成功.

**贪心**: 优先用 10 元找零, 再用 5 元.

```python
def lemonadeChange(bills):
    five = ten = 0
    for b in bills:
        if b == 5:
            five += 1
        elif b == 10:
            if five == 0: return False
            five -= 1
            ten += 1
        elif b == 20:
            if ten > 0 and five > 0:
                ten -= 1; five -= 1
            elif five >= 3:
                five -= 3
            else:
                return False
    return True
```

### 5.8 LeetCode 941 - 有效的山脉数组 (Easy)

**题目**: 数组先升后降, 且严格.

**贪心**: 单次扫描, 找峰.

```python
def validMountainArray(arr):
    n = len(arr)
    i = 0
    # 上升
    while i < n - 1 and arr[i] < arr[i + 1]:
        i += 1
    if i == 0 or i == n - 1:
        return False
    # 下降
    while i < n - 1 and arr[i] > arr[i + 1]:
        i += 1
    return i == n - 1
```

### 5.9 LeetCode 1005 - K 次取反后最大化的数组和 (Easy)

**题目**: 数组, K 次取反操作 (一次取反一个数), 求最大和.

**贪心**: 优先取反小的负数; 剩余偶数次则不动; 奇数次则取反最小绝对值.

```python
def largestSumAfterKNegations(nums, k):
    nums.sort()
    i = 0
    while i < len(nums) and nums[i] < 0 and k > 0:
        nums[i] = -nums[i]
        i += 1
        k -= 1
    if k % 2 == 1:
        nums.sort()
        nums[0] = -nums[0]
    return sum(nums)
```

### 5.10 LeetCode 871 - 最低加油次数 (Hard)

**题目**: 起点到终点 target, 油箱容量无限, 路上若干加油站. 求最少加油次数.

**贪心**: 优先用最大油量 (最大堆), 不够时加油.

```python
def minRefuelStops(target, startFuel, stations):
    import heapq
    if startFuel >= target: return 0
    stations.append((target, 0))  # 终点视为"加油站"
    fuel = startFuel
    stops = 0
    prev = 0
    pq = []  # max heap (用负数)
    for pos, cap in stations:
        fuel -= (pos - prev)
        while fuel < 0 and pq:
            fuel += -heapq.heappop(pq)
            stops += 1
        if fuel < 0:
            return -1
        heapq.heappush(pq, -cap)
        prev = pos
    return stops
```

### 5.12 LeetCode 765 - 情侣牵手 (Hard)

**题目**: 2N 个人坐 2N 个位置, 每对情侣一对 (2N, 2N+1). 每次交换任意两个人, 求最少交换次数让情侣相邻.

**贪心 + 并查集**: 把每对情侣看作一个图节点, 把座位上相邻的人连线, 连通分量大小 c, 需要 c-1 次交换.

```python
def minSwapsCouples(row):
    n = len(row) // 2
    parent = list(range(n))
    def find(x):
        while parent[x] != x:
            parent[x] = parent[parent[x]]
            x = parent[x]
        return x
    def union(a, b):
        ra, rb = find(a), find(b)
        parent[ra] = rb
    for i in range(0, len(row), 2):
        a, b = row[i] // 2, row[i + 1] // 2
        union(a, b)
    return n - len({find(i) for i in range(n)})
```

```python
def movesToStamp(stamp, target):
    n = len(target)
    m = len(stamp)
    done = [False] * n
    res = []
    visited = set()
    while True:
        changed = False
        for i in range(n - m + 1):
            if i in visited: continue
            j = 0
            while j < m and (target[i + j] == stamp[j] or not done[i + j]):
                j += 1
            if j == m:
                # i 是有效印章
                for k in range(m):
                    target[i + k] = '?'
                visited.add(i)
                res.append(i)
                changed = True
        if not changed: break
    return res[::-1] if all(done) else []
```

```python
        diff[b + 1] -= 1
```

## 6. 贪心 vs DP

| 维度 | 贪心 | DP |
|---|---|---|
| 状态 | 不存历史 | 存所有子问题 |
| 时间 | 通常 $O(n)$ 或 $O(n \log n)$ | $O(n^k)$ |
| 证明 | 难 (要证明局部最优 = 全局最优) | 不需要证明 |
| 适用 | 满足贪心选择性质 | 满足最优子结构 + 重叠子问题 |

**决策**: 先想贪心, 贪心不行再 DP.

### 6.1 何时用贪心?

| 信号 | 暗示贪心可行 |
|---|---|
| 题目要求"最小/最大代价" | 可能是贪心 |
| 答案与"排序后顺序选择"有关 | 排序后贪心 |
| 状态是"当前最大值/最小值" | 维护局部最优 |
| 题目说"最优子结构" | 贪心或 DP 都可 |
| "每一步做当前看起来最好的" | 贪心 |

### 6.2 何时用 DP?

| 信号 | 暗示 DP 必要 |
|---|---|
| 需要存历史状态 | DP |
| 多选择互相影响未来 | DP |
| "最小路径和"类多阶段决策 | DP |
| 有"重叠子问题" | DP |
| 答案不是单调的 | DP |

### 6.3 决策流程图

```text
问题: 求最优解
├── 能直接排序 + 一次扫描解决? → 贪心
├── 有"反证 / 交换论证" 自然思路? → 贪心
├── 需要"状态转移"? → DP
├── 能用 DP 但复杂度过高? → 看是否能贪心
└── 大规模 / 多种状态? → DP
```

## 11. 贪心思想的深度剖析

### 11.1 贪心与单调性的关系

贪心通常依赖"单调性":

- 单调递增: 后续不会破坏前面.
- 单调递减: 前面决策不影响后面.

不单调的问题, 贪心常常失效, 需用 DP.

### 11.2 贪心与排序

排序是贪心的"前置工具":

1. **排序后顺序处理**: 区间调度, 跳跃游戏, 任务调度.
2. **排序后分治**: 中位数.
3. **排序后建堆**: 流量分配.

### 11.3 贪心与堆

堆用于"动态最优":

| 题型 | 堆用法 |
|---|---|
| 加油站 | 当前剩余油量 |

## 12. 实战证明技巧

### 12.1 怎样"找到"贪心的正确方向?

1. **多举小例子**: 手动模拟 n=3, n=4.
2. **看反例**: 试图构造一个失败的反例, 失败往往揭示正确方向.
3. **看极端**: 假设只有一个元素, 应该选什么? 然后扩展到多个.
4. **降维**: 排序后问题简化 (因为排序打破了"无序"维度).
5. **从大到小 / 从小到大**: 排序方向往往是关键.

### 12.2 写出"严格"的证明

数学证明常见 5 步:

1. **陈述**: 设 G 是贪心解, O 是任意最优解.
2. **找不同**: 设第一个不同选择是 i.
3. **替换**: 把 O 的 i 替换为 G 的 i.
4. **不劣化**: 证明替换后仍是最优解 (因为 G 的选择更"紧").
5. **归纳**: 直到 G = O', 所以 G 是最优.

### 12.3 常见错误

1. **未排序直接贪心**: 顺序敏感问题, 必须排序.
2. **贪心方向错误**: end 排序 vs start 排序.
3. **状态丢失**: 用错变量名, 导致状态丢失.
4. **整数溢出**: sum 可能很大.

### 17.1 LeetCode 1488 - 避免洪水泛滥 (Medium)

**题目**: 给若干天降雨数据, 一些天不下雨可以抽干一个湖, 避免同一湖两次洪水.

**思路**: 维护当前不下雨的天, 遇到下雨就用最早的"不下雨"天去抽.

```python
def avoidFlood(rains):
    from sortedcontainers import SortedList
    full = {}  # lake -> 蓄水日
    dry = SortedList()  # 不下雨日
    res = [1] * len(rains)
    for i, lake in enumerate(rains):
        if lake == 0:
            dry.add(i)
            res[i] = 1  # 占位, 后面会改
        else:
            if lake in full:
                # 需要找之前的 dry 日
                idx = dry.bisect_right(full[lake])
                if idx >= len(dry):
                    return []
                d = dry.pop(idx)
                res[d] = lake
            full[lake] = i
            res[i] = -1
    return res
```

### 17.6 LeetCode 1606 - 找到处理最多请求的服务器 (Hard)

**题目**: 服务器处理请求, 给定 arrival 和 load 数组, k 个服务器可用, 求最忙服务器的编号.

**思路**: 双优先队列 (空闲 + 繁忙).

```python
def busiestServer(k, arrival, load):
    import heapq
    free = list(range(k))
    heapq.heapify(free)
    busy = []  # (end_time, server_id)
    cnt = [0] * k
    for i in range(len(arrival)):
        t = arrival[i]
        # 释放忙碌的
        while busy and busy[0][0] <= t:
            _, sid = heapq.heappop(busy)
            heapq.heappush(free, sid)
        if not free:
            continue
        # 取一个 server
        sid = heapq.heappop(free)
        if sid < i % k:
            sid = heapq.heappop(free)
        heapq.heappush(busy, (t + load[i], sid))
        cnt[sid] += 1
    max_cnt = max(cnt)
    return [i for i in range(k) if cnt[i] == max_cnt]
```

```python
def avoidFlood_v2(rains):
    res = [-1] * len(rains)
    full = {}
    dry_days = []
    for i, lake in enumerate(rains):
        if lake == 0:
            dry_days.append(i)
```

## 21. 实战模板集

### 21.1 区间调度通用模板

```python
def interval_scheduling(intervals, by='end', op='select_non_overlap'):
    """通用区间调度模板."""
    if by == 'end':
        intervals.sort(key=lambda x: x[1])
    elif by == 'start':
        intervals.sort(key=lambda x: x[0])
    selected = []
    last_end = -float('inf')
    for itv in intervals:
        if op == 'select_non_overlap':
            if itv[0] >= last_end:
                selected.append(itv)
                last_end = itv[1]
        elif op == 'merge':
            if not selected or selected[-1][1] < itv[0]:
                selected.append(list(itv))
            else:
                selected[-1][1] = max(selected[-1][1], itv[1])
    return selected
```

### 21.2 跳跃游戏通用模板

```python
def jump_game(nums, mode='can'):
    n = len(nums)
    if n <= 1: return 0 if mode == 'min' else True
    if mode == 'can':
        max_reach = 0
        for i in range(n):
            if i > max_reach: return False
            max_reach = max(max_reach, i + nums[i])
        return True
    elif mode == 'min':
        jumps = end = farthest = 0
        for i in range(n - 1):
            farthest = max(farthest, i + nums[i])
            if i == end:
                jumps += 1
                end = farthest
        return jumps
```

### 21.3 双向指针通用模板

```python
def two_pointer(nums, target):
    nums.sort()
    i, j = 0, len(nums) - 1
    while i < j:
        s = nums[i] + nums[j]
        if s == target:
            return [i, j]
        elif s < target:
            i += 1
        else:
            j -= 1
    return []
```

### 21.4 堆维护贪心模板

```python
import heapq
def heap_greedy(items, capacity):
    """堆 + 贪心: 用最小堆维护"当前最差"以便替换."""
    pq = []  # min heap
    for item in items:
        heapq.heappush(pq, item)
        if len(pq) > capacity:
            heapq.heappop(pq)
    return sum(pq)
```

历史维度上,我们看到三个规律:

1. **从特殊到一般**: 早期方法往往针对特定场景,后期抽象出通用框架。学习的认知规律也是先掌握具体案例,再抽象出一般模式。这种"自下而上"的学习方式,在机器学习模型的设计里反复出现。

2. **从手工到自动**: 经验规则逐步被数据驱动的方法取代。在早期,很多 AI 系统依赖人工编写的规则。统计学习方法的崛起让"从数据中学习"成为可能。深度学习进一步把特征工程也自动化了。今天的大模型时代,我们看到端到端学习从感知扩展到了推理与生成。

**2. 思维框架视角的展开**

从思维框架视角出发,我们可以把 "贪心算法" 拆解为以下几个层次:

**第一层: 概念层** —— 这是最抽象的层次,定义了我们要研究的对象是什么。例如,"推荐系统"在概念层是一个"为用户从物品集合中筛选合适物品"的问题。这个层次的特点是清晰、稳定、不易变化。一个好的概念定义应该具备几个特征:可操作性、可测量性、可扩展性。

**第二层: 模型层** —— 把概念实例化为数学模型。同一概念可以有不同的模型化方式,例如"推荐系统"可以是协同过滤、矩阵分解、深度学习等。模型的选择决定了后续算法的空间,也决定了能利用的归纳偏置(比如序列模型擅长捕捉时序依赖,图模型擅长建模关系结构)。模型选型是工程实践中最重要的决策之一。

**第三层: 算法层** —— 在选定模型下,具体的求解方法。这一层最活跃,新算法层出不穷。同一模型往往有多种算法,各有优劣。例如同样是优化深度网络,可以选择 SGD、Adam、L-BFGS 等不同算法。算法的选择要考虑收敛速度、数值稳定性、计算成本等多个维度。

**第四层: 工程层** —— 算法落地的实现细节,包括数据流水线、训练框架、推理优化、监控告警等。工程层是研究到生产的桥梁,决定了一个方法能否真正用起来。一个在论文里表现很好的算法,如果不能高效实现、不能稳定运行、不能快速迭代,就没有实际价值。工程能力是把研究转化为生产力的关键。

**第五层: 业务层** —— 在具体业务场景中的表现。同一技术在不同业务里效果差异巨大,因为业务目标、数据分布、用户行为都有差异。从业务视角看技术,我们必须回答几个问题:这个技术解决了什么业务问题?投入产出比如何?长期可持续吗?技术评估必须与业务目标对齐,否则容易陷入"技术自嗨"的陷阱。

**3. 数学形式化(简洁版)**

虽然我们强调思维框架视角,但数学形式化提供了共同语言。机器学习的核心问题可以表达为:给定输入样本,学习一个映射函数,使得函数输出与真实目标的差距最小化。这个抽象捕捉了分类、回归、生成等大多数任务的本质。

进一步,优化目标通常加入正则化项来控制模型复杂度,平衡经验风险与模型容量。统计学习理论给出了泛化误差的上界,告诉我们模型越复杂并不一定越好——**奥卡姆剃刀**在数学上有严格的形式化。

偏差-方差分解是另一个核心框架:误差可以分解为模型偏差(欠拟合)、方差(过拟合)和不可约噪声三部分。理解这个分解有助于诊断模型表现、选择合适复杂度。

在数值稳定性方面,有几个常见陷阱: 浮点数精度有限、Log-Sum-Exp 计算要减去最大值、Softmax 在大数值下会溢出。这些工程细节常常决定一个模型能否在生产环境稳定运行。

**4. 信息论视角**

信息论为"贪心算法" 提供了统一的视角:**学习的本质是从数据中提取与目标相关的信息**。

互信息衡量知道一个变量后,另一个变量不确定性减少的量。在机器学习中,它被广泛用于特征选择、表示学习、多模态对齐等场景。

KL 散度衡量两个概率分布的距离,在交叉熵损失、变分推断、策略梯度等场景无处不在。需要注意它是**不对称**的——不同方向有不同的解释。

信息瓶颈原则指出,我们应该寻找既紧凑又预测性强的表示。这一思想影响了大量表示学习方法的设计,包括对比学习、自监督学习、多模态预训练等。

**7. 实践建议**

结合 "贪心算法" 的特点,实践中有以下建议:

1. **数据优先**: 数据质量决定上限,模型只是逼近这个上限。把 50% 的时间投入到数据理解和清洗上,这条经验被无数实践证明。数据问题往往比模型问题更关键,但也更容易被忽视。

2. **基线先行**: 先用最简单的方法(如逻辑回归、规则)做基线,确认增益是来自方法还是数据。没有强基线的"创新"往往不靠谱。很多看似 fancy 的方法,在强基线面前提升有限。

3. **迭代式改进**: 不要追求一步到位,而是 baseline → 简单改进 → 高级方法 → 调优。每一步都用验证集确认有提升。每一步的提升幅度通常递减,要预期边际收益下降。

4. **失败案例分析**: 重点看模型做错的样本,往往能发现系统性问题。错误样本里藏着模型没学会的知识。把这些样本按错误类型分类,可以发现模型的薄弱点。

5. **A/B 测试**: 在生产环境做对照实验,用业务指标而非离线指标评估。离线指标只是手段,业务指标才是目的。指标可以被优化,但业务目标很难直接优化。

6. **监控与回滚**: 上线后持续监控关键指标,异常时快速回滚。任何线上系统都必须考虑"最坏情况",并预先设计好应对方案。

**8. 常见误解**

对 "贪心算法" 常见的误解包括:

1. **"模型越复杂越好"**: 实际上,简单模型 + 好数据往往优于复杂模型 + 烂数据。这条法则在实践中反复被验证。

2. **"训练 loss 越低越好"**: 训练 loss 低不代表泛化好,可能过拟合。要看验证集表现,做误差分析。

3. **"指标好就等于业务好"**: 离线指标与在线业务有 gap,必须做 A/B 测试。指标可以被优化,但业务目标很难直接优化。

4. **"新方法一定比旧方法好"**: 新方法通常针对特定场景,在你的场景未必更好。要谨慎评估,先复现,再改进。

5. **"开源即用"**: 开源代码与你的数据/工程栈往往有 gap,需要适配。盲目复用经常踩坑,要理解代码再做改动。

"贪心算法" 与以下主题密切相关:

- **上游**: 数据质量、特征工程、业务理解。这些决定了模型的天花板。
- **下游**: 工程部署、效果监控、迭代优化。这些决定了模型的下限。
- **平行**: 类似方法、竞争方案、补充技术。了解竞品才能做得更好。

理清这些关系,有助于建立完整的知识图谱。技术学习不能孤立,要在关系网络中理解。每一个技术节点都与其他节点相连,只看到一个节点会失去全局视野。
