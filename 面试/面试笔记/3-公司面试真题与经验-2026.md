# 3-公司面试真题与经验-2026

> **定位**：从公开候选人面经中提取可复用规律，不把培训软文或单一匿名帖子当成确定事实。
>
> **证据标记**：`[原始面经]` 指候选人自述；`[二次转载]` 指转载或汇编；`[归纳]` 指多篇公开资料共同出现的规律。
>
> **隐私原则**：不记录候选人姓名、联系方式和可识别身份；薪酬仅保留公开口径，不把个案当市场定价。

---

## 0. 一句话总结

**推荐 / LLM 算法面试不是背八股竞赛，而是“项目证据 × 基础推导 × 可运行代码 × 业务判断 × 稳定沟通”的乘法。**

任何一项接近零，都可能在对应轮次被淘汰。

一面常验证“会不会”。

二面常验证“为什么”。

三面常验证“能否负责真实业务”。

HR 面常验证“是否真的会来、能否稳定入职、期望是否可落地”。

最常见的失败不是不会某个冷门模型，而是简历写了却讲不清、算法有思路却写不完、项目有结果却无法证明、系统设计不先问约束。

建议配合 `../工程与职业/11-算法工程师面试全攻略.md`、`../工程与职业/8-职业发展与晋升路线.md` 和 `../工程与职业/9-项目展示与技术影响力.md` 使用。

## 1. 字节跳动 - 推荐 / LLM 算法

### 1.1 招聘流程

#### 1.1.1 常见流程

公开面经中常见流程如下：

1. 官网、内推或人才库捞取。
2. 部分岗位先笔试，部分部门直接技术面。
3. 一面：项目、基础、一道或两道代码。
4. 二面：项目深挖、模型原理、业务题、代码。
5. 三面：负责人面，开放题、系统设计、研究判断。
6. 部分岗位增加交叉面或第四轮技术面。
7. HR 面：意向、地点、实习周期、已有 offer、稳定性。
8. offer call、意向书、审批与正式 offer。

流程会因业务线、校招 / 社招、实习 / 正式岗位和 HC 状态变化。

不要把“三轮”理解成固定规则。

AI Lab、豆包、抖音推荐、商业化、TikTok 推荐的考察权重不同。

公开案例显示字节约面节奏经常较快。

也有候选人一轮后等待数日或一周才收到下一轮通知。

面试时间常见 40—90 分钟。

连续安排二、三面时，应提前准备饮水和可持续输出节奏。

#### 1.1.2 推荐岗各轮侧重

| 轮次 | 高频考察 | 通过信号 | 危险信号 |
|---|---|---|---|
| 一面 | 简历真实性、推荐基础、概率、代码 | 能解释模型细节并写完中等题 | 只背模型名、代码边界错 |
| 二面 | 项目决策、多任务、召回排序、业务偏差 | 能比较方案并量化结果 | 只说“效果更好” |
| 三面 | 场景设计、系统取舍、研究视野 | 主动澄清约束并形成闭环 | 发散但不收敛 |
| 交叉面 | 通用基础、跨方向理解、文化匹配 | 不依赖原团队上下文也能讲清 | 项目只在熟人语境下成立 |
| HR 面 | 意愿、地点、稳定性、时间 | 信息一致、表达诚实且积极 | 前后口径冲突 |

#### 1.1.3 LLM 岗各轮侧重

一面常覆盖 Transformer、LLaMA、RMSNorm、SwiGLU、数据清洗、PPL 和编码。

二面常覆盖数据配比、评测、前沿模型、工具调用、训练困难和论文。

三面常覆盖 DeepSpeed、ZeRO、DP / DDP、显存与训练时间估算、训练监控、解码策略。

高级岗位还会追问：

- 模型为什么 work。
- 数据比模型更重要时如何验证。
- SFT 后为什么需要 RL。
- Reward hacking 如何发现。
- 训练与推理成本如何核算。
- 方案如何上线、降级和监控。

### 1.2 笔试题型

#### 1.2.1 编程题

常见为 2—4 道编程题，题型集中在：

- 哈希与前缀和。
- 二分查找。
- BFS / DFS。
- 最短路。
- 动态规划。
- 链表与二叉树。
- 字符串滑动窗口。
- 模拟与边界处理。

公开求职记录中有人因笔试代码未通过而止步。

“有思路”通常不能替代通过测试用例。

Python 要警惕超时。

C++ 要警惕调试成本。

选语言应以最熟练、最能稳定 AC 为准。

#### 1.2.2 选择与基础题

可能覆盖：

- 概率统计。
- 数据结构与复杂度。
- 操作系统与计算机网络。
- Python / C++ 语言基础。
- 机器学习与深度学习。
- 推荐指标。
- NLP / LLM 基础。

#### 1.2.3 推荐专项题

- DIN 的局部激活与 attention unit。
- DIEN 如何建模兴趣演化。
- MMoE、PLE、ESMM 的差异。
- 多任务 loss 如何平衡。
- 位置偏差、曝光偏差、选择偏差。
- User-CF 与 Item-CF 的适用场景。
- AUC、GAUC、NDCG 的含义。
- 召回、粗排、精排和重排的工程约束。

#### 1.2.4 LLM 专项题

- 手写 RMSNorm。
- 手写 MHA / GQA / Cross-Attention。
- RoPE 与其他位置编码。
- LLaMA 的结构变化。
- ZeRO-1 / 2 / 3 分别切什么。
- 数据清洗、去重、质量评分与数据配比。
- PPL 公式与局限。
- SFT、PPO、DPO、GRPO。
- KV Cache、PagedAttention、投机解码。

### 1.3 一面典型问题

#### 1.3.1 推荐方向

1. 请用 90 秒介绍自己。
2. 选择一个最能代表你的项目。
3. 你在项目中具体负责什么？
4. 项目 baseline 是什么？
5. 为什么使用 MMoE 而不是 shared-bottom？
6. PLE 如何缓解负迁移？
7. ESMM 为什么在全空间建模？
8. 多个 loss 怎么融合？
9. 是否用过自适应权重或 PCGrad？
10. 如何判断存在 position bias？
11. 还知道哪些推荐偏差？
12. DIN 的 attention score 怎么算？
13. 为什么 attention 要除以 $\sqrt{d_k}$？
14. AUC 与 GAUC 的区别是什么？
15. GAUC 有什么局限？
16. User-CF 与 Item-CF 如何选择？
17. 新用户和新物品如何冷启动？
18. 召回率下降如何定位？
19. 离线提升、在线不涨有哪些原因？
20. 写二叉树最大宽度或最大路径和。

#### 1.3.2 LLM 方向

1. Transformer 与 LLaMA 的归一化有什么区别？
2. 手写 RMSNorm。
3. ReLU、GeLU、SwiGLU 有什么差异？
4. BERT 的预训练任务是什么？
5. BERT embedding 由哪些部分组成？
6. 常见位置编码如何比较？
7. PPL 如何计算？
8. 数据质量过滤用什么规则或模型？
9. 什么样的数据更适合模型学习？
10. 端到端大模型与多个小模型的取舍？
11. LLaMA 使用哪类 attention？
12. 显存不足怎么办？
13. LoRA 插在哪些层？
14. 全量微调与 LoRA 如何选？
15. 写一道 Easy / Medium LeetCode。

#### 1.3.3 一面回答标准

先给结论。

再给公式或结构。

再给项目中的实际选择。

最后给限制和替代方案。

示例：

```text
结论：我们选 PLE，不是因为它一定优于 MMoE，而是任务冲突明显。
证据：CTR 上升时 CVR 连续下降，梯度余弦多次为负。
方案：共享专家保留共性，任务专家隔离冲突，并按任务不确定性调 loss。
结果：离线两个任务同时改善；线上护栏指标无显著下降。
边界：任务高度相关、资源紧张时，MMoE 可能更划算。
```

### 1.4 二面典型问题

#### 1.4.1 项目深挖

- 为什么做这个项目？
- 原方案真正的瓶颈是什么？
- 你如何证明不是数据波动？
- 方案失败过几次？
- 消融实验支持哪条结论？
- 如果移除你负责的模块，会发生什么？
- 项目中谁做了什么？
- 指标提升是否达到统计显著？
- 上线后如何监控？
- 出现回滚时怎么处理？

#### 1.4.2 推荐系统

- 特征交互模型有哪些演进？
- LR 为什么使用 log loss，而不是 MSE？
- 长序列如何压缩？
- 实时用户塔如何更新？
- 多路召回怎么分配配额？
- Hard negative 如何构造？
- 曝光偏差如何纠正？
- 推荐是否一定需要召回？
- 如何兼顾商业收益和用户体验？
- 生成式推荐与传统双塔如何结合？

#### 1.4.3 LLM 系统

- 预训练数据配比的依据是什么？
- 如何评估数据质量？
- 主流 LLM 架构有哪些共同变化？
- 训练 LLM 最大困难是什么？
- 国内开源模型如何比较？
- 工具调用如何实现和评估？
- 推理能力的瓶颈在哪里？
- RAG 召回覆盖率低怎么办？
- 如何约束模型输出 JSON？
- 如何发现与缓解灾难性遗忘？

#### 1.4.4 二面代码题

公开案例出现过：

- 两数组元素最小绝对差。
- 硬币划分。
- 最长无重复子串。
- 买卖股票两次。
- 迷宫最短路径。
- LRU 风格数据结构。

面试官经常追问最优复杂度。

先写稳定解，再讨论优化。

不要为了炫技直接跳过可验证的朴素解。

### 1.5 三面典型问题

#### 1.5.1 负责人视角

1. 这个项目对业务的长期价值是什么？
2. 如果给你更多算力，你会优先扩大模型还是数据？
3. 如何设计一套从数据到上线的完整系统？
4. 你的方案失败时，最小降级路径是什么？
5. 下一代推荐系统会如何演进？
6. LLM 与推荐结合的真实收益点在哪里？
7. 哪些指标容易被优化“作弊”？
8. 如何做长期价值而非只看 CTR？
9. 如何将研究原型变成稳定服务？
10. 如果重新做一次，你会删除什么？

#### 1.5.2 LLM 训练工程

- DeepSpeed 三个 ZeRO 阶段分别分片什么？
- 每个阶段的通信与内存代价是什么？
- DP 和 DDP 有何差异？
- 训练时间如何估计？
- 最多使用过多少张卡？
- GPU 利用率如何测量？
- MFU 低如何定位？
- 训练过程中监控哪些指标？
- 7B / 70B 的参数与显存如何估算？
- 预训练与 SFT 如何分别评测？

#### 1.5.3 开放场景

公开案例出现过：

- 千万级视频库做重复视频检索。
- 大量磁盘数组求交集，且内存受限。
- 搜索 Query 联想与错别字纠正。
- 判断 Query 是否具有视频意图。
- 大文件中的专有名词计数与分布式处理。
- 含障碍和状态的网格最短路径。

回答模板：

```text
1. 先确认数据规模、QPS、延迟、召回率和内存约束。
2. 给出最小可行基线。
3. 找到主要瓶颈。
4. 只优化瓶颈，不堆组件。
5. 给出离线指标、在线指标和护栏。
6. 说明失败时的回滚与兜底。
```

### 1.6 HR 面常见问题

1. 为什么选择字节？
2. 为什么选择该业务线？
3. 是否愿意长期留在目标城市？
4. 当前还有哪些面试流程？
5. 手里有几个 offer？
6. 最早何时入职？
7. 实习能持续多久？
8. 是否接受业务调整？
9. 为什么没有投其他研究团队？
10. 未来三年的职业规划是什么？
11. 最看重团队、方向还是薪资？
12. 是否有继续读博计划？
13. 遇到高压项目怎么处理？
14. 你最大的优点和待改进项是什么？
15. 如果今天发 offer，你接受的概率多大？

HR 面不是“走过场”的同义词。

技术评价通过后，仍可能因 HC、稳定性、地点、期望、候选人排序而失败。

回答已有 offer 时，不隐瞒，但避免炫耀或制造不可信压力。

表达拒绝无效加班时，应聚焦效率与责任，不把面试变成价值观对抗。

所有轮次的学校、毕业时间、期望地点和可入职时间必须一致。

### 1.7 真实面试经验

#### 1.7.1 案例 A：字节大模型算法三轮

**来源**：牛客《字节大模型算法一二三面面经》。

**岗位**：大模型算法。

**流程**：一面、二面、三面。

**一面问题**：Transformer / LLaMA 归一化差异、RMSNorm、FFN、SwiGLU、数据清洗、PPL、BERT、位置编码、Prompt、两道代码题。

**二面问题**：论文、数据配比、训练数据可学习性、主流模型结构、评测、工具调用、国内模型、推理上限。

**三面问题**：硬件利用率、DeepSpeed、ZeRO、训练时间估算、DP / DDP、训练监控、预训练数据处理、解码策略、Cross-Attention。

**可复用结论**：LLM 岗要求数据、模型、训练、推理、硬件五层都能串起来。

#### 1.7.2 案例 B：字节推荐算法一二面

**来源**：牛客《字节-推荐算法一面二面》。

**岗位**：推荐算法。

**一面问题**：MMoE、ESMM、PLE、SNR、多任务 loss、position bias、CNN、LSTM、Self-Attention、扑克牌概率、二叉树最大宽度。

**二面问题**：代表性经历、CTR 特征交互、LR 推导、log loss、条件概率、硬币划分、协同过滤。

**结果信号**：一面后很快约二面，二面后收到三面通知。

**可复用结论**：项目中的一个模型名会沿着“原理—局限—替代—业务效果”连续追问。

#### 1.7.3 案例 C：字节算法四轮并获意向

**来源**：CSDN 二次转载《字节跳动算法全四面详细面经》。

**背景**：研究方向为文本匹配 / NLP。

**一面**：项目与“小兔棋盘”算法题。

**二面**：论文深挖、迷宫最短路径，候选人起初误用 DFS，经提示改为 BFS。

**三面**：最小覆盖子串、概率、公用大文件计数、Query 视频意图、CNN / RNN / Transformer、Python 动态数组。

**四面**：样本构造、搜索联想、错别字、连续区间和、含负数扩展。

**结果**：公开文章称收到意向书。

**可复用结论**：高轮次并不只看是否秒答，更看接受提示后能否修正并完成。

#### 1.7.4 案例 D：机器学习算法三面 + HR 获 offer

**来源**：牛客《字节跳动机器学习算法岗面筋，一二三面+hr面》。

**背景**：985 硕，论文有但代码自评较弱。

**一面代码**：二叉树直径，边界条件有问题后修正。

**二面代码**：两数组元素差绝对值最小，给出排序 + 二分，未得到最优双指针。

**三面代码**：最深叶节点最近公共祖先，在面试官引导下推出递推。

**HR**：地点、岗位理解、其他 offer、实习与留用意愿。

**结果**：拿到 offer。

**可复用结论**：代码并非要求每题完美，但思路、沟通、修正能力和其他证据会共同评分。

#### 1.7.5 案例 E：TikTok 推荐实习一面

**来源**：牛客《字节 tiktok 推荐算法实习一面（已过）》。

**时长**：约一小时。

**问题**：多域数据分析、项目每一步动机、Transformer、QKV、MHA、FlashAttention、梯度下降、AdamW、ROC / PR、AUC / GAUC、NDCG。

**代码**：最长有效括号，候选人未完成。

**结果**：帖子标题标注一面通过。

**可复用结论**：一次代码失误不一定直接淘汰，但不能把它当作可复制策略。

#### 1.7.6 案例 F：AI Lab 提前批多轮获 offer

**来源**：牛客《字节跳动 AILab 提前批算法工程师面经（已收到 offer）》。

**一面**：图上的“红人”识别、KMeans TensorFlow 实现。

**二面**：ACM、GitHub 项目、实习、AAAI 论文。

**三面**：TensorFlow 写 KNN、可微性、argmax 导数、矩阵乘法与优化。

**交叉面**：Word2Vec、FastText、ELMo、GPT、BERT、自注意力、职业规划。

**结果**：offer call。

**可复用结论**：简历中的竞赛、开源、论文与实习都可能成为主线；不要只准备岗位八股。

### 1.8 失败原因分析

#### 1.8.1 失败原因清单

1. 论文只会复述摘要。
2. 项目中的数据构造解释不清。
3. 只知道模型名称，不知道为什么选。
4. 推荐指标不会从统计含义解释。
5. 算法题不先澄清边界。
6. 写出代码但不能处理空输入和重复值。
7. 把 BFS / DFS、并集 / 交集等题意看错。
8. 追求最优解，导致朴素解也没写完。
9. 不会估算参数、显存、FLOPs、训练时间。
10. 开放题堆名词，没有基线和约束。
11. 项目结果没有显著性和归因证据。
12. HR 面意愿表达模糊或信息前后冲突。

#### 1.8.2 避免方式

- 每个简历名词准备“定义、公式、选择原因、替代方案、线上结果、失败案例”。
- 每个项目画一张数据流图和一张系统图。
- 每道代码题先说复杂度，再写测试样例。

### 2.5 offer 谈判经验

#### 2.5.1 谈判前先算总包

```text
总现金 = 月 base × 发薪月数 + 年终奖 + 签字费
总包 = 总现金 + 可兑现股票 / 期权 + 明确补贴
风险调整总包 = 总包 - 不确定奖金折价 - 股票波动折价 - 搬迁成本
```

不要把“最高年终奖”当保证收入。

不要把未说明归属期的股票按现金等价计算。

社招还要确认竞业、试用期、职级、汇报线和绩效分布。

#### 2.5.2 可谈要素

- Base。
- 发薪月数。
- 签字费。
- 股票 / 期权。
- 职级。
- 汇报团队。
- 入职日期。
- 搬迁支持。
- 年假。
- 试用期薪资比例。

#### 2.5.3 谈判话术

```text
非常感谢团队的认可，我对岗位和业务方向都很感兴趣。
为了做最终决定，我想确认职级、固定现金、奖金口径和股票归属方式。
结合我在推荐 / LLM 项目中能够直接承担的职责，以及手头其他机会的可比总包，
如果固定现金或签字费能进一步优化到 X 区间，我会更有信心尽快确认。
```

#### 2.5.4 避坑

1. 没有书面 offer 前不裸辞。
2. 口头 offer 不等于 HC 最终批准。
3. 不伪造竞品 offer。
4. 不用威胁口吻谈判。
5. 不只谈数字，要谈岗位范围与成长。
6. 校招应确认违约成本。
7. 社招应确认背调范围。
8. 海外回流应确认税前税后、落户与搬迁。

- 模糊需求先反问还是先检索？
- Agent 评测维度有哪些？
- 如何防止循环调用？

### 4.3 真实经验

#### 4.3.1 案例 A：美团大模型完整一、二面

**来源**：牛客《美团大模型算法岗完整面经（一面+二面）》。

**一面**：职业规划、团队介绍、SFT / RL、Attention 维度、Workflow / Agent、Memory / RAG、GRPO 显存、KMeans、两数之和。

**二面**：数据质量、数据配比、SFT loss、Thinking、RL 数据、Reward hacking、训练监控。

**可复用结论**：二面明显从概念切换到数据与训练决策。

#### 4.3.2 案例 B：美团搜索推荐二面失败

**来源**：牛客《面试复盘：美团搜索推荐算法一、二面面经》。

**背景**：候选人 NLP 研究为主，推荐经历较浅。

**一面**：推荐流程、双塔、DIN、研究方向，面试官有引导，进入二面。

**二面**：论文数据与训练、显著性、多目标、召回、冷启动、最长无重复子数组、被围绕区域。

**结果**：二面失败。

**候选人复盘**：项目介绍不清，多任务理解浅，编程题理解出错；认为代码未做出是高风险因素。

#### 4.3.3 案例 C：美团基础研发大模型实习

**来源**：牛客《美团基础研发 大模型算法工程师实习面经》。

**一面**：P-Tuning、训练监控、训练步数、RLHF、LLaMA-Factory、DPO、旋转数组最小值。

**二面**：训练数据、RLHF 阶段重要性、PPO、Reward Model、效率、多目标奖励、DPO、爬楼梯优化。

**可复用结论**：开放题重点是取舍和判断，而非背标准答案。

#### 4.3.4 案例 D：美团搜索推荐已 OC

**来源**：公开转载《美团搜索推荐算法工程师面经（已 OC）》。

**流程**：9 月 3 日一面、9 月 9 日二面、9 月 20 日 OC；无独立 HR 面。

**一面**：腾讯 / 快手实习、NPU、LongLoRA、LLM + 推荐、GNN、论文、BN、重排链表。

**二面**：实习挑战、NPU debug、论文落地、GNN 采样、学习方法、Transformer、位置编码、GitHub PR、Top-K。

**可复用结论**：工程平台经历、开源贡献和学习方法也可成为重要证据。

#### 4.3.5 案例 E：美团大模型推荐实习一面

**来源**：牛客《美团大模型推荐算法一面-实习面经》。

**问题**：BM25、混合检索、Reranker 数据、Query 改写、GRPO、训练推理优化、Embedding 结构与维度。

**代码**：合并去重数组。

**可复用结论**：大模型推荐岗正在融合传统检索、RAG、后训练和工程效率。

### 4.4 美团失败高发点

- 研究方向与岗位不匹配，却没有补足推荐业务。
- 论文结果无法解释随机性和置信度。
- 只会“召回—排序”口号，不知道何时需要召回。
- 多任务只听过模型名。
- 冷启动方案停留在“热门推荐”。
- 代码题看错题意。
- 写了 RAG 项目却说不清负样本和 reranker。
- RL 只背 PPO / DPO，不会设计 Reward。

### 4.5 准备建议

推荐岗必须掌握经典模型与生成式推荐两条线。

LLM 岗必须能讨论数据质量与 Reward，而非只讲 Transformer。

准备至少两个业务案例：外卖 / 闪购 / 酒旅任选其二。

每个案例明确用户、商家、平台三方目标。

面试代码优先保证正确，再优化空间。

## 6. 互联网公司 P6/P7 算法工程师 offer 案例

> 本节是基于公开多案例抽象的“画像案例”，不是冒充某个匿名候选人的逐字经历。

### 6.1 案例 1：校招 P6

#### 6.1.1 背景

- 985 / 211 硕士。
- 一段大厂推荐或 LLM 实习。
- 一篇在投 / 已发表论文，或高质量竞赛成果。
- LeetCode Hot 100 基本熟练。
- 项目能提供数据、模型、工程、业务完整闭环。

#### 6.1.2 面试表现

一面稳定完成中等题。

二面能解释模型选型和失败实验。

三面能设计简化系统并说明成本。

HR 面入职意愿明确。

#### 6.1.3 定级证据

- 独立完成核心模块。
- 能将模型部署上线。
- 有可量化收益。
- 能处理常见故障。
- 研究潜力或工程能力突出。

#### 6.1.4 风险

校招“P6”或同等高档并非统一公司标准。

论文数量不能替代实习贡献。

SSP 也可能受批次、HC 和竞争池影响。

### 6.2 案例 2：社招 P7

#### 6.2.1 背景

- 5—8 年推荐 / 搜索 / 广告或 LLM 经验。
- 独立负责一条模型链路或业务方向。
- 跨算法、工程、数据、产品协作。
- 至少一个从 0 到 1 或显著重构项目。
- 有团队指导或技术影响力。

#### 6.2.2 面试重点

- 业务目标如何定义。
- 你是否真正做过关键决策。
- 如何管理实验与上线风险。
- 如何推动跨团队协作。
- 方案如何复用到多个场景。
- 如何培养成员。
- 下一代技术路线判断。

#### 6.2.3 offer 评估

不要只看 P7 名称。

需要比较实际职责、汇报对象、团队资源、绩效分布和晋升窗口。

“高职级、窄职责”可能不如“稍低职级、真实 owner”。

### 6.3 案例 3：跨行转型

#### 6.3.1 公开参照

牛客公开案例中有测绘地信背景候选人，算法求职受挫后转向地图数据产品，最终获得高德意向。

也有 GNN 研究候选人凭论文与推荐实习转向 LLM，并获得多家大厂机会。

#### 6.3.2 可复制路径

1. 保留原领域的独特资产。
2. 找到与目标岗位共同的问题结构。
3. 用一个真实项目完成能力迁移。
4. 简历突出迁移后的证据，不写空泛“热爱 AI”。
5. 选择允许邻域迁移的团队。

#### 6.3.3 示例

```text
原领域：量化 / GNN / 地图 / CV
共同资产：大规模数据、表示学习、在线系统、评测、领域知识
目标岗位：推荐 / LLM
桥接项目：检索、排序、RAG、多模态、图增强 LLM
证明方式：可复现实验 + 线上或真实用户反馈 + 性能指标
```

### 6.4 案例 4：海外回流

#### 6.4.1 常见优势

- 英文论文与国际协作。
- 大规模系统或研究经历。
- 对国际开源生态熟悉。
- 可能具备较强系统设计能力。

#### 6.4.2 常见风险

- 对国内业务指标不熟。
- 薪资锚点差异大。
- 对职级映射理解不一致。
- 入职时间、签证、搬迁复杂。
- 沟通偏研究，缺少业务闭环。

#### 6.4.3 面试策略

把研究结果翻译成业务价值。

明确国内可入职日期。

薪资比较使用税后、股票归属和生活成本。

提前学习国内推荐场景和指标。

不要只讲论文 novelty，要讲系统成本和上线风险。

## 7. 失败案例库

### 7.1 简历筛选失败

#### 7.1.1 案例 1：25 届算法投递大量简历挂

**来源**：牛客《25届算法投递之路》。

**背景**：双非本科、硕士、非计算机相关专业，目标算法岗。

**结果**：公开记录列出多家公司简历挂，包括快手、阿里云等。

**可能原因**：岗位竞争激烈、方向匹配不足、算法证据不够强。

**避免**：按 JD 定制关键词；用项目结果证明能力；先争取邻近岗位或实习。

#### 7.1.2 案例 2：投递过晚导致机会减少

**来源**：牛客《推荐系统算法岗秋招个人总结》。

候选人提到部分大厂投递较晚，HC 已减少，腾讯简历未获得机会。

**避免**：核心岗位提前批开始即准备；非目标公司先练手，目标公司不要拖到末期。

### 7.2 笔试挂

#### 7.2.1 案例 3：多家公司笔试止步

**来源**：牛客《25届算法投递之路》。

公开记录包括小米、京东、美团、字节等笔试挂。

**避免**：每周做限时模拟；按真实输入输出写；训练多题时间分配；复盘未过用例。

#### 7.2.2 案例 4：Python 超时，切 C++ 又来不及

**来源**：LeetCode 讨论《算法岗｜迟到的秋招日记》。

候选人第一题通过，第二题 Python 超时，临时换 C++ 后未调完，笔试失败。

**避免**：不要在考试末段换语言；先估复杂度；准备 Python 快 IO 和常见优化。

### 7.3 一面挂

#### 7.3.1 案例 5：算法题未完全 AC

**来源**：牛客《春招结束了，0offer》。

候选人多次基础回答不错，但算法题没完全 AC，一面或后续失败。

其中一次通过熟人查看后台，反馈为算法未 AC。

**避免**：刷题不只看题解；必须计时、手写、测试边界。

#### 7.3.2 案例 6：场景题没有思路

**来源**：同一求职复盘。

京东面试中基础八股能答，场景题无法展开而失败。

**避免**：用“约束—基线—瓶颈—优化—指标—兜底”固定框架训练场景题。

### 7.4 二面挂

#### 7.4.1 案例 7：美团二面推荐深度不足

**来源**：牛客《面试复盘：美团搜索推荐算法一、二面面经》。

候选人一面通过，二面暴露论文介绍、推荐多任务、召回和代码题理解问题。

**避免**：不要依赖课程项目名；必须理解数据、训练、实验、工程和业务目标。

#### 7.4.2 案例 8：十二次二面失败的复盘

**来源**：牛客《二面永远是我的滑铁卢》。

候选人自述投 200+ 简历，12 家止步二面；根因是教程项目缺乏真实深度，只背八股。

**避免**：为每个技术选型准备替代方案、失败记录和指标证据；使用追问树 mock。

### 7.5 三面挂

#### 7.5.1 案例 9：系统设计只解决一半

**来源**：LeetCode 讨论《算法岗｜迟到的秋招日记》。

候选人在三面遇到系统设计，当场不熟，讨论后只解决一个关键问题，最终未通过。

**避免**：算法岗也要练系统设计；先澄清规模和约束，再画数据流与在线链路。

#### 7.5.2 案例 10：审题错误导致开放题雪崩

**来源**：字节 AI Lab 三轮面经二次转载。

候选人把数组“交集”看成“并集”，直到结束前被提醒。

**避免**：复述题意；给一个小例子验证；开放题先确认输出定义。

### 7.6 HR 面挂

#### 7.6.1 案例 11：蚂蚁 HRBP 挂

**来源**：CSDN《面试之路：从拒绝到 Offer》。

候选人自述在蚂蚁第四面 / HRBP 阶段失败。

公开摘要未给出具体对话，因此不能推断原因。

**避免**：技术通过后仍准备稳定性、动机、地点、薪资和经历一致性。

#### 7.6.2 案例 12：技术面通过后 HR 排序失败

**来源**：牛客《春招结束了，0offer》。

候选人用友技术流程通过，HR 面后等待两周，先待定后失败。

**避免**：保持并行流程；不要把 HR 面视作已拿 offer；主动确认时间线但不过度催促。

### 7.7 offer 被收回

#### 7.7.1 案例 13：口头 offer 因 HC 消失

**来源**：牛客《一个非科班渣硕的算法转非技术岗的艰难秋招之路》。

候选人获得创业公司 HR 明确口头承诺，国庆后迟迟未收到正式 offer，最终被告知 CTO 取消需求。

**避免**：书面 offer 前继续求职；确认 HC 是否批准；不要仅凭 HR 口头承诺停止流程。

#### 7.7.2 案例 14：薪资口径前后变化

**来源**：牛客《春招结束了，0offer》。

候选人记录某公司早期沟通可给 15k，最终 OC 口径变为最高 8k，并称工作数年后可能达到 15k。

**避免**：在流程早期问清固定薪资范围；最终以书面条款为准；不要把未来涨薪当当前 offer。

### 8.3 参考答案模板

#### 8.3.1 两数之和

```python
def two_sum(nums: list[int], target: int) -> list[int]:
    seen = {}
    for i, x in enumerate(nums):
        if target - x in seen:
            return [seen[target - x], i]
        seen[x] = i
    return []
```

时间 $O(n)$，空间 $O(n)$。

#### 8.3.2 无重复字符最长子串

```python
def length_of_longest_substring(s: str) -> int:
    last = {}
    left = ans = 0
    for right, ch in enumerate(s):
        left = max(left, last.get(ch, -1) + 1)
        last[ch] = right
        ans = max(ans, right - left + 1)
    return ans
```

关键是左边界不能回退。

#### 8.3.3 LRU Cache

```python
from collections import OrderedDict

class LRUCache:
    def __init__(self, capacity: int):
        self.capacity = capacity
        self.data = OrderedDict()

    def get(self, key: int) -> int:
        if key not in self.data:
            return -1
        self.data.move_to_end(key)
        return self.data[key]

    def put(self, key: int, value: int) -> None:
        if key in self.data:
            self.data.move_to_end(key)
        self.data[key] = value
        if len(self.data) > self.capacity:
            self.data.popitem(last=False)
```

面试官若要求手写底层，再改为哈希 + 双向链表。

#### 8.3.4 二叉树最大路径和

```python
def max_path_sum(root) -> int:
    ans = float("-inf")

    def gain(node):
        nonlocal ans
        if not node:
            return 0
        left = max(gain(node.left), 0)
        right = max(gain(node.right), 0)
        ans = max(ans, node.val + left + right)
        return node.val + max(left, right)

    gain(root)
    return ans
```

向父节点返回时不能同时带左右两支，否则路径分叉。

#### 8.3.5 岛屿数量

```python
def num_islands(grid: list[list[str]]) -> int:
    if not grid:
        return 0
    m, n = len(grid), len(grid[0])

    def dfs(i: int, j: int) -> None:
        if not (0 <= i < m and 0 <= j < n) or grid[i][j] != "1":
            return
        grid[i][j] = "0"
        dfs(i + 1, j)
        dfs(i - 1, j)
        dfs(i, j + 1)
        dfs(i, j - 1)

    ans = 0
    for i in range(m):
        for j in range(n):
            if grid[i][j] == "1":
                ans += 1
                dfs(i, j)
    return ans
```

#### 8.3.6 最长递增子序列

```python
from bisect import bisect_left

def length_of_lis(nums: list[int]) -> int:
    tails = []
    for x in nums:
        i = bisect_left(tails, x)
        if i == len(tails):
            tails.append(x)
        else:
            tails[i] = x
    return len(tails)
```

`tails[i]` 表示长度为 `i + 1` 的递增子序列可达到的最小结尾。

#### 8.3.7 零钱兑换

```python
def coin_change(coins: list[int], amount: int) -> int:
    inf = amount + 1
    dp = [0] + [inf] * amount
    for x in range(1, amount + 1):
        for c in coins:
            if c <= x:
                dp[x] = min(dp[x], dp[x - c] + 1)
    return -1 if dp[amount] == inf else dp[amount]
```

#### 8.3.8 最长公共子序列

```python
def longest_common_subsequence(a: str, b: str) -> int:
    dp = [0] * (len(b) + 1)
    for x in a:
        prev = 0
        for j, y in enumerate(b, 1):
            old = dp[j]
            if x == y:
                dp[j] = prev + 1
            else:
                dp[j] = max(dp[j], dp[j - 1])
            prev = old
    return dp[-1]
```

## 9. 智力题库

### 9.1 二十道经典题

#### 9.1.1 三份牌中大小王同组

**题目**：54 张牌均分三份，大小王在同一份的概率？

**思路**：固定大王后，小王在剩余 53 个位置中，有同组剩余 17 个位置。

**答案**：$17/53$。

#### 9.1.2 五局三胜与三局两胜

**题目**：单局胜率固定时，哪种赛制更能让强者获胜？

**思路**：设单局胜率 $p>0.5$，分别计算二项分布尾概率。

**结论**：局数越多，强者获胜概率通常越高；若 $p=0.5$ 则都公平。

#### 9.1.3 两个均匀变量之和

**题目**：$x,y\sim U(0,1)$，求 $x+y<1$ 的概率。

**思路**：单位正方形中直线下方三角形面积。

**答案**：$1/2$。

#### 9.1.4 三个均匀变量之和

**题目**：$x,y,z\sim U(0,1)$，求 $x+y+z<1$。

**思路**：单位立方体内四面体体积。

**答案**：$1/6$。

#### 9.1.5 两个均匀变量最小值期望

**题目**：独立 $a,b\sim U(0,1)$，求 $E[\min(a,b)]$。

**思路**：$P(\min(a,b)>t)=(1-t)^2$，对 $t$ 从 0 到 1 积分。

**答案**：$1/3$。

#### 9.1.6 三门问题

**题目**：主持人打开一扇羊门后是否换门？

**思路**：初选中奖概率 $1/3$，其余门合计 $2/3$；主持人信息将 $2/3$ 集中到未开的门。

**答案**：换门，中奖率 $2/3$。

#### 9.1.7 生日悖论

**题目**：多少人时至少两人同生日概率超过 50%？

**思路**：计算全不相同概率并取补集。

**答案**：23 人。

#### 9.1.8 两根绳子计时 45 分钟

**题目**：两根燃烧不均、各烧 60 分钟的绳子如何计 45 分钟？

**思路**：绳 A 两端点燃，绳 B 一端点燃；A 烧完 30 分钟时点燃 B 另一端，B 再烧 15 分钟。

#### 9.1.9 8 球称重

**题目**：8 个球一个较重，两次天平找到。

**思路**：3、3、2 分组；先称 3 对 3，再在可疑组中一次定位。

#### 9.1.10 1000 瓶毒药与 10 只鼠

**题目**：一轮实验找出一瓶毒药。

**思路**：用 10 位二进制编码瓶号，每只鼠喝对应位为 1 的样本混合液。

#### 9.1.11 囚徒与灯泡

**题目**：随机进入房间，如何确认所有人都来过？

**思路**：指定计数者；其他人仅第一次遇到灯灭时开灯；计数者累计关灯次数。

#### 9.1.12 两个鸡蛋与 100 层楼

**题目**：最坏最少次数？

**思路**：第一次按递减步长投掷，使最坏次数相等；找最小 $n$ 满足 $n(n+1)/2\ge100$。

**答案**：14 次。

#### 9.1.13 25 匹马找前三

**题目**：每次赛 5 匹，无计时器，最少几场？

**思路**：先 5 组赛，再组冠军赛，排除不可能者，最后候选赛。

**答案**：7 场。

#### 9.1.14 海盗分金币

**题目**：海盗按提案、投票、处决规则分金币。

**思路**：从最少人数向后逆推，分析每人的下一状态收益。

**重点**：先澄清平票是否通过、偏好顺序和人数。

#### 9.1.15 帽子颜色

**题目**：若干人可见他人帽子，如何保证最多人答对？

**思路**：使用奇偶校验；第一个人传递全局 parity，其余据此推断。

#### 9.1.16 切蛋糕八块

**题目**：三刀最多切八块？

**思路**：前两刀十字切四块，第三刀水平穿过四块。

#### 9.1.17 9 个点四条直线

**题目**：不抬笔用四条直线连接九点。

**思路**：直线可以延伸到点阵外，突破隐含边界。

#### 9.1.18 假硬币与不确定轻重

**题目**：12 枚硬币一枚异常，且不知轻重，三次称重找出。

**思路**：每次称重有三种结果，共 $3^3=27$ 种，可编码 24 种“硬币 × 轻重”状态；使用预先设计的平衡分组。

#### 9.1.19 蓄水池抽样

**题目**：未知长度流中等概率抽一个元素。

**思路**：第 $i$ 个元素以 $1/i$ 概率替换当前样本。

**证明**：元素 $j$ 最终保留概率为 $1/j\prod_{k=j+1}^n(1-1/k)=1/n$。

#### 9.1.20 砝码称量

**题目**：用最少砝码称 1 到 40 的整数重量，砝码可放两边。

**思路**：平衡三进制，每位取 -1、0、1。

**答案**：1、3、9、27。

### 9.2 智力题答题原则

先确认规则。

用小规模例子验证。

概率题优先找对称性、条件概率或几何面积。

状态题优先逆推。

信息题计算每次操作可区分多少状态。

面试官更看推理过程，不只看最终数字。

## 10. 失败原因 Top 10

### 10.1 项目讲不清

**表现**：背景过长、职责模糊、指标无证据。

**根因**：项目是团队做的，但候选人没有提炼个人决策。

**避免**：准备 90 秒、5 分钟、15 分钟三个版本。

### 10.2 算法题做不出

**表现**：刷过但无法从空白写出。

**根因**：只看题解，没有限时手写和边界测试。

**避免**：每题至少一次闭卷写完；每周模拟两场。

### 10.3 系统设计答不全

**表现**：直接堆 Redis、Kafka、向量库和模型名。

**根因**：没有先确认规模和 SLO。

**避免**：固定使用“需求—规模—架构—瓶颈—监控—降级”。

### 10.4 基础知识薄弱

**表现**：会使用 LoRA / DIN，却不会公式、维度和复杂度。

**根因**：工程使用替代了原理学习。

**避免**：每个核心模块手写一次最小实现。

### 10.5 沟通能力差

**表现**：长篇绕圈、不回应问题、被提示后仍固守原答案。

**根因**：没有结构化表达和澄清习惯。

**避免**：结论先行；每两分钟检查是否回答了原问题。

### 10.6 业务理解不足

**表现**：只谈 AUC，不知道用户、商家、平台目标。

**根因**：把算法岗位理解为离线建模。

**避免**：每个项目写出北极星指标、护栏指标和成本指标。

### 10.7 简历真实性或一致性存疑

**表现**：术语写得很深，追问时说是同事负责。

**根因**：过度包装。

**避免**：删除无法独立讲清的内容；明确团队与个人贡献。

### 10.8 缺少实验可信度

**表现**：只报最好一次结果，无法解释显著性、随机种子和数据切分。

**根因**：没有把实验当因果证据。

**避免**：保留多次实验、置信区间、消融和线上护栏。

### 10.9 面试轮次准备错位

**表现**：二面仍只背一面八股，三面仍只讲细节。

**根因**：不知道各轮考察目标。

**避免**：一面练正确性，二面练深度，三面练取舍，HR 练一致性。

### 10.10 稳定性与意愿表达失误

**表现**：地点、入职时间、offer 情况前后不一致。

**根因**：没有提前整理真实口径。

**避免**：写一页 HR 信息表，所有轮次保持一致。

### 11.2 面试进行中

先确认题意。

不知道时不要编造。

可以说：

```text
这部分我没有在生产环境直接做过。
我先基于已知约束给一个可验证方案，再说明需要补充的数据。
```

代码题边写边解释不变量。

开放题先问约束。

项目题明确“我”与“团队”。

被纠正时快速更新，不争辩。

时间不足时先给完整基线。

### 11.3 反问环节

#### 11.3.1 高质量问题

1. 团队当前最重要的业务指标是什么？
2. 这个岗位入职三个月的成功标准是什么？
3. 当前最大技术瓶颈在数据、模型还是系统？
4. 推荐 / LLM 项目从实验到上线通常经历哪些环节？
5. 团队如何做代码与实验 review？
6. 新成员通常负责多大范围？
7. 未来一年最关键的技术路线是什么？
8. 团队如何平衡短期指标和长期研究？

#### 11.3.2 避免问题

官网可直接查到的问题。

第一轮就只问薪资福利。

带有攻击性的加班质问。

要求面试官当场承诺晋升。

询问机密模型参数和内部数据。

### 11.4 复盘

面试结束后 30 分钟内记录全部问题。

标记：答对、部分、不会、表达差。

只选最高影响的三个问题补课。

补课必须留下可运行代码、公式推导或新回答。

下一场前重新口述。

不要只写“项目没准备好”。

要写成可执行项：

```text
失败描述：被问 ESMM 的全空间建模，只会背 pCTCVR=pCTR×pCVR。
根因：不知道训练标签与推断空间差异。
动作：画样本空间图；推导两个 loss；用 toy data 实现一次。
验证：5 分钟内讲清选择偏差与推断公式。
```

## 13. 使用这份文档的七天计划

### 13.1 Day 1：简历与项目

选择两个项目。

分别写 90 秒与 5 分钟版本。

补齐数据、模型、工程、业务、失败、反思。

### 13.2 Day 2：推荐基础

复习 DIN、DIEN、MMoE、PLE、ESMM。

手画召回—粗排—精排—重排链路。

讲清 AUC、GAUC、NDCG。

### 13.3 Day 3：LLM 基础

手写 MHA、RMSNorm、LoRA。

复习 RoPE、GQA、KV Cache、FlashAttention。

### 13.4 Day 4：训练与系统

口算 7B 显存。

复习 ZeRO 与并行策略。

设计一个推荐服务和一个 LLM 服务。

### 13.5 Day 5：代码

限时完成 8 道高频题。

每题写边界和复杂度。

### 13.6 Day 6：模拟

做一场推荐 mock。

做一场 LLM mock。

录音并复盘。

### 13.7 Day 7：HR 与 offer

统一地点、时间、薪资和已有流程口径。

准备五个反问。

计算总包并写谈判底线。

## 15. 一句话收尾

> **真正有效的面经，不是让你预测下一道题，而是让你在题目变化后仍能从原理、证据和约束出发完成回答。**
>
> 面试不是证明你什么都知道，而是证明你能把真实问题讲清楚、做出来、上线并负责到底。
